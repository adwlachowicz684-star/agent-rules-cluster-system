## 判据（先读）

### B02 · while 退出条件

正确：有限上界 + guard 计数器；

**扫描特征**：`while` 体内 `*= 2` / `++` / `+=`，条件涉及 `Infinity` / `maxRadius` / `limit`。

### B03 · 递归

正确：传访问集或深度上限；

**扫描特征**：**普通函数自递归**与**方法自递归**两种形态都会检；

**如何确认**：深度是否由数据决定（子表互引用、嵌套树）→ 是则必改。

### F01 · 反序列化入口

正确：`import` 复用与 `register`/`set` **相同的归一化函数**；

**扫描特征**：`import*`/`deserialize`/`load` 内直接 `this._x.set/push/add`； 规律：后加的便捷入口最容易漏校验。

### J01 · 多步写操作原子性

正确：先全量预检再统一动账，或 try/catch 整体回滚；

**扫描特征**：扣减与增加在相邻行且无 `try`。

### M02 · 判定依赖脏数值

正确：比较前先校验有限性；

**扫描特征**：`can*`/`has*` 返回 boolean，体内有数值比较但无 `isFinite`/`numOr`。

### R01 · 路径写入未过滤危险段

正确：解析后拒绝 `__proto__`/`prototype`/`constructor` 段，只在自有容器写入； 特征（两种写法都覆盖）：① `str.split('.')` ② 正则 `/([^.[\]]+)|\[(\d+)\]/g` ③ `parsePath` 类函数； **为什么**：不可信存档/网络差量可**改写进程级对象行为**。只扫 split 会漏掉正则实现。

### R03 · 路径协议不可逆

正确：JSON Pointer（RFC 6901）或带转义 token 数组；

**扫描特征**：路径解析 + patch 应用同时存在； 失效：`{'a.b':1}` 往返一次变成 `{'a.b':1, a:{b:2}}`，合法 JSON 键被静默改造成另一棵树。

### W01 · 交易/批量数量未校验有限正整数

正确： `Number.isInteger(n) && n > 0 && Number.isFinite(n)`；

**扫描特征**：`buy`/`sell`/`craft`/`pullN`/`roll`/`simulate`/`prewarm` 的数量参数无双重校验； 失效：购买 `-2` 件 → `total = -20` → **钱包凭空增加 20、库存增加 2**，日志却记为成功。 注意：`<= 0` 挡不住 NaN，且必须同时查整数性。

### X02 · 定时器无清理

正确：`schedule`↔`unschedule`、`setInterval`↔`clearInterval`、 `setTimeout`↔`clearTimeout`，**三套机制各自配对，不能互相替代**；

**扫描特征**：有注册无清理；确认：是否为全局单例（是 → 标"待确认：生命周期长于页面"）。

## 审查流程

每条三步：

1. **看上下文** —— 必须读命中行**上方 10~30 行注释**。
   这个库大量「看起来像 bug」的写法上方有长注释解释原因，
   **没读注释就报问题是最高频的误报来源**。
2. **问三个问题**：
   - 该值**可能**取到非法值吗？（配置/用户输入/前序运算 → 是；常量/枚举 → 否）
   - 取到非法值后**会报错吗**？（不报错 = 静默失效，严重度更高）
   - 能恢复吗？（不可逆 → 严重度更高）
3. **存疑写探针实测**，不靠推理下结论。

**常见降级**（命中即非真问题）：

| 情况 | 处理 |
|---|---|
| 字段为非数值型（布尔/字符串/枚举） | 忽略 |
| 参数只可能是常量或枚举 | 忽略 |
| 用的是 `clampNum` / `numOr`（内部 isNaN→fallback 有兜底） | 忽略 |
| 上游已夹紧 / 已收口 | 忽略 |
| 文档已明确标注为设计意图 | 降 P2 |
