## 每个文件都是自包含的

拿到文件即可开工，不需要回头查 skill。每个文件含：

1. **判据** —— 涉及模式的正确做法 / 扫描特征 / 如何确认
2. **已实测标注** —— 哪些模式已跑过复现（同类直接登记，别重复劳动）
3. **审查流程** —— 三步法 + 常见降级表
4. **待审清单** —— 带源码行号与代码片段
5. **回报格式** —— 统一模板，便于汇总

## 审查三步（每个文件里都有）

1. **看上下文** —— 必须读命中行**上方 10~30 行注释**。
   这个库大量「看起来像 bug」的写法上方有长注释解释原因。
   **没读注释就报问题是最高频的误报来源。**
2. **问三个问题** —— 可能取到非法值吗？会报错吗？能恢复吗？
3. **存疑就写探针实测**，不靠推理下结论。

## 降级规则（避免噪音）

| 情况 | 处理 |
|---|---|
| 字段为非数值型（布尔/字符串/枚举） | 忽略 |
| 参数只可能是常量或枚举 | 忽略 |
| 用的是 `clampNum` / `numOr`（内部 isNaN→fallback 有兜底） | 忽略 |
| 上游已夹紧 / 已收口 | 忽略 |
| 文档已明确标注为设计意图 | 降 P2 |

## 回报格式

在表格里填「判为」（`真问题` / `误报` / `存疑`）和「依据」，
再单独列真问题清单，最后一行汇总：

```
真问题 X 条 · 误报 Y 条 · 存疑 Z 条
```

真问题清单每条四项：现状 / 后果 / 建议 / 实测。
