## 判据（先读）

### A04 · 累加 / EMA

正确：脏样本**丢弃**（`if (!Number.isFinite(s)) return;`）， 不是兜底 0；特征：`this._x +=` / `lerp(this._x, ...)` 无 `isFinite`；

**如何确认**：是否参与后续所有帧（是 → 污染不可逆）。用兜底值会把「数据坏了」伪装成正常值。

### D02 · 参数未使用

正确：用起来或删除；

**扫描特征**：类方法 / 独立函数 / 箭头方法三种形态都检；

**如何确认**：是否为刻意保留的签名参数（接口一致性）→ 是则降级。

### P02 · Infinity 当哨兵

正确：空集用 `length === 0` 或 `null`；

**扫描特征**：`= -Infinity` / `=== Infinity` 等； **为什么**：±Infinity 是**合法数值**，当哨兵会把含合法极值的集合静默替换为 fallback。

### P03 · Math.max/min 当守卫

正确：`clampNum` 或先 `Number.isFinite`；

**扫描特征**：`Math.max(数字, 变量)`；失效矩阵： ``` Math.max(1, NaN) → NaN （守卫失效） Math.max(1, Infinity) → Infinity （当数组尺寸会崩） Math.max(1, -5) → 1 （只有这个符合预期） ```

### Q01 · TypedArray/大数组尺寸未收口

正确：有限正整数 + **总元素量上限**；

**扫描特征**：`new Array(x)` / `new Float32Array(x)`，x 非字面量且附近无 clamp； **为什么 P0**：错误不在 API 边界报出，而是传导到底层 `RangeError` 或瞬时 OOM， **诊断信息完全指向不了配置字段**。特别检查宽高相乘（两个都合法但乘积极大）。

### Q03 · 分桶不回收空桶

正确：删除元素后若 `bucket.size === 0` 同步删 Map key；

**扫描特征**：`new Map()` 分桶字段有 `.delete(` 但全文无 `.size === 0`； **为什么 P0**：开放世界持续移动会**长期积累空桶**，难以察觉的内存泄漏。

### R02 · 批量删除未降序

正确：同一父数组多个索引必须**按索引降序** splice；

**扫描特征**：循环内 `splice` 且上下文无 `sort`/`reverse`； 失效：`['a','b','c']` 删 [1] 与 [2]，先删 1 后原 [2] 移到 [1]，结果 `['a','c']` 而非 `['a']`。 **按路径深度排序不足以处理同层多删。**

### R04 · 复合 key 未编码

正确：长度前缀编码/转义，或结构化 tuple / 嵌套 Map；

**扫描特征**：`join('|')` 拼 key 或模板字符串 `${a},${b}`； 失效：`{a:'1,b=2'}` 与 `{a:'1', b:'2'}` 生成同一 key → 两个维度写入同一项，数值静默合并。

## 审查流程

每条三步：

1. **看上下文** —— 必须读命中行**上方 10~30 行注释**。
   这个库大量「看起来像 bug」的写法上方有长注释解释原因，
   **没读注释就报问题是最高频的误报来源**。
2. **问三个问题**：
   - 该值**可能**取到非法值吗？（配置/用户输入/前序运算 → 是；常量/枚举 → 否）
   - 取到非法值后**会报错吗**？（不报错 = 静默失效，严重度更高）
   - 能恢复吗？（不可逆 → 严重度更高）
3. **存疑写探针实测**，不靠推理下结论。

**常见降级**（命中即非真问题）：

| 情况 | 处理 |
|---|---|
| 字段为非数值型（布尔/字符串/枚举） | 忽略 |
| 参数只可能是常量或枚举 | 忽略 |
| 用的是 `clampNum` / `numOr`（内部 isNaN→fallback 有兜底） | 忽略 |
| 上游已夹紧 / 已收口 | 忽略 |
| 文档已明确标注为设计意图 | 降 P2 |
