## 判据（先读）

### A03 · clamp 前置校验

> ✅ **已实测确认**：`clamp(NaN ?? 1, 0, 4)` → `NaN`（期望 1）
> 同类条目按真问题登记，只需确认覆盖面是否完整。

正确：入参来自外部时先 `Number.isFinite`； **注意：`clampNum` / `numOr` 不算问题**——它们内部走 `numOr(v,NaN)`+`isNaN→fallback`，非有限值有兜底，不穿透；只有裸 `clamp` / `clamp01` 才是。

**扫描特征**：`clamp*(opts.x, ...)` 附近无 `isFinite`；确认：调用方有没有兜住。

### C01 · 外部键查表

**扫描特征**：`TABLE[k]` 或 `k in TABLE`；危险键：`toString` / `constructor` / `__proto__` / `valueOf` / `hasOwnProperty`。

### E01 · 监听器遍历

> ✅ **已实测确认**：订阅 A/B/C，A 在回调内退订 → 执行 A、C，B 被跳过
> 同类条目按真问题登记，只需确认覆盖面是否完整。

正确：`[...this._listeners].forEach(...)` 或倒序索引；

**扫描特征**：`_listeners`/`_handlers`/`_callbacks` + `.forEach`； **标准测法**：三个订阅者 A/B/C，A 在回调里退订，**执行序列必须包含 B**。

### S01 · 调试/作弊/后门默认启用

> ✅ **已实测确认**：`enabled ?? true`，未显式关闭时生产环境可用
> 同类条目按真问题登记，只需确认覆盖面是否完整。

正确：`enabled`/`debug`/`cheat`/`devMode` 默认 **false**， 宿主显式开启；生产构建应 hard fail 或剔除；

**扫描特征**：`enabled = true` / `enabled: true` / `enabled ?? true`； **为什么 P0**：生产构建漏配即可暴露作弊命令、经济/关卡修改能力。 把安全寄托于「调用方记得关」不可靠。

### T01 · while 做角度归一化

> ✅ **已实测确认**：`d = Infinity` 时 1001 次迭代仍不收敛 → 主线程挂死
> 同类条目按真问题登记，只需确认覆盖面是否完整。

正确：**常数时间取模**并先拒非有限值 ```typescript const norm = (a: number) => { const r = a % (Math.PI * 2); return r < 0 ? r + Math.PI * 2 : r; }; ```

**扫描特征**：`while` 体内 `- 360` / `- 2*Math.PI`（单语句与带大括号两种形态都检）； 失效：`diff` 为 `Infinity` 时减 360 后仍为 `Infinity` → **永不退出**。

## 审查流程

每条三步：

1. **看上下文** —— 必须读命中行**上方 10~30 行注释**。
   这个库大量「看起来像 bug」的写法上方有长注释解释原因，
   **没读注释就报问题是最高频的误报来源**。
2. **问三个问题**：
   - 该值**可能**取到非法值吗？（配置/用户输入/前序运算 → 是；常量/枚举 → 否）
   - 取到非法值后**会报错吗**？（不报错 = 静默失效，严重度更高）
   - 能恢复吗？（不可逆 → 严重度更高）
3. **存疑写探针实测**，不靠推理下结论。

**常见降级**（命中即非真问题）：

| 情况 | 处理 |
|---|---|
| 字段为非数值型（布尔/字符串/枚举） | 忽略 |
| 参数只可能是常量或枚举 | 忽略 |
| 用的是 `clampNum` / `numOr`（内部 isNaN→fallback 有兜底） | 忽略 |
| 上游已夹紧 / 已收口 | 忽略 |
| 文档已明确标注为设计意图 | 降 P2 |
