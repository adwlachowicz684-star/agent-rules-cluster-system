## 二、审查框架（每个单元必查 9 项）

| # | 维度 | 判据 | 典型症状 |
|---|---|---|---|
| 1 | **依赖合规** | 只 import `_core` / `ds` / 同目录 | 横向依赖破坏可拷贝性 |
| 2 | **参数校验** | 是否挡住 `NaN` / `Infinity` / 负数 | `x <= 0` 挡不住 NaN |
| 3 | **脏数据守卫** | 入口 / 出口是否拦截 NaN、Infinity | 血条消失、静默挂起 |
| 4 | **遍历安全** | 回调中增删集合是否用快照或倒序 | 订阅者被静默跳过 |
| 5 | **时间源** | 是否可注入 `now`，无硬编码 `Date.now` | 单测 flaky、无法回放 |
| 6 | **随机源** | 是否通过 `IRandomSource` 注入 | 破坏可复现 |
| 7 | **destroy 幂等** | 是否有 `_destroyed` 状态标记 | 销毁后复活 |
| 8 | **文档一致性** | README 的 API 签名 vs 源码实际签名 | 照文档写直接崩 |
| 9 | **单元特有逻辑** | 该领域的核心算法与边界 | 因单元而异 |

## 七、全局议题（跨单元）

### Q06 容器摘除未清内容（已沉淀为 skill 模式）

来源：`event-bus` E-01。与既有 Q03「空桶不回收」是**反向同类**：
Q03 删元素不删空桶，Q06 删桶不清内容。

- 后果：闭包（如 `on()` 返回的取消函数）仍持有容器 → 无法 GC；存续复查失效
- 排除条件：无闭包持有途径 → 误报；摘除时容器已空（同行 `.size === 0`）→ 误报
- 已加入 `ts-unit-audit` 扫描器（模式总数 61 → 62）

### Q04 归属校验检测补全（本轮）

历史 Q04 只检测 `prewarm` 上界与 `active` 下限，**归属校验这一半从未实现**。
本轮补全，判据从"有没有 `has()`"改为"**扣减是否无条件**"：

- 为什么不能按 `has()` 判：重复归还拦截也用 `has()`，但它查的是"是否已空闲"，
  方向与归属相反 → 实测会漏掉只有重复拦截的池（pool 正是这种情况）
- 新判据：`put()` 里 active 扣减若直接写在方法体（花括号深度 1）→ 无条件 → 报
- 实测：全库仅 `pool/Pool.ts:178` 命中，无误报
