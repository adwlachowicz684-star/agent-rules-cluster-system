# 严重度定级

## 三级定义

| 级别 | 定义 | 判据 |
|---|---|---|
| **P0** | 产生错误结果 / 崩溃 / 泄漏，且**静默**（不报错） | 必须修，阻断发布 |
| **P1** | 边界条件错误、契约不一致（注释说谎）、O(n²) 退化 | 应该修 |
| **P2** | 可读性、冗余、文档瑕疵 | 可选，视返工成本 |

## 附加标记

与 P0/P1/P2 并行使用，标注问题性质：

| 标记 | 含义 | 何时用 |
|---|---|---|
| **regression** | 修复 A 时引入 B | 修复复核场景；**一律按 P0 的下限处理**，回归比原缺陷更危险 |
| **praise** | 实现得当、值得保留 | 写进「验证过没问题的部分」，结构化标注 |
| **pre-existing** | 本次未改动但已存在的老问题 | 与新增问题分开计数，避免把存量算成增量 |

## 采纳的硬门槛（三件套缺一不可）

一条问题要成立，必须同时给出：

1. **行号** —— 精确到 `<文件>:<起止行>`
2. **证据** —— 实测输出，或可验证的推导链
3. **后果** —— 什么场景下暴露、表现为什么症状

**说不出后果的问题不成立** —— 通常意味着它不是真问题，或没想清楚。

## 5 条升级规则

满足任一即**定为 P0**，即使按定义原判 P1：

1. **安全 / 经济 / 权限链路的「放行」** —— 放行意味着白给钱、放过作弊、绕过权限
2. **主线程挂死** —— 循环上界不收敛、无限递归、角度归一化死循环
3. **不可逆的状态污染** —— 一次非法值永久失效，需重开才能恢复
4. **数据静默损坏** —— 原型污染、patch 索引失效、路径不可逆、存档写坏
5. **对外承诺完全失效** —— 声明的 API 永远返回错误值、参数完全无效

## 三个反问

### 1. 它会报错吗

**不报错的缺陷比报错的严重。** 抛异常至少能被发现、能捕获、有堆栈。
静默返回错误结果的问题往往在生产环境潜伏很久。

典型：伤害管线返回 NaN → 写进血量 → 血条消失，无异常、无日志。

### 2. 用户会不会遇到

- 正常路径必然遇到 → P0
- 特定配置/输入才遇到 → P0（若静默）或 P1
- 只有极端边界才遇到 → P1

注意「特定输入」的广度：配置缺字段（`undefined` 参与运算得 `NaN`）是**高频**的，
不是边缘情况。

### 3. 能恢复吗

- 重启模块能恢复 → 轻一档
- 必须重开游戏/清空存档 → 重一档

## 文档类问题的从严判据

| 情形 | 定级 | 理由 |
|---|---|---|
| 文档与实现不一致 | **默认 P1** | 写错的文档比没文档更糟 |
| **文档把缺陷记为设计意图** | **默认 P0** | 它会阻止下一个人修复 |
| 注释声称「只影响观感」但实际影响逻辑 | **P0** | 同上，且会误导随机源/时间源的正确注入 |

## 特殊情形

### 性能问题

- O(n²) 且 n 有上限（最多几十）→ P2
- O(n²) 且 n 可配置到 1e7 → P0（可被配置触发卡死）
- 每帧分配数组（如遍历快照）→ P2，除非在热路径

### 无 destroy 状态标记

通常 P2。但若对象销毁后仍被外部持有引用并继续使用，且这种使用**不报错**，升 P1。

### 并行实现的取舍

同一功能两套实现本身不是缺陷；但**没有分工说明**导致调用方无法选择，
或两套的缺陷修复不同步 → 定为全局议题（见 `global-consistency.md`）。

## 扫描候选的降级

模式扫描给出的是候选，确认后按实际影响定级。常见降级：

| 模式 | 降级条件 |
|---|---|
| D02 参数未使用 | 刻意保留的签名参数（接口一致性） → P2 或忽略 |
| A01 `<=0` 守卫 | 该参数实际不可能为 NaN（常量、枚举） → 忽略 |
| **A03 `clamp` 穿透** | **用的是 `clampNum` / `numOr` 而非裸 `clamp` → 忽略**（前者内部走 `numOr(v,NaN)`+`isNaN→fallback`，非有限值有兜底，不穿透） |
| O04 返回内部引用 | 文档已明确标注「返回内部引用，勿持有」 → P2 |
| A02 `??` 未收口 | 字段为非数值型 → 忽略 |
| N01 硬编码时间源 | 已有 `now?: () => number` 注入口 → 忽略 |
| R01 路径解析 | 路径不来自外部输入 → 忽略 |
| P04 slice/splice | 参数已在上游夹紧为非负 → 忽略 |

## 驳回清单（提高审查信噪比）

遇到以下情况不要报：

1. **证据不足** —— 只有推理没有实测。先写最小复现跑一遍
2. **这其实是设计意图** —— 大量「看起来像 bug」的写法都带长注释解释原因。
   **没读注释就报问题是最高频的误报来源**
3. **后果不成立** —— 理论上存在但触发路径不存在（内部私有方法、参数已在上游夹紧）
4. **重复劳动** —— 报了已审结的地基单元或已知全局问题
5. **超出范围** —— 本轮只审不改；「顺手重构」一律不做

## 定级输出格式

```markdown
| 等级 | 数量 |
|---|---|
| P0 | 2 |
| P1 | 4 |
| P2 | 3 |

### P0-1 · <一句话>
### P0-2 · <一句话>  [regression]
### P1-1 · <一句话>
### P2-1 · <一句话>     ← P2 可表格化，不必逐个展开
```

数量按**问题条目**统计；一个条目可能覆盖同一单元中的多个同源入口，
需在条目里说明影响面。
