兜底才是常态（110:2）。**细化流程应能映射回骨架六步，

### 三、组合模型（补进 skeleton.md 第八节）

跨域组合的真正难点不是顺序，是**接缝**：
「A 做完的产出，B 接不上，因为接口没约定」。
**排序排错不是返工主因，接缝才是。**

- 产物契约：产出物必须**能指到具体符号/文件/信号**，⛔ 不能是"做完了"
- 三种关系：**依赖**（拓扑排序）/ **接缝**（加接线流程）/ **共享**（⛔ 耦合不是复用）
- ⛔ 不要在流程内偷偷适配对方格式——适配会**散落多处，以后改接口时找不到**

## 2026-09-24 新增 FL-03「从零建设一个新 skill」+ 批量填充

引擎此前只有「往已有库加条目」（`FL-01`），**没有从零建 skill 的流程**。
两者判定完全不同：加条目不用判"该不该建"，建新 skill 必须先判。

### 最关键：第 0 问（两个方向都要防）

| 方向 | 后果 | 判据 |
|---|---|---|
| **查不到就建新的** | **skill 爆炸主因**——同一能力变两个包，之后每次命中命中的是不同的那个 | 先查：查不到 ≠ 没有（用原子词再查一次证明"查法对"） |
| **该建 skill 却拆成条目** | 能力散落在几十条里，**没人知道有这套能力**，检索命中率极低 | 这东西**单独拿出来能用吗**？能 → 它是 skill |

### 七步

定边界 → 定大类 → 定契约（骨架）→ 填内容 → **注册索引** →
**首次命中验证** → 留痕。

**第 5 步最易失效**：跳过后文件全在，但定向加载找不到——
静默失效，不报错，只有下次检索才发现"我明明建了"。

**第 6 步最易被省**：⚠ **检索命中 ≠ 照做能产出**。
只验证"能检索到"不验证"照做能产出"，等于建了个空壳。

### 批量填充专节（替换 Step 4）

手上有成批现成素材时，逐条写三件套不可行。四步：

    B1 盘点 → B2 定映射 → B3 灌入 → B4 抽条目

⚠ **B2 定映射必须在灌入之前**——先灌再分类要重新分，**比一开始就分好贵十倍**。
⚠ **B4 不能省**——成批文档不抽索引条目，**检索命中率极低**；

⛔ **素材是输入，不是结论**——与现有实现冲突时标冲突，**不静默覆盖**。

## 2026-09-24 补 FL-04 审核流程 + 退出码码表接入

### 一、FL-04「审核一个 skill」（结构缺口）

引擎此前有「从零建」（`FL-03`）与「闭环」（`FL-02`），
**但没有「怎么审一个 skill」的流程**。
闭环第 ② 步只写了"用审查册对照"，没展开成可执行步骤——
**有建设流程没审核流程，结构上是缺一半**。

七节 + 七步：摸清全貌 → 过驳回清单 → 逐区审查 →
查失效形态 → 分级 → 出清单 → 留痕。

**三张表设计**（关键）：

| 表 | 内容 |
|---|---|
| 表一 | 必须改（P0/P1） |
| 表二 | 可记 backlog（P2） |
| 表三 | **没判据的发现**（靠人肉发现的） |

⛔ **三张表不能合并** —— 合并到表一会**声称全部由判据覆盖**，
掩盖"哪些是靠人肉发现的"。

⛔ **本流程只读审查册，不读建设册** ——
读建设册会把"哪里不行"写成"建议改成 X 流程"，**丢掉位置和证据**。

### 二、退出码码表（反哺 code-audit AR-04）

**实测发现两个真失效**：

    ① lint.py --json 有 error 也返回 0
       → CI 用它解析 = 永远绿灯，gate 形同虚设
    ② 环境未初始化（domains/ 不存在）与「真有问题」都返回 1
       → 无法区分「先去 init」和「库里有违规」

码表：`scripts/exitcode.py`
0 成功 / 1 工具错 / 2 参数错 / 3 环境不满足 / 4 被拦下。

**关键区分：4 = 你的内容有问题（改它）；1 = 工具有问题（修它）。**
混了会让人去修工具，而该修的是内容。

### 三、`sys.exit("字符串")` 是反模式

domain.py 有 6 处 `sys.exit(f"...")` ——
Python 会把字符串打到 stderr 并返回**退出码恒为 1**。
所有失败路径无差别：找不到配置文件、配置写错、大类未注册 **都是 1**。

已改：找不到配置 → `die(ENV)`；配置错误/未注册大类 → `die(USAGE)`。
env.py：环境不满足从 1 改 **3**（`sys.exit(OK if ok else ENV)`）——
这是最贴合 ENV 语义的一处。

### 四、接入率守护（第七条）

新增 `check_exitcode_adoption`。

⚠ **两种不同的合法接入都要认**：
① 用 argparse（未知参数自动退出 2，与 USAGE 一致）
② 导入 exitcode（能进一步区分 ENV/BLOCKED）

⛔ 只认 ② 会把用 argparse 的脚本全部误报成「没接」——
**误报的检查会被关掉**（falsepos 第十四条）。

剩余 consolidate / index / structure / note 四个脚本
保持 info 级欠账（诚实可见），未虚假接入。

自检 39 → 42。变异验证：把 --json 改回"直接 return"
（原 bug）→ 41/1，**确认该用例真在查**。
