## 2026-09-24 反哺：从 game-dev 流程体系提炼通用流程规范

game-dev 那边的 Godot 流程体系是**实测过的规模**——11 个已细化域、
110 个域靠骨架兜底。剥离领域特化部分（Godot API、物理帧、存档加密），
提取任何流程都成立的骨架，落到 `flow/`：

| 新文件 | 内容 |
|---|---|
| `flow/step-spec.md` (132 行) | **Step 五字段**【读】【做】【产出】【判据】【审】+ 【判据】可观测 + 两级审核 + 七节模板 |
| `flow/skeleton.md` (142 行) | **骨架兜底**六步 + 「不做什么」至少两条 + 接缝清单 + 参数回填 + 锚点 ID 稳定 + 多对多全局层 |

**最值钱的两条**：
① **【产出】不能省** —— "做完了"这种产出无法被下游按名字对接，
   是返工的主要来源。判据：**下游只看产出声明就知道怎么接吗？**
② **【判据】必须可观测** —— "应该没问题""感觉对了"不算。
   **写不出判据的步骤 = 切分有问题**，要拆细或改成可测形式。

**骨架兜底**：⛔ 不允许"没有流程就凭记忆开工"。细化永远是少数、
兜底才是常态（110:2）。**细化流程应能映射回骨架六步，
映射不上的骨架步 = 该域的盲区**——要么补，要么显式说明"这是有意的"。

同时给 `flow/consolidation.md` 的整合八步补了【产出】/【判据】表
（这九步此前只有动作，没有产出与验收标准）。

### 三、组合模型（补进 skeleton.md 第八节）

跨域组合的真正难点不是顺序，是**接缝**：
「A 做完的产出，B 接不上，因为接口没约定」。
**排序排错不是返工主因，接缝才是。**

- 产物契约：产出物必须**能指到具体符号/文件/信号**，⛔ 不能是"做完了"
- 三种关系：**依赖**（拓扑排序）/ **接缝**（加接线流程）/ **共享**（⛔ 耦合不是复用）
- ⛔ 不要在流程内偷偷适配对方格式——适配会**散落多处，以后改接口时找不到**

### 二、退出码码表（反哺 code-audit AR-04）

**实测发现两个真失效**：

    ① lint.py --json 有 error 也返回 0
       → CI 用它解析 = 永远绿灯，gate 形同虚设
    ② 环境未初始化（domains/ 不存在）与「真有问题」都返回 1
       → 无法区分「先去 init」和「库里有违规」

码表：`scripts/exitcode.py`
0 成功 / 1 工具错 / 2 参数错 / 3 环境不满足 / 4 被拦下。

**关键区分：4 = 你的内容有问题（改它）；1 = 工具有问题（修它）。**
混了会让人去修工具，而该修的是内容。

### 三、`sys.exit("字符串")` 是反模式

domain.py 有 6 处 `sys.exit(f"...")` ——
Python 会把字符串打到 stderr 并返回**退出码恒为 1**。
所有失败路径无差别：找不到配置文件、配置写错、大类未注册 **都是 1**。

已改：找不到配置 → `die(ENV)`；配置错误/未注册大类 → `die(USAGE)`。
env.py：环境不满足从 1 改 **3**（`sys.exit(OK if ok else ENV)`）——
这是最贴合 ENV 语义的一处。
