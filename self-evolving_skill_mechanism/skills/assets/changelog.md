## 2026-09-24 反哺：从 game-dev 流程体系提炼通用流程规范

game-dev 那边的 Godot 流程体系是**实测过的规模**——11 个已细化域、
110 个域靠骨架兜底。剥离领域特化部分（Godot API、物理帧、存档加密），

**最值钱的两条**：
① **【产出】不能省** —— "做完了"这种产出无法被下游按名字对接，
   是返工的主要来源。判据：**下游只看产出声明就知道怎么接吗？**
② **【判据】必须可观测** —— "应该没问题""感觉对了"不算。
   **写不出判据的步骤 = 切分有问题**，要拆细或改成可测形式。

**骨架兜底**：⛔ 不允许"没有流程就凭记忆开工"。细化永远是少数、
兜底才是常态（110:2）。**细化流程应能映射回骨架六步，
映射不上的骨架步 = 该域的盲区**——要么补，要么显式说明"这是有意的"。

同时给 `flow/consolidation.md` 的整合八步补了【产出】/【判据】表

### 三、组合模型（补进 skeleton.md 第八节）

跨域组合的真正难点不是顺序，是**接缝**：
「A 做完的产出，B 接不上，因为接口没约定」。
**排序排错不是返工主因，接缝才是。**

- 产物契约：产出物必须**能指到具体符号/文件/信号**，⛔ 不能是"做完了"
- 三种关系：**依赖**（拓扑排序）/ **接缝**（加接线流程）/ **共享**（⛔ 耦合不是复用）
- ⛔ 不要在流程内偷偷适配对方格式——适配会**散落多处，以后改接口时找不到**

## 2026-09-24 新增 FL-03「从零建设一个新 skill」+ 批量填充

引擎此前只有「往已有库加条目」（`FL-01`），**没有从零建 skill 的流程**。
两者判定完全不同：加条目不用判"该不该建"，建新 skill 必须先判。

### 最关键：第 0 问（两个方向都要防）

| 方向 | 后果 | 判据 |
|---|---|---|
| **查不到就建新的** | **skill 爆炸主因**——同一能力变两个包，之后每次命中命中的是不同的那个 | 先查：查不到 ≠ 没有（用原子词再查一次证明"查法对"） |
| **该建 skill 却拆成条目** | 能力散落在几十条里，**没人知道有这套能力**，检索命中率极低 | 这东西**单独拿出来能用吗**？能 → 它是 skill |

### 七步

定边界 → 定大类 → 定契约（骨架）→ 填内容 → **注册索引** →
**首次命中验证** → 留痕。

**第 5 步最易失效**：跳过后文件全在，但定向加载找不到——
静默失效，不报错，只有下次检索才发现"我明明建了"。

**第 6 步最易被省**：⚠ **检索命中 ≠ 照做能产出**。
只验证"能检索到"不验证"照做能产出"，等于建了个空壳。

### 批量填充专节（替换 Step 4）

手上有成批现成素材时，逐条写三件套不可行。四步：

    B1 盘点 → B2 定映射 → B3 灌入 → B4 抽条目

⚠ **B2 定映射必须在灌入之前**——先灌再分类要重新分，**比一开始就分好贵十倍**。
⚠ **B4 不能省**——成批文档不抽索引条目，**检索命中率极低**；
   判据：只能命中到文件 = B4 没做。

⛔ **素材是输入，不是结论**——与现有实现冲突时标冲突，**不静默覆盖**。

### 修检查器判据：Step 按节点 ID 识别，不按标题含 Step

`### 批量四步（替换 Step 4）` 被当成真 Step → 报"缺五字段"。
它只是**提到** Step 4，不是 Step。

**节点 ID `[FL-xx#S1]` 才是稳定标识。**
这正是 falsepos 第十四条「判据看语义方向，不看表面特征」：
标题里有 Step 字样 ≠ 它是 Step。

变异验证通过（改回"含 Step 字样即识别"后 38/1）。自检 38 → 39。
