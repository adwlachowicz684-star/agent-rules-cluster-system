# 技能集群（Skill Evolution）

一个可持续增长的技能库。**只增不减**——不用的技能冷藏，不删除。
目标：任何复杂任务都能在库里找到对应流程。

## 核心原则

**只存技能，不存事实。** 判据：**换个项目还成立吗？** 不成立 → 项目事实，不入库。

**只写正确路径。** 不写"我犯过什么错"，只写"这类事该怎么做"。

**细节写全，按需加载。** 每个技能文件写完整流程，让陌生 AI 只看这一个文件就能干活；
平时不占上下文，靠索引定向调取。**写的时候不嫌多，读的时候不占地方。**

**操作一律命令化。** 能写成命令或脚本的，绝不用散文描述——省思考时间、省上下文、
保证每次执行一致。**技能里出现「先…然后…再…」就该抽命令了。**

**知识点必须落地到流程。** 只写「要注意 X」而不改变任何一步动作，是纯负债。
判据：**它改变了哪个流程的哪一步？** 答不出来 → 改写或删除
（`lint.py` 自动报孤立知识点）。详见 `howto/knowledge-landing.md`。

|---|---|---|---|

| **`common/`** (1) | 元规则、共用约定 | 「本文讲…」 | **不确定读哪个区时** |
| **`craft/`** (4) | 品位与技巧 | 「好的…应该…」 | 想做得更好时 |

**三种场景需要展开**：
- 不知道某句话该进哪个区 → `reference/common/split-two-books.md` 第二节
- 审核 / 加检查项 → `reference/audit/self-verification.md`（索引，按失效大类分三册）
- **走流程 / 新建流程** → `reference/flow/index.md`（FL-xx 登记表 + 新建四步）
- **从零建一个新 skill** → `reference/flow/new-skill.md`（`FL-03`，含批量填充）

> ⛔ `flow/` 里 `meta` 与 `procedure` 必须分开标记（否则举例被当真步骤 → 误报）。详见总纲 3.7。

> **为什么分五区**（判据与边界见总纲）：howto 管做完、audit 管不坏、
> **craft 管要好**——缺了 craft 只会停在「做完、没毛病」。

| `pending/draft.md` | 会话内草稿 | 出现捕获信号时追加一行 |

`<root>` = `config.yaml` 的 `root`（默认 `~/.ai/domains`）。
项目通过 junction 接入某大类，但 AI 可用绝对路径访问全局索引与所有大类。

## 两册闭环（自我迭代强化）

**建设册开发 → 审查册审查 → 调整 → 回看建设册 → 两册互补 → 回到建设。**

第 ④ 步「回看」最易跳过，三问（**逐条问**）：
① 流程不够详细？　② 内容有疏漏（缺那句「该怎么做」）？　③ 脚本不够严谨？

**审查册也自查**：报出的问题若**找不到对应判据** → 补一条。
**互补必须双向确认**：补一边要问另一边有没有对应项。
判据：**两册同步增长 = 健康；审查册涨而建设册不动 = 停滞**。
详见 `reference/flow/closed-loop.md`。

## 常驻行为

0. **定位大类**（任务开始时）— `python3 scripts/domain.py --detect`
1. **定向加载**（严格按序，各层性质不同）
   ```
   ① .ai-local/rules.md      项目特化，最高优先级
   ② <大类>/rules/*.md       领域硬约束，必读（20-30 行）
   ③ <大类>/INDEX.md         本类技能索引（~20 行，不读全局）
   ④ 命中 → 整包加载 skills/ 下该文件；未命中 → 查索引的「通用」分区
   ⑤ 有 agents/ 需求 → 加载角色定义
   ```
   **不读全局 INDEX.md** —— 它随技能数增长，只在跨类检索时用。
2. **捕获**（会话中）— 出现信号向 `pending/draft.md` 追加一行，不分析、不打断。
   **显式纠正只占少数**，用户重做 / 改输出 / 换说法重问是更常见的隐性信号
3. **整合**（会话结束）— 过闸 → 驳回清单 → 查重 → 判定归属 → 写入 → 重建索引。
   ⚠ 长会话捕获 ≥10 条时**分段整合**，别攒到最后丢细节。详见 `flow/consolidation.md`
4. **留痕**（改了就记）— `python3 scripts/note.py "<ID>" <类型> "<原因>"`
5. **改后重跑比对** — `lint.py` + `index.py --check`，确认没顺手引入新问题
6. **自检**（定期）— `lint.py`（体积/ID/字段/孤立知识点/死链/重复副本/标注退化）
   + `consolidate.py` 查重复；`--self-test` 验证检查项没失效。
   ⚠ **加检查项必须同步加坏样例**——永远绿的检查等于没有。
   另跑 `mutate.py` **回放历史缺陷**：自检全绿 ≠ 覆盖了真实修过的缺陷（第二十二条）。
   详见 `reference/audit/self-verification.md`

## 两个"装不下"的出口

**① 环境装不下** — `applies_to: python>=3.8, os:linux`，**两条都留**；
加载前 `env.py --check "约束"`。详见 `reference/howto/env.md`。
**② 类目装不下** — `--route-check` → `--propose-new` → `--apply`，
**AI 在提案这步停住**。详见 `reference/howto/structure-evolution.md`。

## 改了就记一行（assets/）

`note.py "<ID>" <类型> "<原因>" --src 实测` · `note.py --show`（**改旧规则前先查**）。
类型：新增 / 补充 / 修正 / 更新 / 参考 / 合并 / 拆分 / 冷藏

## 单文件体积上限

最要紧两条：**`rules/*.md` 50 行** · **`skills/*.md` 500 行**。
**超限但有理由** → 按需层写 `<!-- oversize-exempt: 理由 -->` 降为提示；
**常驻层不能豁免**，超限只能下沉。
`lint.py` 还会在 **80% 处提前预警**、章节 >12 时提示拆分——别等超限才拆
（那时已长到要重写目录）。
⚠ **那是加载成本上限，不是充实度判据**：判「模块够不够」看
`reference/craft/substance.md`（不看数量看质量）。
其余见 `reference/howto/writing-rules.md`。

## 归位与分层（四条速判）

| 环节 | 判据 | 详 |
|---|---|---|
| **第零道闸** | 是「怎么做」还是「是什么」？后者（路径/文件名/项目背景）→ 丢弃 | 下方专节 |
| **技能归属** | 命中 ≥2 个大类关键词 → 自动推荐；只命中泛词 → 必须问用户。⛔ 归错类比不归更糟 | `howto/domain-routing.md` |
| **冷热分层** | **不删除任何技能**，命中数只定加载优先级（热=必扫/冷=命中加载/冷藏=仅存索引）。⚠ 0 命中先分清真低频还是 keywords 太窄 | `howto/consolidation-place.md` |
| **`verified`** | `yes \| no \| partial`，只标注不校验；**整合报告必须分三类**，混一张表等于声称全验证 | `flow/consolidation.md` |

**捕获信号**：出现就往 `pending/draft.md` 追加一行。
**最易漏的一条**：用户重做 / 改你的输出 / 换说法重问 = 隐式负反馈。
完整判定表见 `howto/capture-signals.md`。

## 四道门槛 + 驳回清单 + 三件套

| | 内容 |
|---|---|
| **四道门槛**（正面） | 可迁移 · 已抽象 · 可执行 · 已验证。任一不过 → 丢弃 |
| **驳回清单**（负面） | 见审查册 `reference/audit/rejection.md`（6 条，含「先 `note.py --show` 溯源」） |
| **三件套** | 来源 · 证据 · 后果，缺一条就补，别默默入库 |

`consolidate.py` 自动扫驳回清单与三件套。
**说不出「不这么做会怎样」的，通常不是真技能。**
详细判据与「批量相似怎么抽样」见 `reference/howto/consolidation-gate.md`。

## 违反即升级

规则已写却仍被违反 → **不是记性问题，是规则设计问题**：不够显眼 / 不够具体 /
反直觉 / 放错层，依次检查。同一条目 ≥2 次 → 进下方最高优先级区。
