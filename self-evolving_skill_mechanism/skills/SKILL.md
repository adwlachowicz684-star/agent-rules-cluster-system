# 技能集群（Skill Evolution）

一个可持续增长的技能库。**只增不减**——不用的技能冷藏，不删除。
目标：任何复杂任务都能在库里找到对应流程。

## 核心原则

**只存技能，不存事实。** 判据：**换个项目还成立吗？** 不成立 → 项目事实，不入库。

**只写正确路径。** 不写"我犯过什么错"，只写"这类事该怎么做"。

**细节写全，按需加载。** 每个技能文件写完整流程，让陌生 AI 只看这一个文件就能干活；
平时不占上下文，靠索引定向调取。**写的时候不嫌多，读的时候不占地方。**

**操作一律命令化。** 能写成命令或脚本的，绝不用散文描述——省思考时间、省上下文、
保证每次执行一致。单行给命令，多行封 `scripts/` 只留一行调用。
**这条对生成的技能同样有效**：技能里出现「先…然后…再…」就该抽命令了。

## 目录地图

| 路径 | 内容 | 何时读 |
|---|---|---|
| **`<root>/<大类>/INDEX.md`** | **大类索引**（~20 行） | **任务开始读这个** |
| `<root>/INDEX.md` | 全局总索引 | 仅跨类检索时读 |
| `<root>/<大类>/rules/*.md` | 领域硬约束（20-30 行） | **每次必读** |
| `<root>/<大类>/agents/*.md` | 角色定义 | 涉及专业输出时 |
| `<root>/<大类>/skills/*.md` | 技能包 | 命中时整包加载 |
| `<root>/_common/skills/*.md` | 跨领域通用技能 | 本类没命中时 |
| `.ai-local/` | 项目特化覆盖层 | 项目内存在即读 |
| `SKILLS/_hot.md` | 跨领域高频铁律 | 每次任务前必扫 |
| `SKILLS/_preferences.md` | 用户稳定偏好 | 每次任务前必扫 |
| `SKILLS/_commands.md` | 通用命令 | 需要动手时 |
| `<root>/<大类>/assets/` | **变更溯源**（为什么改） | 改了技能后记录 |
| `config.yaml` | 大类根目录、体积上限 | 需要定位大类时 |
| `scripts/env.py` | 环境探测与约束检查 | 技能因版本/系统分化时 |
| `reference/layers.md` | rules/agents/skills 三层划分 | 不确定内容放哪层时 |
| `reference/versioning.md` | 版本分化（py/os 差异） | 相似条目该合并还是并存 |
| `reference/anti-patterns.md` | 反模式与官方规范 | 写完技能后对照检查 |
| `reference/structure-evolution.md` | 新建/调整结构 | **现有类目装不下时** |
| `reference/env.md` | 环境分化（版本/系统差异） | 同一技能有多个版本写法时 |
| `reference/domain-routing.md` | 大类路由协议 | 判定技能归属时 |
| `reference/loading.md` | 定向加载协议 | 不确定怎么加载时 |
| `reference/consolidation.md` | 整合协议 | 会话结束时 |
| `pending/draft.md` | 会话内草稿 | 出现捕获信号时追加一行 |

`<root>` = `config.yaml` 的 `root`（默认 `~/.ai/domains`）。
项目通过 junction 接入某大类，但 AI 可用绝对路径访问全局索引与所有大类。

## 常驻行为

0. **定位大类**（任务开始时）— `python3 scripts/domain.py --detect`
1. **定向加载**（严格按序，各层性质不同）
   ```
   ① .ai-local/rules.md      项目特化，最高优先级
   ② <大类>/rules/*.md       领域硬约束，必读（20-30 行）
   ③ <大类>/INDEX.md         本类技能索引（~20 行，不读全局）
   ④ 命中 → 整包加载 skills/ 下该文件；未命中 → 查索引的「通用」分区
   ⑤ 有 agents/ 需求 → 加载角色定义
   ```
   **不读全局 INDEX.md** —— 它随技能数增长，只在跨类检索时用。
2. **捕获**（会话中）— 出现信号向 `pending/draft.md` 追加一行，不分析、不打断。
   **显式纠正只占少数**，用户重做 / 改输出 / 换说法重问是更常见的隐性信号
3. **整合**（会话结束）— 过闸、查重、**判定归属大类**、写入、重建索引
4. **留痕**（改了就记）— `python3 scripts/note.py "<ID>" <类型> "<原因>"`
5. **自检**（定期）— `python3 scripts/lint.py`（体积 / ID / 字段）

## 两个"装不下"的出口

**① 环境装不下**（同一技能在不同环境写法不同）— 用 `applies_to` 标注，
**两条都留**，不删旧版本写法：
```yaml
applies_to: python>=3.8, os:linux
```
加载前 `python3 scripts/env.py --check "python>=3.8, os:linux"`。详见 `reference/env.md`。

**② 类目装不下**（现有大类都归不精准）— **提提案，不自行改结构**：
```bash
python3 scripts/structure.py --route-check "<描述>"          # 是否装得下
python3 scripts/structure.py --propose-new 名 --key k --kw "词,词"   # 只生成提案
python3 scripts/structure.py --apply                         # 用户确认后执行
```
| 判定 | 动作 |
|---|---|
| `ok` / `core_hit` | 直接归位 |
| `weak_match` | 确认后归，或考虑新建 |
| `ambiguous` | 提议中间大类 |
| `no_match` | **提议新建大类** |

**硬约束：AI 在提案这步停住** —— 结构变更影响所有后续归类，
误操作代价远高于多问一次。详见 `reference/structure-evolution.md`。

## 改了就记一行（assets/）

技能条目攒多了，半年后看到一条规则没人记得它怎么来的。
**改了就往 `assets/changelog.md` 记一行**，只写一句：

```bash
python3 scripts/note.py "LAW-R003" 补充 "合同审查漏了违约金条款" --domain legal
python3 scripts/note.py "C047" 更新 "macOS sed 需空参数" --src 实测
python3 scripts/note.py --show                    查看记录
```

类型：新增 / 补充 / 修正 / 更新 / 参考 / 合并 / 拆分 / 冷藏

## 单文件体积上限

超过就该拆（`python3 scripts/lint.py` 预警，不硬报错）：

| 文件 | 上限 | 超了 |
|---|---|---|
| `rules/*.md` | **50 行** | 混进流程了 → 移到 `skills/` |
| `agents/*.md` | 100 行 | 按场景拆角色 |
| `SKILL.md` | 200 行 | 细节下沉 `reference/` |
| `assets/*.md` | 300 行 | 按年/季度归档 |
| `reference/*.md` | 400 行 | 按主题拆 |
| `skills/*.md` | 500 行 | 按子任务拆包，`related` 互链 |

**`rules/` 的 50 行最要紧**——它每次任务都要读，
混进流程会让「必读」变成「读不完」，等于没有约束。

## `verified` 字段：只标注，不校验

```yaml
verified: yes | no | partial
```

**只作参考，不做任何自动校验**：标 `no` 不会拒绝加载，标 `yes` 也不免检。
用途是回溯时知道该信几分——标 `no` 的出错优先怀疑它，标 `yes` 的出错检查环境是否变了。

## 技能归属（写入哪个大类）

四问，从强信号到弱信号：

1. **换个大类还成立吗？** 成立 → `_common`
2. **当前项目接入哪个大类？** ← 最强信号，默认归属
3. **`--route` 关键词命中哪个？** `python3 scripts/domain.py --route "<描述>"`
4. **是领域技能还是领域知识？** 知识（法条/API 参数）→ 进 `rules/` 不进 `skills/`

**推荐 ≠ 自动写入**：归错类比不归更糟，必须确认。
完整协议见 `reference/domain-routing.md`。

## 捕获信号（简表）

| 信号 | 归位 |
|---|---|
| 自我修正（"不对/重来/实际上"）、重试 ≥2 次 | 领域包 或 `_hot.md` |
| 用户纠正、重新表述需求 | 领域包 + `_preferences.md` |
| 走弯路后找到更短路径 | 领域包「流程」段 |
| 思路想通了 | 领域包「判断依据」段 |
| 写出通用代码/命令 | `_commands.md`（多行逻辑封成脚本） |
| 散文描述的操作步骤 | **抽成命令**，不留「先…然后…再…」 |
| 用户第 2 次表达同一偏好 | `_preferences.md` |
| **用户重做 / 改你的输出 / 换说法重问** | **隐式负反馈**，最易漏 |
| 已写规则本次仍违反 | **不新增**，走「违反即升级」 |

完整判定见 `reference/capture-signals.md`。

## 第零道闸 + 四道门槛

**第零道闸**：描述的是"怎么做"还是"是什么"？是"是什么"（路径/文件名/项目背景）→ 直接丢弃。

**四道门槛**：**可迁移**（换个项目还成立吗）· **已抽象**（模式还是个案）· **可执行**（能照着做）· **已验证**（真跑通过）。任一不过 → 丢弃。

## 冷热分层（替代删除）

**不删除任何技能。** 命中数只决定**加载优先级**，不决定存亡。

| 层 | 判据 | 加载方式 |
|---|---|---|
| 🔥 热 | 命中高 / 跨领域通用 | 任务前必扫 |
| ❄️ 冷 | 有命中但低频，或新入库 | 索引命中时加载 |
| 🧊 冷藏 | 长期 0 命中 | 仅存索引，命中即回热 |

**冷藏不是删除**：文件原样保留，索引里仍有它，下次检索到自动回热。

## 违反即升级

规则已写却仍被违反 → **不是记性问题，是规则设计问题**。依次检查：
不够显眼（上浮热区）· 不够具体（改写成可执行判据）· 反直觉（加 ⚠）· 放错层。

同一条目被违反 ≥2 次 → 进下方最高优先级区。
