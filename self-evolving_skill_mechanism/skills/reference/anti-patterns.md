# 反模式与最佳实践

> 来源：Anthropic 官方 Skill 编写规范 + 社区实践。
> 这是**质量红线**：写完技能后逐条对照，命中任一条就要改。

## 一、目录与组织

| ❌ 反模式 | 后果 | ✅ 正确 |
|---|---|---|
| 所有细节堆在 SKILL.md | 抓不住重点 | 主文件作目录，细节拆到 `reference/` |
| SKILL.md 正文 > 500 行 | 加载慢、注意力稀释 | 拆分为独立文件 |
| 文件引用嵌套过深（A→B→C） | AI 迷路、读不到底 | **引用只深一层** |
| 用 `docs/file1.md` 这种命名 | 无法按内容定位 | 按领域命名 `reference/finance.md` |
| Windows 风格路径 `configs\deploy.yaml` | Linux 报错 | 一律正斜杠 |

## 二、描述与触发（最关键）

**description 决定 AI 会不会选中这个技能。** 规则：

- **第三人称**："处理 Excel 文件并生成报表"，不是"我能帮你处理 Excel"
- **同时包含「做什么」和「何时用」**
- **写进触发词**：用户可能说的同义词要出现

```yaml
# ✅
description: 分析 Excel 表格、创建透视表、生成图表。当用户提到 Excel、电子表格、表格数据或 .xlsx 文件时使用。
# ❌
description: 帮助处理文档
```

## 三、步骤精确性（最容易犯）

**每个步骤必须精确到可判定**，不能给 AI 自由发挥空间。

| ❌ 模糊 | ✅ 精确 |
|---|---|
| 检查 prId 是否有效 | 检查 prId 是否为 6 位字符串 |
| 注意格式 | 表格列宽对齐，二级标题下空一行 |
| 认真检查依赖 | 逐项确认：路径存在 / 编码 utf-8 / 依赖已装 |
| 适当处理异常 | 文件不存在时提示用户并给出创建命令 |

**判据**：一个不熟悉该领域的 AI 照着做，能明确知道"这一步做没做对"吗？

## 四、执行意图：Run 还是 See

脚本引用必须说清是**执行**还是**参考阅读**，否则 AI 可能去读一个本该运行的脚本。

```
✅ 运行 analyze_form.py 提取表单字段        （执行）
✅ 提取算法参见 analyze_form.py             （参考）
❌ 使用 analyze_form.py                     （意图不明）
```

## 五、依赖与前置（我之前的盲点）

**绝不假设工具已安装。**

```markdown
# ❌
用 pdf 库处理文件

# ✅
前置依赖：pip install pypdf
from pypdf import PdfReader
```

每个技能包开头写明：
- 需要哪些工具/包（含安装命令）
- 环境要求（Python 版本、OS、外部服务）
- **不满足时怎么办**（降级方案或明确报错）

## 六、失败策略（我漏掉的一整段）

**没有失败分支的技能，AI 出错后会自由发挥。**

每个流程都要有：
- 每步的失败判据（怎么知道这步失败了）
- 失败后的动作（重试 / 降级 / 中止并询问）
- 不可自动恢复时如何向用户报告

## 七、时效性信息

| ❌ | ✅ |
|---|---|
| "2025年8月前用旧 API，之后用新 API" | 旧写法放 `deprecated/`，注明"不再推荐" |
| 把版本号硬编码进流程 | 版本差异用 `applies_to` 标注，两条并存 |

**版本差异 ≠ 错误**（见 `versioning.md`）。
不要把"Python 3.8 用 A、3.12 用 B"当成冲突删掉一条。

## 八、其他

| ❌ | 后果 | ✅ |
|---|---|---|
| 提供过多选择（可用 PG/MySQL/SQLite…） | 决策成本高、易跑偏 | 给默认值："默认 PG，仅兼容需求时用 MySQL" |
| 术语不一致（Endpoint/API URL 混用） | 理解成本 | 全文统一术语，必要时加术语表 |
| 无验证步骤 | 静默失败 | 关键操作后必须校验 |
| 抽象示例 | 无法照做 | 示例要具体，能直接跑 |

## 九、测试要求

官方建议每个技能：

- **至少 3 个评估场景**
- 用**不同能力的模型**测过（弱模型也能读懂 = 写清楚了）
- 用**真实场景**测，不是玩具例子

**自检**：把技能丢给一个"没参与过这个项目"的 AI，它能独立完成吗？

## 十、与 Memory 的边界（重要）

| | Skill（本库） | Memory |
|---|---|---|
| 存什么 | **怎么做**（程序性知识） | **是什么**（声明式知识） |
| 加载 | 按需 | 始终在线 |
| 容量 | 无上限 | 严格受限（约 2200 字符） |
| 谁维护 | 用户创建 + AI 沉淀 | AI 自主管理 |

**把 Memory 的内容写进 Skill 是错的**：
"用户叫张三、项目用 React" → 这不是技能，是事实，不该进技能库。

这正好对应本库的第一原则：**只存技能，不存事实**。
