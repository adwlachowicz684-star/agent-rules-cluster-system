# 定向加载协议

> 解决的问题：技能库会越来越庞大，**全部读进上下文不现实也没必要**。
> 目标：每次任务只加载用得上的那一两个包，其余零开销。

## 三层加载结构

| 层 | 内容 | 加载时机 | 成本 |
|---|---|---|---|
| **L0 路由** | `SKILL.md` | 始终 | ~80 行 |
| **L1 覆盖** | `.ai-local/rules.md` | 存在即读 | ~15 行 |
| **L2 约束** | `<大类>/rules/*.md` | **每次必读** | 20-30 行 |
| **L3 索引** | `<大类>/INDEX.md` | 每次（不读全局） | ~20 行 |
| **L4 技能** | `skills/*.md` | 命中时整包 | 单包 100-200 行 |
| **L5 角色** | `agents/*.md` | 涉及专业输出 | ~30 行 |

**常驻合计 ≈ 150 行，且与技能总数无关。**

**平时上下文占用 = L0 + L1 ≈ 110 行。**
领域包再写得多也不占地方——这正是"内容写全"与"不占上下文"能同时成立的原因。

## 加载流程

```
任务开始
   │
   ├─ 0. python3 scripts/domain.py --detect
   │     得知当前大类 + 本地覆盖层是否存在
   │
   ├─ 1. 读 .ai-local/rules.md        项目特化，最高优先级（不存在则跳过）
   │
   ├─ 2. 读 <大类>/rules/*.md          领域硬约束，必读
   │     例：法律 → "法条精确到条/款/项""不做确定性胜诉判断"
   │
   ├─ 3. 读 <大类>/INDEX.md            本类技能索引（~20 行）
   │     ① 查「本类技能」分区
   │     ② 没命中 → 查「通用技能」分区（来自 _common）
   │     ③ 都没有 → 不加载，直接开工
   │     ※ 不读全局 INDEX.md（它随技能数增长，仅跨类检索时用）
   │
   ├─ 4. 命中 → 整包加载 skills/ 下该文件
   │     需要领域参数时，回读 rules/ 中的字段定义（三层覆盖）
   │
   ├─ 5. 涉及专业输出 → 加载 agents/ 角色定义
   │
   └─ 6. 用到某技能 → python3 scripts/index.py --find <关键词>
         计数 +1；冷藏项自动回热
```

**为什么第二步读 rules 而不是 skills**：rules 是"每次都要遵守但只有两行"的约束，
skills 是"用得上才看但很长"的流程。把领域约束常驻，
能避免每个技能包里都重复写一遍同样的限制。

## 关键词匹配的实操要点

**用户说法 ≠ 你的命名。** 在 `keywords` 里把同义词写全：

```yaml
keywords: [交付, 打包, zip, 压缩, 多文件, 产物, 附件, 下载]
```

用户说"帮我压缩一下"也要能召回到「文件产出与交付」。

**匹配失败时的处理**：不是直接放弃，而是：

1. 换更泛的词再试一次（`zip` → `文件`）
2. **确认检索真的跑了** —— `--find` 返回空有两种可能：库里没有，
   或一个包都没扫到（domains 未实例化 / root 指错）。后者会让你误以为"没这技能"。
   用 `python3 scripts/index.py --check` 区分：扫到 0 个包会明确告警，而不是报"一致"
3. 仍无 → 确认库里真没有 → 正常开工，会话结束把新流程入库

## 整包加载 vs 片段加载

**默认整包加载**——但包大到一定规模后要分级，否则「加载了但读不深」。

| 包体积 | 策略 | 理由 |
|---|---|---|
| **< 200 行** | **整包加载**（默认） | 八段结构自洽，拆开读会丢上下文 |
| **≥ 200 行** | **段落级加载 + 自动附带**（见下） | 整包塞进上下文，等于每节都没读透 |
| 首次接触该领域 | **整包读一遍**，之后按段 | 先建立心智模型，否则不知道该取哪段 |

**为什么 200 行是分界**：经验值是「一次能真正读进去」的上限。
超过之后整包加载的边际收益转负——占着上下文，却没有一段被认真用上。

### 段落级加载：只取片段会丢上下文

八段结构自洽，意味着**拆开取必须把关联段落一起带上**。
只取「完整流程」而不带「已知坑」，结果是：照着流程做，却不知道那一步有坑。

自动附带三类（不用手工拼）：

| 类型 | 何时带 | 为什么必须带 |
|---|---|---|
| **「已知坑」段** | **总是带** | ⚠ 是对流程各步的补充，省了必踩 |
| 引用了目标段的段落 | 引用匹配 | 「变体」常引用「适用场景」，拆开就是断的 |
| 「前置依赖」段 | 首次接触该包时 | 不知道要装什么，流程第一步就卡住 |

### 边界：什么时候不该省

细粒度加载不是万能的。两种情况下**别省**：

1. **首次接触某领域** —— 还没建立心智模型时，
   八段结构整体比任何单段都重要，先整包读一遍
2. **确认候选/做决策时** —— 需要交叉对照多个段落才能判断，
   只读命中那一段会误判

**判据**：你是不是已经知道「该取哪一段」？
答得出来 → 段落级。答不出来（因为还没读过这个包）→ 整包读。

## 计数与回热

**用到就计数**，这是唯一维护成本的时刻：

```bash
python3 scripts/index.py --find 打包
```

一条命令同时完成三件事：检索 + 命中 +1 + 冷藏回热。不用手动改数字。

**为什么计数重要**：命中数决定分层建议（`--stats`），
分层决定下次加载优先级。不计数 → 分层失准 → 热区里堆着没用的东西。

## 与「定向加载机制」的接口预留

用户计划自建定向加载机制。本库为此预留的标准接口：

| 接口 | 位置 | 用途 |
|---|---|---|
| frontmatter 元数据 | 每个 `domains/*.md` 头部 | 提供 id / keywords / trigger / tier / hits |
| `INDEX.md` | 根目录 | 一行一技能的总表，可直接解析 |
| `--find` 检索 | `scripts/index.py` | 关键词检索 + 计数 + 回热 |
| `--stats` 分层建议 | `scripts/index.py` | 输出分层调整建议 |

自建机制只需按 frontmatter 解析即可接入，不需要改动文件结构。

## 反模式

| ❌ 不要 | 原因 | ✅ 应该 |
|---|---|---|
| 把所有包都读进来 | 失去分层意义 | 只加载命中的 |
| 只读「完整流程」段 | 会踩「已知坑」里写着的坑 | 整包读，或带「已知坑」一起取 |
| 关键词写 2 个 | 用户换个说法就召不回 | 写全同义词 |
| 忘了计数 | 分层失准 | 用到就 `--find` |
| 为省事把领域规则塞进 `_hot.md` | 热区膨胀，拖慢每次任务 | 领域专属进 domains/ |
| `--find` 空就认定"库里没有" | 可能是压根没扫到包 | 先 `index.py --check` 确认扫到几个 |
| 大包（≥200 行）也整包塞 | 占上下文却没一段读透 | 段落级 + 自动附带关联段 |

## 大类环境下的加载

项目只 junction 到**一个**大类，但视野不限于此：

| 范围 | 访问方式 |
|---|---|
| 当前大类的技能 | 项目内 `<link_name>/skills/` 或绝对路径 |
| 通用技能 | 项目内 `<link_name>/_common/skills/`（大类内的链接） |
| 全局索引 | 绝对路径 `<root>/INDEX.md` |
| 其他大类 | 绝对路径 `<root>/<其他大类>/skills/` |

**junction 限制的是项目视图，不是 AI 的视野。**
需要跨类技能时直接用绝对路径读，不必切换链接。

完整协议见 `reference/domain-routing.md`。

## 三层覆盖：通用技能如何适配领域差异

通用技能（如"结构化输出"）在不同大类需要不同字段。做法：

1. 通用包里**不写死字段**，只写"按 `rules/` 中的定义填充字段"
2. 领域 `rules/_domain.md` 里定义具体字段（几行）
3. 加载通用技能时，同时读领域 rules 拼装

这样通用技能一个字不改，领域差异只需几行。
详见 `reference/layers.md`。

## 项目级覆盖层 `.ai-local/`

```
项目/
├── .ai          → junction（共享，改了影响同大类所有项目）
└── .ai-local/   → 真实目录（独有，最高优先级）
    ├── rules.md
    └── skills/
```

**晋升判据**：`.ai-local/` 的内容被**第二个项目**也需要时 →
用 `--route` 判定，跨领域通用则晋升到 `_common`，否则晋升到该大类。
