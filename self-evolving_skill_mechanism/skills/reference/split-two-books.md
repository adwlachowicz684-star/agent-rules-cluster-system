# 两册分工：建设册写「怎么做」，审查册写「不能怎么做」

> 这是整个技能库的**元结构**。不确定一份内容该放哪、该读哪，先看这一篇。

---

## 一、为什么必须分开

一句话：**建设时想着「别犯错」，会让你写得又短又空；
审查时想着「怎么做」，会让你把问题改写成建议。**

两件事的目标函数相反：

| | 建设（写技能） | 审查（审技能） |
|---|---|---|
| 要产出 | 一个能照着做的流程 | 一份「哪里不行」的清单 |
| 注意力 | 这件事**该怎么做** | 这份东西**在哪会失效** |
| 失败形态 | 写得含糊、不可执行 | 报得笼统、没有位置/证据/后果 |
| 读错册的代价 | **缩手缩脚**，写出来的全是免责声明 | **下手改坏**，把有理由的设计当缺陷改掉 |

实测的代价：

- **建设时读审查册** → 满脑子"这样会不会被驳回"，结果写出的技能
  通篇是「注意…」「不要…」，而**没有任何可执行步骤**。
  这正是 `knowledge-landing.md` 批判的"正确的废话"——
  它只是换了个方向产生。
- **审查时读建设册** → 看到的是"这个流程应该这样走"，
  于是把「这里不符合流程」写成「建议改成 X 流程」，
  **丢掉了位置和证据**，变成一条无法执行的优化建议。

## 二、判据：一句话该进哪册

> **换个项目还成立吗？** —— 这是决定是否入库的判据（两册通用）。
> 决定进哪册的是另一句：

**这句话是在描述「要做什么」，还是在描述「什么情况下它不成立」？**

| 表述 | 归属 |
|---|---|
| 「整合时先查溯源再改」 | 建设册 |
| 「没查溯源就改旧规则，是最高频的误改来源」 | **审查册** |
| 「判据要写位置 + 证据 + 后果」 | 建设册 |
| 「只会说『应该』『可能』的不成立」 | **审查册** |
| 「版本分化用 `applies_to` 标注且两条都留」 | 建设册 |
| 「检查长期红灯等于检查已经死了」 | **审查册** |

**同一件事在两册各有一句，不是重复。**
例：「必须先查溯源」是建设册的动作；
「没查溯源是最高频误改来源」是审查册的判据。
前者告诉你做什么，后者告诉你不做的代价——**后者才是让人真的去做的理由**。

## 三、两册的边界（易混的三种）

### 3.1 「排除条件」属于审查册，不属于建设册

建设册写「命中什么」，审查册写「什么情况下不算」。

最常见的错误是把排除条件写进建设册的判据里，
于是**建设时要同时想"命中"和"不命中"**，判据越写越长、越写越不敢用。

正确做法：建设册只给主路径；排除条件由审查册逐条列。
（`self-verification.md` 第十四条专门讲这条。）

### 3.2 「为什么」两句都要，但落点不同

- 建设册的「为什么」= **不这么做的后果**（用来判断要不要照做）
- 审查册的「为什么」= **这个失效形态是怎么发生的**（用来判断是不是这条）

前者面向执行者，后者面向排查者。

### 3.3 驳回清单属于审查册

`rejection.md`（原在 `consolidation.md` 内）明写"什么不该入库"——
它是审查册，已从建设册拆出。
整合流程里遇到该驳回的条目，**跳转过去对照，不要把清单抄回流程里**。

## 四、目录

两册不是各写各的——**建设 → 审查 → 回看 → 互补**的闭环见
`closed-loop.md`。本节只列归属。

### 建设册（怎么做 → 写/改/生成技能时读）

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| `closed-loop.md` | **闭环迭代协议**（建设→审查→回看→互补） | 审查之后 / 两册补充时 |
| `knowledge-landing.md` | 知识点落地协议（不写正确的废话） | 写/改技能时 |
| `writing-rules.md` | 规则怎么写 | 写单条规则时 |
| `layers.md` | rules/agents/skills 三层划分 | 不确定内容放哪层时 |
| `loading.md` | 定向加载协议 | 不确定怎么加载时 |
| `domain-routing.md` | 大类路由协议 | 判定技能归属时 |
| `consolidation.md` | 整合协议（八步 + 三件套 + 三类清单） | 会话结束时 |
| `capture-signals.md` | 捕获信号与写入位置 | 会话中捕获时 |
| `structure-evolution.md` | 新建/调整结构 | 现有类目装不下时 |
| `versioning.md` / `env.md` | 版本 / 环境分化 | 同一技能有多个版本写法时 |
| `global-rule.md` | 可粘进系统提示词的全局片段 | 要让定向加载成为默认行为时 |

### 审查册（不能怎么做 → 审核既有技能 / 提优化建议时读）

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| `self-verification.md` | **自检协议**（检查会不会其实没在查） | 加检查项 / 工具报「通过」时 / 加豁免后 / 命中数突降为 0 / **检查长期失败时** / 拼接生成内容后 |
| `rejection.md` | **驳回清单**（什么不该入库） | 判断某条目该不该留时 |
| `anti-patterns.md` | 反模式与官方规范 | 写完技能后对照检查 |
