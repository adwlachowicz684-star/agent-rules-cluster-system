# 三层目录协议：rules / agents / skills

> 你的大类文件夹给了三个目录，它们的性质完全不同，混用会让每个技能包
> 都塞满重复的领域约束。这里是划分标准。

## 一句话区别

| 目录 | 是什么 | 类比 |
|---|---|---|
| `rules/` | 领域**硬约束**——不能做什么、必须做什么 | 交通法规 |
| `agents/` | 领域**角色**——在这个领域里是谁、什么语气 | 职业身份 |
| `skills/` | 领域**能力**——怎么干活的具体流程 | 操作手册 |

## 划分判据（拿不准时用）

```
这条内容每次任务都要遵守吗？
├─ 是 → rules/（且应该只有几行；超过 30 行说明混进了流程）
└─ 否 → 它描述的是"我是谁"还是"我怎么干"？
       ├─ 我是谁（身份/语气/判断倾向）→ agents/
       └─ 我怎么干（步骤/流程/命令）  → skills/
```

**最容易搞混的一对**：

| 内容 | 去哪 | 为什么 |
|---|---|---|
| "引用法条必须精确到条/款/项" | `rules/` | 每个法律任务都要遵守，一句话 |
| "合同审查的六步流程" | `skills/` | 只有审查合同才用，很长 |

判据：**rules 是"每次都要看但只有两行"，skills 是"用得上看但很长"。**

## 各层规范

### `rules/` — 领域硬约束

- **加载方式**：每次任务前必读（与技能数无关，永远只有 20-30 行）
- **命名**：`_domain.md` 为主文件，可拆分 `_common.md`（跨领域通用）
- **内容**：输出约束 · 禁止事项 · 必须确认的事项 · 术语口径表
- **红线**：不写流程、不写步骤、不写"如何做"

```markdown
# 法律 — 领域规则

## 输出约束
- 引用法条精确到条/款/项
- 金额标注币种与口径

## 禁止事项
- 不给确定性胜诉判断，用"可能性评估"
```

### `agents/` — 角色定义

- **加载方式**：涉及该领域专业输出时加载
- **命名**：`_role.md` 通用角色，或按场景拆 `reviewer.md` / `drafter.md`
- **内容**：身份 · 语气风格 · 判断倾向 · 边界（何时该问而非自行判断）

**边界段最有用**：写清"遇到什么情况应提示用户而不是自行判断"，
比写一堆语气描述更能改变行为。

### `skills/` — 能力包

- **加载方式**：按索引命中后**整包加载**
- **结构**：八段式（适用场景 / 完整流程 / 判断依据 / 已知坑 / 变体 / 片段 / 变更）
- **无长度上限**：细节写全，靠分层解决占用

## 三层覆盖：通用流程 + 领域差异

**问题**：「结构化输出」是通用技能，但法律的字段是「案由/当事人/法条引用」，
教育是「知识点/学情/作业」。复制两份会不同步，写一份会四不像。

**解法：参数化。** 通用包写流程，领域 `rules/` 提供字段定义。

```
_common/skills/structured-output.md    ← 流程骨架
  步骤 2「按领域规则定义填充字段」
        ↑ 运行时读取
法律/rules/_domain.md                   ← 字段定义（4 行）
  案由 / 当事人 / 引用法条 / 结论
```

通用包里**不写死字段**，只写"填充 `rules/` 中定义的字段"。
这样领域差异只要几行，通用技能一个字都不用改。

**写法约定**：通用技能里需要领域参数的地方，明确标注
`← 见 <大类>/rules/_domain.md 的「字段定义」`，让加载者知道去哪取。

## 优先级（冲突时以谁为准）

```
项目 .ai-local/rules.md      ← 最高（项目特化）
      ↓
大类 rules/*.md              ← 领域硬约束
      ↓
_common/rules/_common.md     ← 通用铁律
      ↓
SKILLS/_hot.md               ← 引擎自带热区
```

上层覆盖下层，同层后者不覆盖前者（全部叠加生效）。

## 项目级覆盖层 `.ai-local/`

**为什么需要**：同一个大类下的两个项目，需求不可能完全一样。

```
项目A/
├── .ai → junction → <root>/法律        共享的，改了影响所有法律项目
└── .ai-local/                          真实目录，本项目独有
    ├── rules.md                        项目特化规则（最高优先级）
    └── skills/                         项目专属技能
```

**关键**：`.ai` 是链接（共享），`.ai-local` 是真实目录（独有）。
项目删掉不影响大类，大类更新不影响项目定制。

**什么时候该晋升**：`.ai-local/` 里的东西被**第二个项目**也需要时，
就该提炼成通用技能晋升到大类或 `_common`。
判据：`--route` 判定为跨领域通用 → 晋升。

## 二级索引：为什么每个大类要有一份

**问题**：全局 `INDEX.md` 随技能数线性增长，是唯一会随时间恶化的常驻项。

```
 20 个技能 → 全局索引约 55 行  ✓
 60 个技能 → 全局索引约 95 行  ⚠
150 个技能 → 全局索引约 185 行 ⚠
```

**解法**：任务开始时只读**当前大类**的索引（约 20 行），
全局索引仅在跨类检索时才读。

```
<root>/INDEX.md          全局（跨类检索才读）
<root>/法律/INDEX.md     大类索引（任务开始必读，20 行）
```

大类索引自动包含「通用技能」分区，无需跳转 `_common` 就能看到。
