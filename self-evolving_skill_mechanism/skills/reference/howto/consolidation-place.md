# 整合·归位：放哪、叫什么

> **本区性质：howto / 怎么做。**
> 判「写进去之后放哪」——归位决策、归属判定、ID 规范、冷热分层。

---

## 归位决策第二步：放 reference/ 的哪个区？

（第一步是放哪个大类，见下节。本节解决**进了本 skill 之后放哪个区**。）

整合八步的第 6 步「判定归属」实际要做**两次**：

```
① 放哪个大类？      → domain-routing（9 个大类）
② 放 reference/ 哪个区？  → 本节
```

**第 ② 步常被跳过**——因为写的时候知道自己在写什么，
但半年后审核的人不知道该去哪个区找。

| 你要写的这句话… | 进 |
|---|---|
| 遇到 X 情况该怎么做 | `howto/` |
| 什么情况下它不成立 | `audit/` |
| 第一步…第二步… | `flow/` |
| 本文讲…（元规则） | `common/` |
| 好的 X 应该…（判断标准） | `craft/` |

**判定不了时**：默认进 `howto/`（它是主路径），
但**在文首写明「本区性质」**，下次整理时按性质再挪。
`lint.py` 会按区检查，放错的区会在审核时显出来。

## 归位决策：放哪里

| 判据 | 去向 |
|---|---|
| 跨领域通用、每次任务都可能用到 | `SKILLS/_hot.md`（H#） |
| 属于某个任务领域的完整流程 | `SKILLS/domains/<领域>.md`（D#） |
| 领域已存在，只是补充细节 | 追加到该领域包的对应段落 |
| 单个可复用命令 | `SKILLS/_commands.md`（C#） |
| 用户偏好 | `SKILLS/_preferences.md`（F#） |

**新建 vs 追加**：领域包已存在时**优先追加**，不要为了"独立"拆成新包。
只有当一个包超过 ~200 行、且内部能清晰切成两个子任务时，才拆包（用 `related` 互链）。

## 归属判定：写进哪个大类

**四问，从强信号到弱信号**（完整协议见 `reference/howto/domain-routing.md`）：

| 问 | 判据 | 结论 |
|---|---|---|
| 1. 换个大类还成立吗 | 成立 | → `_common` |
| 2. 当前项目接入哪个大类 | `domain.py --detect` | → 该大类（**最强信号**） |
| 3. 关键词命中哪个 | `domain.py --route "<描述>"` | → 推荐候选 |
| 4. 是技能还是知识 | 知识（法条 / API 参数） | → `rules/`，不进 `skills/` |

**推荐 ≠ 自动写入**：置信度不足时向用户确认，归错类比不归更糟。

**补充优先于新建**：目标大类已有同类技能 → 编辑该文件追加段落，不要新建重复包。

**装不下则提结构提案**：若 `--route-check` 返回 `no_match` / `ambiguous`，
说明现有分类不适配 → 走 `reference/howto/structure-evolution.md` 的提案流程，
**不硬塞、不自行新建目录**。

## ID 规范

| 前缀 | 位置 | 示例 |
|---|---|---|
| H | `_hot.md` 热区 | H007 |
| D | `domains/*.md` 领域包 | D003 |
| C | `_commands.md` 命令 | C019 |
| F | `_preferences.md` 偏好 | F004 |

**ID 一经分配永久保留，永不复用**（避免旧引用指向新内容）。

## 冷热分层（替代删除）

**不删除任何技能。** 命中数决定**加载优先级**，不决定存亡。

| 层 | 判据 | 加载方式 |
|---|---|---|
| 🔥 `hot` | 命中高 / 跨领域通用 | 任务前必扫 |
| ❄️ `cold` | 有命中但低频，或新入库 | 索引命中时加载 |
| 🧊 `archive` | 长期 0 命中（>90 天） | 仅存索引，命中即回热 |

**冷藏操作**：把文件移到 `SKILLS/archive/`，frontmatter 改 `tier: archive`。
**索引里保留该条目**，下次被检索到时自动回热（`index.py` 已实现）。

### 为什么不用「删除」

| | 删除 | 冷藏 |
|---|---|---|
| 低频但重要的技能 | 误删，下次从零摸索 | 保留，命中即回 |
| 库体积 | 变小，但也变弱 | 变大，但分层后不占上下文 |
| 长期目标 | 库停滞在小规模 | 持续扩充成集群 |

**体积不是问题，加载才是。** 分层 + 索引已经解决了加载成本，
所以没有理由为了省空间牺牲技能积累。

## 冷热分层的诊断：0 命中到底是哪种

长期 0 命中只有两种可能，处置完全相反：

| 可能 | 判据 | 处置 |
|---|---|---|
| **真低频** | 换同义词检索能召回，只是没用上 | 冷藏保留，命中即回热 |
| **关键词太窄，召不回** | 换同义词仍检索不到 | **补 keywords 同义词** |

区分方法：`python3 scripts/index.py --find <同义词>`，
换两三种说法试。都召不回 → 是关键词问题，不是低频。
**误判成低频就冷藏掉了，等于这条技能永久消失。**
