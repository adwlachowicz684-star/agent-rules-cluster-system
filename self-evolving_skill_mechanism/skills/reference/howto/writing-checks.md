动词是「**问**」「**对照**」——这是**写检查时要做的事**，
不是「哪里不行」。
失效形态条目本身留在

- 审查册记**这个形态怎么发生的**（排查者视角）

## 一、这一族是什么

前面四条（一、七、十八、二十一）讲的是**同一件事的不同面**：

| 条 | 形态 | 一句话 |
|---|---|---|
| 一 | 断言被掏空 | 用例恒绿，因为它压根不验证 |
| 七 | **扫描范围不对** | 扫错目录 / 漏掉入口文件 |
| 十八 | **认错类型** | 缺列就识别不出类型 → 检查跳过 |
| 二十一 | **声明没生效** | 声明了但没人读，或读了没改变结果 |

ⓘ 本项目**连续 5 次**栽在这一族上，形态各不相同：

| # | 实际形态 | 表现 |
|---|---|---|
| 1 | 断言用 `any()` | 一条改坏，另一条还在 → 照样绿 |
| 2 | 断言蹭真库数据 | 真库干净 → `chk(True)` 顶替 → 从未验证 |
| 3 | 断言范围污染 | 扫全库时被前面用例残留带红 |
| 4 | **扫描目录不含入口** | 缺陷在 SKILL.md，检查只扫 reference/ |
| 5 | **类型识别用完整匹配** | 缺列 → 认不出类型 → 检查跳过 |

## 二、共同特征

> ⛔ **检查存在、跑得绿、返回 0 条——三种都可能是"没在查"。**

ⓘ 这是它比"检查报错"危险得多的原因：
**报错会拦住你，而绿色不会**。

## 三、⛔ 第 -1 问：这条**该不该**做成检查器？

不是所有判据都适合自动化。实测两例（同一轮做的，结果完全相反）：

| 判据 | 误报率 | 判据性质 | 结论 |
|---|---|---|---|
| 表格列数错位（第十七条） | **0%** | 结构性事实 | ✅ 上线 |
| 用数量论证质量（第二十三条） | **100%** | 纯语义判断（论证谬误） | ⛔ **不上线** |

⇒ **判据：能不能只看结构就判定，不需理解意图？**

- 能 → 做检查器
- 不能 → **留在人工对照清单**，并把这个结论写进那条判据里

### ⛔ "不上线"也要写下来

⛔ 什么都不写，半年后有人会重新尝试、重新踩一遍 100% 误报。
⇒ 在对应判据下写「⛔ 已评估：不适合自动检查」+ **实测数据**。

ⓘ **负面结论也是结论**——它省下的是下一轮重复踩坑的成本。

### ⛔ 但可执行部分要另找落点

第二十三条不适合自动查，可它的**可量化部分**（数字会过期）
已经在 `check_volatile_counts` 里落地了。
⇒ 一条判据可能**部分可自动化**，不要因为整体不行就全不做。

## 三、⛔ 第 0 问：先在真库上跑一遍，数误报率

| 检查器 | 第一版误报率 |
|---|---|
| `check_selftest_duality` | 5/9 ≈ 56% |
| `check_scope_selfreport` | **4/5 = 80%** |
| `check_mirror_pairs` | 上线即误报 8 条 |

⇒ **我写判据时想的是"理想形态"，而代码里有大量"合理变体"。**

**判据：写检查器前先跑真库，误报率超 30% 就回去改判据——不要加豁免。**

⛔ **豁免不是解决办法**：它把误报从"报出来"变成"看不见"，
而看不见的误报会持续消解信任，直到某天检查被整体关掉且没人记得为什么。

ⓘ 每改一次判据要**重跑**——`check_scope_selfreport` 从第 4 版改到第 6 版
才归零，中间一度从 1 条涨到 6 条（收窄"什么是通过信号"引入了新误报）。

详细论证与三步流程见
[`../audit/self-verification-falsepos.md#二十九`](../audit/self-verification-falsepos.md#二十九)。

## 三、写检查时的八问（逐条对照，⛔ 不要凭感觉）

| # | 问 | 不对会怎样 |
|---|---|---|
| 1 | **扫描范围包含入口文件吗？** | 最常被读的文件永远不被检查（第 5 次） |
| 2 | **类型识别用主键还是完整匹配？** | 缺列 → 认不出 → 检查跳过 |
| 3 | **断言只针对自造样本吗？** | 被无关残留带红/带绿 |
| 4 | **反侧写了吗？** | 只造正侧 = "缺反侧"从未验证 |
| 5 | **样本真的触发了目标状态吗？** | 空列表让 `all()` 恒真、`any()` 恒假 |
| 6 | **破坏后必然超阈值吗？** | 用例造得太温和 = 变异测不出差别 |

ⓘ 第 6 问的来源：写 `check_doc_shape` 用例时连踩两次——
先放 3 个 `##`（都不超），再放 10 个（正好等于阈值），
**两次都测不出差别**，变异测试照样全绿。

### ⚠ 一条反直觉的实测

> **把一条真断言换成 `chk(True)`，自检总数完全不变（61/0 → 61/0）。**

**数字对注水毫无抵抗力。**
⇒ 覆盖必须靠**结构**（每个检查项有没有专属用例），
不能靠**总数**。这正是第二十三条（「能数出来的」≠「该判的」）的实证。

## 四、第七问：⛔ 断言「输入非空」，不要断言「输出非空」

反哺自 `corpus_guard.py`。

上一轮的教训：路径改名后 `os.listdir()` 过滤 `.md` 得到空列表
→ 收集到 0 条 → **脚本正常退出、不报错**，整套机制空转一整轮。

⛔ 失败模式是「**返回 0 条**」而不是「报错」，
所以任何「能跑通」的检查都查不出来。

### ⛔ 为什么不能断言「输出 > 0」

> ⚠ **输出为 0 往往是好状态**：
> 断链报 0 = 全部修好了；索引报 0 问题 = 索引是干净的。
> ⛔ 若断言"输出 > 0"，则**修完问题反而自检失败**——判据方向是反的。

⇒ **✅ 真正的判据是「输入语料非空」**：

```
扫到 0 个文件 / 0 个概念 / 0 个 token
  → 只有一个解释：**路径指错了层**
```

⚠ 这个不变量在「结果完美」和「结果糟糕」时**都必须成立**——
这正是它比"断言输出"强的地方：**输出会随质量变化，输入不会**。

ⓘ 与第十八条（查不到 ≠ 没有）分工：
那条说"报没有之前先证明**查法对**"，本条给出**怎么证明**。

## 五、第八问：⛔ 引用「有效」≠ 引用「相关」

反哺自 `check-map-relevance.py`。

> ⚠ 弱引用已清零（每个【审】都带 `#N`），
> 但 **"指到了"不等于"指对了"**。
> 自动化只能保证编号存在、不歧义，
> 保证不了这条坑跟当前 Step **真的有关**。
> ⛔ 指错的后果是"我审过了，但审的不是这一步的坑"
> ——**比弱引用更隐蔽**。

### 判据：技术标识交集（三个实现细节都是踩出来的）

```python
# ① 中文用 bigram 滑动窗口，⛔ 整词匹配会失效：
#    "感知独立成层" 与 "感知和寻路" 明明共享"感知"，
#    整词切出来是两个词 → 判零交集
# ② 剔除高频虚词 bigram，⛔ 否则任何两句都"有交集"
# ③ ⛔ 纯小写无下划线的英文词此前匹配不到 ——
#    只认「首字母大写」和「带下划线」两种，
#    导致 hitbox ↔ hitbox 判为零交集
```

ⓘ ③ 是「认错类型」的又一变体（falsepos 第十四条）——
**同一形态第 6 次**：检查写了、跑得绿，但它认的对象不对。

### ⛔ 过期豁免 = 遮羞布

同一脚本的注释：

> ⚠ 每条豁免必须写理由；自检会校验豁免项**仍然存在**，
> 映射改了而豁免没删 → 报「过期豁免」。
> ⛔ **豁免变成掩盖真问题的遮羞布**。

⇒ **豁免登记必须双向校验**：
登记了但目标不存在 = 过期，要删；
反之（目标存在但没登记）= 漏登记。

ⓘ 与第二十六条（「回到」列最容易过期）是同一件事，
但这条**可以自动检查**——那条只能人工。

### ⚠ 实测：它自己就有假阳性

真库跑出来 **8 条过期豁免全部命中**，
但抽查其中一条（`ai/02` S1 → `ai-behavior.md#1`）**映射确实存在**。

查下去是代码顺序问题：

```python
et = entry_text(path, sec)
if et is None:
    continue          # ⛔ 这里 continue 了
_sh = stok & tokens(et)
_key = (...)
seen.add(_key)        # ← 在 continue 之后，没执行
```

⛔ **「条目查不到」和「映射不存在」被当成了同一件事**。

⇒ 判据：**豁免校验的 `seen` 必须在任何 `continue` 之前收集**，
否则"查不到"会被误判成"已删除"。

## 六、⛔ AST 提取：同一个节点会被遍历到两次

**三件套**

| | |
|---|---|
| **来源** | 2026-09-26 开发 `check_scope_selfreport`（信号 B：自己踩的坑） |
| **证据** | 实测：把 `FormattedValue` 和它内部的 `Name` **都**还原成 `{}` → 得到 `"{}{}"`，范围信号正则失效，用例恒绿 |
| **后果** | 提取出的文本与源码不符 → 范围信号永远匹配不上 → **检查器误报**；⛔ 误报的检查会被关掉（falsepos 第十四条） |

```python
# ⛔ 错：ast.walk 会同时给出 FormattedValue 和它内部的 Name
for x in ast.walk(a):
    if isinstance(x, ast.FormattedValue): txt += "{}"
    elif isinstance(x, ast.Name):         txt += "{}"   # → "{}{}"

# ✅ 对：只处理 FormattedValue
for x in ast.walk(a):
    if isinstance(x, ast.Constant) and isinstance(x.value, str): txt += x.value
    elif isinstance(x, ast.FormattedValue): txt += "{}"
```

**判据**：同一个语法结构，**父节点和子节点都可能命中你的 isinstance**。
写之前先打印一次提取结果，看有没有**重复占位**。

ⓘ 与第七问同族：那一条说「断言输入非空」，这一条说「提取要验证提取对了没」——
**都是"中间产物没人看"**。
