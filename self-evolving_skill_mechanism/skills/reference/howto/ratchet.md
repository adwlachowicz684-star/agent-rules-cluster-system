# 棘轮机制：只进不退

> **本区性质：howto / 怎么做。**
> 改完之后怎么保证没变差。判定「该不该入库」见 [`consolidation-gate.md`](consolidation-gate.md)。

---

## 一、为什么需要

自进化的最大风险**不是"长不大"，而是"长了但变差了"**。

差别在于：长不大是**看得见的**——库就那些内容，谁都知道。
**变差是静默的**——内容变多了、看起来更全了，
但某条判据其实被改松了、某个步骤其实被删了、某个检查其实不再报错了。

⛔ **没有门禁的进化，会往"看起来更全"的方向漂。**

判据：

> **能不能证明这次改动让库变好（或至少没变差）？**
> 证明不了 → 不该合进去。

---

## 二、与「只增不减」的关系（易混）

| | 管什么 | 不许做什么 |
|---|---|---|
| **只增不减** | 技能的**存亡** | 不许**删除**冷门技能（冷藏，不删） |
| **棘轮** | 改动的**质量** | 不许合入**导致退化**的修改（回滚） |

两者不冲突，是**不同层的门禁**：
经验不丢（只增不减）∧ 质量不降（棘轮）。

⚠ 最常见的误解：把"只增不减"理解成"改了就不能撤回"。
**恰恰相反——删除会丢经验，回滚不会。** 回滚是恢复上一个更好的状态。

---

## 三、三种基准（改之前先挑一种）

| 基准 | 适用 | 怎么判定 |
|---|---|---|
| **回归集** | 已有可复现的失败案例 | 改动后重跑，之前能查出的**必须还能查出** |
| **自检计数** | 检查项改动 | 自检通过数**不能下降**（42 → 41 就是退化） |
| **变异验证** | 新增检查项 | 破坏样本后**必须变红**（不变红 = 检查没在查） |

⛔ **没有基准就不要改判据。** 判据一改，
"什么算问题"就跟着变了——而你在用新标准评价自己的改动，
**这是自己给自己打分**。

⚠ 若确实必须先改判据（比如旧判据明显错了）：
先记录**旧判据下的现状**（哪几条命中），改完再用新判据跑，
并把"哪些是新判据才报出来的"单独列出——
⛔ 不能混在一张表里声称"问题变多了"。

---

## 四、退化了怎么办：回滚，不是继续改

```
发现退化 → 回滚到上一个好状态 → 重新设计改动 → 再跑基准
```

⛔ **不要就地继续改**。理由：

1. 就地改是在**已经变差的状态上叠补丁**，通常越叠越乱
2. 退化可能不止一处，就地改只修了你看到的那处
3. 回滚后重新设计，往往发现**原改动本身就该换个做法**

ⓘ 回滚不丢东西——改动在版本历史里，经验也在库里。
**棘轮管的是"当前状态"，不是"不许尝试"。**

---

## 五、入库后的复核（棘轮的后端）

合入不是终点。三类信号说明**当初的判断可能错了**：

| 信号 | 说明 |
|---|---|
| 某条加了却**从没被命中** | 可能判据写窄了，或它压根不是真问题 |
| 某条被命中但**每次都被判误报** | 判据认错了对象 |
| 同一处**反复被改** | 说明没想透，不是"再调一次就好" |

⛔ 不要默默改掉——先 `note.py --show` 看它当初为什么这么写。
**凭"现在看着不对"改，会毁掉有理由的设计。**

## 六、自检（30 秒）

- [ ] 这次改动**有基准**吗？改动前后都跑过吗？
- [ ] 自检通过数**没下降**？（42 → 41 就是退化）
- [ ] 新增检查项做过**变异验证**吗？（破坏后必须变红）
- [ ] 判据改了的话，**新旧判据的结果分开列**了吗？
- [ ] 发现退化时，是**回滚**而不是就地继续改？
- [ ] 有"加了却从没命中"的条目吗？（可能是假需求）
