# 闭环流程：建设 → 审查 → 回看 → 互补

> **本区性质：flow / 端到端流程。**
> 两册怎么配合着把技能库迭代强化。


> **流程 ID**：`FL-02`（**分配后不改**）
> **前置**：已完成一次建设产出（写完 / 改完技能）
> **本步交付**：建设册与审查册同步增长（不是审查册独自变厚）
> **对应**：做法 `howto/writing-rules.md` · 审核 `audit/self-verification.md`

ⓘ 七节顺序**固定**。五步闭环与三问需整体对照执行。

---

## 0. 交付物定义

跑完本流程，应该能**直接指认**：

1. **审查清单**：这次报出的"哪里不行"，每条带位置与证据
2. **建设册的新一句**：每条失效形态对应一句"该怎么做"
3. **审查册的新判据**：靠人肉发现的问题已写成可复现的判据

⚠ **只有 1 没有 2 和 3 = 闭环没转**。
判据：**技能库在变强，还是只在变厚？**

## 1. 前置检查清单

- [ ] 已有一次建设产出（写完 / 改完的技能）
- [ ] 已能说出这次改了什么、为什么改
- [ ] ⚠ 不是在建设途中（先做完，再审查）

## 2. 工序

```
① 建设 → ② 审查 → ③ 调整 → ④ 回看 → ⑤ 互补 → 回到 ①
```

### Step 1　建设　`[FL-02#S1]`

【读】`howto/writing-rules.md#第一问：这条写进 reference/ 的哪个区？`

【做】用建设册（`howto/`）写 / 改 / 生成技能

【产出】一份技能产出（条目 / 文件 / 脚本改动）

【判据】产出只写了"怎么做"，没有混入"不能怎么做"

【审】`audit/anti-patterns.md`

### Step 2　审查　`[FL-02#S2]`

【读】`audit/self-verification.md`

【做】用审查册（`audit/`）逐条对照，出「哪里不行」清单

【产出】问题清单：每条带**位置 + 证据**

【判据】每条问题能指出"在哪个文件哪一段"，⛔ 不是"感觉有问题"

【审】`audit/rejection.md`（先过驳回清单，别把设计意图当缺陷）

### Step 3　调整　`[FL-02#S3]`

【读】`howto/consolidation-practice.md#改完必须重跑：改 A 引入 B 按最高级`

【做】按审查结果改技能本身

【产出】改完的技能 + 复跑记录

【判据】原来报的问题已消失，且**没有引入新问题**（重跑验证）

【审】`audit/self-verification-silent.md#十三`

### Step 4　回看建设册　`[FL-02#S4]`

【读】`howto/writing-rules.md`（整册，逐条对照）

【做】拿审查结果反查建设册，问三个问题：

| # | 问 | 命中了要做什么 |
|---|---|---|
| 1 | **流程不够详细？** 建设册的步骤，细到陌生 AI 照做不会走偏吗？ | 补具体动作。判据：**能不能只靠这一个文件干活** |
| 2 | **内容有疏漏？** 这个失效形态，建设册里有对应的"该怎么做"吗？ | 补那一句。**这是审查册反哺建设册的唯一通道** |
| 3 | **代码/脚本不够严谨？** 是不是某个脚本静默失败 / 假绿 / 参数不校验？ | 改脚本，并把失效形态补进审查册 |

【产出】建设册的新增/修改（三问各至少过一遍）

【判据】这次报的**每条**问题都问过三问，⛔ 不是只挑容易的问

【审】⛔ **本步最容易跳过**——改完技能后"事情已经做完了"，
而回看是**额外的一步**。所以三问写成硬性的，不是"有空再看"。

### Step 5　互补（双向确认）　`[FL-02#S5]`

【读】`../common/split-two-books.md`

【做】两册互相确认：

- 建设册补充时问：**这个"该怎么做"，审查册里有它的失效形态吗？** 没有 → 补
- 审查册补充时问：**这个"不能怎么做"，建设册里有对应的"怎么做"吗？** 没有 → 补

【产出】两册各自的新增（若单侧缺失则补另一侧）

【判据】两册**同步增长**；⛔ 审查册涨而建设册不动 = 停滞

【审】`audit/self-verification-falsepos.md#十一`

## 3. 参考实现

最小闭环命令序列：

```bash
python3 scripts/lint.py              # 审查：全量检查
# 按报告改技能
python3 scripts/lint.py --self-test  # 复跑：确认检查本身还工作
python3 scripts/lint.py              # 再审查：确认问题消失且未引入新问题
```

ⓘ 第 ④ 步（回看建设册）**没有命令**——它是三问，必须人/AI 逐条过。

## 4. 验收清单

- [ ] 这次审查报的问题，**逐条**问过三问（不是只挑容易的）
- [ ] 有没有「审查册找不到判据」的发现？有 → 补判据了吗
- [ ] 建设册补的那句，审查册有对应失效形态吗（双向确认）
- [ ] 审查册补的那条，建设册有对应"怎么做"吗（双向确认）
- [ ] ⚠ `lint.py` 报的接近上限 / 章节过多，规划拆分了吗
- [ ] ⛔ 改完重跑过吗（确认没引入新问题）

⛔ 不能"改完就算闭环了"。

## 5. 常见返工

⚠ **跳过第 ④ 步回看** —— 这是最常见的停滞形态。
表现：审查册越写越厚（不断吸收新失效），建设册原地不动
（没人回去补那句"该怎么做"）。结果同一个坑反复踩——
**记录了十次"这里会静默失效"，建设册始终没写"这里必须显式报错"**。

实测（本仓库）：`self-verification.md` 从 137 涨到 522 行、20 条
（8 条是这几轮补的；现已按失效大类拆成 silent / falsepos / credibility 三册），
同期建设册只增加了驳回清单的拆出。**审查册在独自长大**——正是闭环缺失的症状。

⚠ **互补只做单向** —— 只补审查册，技能库会变成"别这样别那样"，
没有可执行步骤；只补建设册，没人知道它在哪失效，下次照踩。

⚠ **把设计意图当缺陷改** —— 改之前没查溯源（`note.py --show`）。
半年后没人记得一条规则怎么来的，凭"看起来不对"改掉会毁掉有理由的设计。

⚠ **改 A 引入 B 却只按 B 的级别报** —— 按**最高级**报。

## 6. 下一步

→ 回到 [`consolidation.md`](consolidation.md)（`FL-01`）：
把本次闭环产生的条目正式入库。

**自审**：打开 `audit/self-verification.md`（索引），按失效大类过 20 条自检协议。

## 7. 整体审核（流程级收尾）

ⓘ 各 Step 的【审】是**步骤级即时检查**；本节是**流程级复查**。

- [ ] 逐条过 `audit/self-verification.md`
- [ ] 步骤级【审】列过的条目**再过一遍**（做完再看的视角不同）
- [ ] ⚠ 三问逐条问过（第 ④ 步）
- [ ] ⚠ 两册是否同步增长——**审查册涨、建设册不动 = 停滞**

## 附：为什么需要闭环

只建设不审查 → 技能写得顺手，但没人知道它在哪会失效。
只审查不回看 → 每次都在报同一类问题，
而**建设册里从来没有对应的那一句**。

## 附：自我迭代强化（累积效应）

闭环跑起来后，技能库会自己变强，不需要外部推动：

1. 每次踩坑 → 审查册多一条判据（下次同类坑自动被抓）
2. 每条判据 → 建设册多一句"该怎么做"（下次不会踩）
3. 建设册越细 → 审查报的问题越少、越聚焦
4. 审查册越全 → 第 ④ 步的三问越容易命中

**判据：技能库在变强还是只在变厚？**

| 信号 | 含义 |
|---|---|
| 审查册涨、建设册不动 | **停滞**——同一个坑反复踩，只是记录得越来越详细 |
| 两册同步增长 | 健康——每次失效都转化成了可执行步骤 |
| 同一形态反复报出 | 第 ④ 步第 2 问没做——建设册缺那一句 |

## 附：自检器（替代自觉）

闭环靠自觉不会转（实测：`_hot.md` 命中数长期全 0）。
所以把触发条件做成 `scripts/lint.py` 的自动检查：

| 检查项 | 触发 | 提示做什么 |
|---|---|---|
| **体积预警** | 超过上限 | 拆文件或下沉细节 |
| **接近上限预警** | 达到上限 **80%** | **现在就规划拆分**，别等到超限 |
| **章节过多** | 单文件 `##` 章节 > 12 | 内容已不适合单文件，按主题拆 |
| **孤立知识点** | 写了「要注意 X」但不改变任何一步 | 改写或删除 |
| **豁免可验证** | 声明了体积豁免 | 理由不成立就该拆 |
| **标题重复 `#`** | `## ## x` | 拼接时多带了一组 |
| **五分体系完整** | 区缺失 / 无性质标记 / **标记与目录不符** | 见 `../common/split-two-books.md` |

**接近上限预警为什么要有**：等到超限才报，往往已经长到拆不动了
（400 行的文件拆成三份，要重写目录和交叉引用）。80% 时提示，还有余裕规划。

```bash
python3 scripts/lint.py              # 全量检查
python3 scripts/lint.py --json       # 机器可读
python3 scripts/lint.py --self-test  # 验证检查项本身还工作
```
