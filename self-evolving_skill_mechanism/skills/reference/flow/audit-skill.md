# 审核一个 skill

> **本区性质：flow / 端到端流程。**
> 拿到一个已有 skill，从头审一遍；审查册怎么用见本流程，
> 审查完怎么改见 `closed-loop.md`（`FL-02`）。

> **流程 ID**：`FL-04`（**分配后不改**）
> **前置**：有一个待审的 skill（自己刚建的 → 接 `FL-03`；已存在很久的 → 定期审）
> **本步交付**：「哪里不行」清单，每条带**位置 + 证据 + 后果**
> **对应**：做法 `howto/writing-rules.md` · 审核 `audit/` 三册

> ⛔ **本流程只读审查册（`audit/`），不读建设册（`howto/`）。**
> 读建设册会把「哪里不行」写成「建议改成 X 流程」——**位置和证据全丢了**。
> 怎么改是 `FL-02` 第 ③ 步的事，不是审查的事。
> 判据见 `../common/split-two-books.md`。

ⓘ 七节顺序**固定**。

---

## 0. 交付物定义

审完应该能**直接指认**：

1. **问题清单**：每条有位置（哪个文件哪一段）+ 证据（凭什么说它不行）
2. **分级**：P0（必须改）/ P1（应该改）/ P2（可记 backlog）
3. **新判据**：靠人肉发现的问题已写成可复现的判据

⚠ **只有 1 和 2，没有 3 = 白审一半**。
**没有判据的发现是不可复现的发现**——下次换个人就发现不了。
补判据是 `FL-02` 第 ⑤ 步，但**在本流程内就要识别出"这条没判据"**。

---

## 1. 前置检查清单

- [ ] 待审对象**明确**（哪个 skill / 哪些文件），不是"整个库随便看看"
- [ ] 已能拿到它的**溯源记录**（`note.py --show` / changelog）
- [ ] ⚠ 不在建设途中（**先做完，再审查**）
- [ ] ⛔ 手边只开了审查册，没开建设册

⚠ 缺一样就先补——尤其第 3 条：边建边审会把"还没写完"当成缺陷报出来。

## 2. 工序

### Step 1　摸清全貌　`[FL-04#S1]`

【读】待审 skill 的 `SKILL.md`（**只看目录地图**）

【做】看目录地图，确认它声称有哪些区、各区声称装什么

【产出】一张"它声称有什么"的清单

【判据】**只看 `SKILL.md` 就能说出该去哪找什么**；说不出 → 目录地图不合格

【审】`audit/anti-patterns.md`

### Step 2　先过驳回清单　`[FL-04#S2]`

【读】`audit/rejection.md`（6 条）

【做】过一遍驳回清单，把"可能是既有设计意图"的先排除

【产出】排除列表（含排除理由）

【判据】每条排除项都能说出"它为什么是有意的"

【审】⛔ **不查溯源就改，是最高频的误改来源**。
先 `note.py --show <ID>` 看它当初为什么这么写；
凭"看起来不对"改掉会毁掉有理由的设计。

### Step 3　逐区审查　`[FL-04#S3]`

【读】`audit/self-verification.md`（三册索引）

【做】按区过：

| 区 | 审什么 |
|---|---|
| `howto/` | 每条是否只写"怎么做"、有没有混入"不能怎么做" |
| `audit/` | 每条是否有判据、判据是否可复现 |
| `flow/` | Step 五字段、两级审核、`FL-xx` 登记（跑 `lint.py`） |
| `common/` | 元规则是否被各区引用（不引用 = 没人读） |
| `craft/` | 有没有"做完、没毛病"但**不好用**的部分 |

【产出】各区的问题（每条带位置 + 证据）

【判据】每条能指出"在哪个文件哪一段"，⛔ 不是"感觉有问题"

【审】`audit/self-verification-silent.md`（先确认检查真在查）

### Step 4　查失效形态　`[FL-04#S4]`

【读】`audit/self-verification-silent.md` · `-falsepos.md` · `-credibility.md`

【做】按三类逐条问：

- **silent**：有没有检查在跑但没在查？（长期红灯 / 0 条不报错）
- **falsepos**：有没有判据认错了对象？（把正确写法判成违规）
- **credibility**：有没有信号真假难辨？（"没跑起来"冒充"跑了没命中"）

【产出】失效形态清单（分类：silent / falsepos / credibility）

【判据】每条能归到一类；归不上的**单列**，不要硬塞

【审】⛔ **查不到 ≠ 没有**（[EC-01](../common/blocks.md#ec-01-查不到--没有)）——报"没有"之前先证明"查了"且"查法对"

### Step 5　分级与排序　`[FL-04#S5]`

【读】`audit/rejection.md#说不出后果`

【做】按后果严重度分级：

| 级 | 判据 | 处置 |
|---|---|---|
| **P0** | 会导致**静默错误结果**（假绿 / 漏报 / 覆盖） | 必须改 |
| **P1** | 会导致**误报或难用**，但结果仍可见 | 应该改 |
| **P2** | 瑕疵，不影响正确性 | 记 backlog |

【产出】分级清单，P0 在前

【判据】每条说得出"不这么改会怎样"；说不出 → **不是真问题**，驳回

【审】⚠ **说不出后果的通常不是真技能，同理也不是真问题**

### Step 6　出清单　`[FL-04#S6]`

【读】`audit/anti-patterns.md`

【做】输出三张表：

**表一：必须改（P0/P1）**

| 位置 | 证据 | 后果 | 级 |
|---|---|---|---|

**表二：可记 backlog（P2）**

| 位置 | 问题 | 级 |
|---|---|---|

**表三：没判据的发现**（靠人肉发现的）

| 发现 | 为什么现有判据抓不到 | 待补判据 |
|---|---|---|

【产出】三张表

【判据】表三非空时**必须在 `FL-02` 里补判据**；
⛔ 不能合并到表一——合并等于声称"现有判据已覆盖"

【审】⛔ **三张表不能合并**。合并等于声称全部由判据覆盖——
正是"报告看起来很完整，但没人知道哪些是靠人肉"的来源。

### Step 7　留痕　`[FL-04#S7]`

【读】`howto/consolidation-gate.md#入库三件套（缺一不可）`

【做】`note.py` 记本次审查；表三的发现**立即进 `pending/draft.md`**

【产出】审查记录 + 待补判据已进入捕获缓冲

【判据】下次审查能看到"上次报过什么、改了没有"

【审】`audit/anti-patterns.md`

## 3. 参考实现

一次完整审查的最小命令序列：

```bash
python3 scripts/note.py --show <ID>        # 溯源：它当初为什么这么写
python3 scripts/lint.py                    # 结构 / 死链 / 五区 / flow 规范
python3 scripts/lint.py --self-test        # 检查本身还工作吗
python3 scripts/consolidate.py             # 查重
```

ⓘ **没有"一键审核"**——Step 3/4/5 必须人（或 AI）逐条过，
脚本只能覆盖结构性检查。

## 4. 验收清单

- [ ] 只读了审查册，没读建设册
- [ ] 每条问题有**位置 + 证据**，不是"感觉有问题"
- [ ] ⛔ 先查过溯源（没把设计意图当缺陷改）
- [ ] 按 silent / falsepos / credibility 分过类
- [ ] 每条说得出**后果**；说不出 → 驳回
- [ ] ⚠ 三张表**没有合并**
- [ ] ⚠ 表三的发现已进 `pending/draft.md`（待补判据）
- [ ] 跑过 `lint.py --self-test`（确认检查本身没失效）

⛔ 不能"看了一遍觉得还行"就过。

## 5. 常见返工

⚠ **读着建设册审核** —— 会把"哪里不行"写成"建议改成 X 流程"，
**丢掉位置和证据**。改的人拿到建议，不知道原问题在哪、为什么不行。

⚠ **不查溯源就判缺陷** —— 半年后没人记得一条规则怎么来的，
凭"看起来不对"改掉，会毁掉有理由的设计。**先 `note.py --show`。**

⚠ **三张表合并成一张** —— 等于声称全部由判据覆盖。
读的人无法区分"判据抓到的"和"人肉发现的"。

⚠ **只报"感觉有问题"** —— 没有位置的报告无法行动。
判据：**能不能指出在哪个文件哪一段？**

⚠ **把静默失效和误报混为一谈** —— 两者修法相反：
silent 要让它报错，falsepos 要让它别报。混了会改错方向。

⚠ **边建边审** —— 会把"还没写完"当成缺陷报出来，
审完还要回头重审一遍已完成的部分。

## 6. 下一步

→ [`closed-loop.md`](closed-loop.md)（`FL-02`）第 ③ 步：
按本清单改 skill 本身 → 第 ④ 步**回看建设册** → 第 ⑤ 步补判据。

**自审**：本次审查本身也要能过 `lint.py`。

## 7. 整体审核（流程级收尾）

ⓘ 各 Step 的【审】是**步骤级即时检查**；本节是**流程级复查**。

- [ ] 逐条过 `audit/anti-patterns.md`
- [ ] 步骤级【审】列过的条目**再过一遍**（做完再看的视角不同）
- [ ] ⚠ 确认全程**没读建设册**
- [ ] ⚠ 三张表没合并
- [ ] ⚠ 表三非空 → 已进 `pending/draft.md`
- [ ] 若审查中发现脚本问题 → ⚠ 还要跑 `--self-test`：
      **报问题的工具自己可能就是失效的那个**
