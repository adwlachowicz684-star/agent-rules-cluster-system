# 归档：把本轮草稿收进历史

> **流程 ID**：`FL-05`（**分配后不改**）
> **前置**：`pending/draft.md` 里有本轮捕获，且**已整合完毕**
> **本步交付**：草稿进了 `pending/archive-YYYYMM.md`，`draft.md` 重置为空模板
> **对应**：做法 `howto/capture-signals.md` · 审核 `audit/self-verification-silent.md`

> ⚠ **归档前必须先整合。** 归档会**重置 `draft.md`**——
> 没整合就归档 = 本轮捕获**永久丢失**。
> 这不是"可能丢"，是脚本行为：归档成功后 `draft.md` 一定被清空。

ⓘ 七节顺序**固定**。

---

## 0. 交付物定义

跑完应该能**直接指认**：

1. `pending/archive-YYYYMM.md` 里有本轮捕获（**条数对得上**）
2. `pending/draft.md` 已重置为空模板
3. 归档的条数 **≥ 你记得自己写了几条**

⚠ 第 3 条指认不出来 = 丢了内容。

## 1. 前置检查清单

- [ ] ⛔ **本轮捕获已整合完毕**（走过 `FL-01`）

- [ ] `pending/draft.md` 非空

⚠ 第 1 条不满足就归档，等于把本轮经验扔掉。

## 2. 工序

### Step 1　确认整合完成　`[FL-05#S1]`

【读】`pending/draft.md`

【做】逐条问：这条进库了吗？还是要留到下轮？

【产出】「已入库」与「留待下轮」两张清单

【判据】没有"不知道进没进"的条目

【审】⛔ **没整合就归档 = 永久丢失**——脚本会清空 `draft.md`，
⛔ 且**没有回收站**

### Step 2　抢救未整合项　`[FL-05#S2]`

【读】Step 1 的「留待下轮」清单

【做】把这些条目**抄到别处**（下轮草稿 / 任务记录 / `pending/` 下新文件）

【产出】未整合项已在 `draft.md` 之外留了副本

【判据】清空 `draft.md` 后，这些条目**仍然能找到**

【审】⛔ 不要"记在脑子里"——归档后 `draft.md` 重置，
⛔ 只剩脑子里的那份

### Step 3　记录基线　`[FL-05#S3]`

【读】`pending/draft.md` 的有效行数

【做】`grep -cvE '^\s*(#|<!--|-->|$)' pending/draft.md`

【产出】一个数字：**归档前有多少条**

【判据】这个数字记下来了

【审】⛔ **本步不能省**——没有基线就无法判断归档丢没丢东西。
归档脚本会告警"少了 N 行"，但**你得知道原本是几行**才知道该不该紧张。

### Step 4　执行归档　`[FL-05#S4]`

【读】`scripts/archive.sh`

【做】`bash scripts/archive.sh`

【产出】`pending/archive-YYYYMM.md` + 脚本输出的"已归档 N 条"

【判据】**N ≥ Step 3 的基线 - 1**（少 1 是表格分隔线，正常）

【审】⚠ **N 明显小于基线 = 内容被过滤掉了**，先看脚本的过滤规则。
实测教训：早先的过滤规则把 `|` 开头的行全丢了，
**表格形式写的捕获整条消失**，退出码还是 0。

### Step 5　核对归档内容　`[FL-05#S5]`

【读】`pending/archive-YYYYMM.md` 尾部

【做】看本轮段落，确认内容完整、没被截断

【产出】确认无误（或发现缺失）

【判据】归档里的条目**逐条对得上** Step 1 的清单

【审】⚠ 只看"已归档 N 条"不够——**条数对也可能内容错**。
⛔ 归档后 `draft.md` 已重置，此时发现缺失就来不及了。

### Step 6　留痕　`[FL-05#S6]`

【读】`howto/consolidation-gate.md#入库三件套（缺一不可）`

【做】`note.py` 记本次归档（条数 + 来源时间段）

【产出】变更溯源记录

【判据】半年后能答出"这批经验是什么时候、从哪轮来的"

【审】`audit/anti-patterns.md`

## 3. 参考实现

```bash
# S3 基线
grep -cvE '^\s*(#|<!--|-->|$)' pending/draft.md

# S4 归档
bash scripts/archive.sh          # 输出「已归档 N 条」

# S5 核对
tail -20 pending/archive-$(date +%Y%m).md
```

ⓘ 归档是**幂等**的：同一天跑两次，第二次会因为 `draft.md` 已空而
输出"草稿为空，无需归档"。

## 5. 常见返工

⚠ **先归档后整合** —— 最严重。`draft.md` 被清空，
本轮捕获**永久丢失**，无回收站。
判据：**归档的唯一目的是给"已整合完的草稿"腾地方**，不是保存手段。

⚠ **不记基线** —— 脚本告警"少了 N 行"时，你不知道原本该有几行，
无法判断是丢了内容还是只丢了分隔线。

⚠ **只信条数不信内容** —— 条数对也可能内容错
（比如表格内容被过滤成空行仍计数）。

⚠ **把归档当备份** —— 归档文件是**历史流水**，按月累积、不分主题。
找某条经验应该用 `index.py --find`，不是翻归档。
