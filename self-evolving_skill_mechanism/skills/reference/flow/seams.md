# 流程接缝：上下游对不对得上

> **本区性质：flow / 元规则。**

> **流程之间对不上的地方，是返工的主要来源。**
> 单个流程内部每一步都做对了，拼起来仍然可能不成立。

## 一、为什么单独一篇

反哺自 game-dev 的 28 个域流程——**每个域的 07 验收都有一个独立的「接缝复查」步**：

> ⛔ **这六条不查，部件全合格也可能拼不起来。**

⇒ 审核是**三级**（`acceptance.md` 第十三节）：
步骤级【审】→ 功能点级复查 → **域级接缝复查**。
第三级必须独立成步，因为**前两级都是"看自己"，第三级才是"看别人"**。

## 二、⛔ 实证：主链路第一次真跑，4 个断点全是接缝

主链路六步：捕获 → 整合 → 归档 → 索引 → 召回。
第一次在真实数据上跑通，**每一步都断**，而断的全是接缝：

| # | 接缝 | 表象（看起来像什么） | 真因 |
|---|---|---|---|
| 1 | 捕获 → 整合 | "草稿为空" | draft 的捕获行被 `<!-- -->` 包着，整合器**当注释丢弃** |
| 2 | 整合 → 归档 | "归档成功" | 「归档前必须先整合」只是**清单**，没有强制机制 |
| 3 | 整合 → 索引 | "索引是干净的" | `domain_dir` 用 name（开发）而目录是 key（dev）⇒ 扫不存在路径 |
| 4 | 索引 → 召回 | "未命中，还没这技能" | 同上，索引 0 项，`--find` 输出"库里还没有" |

⛔ **四个的失败模式完全相同：返回 0 条而不是报错。**
⇒ 报错会拦住你，而"没有"不会。这正是
[`../audit/self-verification-silent.md#十八`](../audit/self-verification-silent.md) 写的，
只不过这次被断的是**流程与流程之间**。

## 三、主链路接缝表

| 接缝 | 上游产出 | 下游期望 | 一致 | 断点 |
|---|---|---|---|---|
| 捕获 → 整合 | `pending/draft.md` 的捕获行 | `consolidate.py` 能逐条读到 | ✅ 已修 | #1 |
| 整合 → 归档 | 指纹 + 已整合标记 | `archive.sh` 比对不匹配则 exit 3 | ✅ 已修 | #2 |
| 整合 → 索引 | `domains/<key>/skills/*.md` | `index.py` 重建后项数 > 0 | ✅ 已修 | #3 |
| 索引 → 召回 | `INDEX.md` | `--find` 命中并给出理由 | ✅ 已修 | #4 |
| 归档 → 索引 | `archive-*.md` | 历史可回查（不参与检索） | ✅ 一致 | — |

ⓘ 五条里**四条断过**。⛔ 不要因为"现在都修好了"就认为接缝天然一致——
它们一致是因为**断过一次才对齐的**。

## 四、判据

**接缝清单里每一行都要标注「一致」或「已适配」，且适配要单独立一步。**

⛔ **不要在各流程内部偷偷转格式**——那些转换会散落多处，
改接口时找不到（`skeleton.md` 第四节同条，逐字出现在 game-dev 6 个域）。

### 写法

```
| 接缝 | 上游产出 | 我这边期望 | 是否一致 |
|---|---|---|---|
| 捕获 → 整合 | draft.md 捕获行 | 逐条可读 | ✅ 一致 |
```

⚠ 「是否一致」列**最常被省**，而它恰恰是这一列唯一的作用——
没有它，表就退化成一张"我知道有哪些邻居"的清单，
**看起来完整，实际上一条都没被判过**。

## 五、⛔ 接缝不是接口文档

接口文档写"对方提供什么"，接缝表写"**我这边接得上吗**"。

⇒ 同一个东西两份描述，而**只有接缝表会被复查**。
⛔ 只写接口文档 = 有人声明了格式，但没人确认过它能被消费。

判据：**这条接缝，上次是谁在什么时刻验证过的？**
答不出 = 它只是被声明，没被验证。

## 六、自检（30 秒）

- [ ] 流程的接缝清单里，「**是否一致**」列填了吗？
- [ ] 不一致的接缝，是**单独立了一步适配**，还是在流程里偷偷转？
- [ ] 这条接缝**上次被验证**是什么时候？（⛔ 只是被声明 ≠ 被验证）
- [ ] 失败模式是"返回 0 条"还是"报错"？（前者要专门加守卫）
