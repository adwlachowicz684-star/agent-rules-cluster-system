# 整合流程（会话结束时执行）

> **本区性质：flow / 端到端流程。**
> 只讲「按什么顺序做」；判定标准在 `howto/consolidation-rules.md`。


> **流程 ID**：`FL-01`（**分配后不改**）
> **前置**：无（会话中随时可跑；会话结束时必跑）
> **本步交付**：条目入库 + 索引更新 + 三张清单
> **对应**：做法 `howto/consolidation-rules.md` · 审核 `audit/rejection.md`

> **不要边干活边写库** —— 碎片化会让同一个坑在库里变成三条。
> 技能只增不减：整合的目标是把新经验**放对位置**，不是把旧的删掉。

ⓘ 七节顺序**固定**——要找"验收标准"永远在第 4 节。
判定标准（四道门槛、归位决策、ID 规范…）在 `howto/consolidation-rules.md`，
本文件只在【读】里指向它。

---

## 0. 交付物定义

跑完本流程，应该能**直接指认**三样东西：

1. **新条目**已进某大类的 `skills/`，带 ID 和三件套
2. **索引已重建**——`index.py --find <关键词>` 能找到它
3. **三张清单**：已验证 / 未验证 / 需人工确认

⚠ 任何一样指认不出来，整合不算完成——
尤其是第 2 条：条目进了库但索引没重建，
表现为"明明写过了却检索不到"，**这是静默失效，不报错**。

## 1. 前置检查清单

- [ ] `pending/draft.md` 有内容（空则无需整合）
- [ ] 已能说出每条草稿的**来源**（实测 / 推断 / 听说）
- [ ] ⚠ 不是在干活中途（碎片化会让一个坑变成三条）

⚠ 缺一样就先补。

## 2. 工序

### Step 0　分诊　`[FL-01#S0]`

【读】`howto/consolidation-gate.md#第零道闸：技能还是事实`

【做】过「第零道闸」：事实（路径/文件名/项目背景）直接丢弃

【产出】丢弃清单（含每条的丢弃理由）

【判据】每条丢弃项都能说出「换个项目还成立吗」的答案

【审】`howto/knowledge-landing.md`

### Step 1　过四道门槛　`[FL-01#S1]`

【读】`howto/consolidation-gate.md#四道门槛详解`

【做】读 `pending/draft.md`，逐条过四道门槛，不过关的直接丢弃

【产出】过闸结果：每条标注「留」或「丢」

【判据】留下来的每条都过了四道门槛，说得出各自过了哪几道

【审】`audit/rejection.md#证据不足`

### Step 2　查重　`[FL-01#S2]`

【读】`howto/consolidation-gate.md#批量相似条目：抽样，不逐条`

【做】`python3 scripts/consolidate.py` 出报告，再人工过一遍

- 语义等价 → 只命中 +1，**不新增**（重复是腐烂的开始）
- 语义冲突 → 留证据更强的，显式标注冲突及理由
- 相关但不重复 → 新增条目

【产出】三类判定：等价 / 冲突 / 新增

【判据】`consolidate.py` 报告里的同类项**每条都归了类**，没有未判定项

【审】`howto/consolidation-gate.md#强度分级`

### Step 3　归属　`[FL-01#S3]`

【读】`howto/consolidation-place.md#归属判定：写进哪个大类`

【做】判定写进哪个大类，再决定放哪个文件

【产出】目标大类 + 目标文件

【判据】放 `common/` 里有兜底理由；不属 `common/` 的有明确归属

【审】`howto/domain-routing.md`

### Step 4　归位　`[FL-01#S4]`

【读】`howto/consolidation-gate.md#入库三件套（缺一不可）` · `howto/consolidation-place.md#ID 规范`

【做】写入该大类的 `skills/`，分配 ID

【产出】新条目 + 分配的 ID

【判据】三件套（来源/证据/后果）齐全，缺一件即不合格

【审】`howto/consolidation-place.md#归位决策：放哪里`

### Step 5　重建索引　`[FL-01#S5]`

【读】`howto/loading.md#重建索引`

【做】`python3 scripts/index.py`（**必做**）

【产出】更新后的索引文件

【判据】`index.py --find <关键词>` 能找到新条目

【审】⛔ **本步最容易被跳过**——跳过后条目确实进了库，
但**定向加载找不到**，表现为"明明写过了却检索不到"。
这是静默失效，不报错。

### Step 6　分层复核　`[FL-01#S6]`

【读】`howto/loading.md#冷热分层`

【做】`python3 scripts/index.py --stats`，按建议调整 tier

【产出】tier 调整记录

【判据】`--stats` 无「该上浮却没上浮」的建议

【审】`howto/consolidation-place.md#冷热分层的诊断：0 命中到底是哪种`

### Step 7　归档草稿　`[FL-01#S7]`

【读】`howto/consolidation-practice.md#长会话：分段整合，别攒到最后`

【做】`bash scripts/archive.sh`

【产出】清空后的 `draft.md`

【判据】`draft.md` 为空，且内容已进库（能在索引里找到）

【审】`howto/consolidation-practice.md#静默 vs 确认`

### Step 8　报告　`[FL-01#S8]`

【读】`howto/consolidation-practice.md#整合量分档`

【做】输出**三类清单**，不是一段话

【产出】**三张表**：已验证 / 未验证 / 需人工确认

【判据】能区分「验证过没问题」和「根本没验证」

【审】`howto/consolidation-practice.md#改完必须重跑：改 A 引入 B 按最高级`

## 3. 参考实现

一次完整整合的最小命令序列：

```bash
python3 scripts/consolidate.py          # 查重报告
python3 scripts/index.py                # 重建索引（⛔ 不可省）
python3 scripts/index.py --stats        # 分层复核
bash scripts/archive.sh                 # 归档草稿
```

ⓘ 三张清单的模板见下方「报告的三类清单」。

## 4. 验收清单

- [ ] 每条草稿都过了第零道闸（事实已丢）
- [ ] 每条留下的都过了四道门槛
- [ ] 查重报告里没有未判定项
- [ ] 新条目有三件套 + ID
- [ ] ⚠ `index.py --find` 能找到新条目（**第 5 步**）
- [ ] `--stats` 无该上浮却没上浮的建议
- [ ] `draft.md` 已清空
- [ ] ⚠ 三张清单已输出，**没有混成一张表**

⛔ 不能"差不多整合完了"就过。

## 5. 常见返工

⚠ **跳过第 5 步重建索引** —— 条目进了库但定向加载找不到。
这是**静默失效**：不报错、不为空，只有到下次检索时才发现"我明明写过了"。

⚠ **三张清单混成一张表** —— 等于声称全部验证过。
读者无法区分「验证过没问题」和「根本没验证」。

⚠ **边干活边写库** —— 碎片化会让同一个坑在库里变成三条，
之后每次命中都命中到不同的那条，永远修不干净。

⚠ **长会话攒到最后整合** —— 攒多了以后四道门槛过不完，
最后变成"看着差不多就入库"。分段整合。

⚠ **改 A 引入 B 却只按 B 的级别报** —— 按**最高级**报，
否则引入的 P0 被当成 P2 处理掉了。

## 6. 下一步

→ 整合完成后走 [`archive.md`](archive.md)（`FL-05`）归档本轮草稿。
⛔ **先整合后归档**——归档会重置 `draft.md`，没整合就归档 = 本轮捕获永久丢失。

→ 整合完成后走 [`closed-loop.md`](closed-loop.md)（`FL-02` 闭环）：
审查 → 调整 → **回看建设册** → 两册互补。

**自审**：打开 `audit/rejection.md`，逐条过驳回清单。

## 7. 整体审核（流程级收尾）

ⓘ 各 Step 的【审】是**步骤级即时检查**；本节是**流程级复查**。
**两级都要走**——做完再看的视角不同。

- [ ] 逐条过 `audit/rejection.md`，每条说出"我们是怎么避免的"
  - ⛔ 不能"应该没这个问题"
- [ ] 步骤级【审】列过的条目**再过一遍**
- [ ] ⚠ 三张清单没有混成一张
- [ ] ⚠ 索引已重建（第 5 步）——**这是本流程最易失效的一步**
- [ ] 若本次整合涉及脚本改动 → ⚠ **还要跑 `lint.py --self-test`**：
      各部件合格 ≠ 拼起来能用

## 报告的三类清单（第 8 步必做）

**整合结束时必须输出三张表。没有这三张表，整合不算完成**——
读者无法区分「验证过没问题」和「根本没验证」。

### 表一：已验证（有实测 / 有证据）

| 条目 | 证据 | 结论 |
|---|---|---|

### 表二：未验证（有理由但没实测）

| 条目 | 为什么没验证 | 风险 |
|---|---|---|

### 表三：需人工确认（判断不了）

| 条目 | 卡在哪 | 需要谁定 |
|---|---|---|

⛔ **三张表不能合并**。合并等于声称全部验证过——
这正是"报告看起来很完整，但没人知道哪些是真的"的来源。
