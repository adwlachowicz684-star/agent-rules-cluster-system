# 召回：把已入库的找回来

> **流程 ID**：`FL-06`（**分配后不改**）
> **前置**：无（每次任务开始前都能跑）
> **本步交付**：当前任务该加载哪些技能，以及**为什么是这些**
> **对应**：做法 `howto/loading.md` · `howto/routing-signals.md` · 审核 `audit/self-verification-credibility.md`

> ⓘ **本流程是主链路的出口**：前面捕获 / 整合 / 归档 / 索引，
> 都是为了**这一刻能找回来**。找不回来，前面全白做。

ⓘ 七节顺序**固定**。

---

## 0. 交付物定义

跑完应该能**直接指认**：

1. 该加载的**具体文件**（不是"大概是某个区"）
2. 命中的**证据**（哪些关键词 / 信号命中了）
3. 没命中时的**结论**（真空白 / keywords 太窄 / 查法不对）

⚠ 第 3 条指认不出来 = 无法判断"没有"是不是真的没有。

---

## 1. 前置检查清单

- [ ] 索引是最新的（跑过 `index.py` 写入/重建）
- [ ] 知道自己要什么（**任务描述**，不是"随便看看"）
- [ ] ⚠ 区分「检索库里有没有」与「判定对象属于哪类」

⚠ 第 3 条：`--find` 是关键词匹配，判定归属要用**确定性扫描**
（见 `howto/routing-signals.md`）。两者混用是"查不到就新建"的主因。

---

## 2. 工序

### Step 1　先想清楚要什么　`[FL-06#S1]`

【读】当前任务描述

【做】抽出 **3~5 个原子词**（不是整句）

【产出】原子词清单

【判据】每个词单独拿出来**仍有区分度**（不是"流程""输出"这类泛词）

【审】⚠ 用整句去查必然 0 命中；用泛词去查命中一堆无关的。
**判据：这个词能区分"是它"和"不是它"吗？**

### Step 2　检索　`[FL-06#S2]`

【读】`howto/loading.md#关键词匹配的实操要点`

【做】`python3 scripts/index.py --find <原子词1> <原子词2> ...`

【产出】命中列表（含匹配度排序）

【判据】命中的前几条**确实与任务相关**

【审】⛔ **命中数不是越多越好**——排在后面的可能是"只命中一个泛词"

### Step 3　判定「没有」是哪一种　`[FL-06#S3]`

【读】`audit/self-verification-silent.md#十八`

【做】0 命中时，**先证明"查了"且"查法对"**：
换 2~3 个同义词再查一次

【产出】结论：**真空白** / **keywords 太窄** / **查法不对**

【判据】能说出是哪一种，并给出证据

【审】⛔ **查不到 ≠ 没有**。三种「0 命中」：

| 类型 | 怎么识别 | 怎么防 |
|---|---|---|
| **空转** | 索引为空 / 路径写错 → 扫到 0 个文件 | 先断言输入非空 |
| **误判** | 查"录像回放"判 0，实际有 `replay.md` | 用**原子词**再查 |
| **真空白** | 前两者排除后才成立 | — |

⚠ **本步是召回里最容易出错的一步**，也是整个引擎最常踩的坑。

### Step 4　补同义词（而不是判真空白）　`[FL-06#S4]`

【读】`howto/consolidation-place.md#冷热分层的诊断`

【做】若是 keywords 太窄 → 补同义词后**重查**

【产出】补词后的命中列表

【判据】补完能命中

【审】⛔ **不要直接判"库里没有"**——
误判成低频会让那条技能**永久冷藏**，等于丢了一条。

### Step 5　加载　`[FL-06#S5]`

【读】`howto/loading.md#整包加载 vs 片段加载`

【做】按命中加载：<200 行整包 / ≥200 行段落级

【产出】已加载的内容

【判据】加载的是**需要的那几节**，不是整个文件

【审】⚠ 常驻量有上限——**不要一次加载十份**

### Step 6　回热　`[FL-06#S6]`

【读】`howto/loading.md#计数与回热`

【做】命中计数 +1（冷藏的自动回热）

【产出】命中数更新

【判据】下次同样任务能排得更前

【审】⛔ **不回热 = 冷热分层失效**。
命中了却没计数，那条会一直被判"低频"。

### Step 7　用不上就留痕　`[FL-06#S7]`

【读】`howto/capture-signals.md`

【做】命中但**不好用**的内容 → 记进 `pending/draft.md`

【产出】一条捕获（"召回了但用不上"是重要信号）

【判据】下次整合时能知道"这条需要改"

【审】⛔ **召回了但没用上，是最容易被忽略的负反馈**。
不记的话，库里会一直留着"能检索到但没用"的条目。

## 3. 参考实现

```bash
# S2 检索（用原子词，不是整句）
python3 scripts/index.py --find 归档 草稿 整合

# S3 判定「没有」是哪一种（换同义词再查）
python3 scripts/index.py --find 存档 历史 收尾

# 确认索引本身是好的（空转检测）
python3 scripts/index.py --stats
python3 scripts/index.py --check      # 防漂移：索引 vs 磁盘
```

ⓘ `--stats` 显示技能包数量。**扫到 0 个包时它必须告警**，
否则"空集上跑出来的通过"没有意义（H011）。

## 4. 验收清单

- [ ] 用的是**原子词**，不是整句或泛词
- [ ] 命中的前几条确实相关（不是只命中泛词）
- [ ] ⛔ 0 命中时**换同义词再查过**（证明"查法对"）
- [ ] ⛔ 判"真空白"前排除了空转与误判
- [ ] 命中后计数 +1（回热）
- [ ] ⚠ 命中但不好用的已记入 `draft.md`

## 5. 常见返工

⚠ **用整句检索** —— 带引号整串做子串匹配**必然失败**。
判据：把词单独拿出来还有区分度吗？

⚠ **0 命中就判"库里没有"** —— 三种「0 命中」里只有一种是真空白。
直接判真空白 → 去新建一条**早已存在**的技能。

⚠ **命中了但不回热** —— 冷热分层失效，那条永远排不上来。

⚠ **命中了但没用上，也不记录** —— 最隐蔽的负反馈。
库里会一直留着"能检索到但没用"的条目，**没人知道它没用**。

⚠ **一次加载十份** —— 常驻量有上限。
判据：**这份不加载，任务会做错吗？**
