# flow/ 区总索引

> **本区性质：flow / 元规则（本区索引）。**


> **本区装「端到端流程」**：从头走到尾做完一件事。
> 与 `howto/`（可单独取用的做法）的区别见 `../common/split-two-books.md` 3.6。

---

## 一、本区的两类文件

| 类型 | `flow-type` | 是什么 | 受哪些检查 |
|---|---|---|---|
| **元规范** | `meta` | 讲「流程该怎么写」，本身不是流程 | 不检查 Step 五字段 |
| **具体流程** | `procedure` | 一个可照着走完的流程 | **检查**五字段 + 两级审核 + ID |

⚠ **必须区分**：元规范里必然**举例** Step（"流程文件七节模板"），
不区分的话，那些示例会被当成真步骤检查——**举例的模板永远不完整，
必然误报，而误报的检查会被关掉**。

判据：**这个文件是「讲怎么写」，还是「照着做」？**

> 只登记不写文件 → 报「登记了但文件不存在」。
> **两向都查**，否则索引会单向失真。

## 三、没有对应流程时怎么办

⛔ **不允许"没有流程就凭记忆开工"。**

套 [`skeleton.md`](skeleton.md) 的通用六步：

```
0 定边界 → 1 定契约 → 2 最小闭环 → 3 接外部 → 4 异常边界 → 5 验收
```

细化后的流程**应能映射回这六步**——映射不上的骨架步 = 该域的盲区
（要么补，要么显式说明"这是有意的"）。

## 四、新建一个流程

1. 复制 [`_template.md`](_template.md)（七节骨架已就位）
2. 分配下一个 `FL-xx`（**分配后不再改**，改了引用它的地方全成死链）
3. 在**本文件**第二节登记表里加一行
4. 跑 `python3 scripts/lint.py` 确认无 error

## 五、ID 规范

| ID | 形态 | 稳定性 |
|---|---|---|
| 流程 ID | `FL-01` `FL-02` | **分配后不改** |
| 节点 ID | `[FL-01#S3]` | **分配后不改**（流程工具按它记进度） |
| 全局块 ID | `GC-xx`（见 `../common/`） | **分配后不改** |

⚠ **ID 一改，进度就断了**——流程工具按它记录"哪个节点做完了"。
