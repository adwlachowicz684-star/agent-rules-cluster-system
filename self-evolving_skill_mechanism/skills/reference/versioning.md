# 版本分化协议

> **核心命题：不同环境有不同写法，这不是冲突，是分化。**
> 把"Python 3.8 用 A、3.12 用 B"当成冲突删掉一条，是最典型的误删。

## 为什么需要单独一套机制

原来的冲突消解规则是「语义冲突 → 留证据更强的那条」。
这条规则有个致命前提：**两条必须在同一环境下竞争**。
但 `py3.8 用 X` 和 `py3.12 用 Y` 根本不在同一环境生效——它们都对。

**误判的代价**：删掉一条 → 下次在另一个环境里，技能库给出错误写法。
这比留着两条冗余严重得多。

## 判定流程

```
两条内容相似（疑似冲突）
   ↓
先问：它们的适用环境重叠吗？
   ├─ 不重叠 → **版本分化**，两条都留，标注各自 applies_to
   └─ 重叠   → 真冲突，才走「留证据更强的」消解
```

**宁可判成"不重叠"多留两条，也不误判成冲突删掉一条。**

## 约束写法 `applies_to`

| 写法 | 含义 |
|---|---|
| 空 / `-` / `*` | 通用，任何环境 |
| `python>=3.9` | Python 3.9 及以上 |
| `python<3.9` | Python 3.9 以下 |
| `python>=3.8,python<4` | 区间（逗号=且） |
| `os:linux` / `os:darwin` / `os:windows` | 操作系统 |
| `shell:bash` / `shell:cmd` | Shell 类型 |
| `rg` / `!rg` | 需要（不需要）某工具 |

多个条件用逗号或分号分隔，**全部满足才算匹配**。

## 命令

```bash
python3 scripts/env.py                          查看当前环境
python3 scripts/env.py --check "python>=3.9"    检查约束（退出码 0=适用）
python3 scripts/env.py --json                   输出 JSON
```

## 在库里的呈现

命令库加「适用环境」列，**同一场景按环境拆成多行**：

| ID | 场景 | 命令 | 适用环境 |
|----|------|------|---------|
| C006 | 跨文件批量替换 | `rg -l '旧串' DIR \| xargs sed -i 's/旧串/新串/g'` | os:linux |
| C047 | 跨文件批量替换 | `rg -l '旧串' DIR \| xargs sed -i '' 's/旧串/新串/g'` | os:darwin |
| C050 | 合并字典 | `z = a \| b` | python>=3.9 |
| C051 | 合并字典 | `z = {**a, **b}` | python<3.9 |

**检索时自动按当前环境过滤/优先**——在 Linux 上不会给你 macOS 的 sed 写法。

## 领域包的版本分化

整包因环境而异时，在 frontmatter 标注：

```yaml
---
id: D010
name: 异步任务处理
applies_to: python>=3.11      # 整包仅适用于 3.11+
---
```

包内局部有差异时，用**分节**而非分文件：

```markdown
### 步骤 3：创建任务

**python>=3.11**：用 `asyncio.TaskGroup`
**python<3.11**：用 `asyncio.gather`，注意异常需手动收集
```

## 与「违反即升级」的关系

如果某条带 `applies_to` 的规则在当前环境下被违反，
先确认**环境探测是否正确**——约束没写对会让技能在该生效时不生效。

| 现象 | 诊断 |
|---|---|
| 技能没被加载 | `applies_to` 是否写太严？环境探测准吗？ |
| 加载了但写法不对 | 约束是否漏标？该拆成两条？ |
| 两个环境都给同一写法 | 可能只存了一条，另一条被当冲突删了 |

## 反模式

| ❌ | ✅ |
|---|---|
| 把版本差异当冲突删一条 | 判定环境不重叠 → 两条都留 |
| 命令里写死单一环境写法 | 按环境拆行，标注 `applies_to` |
| 用注释说明"mac 上要改" | 拆成独立条目，可被检索到 |
| 约束写太严导致技能永不加载 | 只在确有差异时才加约束 |
| 时效性信息写进正文 | 旧写法移入 `deprecated/` |
