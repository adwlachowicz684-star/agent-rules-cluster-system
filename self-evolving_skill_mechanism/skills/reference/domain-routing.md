# 大类路由协议

> 配套机制：项目文件夹通过 **junction / 软链接** 接入某个大类文件夹，
> 大类文件夹内含 `agents/` `skills/` `rules/` 三个子目录。
> 技能按归属写入对应大类的 `skills/`。

## 目录结构

```
<大类根目录>/                      （config.yaml 的 root，如 ~/.ai/domains）
├── INDEX.md                      全局总索引（自动生成）
├── _common/                      通用大类：跨领域技能
│   ├── agents/  skills/  rules/
├── 法律/
│   ├── _common → ../_common      ← junction，让进入本大类也能访问通用
│   ├── agents/  skills/  rules/
├── 开发/
├── 教育/
├── 美术/
├── 小说创作/
└── ...
```

项目侧：

```
项目A/
├── .ai → junction → <root>/法律      ← 一次性接入
│   ├── _common/                       ← 链接传递，通用技能可见
│   ├── agents/  skills/  rules/
└── （项目自己的文件）
```

**为什么每个大类内要 junction 到 `_common`**：
一次只能接入一个大类，但通用技能（文件交付、调试流程）任何项目都要用。
没有这条链接，进法律项目就看不到通用技能，只能逐类复制——那就失去了集中管理的意义。

## 归属判定：写进哪个大类

### 判定顺序（四问，从强信号到弱信号）

**一问：这条换个大类还成立吗？**
成立 → `_common`。不成立 → 继续。
> "产物 ≥5 个打包 zip" 在法律、开发、教育项目里都一样 → `_common`

**二问：当前项目接入的是哪个大类？**
这是**最强信号**。项目的方向就是技能的默认方向。
> 法律项目里学到的"合同审查流程" → 归 `法律`，除非它明显是通用的

**三问：关键词命中哪个大类？**
```bash
python3 scripts/domain.py --route "合同审查与风险点标注流程"
```
输出候选与置信度。**推荐不等于自动写入**——归错类比不归更糟。

**四问：是领域技能还是领域知识？**
| | 领域技能 ✅ → `skills/` | 领域知识 ❌ → `rules/` 或知识库 |
|---|---|---|
| 法律 | 合同审查的操作流程 | 民法典第几条写了什么 |
| 开发 | 调试报错的方法论 | 某个 API 的参数说明 |
| 医疗 | 病历结构化流程 | 某种病的临床表现 |

**技能库只收"怎么用知识干活"，不收"知识本身"。**

### 置信度规则

| 情况 | 处理 |
|---|---|
| 唯一候选 | 直接推荐（命中 1 词时标注"建议确认"） |
| 分差 ≥2 | 推荐高分者 |
| 分差 1 | 提示两个候选，人工判断 |
| 零命中 | 归 `_common` |
| 当前大类在候选中 | **加权 +1**（项目方向优先） |

## 写入流程

```bash
# 1. 探测当前项目的大类
python3 scripts/domain.py --detect

# 2. 推荐归属（拿不准时）
python3 scripts/domain.py --route "<技能描述>"

# 3. 写入指定大类
python3 scripts/index.py --add <文件>.md --domain legal

# 4. 重建全局索引
python3 scripts/index.py
```

**补充 vs 新建**：目标大类已有同类技能文件时，
`--add` 会提示"已存在同名文件"——此时应**编辑已有文件、追加到对应段落**，
不要新建重复包。追加优先于新建（见 `consolidation.md`）。

## 加载流程（改造后）

```
任务开始
  │
  ├─ 1. python3 scripts/domain.py --detect → 得知当前大类
  │
  ├─ 2. 读 <root>/INDEX.md
  │     ① 先在当前大类的分组里找
  │     ② 没命中 → 查 _common 分组
  │     ③ 还没有 → 不加载，直接开工
  │
  ├─ 3. 命中 → 整包加载该技能文件
  │
  └─ 4. 用到 → python3 scripts/index.py --find <关键词>（计数 + 回热）
```

**绝对路径访问**：项目虽只 junction 到某个大类，
但 AI 仍可用绝对路径读 `<root>/INDEX.md` 和其他大类——junction 限制的是项目视图，不是 AI 的视野。

## 跨大类引用

技能可以引用其他大类的技能，用 `related` 字段标注：

```yaml
related: [D001, LAW-R003]     # D001 在 _common，LAW-R003 在法律
```

引用时不复制内容，只记 ID + 大类，加载时按 ID 到全局索引里找。

## 新增大类

编辑 `config.yaml` 的 `domains` 段：

```yaml
domains:
  psychology:
    name: 心理
    desc: 心理咨询、评估、干预
    keywords: [咨询, 评估, 干预, 量表, 情绪, 认知, 来访者]
```

然后：
```bash
python3 scripts/domain.py --init        # 建目录 + 通用链接
```

**关键词要写全同义词**，这是召回率的关键。宁多勿少。

## 反模式

| ❌ 不要 | 后果 | ✅ 应该 |
|---|---|---|
| 写进项目文件夹 | 项目删了技能就没了 | 写进大类根目录真实路径 |
| 写进 junction 虚拟路径 | 链接切换后丢失 | 同上（junction 透明，但显式写真实路径更安全） |
| 每个大类复制一份通用技能 | 改一处要改 N 处 | 放 `_common`，靠链接访问 |
| 全自动归属不确认 | 归错类比不归更糟 | 推荐 + 人工确认 |
| 把领域知识塞进 skills/ | 技能库变成资料堆 | 领域知识进 `rules/` 或知识库 |
| 大类分太细 | 一个技能不知道归哪 | 先粗后细，用熟了再拆 |

## 接入检查清单

新项目接入时逐项确认：

- [ ] `python3 scripts/domain.py --link <key> <项目路径>` 已执行
- [ ] 项目内 `<link_name>/skills` 可见
- [ ] 项目内 `<link_name>/_common/skills` 可见（通用技能）
- [ ] `python3 scripts/domain.py --detect` 能正确识别大类
- [ ] 新技能会归到正确大类（用 `--route` 验证一次）
