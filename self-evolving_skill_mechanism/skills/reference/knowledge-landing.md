# 知识点落地协议

> 一句话：**没落到流程步骤上的知识点，等于没写。**

## 为什么单列一节

技能库最常见的腐烂方式不是写错，而是**堆了一堆正确但无用的话**。

「要注意边界条件」「性能很重要」「应当谨慎处理异常」——这些都对，
但读完以后**行为不会有任何改变**。它们占用了上下文，却没改变任何一步动作，
是纯负债。

判据很简单：

> **一个知识点写进 skill 后，它改变了哪个流程的哪一步？**
> 答不出来 → 流于理论 → 改写或删除。

## 三种流于理论的典型

| 形态 | 长什么样 | 为什么没用 |
|---|---|---|
| **口号式** | 「要注意边界条件」「谨慎处理」 | 没说边界是什么、怎么判、判了怎么办 |
| **认知式** | 「理解 X 的原理对排查很有帮助」 | 原理不改变动作，只改变心情 |
| **孤立式** | 写在了「注意事项」里，但流程中没有任何一步引用它 | 执行时根本不会走到那儿 |

**孤立式最隐蔽**。它看起来最像正经内容——有标题、有条目、甚至有 id，
但流程从头跑到尾都不会碰到它。检查方法见下方「反向检索」。

## 落地四问（写每条前过一遍）

1. **落在哪一步？** — 具体到「哪个流程的第几步」，不能是「相关流程」
2. **改成什么？** — 写出改后那一步的措辞。写不出 → 说明还没想清楚
3. **可执行吗？** — 能写成命令、判据、或可判定的检查项吗？能就写
4. **谁会发现违反？** — 违反时是脚本报错、还是靠自觉？能脚本化就脚本化

四问全过 → 落地。任一不过 → 继续改，或承认它不值得入库。

## 落地强度（从强到弱，优先用强的）

| 强度 | 形式 | 例 |
|---|---|---|
| ★★★ | **脚本/命令自动执行** | `python3 scripts/lint.py` 自动查出 |
| ★★☆ | **流程里某一步的判据** | 「第 3 步：逐项确认 路径存在 / 编码 utf-8 / 依赖已装」 |
| ★☆☆ | **可判定的检查项** | 「改前先 read 原文件」——做没做一眼能看出 |
| ☆☆☆ | 陈述性描述 | 「要注意一致性」 ← **不合格，不许停在这一点** |

**强度 ≤ ★☆☆ 的条目，必须在流程里有对应步骤**，否则就是孤立知识点。

## 反例 → 正例

| ❌ 流于理论 | ✅ 落地到流程 |
|---|---|
| 注意边界条件 | 第 2 步后加判据：上界先 `clamp` 到有限值，再进循环 |
| 处理异常要谨慎 | 文件不存在 → 提示用户并给出创建命令；编码错 → 换 utf-8 重试一次 |
| 性能很重要 | 循环内禁止 `filter/map` 调全量扫描方法；超 1e4 条改索引 |
| 保持术语一致 | 全文统一用「端点」；`reference/` 建术语表，写完 grep 一遍旧词 |
| 重要操作要确认 | 删除 / 覆写 / 推送前，先输出待操作清单，等显式确认 |
| 注意依赖 | 技能包开头写前置依赖 + 装命令 + 不满足时的降级方案 |

## 反向检索：怎么发现孤立知识点

写完技能后跑一遍，**确认每个知识点都被流程引用**：

```bash
# 1. 列出所有「注意事项 / 已知坑 / 要点」里的条目
rg -n '^[-|]' skills/<包>.md | rg '注意|坑|要点|应当|应该'

# 2. 逐条拿关键词回查「完整流程」段，看有没有被引用
rg -n '<关键词>' skills/<包>.md

# 3. 一条都没被引用的 → 孤立，改写进流程或删除
```

**自动化版本**（`python3 scripts/lint.py` 的 `orphan-knowledge` 检查项）：
扫描所有技能包，找出「注意事项类段落里的条目」在「流程段」中零引用的，列为预警。

## 与「操作命令化」的关系

「操作必须命令化」管的是**动作怎么表达**；
本节管的是**知识点有没有落点**。两者是两道不同的关：

| | 管什么 | 典型病症 |
|---|---|---|
| 命令化 | 动作是否可执行 | 用散文描述「先…然后…再…」 |
| 落地（本节） | 知识是否改变行为 | 写了但流程不引用，行为零变化 |

一条知识点可以**命令化得很好但仍然孤立**——
比如把「谨慎处理异常」写成了命令，但流程里没有任何一步会走到它。
所以它必须先过本节，再过命令化。

## 自检（写完技能后 30 秒）

- [ ] 每个「注意事项」条目，都能指出它在流程第几步被用到
- [ ] 没有「要注意 X」这种没给判据的条目
- [ ] 新增的知识点，是否让某个流程步骤的措辞变了？没变 → 没落地
- [ ] `python3 scripts/lint.py` 的 orphan-knowledge 无预警
- [ ] 强度 ≤ ★☆☆ 的条目，是否都挂到了流程步骤上

## 变更溯源

改了知识点落地方式也要记一行：

```bash
python3 scripts/note.py "H015" 补充 "知识点未落流程，执行时走不到" --src 反哺
```
