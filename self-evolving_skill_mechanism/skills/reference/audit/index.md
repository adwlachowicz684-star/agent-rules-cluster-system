## ⛔ 按症状接入：你看到了什么

⛔ **本区入口按"症状"，不按"动作"**——来查错的人手上有的
是一个**现象**（检查全绿但问题还在），不是一个动作。

| 你看到什么现象 | 查哪份 | 典型条目 |
|---|---|---|
| **检查全绿，但问题还在** | [静默类](self-verification-silent.md) | 一、检查项必须能红<br>七、新建设施必须配接入率检查<br>十八、查不到 ≠ 没有 |
| **报了一堆，但都是误报** | [误报类](self-verification-falsepos.md) | 十、认「等价的正确写法」<br>十四、看语义方向不看表面特征<br>三十一、别把引用行自己当证据 |
| **信号有了，但不知真假** | [可信度类](self-verification-credibility.md) | 三、三态不要二态<br>五、标注字段必须可回填<br>二十二、自检全绿 ≠ 覆盖历史缺陷 |
| **这条该不该入库** | [驳回清单](rejection.md) | 证据不足 / 一次性的 / 描述性赞美的 |
| **审一个 skill 哪里不行** | [反模式与最佳实践](anti-patterns.md) | 二、描述与触发（最关键）<br>三、步骤精确性（最容易犯） |
| **要写一份反模式清单** | [清单形态](antipattern-form.md) | 误解类 / 遗漏类 / **坑类** |
| **不知道三册该查哪册** | [自检协议（索引）](self-verification.md) | 三册分工 + 落地强度对照 |

## ⛔ 三册自检协议怎么选

```
问题出在哪一层？
├─ 检查压根没在查（跑得绿但没验证）  → silent   静默类
├─ 在查，但判据不准（误报/漏报）     → falsepos 误报类
└─ 判据对，但结论真假难辨            → credibility 可信度类
```

⛔ 三册是**按失效位置**分的，不是按主题分的。
按主题找会同时命中三册，读的人反而更困惑。

## ⛔ 入口形态由用法类型决定

本区是"**怎么查错**" ⇒ 入口按**症状**（我看到了什么）。
对照另外三区：

| 区 | 用法 | 入口形态 | 提问方式 |
|---|---|---|---|
| **howto** | 怎么做 | **按动作** | 我在做什么？ |
| **audit** | 怎么查错 | **按症状** | 我看到了什么现象？ |
| **craft** | 什么算好 | **按犹豫** | 我在纠结什么？ |
| **flow** | 按什么顺序做 | **按场景** | 我在什么情况？ |

⇒ 判据：**读的人来这一层时，手上已经有什么？**
按那个东西组织入口。详见 `howto/index.md` 同名章节。
