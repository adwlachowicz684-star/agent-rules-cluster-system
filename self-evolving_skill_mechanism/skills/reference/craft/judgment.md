# 尺度与取舍

> **本区性质：craft / 品位与技巧。**
> 讲「多少算够、冲突时选哪个、什么时候该停」。
> 什么算好见 [`taste.md`](taste.md)；具体手法见 [`techniques.md`](techniques.md)。

---

## 一、为什么单独一层

`howto/` 教你**怎么做完**，`audit/` 告诉你**哪里不行**，
`taste.md` 告诉你**什么算好**——但三者都回答不了一个问题：

```
两个都对的东西冲突时，选哪个？做到什么程度该停？
```

这不是"怎么做"的问题，也不是"对不对"的问题，
是**程度**的问题。没有这一层，会出现两种典型偏差：

| 偏差 | 表现 | 来源 |
|---|---|---|
| **过度** | 每条规则都配三件套、样例、反例，写到没人读 | 把"写全"理解成"无上限" |
| **不足** | 一句"要注意 X"就当写过了 | 把"精简"理解成"不展开" |

ⓘ **本层是「好」与「对」之间的校准器**：
`taste.md` 定标准，本文定**度**。

## 二、总判据：**改一个字会怎样**

拿不准"多少算够"时问一句：

> **再改一个字，读它的人会做出不同的决定吗？**

| 答案 | 结论 |
|---|---|
| 会 | 还**没写够**，继续 |
| 不会 | 已经**够了**，停 |

⛔ 不要用"字多不多"判断——**长不等于啰嗦，短不等于精炼**。
一段 200 字的排查步骤可能是精确的；
一句"检查边界条件"可能是废话。

**判据是「信息量」，不是「字数」。**

## 三、四组常见冲突（没有标准答案，只有取舍原则）

### ① 写全 vs 精简

用户偏好 F002 明确「宁可写全写详细，不要为精简牺牲完整性」。
但**写全不是无限写**——它的边界是：

```
⛔ 不该省的：来源、证据、后果、判据、反例
✅ 该省的：同义复述、客套、把判据换个说法再说一遍
```

⚠ **最常见的"伪写全"**：同一条判据在正文、表格、自检清单里各写一遍。
三处一旦不同步，读的人不知道该信哪个——**这比只写一遍更糟**。

**判据：三处里有一处改了，另外两处会自动跟着改吗？**
不会 → 说明它们本该是一处（留指针）。

### ② 拆分 vs 合并

| 拆 | 合 |
|---|---|
| 各部分**独立可查** | 必须**整体对照**才有用 |
| 单独加载能读懂 | 拆了要来回翻 |
| 更新频率不同 | 总是一起改 |

**判据：能不能举出"只读其中一份就够了"的场景？**
能 → 拆；不能 → 合。

⚠ **为了指标拆是最常见的错**：文件超限就机械地切成两半，
结果两半都读不完整。**拆分的目的是"按需加载"，不是"降低行数"**。

### ③ 自动化 vs 人工

能自动查的一定要自动查（`self-verification` 第十九条）。
但**不是所有判据都能自动化**：

| 能自动查 | 不能（至少暂时不能） |
|---|---|
| 死链、重复、字段缺失、ID 冲突 | 「这条判据写得对不对」 |
| 格式违规、体积超限 | 「这个分类合不合理」 |

⛔ **不要为了"全自动化"把不能自动查的判据硬写成能查的**——
硬写的判据必然误报，而**误报的检查会被关掉**。

**判据：这条判据误报的代价多大？** 大到无法接受 → 留人工，标清楚。

### ④ 现在做 vs 记下来

| 现在做 | 记 backlog |
|---|---|
| **静默**失效（假绿 / 漏报 / 覆盖） | 可见的瑕疵 |
| 会导致**错误决策** | 只是不好用 |
| 影响**已入库内容**的正确性 | 只影响效率 |

⚠ **排序错了的代价**：先修"不好用"而放着"假绿"不管，
等于把工具打磨得很好用，只是它**一直在说谎**。

## 四、什么时候该停（四条）

**① 陌生人能照做** —— `taste.md` 的总判据，达到了就停。

**② 反面用例写出来了** —— 能说清"什么情况会失效"，
说明你真的理解了这条规则；说不出 → 还没想透，继续想不是继续写。

**③ 自检清单能列出** —— 列不出"我怎么知道做对了"，
说明这条规则本身不可验证。**不可验证的规则不该入库**。

**④ 再写就是换个说法重复** —— 立刻停。
重复不会增加说服力，只会**增加不同步的风险**。

## 五、过度与不足的信号

| 信号 | 说明 |
|---|---|
| 一份文档三年没人动，但每次都要读 | **过度**：它已经变成了仪式 |
| 有人照做还是做错 | **不足**：缺了关键一步，不是"他没认真" |
| 自检清单全是"检查有没有…" | **不足**：只有动作没有判据 |
| 同一条改了三次还在改 | **过度或不足**：先判是哪种，别一直微调 |

⚠ **"有人照做还是做错"是不足的最强信号**——
不要归因为执行者的问题。判据写对了，陌生人就该能做对。
