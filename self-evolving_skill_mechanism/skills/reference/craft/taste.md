# 品位：什么算「好」

> **本区性质：craft / 品位层。**
> 判据与归属见 `../common/split-two-books.md` 第四节。
> 与 howto（怎么做）的区别：**howto 教你怎么做完，本区告诉你做完的东西好不好。**

---

## 一、为什么单独一层

howto 回答"怎么做"，audit 回答"哪里不行"。
**但这两者之间还有一层是空的**：

```
howto    教你怎么做完          → 照做能产出
audit    告诉你哪里不行        → 能挑出毛病
─────────────────────────────────────────
craft    告诉你什么算好        → 没有它，你只会"做完"和"没毛病"，
                                 不知道"好"长什么样
```

**没毛病 ≠ 好。** 一份文档可以既不违反任何 audit 判据，
又完全不好用——例：每条规则都格式正确、来源明确、后果具体，
但没有一条是你真正会遇到的情况。

audit 是下限（不许坏），craft 是上限（要好）。
只做 audit 会得到"合格的平庸"。

## 二、总判据：陌生人测试

**唯一的核心判据**：

> 一个**不认识你、没参与过上下文**的人，只看这一个文件，
> 能不能照着干成活？

这是核心原则 ③「细节写全，按需加载」的可检验形式。
四个可查的推论：

| 推论 | 查法 |
|---|---|
| **不用猜** | 有没有"酌情""适当""视情况"这类要读者自己决定的词？ |
| **不用问** | 有没有"看情况""问用户"这种把判断推回去的表述？ |
| **不用翻** | 有没有指向别处的指针是**活的时候才需要**的？ |
| **能验证** | 做完了怎么知道做对了？有没有验收动作？ |

## 三、内容品位：四条

### 1. 写正确的废话 = 没写

```
✗ 「要注意性能问题」
✗ 「应当合理使用缓存」
✗ 「注意边界情况」
```

判据：**它改变了哪个流程的哪一步？** 答不出来 → 改写或删除。
`lint.py` 会自动报孤立知识点（`howto/knowledge-landing.md`）。

### 2. 反例比正例更值钱

只写"应该这样做"，读者不知道"不这样会怎样"，
于是遇到模糊地带时倾向跳过。

**带反例的写法**：不要 X，因为 Y 情况下会 Z。
`audit/anti-patterns.md` 有统一的反例格式。

### 3. 排除条件和命中条件一样重要

```
✗ 「用 has() 查对象池」         —— 漏掉只有重复拦截的池
✓ 「用 has() 查归属；**但**若池本身用 has() 做重复归还拦截，
     两者语义相反，按 has() 写判据会漏」
```

**只写命中条件的判据必然误报**——而误报会让整份文档被忽略。
（来源：`audit/self-verification.md` 第十四条）

### 4. 数字要带来源，来源要能复核

```
✗ 「体积超过 300 行就该拆」
✓ 「超过上限（reference 400 行，见 config.yaml）
     → lint.py 会在 80% 处提前预警」
```

**没有来源的数字无法在前提变化时更新**——
下次上限改了，没人知道文档里这个 300 也要跟着改。

## 四、表达品位：三条

### 1. 命令化优于散文

```
✗ 「先检查一下配置，然后跑一次同步，最后确认结果」
✓ python3 scripts/lint.py --self-test && python3 scripts/consolidate.py --self-test
```

判据：技能里出现「先…然后…再…」就该抽命令了（核心原则 ④）。
好处三重叠：省思考、省上下文、保证每次一致。

### 2. 一行能说完的不要分点

分点会让读者以为是并列关系。
**有因果 / 时间顺序的用句子，真正并列的才用列表。**

### 3. 标题是给"扫读的人"看的

读者第一次是**扫标题**决定要不要读正文。
标题写「说明」= 逼他读正文才知道是什么。

```
✗ ## 补充说明
✓ ## 为什么 80% 处要预警而不是等超限
```

## 五、结构品位：两条

### 1. 一个文件一个主题

判据：**能不能用一句话说清这个文件解决什么问题？**
说不清 → 里面塞了多个主题，该拆。

`lint.py` 会在 `##` 章节 >12 时提示拆分。

### 2. 常驻层只放"每次都要付的东西"

常驻层（SKILL.md / rules / SKILLS）每次任务都占上下文。
**放进去的每一行的判据：每次都会用到吗？**
答不出来就下沉到按需层。

**常驻层不能声明体积豁免**——理由再充分也不能让它不占。

## 六、自检（30 秒）

- [ ] 陌生人只看这一个文件，能干成活吗？
- [ ] 有没有"酌情""视情况""问用户"？有 → 改成具体判据
- [ ] 排除条件写了吗？（只写命中条件 = 必然误报）
- [ ] 数字带来源了吗？来源能复核吗？
- [ ] 标题能让扫读的人决定要不要读吗？
- [ ] 一句话说得清这个文件解决什么问题吗？
- [ ] 常驻层的每一行，每次都会用到吗？
