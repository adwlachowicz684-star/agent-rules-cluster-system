# 填充计划

本 skill 当前是**占位壳子**。这份文件记录要填什么、按什么顺序填、
以及为什么暂时不填。

## 为什么先留空

本地化流程**高度依赖实际项目形态**：

- 独立游戏（几个语言、开发者自己管）
- 中大型项目（十几个语言、外包翻译、有本地化经理）
- 持续更新的长线运营（每次版本增量翻译）

这三类的流程完全不同。**在没有真实项目形态之前写流程，写出来的一定是错的**，
而错误的流程会被当标准执行，比没有更糟。

所以现在只定结构与分工，等 Godot 大型项目开发推进到需要多语言时，
按真实需求填。

## 待填清单

按依赖顺序排，前面的没定后面做不了：

### P0 — 地基（先定，否则后面全乱）

| 主题 | 内容 | 为什么先做 |
|---|---|---|
| **Key 规范** | 命名规则、层级、禁止用原文当 key | 改一次 key = 改所有引用和所有语言的表 |
| **单一数据源** | 文案放哪（CSV / 表格 / TMS）、谁改、怎么合并 | 多处维护必然不同步 |
| **变量与插值** | 占位符格式（`{n}` vs `%s`）、复数规则、性别/格变化 | 翻译时最容易出错的地方 |
| **不该翻译的** | 内部 ID、存档 key、日志、配置值 | 翻了会导致存档/配置错乱 |

### P1 — 流程

| 主题 | 内容 |
|---|---|
| 翻译工作流 | 提取 → 派发 → 回收 → 导入 → 验证 的完整链路 |
| 术语表 | 怎么建、怎么同步给译者、专有名词处理 |
| 机器翻译 | 什么时候可用、什么时候必须人工、后编辑流程 |
| 上下文提供 | 译者看不到界面怎么办（截图、注释、字符限制说明） |

### P2 — 质量

| 主题 | 内容 |
|---|---|
| 伪本地化 | 用伪翻译测溢出和漏翻的具体做法 |
| 翻译 QA | 术语一致性、占位符完整性、长度、编码、截断 |
| 母语者验收 | 怎么组织、查什么 |

### P3 — 工程

| 主题 | 内容 |
|---|---|
| 版本同步 | 增量翻译、新增 key 的下发、删 key 的清理 |
| 工具链 | 提取脚本、格式转换、与 TMS 对接 |
| 各引擎适配 | Godot / Unity / Unreal 各自的坑 |

## 与开发技能的接口

技术实现（引擎 API 层）**不在本 skill 重复写**：

- Godot 4.x → `game-dev/references/godot/i18n.md`
- 其它引擎 → 各开发技能对应文件

本 skill 引用它们，不复制。改引擎 API 去开发技能改。

## 填充时的原则

1. **先有真实需求再写** —— 不臆造流程
2. **每条都要能落地** —— 说不出"谁在什么时候做什么"的不写
3. **标注适用规模** —— 独立游戏的做法和中大型项目不同，别混着写
4. **有反例** —— 光说"应该怎么做"没用，要说"不这么做会怎样"
