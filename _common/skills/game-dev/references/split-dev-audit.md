# 开发 skill 与审查 skill 的信息分工

同目录下的 `code-audit`（审查）与本 skill（开发）会涉及**大量相同的 API**。
必须有一条明确的切割线，否则两份文档会互相抄，最后都变成半吊子。

## 切割标准：读者在什么状态下需要它

| 状态 | 用哪个 | 句式 | 产出形态 |
|---|---|---|---|
| 「我要实现 X，不知道怎么做」 | **game-dev** | 要实现 X，用 Y，像这样 | 可抄的完整代码块 |
| 「我写完了，想知道有没有坑」 | **code-audit** | 如果出现 Z，说明错了 | 判据 + 级别 + 确认方法 |

**同一条知识的两个面**，不是两份拷贝：

| API | game-dev 写什么 | code-audit 写什么 |
|---|---|---|
| `move_and_slide()` | 角色移动标准模板（含 velocity、重力累加、is_on_floor 判定） | `move_and_slide(...)` 带参 → P0（3.x 残留） |
| `create_tween()` | 保存引用 + 重启前 kill 的模板 | GD02 未保存引用 → P0 |
| `FileAccess` | 存档读写完整例子（user://、判 null、close） | GD41 未 close → P1；GD43 写 res:// → P1 |
| `remove_child` | 对象池/销毁两种去向的写法 | GD01 后无释放 → P0 |

## 格式必须有区别（不能"一样的知识写两遍"）

| | game-dev | code-audit |
|---|---|---|
| 组织单位 | **任务**（实现角色移动 / 做存档 / 做 UI） | **风险面 / 规则 ID** |
| 内容重心 | 正确写法、选型依据、参数含义 | 错误特征、定级、误报排除 |
| 代码块 | 完整可运行，能直接抄 | 只给反例片段 + 一行修复 |
| 检索方式 | 「我要做什么」→ 方案 | 「代码里出现什么」→ 判据 |
| 是否判级别 | 否 | 是（P0/P1/P2） |

**为什么必须有区别**：开发时要"能抄"，审查时要"能判"。
把判据塞进开发文档，写代码的人要在一堆"如果…就错了"里找正确写法；
把模板塞进审查文档，审查的人要在代码块里找特征字符串。两边都变难用。

## 三类信息的归属

### 只在 game-dev（审查不会有）

- **选型决策树**：CharacterBody 还是 RigidBody、Timer 节点还是 SceneTreeTimer
- **项目结构约定**：目录怎么放、场景怎么组织
- **完整可运行示例**：带上下文，不是片段
- **迁移步骤**：3.x → 4.x 怎么一步步改
- **性能预算与取舍**：为什么这么选

### 只在 code-audit（开发不会有）

- 静态判据正则、规则 ID、级别
- 确认/验证方法（怎么证明它真错了）
- 误报排除清单
- 扫描器实现

### 两边都要，但格式不同（交叉引用，不复制）

生命周期、资源、Tween/Timer、信号、IO、物理、UI、3D —— 这些**高频且易错**，
开发要给出正确写法，审查要能识别错误。

**规则：单边维护 + 互相指向。**

- game-dev 里：给正确模板，末尾写「⚠ 漏了会被 `code-audit` 的 GD02 抓」
- code-audit 里：给判据，末尾写「正确写法见 `game-dev` 的 xxx 节」

这样改一处不会漂移。若两边都写一遍完整内容，改的时候必然只改一处，
另一处就过期——这正是本仓库反复出现的「文档与实现不一致」。

## 路由差异

| | code-audit | game-dev |
|---|---|---|
| 输入 | 现有代码库 | 用户想实现什么 |
| 路由维度 | **风险面**（代码里有什么风险） | **引擎 + 功能域**（要做什么功能） |
| 路由依据 | 扫源码找特征 | 引擎配置文件 + 用户诉求 |
| 输出 | 场景列表 → 加载判据 | 引擎包 + 功能域 → 加载方案 |

开发路由是**二维**的：先定引擎（project.godot → Godot），再定功能域
（角色控制 / UI / 存档 / 动画 / 音频 / 3D / 网络）。

## 新增引擎时两边要一起动

| 步骤 | code-audit | game-dev |
|---|---|---|
| 1 | 建 `p-<引擎>.md` 判据 | 建 `<引擎>/` 开发包 |
| 2 | 写扫描器 + 自检 | 写任务模板 |
| 3 | 接 `code-audit/scripts/route.py` 信号 | 接 `game-dev/scripts/dev-route.py` 信号 |
| 4 | 补 fixture | 补示例 |

**只做一边 = 该引擎半接线**：能审但不知道怎么写，或能写但审不出来。
本仓库已出现过三次这类失效（新增语言包没接路由信号），别再犯。
