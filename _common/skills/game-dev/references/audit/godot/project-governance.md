# project-governance — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/project-governance.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 性能预算写"60 FPS" | 要目标硬件×画质×场景×稳定态指标 |
| 2 | 只看平均 FPS | 泄漏与低频卡顿藏在均值后，要看 P95/P99 |
| 3 | Profiler 开着测发布预算 | 测量本身有开销，结果不可用 |
| 4 | Profiler 能测 C# | 不支持，要用 Rider/dotTrace |
| 5 | release 包读 Performance 监视器 | 部分恒返回 0，且有些每秒才更新 |
| 6 | headless 能代表渲染性能 | 只适合逻辑/加载/内存/服务器回归 |
| 7 | 帧率不到 60 就是脚本慢 | 帧时间含渲染，物理/粒子/音频都可能 |
| 8 | CI 单次采样判定 | 要 warm-up + N 样本 + 均值/P95/P99 |
| 9 | 今天快 1% 算优化有效 | 测量有抖动，要固定条件与 retest |
| 10 | 优化 PR 不用附基线数据 | 没有数据不得标为性能修复 |
| 11 | 模板版本号相同就行 | 还要 stable/beta、标准/.NET、平台、架构、符号 |
| 12 | 预设名不用加引号 | 空格与大小写必须完全一致 |
| 13 | version 字段当构建号 | 营销版本与构建号要分开 |
| 14 | 密钥写进 export_presets.cfg | 只在 CI secret |
| 15 | debug_symbols 默认就够 | 默认 no，崩溃堆栈没行号 |
| 16 | 拿 release 包分析崩溃 | 找不到对应符号，符号要一一对应保存 |
| 17 | 评审只审 .gd | .tscn 也是代码，节点/信号/owner 都要审 |
| 18 | 检查 res:// 文件存在就够 | 4.4+ UID 身份更关键，要同时看 |
| 19 | 用本地缓存打开项目评审 | 要执行 --import |
| 20 | 没报错=没风险 | 常给 push_error/warn 但不崩 |
| 21 | 一个 PR 改完格式+状态+流程 | 高影响要拆：兼容读取→切换写入→清理 |
| 22 | 版本信息写在 TRES 注释里 | Godot 会丢弃注释，要用显式版本字段 |
| 23 | 把默认属性写进去当修复 | 手工默认项保存时会被丢弃 |
| 24 | 重构后只测编辑器 | 要测目标平台与 release 包 |
| 25 | 一次 500 文件大扫除 | 每次提交要保持游戏可启动 |
