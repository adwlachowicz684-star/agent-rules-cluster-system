# plugins — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/plugins.md`

## 坚决不要引入的 8 种情况

1. **维护已停止**（最后一次提交超过一年）
2. **许可证不清**或有传递依赖风险
3. **与引擎版本强耦合**且无兼容矩阵
4. **功能太小自己写更快**（二十行脚本的事）
5. **引入后无法替换**（侵入数据格式）
6. **强制接管 UI 与存档**（如库存框架）
7. **无 CI 无测试**（改一行都可能崩）
8. **只为"听说更好"**（物理、渲染替换类）

## 反直觉坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | MIT 插件都能放心商用 | MIT 只覆盖插件本身，传递依赖另有条款 |
| 2 | 版本数字相近就能装 | GDExtension 按 **api_version** 对齐，是硬约束 |
| 3 | 官方收录就是官方背书 | 社区提交；且库本身处于维护模式 |
| 4 | 编辑器插件最安全 | 它污染工程文件，协作者必须装同款 |
| 5 | 批量工具越多越省事 | **操作频率**才是标准，低频操作是过度工程 |
| 6 | 行为树自己写很快 | 复杂度全在运行时调试（可视化断点、性能监控） |
| 7 | DI 容器越大越专业 | autoload 已解决八成问题 |
| 8 | 库存有现成轮子就用 | 它锁死整套玩法数据 |
| 9 | 换物理只是改设置 | 全项目回归测试 |
| 10 | 网络框架让联机变简单 | 把简单问题变难 |
| 11 | 调试工具越多越好找瓶颈 | 工具堆叠**改变帧时间分布**，卡顿更难复现 |
| 12 | GDExtension 提升整体性能 | 收益只在**热路径**，非热点重写只增负担 |
| 13 | 编辑器插件不进运行时所以无风险 | 改写 `.tscn` 后其他人必须装同款才能合并 |
| 14 | 插件能加速开发 | 引入 + 学习 + 版本对齐成本常被低估 |
