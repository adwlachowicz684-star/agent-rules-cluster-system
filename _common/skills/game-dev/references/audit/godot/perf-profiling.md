# perf-profiling — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/perf-profiling.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 编辑器 FPS 够就够 | 编辑器有 gizmo/热重载，**不能代表目标设备** |
| 2 | 平均 60FPS 就流畅 | **P99 才是卡顿指标** |
| 3 | 测一次就行 | 移动端要**测 10 分钟**（热节流） |
| 4 | 帧时间 = process 时间 | 含物理到渲染的全部逻辑 |
| 5 | Inclusive 高就要优化它 | **看 Self**，它可能只是调了贵函数 |
| 6 | Profiler 能看 C# | **不覆盖**，要原生工具 |
| 7 | 监视器发布版也能用 | **部分只在 debug 可用，发布版返回 0** |
| 8 | FPS 监视器实时的 | **可能延迟 1 秒** |
| 9 | primitive 数 = 三角形数 | 因 prepass/shadow **约 2–3 倍** |
| 10 | 内存泄漏看节点数 | **看对象数**更准 |
| 11 | Forward+ 能开无限灯 | 是摊销，**取决于屏幕覆盖** |
| 12 | 移动端内存有统一上限 | **按机型分档**，没有统一值 |
| 13 | 纹理压缩只省包体 | **主要省带宽** |
| 14 | Web 也能用 Forward+ | **只能 Compatibility** |
| 15 | 热节流降档一次就够 | 要带**迟滞**，否则边界跳档 |
| 16 | XR 是单眼 draw call ×2 | 每眼完整管线，要看**双眼总量** |
| 17 | XR 刷新率写死 90 | 由 **runtime 决定**，要读 API |
| 18 | 首帧卡是 GPU 问题 | 通常是 **shader 编译** |
