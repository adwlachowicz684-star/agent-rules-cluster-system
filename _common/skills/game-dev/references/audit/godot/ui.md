# ui — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/ui.md`

## 常见漏写

| # | 漏写 | 后果 | 审查规则 |
|---|---|---|---|
| 1 | 每帧赋值 `Label.text` | 每次触发重排，大文本明显卡 | GD13 |
| 2 | 重建列表只 `remove_child` 不 `queue_free` | 节点累积 | GD01 |
| 3 | UI 不用 CanvasLayer | 相机移动时 HUD 跟着跑 | 人工 |
| 4 | `await` 后不判 `is_instance_valid` | 节点已释放，访问报错 | GD75 |
| 5 | 菜单没设默认焦点 | 手柄玩家无法操作 | 人工 |
| 6 | 长文本用 `text +=` 累加 | 每帧全量重建，卡 | 人工 |
| 7 | 硬编码像素坐标 | 换分辨率 UI 错位 | 人工 |
| 8 | 大列表全量 instantiate（几百格） | 卡；要**固定数量 + 复用**（只改内容不改数量） |
| 9 | UI 文本写死明文 | 无法本地化；要存 `key` 用 `tr()` 取 |
| 10 | 弹窗关闭后不归还焦点 | 手柄玩家**直接失灵**；焦点链决定可玩性，不是无障碍的额外工作 |
| 11 | 拖拽只按鼠标路径做 | 键盘/无障碍发起时 `at_position` 是 **`Vector2.INF`**，拿到垃圾索引且不报错 |
| 12 | BBCode 用"删标签"处理用户输入 | 官方反对：用户不理解为何内容被删；要 `escape_bbcode` **转义** |
| 13 | 数据一变就全量重建 UI | 焦点/滚动位置丢失 + 卡顿；要**只在变化时赋值**的增量更新 |
| 14 | stretch 照抄 4.6 的写法 | ⚠ **4.7 默认值变了**（mode `disabled`→`canvas_items`、aspect `keep`→`expand`）；照旧写会"UI 被拉伸" |
| 15 | 容器子项靠锚点定位 | ⛔ 容器内锚点**会被容器覆盖**；用 `size_flags` + `custom_minimum_size` |
| 16 | 边距给每个子项设 offset | 换分辨率必错位；用 `MarginContainer` 的 `theme_override_constants/margin` |
| 17 | 数据一变就赋值（不看是否变化） | 每帧触发 `Label` 重排；要**先比对再赋值** |
| 18 | 血条只用 ProgressBar | ⛔ 玩家看不到数值；要 ProgressBar **+ 自己的 Label** |
| 19 | 数字滚动无收敛守卫 | 到达目标后仍在跑 `_process`；要早退 |
| 20 | 打字机用 `text +=` | 每帧全量重解析；用 `append_text()`（只解析新增） |
| 21 | 打字机不提供"跳过" | 玩家无法快进；要能一次显示全部 |
| 22 | 场景切换不锁输入 | ⛔ 过场黑屏时玩家还在按，会**触发新场景的按钮** |
| 23 | 只在一种分辨率下看过 | ⛔ 必测多种分辨率/比例；`keep` 与 `expand` 表现完全不同 |
| 24 | 只在中文下看过 | ⛔ 德语/俄语通常比中文长 **30–50%**，会撑破布局；还要查缺字 |
| 25 | 反复开关界面没测过 | 三类泄漏源：只 `remove_child` 不 `queue_free`、重复 `connect` 不 `disconnect`、Tween 未释放 |
| 26 | 各界面单独测都通过就行 | ⛔ 部件合格 ≠ 拼起来能用；要有**接缝复查**与集成验收 |
