# ui — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/ui.md`

## 常见漏写

| # | 漏写 | 后果 | 审查规则 |
|---|---|---|---|
| 1 | 每帧赋值 `Label.text` | 每次触发重排，大文本明显卡 | GD13 |
| 2 | 重建列表只 `remove_child` 不 `queue_free` | 节点累积 | GD01 |
| 3 | UI 不用 CanvasLayer | 相机移动时 HUD 跟着跑 | 人工 |
| 4 | `await` 后不判 `is_instance_valid` | 节点已释放，访问报错 | GD75 |
| 5 | 菜单没设默认焦点 | 手柄玩家无法操作 | 人工 |
| 6 | 长文本用 `text +=` 累加 | 每帧全量重建，卡 | 人工 |
| 7 | 硬编码像素坐标 | 换分辨率 UI 错位 | 人工 |
| 8 | 大列表全量 instantiate（几百格） | 卡；要**固定数量 + 复用**（只改内容不改数量） |
| 9 | UI 文本写死明文 | 无法本地化；要存 `key` 用 `tr()` 取 |
| 10 | 弹窗关闭后不归还焦点 | 手柄玩家**直接失灵**；焦点链决定可玩性，不是无障碍的额外工作 |
| 11 | 拖拽只按鼠标路径做 | 键盘/无障碍发起时 `at_position` 是 **`Vector2.INF`**，拿到垃圾索引且不报错 |
| 12 | BBCode 用"删标签"处理用户输入 | 官方反对：用户不理解为何内容被删；要 `escape_bbcode` **转义** |
| 13 | 数据一变就全量重建 UI | 焦点/滚动位置丢失 + 卡顿；要**只在变化时赋值**的增量更新 |
