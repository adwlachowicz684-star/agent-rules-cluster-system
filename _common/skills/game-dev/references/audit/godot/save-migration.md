# save-migration — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/save-migration.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 格式不会大变 | **必然要变**，问题是怎么办 |
| 2 | 版本号以后加也行 | 第一天没写就**只能猜** |
| 3 | 格式版本 = 游戏版本 | 是**三个独立**的版本 |
| 4 | 加密存档的元数据够用 | **不能替代**自己的版本字段 |
| 5 | 版本号放文件头就行 | 加密档**解密后才能读** |
| 6 | 迁移不用备份 | **不可逆**，失败即丢进度 |
| 7 | 迁移后签名还在就有效 | **必须重算**，否则是假象 |
| 8 | 降级读会报错 | **`get_value` 返回默认值**，静默错 |
| 9 | 损坏和降级一样处理 | 要**区分**，否则日志无法归因 |
| 10 | 未来版本硬塞进去 | 要**拒绝** |
| 11 | 写盘是原子的 | 写一半崩会**损坏**，要临时文件+原子替换 |
| 12 | 迁移一次到位更好 | **逐级**更好维护 |
| 13 | 枚举加项不影响 | 数字存储**可能错位** |
| 14 | 删字段就删干净 | 回滚需要**保留旧数据** |
| 15 | 迁移代码跑通就行 | 要**历史样本回归测试** |
| 16 | 迁移写成一个大 switch 就行 | 应是**链**，每步可单独测试 |
| 17 | 直达迁移和逐级迁移选一个 | 并存时**结果必须一致**，要对拍 |
| 18 | 删字段就是删掉 | 是**四个阶段**，能回滚就不能真删 |
| 19 | 迁移失败就开新档 | ⚠ **等于删除进度**，必须用户可见 |
| 20 | 损坏和过新都提示"存档损坏" | 过新应提示**更新游戏** |
| 21 | 样本库有几个正常存档够了 | 要**最简/最全/边界**三类 |
| 22 | 样本可以事后补造 | 补造的是"按当前代码猜的"，**验证不了真实历史** |
| 23 | 迁移失败不用上报 | 不上报 = **永远不知道**，表现为玩家默默流失 |
| 24 | 上报时带上存档便于排查 | ⛔ 存档含**个人信息**，不能上报 |
| 25 | 降级失败了默默覆盖 | 要**保留原文件**，⛔ 不覆盖不删除 |
