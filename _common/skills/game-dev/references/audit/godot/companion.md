# companion — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/companion.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Godot 有 Pet/Mount/Summon 节点 | **一个都没有**，全是项目层组合 |
| 2 | 宠物是会动的装备 | 错：要**独立 AI / 生命周期 / 状态机 / 同步**，三层分离 |
| 3 | SpeciesTemplate 能直接改 | 共享 Resource，改一只**影响所有同类** |
| 4 | 复活冷却用 Timer | 退进程就丢，存 **UTC 时间戳** |
| 5 | 多宠各自索敌没问题 | 会**集火同一目标**，要分区或优先级 |
| 6 | 离线饱食度不用算 | 上线后**忠诚度断崖下降**（但补算要封顶） |
| 7 | 骑乘时两个 CharacterBody3D 各自移动 | 一帧延迟 + 穿模；**只有坐骑驱动** |
| 8 | reparent 在信号回调里直接做 | **物理引擎崩溃**，要 `call_deferred` |
| 9 | `reparent(p)` 就够了 | ⛔ 官方 `keep_global_transform` 默认 **true**（保留），所以这句没错；⛔ 但**别因此手写** `remove_child`+`add_child` 去`补偿`，那才真丢全局变换（见 #25 / #26） |
| 10 | 骑乘后角色碰撞不用关 | 双碰撞体互挤**穿模** |
| 11 | 下马随便找个位置 | 要预检测，否则**卡进墙里** |
| 12 | authority 转了就能骑 | 有延迟，要**两阶段确认**，否则各自移动 |
| 13 | 每个召唤物一个节点没问题 | 50+ 个线性叠加，要**分层 + 对象池** |
| 14 | MultiMesh 能带动的召唤物 | **不支持骨骼动画** |
| 15 | 客户端上限够了 | 数量上限要**服务端强制** |
| 16 | 池子耗尽返回 null 不用管 | 调用方**必须检查**，否则 NPE |
| 17 | 池里节点可以 queue_free | 混用留下**野指针**，池中永不 free |
| 18 | MultiplayerSpawner 配对象池 | 语义冲突，客户端看到**幽灵节点** |
| 19 | 召唤物伤害归属不用存 | 要 `caster_id`，消失后**仇恨残留** |
| 20 | 孵化结果领取时随机 | 可**反复刷稀有度**，必须开始时 roll 并存储 |
| 21 | 合成完成时才扣材料 | 会被**多个合成台重复利用**，开始即扣 |
| 22 | 多槽孵化更新第一个就行 | 其他槽**永远不完成** |
| 23 | 取消返还直接给 | 背包满会**凭空消失**，要检查或存临时区 |
| 24 | 合成队列上限查 active | 要查 `queue + active` **总数** |
| 25 | `reparent(p)` 默认会丢全局变换 | ⛔ **写反了**：官方 `keep_global_transform` 默认 `true`（保留）。⛔ 真正的风险是误以为默认丢，去手写 `remove_child`+`add_child` 补偿，那才真丢 |
| 26 | reparent 完不用管 | ⛔ 官方 Warning：插值开启时会在下一物理帧**从旧位置滑到新位置**；要 `reset_physics_interpolation()`，⛔ 且必须在移动**之后**调用 |
| 27 | `keep_global_transform` 对所有节点有效 | ⛔ 只对 `Node2D` / `Node3D` / `Control` 生效，且 `Control` **只保留 position**；普通 `Node` 传 true 也无效 |
| 28 | 飞行坐骑用 FLOATING 模式照常判 `is_on_floor()` | ⛔ 官方：该模式**所有碰撞都报 on_wall**，速度恒定 → `is_on_floor()` **永远 false**，永远判不到落地 |
| 29 | `spawn_limit` 设了就等于服务端权威 | ⛔ 它是**客户端复制上限**，改包即可绕过；服务端仍必须自己数 |
| 30 | `spawn_function` 里自己 `add_child()` 返回的节点 | ⛔ 官方：不要，引擎自动加；且返回的节点**必须不在场景树中** —— 这与对象池 【留在树里隐藏】 的语义直接冲突 |
| 31 | MultiMesh 要动画就只能整块放弃 | VAT 可行：烘进顶点贴图 + `INSTANCE_CUSTOM` 传索引；⛔ 代价是**无混合与 IK**，要按 【是否需混合】 再分一层 |
| 32 | 宠物死亡改个动画就行 | 死亡/复活是**状态机态**；与背包数据耦合 → 复活后等级/忠诚度错乱 |
| 33 | 宠物跟随直接追主人目标点 | 会叠在主人身上且互相挤压；要有偏移槽位 + 避让优先级 |
| 34 | 宠物 AI 与主人同等优先级 | 主人过场/强制移动期间宠物继续追击 → 穿进过场镜头，⛔ 应进入 `Return` |
| 35 | 骑乘关掉角色碰撞层就完事 | 下马要**恢复**，且恢复时机必须在 reparent 之后；顺序反了骑手卡进墙里 |
| 36 | 池化取出的节点仍在树里就返回给 `spawn_function` | ⛔ 官方要求返回 【不在场景树中的 Node】；在树中会导致重复挂载或客户端幽灵节点 |
| 37 | 池化复用不重置 `NavigationAgent` | 残留旧路径 → 新召唤物沿上一只的路径跑，表现为 【AI 莫名乱走】 |
| 38 | 孵化结果只存在内存里 | 重连后重 roll，⛔ 等于又变回 【领取时随机】，可反复刷稀有度 |
| 39 | 合成台并发 【点得快测不出】 就不用管 | 客户端同时点两台**必然**竞态；服务端不串行就重复扣/重复产 |
| 40 | 召唤物上限只查当前存活数 | 要查 【存活 + 正在创建】；只查存活会在创建瞬时超限 |
| 41 | 骑手与坐骑只需转一个 authority | 两者是**两个需同步的实体**，只转一个 → 延迟期间各自移动 |
| 42 | 离线衰减按客户端本地时钟算 | ⛔ 系统时钟可被玩家设置（见 `vip` / `monetization` 域）；必须用服务端下发时间戳 |
| 43 | 宠物成长/进化判定只跑客户端 | 可改包直接满级，要**服务端权威**（与 #15 同源，但这条在成长线） |
| 44 | 上下马只做客户端距离判定 | 可瞬移/穿墙上马，服务端要校验**距离与地形条件** |

## 审核时逐条问自己

1. 宠物有**独立状态机**吗？死亡/复活态与背包数据耦合了吗？
2. SpeciesTemplate 是直接改还是 `duplicate()` / `local_to_scene`？
3. 所有冷却/计时存的是**绝对时间戳**还是 Timer / 剩余秒数？
4. 骑乘时是不是**只有一个** CharacterBody3D 在 `move_and_slide()`？
5. reparent 是否在信号回调里直接执行？是否保留了全局变换？
6. 上马后角色的 collision_layer 关了吗？下马点有安全检测吗？
7. 召唤物超过 20 个时走的是哪一层渲染方案？上限是服务端强制的吗？
8. 对象池的 `acquire()` 返回值调用方检查了吗？`_reset()` 清干净了吗？
9. 孵化/合成的结果是**开始时** roll 的吗？
10. 有没有任何一个"宠物/坐骑/召唤物"的状态判定**只跑在客户端**？
11. 骑乘期间是**只有一个** `CharacterBody3D` 在 `move_and_slide()` 吗？
12. reparent 之后调 `reset_physics_interpolation()` 了吗？是**在移动之后**调的吗？
13. 飞行坐骑的落地判定用的是 `is_on_floor()` 吗？（⛔ FLOATING 模式下它永远 false）
14. 召唤物上限是**服务端**强制的吗？`spawn_limit` 有没有被当成权威上限？
15. 孵化/合成的结果**落库**了吗？重连后还是不是同一份？
