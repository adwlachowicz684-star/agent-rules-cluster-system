# genres-rts — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/genres-rts.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 指令队列用信号串起来 | 信号只适合"已发生"，不适合"待执行意图"，要用显式数据结构 |
| 2 | `Camera2D.screen_to_world_point()` | 没有这个方法，要用 `get_screen_transform().affine_inverse()` |
| 3 | 用 `Area2D` 套选框 | 框选是屏幕矩形 + 世界坐标转换 + `Rect2.has_point()` |
| 4 | `Rect2.has_point()` 边界算包含 | 约定右/底边缘不算，要手动加容差 |
| 5 | 编队把所有单位指同一目标点 | RVO 能缓解但引入抖动，要算偏移位各自寻路 |
| 6 | `Light2D` 能做战争迷雾 | 那是 2D 光照阴影，迷雾要独立格子状态 + 批量脏区提交 |
| 7 | 每帧 `get_nodes_in_group("units")` | 全树扫描，应持有 `Array[Unit]` |
| 8 | 1000 个 `CharacterBody2D` 各跑物理 | 要按规模分三档降级，>800 走逻辑网格 + MultiMesh |
| 9 | 2D RTS 靠 Jolt 加速 | Jolt 是 3D 默认物理，2D 默认仍是 Godot Physics |
| 10 | 每帧各单位写一次 `set_cell` 更新视野 | 反复触发重算，要脏区批量提交 |
| 11 | 迷雾层开 `navigation_enabled` | 会生成无意义导航区域，要关掉 |
| 12 | `intersect_point()` 默认够用 | 默认 max_results=32，密集单位会被截断 |
| 13 | `Camera2D.global_position` 当屏幕中心 | 官方 Note：平滑与 limits 会让它不等于真实屏幕位置，要用 `get_screen_center_position()`；框选矩形整体偏一个平滑量 |
| 14 | `Camera2D.global_rotation` 当屏幕朝向 | 同一条官方 Note（旋转平滑会导致不同），要用 `get_screen_rotation()` |
| 15 | 用 `Camera2D` 继承的 `get_screen_transform()` 做屏幕→世界 | 那是 `CanvasItem` 的方法，逆变换到**节点局部空间**；要用 viewport 的 `screen_transform * canvas_transform` 再取逆 |
| 16 | 把 `_input()` 的 `event.position` 当世界坐标 | 它是 **viewport 坐标**（官方论坛口径），直接当世界点用会让框选随窗口缩放漂移 |
| 17 | 给上千个单位全开 `avoidance_enabled` | 官方原话：大量注册代理的避障有显著性能开销，只应在**当前需要**的 agent 上开 |
| 18 | 设了 `target_position` 就等着走 | 官方 Note：必须**每物理帧**调一次 `get_next_path_position()`，否则内部路径逻辑不更新 |
| 19 | 在 `waypoint_reached` 回调里调 `get_next_path_position()` | 官方写明该方法会触发新的路径计算，在信号回调里调会**无限递归**；表现为走到第一个点后停住、无报错 |
| 20 | 命令队列用节点树或信号表示 | 不支持插入 / 取消 / 替换，且单位死亡后残留；命令要是显式 `Array[Command]` 数据结构 |
| 21 | 单位死亡后不清命令队列 | 目标失效的队首命令反复占用执行位，单位表现为站住不动但仍在编队里 |
| 22 | 命令里存节点引用当目标 | 目标销毁后变成悬挂引用或 `null`，⛔ 不报错；要存稳定的 `unit_id` 并做有效性检查 |
| 23 | 框选满了就当全选了 | `max_results` 截断**按返回顺序不是按优先级**，返回数等于上限时要能判断可能还有 |
| 24 | 框选用 `Area2D` 实体套 | 要等物理帧才出结果（延迟一帧），且上千单位时开销大；用屏幕 `Rect2` 加世界坐标转换 |
| 25 | 迷雾只存 visible 一态 | 要 `visible / explored` 两态，否则离开视野就全黑，失去探索过的信息 |
| 26 | 迷雾按帧实时写 `set_cell` | 反复触发导航与渲染重算；要脏区收集、逻辑帧末一次性提交 |
| 27 | 多阵营共享一张迷雾层 | 己方视野会被敌方单位反推泄漏；每方一张独立层 |
| 28 | 每帧 `get_nodes_in_group` 取单位 | 全树扫描；`UnitManager` 持有 `Array[Unit]`，启停只改数组 |
| 29 | 编队偏移写死不随朝向转 | 队形在转向时会翻转或穿插；偏移要按行进方向旋转 |
| 30 | 降级档位沿用固定数字阈值 | 档位是**实测**出来的，不是品类惯例；⛔ 填错不会报错，只表现为某个规模段突然掉帧 |
| 31 | 直接改 `position` 但仍挂 `CharacterBody2D` | 物理与逻辑双驱动，表现为抖动或穿墙；降级档要么走物理要么跳过物理，⛔ 不能并存 |
| 32 | 每帧刷新 `target_position` 为当前目标点 | 会每帧触发一次重新寻路；只在目标真正变化时设 |
| 33 | 单位标识用节点路径 | 重连后路径失效；用服务端下发的稳定 `unit_id` |
| 34 | 框选结果不排序直接下发 | 下发顺序不确定会让编队位置每次操作后互换，表现为点了两次队形变了 |
| 35 | 迷雾层 `navigation_enabled` 留默认 | 会生成无意义的导航区域；要关掉 |
| 36 | 命令推进挂在渲染帧 | 帧率一变命令推进速度跟着变，表现为高刷屏上单位走得快；要挂固定逻辑步长 |
| 37 | 队列清空后什么都不做 | 空队列与执行中在外部无法区分，表现为选中后点地面没反应；要有显式待命态供 UI 查询 |
| 38 | 客户端提交单位结算结果 | 改包伪造在正常流程里永远测不出来；命令、结算、资源三类必须服务端权威 |
| 39 | 降频与脏区提交挂在渲染帧 | 帧率一变 AI 决策频率跟着变；要挂逻辑 tick 并按 `unit_id` 错峰分散 |
