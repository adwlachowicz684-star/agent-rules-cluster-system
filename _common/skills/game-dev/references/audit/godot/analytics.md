# analytics — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/analytics.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 事件名随时能改 | 进生产后改 = 历史数据不可比 |
| 2 | 三层命名更清晰 | 会变成同义事件泛滥 |
| 3 | 用设备 ID 做玩家 ID | **合规风险**，必须可重置可匿名 |
| 4 | 每条事件发一个 HTTP | 要批量，否则卡顿又费电 |
| 5 | 断网就丢数据 | 要**本地缓存 + 重试** |
| 6 | 退出时不用管 | 未上报队列要持久化 |
| 7 | `HTTPRequest` 创建就能用 | 必须 `add_child` 进树 |
| 8 | 在 `_process` 里随手上报 | 高频事件会拖垮帧率，要节流 |
| 9 | 枚举用数字省空间 | 后续无法解读，用稳定字符串 |
| 10 | 记录中文显示名方便 | ID 改了就断，用数据表主键 |
| 11 | 通关率低就是太难 | 也可能是迷路/无聊，要结合时长 |
| 12 | 分析是上线前才做 | 事件模型要早期定，否则无法回溯 |
| 13 | 事件 ID 用系统时钟生成就行 | 官方：系统时钟**用户可手动设置**，改时间会造成 ID 碰撞，服务端去重把真实数据**误删**且无报错 |
| 14 | `client_ts` 记当前时间就行 | 系统时间倒流会让漏斗步骤乱序、留存算错，报表只表现为"数据变了" |
| 15 | `OS.get_unique_id()` 当玩家 ID 很方便 | 是设备唯一标识（属个人数据），且官方注明**可被外部程序伪造**、重装或换硬件后**会变** |
| 16 | 先采集、同意后再上报就行 | 本地已存未同意期间的行为数据 = 已完成采集；同意开关形同虚设 |
| 17 | 埋点开关默认开就行 | 玩家必须能关闭非必要分析；关了只是不显示而仍在采 = 违规 |
| 18 | 用 peer ID 当会话键 | 那是连接号，每次重连都变；一次游玩被切成多个"会话"，时长与留存全错 |
| 19 | 队列放内存里就行 | 玩家会强杀进程；只在内存则全部丢失，且**无任何报错**只表现为数据变少 |
| 20 | 缓存能存多少存多少 | 弱网时无限增长打满磁盘配额，表现为"越玩越卡"甚至存档失败 |
| 21 | 缓存直接覆盖写就行 | 写一半崩掉留下半截 JSON，`JSON.parse_string()` 返回 `null` 与"队列为空"无法区分，整份被静默丢弃 |
| 22 | 监听 `_notification` 就能保存 | 官方：调用 `SceneTree.quit()` **不发送**该通知，且"即使延迟那行强制退出的代码也不行" |
| 23 | 退出通知只有 `WM_CLOSE_REQUEST` | 官方：安卓发的是 `NOTIFICATION_WM_GO_BACK_REQUEST`，iOS 不支持；只监听前者则安卓零触发 |
| 24 | 收到退出请求会走我的保存逻辑 | 默认 Godot 会自行退出；必须先 `set_auto_accept_quit(false)` 才能接管 |
| 25 | 发完通知程序就退出了 | 4.x 中 `propagate_notification` **不终止程序**（与 3.x 不同），不补 `quit()` 会关不掉 |
| 26 | HTTP 超时用默认值就行 | `timeout` 默认 `0.0` 含义是**永不超时**；配合状态守卫会让 flush 永久停摆、队列无限涨 |
| 27 | 一个 `HTTPRequest` 能并发发多个 | 后一个会取消前一个，表现为"数据丢一半"，且不报错 |
| 28 | 收到 200 就清空队列是安全的 | 响应回程丢失时服务端已入库而客户端以为失败，重试即**重复计数**（付费事件致命） |
| 29 | 失败就立刻重试 | 无退避会在服务端抖动时自行放大为雪崩；失败也不应清空队列 |
| 30 | 重试超限就丢弃 | 应保留并计数上报丢弃量，否则数据成片消失且无人知晓 |
| 31 | 付费事件走批量省请求 | 玩家付费后强杀进程，事件还在队列里 → 服务端有订单、分析后台无事件 |
| 32 | 所有事件一视同仁 | 关键事件（付费 / 通关）必须立即上报；不分清则要么对账差，要么请求风暴 |
| 33 | 看整体通关率就够了 | 看不出**在哪一步**流失；且低通关率未必是太难，也可能是迷路或无聊 |
| 34 | 事件含义写在代码注释里 | 新人看不到已有事件，必然重复造同义事件名；字典必须有唯一文档位置 |
| 35 | 只管采集、不用管删除 | 保留期限与删除机制是合规项；⛔ 具体天数由运营与法务定，不许编 |
| 36 | 死亡事件记"死了"就行 | 不记位置则热力图画不出，只能退回"这关太难"这种无法行动的结论 |
| 37 | 数据不用带版本号 | 热更前后数据混在一起，一次热更引起的指标变化会被误读成"玩家行为变了" |
| 38 | 难度参数写死在包里 | 每次调参都要等发版，反馈周期长到无法做 A/B，也就谈不上用数据调优 |
