# ai-behavior — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/ai-behavior.md`

## 常见坑

| # | 坑 | 后果 |
|---|---|---|
| 1 | 简单 AI 也上 BT | 维护成本高于 FSM，没收益 |
| 2 | 每个敌人复制整棵树 | 节点膨胀，不如组件复用 |
| 3 | 忘记返回 RUNNING | 动画/寻路每帧重头执行 |
| 4 | RUNNING 无 abort | 低优先级任务永久阻塞高优先级反应 |
| 5 | 把 FAILURE 当错误 | 用 push_error 刷屏，掩盖真问题 |
| 6 | 黑板存引擎对象引用 | 存档无法序列化 / 悬空引用 |
| 7 | Task 里塞寻路和伤害结算 | 树变成回调壳，无法测试 |
| 8 | 插件版本不锁 | 上游改动导致 CI 随机红 |
| 9 | 只在编辑器里测过 | 运行时 tick 时机与编辑器不同 |
| 10 | AI 与物理帧不同步 | 抖动、判定不稳定（AI 应走 `_physics_process`） |
| 11 | Idle 就是"什么都不做" | 它至少管**朝向、微动作、感知**；空 Idle 会让敌人像雕像 |
| 12 | 转移条件写在各状态的 `_process` 里 | "有哪些转移"无法一眼看全；⛔ DEAD 能否被转移出来都没人知道 |
| 13 | 状态切换不加最短驻留 | 阈值边界**每帧抖动**（敌人原地抽搐）；要 `MIN_*_TIME` |
| 14 | 进入/退出逻辑散落各处 | Chase 被打断进 STAGGER 时忘了停寻路 → **硬直中还在滑行**；要统一 `_on_enter`/`_on_exit` |
| 15 | DEAD 只是一个不再转移的状态 | 死亡单位仍占**攻击令牌、预约掩体、感知候选** → "AI 集体发呆"的源头之一 |
| 16 | 威胁表/黑板不清理死亡目标 | 长时间挂机**无限增长**（经典泄漏）；要有 TTL 或离场清理 |
