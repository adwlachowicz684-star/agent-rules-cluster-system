# input-remap — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/input-remap.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 用 3.x 的 scancode | 4.x 是 keycode/physical_keycode，**混用会静默存错** |
| 2 | `get_action_list()` 还能用 | 4.x 是 **`action_get_events()`** |
| 3 | 改 InputMap 会写回项目设置 | 改的是**内存副本** |
| 4 | 键位三个字段都存上更保险 | **只能设一个**，否则布局变化就错 |
| 5 | 用 keycode 存键位 | 应以 **physical_keycode** 为主键 |
| 6 | InputEvent 能直接存 JSON | 要**转纯字典** |
| 7 | 键位不用版本号 | 格式一变旧键位就废 |
| 8 | `_input` 里抓按键就行 | 要 **`_gui_input()` 独占消费** |
| 9 | ESC 自然就是取消 | 要**显式规则**，否则同时触发菜单 |
| 10 | 轴捕获不用死区 | 轻微触碰会**误触发** |
| 11 | 按钮和轴一起处理 | 是**两类事件** |
| 12 | 振动会自己停 | **不会**，退出场景/崩溃都在振 |
| 13 | duration=0 就是不振动 | 是**无限振动** |
| 14 | 一个键绑两个动作无所谓 | 要**同设备冲突检测** |
| 15 | 编辑器里读键位用 InputMap | ⚠ 拿到的是**编辑器**的，要走 ProjectSettings |
| 16 | 初始化时 load_from_project_settings 更干净 | ⚠ **会清空**玩家自定义键位 |
| 17 | 死区是全局的 | 是 **action 级**，默认 0.5 偏大 |
| 18 | `event_is_action` 严格区分修饰键 | 默认 `exact_match=false` **会忽略**修饰键与方向 |
| 19 | 加载键位直接 add | ⛔ 会**叠加**，要先 `action_erase_events` |
| 20 | 轴存 axis_value 更精确 | 会把"当前推了多少"存进去，**死区判断全乱** |
| 21 | 版本不匹配就尽力解析 | 应**回默认+提示**，⛔ 不静默产生错误映射 |
| 22 | 一个手柄就是一个设备 | ⚠ SteamInput 会造**虚拟设备**，可能翻倍 |
| 23 | device 索引可以存档 | 重新插拔会变，⛔ **不要持久化** |
| 24 | 长振动一次调用就行 | 官方：部分硬件**不兼容长时长**，要重启效果 |
| 25 | 改键界面取消时不用管振动 | ⚠ 取消后**振动继续**，是必停时机之一 |
| 26 | 不用 InputMap，直接判 `KEY_*` 常量 | ⛔ 玩家**无法改键**、手柄不通用；一切输入都要走 **action** |
