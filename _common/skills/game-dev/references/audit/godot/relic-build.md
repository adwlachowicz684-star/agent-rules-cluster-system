# 审核条目 —— 遗物 / 局内构筑（Roguelite 养成层）

> 用法：按功能点收尾时逐条对照。格式：本能以为 → 实际 → 审查规则

| # | 本能以为 | 实际 | 审查规则 |
|---|---|---|---|
| 1 | 遗物/词条/局外解锁共用一套来源结构 | 失效时机完全不同（换装 / 局末 / 永久） | ⚠ 效果可共用，**来源不可共用** |
| 2 | 遗物做成 `Node` 好挂特效 | 不能进存档与网络包，序列化带整棵子树 | ⚠ 必须是 `Resource` |
| 3 | 可叠加遗物用"持有多个实例"表达 | 协同判定与 UI 都变复杂 | ⚠ 用 `stacks` 字段 |
| 4 | 三选一走全局 `randi()` | UI 抖动/粒子都会消耗序列 → 同种子结果不同 | ⛔ 必须用独立 RNG 实例 |
| 5 | 先恢复 `state` 再设 `seed` | 官方：**改 seed 会重置 state**，恢复被覆盖 | ⛔ 顺序必须是先 seed 后 state |
| 6 | 用局数/玩家 ID 直接当种子 | 官方：RNG **无雪崩效应**，相似种子产生相似序列 | ✅ 种子必须先过 `hash()` |
| 7 | `rand_weighted` 不判返回值 | 空数组返回 **-1** → 取到 `pool[-1]` = 最后一个，不报错 | ⚠ 每次调用后必须判 `-1` |
| 8 | 协同写在遗物内部（A 判断有没有 B） | 加新遗物要改所有相关遗物 | ⚠ 独立协同表 |
| 9 | 协同按遗物数量判定 | 同一遗物叠 3 层也会触发需要 3 件不同的规则 | ⚠ 按**去重集合**判定 |
| 10 | 每帧遍历遗物累加属性 | 遗物越多越卡，且前期测不出来 | ⚠ 脏标记快照，拿遗物时才重算 |
| 11 | 减伤类遗物随便叠加 | 叠到 100% 除零 → NaN 或负数 | ⛔ 组合必须受约束 |
| 12 | 局外解锁等通关时一起存 | 中途崩溃则整局解锁全丢，玩家明确感知 | ⚠ 获得瞬间落盘 |
| 13 | 存档存遗物模板本身 | 配表删遗物后旧档指向空，且**不报错** | ⛔ 只存 `relic_id` |
| 14 | 拿遗物后不刷缓存 | UI 显示旧面板 → 玩家以为没拿到 | ⚠ 立即重算并广播 |
| 15 | 预览与生效各算一遍 | 两边漂移："预览 +10%，实际 +8%" | ⛔ 共用同一试算函数 |
| 16 | 抽取结果客户端决定 | 可伪造遗物来源 | ⛔ 服务端裁决 |
| 17 | 稀有度权重写死在代码 | 改数值要发版 | ⚠ 权重进配表 |
| 18 | 池抽空了让它自然为空 | 见 #7，`pool[-1]` 静默返回最后一个 | ⚠ 池空要有显式兜底 |
| 19 | 局内遗物影响局外排行榜而不校验 | 客户端可伪造 | ⚠ 排行榜提交要校验遗物来源 |
| 20 | 遗物效果直接 `attack +=` | 下次重算被覆盖 → "拿了变强，打一场又回去" | ⛔ 并入统一属性管线 |
| 21 | 协同触发后不记录来源 | 玩家问"为什么没触发"时无法回答 | ⚠ 记录参与协同的 `relic_id` |
| 22 | 三选一的选项顺序每次随机排 | 影响种子复现，回放对不上 | ⚠ 排序也要走同一个 RNG |
| 23 | 验收时把证明场景改成「实际实现的样子」 | 场景跑不出来说明定性错了；改场景等于自欺，验收失去意义 | ⛔ 改定性，不改场景 |
