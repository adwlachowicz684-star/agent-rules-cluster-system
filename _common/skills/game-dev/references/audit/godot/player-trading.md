# player-trading — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/player-trading.md`
>
> 边界：本篇是**资产流通**（已存在的资产怎么从 A 到 B）。
> 产出与消耗侧见 `audit/godot/economy.md`；商业化/支付见 `audit/godot/monetization.md`。

⚠ **一句话**：客户端请求交易，服务端决定一切；
任何资产离开一个位置时，必须先建立另一个位置的权威暂存状态。

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 交易就是"减 A 加 B" | 五种形态必须共用**一个** `TransferAsset` 原子操作，否则五套背包五种漏洞 |
| 2 | 交易代码直接改背包表 | 要共享服务化 owner |
| 3 | 支持直接交易 = 省一个拍卖行 | 直接交易是**社交让步**（议价/以物易物/赠与），不是功能替代 |
| 4 | 流转的是模板 | 流转的是**实例**；`template_id` 只用于展示，⛔ 不作成交依据 |
| 5 | 绑定是个显示标签 | 绑定是**迁移函数的输入**（ALLOWED/DENIED/CONVERT/DELAYED），每次重新求值 |
| 6 | 可以缓存客户端发来的"可交易" | ⛔ 必须用实例当前状态与版本重新求值 |
| 7 | 拆分沿用旧 stack_id | 会指向已不存在的实例；要**退役旧 ID、生成新实例、写血缘、校验总量** |
| 8 | 上架后物品还在背包，成交时再检查 | 卖家可继续装备/销毁/邮寄/再挂 → **双卖**；上架即托管 |
| 9 | 客户端显示预估费就是实际费 | 余额、VIP 折扣、费率在请求途中会变；⛔ 客户端不得决定实际扣费 |
| 10 | "正在结算"和"已成交"可以并存 | 必须互斥；竞争时只有先拿到**挂单版本**的行能完成 |
| 11 | 先给双方返回成功再后台尽量结算 | ⛔ 绝不能这样做，失败方要退款并给幂等错误码 |
| 12 | 一口价用客户端传来的单价 | 服务端必须**重新读取最新挂单价格** |
| 13 | 竞价就是显示当前最高价 | 本质是**冻结领先者资金到结束**；定时器只转待结算，结算用唯一令牌 |
| 14 | 代拍做成客户端自动点价 | 要建模为**服务端订单**，只出价到最低可领先额，绝不超玩家上限 |
| 15 | 价格显示缓存可直接成交 | 排序可异步，**成交必须实时**；界面显示"价格待确认" |
| 16 | 把全服最低挂单价当成交价 | 可能是诱饵、误操作或被脚本抢走的临时价 |
| 17 | 玩家定价和系统定价二选一 | 要**玩家发现 + 服务端软边界 + 风险处置** |
| 18 | 服务端自动把超界价改成"合理价" | 卖家会抱怨系统偷改；应**拒绝**而非篡改 |
| 19 | 中位数用全部挂单算 | 要剔除未真正成交、撤销/回滚、关联订单、自买自卖 |
| 20 | 买家付税与卖家付税混用 | UI 缓存、历史邮件、税率配置会不一致；**不可混用** |
| 21 | 阶梯税让客户端选档位 | 要按本次 taxable base 服务端算；且要限制拆单 |
| 22 | 税进系统钱包 = 回收 | 进钱包再花仍是货币回流；**销毁**才真正减少存量 |
| 23 | 系统账户（公会/跨服/代售）不计税 | 应视为普通市场收入或另设 sink |
| 24 | 客户端"预计到手"= 保证获得 | 撤销/争议/回滚都会改变最终收入 |
| 25 | 直接交易确认后还能改 offer | 要版本锁；任一方物品失效**整个取消**，不做部分成交 |
| 26 | 距离校验用客户端位置 | 要**服务端测距** |
| 27 | 公会仓库 = 共享背包 | 是带 ACL 的库存服务；会长⛔ 不能豁免经济规则 |
| 28 | 公会取出即可转卖 | 公会成**洗号中转站**；要区分暂存区/公共区/审批区 |
| 29 | 摊位物品仍是背包可装备品 | 托管后不是 |
| 30 | 货款立即到账 | 盗号最优路径：登录→批量挂单→低价扫给同伙→转服；必须**延迟到账** |
| 31 | 二次密码/设备提示能止损 | 只是提高门槛，**不能撤销已完成盗窃** |
| 32 | 延迟策略写死在客户端常量 | 要放**热更新策略表**，且只作用于新交易，⛔ 不追溯旧订单 |
| 33 | 延迟结束自动发到背包 | 背包满/离线/上限会造成**隐形丢失**；要"可领取"+主动领取复查 |
| 34 | 附件到期只删记录 | 要先转待回收，再返还或销毁 |
| 35 | 撤销只回滚货币 | 要**全有或全无**；买家可能已把货款用于强化或转给第三人 |
| 36 | 补偿金当成正常交易收入 | 必须走**独立系统账** |
| 37 | 风控只看"这笔是否异常" | 要看**关系链**：账号/设备/网络/行为/资金图 |
| 38 | 只检查 `is_bound` 布尔 | 会漏"绑定于 A 却被客户端改成可交易"；要按**快照**恢复 |
| 39 | 绑定解除可由客户端触发 | 必须来自**服务端事件**（使用时绑定/赠送许可/官方解绑券） |
| 40 | 邮件附件无摩擦 = 方便 | 会变成**洗钱通道**；要脱敏视图、延迟、限制同设备/IP 总流入 |
| 41 | 日志记"A 给 B 1000 金"够了 | 还要前后余额、实例快照、绑定、税、挂单版本、风险标签 |
| 42 | 日志只写结果 | 要写**请求前快照 + 意图 + 结果**（DECISION + EFFECT 两个事件） |
| 43 | 只保存最后余额 | 误扣误发变成**无法定责的黑箱** |
| 44 | 经济日志里存完整 IP/凭据/聊天 | 只写**哈希 ID 与摘要** |
| 45 | 客户端先扣物品再等服务端确认 | ⛔ 没有"半权威"的便利做法 |
| 46 | 写操作 RPC 用 unreliable 求速度 | 重复扣款/乱序成交/一次出价应用两次都**不可逆** |
| 47 | reliable 就等于幂等 | 不保证；要版本 + 唯一请求 ID + **结算令牌**防重 |
| 48 | `client_nonce` 替代服务端幂等键 | 只是客户端去重键；服务端键要含会话/玩家/操作/版本/请求哈希 |
| 49 | 返回"已成交，请客户端扣款" | ⛔ 绝不；只返回服务端算出的价格/税/余额哈希/状态/错误码 |
| 50 | RPC 传 `Resource` / `Callable` | 官方明确**不序列化 Object/Callable**；只传稳定 ID 与摘要 |
| 51 | 把服务端库存表赋给客户端节点 | ⛔ 禁止 |
| 52 | `set_multiplayer_authority()` 会自动同步 | 官方明确**不会**；要自己 spawn/RPC/同步器复制 |
| 53 | 玩家权威自己的角色 = 也权威钱包/挂单/邮件 | ⛔ 钱包、挂单、邮件权威必须留服务端 |
| 54 | 跨服当普通背包转移 | 时钟/账本/封禁/上限不一致会**复制资产**；要全局 ID + 独立账本 + 结算队列 |
| 55 | 上架不收保证金 = 占位免费 | 恶意占位与刷屏挂单**零成本**；要保证金 + 同时挂单数上限，撤销按规则扣费 |
| 56 | 搜索直接读实时库存 | 展示与成交不一致；要基于**挂单快照**，⛔ 别让已成交的货还出现在列表里 |
| 57 | 挂单到期只改状态 | 物品留在托管里**永久消失**，且列表里查不到；要主动返还并写审计 |
| 58 | 竞价定时器直接结算 | 截止前一毫秒出价会争议，且重入会结算两次；定时器**只转待结算**，结算用唯一令牌 |
| 59 | 一口价与竞价共用一个价格字段 | 同步成交与条件订单语义不同；分开存，否则改价时两边互相污染 |
| 60 | 价格统计不区分形态 | 摆摊/直交/拍卖混算 → 中位数失真；要按形态分窗口，低成交量回退到成本锚 |
| 61 | 结算时用下单时的旧税率 | 热更后新旧订单税率不一致；结算时按**当前**策略重算 |
| 62 | 撤销只冻结当前订单 | 下游已转走，撤销落空；要**同时冻结后续转移链**，并从当前持有人回滚 |
| 63 | 日志保留期一刀切 | 要么合规超限要么丢真相；分三层：原始账本 / 个人历史 / 风控聚合特征 |
| 64 | 断线重连保留本地缓存 | 显示与服务端不一致；要用服务端状态**整体替换**本地缓存 |

## 审核时逐条问自己

1. 五种交易形态是否共用**同一个** `TransferAsset`？还是有五套背包写法？
2. 成交依据的是**实例 ID** 还是模板 ID？词条快照是否随实例锁定？
3. 上架那一刻物品**是否已移入托管**？卖家还能装备/销毁/再挂吗？
4. 绑定是在**每次状态迁移时按策略重新求值**吗？回滚按快照还是按模板重置？
5. 拆分是否**退役旧 stack_id 并生成新实例**？总量守恒校验了吗？
6. 一口价是服务端**重新读价格**还是信客户端传值？
7. 竞价是否**冻结领先者资金**？结算由唯一令牌还是定时器直接完成？
8. 成交价是实时查的还是用缓存价？连点会不会重复下单？
9. 税是买家付还是卖家付？有没有混用？阶梯档位由谁算？
10. 税是**销毁**还是进系统钱包？系统账户计税了吗？
11. 高价值交易有**延迟到账**吗？延迟策略在热更新表还是写死在客户端？
12. 延迟结束是自动发背包还是"可领取 + 主动领取复查"？
13. 撤销是**全有或全无**吗？只追货币够不够？
14. 风控看的是单笔还是**关系链**？
15. 日志写了**请求前快照 + 意图 + 结果**吗？还是只有结果？
16. 有没有任何一条"价格 / 税 / 库存扣减 / 成交判定"**只跑在客户端**？

> ⚠ **本篇应 100% 服务端权威**：客户端只发"我要做什么"和本地 ID，
> 不得携带成交价、税额、物品属性、余额变化或结算结果。
> 只要有一项在客户端算，就是可伪造的作弊入口。
