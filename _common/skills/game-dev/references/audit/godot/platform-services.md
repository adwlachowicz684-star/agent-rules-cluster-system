# platform-services — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/platform-services.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Godot 有成就系统 | **完全没有**，全靠平台或自建 |
| 2 | 直接调平台 API 就行 | 要**抽象一层**，否则换平台重写 |
| 3 | 平台调用是同步的 | **都是异步**，要 await |
| 4 | 离线桩随便写个 print | 它是**开发主路径**，要存盘+可注入失败 |
| 5 | GodotSteam 支持 4.x 就能用 | 与 SDK/客户端/模板**强耦合**，要按 4.7.2 构建 |
| 6 | `steam_appid.txt` 发布也要带 | 发布**不要包含**，是错误来源 |
| 7 | steam_appid.txt 就是 DRM | **两回事** |
| 8 | 没 Steam 客户端就该崩 | 要**降级**，用桩缓存待提交 |
| 9 | steam_appid.txt.txt 不可能 | Windows 隐藏扩展名**很常见** |
| 10 | 插件写"4.3+"就覆盖 4.7.2 | 要**逐项验收** |
| 11 | Game Center ID 就是玩家 ID | 要**换绑**成业务 player ID |
| 12 | token 放客户端没事 | **秘密必须留服务端** |
| 13 | 有 DRM 就防作弊了 | DRM ≠ 反作弊 |
| 14 | 内购客户端说了算 | 要**服务端校验** |
| 15 | EOS 接入简单 | 跨平台统一但**接入复杂** |
