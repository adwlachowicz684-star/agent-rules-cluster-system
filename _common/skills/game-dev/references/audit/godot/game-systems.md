# game-systems — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的做法部分：`howto/godot/game-systems.md`
> 流程见 `flow/godot/inventory/`（库存部分）

## 库存：常见坑

⚠ **库存的四层是硬约束**：`ItemDefinition`（共享、不可变）/
`ItemInstance`（唯一 id、耐久、附魔）/ `InventorySlot`（只存 id+count）/
`Inventory`（管槽位与实例）。⛔ 槽位直接存物品对象是头号反模式。

| # | 反模式 | 后果 |
|---|---|---|
| 1 | 槽位直接存物品对象 | 移动/交换时深拷贝，耐久附魔被复制出多份且不同步 |
| 2 | 唯一物品（`is_unique`）走堆叠分支 | 出现两把同 id 神器 |
| 3 | `max_stack = 1` 的装备走堆叠分支 | 同上，装备被"合成"成一个槽 |
| 4 | 容量满了静默丢弃 | 玩家物品**凭空消失**，且无法追回 |
| 5 | `add()` 不返回实际放入数量 | 调用方不知道放了多少，部分放入被当成全放入 |
| 6 | 交易/移动改一半失败 | **脏数据不可逆**——物品既在原处又在新处，或两边都没了 |
| 7 | 实例 id 用 `randi()` 生成 | 存档回读后 id **冲突**（不同物品拿到同一 id） |
| 8 | 客户端库存权威 | 改内存加物品，服务端无从校验 |
| 9 | UI 直接改库存数据 | 逻辑散落在 UI 里，无法单测、无法服务端复用 |
| 10 | `remove()` 后不 erase 实例字典 | 实例泄漏，存档体积单调增长 |
| 11 | 堆叠判定只看 `id` 不看 `max_stack` | 不可堆叠物品被强行堆叠 |
| 12 | 序列化只存 slots 不存 instances | 回读后所有实例数据丢失（耐久归满、附魔消失） |
| 13 | 堆叠时把不同 `custom_data` 的实例并到一起 | 附魔/耐久不同的物品被合并，数据丢失 |
| 14 | 容量用"当前槽数"而不是配置值 | 扩容道具改了配置但已存档的容器没变 |
| 15 | 移动槽位时先删后加 | 中间态失败 = 物品消失（⛔ 要先试算再提交） |

## 对话系统：常见坑

| # | 反模式 | 后果 |
|---|---|---|
| 16 | 对话内容写在代码里 | 改一句台词要重编译，且无法交给文案 |
| 17 | 对话推进靠 `await` 嵌套 | 中途退出/存档时状态机悬空 |
| 18 | 分支条件用 if-else 硬编码 | 加一条分支要改 Runner |
| 19 | 对话中不锁玩家输入 | 对话时角色还能跑，能卡进对话触发区循环触发 |
| 20 | 打字机效果用 `text +=` 逐字累加 | 每帧全量重建文本，长句明显卡顿 |

## 任务系统：常见坑

| # | 反模式 | 后果 |
|---|---|---|
| 21 | 任务进度靠每帧轮询检查 | 帧开销随任务数线性增长，且顺序不确定 |
| 22 | 任务状态用散落的布尔 | 加一个任务要改多处，无法序列化 |
| 23 | 任务目标与完成条件写死在类里 | 每种任务一个新类，配置驱动失效 |
| 24 | 已完成任务的奖励重复发放 | 靠"是否已领"布尔，跨存档/跨天判断错 |
| 25 | 任务链依赖靠数组顺序隐式表达 | 策划拖一下顺序，前置关系就变了 |

## 命令解释器（共用地基）：常见坑

| # | 反模式 | 后果 |
|---|---|---|
| 26 | 命令直接执行而不经过解释器 | 无法撤销、无法日志、无法服务端校验 |
| 27 | 命令参数用 `Array` 裸传 | 顺序错了不报错，静默执行错的参数 |
| 28 | 命令执行失败但不回滚 | 扣了费没给物品 |
| 29 | 存档不写版本字段 | ⛔ 以后无法迁移；版本要**第一行**且带默认值策略 |
| 30 | 每帧 `load()` 图标纹理 | ⚠ 每次都走一次磁盘与解码；要**缓存**并按 id 复用 |
