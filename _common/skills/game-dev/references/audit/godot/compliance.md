# compliance — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/compliance.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 上线前补一份隐私政策就合规 | 中国大陆硬门槛在**立项阶段**：出版单位资质 + ICP 证 + 版号 |
| 2 | 版号 80 工作日就是拿号周期 | 80 日是**受理后**行政时限，不含前置评估、初审、补正、内容修改 |
| 3 | 个人开发者账号能上线商业游戏 | **不能**，出版/运营主体都是法定资质 |
| 4 | 内测不用版号 | 公开可注册 / 收费 / 有广告收益的测试**视为运营**；限额测试 ≤ 2 万且须删档 |
| 5 | 没收入或已退款就没事 | 已见无违法所得仍罚 5.5 万元的案例 |
| 6 | 防沉迷是 22:00–8:00 + 节假日 3 小时 | 那是 **2019 通知**；现行（2021 通知）是**周五六日及法定节假日 20–21 时、1 小时** |
| 7 | 实名是充值前做一下 | 是**登录前置**，未实名（含游客模式）**不得提供任何服务** |
| 8 | 客户端校验证件格式 = 实名 | 信任根必须是**服务端** + 国家统一验证系统的结果 |
| 9 | 充值限额按单款游戏算 | 法条口径是**同一网络游戏企业**；跨产品聚合要由统一账号做 |
| 10 | 人脸验证越全越好 | 生物识别是**敏感个人信息**，需特定目的 + 充分必要性 + 单独同意 |
| 11 | 8+/12+/16+ 是分级制度 | 是**适龄提示**，且**没有 18+ 档** |
| 12 | 适龄提示阈值可以照行业惯例写 | 官方公开页面未给出逐项阈值，**不得编造** |
| 13 | 未实名可以先试玩再提示 | **未实名不得游戏**的规则高于任何"先试玩"设计 |
| 14 | 注销账号 = `DELETE FROM users` | 要做成**状态机**；法定保留数据走去标识化 + 到期删除标记 |
| 15 | 第三方 SDK 删不掉就能免责 | **不能**，接收方必须同步删除或停止处理 |
| 16 | 只存设备标识符不涉及未成年人 | 昵称、头像、聊天、位置、支付记录**若可识别未成年人**都要纳入评估 |
| 17 | 服务器在国内就没有出境 | 跨境**运维、备份、访问**都算；且按"当年累计人数"动态判定 |
| 18 | UGC 是用户自发内容，平台无责 | 昵称/头像/公会名/聊天/公告/交易留言**都要治理** |
| 19 | 敏感词库是一份固定文件 | 要**版本号 + 来源 + 更新日期 + 审批 + 失效日期**，且有误杀漏杀抽检 |
| 20 | GDPR 儿童同意年龄是 13 岁 | 默认 **16 岁**，成员国可降至不低于 13，**按玩家所在地**判定 |
| 21 | 云服务总部在欧洲就没跨境问题 | 仍需充分性决定 / 适当保障 / 特定例外 |
| 22 | CCPA 响应 45 天 | 45 日，可**通知后延长 45 日**，合计最长 90 日 |
| 23 | 韩国 16 岁以下 0–6 时锁服 | 存在废止争议，**未核实前不得硬编码** |
| 24 | 商店隐私问卷填一次就行 | 覆盖自身 + 第三方 SDK 的**实际行为**，新增 SDK 必须同步更新 |

| 25 | 合规可以边做边定地区 | 地区决定适用哪套规则；先建的那套在另一地区可能是错的，改造成本远高于一开始就分清 |
| 26 | 版号和商店审核一样，提交后等结果就行 | 是**上线前置许可**，周期与商店审核不在一个量级；按商店审核周期并行排期会整体失效 |
| 27 | 无版号上线最多下架，以后补办 | 后果发生在已投入推广之后；停损成本远高于延后上线，⛔ 不存在'继续跑等补办'这个选项 |
| 28 | 送审材料是法务的事 | 部分材料需**技术产出**（屏蔽词库版本、防沉迷版本、适龄评估截图）；送审前才发现缺项会直接卡住，无法临时补齐 |
| 29 | 法律阈值先按行业惯例填一个，以后再改 | 法律文本会修订；填进去的数字会被下游当事实使用，⛔ 且没人会再去复核它。留空会被门禁拦截，填错不会 |
| 30 | 直接填商店问卷就行，不必先做数据地图 | 没数据地图只能凭印象填；⛔ 新增 SDK 带来的新数据流没人知道要更新，声明必然对不上 |
| 31 | 先采着，以后可能用 | 采集已发生即产生合规义务，⛔ 而且没人会回来清理，数据地图会持续膨胀 |
| 32 | 新增 SDK 记得更新隐私清单就行 | SDK 分散在各人各分支接入；⛔ 一次漏更新要到商店审核阶段才发现，此时数据流已上线运行 |
| 33 | 把所有第三方域名填进追踪域最保险 | 官方原文：未授予追踪许可时对这些域的请求**会失败且 App 收到错误**；⛔ 崩溃上报、远程配置、登录鉴权会一起静默失效，且不报错 |
| 34 | 先采集，同意开关后补 | 同意前的采集已经发生，⛔ 且无法追溯哪些数据是违规采的；补救只能全量清除（含合法数据） |
| 35 | 实名放在充值前做一下就行 | 未实名玩家可完整游玩，⛔ 防沉迷的时段限制对其无法生效，等于绕过整个未成年人保护闭环 |
| 36 | 客户端判定加提示就够了 | 客户端可被改包绕过；⛔ 且服务端日志里没有该次拦截记录，无法向监管举证'已经拦了' |
| 37 | 充值限额做成后台可配置更灵活 | 一旦可调就存在被调高且不留合规评审记录的路径；⛔ 举证时需证明'取值始终是法条数字'，配置项做不到 |
| 38 | 客户端自己算时长并弹提示就够了 | 本地计时可被改系统时间绕过（⛔ 系统时钟可被玩家手动设置）；且客户端结果与服务端账不一致时无法对齐 |
| 39 | 各地区规则先按已知信息写死 | 规则可能已变更（如某地区宵禁是否已废止）；⛔ 写死后会持续执行一条已失效的限制，表现为该地区玩家特定时段无法登录且不报错 |
| 40 | 注销就是 DELETE 掉用户行 | 下游日志、订单、举报记录仍留着同一份个人信息；⛔ 既没完成删除义务，也没留下完成证据 |
| 41 | 删除失败时静默跳过没关系 | 用户认为已注销而数据仍在；⛔ 且没有任何记录说明哪里没删掉，无法补救也无法举证 |
| 42 | 保留期限统一填一个天数 | 不同数据的必要性完全不同（订单凭证 vs 行为日志）；⛔ 统一天数要么过短无法举证、要么过长超出必要，且填后无人复核 |
| 43 | 数据出境是个'是否出境'的开关 | 是**目的 × 类型 × 人数**的组合判定；⛔ 布尔开关表达不了'这类出境那类不出'，结果是该评估的没评估 |
| 44 | 14 岁以下与敏感信息走同一套流程 | 单独同意是硬性要求；⛔ 混在同路径意味着从未取得过有效的单独同意，而这**在流程上完全看不出来** |
| 45 | 不必专门维护 SDK 清单 | 没人知道线上到底接了哪些 SDK；⛔ 于是数据地图不可能完整，商店问卷必然有遗漏，且只在审核被拒时暴露 |
| 46 | 客户端过滤违规内容就够了 | 改包即可绕过；⛔ 且服务端从未见过违规内容，也就没有违规记录，无法举证'已经治理了' |
| 47 | 屏蔽词库不用进构建元数据 | 出事时无法回答'当时用的是哪版词库'；⛔ 而举证需要的正是这个对应关系 |
| 48 | 处置完就行，不必留痕 | 监管问到'处理了多少违规内容'时无法回答；⛔ 也无法证明处置是及时的 |
| 49 | 新增 SDK 靠人工记住更新隐私清单 | SDK 由不同人在不同分支接入；⛔ 一次漏更新就把未声明的数据流带上线，且要等到审核才发现 |
| 50 | 可以用大小写区分国内版和海外版 | 官方：Bundle ID **大小写不敏感**；⛔ 系统视为同一应用，失败发生在签名与安装阶段（覆盖安装/签名冲突），且没有任何日志说明是大小写问题 |
| 51 | 导出项目名随意，带空格也没事 | 官方 Note：带空格可导致 Xcode 项目文件损坏；与源项目同名会导致签名问题；⛔ 两条在 Godot 侧**全程无报错**，损坏要到 Xcode 里才显现 |
| 52 | Team ID 留空也能导出 | 官方：留空会导致导出器**直接抛错**；⛔ 且报错在导出末尾，前面的配置工作全部白做 |
| 53 | 元数据清单写成文档就够了 | 文档会过期而门禁不会；⛔ '缺一项'的后果在发布后才显现（无法举证、无法回溯），那时包已经出去了 |
| 54 | 问卷凭印象填就行 | SDK 升级、域名变更都不会反映到问卷上；⛔ 声明与实际不一致会同时触发商店审核与监管风险 |
| 55 | 版本号不改也能提 | 商店会拒收；⛔ 格式非法同样拒收，且两者的错误信息都不指向'版本号没改' |
| 56 | 提交前不必抓包 | SDK 初始化时机与 A/B 分支都会影响实际请求；⛔ 只测一条路径会漏掉'部分用户才触发'的数据流 |
| 57 | 只在已授权状态测就够了 | 未授权才是相当比例用户的真实状态；⛔ 失败表现是'部分功能静默不可用'，在已授权环境下永远不会复现 |
| 58 | 只测注销成功路径 | 失败路径从未被执行过；⛔ 而'用户以为已注销但数据还在'恰恰只发生在失败路径上 |
| 59 | 正常时间下测过就行 | 系统时钟可被玩家手动设置，客户端本地计时会因此失效；⛔ 且这个失效只在改时间后才出现，正常环境下全绿 |
| 60 | 只测正常发布流程 | 门禁从未在失败路径上被验证过；⛔ 而门禁失效的后果（发布后无法举证）只在真缺项时才暴露 |
| 61 | 待法务复核项可以先上线后补 | 法律文本会修订；⛔ 未复核意味着线上可能正在执行一条已失效或错误的规则，且不报错，只表现为某些用户被莫名限制 |

## 审核时逐条问自己

1. 版号 / 出版物号 / 运营主体是否在**构建元数据**里？发布门禁是否检查？
2. 送审版本与正式版本的**脚本、屏蔽词库、防沉迷说明**是否一致？
3. 未实名用户是否**真的**进不了游戏（含游客模式）？
4. 未成年人时段用的是 **2021 通知口径**还是 2019 口径？
5. 充值限额的**累计口径**是单游戏还是企业统一账号？
6. 注销流程是否**有状态、有证据**？第三方是否同步？
7. 数据地图是否覆盖**境外客服工单与远程排查**这类隐性出境？
8. 新增 SDK 时 CI 是否阻止未更新隐私清单的版本合入？
9. 敏感词库是否有**版本号与失效日期**，还是一份没人维护的文本？
10. 有没有任何一条合规判定**只跑在客户端**？
