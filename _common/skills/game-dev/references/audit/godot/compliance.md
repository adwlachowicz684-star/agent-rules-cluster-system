# compliance — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/compliance.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 上线前补一份隐私政策就合规 | 中国大陆硬门槛在**立项阶段**：出版单位资质 + ICP 证 + 版号 |
| 2 | 版号 80 工作日就是拿号周期 | 80 日是**受理后**行政时限，不含前置评估、初审、补正、内容修改 |
| 3 | 个人开发者账号能上线商业游戏 | **不能**，出版/运营主体都是法定资质 |
| 4 | 内测不用版号 | 公开可注册 / 收费 / 有广告收益的测试**视为运营**；限额测试 ≤ 2 万且须删档 |
| 5 | 没收入或已退款就没事 | 已见无违法所得仍罚 5.5 万元的案例 |
| 6 | 防沉迷是 22:00–8:00 + 节假日 3 小时 | 那是 **2019 通知**；现行（2021 通知）是**周五六日及法定节假日 20–21 时、1 小时** |
| 7 | 实名是充值前做一下 | 是**登录前置**，未实名（含游客模式）**不得提供任何服务** |
| 8 | 客户端校验证件格式 = 实名 | 信任根必须是**服务端** + 国家统一验证系统的结果 |
| 9 | 充值限额按单款游戏算 | 法条口径是**同一网络游戏企业**；跨产品聚合要由统一账号做 |
| 10 | 人脸验证越全越好 | 生物识别是**敏感个人信息**，需特定目的 + 充分必要性 + 单独同意 |
| 11 | 8+/12+/16+ 是分级制度 | 是**适龄提示**，且**没有 18+ 档** |
| 12 | 适龄提示阈值可以照行业惯例写 | 官方公开页面未给出逐项阈值，**不得编造** |
| 13 | 未实名可以先试玩再提示 | **未实名不得游戏**的规则高于任何"先试玩"设计 |
| 14 | 注销账号 = `DELETE FROM users` | 要做成**状态机**；法定保留数据走去标识化 + 到期删除标记 |
| 15 | 第三方 SDK 删不掉就能免责 | **不能**，接收方必须同步删除或停止处理 |
| 16 | 只存设备标识符不涉及未成年人 | 昵称、头像、聊天、位置、支付记录**若可识别未成年人**都要纳入评估 |
| 17 | 服务器在国内就没有出境 | 跨境**运维、备份、访问**都算；且按"当年累计人数"动态判定 |
| 18 | UGC 是用户自发内容，平台无责 | 昵称/头像/公会名/聊天/公告/交易留言**都要治理** |
| 19 | 敏感词库是一份固定文件 | 要**版本号 + 来源 + 更新日期 + 审批 + 失效日期**，且有误杀漏杀抽检 |
| 20 | GDPR 儿童同意年龄是 13 岁 | 默认 **16 岁**，成员国可降至不低于 13，**按玩家所在地**判定 |
| 21 | 云服务总部在欧洲就没跨境问题 | 仍需充分性决定 / 适当保障 / 特定例外 |
| 22 | CCPA 响应 45 天 | 45 日，可**通知后延长 45 日**，合计最长 90 日 |
| 23 | 韩国 16 岁以下 0–6 时锁服 | 存在废止争议，**未核实前不得硬编码** |
| 24 | 商店隐私问卷填一次就行 | 覆盖自身 + 第三方 SDK 的**实际行为**，新增 SDK 必须同步更新 |

## 审核时逐条问自己

1. 版号 / 出版物号 / 运营主体是否在**构建元数据**里？发布门禁是否检查？
2. 送审版本与正式版本的**脚本、屏蔽词库、防沉迷说明**是否一致？
3. 未实名用户是否**真的**进不了游戏（含游客模式）？
4. 未成年人时段用的是 **2021 通知口径**还是 2019 口径？
5. 充值限额的**累计口径**是单游戏还是企业统一账号？
6. 注销流程是否**有状态、有证据**？第三方是否同步？
7. 数据地图是否覆盖**境外客服工单与远程排查**这类隐性出境？
8. 新增 SDK 时 CI 是否阻止未更新隐私清单的版本合入？
9. 敏感词库是否有**版本号与失效日期**，还是一份没人维护的文本？
10. 有没有任何一条合规判定**只跑在客户端**？
