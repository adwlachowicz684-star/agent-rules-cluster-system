# xr — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/xr.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 移动相机就是移动玩家 | 相机每帧被覆盖，必须动 `XROrigin3D` |
| 2 | 控制器有速度 API | **没有**，要自己多样本平均 |
| 3 | 单帧差分算速度够用 | 120Hz 上出尖峰 |
| 4 | 抓取只要改父子关系 | 失去物理碰撞 |
| 5 | 释放不传速度也行 | 手感极假，"掉在手里" |
| 6 | 睡着的刚体能抓 | 抓不起来，要禁休眠 |
| 7 | 抓取不用记偏移 | 物体瞬移到手腕中心 |
| 8 | 传送只要命中就行 | 要四重判定，否则传进墙里 |
| 9 | 传送可以瞬移 | 必须淡入淡出，否则晕 |
| 10 | VR 掉帧只是卡 | 会让人**呕吐** |
| 11 | 所有 draw call 都 ×2 | 后处理/MSAA 翻倍，几何大多共享 |
| 12 | MSAA + 注视点随便开 | 某些合成层上可能冲突 |
| 13 | 手部追踪 = 手指精度够 | `has_tracking_data` 为真可能仍是控制器推断 |
| 14 | VR UI 用 2D 控件 | 要用 3D 面板 + 指针射线 |
| 15 | world_scale 只影响某个物体 | 是全局统一缩放 |
| 16 | 相机 cull_mask / FOV 能用来隐藏层或调视野 | `use_xr` 为真时**只有近远裁剪面可信**，改了不生效，而面板上确实勾着 |
| 17 | 相机跟场景其余部分一样走物理插值 | `XRCamera3D` 硬编码关闭插值，挂它下面的手持物与场景不同步、相对抖动 |
| 18 | `tracking_confidence` 在 `XRController3D` 上 | 在 **`XRPose`** 上；`XRNode3D` 只有 `get_pose()`，没有这个属性 |
| 19 | 追踪丢失后手柄会自动隐藏 | `show_when_tracked` 默认 `false`，且 `invalidate_pose` **不清最后状态**，手柄停在原地继续参与交互 |
| 20 | 位姿不可信时照常拿去算 | 必须有降级路径（暂停交互 / 保持上一有效位姿 / 提示玩家），⛔ 不能假设位姿永远有效 |
| 21 | `center_on_hmd` 只是把位置居中 | 默认 `RESET_FULL_ROTATION` **会重置朝向**，三种模式必须显式选，⛔ 不写就是重置玩家朝向 |
| 22 | 转向方式写死平滑旋转就行 | 不提供 snap turn 选项会让一部分玩家直接晕，⛔ 而平滑转向在开发机上自己测不出 |
| 23 | 降级路径看代码分支走通就行 | 必须**真机遮挡实测**：分支写对了不代表触发条件对，遮挡事件在编辑器里根本不发生 |
| 24 | 传送命中了就是合法落点 | 要四重判定（命中 / 法线朝上 / 头顶空间 / 允许区域），⛔ 少一重就传进墙里或虚空 |
| 25 | VR 掉帧只是卡一下 | 掉帧**致晕**，必须人为注入卡顿实测恢复过程，⛔ 不是看平均帧率 |
