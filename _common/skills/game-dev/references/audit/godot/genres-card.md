# genres-card — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/genres-card.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 连锁用信号连接实现 | 无法控顺序、入栈、插入响应、取消，要用显式栈 |
| 2 | 效果里直接 `target.take_damage(5)` | 跳过响应链，要生成事件入栈 |
| 3 | `Array.shuffle()` 洗牌 | 用全局 RNG 状态，无法复现/服务器校验 |
| 4 | 混用 `randf()` 与 `rng.randf()` | 两套状态，同种子不同结果 |
| 5 | 牌库空了洗弃牌堆再抽同帧无保护 | 会抽到刚洗进去的同一张，要标记 is_reshuffling |
| 6 | 卡牌是 Node/PackedScene | 同张卡多份实例成倍耗内存，数据要 Resource |
| 7 | 卡牌存档用 JSON | 无法表达 Resource 引用与类型，要用 .tres/.res |
| 8 | `FLAG_COMPRESS` 对 .tres 有效 | 仅对二进制资源有效 |
| 9 | 循环里 `instantiate()` 卡牌视图 | 很贵，要用固定容量池 |
| 10 | UI 重排滥用 `queue_redraw()` | 布局重算比纹理更耗，会拖垮拖拽帧 |
| 11 | 效果栈无深度保护 | 响应链会无限递归，要设上限与"本轮已响应"标记 |
| 12 | 伤害数字/特效在逻辑里直接播 | 应从结算结果驱动 |
