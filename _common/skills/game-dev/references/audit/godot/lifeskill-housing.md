# lifeskill-housing — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/lifeskill-housing.md`
>
> 边界：本篇是**生活玩法本身**。时间推进的数学见 `audit/godot/time-progression.md`。

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 采集/加工/家园是四个玩法 | 是**同一个材料闭环的三个闸门** |
| 2 | 各系统自己定义材料 ID | 会出现**多套 ID/堆叠/绑定/权威源** |
| 3 | 绑定只在 UI 显示 | 必须**随物品流动**；否则可绕公共加工设施转移 |
| 4 | `duplicate(false)` 就深拷贝了 | **浅拷贝**，数组/字典/嵌套 Resource 仍共享 |
| 5 | `local_to_scene` 能当持久状态 | 只是场景级局部，**不能替代服务端状态** |
| 6 | 每个矿点一个节点 | 2000 个节点 → 节点树/循环/碰撞/序列化/draw call 全线性叠加 |
| 7 | 刷新用相对倒计时 | 停服/分区/离线/时钟校正会**累积漂移**；要用绝对锚点 |
| 8 | 开放世界与个人领地用同一套刷新 | 前者要竞争与随机占槽，后者要确定性与离线收益 |
| 9 | 固定点位整点刷新 | 玩家**整点蹲守**；用共享池随机占槽 |
| 10 | 保底靠放大 RNG | 保底要**进状态**（未命中计数持久化） |
| 11 | 配方就是单入单出 | 真实链是**多级 DAG**：中间物/副产物/损耗/失败 |
| 12 | 入队即扣材料 | 要**开始制作时**原子扣减；入队只做可逆预留 |
| 13 | 批量制作塞进单次 RNG | 要拆成 N 个任务，否则一次承担极高损失 |
| 14 | 不用检查循环依赖 | 一个"通用回收配方"就能**无限增值** |
| 15 | 材料不足直接删任务 | 要 `READY/MISSING/WAITING/PAUSED`，**自动暂停优于静默删除** |
| 16 | 客户端按名称模糊匹配替代材料 | 替代组必须**数据层显式配置** |
| 17 | 失败全保留材料 | 品质堆叠无风险 |
| 18 | 失败清空所有材料 | 新玩家无法接受 |
| 19 | 暴击+完美+无损能叠加 | 三类要**互相独立** |
| 20 | 熟练度线性增长 | 线性增产/涨价会崩；收益曲线要有边际 |
| 21 | 回收率不封顶 | 出现**完美闭环**、供给通胀、**无损刷熟练度** |
| 22 | 用物理碰撞做放置校验 | 碰撞是"这一帧是否重叠"，受浮点/休眠/CCD 影响；**不可回放不可存档** |
| 23 | 旋转用连续角度 | 要 **90° 枚举**；网格用整数 `Vector3i` |
| 24 | 各端自己 snap | 要**共用同一个 snap()**，物理查询不能分别决定 |
| 25 | 简单校验就进物理阶段 | 要按十步顺序，任何前置失败都不进物理 |
| 26 | 多人同时摆放不用版本 | 要 `home.version`，不匹配返回 `stale_version` |
| 27 | 家具加成无限累加 | 要 `max_furniture`/`total_bonus_cap`/`per_stat_cap`/同类上限 |
| 28 | 可见性 = 编辑权 | 两个**独立权限维度**；访客不能改经济状态 |
| 29 | 同步物理查询结果 | 不可回放；只同步**批准后的状态** |
| 30 | 纯产出没副作用 | 会**通货膨胀**；要从净产出速率反推 |
| 31 | 成千上万 MeshInstance3D 没问题 | 逐个提交慢，要 **MultiMesh**（仍需外部可见性 AABB） |
| 32 | `duplicate(true)` 就深拷贝了 | **Array/Dictionary 里的子资源永不复制**（官方），改副本会改到模板 |
| 33 | 熟练度等级 = 配方解锁 | 知识与等级是**两张表**；解锁走知识表（一次性事件） |
| 34 | 权重表与等级表共用一套数值 | 三张表职责不同；调等级会**顺带改坏品质分布** |
| 35 | `any_peer` 收到就执行 | 必须 `get_remote_sender_id()` 校验，否则可冒名操作 |
| 36 | 动态节点 RPC 随便命名 | 两端 **NodePath 必须相同**，否则**静默不调用**且不报错 |
| 37 | 官方会校验 RPC 参数 | **参数不校验**（签名只校验函数名/返回类型/NodePath），服务端必须逐项校验 |
| 38 | 判定跑客户端也能兜住 | 采集产出/合成结果/放置合法性**必须只跑服务端** |

## 审核时逐条问自己

1. 同一种材料在采集/加工/家园里是**一个 ID** 吗？堆叠与绑定规则一致吗？
2. 采集点是**数据 + 视图**还是节点自带状态？
3. 刷新存的是**绝对时间**还是倒计时？停服/校时后会不会漂移？
4. 保底计数**持久化**了吗，还是只在内存里放大 RNG？
5. 配方支持中间物/副产物/损耗/失败吗？多级链做过**循环依赖检查**吗？
6. 材料扣减是**开始时原子扣**还是入队就扣？失败时退回路径对吗？
7. 失败与损耗有没有承担经济功能？暴击/完美/无损是不是互相独立？
8. 熟练度与回收率有**硬上限**吗？会不会出现无损刷熟练度？
9. 放置校验是**整数占格表**还是物理查询？各端 `snap()` 是同一个吗？
10. `home.version` 有吗？多人同时摆放会冲突覆盖吗？
11. 家具加成有 `per_stat_cap` 吗？摆一千张桌子会怎样？
12. 有没有任何一条"采集产出 / 合成结果 / 放置合法性"判定**只跑在客户端**？
