# build-affix — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/build-affix.md`
>
> 边界：本篇是**构筑合法性与词条组合语义**。卡牌对战本身见 `audit/godot/genres-card.md`。

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 构筑和词条是一回事 | 两条规则：构筑约束**牌池与赛制**，词条约束**属性组合** |
| 2 | 三层（构筑/装备词条/局内词条）放一个对象 | 后期最难拆的数据债务 |
| 3 | 共享 Resource 直接改 | 会**污染其他实例**；要 `duplicate(true)` 或 `local_to_scene` |
| 4 | 把临时强化塞进共享 `.tres` | ⛔ 定义要不可变 |
| 5 | AffixOp 一个"数值"字段够 | 要 `stat × op × value × condition`，乘除要有 group 与 cap |
| 6 | 词条存最终值方便 | **改表后无法重算**，多版本混合不可审计 |
| 7 | 一个 version 字段够 | `generation_version`（掉落/槽位）与 `balance_version`（数值）**要分开** |
| 8 | 旧装备"转成新版本"就行 | 旧 roll 映射变了就没法含糊；要明选回滚/重随机/取旧值/锁定 |
| 9 | 从一个大池抽 N 条再删不合法的 | 槽位数失控或反复重试；要**先定槽位再逐槽抽** |
| 10 | 槽位绑一个全局池 | 要按**部位 + 槽位类型**声明 |
| 11 | UI 判断"名称相同就禁止重复" | 同 `uniqueness_group` 但**名称不同**仍会超量 |
| 12 | 减伤相乘没问题 | 两条 75% → 93.75% 总减伤，逼近**无敌** |
| 13 | 组内也相乘 | 要**组内求和、组间相乘**，再 clamp |
| 14 | 互斥只在生成时检查 | 要四个入口：生成/换装/局内选择/属性聚合 |
| 15 | 协同就是"加 15%" | 数值协同与**触发协同**是两种，后者要走事件图 |
| 16 | 给每对词条写组合奖励 | 形成 **O(n²)** 声明；要用 trigger + condition_set |
| 17 | 每次伤害遍历所有词条 | 要 **source table + dirty snapshot** |
| 18 | 临时词条不管消失时机 | 会**跨局残留**；要绑 `combat_ended`/`room_cleared` |
| 19 | 构筑校验点"开始"时做一次 | 要**组卡/保存/开局三层**，开局可能因轮换而失效 |
| 20 | 保存 30 张物理卡 | 保存**意图**（card_id + count），加载再展开句柄 |
| 21 | 客户端校验通过就能开局 | 服务端要**重跑同一套 validator 并签名** |
| 22 | 卡牌改数值后旧构筑继续用 | 要禁开局 + 迁移预览，⛔ **不要随机替换** |
| 23 | 禁用表写死 | 要可热更 |
| 24 | 三选一必然有核心牌 | ⓘ **不是通用规则**，属策划承诺 |
| 25 | 服务端权威 = 在 Godot 里复制逻辑 | 要**同一份规则定义、同一份评估顺序**，否则版本漂移 |

## 审核时逐条问自己

1. 构筑 / 装备词条 / 局内词条 是三个对象还是一个？
2. 共享的 Definition 有没有被原地修改过？
3. 装备存的是**最终值**还是 `affix_id + roll + 双 version`？
4. `generation_version` 和 `balance_version` 分开了吗？
5. 减伤走的是**组内求和 + 组间相乘 + clamp** 吗？有全局承伤下限吗？
6. 互斥检查覆盖了**四个入口**吗？
7. 触发协同走事件图了吗？有没有 O(n²) 的配对声明？
8. 每次属性访问是全量遍历还是脏标记快照？
9. 临时词条在局末**确实消失**了吗？
10. 构筑在**组卡/保存/开局**三处都校验了吗？服务端会重跑并签名吗？
11. 卡牌改数值后，旧构筑是禁止开局还是被静默按新数值使用了？
12. 有没有任何一条"构筑合法性 / 词缀生成"判定**只跑在客户端**？
