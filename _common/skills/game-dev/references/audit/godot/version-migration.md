# version-migration — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/version-migration.md`

## 常见坑

| 坑 | 后果 |
|---|---|
| 认为"4.x 内部升级"很安全 | 4.3/4.4 都是结构性变化 |
| 4.3 后仍用旧 `set_cell(layer, ...)` | 不报错但图块不出现 |
| 忽略 2D 物理插值 | 手感变了，看不出原因 |
| 靠 `using` 别名处理 TileMap | 图层/坐标/碰撞全错 |
| 迁移前不备份 | 官方工具不备份 |
| 认为自动改名覆盖了字符串 | 路径/组名/信号名不会改 |
| 迁移 `.godot/` 产物 | 格式不兼容 |
| 不知道 4.x 自动 randomize | 随机行为变了，回放失效 |
| 用 `has_feature` 猜 API | 它是环境检测 |
| 插件写版本范围 | 小版本升级后崩溃 |
| 先改业务再处理资源 | 分不清是脚本还是资产问题 |
| 长期维持双版本 | 分支差异持续扩大 |
