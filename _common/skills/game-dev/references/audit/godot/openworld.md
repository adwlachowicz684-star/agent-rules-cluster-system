# openworld — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/openworld.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 异步加载就不卡 | `instantiate` 必须主线程，才是大头 |
| 2 | `load_threaded_get` 不阻塞 | 未完成时**会阻塞** |
| 3 | 一个半径够了 | 没有滞回会在边界**抖动加载** |
| 4 | 按数量分帧 | 要按**时间预算**切 |
| 5 | Godot 有内置地形 | 4.x **没有**，用 Terrain3D 或自写 |
| 6 | 双精度是勾选项 | 要重编译 editor + **所有**模板 |
| 7 | 8192 米内绝对安全 | 误差随 2 的幂成倍变，无固定阈值 |
| 8 | 原点重置只移相机 | 所有坐标消费方都要同步 |
| 9 | 大世界精度问题会早点暴露 | 小项目**测不出来** |
| 10 | 自动 LOD 按距离 | 按**屏幕覆盖度** |
| 11 | OBJ 也能自动生成 LOD | **不能**，glTF/blend/FBX 才行 |
| 12 | 高频加载用 queue_free | 要池化 |
| 13 | 存档存全量地形 | 存**增量** |
| 14 | 双精度后插件也变双精度 | 插件若无对应构建，仍按 32 位 |
| 15 | 精度上限只记一个数 | 官方按**视角**分档：第一人称 4096、第三人称 8192、俯视 32768、一般 3D 65536，**错一档差 2 倍** |
| 16 | 双精度开了渲染就不抖 | 位置送 GPU 前**降回单精度**，靠 emulation 模拟；渲染改善**不是自动的** |
| 17 | Metal 也支持 shader 双精度 | **不支持**（所有 Apple 设备）；部分集显直接崩溃 |
| 18 | 双精度是「性能换精度」的普适解 | 低端移动设备**表现不好**，官方建议低端改用原点重置 |
| 19 | 传送后等纹理自己加载完 | 要 `flush_texture_streaming()`，否则**从低分辨率渐变**（传送过去一片模糊） |
| 20 | 纹理流送开了就完事 | 超 VRAM 预算会**自动降分辨率**，要查 `get_memory_budget_bytes_used()` |
| 21 | 加载只有「加载/卸载」两态 | 要请求→解码→实例化→就绪→预热→卸载，缺态则状态不一致 |
| 22 | 超出半径立刻卸载 | 要 `unload_delay`，否则边界来回走**抖动式加载** |
| 23 | 池化对象直接复用 | 不重置状态则**残留上一次的数据** |
| 24 | 池子可以无限增长 | 要设上限，否则内存**只增不减** |
| 25 | 地形用一张大 mesh | 要分块，否则无法流式加载、无法部分更新 |
| 26 | 剔除就用 `queue_free` | 高频切换用 `visible` + 池化，`queue_free` 重建成本高 |
| 27 | 导航网格全量重烘 | 要分块烘，否则每加载一个 chunk 全量重烘一次 |
| 28 | 原点重置只移玩家和相机 | 音频监听器、粒子、后处理目标、物理、导航**都要同步** |
| 29 | 原点重置只改 Node3D | shader uniform 里的世界坐标**不会跟着改** |
| 30 | 单机正常多人就正常 | 各端原点不同，每个网络包都要 `world ↔ local` 转换 |
| 31 | 大世界存档不用版本号 | 老档**悬空**，改结构后读不出来 |
| 32 | 验收在原点附近跑一圈就行 | 要**跑到世界边缘**测，精度问题只在远处出现 |
| 33 | 可见距离设大点就能看远 | 剔除失效，draw call 暴涨 |
| 34 | LOD 突跳直接切就行 | 用 **dither fade** 缓解，代价很小 |
| 35 | chunk 加载失败重试就行 | 要记录失败状态，否则**反复重试**卡死 |
| 36 | 加载预算按数量切 | 要按**时间**切，数量与耗时不成正比 |
| 37 | 装饰物随便放 | 要按 chunk 归属，否则卸载时**漏卸** |
| 38 | 首帧加载慢是正常的 | 要区分**资源加载**与**着色器编译**，两者叠加互相掩盖 |
