# art-assets — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/art-assets.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Filter 在纹理导入页设 | 4.x 在 **CanvasItem 属性**，项目设置是默认 |
| 2 | 像素糊是 PNG 质量差 | 五个环节叠加，先查 Filter 和整数缩放 |
| 3 | Repeat 开了更省事 | UI/图标开了会采样到相邻像素 |
| 4 | Mipmap 是画质选项 | 是"缩小稳定性"，代价内存 +33% |
| 5 | 图集内切片能单独设 Repeat | 判定对象是**整个图集纹理** |
| 6 | 无损压缩最好 | 按用途分层，显存和加载时间也要算 |
| 7 | Basis Universal 万能 | 质量差、编码慢、加载要转码 |
| 8 | Basis 显存更低 | 与 VRAM Compressed 相近 |
| 9 | glTF 导入就不用检查 | 材质、缩放、动画仍要核对 |
| 10 | 材质 clone 一下没关系 | 破坏批处理（自动实例化要求同材质） |
| 11 | 法线贴图当颜色导入 | sRGB 设错，法线/粗糙度/金属度必须 **Linear** |
| 12 | 音频都用 OGG 省体积 | 短音效解码延迟会迟到 |
| 13 | 中文字体直接塞进去 | 必须**子集化**，否则包体爆炸 |
| 14 | 字体缩放糊了没办法 | 开 **MSDF** |
| 15 | FMOD/Wwise 有官方支持 | **没有**一级集成，社区绑定维护状态现查 |
| 16 | SVG 里带文本 | ⛔ 官方：Godot 使用的 SVG 库**不支持对 SVG 中的文本做光栅化**，必须先把文本转为路径，否则**该文本不会出现在光栅化图像中**且⛔ **不报任何错** —— 表现为"logo 里的字整块消失"，排查被引向缩放或渲染顺序 |
| 17 | 不知道「检测 3D」会自动改写导入设置 | ⛔ 官方：纹理一旦在 3D 场景中使用（如作 `BaseMaterial3D` 贴图），Godot 会**自动重新导入**：启用 mipmap、压缩模式改为 VRAM Compressed。⛔ 没人动过设置，纹理却变了，而导入面板显示得"像一直如此" |
| 18 | 手动改压缩模式来对抗 3D 检测 | ⛔ 官方：除非修改「检查 3D > 压缩至」，否则下次触发检测又被改写 —— 表现为"改了又自动变回去" |
| 19 | 以为漏字会显示成豆腐块 | ⛔ 官方：`allow_system_fallback` 默认 **true**，找不到字形时自动用系统字体兜底，⛔ 表现**不是豆腐块，而是各平台字形不一致** —— 比豆腐块更难发现，因为本机"明明能显示" |
| 20 | 所有字体都开 MSDF | ⛔ 官方：MSDF 缺点是**小字号缺乏 hinting**（不如传统光栅化清晰）、低端移动设备基础渲染成本更高、**无法启用 LCD 子像素优化**、首次显示小字号新字符成本更高。⛔ 小字号 UI 正文开了反而更糊，而这恰是最常用的字号 |
| 21 | 改 hinting 没效果就当引擎 bug | ⛔ 官方：非 None 的 hinting **只对含 hinting 数据的字体生效**；改了没变化通常说明字体文件本身没有 hinting 指令，需换带数据的版本或开 `force_autohinter` |
| 22 | `.uid` 文件不提交进版本控制 | ⛔ 官方：`.uid` 仅供编辑器使用（导出时迁移进 uid database），但要求**提交进版本控制**（同 `.import`）。⛔ 不提交则别人拉下来 UID 失效、回退到路径查找，若文件同时被移动过则**引用断裂** —— 表现为"他那儿全红、我这儿正常"，两边都没改过引用 |
| 23 | 认为 4.4 之前也能随便移动脚本 | ⛔ 官方：4.4 前**脚本与着色器不支持 UID**（纯文本格式无处存 UID），4.4 起才靠 `.uid` 伴生文件补上 —— 老项目按"可直接移动"操作仍会断，且断的是别人机器上 |
| 24 | 图集不设 padding / extrusion | 过滤会采样到相邻区域，产生图集缝隙、闪烁、莫名边框；⛔ 源图放大时看不出来，**缩小后才明显**，于是"验收时没发现" |
| 25 | 音频采样率混用 | ⛔ 重采样开销与音质损失；⛔ 单条素材听不出问题，**多条叠在一起才暴露**，排查被引向混音设置 |
| 26 | 循环 BGM 用 MP3 | ⛔ MP3 几乎无法无缝循环，循环点会有咔哒声；⛔ 编辑器里短时试听听不出来，包体里长时间播放才明显 |
| 27 | glTF / FBX 导入后不核对缩放 | ⛔ 单位不一致是经典坑：模型本身没问题，导入后尺寸就错了。⛔ 排查被引向场景节点缩放，改节点 scale 等于把错误固化进场景 |
| 28 | 法线绿通道约定不统一 | ⛔ DirectX 与 OpenGL 约定相反，混用表现为"光照方向怪"而贴图看着完全正常；⛔ 必须写进项目规范，否则不同美术给的图互相冲突 |
| 29 | 把「检查 3D > 压缩至」设为 Disabled 就等于改回来了 | ⛔ 官方：*"Changing this to Disabled then reimporting will not change the existing compress mode"* —— Disabled **只停止自动改写，不回滚已改的**；⛔ 表现为"设了 Disabled 重新导入，面板仍是 VRAM Compressed"，被当成选项失效或引擎 bug。⛔ 必须两步：先设 Disabled 停止改写 → 再手动改回 Lossless → 重新导入 |
| 30 | 法线贴图沿用 `compress/normal_map` 默认 Detect | ⛔ 官方：一旦检测到被当作法线用，会**自动改为 RGTC 并重新导入**；官方注明此时*"必须调整使用了该法线贴图蓝通道的自定义着色器"*。⛔ 表现为"自定义着色器取蓝通道某天开始不对"，而贴图没换、设置没人动过，**且内置材质一切正常**（官方：内置材质忽略蓝通道），问题被掩盖 |
| 31 | 设 `mipmaps/limit` 来限制层数省内存 | ⛔ 官方明确标注 **Unimplemented**：*"This currently has no effect when changed."* ⛔ 零效果、零报错，面板上写进去的数字让人以为生效了；省内存只能靠关 mipmap 或换压缩模式 |
| 32 | 像素风字体沿用 `subpixel_positioning` 默认值 | ⛔ 官方明确反向要求：*"对于具有像素艺术外观的字体，应将其设置为 Disabled"*。⛔ 表现为"文字发虚、与像素画风不符"，而排查被引向字号或分辨率 —— 因为它是"画质更好"的选项，没人会想到要关掉 |
| 33 | 中文项目开了子像素定位却不预渲染字形 | ⛔ 官方：子像素定位的缺点是初始渲染耗时，*"可能导致游戏过程中出现卡顿"*；预渲染指定字形范围可缓解，但**代价是初始加载时间与内存增加**。⛔ 三难：不发虚 / 不卡顿 / 不涨内存**不可能同时满足**，必须实测定档，⛔ 没有默认值可用 |
| 34 | 把 `oversampling` 当清晰度开关调 | ⓘ 官方：*"大多数情况下应该保持为 0.0"* —— 它是在保持物理大小前提下改用更高/更低分辨率渲染的**覆盖系数**，不是画质选项；⛔ 调大后小字号反而更糊，且内存成本被算到字体上 |
| 35 | 资产规范口头约定 / 没写进项目文档 | ⛔ 规范没写下来等于没有：后期整理成本极高，而"整理"永远排不进迭代，⛔ 于是它以"先这样吧"的形式累积到出包前；⛔ 只写"必须 snake_case"而无例外条款，第一次遇到第三方素材就会破例，破例一次后规范不再是规范 |
| 36 | 导入设置靠人打开面板检查 | ⛔ 自动改写（`detect_3d`、`compress/normal_map`）在面板上**显示得"像一直如此"**，没有一个"上次的值"可对照，⛔ 人审永远发现不了"它变了"；⛔ 必须有可跑的校验（脚本扫 `.import`）与开工/收尾两份快照 |
| 37 | 源图透明像素留黑边 / 用透明抗锯齿混色 | ⛔ 缩小后会采样到黑边，表现为"缩小时边缘发暗"，⛔ 而**放大验收完全看不出来**，于是稳定活到出包后；⛔ 单张看着只是"边缘有点暗"，几十张一起出现在界面上就是"整体脏" |
| 38 | 用编辑器里看到的包体/显存数字做结论 | ⛔ 导出版的导入产物与编辑器不同（压缩、Basis 转码、3D 检测状态都可能不同），⛔ 表现为"编辑器里一切正常、出包后爆内存"，⛔ 而排查被引向"平台问题"；⛔ 只记总量还无法定位是哪类资产超了，分档才有指导意义 |
