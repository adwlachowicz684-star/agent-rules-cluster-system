# projectile — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/projectile.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 有专门的子弹节点 | **没有**，按需求选路线 |
| 2 | 子弹快就用 RigidBody | 看**轨迹可变/物理交互/权威**三点 |
| 3 | 有尾迹就得用物理 | **尾迹只是视觉** |
| 4 | 开 CCD 就不穿模 | 官方说"**有时有效**" |
| 5 | 提高 tick 能根治 | 官方明确**更耗 CPU**，且不替代扫描 |
| 6 | 射线扫描是精确碰撞 | 是**近似**，会漏边缘 |
| 7 | ShapeCast = 胶囊碰撞 | 是**扫描区域近似** |
| 8 | 预测线自己算简化版 | 会与落点**不一致** |
| 9 | 预测线画到底 | 只画到**首个碰撞点** |
| 10 | 子弹逐帧同步 | 应同步**开火事件** |
| 11 | 命中判定客户端说了算 | 要**服务器权威** |
| 12 | 有内置命中回溯 | **未检索到**，待核对 |
| 13 | RigidBody 能每帧摆位 | 会造成**不可预测行为** |
| 14 | 只看射线结果调试 | 还要看**mask 与 exclude** |
| 15 | 一帧只会命中一次 | 要**去重** |
| 16 | hitbox 用 Area3D，射线自然会打中 | ⚠ `collide_with_areas` **默认 false**，打不中 |
| 17 | areas 和 bodies 都开更保险 | 会有**两套命中结果**，爆头时灵时不灵 |
| 18 | 起点在墙内会命中 | ⚠ `hit_from_inside` **默认 false**，且命中时**法线为零** |
| 19 | 法线为零时也能算反射 | 会得到 **NaN/零方向**；要用速度反向兜底 |
| 20 | 射线节点会排除发射者 | 只排除**直接父级**；祖父节点不排除 |
| 21 | 同一帧多次查询可以用节点 | 节点**每物理帧一次**，要用即时射线 |
| 22 | `force_raycast_update` 要先 enabled | 官方：**enabled 不需要为 true** |
| 23 | 提高 tick 解决穿透最省事 | 官方：**耗 CPU**，移动端/web 可能不可行 |
| 24 | 子步进不用封顶 | 速度异常时会变成几千步，**帧率崩** |
| 25 | 命中后跑完剩余子步 | 会**同帧多次命中同一目标** |
| 26 | 缩放碰撞形状能改弹丸大小 | 官方：**不支持缩放**，要改 extents |
| 27 | 改 extents 只影响这一个 | shape 资源**默认共享**，会影响全部 |
| 28 | `intersect_shape` 第一个就是最近的 | **不保证顺序**，要按距离排序 |
| 29 | 穿透弹禁用碰撞就够了 | 目标紧贴时会**漏掉第二个** |
| 30 | 回池不用清命中集合 | 残留导致**第二发打不中** |
| 31 | 弹射后保留命中集合 | 弹回来打不到同一目标，像 bug |
| 32 | 追踪直接设 position | 会让子步进的"上一帧位置"**失效** |
| 33 | 预测用帧 delta 就行 | 要 **FIXED_DT**，否则抖动+系统性偏差 |
| 34 | 预测步数不封顶 | 平射时几百次射线/帧 |
| 35 | 有超距回收就够了 | 朝天射**永不超距**，还要超时 |
