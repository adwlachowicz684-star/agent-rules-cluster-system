# projectile — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/projectile.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 有专门的子弹节点 | **没有**，按需求选路线 |
| 2 | 子弹快就用 RigidBody | 看**轨迹可变/物理交互/权威**三点 |
| 3 | 有尾迹就得用物理 | **尾迹只是视觉** |
| 4 | 开 CCD 就不穿模 | 官方说"**有时有效**" |
| 5 | 提高 tick 能根治 | 官方明确**更耗 CPU**，且不替代扫描 |
| 6 | 射线扫描是精确碰撞 | 是**近似**，会漏边缘 |
| 7 | ShapeCast = 胶囊碰撞 | 是**扫描区域近似** |
| 8 | 预测线自己算简化版 | 会与落点**不一致** |
| 9 | 预测线画到底 | 只画到**首个碰撞点** |
| 10 | 子弹逐帧同步 | 应同步**开火事件** |
| 11 | 命中判定客户端说了算 | 要**服务器权威** |
| 12 | 有内置命中回溯 | **未检索到**，待核对 |
| 13 | RigidBody 能每帧摆位 | 会造成**不可预测行为** |
| 14 | 只看射线结果调试 | 还要看**mask 与 exclude** |
| 15 | 一帧只会命中一次 | 要**去重** |
