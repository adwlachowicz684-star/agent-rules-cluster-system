# genres-tactics — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/genres-tactics.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 判定依赖 TileMapLayer 的 tile 数据 | 它是呈现层不是规则层，旋转缩放不该影响规则 |
| 2 | 用 TileMapLayer 格子坐标算六边形邻居 | 它是正交网格，轴向坐标 6 邻居要自己写 |
| 3 | 尖顶/平顶两套公式混用 | 是两套不同公式，不能混 |
| 4 | 朝向用"面朝目标的方向角" | 战棋朝向是离散枚举，rotation 只管视觉插值 |
| 5 | 行动点与移动力混为一谈 | 一个是路径成本累加，一个是资源结算 |
| 6 | 边执行边发现 AP 不够 | 要在命令合法性校验阶段算清 |
| 7 | 战斗结算用帧驱动 | 同回合多单位/暴击触发会有顺序依赖，要用事件队列 |
| 8 | AI 直接 `move_and_slide` 到目标 | 托管战斗在离散棋盘规划，落地是格坐标再插值 |
| 9 | AI 每物理帧思考 | 按战斗 tick（如 0.2s）推进即可，表现插值填补 |
| 10 | 每帧改 visible 做显隐 | 触发 CanvasItem 绘制状态变化，静态部分不要每帧动 |
| 11 | `visible` 等于真的可见 | 还取决于祖先，要用 `is_visible_in_tree()` |
| 12 | UI 与单位混在同一 z 空间 | z_index 在 Node2D 与 Control 间共享，要统一规划 |
