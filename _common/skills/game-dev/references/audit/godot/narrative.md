# narrative — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/narrative.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Godot 不支持叙事系统 | 有 Resource/信号等底层能力，**要自己组织** |
| 2 | flag 写各 NPC 里方便 | 会**无法重构**，要集中 |
| 3 | flag 名随便起 | 会**撞车**，要三段式 |
| 4 | StringName 就是规范 | 只是**身份稳定**，不是命名规范 |
| 5 | 结局写 if elif | 要**判定表** |
| 6 | 结局靠数组顺序 | 要**显式优先级** |
| 7 | 优先级相同无所谓 | 要按**稳定 ID** 消除未定义行为 |
| 8 | 数据合法就能达成 | 还要查**可达性**（A 被 B 挡住） |
| 9 | 隐形前置省事 | 会**卡关**，要给替代提示 |
| 10 | 选项灰掉和不显示一样 | UI 不同，**逻辑都未满足** |
| 11 | 对话效果时机随便 | 要明确**选中时 vs 结束时** |
| 12 | 对话中途不能存档 | 要想好**从哪句恢复** |
| 13 | 存档压成一个字典 | 要**分层**保存 |
| 14 | 周目继承全都有 | 等级/装备/flag **各不相同** |
| 15 | 动态难度越明显越好 | 被察觉会**劝退** |
| 16 | 动态难度和成就不冲突 | **会冲突**，要提前想 |
| 17 | 旧字段不写没关系 | 迁移要**全部给默认值** |
| 18 | 检查点=关卡解锁源 | 都要从**单一数据源**来 |
