# account-security — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/account-security.md`
>
> 边界：本篇是**账号本身**。反外挂与存档加密见 `audit/godot/security.md`。

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 先设计登录界面 | 要先设计**身份/凭证/会话/角色**四者的唯一键 |
| 2 | 信任客户端传的 account_id | 只信**服务端从会话查出**的 ID，否则越权 |
| 3 | 用手机号/邮箱当主键 | 是可变更登录名；主键要内部生成 |
| 4 | 存 `issuer + 第三方可变 ID` | 第三方的可变 ID 会变；存 `issuer + subject` |
| 5 | MD5/SHA-256 加盐就安全 | **快速摘要**，salt 只防彩虹表不防 GPU 试错 |
| 6 | 抄文章的 Argon2 参数 | 要按自己 CPU/内存**实测**；调太高制造 DoS 面 |
| 7 | salt 存常量/用用户名当 salt | 必须**每口令唯一随机 salt** |
| 8 | 定期强制改密码更安全 | NIST 已不要求；只在有泄露证据时强制 |
| 9 | 用户名不存在要提示 | 与口令错误、2FA 失败返回**同样模糊提示**（防枚举） |
| 10 | 纯无状态 JWT 够用 | 无吊销能力 → 改密/登出/盗号后**无法失效** |
| 11 | refresh 长期有效 | 要轮换；**重用必须撤销整个 family** |
| 12 | 改密时删客户端 token | 要撤销 **refresh family**，不是清本地 |
| 13 | 高危操作用旧 access 放行 | 改邮箱/手机/支付/解绑 2FA 必须**重新验证** |
| 14 | 客户端互相通知踢人 | 多端政策要**服务端**保存会话列表 |
| 15 | 登录成功沿用旧会话 | **会话固定**漏洞；必须发新会话 |
| 16 | TOTP 窗口开大点方便 | 扩大窗口**提高爆破成功率**；RFC 建议最多 1 个时间步 |
| 17 | 恢复码明文存 | 要**按一次一码存哈希**（与密码同等级） |
| 18 | 短信验证码当强验证 | NIST 列为 **RESTRICTED**；有 SIM swap 风险 |
| 19 | 强制 2FA 一刀切 | "找不到手机"会变**永久丢号**；要绑风险 + 给替代路径 |
| 20 | 安全问题是好的找回方式 | NIST 明确**不能作为身份证明** |
| 21 | 客服能跳过第二因素 | **最易被社工绕过**；要双人复核 + 随机工单分配 |
| 22 | 找回一律冻结账号 | 分级：低限重复发起、中冻敏感操作、高才冻登录 |
| 23 | IP/设备指纹能当身份 | 只能**增信**；NAT/VPN/共享设备会误伤 |
| 24 | 风控高分就自动封号 | 要**安全降级**：宁可不给交易，不要自动封 |
| 25 | 登录日志永久保存 | PIPL 要求**最短必要期限**；无统一法定天数 |
| 26 | 注销 = 删角色 | 登录/支付资料还在就**没完成删除义务** |
| 27 | 封 IP/设备能独立封禁 | 只能作风险信号，**不能独立承担永久封禁** |
| 28 | 转服失败重试就行 | 要**同一幂等键补偿**，否则玩家两边各一份唯一道具 |
| 29 | 账号合并默认覆盖 | 两边都有资产时**拒绝自动合并**；默认安全失败 |
| 30 | `user://` 能存 token | 官方定位是**存档与配置**，不是凭据库 |
| 31 | "记住密码"存加密文件 | 密钥仍可被同进程/PCK 取得；**不存密码**，只存可撤销 refresh |
| 32 | 清了本地文件 = 已登出 | 要**服务端撤销**；本地清理不可替代 |
| 33 | 崩溃上报带上 token 方便排查 | 必须**脱敏**（token/邮箱/内部 ID/请求头） |

## 审核时逐条问自己

1. 身份 / 凭证 / 会话 / 角色 四层有没有**唯一键与授权表**？
2. 有没有任何业务请求**直接信任客户端传的角色或权限字段**？
3. 密码用的是慢哈希吗？参数是实测的还是抄的？salt 每个口令唯一吗？
4. refresh 有轮换吗？**重用检测**会撤销整个 family 吗？
5. 改密 / 登出 / 盗号时撤销的是**服务端会话**还是只清了本地？
6. TOTP 验证窗口开了几个？恢复码是哈希存储吗？
7. 短信是不是被当成了**唯一**强验证？
8. 找回流程里，客服能不能单方面跳过第二因素？
9. 风控的自动处置**可回滚**吗？有没有"宁可不交易也不封号"的降级？
10. 注销删除的是角色，还是**可识别个人信息的全部**？
11. 客户端有没有把 token 写进 `user://`、Autoload、日志或崩溃上报？
12. 有没有任何一条"登录态/风控/封禁"判定**只跑在客户端**？
