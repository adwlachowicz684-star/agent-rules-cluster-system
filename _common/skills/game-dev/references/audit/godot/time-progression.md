# time-progression — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/time-progression.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 建造/挂机/体力是三种系统 | **同一个内核**：`elapsed = now - last_settled_at` |
| 2 | `_from_system` 读一次是准的 | 单次可能准，**两次的差不可信**（官方明确警告） |
| 3 | 存档存"剩余秒数" | 派生值，被杀进程/加成变化/暂停后**全失真**；存绝对锚点 |
| 4 | `get_ticks_msec()` 能存进存档 | 进程重启**归零**，不能跨会话 |
| 5 | `_process(delta)` 累加就行 | **不跨会话**，关机即停；只做在线高频更新 |
| 6 | `floor` 后不用管余数 | 不写回 → **系统性偏低**，且偏差与速率成反比 |
| 7 | 零头四舍五入补一次 | 频繁进出场景可**反复触发向上取整**，凭空产出 |
| 8 | float 累加器够用 | **长期漂移，对账失败**，⛔ 禁止 |
| 9 | 离线速率按"回来那一刻"算 | 错：要用**离线期间真实生效的规则**，按事件日志分段 |
| 10 | VIP 加成塞一个 multiplier | 速率加成与**上限加成是两个字段**，混用会配置错乱 |
| 11 | 挂机不封顶更良心 | 等于**奖励长时间离线**，瓦解在线行为 |
| 12 | 封顶后累积"欠账" | 会造成断网/维护后的天量补偿，难解释难对账；**不欠账** |
| 13 | 加速计费在客户端算 | 典型**计费漏洞**；剩余时长要服务端按当时速率重算 |
| 14 | 扣款和产出分两步 | 要**原子化**，否则"扣钱没完成/完成没扣钱" |
| 15 | 立即完成另写一条路径 | 应复用结算管线，另写必在**分段/封顶/重置**上分叉 |
| 16 | 红点靠到达时刻推送 | 关机/杀进程/挂起**都会漏**；要实时查询已完成条目 |
| 17 | 购买体力和自然恢复共用一个锚点 | 买一次体力会**重置恢复时钟**，白赚一段恢复 |
| 18 | 每日重置按玩家本地午夜 | 跨时区变长短、夏令时**跳过或重复触发**；用服务器时区 |
| 19 | 重置是每天 05:00 发个事件 | 是**硬边界**，要能补算任意时刻的所有边界 |
| 20 | 重置时队列自动处理 | 逐类约定；**重置清0 + 剩余秒数存档**是最危险组合 |
| 21 | 客户端算"今天是第几周期" | 时区偏差会造成"领过/没领过"冲突；服务端下发 cycle_id |
| 22 | PAUSED 回调里做结算 | 网络不可用、iOS 只有**约 5 秒**；只做持久化 |
| 23 | FOCUS_OUT 就等于挂起 | 切桌面/弹窗也会触发；挂这里会**高频 I/O 与重复结算** |
| 24 | `SceneTreeTimer` / `time_scale` 能用于存档时间轴 | 受暂停与缩放影响，**只能用于表现** |

## 审核时逐条问自己

1. 存档里存的是**绝对时间戳**还是剩余秒数？
2. 结算用的时间源对不对？有没有把系统时钟用于精确差分？
3. `floor` 之后的余数**写回锚点**了吗？用的是整型还是 float？
4. 离线 8 小时期间速率变化过吗？分段是按**事件日志**重建的还是按当前快照倒推的？
5. 封顶时长有值吗？补签与加成叠加后**会不会越过系统硬上限**？
6. 加速计费在服务端吗？扣款与落库原子吗？
7. 红点是实时查询还是靠推送？
8. 体力购买次数与自然恢复**是两个锚点**吗？
9. 重置边界用的是服务器时区吗？夏令时切换那天测过吗？
10. PAUSED 回调里有没有做网络请求或大批量结算？
11. 有没有任何一条"产出/计费"判定**只跑在客户端**？
