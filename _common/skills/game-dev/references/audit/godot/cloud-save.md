# cloud-save — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/cloud-save.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 云存档就是上传文件 | 核心是**冲突** |
| 2 | 本地较新就覆盖 | **静默覆盖最危险** |
| 3 | 用文件修改时间判冲突 | **时钟不可信**，要逻辑版本号 |
| 4 | 版本号用构建号 | 一个构建内可能**多次写入** |
| 5 | Godot 有云存档 API | **没有**，要平台 SDK |
| 6 | 插件写"支持 4.x"就能用 | 要**按 4.7.2 专用构建**验证 |
| 7 | iOS 的 user:// 都会备份 | Caches/Temporary **不备份** |
| 8 | 冲突提示显示时间戳 | 要显示**相对时间**与设备 |
| 9 | 版本降级是边缘情况 | 是**正常路径** |
| 10 | 设置也要同步 | 画质/操作偏好**不该同步** |
| 11 | 写存档是原子的 | 写一半崩会**损坏存档**，要原子写 |
| 12 | HTML5 用文件系统 | 用 **IndexedDB** |
| 13 | Lamport 时钟能解决一切 | 是**补充**，防丢失仍需领域合并 |
| 14 | 云存档可信 | **可被篡改**，要服务端校验 |
| 15 | 拉云端存档再比对就行 | 应**先拉元数据**，否则白下载 |
| 16 | 冲突判断完就完了 | 落地后**还要再跑迁移链**（云端可能是旧格式） |
| 17 | 存档要等云端返回才成功 | 本地成功即返回；云端**异步重试** |
| 18 | 同步队列放内存里 | 要**持久化**，否则关掉游戏就丢 |
| 19 | 冲突自动选一个 | = **静默丢弃**进度；玩家选择是必备兜底 |
| 20 | 字段级 last-write-wins 就是合并 | 会得到"金币新+任务旧"的**不可能状态** |
| 21 | 所有字段都能合并 | 进度/背包/任务**只能整体取一份** |
| 22 | 冲突 UI 给两个按钮够了 | 要**能预览内容**，且落选项要**备份** |
| 23 | 画质设置也同步 | ⛔ 本机专属；同步会把 PC 画质拉到手机档 |
| 24 | 云容量无限 | 有**配额**；满了通常**不报错只是同步失败** |
| 25 | Web 存档不会被清 | 浏览器**可主动清除**；隐私模式配额**可能为 0** |
| 26 | 同步失败不影响玩家 | 表现为"换设备进度没了"，且**后台看不出** |
| 27 | `get_data_dir()` 就是 user:// | 官方：那是**全局**目录，用错会跨项目覆盖 |
