# combat — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/combat.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 碰撞体回调里写伤害逻辑 | 加一条规则要改所有武器回调 |
| 2 | hitbox 常开省事 | 走路也在造成伤害 |
| 3 | 判定放 `_process` | 帧率不同手感不同，要放 `_physics_process` |
| 4 | 改了射线 target 就能用 | 要 `force_raycast_update()` |
| 5 | 一次攻击一个回调 | 同帧多重叠 → 要 `attack_id` 去重 |
| 6 | 暴击和格挡都随机判 | 顺序必须写死，否则玩家无法预期 |
| 7 | buff 数值加起来就行 | flat 与 percent 要分顺序 |
| 8 | DoT 每帧扣血 | 帧率影响结果，要固定 tick |
| 9 | buff 自己播特效 | 移除时容易残留，状态应只管数据 |
| 10 | 技能写死在代码里 | Resource 数据驱动，策划可配 |
| 11 | 动画时长用计时器对齐 | 动画一改就错，用 Call Method Track |
| 12 | 打击感靠调大伤害数字 | 是 hitstop+特效+音效的**同步反馈** |
| 13 | hitstop 用 await 等恢复 | `time_scale=0` 时 await 也被冻 |
| 14 | 粒子在顿帧时也会停 | 4.7 修了这个行为，升级要重测 |
| 15 | 连招吃键是玩家手慢 | 缺输入缓冲 |
| 16 | 硬直时长只放攻击方 | 要**两个来源分开**：攻击方 base_hitstun × 受击方 combo scaling |
| 17 | 出招硬直和受击硬直共用一个 stun 字段 | 两种完全不同的状态；被打断是**转入受击**，不是计时器相加 |
| 18 | 硬直不递减，加个连段上限就行 | 连段断得突兀；要**按真实时间**衰减并设 floor |
| 19 | 空中/地面共用一套衰减计时器 | 落地会重置衰减 → 空中连变地面长连；要**两套独立** |
| 20 | 暴击也走衰减链路 | 连段越深暴击越打不出硬直，**设计意图被自己的衰减吃掉**；要 `ignore_decay` |
| 21 | 霸体 = 减伤 | 霸体是**延迟硬直**，期间照掉血照吃状态；混了玩家无法判断该堆什么 |
| 22 | 霸体每帧重新判定 | 轻击一下把霸体打掉但状态还挂着；要**窗口结束统一结算** |
| 23 | 韧性缓慢回血 | 会出现模糊半恢复态；要**瞬时回满 + 连续 X 秒未受击** |
| 24 | 霸体无代价 | 变无脑站桩；代价至少一项（动作慢/耗资源/可视/可被抓取） |
| 25 | 格挡和招架共用一个防御条 | 格挡耗**持续资源**，招架耗**时间窗口**，是两种资源 |
| 26 | 招架做成概率触发 | 消灭可读性与成长曲线；玩家会一直按住 → 无脑站桩 |
| 27 | 招架是伤害之后的回调 | 那时伤害已扣硬直已进，再撤销是一堆 flag 抵消；要**先于伤害结算分支** |
| 28 | 招架失败无代价 | 成无风险选项；要显式 `fail_recovery` 配表 |
| 29 | 破防窗口不给收益 | 破防系统不成立；窗口要够**一次**攻击落地、不够**两次** |
| 30 | 处决条件是「血量低」 | 那是奖励不是技巧；优先级应 背后未警觉 > 破防 > 血量阈值 |
| 31 | 处决期间可被任意伤害打断 | 处决成**自伤动作**；攻击方要无敌、目标不可打断 |
| 32 | 部位 = 伤害结算里加个 flag | 部位是**独立实体**，有独立 HP 且与本体分离 |
| 33 | AI 直接读 part.hp | 要发 `part_broken(part_id, flags)` 信号让行为树监听 |
| 34 | 部位破坏 = 换模型 | 是**掉落物 + 模型切换 + 残留表现**三件事 |
| 35 | 取消窗口是个布尔 | 要区分 **BUFFER（提前输入）** 与 **INSTANT（恰好落窗）** |
| 36 | 「动画播完自动连」 | 合法派生是**设计内容**；要显式 CancelTable，换武器只换数据 |
| 37 | 优先级靠 if-else 书写顺序 | 要写成**常量数组** |
| 38 | 每个状态各存一份 InputBuffer | 要**全局唯一**，各状态读取并消费 |
| 39 | 攻防双方互相持引用 | 要靠事件与 AttackContext 解耦，结果用**返回码**回流 |
| 40 | 等服务端确认才表现招架 | 60ms 延迟足以让短窗口完全不可用；要**客户端预测 + 服务端校正** |
| 41 | 帧数据硬编进代码 | ⚠ 动画一改就对不上；要由**动画事件**驱动（Call Method Track）而不是计时器 |
