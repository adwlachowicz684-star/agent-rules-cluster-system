# 成就系统 审查表

| # | 本能以为 | 实际 | 审查规则 |
|---|---|---|---|
| 1 | 定义和状态存一起 | ⛔ 改 `target_progress` 后旧存档覆盖新定义 | 必须分离：定义 Resource / 状态存档 |
| 2 | 用显示名当成就 key | ⛔ 改名后存档对不上，进度全丢且不报错 | `id` 必须是稳定 `StringName` |
| 3 | 进度记本次会话 | ⛔ 重开清零，永远解锁不了 | 必须跨会话累计并落盘 |
| 4 | 轮询判条件 | ⛔ 掉帧且捕捉不到瞬时事件 | 事件驱动 `connect` |
| 5 | 复合成就每事件重算 | ⛔ `O(n×m)` 且子条件中间态丢失 | 子条件独立存 `sub_progress` |
| 6 | 先弹通知再发奖 | ⛔ 发奖失败则看到解锁但没拿到 | 顺序：判达成→标记→发奖→通知 |
| 7 | 发奖不用判重 | ⛔ 重放事件重复发奖，可刷 | 以 `id` 为键幂等 |
| 8 | 标记后异步发奖 | ⛔ 崩溃时解锁了但奖励没了 | 标记与发奖一起落盘 |
| 9 | 隐藏成就全都隐藏 | ⛔ 玩家不知道自己拿没拿到 | 标题/进度/是否解锁必须展示 |
| 10 | 描述放客户端就保密 | ⚠ 改包可见 | 真保密要服务端下发 |
| 11 | Godot 内置 Steam 成就 | **没有**，要插件且需查兼容性 | 见 `platform-services.md` |
| 12 | 平台同步失败就算了 | ⛔ 永久丢失，本地与平台对不上 | 必须可重试 |
| 13 | 以平台为准 | ⚠ 平台不可用时本地解锁被回滚 | 通常以本地为准推送 |
| 14 | 新增成就从零开始记 | ⛔ 老号永远拿不到 | 用已有统计值 backfill |
| 15 | 进度与统计各存一份 | ⚠ 出现"统计 100 进度 87"对不上 | 定死谁是权威，另一个派生 |
| 16 | 事件不带参数 | ⚠ "单次伤害过万"只能回头改签名 | 事件参数一次带够 |
| 17 | 每日重置用系统时间 | ⛔ 改系统时间即刷新 | 见 `environment-systems.md#8` |
| 18 | 解锁时间戳存本地格式化串 | ⚠ 跨时区/改时间即对不上 | 存 UTC 秒 |
| 19 | 成就奖励直接改背包 | ⚠ 背包满则奖励静默丢失 | 走经济通道并判容量 |
| 20 | 移除成就直接删定义 | ⛔ 已解锁玩家的存档悬空 | 标记废弃而非删除 |
| 21 | 子条件顺序判定短路 | ⚠ 玩家完成 B 再 A 时不触发 | 每次推进后全量子条件 OR 判定 |
| 22 | 隐藏成就进度也隐藏 | ⚠ 玩家无反馈，以为没做 | 给进度条 |
| 23 | 解锁通知与奖励弹窗各弹一次 | ⚠ 玩家看到两个弹窗以为发了两份 | 合并为一次 |
| 24 | 成就判定放在奖励之后 | ⛔ 未达成也发奖 | 判达成是发奖的前置 |
| 25 | 测试只测新号 | ⛔ 老号 backfill 路径测不到 | 必须同时测新号与老存档 |
