# social — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/social.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Godot 自带大厅/房间 | **没有**，要自己搭服务 |
| 2 | ENet 是完整 P2P 平台 | 只是 **UDP 传输层** |
| 3 | ENet 能穿透 NAT | **不能**，要信令服务 |
| 4 | mesh 不用服务器 | 仍需**信令交换地址** |
| 5 | 房主=创建者 | 是**临时协调者**，要能迁移 |
| 6 | 创建者退出房间就没了 | 要**显式迁移策略** |
| 7 | 客户端过滤敏感词够用 | **改包就绕过**，要服务器过滤 |
| 8 | 聊天不用存 | 要**留存**配合举报取证 |
| 9 | 举报存个玩家 ID 就行 | 要存**证据快照** |
| 10 | 好友列表存客户端 | 要**存服务器** |
| 11 | peer ID 能当玩家身份 | **不能**，要独立会话 |
| 12 | 匹配 Godot 会做 | **不提供** |
| 13 | 掉线后社交状态也丢了 | 分**控制面/数据面**就不会 |
| 14 | 私聊保存期有统一规定 | **未给出**，按最小必要原则定 |
| 15 | 玩家名/头像不用审 | 是 **UGC**，要过审 |
| 16 | 阵营就是角色表一个枚举 | 要分 `main_faction_id`/`memberships`/`temporary_affiliations` 三层 |
| 17 | 阵营关系对称 | **必须非对称有向**；A 对 B 友好 ≠ B 对 A 友好，⛔ 不自动镜像 |
| 18 | 写死「同阵营不能攻击」 | 那是**战斗规则**不是 DB 约束；要房间级 PvpContext 冻结 |
| 19 | 战斗中能切阵营 | ⛔ 不能回溯修改已冻结的上下文 |
| 20 | 势力只存人数 | 要存**可作战人口**（活跃/在线/参战率），否则误判强势 |
| 21 | 势力积分单一排名 | 要分**控制分/战斗分/贡献分** |
| 22 | 阵营切换只扣钱 | 主要风险是**身份套利**；要时间+关系+经济三重代价 |
| 23 | 「免费转阵营」真免费 | 只是把代价移到冷却/窗口/审批 |
| 24 | 据点控制权写进角色表 | 要独立 CapturePoint + ControlVersion + **服务端时钟**衰减 |
| 25 | 赛季结束用新参数算旧战役 | ⛔ 必须用**该赛季配置版本**的冻结快照 |
| 26 | 人多的一方奖励更多 | 正反馈失衡；要补偿**对弱势方有直接贡献的行为** |
| 27 | 全阵营 Buff 无限期 | 要限时并同时观察转阵营率 |
| 28 | 干预不向玩家解释 | 会像黑箱操纵；要说清补偿什么、多久、依据哪个赛季 |
| 29 | 每分钟读全量平衡数据 | 会压垮 DB；要 15–60 秒采样 + 三个平滑窗口 |
| 30 | 声望只涨不跌 | 只是一根上涨的线；要**能衰减、能负值、能解除锁定** |
| 31 | 衰减惩罚活跃玩家 | 要从「上次获得后」计时，活跃行为要能抵消 |
| 32 | 战力当匹配依据 | 测的是养成不是操作（跨职业不可比/堆无用词条/版本虚高） |
| 33 | 战力只显示一个大数字 | 要**分维度 + 职业百分位 + 装备建议 + 总分** |
| 34 | 客户端算战力上传 | ⛔ 服务端算并缓存；缓存键要含**公式版本** |
| 35 | 战报存全量状态 | 要 `初始哈希 + 输入序列 + 种子 + 配置版本 + 事件摘要` |
| 36 | float 换 double 就确定性了 | IEEE 754 **不保证跨平台**一致；要冻结步长/随机序号/排序/回调顺序 |
| 37 | 回放跨版本「尽力兼容」 | 要**写入时隔离**，旧回放用旧快照；商业产品也限定只能看当前版本 |
| 38 | 战绩本来就是公开的 | PIPL 要求最小范围 + 单独同意；**未满 14 岁属敏感个人信息** |
| 39 | 公开精确对局时间 | 结合其他数据可形成**行踪** |
| 40 | 公开原始输入序列 | ⛔ 不建议 |
| 41 | 关系社交没有解除冷却 | 可反复建立/解除**刷奖励** |
| 42 | 关系加成无上限 | 叠满会破坏数值 |
| 43 | 成员列表塞进频道对象 | 热点频道会拖垮战斗服；频道/成员资格/**扇出**三者分离 |
| 44 | 世界频道刷屏只靠限流 | 会误伤正常玩家；要用**发言道具/冷却**这类经济手段 |
| 45 | `_ready()` 里 `set_multiplayer_authority(multiplayer.get_unique_id())` | 该脚本在**每个 peer 上对每个 avatar 都跑一遍** → 每个 peer 本地都声称拥有全部角色；权威须推导自两端一致的 `name.to_int()`；⛔ 且该调用**不会自我复制**、`recursive` 不覆盖后加子节点 |
| 46 | 只转发 TCP 端口 / 不看 `create_server()` 返回值 | Godot 高层多人只走 **UDP**；返回值可能是 `ERR_ALREADY_IN_USE` / `ERR_CANT_CREATE`，不检查则「在跑但一个连接都接不进来」 |
| 47 | 只测「正常退出再登录」 | 重连与首次登录是两条路径；须**强杀进程**再连，逐字段核对好友、邮件、关系与战绩 |
| 48 | 主动退出与断线走同一条超时路径 | 主动退出会有「房间悬空」窗口；两条路径要分开 |
| 49 | 房间设置由房主本地改了就广播 | 房主改包即可伪造；且新加入者的设置来源与老成员**不一致** |
| 50 | 交接时让新房主重新拉一次状态 | 交接期间仍允许改设置 → 新老房主变更互相覆盖，表现为「我锁了地图却开了别的图」 |
| 51 | 心跳超时小于常见网络抖动 | NAT 抖动即误判掉线 → 频繁交接；验收须**拔网线**而非点退出，且交接只能发生一次 |
| 52 | 排队无超时、也无放宽策略 | 低峰期永远排不到人；放宽了不告知玩家则像黑箱操纵 |
| 53 | 拿战力当主匹配分 | 战力测的是**配置与养成**不是操作；高分低操作玩家污染队伍 |
| 54 | 把房间号直接给客户端让它自己连 | 可被猜到并挤进别人的房间；要用一次性连接票据并在服务端核对 |
| 55 | 组队各自排队再尝试合房 | 五人队可能永远凑不齐；须以**队伍为单位**报名 |
| 56 | 队伍分取平均分 | 一个大带四个新手会持续摧毁对手体验；应偏向高段 |
| 57 | 频道、成员资格、扇出三者合一 | 热点频道（世界频道）拖垮战斗服；扇出须独立限流 |
| 58 | 世界频道刷屏只靠限流 | 会误伤正常玩家；须用**发言道具/冷却**这类经济手段 |
| 59 | 只测「正常发一条违规消息被拦」 | 那条走的是客户端过滤，服务端路径从未被执行；须**改包**绕过客户端后再验证服务端仍拦下并可取证 |
| 60 | 关系只有绑定和收益、没有解除代价 | 可反复建立/解除**刷奖励** |
| 61 | 解除即可重建、只限单次不限批量 | 刷奖励的循环成立；批量解除同样要限流 |
| 62 | 关系加成无硬上限 | 叠满所有关系破坏数值，且很难在不删数据的情况下回收 |
| 63 | 合规条款在本域自行定义 | ⛔ 指向 `compliance.md`，不重复也不编造 |
| 64 | 只测阵营「切换成功」 | 套利不是切换功能的 bug，而是**切换没有代价**造成的经济漏洞；须付出时间、关系和经济三重代价 |
| 65 | 以为把 `float` 换成 `double` 就确定性了 | IEEE 754 不保证跨编译器/平台/数学库/线程调度/物理求解器一致；须冻结步长、随机源、容器与排序 |
| 66 | 战报默认全部公开 | ⛔「战绩本来就是公开的」不能成为默认逻辑；须分五档并做脱敏投影 |
| 67 | 手动点几次验证关系冷却 | 刷取发生在脚本速率上；须测**批量**建立/解除并核对奖励总数 |
| 68 | 切换后旧阵营待领奖励仍可领 | 退出时未领奖励须作废，否则身份套利（开战前转入领奖、战后转回）成立 |
| 69 | 战报只放一次看着对 | 确定性失败是**偶发**的；须连放 20 次逐次比对，且旧回放按旧版本重放 |
