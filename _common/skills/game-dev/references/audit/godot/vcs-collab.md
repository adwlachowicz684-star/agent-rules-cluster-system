# vcs-collab — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/vcs-collab.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | `.uid` 是生成物该忽略 | 官方明确必须提交，忽略会引用错配 |
| 2 | 移动 .gd 就够了 | 同名 .uid 侧车必须一起移动 |
| 3 | 文本格式就能安全语义合并 | 可 diff ≠ 可合并，可能重复节点/错父级 |
| 4 | 合并后文件合法 = 加载正确 | 要跑 headless 校验 + 冒烟 + 目视 |
| 5 | .tscn 冲突就 checkout --ours | 丢一边的节点/脚本/连接，比冲突更糟 |
| 6 | 没有内置锁就没法防并发编辑 | 靠小场景+所有权+分支策略+钩子+沟通 |
| 7 | LFS Lockable 能防两人同时编辑 | 只防未授权推送，不防编辑器同时打开 |
| 8 | 目录名用创作者姓名/临时日期 | 名称要表达"它是什么/用于什么" |
| 9 | 源资产与导入产物混一层 | 要分开层级 |
| 10 | 发明 a_*/z_* 排序前缀 | 前缀要词典化：mat_/tex_/snd_/env_ |
| 11 | resource_local_to_scene 是共享变体答案 | 实例化时复制，只适合需独立状态的资源 |
| 12 | 有 UID 就随便移动都不会坏 | 前提 .uid 提交且一起移动 |
| 13 | UID 消除了场景冲突 | 减少路径破坏，但文件结构仍冲突 |
| 14 | 复制侧车文件无所谓 | 重复 UID 导致身份混乱 |
| 15 | 手工搬目录 | 要脚本执行并生成变更清单 |
| 16 | LFS 用 * 全追踪 | 白名单，且首次提交前配置 |
| 17 | CI 不用管 LFS 凭证 | 拉取代码会变成拉取整个资产历史 |
| 18 | .import 一律忽略 | 取决于项目布局与重导入策略 |
