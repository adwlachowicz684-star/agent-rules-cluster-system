# netsync-advanced — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/netsync-advanced.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Synchronizer 能解决联机平滑 | 只是复制器，预测/回滚/插值都要自己写 |
| 2 | `@rpc` 默认不可靠 | **默认 reliable**，高频同步要显式改 |
| 3 | 客户端能直接调 RPC | 默认 authority，调用被**静默忽略** |
| 4 | 预测存个位置就行 | 必须存**输入历史**才能重放 |
| 5 | 误差就纠正 | 没阈值会持续抖动 |
| 6 | 重放用帧 delta | 必须用**固定 dt**，否则越纠越错 |
| 7 | 远端实体直接用最新包 | 到达不均匀，要**延迟缓冲 + 插值** |
| 8 | `get_remote_sender_id()` 随时可用 | 只在 RPC 函数内有效，await 后失效 |
| 9 | Godot 保证确定性 | **不保证**，锁步要自己保证 |
| 10 | Resource 能直接同步 | **不能**同步 Object/RID，要拆成 ID |
| 11 | ENet 到处能用 | Web 平台不可用 |
| 12 | WebSocket 和 ENet 差不多 | TCP 有**队头阻塞** |
| 13 | 先写代码再定部署 | P2P 与专用服务器权威模型不同，切换=重写 |
| 14 | `any_peer` 只是方便 | 是攻击面，必须双校验 |
| 15 | 家用宽带能开服 | 有 CGNAT/动态 IP/封端口 |
| 16 | `@rpc` 的 channel 写中间位置 | ⛔ 顺序错了会静默当作别的意思；channel 必须放**最后一位** |
| 17 | 回滚时把音效/粒子/伤害数字一起回滚 | 它们是**纯副作用**；重放会**再触发一次**（开火声响两遍） |
| 18 | 快照里塞节点引用/纹理/粒子状态 | ⛔ 完整场景序列化既慢又含不可序列化对象；只存**确定模拟**需要的字段 |
| 19 | 未确认输入队列不设上限 | 服务器长时间不回包会让重放越来越长，卡死 |
| 20 | 快照让接收端用**到达时间**打时间戳 | ⛔ 乱序/晚到会**直接改变世界**；必须发端打模拟时钟 |
| 21 | 预测/回滚/插值各用各的时间基准 | 出现"画面里打中了、服务器判定没中"；三者要共用同一套 tick 时钟链 |
| 22 | 快照缓冲不清理过期包 | 长时间运行无限增长，且插值会拉出诡异结果 |
| 23 | 缓冲时长照抄经验值 | ⓘ 350ms 是 10Hz+5%丢包下的经验值，**必须实测**；缓冲越小越抖、越大越放大控制误差 |
| 24 | 生成/销毁走 unreliable | ⛔ 丢一个"生成"包，该实体在客户端**永远不存在**；生灭不能丢，位置可以丢 |
| 25 | authority 迁移到达前不做处理 | 空窗期输入被当成"别人的输入"应用；要标 `pending_transfer` |
| 26 | 客户端本地 authority 不一致就强制改 | 应**等权威状态纠正**，⛔ 不要本地硬改（会与服务器分叉） |
| 27 | 允许客户端自己调 `set_multiplayer_authority()` | = 任何人都能夺取任何实体控制权；迁移必须由**服务端**发起并校验 |
| 28 | 只在理想网络下测过 | ⛔ 局域网 <5ms 隐藏所有抖动问题；必须测 20/80/150ms+5%丢包三档 |
| 29 | 服务端在 RPC 回调里做阻塞 IO | 数据库/验证走队列；⛔ 在回调里查库 = 每个玩家输入都在等磁盘 |
| 30 | 输入队列不设上限 | ⛔ 不设上限，恶意/异常客户端可撑爆服务端内存 |
| 31 | 觉得"权威服务器 = 反作弊" | ⛔ 权威只是"你能执行服务端代码"；仍需认证、限流、审计、幂等 |
| 32 | 输入只发方向向量 | ⛔ 没有**序号**无法回滚、没有**采集时刻**无法算延迟；三要素缺一不可 |
