# xr-deep — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/xr-deep.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | XR 就是换个相机 | 要移 `XROrigin3D`，相机属性被覆盖 |
| 2 | 相机位置是实时的 | **滞后几毫秒**，不能当物理抓手 |
| 3 | 手部追踪到处都有 | SteamVR 通常是**控制器模拟**的 |
| 4 | 抓取 = 设为子节点 | 动态刚体要 **Joint 或速度追踪** |
| 5 | 控制器有速度 API | **没有**，要自己差分 |
| 6 | 释放物体自己会飞 | 要**显式写线速度与角速度** |
| 7 | pinch 用固定距离阈值 | 手指长度因人而异，要**归一化** |
| 8 | 快速挥手不算捏合 | 会被误判，要**用速度防抖** |
| 9 | 关节速度 = 抓取点速度 | 不一定相同，手锚要自己差分 |
| 10 | 平滑移动最自然 | 最易致晕，**优先传送** |
| 11 | 晕动症是个别人体质 | 成因明确（前庭冲突），可缓解 |
| 12 | XR 是单眼×2 | 每眼完整管线，看**双眼总量** |
| 13 | 刷新率写死 90 | 由 **runtime 决定**，要读 API |
| 14 | 插件抓取节点和自己代码能混用 | 两套所有权**互相覆盖** |
| 15 | 空间 UI 放那就能点 | 要处理射线碰撞层与可读性 |
