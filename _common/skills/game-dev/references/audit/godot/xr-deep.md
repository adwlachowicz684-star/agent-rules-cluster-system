# xr-deep — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/xr-deep.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | XR 就是换个相机 | 要移 `XROrigin3D`，相机属性被覆盖 |
| 2 | 相机位置是实时的 | **滞后几毫秒**，不能当物理抓手 |
| 3 | 手部追踪到处都有 | SteamVR 通常是**控制器模拟**的 |
| 4 | 抓取 = 设为子节点 | 动态刚体要 **Joint 或速度追踪** |
| 5 | 控制器有速度 API | **没有**，要自己差分 |
| 6 | 释放物体自己会飞 | 要**显式写线速度与角速度** |
| 7 | pinch 用固定距离阈值 | 手指长度因人而异，要**归一化** |
| 8 | 快速挥手不算捏合 | 会被误判，要**用速度防抖** |
| 9 | 关节速度 = 抓取点速度 | 不一定相同，手锚要自己差分 |
| 10 | 平滑移动最自然 | 最易致晕，**优先传送** |
| 11 | 晕动症是个别人体质 | 成因明确（前庭冲突），可缓解 |
| 12 | XR 是单眼×2 | 每眼完整管线，看**双眼总量** |
| 13 | 刷新率写死 90 | 由 **runtime 决定**，要读 API |
| 14 | 插件抓取节点和自己代码能混用 | 两套所有权**互相覆盖** |
| 15 | 空间 UI 放那就能点 | 要处理射线碰撞层与可读性 |
| 16 | 开局就能查手部追踪是否支持 | `is_hand_tracking_supported()` 初始化前返回 `false`，⛔ 会被误判成不支持而走降级分支 |
| 17 | 关节位置返回了就能直接用 | 要按 `get_hand_joint_flags` 区分 valid 与 tracked，⛔ 未置 tracked 位是**预测数据**不是实测 |
| 18 | 手部追踪与控制器做两套交互逻辑 | 要共享同一套游戏语义，⛔ 两套逻辑必然行为不一致且只在一侧被测过 |
| 19 | 隧道视野是美术效果 | 它是**舒适度设置**，强度必须暴露给玩家，⛔ 写死等于替玩家决定能承受多晕 |
| 20 | 先选渲染器再补 foveation | 动态 foveation **只在 Compatibility**，与「XR 必须 Mobile / Forward+」冲突，⛔ 顺序反了要换渲染器 |
| 21 | `render_target_size_multiplier` 在 `_ready()` 里设 | 官方要求**初始化前**设，⛔ `_ready()` 通常已太晚，表现为设了没效果 |
| 22 | foveation 设一次就一直有效 | 要在接口初始化**之后**设，且 Vulkan 下还要 `Viewport.vrs_mode = VRS_XR` |
| 23 | 掉帧就先减对象与材质 | 降负载顺序是动态分辨率 → LOD / 遮挡 / 远处阴影，⛔ 先减对象会先毁掉画面 |
| 24 | 抓取释放点几次没问题就行 | 要**高频循环**实测（上千次），穿模与丢失只在高频与极端速度下暴露 |
| 25 | 自己不晕就没问题 | 晕动症要**真人实测**：开发者因反复暴露而耐受，⛔ 主观感受不能当判据 |
