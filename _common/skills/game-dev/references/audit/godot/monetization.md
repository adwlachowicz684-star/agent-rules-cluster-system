# monetization — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/monetization.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Godot 有官方 IAP | 4.x **全系列没有** |
| 2 | 客户端能判断付没付钱 | **绝不能信**，要服务器验收据 |
| 3 | 抽卡随机放客户端就行 | 会被改，**必须在服务器** |
| 4 | 保底存本地 | **会被清档绕过**，要存服务器 |
| 5 | 公示概率=合规 | 还差**替代获取途径** |
| 6 | 中国抽卡就是公示概率 | 是**四件套** |
| 7 | 未成年限额是法务的事 | 是**产品需求**，要实现 |
| 8 | 付了钱就发货 | 掉单会**丢钱**，要幂等和恢复 |
| 9 | 订单号随便生成 | 要**幂等**防重复发货 |
| 10 | 抽卡能直接充钱抽 | 要加**中间游戏币**层 |
| 11 | 概率公示手填一份 | 要**与实现同源**且可校验 |
| 12 | 广告回调可信 | 要看完回调，**服务器发奖励** |
| 13 | 月卡按本地时间算 | 要 **UTC** |
| 14 | 抽卡结果不用存 | 要**留存 ≥90 日** |
| 15 | 韩国/台湾不用管 | 2023/2024 起**强制公示** |
| 16 | Android 忘了开 `INTERNET` 权限 | 官方：否则**任何**网络通信被阻断，支付请求无回调也不报错 |
| 17 | 一个 `HTTPRequest` 同时发多个请求 | 官方明确不要对单个节点并发请求，会互相打断 |
| 18 | 拿 `OS.get_unique_id()` 当安全依据 | 官方：可被外部程序伪造；重装或换硬件后会变 |
| 19 | `HTTPRequest.timeout` 用默认值 | 官方默认 `0.0`，含义是**不超时**，请求可能永远挂着 |
| 20 | 补单失败就提示玩家重新购买 | 应提示恢复购买；重新购买会产生第二笔订单 |
| 21 | 各类失败统一成一个错误码 | 网络失败与已发货混为一谈，重试即重复发货 |
| 22 | 补单只在启动时跑一次 | 那次恰好断网则**永久掉单** |
| 23 | 补单成功立刻删本地单据 | 异步发货失败则永久丢失 |
| 24 | 本地单据只存内存或用设备 ID 加密 | 崩溃或重装后无据可依 |
| 25 | 广告无填充时反复重试或卡住玩法 | 会被平台限流，且玩家被永久卡住 |
| 26 | 广告奖励在客户端发放 | 回调可伪造，⛔ 必须服务端发 |
| 27 | 看完没回调就当没看 | 要有超时与查询接口，否则玩家白看 |
| 28 | 广告奖励不判重 | 同一回调重放即重复发放，放大倍数比内购更大 |
| 29 | 抽卡不做每日次数上限 | 国内常见 50 次，低成本高信号量的合规动作 |
| 30 | 自己定义价格档位 | 各平台有**固定档位**，随便定价会导致配置不上或被拒审 |
| 31 | 价格按汇率自己换算 | 要用平台返回的本地化价格，否则展示价与实扣不一致 |
| 32 | 周期重置按本地时区 | 要 **UTC**，否则跨时区玩家一天能刷两次 |
| 33 | 退款只扣货币不回收物品 | 已发道具仍在玩家手里，可被白嫖或转卖 |
| 34 | 退款不进同一条审计链 | 发放与退款拼不起来，对不上账 |
| 35 | 未成年限额当成法务的事 | 是**产品需求**，没实现就是没实现 |
| 36 | 审计日志允许 UPDATE | 那就不是审计日志，事后无法自证 |
| 37 | 风控阈值硬编码 | 出事时改一个数字要发版，而攻击窗口在小时级 |
| 38 | 验收只在正常网络下测 | 掉单、改时间、重放只在**敌意环境**出现 |
| 39 | 商业化判定进热更包 | ⛔ 等于把定价权交给热更通道，可直接改价 |
| 40 | 概率公示只在游戏内不留档 | 需要能自证**当时**公示的是什么 |
| 41 | 广告频次不设冷却 | 可连看刷奖励，且会被平台限流影响全服 |
