# level-design — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/level-design.md`
>
> 边界：本篇是**人怎么设计并搭建关卡**（与"程序化关卡生成"是两回事）。

⚠ **一句话**：白盒验收的不是"模型摆完了"，而是**玩家能否完成、是否误走**。

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 关卡就是把场景搭出来 | 是**心流曲线**四要素（空间/引导/节奏/挑战） |
| 2 | 先摆箱子再想玩法 | ⛔ 要先写**关卡卡表**（目标/挑战/资源/引导/松弛） |
| 3 | 直接上美术更快 | 白盒返工**更贵**（几何返工变成美术+程序一起返工） |
| 4 | 白盒等美术完再验可玩性 | ⛔ **白盒阶段就要能跑** |
| 5 | 设计者自己试玩算验收 | ⛔ 要**没参与设计的人**试玩（设计者知道答案） |
| 6 | 玩家卡住 = 有挑战 | ⚠ 分不清"卡住"和"挑战"就是设计失败 |
| 7 | 有死路没关系，玩家会回头 | ⛔ **无死路是硬要求**：任何可达区域都要能回到上一检查点 |
| 8 | 引导就是加箭头 | ⛔ 要用**光照/色彩/形状/声音**，箭头是最后手段 |
| 9 | 检查点随便放 | ⚠ 失败成本要可接受：**重玩时间 < 挑战时间** |
| 10 | 白盒不用测帧率 | ⚠ 要测，⛔ 别等美术完才发现 |
| 11 | CSG 可以做最终资产 | 官方定位是**原型** |
| 12 | CSG 已弃用 | 4.7 仍在**主线维护**并增强（自动平滑、吸附、轴向测量） |
| 13 | 所有几何塞一个 Combiner | ⛔ 要**隔开局部运算**，否则改一处重算全部 |
| 14 | CSG 碰撞体自动就是对的 | ⚠ 复杂布尔可能产生意外碰撞面；白盒通过后要**烘焙成 Mesh 换正式碰撞** |
| 15 | 关卡数值写进场景 | ⛔ 要**数据驱动**，用 Resource 存配置 |
| 16 | 每个关卡复制一份数值 | ⛔ 跨实例共用配置要用 Resource |
| 17 | .tscn 是文本就能合并 | **语义冲突不会自动解决** |
| 18 | 多人同时编辑一个场景没问题 | 要**拆小 + 单人所有权 + 编排器接入** |
| 19 | 跳关功能以后再说 | **决定迭代速度**，要早做 |
| 20 | 能跳过去 = 能测到 | ⚠ 跳转要能**带状态**（中段、指定装备、跳过教程） |
| 21 | 灰盒就是白盒加点细节 | ⚠ 灰盒 = 白盒 + 正确碰撞 + 临时光照 + **已配置的玩法逻辑** |
| 22 | 关卡验收看模型摆完没 | 验收**玩家能否完成** |

## 审核时逐条问自己

1. 有没有关卡卡表？还是直接开始摆几何？
2. 白盒阶段能不能跑？有没有玩家控制器？
3. 有没有找**没参与设计的人**试玩？
4. 有没有死路？任何可达区域能否回到上一检查点？
5. 引导是环境语言还是箭头？
6. 检查点之间的失败成本可接受吗？
7. 白盒阶段测过帧率吗？
8. CSG 是当原型还是当交付资产？碰撞有没有烘焙成 Mesh？
9. 关卡数值是数据驱动还是硬编码进场景？
10. `.tscn` 有没有多人同时编辑？
11. 跳关入口能不能带状态？

> ⚠ **白盒验收清单（逐条打勾，⛔ 不能"看起来差不多了"）：**
> 玩家不看提示能找到第一条路 · 每个跳跃在能力范围内且失误不会卡死 · **无死路** ·
> 失败成本可接受 · 目标物进入时可见 · 无跳过内容的捷径 · 帧率达标 · 光照能区分可走/不可走。
