# firearms — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/firearms.md`
>
> 边界：本篇是**枪械这一武器门类**。伤害与对抗层见 `audit/godot/combat.md`；
> 投射物穿透与预测线见 `audit/godot/projectile.md`。

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 枪械就是个开火函数 | 是**射击状态与规则层**；所有参数要从同一份 FireContext 派生 |
| 2 | 动画通知里写 `current_ammo` | 换弹取消/快速切换/预测回滚会**失去唯一事实源** |
| 3 | 输入只在按下瞬间消费 | 连按两次只开一枪；要 `BufferedAction` |
| 4 | hitscan 和 projectile 比优劣 | 选择依据是**手感**（需不需要感知弹丸），不是技术偏好 |
| 5 | 每帧挂 RayCast3D 开火时读 | 那是上一物理帧结果；要 `force_raycast_update()` 或直接空间查询 |
| 6 | 在 `_process()` 里用直接空间查询 | 安全期在 `_physics_process()` |
| 7 | 摄像机命中点当子弹终点 | 贴墙、探头、部位判定**全错位**；要归一到权威命中源 |
| 8 | 后坐力 = 镜头抖动 | 要拆**视觉 / 模式 / 扩散**三个独立变量；混了准星与落点永久错位 |
| 9 | 直接改摄像机旋转生成弹道 | 同上 |
| 10 | 后坐力纯随机 | 没有可学习性，压枪技术无意义；要固定模式 + 越界稳态 |
| 11 | 后坐力每帧朝零插值 | 开火期间第一发上抬被立即抵消；要 `decay_delay` 后接管 |
| 12 | 压枪后从摄像机角度插值回正 | 玩家已下压鼠标，枪口却停在准星下方 |
| 13 | 视觉后坐力无限累积 | 要短期上抬/中期阻尼/长期 roll 分层 |
| 14 | 动画师手工 key 后坐力动作 | 必须依赖 `pattern_offset`，不能与数据无关 |
| 15 | 扩散是个隐藏随机数 | 不可读的 Random Circle 只是**随机惩罚**；准星要实时显示命中半径 |
| 16 | 准星反向参与命中 | 缩放动画、画布宽高比会偷偷改变枪法 |
| 17 | 准星显示 2° 实际 4° | 玩家认为系统骗他 |
| 18 | 首发扩散设为零 | 首发精度是**可配置窗口**，基础值可留极小扰动作门槛 |
| 19 | 连发扩散无限叠加 | 要"每发固定增量 + 恢复折扣" |
| 20 | 所有武器都做弹道下坠 | 短距高弹速只有零点几像素，应归零 |
| 21 | sub-step 用可变 dt | 帧率会改变下坠量；要固定 `h` + 累加器 |
| 22 | 预测线和真实弹道两套函数 | 会"预测线穿墙、实际命中墙后"；要**共用同一积分器** |
| 23 | 穿透复用装饰性材质标签 | 要独立规则表（层数/厚度/硬度/角度/衰减） |
| 24 | 穿透靠一个布尔 | 薄墙扫射与厚墙单点是不同玩法 |
| 25 | 动画播完 = 换弹完成 | 真正改弹药的是 `SwappingMag` 的**逻辑门限** |
| 26 | 战术换弹和空仓换弹统一扣备弹 | 战术换弹枪膛留一发，统一扣会让**玩家白丢一发** |
| 27 | 取消换弹 = 动画可随便打断 | 条件应是"**弹药已加入**"；取消不得重跑 `add_magazine()` |
| 28 | 切枪停了动画但逻辑没跑 | "取消换弹但弹药没加" |
| 29 | 开火能在换弹任意阶段打断 | "换弹不能开火"的窗口被废掉；只在 `READY` 允许 |
| 30 | 动画通知反向驱动弹药 | 要状态机推进，动画用 seek/cross-fade 跟 |
| 31 | 切换是销毁武器再实例化 | 要 `disable` 而非销毁；弹药存实例或 loadout |
| 32 | 切枪取消换弹是免费加速 | 那是**经济型漏洞**不是操作深度 |
| 33 | 等动画完全结束才允许射击 | 玩家感觉输入迟钝；要有独立**部署门限** |
| 34 | 切换期间射击请求直接执行 | 新武器可能还没部署；要丢弃/缓冲/延迟三选一 |
| 35 | ADS 是"开镜动画播完" | 是独立状态机 `INACTIVE/ENTERING/STEADY/EXITING` |
| 36 | ADS 瞬间消除全部扩散 | 玩家感觉前几毫秒开了挂 |
| 37 | 扩散乘区散落在 if-else | 要写进**数据规约**，乘法加法二选一 |
| 38 | FOV 用 `lerp(cur,tgt,speed*dt)` | 帧率不安全；要 `1 - exp(-k*dt)` |
| 39 | ADS 覆盖后坐力 | 模式与视觉后坐力要分开，不得互相覆盖 |
| 40 | 一个"叶子碰撞体"同时管弹道/AI视线/隐藏 | 会"客户端看到草、服务器没有这根草" |
| 41 | 探头 = 把角色整体偏移 | 要控制**可见比例/暴露时间/枪口位置** |
| 42 | 射线从摄像机中心发 | "看到头露出来却打不到人" |
| 43 | 射线从枪口发 | 贴墙探头"看不见目标却命中"；两者都要归一到**统一命中源** |
| 44 | 预测线从摄像机中心积分 | 要从同一命中源 socket 积分 |
| 45 | 掩体收益按摄像机能否看见敌人算 | 要按**暴露比例/受击部位** |
| 46 | 客户端把渲染结果发回服务端 | 摄像机只能用于输入投射 |
| 47 | 探头可逐帧自由拖到墙外 | 要固定时长状态机 + 胶囊夹紧 |
| 48 | 备弹只按武器存 | 三种模型（武器/弹药类型/弹匣）是不同设计，要选 |
| 49 | RPC 信任客户端的 `current_ammo` | `consume()` 永远先检查再写值 |
| 50 | 弹药类型用武器名字符串 | 要稳定 `AmmoType` 资源 |
| 51 | 爆炸半径复用 hitscan 单点 | 要独立 area/几何查询 |
| 52 | 客户端说"我打中 X 扣 Y 血" | ⛔ 命中判定绝不能客户端定 |
| 53 | 每帧给每个 projectile 发位置 RPC | 服务端持续模拟 + 低频同步 + 客户端预测外插 |
| 54 | 混用 `get_ticks_msec()` 与服务器 tick | 时基要统一 |
| 55 | rewind 无窗口上限 | 会引入重计算、时钟伪造、时间跳跃漏洞 |
| 56 | 修好 rewind 就没 peeker's advantage | 那是**预测与延迟的固有产物**，只能缓解 |
| 57 | 观战视角混入 rewind 逻辑 | 会造成误判 |
| 58 | 客户端反馈反向改变伤害 | 反馈可协商，⛔ 不得改变伤害 |

## 审核时逐条问自己

1. 后坐力是三个独立变量吗？玩家压枪时准星和落点对得上吗？
2. 扩散玩家**读得出来**吗？准星显示的值和真实用的是同一个吗？
3. 预测线和真实弹道调用的是**同一个** `step_ballistic()` 吗？
4. 换弹的**逻辑门限**和动画结束是分开的吗？战术换弹会不会白丢一发？
5. 取消换弹时，弹药、状态、动画、输入四者一致吗？
6. 切换是 `disable` 还是销毁？切回时弹药是从运行时恢复还是读默认值？
7. 切枪取消换弹会不会变成**免费满弹**？
8. ADS 过渡期会不会瞬间消除扩散？FOV 插值帧率安全吗？
9. 命中射线从哪个 socket 发出？探头时会被墙挡住吗？
10. 客户端有没有把**渲染结果**发回服务端当判定依据？
11. `consume()` 是先检查再写值吗？RPC 里有信客户端的弹药数吗？
12. 有没有任何一条"命中 / 伤害 / 弹药 / 换弹结果"判定**只跑在客户端**？
13. rewind 有窗口上限吗？观战视角混入了吗？
