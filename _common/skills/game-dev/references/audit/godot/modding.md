# modding — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/modding.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Mod 就是装个 EditorPlugin | 玩家 Mod 走 **`load_resource_pack()`** |
| 2 | 先加载的优先 | **后来加载的压过先前的** |
| 3 | `replace_files=false` = 后来者优先 | 是**不覆盖** |
| 4 | 有官方 zip 自动导入器 | **没有**，别复制编辑器导入管线 |
| 5 | 解压时拼文件名没事 | 未校验 `../` = **任意文件写入** |
| 6 | Mod 脚本能被沙箱隔离 | **不能**，权限与游戏脚本相同 |
| 7 | 不覆盖就安全 | **不构成沙箱** |
| 8 | `res://` 能 globalize 成真实路径 | 导出项目里**不行** |
| 9 | C# dll 随时加载 | 必须在资源包**之前** |
| 10 | 不用记录 pack 来源 | 出问题时**无法定位** |
| 11 | 登记的路径 = 最终解析结果 | 只是**声明来源** |
| 12 | 4.x 的 Zip 只能读 | **ZIPPacker 能写** |
| 13 | 卸载 Mod 不影响存档 | **可能打不开**，要降级策略 |
| 14 | Mod 之间无依赖 | 要处理**加载顺序** |
