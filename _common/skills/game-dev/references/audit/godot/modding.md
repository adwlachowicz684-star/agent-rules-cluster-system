# modding — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/modding.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Mod 就是装个 EditorPlugin | 玩家 Mod 走 **`load_resource_pack()`** |
| 2 | 先加载的优先 | **后来加载的压过先前的** |
| 3 | `replace_files=false` = 后来者优先 | 是**不覆盖** |
| 4 | 有官方 zip 自动导入器 | **没有**，别复制编辑器导入管线 |
| 5 | 解压时拼文件名没事 | 未校验 `../` = **任意文件写入** |
| 6 | Mod 脚本能被沙箱隔离 | **不能**，权限与游戏脚本相同 |
| 7 | 不覆盖就安全 | **不构成沙箱** |
| 8 | `res://` 能 globalize 成真实路径 | 导出项目里**不行** |
| 9 | C# dll 随时加载 | 必须在资源包**之前** |
| 10 | 不用记录 pack 来源 | 出问题时**无法定位** |
| 11 | 登记的路径 = 最终解析结果 | 只是**声明来源** |
| 12 | 4.x 的 Zip 只能读 | **ZIPPacker 能写** |
| 13 | 卸载 Mod 不影响存档 | **可能打不开**，要降级策略 |
| 14 | Mod 之间无依赖 | 要处理**加载顺序** |
| 15 | 在 `_ready()` 里加载包就行 | ⛔ 必须 autoload 的 **`_init()`**，晚了 preload 已发生 |
| 16 | 菜单里加载包会作用于所有场景 | **已 `preload()` 的场景不受影响** → 装了没变化 |
| 17 | 相对路径 `mods/foo.pck` 没问题 | CWD **不保证是 exe 目录**，搜索栏启动即失效 |
| 18 | ZIP 包也能移除原版文件 | ⛔ **只有 PCK 支持文件移除**，补丁要删文件只能用 PCK |
| 19 | ZIP 主包会被自动使用 | ⚠ **已知 bug**，需 `--main-pack` 启动脚本 |
| 20 | 依赖按目录名字面序加载 | ⛔ 必须**拓扑排序**，否则报错指向依赖者而非真因 |
| 21 | 循环依赖会自然报错 | 要**主动检测**，否则两个都失败且无从下手 |
| 22 | 存档记"启用数量"够 | ⛔ 要记 **id + 版本**，数量相同但内容全错 |
| 23 | 游戏本体用 tool build 无妨 | ⛔ 官方：**不该用**（安全），Mod 工具与游戏分离 |
| 24 | `add_import_plugin()` 能做玩家 Mod | 面向**编辑器导入**，不是玩家侧 |
| 25 | `offset` 对 ZIP 也有效 | ⚠ **仅 PCK 有效**（官方 Note） |
| 26 | `read_file()` 是流式的 | 会把**整个条目读进内存** |
| 27 | 调试 UI 显示声明来源即可 | ⛔ 覆盖式下**不等于解析结果**，要标注区分 |
| 28 | 引擎内置 Mod 沙箱 | **没有**；第三方插件有，但不是引擎能力 |
| 29 | 加载失败静默继续 | 要**显式记录并提示**，否则玩家以为装上了 |
| 30 | 顺序写死在代码里 | 顺序即优先级，**玩家该能调整** |
| 31 | 不用记 sha256 | 无法区分**原版 / 补丁 / DLC / Mod** |
| 32 | 缺 Mod 时崩溃可接受 | 要**降级提示**而非崩溃 |
| 33 | Mod 与 DLC 同一套校验 | **信任级别不同**，不该共用 |
| 34 | 临时解压目录不用清理 | 磁盘**泄漏**，多次加载后堆积 |
| 35 | 文件存在即认为 Mod 合法 | 要**校验清单**（id/版本/依赖） |
| 36 | 加载顺序配置不进存档 | 换机器后**顺序丢失** → 冲突复现 |
| 37 | Mod 脚本与游戏脚本同名无所谓 | 覆盖后**行为不可控**，要命名空间隔离 |
| 38 | 加密 PCK 无法被解包 | ⚠ 加密只防 casual，**不是安全边界** |
| 39 | "装 Mod 是安全的"不用特别说明 | ⛔ 等同运行他人代码，**必须明示给玩家** |
