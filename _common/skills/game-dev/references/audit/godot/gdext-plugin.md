# gdext-plugin — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`flow/godot/gdext-plugin.md`

## 第三部分：常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | C++ 一定更快 | 先 profile；热点在 GPU/加载时换语言无用 |
| 2 | godot-cpp 随便配 | **必须匹配引擎小版本 + 浮点精度** |
| 3 | 4.0 的扩展能用在 4.1+ | **不能**，4.0→4.1 是 ABI 硬断裂 |
| 4 | 兼容报错就加优化 | 是版本下限/入口符号/API JSON 三者不一致 |
| 5 | 双精度引擎能用旧扩展 | 精度是 ABI，必须重编译 |
| 6 | `reloadable=true` 能做生产热更 | **只在编辑器**，官方建议仅调试 |
| 7 | 社区绑定看 Star 就够 | 要查版本匹配、维护状态、热重载 |
| 8 | 插件不加 @tool 也能跑 | 编辑器里不执行，看起来毫无效果 |
| 9 | 插件不用管注销 | 残留 UI、重复启用翻倍、状态泄漏 |
| 10 | @tool 脚本无害 | 副作用会**真的改场景文件** |
| 11 | 插件改的东西能撤销 | 不接 UndoRedo 就无法撤销 |
| 12 | 改了导入器就生效 | 导入缓存要显式处理 |
| 13 | GDExtension 能替代改引擎 | 深层机制要用静态 C++ 模块 |
| 14 | 热重载能迁移已创建对象 | 静态状态和已创建对象不能迁移 |
| 15 | Windows 分发只要 dll | Swift 等语言还要带运行库 |
