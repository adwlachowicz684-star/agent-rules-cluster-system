# security — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于流程结束后审核自己的产出、约束边界。
> 「怎么做」见同 skill 的流程部分：`howto/godot/security.md`

## 常见漏写

| # | 漏写 | 后果 |
|---|---|---|
| 1 | 加密但不签名 | CBC 比特翻转，金币字段可被定向改 |
| 2 | 复用 IV | 相同明文产生相同密文前缀，泄露结构 |
| 3 | 用 `==` 比 HMAC | 时序侧信道 |
| 4 | 先解密后验签 | 把攻击者数据喂给解密器 |
| 5 | 密钥硬编码在脚本 | PCK 解包后可读，等于没加密 |
| 6 | 用系统时间做每日奖励 | 改时钟即绕过 |
| 7 | 检测到就崩溃 | 暴露检查点位置，反而更好绕过 |
| 8 | 客户端加密当防作弊 | 结构性无效，密钥必在客户端 |
| 9 | 压缩加密顺序反了 | 压缩率接近零 |
| 10 | 联网逻辑放客户端 | 加多少 HMAC 都没用 |
| 11 | 不写"能防 / 防不住"清单就开工 | 防作弊变成无终点需求，边界反复被重新争论 |
| 12 | 把"有签名"当成服务端可信任数值 | 签名只给完整性与成本，不给真实性 |
| 13 | 不列权威动作清单就分派开发 | 一半校验一半不校验，取决于当时谁在写 |
| 14 | 检测到了就崩溃或弹窗警告 | ⛔ 暴露检查点位置，被 NOP 掉 |
| 15 | 把 PCK 加密写进"防住了什么" | 整体威胁清单失真，定位是门槛不是安全 |
| 16 | 高价值动作只校验其中几项 | 漏归属=替别人操作，漏状态机=负数金币 |
| 17 | 接受客户端"动作发生时间"作为事实 | 改包即冷却失效，服务端日志还看起来正常 |
| 18 | 用客户端 nonce 顶替业务幂等键 | 防不住同一笔业务被合法地发两次 |
| 19 | 上了 HMAC 就省掉服务端数值校验 | 自制客户端自己签，签名合法而数值是假的 |
| 20 | 协议里出现客户端填报的结果字段 | 校验围绕"结果合不合理"而非"输入能否产生" |
| 21 | key 长度不对（非 32 字节） | ⛔ 不报长度错，只返回 null 或乱码，误判成密钥内容问题 |
| 22 | 生成了随机 IV 却没传给 open_encrypted | ⛔ 表面规范、实际仍是空 IV，多存档前缀相同 |
| 23 | 只加密不加 HMAC | ⛔ 比特翻转可改金币位，解密不报错 |
| 24 | 先解密后验签 | 把攻击者构造的数据喂给解密器 |
| 25 | 压缩与加密顺序反了 / 链式调用 | 压缩率接近零，表现为"存档没变小" |
| 26 | 用 randi() 生成 IV 或密钥 | ⛔ 非 CSPRNG，IV 看着随机但可预测 |
| 27 | 把所有数值都保护起来 | 开销复杂度双涨，"哪些重要"再也说不清 |
| 28 | 内存存明文或掩码固定 | 变化锁定可直接定位 |
| 29 | 受保护数值没有范围自检 | 天文数字直到上榜才被发现 |
| 30 | 自检放在 _process 每帧执行 | 开销随字段数线性增长，收益不变 |
| 31 | 把内存保护当成"已防作弊"的证据 | 真正的防线是服务端校验 |
| 32 | 用系统时钟算体力恢复/离线收益 | ⛔ 玩家改表即绕过，且全程不报错 |
| 33 | 用累计游玩时长判定"每日" | 挂机也算一天，客户端无权威墙钟 |
| 34 | 计时字段不进签名范围 | 改存档即刷新每日奖励，验签还照样通过 |
| 35 | 倍速检测用引擎 delta 判定 | 加速工具同时影响它，测不出来 |
| 36 | 倍速检测直接踢人 | ⛔ 240Hz 用户被误封，投诉以"我什么都没做"出现 |
| 37 | 前后端各自拼接规范化串 | 换行符/顺序/编码任一不同即验签失败，误判成密钥错 |
| 38 | 给 hmac_digest 传 SHA-512 | ⛔ 官方仅支持 SHA-1/SHA-256，不报"不支持"只给错结果 |
| 39 | HMAC 密钥用客户端内置固定字符串 | PCK 解包即可读出，等同硬编码 |
| 40 | nonce 按时间生成 / 只内存去重 / 集群无共享 | 碰撞、重启后可重放、多副本重复执行 |
| 41 | 用 == 比对 HMAC | ⛔ 时序侧信道，功能完全正确但仍不安全 |
| 42 | 检测到之后给攻击者可观测反馈 | 静默标记/回滚/上报/隔离四选一，崩溃与弹窗除外 |
| 43 | 只测"正常存档能读"，不做翻转测试 | 验签路径从未被执行 |
| 44 | 只在正常系统时间下测 | ⛔ 改时间才暴露的失效，正常环境全绿 |
| 45 | 只测"请求能成功"，不测重放 | ⛔ 三条防线单次请求下一条都不触发 |
| 46 | 只测"签名能通过"，不测改包 | "有签名却不校验"是典型假安全 |
| 47 | 只测"检测能触发"，不测反应 | ⛔ 反应才是决定成败的一半 |
| 48 | 把 Godot 内置哈希当密码 KDF 用 | ⛔ 4.x 无 PBKDF2/bcrypt/scrypt/argon2，只有 MD5/SHA-1/SHA-256 |
