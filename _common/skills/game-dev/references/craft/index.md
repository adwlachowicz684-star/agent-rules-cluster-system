# craft 层索引：品位与技艺（Godot 4.x）

ⓘ **本层的定位**：howto 写"怎么做"，audit 写"怎么查错"，flow 写"按什么顺序做"，
**craft 写"做到什么程度算好"**。

⛔ **本层是主观的，且明确标注为主观**。
howto 里的值是**可核实的官方事实**，本册的值是**行业经验区间与共识**。

⚠ 引用规则：**不要在本层找官方口径**。需要"这个 API 到底是什么行为"时查 howto。

---

## 按需求入口

| 我要判断… | 看哪个文件 | 关键内容 |
|---|---|---|
| **这个参数该给多少** | `godot/feel-params.md` | 土狼时间 · 跳跃缓冲 · 顿帧 · 屏震 trauma · 输入延迟预算 · 相机阻尼 · 顶点悬停 |
| **看起来好不好 / 是否符合行业惯例** | `godot/aesthetics.md` | 视觉层次 60-30-10 · 缓动曲线选择 · 次级动效 · 打击感配方 · 镜头语言 · 强度一致性 |
| **还能加什么让它超出预期** | `godot/polish.md` | 四层模型（功能→反馈→润色→惊喜）· 按系统打磨清单 · 什么时候该停 |
| **哪里显得廉价** | `godot/cheapness.md` | 匀速线性 · 音画不同步 · 重复反馈 · 占位资源 · 打磨程度不一致 |

## 与其他三层的关系

| 层 | 回答 | 【】字段 | 性质 |
|---|---|---|---|
| howto | 怎么做 | 【读】 | 事实（可核实） |
| audit | 怎么查错 | 【审】 | 事实（可核实） |
| flow | 按什么顺序做 | — | 流程 |
| **craft** | **做到什么程度算好** | **【品】** | **经验（主观）** |

ⓘ 【品】是**可选字段**：技术性 Step 没有审美维度时不必填。
⛔ 但填了就必须指得准——与【审】同样受零交集检查约束。

---

## ⛔ 本层的使用禁忌

1. **不要把经验区间当官方数值引用** —— 需要官方口径时查 howto
2. **不要只抄区间中值** —— 两端对应不同游戏体验，中值两边不讨好
3. **不要在功能没做完时做惊喜层** —— 会变成"华而不实"
4. **不要用堆资源解决廉价感** —— 廉价感来自不协调，不是资源少
