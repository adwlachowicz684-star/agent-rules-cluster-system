# 打磨清单：从"能用"到"超出预期"

ⓘ **本册的性质**：功能做完之后，还能加什么让它**超出预期**。

⛔ 本册**不是**功能清单——功能清单在 flow 层。
本册只写"功能已经正确了，但还显得不够"的那部分增量。

---

## 0. 四层模型

> **验收的顺序不能颠倒：功能 → 反馈 → 润色 → 惊喜。**

| 层 | 状态 | 玩家感受 | ⛔ 跳层的后果 |
|---|---|---|---|
| **1 功能** | 能做这件事 | "能用" | — |
| **2 反馈** | 做了有反应 | "知道发生了什么" | ⛔ 跳过反馈直接润色 = **好看但不知道自己在干嘛** |
| **3 润色** | 反应有层次 | "做得挺细" | — |
| **4 惊喜** | 超出预期一点 | "这个游戏有想法" | ⛔ 功能没做完就加惊喜 = **花哨但不实用** |

⛔ **最常见的错误是在第 1 层没做完时做第 4 层**。表现为：
有炫酷的粒子和音效，但基础操作有 bug —— 玩家的评语会是"华而不实"。

ⓘ 判断自己在第几层的方法：**关掉所有特效，游戏还能玩吗？**
能玩且清楚，说明第 1、2 层到位了；不能，说明还在补基础。

---

## 1. 反馈层（第 2 层）：每个操作都要有回应

| 操作 | 最小反馈 | ⛔ 缺失时的表现 |
|---|---|---|
| 按键 | 视觉 + 音效 | 玩家怀疑"按到了吗" |
| 命中 | 顿帧 + 闪白 + 音效 | "打上去没感觉" |
| 受伤 | 屏震 + 红边 + 音效 | "血莫名少了" |
| 拾取 | 图标飞向背包 | "捡到了吗？" |
| 失败 | 明确的失败表现（不是只弹文字） | "我以为还在进行中" |
| 加载 | 进度 + 占位（不是黑屏） | "是不是卡死了" |

ⓘ 判据：**玩家不应该需要看 UI 才知道发生了什么**。
需要盯血条才知道自己被打 = 反馈层缺失。

⚠ 加载的黑屏尤其值得处理：黑屏超过 **2 秒**，
玩家就会开始怀疑崩溃——即使实际只用了 3 秒。

---

## 2. 润色层（第 3 层）：让反馈有层次

| 项 | 做法 |
|---|---|
| **强度分档** | 轻/中/重三档，见 `craft/godot/aesthetics.md` 第 6 节 |
| **次级动效** | 附属物滞后 30–80ms，见 `craft/godot/aesthetics.md` 第 3 节 |
| **状态有过渡** | ⛔ 直接 `visible = false` 是廉价的，至少淡出 |
| **连续事件不重复播同一反馈** | 连击的第 2、3 下要有变化 |
| **边界有缓冲** | 到边界不是硬停，有阻尼或回弹 |

⛔ **"重复"是润色层最大的敌人**：同一个音效连播 5 次，
第 3 次开始玩家就会烦躁。做法是准备 3 个变体轮换，或做音高微调。

ⓘ 一个低成本高收益项：**随机化**。
粒子角度、音效音高（±5%）、动画速度（±10%）加一点随机，
成本几乎为零，但"机械感"会明显下降。

---

## 3. 惊喜层（第 4 层）：超出预期的那一点

> **判据：惊喜是"玩家没要求、但看到会觉得这游戏有想法"的东西。**

⛔ 惊喜**不是**更多特效。堆特效不会让人惊喜，只会让人觉得闹。

| 惊喜类型 | 例子 |
|---|---|
| **体贴** | 掉落物自动吸过来（省去玩家跑过去捡） |
| **呼应** | 角色走过水面时，倒影里的动作是同步的 |
| **记忆** | 第二次进入某地，NPC 记得上次的事 |
| **连贯** | 战斗结束，角色的喘息动作不立刻切回待机 |
| **宽容** | 差一点没跳上平台时，给一点边缘吸附 |

ⓘ 这些的共同点：**成本不高，但需要有人想到**。所以本册列它们。

⚠ 关于"体贴"这一类，有个重要的行业惯例：
**凡是让玩家重复做的机械操作，都值得被优化掉**。
捡东西、确认对话框、来回跑路——这些是"打磨"最该瞄准的目标。

---

## 4. 按系统分的打磨清单

### 4.1 角色

- [ ] 待机动画有呼吸/微动（⛔ 完全静止的待机 = 木偶）
- [ ] 起步与急停有过渡帧，不是瞬间满速
- [ ] 转向有转身动作或至少不瞬移朝向
- [ ] 落地有压缩、起跳有拉伸（挤压拉伸）
- [ ] 长时间无操作进入"无聊待机"（打哈欠、看四周）

### 4.2 战斗

- [ ] 击杀反馈强于命中反馈一档
- [ ] 连击的每一段反馈有变化
- [ ] 受击方有反应（不是只有攻击方在动）
- [ ] 死亡有过程（不是瞬间消失）
- [ ] 暴击/特殊状态有额外一层反馈

### 4.3 UI

- [ ] 所有过渡 150–300ms，有缓动
- [ ] 数字变化是滚动而不是瞬变（大额数字尤其）
- [ ] 按钮有按下/悬停/禁用四态
- [ ] 长文本有换行与截断处理
- [ ] ⛔ 没有 Godot 默认图标/占位资源

### 4.4 音频

- [ ] 音效与画面同步（差 ≤1 帧）
- [ ] 有 ducking
- [ ] 重复音效有变体
- [ ] 音乐转场是交叉淡入，不是硬切
- [ ] 音量分层（BGM/SFX/语音可调）

### 4.5 场景

- [ ] 进入场景有过渡，不是黑屏
- [ ] 远处有雾/色彩层次（不是纯色背景）
- [ ] 有环境音（即使很轻）
- [ ] 可交互物有视觉提示（高亮/描边/浮动图标）

---

## 5. 怎么判断"够了"

> **判据：把打磨项加进去之后，玩家有没有提到它？**

⛔ 玩家**主动提到**的打磨 = 有效的。玩家没提到 = 可能是自嗨。

ⓘ 但也有反例：**反馈层的东西玩家永远不会提**，因为好的反馈是"感觉不到存在"的。
所以这条判据只适用于**惊喜层**，不适用于反馈层。

⚠ 打磨的终止条件（避免过度）：
- 反馈层：**每个操作都有回应** → 停
- 润色层：**没有重复感、有层次** → 停
- 惊喜层：**每个系统有 1–2 个** → 停

⛔ 惊喜层超过 2 个/系统会稀释重点，且**维护成本随数量线性上升**。

---

## 6. 自检（30 秒）

1. 关掉所有特效，游戏还能玩且清楚吗？（能 = 第 1、2 层到位）
2. 每个玩家操作都有回应吗？
3. 有没有音效/动画在重复播放同一份？
4. 有没有"玩家必须重复做的机械操作"还没被优化？
5. 每个系统有没有至少 1 个惊喜项？
6. 有没有任何地方还是默认占位资源？

---

## 7. 待核对项

| 项 | 怎么验 |
|---|---|
| 音画同步帧数 | 60fps 录屏逐帧比对 |
| 待机是否仍有微动 | 静止 10 秒录屏，看有没有像素变化 |
| 惊喜项是否被玩家注意 | 找不看说明的人玩 5 分钟，问"有没有觉得哪里做得意外地好" |
