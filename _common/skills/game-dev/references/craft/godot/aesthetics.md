# 审美与行业惯例（Godot 4.x）

ⓘ **本册的性质**：记录"有行业共识、但没有标准答案"的审美原则。

⛔ 本册不是风格指南。**不规定你的游戏该是什么风格**，只记录：
哪些做法在多数项目里被反复验证为"看起来更好"，以及它们**为什么**成立。

---

## 0. 总判据：截图测试

> **把游戏的一帧截图给不看说明的人看，他能说出这是什么游戏、现在在发生什么吗？**

⛔ 说不出来，通常不是美术资源不够，而是**视觉层次没建立**：
所有元素的对比度接近，眼睛不知道该看哪里。

ⓘ 这条判据比"好不好看"更有用，因为它是**可执行的**：不需要美术能力，
任何人都能拉一个路人做这个测试。

---

## 1. 视觉层次：一个画面只允许一个主角

| 原则 | 说明 |
|---|---|
| **60-30-10** | 主色 60%、辅色 30%、强调色 10%。⛔ 平均分配 = 没有重点 |
| **强调色只给"需要被点到的东西"** | 可交互物、危险物、目标 |
| ⛔ 饱和度普遍拉高 | 所有东西都在"强调" → 等于没有强调，且**画面躁** |

⚠ **背景降饱和是行业惯例**：前景角色饱和度高、背景低。这不是为了好看，
是为了让玩家的眼睛**自动落在角色上**——否则玩家要"找"自己在哪。

⛔ 反例：UI 用高饱和色铺满、场景也是高饱和 → 玩家分不清 UI 和世界。
多人游戏里这会造成实际的**操作失误**（点到 UI 以为点了地面）。

---

## 2. 动效：缓动曲线不是"随便选一个"

| 场景 | 曲线 | 为什么 |
|---|---|---|
| 元素**入场** | ease-out（起步快、结束慢） | 快点出现，别让玩家等 |
| 元素**退场** | ease-in（起步慢、结束快） | 先给"要走了"的信号，再快速消失 |
| 元素**在屏幕上移动** | ease-in-out | 有加速减速，像有质量 |
| ⛔ 任何地方用 linear | — | 匀速运动**看起来是机械的**，没有生命感 |

⛔ **`linear` 是廉价感最大的单一来源**。一个全用 linear 的 UI，
即便配色、图标都很好，也会被评价为"像 Demo"。

ⓘ 但反过来也要注意：**过长的缓动 = 迟钝**。UI 过渡 **150–300ms** 是行业惯例，
超过 400ms 玩家会觉得"卡"——而这里的"卡"会被误报成性能问题。

---

## 3. 次级动效（Secondary Motion）

> **原则：主物体动了，跟他相关的东西要"跟着动"，但不能一起动。**

| 层级 | 延迟 | 例子 |
|---|---|---|
| 主体 | 0 | 角色身体 |
| 附属 | **30–80 ms** | 服装、头发、披风、武器挂件 |
| 环境反馈 | **100–200 ms** | 落地扬尘、草的摆动 |

⛔ **全部同步动 = 廉价**。这是"看起来很假"的核心原因——真实世界里
没有任何东西是刚性连接的，所有附属物都有滞后。

⚠ 反过来的错：附属物**延迟太大**（>200ms）→ 看起来像"掉了"，不是"跟着"。

ⓘ Godot 里实现：不要给附属物也做物理模拟（太贵且不稳），
用**延迟跟随历史位置**（记录主体 N 帧前的位置，附属物 lerp 过去）就够了。

---

## 4. 打击感配方：叠加，不是加量

一个"有分量"的打击由这些要素**在同一时刻对齐**构成：

```
画面：顿帧（30-80ms）+ 闪白（2-4 帧）+ 屏震 + 粒子
音频：低频冲击 + 高频细节（两层，同时起）
```

⛔ **只堆视觉不听声音 = 打击感做不出来**。打击感至少一半来自音频，
尤其是**低频**——低频给"重量"，高频给"质地"。

ⓘ 行业惯例的两个细节：

- **受击方的反应比攻击方更重要**：敌人被打了有没有反馈，比挥剑动作精不精美更决定手感
- **击杀反馈要比命中反馈强一档**：击杀是"奖励时刻"，与命中共用同一套反馈会显得平淡

⚠ 音频分层（ducking）：打击音效起来时，**背景音乐短暂降 3–6 dB**。
不做 ducking 的结果是"音效被音乐吃掉"，玩家觉得音效没做。

## 5. 镜头语言

| 惯例 | 说明 |
|---|---|
| **跟随有滞后** | 相机永远比角色慢一点，给出速度感 |
| **前瞻（look-ahead）** | 朝移动方向偏 1–3 米 |
| **场景切换不硬切** | 至少 150ms 过渡，⛔ 硬切会让玩家瞬间失去方位 |
| **重要事件推近** | 击杀、开箱、剧情触发时短促推近再拉回 |

⛔ **相机频繁切换 = 晕**。同一场战斗里为了"炫"不停换机位，
玩家的抱怨会是"头晕"而不是"镜头不好"——**归因会被带偏**。

ⓘ 一个反直觉的惯例：**镜头震动和打击反馈不要同时拉满**。
两者都强时，玩家看不清发生了什么，反馈反而变弱。

---

## 6. 一致性：同一动作，不同对象，强度要成体系

> **判据：如果打击小怪和打击 Boss 的反馈完全一样，那反馈就没有传递信息。**

⛔ 反馈强度**无差别**是廉价感的重要来源：它让玩家觉得"游戏没在做区分"。

ⓘ 建立一张强度表（即使只是三档），比给每个对象单独调更可控：

| 档 | 顿帧 | 屏震 | 音效 |
|---|---|---|---|
| 轻 | 30ms | trauma 0.15 | 单层 |
| 中 | 80ms | trauma 0.35 | 两层 |
| 重 | 150–200ms | trauma 0.6 | 两层 + ducking |

⚠ 反过来：**不同武器/技能之间要有音色与节奏的区别**，
完全相同的反馈会让玩家感觉"换武器只是数值变了"。

---

## 7. 反模式：立刻显廉价的六件事

| # | 廉价做法 | 为什么廉价 |
|---|---|---|
| 1 | 全用 linear 缓动 | 机械感 |
| 2 | 所有反馈同强度 | 没有信息层次 |
| 3 | 状态切换无过渡 | 像开关，不像有物理 |
| 4 | 音画不同步 | ⛔ **最容易被察觉**，超过 1 帧就能感觉到 |
| 5 | 无次级动效 | 所有东西刚性连接，很假 |
| 6 | 默认占位资源上线 | 玩家立刻识别出"这是没做完的" |

⛔ 第 4 条尤其值得强调：音画不同步是**唯一一个不需要审美能力就能察觉**的廉价感来源，
而且一旦被察觉，其他所有打磨都会被忽略。

---

## 8. 自检（30 秒）

1. 截一帧给不看说明的人 → 他能说出这是什么游戏、在发生什么吗？
2. 有没有任何地方用了 linear 缓动？
3. 附属物（服装/挂件/UI 装饰）相对主体有 30–80ms 滞后吗？
4. 打击音效与画面差几帧？（录屏逐帧看）
5. 小怪和 Boss 挨打的反应有区别吗？
6. 有没有默认占位资源（Godot 图标、灰色方块）还在场景里？

---

## 9. 待核对项

| 项 | 怎么验 |
|---|---|
| 音画同步 | 录屏 60fps，数音效波形起点与画面变化点相差几帧 |
| ducking 是否生效 | 打击瞬间看 BGM 音量包络有没有下凹 |
| 次级动效延迟 | 逐帧看披风相对身体的滞后帧数 |
