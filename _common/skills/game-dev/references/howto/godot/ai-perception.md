# AI 感知系统（Godot 4.7.2）

`ai-behavior.md` 讲决策（FSM/BT/GOAP），`ai-navigation.md` 讲寻路，
本文讲**目标是怎么被发现的**——此前完全空白。

## 0. 为什么感知要独立成层

**寻路回答"知道目标后怎么走"，感知回答"目标是谁、可信度如何、最后在哪里"。**

⚠ 两者混写的问题根源不是函数太多，而是**信号传播方向错了**：
寻路需要目标位置，但它**不需要知道这个位置来自眼睛、耳朵、同伴还是脚本作弊**。

若在 `_physics_process()` 里先写"检测玩家、设速度、移动"，
再加听觉时就会把声音衰减、记忆、警戒等级全塞进移动函数。

**正确边界是单向数据流**：

```
感知产生证据 → 决策消费证据 → 行动把目标转为速度与动画
```

⚠ **感知输出的不是 `bool`**，至少要有：
候选对象、置信度、最后已知位置、最后观察时间、传感器类型、是否需前往调查。

## 1. 视觉：距离、角度、遮挡三条独立闸门

顺序很重要——先便宜的后贵的：

```
平方距离剔除 → 单位向量点积视锥 → 物理遮挡射线
```

⚠ **距离用 `distance_squared_to()`** 避免开方。
⚠ **角度用 `dot()`** 避免 `acos()`。
⚠ **两项优化都要求方向向量已归一化。**

⚠ **遮挡必须用射线** —— 只判距离和角度会**隔墙看人**。

```gdscript
var query := PhysicsRayQueryParameters3D.create(from, to, collision_mask, exclude)
var result := get_world_3d().direct_space_state.intersect_ray(query)
```

⚠ **4.x 必须创建 `PhysicsRayQueryParameters3D`** ——
不能沿用 3.x 的裸参数写法。

⚠ **射线结果非空 ≠ 看见目标** ——
必须比较 `result["collider"]` 与候选对象，命中的可能是墙。

返回字典含 `position` / `normal` / `collider` / `collider_id` / `rid` / `shape`；
无命中返回**空字典**。

⚠ **感知层要单独建碰撞层**（视觉层 vs 物理层分离），否则要为感知改物理配置。

## 2. 听觉：声音是有位置、有寿命的事件

- 事件建模：发出者、位置、响度、寿命
- 全局声音管理器 / 事件总线
- 距离衰减
- **听到但没看到 → 去查看**（不是直接进入战斗）

## 3. 记忆：丢失目标 ≠ 丢失证据

⚠ **感知不是每帧算完就丢** —— 目标丢失后要保存**最后已知位置**，
并经历 **搜索 → 放弃 → 返回** 的有限状态。

⚠ **记忆不是缓存变量**，它是一个有状态的过程。

### 目标选择

评分维度：距离、可见性、威胁度、上次攻击时间。

⚠ **必须加迟滞** —— 否则会在两个候选的评分边界反复切换目标。

## 4. 群体共享

⚠ **不要让一个敌人瞬间改写所有同伙的黑板** ——
用**警戒等级**（未察觉 / 怀疑 / 警戒 / 战斗）+ **带延迟的传播**。

## 5. 性能与调试

⚠ **感知的检测频率不等于帧率** —— 10Hz 通常足够。
⚠ **不要每帧对每个敌人做全量检测** —— 分帧 / 距离剔除 / 空间哈希。

调试可视化：画出视锥、射线、最后已知位置。
⚠ 没有可视化调试的感知系统，调参会变成猜谜。
