# 生存与角色状态：生命、耐力、饥饿、死亡重生、检查点（Godot 4.7.2）

"生命值""耐力""stamina""饥饿""体温""负重""重生""复活""存档点" 此前 **几乎全部 0 命中**。

⚠ **0 命中等同于"引擎没有这套东西"** —— Godot 节点库里没有
`HealthComponent`、`StaminaComponent`、`Checkpoint`、`SurvivalAttributeSet`。
系统应由项目定义。

> **体力/耐力的恢复怎么按时间结算**（绝对锚点、余数写回、封顶、跨日重置）
> 见 `time-progression.md`。本篇只讲状态本身，不讲恢复的时间数学。

## 0. ⚠ 数值四层必须分开

**`base_value` / `additive` / `multipliers` / `current` 必须分层。**

最常见的错误是把"血量上限"写成一个变量，装备、技能、食物、诅咒的效果
反复加减同一个变量。后果：撤销困难、来源泄漏、重复配装后无法无损卸下、
同一属性被多个系统并发写入的竞态。

| 层 | 性质 | 存不存 |
|---|---|---|
| `base_value` | **存档输入**（永久基础值） | ✅ 存 |
| `additive` / `multipliers` | 运行时视图（临时修饰器） | ✅ 存（含到期时间） |
| `current` | 运行时状态 | ✅ 存 |
| **最终上限** | 计算结果 | ❌ **不存** |

⚠ **保存输入而非保存计算结果** —— 否则上限变化会造成超上限、比例回血错误、
永久容量丢失。

这回答了那个经典问题："上限被临时药水提高后，回满的血量应不应该保留？"
→ modifier 仍在则允许保留；已过期则重新夹取。
⚠ **不要把"上次显示的满血值"写回磁盘**。

## 1. 资源再生与消耗

耐力/饥饿/体温应共享同一个 `ResourceBudget` 模型，但 ⚠ **时间源必须分层**：

| 用途 | 时间源 |
|---|---|
| 真实延时 | `ignore_time_scale = true` |
| 暂停敏感逻辑 | `PROCESS_MODE_PAUSABLE` |
| 持续衰减 | 物理帧累计 |

ⓘ **`process_always` 这个写法不存在。** 官方 `Node.ProcessMode` 是五个值：

| 值 | 官方说明 |
|---|---|
| `PROCESS_MODE_INHERIT = 0` | 从父节点继承，**新建节点的默认** |
| `PROCESS_MODE_PAUSABLE = 1` | 仅 `SceneTree.paused == false` 时处理，**根节点的默认** |
| `PROCESS_MODE_WHEN_PAUSED = 2` | 仅 `paused == true` 时处理 |
| `PROCESS_MODE_ALWAYS = 3` | 始终处理 |
| `PROCESS_MODE_DISABLED = 4` | 从不处理 |

⚠ **"暂停敏感"对应的是 `PAUSABLE`，不是"关掉 always"** ——
两者不是同一个开关的两个取值，写错会导致该停的没停。

⚠ **离线时间补算**是可作弊点（改时钟 / 隔天回来补恢复）—— **待核对**，
按项目是否联网、是否允许离线决定。

## 2. ⚠ 死亡是状态机，不是布尔值

**`TRIGGERED → PLAYING → SETTLING → RESPAWNING`**

⚠ 不能让 `_process` 反复触发。

**死亡期间要禁止**：输入、移动、伤害、拾取、**保存**、重生调用。

### 重生：快照→清场→生成→恢复→释放

**该清掉**：临时修饰器、输入缓冲、Tween、Timer、**飞行中的投射物**
**该保留**：永久进度、背包（按设计）

⚠ **最容易漏的四个**：正在播放的 Tween、正在等待的 Timer、
已连接的信号、飞行中的投射物。

⚠ **`create_tween()` 创建的 Tween 并不自动绑定节点** ——
这是"跨场景引用泄漏"的根源。不要把死亡流程里所有等待都丢给匿名 `await`。

## 3. ⚠ 检查点不覆盖手动存档

**检查点只覆盖"重生事实"，不覆盖玩家手动存档。**

⚠ **死亡在状态结算后才提交临时存档**；进入死亡播放期间**禁止保存**，
否则会把"死亡状态"写进稳定存档。

检查点要存的不只是坐标：还要朝向、当前任务状态、已拾取物品、场景状态。
⚠ 重复触发、进入即触发 vs 需要交互，要提前定。

## 4. 负重与背包容量

按重量 / 按格数 / 按件数三种模型。
⚠ 超重的处理要明确（不能动？减速？）—— 超重降移速应走**修饰器**，不要直接改速度。

> **反模式清单（不能怎么做，审核用）** → `audit/godot/survival.md`


## 5. 修饰器的完整生命周期（四层怎么落地）

⚠ 第 0 节说了"要分四层"，但**分层本身不解决问题** ——
真正的难点是**修饰器怎么安全地加、撤销、过期**。

### ⚠ 每个修饰器必须有来源 ID

⚠ **没有来源 ID，就无法精准撤销**，只能"全部重算"或"猜着删"。
这是"卸下装备后属性没还原"的根因。

```gdscript
class_name Modifier
var source_id: StringName      # ⚠ 必填：谁加的（"equip:sword_3" / "food:stew"）
var stat: StringName
var additive: float
var multiplier: float
var expires_at: int            # 0 = 永久
```

ⓘ 撤销走 `source_id`，⛔ 不走"值相等匹配"——
两个 +10 的修饰器，删错一个玩家看不出来，但数值已经错了。

### 重算流程（唯一正确的顺序）

```text
current_ratio = current / old_max      ⚠ 先取比例，再改上限
max = (base + Σadditive) * Πmultiplier
current = clamp(current, 0, max)       ⚠ 再夹取
if 修饰器仍在: current = max * current_ratio   # 回满/按比例恢复
```

⚠ **顺序反了会丢血**：先夹取再算比例 → 上限下降时
`current` 已被截断，比例取到的是**截断后**的值，恢复不回来。

ⓘ 这就是第 0 节那个问题的完整答案：
**modifier 仍在 → 按比例还原；已过期 → 只夹取，不还原。**

### ⚠ 到期检查不能靠每帧遍历

⚠ **每帧遍历全部修饰器在修饰器多时是浪费**，
更糟的是**到期时刻与帧不对齐**，表现为"buff 晚消失一帧"或"提前消失"。

✅ 用**最近到期时间**驱动：维护一个最小堆/排序数组，
只在 `next_expiry <= now` 时才做清理与重算。

ⓘ 但要注意：**暂停/切场景时"现在"是什么**要与第 1 节的时间源一致，
否则暂停期间 buff 会继续倒计时。

## 6. 死亡状态机：四个阶段各做什么

⚠ 第 2 节给了四个阶段名，这里给每阶段的**具体职责与退出条件**。

| 阶段 | 做什么 | ⛔ 禁止 | 退出条件 |
|---|---|---|---|
| `TRIGGERED` | 记录死因/位置、冻结输入、**广播一次** | ⛔ 再触发第二次 | 动画开始 |
| `PLAYING` | 播放死亡动画、音效、镜头 | ⛔ 接受伤害/拾取/**保存** | 动画结束 |
| `SETTLING` | 掉落结算、任务失败、统计上报 | ⛔ 移动 | 结算完成 |
| `RESPAWNING` | 快照→清场→生成→恢复→释放 | ⛔ **保存** | 回到可控 |

⚠ **"保存"在两个阶段都被禁止**（`PLAYING` 与 `RESPAWNING`），
因为此时存档里会写进"正在死亡"的中间态。
⛔ 只在 `SETTLING` **结算完成后**才提交。

### ⚠ `await tween.finished` 可能永远不返回

⚠ **这是"死亡流程卡在中间阶段"的头号原因。**

Tween 在**其绑定节点被释放时会被 kill**，
而**被 kill 的 Tween 不会发出 `finished` 信号**。

⛔ 症状：玩家死了，动画播到一半，游戏卡住不动。
没有报错、没有崩溃——只是 `await` 永远不返回。

```gdscript
# ⛔ 危险：节点若在动画中被 free，这一行永远卡住
await tween.finished

# ✅ 安全：给超时兜底
tween.finished.connect(_on_death_anim_done)
_death_timer.start(MAX_DEATH_ANIM_SEC)     # ⚠ 超时强制进入下一阶段
```

✅ 三条防御：
1. **必须有超时兜底**（⛔ 不依赖动画一定播完）
2. 用 `get_tree().create_tween()` + `bind_node()` 绑到**活得比动画久**的节点
3. 需要跨场景存活的，绑到 autoload

ⓘ 顺带一条：`Tween.new()` 手动创建的对象是**无效的**，
必须用 `create_tween()`（官方原话：*"created manually... are invalid"*）。

### ⚠ 暂停时信号仍然会触发

⚠ **官方明确：节点停止处理时，`_process` / `_physics_process` /
`_input` / `_input_event` 不再被调用，但**信号照常工作**，
连接的函数会执行——即使脚本挂在已暂停的节点上。**

⛔ 这条直接击穿"我把 `process_mode` 设成 PAUSABLE 就安全了"的假设：
**用信号驱动的保存、伤害、拾取，在暂停期间依然会跑。**

✅ 死亡/暂停期间要拦的行为，**必须在回调内部再判一次状态**，
⛔ 不能只靠 `process_mode`。

ⓘ 另外官方注明：`SceneTree.paused = true` 会**同时暂停 2D 与 3D 物理**；
若确实需要物理继续，要用物理服务器的 `set_active` 单独控制。

## 7. ⚠ 力竭：耐力归零不是"没了"，是进状态

ⓘ 第 1 节说耐力共享 `ResourceBudget`，但**归零之后的行为此前没写**。

⚠ **"耐力 = 0 就禁止行动"是最差的处理** ——
玩家会被卡在一个"只能站着等"的状态，且没有任何可供优化的操作。

✅ 三种可选，按项目选一种并写进设计文档：

| 方案 | 体验 | 代价 |
|---|---|---|
| **力竭惩罚态** | 进入 `EXHAUSTED` 若干秒，期间无法冲刺、恢复变慢 | 要有 UI 明示 |
| **允许透支** | 可继续冲刺，但进入"负债" | 要处理负债上限 |
| **软性惩罚** | 不禁止，只是大幅降低效率 | 惩罚感弱 |

⚠ 选了力竭态，**必须有明确的进入与退出条件**：

```text
进入：stamina <= 0 且 正在消耗
退出：stamina >= EXIT_THRESHOLD        ⚠ 不是 >= 0
```

ⓘ **`EXIT_THRESHOLD` 必须大于 0** ——
否则玩家刚恢复一点点就能冲刺，立刻又归零，
进入"抽搐式"的反复进出（表现为一直在喘气却走不动）。

⚠ 力竭态本身也是个修饰器，**要带 `source_id`**（第 5 节），
否则撤销时会误删玩家的其它 buff。

⚠ **力竭态要不要存档要提前定** ——
存了，读档后玩家一进来就在喘气；不存，刷新状态就能绕过惩罚。

## 8. 检查点：存什么与怎么恢复

⚠ 第 3 节说了"不只有坐标"，这里给可执行的清单与恢复顺序。

### 检查点快照内容

| 类别 | 字段 |
|---|---|
| 位置 | 坐标、**朝向**、所在场景 |
| 角色 | 血量/耐力等 `current`、**永久修饰器** |
| 进度 | 任务状态、已触发的事件 flag |
| 世界 | 已拾取物品、已开启的门、已击杀的 Boss |
| ⛔ 不存 | 临时 buff、**飞行中的投射物**、正在播放的动画 |

⚠ **临时 buff 不存** —— 否则玩家能通过"死亡重来"把临时 buff 变成永久。

### ⚠ 恢复顺序不能反

```text
1. 载入场景（或传送到检查点所在场景）
2. 清场：临时修饰器、投射物、Tween、Timer、输入缓冲
3. 放置角色（坐标 + 朝向）
4. 恢复数值（current / 永久修饰器）
5. 恢复世界状态（门、物品、Boss）
6. 交还控制权
```

⚠ **第 2 步在第 3 步之前** ——
先放角色再清场，会有"角色刚落地就被残留投射物打死"的连死。

⚠ **第 6 步最后** —— 提前交还控制权会出现
"玩家已经能操作，但世界还没恢复完"的撕裂状态。

### 触发策略要提前定死

| 问题 | 选项 |
|---|---|
| 进入即触发 vs 需要交互 | 影响节奏 |
| 重复触发（覆盖还是忽略） | ⚠ 覆盖会让玩家"回退到更早的点" |
| 是否允许回退到更早的检查点 | 多半不该 |
|  multiplayer 下检查点归谁 | 要服务端权威 |

⚠ **"重复进同一个检查点"默认应是忽略，不是覆盖。**
覆盖的情况下：玩家先到 A 再到 B，回头踩一下 A → 被拉回 A。
