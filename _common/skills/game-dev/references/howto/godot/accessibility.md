# 无障碍与字幕系统（Godot 4.7.2）

"色盲""字幕" 此前 **0 命中**。商业项目（尤其主机/PC 发行）越来越把它当上架门槛。

## 0. 无障碍不是"加个选项"

⚠ **交互层（焦点链、键盘/手柄导航）见 `ui-advanced.md`**，本文只讲呈现层。

三类核心障碍对应**不同信息通道**：

| 障碍 | 影响的通道 |
|---|---|
| 视觉 | 读取颜色、文字、界面、空间信息 |
| 听觉 | 语音、提示音、方位判断 |
| 运动 | 反应速度、按键次数、握持方式、连续操作 |

⚠ **无障碍 ≠ 难度选项**，不要混为一谈。
⚠ **要在白板阶段介入** —— 到 QA 阶段再补，通常需要重做材质、UI、图标、教程与本地化文本。

（本文只讲**呈现层**：字幕、色盲、屏幕阅读器。
**交互层**——焦点链、键盘/手柄导航——见 `ui-advanced.md`）

**4.7.2 的官方底座**：已通过 AccessKit 提供 Control 节点的屏幕阅读器支持，
可读取系统「高对比度」「减少动画」「减少透明度」偏好。
⚠ 但**这只是底座，不等于游戏已经无障碍**。

## 1. 视觉：色盲不是"加个滤镜"

⚠ **红绿色觉障碍在北欧裔男性中约 1/12**，是最高发的类型。

⚠ **只改颜色不够** ——
如果角色用红色表示可攻击、蓝色表示不可攻击，**颜色即信息**，加滤镜也解决不了。
必须同时提供**形状、图标、亮度与文字冗余**。

色盲模式的实现：shader 后处理 vs 调色板替换，各有优劣。

**其他视觉项**：
- 文字大小与对比度（⚠ 不是简单放大字体，要处理布局溢出）
- 高对比模式
- 动态模糊/镜头晃动可关闭

### 光敏性癫痫

⚠ 工程安全线（**风险降低准则，不是医学保证**）：

| 维度 | 阈值 |
|---|---|
| 闪烁频率 | **每秒不超过 3 次** |
| 同时闪光面积 | **不超过屏幕 1/4** |
| 饱和红闪烁 | **更严格** |
| 亮度 | 普通 < 20 cd/m²，红闪 < 6 cd/m² |

按"闪烁次数、面积、亮度、颜色、时长"**五维评估**。

## 2. 听觉：字幕承载的是音频事件

⚠ **字幕 ≠ 对话文本** —— 还要包含"[脚步声]"这类**非语音音频线索**。

字幕数据结构：`speaker`（`ambient`/`sfx`/`music` 用于非语音）、文本、时间轴。
要与音频时间轴同步。样式要可配置（大小、背景、颜色）。

**其他听觉项**：
- 单声道下混（单耳听力玩家）
- 音乐/音效/语音独立音量（见 `audio-advanced.md`）
- 视觉替代音频（用 UI 提示代替关键音效）

## 3. 运动：操作无障碍

- 按键重映射（见 `input-remap.md`）
- **长按改为切换（toggle）**
- **QTE 与快速反应的替代路径**
- 可调节游戏速度
- ⚠ **自动瞄准/辅助瞄准也是无障碍的一部分**
- 单手操作模式

## 4. 设置系统

⚠ **首次启动的引导式设置** —— 让玩家先选，而不是藏进二级菜单深处。

- 设置项分类与持久化
- 可读取 OS 级无障碍偏好
- 设置变更**即时生效**（不是重启才生效）

> **反模式清单（不能怎么做，审核用）** → `audit/godot/accessibility.md`


## 5. 屏幕阅读器：官方底座怎么真正用起来

ⓘ 官方原文要点（"创建应用程序" → 屏幕阅读器集成）：

**① Godot 会自动检测屏幕阅读器是否在运行，检测到就自动启用无障碍支持。**

⚠ 这意味着**默认行为跟你测出来的可能不一样** ——
开发机上没开屏幕阅读器，无障碍支持就是关的；
玩家机器上开着，行为就变了。
⛔ 不配置就上线 = 你从没测过玩家实际走的那条路径。

配置项：`accessibility/general/accessibility_support`

| 取值 | 用途 |
|---|---|
| 自动（默认） | 检测到屏幕阅读器才启用 |
| **强制启用** | ⚠ 当调试工具**未被 Godot 识别为屏幕阅读器**时必须用这个 |
| 禁用 | 明确不需要时 |

ⓘ **强制启用是开发期必需** ——
很多辅助功能调试工具不会被识别为屏幕阅读器，
不强制开启你就**根本连不上**，会误以为"屏幕阅读器支持坏了"。

**② ⚠ 屏幕阅读器的音频不经过 Godot。**

官方原话：*"屏幕阅读器支持是直接使用屏幕阅读器应用程序本身来播放音频
（而不是通过 Godot 项目）"*。

✅ 推论：**即使把音频驱动设为 Dummy，屏幕阅读器仍能正常工作**。
⛔ 反过来也成立：你在游戏里做的音量、总线、混音**对它完全无效**。

⚠ 这条直接影响排查：屏幕阅读器没声音时，
去查 Godot 音频总线是**完全错误的方向**。

**③ ⚠ 官方明确：要达到良好可用性需要做大量工作。**

不是开了开关就无障碍。官方要求两件事：

| 必做 | API |
|---|---|
| 定义无障碍标签 | `Control.accessibility_name` |
| 定义无障碍描述 | `Control.accessibility_description` |
| ⚠ **确保读取流程符合逻辑顺序** | 靠节点树顺序 |

⚠ **`accessibility_name` / `accessibility_description` 是官方 API，
不填的话屏幕阅读器读出来的是"按钮"** ——
玩家听到一串没有意义的"按钮、按钮、按钮"。

ⓘ **逻辑顺序 = 节点树顺序**，不是视觉顺序。
这就解释了为什么"UI 好看但读起来乱"：
容器重排改变了视觉顺序，节点树却还是原来的。

✅ 判据：**按 Tab 键走一遍，与你眼睛看到的顺序一致**。

**④ 测试工具（官方点名）**：Windows **NVDA** / macOS **VoiceOver** / Linux **Orca**。

⚠ 官方建议"在目标平台上用主流屏幕阅读器测试"。
⛔ 只靠"开了开关没报错"不算测过。

### ⚠ 常见误判

| 现象 | 真实原因 |
|---|---|
| 开发机上屏幕阅读器没反应 | 没开屏幕阅读器 → 自动模式下**根本没启用** |
| 开了 NVDA 还是读不出 | 调试工具未被识别 → 要**强制启用** |
| 读出来全是"按钮" | 没填 `accessibility_name` |
| 读的顺序很乱 | **节点树顺序 ≠ 视觉顺序** |
| 调游戏音量影响它 | ⛔ 不会，它走系统，不是 Godot 音频 |

## 6. 色盲：从"颜色即信息"到冗余的流程

⚠ **核心判据只有一句**：**把颜色去掉，这个信息还在吗？**

⛔ 红色=可攻击、蓝色=不可攻击 → 去掉颜色后**无法区分** → 不合格。
✅ 红=骷髅图标、蓝=盾牌图标 → 去掉颜色仍能区分 → 合格。

### 冗余的四个通道（至少再加一个）

| 通道 | 适用 | ⛔ 注意 |
|---|---|---|
| **形状** | 图标、血条分段 | 小尺寸下形状会糊 |
| **图标** | 状态、阵营、可交互 | 要进图集，别用文字 |
| **亮度** | 高亮/置灰 | 与背景对比要够 |
| **文字** | 数值、状态名 | 要本地化 |

⚠ **亮度这条最容易被忽略**，但它对**全色盲**（约 1/30000）是唯一可用通道。

### 色盲模式：两种实现的选择

| 实现 | 优点 | ⚠ 代价 |
|---|---|---|
| **shader 后处理** | 一处生效，覆盖面广 | ⚠ **会改掉 UI**，可能让菜单也变色 |
| **调色板替换** | 精确、只改该改的 | 要遍历所有材质，漏一个就残留 |

ⓘ 折中：后处理只作用于**世界层**，UI 走调色板。
⛔ 全靠后处理的话，玩家会问"为什么我的菜单也变灰了"。

⚠ **不要只做三种滤镜（红绿/蓝黄/全色盲）** ——
真实色觉是连续谱，三种预设只是**三个采样点**。
✅ 至少要提供**强度调节**，让玩家自己找。

## 7. 字幕系统：数据结构与同步

⚠ **字幕 ≠ 对话文本**（第 2 节已说），这里给可落地的结构。

### 最小字段集

| 字段 | 说明 |
|---|---|
| `speaker` | 说话者；非语音用 `ambient`/`sfx`/`music` |
| `text` | 显示文本 |
| `start_ms` / `end_ms` | ⚠ **音频时间轴**，不是"显示多久" |
| `priority` | 同时多条时的取舍 |
| `speaker_color` | 可选，用于区分说话者 |

⚠ **时间轴必须绑音频，不能绑游戏时间** ——
游戏暂停/慢放时，字幕跟着音频走才对。
⛔ 用游戏时间会出现"暂停后字幕还在滚"。

### 非语音音频线索（最容易漏）

✅ 必做的几类：`[脚步声]` `[枪声]` `[警报]` `[门响]` `[敌人接近]`

⚠ **判据**：**关掉声音玩一遍，能不能玩下去？**
⛔ 不能 = 字幕系统不合格。

ⓘ 这条也是**听力正常玩家的刚需**（公共场合静音玩），
所以它不是"无障碍专属功能"，而是通用质量项。

### 样式可配置项

大小 / 背景（⚠ 半透明黑底是刚需，不是审美）/ 颜色 / 边缘描边 / 每行字数。

⚠ **背景板不是可选的** ——
在明亮场景里，白字直接压在雪地上**完全看不清**。

## 8. 运动无障碍：三类改造

| 类型 | 改造 | ⚠ 关键点 |
|---|---|---|
| **长按 → 切换** | 长按 2 秒改为按一下开/关 | ⛔ 不是所有长按都适合（蓄力类不行） |
| **QTE 替代** | 给一条不按 QTE 的路径 | ⚠ 两条路径的**奖励要等价**，否则是惩罚 |
| **自动/辅助瞄准** | 归入无障碍 | 很多人不知道这也是无障碍项 |

⚠ **"提供了替代路径"不等于无障碍** ——
如果替代路径明显更难/奖励更少，等于没有。

ⓘ **可调节游戏速度**是收益最高的一项：
它同时帮助运动障碍、反应较慢、以及**新手**，成本却很低。

## 9. 设置系统：即时生效是最难的一条

⚠ **"设置变更即时生效（不是重启才生效）"** 这一条的实现成本被严重低估。

| 设置 | 为什么难 |
|---|---|
| 字幕大小 | 要重排所有 UI |
| 色盲模式 | 要重刷所有材质 |
| 键位 | 要重建 InputMap（见 `input-remap.md`） |
| 振动开关 | ⚠ 要**立刻停掉正在振动的**（见 `input-remap.md` 第 5 节） |

✅ 判据：**改完立刻能看到/感到变化**。
⛔ "保存了但下次启动才生效"在主机平台可能过不了认证。

⚠ **首次启动的引导式设置**要在**进游戏前**做，
⛔ 不能等玩家进了战斗才发现看不清字幕。
