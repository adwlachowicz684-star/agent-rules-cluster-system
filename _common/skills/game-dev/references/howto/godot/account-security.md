# 账号安全、生命周期与风控（Godot 4.7.2）

**此前文档里「盗号 / 账号找回 / 二次验证 / 转服 / 申诉」全部 0 命中。**

> ⚠ **与 `security.md` 的分工**：那篇是**反外挂与存档加密**（请求签名、内存值保护、
> 时间作弊、PCK 加密）。本篇是**账号本身**——认证、会话、找回、风控、生命周期。
> 分服合服见 `sharding-matchmaking.md`；平台账号与令牌见 `platform-services.md`；
> 注销与个人信息删除的合规侧见 `compliance.md`。

⚠ **Godot 是客户端，不是安全边界。** 它只能把服务端已签发的短期 access token
暂存在内存，把刷新凭据放进**平台安全存储**（iOS Keychain / Android Keystore）。

> 审核用反模式清单见 `audit/godot/account-security.md`

## 0. 先分清四个对象，否则后面全白做

```
身份（Identity）  账号 ID、注册联系方式、历史
凭证（Credential） 密码哈希、TOTP 密钥、OAuth subject
会话（Session）    当前登录态
角色（Role/Shard） 游戏内资产
```

⚠ **最该先设计的不是登录界面，是这四者的唯一键与授权表。**
这一层缺失，后面加再多加密和风控都只是**把越权入口包起来**。

⚠ **业务请求只信任"服务端从会话查出的账号 ID"**，
绝不能直接信任客户端传来的 `account_id` / `role_id` / `is_admin`。

⚠ **账号主键要内部生成**，不能用手机号、邮箱或可枚举昵称（这些是可变更的登录名）。
第三方登录存 `issuer + subject`，不能只存第三方返回的可变用户 ID。

## 1. 密码存储：快速摘要加盐不算密码哈希

⚠ **MD5 / SHA-1 / SHA-256 的问题是速度。** salt 只解决彩虹表，**不解决低成本并行猜测**——
攻击者拿到表后可用 GPU 高速试错。bcrypt / scrypt / Argon2id 通过可调工作因子与内存硬度提高成本。

| 场景 | 推荐 | 可复核起点 |
|---|---|---|
| 新系统 | **Argon2id** | `m=19456 KiB (19 MiB), t=2, p=1` 起测 |
| Argon2id 不可用 | scrypt | 最低 `N=2^17, r=8, p=1` |
| 仅旧系统兼容 | bcrypt | cost ≥ 10（通常可升 12），注意 **72 字节输入边界** |
| FIPS 要求 | PBKDF2-HMAC-SHA256 | 至少 600,000 次迭代 |

⚠ **参数必须按自己的 CPU/内存预算实测，不能照抄文章。**
在预发布环境测 p50/p99 延迟与登录峰值——把成本无上限调高同样会制造 **DoS 面**。

⚠ **存储方案错比算法错更常见**：salt 存成常量、用用户名或时间当 salt、
省略唯一随机 salt、十六进制后再 base64 造成截断、登录/迁移时悄悄降级到 SHA-1、
把密码提示明文入库、忘记重新哈希。

⚠ **升级策略**：用户下次成功登录时用新参数重哈希；遗留弱哈希不要强行全量重置。

⚠ **NIST 当前不再要求定期强制改密码**，只在有泄露证据时强制改；
不要求复杂字符组合，但应检查已知泄露口令，允许至少 8 字符、最好到 64 字符。
实现上：拒绝常见/已泄露口令 · 允许长口令和空格 · Unicode 先 NFKC/NFKC 规范化 ·
**按账号 + 网段 + 设备指纹三维限流** · 用户名不存在/口令错误/2FA 失败返回**同样模糊提示**（防账号枚举）。

## 2. 会话：access 短命，refresh 可撤销且必须轮换

⚠ **access token 是短时能力证明（5–15 分钟），refresh token 才是长期凭证。**
refresh 只在换发端点使用，**不进业务请求、不进日志**。

⚠ **纯无状态 JWT 若没有服务端吊销能力，改密、登出、盗号后都无法立即失效。**
游戏账号至少要有服务端 refresh 状态表或 token family 记录。

⚠ **refresh 重用检测是把"泄露"变成"告警"的核心。**
每次换发新 refresh 后令旧值失效；**已失效值再次出现 = 有人在用旧令牌 → 撤销整个 family**，
让 access 快速失效、要求完整重认证并通知用户。检测时不能假定能区分谁是攻击者。

**最容易被绕过的六处：**

1. 没显式声明算法（拒绝 `none`、不接受 RS256 公钥当 HMAC 密钥）
2. 改密/登出/确认盗号时**只删客户端 token，没撤销 refresh family**
3. 高危操作（改邮箱、换手机、改支付、解绑 2FA）用昨天的 access token 单向放行
4. refresh 没有闲置上限（如 7 天）与绝对上限（如 30 天）
5. 多端政策由客户端互相通知踢人——**必须服务端保存会话列表**
6. **会话固定**：登录成功后必须发新会话，旧匿名会话立即失效

⚠ **令牌泄露的处置是按凭证撤销，不是"删文件"。**
客户端清内存与本地缓存 ≠ 用户已登出。

## 3. 2FA：TOTP 是基线，短信只能当受限备选

⚠ **TOTP 证明"知道共享密钥且能在时间窗内计算"，不证明对方是官方服务器。**

`TOTP(K, T)`，`T = floor((unix_time - T0)/X)`，RFC 6238 默认 **X = 30 秒**。
共享密钥**至少 128 位、推荐 160 位，必须用 CSPRNG**，不能用玩家输入的字符串。

⚠ **验证默认只接受当前和前后各一个步**（`T-1/T/T+1`）。
RFC 建议网络延迟最多容忍一个时间步；**扩大窗口会提高爆破成功率**。
每个码在同一窗口内只能成功一次（防重放）；连续失败（如 5 次）后强制冷却。

⚠ **TOTP 密钥泄露 = 所有历史未来码都可计算** → 密钥库独立加密、最小化访问、
**日志只存模糊余量与验证结果，绝不记密钥**。

⚠ **恢复码是一次性查找秘密**：8–10 个各约 10 位随机码，
**按一次一码保存哈希（与密码同等级）**，显示一次并强制下载/抄写，用完立即作废。

⚠ **短信有真实 SIM swap 风险**，NIST 已把 PSTN/SMS OTP 列为 **RESTRICTED**——
绝不能做唯一强验证，高价值资产/支付/绑定修改优先 TOTP 或 WebAuthn/通行密钥。

⚠ **强制 2FA 应绑定风险而非一刀切**：高价值账号、充值/交易、管理员/客服、
异常登录、绑定变更。且必须提供至少一个替代恢复路径，
否则强制 2FA 会把"找不到手机"变成**永久丢号**。

## 4. 找回与申诉：恢复必须和正常登录同强度

⚠ **找回首先是身份证明，不是客服自由裁量。**
OWASP 建议收集注册阶段已掌握的硬数据 + 带外随机码；
⚠ **NIST 明确自服务重置不能依赖安全问题作为身份证明**——
答案往往公开、多站复用，且需要明文保存。

**六步流程（高风险决定后移）：**

1. 提交账号标识 → **无论是否存在都返回同一模糊响应**（防枚举）
2. 服务端建找回会话，进入限流与验证码，**不立即冻结正常密码登录**
3. 验证原绑定邮箱/手机、已注册 TOTP/恢复码等受控因子（短信只作备选）
4. 高价值账号追加"知识证据"：充值订单号、订单对应角色/区服、注册近似日期
5. 低风险且双因素成立 → 允许改密 + **撤销全部 refresh** + 通知 + 审计
6. 高价值/渠道不可达/证据矛盾 → 人工申诉（限时、证据清单、**随机工单分配、双人复核**）

⚠ **最容易被社工绕过的是"客服能跳过第二因素"。**
攻击者能说出角色名、最近登录地、订单尾号、社交资料。证据要分三级：

| 级别 | 内容 |
|---|---|
| **强证据** | 原邮箱/手机控制、已注册 MFA |
| **可复核证据** | 支付订单与角色/时间的密码学或渠道校验 |
| **弱证据** | 角色名、截图、好友关系、社交主页 |

→ **只有强证据或可核验支付证据组合才能自动找回**，弱证据只能辅助人工判断。

⚠ **找回申请应触发保护，但不能一刀切冻结**：
低风险仅限制重复发起与改绑定；中风险冻结敏感操作（改邮箱/手机、解绑 MFA、交易）
**但不冻结继续游戏**；高风险（资产已异动、客服确认盗号）才冻结登录与交易。
冻结必须带原因、期限、撤销入口、通知渠道与申诉编号。⚠ **客服不能口头取消风控。**

## 5. 盗号与风控：信号只增信，不能当认证因子

⚠ **盗号路径的共性是"第一因素已失守"** —— 撞库、钓鱼、信息窃取木马、
SIM swap、会话劫持、恶意 OAuth 应用、内部社工与**客服冒充**。

⚠ **玩家电脑上的凭据不应被客户端读取后上传给所谓"反作弊模块"** ——
这会把单机攻击面扩大到服务端。

**三档处置：**

| 等级 | 典型信号 | 动作 | 不能做 |
|---|---|---|---|
| 低 | 已知设备、长期城市、成功 MFA | 放行 + 审计 | 不要求每次重认证 |
| 中 | 新设备、新城市、短时多近似位置 | 要求 TOTP/恢复码，限制改绑定 | 不公开"异地登录"具体规则 |
| 高 | 凭据填充特征、会话重用、绑定突变、资产外移 | 二次验证、冻结交易、人工申诉、通知 | 不靠客户端弹窗直接放行 |

⚠ **IP 与地理位置精度有限**，VPN、IPv6、运营商 NAT、旅行都会误报；
**设备指纹不等于身份，更不能据此直接封禁**。

⚠ **自动处置必须可回滚，并设"安全降级"**：
宁可不给高风险交易，也不要自动封号；客服撤销时同步恢复资产或给补偿工单。

⚠ **登录日志服务于安全、调查与法定义务，不是无期限流水。**
至少记：时间、账号 ID（非昵称）、认证步骤结果、IP、网络类型/AS、匿名设备 ID、
客户端版本、MFA 方法、会话 ID、风控动作、请求 ID。
⛔ **绝不记**：密码、TOTP 密钥、明文恢复码、完整 token、短信内容、身份证号。
保留期写进隐私政策——PIPL 要求"实现处理目的所必要的最短时间"，
⚠ **没有统一法定天数，需按处理目的与法定义务自定，不能"以防万一"永久保存。**

## 6. 生命周期：注销 ≠ 停用 ≠ 删角色

⚠ **注销是用户要求删除账号及相关个人信息，通常不可逆；停用/休眠可能是欠费、
长时间不登录或合规暂停。** 可以撤销短期休眠与未执行的注销，
但不应承诺永久注销可恢复。

**注销主线**：认证 → 展示影响（角色、好友、订阅、未消费余额、第三方绑定）→
显式确认 → **可撤销宽限期（常见 7–30 天，ⓘ 待项目法务确认）** → 到期删除或匿名化
账号标识、联系方式、实名资料、广告标识、营销同意。

⚠ **注销不能只删游戏角色** —— 若仍保留可识别个人的登录/支付资料，
个人信息删除义务并未完成。支付/订单/税务/争议记录按法定期限**去标识化 + 隔离保存**。

⚠ **封禁粒度决定误伤面**：可作用于账号、角色、设备实例、IP 段、支付渠道、聊天功能。
但⚠ **账号与角色封禁必须有原因、期限、证据引用和工单号；
IP/设备只能作风险信号，不能独立承担永久全局封禁。**
"封设备"要区分 rooted/越狱、模拟器、共享设备、恶意实例与租借账号。

⚠ **转服最难的是并发写入与幂等，不是地图兼容。**
预检查（账号状态、等级、冷却期、目标服容量、重名、未结订单、封禁、赛季、绑定）→
事务：源服冻结 → 生成转移单与幂等键 → 复制/移动 → 更新跨服索引 → 目标服激活 → 源服置空。
⚠ **任何失败按同一幂等键补偿**，否则玩家两边各持一份唯一道具。

⚠ **账号合并默认安全失败，不默认覆盖**：两边都有充值/资产/赛季成绩/处罚记录时
**拒绝自动合并**，要求先转移或提交工单。合并要用时间线快照记录哪一方胜出，
⚠ **邮件/手机、实名、支付证据、好友关系不得被攻击者控制的一方覆盖。**

## 7. Godot 侧的正确位置

⚠ **`user://` 不是安全凭据库。** 官方文档把它描述为"面向游戏存档和配置文件"
的用户数据文件夹。⛔ **`ConfigFile` 与明文 `user://token.cfg` 都不能存放
access/refresh token、TOTP 密钥、密码或客服工单凭据。**

⚠ **"记住密码"的风险是把长期秘密交给客户端文件。**
即使文件用 Godot 对称加密封装，密钥仍可由同一进程、导出 PCK 或同设备其他应用间接访问。
正确方案：**不保存密码**，只保存可撤销的 refresh token 并放进平台安全存储。
PC/Mac/Linux 没有统一"安全区"，应按系统凭据库实现或降低离线续期能力。

```
1. 启动读内存 access token；没有或快过期 → 调 refresh，不读文件
2. 登录走系统浏览器/平台 SDK（OAuth/OIDC），Godot 只接收一次性回调码
3. 所有请求由统一 AuthClient 注入 token；401 触发一次轮换，连续失败清本地态回登录
4. refresh 被拒 / family 撤销 / 绑定变更 → 清空内存与平台存储，展示服务端原因，
   ⚠ 不自动用旧密码重登
5. 注销先调后端撤销再清本地；网络失败也要显示"正在登出"，⛔ 不假装凭据仍有效
```

⛔ **不要自建一个对所有脚本全局可读的"解密单例"**；
⛔ 日志、崩溃上报、分析、模组回调都不得读取 token；
⛔ token 不进命令行、导出配置、Autoload 属性、版本控制。
⚠ **崩溃报告必须脱敏**——token、邮箱、内部用户 ID、请求头发前剥离。

## 8. 待核对项（运行时验证）
