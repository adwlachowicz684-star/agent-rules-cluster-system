# 关卡设计与编辑工作流（Godot 4.7.2）

"关卡编辑" 此前 0 命中。⚠ **这和"程序化关卡生成"是两回事** ——
那是自动生成，这是**人怎么设计并搭建关卡**。

## 0. 关卡 = 空间 + 引导 + 节奏 + 挑战

⚠ **关卡设计不是"把场景搭出来"**，是设计玩家的心流曲线。

从"玩家此时应做什么、应有什么感受"出发，**而不是从"这里放一个箱子"**。
先写一屏关卡卡表：`[目标]` / `[挑战]` / `[资源]` / `[引导]` / `[松弛]`。
它随后成为白盒验收单——验收的不是"模型摆完了"，而是玩家能否完成、是否误走。

工作流：**白盒（blockout）→ 灰盒 → 美术 → 打磨**。

⚠ **不做白盒直接上美术，往往不是省时间** —— 而是把几何返工变成美术与程序一起返工。

## 1. 白盒（blockout）的完整流程

⚠ **白盒的目标不是"把几何摆出来"，是验证玩家能否完成、会不会误走。**

### 第一步：写关卡卡表（先于任何几何）

每一屏（或一个挑战段）填一张：

```text
[目标]   玩家这一屏要达成什么（一句话，可验证）
[挑战]   阻止他达成的是什么（敌人 / 地形 / 资源限制 / 信息缺失）
[资源]   玩家手里有什么（技能、道具、掩体、退路）
[引导]   他怎么知道该往哪走（光照、色彩、形状、声音、NPC，⛔ 不是箭头）
[松弛]   紧张之后的喘息点在哪
```

⚠ **卡表随后成为白盒验收单** —— 验收的不是"模型摆完了"，而是玩家能否完成、是否误走。

### 第二步：按"可走通"而非"好看"建几何

```
1. 用 CSG 基本形状（Box / Cylinder）搭出**可通行体积**，⛔ 不放任何装饰
2. 尺寸先用真实比例：门高 2m、台阶 15cm、跳跃距离按角色能力实测
3. 只做三种材质：可走（灰）、不可走（红）、目标物（黄）
4. ⚠ 立刻装上玩家控制器跑一遍 —— 白盒阶段就要能跑
```

⚠ **不做白盒直接上美术，往往不是省时间** —— 而是把几何返工变成美术与程序一起返工。

### 第三步：灰盒验证（白盒通过后才做）

灰盒 = 白盒 + 正确的碰撞 + 临时光照 + 已配置的玩法逻辑。
验收方式：**找没参与设计的人试玩**，⛔ 设计者自己玩不算（他知道答案）。

必问三个问题：
1. 你在哪卡住了？（卡住 ≠ 挑战，分不清就是设计失败）
2. 你以为要去哪？实际去了哪？（偏差就是引导失效）
3. 哪里你觉得"莫名其妙就过了"？（说明挑战没生效）

> **反模式清单（不能怎么做，审核用）** → `audit/godot/level-design.md`

## 2. 关卡验收清单

⚠ 逐条打勾，⛔ 不能"看起来差不多了"就过：

- [ ] 玩家能在**不看提示**的情况下找到第一条路径
- [ ] 每个跳跃/攀爬都在角色能力范围内，且**最坏情况**（失误后）不会卡死
- [ ] ⚠ **无死路**：任何可达区域都能回到上一个检查点（这是硬要求）
- [ ] 检查点之间**失败成本可接受**（重玩时间 < 挑战时间）
- [ ] 目标物在**进入时可见**或在合理探索距离内
- [ ] 无"跳过内容"的捷径（除非是设计意图）
- [ ] 帧率在目标平台上达标（白盒阶段就要测，⛔ 别等美术）
- [ ] 光照/色彩能区分"可走"与"不可走"

## 3. CSG：官方定位是"关卡原型"，不是交付资产

官方文档明确：*"Level prototyping is one of the main uses of CSG in Godot"*。

### 节点体系与三种布尔运算

```
CSGCombiner3D          # 只负责组织合并，把局部运算隔离开
  ├── CSGBox3D         # Union（默认）
  ├── CSGCylinder3D    # Intersection
  └── CSGMesh3D        # Subtraction（挖洞）
```

⚠ **`CSGCombiner3D` 适合把"房间""家具""洞"的局部运算隔离开** ——
⛔ 不要把所有几何塞进一个 Combiner（改一处会重算全部）。

**4.7 新增**：CSG 自动平滑、碰撞体吸附路径点、顶点吸附、轴向测量
→ 说明 CSG 与精确摆放仍在主线维护（⚠ 不是"已弃用"，也⛔ 不是"可做最终资产"）。

### ⚠ CSG 的两个限制

1. ⛔ **CSG 不应成为最终美术资产** —— 它是原型工具
2. ⚠ **CSG 的碰撞体是自动生成的**，但复杂布尔运算可能产生意外碰撞面
   → 白盒通过后要**烘焙成 Mesh** 并替换为正式碰撞体（⚠ 待核对：是否存在统一替代 CSG 的正式白盒工具 · 验证：查 4.7.2 官方文档与社区方案）

## 4. 关卡场景的组织方式

```text
关卡 = 小场景 + 逻辑锚点 + 数据资源
```

| 节点 | 承担 |
|---|---|
| `Marker3D` | 位置/朝向（出生点、检查点、刷怪点） |
| `Area3D` | 区域事件（触发区、边界） |
| `Path3D` | 路径编辑（巡逻路线、引导线） |

- 跨实例共用的配置用 **Resource**（⛔ 不要每个关卡复制一份数值）
- 关卡流程用脚本或专门的服务场景
- ⚠ **关卡里不要硬编码逻辑** —— 用数据驱动

✅ 推荐的实例化结构：

```gdscript
### 关卡数据（Resource）—— 策划改这个，⛔ 不改场景
class_name LevelData extends Resource
@export var spawn_points: Array[Vector3]
@export var checkpoint_count: int
@export var enemy_waves: Array[WaveData]
@export var time_limit_sec: float

### 关卡场景只读 LevelData 并构建，⛔ 场景本身不含玩法数值
```

## 5. ⚠ .tscn 是文本 ≠ 可安全自动合并

⚠ **多人同时编辑同一场景，文本格式降低了存储负担，却不会自动解决语义冲突。**

典型冲突：两人各自加节点、Git 合并成功、但 `node_paths` 指向的节点被改名 → 运行时崩溃且不报在合并处。

✅ 应对三条：
1. **拆小场景** —— 一个 `.tscn` 只负责一小块
2. **锁单人所有权** —— 同一时刻只有一人编辑某场景
3. **尽量通过自动加载的编排器接入** —— 跨场景引用走名字/路径而非直接节点引用

## 6. 快速迭代是基础设施

⚠ **没有快速跳转的调试入口，测一个后期关卡要从头玩一遍** ——
这不是锦上添花，是**决定迭代速度的基础设施**。

✅ 三件套（白盒阶段就要有）：

```
1. 从任意关卡启动（命令行参数）
   --level=chapter3_boss
2. 关卡跳转命令（GM 命令面板）
   /jump chapter3_boss
3. ⚠ 白盒阶段就要能跑（可玩性验证不能等美术）
```

⚠ 跳转入口要能带状态（跳到关卡中段、带指定装备、跳过教程），
否则"能跳过去"和"能测到"是两回事。


## 7. 关卡生命周期：统一状态机，⛔ 不要散在各处

关卡不是"一个场景 + 一堆触发区"，它有**自己的状态**：

```text
LOADING ──→ RUNNING ──┬──→ CLEARED ──→ （切下一关）
                      └──→ FAILED  ──→ （重生 / 重开）
                      └──→ PAUSED  ──→ RUNNING
```

⚠ **为什么必须集中**：散在各处的后果是"通关了但敌人还在追"
"失败了但还能拾取""加载中玩家已经在操作"——
每一条单独看都像小 bug 叠加起来就是"关卡状态不可信"。

```gdscript
enum Phase { LOADING, RUNNING, PAUSED, CLEARED, FAILED }

var phase: Phase = Phase.LOADING

func _try_clear() -> void:
    # ⚠ 通关判定**每帧都可能为真**（玩家站在触发区里来回走）
    if phase != Phase.RUNNING:
        return                     # ⛔ 没有这道门就会重复触发
    phase = Phase.CLEARED
    _lock_input()
    level_cleared.emit()
```

⛔ **通关/失败不是"弹一个 UI"，是状态转移。** 只弹 UI 不改状态的话，
结算界面弹出期间玩家仍在被攻击、仍能拾取、仍能再次踩到通关点。

ⓘ 与相邻域的分工：

| 管什么 | 归谁 |
|---|---|
| 死亡 / 重生 / 检查点快照 | `howto/godot/survival.md`（⛔ 检查点只覆盖**重生事实**） |
| 关卡解锁 / 章节进度 | `howto/godot/narrative.md`（⛔ 检查点 ≠ 关卡解锁源） |
| 本关内的阶段与结算 | 本篇 |

设了 `PROCESS_MODE_PAUSABLE` 也不能保证暂停期间什么都没跑。
