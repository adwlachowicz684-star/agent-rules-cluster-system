# Godot 4.x 版本控制与资源组织

## 0. 最重要的一条：`.uid` 必须入库

4.4 引入脚本/着色器侧车 `.uid` 后，**重命名和移动资源不再等于破坏引用**，
但前提是 `.uid` 进入版本控制并随源文件一起移动。

⚠ **`.gitignore` 里排除 `*.uid` 是最严重的错误** ——
官方明确 `.uid` 必须提交；忽略后不同机器可能生成不同 UID，
导致脚本、着色器引用错配。

```gitignore
# Godot 4.1+
.godot/
*.translation

# 错误：不要这样做
# *.uid
```

⚠ **只移动 `.gd`/`.gdshader` 而不移动同名 `.uid`** ——
外部移动时必须把侧车文件一起移动。

## 1. 文本可 diff ≠ 可语义合并

`.tscn`/`.tres` 是文本格式便于版本控制，但"可 diff"不等于"可合并"。

⚠ **合并后文件合法 ≠ Godot 加载正确** ——
可能仍存在重复节点、错误父级、丢失连接、资源错配。
合并后要跑 headless 校验 + 冒烟场景 + 目视检查关键关卡。

⚠ **不要见到 `.tscn` 冲突就 `git checkout --ours/--theirs`** ——
会丢失一边的新节点、脚本、连接或资源 ID，往往比冲突本身更糟。

**冲突演练**：先备份两侧 → 运行格式/导入检查 → 逐节点比较，不是逐行盲选。

## 2. 缩小同时编辑窗口

**无法拆分的共同编辑**：短任务、频繁同步主干、尽早提交合并，
不要各开两周分支。

**拆分粒度三条硬约束**：
- 一个场景最好由一个负责人维护
- 一个场景最好只因一种业务变化频繁修改
- 一个场景应能单独打开、单独测试、单独 revert

⚠ **"Godot 没有二进制锁，所以没法防止两人编辑同一场景"——技术上对，结论错。**
真正治理靠小场景、明确所有权、分支策略、钩子和沟通。

⚠ **Godot 没有内置服务器锁**；LFS 的 Lockable 只防未授权推送，
不能阻止两个编辑器同时打开文件。"场景锁"只能是工作流约定。

## 3. 目录与命名

```
core/  gameplay/  ui/  world/
assets/source/  assets/imported/
resources/  tests/  tools/  addons/
```

⚠ **目录名不要以创作者姓名、临时任务或临时日期为中心** ——
名称应表达"它是什么/用于什么"。

⚠ **源资产（.blend/.psd/.fbx）不应与导入后使用目录混在同一层级**。

命名用 `snake_case`（Godot 惯例）；C# 类型与文件名用 `PascalCase`。
路径只在 `res://` 内统一用正斜杠 `/`。

前缀要词典化：`mat_*` / `tex_*` / `snd_*` / `env_*`。
⚠ **不要发明 `a_*`、`z_*` 这类排序前缀**。

## 4. 复用：小场景 + 数据化 Resource

变体优先级：**Resource 数据变体 → 继承场景 → 复制整个 `.tscn`**。

⚠ **每次复制场景都要回答：复制的是数据、行为还是二者？**
只是数值不同 → 抽取配置资源；只是外观不同 → 抽取材质/主题。

⚠ **`resource_local_to_scene` 不是"共享变体"的默认答案** ——
它在实例化时复制资源，适合需要独立状态的材料/曲线。

⚠ **不要把同一材质/网格/动画反复内嵌进多个场景** ——
既膨胀 diff 也破坏复用。

⚠ **也不要"过碎"** —— 拆分边界是业务职责与变化频率，不是节点数量。

## 5. UID 的正确心智模型

⚠ **"4.4 有 UID，所以随便移动都不会坏"是危险结论** ——
官方保证移动后引用可追踪，但前提是 `.uid` 被提交并一起移动。

⚠ **UID 减少了路径破坏，却没有消除场景冲突** ——
移动资源后 A 的引用通过 UID 保持，B 仍可能在同一文件里增删节点，
合并时文件结构本身仍然冲突。

⚠ **不要在不同文件上复制相同 UID** —— 会导致资源身份混乱。

⚠ **不要手写或"重置" UID** —— 由编辑器生成与维护。

⚠ **diff 里不要只删 `path`** ——
即便 UID 有效，路径仍是人类审阅、加载回退、日志定位的线索。

## 6. 移动资源的十步

```
1. 列出目标文件及其 .uid 侧车
2. 校验目标路径无冲突
3. 校验所有 .uid 内容唯一且格式正确
4. 原子移动源文件 + 侧车文件
5. 更新所有 Godot/脚本/工具引用
6. 在干净仓库重新打开项目
7. 重新导入资源
8. 运行 GUT + headless 冒烟 + 关键场景测试
9. 生成引用/孤立文件报告
10. 提交并记录旧路径→新路径映射
```

⚠ **目录重组只由脚本执行并生成变更清单** —— 不要手工搬。

## 7. Git LFS 的用法与坑

⚠ **LFS 用白名单而非 `*`** —— 只追踪体积大、变化频率低的源资产。

⚠ **应在首次提交目标文件前配置** —— 事后迁移需要专门处理历史。

⚠ **CI runner 要提供 LFS 凭证、容量和克隆策略** ——
否则"拉取代码"变成"拉取整个资产历史"。

⚠ **`.import` 是否忽略取决于项目布局与重导入策略** —— 不能机械套用旧模板。

## 8. 行尾与属性

```gitattributes
* text=auto eol=lf
*.gd text eol=lf
*.tscn text eol=lf
*.tres text eol=lf
*.gdshader text eol=lf
*.uid text eol=lf
```

⚠ **Windows Git 常把 `core.autocrlf` 设为 `true`，会造成行尾噪声** ——
生成的 `.gitattributes` 会强制 LF。
