# 美术资产管线

"美术给了资源，怎么正确进 Godot"。本文讲**导入设置与工作流**，不是美术技法。

## 0. 2D 纹理：三个开关的真正含义

⚠ **Godot 4 的 Filter / Repeat 在 CanvasItem 属性里设**（不在纹理导入页），
项目设置作为默认；3D 则在逐材质配置。

### Filter —— 控制"非整数像素对应时的插值"，不是画质高低

| | 该用 |
|---|---|
| **Nearest** | 像素美术（必须） |
| **Linear** | 高清 2D、旋转/缩放对象、Tilemap 缩小层 |

⚠ 4.x 默认 CanvasItem 过滤是**双线性**——
精灵缩小、旋转、平移或相机缩放后，纹理像素不再一一对齐屏幕像素，
就会出现半像素、边缘混色、闪烁。**像素项目要在项目设置里关掉默认过滤。**

### Repeat —— 只有需要连续铺开时才开

| 开 | 关 |
|---|---|
| 地面、墙壁、噪声、可滚动背景 | 按钮、头像、图标、立绘、NinePatch |

⚠ **图集资源的 Repeat 判定对象是整个图集纹理**，不是图集内的逻辑区域。
跨边界污染正是图集缝隙、闪烁、莫名边框的来源。

### Mipmap —— "缩小稳定性"开关，不是高清必选项

- 开了：3D 远距离 / 2D 缩小时不颗粒化，性能通常改善
- 代价：**内存 +33%**

### 配置速查表

| 资产类型 | Filter | Repeat | Mipmaps |
|---|---|---|---|
| 像素角色/道具/等比例精灵 | Nearest | 关 | 通常关 |
| 像素 Tilemap | Nearest | 按需 | 通常关 |
| 高清背景、旋转/缩放图层 | Linear | 按需 | 建议开 |
| UI 图标、头像、立绘 | Linear | 关 | 关或测 |
| 可平铺地面/噪声 | 按需 | **开** | 缩小场景建议开 |
| 法线/数据贴图 | 由材质定 | 由材质定 | 按需 |

## 1. 像素美术"糊了"的五个原因（按排查顺序）

⚠ **经典误区**：以为是源 PNG 质量差。其实是五个环节叠加：

1. 项目默认开了线性 Filter
2. 相机/节点缩放不是**整数倍**
3. 相机、Sprite、Control 位置有 **0.5 像素偏移**
4. 窗口整数缩放没开，或逻辑分辨率与窗口不成整数比
5. Mipmap、平滑、抗锯齿或 CanvasGroup 改变了采样

**排查顺序（从简到繁）**：
先确认 Filter → 冻结相机变换、位置取整 → 目标分辨率截图逐像素比对。
**不要一开始就怀疑源 PNG。**

### 源资产纪律（比格式更重要）

- 保留干净边缘，**不使用透明抗锯齿混色**
- 透明像素的颜色**填充邻近可见颜色**（避免采样到黑边）
- 导出 PNG 时不要叠加缩放、锐化、色彩管理、模糊
- 图集切片设置 **extrusion/padding**，防止过滤跨到相邻区域

## 2. 纹理压缩：按用途分层，不是"无损最好"

| 模式 | 适合 |
|---|---|
| **Lossless**（2D 默认） | 像素、UI、含文字/1px 细节、需精确读取的数据纹理 |
| **VRAM Compressed**（3D 默认） | 数量多、尺寸大的照片背景、立绘、3D 纹理 |
| **Lossy** | 磁盘体积敏感、对少量压缩痕迹不敏感的大图 |
| **VRAM Uncompressed** | HDR/float、渲染目标、计算纹理（内存峰值高） |

⚠ **"高清 2D 该开什么"由内存预算决定，不是视觉风格。**

### Basis Universal

⚠ **它是"超压缩交换格式"，不是普通图像压缩**：
先把纹理编码成可在加载时转码成多数 GPU 压缩格式的形式。

| 收益 | 代价 |
|---|---|
| 文件非常小 | 质量**较低**（块状伪影、颜色偏移、法线方向异常） |
| 享受 VRAM 压缩 | **编码时间长**（影响首次导入和 CI） |
| 适合 Web/移动/下载体积敏感 | **加载时要转码**，首次进场景可能更慢 |

⚠ 显存占用并不比普通 GPU 压缩低。
⚠ **不支持浮点图像**（Godot 会内部回退到 VRAM Compressed）。

**不适合**：角色面部、小字号 UI、像素硬边、法线贴图、数据贴图、美术复审阶段。

⚠ **推荐流程**：开发期用 Lossless/VRAM Compressed 快速迭代，
发布前把候选纹理批量转 Basis Universal 做 A/B 验收。

### ⚠ 检测 3D（detect_3d）：导入期会**自动改写**你的设置

⚠ 官方口径：默认导入选项（**无 mipmap + Lossless**）是为 2D 准备的。
一旦纹理在 3D 场景中被使用（例如作为 `BaseMaterial3D` 的贴图），
Godot 就会**把导入选项改成对 3D 更友好**：启用 mipmap、压缩模式改为 VRAM Compressed，
并**自动重新导入** —— 除非显式修改了「检查 3D > 压缩至」选项。

⛔ 后果不是"画质变了"这么简单：

- 2D 项目的纹理被临时拖进 3D 场景试一次，**导入设置就此被改写**，而没人动过它
- 之后"纹理糊了 / 显存涨了 / 包体大了"，排查必然被引向"美术换了图"或"谁改了设置"
- ⛔ 而它表现为**导入面板上就是 VRAM Compressed** —— 看起来像一直如此

⛔ 判据：**要改回来得改「检查 3D > 压缩至」，不是手动改压缩模式** ——
手动改回去，下次触发检测照样被改写，表现为"改了又变回去"。

⛔ 但官方原话里还有半句，它决定了"改回去"到底怎么做：
`detect_3d/compress_to` **改为 Disabled 再重新导入，并不会改变纹理上已有的压缩模式**
（*"Changing this to Disabled then reimporting will not change the existing compress mode"*），
只有**显式选 VRAM Compressed 或 Basis Universal** 才会生效。

⛔ 于是这里必须**两步都做**，只做一半都不生效：

| 只做这一步 | 表现 |
|---|---|
| 只设 Disabled | 面板**仍是 VRAM Compressed**，看着像"选项没生效" |
| 只手动改回 Lossless | 下次检测到 3D 使用又被改写，"改了又变回去" |

正确顺序：**先把「检查 3D > 压缩至」设为 Disabled（停止自动改写）→ 再手动把压缩模式改回 Lossless → 重新导入**。

### ⚠ 检测法线（compress/normal_map）：同一个"自动改写"族，还会动你的着色器

⚠ 官方口径：`compress/normal_map` 默认是 **Detect** ——
*"if the texture is ever detected to be used as a normal map, it will be changed to Enable and **reimported automatically**"*，
即自动改用 **RGTC**（法线只需要 R/G 两通道）。

⛔ 官方同时注明的代价：*"RGTC compression affects the resulting normal map image.
You will have to adjust **custom shaders that use the normal map's blue channel** to take this into account."*

⛔ 表现为"自定义着色器里从法线贴图取蓝通道，某天开始不对了"，
而⛔ **贴图没换、导入设置没人动过、内置材质一切正常**
（官方：内置材质着色器无论内容如何都忽略蓝通道）。
排查必然被引向着色器代码或光照，不会想到是"纹理被自动转成了 RGTC"。

ⓘ 判据：凡是**自己采样法线贴图**的自定义着色器，都要先确认这张图的
`compress/normal_map` 当前是 Detect 还是 Enable；需要蓝通道就**显式设为 Disabled**，别靠 Detect。

### ⚠ mipmaps/limit：官方标注未实现

⚠ 官方原文：*`int mipmaps/limit = -1` —— "**Unimplemented.** This currently has no effect when changed."*

⛔ 设了它期望"限制 mipmap 层数省内存"，实际**零效果、零报错**，
面板上写进去的数字还会让人以为生效了。内存要省只能靠关 mipmap 或换压缩。

## 3. 图集

**为什么打图集**：减少 draw call。

- `AtlasTexture` / 精灵图集（Godot 内置）
- 外部工具（TexturePacker 等）导入

⚠ 图集内的逻辑切片不适合设 Repeat（见上文）。
⚠ 图集切片要设 padding/extrusion。

## 4. 3D 资产

### 格式

| 格式 | 说明 |
|---|---|
| **glTF（.glb/.gltf）** | **交换首选** |
| FBX / OBJ / Blender(.blend) | 各自取舍 |

⚠ "glTF 是首选"≠"无需检查"——导入后仍要核对材质、缩放、动画。

### 导入设置

- **材质导入模式**：外部材质 vs 内置
- **网格压缩**
- **动画导入**：骨骼、动画剪辑切分
- ⚠ **缩放问题**：FBX 单位不一致是经典坑，导入后先核对尺寸

### PBR 与贴图通道

⚠ **常见错误**：
- **法线贴图绿通道翻转**（DirectX vs OpenGL 约定）
- **sRGB 设错**（颜色贴图要 sRGB，法线/粗糙度/金属度**必须 Linear**）

⚠ 从 Blender/Substance 导出时，AO/Roughness/Metallic 的打包约定要固定下来，
写进项目规范。

### 共享材质

⚠ **共享材质为什么重要**：
自动实例化要求"同 Mesh + 同材质"（见 `render-pipeline.md`）。
给每个实例 clone 一份材质 = 批处理全部失效。

## 5. 资源组织与命名

⚠ **Godot 惯例是 `snake_case`**（文件、节点、变量）。
⚠ **4.4+ 引入 Universal UID** —— 移动/重命名文件不再断开引用。

⛔ **`.uid` 文件必须提交进版本控制**：官方说明，`.uid` 由编辑器自动生成、
**仅供编辑器使用**（导出时信息迁移进 uid database），
但**使用版本控制的用户应当把这些文件加进去**，与 `.import` 同理。

⛔ 不提交的后果是**协同侧的静默断链**：
本机一切正常（`.uid` 还在本地磁盘上），别人拉下来没有 `.uid` → UID 引用失效 →
回退到路径查找 → 若文件同时被移动或重命名过，**引用直接断裂**。
⛔ 表现为"他那儿打开全是红字，我这儿好好的"，且两边都没改过任何引用。

ⓘ 还有一个版本前提：4.4 之前**脚本与着色器不支持 UID**
（它们是纯文本格式，没有地方存 UID），4.4 起才靠 `.uid` 伴生文件补上。
⛔ 所以"文件可以随便移动"这个结论，对 4.4 之前建的项目**不成立**。

建议目录结构：

```
res://
├── art/
│   ├── characters/
│   ├── environment/
│   └── ui/
├── audio/
├── data/           # Resource 数据（技能、关卡配置）
├── scenes/
└── scripts/
```

⚠ 命名规范要**写进项目文档**并让美术遵守，
否则后期整理成本极高。

## 6. 音频资产

| 格式 | 取舍 |
|---|---|
| **WAV** | 无压缩无延迟、体积大 —— **短音效** |
| **OGG** | 有压缩、需解码 —— **BGM 与长音频** |
| **MP3** | 许可与循环点不友好，一般不选 |

⚠ **循环 BGM 用 OGG 要注意循环点**；MP3 几乎无法无缝循环。
⚠ 短音效用 WAV —— OGG 的解码延迟会让密集触发的音效迟到。
⚠ **采样率要统一**，混用会出问题。

⚠ **FMOD / Wwise**：Godot 没有官方一级集成（确认现状）。
要用的话是社区绑定，维护状态需现查。

## 7. 字体（中文游戏是硬需求）

⚠ **中文字符集巨大**，字体文件会非常大 —— 必须做**子集化**（只保留用到的字）。

- **MSDF**：缩放不模糊，适合会缩放的文本
  （项目设置 `gui/theme/default_font_multichannel_signed_distance_field`，
  或 DynamicFont 导入选项里开）
- 系统字体：`SystemFont.multichannel_signed_distance_field`

⚠ **不开启 MSDF 时缩放会模糊/像素化**（尤其位图字体与非 MSDF 动态字体）。

⚠ 4.7 起 `ResourceImporterDynamicFont.hinting` 默认从 1 变 3 ——
升级后字体渲染会变（见 `version-47-48.md`）。

### 三个默认值：会让你得到"看起来正常"的错误结果

⚠ **`allow_system_fallback` 默认 `true`** —— 本字体找不到字形时，
自动用系统字体兜底。官方注明：这让支持 CJK 字符或 emoji 更简单，
因为不必在项目里塞一份 CJK/emoji 字体。

⛔ 对本域的后果：**漏字不会显示成豆腐块，而是显示成系统字体** ——
于是"字体子集化没做全"这个问题**在本机完全看不出来**，
只会表现为**各平台字形不一致**。⛔ 官方同时注明：系统字体外观因平台而异，
且加载系统字体仅 Windows / macOS / Linux / Android / iOS 支持。

⚠ **MSDF 不是"全都开"** —— 官方列出的缺点有四条：
小字号**缺乏 hinting**（不如传统光栅化清晰）、
低端移动设备基础渲染成本更高、
**无法启用 LCD 子像素优化**、
首次显示小字号新字符时成本更高（可用 `preload` 预渲染缓解）。

⛔ 小字号 UI 正文开了 MSDF 反而更糊 —— 而这恰恰是最常用的字号。
⛔ 判据是"会不会缩放"：会缩放的开 MSDF，固定小字号的**不要开**。

⚠ **改了 hinting 没效果 ≠ 引擎有问题** —— 官方注明，
非 None 的 hinting **只对含 hinting 数据的字体生效**。
改了没变化通常说明该字体文件本身没有 hinting 指令：
要么换带 hinting 数据的版本，要么在导入面板开 `force_autohinter`
（用 FreeType 的自动微调器生成）。

### ⚠ subpixel_positioning：像素字体必须关，中文要算预渲染成本

⚠ 官方口径：`subpixel_positioning` 分四档（Disabled / Auto / One Half of Pixel / One Quarter of Pixel），
子像素定位*"可改善字体渲染外观，尤其是在较小的字体大小下"*，
**缺点**是初始渲染字体需要更多时间，*"这可能会导致游戏过程中出现卡顿，特别是在使用大字体时"*。

⛔ 官方明确的一条反向要求：**"对于具有像素艺术外观的字体，应将其设置为 Disabled"**。
⛔ 像素风项目沿用默认，表现为"文字边缘发虚、和像素画风不一致"，
而排查被引向字号或分辨率 —— 因为它是"质量更好"的选项，没人会想到要关掉。

ⓘ 配套的官方权衡：可以**预渲染指定字形范围**来避免游戏中渲染新字形时卡顿，
*"特别是在启用 subpixel_positioning 的情况下"*；
代价是**初始加载时间增加、内存使用量也增加**。
⛔ 对中文项目这就是三难：不开子像素小字发虚、开了可能卡顿、
预渲染能解卡顿但把加载时间和内存顶上去 —— **没有默认值能同时满足，必须实测定档**。

⚠ `oversampling` 官方注明"大多数情况下应该保持为 `0.0`"——
它是"在保持物理大小的前提下用更高/更低分辨率渲染"的覆盖系数，不是清晰度开关。

> **反模式清单（不能怎么做，审核用）** → `audit/godot/art-assets.md`


## 8. SVG：文本必须先转成路径

⚠ 官方：Godot 使用的 SVG 库**不支持对 SVG 图像中的文本进行光栅化**，
必须先把文本**转换为路径**，否则**该文本不会出现在光栅化后的图像中**。

⛔ 后果是"美术给的 SVG logo / 图标，导入后文字整块消失"，
而⛔ **导入过程不报任何错** —— 文件在位、尺寸也对、缩略图可能还有，
只是内容少了一块。排查必然被引向缩放、路径或渲染顺序，
几乎不会想到是"源文件里有文本"。

ⓘ 判据：凡是"设计师从 Figma / Illustrator 导出的 SVG"，
默认都要过一遍"文本转曲"，除非确认过里面没有 `<text>`。
