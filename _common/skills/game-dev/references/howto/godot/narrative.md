# 叙事与进程：任务链、对话树、分支结局、周目（Godot 4.7.2）

"任务链""对话树""好感度""多结局""章节""关卡选择""周目""动态难度" 此前 **全部 0 命中**。
基础数据结构见 `game-systems.md`，本文讲**叙事如何推进、分支如何管理、结局如何判定**。

⚠ Godot 没有"叙事系统"官方子系统。它提供的是自定义 `Resource`、信号、
`StringName`、`ResourceSaver/Loader` —— 真正的问题是把这些组织成
**可测试、可迁移、可持久化**的边界。

## 0. ⚠ 首要任务不是写对话 UI，是建单一数据源

**flag、计数器、关系值必须集中在 `StoryState`，禁止散落在 NPC、关卡或任务脚本。**

⚠ 散落是"后期无法重构"的头号原因。

### flag 命名：三段式

`has_key` 会在"铁匠铺钥匙""地牢钥匙""教程钥匙"之间撞车；
`met_alice` 还会与 `met_alice_2` 形成无法排序的命名。

推荐三段式：
- `global.` —— 跨周目可继承
- `meta.` —— 元进度
- `act1.smith.dialogue.shown.*` —— 演出事实（区别于世界事实）

⚠ **禁止在脚本里手写魔法字符串**，用常量集合或资源路径 ID。
统一用 `StringName` 稳定身份并提高字典比较效率，
但 ⚠ **`StringName` 不是命名规范本身**。

## 1. 任务链

状态机：未接取 / 进行中 / 可交付 / 已完成 / 失败 / 过期。
⚠ 目标类型（击杀/收集/到达/对话/复合）要**可配置不要写死**。

### ⚠ 隐形前置要可查询，不能成为黑盒

`prerequisites` 是玩家能理解的前置；`hidden_prerequisites` 是隐形前置。
**二者都必须可检查，但只有前者默认进日志。**

隐形前置不是天然邪恶（避免显示"先买五瓶药水"这类无关长列表），
但 ⚠ **导致玩家卡关就是设计缺陷**。修法不是隐藏，是**给替代提示**：
把"需要声望 20"变成"守卫低声说商会只对熟客开门"。

## 2. 对话树

结构：`DialogueNode` + `Choice` + 条件 + 效果。

- ⚠ **选项不满足条件时：不显示 vs 显示但灰掉** —— 体验差异很大，
  逻辑上都是"未满足"
- ⚠ **效果的时机**：选中时执行还是对话结束时执行，要明确
- ⚠ **对话中途存档**，恢复时从哪句继续
- ⚠ 对话中读写变量（"如果你有 X 就多一个选项"）

自定义 `Resource` 能**自动递归序列化子资源**，所以保存槽、运行时世界状态、
叙事快照、任务运行时数据要**分层**，不要压成一个巨型字典。

## 3. 分支与多结局（核心）

⚠ **结局判定不能写成一串 `if elif`** —— 分支少时看似清晰，
很快出现**优先级、重复条件、测试覆盖、策划改表**的问题。

结局应由**数据记录**定义：`id` / `priority` / `conditions` /
`flags_to_set` / `required_flags` / `incompatible_with`。

判定器：先找出所有满足的结局 → 按优先级排序 → 处理冲突。

⚠ **优先级必须显式配置**，不能依赖资源数组顺序；
编辑器应检查**重复优先级**并提醒策划。

⚠ 冲突列表要检查"**A 排斥 B、B 也满足、最终选谁**"的可达性 ——
否则数据合法但玩家永远进不去 A。

⚠ 优先级相同时按**稳定 ID 排序**，消除未定义行为。

### "真结局"的设计陷阱

⚠ 玩家不看攻略根本触发不了 —— 要评估这是否你想要的效果。

## 4. 进程结构：章节 / 关卡选择 / 周目

⚠ **关卡选择界面的解锁状态**必须从单一数据源来。

**NewGame+ 继承策略**要分别定义：等级 / 装备 / 剧情 flag 各不相同。
⚠ 周目计数与"只在一周目出现的事件"要单独处理。

## 5. 动态难度

做法：按表现调整 / 按死亡次数 / 橡皮筋 AI。

⚠ **要让玩家察觉不到** —— 被察觉会觉得被羞辱。
⚠ 与成就/排行榜的冲突要提前想清楚。

## 6. ⚠ 旧字段必须给默认值

迁移函数要给所有旧字段默认值，**不要依赖未初始化变量**（呼应 `save-migration.md`）。

> **反模式清单（不能怎么做，审核用）** → `audit/godot/narrative.md`


## 7. ⚠ 对话节点 ID 必须可校验，不能是裸字符串

⚠ **`next_node_id` 写错一个字母，对话会在中途断掉** ——
不是当场报错，而是玩家走到那一句时找不到下一句。

⛔ 症状极具迷惑性：**测试时正常，上线后玩家反馈"对话说到一半没了"**。
因为测试通常只走几条主线，分支节点没人走到。

### 三层防御

| 层 | 做法 | 时机 |
|---|---|---|
| **ID 注册表** | 所有节点 ID 集中在一个 `Resource`/常量文件 | 写的时候 |
| **导入/构建期校验** | 遍历全部节点，检查每个 `next` 都存在于注册表 | 提交前 |
| **运行时兜底** | 找不到就**明确报错并停在原地**，⛔ 不要静默结束对话 | 运行时 |

⚠ 第三层是关键：⛔ **"找不到就结束对话"是最坏的处理** ——
它把"数据错误"伪装成"剧情结束"，玩家和策划都不会发现。

✅ 正确：找不到时打错误日志 + 显示一个开发者可见的提示，
让玩家知道"这里坏了"而不是"剧情就这样"。

### 选项的 `next` 也要校验

⚠ 比正文更容易漏：**选项分支通常在测试时全被跳过**。

ⓘ 判据：校验器要覆盖 `line.next` 与 `choice.next` **两类**，
且**默认不显示的选项**（见第 2 节）同样要校验。

## 8. ⚠ 对话状态绝不能存在 UI 节点里

⚠ **"当前说到哪一句"不能是 UI 节点的成员变量。**

⛔ 后果链：
- UI 关闭 / 场景切换 → 状态丢失，玩家**不知道自己说到哪了**
- 存档读回 → 对话从头开始
- 中途退出再进入 → 重复触发已执行过的效果

✅ 正确：状态放在 **autoload 的 `DialogueManager`**（或 `StoryState` 的一部分），
UI 只是**渲染层**。

ⓘ 这呼应第 0 节的单一数据源：
⚠ **UI 是最容易藏状态的地方**，因为它"看起来就是显示当前进度的"。

### 打字机效果必须有跳过

⚠ **强制玩家按固定速度读完，是最常见的体验抱怨之一。**

✅ 两条必备：
- 点击/按键 → **立即显示完整本句**（⛔ 不是跳到下一句）
- 再点一次 → 才进下一句

ⓘ "立即完成本句"与"进入下一句"是两个动作，
⛔ 合成一个会导致玩家想快进时**误跳过还没看的选项**。

### ⛔ 不要用 `OS.delay_msec()` 做逐字显示

⚠ 它会**阻塞主线程**，表现为整个游戏卡住（不只是对话）。

✅ 用 `create_timer()` 或 `Tween`。

## 9. 对话与存档的接缝（三个必须对齐的点）

| 接缝 | ⚠ 不对齐的后果 |
|---|---|
| **已执行的"效果"不能重放** | 读档后再次对话 → 奖励**又发一次** |
| **中途存档从哪句恢复** | 从对话开头恢复 → 玩家重复看；从当前句恢复 → 要看上下文是否还在 |
| **选项的历史记录** | 分支结局判定依赖"选过什么"，丢了就判错 |

⚠ **效果必须带"已执行"标记**，且标记要随存档持久化。
⛔ 不能依赖"玩家不会回来说同一句话" —— 任务型对话几乎必然重复进入。

ⓘ 推荐：效果记录为 `{node_id, effect_index, executed:true}` 的集合，
⛔ 不要只记 node_id（一个节点可能有多个效果）。

### 对话中的变量读写

⚠ "如果你有 X 就多一个选项"这类逻辑，
✅ 应在**进入节点时求值**，⛔ 不是在打开对话时一次性求值 ——
否则对话过程中获得物品，选项不会更新。

## 10. ⚠ 分支可达性要能自动验证

第 3 节说了要检查"**A 排斥 B、B 也满足、最终选谁**"的可达性。
这里给可执行的做法。

⚠ **"数据合法"不等于"玩家能到达"**：
所有 ID 都存在、所有条件语法正确，但某个结局被另一个永远先满足的结局挡住
→ **玩家永远看不到它，而所有检查都是绿的**。

✅ 两种验证，成本不同：

| 方法 | 做法 | 能发现 |
|---|---|---|
| **静态遍历** | 枚举所有条件组合，按判定器跑一遍，统计每个结局命中次数 | 结局**从未命中** → 不可达 |
| **随机走查** | 模拟玩家随机选择，跑 N 次，统计分布 | 结局**出现概率异常**（过难/过易） |

⚠ 静态遍历在 flag 多时组合爆炸 ——
✅ 折中：只对**影响结局的 flag** 做全组合，其余取默认值。

ⓘ 判据：**每个结局至少有一条可达路径**。
⛔ 出现 0 次的结局要当成 bug 处理，不是"玩家运气不好"。

### 冲突表的对称性

⚠ `incompatible_with` 要检查**双向一致**：
A 写了排斥 B，但 B 没写排斥 A → 判定顺序不同会得到不同结果。

✅ 校验器应把冲突关系**补全为对称**，或**报出来要求策划显式写全**。
