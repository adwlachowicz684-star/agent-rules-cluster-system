# Godot 4.x AI 战术层：目标选择 / 阵型 / 掩体 / 协同

决策层见 `ai-behavior.md`，寻路见 `ai-navigation.md`，感知见 `ai-perception.md`。
本文讲它们之上的**第四层：战术**——"多个 AI 怎么打"，而不是"单个 AI 怎么走"。

⚠ **把战术逻辑写进单个敌人的 AI，是这个域最贵的错误。**
"不要一拥而上""要包抄""轮流攻击"这些规则天生是**跨个体**的，
写在个体里就只能靠个体互相猜测，最后变成一堆互相矛盾的补丁。

## 0. 先分四层，别混在一起

| 层 | 回答 | 本文 |
|---|---|---|
| 感知 | 我知道什么 | `ai-perception.md` |
| 决策 | 我现在做什么 | `ai-behavior.md` |
| **战术** | **我们怎么打、谁先上、站哪** | **本篇** |
| 执行 | 怎么走过去、怎么挥刀 | `ai-navigation.md` `combat.md` |

⚠ 一个具体判据：**"只留一个敌人时这条规则还成立吗？**
成立 → 是决策层；不成立 → 是战术层。"

ⓘ "看到玩家就追"是决策层（单个也成立）。
"同时最多两个敌人攻击"是战术层（单个时毫无意义）。

## 1. 目标选择：评分 + 迟滞 + 仇恨

### 评分维度

⚠ 见 `ai-perception.md` 第 3 节：距离、可见性、威胁度、上次攻击时间。
⚠ **必须加迟滞**——否则在两个候选的评分边界**反复切换目标**。

ⓘ 迟滞的标准做法：**换目标要求新目标分数高出当前目标一个阈值**
（如高出 20%），不是"谁分高谁上"。

```gdscript
const SWITCH_MARGIN := 1.2    # 新目标要高出 20% 才换

func _maybe_switch(best: int, best_score: float) -> void:
    if best == _current:
        return
    if best_score > _score_of(_current) * SWITCH_MARGIN:
        _current = best
```

⚠ 还要加**最短保持时间**（如 2 秒），
否则即使有阈值，激烈战斗中仍会每几百毫秒抖一次。

### 仇恨表不是可选项

⚠ **仇恨（threat）要单独成表，⛔ 不能只靠"当前目标"这一个变量。**

| 目标 | 累计威胁 | 最后攻击时间 |
|---|---|---|
| 玩家 | 120 | 0.4s |
| 宠物 | 35 | 3.1s |

ⓘ 有了仇恨表才能回答：目标死亡/消失后打谁（取剩余最高）、
被治疗/嘲讽时怎么转移（加威胁，不是直接设目标）、
为什么不追着脆皮输出跑（威胁按实际承受伤害累计）。

⚠ **转移目标 ≠ 重设目标。** 嘲讽应该是"给该目标加一大笔威胁"，
让它自然在下一轮评分中胜出；
⛔ 直接设 `_current = taunter` 会让嘲讽结束时 AI 立刻回头——
正确行为是仇恨表仍在，嘲讽的那一笔应**随时间衰减**。

## 2. 阵型与编队：锚点 + 偏移

⚠ **不要给每个单位各自设"玩家位置"为目标点。**
结果是所有人挤向同一个点，然后被避障推开再挤回来——
表现为"一群敌人在原地蠕动"。

✅ 正确模型：**队形有一个锚点 + 每个单位一个槽位偏移**。

```gdscript
# 槽位是相对锚点的局部偏移（队形空间），不是世界坐标
func slot_position(anchor: Vector3, facing: float, slot: int) -> Vector3:
    var local := FORMATION[slot]           # 如 (-1.5, 0, -2.0)
    return anchor + Vector3(local.x, 0, local.z).rotated(Vector3.UP, facing)
```

⚠ **槽位要固定分配**，⛔ 不要每帧按距离重新分配——
那会让两个单位争夺同一个槽位，来回横跳。
ⓘ 分配时机：加入小队时；单位死亡/离队时重排。

⚠ **槽位也要走导航。** 直接把世界坐标当目标会穿墙——
算出槽位世界坐标后仍要交给 `NavigationAgent`（见 `ai-navigation.md`）。

### `avoidance_priority` 是编队的隐形工具

⚠ 官方原话（见 `ai-navigation.md` 第 8 节）：
高优先级代理**不为低优先级让路**，低优先级的要让得更多。

✅ 给队长/Boss/冲锋单位设高优先级，小兵让路——
比手写推挤逻辑简单，且是引擎内建的。

## 3. 掩体与战术位置

⚠ **Godot 没有"掩体系统"。** 掩体是纯玩法概念，要自己做。

### 掩体点要预烘焙，不要运行时查询

⚠ 运行时用射线找掩体 = 每个单位每帧几十条射线，且**结果不稳定**
（同一个位置两次查询可能给出不同点，单位来回跑）。

✅ 关卡编辑时放置 `CoverPoint` 节点（或标记），
运行时只做**查表 + 打分**。

### 打分维度

```text
距自身近（远了跑去挨打）
能挡住当前威胁方向（掩体在"我↔敌人"连线上）
当前未被占用（⛔ 两个单位抢同一个掩体是经典 bug）
能攻击到目标（躲在完全打不到人的掩体里 = 卡死）
```

⚠ **"占用"必须是预约制**，不是"到了才算占用"。
两个单位同时选中同一个掩体 → 都跑过去 → 挤在一起。
✅ 选中即标记 `reserved_by`，离开时释放。

⚠ **还要有超时释放**，否则单位中途死亡会让掩体**永久锁定**。

## 4. 群体协作：攻击令牌

⚠ **"同时最多 N 个敌人攻击"是战术层最基础的一条规则。**
没有它，一群敌人会同时挥刀，玩家毫无反应窗口——
这是"AI 很强但不好玩"的头号原因。

```gdscript
class_name AttackTokenPool
extends Node

@export var max_attackers := 2
var _holders: Array[Node] = []

func request(who: Node) -> bool:
    if who in _holders:
        return true
    if _holders.size() >= max_attackers:
        return false
    _holders.append(who)
    return true

func release(who: Node) -> void:
    _holders.erase(who)          # ⚠ 死亡/离战也要调
```

⚠ **令牌必须能被强制回收。**
单位在持有令牌时死亡/被击退/进入硬直 → 令牌泄漏 →
**所有人都不再攻击**。这是最典型的"AI 突然集体发呆"的原因。

✅ 三个回收时机：攻击动画结束、进入硬直/死亡、离战。
ⓘ 更稳的做法是**带超时的令牌**（超过 N 秒自动回收），作为兜底。

ⓘ 同类机制还有：**包围位限制**（最多几个单位能占据近战位，
其余的在外围游走/等待），比"一拥而上"观感好得多。

## 5. 攻击节奏：间隔、冷却、破绽

⚠ **攻击间隔不能是固定值。** 所有敌人同频 → 玩家找到节拍后无脑闪避。

✅ 三件套：
- **个体冷却**（每次攻击后随机 0.8–1.5 倍基础间隔）
- **令牌限制**（见上，控制并发）
- **破绽窗口**（攻击后摇期间受击加成/防御下降）

⚠ **破绽窗口要给玩家可读的信号**，⛔ 不只是数值。
否则玩家不知道"现在可以反击"，机制等于不存在。

ⓘ 相关：战斗层的硬直/霸体见 `combat.md` 第 8 节。

## 6. 难度自适应

⚠ 难度自适应有两条路，选错会让玩家察觉被"操纵"：

| 做法 | 玩家是否可察觉 | 适用 |
|---|---|---|
| 改**数值**（血量、伤害） | ⚠ 易被察觉（"怎么突然变肉了"） | 尽量不用 |
| 改**行为参数**（攻击频率、并发数、反应延迟） | ⛔ 不易察觉 | ✅ 优先 |

✅ 优先调：反应延迟、攻击令牌数、搜查坚持时间、掩体使用频率。
⛔ 谨慎调：伤害、血量、命中率。

⚠ **不要实时反馈式调整**（玩家连胜→立刻变强）。
玩家会感到"赢了就被惩罚"。
✅ 用**长时间窗口的滚动统计**，且**单向**（只降低难度，不暗中提高），
或明确作为难度档位让玩家自己选。

## 7. AI 性能预算与 LOD

⚠ **AI 是唯一会随单位数平方级变贵的系统。**
20 个敌人 × 每个每帧检测 20 个目标 = 400 次。

### 三条正交的省法

| 手段 | 做法 |
|---|---|
| **降低频率** | 感知 10Hz 通常够（见 `ai-perception.md`）；远处单位 2–4Hz |
| **分帧** | 每帧只更新 N 个 AI，其余排队 |
| **LOD 降级** | 远处/屏幕外：关避障、关感知细节、只跑简化的巡逻 |

⚠ **分帧不能让 AI "变笨得不一致"** ——
⛔ 每个单位每 5 帧才思考一次，但**第几帧**要错开（按 id 取模），
否则会出现"所有敌人同一帧一起决策"的尖峰。

⚠ **LOD 切换要有迟滞**，否则单位在边界反复切换时行为会跳变
（正在攻击的突然降级成巡逻）。

### 关掉什么最有效

ⓘ 按性价比排序：
1. **`avoidance_enabled`** —— 官方明确"Avoidance processing with many
   registered agents has a **significant performance cost** and should only be
   enabled on agents that currently require it"
2. 感知射线数量与频率
3. 重规划路径的频率（`path_max_distance` 别设太小，见 `ai-navigation.md` 第 8 节）

✅ 动态开关避障：只对**近处且在移动中**的单位开。

## 8. AI 调试可视化

⚠ **没有可视化调试的 AI 系统，调参会变成猜谜**
（见 `ai-perception.md` 第 5 节）。

✅ 至少画这些：

| 画什么 | 作用 |
|---|---|
| 当前状态 / 行为树活动节点 | 知道"它现在在想什么" |
| 视锥与感知射线 | 知道"它到底看没看见" |
| 路径与当前目标点 | 知道"它要去哪" |
| 最后已知位置 | 知道"记忆对不对" |
| 令牌持有者 / 槽位分配 | 知道"为什么它不上" |

ⓘ 内建可复用的：
`NavigationAgent` 的 `debug_enabled` + `debug_path_custom_color`
（见 `ai-navigation.md` 第 8 节），导航路径⛔ 不用自己画。

⚠ **调试可视化要有总开关，且默认关。** 一屏 20 个视锥会看不清画面，
也会掩盖真实渲染问题。
