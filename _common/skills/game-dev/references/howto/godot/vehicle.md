# Godot 4.x 载具 / 驾驶

> **适用**：轮式载具（车/卡丁车/坦克履带）。
> **不适用**：飞行器、船舶（走 `RigidBody3D` + 自定义力）。
> ⚠ 本域的核心不是"车能不能动"，而是 **"悬挂与重心调得对不对"**。

## 0. 先定性：轮式与非轮式走不同节点

⚠ **`VehicleBody3D` 是轮式载具的专用节点**，它继承 `RigidBody3D`。

⛔ 关键区别：它的动力**全部经由 `VehicleWheel3D` 的接地点输出**。
无轮载具（飞行/船）用它 → 动力没有出口 →
表现为"改什么参数都没反应"，而排查方向被引到"参数没生效"。

✅ 判据：

| 有无轮子 | 根节点 |
|---|---|
| 有（车/摩托/履带） | `VehicleBody3D` |
| 无（飞行/船/悬浮） | `RigidBody3D` + 自定义力 |

ⓘ 履带车也归轮式：用多个 `VehicleWheel3D` 模拟，
⛔ 不要因为"看起来没有轮子"就改走 `RigidBody3D`。

## 1. 节点结构：车身是根，车轮是子节点

⚠ 车轮必须是 `VehicleBody3D` 的**直接**子节点。

```text
VehicleBody3D            # 根
├── MeshInstance3D       # 车身外观
├── CollisionShape3D     # 车身碰撞
└── VehicleWheel3D × N   # 车轮，直接子节点
    └── MeshInstance3D   # 轮子外观
```

⛔ 车轮挂在车身**之外**（如并列在场景根）→
`VehicleBody3D` 找不到车轮 → 无动力输出，
⚠ **不报错**，只是"车不动"。

⚠ **物理层不自动渲染轮子**：
不挂 `MeshInstance3D` → 运行时看不到轮子，
⛔ 而"车能开"会让人误以为做完了。

ⓘ 车轮职责标记：
- `use_as_steered`：参与转向（通常是前轮）
- `use_as_traction`：参与驱动（决定前驱/后驱/四驱）

⛔ 不标记 → 转向/动力施加到错误的轮子上，
表现为"打方向盘车头不动"。

## 2. ⛔ 车轮不要用碰撞体，用射线

⚠ `VehicleWheel3D` **自带射线检测地面**，不需要碰撞体。

⛔ 给车轮加 `CollisionShape3D` → 与车身碰撞体**互相挤压** →
表现为"车一放地上就弹飞"或"原地抖动"。

✅ 判据：车轮子树里**只能**有 `MeshInstance3D`。

ⓘ 这与直觉相反：看得见的轮子反而不该有碰撞，
碰撞是由**射线**虚拟出来的接地点提供的。

## 3. ⛔ mass 必须显式设，否则载具不动

⚠ `VehicleBody3D` 继承 `RigidBody3D`，质量参与物理计算。

⛔ 依赖子节点自动计算，而子节点（车轮）**不贡献质量** →
总质量异常（常为 0 或极小）→
表现为"推不动"或"一碰就飞"，**不报错**。

✅ 判据：检视器里 `mass` 显式非 0。

ⓘ 质量还决定 04 的 `suspension_stiffness` 该调多大——
不先定质量，悬挂刚度没法算。

## 4. 重心与防翻：低速翻车是参数问题

⚠ **翻车是「重心 + 转向 + 速度」三者的合结果。**

⛔ 重心高于悬挂点 → 过弯即翻，
表现为"低速转弯也翻车"，
⛔ 常被误判为"转向力太大"，于是越调越错。

✅ 判据：重心**低于**悬挂点。

⚠ 高速转向必须衰减：转向幅度随速度增大而减小。

⛔ 不衰减 → 高速打满方向直接翻车，
⚠ 常被误判为"物理引擎有问题"。

ⓘ **手感优先于物理正确性**（见 `common/howto/principles.md#GC-07`）：
真实车辆会翻，但游戏里通常要"不好翻"，
⛔ 不要为了物理真实而让玩家一转弯就翻。

## 5. 悬挂四元组：travel / stiffness / damping / rest_length

⚠ 四个参数要**一起调**，单调一个往往无效。

| 参数 | 作用 | ⛔ 常见问题 |
|---|---|---|
| `suspension_travel` | 悬挂可压缩行程 | **为 0 → 不压缩，车身不随地形，像滑板**（最隐蔽） |
| `suspension_stiffness` | 支撑车重 | 不足 → 车身"坐地"、过坎触底 |
| `damping_compression` / `damping_relaxation` | 抑制弹跳 | **为 0 → 无限弹跳**（最像引擎 bug） |
| `rest_length` | 悬挂自然长度 | 不当 → 轮子悬空或穿地 |

⛔ **`suspension_travel = 0` 是最隐蔽的假完成**：
车能开、轮子贴地，但车身不跟随地形，且**不报错**。

⛔ **`damping = 0` 是最容易被误判的现象**：
表现为"过个坎车身一直晃"，
常被当成物理引擎的 bug 去查，实际只是没设阻尼。

ⓘ 调参判据（可验收）：
- 静止时悬挂**未压到底**
- 过减速带后 **2 秒内停稳**
- 从高处落下**压缩后回弹并停稳**，不穿地

## 6. ⚠ engine_force / steering 是持续属性，不是脉冲

⚠ `engine_force`、`brake`、`steering` 是**车轮上的持续属性**，
设一次就持续生效，⛔ **不会自动归零**。

⛔ 每帧只在"有输入"时设值、无输入时**忘了设 0** →
表现为"松开 W 车还在加速"，**不报错**。

✅ 做法：在 `_physics_process(delta)` 里，
⛔ 无输入分支**显式归零**。

⚠ 且要在**物理帧**而非渲染帧：
⛔ 写在 `_process` → 与物理步长不同步 →
表现为"帧率高时车快、帧率低时车慢"。

✅ `steering` 回正要**渐进**：`lerp(steering, 0, k)`。
⛔ 直接置 0 → 方向盘瞬间弹正 → 高速甩头。

ⓘ `steering` 是**弧度**不是角度（见 `common/audit/global.md#GA-01`），
典型可用范围约 ±0.5，用角度值会导致转向过猛。

## 7. 待核对项（运行时验证）

> ⚠ 以下为本域**尚无统一数值**的项，落地时必须实测确认。
> ⛔ 不要凭印象填数值——这些恰恰是各项目差异最大的地方。

- ⚠ 待核对：mass 与轮数决定的 stiffness · 验证：静止时悬挂未压到底，过坎不触底
- ⚠ 待核对：转向衰减曲线 · 验证：最高速打满方向不翻车
- ⚠ 待核对：damping 两个值 · 验证：过减速带后 2 秒内停稳
- ⚠ 待核对：下车点位置 · 验证：下车后角色站在车门旁，不卡在车里
- ⚠ 待核对：切换冷却时长 · 验证：连按 100 次不漂移、不反复切换
- ⚠ 待核对：网络下载具同步的是控制输入还是物理状态 · 验证：确认控制者唯一，无两端抢控

## 8. 乘员：用 Area3D 检测，状态独立于载具

⚠ 乘员检测用 `Area3D` 包围车身，⛔ **不用车身碰撞体的信号**。

⛔ 用车身 `body_entered` → 地面/道具也触发 →
乘客列表混入非角色，表现为"车里莫名多了东西"。

✅ 做法：`Area3D` + 信号回调里**先过滤类型**再加表。

⚠ **乘员状态必须存外部**（独立的载具管理器），
⛔ 挂在载具子节点上 → 载具销毁 → 乘客引用悬空 → 崩溃。

⛔ 销毁顺序：先让所有乘客下车并定位 → 再销毁载具。
反了 → 角色位置丢失 → 掉出地图或崩溃。

ⓘ 上车后要**关闭角色与车身的碰撞**，
⛔ 不关 → 互挤 → "上车后被弹飞"，常被误判为物理穿透。

## 9. 上下车是事务：先定位，再切换

⚠ 顺序：**先定位角色 → 再交还控制权**。

⛔ 顺序反了 → 定位发生在控制交还之后 →
位置被移动逻辑覆盖 → 表现为"下车后人回到原点"。

⛔ **禁止 reparent 角色到载具**：
角色的物理体仍在世界 → 与车身互挤 → 抖动/弹飞，且不报错。

✅ 做法：角色保持独立节点，上车时隐藏并跟随。

⚠ **必须有切换冷却**：无冷却 → 连按触发同帧多次切换 →
状态翻转、位置抖动，表现为"车里车外闪现"。

⛔ 切换期间**输入不能串台**：
不切输入上下文 → 角色与车同时响应 → "人和车一起动"。

ⓘ 条件不满足（满员/车毁/距离不足）时，
⛔ 静默失败会让玩家以为"上车键坏了"，应给明确反馈。
