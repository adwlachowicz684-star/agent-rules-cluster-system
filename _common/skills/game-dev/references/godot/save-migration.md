# 存档迁移（Godot 4.7.2）

⚠ **这与"云存档/冲突"是两回事** ——
迁移是"**存档格式变了怎么办**"，云存档是"多设备之间怎么同步"（见 `cloud-save.md`）。

## 0. 格式必然要变

新增字段、改字段类型、删除字段、扩展枚举、重排数组都会发生。
**真正的问题不是"要不要迁移"，而是能否从旧存档无损到达当前格式。**

⚠ **`VERSION` 字段要从第一天就写进去** ——
第一天没写格式版本，日后就只能**猜**，而猜错的代价是**玩家进度消失**。

### 三个"版本"要分开

⚠ **存档格式版本 ≠ 游戏版本号 ≠ 构建号** —— 三者常被混为一谈。

存档格式版本应设计为**单调递增整数**，与另外两者完全分开。

### 版本字段的位置

必须位于**所有迁移逻辑都能读到的稳定位置**：

| 格式 | 放哪 |
|---|---|
| JSON | 顶层 `schema_version` |
| ConfigFile | 固定节（如 `[meta]` 下的 `schema_version`） |
| 自定义二进制 | **解密后**、可预测的头部 |

⚠ 不要埋在实体子结构里，也不要依赖不同节的读取顺序。

⚠ **加密存档必须先解密才能读到版本号** ——
所以版本号只能放在**解密边界内**，不能依赖密文之外的位置。
⚠ **加密元数据不能替代自己的版本字段。**

## 1. 三种失败必须区分

| 类型 | 表现 | 处理 |
|---|---|---|
| **损坏** | 无法解密 / HMAC 失败 / JSON 断裂 / 关键字段缺失 | 备份恢复，或用户可见的"存档损坏" |
| **降级** | 旧程序读新存档 | **明确拒绝或提示升级**，不能默默覆盖 |
| **未知未来版本** | 版本高于当前 | **拒绝**，不要硬塞进迁移链 |

⚠ 区分开的意义：日志才能准确回答"是文件坏了、程序旧了，还是迁移写错了"。

⚠ **降级尤其危险**：`ConfigFile.get_value` 对缺失键**返回默认值**，
旧程序遇到未知字段**往往不报错**，却把新状态**静默填成默认值**。

## 2. 迁移的执行

```
备份 → 逐级迁移 → 校验 → 重算 HMAC → 原子替换
```

⚠ **迁移前必须备份** —— 迁移是**不可逆操作**，失败即丢失玩家进度。

⚠ **迁移后必须重算 HMAC/校验值** ——
否则**旧签名会给新数据披上"已验签"的假象**。

**写盘**：先落临时文件，校验并备份后再**原子替换**（写一半崩会损坏存档）。

**逐级迁移 vs 一次性迁移**：逐级更好维护，但要保证链条完整。

## 3. 字段级兼容

| 变更 | 注意 |
|---|---|
| 新增字段 | 默认值从哪来（不能依赖"缺失即 0"） |
| 删除字段 | 旧数据要不要留（回滚需要） |
| 类型变更 | int → float 等，要显式转换 |
| ⚠ 枚举扩展 | 旧存档存的是数字，新增项**会不会错位** |
| 嵌套/数组 | 重排与长度变化 |
