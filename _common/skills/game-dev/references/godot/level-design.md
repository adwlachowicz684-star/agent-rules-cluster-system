# 关卡设计与编辑工作流（Godot 4.7.2）

"关卡编辑" 此前 0 命中。⚠ **这和"程序化关卡生成"是两回事** ——
那是自动生成，这是**人怎么设计并搭建关卡**。

## 0. 关卡 = 空间 + 引导 + 节奏 + 挑战

⚠ **关卡设计不是"把场景搭出来"**，是设计玩家的心流曲线。

从"玩家此时应做什么、应有什么感受"出发，**而不是从"这里放一个箱子"**。
先写一屏关卡卡表：`[目标]` / `[挑战]` / `[资源]` / `[引导]` / `[松弛]`。
它随后成为白盒验收单——验收的不是"模型摆完了"，而是玩家能否完成、是否误走。

工作流：**白盒（blockout）→ 灰盒 → 美术 → 打磨**。

⚠ **不做白盒直接上美术，往往不是省时间** —— 而是把几何返工变成美术与程序一起返工。

## 1. CSG：官方定位是"关卡原型"，不是交付资产

官方文档明确：*"Level prototyping is one of the main uses of CSG in Godot"*。

节点体系：`CSGCombiner3D` + 基本形状/网格/多边形，
三种布尔运算 **Union / Intersection / Subtraction**。
`CSGCombiner3D` 只负责组织合并，适合把"房间""家具""洞"的局部运算隔离开。

**4.7 新增**：CSG 自动平滑、碰撞体吸附路径点、顶点吸附、轴向测量
→ 说明 CSG 与精确摆放仍在主线维护。

⚠ **CSG 不应成为最终美术资产。**（待核对：是否存在统一替代 CSG 的正式白盒工具）

## 2. 关卡场景的组织方式

```
关卡 = 小场景 + 逻辑锚点 + 数据资源
```

| 节点 | 承担 |
|---|---|
| `Marker3D` | 位置/朝向（出生点、检查点） |
| `Area3D` | 区域事件（触发区） |
| `Path3D` | 路径编辑（巡逻路线） |

- 跨实例共用的配置用 **Resource**
- 关卡流程用脚本或专门的服务场景
- ⚠ **关卡里不要硬编码逻辑** —— 用数据驱动

## 3. ⚠ .tscn 是文本 ≠ 可安全自动合并

⚠ **多人同时编辑同一场景，文本格式降低了存储负担，却不会自动解决语义冲突。**

应对：**拆小场景 + 锁单人所有权 + 尽量通过自动加载的编排器接入**。

## 4. 快速迭代是基础设施

⚠ **没有快速跳转的调试入口，测一个后期关卡要从头玩一遍** ——
这不是锦上添花，是决定迭代速度的基础设施。

- 从任意关卡启动（命令行参数）
- 关卡跳转命令
- 白盒阶段就要能跑（可玩性验证不能等美术）

## 5. 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 关卡就是把场景搭出来 | 是**心流曲线**四要素 |
| 2 | 直接上美术更快 | 白盒返工**更贵** |
| 3 | 白盒等美术完再验可玩性 | **白盒阶段就要能跑** |
| 4 | CSG 可以做最终资产 | 官方定位是**原型** |
| 5 | CSG 已弃用 | 4.7 仍在**主线维护**并增强 |
| 6 | .tscn 是文本就能合并 | **语义冲突不会自动解决** |
| 7 | 多人同时编辑一个场景没问题 | 要**拆小 + 单人所有权** |
| 8 | 逻辑写进关卡场景方便 | 要**数据驱动** |
| 9 | 跳关功能以后再说 | **决定迭代速度**，要早做 |
| 10 | 关卡验收看模型摆完没 | 验收**玩家能否完成** |
| 11 | 卡表是策划的事 | 它是**白盒验收单** |
| 12 | Marker3D 只是个空节点 | 它是**位置/朝向锚点**的规范做法 |
