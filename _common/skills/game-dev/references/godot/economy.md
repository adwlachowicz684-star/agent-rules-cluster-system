# 经济系统与长线进度（Godot 4.7.2）

"天赋树""养成"此前 **0 命中**。本文讲大型项目的经济与长线系统。

## 0. 地基：货币不能只是一个 int

⚠ **多货币、来源追踪、上限** —— 后期加货币种类时，单 int 要改所有调用点。

⚠ **单一数据源**：所有改货币的地方必须走同一个入口，否则对不上账。

⚠ **浮点不能碰货币**（精度问题），但加成计算又绕不开浮点。
解法不是"全程用 int"，而是**把两层彻底分开**：

```
货币与计数 = 整数域
加成的乘区管线 = 浮点域
两者只在一个明确的转换点相接
```

事务与日志：出问题要能查账。

## 1. 掉落系统

**核心不是"抽一个"，而是"如何定义一次抽取"** ——
权重、保底、条件过滤、次数限制共同决定输入（表、上下文、历史）与输出（结果、状态变更）。
边界没划清，代码会退化成敌人脚本里的一堆 `if`。

### 保底（pity）

⚠ **掉落最大的坑不是随机算法，是保底状态的存储与重置。**

- 引擎不会帮你维护"连续未中次数" —— **必须随存档持久化**
- ⚠ **必须与抽卡池绑定**，不能全局共用一个计数器
- `RandomPCG::rand_weighted` **明确禁止负权重**

**期望值要算出来验证** —— 配表时确认概率对不对，而不是靠玩家反馈。

⚠ **客户端算掉落 = 可篡改**。有联机时掉落必须在服务端。

## 2. 商店

⚠ **购买校验放服务端**（如果联机）。
⚠ **失败原因要能区分**：货币不足 / 已达上限 / 已下架 —— 统一报"购买失败"会无从排查。

**限购的本质是"计数 + 周期重置"**。
⚠ 最难的是重置：日按哪时区、周从周几开始、跨周期旧计数怎么处理。
⚠ **限购计数必须容忍"玩家跨周期不在线"**。

## 3. 养成与天赋树

### 崩坏点集中在三处

**① 洗点** —— 必须按「取消分配 → 校验 → 扣点」三步，**且在同一事务内完成**。

**② 依赖检查** ——
⚠ **"最大等级"不是"做多个节点"**，而是节点内部的 `current_rank` / `max_rank` 状态。
拆成 I/II/III 三个节点会导致：前置关系爆炸 + 洗点要按依赖逐级回退极易出错。

**③ 叠加法** —— 见下。

### 加成计算：数值崩坏的头号来源

一个"攻击力 +20%"会因实现方式不同而给出完全不同的结果，
**而策划配表时默认它只有一个含义。**

| 方式 | 公式 | 上例（基础100，两个+20%） |
|---|---|---|
| **加法叠加**（同加区求和） | `Base × (1 + Σb)` | `100 × 1.4 = 140` |
| **乘法叠加**（独立因子相乘） | `Base × Π(1+b)` | `100 × 1.2 × 1.2 = 144` |
| **独立乘区**（不同维度） | `Base × A × C × D × …` | 按区相乘 |

**加法的边际收益递减**：已有 +200% 时再 +20%，提升只有约 6.7%。
→ 适合**投放量大、玩家容易堆高**的基础属性，膨胀可控。

**独立乘区的边际收益恒定**：提升比例永远是 20%，加得越多膨胀越快。
→ **必须严格限制投放渠道与数量上限**，否则后期数值失控。

⚠ **叠加顺序必须固定**：`加区 → 乘区 → 独立乘区`，
否则同样的词条组合会因**重算顺序不同**给出不同结果。

## 4. 任务/成就与长线

⚠ **任务条件不要每帧轮询** —— 事件驱动。

⚠ **长线系统唯一可靠的时间源是服务器 UTC** ——
客户端本地时间不可信（可改系统时钟、跨时区、夏令时切换会让"每天 5 点重置"缺一天或多一天）。
`Time.get_unix_time_from_system()` 返回 UTC 时间戳，应作为唯一依据。

## 5. 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 货币一个 int 够 | 要多货币 + 来源追踪 + 上限 |
| 2 | 各处直接改货币 | 必须**单一入口**，否则对不上账 |
| 3 | 浮点算货币小心点就行 | **整数域与浮点域要分开** |
| 4 | 保底计数放内存 | **必须随存档持久化** |
| 5 | 全游戏一个保底计数 | 必须**与卡池绑定** |
| 6 | 权重可以有负数 | `rand_weighted` **明确禁止** |
| 7 | 客户端算掉落没问题 | **可篡改**，联机要服务端 |
| 8 | 购买失败统一提示 | 要能**区分原因** |
| 9 | 限购重置按本地时间 | 要 **UTC**，本地不可信 |
| 10 | 跨周期不在线不用管 | 计数必须**容忍缺席** |
| 11 | 天赋 I/II/III 三个节点 | 应是**单节点带 rank** |
| 12 | 洗点直接清空重分配 | 要「取消→校验→扣点」**同一事务** |
| 13 | +20% 就是乘 1.2 | 三种叠加**结果不同**，要约定 |
| 14 | 属性每次重算都一样 | **顺序必须固定** |
| 15 | 独立乘区越多越爽 | **必须限数量**，否则数值崩坏 |
| 16 | 任务每帧检查条件 | 要**事件驱动** |
