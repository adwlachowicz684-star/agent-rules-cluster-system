# 谜题与交互机关：开关、锁、光线反射、推箱子（Godot 4.7.2）

"谜题""机关""镜子""压力板""推箱子""重力谜题" 此前 **全部 0 命中**。

⚠ **0 命中是正常的** —— Godot 没有"谜题系统"内置模块。
它不是引擎特性，而是每个项目自己搭的一套**协议**。

## 0. ⚠ 先定协议再写机关

**"每个机关各写一套交互逻辑"不是组织问题，是系统性崩溃。**

当门、开关、钥匙、传送器各自监听输入、各自做高亮、各自判定能否触发，
迟早撞上这三种冲突：

1. 同一个键在一帧里被两个机关同时消费
2. 玩家站在门和开关中间，**两个都高亮**，不知道会触发谁
3. 死亡过场期间输入穿透，**玩家在演出时把机关全触发了**

解法不是写更多代码，是抽出 `Interactable` 抽象（统一
`can_activate` / `activate` / `get_prompt`），配 `InteractionBus` 单例
处理打断与提示。

### 检测

**Area 粗筛 + 射线精排**。
`RayCast3D` 每物理帧缓存；`direct_space_state.intersect_ray` 的
`exclude` 要传 `self.get_rid()` 防自击中。

### 输入要抽象成"意图"

不要把交互直接绑按键 —— 键鼠/手柄/触屏的差异要压在一个函数里。
触屏把屏幕坐标投影成世界射线打到 `Interactable` 就触发。

## 1. ⚠ 状态与运行时必须分开

| | 例子 | 存不存 |
|---|---|---|
| **状态** | 门是开还是关 | ✅ 存 |
| **运行时** | 门正在播 0.6 秒开启动画 | ❌ 不存 |

⚠ 读档时让门根据 `open` 调 **`seek(length, true)` 跳到动画终点**，
而不是回放动画，也不是存 `current_animation_position`
（官方明确该属性**只有 getter**）。

`PuzzleState` 用「场景路径 + 实例 ID」做键，支持 `schema_version` 迁移。

### 组合逻辑要数据驱动

机关之间的 AND / OR / 序列用 `Combinator` + `Resource` 描述规则，
**不要在开关里写死"我要开那扇门"**。

## 2. ⚠ 反射谜题：迭代上限是数学问题

两面镜子互相照射 → 光无限反射 → **算法永不结束 → 主线程卡死**。

```
MAX_BOUNCES = 8   # 硬性切断（一般谜题 4-6 够）
```

⚠ **方向用 `Vector3.bounce(normal)`，不是 `reflect()`**

Godot 的 `reflect()` 是"对法线所在平面做镜面"，`bounce()` 才是多数引擎
所说的 reflect。源码里 **`bounce = -reflect`** —— 混用会得到相反结果。

⚠ 每次反射用上一次命中的 `RID` 做 `exclude`，
避免第二跳立刻击中同一面镜子的背面。

## 3. 推箱子：用网格不要用物理

⚠ **网格实现才能做确定性可解校验与 undo**；
物理方案补不完卡死检测。

⚠ 推箱子最怕"推到死角无法挽回" —— **必须有 undo 或 reset**。

## 4. ⚠ 防卡关是解谜游戏的生死线

**玩家卡关是解谜游戏最大的流失原因，而设计者永远低估它。**
你自己做过几十遍的关卡成了肌肉记忆，新玩家可能盯着墙看五分钟。

**防死锁的底线：任何状态下都存在一条回到已知安全状态的路径。**

| 谜题类型 | 安全路径 |
|---|---|
| 推箱子 | undo + reset |
| 开关组合 | "全部拨回初始"按钮 |
| 光线谜题 | 镜子可自由旋转（本身就是安全态） |
| 钥匙 | 永不失落 或 提供替代路径 |

⚠ 这条要在**设计文档阶段**写进每关检查清单，不是开发后期补。

提示系统要**分级**（阈值 45/90/150 秒为占位值，需按项目实测调），不要一次给完。

## 5. 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Godot 有谜题系统 | **没有**，是项目自己搭的协议 |
| 2 | 每个机关各写一套 | 会**系统性崩溃**，要统一 Interactable |
| 3 | 交互绑 E 键就行 | 要抽象成**意图**（键鼠/手柄/触屏） |
| 4 | 高亮随便做 | 多个同时高亮会**不知道触发谁** |
| 5 | 过场时不能交互 | 输入会**穿透**，要显式禁用 |
| 6 | 机关状态存动画进度 | 要存**开/关**，读档 seek 到终点 |
| 7 | current_animation_position 能存 | 官方只有 **getter** |
| 8 | 组合逻辑写死 | 要**数据驱动** Combinator |
| 9 | 反射迭代慢慢调 | 是**数学问题**，要硬上限 |
| 10 | reflect 就是反射 | Godot 里要用 **bounce**（相差负号） |
| 11 | 反射不用 exclude 上一个 | 会**击中同一镜子背面** |
| 12 | 推箱子用物理自然 | 要**网格**才能校验与 undo |
| 13 | 推死了重开就行 | 必须给 **undo/reset** |
| 14 | 卡关是玩家笨 | 是**设计问题**，要有安全路径 |
| 15 | 提示一次给完 | 要**分级** |
| 16 | 压力板一个物体 | 要处理**多个物体压着** |
| 17 | 传送器触发就传 | 会**无限循环**，要冷却/过滤 |
| 18 | 破坏物不存档 | 破坏状态要**持久化** |
