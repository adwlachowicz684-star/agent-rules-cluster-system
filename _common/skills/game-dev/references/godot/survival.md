# 生存与角色状态：生命、耐力、饥饿、死亡重生、检查点（Godot 4.7.2）

"生命值""耐力""stamina""饥饿""体温""负重""重生""复活""存档点" 此前 **几乎全部 0 命中**。

⚠ **0 命中等同于"引擎没有这套东西"** —— Godot 节点库里没有
`HealthComponent`、`StaminaComponent`、`Checkpoint`、`SurvivalAttributeSet`。
系统应由项目定义。

## 0. ⚠ 数值四层必须分开

**`base_value` / `additive` / `multipliers` / `current` 必须分层。**

最常见的错误是把"血量上限"写成一个变量，装备、技能、食物、诅咒的效果
反复加减同一个变量。后果：撤销困难、来源泄漏、重复配装后无法无损卸下、
同一属性被多个系统并发写入的竞态。

| 层 | 性质 | 存不存 |
|---|---|---|
| `base_value` | **存档输入**（永久基础值） | ✅ 存 |
| `additive` / `multipliers` | 运行时视图（临时修饰器） | ✅ 存（含到期时间） |
| `current` | 运行时状态 | ✅ 存 |
| **最终上限** | 计算结果 | ❌ **不存** |

⚠ **保存输入而非保存计算结果** —— 否则上限变化会造成超上限、比例回血错误、
永久容量丢失。

这回答了那个经典问题："上限被临时药水提高后，回满的血量应不应该保留？"
→ modifier 仍在则允许保留；已过期则重新夹取。
⚠ **不要把"上次显示的满血值"写回磁盘**。

## 1. 资源再生与消耗

耐力/饥饿/体温应共享同一个 `ResourceBudget` 模型，但 ⚠ **时间源必须分层**：

| 用途 | 时间源 |
|---|---|
| 真实延时 | `ignore_time_scale = true` |
| 暂停敏感逻辑 | `process_always = false` |
| 持续衰减 | 物理帧累计 |

⚠ **离线时间补算**是可作弊点（改时钟 / 隔天回来补恢复）—— **待核对**，
按项目是否联网、是否允许离线决定。

## 2. ⚠ 死亡是状态机，不是布尔值

**`TRIGGERED → PLAYING → SETTLING → RESPAWNING`**

⚠ 不能让 `_process` 反复触发。

**死亡期间要禁止**：输入、移动、伤害、拾取、**保存**、重生调用。

### 重生：快照→清场→生成→恢复→释放

**该清掉**：临时修饰器、输入缓冲、Tween、Timer、**飞行中的投射物**
**该保留**：永久进度、背包（按设计）

⚠ **最容易漏的四个**：正在播放的 Tween、正在等待的 Timer、
已连接的信号、飞行中的投射物。

⚠ **`create_tween()` 创建的 Tween 并不自动绑定节点** ——
这是"跨场景引用泄漏"的根源。不要把死亡流程里所有等待都丢给匿名 `await`。

## 3. ⚠ 检查点不覆盖手动存档

**检查点只覆盖"重生事实"，不覆盖玩家手动存档。**

⚠ **死亡在状态结算后才提交临时存档**；进入死亡播放期间**禁止保存**，
否则会把"死亡状态"写进稳定存档。

检查点要存的不只是坐标：还要朝向、当前任务状态、已拾取物品、场景状态。
⚠ 重复触发、进入即触发 vs 需要交互，要提前定。

## 4. 负重与背包容量

按重量 / 按格数 / 按件数三种模型。
⚠ 超重的处理要明确（不能动？减速？）—— 超重降移速应走**修饰器**，不要直接改速度。

## 5. 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 有 HealthComponent | **没有**，要自己定义 |
| 2 | 血量上限一个变量够 | 要**四层分开** |
| 3 | 存最终上限省事 | 会**超上限/比例错误**，要存输入 |
| 4 | 临时的血能留着 | modifier 过期要**重新夹取** |
| 5 | 死亡是个 bool | 是**四阶段状态机** |
| 6 | 死了还能存档 | 会把**死亡状态写进去** |
| 7 | 重生重置血量就行 | 还有 **Tween/Timer/信号/投射物** |
| 8 | Tween 会随节点销毁 | **不自动绑定节点** |
| 9 | 死亡等待用 await 随便写 | 会**跨场景泄漏** |
| 10 | 检查点=存档 | 只覆盖**重生事实** |
| 11 | 检查点只存坐标 | 还要朝向/任务/拾取/场景态 |
| 12 | 暂停时饥饿还掉 | 要按**时间源分层**决定 |
| 13 | 离线时间可以补 | 是**可作弊点**，待核对 |
| 14 | 超重直接改速度 | 要走**修饰器** |
| 15 | 耐力耗尽就没了 | 要考虑**力竭惩罚状态** |
| 16 | 死亡期间还能被打 | 要**禁止伤害** |
| 17 | 死亡时能拾取 | 要**禁止拾取** |
| 18 | 修饰器随便加减 | 会**撤销困难/来源泄漏** |

## 6. 待核对项（运行时验证）

⚠ 待核对：离线时间是否补算 · 验证：按项目联网/离线策略与反作弊需求决定

⚠ 待核对：暂停时持续衰减是否继续 · 验证：按玩法测一遍暂停/后台/切场景
