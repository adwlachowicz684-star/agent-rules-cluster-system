# 美术资产管线

"美术给了资源，怎么正确进 Godot"。本文讲**导入设置与工作流**，不是美术技法。

## 0. 2D 纹理：三个开关的真正含义

⚠ **Godot 4 的 Filter / Repeat 在 CanvasItem 属性里设**（不在纹理导入页），
项目设置作为默认；3D 则在逐材质配置。

### Filter —— 控制"非整数像素对应时的插值"，不是画质高低

| | 该用 |
|---|---|
| **Nearest** | 像素美术（必须） |
| **Linear** | 高清 2D、旋转/缩放对象、Tilemap 缩小层 |

⚠ 4.x 默认 CanvasItem 过滤是**双线性**——
精灵缩小、旋转、平移或相机缩放后，纹理像素不再一一对齐屏幕像素，
就会出现半像素、边缘混色、闪烁。**像素项目要在项目设置里关掉默认过滤。**

### Repeat —— 只有需要连续铺开时才开

| 开 | 关 |
|---|---|
| 地面、墙壁、噪声、可滚动背景 | 按钮、头像、图标、立绘、NinePatch |

⚠ **图集资源的 Repeat 判定对象是整个图集纹理**，不是图集内的逻辑区域。
跨边界污染正是图集缝隙、闪烁、莫名边框的来源。

### Mipmap —— "缩小稳定性"开关，不是高清必选项

- 开了：3D 远距离 / 2D 缩小时不颗粒化，性能通常改善
- 代价：**内存 +33%**

### 配置速查表

| 资产类型 | Filter | Repeat | Mipmaps |
|---|---|---|---|
| 像素角色/道具/等比例精灵 | Nearest | 关 | 通常关 |
| 像素 Tilemap | Nearest | 按需 | 通常关 |
| 高清背景、旋转/缩放图层 | Linear | 按需 | 建议开 |
| UI 图标、头像、立绘 | Linear | 关 | 关或测 |
| 可平铺地面/噪声 | 按需 | **开** | 缩小场景建议开 |
| 法线/数据贴图 | 由材质定 | 由材质定 | 按需 |

## 1. 像素美术"糊了"的五个原因（按排查顺序）

⚠ **经典误区**：以为是源 PNG 质量差。其实是五个环节叠加：

1. 项目默认开了线性 Filter
2. 相机/节点缩放不是**整数倍**
3. 相机、Sprite、Control 位置有 **0.5 像素偏移**
4. 窗口整数缩放没开，或逻辑分辨率与窗口不成整数比
5. Mipmap、平滑、抗锯齿或 CanvasGroup 改变了采样

**排查顺序（从简到繁）**：
先确认 Filter → 冻结相机变换、位置取整 → 目标分辨率截图逐像素比对。
**不要一开始就怀疑源 PNG。**

### 源资产纪律（比格式更重要）

- 保留干净边缘，**不使用透明抗锯齿混色**
- 透明像素的颜色**填充邻近可见颜色**（避免采样到黑边）
- 导出 PNG 时不要叠加缩放、锐化、色彩管理、模糊
- 图集切片设置 **extrusion/padding**，防止过滤跨到相邻区域

## 2. 纹理压缩：按用途分层，不是"无损最好"

| 模式 | 适合 |
|---|---|
| **Lossless**（2D 默认） | 像素、UI、含文字/1px 细节、需精确读取的数据纹理 |
| **VRAM Compressed**（3D 默认） | 数量多、尺寸大的照片背景、立绘、3D 纹理 |
| **Lossy** | 磁盘体积敏感、对少量压缩痕迹不敏感的大图 |
| **VRAM Uncompressed** | HDR/float、渲染目标、计算纹理（内存峰值高） |

⚠ **"高清 2D 该开什么"由内存预算决定，不是视觉风格。**

### Basis Universal

⚠ **它是"超压缩交换格式"，不是普通图像压缩**：
先把纹理编码成可在加载时转码成多数 GPU 压缩格式的形式。

| 收益 | 代价 |
|---|---|
| 文件非常小 | 质量**较低**（块状伪影、颜色偏移、法线方向异常） |
| 享受 VRAM 压缩 | **编码时间长**（影响首次导入和 CI） |
| 适合 Web/移动/下载体积敏感 | **加载时要转码**，首次进场景可能更慢 |

⚠ 显存占用并不比普通 GPU 压缩低。
⚠ **不支持浮点图像**（Godot 会内部回退到 VRAM Compressed）。

**不适合**：角色面部、小字号 UI、像素硬边、法线贴图、数据贴图、美术复审阶段。

⚠ **推荐流程**：开发期用 Lossless/VRAM Compressed 快速迭代，
发布前把候选纹理批量转 Basis Universal 做 A/B 验收。

## 3. 图集

**为什么打图集**：减少 draw call。

- `AtlasTexture` / 精灵图集（Godot 内置）
- 外部工具（TexturePacker 等）导入

⚠ 图集内的逻辑切片不适合设 Repeat（见上文）。
⚠ 图集切片要设 padding/extrusion。

## 4. 3D 资产

### 格式

| 格式 | 说明 |
|---|---|
| **glTF（.glb/.gltf）** | **交换首选** |
| FBX / OBJ / Blender(.blend) | 各自取舍 |

⚠ "glTF 是首选"≠"无需检查"——导入后仍要核对材质、缩放、动画。

### 导入设置

- **材质导入模式**：外部材质 vs 内置
- **网格压缩**
- **动画导入**：骨骼、动画剪辑切分
- ⚠ **缩放问题**：FBX 单位不一致是经典坑，导入后先核对尺寸

### PBR 与贴图通道

⚠ **常见错误**：
- **法线贴图绿通道翻转**（DirectX vs OpenGL 约定）
- **sRGB 设错**（颜色贴图要 sRGB，法线/粗糙度/金属度**必须 Linear**）

⚠ 从 Blender/Substance 导出时，AO/Roughness/Metallic 的打包约定要固定下来，
写进项目规范。

### 共享材质

⚠ **共享材质为什么重要**：
自动实例化要求"同 Mesh + 同材质"（见 `render-pipeline.md`）。
给每个实例 clone 一份材质 = 批处理全部失效。

## 5. 资源组织与命名

⚠ **Godot 惯例是 `snake_case`**（文件、节点、变量）。
⚠ **4.4+ 引入 Universal UID** —— 移动/重命名文件不再断开引用（确认当前版本行为）。

建议目录结构：

```
res://
├── art/
│   ├── characters/
│   ├── environment/
│   └── ui/
├── audio/
├── data/           # Resource 数据（技能、关卡配置）
├── scenes/
└── scripts/
```

⚠ 命名规范要**写进项目文档**并让美术遵守，
否则后期整理成本极高。

## 6. 音频资产

| 格式 | 取舍 |
|---|---|
| **WAV** | 无压缩无延迟、体积大 —— **短音效** |
| **OGG** | 有压缩、需解码 —— **BGM 与长音频** |
| **MP3** | 许可与循环点不友好，一般不选 |

⚠ **循环 BGM 用 OGG 要注意循环点**；MP3 几乎无法无缝循环。
⚠ 短音效用 WAV —— OGG 的解码延迟会让密集触发的音效迟到。
⚠ **采样率要统一**，混用会出问题。

⚠ **FMOD / Wwise**：Godot 没有官方一级集成（确认现状）。
要用的话是社区绑定，维护状态需现查。

## 7. 字体（中文游戏是硬需求）

⚠ **中文字符集巨大**，字体文件会非常大 —— 必须做**子集化**（只保留用到的字）。

- **MSDF**：缩放不模糊，适合会缩放的文本
  （项目设置 `gui/theme/default_font_multichannel_signed_distance_field`，
  或 DynamicFont 导入选项里开）
- 系统字体：`SystemFont.multichannel_signed_distance_field`

⚠ **不开启 MSDF 时缩放会模糊/像素化**（尤其位图字体与非 MSDF 动态字体）。

⚠ 4.7 起 `ResourceImporterDynamicFont.hinting` 默认从 1 变 3 ——
升级后字体渲染会变（见 `version-47-48.md`）。

## 8. 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Filter 在纹理导入页设 | 4.x 在 **CanvasItem 属性**，项目设置是默认 |
| 2 | 像素糊是 PNG 质量差 | 五个环节叠加，先查 Filter 和整数缩放 |
| 3 | Repeat 开了更省事 | UI/图标开了会采样到相邻像素 |
| 4 | Mipmap 是画质选项 | 是"缩小稳定性"，代价内存 +33% |
| 5 | 图集内切片能单独设 Repeat | 判定对象是**整个图集纹理** |
| 6 | 无损压缩最好 | 按用途分层，显存和加载时间也要算 |
| 7 | Basis Universal 万能 | 质量差、编码慢、加载要转码 |
| 8 | Basis 显存更低 | 与 VRAM Compressed 相近 |
| 9 | glTF 导入就不用检查 | 材质、缩放、动画仍要核对 |
| 10 | 材质 clone 一下没关系 | 破坏批处理（自动实例化要求同材质） |
| 11 | 法线贴图当颜色导入 | sRGB 设错，法线/粗糙度/金属度必须 **Linear** |
| 12 | 音频都用 OGG 省体积 | 短音效解码延迟会迟到 |
| 13 | 中文字体直接塞进去 | 必须**子集化**，否则包体爆炸 |
| 14 | 字体缩放糊了没办法 | 开 **MSDF** |
| 15 | FMOD/Wwise 有官方支持 | **没有**一级集成，社区绑定维护状态现查 |
