# 01 伴侣物模型与三层地基（伴侣物域）

> **本步交付**：三层模型 + 归属字段 + 服务端权威口径
> **对应**：流程 `howto/godot/companion.md` · 审核 `audit/godot/companion.md`

## 0. 交付物定义

1. 模板 / 实例 / 节点三层已定义，且**逐层写下不应混入什么**
2. 归属字段（主人 + 忠诚度 + 亲密度 + 出战位）已存在
3. 所有冷却与到期存的是**绝对时间戳**，不是 Timer / 剩余秒数
4. 死亡与复活是**状态机态**，不与背包数据耦合
5. 离线衰减的补算与封顶口径已确立，且用服务端时间戳

## 1. 前置检查清单

- [ ] 能用一句话说清三层各自职责与禁止字段
- [ ] 归属字段已存在，⛔ 不是"只有持有者 ID"
- [ ] 冷却存的是绝对时间戳
- [ ] 死亡态在状态机里，不在背包数据里
- [ ] 离线衰减有封顶，且时间源来自服务端

## 2. 工序

### Step 1　宠物不是会动的装备，先写三层各自的禁止项　`[companion/01#S1]`

【读】`howto/godot/companion.md#0. 第一个要纠正的抽象`

【做】
定义 `SpeciesTemplate`（只读共享：物种属性、成长率、进化链）、
`CompanionInstance`（每宠唯一：等级、经验、忠诚度、饱食度、出战位）、
`CompanionNode`（活体：状态机 + 动画 + 技能）三层，并**逐层写下不应混入什么**。
⛔ 当成装备处理 —— AI 无处安放、死亡状态与背包数据耦合、
多人同步时动画没处同步，表现为"宠物能召唤但一动不动"，且不报错。

ⓘ 三层分开的收益在审计时才显现：出问题时能直接问
"是模板错了、实例错了、还是节点错了"，⛔ 混成一层就只能全量排查。

【产出】三层数据结构定义（含各层禁止字段清单）

【判据】指着任意字段能说出它属于哪一层；⛔ 没有字段跨层重复出现。

【审】`audit/godot/companion.md#1`、`audit/godot/companion.md#2`

### Step 2　共享模板不能改：个体数据必须 duplicate 或 local_to_scene　`[companion/01#S2]`

【读】`howto/godot/companion.md#0. 第一个要纠正的抽象`

【做】
明确 `SpeciesTemplate` 是**共享 Resource**，个体数据用 `duplicate()` 或
`resource_local_to_scene` 分离。
⛔ 直接改模板 —— 改一只**影响所有同类宠物**，
表现为"给 A 宠物升级，全服同类宠物一起升级"，
⛔ 而排查时必然被引向"升级逻辑写错了"，因为每一处单看都对。

ⓘ 这与装备模板不能内嵌存档是同一个坑（见 `economy` 域）；
⛔ 区别在于宠物还要额外带一份**运行时状态**（饱食度会变），
所以它比装备更容易被误改。

【产出】模板只读公约 + 个体数据的复制口径

【判据】改一只宠物的属性，同类其他宠物**画面上不变**。

【审】`audit/godot/companion.md#3`

### Step 3　冷却与到期存绝对时间戳，⛔ 不用 Timer　`[companion/01#S3]`

【读】`howto/godot/companion.md#状态机必须显式`

【做】
复活冷却、孵化计时、进化倒计时全部存**绝对时间戳**（`cooldown_until`），
登录时用时间差判断。
⛔ 用 `Timer` 或"剩余秒数" —— 退出进程就丢，
表现为"重开游戏冷却归零"或"读档后又要等一遍"，
⛔ 而这类 bug 在单次游玩内**完全测不出来**。

ⓘ 这与孵化计时、生产队列是同一条规则（见 `time-progression` 篇）；
⛔ 本域额外要求：时间戳由**服务端下发**，不用客户端系统时钟。

【产出】时间戳字段清单 + 登录时的补算流程

【判据】杀掉进程再进，冷却剩余时间与退出前一致。

【审】`audit/godot/companion.md#4`

### Step 4　死亡与复活是状态机态，⛔ 不能只改动画　`[companion/01#S4]`

【读】`howto/godot/companion.md#状态机必须显式`

【做】
把 `Dead` 与复活冷却做成**显式状态机态**，与背包里的持有数据分离。
⛔ 只改动画、状态仍在 `Follow` —— 死亡宠物继续索敌与移动，
表现为"尸体在追人"，而动画确实播的是死亡动画，⛔ 两边日志都自洽。

ⓘ 反向也成立：复活后若从背包数据重建等级，会丢掉死亡前的忠诚度与饱食度，
表现为"复活后宠物不认主人"，排查被引向忠诚度系统。

【产出】状态机定义（含 Dead / 复活冷却的进入与退出条件）

【判据】死亡宠物不索敌不移动；复活后忠诚度与饱食度与死亡前一致。

【审】`audit/godot/companion.md#32`

### Step 5　离线衰减要补算、要封顶、且用服务端时间戳　`[companion/01#S5]`

【读】`howto/godot/companion.md#饱食度与忠诚度的离线衰减`

【做】
登录时按时间差补算饱食度与忠诚度，**并封顶**。
⛔ 不补算 —— 上线后忠诚度**断崖式下降**，玩家感知是"没玩就掉光了"。
⛔ 补算不封顶 —— 等于惩罚长时间离线，会让玩家**不敢下线**。

ⓘ 时间源必须用**服务端下发的时间戳**：客户端系统时钟可被玩家设置
（与 `vip` / `monetization` 域同源的禁令）。
⛔ 用本地时钟的表现是"改系统时间就能刷饱食度"，且不报错。

【产出】补算公式 + 封顶时长 + 服务端时间戳字段

【判据】改客户端系统时间后重登，衰减量与真实流逝一致。

【审】`audit/godot/companion.md#6`、`audit/godot/companion.md#42`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：三层分离 + 绝对时间戳 + 服务端时间源
class_name SpeciesTemplate extends Resource
# ⛔ 不混入：个体等级、忠诚度、当前出战位、运行时节点引用
@export var species_id: StringName
@export var growth_rate: float
@export var evolve_chain: Array[StringName]

class_name CompanionInstance extends Resource
# ⛔ 不混入：网格 / 动画 / 场景节点本体
@export var instance_id: StringName
@export var species_id: StringName
@export var owner_id: int
@export var loyalty: float
@export var satiety: float
@export var cooldown_until: int      # ⛔ 绝对时间戳，不是剩余秒数
@export var battle_slot: int

class_name CompanionNode extends CharacterBody3D
# ⛔ 不混入：存档读写、经济结算
enum S { IDLE, FOLLOW, COMBAT, DEAD, RETURN, STUNNED }
@export var state: S = S.IDLE
```

ⓘ 补算用的 `now` 由服务端下发（`server_now`），
⛔ 不取 `Time.get_unix_time_from_system()`。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 宠物召唤出来一动不动 | 当成装备，AI 无处安放 | S1 |
| 给一只升级全服同类一起升 | 改了共享模板 | S2 |
| 重开游戏冷却归零 | 用 Timer / 剩余秒数 | S3 |
| 尸体在追人 | 死亡只改了动画 | S4 |
| 长时间离线回来忠诚度掉光 | 补算没封顶或用本地时钟 | S5 |
