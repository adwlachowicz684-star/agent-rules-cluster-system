# 04 召唤物：数量分层与对象池（伴侣物域）

> **本步交付**：四层渲染选型 + 服务端强制上限 + 池化契约
> **对应**：流程 `howto/godot/companion.md` · 审核 `audit/godot/companion.md`

## 0. 交付物定义

1. 按数量分了层（重型 / 中型 / 轻型 / 超轻型），每层对应确定的渲染与 AI 方案
2. 需要动画的召唤物已按"是否要混合"再分一层，⛔ 不是简单二分
3. 数量上限由**服务端强制**，`spawn_limit` 没被当成权威上限
4. 对象池的 `acquire()` 返回值调用方必检，复用必 `_reset()`
5. 池与 `MultiplayerSpawner` 的语义冲突已按官方 `spawn_function` 口径处理

## 1. 前置检查清单

- [ ] 每种召唤物都能说清它属于哪一层
- [ ] 上限是服务端判的，不是只设了 `spawn_limit`
- [ ] `acquire()` 返回 null 时调用方有处理
- [ ] 复用时清了 `NavigationAgent` 的残留路径
- [ ] `spawn_function` 返回的节点不在场景树中

## 2. 工序

### Step 1　先按数量分层，⛔ 别每个召唤物一个节点　`[companion/04#S1]`

【读】`howto/godot/companion.md#3. 召唤物：数量是性能死穴`

【做】
按预期数量先把召唤物分到四层，每层定死渲染与 AI 方案：
重型（1–3 个，独立节点 + 独立状态机）、中型（4–16，独立节点 + 简化 FSM）、
轻型（16–100，MultiMesh / GPUParticles，无 AI）、超轻型（100+，RenderingServer 直绘，纯数据）。
⛔ 每个召唤物都做成独立节点 —— 独立的 `_physics_process`、
独立的碰撞注册、独立的 draw call、独立的 `AnimationPlayer`，**50+ 个时线性叠加**。

⛔ 先写完"每个一个带 AI 的节点"再改分层，等于**整块重写** ——
这是本域最容易一次性浪费掉的工作。

【产出】召唤物分层表（数量区间 ↔ 渲染方案 ↔ AI 方案）

【判据】指着任一召唤物能说出它属于哪一层、为什么。

【审】`audit/godot/companion.md#13`

### Step 2　需要动画的召唤物要按"是否要混合"再分一层　`[companion/04#S2]`

【读】`howto/godot/companion.md#3. 召唤物：数量是性能死穴`

【做】
`MultiMesh` 不支持骨骼动画（每个实例无独立动画状态）。
需要动画的召唤物要么留在独立节点层，要么走 **VAT**（把动画烘进顶点/法线贴图，
用 `INSTANCE_CUSTOM` 传每实例的动画索引与帧号，在 `vertex()` 里手工采样）。
⛔ 简单二分成"要动画的用节点、不要的用 MultiMesh" ——
忽略了 VAT 这条中间路径，会把本可以合批的中型召唤物全做成独立节点。

ⓘ VAT 的代价是**失去动画混合与 IK**，
⛔ 所以判据不是"要不要动画"，是"**要不要混合**"。

【产出】动画方案选型表（独立节点 / VAT / 无动画）

【判据】每个需要动画的召唤物都明确写了是否要混合。

【审】`audit/godot/companion.md#14`、`audit/godot/companion.md#31`

### Step 3　上限由服务端强制，⛔ 别把 spawn_limit 当权威　`[companion/04#S3]`

【读】`howto/godot/companion.md#5. 服务端权威边界`

【做】
召唤物数量上限在**服务端**判定与计数。
`MultiplayerSpawner.spawn_limit` 是官方内置上限（默认 `0` 表示无限制），
但它是**客户端侧的复制上限**，
⛔ 改包即可绕过 —— 服务端仍必须自己数。

ⓘ 计数口径也有坑：要查"**存活 + 正在创建**"的总数。
⛔ 只查存活数 —— 创建瞬时超限，
表现为"明明设了 20 个上限，实测能出 23 个"。

【产出】服务端计数口径（含正在创建的占位）+ `spawn_limit` 的辅助定位说明

【判据】改包把客户端上限改成 999，服务端仍拦在设定值。

【审】`audit/godot/companion.md#15`、`audit/godot/companion.md#29`、`audit/godot/companion.md#40`

### Step 4　对象池：acquire 返回值必检，复用必 reset　`[companion/04#S4]`

【读】`howto/godot/companion.md#对象池`

【做】
`acquire()` 在池耗尽时返回 `null`，**调用方必须检查**；
复用时必须 `_reset()` 清干净状态。
⛔ 不检查返回值 —— 空引用错误，且只在**峰值并发**时出现。
⛔ 不清状态 —— 新召唤物以**上一只的速度飞出去**，
表现为"召唤物偶尔暴冲"，⛔ 而复现概率与池的复用时机相关，极难稳定复现。

ⓘ 池中节点永不被 `queue_free()`（`queue_free` 与池混用会留下野指针）。
⛔ 复用时还要清 `NavigationAgent` 的残留路径，
否则新召唤物沿**上一只的路径**跑。

【产出】`acquire()` / `release()` 实现 + `_reset()` 的清理项清单

【判据】池耗尽时返回 null 且调用方有处理；复用后不暴冲、不沿旧路径。

【审】`audit/godot/companion.md#16`、`audit/godot/companion.md#37`

### Step 5　池与 MultiplayerSpawner 的语义冲突按官方口径解　`[companion/04#S5]`

【读】`howto/godot/companion.md#对象池`

【做】
`MultiplayerSpawner` 期望 `instantiate()` / `queue_free()`，与池的 show/hide 语义冲突。
按官方口径解：**用 `spawn_function` 从池里取节点返回**。
⛔ 但要满足两条官方约束：
1. 返回的节点**必须不在场景树中** —— 池化的"留在树里隐藏"要改成"先移出树再返回"；
2. ⛔ **不要自己 `add_child()`**，引擎会自动加。

⛔ 不满足第 1 条 → 重复挂载；不满足第 2 条 → 客户端看到**幽灵节点**。

ⓘ 另：池子只在服务端维护，客户端通过同步属性控制可见性，
⛔ 客户端也维护一份池，两端计数不一致会更难查。

【产出】`spawn_function` 的取池实现 + 客户端可见性同步口径

【判据】多端召唤物数量与位置一致，客户端无幽灵节点。

【审】`audit/godot/companion.md#18`、`audit/godot/companion.md#30`、`audit/godot/companion.md#36`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：分层 + 服务端计数 + 池化契约 + spawn_function
# MAX_SUMMONS 见 00 参数登记，待实测；⛔ spawn_limit 只是客户端复制上限
var _alive: int = 0
var _pending: int = 0    # ⛔ 正在创建的也要计入，否则创建瞬时超限

func can_summon() -> bool:
    return _alive + _pending < MAX_SUMMONS

func acquire(scene_path: String) -> SummonNode:
    var pool: Array = _pools.get(scene_path, [])
    if pool.is_empty():
        push_error("Pool exhausted: %s" % scene_path)
        return null          # ⛔ 调用方必须检查返回值
    var n := pool.pop_back() as SummonNode
    n.visible = true
    n.set_physics_process(true)
    n._reset()               # ⛔ 不清状态会让新召唤物以旧速度飞出去
    return n

# ⛔ 官方要求：返回"不在场景树中的 Node"，且不要自己 add_child
func _spawn_from_pool(data: Variant) -> Node:
    var n := acquire(String(data))
    if n.get_parent():
        n.get_parent().remove_child(n)   # 先移出树，⛔ 否则重复挂载
    return n
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 50+ 个召唤物帧率暴跌 | 全是独立节点 | S1 |
| 该合批的中型全做成节点 | 漏了 VAT 中间路径 | S2 |
| 实测数量超过上限 | 只查存活没算正在创建 | S3 |
| 召唤物偶尔暴冲 | 复用没清状态 | S4 |
| 客户端看到幽灵节点 | 返回了在树中的节点 / 自己 add_child | S5 |
