# 02 宠物状态机与 AI 协同（伴侣物域）

> **本步交付**：显式状态机 + 主人优先级 + 索敌分配 + 跟随槽位
> **对应**：流程 `howto/godot/companion.md` · 审核 `audit/godot/companion.md`

## 0. 交付物定义

1. 状态机显式（Idle / Follow / Combat / Dead / Return / Stunned）
2. 主人优先级**高于**宠物，过场与强制移动期间宠物进 `Return`
3. 多宠索敌有分区或优先级分配，⛔ 不集火同一目标
4. 跟随有偏移槽位，⛔ 不直接追主人目标点
5. 与 `ai` 域的寻路接缝已指认到具体符号

## 1. 前置检查清单

- [ ] 状态机是显式枚举，不是一串 bool
- [ ] 主人强制移动时宠物会退出追击
- [ ] 多宠同屏时不会全部打同一个目标
- [ ] 跟随有槽位偏移与互相避让
- [ ] 寻路走 `NavigationAgent3D`，与 `ai` 域口径一致

## 2. 工序

### Step 1　状态机必须显式，⛔ 不用一串 bool　`[companion/02#S1]`

【读】`howto/godot/companion.md#状态机必须显式`

【做】
把状态写成**显式枚举**（`IDLE / FOLLOW / COMBAT / DEAD / RETURN / STUNNED`），
并定义每个态的进入 / 退出条件。
⛔ 用一串 bool（`is_following` / `is_attacking` / `is_dead`） ——
组合出 `is_dead and is_attacking` 这种**本不该存在**的状态，
表现为"尸体在追人""死亡宠物还能被治疗"，
⛔ 而排查时每个 bool 单看都是被正确设置的。

ⓘ 显式枚举的收益在加新态时才显现：加 `STUNNED` 时编译器会指出所有未处理的分支，
⛔ bool 组合不会。

【产出】状态枚举 + 状态转移表（含每个态的进入/退出条件）

【判据】不存在任何"死亡中仍在攻击"的组合态。

【审】`audit/godot/companion.md#32`

### Step 2　主人优先级高于宠物　`[companion/02#S2]`

【读】`howto/godot/companion.md#AI 协同`

【做】
确立：**主人的强制移动与过场动画期间，宠物进入 `Return` 而非继续追击**。
⛔ 宠物与主人同等优先级 —— 过场镜头里宠物追进来，
表现为"宠物穿进过场镜头""过场结束宠物卡在墙里"，
⛔ 而过场本身一切正常，排查被引向过场系统。

ⓘ 判据很直接：**过场期间宠物应该在镜头外或处于 Return**，
⛔ 只要它在镜头里，就是优先级没排对。

【产出】优先级表（主人强制移动 / 过场 / 传送 / 死亡 各自对应宠物态）

【判据】过场播放时宠物不在镜头内，过场结束后能自行归位。

【审】`audit/godot/companion.md#34`

### Step 3　多宠索敌要分区或优先级分配　`[companion/02#S3]`

【读】`howto/godot/companion.md#AI 协同`

【做】
给多宠做索敌分区（按空间或按目标索引分配）或优先级分配。
⛔ 多宠各自独立索敌 —— **集火同一目标**，
三只宠物永远打同一个敌人，玩家感知是"**AI 很蠢**"，
⛔ 而每一只的索敌逻辑单看都完全正确（都选了最近目标）。

ⓘ 这条在正常测试中极难发现：单宠时表现完美，
⛔ 只有出战位开放到 2 个以上才暴露，
而那时玩家已经形成了"宠物很蠢"的印象。

【产出】索敌分配策略（分区规则或优先级表）+ 分配结果的可观测日志

【判据】三只宠物出战时打的是三个不同目标。

【审】`audit/godot/companion.md#5`

### Step 4　跟随要有偏移槽位，⛔ 不直接追主人目标点　`[companion/02#S4]`

【读】`howto/godot/companion.md#AI 协同`

【做】
给每只宠物分配**跟随槽位**（主人周围的偏移点），并加互相避让。
⛔ 直接追主人 `global_position` —— 多宠**叠在主人身上**且互相挤压，
表现为"宠物挤成一坨""主人被宠物推着走"，
⛔ 而单宠时表现完美（单宠不存在挤压）。

ⓘ 避让优先级要低于主人但高于其他宠物：
两只宠物相遇时应该让路，⛔ 不能互相卡住形成僵局。

【产出】槽位分配算法 + 避让优先级定义

【判据】三只宠物跟随时不重叠、不推挤主人。

【审】`audit/godot/companion.md#33`

### Step 5　寻路与 `ai` 域对齐，⛔ 不自造一套　`[companion/02#S5]`

【读】`howto/godot/companion.md#AI 协同`

【做】
宠物的移动与避障走 `NavigationAgent3D`，与 `ai` 域同一套口径。
⛔ 自造一套简化的"朝目标直线走" ——
过不了坎、卡在墙角、上下台阶抖动，
⛔ 而在平坦测试场景里表现完美，于是问题到关卡铺开后才成片出现。

ⓘ 复用 `ai` 域的另一半收益：池化复用宠物节点时，
`NavigationAgent3D` 的**残留路径**要一并清（见 04），
⛔ 自造的那套没有这个约定，反而更容易漏。

【产出】宠物与 `ai` 域的寻路接口契约（含复用时的重置项）

【判据】宠物能绕过障碍到达主人身边；复用后不沿旧路径跑。

【审】`audit/godot/companion.md#33`、`audit/godot/companion.md#37`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：显式状态机 + 主人优先级 + 槽位偏移
enum S { IDLE, FOLLOW, COMBAT, DEAD, RETURN, STUNNED }
# ⛔ 不用一串 bool 代替，避免"死亡中仍攻击"的组合态

# 主人强制移动 / 过场期间，宠物一律进 RETURN，⛔ 不继续追击
func on_owner_forced_move() -> void:
    if state != S.DEAD:
        state = S.RETURN

# 跟随槽位：⛔ 不直接追主人 global_position（多宠会叠在一起）
# FOLLOW_SLOT_RADIUS / TARGET_ASSIGN_RADIUS 见 00 参数登记，待实测
func slot_position(owner_pos: Vector3, idx: int, count: int) -> Vector3:
    var angle := TAU * float(idx) / float(maxi(count, 1))
    return owner_pos + Vector3(cos(angle), 0.0, sin(angle)) * FOLLOW_SLOT_RADIUS
```
