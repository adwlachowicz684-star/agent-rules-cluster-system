# 07 伴侣物验收（伴侣物域）

> **本步交付**：敌意环境实测通过 + 改包与改时钟实测通过
> **对应**：流程 `howto/godot/companion.md` · 审核 `audit/godot/companion.md`

## 0. 交付物定义

1. 强杀进程重连后状态正确（⛔ 不是"点退出再登录"）
2. 改包伪造（满级 / 突破上限 / 改坐标上马）被服务端拒绝
3. 召唤物在数量上限附近压测通过
4. 上下马与飞行模式在真机实测通过
5. 改客户端系统时间不影响离线衰减
6. 对象池耗尽与复用后行为正确

## 2. 工序

### Step 1　强杀进程重连，⛔ 不是点退出再登录　`[companion/07#S1]`

【读】`howto/godot/companion.md#状态机必须显式`

【做】
实测**强杀进程**后重连：冷却剩余、孵化进度、出战位、忠诚度是否正确。
⛔ 只测"点退出再登录" —— 那是**两条不同的代码路径**，
强杀走的是超时判定与服务端补算，点退出走的是正常登出。

ⓘ 本域尤其要测孵化：结果若只在内存里，重连会重 roll，
⛔ 表现为"重连一次就换一个稀有度"，而每次单看都是"正常随机"。

【产出】强杀重连的状态对照记录（含冷却、孵化、出战位、忠诚度）

【判据】强杀前后各状态完全一致，孵化结果不变。

【审】`audit/godot/companion.md#38`、`audit/godot/companion.md#4`

### Step 2　改包伪造必须被服务端拒绝　`[companion/07#S2]`

【读】`howto/godot/companion.md#5. 服务端权威边界`

【做】
构造三类伪造：宠物改满级、召唤物突破上限、改坐标瞬移上马，验证服务端全部拒绝。
⛔ 只测正常路径 —— 伴侣物的伪造**在正常流程里永远测不出来**，
因为它只在有人主动改包时才触发，⛔ 而测试环境下没人会改包。

ⓘ `spawn_limit` 那条尤其要单独验：
⛔ 设了它不等于服务端有上限，改包绕过它才是真实场景。

【产出】三类伪造用例 + 服务端拒绝记录

【判据】三类全部被拒，且客户端回退无中间态。

【审】`audit/godot/companion.md#43`、`audit/godot/companion.md#29`、`audit/godot/companion.md#44`

### Step 3　召唤物在数量上限附近压测　`[companion/07#S3]`

【读】`howto/godot/companion.md#3. 召唤物：数量是性能死穴`

【做】
在上限值附近连续创建/销毁（含快速连点与正在创建时再次请求）。
⛔ 只测"创建 10 个再删掉" —— 超限**只在临界点**出现，
表现为"明明设了 20，偶尔能出 23"。

ⓘ 同时记录帧率：分层选型对不对，只有在这个量级下才看得出来，
⛔ 编辑器里 10 个召唤物的帧率说明不了任何问题。

【产出】压测记录（实际数量峰值、帧率、拒绝次数）

【判据】任何时刻实际数量不超过设定值。

【审】`audit/godot/companion.md#15`、`audit/godot/companion.md#40`

### Step 4　上下马与飞行模式真机实测　`[companion/07#S4]`

【读】`howto/godot/companion.md#reparent 的三个坑`

【做】
实测：连续上下马 20 次、斜坡/墙角/水面下马、飞行坐骑落地。
⛔ 只在平坦地面测一次 —— 穿模与卡墙**全部只在复杂地形出现**，
而平坦地面上一切正常。

ⓘ 飞行模式那条要单独看落地产物：
⛔ 若飞行坐骑永远判不到落地，说明沿用了 `is_on_floor()`（FLOATING 模式下恒 false）。

【产出】真机实测记录（含穿模、卡墙、拖影、落地失败的次数）

【判据】20 次上下马无穿模、无卡墙、无拖影；飞行坐骑能落地。

【审】`audit/godot/companion.md#10`、`audit/godot/companion.md#11`、`audit/godot/companion.md#28`

### Step 5　改客户端系统时间不影响衰减　`[companion/07#S5]`

【读】`howto/godot/companion.md#饱食度与忠诚度的离线衰减`

【做】
把客户端系统时间往前/往后调，重登后验证饱食度与忠诚度衰减与真实流逝一致。
⛔ 用客户端系统时钟 —— 玩家改时间就能刷饱食度或让冷却瞬间结束，
⛔ 而服务端日志里一切正常，因为它信任了客户端上报的时间。

ⓘ 这条与 `vip` / `monetization` 域同源：
⛔ 凡是"到期"相关的判定，时间源都必须来自服务端。

【产出】改时间前后的衰减量对照

【判据】改时间不影响任何衰减与到期结果。

【审】`audit/godot/companion.md#42`、`audit/godot/companion.md#6`

### Step 6　池耗尽与复用后行为正确　`[companion/07#S6]`

【读】`howto/godot/companion.md#对象池`

【做】
把池压到耗尽，验证 `acquire()` 返回 null 且调用方不崩；
再验证复用后的召唤物速度、路径、动画都回到初始值。
⛔ 只测"正常召唤几次" —— 池耗尽只在**峰值并发**出现，
⛔ 而复用污染的表现是"偶尔暴冲""偶尔沿旧路径跑"，极难稳定复现。

【产出】池耗尽与复用的实测记录（含速度、路径、动画三项）

【判据】耗尽时不崩；复用后无暴冲、无旧路径、动画回到首帧。

【审】`audit/godot/companion.md#16`、`audit/godot/companion.md#37`

## 3. 验收清单

- [ ] 强杀重连状态一致、孵化结果不变
- [ ] 三类伪造全部被拒
- [ ] 上限附近压测不越界
- [ ] 20 次上下马无穿模卡墙；飞行能落地
- [ ] 改系统时间不影响衰减
- [ ] 池耗尽不崩；复用后状态干净

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 重连一次换一个稀有度 | 结果没落库 | S1 |
| 有人满级 / 突破上限 | 只测正常路径 | S2 |
| 上限设 20 实测 23 | 只测远离临界点 | S3 |
| 上下马穿模卡墙 | 只测平坦地面 | S4 |
| 改时间能刷饱食度 | 用客户端时钟 | S5 |
| 召唤物偶尔暴冲 | 复用没清状态 | S6 |
