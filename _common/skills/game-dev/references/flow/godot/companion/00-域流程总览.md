# 宠物 / 坐骑 / 召唤物 / 孵化合成 —— 域流程总览

> ⚠ **第 0 步：先定"谁驱动移动、谁判定状态"。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 跟随宠物 / 战宠 | 01 → 02 → 06 → 07 |
| 坐骑 / 骑乘 | 01 → 03 → 06 → 07 |
| 召唤物 / 随从 | 01 → 04 → 06 → 07 |
| 孵化 / 合成台 | 01 → 05 → 06 → 07 |
| 全套伴侣物系统 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过** ——
宠物、坐骑、召唤物技术形态差异很大（活体节点 / 移动驱动权 / 批量节点），
但**生命周期与归属**高度相似。⛔ 不先统一成模板 / 实例 / 节点三层，
就会写出三套互斥逻辑，表现为"宠物能出战、坐骑莫名消失"，
而排查时每一套单看都合理。

⛔ **03 的核心不是"把角色贴到坐骑上"，是移动驱动权的转移**：
先做表现后定驱动权，会在上下马、过场、断线重连时成片返工。

⛔ **05 不能等 UI 做完再补**：孵化结果在"领取时"才随机 = 可反复读档刷稀有度。
⛔ 这是发版后靠补日志无法定位的漏洞 —— 日志里每一次都是"正常随机"。

ⓘ 若本次只是**"加一个新宠物模型、配一张属性表"**，那是资源配置，不套本域。
ⓘ 若只是**排查宠物不动**，先看 `ai` 域定位是寻路问题还是状态机问题，再回本域 02。

ⓘ 分工：
- `howto/godot/companion.md` 讲**各形态的技术做法**（状态机、reparent、对象池、孵化时序）
- `howto/godot/cosmetic.md` 讲**坐骑皮肤等外观资产层**
- 本域讲**这些形态按什么顺序做、怎么保证换场景换版本后仍然对**

⛔ 若本域某步需要"同屏召唤物上限""跟随距离"这类细节，
指向项目实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 伴侣物模型与三层地基 | — | 三层模型 + 归属字段 + 服务端权威口径 |
| 02 | 宠物状态机与 AI 协同 | 01 | 显式状态机 + 主人优先级 + 索敌分配 |
| 03 | 坐骑：移动驱动权转移 | 01 | 单一驱动口径 + reparent 时序 + 碰撞层与下马检测 |
| 04 | 召唤物：数量分层与对象池 | 01 | 四层渲染选型 + 服务端强制上限 + 池化契约 |
| 05 | 孵化合成与随机结果落库 | 01 | 开始时 roll 并落库 + 扣材料时序 + 并发串行 |
| 06 | 服务端权威与多人同步 | 01, 02, 03, 04 | 权威边界清单 + 两阶段确认 + 归属清理 |
| 07 | 伴侣物验收 | 全部 | 敌意环境实测 + 改包与改时钟实测 |

⚠ **01 必须在美术铺开之前**：那时宠物 / 坐骑 / 召唤物已各按各的规范做完，
统一模型意味着三套数据各改一次。

⚠ **04 的数量分层要在第一个召唤物做出来之前**：
分层决定渲染与 AI 方案（独立节点 / MultiMesh / RenderingServer 直绘），
⛔ 先写完"每个召唤物一个带 AI 的节点"再改分层，等于整块重写。

⚠ **06 的权威边界要随功能点同步写，不能最后统一补**：
补的时候会顺手把"客户端预测"也划进权威，表现为"手感变钝"但没人敢改回去。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是单个宠物，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `ai` 域 敌人 AI | 行为与寻路见 `ai`，⛔ 本域只定**主人优先级高于宠物**与索敌分配 |
| `netsync` 域 网络同步 | 传输与 authority 机制见 `netsync`，⛔ 本域定同步**内容**（骑手与坐骑是两个实体） |
| `economy` 域 经济 | 孵化/合成的材料与产出走同一账本见 `economy`，⛔ 本域不另定货币口径 |
| `cosmetic` 域 外观 | 坐骑皮肤与外观资产见 `cosmetic`，⛔ 本域只定坐骑**驱动**不定义外观 |
| `security` 域 安全 | 改包伪造宠物等级的检测见 `security`，⛔ 本域只定权威边界清单 |
| `perf` 域 性能 | 同屏召唤物的帧预算见 `perf`，⛔ 本域只定分层选型，不编数量 |
| `mobile` 域 移动端 | 移动端召唤物数量与内存预算见 `mobile`，⛔ 本域不另定移动端口径 |
| `save` 域 存档 | 伴侣实例的持久化见 `save`，⛔ 本域只定"结果必须落库" |
| `physics` 域 物理 | 物理插值与 `reset_physics_interpolation` 见 `physics`，⛔ 本域只在 reparent 处引用该口径 |
| `boids-swarm` | ⓘ howto 层，暂无 flow 域 —— 群集与避障见该篇 |
| `time-progression` | ⓘ howto 层，暂无 flow 域 —— 离线结算与封顶原则见该篇 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `FOLLOW_SLOT_RADIUS` 跟随槽位半径 | 02 | — | — | 待实测（与宠物体型与主人碰撞半径相关） |
| `TARGET_ASSIGN_RADIUS` 索敌分区半径 | 02 | — | — | 待实测（与同屏敌人数相关） |
| `MOUNT_SNAP_DISTANCE` 上马吸附距离 | 03 | — | — | 待实测（与坐骑体型相关） |
| `DISMOUNT_CLEARANCE` 下马安全间距 | 03 | — | — | 待实测（与骑手碰撞半径相关） |
| `MAX_SUMMONS` 召唤物上限 | 04 | — | — | 待实测（与同屏人数和帧预算相关） |
| 孵化/合成各稀有度权重 | 05 | — | — | 待实测（⛔ 概率公示口径不由本域决定） |
| 离线衰减速率与封顶时长 | 01 | — | — | 待实测（⛔ 封顶太短等于惩罚下线） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发穿模""偶发超限""偶发回退"，
⛔ 而这类偶发在测试环境几乎不出现。
