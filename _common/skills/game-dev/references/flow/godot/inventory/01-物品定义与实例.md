# 01 物品定义与实例（背包与物品域）

> **前置**：已定死"装什么"（见 `00-域流程总览.md` 第 0 节）
> **本步交付**：`ItemDefinition`（共享、不可变）与 `ItemInstance`（唯一 id、可变）两层分离
> **对应**：做法 `howto/godot/game-systems.md` `economy.md` · 审核 `audit/godot/game-systems.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 新建两种物品（可堆叠的药水、不可堆叠的剑），Inspector 里能改属性
2. 生成两个同 def 的实例，**它们的 `instance_id` 不同**，各自改耐久互不影响
3. ⚠ 改 `ItemDefinition` 的数值，所有同类实例**同时**变化（证明是共享模板）
4. 实例 id 从存档回读后**不冲突**

**产出物**（下游按名字对接）：

```text
ItemDefinition (Resource)   id / name_key / icon / item_type / max_stack / is_unique / tags
ItemInstance (RefCounted)   instance_id / def_id / durability / custom_data
Inventory._new_instance(def_id) -> ItemInstance
```

⚠ `instance_id` 的生成规则是本步最关键的产出——02 的槽位只存这个 id，
05 的存档靠它把 slots 和 instances 对上。

## 1. 前置检查清单

- [ ] ⚠ 已确认**模板/实例两层分离**（⛔ 不做分离，后面每次移动都在复制数据）
- [ ] 已确定物品类型枚举（至少区分消耗品/材料/装备/任务物品）

## 2. 工序

### Step 1　定义 ItemDefinition（共享、不可变）　`[inventory/01#S1]`

【读】`howto/godot/game-systems.md#三、库存系统` 与 `#四层`

【做】
```gdscript
class_name ItemDefinition
extends Resource

enum ItemType { GENERIC, CONSUMABLE, MATERIAL, WEAPON, ARMOR, QUEST, CURRENCY }

@export var id: StringName = &""
@export var name_key: StringName = &""      # ⚠ 用 key 不是明文（便于本地化）
@export var icon: Texture2D
@export var item_type: int = ItemType.GENERIC
@export var max_stack: int = 1
@export var weight: float = 0.0
@export var value: int = 0
@export var is_unique: bool = false
@export var tags: Array[StringName] = []
```

⚠ **`max_stack` 与 `is_unique` 是物品定义的一部分**，
⛔ 不是放入算法里的特判（见 03）。

【产出】Inspector 里能新建并修改物品定义

【判据】改一个药水定义的 `max_stack`，所有药水**同时**生效

【审】`audit/godot/game-systems.md` 第 11 条（堆叠判定只看 id 不看 max_stack）

### Step 2　定义 ItemInstance（唯一 id、可变）　`[inventory/01#S2]`

【读】`howto/godot/game-systems.md#四层`

【做】
```gdscript
class_name ItemInstance
extends RefCounted

var instance_id: StringName
var def_id: StringName
var durability: float = 1.0
var custom_data: Dictionary = {}     # 附魔、词条、自定义
```

⚠ 实例**只存会变的东西**。⛔ 不要把 icon、name 复制进来——
那些属于定义，改了定义后实例里那份不会跟着变。

【产出】两个同 def 的实例，`durability` 各自独立

【判据】⚠ 实例 A 的耐久改成 0.5，实例 B 仍是 1.0

【审】`audit/godot/game-systems.md` 第 1 条（槽位直接存物品对象 → 数据不同步）

### Step 3　instance_id 用自增，不用随机数　`[inventory/01#S3]`

【读】`howto/godot/game-systems.md#三、库存系统` 的 ⚠ 提示

【做】
```gdscript
var _next_id: int = 1
func _new_instance(def_id: StringName) -> ItemInstance:
    var iid := StringName("it_%d" % _next_id)
    _next_id += 1
    ...
```

⚠ **用 `randi()` 会在存档回读后 id 冲突**——
不同物品拿到同一个 id，槽位指向错误的实例。

【产出】`_next_id` 随 `_new_instance()` 单调增长，且能被序列化（见 05）

【判据】⚠ 存档→回读→再造 10 个新物品，**没有任何一个 id 与旧 id 重复**

【审】`audit/godot/game-systems.md` 第 7 条（实例 id 用 randi → 回读后冲突）

### Step 4　装备类的四层（若本次涉及装备）　`[inventory/01#S4]`

【读】`howto/godot/economy.md#4. 装备养成：模板 / 实例 / 词条 / 养成状态四层分离`

【做】装备还要再加两层：**词条**与**养成状态**，与模板/实例共四层。
⚠ 词条要存 `affix_id + roll + generation_version`，⛔ 不存最终值
（存最终值 = 策划改表后历史装备无法重算）。

【产出】装备实例能表达"同一把剑、不同词条、不同强化等级"

【判据】⚠ 改数值表后，历史装备能按 `generation_version` 重新算出正确属性

【审】`audit/godot/game-systems.md` 第 13 条（不同 custom_data 的实例被合并）

## 3. 参考实现

```gdscript
# item_definition.gd
class_name ItemDefinition
extends Resource

enum ItemType { GENERIC, CONSUMABLE, MATERIAL, WEAPON, ARMOR, QUEST, CURRENCY }

@export var id: StringName = &""
@export var name_key: StringName = &""
@export var icon: Texture2D
@export var item_type: int = ItemType.GENERIC
@export var max_stack: int = 1
@export var weight: float = 0.0
@export var value: int = 0
@export var is_unique: bool = false
@export var tags: Array[StringName] = []

func can_stack_with(other: ItemDefinition) -> bool:
    if other == null:
        return false
    # ⚠ 两个条件都要：id 相同 且 都可堆叠
    return id == other.id and max_stack > 1 and other.max_stack > 1

# item_instance.gd
class_name ItemInstance
extends RefCounted

var instance_id: StringName
var def_id: StringName
var durability: float = 1.0
var custom_data: Dictionary = {}

func _init(iid: StringName, did: StringName) -> void:
    instance_id = iid
    def_id = did
```

⚠ `can_stack_with()` 里 **`max_stack > 1` 必须两边都判**——
只判一边会出现"目标槽不可堆但仍然并进去"的反向 bug。

## 4. 验收清单

- [ ] `ItemDefinition` 可在 Inspector 新建修改
- [ ] 改定义 → 所有同类实例同时变化
- [ ] 两个实例 `instance_id` 不同，耐久互不影响
- [ ] ⚠ 存档回读后造新物品，id 无冲突
- [ ] `can_stack_with()` 两边都判 `max_stack > 1`
- [ ] 若涉及装备：词条存的是 id+roll+version，不是最终值

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 同一把剑两格耐久不同 | 槽位存了对象副本 | S2 |
| 回读后物品张冠李戴 | id 用随机数 | S3 |
| 改了定义但老物品没变 | 实例复制了静态数据 | S2 |
| 装备被合成一格 | 堆叠没判 max_stack | S1 |
