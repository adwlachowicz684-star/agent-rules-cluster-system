# 05 存档序列化（背包与物品域）

> **前置**：02 容器可用，04 移动已保证 `instance_id` 唯一
> **本步交付**：存档能完整回读——**槽位与实例两个都要存**，回读后 id 不冲突
> **对应**：做法 `howto/godot/game-systems.md` · 审核 `audit/godot/game-systems.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 存档 → 退出 → 回读，**槽位数、堆叠数、耐久、附魔全部一致**
2. 回读后再造新物品，**instance_id 不与旧 id 冲突**
3. 删掉一个物品再存再读，实例字典里**没有残留**
4. ⚠ 连续存读 50 轮，存档体积**不单调增长**

**产出物**（下游按名字对接）：

```text
Inventory.serialize() -> Dictionary    slots + instances + capacity + next_id
Inventory.deserialize(data) -> void
```

⚠ `next_id` **必须一起存** —— 它是 01 定下的 id 不冲突的唯一保证。
⛔ 漏了它，回读后新物品会拿到与旧物品相同的 id。

## 2. 工序

### Step 1　slots 与 instances 两个都要存　`[inventory/05#S1]`

【读】`howto/godot/game-systems.md#三、库存系统` 的 `serialize()`

【做】
```gdscript
func serialize() -> Dictionary:
    return {
        "slots": _slots.duplicate(true),
        "instances": _instances.duplicate(true),
        "capacity": _capacity,
        "next_id": _next_id,          # ⚠ 必须
    }
```

⚠ **只存 slots 不存 instances** → 回读后耐久归满、附魔消失；
反之只存 instances → 槽位顺序与堆叠数丢失。

【产出】序列化结果包含四个键

【判据】⚠ 序列化→反序列化→再序列化，两次结果**完全相等**

【审】`audit/godot/game-systems.md#12`（只存 slots 不存 instances）

### Step 2　next_id 必须持久化　`[inventory/05#S2]`

【读】`howto/godot/game-systems.md#三、库存系统` 的 ⚠ 提示

【做】反序列化时恢复 `_next_id`，⛔ 不要重置为 1。

⚠ 不存 `next_id` 的后果：回读后从 1 开始发新 id，
与已有的 `it_1`、`it_2` **直接冲突**，槽位指向错误实例。

【产出】回读后 `_next_id` 等于存前的最大值 + 1

【判据】⚠ 存前造到 `it_50`，回读后造新物品拿到 `it_51`（⛔ 不是 `it_1`）

【审】`audit/godot/game-systems.md#7`（id 冲突）

### Step 3　反序列化后校验不变量　`[inventory/05#S3]`

【读】`howto/godot/game-systems.md#三、库存系统`

【做】`deserialize()` 末尾跑一次 04 的 `_invariant_check()`：
- 每个槽的 `instance_id` 在 `_instances` 里存在（⛔ 悬空引用）
- 没有 id 出现在两个槽

⚠ 存档可能被手改、可能被旧版本写坏。
**回读时校验，坏档立刻报错**比"玩到一半发现物品错了"好得多。

【产出】坏档能被检出并给出明确错误

【判据】⚠ 手工删掉 instances 里的一条再回读，**明确报错**而不是静默丢物品

【审】`audit/godot/game-systems.md#12`

### Step 4　体积不单调增长　`[inventory/05#S4]`

【读】`howto/godot/game-systems.md#三、库存系统` 的 ⚠ 提示

【做】`remove()` 时 `erase` 实例（02 已做）。本步验证：
连续"加 100 → 全取出"循环 50 轮，存档体积回到起始值。

⚠ 这是"实例泄漏"的观测点——
⛔ 只测一轮看不出来，必须测多轮看**趋势**。

【产出】50 轮循环后体积与第 1 轮相同

【判据】⚠ 第 1 轮与第 50 轮序列化后的字节长度**相等**

【审】`audit/godot/game-systems.md#10`（remove 后不 erase → 泄漏）

### Step 5　版本与迁移（若已有旧档）　`[inventory/05#S5]`

【读】`flow/godot/save/04-存档迁移.md`

【做】库存结构变更时（如加了 `weight` 字段、容量规则改了），
要有 `version` 字段与迁移路径。

⚠ 库存是**玩家资产**——迁移出错是**不可逆的损失**，
比崩溃严重得多。

【产出】`serialize()` 带 `version`；旧档能被迁移而不是被丢弃

【判据】⚠ 用一份旧结构存档回读，物品**一个不少**

【审】`audit/godot/game-systems.md#29`

## 3. 参考实现

```gdscript
const SAVE_VERSION := 1

func serialize() -> Dictionary:
    return {
        "version": SAVE_VERSION,
        "slots": _slots.duplicate(true),
        "instances": _instances.duplicate(true),
        "capacity": _capacity,
        "next_id": _next_id,
    }

func deserialize(data: Dictionary) -> bool:
    if not data.has("slots") or not data.has("instances"):
        push_error("库存存档缺字段：%s" % data.keys())
        return false
    _slots = data["slots"]
    _instances = data["instances"]
    _capacity = int(data.get("capacity", 20))
    _next_id = int(data.get("next_id", 1))     # ⚠ 恢复，不是重置
    if not _invariant_check():
        push_error("库存存档不变量校验失败")
        return false
    changed.emit()
    return true
```

⚠ `duplicate(true)` 是**深拷贝**——
⛔ 用浅拷贝会让序列化结果持有对内部字典的引用，
之后任何改动都会"意外地"改到已导出的快照。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 回读后耐久归满、附魔没了 | 只存了 slots | S1 |
| 回读后物品张冠李戴 | next_id 没存 | S2 |
| 玩久了存档越来越大 | 实例泄漏 | S4 |
| 改结构后老档全丢 | 没版本与迁移 | S5 |
| 坏档静默丢物品 | 回读不校验 | S3 |
