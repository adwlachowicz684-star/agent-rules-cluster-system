## 0. 交付物定义

⚠ 各功能点自己的验收清单**不能替代本步**。
每个部件都合格、拼起来不能用，是跨域开发的典型失败。

做完这一步，应该能**当场演示**：

1. 拾取 → 入包 → 堆叠 → 拖放 → 存档 → 回读，全程物品**一个不少**
2. ⚠ 随机操作 1000 次后，`instance_id` 唯一性不变量**始终成立**
3. ⚠ 连续存读 50 轮，存档体积**不单调增长**
4. ⚠ **没有任何一条路径**会让玩家物品凭空消失

**产出物**：
```text
验收记录（含实测值）
参数登记表已回填（见 00-域流程总览.md 第 4 节）
```

## 2. 工序

### Step 1　全链路串一遍　`[inventory/07#S1]`

【读】`howto/godot/game-systems.md#三、库存系统`

【做】从拾取到回读完整走一遍，**每一步记录物品总数**：

```
拾取 → add() → 堆叠 → 拖放 move() → 跨容器 transfer()
  → serialize() → 存盘 → 读盘 → deserialize() → UI 显示
```

⚠ **每一步之后都核对总数**。⛔ 只看最后有没有报错——
物品是在哪一步少的，事后查不出来。

【产出】每一步的物品总数记录，全程相等

【判据】⚠ 每一步的"所有容器该物品总数"**完全相等**

【审】`audit/godot/game-systems.md` 第 4 条（静默丢弃）

### Step 2　随机压力测试　`[inventory/07#S2]`

【读】`howto/godot/game-systems.md#三、库存系统` 与 `flow/godot/inventory/04-移动与原子性.md`

【做】脚本随机执行 1000 次操作（add / remove / move / transfer），
每次结束后跑 04 的 `_invariant_check()`。

⚠ 手工点 1000 次不现实，必须脚本化。
这是唯一能覆盖"拖快了""刚好满包""同帧多次操作"这些场景的方法。

【产出】1000 次操作的不变量检查结果（应全部 `true`）

【判据】⚠ 1000 次后 `_invariant_check()` 全部为 `true`，
　　　且物品总数与理论值一致

【审】`audit/godot/game-systems.md` 第 6 条（脏数据）

### Step 3　存读循环与体积　`[inventory/07#S3]`

【读】`flow/godot/inventory/05-存档序列化.md`

【做】"加满 100 → 全部取出 → 存 → 读"循环 50 轮，
记录每轮序列化后的字节长度。

⚠ 看**趋势**不看单轮——泄漏是单调增长，
⛔ 只测一轮完全看不出来。

【产出】50 轮的体积曲线

【判据】⚠ 第 50 轮与第 1 轮体积**相等**（允许微小波动，但不得单调增长）

【审】`audit/godot/game-systems.md` 第 10 条（实例泄漏）

### Step 4　消失路径排查　`[inventory/07#S4]`

【读】`howto/godot/game-systems.md#三、库存系统`

【做】⚠ **专门找"物品会消失"的路径**。逐条检查：

| 场景 | 期望行为 |
|---|---|
| 背包满时拾取 | 部分放入 + 提示（⛔ 不是丢弃） |
| 背包满时购买 | 拒绝并提示（⛔ 不是扣钱不给货） |
| 背包满时收邮件附件 | 拒绝，附件留在邮件里 |
| 交易中途失败 | 双方都回到原样 |
| 存档损坏回读 | 明确报错（⛔ 不是静默丢弃） |

⚠ 玩家资产丢失是**最严重**的 bug 类型——
它不会崩溃、不会报错，只是玩家的东西没了。

【产出】上表每行都有实测结论

【判据】⚠ 每行都标注了实际行为，且**没有任何一行**是"物品消失"

【审】`audit/godot/game-systems.md` 第 4 条

### Step 5　接缝复查　`[inventory/07#S5]`

【读】`references/structure.md#5. 组合模型`

【做】列出本域与其他域的接缝，逐条确认：

| 接缝 | 上游产出 | 下游期望 | 一致? |
|---|---|---|---|
| 容器 → UI | `changed` 信号 + `slots()` | UI 订阅并渲染 | |
| UI → 容器 | `move()/add()/remove()` 调用 | 容器返回结果码 | |
| 库存 → 存档 | `serialize()` 四键 | 存档系统落盘 | |
| 库存 → 经济 | `def_id` + 数量 | 商店/掉落查同样的定义 | |
| 库存 → 交易 | `instance_id` | 流转的是实例不是模板 | |

⚠ **各域合格 ≠ 拼起来能用。**
接缝对不上要单独立适配步骤，⛔ 不要在各处偷偷转格式。

【产出】接缝清单，每行标注"一致"或"已适配"

【判据】⚠ 每行都有明确结论，⛔ 没有"应该没问题"

【审】`audit/godot/game-systems.md` 第 9 条

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 拖快了物品串位 | 无不变量检查 | S2 |
| 玩久了存档变大 | 实例泄漏 | S3 |
| 满包购买扣钱没给货 | 没检查 add 返回值 | S4 |
| 交易后物品两边都没有 | 改一半失败 | S4 |
| UI 与容器规则不一致 | UI 自己判了规则 | S5 |
