# 04 二次验证与恢复码（账号安全域）

> **本步交付**：TOTP 窗口口径 + 恢复码哈希存储 + CSPRNG 随机源
> **对应**：流程 `howto/godot/account-security.md` · 审核 `audit/godot/account-security.md`

## 0. 交付物定义

1. TOTP 验证窗口不放大
2. 同一窗口内一个码只能用一次
3. 恢复码**按一次一码存哈希**
4. 密钥与恢复码由 **CSPRNG** 产生
5. 短信只是受限备选；强制 2FA 绑风险且给替代路径

## 1. 前置检查清单

- [ ] 共享密钥长度达标且来自 CSPRNG
- [ ] 验证窗口为当前 + 前后各一个时间步
- [ ] 同窗口内同一码不能二次使用
- [ ] 恢复码是哈希存储，显示一次
- [ ] 有除短信外的第二验证或恢复路径

## 2. 工序

### Step 1　TOTP 窗口不放大　`[account-security/04#S1]`

【读】`howto/godot/account-security.md#3. 2FA`

【做】
验证默认只接受**当前和前后各一个时间步**；每个码在同一窗口内只能成功一次；
连续失败若干次后强制冷却。
⛔ 把窗口开大"方便用户" —— 扩大窗口**提高爆破成功率**，
RFC 建议网络延迟最多容忍一个时间步。
表现为"验证码体系在测试里 100% 通过"，⛔ 而爆破面已经扩大，
排查时没有任何异常可查。

ⓘ 配套：共享密钥**至少 128 位、推荐 160 位**，⛔ 不能用玩家输入的字符串。

【产出】TOTP 参数（时间步长、容忍窗口、冷却阈值、密钥长度）

【判据】超出窗口的码一律拒绝；同码在同一窗口二次使用被拒。

【审】`audit/godot/account-security.md#16`

### Step 2　恢复码按一次一码存哈希　`[account-security/04#S2]`

【读】`howto/godot/account-security.md#3. 2FA`

【做】
恢复码是**一次性查找秘密**：生成多个随机码，**按一次一码保存哈希**
（与密码同等级），显示一次并强制下载 / 抄写，用完立即作废。
⛔ 明文存 —— 库一旦泄露，恢复码就成了绕过 2FA 的直通车，
表现为"开了 2FA 还是被盗"，⛔ 而 2FA 本身的验证逻辑没有出错。

ⓘ 比较时用 `Crypto.constant_time_compare()`，
⛔ 普通 `==` 比较字符串会引入时序侧信道。

【产出】恢复码生成 / 存储 / 作废流程（含哈希与比较口径）

【判据】库中无明文恢复码；用过的码立即失效。

【审】`audit/godot/account-security.md#17`

### Step 3　密钥与恢复码必须走 CSPRNG　`[account-security/04#S3]`

【读】`howto/godot/account-security.md#随机源`

【做】
TOTP 共享密钥、恢复码、找回码一律用 `Crypto.generate_random_bytes()`。
⛔ 用 `randi()` 生成 —— 它不是密码学安全随机源、输出可预测，
密钥空间被压缩到种子空间，
⛔ 表现为"每一次都不同、看起来完全随机"，而安全性远低于预期。

ⓘ 这条在正常测试中**永远测不出来**：
每次生成的码确实不同、用户也确实能验证通过，
⛔ 只有有人针对随机源做分析时才暴露。

【产出】随机源统一入口（所有安全相关随机都走 CSPRNG）

【判据】全局搜索不到用 `randi()` 产生密钥 / 恢复码 / 找回码的地方。

【审】`audit/godot/account-security.md#38`

### Step 4　短信只能当受限备选　`[account-security/04#S4]`

【读】`howto/godot/account-security.md#3. 2FA`

【做】
短信 / 语音 OTP 按 NIST 的 **RESTRICTED** 级别使用：
⛔ 不能作为唯一强验证，高价值资产、支付、绑定修改优先 TOTP 或通行密钥。
⛔ 把短信当强验证 —— SIM swap 可直接接管，
表现为"用户什么都没做错却丢了号"，⛔ 而短信确实发到了"用户的号码"。

【产出】验证因子分级表（TOTP / 通行密钥 / 短信各自的可用范围）

【判据】不存在"仅凭短信即可完成高价值操作"的路径。

【审】`audit/godot/account-security.md#18`

### Step 5　强制 2FA 绑风险，⛔ 不一刀切　`[account-security/04#S5]`

【读】`howto/godot/account-security.md#3. 2FA`

【做】
强制 2FA 绑定**风险**而非账号类型：高价值账号、充值 / 交易、管理员 / 客服、
异常登录、绑定变更。且必须提供**至少一个替代恢复路径**。
⛔ 一刀切强制 —— "找不到手机"会变成**永久丢号**，
表现为客服工单量激增且大量无法解决，
⛔ 而安全策略本身"确实更严格了"。

ⓘ 判据很直接：**一个丢了手机的用户能不能靠别的路径拿回账号**。
不能，就是缺替代路径。

【产出】强制 2FA 触发条件表 + 替代恢复路径清单

【判据】每个被强制的用户都至少有一条自己能走通的恢复路径。

【审】`audit/godot/account-security.md#19`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：CSPRNG 随机源 + 哈希存储恢复码
# ⛔ 常量为占位，实际取值见 00 参数登记，待实测
const RECOVERY_CODE_COUNT := 10
const TOTP_WINDOW_TOLERANCE := 1  # ⛔ RFC 建议最多 1 个时间步

# ⛔ 不用 randi() —— 非 CSPRNG，输出可预测
func new_shared_secret() -> PackedByteArray:
    return Crypto.new().generate_random_bytes(20)  # 160 位

# 恢复码按一次一码存哈希，⛔ 不明文
func store_recovery_code(raw: String) -> void:
    var salt := Crypto.new().generate_random_bytes(16)
    _db.insert(hash_password(raw, salt), salt)

# 比较用常量时间，⛔ 不用 ==
func verify_code(a: String, b: String) -> bool:
    return Crypto.new().constant_time_compare(a.to_utf8_buffer(), b.to_utf8_buffer())
```

## 4. 验收清单

- [ ] 窗口为当前 + 1，同码不可重用
- [ ] 库中无明文恢复码
- [ ] 所有安全随机都走 CSPRNG
- [ ] 短信不是唯一强验证
- [ ] 强制 2FA 有替代恢复路径

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 开了 2FA 仍被盗 | 恢复码明文 | S2 |
| 丢了手机等于永久丢号 | 强制一刀切 | S5 |
| 没做错什么却丢号 | 短信当强验证 | S4 |
| 码每次都不同但可预测 | 用了 randi() | S3 |
