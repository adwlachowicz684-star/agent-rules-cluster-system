# 07 账号安全验收（账号安全域）

> **本步交付**：敌意环境实测通过 + 出包后校验生效实测通过
> **对应**：流程 `howto/godot/account-security.md` · 审核 `audit/godot/account-security.md`

## 0. 交付物定义

1. 改包伪造 ID 的越权请求被服务端拒绝
2. refresh 重用触发整个 family 撤销
3. 出包后 TLS 校验仍生效（无 `client_unsafe()` 残留）
4. 日志与崩溃上报中检索不到 token
5. 注销与转服在敌意并发下结果一致

## 2. 工序

### Step 1　改包伪造 ID 必须被服务端拒绝　`[account-security/07#S1]`

【读】`howto/godot/account-security.md#0. 先分清四个对象`

【做】
构造三类伪造：改 `account_id` 查他人资产、改 `role_id` 操作他人角色、
改权限字段提权，验证服务端**全部使用会话反查结果**。
⛔ 只测正常路径 —— 越权**只在有人改包时才暴露**，
⛔ 而测试环境下没人会改包，所以这条永远"通过"。

ⓘ 服务端日志里每一次都记录为"该账号的正常请求"，
⛔ 事后靠补日志无法定位。

【产出】三类伪造用例 + 服务端拒绝记录

【判据】三类全部被拒，且响应与"真的没有权限"一致。

【审】`audit/godot/account-security.md#2`

### Step 2　refresh 重用触发整个 family 撤销　`[account-security/07#S2]`

【读】`howto/godot/account-security.md#2. 会话`

【做】
实测：拿到一个已轮换掉的旧 refresh，再用它换发一次，
验证整个 family 被撤销、用户被通知、要求完整重认证。
⛔ 只测"刷新一次成功" —— 重用检测**只在旧值被再次使用时触发**，
⛔ 而正常使用路径永远走不到那个分支。

ⓘ 同时验改密与登出：撤销后旧 access 立即不可用。

【产出】重用检测实测记录（含撤销范围、通知、重认证）

【判据】旧 refresh 再用一次即撤销整个 family。

【审】`audit/godot/account-security.md#11`

### Step 3　出包后 TLS 校验仍生效　`[account-security/07#S3]`

【读】`howto/godot/account-security.md#TLS 传输`

【做】
在**导出构建**（不是编辑器）上验证：换成无效证书后连接**失败**。
⛔ 只在编辑器里测 —— 编辑器与导出的证书来源不同，
⛔ 而 `client_unsafe()` 残留会让"连得上"看起来正常，
中间人由此截获 access / refresh token 且**无任何提示**。

⚠ Web 平台要单独验：官方称 Web 上 TLS 校验**始终强制**，
⛔ 因此"桌面能连、Web 握手失败"往往不是 Web 的 bug。

【产出】导出构建的 TLS 校验实测记录（含换证书失败的证据）

【判据】导出构建中换无效证书后连接失败；`is_unsafe_client()` 为 false。

【审】`audit/godot/account-security.md#34`、`audit/godot/account-security.md#36`

### Step 4　日志与崩溃上报检索不到 token　`[account-security/07#S4]`

【读】`howto/godot/account-security.md#5. 盗号与风控`

【做】
全局检索日志、崩溃上报、分析事件里是否出现 token、明文恢复码、
短信内容、身份证号。
⛔ 只测"主流程日志" —— 泄露几乎总是发生在**旁路**
（崩溃上报、第三方 SDK、临时调试开关），
⛔ 而主流程的脱敏做得再好也覆盖不到旁路。

ⓘ "带上 token 方便排查"是最常见的泄露路径，
⛔ 它通常是在某次排查中被临时加进去然后留下的。

【产出】全通道检索记录（日志 / 崩溃 / 埋点 / 第三方 SDK）

【判据】所有通道中检索不到任何 token / 明文码 / 证件号。

【审】`audit/godot/account-security.md#33`

### Step 5　注销与转服的敌意并发实测　`[account-security/07#S5]`

【读】`howto/godot/account-security.md#6. 生命周期`

【做】
并发发起同一账号的注销与转服、同一转移单的重试、
注销宽限期内的撤销，验证结果一致且可追溯。
⛔ 只按正常顺序点一遍 —— 竞态**只在并发时出现**，
⛔ 表现为"转移后两边各一份唯一道具""注销了还能登录"，
而单步执行时每一步都成功。

ⓘ 注销要单独验**删除义务**：到期后按邮箱 / 手机 / 实名反查不到该自然人，
⛔ 只删角色不算完成。

【产出】并发用例 + 结果对照（含唯一道具份数、注销后反查结果）

【判据】并发下唯一道具仍只有一份；注销到期后反查不到。

【审】`audit/godot/account-security.md#28`、`audit/godot/account-security.md#26`

## 3. 验收清单

- [ ] 三类伪造全部被拒
- [ ] 旧 refresh 再用一次即撤销整个 family
- [ ] 导出构建换无效证书后连接失败
- [ ] 全通道检索不到 token
- [ ] 并发下唯一道具只有一份；注销后反查不到

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 改个 ID 能看别人背包 | 只测正常路径 | S1 |
| 盗号者长期在线 | 没测重用检测 | S2 |
| 中间人截获 token 无提示 | 出包残留 client_unsafe | S3 |
| 崩溃上报里发现 token | 旁路未脱敏 | S4 |
| 转服后两边各一份 | 并发未测 | S5 |
