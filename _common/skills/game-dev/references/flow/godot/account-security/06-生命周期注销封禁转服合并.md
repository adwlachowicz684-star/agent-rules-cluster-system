# 06 生命周期：注销 / 封禁 / 转服 / 合并（账号安全域）

> **本步交付**：删除义务口径 + 封禁粒度 + 幂等转移键 + 合并安全失败
> **对应**：流程 `howto/godot/account-security.md` · 审核 `audit/godot/account-security.md`

## 0. 交付物定义

1. 注销删的是**可识别个人信息的全部**，不是只删角色
2. 封禁有**原因、期限、证据引用、工单号**；IP / 设备只作信号
3. 转服用**同一幂等键**补偿
4. 账号合并**默认安全失败**，不默认覆盖
5. 登出与注销的本地清理排在**服务端撤销之后**

## 1. 前置检查清单

- [ ] 注销清单覆盖登录、支付、实名、绑定，不只是角色表
- [ ] 支付 / 订单 / 税务记录是去标识化 + 隔离保存
- [ ] 封禁记录含原因、期限、证据引用、工单号
- [ ] 转移单有幂等键，失败重试不会双份
- [ ] 双方都有资产时合并被拒绝

## 2. 工序

### Step 1　注销 ≠ 删角色　`[account-security/06#S1]`

【读】`howto/godot/account-security.md#6. 生命周期`

【做】
注销删除（或匿名化）的是**账号标识、联系方式、实名资料、广告标识、营销同意**，
⛔ 不能只删游戏角色。
⛔ 只删角色 —— 登录 / 支付资料还在，**个人信息删除义务并未完成**，
表现为"注销成功了，但还能凭邮箱查到这个人"，
⛔ 而注销流程的每一步都执行成功了。

ⓘ 主线：认证 → 展示影响（角色、好友、订阅、未消费余额、第三方绑定）
→ 显式确认 → 可撤销宽限期 → 到期删除或匿名化。

ⓘ 支付 / 订单 / 税务 / 争议记录按法定期限**去标识化 + 隔离保存**，
⛔ 它们不进"删除"也不进"正常使用"。

【产出】注销数据清单（删除 / 匿名化 / 去标识化隔离 三栏）

【判据】注销到期后，按邮箱 / 手机 / 实名反查不到该自然人。

【审】`audit/godot/account-security.md#26`

### Step 2　封禁粒度与证据　`[account-security/06#S2]`

【读】`howto/godot/account-security.md#6. 生命周期`

【做】
封禁可作用于账号、角色、设备实例、IP 段、支付渠道、聊天功能。
账号与角色封禁必须有**原因、期限、证据引用和工单号**；
⛔ IP / 设备只能作风险信号，**不能独立承担永久全局封禁**。
⛔ 用 IP / 设备独立封 —— 共享网络、校园网、NAT、网吧会连坐，
表现为"一大批正常玩家同时被封"，⛔ 而每条封禁记录都有"证据"。

ⓘ "封设备"要区分 rooted / 越狱、模拟器、共享设备、恶意实例与租借账号。

【产出】封禁粒度矩阵（对象 × 期限 × 证据要求 × 可否独立生效）

【判据】不存在仅凭 IP / 设备即可成立的永久封禁记录。

【审】`audit/godot/account-security.md#27`

### Step 3　转服用同一幂等键补偿　`[account-security/06#S3]`

【读】`howto/godot/account-security.md#6. 生命周期`

【做】
预检查（账号状态、等级、冷却、目标服容量、重名、未结订单、封禁、赛季、绑定）
→ 事务：源服冻结 → 生成转移单与幂等键 → 复制 / 移动 → 更新跨服索引
→ 目标服激活 → 源服置空。
⛔ 失败就重试 —— **任何失败必须按同一幂等键补偿**，
否则玩家两边各持一份唯一道具，
⛔ 而"重试"在日志里记录为一次新的正常转移。

ⓘ 转服最难的是**并发写入与幂等**，不是地图兼容。
⛔ 把精力花在地图兼容上，会在并发时才暴露重复资产。

【产出】转移单结构（含幂等键）+ 失败补偿路径

【判据】同一转移单重试 N 次后，唯一道具仍只有一份。

【审】`audit/godot/account-security.md#28`

### Step 4　账号合并默认安全失败　`[account-security/06#S4]`

【读】`howto/godot/account-security.md#6. 生命周期`

【做】
两边都有充值 / 资产 / 赛季成绩 / 处罚记录时**拒绝自动合并**，
要求先转移或提交工单。合并要用时间线快照记录哪一方胜出。
⛔ 默认覆盖 —— 攻击者控制的一方会覆盖掉受害者的
**邮件 / 手机、实名、支付证据、好友关系**，
表现为"合并后账号被对方完全接管"，⛔ 而合并流程执行成功。

ⓘ 判据很直接：**合并后，哪一方胜出是可审计的**。
没有快照就无法追溯，事后无法还原。

【产出】合并冲突规则 + 时间线快照结构

【判据】双方均有资产时合并被拒；合并结果有可审计快照。

【审】`audit/godot/account-security.md#29`

### Step 5　本地清理排在服务端撤销之后　`[account-security/06#S5]`

【读】`howto/godot/account-security.md#7. Godot 侧的正确位置`

【做】
注销与登出都先调**后端撤销**，再清本地；网络失败也要显示"正在登出"，
⛔ 不假装凭据仍有效。
⛔ 先清本地再调后端 —— 网络失败时本地已无凭据，无法重试撤销，
表现为"点了注销但服务端会话还活着"，⛔ 而客户端确实"已注销"。

ⓘ 与 03 同源：**清了本地文件 ≠ 已登出**，判据在服务端侧。

【产出】登出 / 注销的时序（撤销 → 清本地 → 反馈），含网络失败分支

【判据】注销请求失败时，本地凭据仍在且可重试。

【审】`audit/godot/account-security.md#32`、`audit/godot/account-security.md#31`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：幂等转移单 + 先撤销后清理
# ⛔ 常量为占位，实际取值见 00 参数登记，待实测
const TRANSFER_STATES := ["frozen", "moving", "activating", "done", "compensating"]

# 转移单必须带幂等键，⛔ 失败重试不得生成新单
func begin_transfer(account_id: String) -> String:
    var idempotency_key := "%s:%s" % [account_id, _server.transfer_epoch(account_id)]
    return _server.open_transfer(idempotency_key)

# ⛔ 先撤销再清本地；网络失败保留本地凭据以便重试
func request_logout() -> void:
    var ok := await _auth.revoke_family_async()
    if not ok:
        show("正在登出")
        return
    clear_local_state()
```

## 4. 验收清单

- [ ] 注销后按邮箱 / 手机 / 实名反查不到
- [ ] 无仅凭 IP / 设备的永久封禁
- [ ] 转移单重试后唯一道具仍只有一份
- [ ] 双方有资产时合并被拒，且有快照
- [ ] 注销失败时本地凭据仍在

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 注销后还能查到这个人 | 只删了角色 | S1 |
| 一批正常玩家同时被封 | IP 独立封禁 | S2 |
| 转服后两边各一份道具 | 重试没走幂等键 | S3 |
| 合并后账号被接管 | 默认覆盖 | S4 |
| 点了注销服务端还活着 | 先清了本地 | S5 |
