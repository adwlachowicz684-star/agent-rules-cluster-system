# 05 找回申诉与风控处置（账号安全域）

> **本步交付**：证据三级 + 分级冻结 + 安全降级 + 日志脱敏
> **对应**：流程 `howto/godot/account-security.md` · 审核 `audit/godot/account-security.md`

## 0. 交付物定义

1. 安全问题**不能**当身份证明
2. 客服**不能**单方面跳过第二因素
3. 冻结**分级**，不一刀切
4. IP / 设备指纹只**增信**，不当身份
5. 自动处置**可回滚**，宁可不交易也不自动封号
6. 日志**最短必要期限**，敏感字段绝不记

## 1. 前置检查清单

- [ ] 找回的证据分三级，弱证据不能自动通过
- [ ] 高风险决定后移，提交标识阶段只返回模糊响应
- [ ] 冻结分低 / 中 / 高三档，中档不冻结继续游戏
- [ ] 风控自动处置都有回滚入口
- [ ] 日志字段白名单里没有 token / 明文码 / 证件号

## 2. 工序

### Step 1　安全问题不能当身份证明　`[account-security/05#S1]`

【读】`howto/godot/account-security.md#4. 找回与申诉`

【做】
找回首先是**身份证明**，收集注册阶段已掌握的硬数据 + 带外随机码。
⛔ 用安全问题 —— NIST 明确自服务重置**不能依赖**它：
答案往往公开、多站复用，且需要明文保存。
表现为"熟悉受害者的人能答对全部问题"，⛔ 而系统确实"验证了答案正确"。

ⓘ 高风险决定后移：提交账号标识时**无论是否存在都返回同一模糊响应**（防枚举）。

【产出】找回六步流程（含模糊响应与限流、验证码）

【判据】安全问题不作为身份证明；提交标识无法探测账号是否存在。

【审】`audit/godot/account-security.md#20`

### Step 2　客服不能跳过第二因素　`[account-security/05#S2]`

【读】`howto/godot/account-security.md#4. 找回与申诉`

【做】
人工申诉要**限时、证据清单、随机工单分配、双人复核**。
⛔ 允许客服单方面跳过第二因素 —— 这是**最易被社工绕过**的一条：
攻击者能说出角色名、最近登录地、订单尾号、社交资料，
⛔ 而客服操作在系统里记录为"一次正常的客服处理"。

ⓘ 证据三级：强（原邮箱 / 手机控制、已注册 MFA）、
可复核（支付订单与角色 / 时间的校验）、弱（角色名、截图、好友关系）。
⛔ **只有强证据或可核验支付证据组合才能自动找回**。

【产出】证据三级表 + 工单分配与复核规则

【判据】不存在单人工号即可完成高风险找回的路径。

【审】`audit/godot/account-security.md#21`

### Step 3　冻结必须分级，⛔ 不一刀切　`[account-security/05#S3]`

【读】`howto/godot/account-security.md#4. 找回与申诉`

【做】
低风险仅限制重复发起与改绑定；中风险冻结敏感操作（改邮箱 / 手机、解绑 MFA、交易）
**但不冻结继续游戏**；高风险（资产已异动、客服确认盗号）才冻结登录与交易。
⛔ 一律冻结 —— 把正常用户挡在外面，
表现为"被盗的是少数，被冻结的是多数"，⛔ 而工单量会先于问题暴露。

ⓘ 冻结必须带**原因、期限、撤销入口、通知渠道与申诉编号**，
⛔ 客服不能口头取消风控。

【产出】分级冻结矩阵（风险档 × 冻结范围 × 期限 × 撤销入口）

【判据】中风险档下用户仍能正常游戏。

【审】`audit/godot/account-security.md#22`

### Step 4　IP 与设备指纹只增信，⛔ 不当身份　`[account-security/05#S4]`

【读】`howto/godot/account-security.md#5. 盗号与风控`

【做】
IP、地理位置、设备指纹只用于**增信**，⛔ 不能当认证因子，
⛔ 更不能据此直接封禁。
⛔ 用它们当身份 —— VPN、IPv6、运营商 NAT、旅行、共享设备、模拟器都会误伤，
表现为"用户出差回来就被封"，⛔ 而风控分数确实"很高"。

ⓘ 三档处置：低档放行 + 审计；中档要求 TOTP / 恢复码并限制改绑定；
高档二次验证、冻结交易、人工申诉、通知用户。

【产出】信号权重表 + 三档处置动作表

【判据】不存在仅凭 IP / 设备即触发封禁的规则。

【审】`audit/godot/account-security.md#23`

### Step 5　自动处置可回滚，宁可不交易也不自动封号　`[account-security/05#S5]`

【读】`howto/godot/account-security.md#5. 盗号与风控`

【做】
所有自动处置都要**可回滚**并设"安全降级"：
宁可不给高风险交易，⛔ 也不要自动封号。
客服撤销时同步恢复资产或给补偿工单。
⛔ 高分就自动封 —— 误伤的是真实付费用户，
表现为"封禁量上去了、申诉量也上去了、口碑掉了"，
⛔ 而风控模型指标看起来是"有效的"。

ⓘ 另外一条：⛔ 不要把玩家电脑上的凭据读出来上传给所谓"反作弊模块"——
那会把单机攻击面扩大到服务端。

【产出】自动处置清单（每项的回滚动作 + 补偿工单入口）

【判据】每条自动处置都有对应回滚路径，且回滚后资产一致。

【审】`audit/godot/account-security.md#24`

### Step 6　日志最短必要，敏感字段绝不记　`[account-security/05#S6]`

【读】`howto/godot/account-security.md#5. 盗号与风控`

【做】
登录日志记：时间、账号 ID（非昵称）、认证步骤结果、IP、网络类型 / AS、
匿名设备 ID、客户端版本、MFA 方法、会话 ID、风控动作、请求 ID。
⛔ **绝不记**：密码、TOTP 密钥、明文恢复码、完整 token、短信内容、身份证号。
保留期写进隐私政策，按"实现处理目的所必要的最短时间"自定。
⛔ 以防万一永久保存 —— PIPL 要求**最短必要期限**，
⛔ 而"永久"在日志系统里不会报错，只在合规审查时才被发现。

ⓘ 崩溃上报同样要**脱敏**：token、邮箱、内部用户 ID、请求头发前剥离。
⛔ "带上 token 方便排查"是最常见的泄露路径。

【产出】日志字段白名单 + 保留期限 + 崩溃上报脱敏清单

【判据】日志与崩溃上报中检索不到任何 token / 明文码 / 证件号。

【审】`audit/godot/account-security.md#25`、`audit/godot/account-security.md#33`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：分级冻结 + 脱敏日志
# ⛔ 常量为占位，实际取值见 00 参数登记，待实测
enum RiskLevel { LOW, MID, HIGH }
# 中风险冻结敏感操作，⛔ 不冻结继续游戏
const MID_FREEZE := ["change_email", "change_phone", "unbind_2fa", "trade"]

func freeze_scope(level: int) -> Array:
    match level:
        RiskLevel.LOW:  return []
        RiskLevel.MID:  return MID_FREEZE
        _:              return ["login", "trade"]

# 日志字段白名单：⛔ 绝不含 token / 明文码 / 证件号
const LOG_FIELDS := ["ts", "account_id", "step", "ip", "as", "device_anon", "ver", "mfa", "session_id", "action", "req_id"]

# 崩溃上报前剥离，⛔ 不"带 token 方便排查"
func scrub(d: Dictionary) -> Dictionary:
    for k in ["token", "refresh", "email", "id_card", "totp_secret"]:
        d.erase(k)
    return d
```

## 4. 验收清单

- [ ] 安全问题不作身份证明；提交标识无枚举
- [ ] 高风险找回需双人复核
- [ ] 中风险档仍能继续游戏
- [ ] 无仅凭 IP / 设备的封禁规则

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 熟人能答对问题改密 | 用安全问题 | S1 |
| 客服被社工绕过 | 可单方跳第二因素 | S2 |
| 正常用户被大面积冻结 | 冻结一刀切 | S3 |
| 出差回来被封 | IP 当身份 | S4 |
| 封禁量涨、口碑掉 | 高分自动封号 | S5 |
| 合规审查发现永久日志 | 以防万一保存 | S6 |
