# 02 口令存储与强度校验（账号安全域）

> **本步交付**：慢哈希选型 + 实测参数 + 每口令唯一 salt + 模糊提示
> **对应**：流程 `howto/godot/account-security.md` · 审核 `audit/godot/account-security.md`

## 0. 交付物定义

1. 用的是**慢哈希**（Argon2id / scrypt / bcrypt / PBKDF2），不是快速摘要
2. 参数按自己 CPU / 内存与登录峰值**实测**，不是抄来的
3. salt **每口令唯一随机**，不与用户名、常量、时间相关
4. 不强制定期改密，但检查已知泄露口令
5. 用户名不存在 / 口令错误 / 2FA 失败返回**同样模糊提示**

## 1. 前置检查清单

- [ ] 不是 MD5 / SHA-1 / SHA-256 加盐
- [ ] 参数有预发布环境的 p50 / p99 记录
- [ ] salt 是每口令唯一随机值
- [ ] 三种失败返回同一模糊提示
- [ ] 有限流（账号 + 网段 + 设备三维）

## 2. 工序

### Step 1　快速摘要加盐不算密码哈希　`[account-security/02#S1]`

【读】`howto/godot/account-security.md#1. 密码存储`

【做】
改用**慢哈希**：新系统用 Argon2id，不可用时 scrypt，
仅旧系统兼容用 bcrypt（注意 72 字节输入边界），FIPS 要求用 PBKDF2-HMAC-SHA256。
⛔ 用 MD5 / SHA-256 加盐 —— 问题不在算法强度而在**速度**，
salt 只防彩虹表，⛔ 不防拿到表后用 GPU 高速试错。
表现为"数据库泄露后大量账号在很短时间内被撞出"，
⛔ 而哈希本身没有算错，排查被引向"泄露是怎么发生的"。

【产出】哈希选型与迁移路径（弱哈希在下一次成功登录时重哈希）

【判据】单口令哈希耗时在实测记录的量级上，不是微秒级。

【审】`audit/godot/account-security.md#5`

### Step 2　参数必须实测，⛔ 不抄文章　`[account-security/02#S2]`

【读】`howto/godot/account-security.md#1. 密码存储`

【做】
在预发布环境按自己的 CPU / 内存预算与登录峰值测 p50 / p99，
再定工作因子。⛔ 直接抄文章里的数值 —— 参数与机器强相关，
调低了防不住、调高了**制造 DoS 面**（登录峰值把服务端打满）。
⛔ 表现为"要么被撞库、要么一到开服登录就雪崩"，
而两种情况的排查方向完全相反。

ⓘ 公开基线只能当**起测值**，不能当最终值。

【产出】参数实测记录（p50 / p99、峰值 QPS、内存占用）

【判据】参数有实测记录，且登录峰值下服务端不雪崩。

【审】`audit/godot/account-security.md#6`

### Step 3　salt 每口令唯一随机　`[account-security/02#S3]`

【读】`howto/godot/account-security.md#1. 密码存储`

【做】
每个口令生成**唯一随机 salt**并随哈希一起存。
⛔ salt 存成常量、用用户名或时间当 salt ——
相同口令得到相同哈希，彩虹表与批量比对重新生效，
表现为"两个人密码一样，库里哈希也一样"，
⛔ 而加盐逻辑本身"看着是有 salt 的字段"。

⚠ 配套检查：十六进制后再 base64 会造成截断；迁移与登录路径里
⛔ 不能悄悄降级到 SHA-1；密码提示⛔ 不能明文入库。

【产出】salt 生成与存储格式（含长度与编码口径）

【判据】相同口令的两个账号，哈希与 salt 均不同。

【审】`audit/godot/account-security.md#7`

### Step 4　不强制定期改密，但要查泄露口令　`[account-security/02#S4]`

【读】`howto/godot/account-security.md#1. 密码存储`

【做】
按 NIST 当前口径：**不要求**定期强制改密码，只在**有泄露证据**时强制；
不要求复杂字符组合，但检查已知泄露口令，允许至少 8 字符、最好到 64 字符。
⛔ 强制定期改密 —— 用户只是在后面加数字或做微小变形，
表现为"合规了但安全性没提升"，并且显著增加找回工单量。

ⓘ 实现侧三条：拒绝常见 / 已泄露口令 · 允许长口令和空格 ·
Unicode 先做 NFKC 规范化。

【产出】口令策略（长度、泄露检查、强制改密的触发条件）

【判据】仅在有泄露证据时强制改密；相同口令不同 Unicode 表示等价。

【审】`audit/godot/account-security.md#8`

### Step 5　三种失败返回同一模糊提示　`[account-security/02#S5]`

【读】`howto/godot/account-security.md#1. 密码存储`

【做】
**用户名不存在**、**口令错误**、**2FA 失败** 返回**同样的模糊提示**与相近耗时。
⛔ 用户名不存在时单独提示 —— 这是**账号枚举**入口，
攻击者先批量探测哪些账号存在，再做定向撞库，
⛔ 而每一步请求单看都是"正常的失败响应"。

ⓘ 配套：按**账号 + 网段 + 设备指纹**三维限流。
⛔ 只按 IP 限流 —— 换代理即失效；⛔ 只按账号限流 —— 会把受害者锁死在外。

【产出】统一失败响应（文案、耗时口径）+ 三维限流规则

【判据】存在/不存在的账号返回同一响应；三维限流均生效。

【审】`audit/godot/account-security.md#9`
