# 03 会话与令牌轮换（账号安全域）

> **本步交付**：服务端可吊销 + refresh 轮换与重用撤销 + 高危重验证
> **对应**：流程 `howto/godot/account-security.md` · 审核 `audit/godot/account-security.md`

## 0. 交付物定义

1. access 短命，refresh 只在换发端点使用
2. 纯无状态 JWT 也有**服务端吊销能力**
3. refresh **轮换**，重用时撤销整个 family
4. 改密 / 登出 / 盗号撤销的是**服务端 refresh family**，不是清本地
5. 高危操作要求**重新验证**；登录成功必发**新会话**

## 1. 前置检查清单

- [ ] access 有效期在分钟级
- [ ] 服务端能吊销（refresh 状态表或 token family 记录）
- [ ] refresh 每次换发都轮换旧值
- [ ] 重用时撤销整个 family 并通知用户
- [ ] 登录成功后旧匿名会话立即失效

## 2. 工序

### Step 1　无状态 JWT 也要有吊销能力　`[account-security/03#S1]`

【读】`howto/godot/account-security.md#2. 会话`

【做】
access token 是**短时能力证明**（分钟级），refresh 才是长期凭证。
即便用 JWT，也要有服务端 refresh 状态表或 token family 记录。
⛔ 纯无状态 JWT 且没有吊销能力 —— 改密、登出、确认盗号后**无法失效**，
表现为"改了密码，旧设备还能继续玩"，⛔ 而签发与校验逻辑全对。

ⓘ 判断标准很直接：**能不能让某一张 token 立刻失效**。
不能，就是没有吊销能力。

【产出】token 类型表（access / refresh 各自有效期、可用端点、是否可吊销）

【判据】撤销后旧 token 立即不可用。

【审】`audit/godot/account-security.md#10`

### Step 2　refresh 必须轮换，重用撤销整个 family　`[account-security/03#S2]`

【读】`howto/godot/account-security.md#2. 会话`

【做】
每次换发新 refresh 后令旧值失效；**已失效值再次出现**即视为泄露，
撤销整个 family 并要求完整重认证。
⛔ refresh 长期有效 —— 一次泄露等于永久有效，
表现为"用户改了密码，盗号者仍能长期登录"，
⛔ 而每次换发请求单看都是"正常的刷新"。

ⓘ 检测时⛔ 不能假定能区分谁是攻击者：
撤销的是整个 family，不是"最后用的那个"。

ⓘ 同时设闲置上限与绝对上限（见 00 参数登记，待实测）。

【产出】轮换与重用检测流程（含撤销范围与通知动作）

【判据】旧 refresh 再用一次即触发整个 family 撤销。

【审】`audit/godot/account-security.md#11`

### Step 3　撤销的是服务端 refresh family，⛔ 不是清本地文件　`[account-security/03#S3]`

【读】`howto/godot/account-security.md#7. Godot 侧的正确位置`

【做】
改密 / 登出 / 确认盗号时，撤销**服务端 refresh family**；
客户端清内存与本地缓存只是收尾。
⛔ 只删客户端 token —— 服务端会话仍然有效，
表现为"点了退出登录，用抓到的旧 token 还能操作"，
⛔ 而客户端确实"已经登出了"（UI 已回登录页）。

ⓘ 反过来同样成立：**清了本地文件 ≠ 已登出**。
⛔ 判据是服务端侧的状态，不是客户端的表现。

【产出】登出 / 改密 / 盗号三条撤销路径（均含服务端调用）

【判据】三条路径执行后，服务端对应会话全部不可再用。

【审】`audit/godot/account-security.md#12`、`audit/godot/account-security.md#32`

### Step 4　高危操作必须重新验证　`[account-security/03#S4]`

【读】`howto/godot/account-security.md#2. 会话`

【做】
改邮箱、换手机、改支付、解绑 2FA 这类操作，
要求**当前的第二因素验证**，⛔ 不接受昨天的 access token 单向放行。
⛔ 用旧 access 放行 —— 拿到一张旧 token 就能改绑定，
表现为"账号被改绑邮箱后彻底拿不回来"，
⛔ 而请求本身携带的是一张**合法** token。

ⓘ 这条在正常测试中测不出：合法用户带着合法 token 做合法操作，
⛔ 只有"token 已经泄露"这个前提成立时才是漏洞。

【产出】高危操作清单 + 各自的重新验证要求

【判据】高危操作用旧 token 一律被要求重新验证。

【审】`audit/godot/account-security.md#13`

### Step 5　登录成功发新会话，多端列表在服务端　`[account-security/03#S5]`

【读】`howto/godot/account-security.md#2. 会话`

【做】
登录成功后**发新会话**并令旧匿名会话立即失效（防会话固定）；
多端政策由**服务端保存会话列表**。
⛔ 登录成功沿用旧会话 —— 攻击者先拿到一个匿名会话再诱导受害者登录，
于是这个会话变成了受害者的，⛔ 而登录流程一切正常。

⛔ 客户端互相通知踢人 —— 下线的一方收不到通知就永远在线，
表现为"明明踢了，对方还在"，⛔ 而踢人请求确实发出去了。

【产出】会话生命周期（创建 / 轮换 / 失效）+ 服务端会话列表结构

【判据】登录前后会话 ID 不同；踢人后对方会话在服务端已失效。

【审】`audit/godot/account-security.md#15`、`audit/godot/account-security.md#14`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：短命 access + 可吊销 refresh + 轮换
# ⛔ 常量为占位，实际取值见 00 参数登记，待实测
const ACCESS_TTL_SEC := 600
const REAUTH_REQUIRED := ["change_email", "change_phone", "change_payment", "unbind_2fa"]

# 401 只触发一次轮换，⛔ 不无限重试（会放大成登录雪崩）
func on_unauthorized() -> void:
    if _refresh_used_this_round:
        clear_local_state()
        goto_login()
        return
    _refresh_used_this_round = true
    _auth.refresh()

# ⛔ 登出/改密必须调服务端撤销，清本地只是收尾
func logout() -> void:
    _auth.revoke_family()
    clear_local_state()

# 高危操作：⛔ 不接受旧 access 单向放行
func needs_reauth(action: String) -> bool:
    return action in REAUTH_REQUIRED
```

## 4. 验收清单

- [ ] access 分钟级，refresh 可吊销
- [ ] 旧 refresh 再用一次即撤销整个 family
- [ ] 改密/登出后服务端会话失效
- [ ] 高危操作要求重新验证
- [ ] 登录前后会话 ID 不同；踢人在服务端生效

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 改了密码旧设备还能玩 | 无吊销能力 | S1 |
| 盗号者长期在线 | refresh 不轮换 | S2 |
| 点了退出还能用旧 token | 只清了本地 | S3 |
| 账号被改绑邮箱 | 高危用旧 token 放行 | S4 |
| 踢了人对方还在 | 客户端互相通知 | S5 |
