# 账号安全、生命周期与风控 —— 域流程总览

> ⚠ **第 0 步：先定「身份 / 凭证 / 会话 / 角色」四者的唯一键。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 登录 / 注册接入平台账号 | 01 → 03 → 07 |
| 自有账号（密码登录） | 01 → 02 → 03 → 07 |
| 加二次验证 / 恢复码 | 01 → 04 → 07 |
| 找回与申诉流程 | 01 → 05 → 07 |
| 盗号风控与处置 | 01 → 05 → 06 → 07 |
| 注销 / 封禁 / 转服 / 合并 | 01 → 06 → 07 |
| 全套账号体系 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过** ——
登录、找回、风控、注销看起来是四件事，⛔ 但它们共用同一套**唯一键与授权表**。
不先定这四者的边界，后面加再多加密和风控都只是**把越权入口包起来**：
表现为"接口都鉴权了，改个 ID 还是能看别人的角色"，
而排查时每个接口单看都是"已鉴权"。

⛔ **03 的核心是"可撤销"，不是"生成 token"**：
先把 JWT 签出来、后面再补吊销，会在改密、登出、确认盗号时成片返工——
⛔ 因为无状态 JWT 没有服务端状态可撤。

⛔ **06 的注销不能排到最后补**：
注销要动的是**可识别个人信息的全部**（登录、支付、实名、绑定），
若数据模型一开始就把"账号"和"角色"混在一张表里，
⛔ 到合规审查时才拆，等于重做数据层。

ⓘ 若本次只是"接一个平台 SDK 的登录按钮"，那是接入工作，不套本域。
ⓘ 若只是**排查某个接口越权**，先看 `security` 域的服务端权威口径，再回本域 01/03。

ⓘ 分工：
- `howto/godot/account-security.md` 讲**各环节的技術做法**（口令哈希、会话轮换、TOTP、找回分级、Godot 侧边界）
- `audit/godot/account-security.md` 讲**反模式清单**
- 本域讲**这些环节按什么顺序做、怎么保证出包与敌意环境下仍然对**

⛔ 若本域某步需要"会话时长""找回码长度""注销宽限期"这类数值，
指向项目实测或法务确认，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 身份主键与 Godot 侧边界 | — | 四对象唯一键 + 授权表 + 凭据存放与传输口径 |
| 02 | 口令存储与强度校验 | 01 | 慢哈希选型 + 实测参数 + 唯一 salt + 模糊提示 |
| 03 | 会话与令牌轮换 | 01 | 服务端可吊销 + refresh 轮换与重用撤销 + 高危重验证 |
| 04 | 二次验证与恢复码 | 01, 03 | TOTP 窗口口径 + 恢复码哈希 + CSPRNG 随机源 |
| 05 | 找回申诉与风控处置 | 01, 03, 04 | 证据三级 + 分级冻结 + 安全降级 + 日志脱敏 |
| 06 | 生命周期：注销 / 封禁 / 转服 / 合并 | 01, 03 | 删除义务口径 + 封禁粒度 + 幂等转移键 + 合并安全失败 |
| 07 | 账号安全验收 | 全部 | 敌意环境实测 + 出包后校验生效实测 |

⚠ **01 要在第一个业务接口写出来之前**：
那时"账号 ID 从哪来"已经被每个接口各写一遍，
⛔ 统一意味着改所有接口。

⚠ **03 的吊销能力要随登录一起做，不能最后补**：
补的时候会发现 access token 已经发到了客户端且无法失效，
⛔ 表现为"改了密码，旧设备还能继续玩"。

⚠ **05 的客服权限要随找回一起定，不能等客服系统做完**：
等系统做完，权限已经按"客服能操作一切"实现了，
⛔ 表现为"客服能单方面跳过第二因素"，而这是最难被社工审计发现的一条。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是单个登录接口，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `security` 域 安全 | 反外挂、存档加密、请求签名见 `security`，⛔ 本域只定**账号侧**凭据，不另定签名口径 |
| `compliance` 域 合规 | 删除权、去标识化、未成年人校验见 `compliance`，⛔ 本域只定注销的**执行顺序** |
| `sharding` 域 分服合服 | 跨服 ID 与单一写者见 `sharding`，⛔ 转移单的幂等键由本域 06 定 |
| `analytics` 域 埋点 | 登录事件的字段与同意状态见 `analytics`，⛔ 本域只定**哪些字段绝不进埋点** |
| `social` 域 社交 | 好友关系与举报见 `social`，⛔ 本域只定封禁对社交功能的**作用粒度** |
| `platform-export` 域 发布 | 平台 SDK 与构建签名见 `platform-export`，⛔ 本域只定"Godot 只接收一次性回调码" |
| `mobile` 域 移动端 | 移动端凭据进平台安全存储见 `mobile`，⛔ 本域不另定移动端口径 |
| `ops` 域 运营 | 补偿发放与工单见 `ops`，⛔ 本域只定**申诉工单的随机分配与双人复核** |
| `platform-services` | ⓘ howto 层，暂无 flow 域 —— 平台账号与令牌见该篇 |
| `backend-stability` 域 稳定性 | 登录峰值与限流见 `backend-stability`，⛔ 本域不另定限流口径 |

⛔ 而这类偶发在测试环境几乎不出现。
