# 07 合规验收（合规域）

> **本步交付**：敌意环境实测 + 声明一致性核对 + 法务复核闭环
> **对应**：流程 `howto/godot/compliance.md` · 审核 `audit/godot/compliance.md`

## 0. 交付物定义

合规域的 bug **在正常流程下几乎全部测不出来** ——
只在**改包、改系统时间、未授权追踪、注销中途失败、元数据缺项**时才出现。
所以本步验收的不是"功能能跑"，而是这些事发生后
**声明仍与实际一致、删除仍可完成、拦截仍然生效**。

⛔ **全流程跑一遍全部通过，是最危险的假通过。**

## 2. 工序

### Step 1　抓包核对声明与实际一致　`[compliance/07#S1]`

【读】`howto/godot/compliance.md#7. 商店：隐私声明是可验证事实，不是营销文案`

【做】
首次启动抓包，把实际出现的域名、字段、设备标识符
与提交的隐私清单逐项比对。
⛔ 提交前不抓包——SDK 初始化时机与 A/B 分支都会影响实际请求，
⛔ 只测一条路径会漏掉"部分用户才触发"的数据流。

【产出】抓包比对记录（实际 vs 声明）

【判据】实际请求中不存在声明里没有的数据项。

【审】`audit/godot/compliance.md#56`

### Step 2　⛔ 未授权追踪场景必须实测　`[compliance/07#S2]`

【读】`howto/godot/compliance.md#⛔ 追踪域未授权时，网络请求会失败`

【做】
在**未授权 ATT** 的状态下跑完整流程，检查基础功能是否仍可用。
官方原文：未授予追踪许可时，对追踪域的请求会失败。
⛔ 只在已授权状态下测——未授权才是相当比例用户的真实状态，
⛔ 而失败表现是"部分功能静默不可用"，
⛔ 在已授权环境下永远不会复现。

【产出】未授权状态下的功能可用性记录

【判据】未授权时，崩溃上报、远程配置、登录鉴权均正常。

【审】`audit/godot/compliance.md#57`

### Step 3　注销走完状态机全链路　`[compliance/07#S3]`

【读】`howto/godot/compliance.md#删除权要做成状态机，不是一句 DELETE`

【做】
走完申请 → 冷却 → 逐项删除 → 完成，
并**故意制造一个删除失败**验证有留痕。
⛔ 只测成功路径——失败路径从未被执行过，
⛔ 而"用户以为已注销但数据还在"恰恰只发生在失败路径上。

【产出】注销全链路记录（含失败态留痕）

【判据】制造失败后有明确记录，不是静默跳过。

【审】`audit/godot/compliance.md#58`

### Step 4　未成年人限额用改时间做敌意测试　`[compliance/07#S4]`

【读】`howto/godot/compliance.md#2. 实名与防沉迷：服务端强控闭环`

【做】
把系统时间改到极端值，验证时长与限额判定仍由服务端生效。
⛔ 只测正常时间——系统时钟可被玩家手动设置，
⛔ 客户端本地计时会因此失效，
⛔ 而这个失效只在改时间后才出现，正常环境下全绿。

【产出】改时间实测记录（两个极端各一份）

【判据】改时间后客户端展示与服务端判定仍一致。

【审】`audit/godot/compliance.md#59`

### Step 5　构建元数据缺项拦截要实测　`[compliance/07#S5]`

【读】`howto/godot/compliance.md#8. 构建元数据里应该写进去的东西`

【做】
故意缺一项元数据走发布流程，验证被阻断。
⛔ 只测正常发布——门禁从未在失败路径上被验证过，
⛔ 而门禁失效的后果（发布后无法举证）只在真缺项时才暴露。

【产出】缺项拦截实测记录

【判据】缺任一项元数据都被阻断，无一例外。

【审】`audit/godot/compliance.md#60`

### Step 6　⛔ 法务复核项未闭环，不上线　`[compliance/07#S6]`

【读】`howto/godot/compliance.md#9. 待核对项（运行时验证）`

【做】
把所有标注"待法务复核"的项列为上线阻断项，逐项闭环。
⛔ 带着未复核项上线——法律文本会修订，
⛔ 未复核意味着线上可能正在执行一条已失效或错误的规则，
⛔ 而这种错误不会报错，只表现为"某些用户被莫名限制"。

【产出】法务复核闭环清单（每项有复核人与日期）

【判据】不存在仍标"待核对"却已上线的项。

【审】`audit/godot/compliance.md#61`

## 3. 验收清单

- [ ] 抓包比对：实际请求中无未声明数据项
- [ ] ⛔ 未授权追踪状态下基础功能仍可用
- [ ] 注销失败路径有留痕，不静默
- [ ] 改系统时间后判定仍由服务端生效
- [ ] 元数据缺项被发布门禁阻断
- [ ] ⛔ 无"待法务复核"项带病上线

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 审核被拒：声明与实际不符 | 提交前未抓包 | S1 |
| 部分用户功能静默不可用 | 未测未授权场景 | S2 |
| 以为已注销但数据还在 | 只测注销成功路径 | S3 |
| 改时间即可绕过限制 | 只在正常时间测 | S4 |
| 发布后无法举证 | 门禁未在失败路径验证 | S5 |
| 用户被莫名限制 | 未复核项带病上线 | S6 |
