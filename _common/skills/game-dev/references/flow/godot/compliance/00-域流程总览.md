# 合规（发行地基 / 数据声明 / 未成年人 / 删除权 / SDK 治理 / 商店提交）—— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次发行地区与目标挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只在中国大陆上线，先把版号与防沉迷做对 | 01 → 03 → 07 |
| 要上海外（GDPR / CCPA） | 01 → 02 → 04 → 07 |
| 有 UGC、第三方 SDK、广告归因 | 01 → 02 → 05 → 06 → 07 |
| 商店提交阶段才发现声明对不上 | 02 → 05 → 06 → 07（⛔ 顺序已反，见第 3 节） |
| 全套合规 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 无论如何不能跳过** ——
发行地区决定后面每一栏适用哪套规则，
⛔ 地区没定就做防沉迷或隐私，等于先建后拆。

ⓘ 分工：
- `howto/godot/compliance.md` 讲**单个要素怎么满足**（版号、防沉迷、隐私、UGC、海外、商店字段）
- 本域讲**这些要素按什么顺序做、哪些是发布门禁、怎么验收**

⚠ 本域多处标注"由法务复核原文"。
⛔ 那不是没写完：**法律文本会修订**，
⛔ 不得凭行业惯例或旧文档编一个数字出来（见 01/S5）。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 发行地区与主体地基 | — | 地区清单 + 主体资质 + 三栏分清 + 构建元数据字段表 |
| 02 | 数据收集清单与声明一致 | 01 | 数据地图 + 最小必要判定 + 声明与实际一致校验 |
| 03 | 未成年人与身份校验 | 01 | 登录前置实名 + 服务端强控闭环 + 限额硬控 |
| 04 | 删除权与数据生命周期 | 01, 02 | 注销状态机 + 保留期限 + 出境判定 |
| 05 | 第三方 SDK 与 UGC 治理 | 01, 02 | SDK 清单与责任人 + UGC 服务端审核 + 处置留痕 |
| 06 | 商店提交与构建元数据 | 02, 05 | 包标识与导出约束 + 元数据门禁 + 抓包验证 |
| 07 | 合规验收 | 全部 | 敌意环境实测 + 声明一致性核对 + 法务复核闭环 |

⚠ **02 必须在 05 之前**：SDK 的数据流是数据地图的一部分，
⛔ 先接 SDK 再补清单，等于先产生数据再追认声明——
已采集的部分无法追溯。

⚠ **03 与 04 都必须在 06 之前**：商店问卷会问到未成年人政策与删除入口，
⛔ 两者没做就提交，声明必然与实际不符。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `analytics` 域 数据分析 | 同意状态与数据地图同源；⛔ 同意前零采集（见 02/S5） |
| `monetization` 域 商业化 | 充值限额与概率公示是 03 / 06 的输入 |
| `social` 域 社交 | UGC 审核、举报留痕、聊天保存期限，见 04 / 05 |
| `save` 域 存档 | 注销状态机与存档删除走同一事务，见 04 |
| `hotupdate` 域 热更 | 屏蔽词库版本 / 防沉迷版本进元数据，见 06/S4 |
| `account-security` 域 账号安全 | 实名与身份校验的凭据存放见 `account-security/01#S4`，⛔ 本域只定合规义务不另定存放口径 |
| `platform-export` 域 导出发布 | Bundle ID 与权限清单见 `platform-export/04`、`platform-export/05`；⛔ 法务口径仍在本域 06 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**，
⛔ 不许在各处偷偷转格式。

## 3. 本域最容易做反的顺序

⛔ **先做完功能，到商店提交阶段才补合规（06 提前、01/02 靠后）。**

"游戏能玩了"是最直观的验收点，
于是先接 SDK、先上广告归因、先做充值，
⚠ 而此时发行地区没定、数据地图不存在、同意开关还没做。

⛔ 后果链：
SDK 已接 → 数据已采集但说不清收集了什么 → 商店问卷只能凭印象填 →
声明与实际不一致 → 审核被拒 →
为修复它补数据地图 → 但同意前已采集的部分无法追溯 →
⛔ 而此时把广告域名填进追踪域列表以求"合规" →
未授权 ATT 的用户对这些域的请求**全部失败**（见 02/S4）→
变现与统计在部分用户上静默失效，且不报错。

⚠ 这些补丁会让 01 / 02 再也没法正确落地——
因为到处都已经有了"未声明的数据流"。

✅ 正确顺序：先定地区与主体（01），
再钉死数据地图与声明（02），然后才是未成年人（03）、删除权（04）、SDK 治理（05）、提交（06）。
