# 06 商店提交与构建元数据（合规域）

> **本步交付**：包标识与导出约束 + 元数据门禁 + 抓包验证
> **对应**：流程 `howto/godot/compliance.md` · 审核 `audit/godot/compliance.md`

## 0. 交付物定义

1. ⛔ Bundle ID 未靠大小写区分不同包
2. ⛔ 导出项目名不带空格、不与项目目录同名
3. Team ID 与 Bundle ID 已填（留空会抛错）
4. 构建元数据清单作为发布门禁，缺项不发
5. 隐私声明经抓包验证，与实际数据流一致
6. 版本号递增且符合格式约束

## 1. 前置检查清单

- [ ] Bundle ID 未用大小写区分包
- [ ] 导出项目名无空格、未与项目目录同名
- [ ] Team ID 与 Bundle ID 均已填
- [ ] 构建元数据门禁已生效
- [ ] 隐私声明已抓包核对
- [ ] 版本号已递增且格式合法

## 2. 工序

### Step 1　⛔ Bundle ID 大小写不敏感，不能靠它区分包　`[compliance/06#S1]`

【读】`howto/godot/compliance.md#⛔ Bundle ID 大小写不敏感`

【做】
确认不同包之间**不是只靠大小写区分**。
官方原文：Bundle IDs 大小写不敏感（依 `CFBundleIdentifier`）。
⛔ 用 `com.example.MyGame` 与 `com.example.mygame` 区分国内版/海外版——
系统认为是同一个应用，失败发生在签名与安装阶段，
表现为覆盖安装或签名冲突，⛔ 且没有任何日志说明是大小写问题。

【产出】各包的 Bundle ID 对照（确认非仅大小写差异）

【判据】任意两个包的 Bundle ID 转小写后互不相同。

【审】`audit/godot/compliance.md#50`

### Step 2　⛔ 导出项目名不带空格、不与项目目录同名　`[compliance/06#S2]`

【读】`howto/godot/compliance.md#⛔ 导出项目名的两个约束`

【做】
导出 Xcode 项目时，项目名不带空格，且与被导出的 Godot 项目目录不同名。
官方 Note：带空格可导致 Xcode 项目文件损坏；同名会导致 Xcode 签名问题。
⛔ 两条都在 Godot 侧**全程无报错**——导出成功、文件也在，
⛔ 损坏要到 Xcode 里打开才显现，此时已难以回溯是哪个名字引起的。

【产出】导出命名约定（无空格、不同名）

【判据】导出名无空格，且不等于源项目目录名。

【审】`audit/godot/compliance.md#51`

### Step 3　Team ID 与 Bundle ID 留空会直接抛错　`[compliance/06#S3]`

【读】`howto/godot/compliance.md#⛔ 导出项目名的两个约束`

【做】
导出前确认 `App Store Team ID` 与 `Bundle Identifier` 均已填。
官方：留空会导致导出器直接抛错。
⛔ 这是本域少有的**会报错**的一条——
⛔ 但它报错在导出末尾，前面的配置工作全部白做，
所以应在提交前先自查，而不是等抛错再补。

【产出】导出配置自查项（Team ID / Bundle ID 非空）

【判据】导出前两项均非空，不依赖导出器报错才发现。

【审】`audit/godot/compliance.md#52`

### Step 4　构建元数据清单作为发布门禁　`[compliance/06#S4]`

【读】`howto/godot/compliance.md#8. 构建元数据里应该写进去的东西`

【做】
把元数据清单做成发布门禁：缺一项就不发。
⛔ 只当文档——文档会过期而门禁不会，
⛔ 且"缺一项"的后果在发布后才显现（无法举证、无法回溯），
那时包已经出去了。

【产出】发布门禁校验（元数据缺项即阻断）

【判据】故意缺一项元数据，发布被阻断。

【审】`audit/godot/compliance.md#53`

### Step 5　隐私声明用抓包验证，不靠人工填写　`[compliance/06#S5]`

【读】`howto/godot/compliance.md#7. 商店：隐私声明是可验证事实，不是营销文案`

【做】
从首次启动抓包，识别域名、SDK 初始化、请求字段、设备标识符，
映射到问卷类别后再提交。
⛔ 凭印象填问卷——SDK 升级、域名变更都不会反映到问卷上，
⛔ 而声明与实际不一致会同时触发商店审核与监管风险。

【产出】抓包验证记录（域名/字段/标识符 → 问卷类别）

【判据】问卷里每一项都有抓包证据对应。

【审】`audit/godot/compliance.md#54`

### Step 6　版本号递增且符合格式约束　`[compliance/06#S6]`

【读】`howto/godot/compliance.md#8. 构建元数据里应该写进去的东西`

【做】
版本号每次发布递增，且符合商店格式要求（如 iOS `short_version` 仅数字与句点）。
⛔ 不递增——商店会拒收；
⛔ 而格式非法同样拒收，且两者的错误信息都不指向"版本号没改"。
ⓘ 版本号同时是 analytics 域的事件可比性依据，两处必须同源。

【产出】版本号递增校验（发布前）

【判据】新版本号大于上一版，且格式合法。

【审】`audit/godot/compliance.md#55`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：发布门禁（元数据缺项与版本号未递增都阻断）
const META_FIELDS := [
    "publish_contract_no", "approval_no", "publication_no", "operator",
    "version_sha", "script_version", "wordlib_version", "antidiction_version",
    "privacy_policy_version", "sdk_sheet_version", "datamap_version",
]

func verify_release(meta: Dictionary, new_ver: String, old_ver: String) -> PackedStringArray:
    var errs: PackedStringArray = []
    for k in META_FIELDS:
        if not meta.has(k) or str(meta[k]).is_empty():
            errs.append("missing meta: " + k)
    if not _version_gt(new_ver, old_ver):
        errs.append("version not incremented: " + new_ver)
    return errs

func _version_gt(a: String, b: String) -> bool:
    var pa := a.split(".")
    var pb := b.split(".")
    for i in range(maxi(pa.size(), pb.size())):
        var x := int(pa[i]) if i < pa.size() else 0
        var y := int(pb[i]) if i < pb.size() else 0
        if x != y:
            return x > y
    return false
```

## 4. 验收清单

- [ ] 任意两包 Bundle ID 转小写后互不相同
- [ ] 导出名无空格、不与源项目目录同名
- [ ] Team ID 与 Bundle ID 导出前已自查非空
- [ ] 故意缺一项元数据，发布被阻断
- [ ] 问卷每项都有抓包证据
- [ ] 版本号已递增且格式合法

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 覆盖安装 / 签名冲突 | 靠大小写区分包 | S1 |
| Xcode 项目损坏、签名失败 | 导出名带空格或同名 | S2 |
| 导出末尾才报错、配置白做 | 未先自查 Team ID | S3 |
| 发布后无法举证 | 元数据只当文档 | S4 |
| 声明与实际不一致 | 凭印象填问卷 | S5 |
| 商店拒收 | 版本号未递增或格式非法 | S6 |
