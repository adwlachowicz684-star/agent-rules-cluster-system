# 04 删除权与数据生命周期（合规域）

> **本步交付**：注销状态机 + 保留期限 + 出境判定
> **对应**：流程 `howto/godot/compliance.md` · 审核 `audit/godot/compliance.md`

## 0. 交付物定义

1. 注销是**状态机**，不是一句 DELETE
2. 删除过程可查、可证明、可完成
3. 保留期限按最小必要原则定，⛔ 不编天数
4. ⛔ 出境是目的 × 类型 × 人数的组合判定，不是布尔值
5. 14 岁以下与敏感信息单独处理

## 1. 前置检查清单

- [ ] 注销流程是状态机，有中间态
- [ ] 每个中间态可查询、可证明已完成
- [ ] 保留期限已由最小必要原则定（非编造）
- [ ] ⛔ 出境按三要素组合判定
- [ ] 14 岁以下与敏感信息有单独路径

## 2. 工序

### Step 1　⛔ 注销不是立即全量物理抹除，要做成状态机　`[compliance/04#S1]`

【读】`howto/godot/compliance.md#删除权要做成状态机，不是一句 DELETE`

【做】
把注销建模为状态机：申请 → 冷却 → 各存储逐项删除 → 完成/失败。
⛔ 一句 DELETE 直接抹用户行——下游的日志、订单、举报记录仍留着同一份个人信息，
⛔ 结果是"用户表删了但数据还在"，既没完成删除义务，也没留下完成证据。

【产出】注销状态机定义（含中间态与失败态）

【判据】能查询任一注销申请当前处于哪个状态。

【审】`audit/godot/compliance.md#40`

### Step 2　删除要可查、可证明、可完成　`[compliance/04#S2]`

【读】`howto/godot/compliance.md#4. 隐私与删除权：注销 ≠ 立即全量物理抹除`

【做】
每个删除动作留痕，最终产出可举证的完成记录。
⛔ 删除失败时静默——用户认为已注销而数据仍在，
⛔ 且没有任何记录能说明哪里没删掉，无法补救也无法举证。

【产出】删除留痕 + 完成证明（可导出）

【判据】删除失败时有明确记录，不是静默跳过。

【审】`audit/godot/compliance.md#41`

### Step 3　保留期限按最小必要原则定，⛔ 不编天数　`[compliance/04#S3]`

【读】`howto/godot/compliance.md#PIPL（《个人信息保护法》，2021-11-01 施行）`

【做】
逐类数据定保留期限，依据是最小必要原则。
⛔ 凭惯例填一个统一天数——不同数据的必要性完全不同
（如订单凭证 vs 行为日志），
⛔ 统一天数要么过短（无法举证）要么过长（超出必要），
且填进去后没人会再复核。

【产出】按数据分类的保留期限表（含依据）

【判据】每类数据的期限都能说出必要性依据，不是统一值。

【审】`audit/godot/compliance.md#42`

### Step 4　⛔ 数据出境是三要素组合，不是布尔值　`[compliance/04#S4]`

【读】`howto/godot/compliance.md#数据出境是目的 × 类型 × 人数的组合，不是布尔值`

【做】
按目的 × 类型 × 人数三个维度组合判定是否触发出境义务。
⛔ 当成一个"是否出境"的开关——三要素任一变化都会改变结论，
⛔ 布尔开关无法表达"这类数据出境、那类不出"，
结果是该评估的没评估、不该拦的被拦。

【产出】三要素判定表（目的 / 类型 / 人数 → 是否触发）

【判据】改变任一要素，判定结论随之改变。

【审】`audit/godot/compliance.md#43`

### Step 5　14 岁以下与敏感信息单独处理　`[compliance/04#S5]`

【读】`howto/godot/compliance.md#14 岁以下与敏感信息`

【做】
14 岁以下与敏感个人信息走单独路径（单独同意、更短保留、更高保护）。
⛔ 与普通个人信息同路径处理——单独同意是硬性要求，
⛔ 混在同路径里意味着从未取得过有效的单独同意，
而这在流程上完全看不出来。

【产出】14 岁以下与敏感信息的单独处理路径

【判据】存在独立的单独同意流程，不是混在总同意里。

【审】`audit/godot/compliance.md#44`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：注销状态机（⛔ 不是一句 DELETE）
enum DeleteState { APPLIED, COOLING, DELETING, DONE, FAILED }

var _state: int = DeleteState.APPLIED
var _failed_items: PackedStringArray = []

func current_state() -> int:
    return _state

func mark_failed(item: String) -> void:
    # ⛔ 失败必须留痕：静默跳过会导致"以为删了其实还在"
    _failed_items.append(item)
    _state = DeleteState.FAILED
```

## 4. 验收清单

- [ ] 注销有中间态，可查询当前状态
- [ ] 删除失败有留痕，不静默
- [ ] 每类数据保留期限有依据，非统一值
- [ ] ⛔ 出境按目的 × 类型 × 人数三要素判定
- [ ] 14 岁以下与敏感信息有单独同意流程

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 用户表删了但日志里还有 | 一句 DELETE | S1 |
| 无法证明已删除 | 无留痕 | S2 |
| 期限过长/过短 | 统一填一个天数 | S3 |
| 该评估的没评估 | 出境当布尔开关 | S4 |
| 从未取得单独同意 | 敏感信息混同路径 | S5 |
