# 03 未成年人与身份校验（合规域）

> **本步交付**：登录前置实名 + 服务端强控闭环 + 限额硬控
> **对应**：流程 `howto/godot/compliance.md` · 审核 `audit/godot/compliance.md`

## 0. 交付物定义

1. 实名是**登录前置**，不是充值前置
2. 防沉迷时段与充值限额由**服务端强控**
3. 限额是法条数字，硬控且不可配置化
4. 客户端提示只是展示，不构成合规
5. ⚠ 各地差异不硬编码，未核实项保持待核对

## 1. 前置检查清单

- [ ] 实名已置于登录流程之前
- [ ] 时段与限额判定在服务端
- [ ] ⛔ 限额数值来自法条原文且硬控
- [ ] 客户端提示与服务端判定分离
- [ ] ⚠ 各地差异未硬编码（韩国等项仍为待核对）

## 2. 工序

### Step 1　实名是登录前置，不是充值前置　`[compliance/03#S1]`

【读】`howto/godot/compliance.md#实名是登录前置，不是充值前置`

【做】
把实名校验放在登录之后、进入游戏之前。
⛔ 放在充值前——未实名玩家可以完整游玩，
到充值时才校验，⛔ 而防沉迷的时段限制对未实名账号无法生效，
等于绕过了整个未成年人保护闭环。

【产出】实名在登录流程中的位置（登录后、进游戏前）

【判据】未实名账号无法进入游戏，不只是无法充值。

【审】`audit/godot/compliance.md#35`

### Step 2　⛔ 时段与限额必须由服务端强控　`[compliance/03#S2]`

【读】`howto/godot/compliance.md#2. 实名与防沉迷：服务端强控闭环`

【做】
时段与限额的判定与拦截全部在服务端完成。
⛔ 把判定放在客户端——客户端可被改包绕过，
⛔ 而且一旦判定在客户端，服务端日志里就没有该次拦截记录，
⛔ 无法向监管举证"已经拦了"。

【产出】服务端判定与拦截链路 + 拦截日志

【判据】改包绕过客户端提示后，服务端仍然拦下且有日志记录。

【审】`audit/godot/compliance.md#36`

### Step 3　充值限额是法条数字，硬控不可配置化　`[compliance/03#S3]`

【读】`howto/godot/compliance.md#充值限额（法条数字，必须硬控）`

【做】
限额取值来自法条原文，写成硬控逻辑，
⛔ 不做成运营可在后台调整的配置项。
⛔ 配置化——一旦可调，就存在被调高且不留下合规评审记录的路径，
⛔ 而举证时需要证明"取值始终是法条数字"，配置项做不到这一点。

【产出】限额硬控实现（取值来自法条，不可运行时调整）

【判据】不存在任何后台或远程配置能改变该限额。

【审】`audit/godot/compliance.md#37`

### Step 4　客户端提示只是展示，不构成合规　`[compliance/03#S4]`

【读】`howto/godot/compliance.md#服务端要做的事`

【做】
客户端只做展示与引导，所有判定结果由服务端下发。
⛔ 客户端自己算时长并弹提示——本地计时可被改系统时间绕过
（⛔ 系统时钟可被玩家手动设置，
精确计时须用单调的 `get_ticks_usec/msec`），
⛔ 且客户端算出的结果与服务端账不一致时无法对齐。

【产出】服务端下发判定结果，客户端纯展示

【判据】改系统时间后客户端时长显示与服务端判定仍一致。

【审】`audit/godot/compliance.md#38`

### Step 5　⚠ 各地差异不得硬编码，未核实的保持待核对　`[compliance/03#S5]`

【读】`howto/godot/compliance.md#韩国`

【做】
各地规则做成可配置的地区策略，
⛔ 未核实的部分一律保持"待核对"，不得凭印象写死。
⛔ 硬编码未核实的规则（如某地区宵禁是否已废止）——
规则若已变更，线上会持续执行一条已经失效的限制，
⛔ 表现为该地区玩家在特定时段无法登录，且不报错。

【产出】地区策略表（已核实项填值，未核实项标待核对）

【判据】策略表里不存在"凭印象填的"地区规则。

【审】`audit/godot/compliance.md#39`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：客户端只展示，判定由服务端下发
# ⛔ 不在客户端算时长：系统时钟可被玩家设置，须用单调 ticks
var _play_start_msec := Time.get_ticks_msec()

func _elapsed_msec() -> int:
    return Time.get_ticks_msec() - _play_start_msec

# 服务端下发的判定结果，客户端只负责展示
func _on_server_verdict(verdict: Dictionary) -> void:
    if bool(verdict.get("blocked", false)):
        _show_block_dialog(str(verdict.get("reason", "")))
```

## 4. 验收清单

- [ ] 未实名账号无法进入游戏（不只是无法充值）
- [ ] 改包绕过客户端提示后，服务端仍拦下且有日志
- [ ] ⛔ 无任何后台或远程配置可改变充值限额
- [ ] 改系统时间后客户端展示与服务端判定一致
- [ ] ⚠ 策略表中无凭印象填的地区规则

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 未实名玩家可完整游玩 | 实名做在充值前 | S1 |
| 拦截无日志、无法举证 | 判定在客户端 | S2 |
| 限额被后台调高 | 限额配置化 | S3 |
| 改系统时间绕过时长限制 | 客户端自己算时长 | S4 |
| 某地区玩家持续无法登录 | 硬编码了已失效的规则 | S5 |
