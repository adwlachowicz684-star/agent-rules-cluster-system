# 04 存档迁移（存档域）

> **前置**：[01-结构设计](01-存档结构设计.md) + [02-读写落盘](02-读写与原子落盘.md)
> **本步交付**：版本链式升级，且**失败能回滚**
> **对应**：流程 `howto/godot/save-migration.md` · 审核 `audit/godot/save-migration.md`

⚠ **存档格式必然要变。问题不是"会不会变"，是"变了怎么办"。**
⛔ 指望"这次改完以后就不改了"是不现实的。

## 0. 交付物定义

1. 有一组 `migrate_vN_to_vNp1()` 函数，每个只做一件事
2. 能从 v1 一路升到当前版本
3. ⚠ **迁移失败能回滚到迁移前的备份**

## 1. 前置检查清单

- [ ] ⚠ 01 里 `save_version` 已存在
- [ ] 02 的原子落盘与 `.bak` 机制已可用
- [ ] ⚠ 已明确"降级比升级危险"（高版本存档被低版本程序读）
- [ ] 已准备好**各版本的老存档样本**（用于回归测试）

## 2. 工序

### Step 1　建迁移链（⛔ 不能跳版）　`[save/04#S1]`

【读】howto/godot/save-migration.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】
```gdscript
const CURRENT_VERSION := 3

static func migrate(data: Dictionary) -> Dictionary:
    var v := int(data.get("save_version", 0))
    while v < CURRENT_VERSION:
        match v:
            1: data = _migrate_1_to_2(data)
            2: data = _migrate_2_to_3(data)
            _: return {}          # ⛔ 未知版本，拒绝而不是猜
        v = int(data.get("save_version", 0))
        if v <= 0 or v > CURRENT_VERSION:
            return {}             # ⚠ 迁移函数没更新版本号 → 死循环保护
    return data
```

⚠ **必须链式单步**（v1→v2→v3），⛔ 不能写 `migrate_1_to_3` ——
中间插入的字段映射会被跳过，且以后插入 v2.5 时无从下手。

【产出】迁移链

【判据】拿一份 v1 存档 → 能升到 v3，且**每一版都有独立函数**

【审】audit/godot/save-migration.md —— 本步相关的具体条目（步骤级即时检查）

### Step 2　⚠ 迁移前备份（不可省略）　`[save/04#S2]`

【读】howto/godot/save-migration.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】迁移前把原文件复制一份到 `slot_N.save.pre_migrate`

【产出】`.pre_migrate` 备份

【判据】人为让迁移抛异常 → 原档仍能被读回

【审】audit/godot/save-migration.md —— 本步相关的具体条目（步骤级即时检查）

### Step 3　每个迁移函数只做一件事　`[save/04#S3]`

【读】howto/godot/save-migration.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】
```gdscript
static func _migrate_1_to_2(data: Dictionary) -> Dictionary:
    # 只做：atk → attack 改名
    for item in data.get("inventory", []):
        if item.has("atk"):
            item["attack"] = item["atk"]
            item.erase("atk")
    data["save_version"] = 2
    return data
```

⚠ 每个函数可单测。⛔ 不要一个函数里改十处——出问题时无法定位是哪一处。

【产出】每个迁移函数 + 对应单测

【判据】每个函数有独立测试，且**用真实老存档样本**跑过

【审】audit/godot/save-migration.md —— 本步相关的具体条目（步骤级即时检查）

### Step 4　⚠ 迁移后重算校验（最易漏）　`[save/04#S4]`

【读】howto/godot/save-migration.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】迁移完成后，**必须重新计算完整性校验**，⛔ 不能保留旧签名

⚠ 旧签名留在上面 = 给新数据一个"已验签"的假象 —— 校验形同虚设。

【产出】迁移后重新签名

【判据】迁移后 dump：checksum 与 payload **匹配**（不是旧的）

【审】audit/godot/save-migration.md —— 本步相关的具体条目（步骤级即时检查）

### Step 5　处理降级　`[save/04#S5]`

【读】howto/godot/save-migration.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】检测版本号 > `CURRENT_VERSION`：
```gdscript
if v > CURRENT_VERSION:
    # ⛔ 不要尝试"降级读取"——缺字段会静默变默认值
    return {}    # 明确拒绝 + 提示玩家更新游戏
```

⚠ **降级比升级危险**：高版本存档被低版本读，缺失字段变默认值，
玩家表现为"装备没了"但文件还在——**无法恢复**。

【产出】降级拒绝逻辑

【判据】用高版本存档喂给低版本程序 → **明确拒绝**，不静默载入

【审】audit/godot/save-migration.md —— 本步相关的具体条目（步骤级即时检查）

### Step 6　回归样本　`[save/04#S6]`

【读】howto/godot/save-migration.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】保存 v1/v2/v3 各至少一份真实存档作为测试样本

⚠ 每次改迁移逻辑，全部样本跑一遍。
⛔ 没有样本的迁移代码 = 没人验证过的迁移代码。

【产出】样本集 + 自动化回归

【判据】改一次迁移 → 全部样本仍能正确升到当前版本

【审】audit/godot/save-migration.md —— 本步相关的具体条目（步骤级即时检查）

## 3. 参考实现

```gdscript
# save_migration.gd — Godot 4.x
class_name SaveMigration extends RefCounted

const CURRENT_VERSION := 3

static func apply(data: Dictionary) -> Dictionary:
    var v := int(data.get("save_version", 0))
    if v > CURRENT_VERSION:
        push_error("存档版本 %d 高于当前 %d，请更新游戏" % [v, CURRENT_VERSION])
        return {}
    var guard := 0
    while v < CURRENT_VERSION:
        guard += 1
        if guard > 64:
            return {}                    # ⚠ 死循环保护
        var next := v + 1
        data = _step(v, data)
        var nv := int(data.get("save_version", 0))
        if nv != next:
            push_error("迁移 v%d→v%d 未更新版本号" % [v, next])
            return {}
        v = nv
    return data

static func _step(from: int, d: Dictionary) -> Dictionary:
    match from:
        1: return _migrate_1_to_2(d)
        2: return _migrate_2_to_3(d)
        _: return {}

static func _migrate_1_to_2(d: Dictionary) -> Dictionary:
    for item in d.get("inventory", []):
        if item.has("atk"):
            item["attack"] = item["atk"]
            item.erase("atk")
    d["save_version"] = 2
    return d

static func _migrate_2_to_3(d: Dictionary) -> Dictionary:
    # 例：暴击率单位 0-100 → 0-1
    if d.has("crit_rate"):
        d["crit_rate"] = float(d["crit_rate"]) / 100.0
    d["save_version"] = 3
    return d
```

## 4. 验收清单

- [ ] 迁移是**链式单步**，⛔ 没有跳版函数
- [ ] 每个迁移函数**只做一件事**且有单测
- [ ] ⚠ 迁移前**有备份**，失败能回滚（实测）
- [ ] ⚠ 迁移后**重新计算校验**（旧签名不保留）
- [ ] 有死循环保护（迁移函数没更新版本号时不会卡死）
- [ ] 高版本存档喂给低版本 → **明确拒绝**，不静默载入
- [ ] 有 v1/v2/v3 真实样本，改迁移后全样本回归通过
- [ ] ⛔ 未知版本号 → 拒绝，不是猜

## 5. 常见返工

⚠ **跳版迁移（`v1→v3`）** —— 中间版本插入时无从下手，且已上线的跳版逻辑要拆开重来。

⚠ **迁移前没备份** —— 迁移抛异常或迁错了，玩家进度直接没了，不可逆。

⚠ **迁移后不重算校验** —— 旧签名留下，校验形同虚设；且下次读档会用错误签名判断。

⚠ **迁移函数不更新 `save_version`** —— 死循环。必须加 guard 并在测试里覆盖。

⚠ **静默降级读取** —— 玩家"装备没了"，且文件本身还在、看起来正常，极难排查。

⚠ **没有老存档样本** —— 迁移代码从没被真正验证过，上线才发现。
