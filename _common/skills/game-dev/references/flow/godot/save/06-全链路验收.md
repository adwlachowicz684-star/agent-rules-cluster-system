# 06 全链路验收（存档域）

> **前置**：01–05 全部验收通过（不上云则跳过 05）
> **本步交付**：一份可签核的验收报告 + 故障演练记录
> **对应**：审核 `audit/godot/save-migration.md` `cloud-save.md` `security.md`

⚠ **存档的 bug 全部在异常路径。** 只测"保存→读取→成功"等于没测。
本步的核心是**故障演练**。

## 0. 交付物定义

1. 全部故障演练用例的执行记录（每个都**真的跑过**）
2. 各版本存档样本的迁移回归结果
3. 一份"哪些情况会丢进度、概率多高"的诚实评估

## 1. 前置检查清单

- [ ] 01–05 各自验收清单全过
- [ ] 有 v1/v2/v3 真实存档样本
- [ ] ⚠ 有办法模拟：杀进程、磁盘满、文件损坏、断网、改系统时间

## 2. 工序

### Step 1　故障演练（必跑）

【做】逐个执行并记录结果：

| # | 故障 | 预期 | 实际 | 过? |
|---|---|---|---|---|
| 1 | 保存写到 50% 杀进程 | 旧档完好可读 | | |
| 2 | 写完 tmp、rename 前杀进程 | 旧档完好 | | |
| 3 | 主档内容改成全零 | 自动退 `.bak` | | |
| 4 | 主档和 `.bak` 都坏 | 明确提示 + **保留损坏文件** | | |
| 5 | 磁盘写满时保存 | 明确报错，旧档完好 | | |
| 6 | 迁移中途抛异常 | 回滚到 `.pre_migrate` | | |
| 7 | 改系统时间到一年后 | 云同步不让旧档赢 | | |
| 8 | 断网时保存 → 联网重开 | 进度正确 | | |
| 9 | 云端放一份坏档 | **拒绝下载**，本地不受影响 | | |
| 10 | 高版本存档喂给低版本程序 | 明确拒绝，不静默载入 | | |

⚠ **这 10 条每条都要真的执行**，⛔ 不能"代码看起来是对的"。

【产出】演练记录

【判据】10/10 通过；任何一条不过 → 退回对应功能点

### Step 2　迁移回归

【做】用 v1/v2/v3 样本各跑一遍完整迁移

【产出】回归结果

【判据】全部升到当前版本且数据正确（不是"没报错"）

### Step 3　改表兼容性验证

【做】改一条配表数值 → 加载老存档 → 确认显示新数值

⚠ 这是在验 01 的"存输入不存结果"是否真的做到了

【产出】兼容性结论

【判据】老存档显示新数值，⛔ 不是旧数值

### Step 4　过 audit 坑表

【做】`audit/godot/save-migration.md` · `cloud-save.md` · `security.md` 逐条

【产出】坑表确认记录

【判据】每条都能说出"我们怎么避免的"

### Step 5　出诚实评估

【做】写清楚：

- 哪些故障下**仍会丢进度**（诚实，不要写"不可能丢"）
- 每种的概率量级
- 玩家可见的提示是什么

⚠ **宣称"永不丢档"是不可信的**。真正重要的是"丢了能被发现、能申诉、能恢复"。

【产出】评估报告

【判据】报告里至少有一条"仍会丢进度"的场景及其处置

## 3. 验收清单（域级总验）

- [ ] 10 条故障演练**全部真跑过**，10/10
- [ ] v1/v2/v3 样本迁移回归通过
- [ ] 改配表 → 老存档显示新数值
- [ ] 三个 audit 坑表逐条过完
- [ ] 评估报告诚实列出了仍会丢档的场景
- [ ] ⛔ 代码中不存在"检测到异常就清空存档"
- [ ] 有版本号的存档从第一天就有
- [ ] 设置与进度分开
- [ ] ⚠ 玩家在每种失败下**都能看到明确提示**（不是静默）

## 4. 常见返工

⚠ **故障演练只跑了一部分** —— 没跑的那部分就是线上事故。

⚠ **"代码看起来对"就勾过** —— 存档 bug 全部在实现细节里，不看运行结果等于没验。

⚠ **宣称永不丢档** —— 一旦发生，客服无法解释，玩家信任崩塌。

⚠ **没有保留损坏文件** —— 玩家申诉时无从查证。

## 5. 完成

存档域完成。⚠ **每次改动存档结构，都要重跑 Step 1 和 Step 2**，
⛔ 不能只改迁移函数不回归。
