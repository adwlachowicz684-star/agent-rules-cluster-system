# 05 云存档接入（存档域）

> **前置**：[02-读写落盘](02-读写与原子落盘.md) + [03-加密完整性](03-加密与完整性.md)
> **本步交付**：多端同步，且**不会静默覆盖玩家进度**
> **对应**：流程 `howto/godot/cloud-save.md` `platform-services.md` · 审核 `audit/godot/cloud-save.md`

⚠ **云存档的头号事故是"静默覆盖"**：玩家在 A 设备玩了 10 小时，
B 设备上的旧存档上传，把 10 小时覆盖掉了，而且没有任何提示。

## 0. 交付物定义

1. 换设备继续玩，进度正确
2. ⚠ **冲突时有明确提示和选择**，不是静默覆盖
3. 离线可玩，联网后正确同步
4. 上传失败不会丢本地进度

## 1. 前置检查清单

- [ ] ⚠ 02、03 已完成 —— **本地必须先牢靠**（云同步会放大本地的损坏）
- [ ] 已选定云后端（Steam Cloud / 平台服务 / 自建）
- [ ] 已确认玩家账号体系
- [ ] ⚠ 已想清楚冲突策略（这是本步的核心设计）

## 2. 工序

### Step 1　⚠ 定冲突策略（先于代码）　`[save/05#S1]`

【读】howto/godot/cloud-save.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】必须明确回答："本地和云端不一致时，谁赢？"

| 策略 | 行为 | 适用 |
|---|---|---|
| **时间戳新者赢** | 静默选新的 | ⚠ 有风险：设备时钟错会让旧的赢 |
| **时间戳 + 提示** | 选新的，但告知玩家 | ✅ 大多数情况 |
| **让玩家选** | 弹窗列出两端进度 | ✅ 高价值进度 |
| **版本号 + 时间戳** | 综合判断 | 复杂 |

⚠ **绝不能"无条件以云端为准"或"无条件以本地为准"** ——
前者会丢离线进度，后者会丢另一设备的进度。

【产出】冲突策略文档

【判据】能说清"什么情况谁赢"，且每种情况都有玩家可见的结果

【审】audit/godot/cloud-save.md —— 本步相关的具体条目（步骤级即时检查）

### Step 2　⚠ 用服务端时间，不用本地时钟　`[save/05#S2]`

【读】howto/godot/cloud-save.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】上传时带上**服务端接收时间**，比较时用服务端时间

⚠ **客户端本地时间可改**（改系统时间就能让旧存档"变成"最新的）。
这与 `howto/godot/security.md` 的"加速检测必须用 `Time.get_ticks_msec()`"是同一类问题。

【产出】时间戳以服务端为准

【判据】手动把设备时间调到一年后 → **不能让旧存档赢**

【审】audit/godot/cloud-save.md —— 本步相关的具体条目（步骤级即时检查）

### Step 3　上传前先比对　`[save/05#S3]`

【读】howto/godot/cloud-save.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】
```text
① 拉取云端元信息（版本号 + 服务端时间戳 + 校验和）
② 与本地比较
③ 不一致 → 按 Step 1 策略处理
④ 一致 → 无需上传
```

⛔ **不要每次启动无条件上传** —— 这是静默覆盖的直接来源

【产出】比对逻辑

【判据】本地进度比云端新 → **不上传**（等待确认），⛔ 不是自动覆盖云端

【审】audit/godot/cloud-save.md —— 本步相关的具体条目（步骤级即时检查）

### Step 4　离线可玩　`[save/05#S4]`

【读】howto/godot/cloud-save.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】
- 离线时正常读写本地
- 记录"有未同步的改动"

⚠ **离线时不要禁用存档**，也不要在联网后强制用云端覆盖本地

【产出】离线可用 + 联网同步

【判据】断网玩 → 关游戏 → 联网重开 → 进度保留且正确合并

### Step 5　上传失败处理　`[save/05#S5]`

【读】howto/godot/cloud-save.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】
- 上传失败**保留本地**，⛔ 不删除

- ⚠ **重试次数有限**，且失败要有可见提示

【产出】失败不丢数据

【判据】断网时保存 → 本地进度完好；联网后自动补传

## 3. 参考实现（结构示意）

```gdscript
# cloud_save.gd — Godot 4.x（结构示意，后端 API 按平台替换）
signal conflict_detected(local: Dictionary, remote: Dictionary)

enum Resolution { USE_LOCAL, USE_REMOTE, ASK }

func sync(slot: int, on_conflict := Resolution.ASK) -> void:
    var local := SaveIo.load_save(slot)
    var meta := await _fetch_remote_meta(slot)     # {server_time, checksum}
    if meta.is_empty():
        await _upload(slot, local)
        return

    var local_time := await _fetch_local_server_time(slot)   # ⚠ 上次同步时的服务端时间
    if local_time > meta.server_time:
        match on_conflict:
            Resolution.USE_LOCAL: await _upload(slot, local)
            Resolution.ASK:
                conflict_detected.emit(local.to_dict(), meta)
                return                              # ⚠ 等玩家选，不自动覆盖
            _: await _download(slot)
    elif local_time < meta.server_time:
        await _download(slot)
    # 相等：无需动作
```

⚠ 这是对**结构**的示意，不是可直接抄的实现——各平台的云存档 API 不同。
ⓘ Steam Cloud 用 `Steam` API；主机平台各有 SDK；自建走 HTTP。

## 4. 验收清单

- [ ] ⛔ 没有"无条件以云端为准"或"无条件以本地为准"
- [ ] 冲突时有**玩家可见**的提示或选择
- [ ] ⚠ 手动改系统时间 → 不能让旧存档赢
- [ ] 断网玩 → 联网重开 → 进度正确
- [ ] 上传失败 → 本地进度完好，不删除
- [ ] 换设备 → 进度同步，**设置不被覆盖**
- [ ] 两端都有改动 → 进入冲突流程，⛔ 不静默选一个
- [ ] ⚠ 云端的坏存档**不会**覆盖本地好存档（校验失败要拒绝下载）



## 5. 常见返工

⚠ **每次启动无条件上传** —— 静默覆盖的直接来源，且事故发生时玩家毫无察觉。

⚠ **用本地时间戳比较** —— 改系统时间即可触发错误覆盖。

⚠ **云端坏档覆盖本地好档** —— 下载前必须校验，⛔ 不能下载了就用。

⚠ **设置跟着进度一起同步** —— 换设备后键位/画质被覆盖，玩家投诉。

⚠ **本地没做原子落盘就上云** —— 本地一次断电损坏，同步到所有设备。

⚠ **上传失败删本地** —— 网络问题时玩家进度全丢。
