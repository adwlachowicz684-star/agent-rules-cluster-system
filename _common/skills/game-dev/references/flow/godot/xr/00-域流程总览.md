# XR（VR/AR）—— 域流程总览

> ⚠ **第 0 步：先定"位姿谁来定、位姿不可信时怎么办"，再写任何交互。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 搭 XR 最小场景、能进能看 | 01 → 07 |
| 加控制器交互与抓取 | 01 → 02 → 04 → 07 |
| 加手部追踪与捏合 | 01 → 02 → 03 → 07 |
| 做移动、传送、舒适度 | 01 → 05 → 07 |
| 空间 UI 与指针 | 01 → 05 → 07 |
| 帧率不达标 / 戴久了晕 | 01 → 06 → 07 |
| 完整 XR 交互 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过** —— 手柄、手、传送、UI 的形态差异很大，
但**"origin 是唯一可移动节点、相机每帧被覆盖"**这一条完全统一。
⛔ 不先定这条，就会写出第二处移动入口，
表现为"相机怎么又飞了"，而排查会被引向追踪或物理。

⛔ **02 要在任何"用手的位置驱动玩法"之前** ——
位姿在真机上**必然**会不可信（遮挡、放桌上、出跟踪范围），
⛔ 反过来先写交互再补降级，等于承认"位姿永远有效"这个前提，
而它是本域唯一一个在正常游玩中必然会被违反的前提。

⛔ **05 的舒适度不能最后补**：移动方式一旦成为事实标准，
后面加选项就是新功能而不是默认项，
表现为"上线后玩家反馈晕"，而开发机上自己转两下没事。

ⓘ 若本次只是**"换一个手柄模型、调一下手的颜色"**，那是美术资源，不套本域。
ⓘ 若只是**排查头显黑屏**，先查 `platform-export` 域的导出与权限，再回本域 01/06。

ⓘ 分工：
- `howto/godot/xr.md` 讲**基础场景、控制器输入、抓取、传送、晕动症**这些要素本身
- `howto/godot/xr-deep.md` 讲**手部追踪与物理交互**（关节 API、pinch、所有权与动量）
- 本域讲**这些要素按什么顺序做、怎么保证真机遮挡与高刷新率下仍然对**

⛔ 若本域某步需要"pinch 阈值""snap turn 角度""目标刷新率"这类细节，
指向项目实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 原点与相机权威地基 | — | 三层职责 + origin 唯一移动入口 + 相机不可信属性清单 |
| 02 | 追踪有效性与位姿降级 | 01 | 两问式判据 + 显式降级路径 + 居中模式 |
| 03 | 手部追踪与 pinch 判定 | 01, 02 | flags 判据 + 归一化 pinch + 速度防抖 |
| 04 | 抓取与释放动量 | 01, 02 | 单一所有权 + 方案选型 + 动量传递 |
| 05 | 移动、空间 UI 与舒适度 | 01 | 四重传送判定 + vignette + 舒适度可配 |
| 06 | 渲染选型与帧预算 | 01 | 渲染器/foveation 自洽 + 设置时机 + 帧预算 |
| 07 | XR 验收 | 全部 | 真机六项敌意实测 |

⚠ **01 的空间模型要在第一个交互做出来之前**：
它决定后面所有"移动谁、以谁为权威"，
⛔ 先写完传送再改权威来源，等于把所有交互重接一遍。

⚠ **02 的降级路径要在抓取之前**：
抓取是最依赖位姿的交互，
⛔ 抓完了再补降级，会出现"抓着东西时手柄丢失"这个谁都没测过的分支。

⚠ **06 的渲染器要随项目初始化时就定，不能性能不达标时才换**：
换渲染器会连带重测材质、后处理与阴影，属于中期整体返工。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是单个交互，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `physics` 域 物理 | 刚体、关节与休眠见 `physics`，⛔ 本域只定抓取的**所有权与动量传递** |
| `character` 域 角色控制 | 角色移动与相机跟随见 `character`，⛔ 本域只定 `XROrigin3D` 这一种移动入口 |
| `perf` 域 性能 | 剖析方法与预算口径见 `perf`，⛔ 本域只定 XR 的**双眼总量与刷新率换算** |
| `upscaling` 域 画质管线 | 超分与抗锯齿组合见 `upscaling`，⛔ 本域只定分辨率倍率的**设置时机** |
| `shaders` 域 着色器 | 材质与后处理见 `shaders`，⛔ 本域不另定材质口径 |
| `ui` 域 UI | 2D 界面见 `ui`，⛔ 本域讲的是**世界空间 3D 面板** |
| `platform-export` 域 导出发布 | 头显导出、权限与平台服务见 `platform-export`，⛔ 本域只覆盖运行时行为 |
| `mobile` 域 移动端 | 一体机的发热降频与带宽约束见 `mobile`，⛔ 本域不另定移动端口径 |
| `input-audio` | ⓘ howto 层，暂无 flow 域 —— 输入映射与动作见该篇 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `WORLD_SCALE` 世界尺度 | 01 | 1.0 | — | 待实测（⛔ 手关节 API 不应用该值，要自己乘） |
| `FALLBACK` 位姿降级策略 | 02 | PAUSE | — | 待实测（⛔ 三选一，⛔ 不能三种都走） |
| `RECENTER_MODE` 居中朝向模式 | 02 | KEEP_TILT | — | 待实测（⛔ 默认是 FULL_RESET，会重置朝向） |
| `PINCH_ENTER` 捏合进入阈值 | 03 | — | — | 待实测（归一化比值，⛔ 不是厘米） |
| `PINCH_EXIT` 捏合释放阈值 | 03 | — | — | 待实测（⛔ 必须大于进入值） |
| `MAX_TIP_SPEED` 指尖速度防抖 | 03 | — | — | 待实测（⛔ 无此判据会挥手误触发） |
| `SAMPLES` 速度样本数 | 04 | 12 | — | 待实测（⛔ 单帧差分在 120Hz 出尖峰） |
| `THROW_GAIN` 抛出增益 | 04 | 1.0 | — | 待实测 |
| `HAPTIC_GRAB/HOLD/RELEASE` 触觉强度 | 04 | — | — | 待实测（0.0–1.0，⛔ 三处要成体系） |
| `MIN_HEADROOM` 落点头顶净空 | 05 | — | — | 待实测 |
| `MAX_SLOPE_DOT` 法线朝上阈值 | 05 | — | — | 待实测 |
| `SNAP_ANGLE` snap turn 角度 | 05 | — | — | 待实测（⛔ 不提供该选项会有一部分人直接晕） |
| `VIGNETTE_MS` 淡入淡出时长 | 05 | — | — | 待实测 |
| `TARGET_HZ` 目标刷新率 | 06 | — | — | 待实测（⛔ 读 API，不写死 90） |
| `RENDER_SCALE` 分辨率倍率 | 06 | 1.0 | — | 待实测（⛔ 必须在接口初始化**前**设） |
| `FOVEATION_LEVEL` 注视点档位 | 06 | — | — | 待实测（⛔ 必须在接口初始化**后**设） |
| `LATENCY_BUDGET_MS` 输入到画面延迟预算 | 06 | — | — | 待实测（⛔ 与帧率分开登记） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发穿模""偶发误触发""偶发晕"，
⛔ 而这类偶发在开发机与编辑器里几乎不出现。
