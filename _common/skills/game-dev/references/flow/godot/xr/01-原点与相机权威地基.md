# 01 原点与相机权威地基（XR 域）

> **本步交付**：空间模型定性 + 原点为唯一可移动节点 + 相机权威边界已写下
> **对应**：流程 `howto/godot/xr.md` · 审核 `audit/godot/xr.md`

## 0. 交付物定义

1. `XROrigin3D` / `XRCamera3D` / `XRController3D` 三层职责已写下，且写下相机**禁止**怎么用
2. 全局只有一处移动 `XROrigin3D`，没有第二处改 `XRCamera3D` 变换
3. 相机不可信属性清单已写下（FOV / `cull_mask` / `keep_aspect`）
4. HUD 与手持物挂在 `XROrigin3D` 下，不挂 `XRCamera3D`
5. `world_scale` 的取值与"它不作用于手关节 API"已写进参数表

## 1. 前置检查清单

- [ ] 能用一句话说清 origin 与相机的分工
- [ ] 全局搜 `XRCamera3D` 的 transform 赋值，结果为 0
- [ ] 相机不可信属性清单已存在
- [ ] 没有节点挂在 `XRCamera3D` 下
- [ ] `world_scale` 只在一处设置

## 2. 工序

### Step 1　先定空间模型：origin 是唯一可移动节点　`[xr/01#S1]`

【读】`howto/godot/xr.md#1. 最小场景结构`

【做】
写下三层职责，并逐层写下**禁止项**：
`XROrigin3D` 是唯一可移动节点（代表玩家在虚拟世界里的位置），
`XRCamera3D` 每帧被头显覆盖（⛔ 禁止写它的 transform），
`XRController3D` 由 `XRServer` 更新（⛔ 只读取，不写）。
⛔ 先搭场景再补这条 —— 一旦有一处图省事写了相机 transform，
后面所有"相机怎么又飞了"的排查都会被引向追踪或物理，
而真正的成因是有一行赋值覆盖不了。

ⓘ 这条定性同时决定后面所有步：传送、移动、房间规模校准
全都只改 `XROrigin3D`，⛔ 出现第二种移动入口就等于两套真相。

【产出】三层职责表（含各层禁止项）

【判据】指着任意一行移动代码能说出它改的是 origin；⛔ 全局无 `XRCamera3D` 的 transform 赋值。

【审】`audit/godot/xr.md#1`

### Step 2　写下相机不可信属性清单：只有近/远裁剪面可靠　`[xr/01#S2]`

【读】`howto/godot/xr.md#8. ⛔ 官方口径：相机权威、插值与追踪置信度`

【做】
把 `XRCamera3D` 在 `Viewport.use_xr` 为真时**不可信**的属性列成清单
（FOV、`cull_mask`、`keep_aspect` …），只留 `near` / `far` 两个可用。
⛔ 尤其要显式写下"**不能用相机 cull_mask 隐藏层**" ——
想在 VR 里藏一层时改它是**不生效**的，
而属性面板上它确实是勾好的，
⛔ 排查必然被引向层名拼写或渲染层编号，不会想到是相机属性被整体覆盖。

ⓘ 要隐藏层就改 `Viewport` / 节点自身的层与掩码，或换可见性，
⛔ 不是改相机。

【产出】相机不可信属性清单（含替代方案）

【判据】清单里每一条都有对应的替代做法；⛔ 没有"改相机 cull_mask 即可"这类条目。

【审】`audit/godot/xr.md#16`

### Step 3　XRCamera3D 强制关闭物理插值，挂载物不能挂在它下面　`[xr/01#S3]`

【读】`howto/godot/xr.md#8. ⛔ 官方口径：相机权威、插值与追踪置信度`

【做】
确认 `XRCamera3D` 的 `physics_interpolation_mode` 被硬编码为 OFF（面板显示 `2 (overrides Node)`），
并据此把 HUD、手持物、瞄准辅助**全部挂到 `XROrigin3D` 或控制器下**，
⛔ 不挂在 `XRCamera3D` 下。

ⓘ 它是**强制**的、不继承项目设置，所以面板上改不动，
⛔ 试图"把相机插值打开"是无效动作。
⛔ 挂在相机下的物体在项目开了物理插值时会与场景其余部分不同步
（其余插值、它不插值），表现为**相对抖动**，
而这种抖动只在头部运动时可见，静止站着看不出来。

【产出】挂载规则（相机下无子节点，或只有纯视觉无物理的挂件）

【判据】场景树里 `XRCamera3D` 无参与物理的子节点；头部快速运动时挂件不相对抖动。

【审】`audit/godot/xr.md#17`

### Step 4　world_scale 是全局缩放，但手关节 API 不应用它　`[xr/01#S4]`

【读】`howto/godot/xr-deep.md#6. ⛔ 官方口径：渲染器、foveation 与设置时机`

【做】
`world_scale` 只在初始化时设一次并登记进参数表，
并把"**手关节 API 返回的位姿不含 world_scale**"写在同一处。
⛔ 改了 `world_scale` 之后直接用 `get_hand_joint_position()` 的结果 ——
位置与半径**不会跟着缩放**，要自己乘，
表现为"手模型大小/位置不对"，而代码里没有任何乘法错误。

ⓘ 同理，自己读 `XRPose.transform` 算世界坐标也不含 world_scale，
要取 `get_adjusted_transform()`。两条同源，写在一起。

【产出】`world_scale` 取值 + 关节位姿换算说明

【判据】把 `world_scale` 改成 2.0 后，手模型位置与半径仍与视觉一致。

【审】`audit/godot/xr.md#15`

### Step 5　相机位置滞后几毫秒，不能当权威物理抓手　`[xr/01#S5]`

【读】`howto/godot/xr-deep.md#0. OpenXR 不是设备 SDK`

【做】
把"相机位姿**滞后于渲染**几毫秒"写进架构约束，
并规定：所有物理交互（抓取点、射线起点、碰撞）以
`XRController3D` 或手部锚点为准，⛔ 不以相机为准。
⛔ 用相机当抓手 —— 快速转头时抓取点会**系统性偏后**，
表现为"明明抓到了却判定失败"，
⛔ 而慢速测试完全正常，问题只在快速运动时复现。

【产出】权威位姿来源规定（控制器 / 手锚，非相机）

【判据】快速转头并抓取的成功率与静止时一致。

【审】`audit/godot/xr-deep.md#2`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：origin 为唯一移动入口 + 相机权威边界
# ⛔ WORLD_SCALE 由 00 参数表实测回填；此处只示形
extends XROrigin3D

const WORLD_SCALE := 1.0        # 1 游戏单位 = 1 米（官方默认）
const EYE_HEIGHT_COMPENSATE := true

func _ready() -> void:
    XRServer.world_scale = WORLD_SCALE   # ⛔ 全局，只在这里设一次
    var cam := $XRCamera3D as XRCamera3D
    # ⛔ 不要写 cam.transform / cam.fov / cam.cull_mask：use_xr 为真时全部被覆盖
    cam.near = 0.05                      # ⓘ 只有 near / far 可信
    cam.far = 400.0

func move_player(delta_pos: Vector3) -> void:
    global_position += delta_pos         # ⛔ 移动的是 origin，不是相机
```

ⓘ 上例只示范"origin 唯一移动入口 + 相机只留 near / far"，
⛔ 手关节位姿换算见 03，抓取见 04。
