# 04 抓取与释放动量（XR 域）

> **本步交付**：所有权单一 + 方案已选型 + 释放动量已传递 + 触觉强度成体系
> **对应**：流程 `howto/godot/xr-deep.md` · 审核 `audit/godot/xr-deep.md`

## 0. 交付物定义

1. 抓取**不用 reparent**，动态刚体的所有权只有一处
2. 抓取方案（物理关节 / 速度追踪）已选型并写下理由
3. 抓取偏移已记录，抓取期间禁休眠
4. 释放时**显式写入线速度与角速度**
5. 速度计算是**多样本平均**，不是单帧差分

## 1. 前置检查清单

- [ ] 全局没有对动态刚体做 reparent
- [ ] 没有同时用插件抓取节点与自己的物理代码
- [ ] 抓取方案与理由写在参数表里
- [ ] 释放函数里同时写了 linear 与 angular 速度
- [ ] 速度用多样本平均

## 2. 工序

### Step 1　抓取不是改父子关系，且所有权只能有一处　`[xr/04#S1]`

【读】`howto/godot/xr-deep.md#2. 抓取：管理所有权、约束和动量`

【做】
对动态刚体**禁止 reparent**，并明确规定抓取所有权只归一处：
⛔ 一边用插件的抓取节点、一边自己 reparent `RigidBody3D` ——
两套所有权**互相覆盖**，
表现为"抓起来抖、有时自动脱手"，
⛔ 而两套代码单看都正确，日志里也没有冲突记录。

ⓘ 社区插件值得借鉴的是动作映射 / 手型 / 传送指示器，
⛔ 核心抓取保留在自己的物理层。

【产出】所有权归属规定（单一来源）

【判据】全局搜 reparent / add_child 的操作对象，动态刚体命中数为 0。

【审】`audit/godot/xr-deep.md#4`、`audit/godot/xr-deep.md#14`

### Step 2　先选型再实现：物理关节 / 速度追踪二选一　`[xr/04#S2]`

【读】`howto/godot/xr.md#3. 抓取`

【做】
在**物理关节**（`Generic6DOFJoint3D` / `PinJoint3D`，有真实约束感、
物体仍与场景碰撞，但重且可能抖）与**速度追踪**（轻快、有穿模风险）
之间选一种并写下理由。
⛔ 两种混用 —— 同一物体在不同状态下走不同方案，
表现为"有的东西抓着会穿墙、有的很沉"，
⛔ 而每次改动都是局部的，看不出是选型没定。

ⓘ 直接 reparent 只对**非物理**的展示物成立，
⛔ 用在动态刚体上会破坏物理（物体失去碰撞）。

【产出】选型结论 + 理由（写进参数表）

【判据】抓起任意可抓物，行为符合所选方案；⛔ 不存在第三种路径。

【审】`audit/godot/xr.md#4`

### Step 3　记录抓取偏移，并在抓取期间禁休眠　`[xr/04#S3]`

【读】`howto/godot/xr.md#3. 抓取`

【做】
抓取瞬间记录手到物体的**相对偏移**并在每帧保持，
同时把 `sleeping = false` 并临时禁 `can_sleep`。
⛔ 不记偏移 —— 物体会瞬移到手腕中心，
表现为"抓起来跳一下"，⛔ 而这个跳动在慢速抓取时不明显。
⛔ 不禁休眠 —— 睡着的刚体**抓不起来**
（官方老教程专门用 Sleep_Area 禁休眠），
表现为"有的东西抓不动"，⛔ 而它看起来和别的东西没有区别。

【产出】抓取偏移 + 禁休眠的进入/退出处理

【判据】抓取瞬间物体不跳；静止 10 秒后的物体仍能抓起。

【审】`audit/godot/xr.md#6`、`audit/godot/xr.md#7`

### Step 4　释放时显式写入线速度与角速度，触觉强度要成体系　`[xr/04#S4]`

【读】`howto/godot/xr-deep.md#2. 抓取：管理所有权、约束和动量`

【做】
释放瞬间把速度追踪器算出的速度**显式写回**刚体的
`linear_velocity` 与 `angular_velocity`，再恢复 `can_sleep`。
⛔ 只写线速度不写角速度 —— 甩出去的物体不会自转，
表现为"扔出去像掉下来"，手感极假。

同时把触觉反馈的**一致性**定下来：抓取 / 持有 / 释放三处的
触觉强度要**成体系**（⛔ 不是三处各写一个随手的值）。
⛔ 强度不成体系 —— 玩家会觉得物体"有的轻有的重"，
而重量其实完全一样；这种不一致是靠单次体验发现不了的。

ⓘ 官方 `trigger_haptic_pulse` 的 amplitude 取值区间是 0.0–1.0，
frequency 传 0.0 表示用系统默认频率。

【产出】释放函数（含两种速度）+ 触觉强度表

【判据】甩出的物体带自转；同一物体三次操作的触觉强度一致。

【审】`audit/godot/xr-deep.md#25`

【品】`craft/godot/aesthetics.md#6. 一致性：同一动作，不同对象，强度要成体系`

### Step 5　速度要多样本平均，单帧差分在高刷新率上出尖峰　`[xr/04#S5]`

【读】`howto/godot/xr.md#2. 控制器输入`

【做】
用**首尾差分 / 多样本平均**算速度，样本数登记进参数表。
⛔ 单帧差分 —— 在 120Hz 头显上单帧间隔极短，
微小抖动被放大成尖峰，
表现为"扔出去的物体速度乱跳"，
⛔ 而在 72Hz 下测完全正常，问题只在高端设备上复现。

ⓘ 官方已提供逐关节速度，但**关节速度不等于抓取点速度**，
手锚本身仍要自己缓存世界变换差分。

【产出】速度追踪器（多样本）+ 样本数登记

【判据】同一抛出动作在 72 / 90 / 120Hz 下速度量级一致。

【审】`audit/godot/xr.md#3`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：释放动量 + 触觉强度 + 多样本速度
# ⛔ THROW_GAIN / HAPTIC_* / SAMPLES 由 00 参数表实测回填
const SAMPLES := 12                 # 多样本窗口，⛔ 单帧差分在 120Hz 出尖峰
const HAPTIC_GRAB := 0.35           # ⓘ 官方 amplitude 区间 0.0–1.0
const HAPTIC_HOLD := 0.12
const HAPTIC_RELEASE := 0.25        # ⛔ 三处要成体系，不是随手值
const THROW_GAIN := 1.0

var _pos: Array[Vector3] = []
var _t: Array[float] = []

func _process(_d: float) -> void:
    _pos.append(global_position)
    _t.append(Time.get_ticks_usec() / 1e6)
    if _pos.size() > SAMPLES:
        _pos.pop_front(); _t.pop_front()

func velocity() -> Vector3:
    if _pos.size() < 2:
        return Vector3.ZERO
    var dt := _t[-1] - _t[0]
    if dt <= 0.0:
        return Vector3.ZERO
    return (_pos[-1] - _pos[0]) / dt * THROW_GAIN   # ⓘ 首尾差分，不是相邻帧

func release(body: RigidBody3D) -> void:
    body.linear_velocity = velocity()
    body.angular_velocity = _estimate_angular()
    body.set_deferred("can_sleep", true)
    ($XRController3D as XRController3D).trigger_haptic_pulse(
        "haptic", 0.0, HAPTIC_RELEASE, 0.05, 0.0)
```

ⓘ 上例只示范动量与触觉，
⛔ 抓取偏移与禁休眠见 S3，所有权规则见 S1。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 抓起来抖 / 自动脱手 | 插件与自写代码两套所有权 | S1 |
| 有的能穿墙有的很沉 | 两种抓取方案混用 | S2 |
| 抓起来跳一下 / 抓不动 | 无抓取偏移 / 刚体休眠 | S3 |
| 扔出去像掉下来 | 没写角速度 | S4 |
| 120Hz 上速度乱跳 | 单帧差分 | S5 |
