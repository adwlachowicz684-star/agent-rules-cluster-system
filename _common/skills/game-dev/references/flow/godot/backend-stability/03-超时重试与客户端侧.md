# 03 超时重试与客户端侧（服务端稳定性域）

> **本步交付**：超时预算表 + 退避抖动幂等键 + 客户端 jitter
> **对应**：流程 `howto/godot/backend-stability.md` · 审核 `audit/godot/backend-stability.md`

## 0. 交付物定义

1. 每个外部调用、DB 查询、连接建立都有明确超时
2. 可重试 / 不可重试已分类，且分类写成了错误码清单
3. 退避与抖动公式落地，⛔ 抖动覆盖首次重连
4. 重试携带幂等键
5. Godot 客户端的 `timeout` 与 `body_size_limit` 已显式设置

## 1. 前置检查清单

- [ ] 超时预算从玩家可感知总预算向内分配
- [ ] 参数校验失败 / 权限不足 / 幂等冲突标记为不可重试
- [ ] ⛔ 抖动作用于第一次重连，不只是第 2 次以后
- [ ] 幂等键由调用方生成并贯穿整条链路
- [ ] 客户端 `HTTPRequest` 的 `timeout` 与 `body_size_limit` 非默认值

## 2. 工序

### Step 1　每个外部调用都要有超时，预算从外向内分　`[backend-stability/03#S1]`

【读】`howto/godot/backend-stability.md#4. 超时与重试：把瞬时故障扩散成 DDoS 的放大器`

【做】
无限超时会把故障从下游传播到上游线程池，一个慢库拖垮整个接入层。
⛔ **从外向内分配预算**：玩家可感知操作总预算 2–3 秒，
再给鉴权 / 缓存 / DB / RPC 分更短的子超时。
⛔ 反过来（各处各设各的）会出现"每个子超时都合法、加起来超过玩家容忍"的组合，
而这种组合只在真实故障时才第一次被走通。

【产出】超时预算表（总预算 + 每个依赖的子超时）

【判据】任一调用链的各级超时之和不超过总预算

【审】`audit/godot/backend-stability.md#11`


### Step 2　可重试性分类：不是所有失败都能重试　`[backend-stability/03#S2]`

【读】`howto/godot/backend-stability.md#4. 超时与重试：把瞬时故障扩散成 DDoS 的放大器`

【做】
5xx、连接拒绝、限流、超时通常可重试；
参数校验失败、权限不足、幂等冲突**不可重试**。
⛔ 分类必须落成一张错误码清单，⛔ 不能散落在各处的 `if` 里：
散落的判断会随着新增错误码逐渐失效，
表现为"某个新错误被一律重试"，且只有在对端被打挂后才暴露。

【产出】可重试性错误码清单

【判据】任一错误码都能查到它是否可重试

【审】`audit/godot/backend-stability.md#12`


### Step 3　退避 + 抖动，⛔ 抖动必须覆盖首次重连　`[backend-stability/03#S3]`

【读】`howto/godot/backend-stability.md#4. 超时与重试：把瞬时故障扩散成 DDoS 的放大器`

【做】
`delay = min(max_delay, base × 2^attempt) + random(0, delay × 0.2)`。
⚠ **jitter 必须覆盖首次重连**——故障恢复瞬间所有客户端同时按固定周期重连会形成**雷鸣群**。
⛔ 只在第 2 次之后加抖动的写法，恰恰放过危害最大的那一次：
恢复瞬间的第一个波次是全体客户端，规模远大于后续任何一轮。

【产出】退避抖动实现（首次重连也带 jitter）

【判据】首次重连的间隔是随机的，不是固定值

【审】`audit/godot/backend-stability.md#13`


### Step 4　⛔ 重试必须携带幂等键　`[backend-stability/03#S4]`

【读】`howto/godot/backend-stability.md#4. 超时与重试：把瞬时故障扩散成 DDoS 的放大器`

【做】
没有幂等键，重试支付只是把重复发货的风险换成一次失败——
两种结果都不可接受，而"失败"看起来还更安全，于是幂等被长期搁置。
⛔ 幂等键要由**调用方**生成并贯穿整条链路，
⛔ 不能由某一层自己生成：中途生成的键无法覆盖它之前的重试。
ⓘ 支付链路的幂等键与商业化域是同一套（见 `monetization` 域接缝）。

【产出】幂等键规范（生成方、传输字段、保留时长）

【判据】同一请求重放 N 次只生效一次

【审】`audit/godot/backend-stability.md#14`


### Step 5　重试风暴是叠加出来的；熔断打开时返回降级而不是继续重试　`[backend-stability/03#S5]`

【读】`howto/godot/backend-stability.md#4. 超时与重试：把瞬时故障扩散成 DDoS 的放大器`

【做】
网关重试 1 次 + 接入层 2 次 + SDK 2 次 = 单次失败变 **27 倍**下游压力。
⛔ 每层各自"只重试 2 次"看起来都很保守，
而乘积才是真实的放大倍数，且没有任何一层能看到这个乘积。
⚠ **熔断打开时返回降级结果，而不是继续重试**——
对已确认故障的依赖继续重试，是把流量精确倾泻到最脆弱的地方。

【产出】全链路重试次数表（含乘积核算）

【判据】能说出任意失败路径的总放大倍数

【审】`audit/godot/backend-stability.md#15`


### Step 6　客户端重连也要 jitter，且⛔ 不能判定服务健康　`[backend-stability/03#S6]`

【读】`howto/godot/backend-stability.md#10. Godot 客户端侧`

【做】
客户端固定间隔重连会形成雷鸣群；
⛔ **不能由客户端判定服务健康或自行切换服务器**——
客户端能观测到的只有"我这条路通不通"，据此判定健康会把局部网络问题
误判成服务端故障，进而全体切向同一个"看起来更好"的节点。
服务不可用要给明确用户提示。

【产出】客户端重连策略（jitter + 明确提示 + 不自行切换）

【判据】重连间隔随机，且不存在客户端自选服务器的分支

【审】`audit/godot/backend-stability.md#37`


### Step 7　⛔ Godot 客户端的五个默认陷阱：不设就是默认敞口　`[backend-stability/03#S7]`

【读】`howto/godot/backend-stability.md#10. Godot 客户端侧`

【做】
- `body_size_limit` 默认 **-1（无限制）**：官方把这个属性的用途写成防 DoS 手段，
  不设会被超大响应体撑爆内存
- `timeout` 默认 **0.0**：含义是永不超时，服务端不返回时请求永久挂起
- **单节点不能并发**：处理中再发起返回 `ERR_BUSY`，官方要求一请求一节点
- **`Timer` 受 `Engine.time_scale` 影响**：用 `Timer` 做退避时，
  游戏内子弹时间 / 加速会把退避间隔一起缩放，抖动被抹平
- **`wait_time` 低于约 0.05 秒**行为随帧率显著变化：短退避要改用累加 delta

⛔ 这五个都是"不写就是敞口"，且没有任何一个会报错——
它们只在依赖变慢、响应变大、游戏内开加速时才第一次显现。

【产出】客户端请求封装（五个默认值全部显式覆盖）

【判据】新建请求节点时五个值都被显式设置，且退避不用 `Timer`

【审】`audit/godot/backend-stability.md#39`、`audit/godot/backend-stability.md#40`、`audit/godot/backend-stability.md#41`、`audit/godot/backend-stability.md#42`、`audit/godot/backend-stability.md#43`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：五个默认值全部显式覆盖，且退避不用 Timer
const HTTP_TIMEOUT_SEC := 10.0
const BODY_SIZE_LIMIT := 1048576
const RETRY_BASE_MS := 50
const RETRY_CAP_SEC := 2.0
const JITTER_RATIO := 0.2

func _new_request_node() -> HTTPRequest:
	var req := HTTPRequest.new()
	req.timeout = HTTP_TIMEOUT_SEC          # ⛔ 默认 0.0 = 永不超时
	req.body_size_limit = BODY_SIZE_LIMIT   # ⛔ 默认 -1 = 无限制
	add_child(req)
	return req  # ⛔ 一请求一节点：复用会返回 ERR_BUSY

# ⛔ 不用 Timer 做退避：它受 Engine.time_scale 影响，子弹时间会缩放间隔
func _backoff_sec(attempt: int) -> float:
	var delay := minf(RETRY_CAP_SEC, RETRY_BASE_MS * pow(2, attempt) / 1000.0)
	return delay + randf() * delay * JITTER_RATIO
```

## 4. 验收清单

- [ ] 每个外部调用都有超时，子超时之和不超总预算
- [ ] 不可重试的错误码已单独列出
- [ ] ⛔ 首次重连带抖动
- [ ] 幂等键由调用方生成并贯穿链路
- [ ] ⛔ 客户端五个默认值全部显式覆盖

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 一个慢库拖垮接入层 | 调用无超时 | S1 |
| 新增错误被一律重试 | 分类散落在 if 里 | S2 |
| 恢复瞬间全体重连 | 首次未加抖动 | S3 |
| 重试导致重复发货 | 无幂等键 | S4 |
| 失败被放大 27 倍 | 各层重试相乘 | S5 |
| 重连打垮刚恢复的服务 | 客户端固定间隔 | S6 |
| 请求永久挂起 / 内存被撑爆 | 客户端用默认值 | S7 |
