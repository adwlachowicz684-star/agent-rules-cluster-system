# 00 域流程总览 · 开放世界流式加载（openworld 域）

## 0. 先定做什么

⚠ **本域的核心不是"怎么加载"，而是"世界大到必须边玩边加载之后，
怎么保证不卡、不抖、不错位"。**

两个核心风险：**加载卡顿** 与 **坐标精度**。
⛔ 两者的共同点是**小项目完全测不出来**——等你发现时，
地形、寻路、存档都已按错误规模定型，改方案几乎等于重来。

本域讲**按什么顺序做**；单个要素怎么配见做法篇。

## 2. 与其他域的接缝

| 域 | 接缝 |
|---|---|
| level | 小场景走关卡流式加载，大世界才用 chunk；两者半径语义不同 |
| vegetation | 植被分块与 MultiMesh 的可见距离 |
| physics | 原点重置后物理对象与射线查询的同步 |
| netsync | 各端原点不同导致的 `world ↔ local` 转换 |
| perf | 分帧预算与自定义监视器 |
| save | 增量存档与版本号 |
| camera | 传送后相机与纹理流送的配合 |

## 3. 本域最容易做反的顺序

⛔ **先建世界，再定坐标方案。** 精度问题只在远处出现，
而世界建好后地形、寻路、存档都已定型。

⛔ **先做加载，再补滞回。** 没有滞回会在边界**抖动式加载**，
表现为周期性卡顿，⛔ 极易被当成"资源太大"去优化一个根本没问题的资源。

⛔ **单机测通就上多人。** 各端原点不同，单机看起来完全正常。
