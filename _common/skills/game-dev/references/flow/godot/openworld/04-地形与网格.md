## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：地形能显示就算完了。**

⛔ 常见假完成：整块地形一张大 mesh，
于是无法流式加载、无法部分更新，⛔ 而编辑器里看不出任何问题。

做完这一步，应该能**当场演示**：

1. 地形已分块，可按 chunk 加载/卸载
2. ⛔ 导航网格**分块烘**，不是全量重烘
3. 纹理流送已开（若版本支持）
4. ⚠ 已查过 VRAM 占用，知道是否会触发自动降分辨率
5. ⛔ 传送后调用了 `flush_texture_streaming()`

**产出物**（下游按名字对接）：

```text
分块地形（Terrain3D 或自写，按 chunk 划分）
分块导航网格
纹理流送接入 + flush 调用点
```

## 2. 工序

### Step 1　⛔ Godot 4 没有内置可编辑地形节点　`[04#S1]`

【读】`howto/godot/openworld.md#2. 地形`

【审】`audit/godot/openworld.md#5`

⚠ 选项是 Terrain3D（GDExtension）或自写。

### Step 2　⛔ 地形要分块，一张大 mesh 无法流式　`[04#S2]`

【读】`howto/godot/openworld.md#2. 地形`

【审】`audit/godot/openworld.md#25`

### Step 3　⛔ 导航网格要分块烘，否则每加载一块全量重烘　`[04#S3]`

【读】`howto/godot/openworld.md#2. 地形`

【审】`audit/godot/openworld.md#27`

⛔ 全量重烘在 chunk 频繁加载时是主要卡顿源之一，
⛔ 且表现为"加载地形时偶发卡顿"，容易归错因。

### Step 4　⚠ 纹理流送超预算会自动降分辨率　`[04#S4]`

【读】`howto/godot/openworld.md#3. 纹理 VRAM：4.8 的 mip 级流送`

【审】`audit/godot/openworld.md#20`

⚠ 可用 `get_memory_budget_bytes_used()` 查当前占用。
⛔ 表现为"远处贴图莫名变糊"，而去查一个根本没开的 LOD bias。

### Step 5　⛔ 传送后要 flush，否则先糊后清　`[04#S5]`

【读】`howto/godot/openworld.md#3. 纹理 VRAM：4.8 的 mip 级流送`

【审】`audit/godot/openworld.md#19`

⚠ 默认按渐变与 I/O 节流加载。⛔ 表现为"传送后一片模糊，
走两步才清楚"，极易被当成纹理压缩设置问题。

## 3. 参考实现

```gdscript
# 传送落点后：强制立即完成流送，避免从低分辨率渐变
TextureStreaming.flush_texture_streaming()
```

⚠ 另有 `flush_completed` 信号可等待。
⛔ 只在加载画面或传送时调；每帧调会失去节流意义。
