## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：觉得世界不算大，跳过直接开建。**

⛔ 常见假完成：没查官方分档、凭"大概几千米"估规模，
于是坐标方案是在**没有依据**的情况下选定的。

做完这一步，应该能**当场演示**：

1. 世界半径已按**视角类型**选定档位
2. ⛔ 官方上限是**区间上界**这件事已被确认（不是区间本身）
3. 坐标方案已定：原点重置 或 双精度构建
4. ⚠ 若选原点重置：所有坐标消费方已列全
5. ⛔ 若为多人：各端原点不同的转换方案已明确

**产出物**（下游按名字对接）：

```text
规模档位结论（视角类型 + 半径上限）
坐标方案结论（原点重置 / 双精度）
坐标消费方清单（物理/导航/音频/粒子/后处理/shader）
```

## 2. 工序

### Step 1　⛔ 先定世界规模，再动手建　`[01#S1]`

【读】`howto/godot/openworld.md#官方建议的最大范围（单精度）`

【审】`audit/godot/openworld.md#15`

⚠ 官方按**视角**分档：第一人称 4096、第三人称 8192、俯视 32768、一般 3D 65536。
⛔ 记成区间（如"4096–8192"）会整体错一档、上限翻倍。

### Step 2　⛔ 官方上限是「区间上界」，不是硬阈值　`[01#S2]`

【读】`howto/godot/openworld.md#官方建议的最大范围（单精度）`

【审】`audit/godot/openworld.md#7`

⚠ 误差随 2 的幂成倍变化，不存在"8192 米以内绝对安全"。

### Step 3　⛔ 原点重置不是移相机，是所有坐标消费方同步　`[01#S3]`

【读】`howto/godot/openworld.md#方案 A：原点重置（floating origin）—— 推荐`

【审】`audit/godot/openworld.md#8`

⚠ 只重置玩家和相机，不重置远处 NPC、音频监听器、粒子、
后处理目标、导航和物理对象 → **世界瞬间错位**。

### Step 4　⛔ 双精度不是勾选项，且开了渲染照旧抖　`[01#S4]`

【读】`howto/godot/openworld.md#⛔ 开了双精度，渲染照旧抖`

【审】`audit/godot/openworld.md#16`

⚠ 位置送 GPU 前会**降回单精度**，靠 emulation 模拟。
⛔ 所以"开了双精度构建，远处物体照旧抖"不是玄学。

### Step 5　⛔ 多人下各端原点不同，每个包都要转换　`[01#S5]`

【读】`howto/godot/openworld.md#方案 A：原点重置（floating origin）—— 推荐`

【审】`audit/godot/openworld.md#30`

⚠ 服务端用全局坐标、客户端用本地浮动坐标时，
每个网络包都要 `world ↔ local` 转换；处理不一致会"跳格"，
⛔ 而单机看起来完全正常。

## 3. 参考实现

```gdscript
# 坐标消费方清单：原点重置时必须全部同步
#   Node3D.global_position   ← 节点
#   物理 / 导航 / 音频监听器 / 粒子 / 后处理目标
#   shader uniform 里的世界坐标 ← 不会自动跟着改，需手动传
func world_to_local(world: Vector3) -> Vector3:
    return world - active_origin
```

⛔ shader uniform 里的世界坐标**不会**跟随原点重置，必须手动更新。
