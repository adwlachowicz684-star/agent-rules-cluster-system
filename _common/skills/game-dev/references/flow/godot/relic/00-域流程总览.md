# 遗物 / 局内构筑 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只是"局内能拿遗物、加了属性" | 01 → 02 → 03 → 07 |
| 有三选一、可复现种子 | 01 → 02 → 03 → 04 → 07 |
| 有遗物协同/组合触发 | 01 → 02 → 03 → 05 → 07 |
| 有稀有度、权重抽取 | 01 → 02 → 03 → 06 → 07 |
| 全套（含局外解锁） | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **不要因为"roguelike 都有"就全做。**
⚠ 每加一个功能点就多一条与关卡生成域的接缝。

ⓘ 若本次只是**局外**配装（局内属性不变），
那是 `build-affix.md`，⛔ 不要套本域。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 模型定性 | — | 遗物 / 词条 / 局外解锁，什么时候消失 |
| 02 | 遗物池与实例 | 01 | `RelicBase` / `RelicInstance` / `stacks` |
| 03 | 抽取与三选一 | 02 | 独立 RNG 实例 + 先 seed 后 state |
| 04 | 协同与组合 | 03 | 独立协同表 + 去重集合判定 |
| 05 | 稀有度与权重 | 02 | `rand_weighted` + 判 `-1` |
| 06 | 局内快照与局外解锁 | 03 | 脏标记快照 + 关键节点即存 |
| 07 | 构筑验收 | 全部 | 种子复现 + 接缝复查 |

⚠ **02 必须在 03 之前**：没有池结构，无从抽起。
⚠ **03 必须在 04/06 之前**：04 的协同要按已持有的集合判定，
06 的快照要在拿遗物时重算。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `genres-roguelike.md` | 本域是它的养成层：那篇管关卡生成，本域管局内产出 |
| `genres-roguelike.md` 道具池 | 共用累积权重二分；两套权重逻辑不能冲突 |
| `build-affix.md` 脏标记 | 遗物与词条**共用同一套脏标记快照** |
| `build-affix.md` 组合约束 | 减伤类叠加必须受约束（除零 → NaN） |
| `gem-rune.md` | 模板/实例两层**同构**，不发明第三套 |
| `economy.md` 保底 | 保底计数必须持久化且绑定池 |
| `save-migration.md` | 只存 `relic_id`；局外解锁关键节点即存 |
| `netsync-advanced.md` | 抽取结果服务端裁决，客户端不可伪造 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**，
⛔ 不许在各处偷偷转格式（那些转换会散落多处，改接口时找不到）。

⚠ **各功能点自己的验收不能替代集成验收** ——
部件全合格、拼起来不能用，是跨域开发的典型失败。

## 3. 本域最容易做反的顺序

⛔ **先做协同再做抽取。**

协同规则依赖"当前持有哪些遗物"，而这个集合在抽取稳定前是哑的。
更糟的是：先做协同时，为了测试会临时手塞遗物到集合里，
这些临时塞法最后会变成正式代码路径——绕过抽取直接改集合，
**种子复现就此失效**。

✅ 正确顺序：先有抽取（03），再让协同（04）只读已持有集合。
