# 03 抽取与三选一（遗物域）

> **前置**：`02-遗物池与实例.md` 已完成
> **本步交付**：同一个种子**每次抽出的序列完全相同**
> **对应**：做法 `howto/godot/relic-build.md#2. RNG：seed 与 state 是两个层级`
> 　　　审核 `audit/godot/relic-build.md#5`

## 0. 交付物定义

⚠ **这是全域唯一决定"能否复现"的一步**，也是种子玩法（每日挑战、回放）的地基。

⛔ 两个直觉做法都会让种子失效：

| 做法 | 后果 |
|---|---|
| 用全局 `randi()` | UI 抖动/粒子都会消耗序列 → 同种子结果不同 |
| 先恢复 `state` 再设 `seed` | 官方：**改 seed 会重置 state**，恢复被覆盖 |

做完这一步，应该能**当场演示**：

1. 同一个种子跑两遍，**遗物序列逐项相同**
2. ⚠ 存档 → 恢复 `state` → 继续抽，**与存档前一致**
3. 中途开菜单、看 UI，**不影响**后续抽取
4. 玩家 ID 当种子时，**相邻 ID 序列不同**（种子过了哈希）
5. ⚠ 某种稀有度抽完后，**有显式兜底**而不是返回最后一个

**产出物**（下游按名字对接）：

```text
_run_rng: RandomNumberGenerator      # 独立实例，⛔ 不用全局
start_run(seed_value)  # ① seed（过 hash） → ② state（若有）
roll_offering(n)       # 三选一，返回 n 个不重复 relic_id
```

## 2. 工序

### Step 1　⛔ 独立 RNG 实例，不用全局　`[relic/03#S1]`

【读】`howto/godot/relic-build.md#2. RNG：seed 与 state 是两个层级`

【做】`var _run_rng := RandomNumberGenerator.new()`，⛔ 不用全局 `randi()`。

ⓘ 全局 RNG 被 UI、粒子、任何随机共同消耗——
玩家开菜单看一眼都会让序列错位。

【产出】`_run_rng` 独立实例

【判据】⚠ 中途触发 100 次无关随机，**后续抽取序列不变**

【审】`audit/godot/relic-build.md#4`

### Step 2　⛔ 顺序写死：先 seed 后 state　`[relic/03#S2]`

【读】`howto/godot/relic-build.md#2. RNG：seed 与 state 是两个层级`

【做】
```gdscript
_rng.seed  = seed_value    # ① 先
_rng.state = saved_state   # ② 后（若有）
```

⛔ **官方原话：*"Changing the seed will reset the state, so make sure to
set the seed first."* —— 顺序反了，恢复的 state 会被 seed 覆盖。**

⚠ 症状：读档后前几次抽取正常、之后逐渐与存档前不一致，
排查时容易被引到"是不是存档漏了字段"。

【产出】`start_run()` 固定顺序

【判据】⚠ 存档后恢复，**连续抽 20 次与存档前逐次相同**

【审】`audit/godot/relic-build.md#5` `audit/godot/relic-build.md#22`

### Step 3　⚠ 种子必须先过哈希　`[relic/03#S3]`

【读】`howto/godot/relic-build.md#3. 种子质量：RNG 没有雪崩效应`

【做】`_rng.seed = hash(seed_value)`。

⛔ **官方原话：RNG 无雪崩效应，相似种子产生相似序列。**
用局数 `1/2/3` 当种子 → 三局体验几乎一样。

【产出】种子过 `hash()`

【判据】⚠ 种子 1 与种子 2 的序列**不相似**（逐项比对差异）

【审】`audit/godot/relic-build.md#6`

### Step 4　⚠ 三选一不重复且顺序也走同一 RNG　`[relic/03#S4]`

【读】`howto/godot/relic-build.md#2. RNG：seed 与 state 是两个层级`

【做】抽取与排序都从 `_run_rng` 取，⛔ 排序不用 `Array.shuffle()`（那是全局）。

⛔ 排序另用随机会让"同一个种子的三选一顺序"不可复现，
回放对不上，且**不报错**。

【产出】`roll_offering(n)` 返回不重复且顺序确定的 n 个 id

【判据】⚠ 同种子跑两遍，**顺序也逐项相同**

【审】`audit/godot/relic-build.md#22`

### Step 5　⛔ 空池必须显式兜底　`[relic/03#S5]`

【读】`howto/godot/relic-build.md#4. 权重抽取：空数组返回 -1`

【做】每次 `rand_weighted` 后判 `-1`，池空时走显式兜底路径。

⛔ 不判 -1 直接当索引用 → 取到 `pool[-1]` = **数组最后一个元素**，
不崩溃、不报错，只是**每次空池都固定给出同一件遗物**。

ⓘ 这个 bug 的特征是"某种稀有度抽完后再也不出别的"，极难归因。

【产出】`-1` 判定 + 空池兜底

【判据】⚠ 人为清空一个稀有度池，**不再静默返回同一个遗物**

【审】`audit/godot/relic-build.md#7` `audit/godot/relic-build.md#18`

### Step 6　⚠ 抽取结果服务端裁决　`[relic/03#S6]`

【读】`howto/godot/relic-build.md#9. 相关文档`

【做】涉排行榜/成就的局内构筑，抽取在服务端或服务端可校验。

⛔ 客户端决定 → 可伪造遗物来源。

【产出】抽取结果可校验

【判据】⚠ 客户端改为必出稀有，**服务端结果不变**

【审】`audit/godot/relic-build.md#16`

## 5. 常见返工

**① 用全局 RNG。** 开菜单就错序列。

**② 先 state 后 seed。** 恢复被覆盖，前几次对后面错。

**③ 种子不哈希。** 相邻局体验几乎一样。

**④ 不判 -1。** 空池静默返回最后一个。
