## 0. 交付物定义

⚠ **各功能点自己的验收不能替代域级验收。**
部件全合格、拼起来不能用，是跨域开发的典型失败——
遗物尤其如此，它横跨 roguelike 生成 / build-affix / economy / save / netsync 五个域。

做完这一步，应该能**当场演示**并**签核**：

1. 01 定义的三个证明场景全部成立
2. ⚠ **种子复现实测**：同种子两遍，遗物序列逐项相同
3. ⚠ **读档复现实测**：存档恢复 state 后，连续抽取与存档前一致
4. ⚠ **空池实测**：人为清空一个池，不静默返回最后一个
5. ⚠ **接缝复查**：与 genres-roguelike / build-affix / gem-rune / economy 的契约全对上

## 2. 工序

【审】`audit/godot/relic-build.md#23`

### Step 2　⚠ 种子复现实测　`[relic/07#S2]`

【读】`howto/godot/relic-build.md#2. RNG：seed 与 state 是两个层级`

【做】同一个种子跑两遍，逐项比对遗物序列（**含顺序**）。

⛔ 只比对"拿到哪些"不比对顺序 → 三选一的呈现顺序不可复现，
回放对不上，且**不报错**。

【产出】序列比对表

【判据】⚠ id 与顺序**双双一致**

【审】`audit/godot/relic-build.md#22`

### Step 3　⚠ 读档复现实测　`[relic/07#S3]`

【读】`howto/godot/relic-build.md#2. RNG：seed 与 state 是两个层级`

【做】存档 → 恢复 `state` → 继续抽 20 次，与未存档的同一序列比对。

⛔ 这条不测，05 的顺序错误会以"前几次对、后面错"的形式漏到线上——
这是本域**最难复现**的一类 bug。

【产出】读档前后序列比对

【判据】⚠ 连续 20 次**逐次相同**

【审】`audit/godot/relic-build.md#5` `audit/godot/relic-build.md#22`

### Step 4　⚠ 空池实测　`[relic/07#S4]`

【读】`howto/godot/relic-build.md#4. 权重抽取：空数组返回 -1`

【做】人为清空一个稀有度池，确认走显式兜底。

⛔ 不测的话，"空池固定返回最后一个"会一直存在——
它不崩溃、不报错，只是那个稀有度看起来"总出同一件"。

【产出】空池行为记录

【判据】⚠ 不再静默返回同一个遗物，且日志可见兜底路径

【审】`audit/godot/relic-build.md#7` `audit/godot/relic-build.md#18`

### Step 5　⚠ 接缝复查　`[relic/07#S5]`

【读】`howto/godot/relic-build.md#9. 相关文档`

【做】逐条核对 00 总览第 2 节的八条契约：

| 接缝 | 复查点 |

| `genres-roguelike.md` 分层 | 本域只管养成层，不改生成层 |

【产出】接缝复查表
