## 0. 交付物定义

⚠ **与 `gem-rune.md` 同构**：模板/实例两层。
⛔ 不要发明第三套——同项目的宝石、遗物、词条若各有一套，
做"遗物影响装备词条"时要写三份适配。

做完这一步，应该能**当场演示**：

1. 配表改一个遗物的数值，**所有已持有**的该遗物随之变化
2. ⚠ 同一遗物拿 3 次，**实例只有一个**且 `stacks=3`
3. 遗物是 `Resource`，能进存档与网络包
4. ⚠ 卸载/清空局内状态，**不影响**局外解锁
5. `tags` 可用于协同判定（04 的输入）

**产出物**（下游按名字对接）：

```text
RelicBase:      relic_id / rarity / effects[{stat,value,op}] / tags
RelicInstance:  relic_id / instance_id / stacks
RelicPool:      rarity -> Array[relic_id]（进配表，不硬编码）
```

## 2. 工序

### Step 1　⛔ 必须是 Resource 不是 Node　`[relic/02#S1]`

【读】`howto/godot/relic-build.md#1. 遗物池三层：池 / 稀有度 / 实例`

【做】`RelicBase extends Resource`、`RelicInstance extends Resource`。

⛔ 做成 Node 的后果：不能进存档与网络包，
序列化会带上整棵子树。

【产出】两个 Resource 类

【判据】⚠ `ResourceSaver.save()` 能存、能读回，字段相等

【审】`audit/godot/relic-build.md#2`

### Step 2　⚠ 叠加用 stacks 不用多实例　`[relic/02#S2]`

【读】`howto/godot/relic-build.md#1. 遗物池三层：池 / 稀有度 / 实例`

【做】`RelicInstance.stacks` 表达层数。

⛔ 用多实例的话，协同判定要处理"同一 id 出现多次"，
UI 要合并显示——**两处都会变复杂**。

【产出】`stacks` 字段

【判据】⚠ 拿 3 次后实例数为 1、`stacks == 3`

【审】`audit/godot/relic-build.md#3`

### Step 3　⚠ 稀有度与池进配表　`[relic/02#S3]`

【读】`howto/godot/relic-build.md#1. 遗物池三层：池 / 稀有度 / 实例`

【做】`rarity` 与池内容都来自配表，⛔ 不硬编码。

⛔ 硬编码的话改数值要发版，
且"某稀有度抽完了"这类运行时状态无处可存。

【产出】`RelicPool` 配表结构

【判据】⚠ 搜索稀有度数字常量，**结果为 0**

【审】`audit/godot/relic-build.md#17`

### Step 4　⚠ tags 用于协同判定　`[relic/02#S4]`

【读】`howto/godot/relic-build.md#5. 协同：显式遗物，不要让词条互相感知`

【做】`RelicBase.tags: PackedStringArray`。

ⓘ 协同（04）按 tag 或 id 判定，⛔ 不靠遗物内部互相感知。

【产出】`tags` 字段

【判据】⚠ 加一个新遗物，**不需要改**任何已有遗物的定义

【审】`audit/godot/relic-build.md#8`

### Step 5　⚠ effects 用 op 表达加/乘　`[relic/02#S5]`

【读】`howto/godot/relic-build.md#1. 遗物池三层：池 / 稀有度 / 实例`

【做】`effects: [{stat, value, op}]`，`op` 取 `add` / `mul`。

⛔ 只支持 `add` 的话，"暴击伤害 +30%"无法表达，
后期加 `mul` 要改所有配表结构。

【产出】`effects` 结构含 `op`

【判据】⚠ 同一遗物能同时表达 `+10 攻击` 与 `×1.3 暴伤`

【审】`audit/godot/relic-build.md#17`

## 5. 常见返工

**① 做成 Node。** 存不了档、进不了网络包。

**② 叠加用多实例。** 协同与 UI 两处复杂化。

**③ 稀有度硬编码。** 改数值要发版。

**④ effects 只支持 add。** 百分比后期加不进去。
