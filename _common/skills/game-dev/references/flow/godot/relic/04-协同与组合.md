## 0. 交付物定义

⚠ **"拿了 A 又拿 B 触发额外效果"必须做成显式规则。**

⛔ 让遗物互相感知（A 内部判断"我有没有 B"）的话，
规则散落在每个遗物里，**加一个新遗物要改所有相关遗物**。

做完这一步，应该能**当场演示**：

1. 同时持有 A 与 B → 触发；只持有一个 → 不触发
2. ⚠ 同一遗物叠 3 层 → **不触发**需要 3 件不同的协同
3. 加一个新遗物 → **不需要改**任何已有遗物的定义
4. ⚠ 组合受约束：减伤类叠加**不会**到 100%
5. 触发来源可追溯（能列出参与协同的 `relic_id`）

**产出物**（下游按名字对接）：

```text
RelicSynergy: require_ids: Array[StringName] / effect: Dictionary
_check_synergy(owned_set) -> Array[active_synergy]
```

## 2. 工序

### Step 1　⚠ 独立协同表　`[relic/04#S1]`

【读】`howto/godot/relic-build.md#5. 协同：显式遗物，不要让词条互相感知`

【做】`RelicSynergy` 独立成表，⛔ 不写在遗物内部。

⛔ 写在遗物内部 → 加新遗物要改所有相关遗物。

【产出】`RelicSynergy` 资源与配表

【判据】⚠ 加一个新遗物，**不改**任何已有遗物定义

【审】`audit/godot/relic-build.md#8`

### Step 2　⛔ 判定按去重集合　`[relic/04#S2]`

【读】`howto/godot/relic-build.md#5. 协同：显式遗物，不要让词条互相感知`

【做】按 `relic_id` 的**去重集合**判定，不是按 `stacks` 总数。

⛔ 按数量判定 → 同一遗物叠 3 层会触发需要 3 件不同的协同。

【产出】`_check_synergy()` 纯函数

【判据】⚠ 同一遗物叠 3 层**不触发**需要 3 件不同的规则

【审】`audit/godot/relic-build.md#9`

### Step 3　⛔ 组合必须受约束　`[relic/04#S3]`

【读】`howto/godot/relic-build.md#6. 局内属性：脏标记快照，不是每帧遍历`

【做】减伤类叠加上限必须存在，⛔ 不允许到 100%。

⛔ 到 100% 会除零 → **属性变成 NaN 或负数**，
表现为"伤害变成负数，怪越打血越多"。

【产出】减伤类上限约束

【判据】⚠ 堆满减伤遗物，**减伤 < 100% 且属性无 NaN**

【审】`audit/godot/relic-build.md#11`

### Step 4　⚠ 触发来源可追溯　`[relic/04#S4]`

【读】`howto/godot/relic-build.md#5. 协同：显式遗物，不要让词条互相感知`

【做】记录参与触发的 `relic_id` 清单。

⛔ 不记录 → 玩家问"为什么没触发"时无法回答，
只能让他自己数，而他数的结果与你代码算的可能不一致。

【产出】触发来源清单

【判据】⚠ 任一时刻能列出**参与触发的具体 `relic_id`**

【审】`audit/godot/relic-build.md#21`

### Step 5　⚠ 触发后并入属性管线　`[relic/04#S5]`

【读】`howto/godot/relic-build.md#6. 局内属性：脏标记快照，不是每帧遍历`

【做】协同效果是管线的一环，⛔ 不在管线外累加。

⛔ 管线外累加 → 下次重算被覆盖，
表现为"刚触发变强了，打一场又变回去"。

【产出】协同效果在管线内的固定位置

【判据】⚠ 移除参与遗物后，结果与"从未触发过"**逐字段相等**

【审】`audit/godot/relic-build.md#20`

## 5. 常见返工

**① 协同写在遗物内部。** 加新遗物要改一堆。

**② 按 stacks 总数判定。** 叠 3 层误触发。

**③ 减伤无上限。** NaN / 负伤害。

**④ 管线外累加。** 打一场又变回去。
