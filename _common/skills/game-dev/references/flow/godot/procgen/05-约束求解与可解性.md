# 05 约束求解与可解性（程序化生成域）

> **前置**：[03-布局算法与连通性](03-布局算法与连通性.md) 已验收
> **本步交付**：约束集 + 可解性校验 + 失败兜底
> **对应**：流程 `howto/godot/procedural-generation.md` · 审核 `audit/godot/procedural-generation.md`

## 0. 交付物定义

1. WFC 类算法有明确约束集与回退
2. 有锁与钥匙时，**可解性**被单独校验（不只是连通）
3. 求解失败有兜底，不会卡死

- [ ] 03 已完成
- [ ] ⚠ 已列出所有"锁 - 钥匙"关系
- [ ] 有一个能在生成后跑的求解器（模拟通关）

## 2. 工序

### Step 1　把约束写成数据　`[procgen/05#S1]`

【读】`howto/godot/procedural-generation.md#2. 算法选型`

【做】
邻接约束、朝向约束写成表，不是散落在 if 里。
⛔ WFC 是瓦片随机摆？它是**约束求解**，会矛盾，需要回退。

【产出】约束表（数据，不是代码分支）

【判据】改一个约束不用改代码。

【审】`audit/godot/procedural-generation.md#9`

### Step 2　回退策略先写好　`[procgen/05#S2]`

【读】`howto/godot/procedural-generation.md#2. 算法选型`

【做】
矛盾时回退到上一个可解状态，次数有上限。
⛔ 没有回退 → 求解器卡死或产出半截地图，⛔ 且不报错。

【产出】回退次数上限 + 超限行为（换种子重来）

【判据】故意构造矛盾约束 → 生成器**换种子重来**，不卡死。

【审】`audit/godot/procedural-generation.md#9`

### Step 3　可解性单独校验　`[procgen/05#S3]`

【读】`howto/godot/procedural-generation.md#3. 连通性校验是必做步骤`

【做】
模拟通关：从起点出发，遇到锁就检查钥匙是否**在锁之前**可达。
⛔ 以为连通就是能通关 —— 还要**可解**，钥匙顺序错了就是死局。

【产出】可解性报告（每一步拿了什么、开了什么）

【判据】模拟通关器**能跑到终点**；跑不到就是不可解。

【审】`audit/godot/procedural-generation.md#23`

### Step 4　难度上下界　`[procgen/05#S4]`

【读】`howto/godot/procedural-generation.md#3. 连通性校验是必做步骤`

【做】
给生成结果定难度上下界（敌人总强度、资源总量），超界重生成。
⛔ 只按"距离足够远"撒点 → 泊松只管**间距**、**不管玩法密度**，强度不可控，某局强到没法打。

【产出】难度评分 + 可接受区间

【判据】连续生成 100 次，难度评分全部落在区间内。

【审】`audit/godot/procedural-generation.md#10`

### Step 5　兜底种子　`[procgen/05#S5]`

【读】`howto/godot/procedural-generation.md#2. 算法选型`

【做】
重试 N 次仍失败 → 用**已知可解的兜底布局**，并记日志。
⛔ 无限重试 → 生成阶段卡死在加载界面。

【产出】兜底布局 + 失败日志

【判据】人为让 100% 失败 → 仍能进入游戏，且日志有记录。

【审】`audit/godot/procedural-generation.md#9`

## 3. 参考实现

```gdscript
const MAX_RETRY := 8

func generate(seed_src: String) -> Dictionary:
    for i in MAX_RETRY:
        var data := _try_generate(seed_src, i)
        if data.is_empty():
            continue
        if _is_solvable(data) and _difficulty_in_range(data):
            return data
    push_warning("生成失败，使用兜底布局")
    return FALLBACK_LAYOUT.duplicate(true)
```
