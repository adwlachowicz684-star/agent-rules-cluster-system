# 04 内容投放与密度（程序化生成域）

> **前置**：[03-布局算法与连通性](03-布局算法与连通性.md) 已验收
> **本步交付**：合法子区域 + 密度预算 + 节奏
> **对应**：流程 `howto/godot/procedural-generation.md` · 审核 `audit/godot/procedural-generation.md`

## 0. 交付物定义

1. 每个合法子区域单独算可接受点
2. 密度按节奏分布，不是均匀
3. 生成物与手工件风格一致

## 1. 前置检查清单

- [ ] 03 已完成（布局连通且覆盖 100%）
- [ ] ⚠ 已有"合法位置"的定义（离墙多远、坡度上限、是否挡路）
- [ ] 有威胁预算 / 视线 / 出生距离三个维度

## 2. 工序

### Step 1　先划合法子区域　`[procgen/04#S1]`

【读】`howto/godot/procedural-generation.md#3. 连通性校验是必做步骤`

【做】
按区域（房间 / 洞室 / 平台）分别算可接受点，再叠加约束。
⛔ 泊松采样解决布点？它只管间距，**不管玩法密度** ——
只用"距离足够远"会生成四角远离路径、**玩家完全看不到的奖励**。

【产出】合法点集合（按区域分组）

【判据】每个区域都有至少一个可站点；没有"奖励刷在看不见的角落"。

【审】`audit/godot/procedural-generation.md#10`

### Step 2　按区域分配密度预算　`[procgen/04#S2]`

【读】`howto/godot/procedural-generation.md#3. 连通性校验是必做步骤`

【做】
给每个区域一个密度配额（威胁 / 奖励 / 装饰），总量受控。
⛔ 只按"距离足够远"撒点 —— 会出现某一片挤成一团、另一片全空。

【产出】密度配额表（区域 → 各类数量）

【判据】任意两个区域的密度差在设定倍率内。

【审】`audit/godot/procedural-generation.md#10`

### Step 3　噪声驱动的连续投放　`[procgen/04#S3]`

【读】`howto/godot/procedural-generation.md#8. FastNoiseLite 的默认值与取值域`

【做】
用 `FastNoiseLite` 做连续量（植被密度、矿脉走向）。
⚠ `noise_type` 默认 `TYPE_SIMPLEX_SMOOTH`，不是 value 噪声。

【产出】连续密度场

【判据】密度场**平滑过渡**，不是块状跳变。

【审】`audit/godot/procedural-generation.md#17`

### Step 4　阈值要按实际取值域定　`[procgen/04#S4]`

【读】`howto/godot/procedural-generation.md#8. FastNoiseLite 的默认值与取值域`

【做】
cellular 噪声**可能返回大于 1**，阈值不能按 `[0,1]` 拍。
⛔ 把 cellular 当 `[0,1]` 用 → 阈值失效，表现为"洞穴比预期大一圈"。

【产出】阈值表（含每种噪声的实测取值域）

【判据】阈值来自**实测最大值**，不是文档里的"一般为"。

【审】`audit/godot/procedural-generation.md#18`

### Step 5　密度要有节奏　`[procgen/04#S5]`

【读】`howto/godot/procedural-generation.md#3. 连通性校验是必做步骤`

【做】
按段落分配密度：紧张段密、喘息段疏、高潮段最密。
⛔ 以为密度均匀 = 合理 —— 均匀就是**没有节奏**，玩家读不出区域差异，
全程体感强度一样，等于全程没有强度。

【产出】节奏曲线（沿主路径的密度剖面）

【判据】玩家能说出"哪段最紧张"；说不出就是没做出节奏。

【审】`audit/godot/procedural-generation.md#24`
【品】`craft/godot/cheapness.md#6. 生成类廉价感（PCG 特有）`

## 3. 参考实现

```gdscript
func _density_at(path_t: float) -> float:
    # 节奏曲线：0.0 起点 → 0.3 喘息 → 0.7 紧张 → 1.0 高潮
    return clampf(sin(path_t * PI * 1.5) * 0.5 + 0.4, 0.15, 1.0)
```
