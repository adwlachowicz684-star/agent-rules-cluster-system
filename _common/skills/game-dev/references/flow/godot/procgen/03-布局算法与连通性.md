# 03 布局算法与连通性（程序化生成域）

> **前置**：[02-随机源与可复现](02-随机源与可复现.md) 已验收

## 0. 交付物定义

1. 布局算法与场景类型匹配（不拿迷宫当自然地牢）
2. 生成后必做 flood fill，**未访问的地板必须处理**
3. 有环路，不是纯树

## 2. 工序

### Step 1　按场景类型选算法　`[procgen/03#S1]`

【读】`howto/godot/procedural-generation.md#2. 算法选型`

【做】
BSP 用于结构化地牢、递归回溯用于迷宫、元胞自动机用于洞穴、WFC 用于邻接约束明确者。
⛔ BSP 出来就以为能玩 —— 它产出的是**树**，**可能没环**，探索感差。

【产出】算法选型记录（含为什么选它）

【判据】能说出"选它是因为场景类型是 X"，而不是"教程用的这个"。

【审】`audit/godot/procedural-generation.md#6`

### Step 2　生成后立刻 flood fill　`[procgen/03#S2]`

【读】`howto/godot/procedural-generation.md#3. 连通性校验是必做步骤`

【做】
从出生点 flood fill，未访问的地板**改写、连接或删除**。
⛔ 以为 flood fill 可省 —— 除非方法本身保证连通，否则必做。

【产出】覆盖率统计（可达地板 / 总地板）

【判据】覆盖率 **100%**，或剩余部分被明确删除。

【审】`audit/godot/procedural-generation.md#15`

### Step 3　保留最大连通分量　`[procgen/03#S3]`

【读】`howto/godot/procedural-generation.md#3. 连通性校验是必做步骤`

【做】
元胞自动机**最容易产生不可达区域** —— 保留最大连通分量，删掉其余。

【产出】连通分量数量统计

【判据】连通分量数 = 1。

【审】`audit/godot/procedural-generation.md#8`

### Step 4　补环路　`[procgen/03#S4]`

【读】`howto/godot/procedural-generation.md#2. 算法选型`

【做】
先建完美迷宫再按概率**破墙**增加环路，或按距离给不相邻房间补边。
⛔ 迷宫很自然？实际**机械、多长死胡同**，玩家来回跑同一条路。

【产出】环路计数（环数 / 房间数）

【判据】debug 图上能看到明显回路，不是只有一条主路径。

【审】`audit/godot/procedural-generation.md#7`

### Step 5　布局要"有变化"　`[procgen/03#S5]`

【读】`howto/godot/procedural-generation.md#2. 算法选型`

【做】
给这局定一个**母题**（峡谷 / 沼泽 / 废墟），噪声只在母题内变化。
⛔ 纯随机的地形是"每个地方都一样地不一样"，玩家记不住任何地方。

【产出】母题参数（每局随机一个，写入种子契约）

【判据】玩家能凭记忆描述刚走过的地方；描述不出来就是没做出变化。

【审】`audit/godot/procedural-generation.md#6`
【品】`craft/godot/aesthetics.md#8. 程序化内容的审美：随机不等于有变化`

## 3. 参考实现

```gdscript
func _flood_fill(grid: Array, start: Vector2i) -> Array:
    var seen := {}
    var stack := [start]
    while stack.size() > 0:
        var c: Vector2i = stack.pop_back()
        if seen.has(c) or not _is_floor(grid, c):
            continue
        seen[c] = true
        for d in [Vector2i.UP, Vector2i.DOWN, Vector2i.LEFT, Vector2i.RIGHT]:
            stack.append(c + d)
    return seen.keys()
```
