# 合规与法务：版号 / 实名防沉迷 / 隐私 / 出海（Godot 4.7.2）

**此前文档里「版号 / 实名认证 / 适龄提示 / 隐私政策 / 数据删除 / 内容审核 / 用户协议」全部 0 命中。**

> 商业化与支付合规见 `monetization.md`；聊天与举报见 `social.md`；
> 运营配置与补偿见 `ops.md`；SDK 与账号令牌见 `platform-services.md`。

⚠ **Godot 不提供任何合规 API。** 没有实名校验、没有防沉迷计时、没有年龄分级、
没有隐私同意框架、没有数据删除接口。这些全部是**服务端 + 流程**的事，
引擎侧唯一能做对的是「不要假装客户端能兜住」。

> 审核用反模式清单见 `audit/godot/compliance.md`

## 0. 先分清三栏，否则会做无用功

| | 中国大陆 | 海外主要市场 | 共通基础 |
|---|---|---|---|
| 版号 / 许可 | **必须**（ISBN 批准文号 + 出版物号） | 无版号制度，但有商店与分级 | — |
| 实名 | **必须**（国家统一防沉迷实名验证系统） | 无统一实名，但有年龄门 | — |
| 时段 / 充值硬控 | **必须**（法条有具体数字） | 韩国等个别市场有，需当地核实 | — |
| 适龄提示 | **必须**（8+/12+/16+） | 分级机构（如 GRAC、PEGI） | — |
| 隐私政策 / 同意 | 必须（PIPL） | 必须（GDPR / CCPA） | ✅ |
| 删除权 / 导出权 | 必须（PIPL 第 47 条） | 必须（GDPR 第 17/20 条、CCPA） | ✅ |
| 敏感词 / UGC 审核 | 必须 | 视市场 | ✅ |
| SDK 数据台账 | 必须 | 必须（商店隐私问卷） | ✅ |

⚠ **最大的误判是「上线前补一份隐私政策就合规了」。**
在中国大陆，真正的硬门槛在**立项阶段**：没有有资质的出版单位、没有 ICP 证、没有版号，
产品**不能**以运营或商业化方式上线——这与代码写得多好无关。

## 1. 中国大陆：版号是前置许可，不是商店审核

⚠ **法定办结承诺是「自受理申请之日起 80 个工作日」（国家新闻出版署审批事项），
这是行政受理后的时限，不等于企业从立项到拿号的总周期。**

受理前还要走：出版单位内部评估 → 申报材料制作 → 省级初审上报 → 内容修改与材料补正。
→ **版号要作为立项时的并行关键路径，不能排成上线前最后一步。**

### 主体资质（技术团队最容易忽略）

| 角色 | 硬性要求 |
|---|---|
| 出版单位 | 必须具有**网络游戏出版范围**的网络出版服务单位 |
| 运营单位 | 必须持有《增值电信业务经营许可证》（ICP 证） |
| 著作权人 | 国产游戏须为中国公民或内资企业，并提交著作权登记/公证/声明 |

⚠ **小团队不能靠个人开发者账号在中国大陆上线商业网络游戏。**
"代办个人"不能替代法定义务主体。

### 无版号上线的后果（不是理论风险）

《网络出版服务管理规定》第 51 条：取缔、删除全部相关网络出版物、没收违法所得及主要设备工具；
违法经营额 1 万元以上处 **5–10 倍**罚款，不足 1 万元可处 **5 万元以下**罚款。

⚠ **已经退款、没有收入、准备后补都不能自动消除违法状态。**
已见执法案例：一款无版号游戏经退款后认定无违法所得，仍被罚款 5.5 万元。

⚠ **内测不是天然免责。** 官方工作指引明确：
**公开可注册服务器的测试、收费测试、有广告收益的测试或具备其他运营特征的测试，视为网络游戏运营**，
必须先取得批准文号；限额测试用户数**不得超过 2 万**且测试资料须**删档**。

### 送审材料里有技术侧要交的东西

官方目录包含：中文脚本全文、**屏蔽词库**、防沉迷系统功能说明、内容审查管理账号与防沉迷测试账号、
游戏画面截图、演示视频。

⚠ **这决定了版本仓库必须保存与送审版本一致的脚本、资源清单、敏感词库、防沉迷说明和审查账号。**
正式版与审批版内容漂移，本身就是风险。

## 2. 实名与防沉迷：服务端强控闭环

### 现行时段（2021 通知为准）

⚠ **国新出发〔2021〕14 号（2021-09-01 施行）**：
所有网络游戏企业**仅可在周五、周六、周日和法定节假日每日 20 时至 21 时**向未成年人提供 **1 小时**服务，
**其他时间均不得以任何形式提供**。

⚠ **2019 通知的「22:00–次日 8:00 禁玩」「节假日 3 小时 / 其他 1.5 小时」不是现行时段口径。**
2021 通知明确：与 2019 通知不一致的，以 2021 通知为准。
→ 照 2019 口径实现会**错放行**。

### 实名是登录前置，不是充值前置

⚠ **不得以任何形式（含游客体验模式）向未实名注册和登录的用户提供游戏服务。**

⚠ **实名不是"客户端校验证件格式"** —— 法定实名验证通过国家统一系统完成。
客户端只做格式预检可以，但**信任根必须是服务端**：验证结果、账号绑定、时钟来源都在服务端。

⚠ **不要无边界留存身份证照片、完整身份证号或人脸特征** —— 最小必要 + 用途限定 + 访问控制。

### 充值限额（法条数字，必须硬控）

| 年龄段 | 付费服务 |
|---|---|
| **未满 8 周岁** | **不得提供**游戏付费服务 |
| 8 周岁以上未满 16 周岁 | 单次 ≤ **50 元**，每月累计 ≤ **200 元** |
| 16 周岁以上未满 18 周岁 | 单次 ≤ **100 元**，每月累计 ≤ **400 元** |

⚠ 法条口径是「**同一网络游戏企业**所提供的游戏付费服务」，不是单款游戏。
工程上至少先在单游戏内实现单笔 / 自然日 / 自然月累计控制，再由企业统一账号做跨产品聚合。

⚠ **人脸验证不是全体用户的无条件前置条件。**
生物识别属《个人信息保护法》下的**敏感个人信息**，需特定目的 + 充分必要性 + 单独同意。
较稳的边界：人脸只用于**高风险复核**或依法确需场景，并先做必要性评估。
（具体尺度因支付渠道与地区实践而异 → 待项目法务确认）

### 服务端要做的事

账号表至少维护：身份核验结果、出生日期或年龄、未成年人状态、验证时间、实名凭证引用。

```gdscript
# 客户端只展示，不能当判据
func can_play_now(profile: Dictionary, now_unix: int) -> bool:
    if not profile.get("verified", false):
        return false                       # 未实名：不得提供任何服务
    if not profile.get("is_minor", false):
        return true
    return _in_minor_window(now_unix)      # 服务端算：周五六日/法定节假日 20:00-21:00
```

⚠ **每日 1 小时要依据服务器时区 + 法定节假日日历 + 可审计时钟判断**，
并记录进入、退出、断开与补时逻辑。**离线模式、快速恢复、多端并发、时区切换都要服务端重算。**
日志覆盖登录、验证、充值拦截、退款、人工修改与异常并发——但**日志不等于无限期留存身份信息**。

## 3. 适龄提示：不是法律意义上的分级

⚠ **8+ / 12+ / 16+ 是「适龄提示」，中国没有游戏分级制度。**
中国音数协团体标准采用绿色 8+、蓝色 12+、黄色 16+ 三档，**明确没有纳入 18+ 档**。
目的不是放宽内容审核，而是补充严格审查、引导合理使用。

⚠ 各档「不应存在 / 可存在」的逐项判定阈值未从官方公开页面完整取得 → **不要编造阈值**。
（本项待取得正式标准文本后回填）

标识须放置于：官网、客户端注册/登录节点、付费界面、宣传视频与广告等显著位置。

⚠ **未实名者不得游戏的规则，高于任何"先试玩再提示"的产品设计。**

## 4. 隐私与删除权：注销 ≠ 立即全量物理抹除

### PIPL（《个人信息保护法》，2021-11-01 施行）

必须提供：处理者身份与联系方式、处理目的/方式/信息类别、保存期限、权利行使途径、投诉渠道。
涉及敏感个人信息、对外提供、公开、自动化决策的，还要**单独告知**。

⚠ **不能把「登录即同意全部条款」作为唯一路径**，
也不能因玩家拒绝非必要权限而拒绝提供核心玩法。

### 删除权要做成状态机，不是一句 DELETE

⚠ 第 47 条：目的已实现且不再必要、停止服务、保存期限届满、撤回同意或违法违约处理的，
应主动删除，个人亦有权请求删除。**若法定保存期未届满或技术上暂时难以删除，
至少停止除存储和必要安全保护之外的处理。**

```
requested → identity_verified → scheduled/anonymized
          → pending_retention_review → purged
```

- 身份核验后**立即**切断登录、取消会话、删除或匿名化可直接识别自然人的字段
- 订单、退款、税务、安全事件、法定义务要求保留的数据 → **去标识化 + 访问隔离 + 到期删除标记**，
  不是长期保留完整账号资料
- ⚠ **第三方接收方（云厂商、客服、支付、广告、统计、推送）必须同步删除或停止处理。
  不能拿"第三方删不掉"当免责理由。**

### 14 岁以下与敏感信息

⚠ **不满 14 周岁未成年人的个人信息属敏感个人信息**，需监护人同意 + 专门处理规则。
昵称、头像、聊天、设备标识符、支付记录、位置日志若可用于识别未成年人，都要纳入影响评估。

⚠ 生物识别、医疗健康、金融账户、行踪轨迹都属敏感个人信息。
**不要为防沉迷或新手引导默认索取精确后台定位**；确有玩法需要时优先模糊位置 + 会话内一次性授权。

### 数据出境是目的 × 类型 × 人数的组合，不是布尔值

《促进和规范数据跨境流动规定》（2024-03-22 施行）：

| 当年累计向境外提供 | 义务 |
|---|---|
| 不足 10 万人非敏感个人信息 | 免于申报评估 / 标准合同 / 认证 |
| 10 万–100 万人非敏感，或不足 1 万人敏感 | 标准合同或认证 |
| 100 万人以上非敏感，或 1 万人以上敏感 | 安全评估 |

⚠ **人数是"当年累计"的动态阈值，不是一次性项目规模。**
要建数据地图：字段、用途、接收国家/地区、是否敏感、是否可识别、传输频率、累计人数、保存地点；
**每次版本或 SDK 变动都要重算。** 海外云服务、海外客服工单、远程故障排查、
境外母公司访问、广告归因、崩溃分析都可能构成出境。

⚠ 不能只依赖"云厂商说数据在中国"——**跨境运维、备份与访问**没核实等于没查。

## 5. UGC 与 SDK：合规能力要进服务端治理

⚠ **不能把昵称、头像、公会名、聊天、语音转文字、公告、交易留言当成"用户自发内容"而免除治理责任。**

落地控制是五段：**发布前校验 → 发布后巡检 → 用户举报 → 人工复核 → 处置留痕**。

⚠ **敏感词库不是固定文件。** 要按政治、色情、赌博、诈骗、自伤、欺凌、暴恐、隐私、违法违规分类，
维护版本号 + 来源 + 更新日期 + 上线审批 + 失效日期。
**只有命中日志、没有误杀/漏杀抽检，无法证明治理有效。**

服务端留痕至少含：内容哈希、命中规则、模型分数、操作者、审核结果、处置时间、通知状态、申诉状态。

⚠ **SDK 不是"别人收集的数据，与我无关"。**
每个 SDK 都要建台账：采集字段 / 用途 / 是否关联账号或设备 / 是否用于追踪或广告 / 接收方 /
保存期限 / 地域 / 可关闭性。

- 上线门禁检查：数据处理协议、隐私政策、未成年人条款、跨境说明、版本、权限、域名列表、
  初始化时机、关闭开关、升级记录
- **延迟初始化非必要 SDK**，玩家同意前不得用于广告追踪或画像
- ⚠ 服务端限制 SDK 回传的账号字段——不要把原始昵称、聊天、精确位置或未脱敏设备标识发给统计/广告平台

## 6. 海外：GDPR 与 CCPA 是两类独立义务

### GDPR（2018-05-25 生效）

| 权利 | 要点 |
|---|---|
| 第 17 条 被遗忘权 | **有例外**（言论表达、法定义务、公共利益档案、科研统计、法律请求）→ 不能承诺"任何情况立即永久删除" |
| 第 20 条 数据可携权 | 适用于**基于同意或合同 + 自动化处理**的数据，要结构化、通用、机器可读 |
| 儿童同意年龄 | **默认 16 岁，成员国可降至不低于 13 岁** |

⚠ **不是"全欧盟统一 13 岁"。** 德、法、意、西等成员国具体年龄可能不同，
要按**玩家所在地**配置，不能只看语言或商店国家。
⚠ 欧盟跨境传输需充分性决定 / 适当保障 / 特定例外，**不能只因"云服务总部在欧洲"当低风险**。

### CCPA / CPRA（加州）

适用门槛（满足其一）：年总收入 > 2500 万美元；或购买/出售/共享 10 万名以上加州居民个人信息；
或过半收入来自出售加州居民个人信息。

消费者权利：知情、删除、更正、退出出售与共享（"共享"特指跨情境行为广告）、限制敏感信息使用。
⚠ **响应期限 45 日，可通知后延长 45 日（合计最长 90 日）。**
⚠ 删除请求要传递给服务供应商；广告 SDK 若构成跨情境行为广告，必须提供**真正可执行的退出**。

### 韩国

⚠ **"16 岁以下 0–6 时禁止"存在公开冲突材料**：早期《青少年保护法》第 26 条有此规定，
另有材料称 2022-01-01 废止并转为家长选择制。
→ **在取得当地现行法核验前，不要在 Godot 项目里硬编码 0–6 时锁服。**（待核实）
韩国市场另有 GRAC 分级、支付与概率披露要求，不能用中国防沉迷方案替代。

## 7. 商店：隐私声明是可验证事实，不是营销文案

⚠ **商店隐私问卷覆盖自身 + 第三方 SDK 的实际收集行为。声明与实际数据流不一致会同时触发商店审核和监管风险。**

- Apple：App Store 隐私信息（数据类型、用途、是否关联用户、是否用于追踪）；
  自 2024-05 起，常用第三方 SDK 清单上的 SDK 还涉及**隐私清单**与受限 API 使用理由
- Google Play 数据安全：收集/共享的数据、用途、是否加密、是否支持删除请求、是否遵守家庭政策

建议做法：构建流水线里加**隐私清单测试** —— 从首次启动抓包，识别域名、SDK 初始化、请求字段、设备标识符，
映射到问卷类别。⚠ **新增广告/统计/客服/远程配置/崩溃/反作弊 SDK 时，CI 必须阻止未更新隐私清单的版本合入。**


任何生产发布都要检查这些元数据。**缺一项就不该发。**
