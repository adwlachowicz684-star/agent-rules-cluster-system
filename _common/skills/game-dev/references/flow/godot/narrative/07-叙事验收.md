# 07 叙事验收 `[narrative/07]`


⚠ **各功能点自己的验收不能替代本验收** ——
部件全合格、拼起来不能用，是跨域开发的典型失败。

可签核的验收报告。

## 2. 工序

### Step 1　状态完整性验收　`[narrative/07#S1]`

【读】`howto/godot/narrative.md#0. ⚠ 首要任务不是写对话 UI，是建单一数据源`

【做】
验证 `StoryState` 是真正的单一数据源。

| 检查项 | 方法 |
|---|---|
| 无散落 flag | 全项目搜字符串字面量 flag，应为 0 |
| 无 UI 内状态 | 关掉 UI 再打开，对话停在同一句 |
| 可独立测试 | 空场景里能读写 flag |

【产出】
三项检查结果（逐项 通过/不通过）。

【判据】
三项全通过。

---

### Step 2　数据校验器全绿　`[narrative/07#S2]`

【读】`howto/godot/narrative.md#7. ⚠ 对话节点 ID 必须可校验，不能是裸字符串`

【做】
跑 02/S2 与 04/S3 建的校验器，确认：
- 全部 `next` 引用有效
- 冲突关系双向对称
- 无重复优先级

【产出】
校验器输出（0 错误）。

【判据】
0 错误。⛔ 有警告也要写清是否接受。

---

### Step 3　结局可达性验收　`[narrative/07#S3]`

【读】`howto/godot/narrative.md#10. ⚠ 分支可达性要能自动验证`

【做】
跑 04/S4 的可达性校验器。

⚠ 这是本域**最容易漏、后果最严重**的一项：
数据全绿但某个结局玩家永远到不了。

【产出】
每个结局的命中次数表。

【判据】
**每个结局命中次数 ≥ 1**。
⛔ 0 次的必须修，不能记为"已知问题"。

---

### Step 4　存档往返验收　`[narrative/07#S4]`

【读】`howto/godot/narrative.md#9. 对话与存档的接缝（三个必须对齐的点）`

【做】
三项对齐检查：

| 检查项 | 期望 |
|---|---|
| 已执行效果不重放 | 读档后重复对话，**奖励不再发第二次** |
| 中途存档恢复位置 | 从预期位置继续，不是从头 |
| 选项历史保留 | 结局判定依赖的历史选择不丢 |

【产出】
三项检查结果。

【判据】
三项全通过。⚠ 第 1 项失败是最严重的（等于可复制奖励）。

---

### Step 5　走查一遍主线　`[narrative/07#S5]`

【读】`howto/godot/narrative.md#1. 任务链`

【做】
⚠ **必须真人从头玩一遍主线**，⛔ 不能只跑自动化测试。

重点看三类问题：
- 卡关（某步不知道该干嘛）
- 不连贯（剧情跳跃、重复）
- 状态错乱（任务显示已完成但对话还是初次见面的内容）

【产出】
走查记录：卡关点 / 不连贯点 / 状态错乱点（各列举）。

【判据】
三类问题都有明确结论（已修 或 接受并写明理由）。

ⓘ 判据为什么是"有结论"而不是"0 问题"：
⚠ 叙事问题很多是设计取舍，⛔ 强行要求 0 会导致验收被绕过。
✅ 但**每一条都要有明确的处置结论**。

---

ⓘ 本功能点的可运行片段见做法文档对应章节：
`howto/godot/narrative.md`（见各 Step 的【读】锚点）。
⚠ 抄代码前先确认【读】指向的章节与当前 Step 讲的是同一件事。
