## 2. 工序

### Step 1　解锁状态来自单一数据源　`[narrative/05#S1]`

【读】`howto/godot/narrative.md#4. 进程结构：章节 / 关卡选择 / 周目`

【做】
⚠ **关卡选择界面的解锁状态必须从 `StoryState` 来**，
⛔ 不能各界面自己记一份（检查点、关卡解锁、章节解锁要同源）。

【产出】
一个 `is_unlocked(id)` 查询接口，所有界面共用。

【判据】
改一处 flag → 所有相关界面（关卡选择、章节、地图）**同时**反映变化。

【审】`audit/godot/narrative.md#18`（检查点=关卡解锁源 → 都要从单一数据源来）

---

### Step 2　周目继承策略分别定义　`[narrative/05#S2]`

【读】`howto/godot/narrative.md#4. 进程结构：章节 / 关卡选择 / 周目`

【做】
NewGame+ 的继承策略**按类型分别定义**：等级 / 装备 / 剧情 flag 各不相同。

⚠ **不能"全部继承"或"全部清空"** ——
这两个极端都会破坏设计意图（继承全部 → 二周目无挑战；全清空 → 元进度丢失）。

【产出】
一张继承表：每类数据 → 继承 / 清空 / 转换（如等级压缩后继承）。

【判据】
按表逐类验证：二周目开始时每类数据的实际值**与表一致**。

【审】`audit/godot/narrative.md#14`（周目继承全都有 → 等级/装备/flag 各不相同）

---

### Step 3　周目独有的事件　`[narrative/05#S3]`

【读】`howto/godot/narrative.md#4. 进程结构：章节 / 关卡选择 / 周目`

【做】
周目计数 + "只在一周目出现的事件"单独处理。

⚠ 常见遗漏：**剧情 flag 被继承后，二周目把"首次见面"的对话跳过了**，
玩家看到的是不连贯的剧情。

【产出】
一个 `playthrough` 计数 + 事件的周目条件字段。

【判据】
二周目进入 NPC 首次对话 → **对话内容正确**（不是跳到"又见面了"）。

---

### Step 4　动态难度（可选）　`[narrative/05#S4]`

【读】`howto/godot/narrative.md#5. 动态难度`

【做】
三种做法择一：按表现调整 / 按死亡次数 / 橡皮筋 AI。

⚠ **要让玩家察觉不到** —— 被察觉会觉得被羞辱。
⚠ **与成就/排行榜的冲突要提前想清楚**。

【产出】
难度调整函数 + 与成就系统的冲突结论（写明）。

【判据】
让模拟玩家连续失败 N 次 → 难度下调；
且**成就系统中受影响的项已明确标注**或已排除。

【审】`audit/godot/narrative.md#15`（动态难度越明显越好 → 被察觉会劝退）
