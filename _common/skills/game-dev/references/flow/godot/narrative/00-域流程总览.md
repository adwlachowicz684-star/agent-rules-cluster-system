# 叙事与任务域 · 流程总览 `[narrative/00]`

## 0. 先定做什么（⛔ 没写这三行不许开工）

⚠ **在翻任何做法文档之前，先把本次要做的范围写下来。**

⛔ 不做这一步就会顺着 howto 的完整内容往下做，做出需求外的东西。
同一个叙事域，"做一个能对话的 NPC"和"做一套多结局分支系统"
是**两条完全不同的流程**。

### 按需求挑功能点

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只是"能和 NPC 说话、能选选项" | 01 → 02 → 07 |
| 有任务（接取/进度/交付） | 01 → 02 → 03 → 07 |
| 有分支/多结局 | 01 → 02 → 03 → 04 → 07 |
| 有章节、关卡选择、周目 | 再加 05 |
| 有配音/字幕/演出 | 再加 06 |

⛔ **没被挑中的功能点本次不做**，不要"顺手把框架搭全"。

### 本次范围（写在这里）

```
要做什么：
不做什么：
```

## 1. 功能点拆解与依赖顺序

按上表挑出功能点后，按顺序执行。每个功能点文件里有带 ID 的节点
（`[narrative/0X#S#]`），**每个节点都是：读哪段 → 做什么 → 产出什么 → 判据 → 审什么**。

⚠ 依赖顺序不能乱（见下）。

## 2. ⚠ 最容易做反的顺序

```
01 状态与数据源   ← 一切的地基，⛔ 不能跳
 ↓
02 对话树与演出
 ↓
03 任务链
 ↓
04 分支与结局判定
 ↓
05 进程结构（章节/周目）
 ↓
06 配音与字幕
 ↓
07 叙事验收
```

⚠ **最容易做反的顺序**：先做对话 UI 再做状态层。

⛔ 后果：UI 会把状态藏在自己内部（见 howto 第 8 节），
等你要加存档/分支时才发现状态散在 UI 里，**那时已经改不动了**。

ⓘ 判据：`StoryState` 要能在**没有任何 UI** 的情况下被读写和测试。

## 3. 每做完一个功能点必做

做完挑中的功能点后，走 **07 叙事验收**。

⚠ 各功能点自己的验收不能替代域级验收 ——
部件全合格、拼起来不能用，是跨域开发的典型失败。

## 4. 参数登记

⚠ 本域的关键数值要登记在这里，避免散落各处后无法统一调整。

| 参数 | 取值 | 登记于 |
|---|---|---|
| flag 命名前缀 | `global.` / `meta.` / `<act>.<scene>.*` | 01/S2 |
| 结局优先级 | 见结局表 `priority` 字段 | 04/S2 |
| 周目继承策略 | 见继承表 | 05/S2 |
