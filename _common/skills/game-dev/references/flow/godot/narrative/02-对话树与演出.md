## 2. 工序

### Step 1　定对话数据结构　`[narrative/02#S1]`

【读】`howto/godot/narrative.md#2. 对话树`

【做】
定义 `DialogueNode` + `Choice` + 条件 + 效果四件套。
⚠ 目标类型（击杀/收集/到达/对话/复合）要**可配置不要写死**。

【产出】
三个自定义 `Resource`：`DialogueLine` / `DialogueChoice` / `DialogueGraph`。

【判据】
能在检视器里手工搭出一条含 3 句正文 + 2 个选项的对话并跑通。

【审】`audit/godot/narrative.md#11`（对话效果时机随便 → 要明确选中时 vs 结束时）

---

### Step 2　建 ID 注册表与校验　`[narrative/02#S2]`

【读】`howto/godot/narrative.md#7. ⚠ 对话节点 ID 必须可校验，不能是裸字符串`

【做】
所有节点 ID 集中注册；写校验器遍历**全部**节点，
检查 `line.next` 与 `choice.next` 都存在于注册表。

⚠ **默认不显示的选项同样要校验** —— 它们最容易被测试跳过。

✅ 运行时兜底：找不到时**明确报错并停在原地**，
⛔ 不要静默结束对话（那会把数据错误伪装成剧情结束）。

【产出】
一个可执行/可脚本调用的校验器，输出所有悬空引用。

【判据】
故意把某个 `next` 改成一个不存在的 ID，校验器**必须报出**。

【审】`audit/godot/narrative.md#19`（next_node_id 写错没关系 → 会中途断对话）

---

### Step 3　状态放在 Manager，不在 UI　`[narrative/02#S3]`

【读】`howto/godot/narrative.md#8. ⚠ 对话状态绝不能存在 UI 节点里`

【做】
"当前说到哪一句"放在 autoload 的 `DialogueManager`，UI 只做渲染。
NPC 通过信号 `start_dialogue(res)` 发起，⛔ 不要用 `get_node()` 找 UI。

【产出】
`DialogueManager`（autoload）+ 一个纯渲染的 UI 场景。

【判据】
关闭 UI 再重新打开，**对话停在同一句**（不是从头开始）。

【审】`audit/godot/narrative.md#21`（对话状态存在 UI 节点里 → 切场景就丢）

---

### Step 4　选项的条件与显示策略　`[narrative/02#S4]`

【读】`howto/godot/narrative.md#2. 对话树`

【做】
决定选项不满足条件时是**不显示**还是**显示但灰掉**。

⚠ 二者**逻辑上都是"未满足"**，但体验差异很大：
- 不显示 —— 玩家不知道有这条路
- 灰掉 —— 提示"有这条路，但你现在不满足"

✅ 条件应在**进入节点时求值**，⛔ 不是在打开对话时一次性求值
（否则对话中获得物品，选项不会更新）。

【产出】
一个 `evaluate_conditions()`，在节点进入时调用。

【判据】
在一句对话的执行效果里给玩家物品 → 下一句的选项**立刻变化**。

【审】`audit/godot/narrative.md#10`（选项灰掉和不显示一样 → UI 不同）

---

### Step 5　打字机与跳过　`[narrative/02#S5]`

【读】`howto/godot/narrative.md#8. ⚠ 对话状态绝不能存在 UI 节点里`

【做】
逐字显示用 `create_timer()` 或 `Tween`，⛔ **绝不用 `OS.delay_msec()`**（阻塞主线程）。

✅ 必须有两个独立动作：
1. 点击 → **立即显示完整本句**
2. 再点 → 进入下一句

⛔ 合成一个动作会让玩家快进时**误跳过还没看的选项**。

【产出】
带跳过的逐字显示组件。

【判据】
逐字显示进行中点击 → 本句立刻完整显示且**没有进入下一句**；
再点一次才前进。

【审】`audit/godot/narrative.md#22`（打字机不需要跳过 → 要两个动作）

---

### Step 6　中途存档与恢复　`[narrative/02#S6]`

【读】`howto/godot/narrative.md#9. 对话与存档的接缝（三个必须对齐的点）`

【做】
决定对话中途存档时从哪句恢复。
⚠ **已执行的效果不能重放** —— 标记要随存档持久化。

ⓘ 效果记录格式：`{node_id, effect_index, executed:true}`
⛔ 只记 `node_id` 不够（一个节点可能有多个效果）。

【产出】
对话进度的序列化 + 效果已执行集合。

【判据】
对话中途存档 → 读档 → 继续对话：
(a) 从预期位置继续；(b) **已发过的奖励不再发第二次**。

【审】`audit/godot/narrative.md#12`（对话中途不能存档 → 要想好从哪句恢复）

## 5. 常见返工


| 现象 | 根因 | 回到 |
|---|---|---|
| 玩家反馈"对话说到一半没了" | 悬空 next 且静默结束 | S2 |
| 关掉 UI 对话重头开始 | 状态在 UI 里 | S3 |
| 对话中拿到物品选项不更新 | 条件只在打开时求值 | S4 |
| 快进时误跳过选项 | 跳过与前进合成一个动作 | S5 |
| 读档后奖励重复发放 | 效果没有已执行标记 | S6 |
