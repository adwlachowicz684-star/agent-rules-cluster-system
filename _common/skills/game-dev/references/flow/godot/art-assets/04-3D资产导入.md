# 04 3D 资产导入（美术资产域）

> **本步交付**：格式与缩放核对通过 + PBR 通道与 sRGB 正确 + 材质未被逐个 clone
> **对应**：流程 `howto/godot/art-assets.md` · 审核 `audit/godot/art-assets.md`

## 0. 交付物定义

1. 交换格式定为 glTF，且导入后材质/缩放/动画核对过
2. 导入缩放已核对（不是靠改节点 scale 掩盖）
3. 颜色贴图 sRGB、法线/粗糙度/金属度 Linear 已确认
4. 法线绿通道约定已写进项目规范，且自定义着色器已确认不受 RGTC 影响
5. 同 Mesh + 同材质的实例未被 clone 材质

## 1. 前置检查清单

- [ ] 交换格式为 glTF（.glb/.gltf）
- [ ] 导入后尺寸已用参照物核对
- [ ] 各贴图通道的 sRGB/Linear 已逐个确认
- [ ] 法线绿通道约定（DirectX / OpenGL）已写进项目规范
- [ ] 场景中同模型的材质实例数已统计

## 2. 工序

### Step 1　glTF 是首选，但"首选"不等于"免检"　`[art-assets/04#S1]`

【读】``howto/godot/art-assets.md#格式``

【做】
定 glTF 为交换格式，导入后仍逐项核对材质、缩放、动画剪辑切分。
⛔ 不要因为"格式对"就跳过核对 ——
⛔ 材质重建、动画剪辑命名这些都是导入期行为，
出问题表现为"模型在、但材质是默认灰"，排查被引向渲染器。

ⓘ 核对要有**参照物**：
⛔ 只看着模型说"尺寸对不对"没有基准，
⛔ 必须放一个已知尺寸的立方体（比如 1m）作对照，否则"大概对"会一直混过去。

【产出】导入核对清单（材质/缩放/动画三项）

【判据】三项都有明确的"对/不对"结论，不是"看着还行"。

【审】``audit/godot/art-assets.md#9``

### Step 2　缩放错了要改导入，不要改节点 scale　`[art-assets/04#S2]`

【读】``howto/godot/art-assets.md#导入设置``

【做】
导入后发现尺寸不对，回到导入设置改缩放；FBX 单位不一致是经典坑。
⛔ 不要在场景里改节点 `scale` 把它掰正 ——
⛔ 那等于**把错误固化进场景**：模型本身仍是错的，
⛔ 后续任何用到该模型的地方都要再掰一次，而每次掰的系数还不一样。

ⓘ 还有一层：
⛔ 节点 scale 非均匀会连带影响法线与物理形状，
⛔ 表现为"碰撞怪、光照歪"，而排查被引向碰撞体或材质。

【产出】缩放核对记录（含参照物对比图）

【判据】场景中该模型的节点 scale 为 (1,1,1) 且尺寸正确。

【审】``audit/godot/art-assets.md#27``

### Step 3　PBR 通道的 sRGB 要逐个确认　`[art-assets/04#S3]`

【读】``howto/godot/art-assets.md#PBR 与贴图通道``

【做】
颜色贴图设 sRGB；法线、粗糙度、金属度**必须 Linear**。
⛔ 不要沿用导入默认 —— sRGB 设错的表现是"整体发灰/发亮"或"粗糙度数值不对"，
⛔ 而它**看起来像打光问题**，于是排查被引向光照与环境，越调越偏。

ⓘ 从 Blender/Substance 导出时，AO/Roughness/Metallic 的**打包约定**要固定下来并写进规范：
⛔ 不同美术给的图打包顺序不同，单看每张都正常，
⛔ 混在一起就是"这个材质对、那个不对"，且无法用规则解释。

【产出】通道约定文档 + 逐贴图 sRGB 核对记录

【判据】任一张贴图能按约定查出它该是 sRGB 还是 Linear。

【审】``audit/godot/art-assets.md#11``

### Step 4　法线：绿通道约定 + 检测改写会动你的着色器　`[art-assets/04#S4]`

【读】``howto/godot/art-assets.md#检测法线``

【做】
两件事都要做：把绿通道约定（DirectX / OpenGL）写进项目规范；
并确认自定义着色器是否读了法线贴图的**蓝通道**。
⛔ 不要只做前者 —— `compress/normal_map` 默认为 Detect，
一旦检测到被当法线用就会**自动改为 RGTC 并重新导入**，
⛔ 官方注明此时需调整"使用了蓝通道的自定义着色器"。

⛔ 这里有两层掩盖：
**内置材质一切正常**（官方：内置材质无论内容如何都忽略蓝通道），
且**贴图没换、导入设置没人动过**。
⛔ 于是"自定义着色器取蓝通道不对了"被引向着色器代码，而不是导入格式。

ⓘ 需要蓝通道就**显式把 `compress/normal_map` 设为 Disabled**，别靠 Detect 猜。

【产出】绿通道约定 + 自定义着色器蓝通道使用清单

【判据】凡自采样法线的着色器，其法线贴图压缩模式是显式值（非 Detect）。

【审】``audit/godot/art-assets.md#30``

### Step 5　共享材质不要逐个 clone　`[art-assets/04#S5]`

【读】``howto/godot/art-assets.md#共享材质``

【做】
同 Mesh + 同材质的实例共用一份材质；需要逐实例差异时走实例参数。
⛔ 不要给每个实例 clone 一份材质 ——
自动实例化要求"同 Mesh + 同材质"，⛔ clone 会让**批处理全部失效**，
⛔ 而画面完全正常、只是帧率掉了，于是排查被引向"场景太复杂"。

ⓘ 这里有个容易混淆的边界：
⛔ 需要逐实例改颜色时，正确做法不是 clone 材质（破坏批处理），
⛔ 而是走实例参数/顶点色 —— 判定依据是**改的是不是同一个材质资源**。

【产出】场景中材质实例数统计 + 逐实例差异的实现方式说明

【判据】同模型实例的材质资源是同一个；draw call 未随实例数线性增长。

【审】``audit/godot/art-assets.md#10``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const REF_CUBE_SIZE := 1.0   # 参照立方体边长（米），用于缩放核对

# ⛔ 只做统计与告警，不要在这里 clone 材质
func count_materials(root: Node) -> Dictionary:
    var seen := {}
    for n in root.find_children("*", "MeshInstance3D"):
        for i in range(n.get_surface_override_material_count()):
            var m = n.get_surface_override_material(i)
            if m == null:
                continue
            var rid = m.get_instance_id()
            seen[rid] = seen.get(rid, 0) + 1
    return seen

func report_scale_issue(inst: Node3D) -> String:
    var s = inst.scale
    if abs(s.x - 1.0) > 0.001 or abs(s.y - 1.0) > 0.001 or abs(s.z - 1.0) > 0.001:
        return "节点 scale 非 1：缩放错误被固化进场景，应回导入设置改"
    return ""
```

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 模型在但材质是默认灰 | 返工 Step 1（导入后没核对） |
| 碰撞怪、光照歪 | 返工 Step 2（改了节点 scale） |
| 整体发灰、粗糙度不对 | 返工 Step 3（sRGB 设错） |
| 自定义着色器蓝通道不对 | 返工 Step 4（Detect 自动改 RGTC） |
| 帧率掉了但画面正常 | 返工 Step 5（clone 了材质） |
