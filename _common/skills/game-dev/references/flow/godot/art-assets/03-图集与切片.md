# 03 图集与切片（美术资产域）

> **本步交付**：padding/extrusion 定档 + 图集边界不串色 + 缩小后验收无缝隙
> **对应**：流程 `howto/godot/art-assets.md` · 审核 `audit/godot/art-assets.md`

## 0. 交付物定义

1. `ATLAS_PADDING_PX` 与 `ATLAS_EXTRUDE_PX` 已定档并写进导出工具配置
2. 图集内切片的 Repeat 判定对象已明确（整张图集）
3. 源资产已过"透明像素填充邻近色"这一关
4. 缩小后逐像素比对无缝隙、无暗边、无光晕
5. 图集尺寸与压缩模式已按 02 的预算定档

## 1. 前置检查清单

- [ ] 图集工具（内置或外部）已选定，padding/extrusion 可配置
- [ ] 已确认哪些切片需要平铺（需要 Repeat）
- [ ] 源图透明像素已做邻近色填充
- [ ] 图集尺寸落在 02 的显存预算内
- [ ] 缩小后的比对截图已准备

## 2. 工序

### Step 1　打图集的目的是 draw call，先确认值得打　`[art-assets/03#S1]`

【读】``howto/godot/art-assets.md#3. 图集``

【做】
先确认当前 draw call 是被"散图"顶上去的，再决定打图集。
⛔ 不要为了"规范"无脑打 —— 图集会让**单张图的尺寸与压缩**变成一个整体决策，
⛔ 一张 2048 的大图集被迫用同一套压缩，可能比散图更贵。

ⓘ 判断依据要可测：
⛔ "draw call 高"必须是**数出来的**，不是感觉，
⛔ 否则会把"帧率低"直接等同成"该打图集"，而帧率低的成因至少有五类。

【产出】打图集的理由（含 draw call 实测值）

【判据】能给出打之前与打之后的 draw call 对比。

【审】``audit/godot/art-assets.md#36``

### Step 2　padding 与 extrusion 都要设，且作用不同　`[art-assets/03#S2]`

【读】``howto/godot/art-assets.md#3. 图集``

【做】
设 `ATLAS_PADDING_PX`（内边距）**并且**设 `ATLAS_EXTRUDE_PX`（外扩复制边缘像素）。
⛔ 不要只设一个 —— padding 挡的是"采到邻区"，extrude 挡的是**边缘光晕**，
⛔ 只设 padding 的表现是"缝隙没了但边缘发虚/有亮边"，
于是以为还要继续加大 padding，越加越大，图集越来越浪费。

ⓘ 两个参数的代价都是面积：
⛔ 它们会把图集尺寸顶上去，而图集尺寸受压缩格式块对齐影响，
⛔ 于是"为了消缝隙把图集从 1024 加到 2048"可能直接让显存翻四倍。

【产出】padding/extrusion 定档值 + 图集尺寸评估

【判据】缩小后逐像素比对无邻区串色、无边缘光晕。

【审】``audit/godot/art-assets.md#24``

### Step 3　图集内切片不能单独设 Repeat　`[art-assets/03#S3]`

【读】``howto/godot/art-assets.md#Repeat``

【做】
把需要平铺的切片**单独出图或单独打一张图集**，不要混进普通图集。
⛔ 不要指望"图集里这一块开 Repeat" —— 判定对象是**整个图集纹理**，
⛔ 于是"给整张图集开了 Repeat 来服务一个切片"会让其余切片全部出现脏边，
⛔ 且表现为"只有部分图标坏了"，看起来像那几个源文件有问题。

ⓘ 分图集还有个附带收益：
⛔ 平铺用的贴图通常要开 mipmap，而 UI 图集通常不开，
⛔ 混在一张图集里这两个需求直接冲突，只能牺牲一方。

【产出】图集分组方案（平铺组 / UI 组 / 立绘组）

【判据】平铺切片所在图集 Repeat 为开，UI 图集 Repeat 为关且无脏边。

【审】``audit/godot/art-assets.md#5``

### Step 4　源资产先过"透明像素填充与抗锯齿"这一关　`[art-assets/03#S4]`

【读】``howto/godot/art-assets.md#源资产纪律``

【做】
要求透明像素填充邻近可见颜色、不使用透明抗锯齿混色、导出时不叠加缩放与锐化。
⛔ 不要等进引擎再救 —— 透明像素留黑边的问题在**缩小后**才出现，
⛔ 表现为"缩小时边缘发暗"，⛔ 而放大验收完全看不出来，
于是这类问题稳定地活到出包之后。

⛔ 而且它是**批量**的：
⛔ 单张图看着只是"边缘有点暗"，几十张一起出现在界面上就是"整体脏"。

【产出】源资产纪律清单（已发给美术，含示例图）

【判据】随机抽 5 张源图，透明区域采样不是纯黑。

【审】``audit/godot/art-assets.md#37``

### Step 5　验收要在缩小后逐像素比对　`[art-assets/03#S5]`

【读】``howto/godot/art-assets.md#1. 像素美术``

【做】
在目标分辨率下截图，缩小到实际显示尺寸逐像素比对。
⛔ 不要在编辑器里放大看 —— 缝隙与光晕是**缩小才明显**的，
⛔ 放大验收是本能动作，而它恰好把这类问题全部隐藏。

ⓘ 比对还要覆盖**缩放动画过程中**：
⛔ 静态看两个尺寸，会漏掉"缩放经过某个比例时闪一下"，
⛔ 而闪烁是最容易被玩家注意到的那类瑕疵。

【产出】缩小后比对截图（静态 + 缩放过程）

【判据】无邻区串色、无边缘光晕、缩放过程中无闪烁。

【审】``audit/godot/art-assets.md#24``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const ATLAS_PADDING_PX := 2          # 内边距（03 参数表登记）
const ATLAS_EXTRUDE_PX := 1          # 外扩复制边缘像素（03 参数表登记）

# ⛔ 只做配置校验：真正的切片在导入/打包工具里完成
func check_atlas_config(cfg: Dictionary) -> Array:
    var problems: Array = []
    if int(cfg.get("padding", 0)) < ATLAS_PADDING_PX:
        problems.append("padding 不足：线性过滤会采到邻区")
    if int(cfg.get("extrude", 0)) < ATLAS_EXTRUDE_PX:
        problems.append("extrude 未设：padding 挡不住边缘光晕")
    if bool(cfg.get("repeat", false)) and bool(cfg.get("has_ui_slice", false)):
        problems.append("图集开了 Repeat 且含 UI 切片：判定对象是整张图集")
    return problems
```

## 4. 验收清单

- [ ] 打图集的理由有 draw call 实测支撑
- [ ] padding 与 extrusion 都已设（不是只设一个）
- [ ] 需要平铺的切片已单独分组，未与 UI 混图集
- [ ] 源资产透明像素已填充邻近色
- [ ] 缩小后逐像素比对通过，缩放过程无闪烁

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 缝隙没了但边缘发虚 | 返工 Step 2（只设了 padding） |
| 只有部分图标边缘脏 | 返工 Step 3（整图集开了 Repeat） |
| 缩小后边缘发暗 | 返工 Step 4（透明像素留黑边） |
| 验收没发现、出包后被发现 | 返工 Step 5（放大验收） |
| 打完图集反而更慢 | 返工 Step 1（没确认 draw call 成因） |
