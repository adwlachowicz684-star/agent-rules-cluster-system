# 05 字体与中文子集化（美术资产域）

> **本步交付**：中文子集化完成 + MSDF 取舍定档 + fallback 与预渲染定档
> **对应**：流程 `howto/godot/art-assets.md` · 审核 `audit/godot/art-assets.md`

## 0. 交付物定义

1. 中文字体已子集化，`FONT_SUBSET_GLYPHS` 有实际值
2. MSDF 的取舍按"会不会缩放"定档，不是全开
3. `allow_system_fallback` 的行为已知，且有**跨机验证**方法
4. `subpixel_positioning` 已按字体定档（像素字体 Disabled）
5. 预渲染字形范围 `FONT_PRELOAD_RANGES` 已定档，加载/内存代价已实测
6. hinting 改了没效果的原因已查明（字体是否含 hinting 数据）

## 1. 前置检查清单

- [ ] 已统计实际用到的字符集（不是按常用字表估）
- [ ] 会缩放的文本与固定小字号已分类

## 2. 工序

### Step 1　中文必须子集化，且字符集要统计出来　`[art-assets/05#S1]`

【读】``howto/godot/art-assets.md#7. 字体``

【做】
从实际文本（脚本、配置、UI 文案）里**统计**用到的字，再做子集化。
⛔ 不要按"常用字表"估 —— 估少了漏字、估多了白塞，
⛔ 而漏字**不会显示成豆腐块**（fallback 默认 true，见 Step 3），
⛔ 于是"少字"这个问题在本机**永远发现不了**。

ⓘ 统计要覆盖**运行时拼出来的文本**：
⛔ 玩家昵称、数字格式化、占位符替换出来的字不在静态文案里，
⛔ 只扫静态文案必然漏，而漏的恰恰是玩家看得到的那部分。

【产出】字符集统计脚本 + 子集化后的字体文件

【判据】子集化后包体下降；运行时拼出的文本不出现 fallback。

【审】``audit/godot/art-assets.md#13``

### Step 2　MSDF 按"会不会缩放"定档　`[art-assets/05#S2]`

【读】``howto/godot/art-assets.md#7. 字体``

【做】
会缩放的文本开 MSDF；**固定小字号的正文不要开**。
⛔ 不要全开 —— 官方列出的缺点里有一条正是
**小字号缺乏 hinting（不如传统光栅化清晰）**，
⛔ 于是"为了清晰开了 MSDF"的结果是小字**反而更糊**，
⛔ 而这恰恰是最常用的字号，于是全界面都糊。

ⓘ 另外两条官方缺点也要算进去：
低端移动设备**基础渲染成本更高**、**无法启用 LCD 子像素优化**。
⛔ 所以"开了 MSDF 手机上更卡"不是错觉，是官方写明的代价。

【产出】字体清单（逐个标注会缩放/固定、开不开 MSDF）

【判据】固定小字号正文未开 MSDF；会缩放的文本开了且不糊。

【审】``audit/godot/art-assets.md#20``

### Step 3　fallback 默认 true：漏字不报、跨机才现形　`[art-assets/05#S3]`

【读】``howto/godot/art-assets.md#三个默认值``

【做】
明确 `allow_system_fallback` 默认 `true` 的后果，并准备**至少两个平台**的验证。
⛔ 不要靠本机判断"字全不全" —— 找不到字形会自动用系统字体兜底，
⛔ 表现**不是豆腐块**，而是"能显示、但跟你预期不一样"，
⛔ 于是单机验证 100% 通过，只有在不同平台上对比才现形。

ⓘ 官方还注明一件事：
⛔ 系统字体外观**因平台而异**，且加载系统字体只支持
Windows / macOS / Linux / Android / iOS ——
⛔ 也就是说 fallback **在有的平台上根本不会发生**，这解释了为什么"有的机器复现、有的不复现"。

【产出】跨机字形比对记录（≥2 个平台）

【判据】两个平台渲染同一段文本，字形完全一致。

【审】``audit/godot/art-assets.md#19``

### Step 4　subpixel_positioning：像素字体必须关　`[art-assets/05#S4]`

【读】``howto/godot/art-assets.md#subpixel_positioning``

【做】
像素艺术风格的字体把 `subpixel_positioning` 设为 **Disabled**。
⛔ 不要沿用默认 —— 官方明确"对于具有像素艺术外观的字体，应将其设置为 Disabled"，
⛔ 表现是"文字发虚、与像素画风不一致"，
⛔ 而排查被引向字号或分辨率，因为它是"质量更好"的选项，没人会想到要**关掉**。

ⓘ 非像素字体也要按档位选：
⛔ 官方注明子像素定位"**初始渲染需要更多时间**，可能导致游戏过程中卡顿，尤其大字体"，
⛔ 所以"全开最高档"在文本密集的界面上是真实的卡顿来源。

【产出】逐字体的 `subpixel_positioning` 档位表

【判据】像素字体为 Disabled；其余档位有实测（首次出现不卡顿）。

【审】``audit/godot/art-assets.md#32``

### Step 5　预渲染字形：三难，必须实测定档　`[art-assets/05#S5]`

【读】``howto/godot/art-assets.md#subpixel_positioning``

【做】
决定是否预渲染字形范围，并实测它的两个代价（加载时间、内存）。
⛔ 不要两头都要 —— 官方口径：预渲染可避免游戏中渲染新字形时卡顿
（"特别是在启用 subpixel_positioning 的情况下"），
但**代价是初始加载时间增加、内存使用量也增加**。

⛔ 对中文项目这就是三难：
**不发虚 / 不卡顿 / 不涨内存**不可能同时满足。
⛔ 没有默认值能同时满足，必须实测定档，
⛔ 而"先都开着，出问题时再调"在这里不成立 —— 三类问题都只在特定机型上现形。

【产出】`FONT_PRELOAD_RANGES` 定档值 + 加载时间与内存实测

【判据】给出实测数字，且能说清"为了哪一项放弃了哪一项"。

【审】``audit/godot/art-assets.md#33``

### Step 6　hinting 改了没效果，先查字体有没有数据　`[art-assets/05#S6]`

【读】``howto/godot/art-assets.md#三个默认值``

【做】
改 hinting 没变化时，先确认字体文件本身是否含 hinting 指令，
没有就换字体版本或开 `force_autohinter`。
⛔ 不要当成引擎 bug —— 官方明确**非 None 的 hinting 只对含 hinting 数据的字体生效**，
⛔ 于是"改了没效果"被记成"这个选项没用"，而真正的解法（换字体/开 autohinter）从未被尝试。

ⓘ 顺带一条版本相关：
⛔ 4.7 起 `ResourceImporterDynamicFont.hinting` 默认从 1 变 3，
⛔ 升级后字体渲染**会变**，而这不需要任何人改任何设置。

【产出】字体 hinting 数据核查记录 + 档位结论

【判据】能说清当前档位为什么是这个值，以及改了会不会有效果。

【审】``audit/godot/art-assets.md#21``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const FALLBACK_CHECK_TEXT := "示例文本 0123456789 玩家昵称"
const FONT_CHECK_SIZES := [12, 16, 24, 48]

# ⛔ 只做字形覆盖检查：fallback 默认 true，缺字不会报、也不会显示豆腐块
func missing_glyphs(font: Font, text: String) -> Array:
    var miss: Array = []
    for ch in text:
        if font.get_char_size(ch) == Vector2.ZERO:
            miss.append(ch)
    return miss

func report(font: Font) -> String:
    var miss = missing_glyphs(font, FALLBACK_CHECK_TEXT)
    if miss.is_empty():
        return "静态文案无缺字；⛔ 仍需跨机比对：fallback 会静默兜底"
    return "缺字（会被系统字体静默兜底）：" + str(miss)
```
