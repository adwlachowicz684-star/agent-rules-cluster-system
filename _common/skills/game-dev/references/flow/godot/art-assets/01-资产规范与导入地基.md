# 01 资产规范与导入地基（美术资产域）

> **本步交付**：一套写得下来的目录/命名规范 + `.uid` 与 `.import` 入库 + 导入设置可被机器校验
> **对应**：流程 `howto/godot/art-assets.md` · 审核 `audit/godot/art-assets.md`

## 0. 交付物定义

1. 目录结构与 `snake_case` 命名规范**写进项目文档**，不是口头约定
2. `.uid` 与 `.import` 已提交进版本控制，且 `.gitignore` 没有排除它们
3. 已确认项目所用引擎版本对 UID 的支持范围（4.4 是分界）
4. 导入设置有一份可跑的校验（脚本扫 `.import`，不靠人看面板）
5. 内存/包体预算已定档，`TEXTURE_BUDGET_MB` 有值

## 1. 前置检查清单

- [ ] 目录结构与命名规范已写入项目文档
- [ ] `.gitignore` 未排除 `.uid` / `.import`
- [ ] 已确认引擎版本是否 ≥ 4.4（决定脚本与着色器能否靠 UID 移动）
- [ ] 已有脚本能列出所有 `.import` 的关键设置
- [ ] 纹理显存预算 `TEXTURE_BUDGET_MB` 已定档

## 2. 工序

### Step 1　先写规范，再收资源　`[art-assets/01#S1]`

【读】``howto/godot/art-assets.md#5. 资源组织与命名``

【做】
定目录结构与 `snake_case` 命名，**写进项目文档**并让美术遵守。
⛔ 不要口头约定 —— 规范没写下来就等于没有，
⛔ 后期整理成本极高，而"整理"这种事永远排不进迭代，
于是它会一直以"先这样吧"的形式累积到出包前。

ⓘ 写的时候要连带写清**例外**（比如第三方素材保持原命名），
⛔ 只写"必须 snake_case"没有例外条款，第一次遇到第三方资源就会破例，
⛔ 破例一次之后规范就不再是规范了。

【产出】目录/命名规范文档（含例外条款）

【判据】新人只看文档就能放对位置、起对名字。

【审】``audit/godot/art-assets.md#35``

### Step 2　`.uid` 与 `.import` 必须入库　`[art-assets/01#S2]`

【读】``howto/godot/art-assets.md#5. 资源组织与命名``

【做】
把 `.uid` 与 `.import` 提交进版本控制，并确认 `.gitignore` 没排除它们。
⛔ 不要按"生成物不入库"的惯例排除 —— 官方明确要求把它们加进去。

⛔ 后果是**协同侧的静默断链**：
本机一切正常（`.uid` 就在本地磁盘上），别人拉下来没有 `.uid` →
UID 引用失效 → 回退到路径查找 → 若文件同时被移动过则**引用直接断裂**。
⛔ 表现为"他那儿打开全是红字，我这儿好好的"，且两边都没改过任何引用。

【产出】`.gitignore` 复核记录 + 一次"干净克隆后能打开"的验证

【判据】在一台新机器上克隆仓库，项目能直接打开且无红字引用。

【审】``audit/godot/art-assets.md#22``

### Step 3　确认引擎版本对 UID 的支持范围　`[art-assets/01#S3]`

【读】``howto/godot/art-assets.md#5. 资源组织与命名``

【做】
确认项目引擎版本：4.4 之前**脚本与着色器不支持 UID**（纯文本格式无处存 UID）。
⛔ 不要把"文件可以随便移动"当成通用结论 ——
它对 4.4 之前建的项目**不成立**，⛔ 而且断的是**别人机器上**的引用，本机看不出来。

ⓘ 迁移期尤其要显式记一笔：
⛔ 老项目升级到 4.4 后，`.uid` 伴生文件是**补上的**，
但历史引用里已经写死路径的那些，**不会自动变成 UID 引用**。

【产出】版本结论 + 若 <4.4 则补充"移动文件后的引用复核"步骤

【判据】能说清"本项目移动文件是否安全"，而不是"听说 4.4 以后可以"。

【审】``audit/godot/art-assets.md#23``

### Step 4　导入设置要有可跑的校验　`[art-assets/01#S4]`

【读】``howto/godot/art-assets.md#检测 3D``

【做】
写一个扫 `.import` 的脚本，把关键设置（压缩模式、mipmap、filter/repeat、法线压缩）列出来。
⛔ 不要靠人打开导入面板看 —— 自动改写（detect_3d / detect 法线）
在面板上**显示得"像一直如此"**，⛔ 人审永远发现不了"它变了"，
因为它没有一个"上次的值"可以对照。

ⓘ 这份清单还有第二重用途：
⛔ 它是唯一能回答"这张图现在的设置是什么"的东西，
⛔ 而"谁改了设置"这类争论，靠它没有悬念。

【产出】可跑的导入设置清单脚本 + 当前基线快照

【判据】改动任一导入设置后，脚本输出能反映出差异。

【审】``audit/godot/art-assets.md#36``

### Step 5　先定内存与包体预算，再谈单张图　`[art-assets/01#S5]`

【读】``howto/godot/art-assets.md#2. 纹理压缩``

【做】
定 `TEXTURE_BUDGET_MB` 与 `PKG_SIZE_BUDGET_MB`，写进文档。
⛔ 不要从"无损最好"出发 —— 那是 2D 的默认值直觉，
⛔ 而"高清 2D 该开什么"由**内存预算**决定，不是视觉风格。

ⓘ 预算还有个反直觉的用途：
⛔ 它是判断"这张图该不该进图集 / 该不该用 Basis"的**唯一客观依据**，
⛔ 没有它，每个决策都会退化成"看着还行"。

【产出】预算文档（含分平台差异）

【判据】任一张图要改用更高画质的设置时，能算出它占预算的百分比。

【审】``audit/godot/art-assets.md#6``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const IMPORT_KEYS := [
    "compress/mode",
    "mipmaps/generate",
    "detect_3d/compress_to",
    "compress/normal_map",
    "process/filter",
    "process/repeat",
]

# ⛔ read_all 只用于编辑器工具，不要放进运行时代码
func snapshot_imports(dir_path: String) -> Dictionary:
    var out := {}
    var dir := DirAccess.open(dir_path)
    if dir == null:
        push_error("cannot open: " + dir_path)
        return out
    for f in dir.get_files():
        if not f.ends_with(".import"):
            continue
        var cfg := ConfigFile.new()
        if cfg.load(dir_path.path_join(f)) != OK:
            continue
        var row := {}
        for k in IMPORT_KEYS:
            row[k] = cfg.get_value("params", k, "<unset>")
        out[f] = row
    return out
```

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| "他那儿全红、我这儿正常" | 返工 Step 2（`.uid` 没入库） |
| 移动文件后引用断了 | 返工 Step 3（版本 <4.4） |
| "改了设置又变回去" | 返工 Step 4（没有对照基线） |
| 出包后显存爆了 | 返工 Step 5（没有预算） |
| 规范执行不下去 | 返工 Step 1（没写进文档） |
