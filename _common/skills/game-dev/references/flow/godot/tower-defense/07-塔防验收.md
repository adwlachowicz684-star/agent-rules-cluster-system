# 07 塔防验收（塔防域）

> **本步交付**：锁帧一致 + 封路被拒 + 满屏不漏打 + 波次必定推进 + 重连/读档后仍对
> **对应**：流程 `howto/godot/genres-tower-defense.md` · 审核 `audit/godot/genres-tower-defense.md`

## 0. 交付物定义

1. 锁 30 / 60 FPS 跑同一波，刷怪总时长一致
2. 封路被拒绝，且**不会**出现在场怪原地不动
3. 满屏怪时塔不漏打，贴脸怪能选中
4. 任意波次都能推进（全漏光也能判失败结束）
5. 多塔同帧击杀只结算一次
6. 读档/重连后波次与计数仍自洽

## 2. 工序

### Step 1　锁帧一致性：30 / 60 FPS 跑同一波　`[tower-defense/07#S1]`

【读】``howto/godot/genres-tower-defense.md#1. 波次配置用 Resource，不要硬编码数组``

【做】
把帧率锁到 30 与 60 各跑一遍同一波，比较**刷完的总时长**与总只数。
⛔ 只比总只数会漏掉 Timer 依赖帧率的问题（只数一样、时长差一倍），
而这正是低端机上「一波刷特别久」的成因。
ⓘ 顺带在同一轮里记录 `map_get_path` 的调用次数 ——
⛔ 它应该与怪数**无关**，随怪数线性增长就说明缓存没生效。

【产出】两档帧率下的时长 / 只数 / 寻路次数对照

【判据】两档帧率的**总时长**一致；⛔ 寻路次数不随怪数线性增长。

【审】``audit/godot/genres-tower-defense.md#6``

### Step 2　封路测试：把路堵死，看是拒绝还是卡住　`[tower-defense/07#S2]`

【读】``howto/godot/genres-tower-defense.md#8. ⛔ 官方口径：路径查询、避让默认值与 force_update 的代价``

【做】
手动用塔把唯一通路封死。
⛔ **禁止封路的玩法必须看到「建造被拒绝」**；
如果看到的是「怪站着不动」，说明 04/S3 的前置可达性校验没生效。
ⓘ 允许封路（迷宫）的玩法则反过来：必须看到**所有怪重新改道**，
⛔ 出现任何一只原地不动同样是失败。

ⓘ 这条在关卡设计者手里几乎测不出来 ——
没有人会主动去堵死自己设计的路。**必须专门测**。

【产出】封路行为记录（拒绝 / 改道 / 卡住）

【判据】⛔ 无论哪种玩法，结果里都不能出现「在场的怪原地不动且不报错」。

【审】``audit/godot/genres-tower-defense.md#19`　`audit/godot/genres-tower-defense.md#20``

### Step 3　满屏怪：不漏打 + 贴脸能选中　`[tower-defense/07#S3]`

【读】``howto/godot/genres-tower-defense.md#8. ⛔ 官方口径：路径查询、避让默认值与 force_update 的代价``

【做】
把同屏怪数打到上限，逐塔核对：
是否每座塔都在按冷却开火（**没有「偶尔不攻击」**）；
在塔正上方直接生成一只怪，第一个索敌周期内是否被选中。
⛔ 前者是 `max_results` 默认 32 的截断，后者是已重叠被忽略 ——
**两者都不报错**，且射程/mask/冷却检查全绿。

【产出】满屏漏打次数（应为 0）与贴脸选中耗时

【判据】漏打 0 次；⛔ 贴脸怪在一个索敌周期内被选中。

【审】``audit/godot/genres-tower-defense.md#8`　`audit/godot/genres-tower-defense.md#18``

### Step 4　波次必定推进：全漏光也要能结束　`[tower-defense/07#S4]`

【读】``howto/godot/genres-tower-defense.md#5. 波次完成判定要显式计数``

【做】
跑一局**一座塔都不建**，让所有怪全部漏光。
⛔ 期望结果是「正确判失败并结束」，**不是卡在第 1 波**。
这是最快暴露 `escaped` 未计数 / group 判空污染的测试，
⛔ 而它在正常游玩中永远不会发生（正常局怪都会被杀）。

【产出】全漏光一局的结束状态

【判据】能判失败并结束；⛔ 不出现「卡在某波不动」。

【审】``audit/godot/genres-tower-defense.md#4``

### Step 5　多塔同帧击杀：奖励只结算一次　`[tower-defense/07#S5]`

【读】``howto/godot/genres-tower-defense.md#6. 塔的伤害分发：接口，不是字符串``

【做】
脚本驱动 10 座塔在同一物理帧打同一只残血怪，
核对奖励次数与 `killed_count`。
⛔ 单塔测试永远测不出这个 —— 它只在塔密集且怪残血时撞上，
而日志里**每笔奖励都有合法的怪 ID**，看不出重复。

【产出】同帧击杀的奖励次数（应为 1）

【判据】奖励 = 1；⛔ `killed_count` 与奖励次数一致。

【审】``audit/godot/genres-tower-defense.md#3``

### Step 6　读档 / 重连后波次与计数仍自洽　`[tower-defense/07#S6]`

【读】``howto/godot/genres-tower-defense.md#5. 波次完成判定要显式计数``

【做】
波次中途存盘再读档（或联机下重连），核对：
`spawned / killed / escaped` 三个计数、场上怪的位置与路径下标、
池子的占用情况。
⛔ 只测「读档后游戏能继续」会漏掉计数错位，
表现为「读档后这一波永远清不了」 ——
而存档文件里每个字段看起来都对。

【产出】读档前后的计数与场上状态对照

【判据】三个计数读档前后一致；⛔ 读档后当前波仍能正常结束。

【审】``audit/godot/genres-tower-defense.md#4``


## 3. 验收清单

- [ ] 30 / 60 FPS 两档总时长一致
- [ ] 寻路次数不随怪数线性增长
- [ ] 封路不产生"怪原地不动"
- [ ] 满屏漏打 0 次、贴脸能选中
- [ ] 全漏光能判失败并结束
- [ ] 同帧击杀只结算一次
- [ ] 读档后当前波仍能结束

## 4. 常见返工

| 现象 | 返工到 |
|---|---|
| 低端机一波刷特别久 | → `01#S3`（Timer 依赖帧率） |
| 怪多时帧率崩 | → `02#S1`（每只怪独立寻路） |
| 建塔时偶发卡顿 | → `02#S3` / `04#S5`（`map_force_update` 未批量） |
| 怪走进墙里 | → `03#S5`（`path_desired_distance`） |
| 封路后怪卡住 | → `04#S3`（缺前置可达性校验） |
| 校验通过但实际走不通 | → `04#S4`（另建了简化图） |
| 塔偶尔不攻击 | → `05#S3`（`max_results` 截断） |
| 贴脸怪不开火 | → `05#S2`（已重叠被忽略） |
| 波次卡住不推进 | → `06#S2`（`escaped` 未计数） |
| 偶尔多拿奖励 | → `06#S3` / `06#S4` |
| 读档后这波清不了 | → `06#S1`（计数未持久化） |
