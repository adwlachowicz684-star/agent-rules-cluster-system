# 塔防（Tower Defense）—— 域流程总览

> ⚠ **第 0 步：先定"波次是不是数据、路径由谁算、能不能封路"。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 最小可玩：一波怪、几座塔 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |
| 已经有移动与寻路，只补塔防 | 04 → 05 → 06 → 07 |
| 只做波次与刷怪 | 01 → 06 → 07 |
| 迷宫塔防（允许改道/封路） | 01 → 02 → 04 → 07 |
| 怪太多帧率崩 | 01 → 02 → 03 → 05 → 07 |
| 建塔卡顿 / 路径不更新 | 02 → 04 → 07 |
| 波次卡住不推进 | 06 → 07 |

⛔ **01 不能跳过** —— 塔、索敌、封路校验的形态差异很大，
但**"波次是数据、刷怪用累加器、完成用显式计数"**这一条完全统一。
⛔ 不先定这条，就会写成"每只怪自己计时"，
后面所有"这波到底清了没有"都要靠猜，
而 `get_nodes_in_group().is_empty()` 会被池里的休眠怪污染。

⛔ **04 的封路口径不能最后补**：它是**玩法决定**，
一旦允许玩家用塔围出死路，再补校验等于承认
"怪会站着不动"这个已发生状态 —— 而它**不报错**。

ⓘ 02 与 04 是本域最容易互相甩锅的两步：
路径不更新时，成因可能在"没调同步"也可能在"建塔没登记失效"。
⛔ 所以 02 只定**缓存与同步时机**，04 只定**失效登记**，两边不许各调一次。

## 1. 功能点拆解与依赖

| # | 功能点 | 交付 | 依赖 |
|---|---|---|---|
| 01 | 波次数据化与刷怪调度 | 波次是 Resource、累加器刷怪、对象池 | — |
| 02 | 路径与寻路 | `path_id` 缓存、`optimize` 选型、同步时机 | 01 |
| 03 | 敌人移动与避让 | 自己写移动、避让显式开启、`path_desired_distance` | 02 |
| 04 | 建塔与格子 | ⛔ 建塔前可达性校验、失效批量登记 | 02 |
| 05 | 索敌与伤害分发 | 集中降频 query、接口分发 | 01 |
| 06 | 波次结算与经济 | 显式计数、幂等结算、波间窗口 | 01 / 05 |
| 07 | 塔防验收 | 锁帧一致、封路、满屏、漏光、读档 | 全部 |

⛔ **依赖是硬的**：04 的可达性校验要用 02 那张图，
⛔ 另建一张简化校验图会得到"校验通过但实际走不通"，
而两套逻辑各自正确，只有不一致时才出错。

## 2. 域边界与接缝

| 邻域 | 分工 |
|---|---|
| `ai` 域 敌人 AI | 单体行为与状态机见 `ai`，⛔ 本域只定"沿路径走 + 被塔打" |
| `ai-navigation` | ⓘ howto 层，暂无 flow 域 —— 导航网格烘焙与 agent 细节见该篇 |
| `combat` 域 战斗 | 伤害公式与 Buff 见 `combat`，⛔ 本域只定"由谁分发、结算几次" |
| `economy` 域 经济 | 货币与奖励账本见 `economy`，⛔ 本域只产出"该发多少" |
| `perf` 域 性能 | 剖析方法与帧预算见 `perf`，⛔ 本域只定寻路/索敌的调用次数上界 |
| `2d-rendering` 域 2D 渲染 | 排序与图层见 `2d-rendering`，⛔ 本域不另定排序口径 |
| `save` 域 存档 | 持久化机制见 `save`，⛔ 本域只定"三个计数必须一起存" |
| `bullethell` 域 弹幕 | 弹幕的批量判定见 `bullethell`，⛔ 本域是塔防侧的少量弹道 |
| `time-progression` | ⓘ howto 层，暂无 flow 域 —— 离线收益结算时序见该篇 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `POOL_INIT` 池子初始容量 | 01 | 64 | — | 待实测（与同屏上限相关） |
| `MAX_ACTIVE` 同屏怪硬上限 | 01 | 256 | — | 待实测（与移动端内存相关） |
| `WAVE_SCAN_INTERVAL` 索敌降频间隔 | 05 | 0.15 | — | 待实测（⛔ 太大表现为塔反应迟钝） |
| `MAX_CANDIDATES` 索敌结果上限 | 05 | 256 | — | 待实测（⛔ 默认 32 会静默截断） |
| `AVOID_MAX_SPEED` 避让速度上限 | 03 | 180.0 | — | 待实测（⛔ 默认 100 对塔防通常太慢） |
| `PATH_DESIRED_DIST` 路径点到达阈值 | 03 | 8.0 | — | 待实测（⛔ 与格子尺寸挂钩，不抄 20.0） |
| `WAVE_GAP` 波间建塔窗口 | 06 | 3.0 | — | 待实测（⛔ 不写就是隐式 0） |
| `ALLOW_BLOCKING` 是否允许封路 | 04 | false | — | 待实测（⛔ 玩法决定，不是技术默认） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发漏打""偶发卡顿""波次偶发不推进"，
⛔ 而这类偶发在测试环境几乎不出现。
