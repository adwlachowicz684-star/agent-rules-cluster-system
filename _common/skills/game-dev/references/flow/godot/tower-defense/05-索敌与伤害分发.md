# 05 索敌与伤害分发（塔防域）

> **本步交付**：索敌集中降频 + `intersect_shape` 两个静默边界已处理 + 伤害走接口不走名字
> **对应**：流程 `howto/godot/genres-tower-defense.md` · 审核 `audit/godot/genres-tower-defense.md`

## 0. 交付物定义

1. 塔的射程检测是**集中、降频**的 shape query，不是每塔一个 `Area2D` 信号
2. `intersect_shape` 的**已重叠被忽略**与**`max_results` 默认 32 截断**两个边界已处理
3. 伤害分发走**接口**（`take_damage()`），不是 `body.name == ...`
4. 索敌结果与塔的射程/冷却解耦，换目标不需要重查
5. `TileMap` / 地形配了碰撞也不会误伤

## 1. 前置检查清单

- [ ] 全项目无 `body_entered` 用于塔的射程检测
- [ ] 贴着塔刷出的怪能被查到
- [ ] `intersect_shape` 的 `max_results` 是显式给的
- [ ] 伤害分发处无字符串比较节点名
- [ ] 地形格配了碰撞也不会被当成敌人

## 2. 工序

### Step 1　索敌集中降频，不用 body_entered 信号　`[tower-defense/05#S1]`

【读】``howto/godot/genres-tower-defense.md#4. 索敌：降频查询，不要用信号``

【做】
20 座塔 × 200 只怪的 `body_entered/exited` 是**信号风暴**：
每只怪进入/离开每座塔的射程都要派发一次。
改为**集中、降频、按需**的 `intersect_shape` 查询（如 0.15 秒一次）。
⛔ 直觉上"信号只在事件发生时触发所以更省"，
但塔防里进出是**持续发生**的，而怪越多越密，派发次数是塔数×怪数。

ⓘ 降频的间隔要进参数表：⛔ 太快等于没降频，太慢表现为"塔反应迟钝"，
而两者在开发机上都不明显。

【产出】集中索敌器（含降频间隔）

【判据】怪数翻倍时，信号派发次数不随之翻倍。

【审】``audit/godot/genres-tower-defense.md#7``

### Step 2　已重叠的形状会被 intersect_shape 忽略　`[tower-defense/05#S2]`

【读】``howto/godot/genres-tower-defense.md#8. ⛔ 官方口径：路径查询、避让默认值与 force_update 的代价``

【做】
官方原文：*"Any Shape2Ds that the shape is already colliding with e.g.
inside of, will be ignored. Use `collide_shape` to determine the Shape2Ds
that the shape is already colliding with."*

⛔ 怪**贴着塔**刷出来时查不到 —— 而这恰恰是塔最该立刻开火的时刻。
表现为"怪都贴脸了塔还不开火"，检查时射程、mask、冷却**全部正常**。
官方给的补法就是用 `collide_shape()` 单独查一次已重叠的。

【产出】贴脸怪的补查路径（`collide_shape`）

【判据】在塔正上方生成一只怪，⛔ 塔仍能在第一个索敌周期内选中它。

【审】``audit/godot/genres-tower-defense.md#8`　`audit/godot/genres-tower-defense.md#18``

### Step 3　max_results 默认 32，超出静默截断　`[tower-defense/05#S3]`

【读】``howto/godot/genres-tower-defense.md#8. ⛔ 官方口径：路径查询、避让默认值与 force_update 的代价``

【做】
`intersect_shape(parameters, max_results = 32)` ——
超过的结果**静默丢弃，不报错**。
⛔ 大射程塔 + 怪密集时，会**漏掉一部分怪**，
表现为"塔偶尔不攻击"，而射程、mask、冷却全对，
⛔ 排查必然被引向"这只怪是不是免疫/隐身"。

【产出】`max_results` 显式取值（与最大同屏怪数挂钩）

【判据】`max_results` ≥ 同屏怪硬上限；⛔ 满屏怪时塔不会漏打。

【审】``audit/godot/genres-tower-defense.md#18``

### Step 4　伤害分发用接口，不是字符串比较名字　`[tower-defense/05#S4]`

【读】``howto/godot/genres-tower-defense.md#6. 塔的伤害分发：接口，不是字符串``

【做】
敌人统一实现 `func take_damage(amount: float, type: int) -> void`，
塔只调这个接口。
⛔ `body_entered` 回调里 `if body.name == "Enemy"` 有两个坑：
**`TileMap` / `TileMapLayer` 只要配了碰撞形状也会触发 `body_entered`**；
以及 `name` 会被 Godot 自动去重改名（`Enemy2`、`Enemy3` …），
⛔ 后半条尤其阴：第一批怪正常，多了之后**新增的怪**全部漏判。

【产出】`take_damage` 接口与调用点清单

【判据】地形/装饰配了碰撞也不会被当成敌人；⛔ 场上第 100 只怪仍会被正确结算。

【审】``audit/godot/genres-tower-defense.md#3``

### Step 5　索敌结果与塔的射程/冷却解耦　`[tower-defense/05#S5]`

【读】``howto/godot/genres-tower-defense.md#4. 索敌：降频查询，不要用信号``

【做】
索敌器只负责"这一批候选是谁"，塔自己按冷却与优先级挑目标。
⛔ 把冷却写进索敌（没冷却就不查）会让**降频与冷却两个周期耦合**：
表现为"塔的射程变了，攻击频率也跟着变"，
而这种联动在配置时完全看不出来。

ⓘ 换目标（当前目标死了/逃逸）时优先在**已有候选里**挑，
⛔ 每次换目标都重查一次等于把降频降下来的开销又加回去。

【产出】候选列表 → 目标选择 的两段结构

【判据】改射程不影响攻击频率；⛔ 换目标不触发额外 query。

【审】``audit/godot/genres-tower-defense.md#7``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const SCAN_INTERVAL := 0.15     # 索敌降频间隔（秒）
const MAX_CANDIDATES := 256     # ⛔ ≥ 同屏怪硬上限，默认 32 会静默截断
const ENEMY_LAYER := 4          # 敌人碰撞层（⛔ 与项目实际层号对齐）

var _scan_acc: float = 0.0

func _process(delta: float) -> void:
    _scan_acc += delta
    if _scan_acc < SCAN_INTERVAL:
        return
    _scan_acc = 0.0
    var q := PhysicsShapeQueryParameters2D.new()
    q.shape = CircleShape2D.new()
    q.shape.radius = range_radius
    q.transform = global_transform
    q.collision_mask = ENEMY_LAYER
    var hits := get_world_2d().direct_space_state.intersect_shape(q, MAX_CANDIDATES)
    # ⛔ 已重叠的形状被 intersect_shape 忽略，贴脸怪要单独补
    var inside := get_world_2d().direct_space_state.collide_shape(q)
    _retarget(hits, inside)

func _fire_at(e: Node) -> void:
    if e.has_method("take_damage"):
        e.take_damage(damage, damage_type)   # ⛔ 不是 e.name == "Enemy"
```

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 怪多时帧率崩 | 返工 Step 1（信号风暴） |
| 贴脸怪塔不开火 | 返工 Step 2（已重叠被忽略） |
| 塔偶尔不攻击 | 返工 Step 3（`max_results` 截断） |
| 只有前几只怪会被打死 | 返工 Step 4（`name` 被自动去重改名） |
| 改射程后攻击频率也变了 | 返工 Step 5（冷却与降频耦合） |
