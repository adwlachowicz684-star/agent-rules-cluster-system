# 06 波次结算与经济（塔防域）

> **本步交付**：波次完成是显式计数 + 漏怪是显式状态 + 击杀回收进池且只结算一次
> **对应**：流程 `howto/godot/genres-tower-defense.md` · 审核 `audit/godot/genres-tower-defense.md`

## 0. 交付物定义

1. 波次完成用 `spawned == killed + escaped` 显式判定
2. 漏怪（escaped）是**显式状态**，不是"怪消失了"
3. 每只怪的死亡结算**只发生一次**
4. 击杀奖励与池归还的顺序不会造成重复结算
5. 波次间的经济结算与下一波的触发条件明确

## 1. 前置检查清单

- [ ] 无 `get_nodes_in_group("enemies").is_empty()` 判波次清
- [ ] `escaped` 有独立的计数与状态
- [ ] 死亡结算有幂等保护
- [ ] 池归还与奖励发放的顺序已定
- [ ] 波次推进的触发条件写下来了

## 2. 工序

### Step 1　波次完成用显式计数，不用 group is_empty　`[tower-defense/06#S1]`

【读】``howto/godot/genres-tower-defense.md#5. 波次完成判定要显式计数``

【做】
用 `spawned_count == killed_count + escaped_count` 判清场。
⛔ `get_nodes_in_group("enemies").is_empty()` 会被三类东西污染：
**对象池里的休眠怪**（还在树里）、**正在播死亡动画的怪**、**正在退场的怪**。
⛔ 表现为「明明打完了，波次就是不推进」，
而检查时「场上确实没有敌人」—— 因为那些怪在池里或正在淡出。

ⓘ 更隐蔽的一半：这个判定**反过来也会失效** ——
怪提前被移除时 `is_empty()` 会提前为真，
表现为「还有怪在路上，下一波已经开始刷了」。

【产出】`is_wave_clear()` 与三个计数器

【判据】打完最后一只能推进；⛔ 有怪在路上不会提前开下一波。

【审】``audit/godot/genres-tower-defense.md#4``

### Step 2　漏怪是显式状态，不是让怪消失　`[tower-defense/06#S2]`

【读】``howto/godot/genres-tower-defense.md#5. 波次完成判定要显式计数``

【做】
怪到达终点要显式走 `escaped`：扣血/扣资源 → 标记 → 归还池。
⛔ 直接 `queue_free()` 会让计数器对不上（`spawned` 有它、`killed` 没它、
`escaped` 也没它），于是波次**永远清不了**，
而表现为「卡在第 N 波不动」，排查会被引向波次配置的格式。

【产出】`_on_reach_goal()` 的处理链（扣血 → escaped++ → 归还）

【判据】放 10 只怪全部漏光，⛔ 波次仍能正常结束并结算失败。

【审】``audit/godot/genres-tower-defense.md#4``

### Step 3　死亡结算要有幂等保护　`[tower-defense/06#S3]`

【读】``howto/godot/genres-tower-defense.md#6. 塔的伤害分发：接口，不是字符串``

【做】
多座塔同帧打同一只怪是常态（尤其弹道已发射、怪已死的情况）。
⛔ 不加幂等会出现「同一只怪结算两次奖励」，
而它在单塔测试时**永远测不出来** —— 只有塔密集、怪残血时才会撞上。

ⓘ 保护放在**怪自己身上**（`_resolved` 标志），
⛔ 不是放在塔侧判断「目标还活着吗」 ——
后者在多塔同帧时同样会双双通过检查。

【产出】`take_damage` 内的幂等标志

【判据】用脚本让 10 座塔同一物理帧打同一只残血怪，⛔ 奖励只结算一次。

【审】``audit/godot/genres-tower-defense.md#3``

### Step 4　击杀回收与奖励发放的顺序　`[tower-defense/06#S4]`

【读】``howto/godot/genres-tower-defense.md#7. 性能预算``

【做】
顺序固定为：**标记死亡 → 发奖励 → 播表现 → 归还池**。
⛔ 先归还再发奖励，会出现「奖励发给了复用出来的那只新怪」
（池里的实例是同一个对象），
表现为「偶尔多拿一次奖励」，而日志里每笔奖励都有合法的怪 ID。

ⓘ 死亡表现（飘字、碎裂）要在归还**之前**脱离怪节点，
⛔ 挂在怪上的表现会随归还一起被回收，表现为「怪多了之后没有死亡特效」。

【产出】死亡处理顺序（含表现脱离时机）

【判据】满屏怪连续死亡，⛔ 飘字与特效不缺失、不串到新怪身上。

【审】``audit/godot/genres-tower-defense.md#22``

### Step 5　波次推进的触发条件写下来　`[tower-defense/06#S5]`

【读】``howto/godot/genres-tower-defense.md#5. 波次完成判定要显式计数``

【做】
明确是「清场自动开下一波」还是「玩家点开始」或"倒计时"，
以及波间奖励与利息的结算时点。
⛔ 不定就开工，会得到「清场瞬间就刷下一波」这个隐式默认，
玩家没有喘息与建塔窗口 —— 而这属于**手感问题**，
⛔ 它在功能验收里完全测不出（功能是对的）。

【产出】波次推进条件与波间窗口时长

【判据】清场后有明确的建塔窗口；⛔ 不是「最后一死就立刻刷下一波」。

【审】``audit/godot/genres-tower-defense.md#4``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const WAVE_GAP := 3.0           # 波间建塔窗口（秒），⛔ 不写就是隐式 0

var spawned_count := 0
var killed_count := 0
var escaped_count := 0

func is_wave_clear() -> bool:
    return spawned_count == killed_count + escaped_count

func _on_reach_goal(m: Node) -> void:
    escaped_count += 1          # ⛔ 不能只 queue_free
    _life -= m.leak_cost
    release(m)

func _on_die(m: Node) -> void:
    if m._resolved:             # ⛔ 幂等：多塔同帧打同一只
        return
    m._resolved = true
    killed_count += 1
    _grant_reward(m.bounty)     # ⛔ 先发奖励再归还
    _spawn_death_fx(m.global_position)
    release(m)
```

## 4. 验收清单

- [ ] 打完最后一只能推进波次
- [ ] 全部漏光也能正常结束并判失败
- [ ] 多塔同帧击杀只结算一次
- [ ] 满屏连续死亡时特效不缺失
- [ ] 清场后有明确的建塔窗口

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 打完了波次不推进 | 返工 Step 1（group 判空 / 漏怪未计数） |
| 还有怪在路上就刷下一波 | 返工 Step 1（提前移除导致 `is_empty()` 提前为真） |
| 偶尔多拿一次奖励 | 返工 Step 3 / Step 4（无幂等 / 先归还后发奖） |
| 怪多了没有死亡特效 | 返工 Step 4（表现挂在怪上随归还被回收） |
