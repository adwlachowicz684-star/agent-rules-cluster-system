# 06 平台成就对接（achievement 域）

> **前置**：04 解锁与奖励发放
> **本步交付**：**平台 ID 映射 + 失败可重试 + 单向同步**
> **对应**：做法 `howto/godot/achievement.md#6. 平台成就对接`
> 　　　审核 `audit/godot/achievement.md`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：本地解锁了平台也亮了。**

⛔ 常见假完成：同步失败就跳过，
⚠ 网络正常时一切对得上，
⛔ 但**一次抖动就永久丢失**，
表现为"本地已解锁，平台永远差一个"，玩家会认为是游戏 bug。

做完这一步，应该能**当场演示**：

1. ⛔ 平台同步失败**可重试**（失败进队列，下次启动再推）
2. ⚠ 明确以**本地为准**向平台推送
3. ⛔ 承认 Godot 核心**没有**内置成就能力，需插件
4. ⚠ `platform_id` 映射表独立维护
5. ⛔ 每日/每周重置类成就**不用系统时间**

**产出物**：平台 ID 映射表 + 重试队列

## 2. 工序

### Step 1　⛔ 承认 Godot 核心没有内置成就能力　`[06#S1]`

【读】`howto/godot/achievement.md#6. 平台成就对接`

【做】接插件（GodotSteam 等）；版本兼容现查，不假设可用。

【产出】插件选型结论

【判据】⛔ 未接插件时代码**不假装**有平台成就

【审】`audit/godot/achievement.md#11`

### Step 2　⚠ platform_id 映射表独立维护　`[06#S2]`

【读】`howto/godot/achievement.md#6. 平台成就对接`

【做】本地 `id` 与平台 ID 的映射放独立数据表，不散落在代码里。

【产出】映射表

【判据】⚠ 换平台时**只改表**不改逻辑

【审】`audit/godot/achievement.md#11`

### Step 3　⛔ 同步失败必须可重试　`[06#S3]`

【读】`howto/godot/achievement.md#6. 平台成就对接`

【做】失败进重试队列，下次启动/联网时重推；不做"失败即放弃"。

【产出】重试队列（进存档）

【判据】⛔ 断网解锁后恢复联网，平台**补上**该成就

【审】`audit/godot/achievement.md#12`

### Step 4　⚠ 以本地为准向平台推送　`[06#S4]`

【读】`howto/godot/achievement.md#6. 平台成就对接`

【做】本地解锁是权威，向平台单向推送；不因平台状态回滚本地。

【产出】同步方向约定

【判据】⚠ 平台不可用时本地解锁**不会被撤销**

【审】`audit/godot/achievement.md#13`

### Step 5　⛔ 每日/每周重置不用系统时间　`[06#S5]`

【读】`howto/godot/achievement.md#6. 平台成就对接`

【做】重置类成就的时间基准走单调时钟/服务端时间，不用 `get_datetime_dict_from_system()`。

【产出】重置时间源

【判据】⛔ 改系统时间**不会**刷新每日成就

【审】`audit/godot/achievement.md#17`

### Step 6　⚠ 平台回执与本地状态对账　`[06#S6]`

【读】`howto/godot/achievement.md#6. 平台成就对接`

【做】定期比对本地已解锁与平台已解锁集合，差异进重试队列。

【产出】对账机制

【判据】⚠ 两边差异**能被发现**并自动补齐

【审】`audit/godot/achievement.md#12`

## 5. 常见返工

**① 以为引擎内置。** 上线才发现要插件。

**② 同步失败即放弃。** 永久丢失，玩家认为 bug。

**③ 以平台为准。** 平台不可用时本地被回滚。

**④ 重置用系统时间。** 改时间即刷新。
