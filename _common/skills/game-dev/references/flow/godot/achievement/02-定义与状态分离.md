## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：定义写好了、界面能读。**

⛔ 常见假完成：把 `unlocked` / `progress` 一起写进定义 Resource，
⚠ 开发期一切正常（策划改数值，代码跟着改），
⛔ 但上线后**策划改 `target_progress` 时旧存档会带着旧目标值覆盖新定义**，
表现为"改了配置，玩家那边没生效"。

做完这一步，应该能**当场演示**：

1. 定义 Resource 与状态存档**是两个文件**
2. ⛔ 改定义数值后，老存档**不覆盖**新定义
3. ⚠ 状态只存 `progress / unlocked / unlock_timestamp / sub_progress`
4. ⛔ 移除成就走"标记废弃"，不物理删除
5. ⚠ 时间戳存 UTC 秒，不存本地格式化串

**产出物**（下游按名字对接）：

```text
AchievementDefinition（定义，随版本）
AchievementState（状态，进存档）
存档字段：achievements: Dictionary[ StringName, AchievementState ]
```

## 2. 工序

### Step 1　⛔ 定义与状态分成两个类型　`[02#S1]`

【读】`howto/godot/achievement.md#1. 定义与状态分离`

【做】`AchievementDefinition` 只放策划可改的配置；`AchievementState` 只放 `progress/unlocked/unlock_timestamp/sub_progress`。

【产出】两个类型定义

【判据】⛔ 状态类型里**没有** `target_progress` 字段

【审】`audit/godot/achievement.md#1`

### Step 2　⛔ 改定义数值不炸老存档　`[02#S2]`

【读】`howto/godot/achievement.md#1. 定义与状态分离`

【做】读档时以**定义为准**解释状态；状态里不存目标值。

【产出】读档合并逻辑

【判据】⛔ 把 `target_progress` 从 100 改成 50 后，老存档玩家**立刻**判定为已达成

【审】`audit/godot/achievement.md#1`

### Step 3　⚠ 状态只存必要四字段　`[02#S3]`

【读】`howto/godot/achievement.md#2. 进度模型与持久化`

【做】`progress` / `unlocked` / `unlock_timestamp` / `sub_progress`，不存标题描述等派生展示信息。

【产出】`AchievementState` 字段表

【判据】⚠ 存档体积不随成就描述长度增长

【审】`audit/godot/achievement.md#15`

### Step 4　⛔ 移除成就标记废弃，不物理删除　`[02#S4]`

【读】`howto/godot/achievement.md#1. 定义与状态分离`

【做】下线成就改为 `deprecated = true` 保留定义；已解锁玩家的存档状态继续可读。

【产出】废弃标记机制

【判据】⛔ 删掉定义后，已解锁玩家读档**不报错也看不到**该成就

【审】`audit/godot/achievement.md#20`

### Step 5　⚠ 解锁时间戳存 UTC 秒，不存格式化串　`[02#S5]`

【读】`howto/godot/achievement.md#2. 进度模型与持久化`

【做】存整数 UTC 秒；展示时才按本地时区格式化。

【产出】`unlock_timestamp: int`

【判据】⚠ 改系统时区后，展示时间**随之变化但排序不变**

【审】`audit/godot/achievement.md#18`

## 5. 常见返工

**① 状态里存了目标值。** 改配置后老存档覆盖新定义。

**② 物理删除定义。** 已解锁玩家存档悬空。

**③ 时间戳存格式化串。** 跨时区/改时间即对不上。
