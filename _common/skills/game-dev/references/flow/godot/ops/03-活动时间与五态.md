# 03 活动时间与五态（运营域）

> **本步交付**：UTC Unix 秒规范 + 客户端时钟校准 + 五态状态机
> **对应**：流程 `howto/godot/ops.md` · 审核 `audit/godot/ops.md`

## 0. 交付物定义

1. 活动起止一律 UTC Unix 秒，客户端不判资格
2. 时钟校准模块已实现，且输出**仅用于显示**
3. 时钟回拨与快进已检测
4. 五态状态机含"结算中"
5. 停服维护由网关拒绝，不是客户端判断

## 1. 前置检查清单

- [ ] 无本地时间字符串比较活动起止
- [ ] 校准后的时间未用于资格判定
- [ ] 回拨 / 快进能触发重校准
- [ ] ⛔ 状态机有"结算中"
- [ ] 维护态由网关拒绝

## 2. 工序

### Step 1　所有活动时间用 UTC Unix 秒，客户端只接收不计算　`[ops/03#S1]`

【读】`howto/godot/ops.md#3. ⚠ 活动时间必须服务端给`

【做】
客户端只接收**截止 Unix 秒或剩余秒数**，不自己算资格。
⚠ 存储 / 比较 / 日志一律 UTC Unix 秒，绝不存本地时间字符串。
显示时用 `Time.get_datetime_dict_from_unix_time(int(unix_sec))`
（⛔ 先 `int()`，传 float 会截断）。
⛔ 用本地时间判活动 = 改系统时钟就能提前领奖。

【产出】活动时间字段规范（UTC Unix 秒）

【判据】代码中不存在用本地时间字符串比较活动起止

【审】`audit/godot/ops.md#12`


### Step 2　客户端时钟校准只用于倒计时显示，不用于资格判定　`[ops/03#S2]`

【读】`howto/godot/ops.md#8.1 两个时间 API 语义不同，混用必错`

【做】
NTP 思路：`offset = server_time - (client_sent_at + client_recv_at) / 2`，
`rtt = client_recv_at - client_sent_at`。
连续取 3~5 次，**丢弃 rtt 最大的样本**，取剩余中位数；
之后小幅更新 `offset = 0.8*old + 0.2*new`。
⛔ 校准后的时间只用于倒计时显示。
⚠ 时区：`get_unix_time_from_datetime_string()` **不做时区转换**，
运营给北京时间 `2026-09-20 00:00:00+08:00` 必须自己减 8 小时再比较。

【产出】时钟校准模块（输出仅用于显示）

【判据】资格判定代码中不出现校准后的本地时间

【审】`audit/godot/ops.md#13`


### Step 3　⛔ 必须检测时钟回拨与快进，否则改表就能刷每日奖励　`[ops/03#S3]`

【读】`howto/godot/ops.md#8.1 两个时间 API 语义不同，混用必错`

【做】
新值明显小于旧值 → 回拨；跳了数小时 → 快进。两者都要重校准。
⛔ 不检测时玩家把时间往后调一天就能刷每日奖励，**且不报错**——
日志里是一次完全正常的领取。
⚠ 间隔与轮询定时器用 `Time.get_ticks_msec()`（单调，官方说明为 64 位、
约 5 亿年后才回绕，可放心用于测间隔）；
它**不是现实时间**，⛔ 不能存盘、不能跨重启。

【产出】时钟异常检测（回拨 / 快进 → 重校准）

【判据】把系统时间前后调 1 天，检测能触发并重新校准

【审】`audit/godot/ops.md#14`


### Step 4　活动五态：漏掉"结算中"会让玩家以为自己没拿到奖励　`[ops/03#S4]`

【读】`howto/godot/ops.md#3. ⚠ 活动时间必须服务端给`

【做】
`未开始 / 进行中 / 已结束 / 结算中 / 已关闭`。
⛔ "结算中"是最常被漏掉的第四态——活动到点了但奖励还没发完，
这时显示"已结束"会让玩家以为自己没拿到，工单量会在活动结束当天集中爆发。

【产出】活动状态机（五态，含结算窗口）

【判据】活动结束后到奖励发完之前，UI 不显示"已结束"

【审】`audit/godot/ops.md#15`


### Step 5　停服维护由网关或登录服务直接拒绝，不是客户端判断　`[ops/03#S5]`

【读】`howto/godot/ops.md#3. ⚠ 活动时间必须服务端给`

【做】
客户端判断"是否在维护"意味着玩家可以改包绕过，
⛔ 且维护期间的请求仍会打到后端（此时后端可能正在迁移数据）。
正确做法：由网关或登录服务**直接拒绝**，客户端只负责展示返回的提示。

【产出】维护态处理（网关拒绝 + 客户端展示）

【判据】维护期间客户端改包也无法进入游戏

【审】`audit/godot/ops.md#16`

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 改钟提前领奖 | 用本地时间判资格 | S1 |
| 倒计时与服务端不一致 | 校准值被当权威 | S2 |
| 每日奖励被刷 | 无回拨检测 | S3 |
| 活动结束当天工单暴涨 | 缺"结算中" | S4 |
| 维护期请求打到后端 | 客户端判断维护 | S5 |
