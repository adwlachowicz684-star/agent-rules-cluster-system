# 04 签到、战令与周期结算（运营域）

> **本步交付**：服务端日期边界 + 累计经验模型 + 赛季结算任务
> **对应**：流程 `howto/godot/ops.md` · 审核 `audit/godot/ops.md`

## 0. 交付物定义

1. 签到日期边界在服务端算，跨月不重置
2. 补签是一个事务（扣货币 + 标已签 + 加计数）
3. 断签策略在模板里，不在代码里
4. 战令用累计经验模型
5. 双轨共享 `total_xp` 与 `level`
6. 赛季结束由服务端定时结算，不依赖玩家登录

## 1. 前置检查清单

- [ ] 无 `OS.get_date().day` 参与签到计算
- [ ] 补签是原子事务
- [ ] 断签策略是模板字段
- [ ] 战令存 `total_xp` 不存 `xp_in_level`
- [ ] 赛季结算是定时任务
- [ ] 赛季数据归档而非原地覆盖

## 2. 工序

### Step 1　签到日期边界在服务端算，客户端不能数天数　`[ops/04#S1]`

【读】`howto/godot/ops.md#8.3 签到：日期边界在服务端`

【做】
`today = floori((server_now + tz_offset) / 86400.0)`；
差 1 → 连续，差 > 1 → 断签，差 0 → 已签过。
服务端存 `last_signin_day`、`consecutive_days`、
`signin_bitmap`（位图，90 位够一季度）、`makeup_used_in_cycle`。
⛔ 客户端用 `OS.get_date().day` 从 1 数到 31，
月末会把"第 31 天"渲染成"第 1 天"，
⛔ 而这个 bug 只在每月最后一天出现一次，极易被当成偶发。

【产出】签到服务端字段（含位图）

【判据】跨月时签到天数连续，不出现第 1 天

【审】`audit/godot/ops.md#17`


### Step 2　补签必须在一个事务里扣货币 + 标已签 + 加计数　`[ops/04#S2]`

【读】`howto/godot/ops.md#8.3 签到：日期边界在服务端`

【做】
⛔ 分步写会导致断网重发**扣两次货币只标一次**——
玩家看到的是"钱少了但没补上"，工单描述会把人引向签到显示逻辑。
⚠ "是否已用"必须在服务端，不能是客户端的本地标记。

【产出】补签事务（原子）

【判据】模拟断网重发，货币只扣一次且状态正确

【审】`audit/godot/ops.md#18`


### Step 3　断签后重置还是续接是运营策略，写进模板不是写死在代码　`[ops/04#S3]`

【读】`howto/godot/ops.md#8.3 签到：日期边界在服务端`

【做】
`reset_on_break`（清零重数）/ `carry_over`（不清天数，但断掉那天永远拿不到）。
⛔ 写死在代码里意味着改策略要发版，
而运营策略的调整频率远高于发版频率。

【产出】签到模板字段（含断签策略）

【判据】改断签策略不需要改代码、不需要发版

【审】`audit/godot/ops.md#19`


### Step 4　战令用累计经验模型，不用逐级模型　`[ops/04#S4]`

【读】`howto/godot/ops.md#8.4 战令：用累计经验模型`

【做】
`level = max i where total_xp >= xp_thresholds[i]`。
⛔ 逐级模型（`level` + `xp_in_level`）在补发 / 撤回经验、跨级跳跃时
会出现"某一级没给够"的中间态，
⛔ 而这种中间态只在运营手动补发时才出现，测试环境永远测不到。

【产出】战令经验模型（只存 `total_xp`）

【判据】补发经验跨多级后，进度不出现中间态

【审】`audit/godot/ops.md#20`


### Step 5　双轨是资格不是两套数值：共享 total_xp 与 level　`[ops/04#S5]`

【读】`howto/godot/ops.md#8.4 战令：用累计经验模型`

【做】
免费 / 付费轨**共享 `total_xp` 与 `level`**，只是奖励表分开。
`purchased_pass` 由支付回调在服务端置位，
客户端只拿 `pass_entitlement: bool` 渲染锁图标。
⛔ 各存一份经验会导致买付费轨后历史进度对不上，需要补算逻辑。

【产出】战令双轨数据结构

【判据】买付费轨后历史进度无需补算

【审】`audit/godot/ops.md#21`


### Step 6　赛季结束由服务端定时结算，不依赖玩家下次登录　`[ops/04#S6]`

【读】`howto/godot/ops.md#8.4 战令：用累计经验模型`

【做】
`GRANT_ALL_UNCLAIMED`（打包发邮箱）/ `VOID_UNCLAIMED` /
`EXTEND_CLAIM_PERIOD` 写进赛季模板，
服务端在 `claim_deadline` 触发定时任务结算。
⛔ 依赖玩家下次登录意味着**未登录玩家的奖励永久丢失**。
⚠ 赛季数据要**归档而不是原地覆盖**——否则新赛季第 1 天玩家看到上赛季 60 级进度。

【产出】赛季结算任务（服务端定时）

【判据】赛季结束后未登录玩家仍能收到奖励

【审】`audit/godot/ops.md#22`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：签到用位图，不用布尔数组
const SIGNIN_BITMAP_BITS := 90
const DAY_SECONDS := 86400
const MAKEUP_MAX_PER_CYCLE := 3

func today_index(server_now: int, tz_offset: int) -> int:
	return floori((server_now + tz_offset) / float(DAY_SECONDS))
```
