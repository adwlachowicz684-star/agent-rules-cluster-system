# 运营服务端（活动 / 配置 / 补偿 / 兑换码）—— 域流程总览

> ⚠ **第 0 步：先定客户端是什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次要上什么运营能力挑。
> ⛔ 顺序错了比不做更糟：先做界面会得到一个漂亮的壳和一份脆弱的经济。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只想上下线活动开关与公告 | 01 → 02 → 07 |
| 有限时活动（开始 / 结束 / 领奖） | 01 → 02 → 03 → 07 |
| 有签到 / 战令 / 赛季 | 01 → 02 → 03 → 04 → 07 |
| 要发补偿（事故、回档、误发） | 01 → 03 → 05 → 07 |
| 要发兑换码 / 邀请码 | 01 → 05 → 06 → 07 |
| 全套 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 无论如何不能跳过** ——
它是唯一决定"后面 6 个功能点该投多少预算"的一步。
⛔ 跳过 01 直接做 03（活动时间），是最常见的错：
倒计时直观、能立刻看到"活动还剩 3 天"，
⚠ 而此时**资格判定还在客户端** —— 改系统时钟就能提前领奖，且不报错。

ⓘ 分工：
- `howto/godot/ops.md` 讲**单个机制怎么实现**（分桶、配置、五态、签到、战令、CDK）
- 本域讲**这些机制按什么顺序做、哪些必须在服务端、怎么验收**

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 运营边界与客户端定位 | — | 客户端能判 / 不能判两栏清单 + 爆炸半径排期 |
| 02 | 配置下发与灰度回滚 | 01 | 六件套管线 + 解析规范 + 秒级回滚 |
| 03 | 活动时间与五态 | 01, 02 | UTC Unix 秒规范 + 时钟校准 + 五态状态机 |
| 04 | 签到、战令与周期结算 | 01, 03 | 服务端日期边界 + 累计经验模型 + 赛季结算任务 |
| 05 | 补偿发放与幂等 | 01, 03 | 运营流水号幂等 + 重试对账 + CSPRNG 幂等键 |
| 06 | CDK 与兑换码 | 01, 05 | CSPRNG 生成 + 核销事务 + 网关限流 |
| 07 | 运营验收 | 全部 | 敌意环境实测（改钟 / 断网 / 改包 / 重放 / 回滚） |

⚠ **02 必须在 03 之前**：
活动时间要先有可信的下发通道，否则"服务端给的时间"没有可信的传输路径。
⛔ 先做 03 会把倒计时做出来，而时间值仍来自客户端。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `security` 域 防作弊 | 改钟与改包是同一类威胁，⛔ 处置都在服务端（见 03/S3、07/S3） |
| `analytics` 域 埋点 | 埋点必须带 `experiment_id / group`，否则无法分析实验（见 01/S5） |
| `economy` 域 经济 | 补偿与发奖走同一本账本，⛔ 不能另起一套发奖入口（见 05/S1） |
| `monetization` 域 商业化 | 订单幂等键与补偿幂等键是同一套（见 05/S5） |
| `trade` 域 交易 | 兑换码产出的物品与交易产出同一套实例绑定（见 06/S4） |
| `hotupdate` 域 热更 | ⛔ PCK 热更不能换活动逻辑，配置热更是另一条通道（见 02/S5） |
| `compliance` 域 合规 | 活动奖励的概率公示、未成年人限额由 04/S6 的模板字段承载（见 04/S6） |

⛔ **若某条接缝对不上，要单独立一个接线功能点**，
⛔ 不许在各处偷偷转格式。

## 3. 本域最容易做反的顺序

⛔ **先做活动界面与倒计时，把资产与兑换安全排到最后（03、04 提前，05、06 靠后）。**

"活动页能显示还剩 3 天"是最直观的验收点，
于是先做 UI、先做倒计时、先做签到日历动画，
⚠ 而此时发奖与兑换还没有唯一约束和幂等键。

⛔ 后果链：
活动上线 → 界面漂亮、倒计时正常 → 看起来"运营能力齐了" →
发奖与兑换被无限期推迟 →
⚠ 而补偿与兑换码一次重发就是成片的刷取 →
一个脚本就能批量扫码领奖，⛔ 且此时所有界面**一个都不会报警**
（因为它们防的是"显示不出来"，不是"发了两次"）。

✅ 正确顺序：先定边界（01），做可信下发（02）与服务端时间（03），
然后才是签到战令（04）、补偿幂等（05）、兑换码（06）。
