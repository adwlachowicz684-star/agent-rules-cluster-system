# 06 CDK 与兑换码（运营域）

> **本步交付**：CSPRNG 生成 + 核销事务 + 网关限流
> **对应**：流程 `howto/godot/ops.md` · 审核 `audit/godot/ops.md`

## 0. 交付物定义

1. 兑换校验在服务端
2. 码由 CSPRNG 生成
3. 字符集排除易混淆字符 + 唯一约束兜底
4. 核销是事务
5. 批次规则明确（唯一约束 + 叠加策略）
6. 限流在网关层

## 1. 前置检查清单

- [ ] 客户端不含兑换校验逻辑
- [ ] 码由 `Crypto.generate_random_bytes()` 生成
- [ ] 字符集不含 I O 0 1 L
- [ ] 数据库有唯一索引
- [ ] 核销在事务内
- [ ] 限流规则在网关层

## 2. 工序

### Step 1　兑换必须服务端校验，客户端校验等于无限刷　`[ops/06#S1]`

【读】`howto/godot/ops.md#5. CDK / 兑换码 / 邀请码`

【做】
客户端校验 = 可以无限刷。服务端要校验存在 / 未用 / 未过期 / 未达批次限。
⛔ 客户端校验的表现是"正常玩家完全正常"，
只是有一天后台发现兑换量远超发码量——此时已无法追回。

【产出】兑换校验接口（服务端）

【判据】改包伪造"校验通过"仍无法兑换

【审】`audit/godot/ops.md#28`


### Step 2　CDK 必须用 CSPRNG 生成，不能用 randi　`[ops/06#S2]`

【读】`howto/godot/ops.md#8.5 CDK 生成：必须用 CSPRNG`

【做】
`randi()` / `RandomNumberGenerator` 是普通伪随机，种子可预测、可复现 → **只用于玩法**。
⛔ 用它生成兑换码可被批量推算与扫库。
⚠ CSPRNG 官方说明"much slower"，所以只在生成码时用，不用于玩法随机。

【产出】CDK 生成器（服务端，CSPRNG）

【判据】无法从一批已发码推算出下一个码

【审】`audit/godot/ops.md#29`


### Step 3　字符集排除易混淆字符，长度够也要唯一约束兜底　`[ops/06#S3]`

【读】`howto/godot/ops.md#8.5 CDK 生成：必须用 CSPRNG`

【做】
去掉 `I` `O` `0` `1` `L`，推荐 32 字符集（每字符 5 bit），长度 12~16。
⛔ 含易混淆字符会让客服工单里出现大量"码输不进去"，
而这些工单**看起来是输入问题，不会引向生成端**。
⚠ 长度够也要数据库唯一约束兜底——概率再低也要防碰撞，
⛔ 只靠"概率极低"不建唯一索引，碰撞时会造出两个玩家持有同一个码。

【产出】CDK 字符集与长度规范 + 唯一约束

【判据】字符集不含 I O 0 1 L，且数据库有唯一索引

【审】`audit/godot/ops.md#30`


### Step 4　核销是事务：校验 → 标 USED → 发奖 → 提交　`[ops/06#S4]`

【读】`howto/godot/ops.md#8.5 CDK 生成：必须用 CSPRNG`

【做】
`SELECT ... FOR UPDATE` → 校验存在 / 未用 / 未过期 / 未达批次限 →
标 `USED` + 写 `used_by` / `used_at` → 发奖 → 提交。
⛔ 不是事务时，并发下同一码会被两人**同时兑换成功**，
而两人看到的都是"兑换成功"，没人会报错。

【产出】核销事务（服务端）

【判据】并发压测同一码，只有一次成功

【审】`audit/godot/ops.md#31`


### Step 5　批次管理：同批次不能重复兑换，跨批次叠加规则要明确　`[ops/06#S5]`

【读】`howto/godot/ops.md#5. CDK / 兑换码 / 邀请码`

【做】
要有**玩家—批次唯一约束**。跨批次能否叠加写进批次模板，
⛔ 不写清楚时运营会默认"不同批次可以各领一次"，
而实现可能按"同一活动只能领一次"处理。

【产出】批次规则（唯一约束 + 叠加策略）

【判据】同批次重复兑换被拒绝，跨批次行为与模板一致

【审】`audit/godot/ops.md#32`


### Step 6　限流在网关层：单玩家 / 单 IP / 同码连错冷却　`[ops/06#S6]`

【读】`howto/godot/ops.md#5. CDK / 兑换码 / 邀请码`

【做】
单玩家单码每分钟 1 次、单 IP 每分钟 10 次、同码连错 5 次进冷却。
⛔ 限流做在客户端或应用层，扫库请求会**直达数据库**，
表现为数据库慢查询而不是"被攻击"。
⚠ 邀请码双向奖励要防小号刷。

【产出】限流规则（网关层）

【判据】脚本批量试码被网关拦下

【审】`audit/godot/ops.md#33`

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 兑换量远超发码量 | 客户端校验 | S1 |
| 码被批量推算 | 用 randi 生成 | S2 |
| 大量"码输不进去"工单 | 字符集含易混字符 | S3 |
| 同一码两人兑换成功 | 核销非事务 | S4 |
| 跨批次行为与运营预期不符 | 叠加规则未写 | S5 |
| 数据库慢查询 | 限流不在网关 | S6 |
