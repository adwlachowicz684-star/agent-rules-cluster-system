# 01 运营边界与客户端定位（运营域）

> **本步交付**：客户端能判 / 不能判两栏清单 + 爆炸半径排期 + 离线默认值
> **对应**：流程 `howto/godot/ops.md` · 审核 `audit/godot/ops.md`

## 0. 交付物定义

1. "客户端能判 / 不能判"两栏清单已写下，不是凭感觉
2. 已确认 Godot 不内置任何运营后台能力
3. 优先级按爆炸半径排定，资产安全在最前
4. 离线默认值已内置，断网启动有确定表现
5. 埋点字段已带分组信息，关键事件已定服务端校验

## 1. 前置检查清单

- [ ] 已写明"客户端只能展示和转发，不能成为事实来源"
- [ ] 已确认引擎不内置账号 / A/B / 远程配置 / 兑换码
- [ ] 优先级表里资产与兑换安全排第一
- [ ] ⛔ 内置默认配置已编译进包，不是运行时才拉取
- [ ] 埋点字段含 `experiment_id` 与 `group`

## 2. 工序

### Step 1　先写"客户端能判 / 不能判"两栏清单　`[ops/01#S1]`

【读】`howto/godot/ops.md#0. ⚠ 一句话边界`

【做】
玩家可以改配置、改时钟、改内存、重复点击、断线重试、批量扫描兑换码。
因此**活动资格、奖励数量、剩余次数、兑换结果、分桶**都必须服务端决定。
⛔ 不写这两栏清单直接开工——"这个要不要服务端判"会在每个活动被重新争论一次，
⛔ 而争论的结论通常取决于当时谁在写，最后形成一半判一半不判的烂摊子。

【产出】客户端能判 / 不能判两栏清单（写进设计文档）

【判据】指着任一运营判定，能说出它属于哪一栏，且理由不是"应该能判"

【审】`audit/godot/ops.md#1`


### Step 2　Godot 不内置运营后台：没有活动开关、没有签到组件、没有兑换码系统　`[ops/01#S2]`

【读】`howto/godot/ops.md#8. 引擎侧 API：Godot 给什么，你必须写什么`

【做】
不要去 `ProjectSettings` 里找"活动开关"，不要指望 `HTTPRequest` 自带重试，
不要找内置的兑换码或补偿系统。
⚠ 引擎既不内置账号、A/B 测试、远程配置后台，也没有兑换码或补偿系统，
**全部要自建后端或接第三方 LiveOps 服务**。
⛔ 把它们当成"引擎应该有的功能"去找，会浪费大量时间，
并导向"Godot 不适合做运营"这个错误结论。

【产出】自建清单（后端 / 第三方 LiveOps 服务各自承担什么）

【判据】清单里每项都写明了由谁提供，不存在"引擎自带"

【审】`audit/godot/ops.md#2`


### Step 3　按爆炸半径排优先级：资产安全 > 时间可信 > 可运营性 > 展示体验　`[ops/01#S3]`

【读】`howto/godot/ops.md#7. 优先级：按爆炸半径排序`

【做】
先做资产与兑换安全（唯一约束、原子消耗、请求 ID、审计），
再做时间可信（服务端时间锚、五态、结算窗口），
然后可运营性（灰度、公告、停服、回滚），
最后展示体验（离线兜底、倒计时、按钮禁用）。
⛔ 顺序反过来，项目会拥有漂亮界面和脆弱经济。

【产出】优先级排期表（四类各自的时间窗）

【判据】展示体验项没有排在资产安全之前

【审】`audit/godot/ops.md#3`


### Step 4　⛔ 离线默认值必须内置，不能启动后才拉配置　`[ops/01#S4]`

【读】`howto/godot/ops.md#2. 配置下发不是"下载个 JSON"`

【做】
离线玩家拉不到配置。启动后才拉、拉不到就报错或显示空白，是最常见的上线事故。
⛔ 内置默认值不是"兜底文案"，而是能让游戏**完整跑起来**的一套最小配置：
活动入口显示什么、按钮是禁用还是隐藏、奖励图标用什么占位，都要有确定答案。

【产出】内置默认配置（编译进包，不依赖网络）

【判据】断网启动能正常进入主界面，且每个活动入口都有确定表现

【审】`audit/godot/ops.md#4`


### Step 5　埋点必须带分组信息，关键事件由服务端校验　`[ops/01#S5]`

【读】`howto/godot/ops.md#6. 埋点的运营视角`

【做】
客户端报"我通关了"不可信，关键事件要服务端校验；
埋点必须带 `experiment_id` / `group`，**没有分组就无法分析实验**；
断网要缓存并在恢复后补发。
⛔ 埋点不带分组，实验上线后只能看到总量变化，无法归因。

【产出】埋点字段规范（含分组字段与服务端校验项）

【判据】任一关键事件的埋点都能反查到它属于哪个实验分组

【审】`audit/godot/ops.md#5`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：内置默认值必须编译进包，不能是运行时才拉取的东西
const DEFAULT_CONFIG_PATH := "res://config/default_ops.json"
const FALLBACK_ACTIVITY_STATE := "unknown"

func _load_default_config() -> Dictionary:
	var f := FileAccess.open(DEFAULT_CONFIG_PATH, FileAccess.READ)
	if f == null:
		return {}
	var json := JSON.new()
	# ⛔ 不用 JSON.parse_string()：它失败时返回 null，与"内容就是 null"无法区分
	if json.parse(f.get_as_text()) != OK:
		return {}
	return json.data
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 一半判一半不判 | 没定边界 | S1 |
| 花大量时间找"活动开关" | 以为引擎内置 | S2 |
| 界面漂亮但经济被刷 | 优先级排反 | S3 |
| 断网启动白屏 | 没内置默认值 | S4 |
| 实验无法归因 | 埋点无分组 | S5 |
