# 05 补偿发放与幂等（运营域）

> **本步交付**：运营流水号幂等 + 重试对账 + CSPRNG 幂等键
> **对应**：流程 `howto/godot/ops.md` · 审核 `audit/godot/ops.md`

## 0. 交付物定义

1. 补偿按运营流水号幂等，不是按玩家 ID
2. 自动到账与系统邮件的失败态都已处理
3. 发奖失败有重试队列与对账
4. ⛔ 先标已用再发奖
5. 幂等键由 CSPRNG 生成

## 1. 前置检查清单

- [ ] 幂等键含批次标识
- [ ] 背包满时补偿不丢失
- [ ] 有重试队列与对账报表
- [ ] ⛔ 标记与发奖的顺序是先标记
- [ ] `client_req_id` 用 CSPRNG 生成

## 2. 工序

### Step 1　补偿按运营流水号幂等，不是按玩家 ID 去重　`[ops/05#S1]`

【读】`howto/godot/ops.md#4. 补偿与发放：必须幂等`

【做】
⛔ 按玩家 ID 去重会把**不同批次**的补偿误判为重复（玩家只拿到第一批）；
完全不去重则重复发 = 刷道具。
幂等键必须是 `运营流水号（batch_id + player_id）`。
⚠ 两种错误的表现完全相反，但排查时都会被引向"发奖服务有问题"。

【产出】补偿幂等键定义

【判据】同一批次重复提交只发一次，不同批次互不干扰

【审】`audit/godot/ops.md#23`


### Step 2　自动到账与系统邮件：两条路的失败态都要处理　`[ops/05#S2]`

【读】`howto/godot/ops.md#4. 补偿与发放：必须幂等`

【做】
自动到账体验好，但**背包满 / 资产不存在时会失败**；
系统邮件允许异步与客服复核，但要处理**邮件过期、附件满、领取幂等**。
⛔ 只做自动到账且不做失败处理，补偿会在背包满时**静默消失**——
玩家不知道自己错过，运营后台显示"已发放"。

【产出】补偿发放方式与失败处理

【判据】背包满时的补偿不会消失，且能被重试与对账发现

【审】`audit/godot/ops.md#24`


### Step 3　发奖失败要能重试与对账　`[ops/05#S3]`

【读】`howto/godot/ops.md#4. 补偿与发放：必须幂等`

【做】
⛔ "发奖失败就算了"会让问题**只在玩家投诉后暴露**，
而能投诉的玩家只是受损玩家里的一小部分。
要有重试队列与对账报表（应发 vs 实发）。

【产出】发奖重试队列 + 对账报表

【判据】人为制造发奖失败后，队列能自动重试成功

【审】`audit/godot/ops.md#25`


### Step 4　⛔ 先标已用再发奖，不能反过来　`[ops/05#S4]`

【读】`howto/godot/ops.md#5. CDK / 兑换码 / 邀请码`

【做】
反模式："先发奖再标已用" → 发奖成功、标记失败、下次重试**又发一次**。
两步之间必然存在失败窗口，⛔ 顺序决定了这个窗口是"少发"还是"多发"——
少发能对账发现，多发会直接变成经济问题。

【产出】发奖与标记的顺序（先标记）

【判据】在标记与发奖之间注入失败，重试不会重复发奖

【审】`audit/godot/ops.md#26`


### Step 5　幂等键 client_req_id 必须由 CSPRNG 生成　`[ops/05#S5]`

【读】`howto/godot/ops.md#8.5 CDK 生成：必须用 CSPRNG`

【做】
`Crypto.generate_random_bytes()` 生成、用完即弃；
服务端按 `(player_id, client_req_id)` 查重，重复请求**返回首次结果、不再发奖**。
⛔ 用时间戳或 `randi()` 生成会碰撞，而**碰撞的后果是真实请求被去重丢弃**
（玩家点了没反应），比重复发奖更难排查。
⚠ 官方建议尽量减少调用次数，一次多取字节。

【产出】幂等键生成与使用规范

【判据】批量压测下两端生成的 req_id 无碰撞

【审】`audit/godot/ops.md#27`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：幂等键是每次请求新建、用完即弃的
const REQ_ID_BYTES := 16
const IDEMPOTENCY_TTL_SEC := 86400

func new_req_id() -> String:
	var crypto := Crypto.new()
	# ⛔ 不用 randi() / 时间戳：碰撞会让真实请求被去重丢弃
	return crypto.generate_random_bytes(REQ_ID_BYTES).hex_encode()
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 第二批补偿发不出 | 按玩家 ID 去重 | S1 |
| 玩家说没收到但后台显示已发 | 背包满静默失败 | S2 |
| 问题靠投诉才发现 | 无重试对账 | S3 |
| 重发导致多发 | 先发奖后标记 | S4 |
| 点了没反应 | req_id 碰撞 | S5 |
