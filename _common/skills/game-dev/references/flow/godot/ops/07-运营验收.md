# 07 运营验收（运营域）

> **本步交付**：敌意环境实测记录（改钟 / 断网 / 改包 / 重放 / 回滚）
> **对应**：流程 `howto/godot/ops.md` · 审核 `audit/godot/ops.md`

## 0. 交付物定义

1. ⛔ 把系统时间前后调一天，重跑一遍
2. 断网 / 弱网下配置兜底与埋点补发已验证
3. 改包绕过客户端过滤后，服务端仍拦下
4. 并发与重放下幂等成立
5. 灰度回滚实测在承诺时间内生效

## 2. 工序

### Step 1　⛔ 把系统时间前后调一天，再跑一遍全部活动流程　`[ops/07#S1]`

【读】`howto/godot/ops.md#10. 待核对项（运行时验证）`

【做】
只测正常系统时间，**改钟才暴露的失效在正常环境全绿**。
⛔ "正常环境下全绿"是最危险的假通过——
它证明的只是"玩家不主动作恶时系统正常"。
向前调测每日奖励与体力恢复，向后调测活动是否已开始。

【产出】改钟测试记录（前后各一轮）

【判据】调前调后都不出现提前领奖 / 重复领取每日

【审】`audit/godot/ops.md#34`


### Step 2　断网与弱网：配置兜底与埋点补发都要走一遍　`[ops/07#S2]`

【读】`howto/godot/ops.md#6. 埋点的运营视角`

【做】
只在联网环境下测，**离线默认值与断网补发路径从未执行**。
⛔ 这两条路径恰恰是弱网用户唯一会走的路径，
而开发者的网络通常很好，于是它们永远测不到。
补发还要验证不重复——重连后补发两次会造出重复事件。

【产出】弱网测试记录（含断网启动、恢复补发）

【判据】断网启动有确定表现，恢复后埋点补发无重复

【审】`audit/godot/ops.md#35`


### Step 3　改包绕过客户端过滤后，服务端仍必须拦下　`[ops/07#S3]`

【读】`howto/godot/ops.md#0. ⚠ 一句话边界`

【做】
⛔ 只发一条正常兑换请求，走的是**客户端过滤**，
服务端校验路径**从未执行**。
验证方法是让客户端直接构造非法请求（过期码、已用码、超额数量），
确认服务端逐条拒绝，而不是"前端已经拦住了所以后端没测"。

【产出】改包测试记录（服务端逐条拒绝）

【判据】绕过客户端后仍被服务端拒绝

【审】`audit/godot/ops.md#36`


### Step 4　并发与重放：幂等必须成立　`[ops/07#S4]`

【读】`howto/godot/ops.md#4. 补偿与发放：必须幂等`

【做】
⛔ 手动点几次达不到刷取速率，**重放与并发路径未验证**。
要脚本化：同一请求重放 20 次、同一补偿批次重复提交、
同一兑换码并发兑换。

【产出】并发 / 重放测试记录

【判据】同一请求重放 N 次只生效一次

【审】`audit/godot/ops.md#37`


### Step 5　灰度回滚实测：必须能秒级回滚，且不需要发版　`[ops/07#S5]`

【读】`howto/godot/ops.md#1. A/B 测试与灰度：分组必须服务端算`

【做】
⛔ 只测灰度放量不测回滚，**出事时回滚路径从未跑过**。
回滚演练要给出耗时数字，⛔ "尽快回滚"不是承诺。

【产出】回滚演练记录（含实测耗时）

【判据】回滚在承诺时间内生效，且不需要发版

【审】`audit/godot/ops.md#38`


## 3. 验收清单

- [ ] ⛔ 系统时间前后调一天后无异常
- [ ] 断网启动有确定表现，补发无重复
- [ ] 改包后服务端仍逐条拒绝
- [ ] 重放 20 次只生效一次
- [ ] 回滚实测耗时已记录且达标

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 上线后被改钟刷 | 只测正常时间 | S1 |
| 弱网用户白屏 | 未测断网 | S2 |
| 后端校验从未生效 | 只测正常请求 | S3 |
| 重发导致多发 | 未测重放 | S4 |
| 出事回滚不了 | 只测放量 | S5 |
