# 植被 / 大规模散布物 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只是"地上长草，看着有就行" | 01 → 02 → 07 |
| 草要随风摆动 | 01 → 02 → 03 → 07 |
| 树/石头要分远近变精细度 | 01 → 02 → 04 → 07 |
| 植被可以被砍/采集 | 01 → 02 → 05 → 07 |
| 角色要能穿过草丛、不能穿树干 | 01 → 06 → 07 |
| 全套开放世界 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **不要因为"开放世界都有"就全做。**
⚠ 每加一个功能点就多一条接缝，尤其 05（交互）会强制 01 改结构。

ⓘ 若本次只有**几十个**精心摆放的装饰物，
那是普通 `MeshInstance3D`，⛔ 不要套本域——
本域的前提是"数量大到不能逐个建节点"。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 实例化与分块 | — | `MultiMeshInstance3D` 分块 + `custom_aabb` |
| 02 | 材质与抗锯齿 | 01 | alpha scissor + MSAA×alpha AA 配对 |
| 03 | 风与动画 | 02 | 顶点着色器摆动 + 全局风状态 |
| 04 | LOD 与可见距离 | 01 | 近高模/远低模交叉 + margin > 0 |
| 05 | 交互与可采集 | 01 | 平行状态表 + 索引交换 |
| 06 | 碰撞与可行走 | 01 | 只给可碰撞种类加体 |
| 07 | 植被验收 | 全部 | `Vertices Drawn` 实测 + 接缝复查 |

⚠ **01 必须在一切之前**：AABB 与分块决定了后面所有性能手段是否有效。
⚠ **02 必须在 03 之前**：叶片材质定不下来，风动画的顶点位移无处施加。
⚠ **05 依赖 01 分块**：整片一个 MultiMesh 时，砍一棵要重建全部 transform。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `occlusion-instancing.md` | MultiMesh 基础在那篇；本域只讲**分块与 AABB** |
| `environment-systems.md` 天气 | 风强度是**全局状态**，植被只读不写 |
| `openworld.md` 流式加载 | 分块尺寸要与流式单元对齐，否则两套边界 |
| `procedural-generation.md` 泊松采样 | 布点只管"不挤"，**不管玩法密度** |
| `upscaling.md` 抗锯齿 | 本域的 alpha AA 依赖 MSAA，与超分选型联动 |
| `render-pipeline.md` | 渲染器能力矩阵决定哪些手段可用 |
| `lifeskill-housing.md` 采集 | 采集走 05 的状态表，不另起一套 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**，
⛔ 不许在各处偷偷转格式（那些转换会散落多处，改接口时找不到）。

⚠ **各功能点自己的验收不能替代集成验收** ——
部件全合格、拼起来不能用，是跨域开发的典型失败。

## 3. 本域最容易做反的顺序

⛔ **先做交互（05）再做分块（01）。**

"能被砍"直觉上很重要，于是先把整片植被做成一个 MultiMesh 再往上加交互——
ⓘ 而 05 的砍伐要靠"与末尾交换 + 降 `visible_instance_count`"实现，
**整片一个 MultiMesh 时，一次砍伐要重建全部 transform**。

更糟的是：先做交互会让人用"缩放到 0"这种直觉做法，
它导致**索引错位**，表现为"砍第二棵时倒下的是第一棵"——
⛔ 而这个 bug 要到砍第二棵才出现，极难归因。

✅ 正确顺序：先分块（01），再让交互（05）只动一个块。
