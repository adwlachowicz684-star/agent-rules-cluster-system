> **前置**：`01-实例化与分块.md` 已完成
> **本步交付**：砍第 N 棵时**倒下的是第 N 棵**
> **对应**：做法 `howto/godot/vegetation.md#7. ⛔ 可交互植被：MultiMesh 实例没有独立身份`
> 　　　审核 `audit/godot/vegetation.md#20`

## 0. 交付物定义

⚠ **MultiMesh 里的实例不是节点，没有独立 ID、不能单独挂脚本。**

⛔ 两个直觉做法都是错的：

| 做法 | 后果 |
|---|---|
| 把砍掉的缩放到 0 | **索引错位**，第二次砍错树 |
| 删掉后重建全部 transform | 整片一个 MultiMesh 时，砍一棵要重建上万 transform |

做完这一步，应该能**当场演示**：

1. 砍第 N 棵，**倒下的是第 N 棵**（连砍 10 棵逐一核对）
2. ⚠ 砍伐只影响**所在块**，其他块不动
3. 采集结果进背包，且**不重复**
4. 重新加载场景后，已砍的**仍是已砍**
5. ⚠ 状态表与实例数组**同步交换**

**产出物**（下游按名字对接）：

```text
_state: Array         # 平行状态表，按实例索引
_remove_at(index)     # 与末尾交换 + 降 visible_instance_count
```

## 2. 工序

### Step 1　⚠ 建立平行状态表　`[vegetation/05#S1]`

【读】`howto/godot/vegetation.md#7. ⛔ 可交互植被：MultiMesh 实例没有独立身份`

【做】`_state` 数组按实例索引记录状态。

⛔ 不建表 → 无从知道哪棵还在，
而"看起来还在"的状态只有渲染侧知道。

【产出】`_state` 数组

【判据】⚠ 能按索引查到任意一株的状态

【审】`audit/godot/vegetation.md#20`

### Step 2　⛔ 用交换+降count，不用缩放　`[vegetation/05#S2]`

【读】`howto/godot/vegetation.md#7. ⛔ 可交互植被：MultiMesh 实例没有独立身份`

【做】
```gdscript
func _remove_at(i: int) -> void:
    var last := visible_instance_count - 1
    mm.set_instance_transform(i, mm.get_instance_transform(last))
    _state[i] = _state[last]          # ⚠ 状态表必须同步
    visible_instance_count = last
```

⛔ 缩放到 0 → **索引错位**，第二次砍错树。
⚠ 而这个 bug 要到砍第二棵才出现，极难归因。

【产出】`_remove_at()`

【判据】⚠ 连砍 10 棵，**每次倒下的都是目标那棵**

【审】`audit/godot/vegetation.md#20`

### Step 3　⛔ 状态表跟着交换　`[vegetation/05#S3]`

【读】`howto/godot/vegetation.md#7. ⛔ 可交互植被：MultiMesh 实例没有独立身份`

【做】交换 transform 时**同步交换状态**。

⛔ 只改数组不改状态表 = **"砍了 A，倒下的是 B"**，
而且因为只砍一棵时碰巧对，测试很容易通过。

【产出】同步交换逻辑

【判据】⚠ 砍第 1 棵后，**第 1 棵的状态是空、最后一棵的状态被移到了第 1 位**

【审】`audit/godot/vegetation.md#21`

### Step 4　⚠ 只动所在块　`[vegetation/05#S4]`

【读】`howto/godot/vegetation.md#1. ⚠ MultiMesh 是一个 AABB，不是一万个`

【做】砍伐只重建所在块的 transform，⛔ 不重建全部。

⛔ 整片一个 MultiMesh → 一次砍伐重建上万 transform，
表现为"砍一下卡一下"，而在实例少时**测不出**。

【产出】按块定位

【判据】⚠ 砍伐耗时**与块内实例数相关，与总数无关**

【审】`audit/godot/vegetation.md#2`

### Step 5　⚠ 采集不重复发放　`[vegetation/05#S5]`

【读】`howto/godot/vegetation.md#9. 相关文档`

【做】状态置空与发放在**同一事务**内，⛔ 先发放后置空。

⛔ 顺序反了 → 中途失败则物品已发但植被还在，
玩家可以**反复采集同一株**。

【产出】事务边界

【判据】⚠ 发放后强杀进程，重进**不重复获得**

【审】`audit/godot/vegetation.md#25`

### Step 6　⚠ 持久化已砍状态　`[vegetation/05#S6]`

【读】`howto/godot/vegetation.md#9. 相关文档`

【做】已砍索引进存档，⛔ 不重建整片。

⛔ 不存 → 重进场景植被全回来，
玩家"砍了一片树，回来又长出来了"。

【产出】存档字段

【判据】⚠ 重进后已砍的**仍是已砍**

【审】`audit/godot/vegetation.md#21`

## 5. 常见返工

**① 缩放到 0。** 索引错位，砍错树。

**② 状态表不同步。** 砍 A 倒 B，单数测试碰巧通过。

**③ 重建全部。** 砍一下卡一下。

**④ 先发放后置空。** 反复采集同一株。
