# 06 碰撞与可行走（植被域）

> **对应**：做法 `howto/godot/vegetation.md#0. 先定性：这是实例化问题，不是建模问题`
> 　　　审核 `audit/godot/vegetation.md#22`

## 0. 交付物定义

⚠ **植被的碰撞与渲染是两套数据，⛔ 不要想着复用。**

⛔ 两个直觉做法都有代价：

| 做法 | 后果 |
|---|---|
| 每株都加碰撞体 | 一万棵树 = 一万个物理体，物理步进崩 |
| 什么都不加 | 角色穿树而过，而草丛也挡路 |

做完这一步，应该能**当场演示**：

1. 角色**穿过**草丛（不阻挡）
2. 角色**不穿过**树干
3. ⚠ 物理步进时间**不随植被数量增长**
4. 可砍伐的树，砍掉后**碰撞也消失**
5. ⚠ 碰撞只建在**需要的种类**上

**产出物**（下游按名字对接）：

```text
collidable_types: Array[StringName]   # 只有这些种类建碰撞
_collider_for(index)                   # 按索引定位碰撞体
```

## 2. 工序

### Step 1　⚠ 只给需要阻挡的种类建碰撞　`[vegetation/06#S1]`

【读】`howto/godot/vegetation.md#0. 先定性：这是实例化问题，不是建模问题`

【做】`collidable_types` 白名单，只有树干/大石进物理。

⛔ 每株都加 → 一万棵树的物理体让**物理步进直接崩**，
而这个成本在摆几十棵时完全测不出来。

【产出】白名单

【判据】⚠ 物理步进时间**不随植被总数增长**

【审】`audit/godot/vegetation.md#22`

### Step 2　⚠ 草丛不阻挡但要有反馈　`[vegetation/06#S2]`

【读】`howto/godot/vegetation.md#0. 先定性：这是实例化问题，不是建模问题`

【做】草丛不建碰撞体，可用触发区做视觉/音效反馈。

⛔ 什么都不加 → 走进草丛**毫无反馈**，像走在平地上；
而给草丛也加碰撞 → 走不动。

【产出】草丛的反馈方式（触发区 / 无）

【判据】⚠ 走进草丛**能走过去**，且有反馈

【审】`audit/godot/vegetation.md#22`

### Step 3　⛔ 碰撞不复用渲染实例数据　`[vegetation/06#S3]`

【读】`howto/godot/vegetation.md#7. ⛔ 可交互植被：MultiMesh 实例没有独立身份`

【做】碰撞体是独立对象，按索引映射，⛔ 不读 MultiMesh 的 transform 当权威。

⛔ 复用渲染数据 → 摆动位移（03）会被带进碰撞，
表现为"风大时碰撞位置在飘"，时灵时不灵。

【产出】碰撞独立数据源

【判据】⚠ 风速拉到最大，**碰撞结果不变**

【审】`audit/godot/vegetation.md#14`

### Step 4　⚠ 砍掉后碰撞同步移除　`[vegetation/06#S4]`

【读】`howto/godot/vegetation.md#9. 相关文档`

【做】05 的 `_remove_at()` 同时移除对应碰撞体。

⛔ 不同步 → "树没了但撞空气"，
玩家会认为"这游戏有隐形墙"。

【产出】碰撞移除挂在 `_remove_at()` 上

【判据】⚠ 砍掉后**原地可通过**

【审】`audit/godot/vegetation.md#21`

### Step 5　⚠ 导航网格不受装饰性植被影响　`[vegetation/06#S5]`

【读】`howto/godot/vegetation.md#9. 相关文档`

【做】草丛不参与导航烘焙，只有白名单种类参与。

⛔ 草丛参与 → 导航网格被切成碎片，
AI 寻路变慢甚至失败，而**地表看起来是正常的**。

【产出】烘焙参与白名单

【判据】⚠ 铺满草丛后，**寻路耗时不变**

【审】`audit/godot/vegetation.md#22`

### Step 6　⚠ 碰撞数量有上限　`[vegetation/06#S6]`

【读】`howto/godot/vegetation.md#8. 待核对项（运行时验证）`

【做】只有玩家附近的块实例化碰撞体。

⛔ 全部常驻 → 块数一多物理步进就涨，
而这是在**小场景测不出来**的那类问题。

【产出】按块激活碰撞

【判据】⚠ 远离后该块碰撞**被释放**（体数下降）

【审】`audit/godot/vegetation.md#22`
