# 02 资产盘点、ID 映射与冲突枚举（分服合服域）

> **本步交付**：四类资产清单 + ID 映射表 + 冲突枚举表
> **对应**：流程 `howto/godot/sharding-matchmaking.md` · 审核 `audit/godot/sharding-matchmaking.md`

## 0. 交付物定义

1. 盘点覆盖"资产 / 关系 / 引用 / 语义"四类，⛔ 不是列数据库表
2. ID 映射已提前设计，⛔ 不是给主键加偏移量
3. 映射表被当作永久审计数据保留
4. 冲突枚举覆盖语义冲突，⛔ 不只是主键冲突
5. 八类专门样本已在盘点期选出

## 1. 前置检查清单

- [ ] 资产清单含关系与引用，不只是表
- [ ] ⛔ 未列出的表默认是"冻结写入但暂不迁移"
- [ ] ID 映射表已建，且不含偏移量方案
- [ ] 映射表被标为永久保留，⛔ 没有"用完即删"
- [ ] 重名 / 会长 / 待领附件等专门样本已列出

## 2. 工序

### Step 1　资产盘点不是列数据库表　`[sharding/02#S1]`

【读】`howto/godot/sharding-matchmaking.md#1.1 资产盘点：不是列数据库表`

【做】
列数据库表只会得到"有哪些表"，得不到"哪些会坏"。
要盘的是四类：**资产**（货币、道具、订单）、**关系**（好友、公会、师徒）、
**引用**（日志 join、缓存键、历史订单）、**语义**（重名、赛季归属）。
⛔ **未列出的表默认"冻结写入但暂不迁移"**，不是默认复制——
默认复制会把本不该搬的东西一起搬过去，且没人发现。

【产出】四类资产清单（含"暂不迁移"标注）

【判据】任一表都能说出它属于哪一类，且未列出的表已标冻结

【审】`audit/godot/sharding-matchmaking.md#9`


### Step 2　⛔ ID 映射必须提前设计，不能给主键加偏移量　`[sharding/02#S2]`

【读】`howto/godot/sharding-matchmaking.md#ID 映射必须提前设计`

【做】
"被合并服的 ID 全部 +10000000"是最省事的方案，也最危险：
⛔ 它会**破坏协议字段、缓存键、日志 join、历史订单引用**——
这四类地方散落多处，改接口时找不到，且**每一处单独看都合理**。

【产出】ID 映射表（源 ID → 目标 ID，含类型与生成时间）

【判据】映射方案里没有"偏移量"这一列

【审】`audit/godot/sharding-matchmaking.md#10`


### Step 3　⛔ 映射表是永久审计数据，用完不能删　`[sharding/02#S3]`

【读】`howto/godot/sharding-matchmaking.md#ID 映射必须提前设计`

【做】
合服结束后本能是清理临时表。
⛔ 但之后每一次"这个玩家三个月前的订单在哪"都要靠映射表回答，
删掉之后历史问题**永久无法追溯**，且表现为"数据从来就没有过"。

【产出】映射表保留策略（与业务数据同生命周期）

【判据】删除流程里没有指向映射表的清理步骤

【审】`audit/godot/sharding-matchmaking.md#11`


### Step 4　⛔ 冲突枚举要覆盖语义冲突，不只是主键冲突　`[sharding/02#S4]`

【读】`howto/godot/sharding-matchmaking.md#冲突枚举要覆盖语义冲突，不只是主键冲突`

【做】
主键冲突只是最容易查到的一种。
真正的麻烦是**语义冲突**：两个服各有一个叫"清风"的会长、
两个服的赛季进度不同、两边都有待领附件。
⛔ 只枚举主键冲突，dry-run 会报告"无冲突"——
而"无冲突"恰恰说明枚举器漏了东西。

【产出】冲突枚举表（主键 / 唯一键 / 语义三类）

【判据】枚举表里语义冲突条目数 ≥ 主键冲突条目数

【审】`audit/godot/sharding-matchmaking.md#51`


### Step 5　八类专门样本要在盘点期就选出来　`[sharding/02#S5]`

【读】`howto/godot/sharding-matchmaking.md#1.4 校验要从总额对账上升到玩家旅程对账`

【做】
⛔ 随机抽样几张表只能证明"没大规模丢失"，证明不了业务正确。
要沿**玩家旅程**走，并单独挑出八类专门样本（重名、会长、待领附件、进行中订单、
封禁中、公会仓库、师徒、赛季进行中）。
⚠ 这些样本在盘点期就要定好——到校验期再找，往往已无法复现当时的状态。

【产出】八类专门样本清单（含选取条件）

【判据】每一类都有具体样本 ID，不是只写了类名

【审】`audit/godot/sharding-matchmaking.md#17`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：映射表是永久审计数据，批次写入要留痕
const ID_MAP_BATCH_SIZE := 1000

# ⛔ 只读展示用；写入由服务端迁移脚本负责，客户端不参与
func lookup_mapped_id(id_map: Dictionary, src_shard: int, src_id: int) -> int:
	var key := "%d:%d" % [src_shard, src_id]
	return int(id_map.get(key, src_id))
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 合服后功能坏但表都在 | 只盘了表没盘引用 | S1 |
| 历史订单查不到 | 用了偏移量映射 | S2 |
| 三个月前的问题无法追溯 | 删了映射表 | S3 |
| dry-run 报"无冲突" | 只枚举主键 | S4 |
| 对账通过但玩家投诉 | 随机抽样没覆盖专门样本 | S5 |
