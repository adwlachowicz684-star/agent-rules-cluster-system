# 04 校验、开服与回滚语义（分服合服域）

> **本步交付**：玩家旅程对账记录 + 双签核 + 正向补偿预案
> **对应**：流程 `howto/godot/sharding-matchmaking.md` · 审核 `audit/godot/sharding-matchmaking.md`

## 0. 交付物定义

1. 校验已从总额对账上升到玩家旅程对账
2. 能登录不等于能开服，双签核已执行
3. ⛔ 开服后出错的第一反应不是 restore
4. 单点错误走正向补偿，不整体回滚
5. 回滚语义已明确：只能回到内部一致状态

## 1. 前置检查清单

- [ ] 对账沿玩家旅程走，不是只比总额
- [ ] 八类专门样本逐条核对过
- [ ] ⛔ 运维与 QA 双签核记录存在
- [ ] 正向补偿预案已写（不依赖 restore）
- [ ] 回滚目标被定义为"内部一致状态"，不是"停服时刻"

## 2. 工序

### Step 1　⛔ 总额对账通过只证明没大规模丢失，要上升到玩家旅程　`[sharding/04#S1]`

【读】`howto/godot/sharding-matchmaking.md#1.4 校验要从总额对账上升到玩家旅程对账`

【做】
总额对上是最容易做、也最容易骗过自己的一项：
货币总量对了，但**可能 A 的钱记到了 B 头上**。
⛔ 必须沿玩家旅程走一遍：登录 → 看背包 → 看公会 → 领附件 → 打一局 → 下单 → 退出。

【产出】玩家旅程对账记录（逐环节）

【判据】每个环节都有"合服前后一致"的实测记录，不是"总量一致"

【审】`audit/godot/sharding-matchmaking.md#16`


### Step 2　八类专门样本逐条核对　`[sharding/04#S2]`

【读】`howto/godot/sharding-matchmaking.md#1.4 校验要从总额对账上升到玩家旅程对账`

【做】
⛔ 随机抽样几张表，抽中的几乎全是"普通玩家"，
而问题 100% 集中在特殊样本上：重名、会长、待领附件、进行中订单、封禁中、公会仓库、师徒、赛季进行中。
⚠ 这八类要**逐条**核对，不能抽样。

【产出】八类样本核对表（逐条签名）

【判据】每一类都有实测结果与负责人，无"抽样通过"字样

【审】`audit/godot/sharding-matchmaking.md#17`


### Step 3　⚠ 能登录就能开服是不够的：要运维和 QA 双签核　`[sharding/04#S3]`

【读】`howto/godot/sharding-matchmaking.md#5. 待核对项`

【做】
"能登录、能打一局"是开服演示里最常被当作结论的现象，
⚠ 但它覆盖不到邮件、拍卖行、排行榜、公会仓库这些低频高价值路径。
⛔ 必须**运维与 QA 双签核**，且签核项就是上面那些低频路径，不是登录。

【产出】双签核记录（含低频路径逐项结果）

【判据】记录上有两个角色签名，且含至少一条低频路径

【审】`audit/godot/sharding-matchmaking.md#18`


### Step 4　⛔ 开服后出错不能 restore：会构成二次事故　`[sharding/04#S4]`

【读】`howto/godot/sharding-matchmaking.md#1.5 ⚠ 回滚不能回到过去，只能回到「数据仍是内部一致状态」`

【做】
restore 到停服时刻的备份，会**抹掉开服后产生的真实对局、交易与充值**。
⛔ 对已充值的玩家来说，这是比故障本身更严重的**二次事故**——
而且它不可逆。
⚠ 预案里第一条必须写"不要 restore"，而不是"必要时 restore"。

【产出】开服后故障处置预案（第一条为禁止 restore）

【判据】预案第一条明确禁用 restore，且给出替代路径

【审】`audit/godot/sharding-matchmaking.md#19`


### Step 5　⛔ 单点错误优先正向补偿，不是整体回滚　`[sharding/04#S5]`

【读】`howto/godot/sharding-matchmaking.md#回滚后的新数据分三类处理`

【做】
一个玩家的数据错了，本能是回滚整批。
⛔ 但整批回滚会连带影响所有正常玩家，把小故障放大成大故障。
⚠ 正解是**正向补偿 + 单玩家修复 + 审计单**：
把错的那个改对，并留下可追溯的记录。

【产出】单玩家修复流程 + 审计单模板

【判据】存在一条"只改一个玩家"的已执行记录

【审】`audit/godot/sharding-matchmaking.md#20`


### Step 6　⛔ 回滚只能回到"数据仍是内部一致状态"　`[sharding/04#S6]`

【读】`howto/godot/sharding-matchmaking.md#1.5 ⚠ 回滚不能回到过去，只能回到「数据仍是内部一致状态」`

【做】
回滚不是时间旅行。⛔ 它只能回到一个**内部一致**的点，
不能回到"合服开始前那一刻"——因为开服后已经产生了新数据。
⚠ 回滚后要按三类处置新数据：可保留的、需补偿的、必须作废的，
⛔ 且这三类要在回滚前就分好，不是回滚后再决定。

【产出】回滚后新数据三类处置表

【判据】三类各自有明确判定规则，且先于回滚存在

【审】`audit/godot/sharding-matchmaking.md#21`

## 4. 验收清单

- [ ] 玩家旅程逐环节对账记录存在

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 总量对但玩家投诉 | 只做总额对账 | S1 |
| 特殊玩家数据坏 | 随机抽样 | S2 |
| 开服后邮件不能用 | 只测了登录 | S3 |
| 故障后玩家充值消失 | 用了 restore | S4 |
| 小错放大成全服事故 | 整体回滚 | S5 |
| 回滚后数据不自洽 | 以为能回到过去 | S6 |
