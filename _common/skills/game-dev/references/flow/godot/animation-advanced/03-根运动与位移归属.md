# 03 根运动与位移归属（动画进阶域）

> **本步交付**：单一驱动口径 + 朝向换算 + 插值与同步口径
> **对应**：流程 `howto/godot/animation-advanced.md` · 审核 `audit/godot/animation-advanced.md`

## 0. 交付物定义

1. 位移产出方**唯一**（根运动 或 代码，二选一并写清）
2. 根运动增量已按角色朝向换算后应用
3. 视觉抵消口径已确认（启用后视觉位置 ≠ `Node.transform`）
4. 与物理插值、网络同步的配合口径已写下
5. `root_motion_local` 的取值已结合分层需求决定

## 1. 前置检查清单

- [ ] 能一句话说清位移由谁产出
- [ ] 根运动增量做了朝向换算
- [ ] 已确认视觉位置不等于 `Node.transform`
- [ ] 启用物理插值时已安排 `reset_physics_interpolation()`
- [ ] `root_motion_local` 取值已定

## 2. 工序

### Step 1　先定唯一驱动方，⛔ 不是"根运动加法上去"　`[animation-advanced/03#S1]`

【读】`howto/godot/animation-advanced.md#3. 根运动（Root Motion）`

【做】
在"根运动驱动"与"代码驱动"之间二选一并写清，代码里只保留一处位移写入。
⛔ 两边都写 —— 启用根运动后角色的视觉位置**不再等于** `Node.transform`，
此时代码再 `move_and_slide()` 会得到**双倍位移**，
⛔ 表现为"角色跑得比动画快一倍"，而日志里每次移动量都"看起来正常"。

ⓘ 这条是 01 归属清单在位移上的具体落地：
⛔ 01 没定清，这里必然两边都写，且**两边单看都对**。

【产出】位移产出方的唯一口径 + 代码中位移写入点的清单

【判据】全项目搜索位移写入点只有一处；⛔ 没有两处同时写。

【审】`audit/godot/animation-advanced.md#9`、`audit/godot/animation-advanced.md#32`

### Step 2　根运动增量要按朝向换算　`[animation-advanced/03#S2]`

【读】`howto/godot/animation-advanced.md#3. 根运动（Root Motion）`

【做】
应用前把增量从角色局部空间转到世界空间（`transform.basis * motion`）。
⛔ 直接用 —— 角色转身后位移方向仍按动画制作时的朝向，
表现为**"角色朝东走却往北飘"**，
⛔ 而位移量本身完全正确，排查被引向碰撞与速度而非坐标系。

ⓘ 这个症状在角色**正面朝前**时完全不出现（局部与世界重合），
⛔ 所以只测"直线向前跑"会给出假通过。

【产出】朝向换算的唯一实现点

【判据】角色朝任意方向时，位移方向都与朝向一致。

【审】`audit/godot/animation-advanced.md#9`

### Step 3　root_motion_local 按分层需求决定　`[animation-advanced/03#S3]`

【读】`howto/godot/animation-advanced.md#root_motion_local 与混合前后的位移`

【做】
决定 `root_motion_local` 取值：默认 **`false`**（取混合**后**的位移）。
若上层还有叠加/分层，确认是否需要取混合**前**的局部位移。
⛔ 不确认 —— 分层叠加根运动时，混合前后的位移量不同，
表现为**"叠加层一开，位移就变多了"**，
⛔ 而每个动画单独播放时位移都精确，排查被引向动画资源。

ⓘ 与 04 的分层过滤是同一件事的两面：
⛔ 过滤决定哪些骨骼参与，这里决定位移取哪一段。

【产出】`root_motion_local` 取值 + 与 04 分层的对照说明

【判据】开/关叠加层时，基础位移量不变（除非设计如此）。

【审】`audit/godot/animation-advanced.md#27`

### Step 4　与物理插值、网络同步的配合口径　`[animation-advanced/03#S4]`

【读】`howto/godot/animation-advanced.md#3. 根运动（Root Motion）`

【做】
写下三件事：启用物理插值时何时调 `reset_physics_interpolation()`、
哪些根运动参数需要同步、本地与服务端的增量不一致时以谁为准。
⛔ 不写 —— 本地客户端与服务端的根运动增量**可能不同步**，
表现为"多人时角色位置轻微漂移"，
⛔ 而单机测试**完全正常**，这是最典型的只在联机才现形的一类。

ⓘ 与 `physics` 域的接缝：
⛔ 插值快照重置的时机在 `physics` 域，本域只定"根运动属于需要重置的那类位移"。

【产出】同步参数清单 + 插值重置时机 + 增量冲突时的裁决口径

【判据】联机 10 分钟无累积漂移；强杀重连后位置与服务端一致。

【审】`audit/godot/animation-advanced.md#32`、`audit/godot/animation-advanced.md#37`

### Step 5　根运动与 IK 的最终位置归属　`[animation-advanced/03#S5]`

【读】`howto/godot/animation-advanced.md#4. IK（反向动力学）`

【做】
写清"最终位置由谁决定"：根运动给基础位移，IK 只修正骨骼，
⛔ IK 不得再改 `transform`。
⛔ 两边都改 —— 位移和骨骼修正会**互相打架**，
表现为"脚陷进地里"或"手抖"，
⛔ 而根运动单独跑正常、IK 单独跑也正常，只有合起来才出问题。

ⓘ 这条要在美术铺开之前定：
⛔ 等动画都做完了才发现归属没定，等于所有动画重过一遍。

【产出】最终位置归属的一行结论 + IK 禁止修改项的清单

【判据】IK 开关切换 20 次，角色位置**不变**，只有骨骼变。

【审】`audit/godot/animation-advanced.md#30`、`audit/godot/animation-advanced.md#32`

## 3. 参考实现
```gdscript
# ⓘ 承接 03/S1、S2：tree 为 AnimationTree；位移唯一产出方为根运动
func _physics_process(_delta: float) -> void:
    var rm: Transform3D = tree.get_root_motion_transform()
    var motion := transform.basis * rm.origin
    velocity = motion / get_physics_process_delta_time()
    move_and_slide()
```

## 5. 常见返工
| 症状 | 原因 | 回到 |
|---|---|---|
| 角色跑得比动画快一倍 | 两处都写位移 | S1 |
| 朝东走向北飘 | 没做朝向换算 | S2 |
| 叠加层一开位移变多 | root_motion_local 没定 | S3 |
| 联机才漂移 | 同步与插值口径没写 | S4 |
| 脚陷地 / 手抖 | 根运动与 IK 都改位置 | S5 |
