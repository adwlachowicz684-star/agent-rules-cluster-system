# 02 混合空间与参数驱动（动画进阶域）

> **本步交付**：连续量映射 + 轨道类型口径 + 确定性初值
> **对应**：流程 `howto/godot/animation-advanced.md` · 审核 `audit/godot/animation-advanced.md`

## 0. 交付物定义

1. 每个连续参数都有**归一口径**（原始量 → 0..1 的除法与 clamp 写在何处）
2. 混合空间的 `sync` 取舍逐组记录（哪些组开、哪些组关）
3. 转移时机 `switch_mode` 逐条记录，⛔ 受击/攻击不用 AtEnd
4. 多条候选转移的 `priority` 已显式设置
5. 状态名用常量引用，⛔ 不是散落的字符串字面量

## 1. 前置检查清单

- [ ] 每个连续参数能说出它的归一化基准值是什么
- [ ] `sync` 的取舍有逐组记录
- [ ] 受击/攻击的 `switch_mode` 不是 AtEnd
- [ ] 同一状态多条出边都设了 `priority`
- [ ] 状态名来自常量

## 2. 工序

### Step 1　连续量先归一，⛔ 不是直接把速度塞进 blend_position　`[animation-advanced/02#S1]`

【读】`howto/godot/animation-advanced.md#2. 混合空间`

【做】
每个连续参数都写下"原始量 / 基准值"的除法与 clamp，基准值进参数表。
⛔ 直接塞原始速度 —— 混合位置的物理含义会随角色改速而变，
表现为"改了移动速度后动画混合全错"，
⛔ 而排查时混合空间配置没问题、动画资源也没问题。

ⓘ 基准值进参数表还有一层收益：
它是后续 LOD 与难度调参的唯一切入口，
⛔ 散落在脚本里的除数改一处漏一处，表现为"某些状态混合不对"。

【产出】连续参数归一表（参数名 / 原始量 / 基准值 / clamp 范围）

【判据】改一次基准值，所有相关状态的混合同步变化。

【审】`audit/godot/animation-advanced.md#39`、`audit/godot/animation-advanced.md#13`

### Step 2　sync 逐组取舍，⛔ 不是全局开关　`[animation-advanced/02#S2]`

【读】`howto/godot/animation-advanced.md#2. 混合空间`

【做】
逐组记录 `sync`：长度相近的循环（walk/run）**开**，
长度差异大的（idle / jump / attack）**关**。
⛔ 全局开 —— 强制同步长度差异大的动画会**拉伸变形**，
表现为"跳跃落地时腿被拉长"，
⛔ 而混合空间里每个点单独看都正常，只有过渡时才现形。

ⓘ 这条与状态机过渡的 `switch_mode = Sync` 是同一个语义的两处：
⛔ 只在一处改，会出现"混合空间内正常、跨状态过渡变形"的半边症状。

【产出】`sync` 取舍表（混合空间 / 状态机过渡 两列）

【判据】任意两个状态之间来回过渡 20 次，无拉伸变形。

【审】`audit/godot/animation-advanced.md#12`

### Step 3　转移时机逐条定，⛔ 受击与攻击不用 AtEnd　`[animation-advanced/02#S3]`

【读】`howto/godot/animation-advanced.md#switch_mode = 过渡时机，不是淡入算法`

【做】
逐条转移写下 `switch_mode`：响应式移动用 Immediate，
长度相近的循环用 Sync，不可打断的演出用 AtEnd。
⛔ 给受击/攻击用 AtEnd —— 玩家会觉得**操作有延迟**，
而这是手感问题里最难被测试发现的一类：
⛔ 帧数、日志、状态机全都正常，只有玩家的手知道。

ⓘ 反过来也成立：
⛔ 不可打断的演出用了 Immediate，会出现"动画被切成两半"，
表现为"过场播到一半突然跳走"，且只在玩家连续输入时出现。

【产出】转移清单（每条含 switch_mode 与取舍理由）

【判据】受击后 1 帧内开始播；不可打断的演出不被输入打断。

【审】`audit/godot/animation-advanced.md#5`、`audit/godot/animation-advanced.md#4`

### Step 4　多条候选转移必须显式设 priority　`[animation-advanced/02#S4]`

【读】`howto/godot/animation-advanced.md#转移条件的两个限制`

【做】
同一状态的多条出边全部显式设 `priority`（越小越优先）。
⛔ 靠连线顺序 —— 官方口径是 **`priority` 决定，不是顺序**，
不设则"选谁是不确定的"，
⛔ 表现为**难以追踪的偶发随机行为**，
而这恰恰是最容易被归因为"动画系统玄学"的一类，于是被无限期搁置。

ⓘ 同时要写下 `advance_mode`：
可设为 `DISABLED`（该转移不参与）或 `AUTO`（条件为真时自动转移，不靠 travel）。
⛔ 只靠 `travel` 而不用 AUTO —— 状态判定逻辑会全部堆进脚本，
表现为"状态机图和代码两处都要改"，改一处漏一处。

【产出】转移清单补全（含 priority 与 advance_mode）

【判据】同时满足两条出边条件 20 次，每次都走同一条。

【审】`audit/godot/animation-advanced.md#7`、`audit/godot/animation-advanced.md#29`

### Step 5　状态名用常量，⛔ 不是散落字面量　`[animation-advanced/02#S5]`

【读】`howto/godot/animation-advanced.md#读当前状态`

【做】
所有状态名定义为 `const`，脚本里只引用常量。
⛔ 散落字符串 —— `travel` 到不存在的状态**不报错**，
表现为"调用成功但状态没变"，
⛔ 而这类问题在重命名一个状态后才成片出现，且没有一处会亮红。

ⓘ 配套一条：过渡期间 `get_current_node()` 返回的是**目标状态**
（官方：当前状态在淡化开始时就切换）。
所以用它做"是否到达某状态"的判断会**提前为真**，
⛔ 表现为"逻辑比画面早一步"，排查被引向时序而非取值语义。

【产出】状态名常量表 + `get_current_node()` 的使用约束

【判据】重命名任一状态后，全项目零处遗漏；过渡期判断不提前为真。

【审】`audit/godot/animation-advanced.md#8`、`audit/godot/animation-advanced.md#15`

## 3. 参考实现
```gdscript
# ⓘ 承接 02/S1：MAX_SPEED 为 Step 1 归一表的基准值，见 00 参数登记
extends CharacterBody3D

const MAX_SPEED := 5.0
const STATE_JUMP := "jump"

@onready var tree: AnimationTree = $AnimationTree
@onready var playback: AnimationNodeStateMachinePlayback = tree["parameters/playback"]

func _physics_process(_delta: float) -> void:
    var move := Input.get_vector("left", "right", "forward", "back")
    var ratio := clampf(velocity.length() / MAX_SPEED, 0.0, 1.0)
    tree["parameters/Grounded/blend_position"] = Vector2(move.x, move.y)
    tree["parameters/speed"] = ratio
    if is_on_floor() and ratio < 0.01:
        playback.travel("idle")
```
