# 01 状态机与姿势归属地基（动画进阶域）

> **本步交付**：归属清单 + Start 节点口径 + 三个覆盖默认值确认
> **对应**：流程 `howto/godot/animation-advanced.md` · 审核 `audit/godot/animation-advanced.md`

## 0. 交付物定义

1. "谁拥有 transform、谁拥有骨骼姿势、谁拥有参数"三者已写死并分层
2. `AnimationTree` 的启用方式已确认（Start 节点或 `start()`），⛔ 不依赖"active 忘了设"这条旧口径
3. 三个被覆盖的默认值已逐条确认并写下取值
4. `RESET` 动画存在且被确认为确定性初值来源
5. 离散类轨道的 `callback_mode_discrete` 已按轨道类型决定

## 1. 前置检查清单

- [ ] 能一句话说清位移由谁产出
- [ ] Start 节点已连接或 `_ready()` 里调了 `start()`
- [ ] `callback_mode_discrete` 已按"有没有离散轨道"决定
- [ ] `deterministic` 的取值已结合"用不用 Add 类节点"决定
- [ ] `RESET` 动画存在

## 2. 工序

### Step 1　先写归属清单，⛔ 不是先连状态图　`[animation-advanced/01#S1]`

【读】`howto/godot/animation-advanced.md#0. 先分清三件事`

【做】
写下三件事的归属：**谁拥有 `transform`（代码 / 根运动 / 物理）**、
**谁拥有骨骼姿势（树 / IK / 程序化）**、**谁拥有混合参数（脚本 / 服务端）**。
⛔ 先连状态图 —— 图一成型，"这个状态改不改位移"就会随美术需求逐个妥协，
最后变成代码也在改 `transform`、根运动也在改，
表现为**位移翻倍或原地抖动**，而每一处单看都对。

ⓘ 归属清单的收益在接入物理插值与网络同步时才显现：
那时能直接问"这个位移该不该被插值"，⛔ 没清单就只能全量排查。

【产出】三行归属清单（transform / 骨骼姿势 / 混合参数各一行）

【判据】指着任意一处修改能说出它归属哪一行；⛔ 没有同一件事被两行同时认领。

【审】`audit/godot/animation-advanced.md#32`、`audit/godot/animation-advanced.md#1`

### Step 2　启用方式按官方口径确认，⛔ 不是"设 active 就完了"　`[animation-advanced/01#S2]`

【读】`howto/godot/animation-advanced.md#1. 状态机`

【做】
确认启用路径：连 Start 节点，**或在 `_ready()` 里调 `playback.start("idle")`**。
⛔ 只照 3.x 时代的口径设 `active = true` ——
4.x 起 `AnimationMixer.active` 默认已是 **`true`**，
官方教程给出的启用条件是 *"Make sure to either call start() or connect a node to Start."*
⛔ 这会让"配置全对但没输出"被反复归因为"active 忘了设"，
于是加了一行本来就为真的代码，⛔ 真正的成因（没调 `start()`）被永久掩盖。

ⓘ 保留 `tree.active = true` 本身无害，
⛔ 但**不能把它当成排查结论** —— 它是默认状态，不是开关。

【产出】启用路径的唯一口径（Start 节点 或 `start()`，二选一并写清）

【判据】新建最简场景能播；⛔ 去掉 `active` 那行仍能播（证明成因不在这）。

【审】`audit/godot/animation-advanced.md#14`、`audit/godot/animation-advanced.md#1`

### Step 3　三个覆盖默认值逐条确认　`[animation-advanced/01#S3]`

【读】`howto/godot/animation-advanced.md#8. 4.x 的三个覆盖默认值`

【做】
逐条写下取值：`callback_mode_discrete`（AnimationTree 覆盖为 `2`）、
`deterministic`（覆盖为 `true`）、`active`（继承，默认 `true`）。
⛔ 跳过这一步 —— 这三条在属性面板上显示的都是**引擎给的合法值**，
于是"混合结果不对"会被一路查向动画资源与骨骼命名，
⛔ 而资源与骨骼从来都是对的。

ⓘ 这三条的共同形态值得单独记：
**属性面板上的值完全正常，而结果不对，且不报错** ——
这类问题只能靠"先列出被覆盖的默认值"来对冲，靠读面板永远看不出来。

【产出】三行取值表 + 每条"如果不动它，症状是什么"

【判据】能说出每条保持默认时的具体症状；⛔ 没有"应该没事吧"这种结论。

【审】`audit/godot/animation-advanced.md#16`、`audit/godot/animation-advanced.md#18`、`audit/godot/animation-advanced.md#14`

### Step 4　离散轨道按类型决定 callback_mode_discrete　`[animation-advanced/01#S4]`

【读】`howto/godot/animation-advanced.md#⛔ Discrete 轨道在 AnimationTree 里会被强制连续`

【做】
列出所有 `UPDATE_DISCRETE` 轨道（表情 `texture_offset`、开关、整数索引…），
若有，把 `callback_mode_discrete` 设为 `ANIMATION_CALLBACK_MODE_DISCRETE_DOMINANT`。
⛔ 不列 —— AnimationTree 把 Discrete **强制当连续值插值**（官方默认行为），
表现为**表情在混合时滑过去、开关出现中间态**，
⛔ 而轨道属性面板上明明写着 Discrete，排查被引向"是不是该写代码强制赋值"。

ⓘ 官方同时给了另一半口径：
`TYPE_BOOL` 与 `TYPE_INT` 在混合**期间**按 float 处理、取回时才取整 ——
所以"混合过程中的中间态"是设计如此，⛔ 不是 bug，要看的是取回后的值。

【产出】离散轨道清单 + `callback_mode_discrete` 的取值决定

【判据】混合到一半时，离散轨道在画面上**不出现中间态**。

【审】`audit/godot/animation-advanced.md#17`、`audit/godot/animation-advanced.md#16`

### Step 5　RESET 动画与确定性初值　`[animation-advanced/01#S5]`

【读】`howto/godot/animation-advanced.md#⛔ deterministic 为 true 让 Add 类节点效果减半`

【做】
确认 `RESET` 动画存在，并写下"总混合量为 0 时结果等于 RESET"这条口径。
⛔ 没有 RESET —— `deterministic = true` 下总权重为 0 时**没有初值可累加**，
表现为"某些状态组合下角色摆出奇怪姿势"，
⛔ 而这个姿势既不来自任何一条动画，也不报错，排查时无法归因。

ⓘ 反向的一条同样要写：
⛔ 不要因为"Add 类节点效果减半"就把 `deterministic` 一律关掉 ——
关掉后总权重恒定 1.0 且缺轨道的动画不补初值，
⛔ 换来的是"混合不再可复现"，而这正是验收最依赖的性质。

【产出】RESET 动画清单 + `deterministic` 的取舍记录（含用了哪些 Add 类节点）

【判据】任意状态组合下都有确定初值；⛔ 没有"姿势凭空出现"。

【审】`audit/godot/animation-advanced.md#36`、`audit/godot/animation-advanced.md#19`、`audit/godot/animation-advanced.md#35`

## 3. 参考实现
```gdscript
# ⓘ 承接 Step 1–5：tree 为 AnimationTree，playback 为状态机 playback
extends CharacterBody3D

@onready var tree: AnimationTree = $AnimationTree
@onready var playback: AnimationNodeStateMachinePlayback = tree["parameters/playback"]

const STATE_IDLE := "idle"

func _ready() -> void:
    # ⓘ 4.x 默认 active 已为 true；这里是显式启用路径
    tree.callback_mode_discrete = AnimationMixer.ANIMATION_CALLBACK_MODE_DISCRETE_DOMINANT
    playback.start(STATE_IDLE)
```

## 5. 常见返工
| 症状 | 原因 | 回到 |
|---|---|---|
| 位移翻倍 / 原地抖动 | 位移被两处同时产出 | S1 |
| 配置全对但没输出 | 归因成 active，实际没调 start() | S2 |
| 混合结果说不清哪来的 | 没列覆盖默认值 | S3 |
| 表情滑动、开关有中间态 | Discrete 被强制连续 | S4 |
| 某些组合下姿势凭空出现 | 无 RESET 初值 | S5 |
