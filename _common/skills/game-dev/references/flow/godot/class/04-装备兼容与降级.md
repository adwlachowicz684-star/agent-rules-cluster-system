# 04 装备兼容与降级（转职域）

> **前置**：`03-转职事务.md` 已完成（试算阶段已存在）
> **本步交付**：转职后**不会瞬间裸装**，且失效清单在转职前就可见
> **对应**：做法 `howto/godot/class-awaken.md#3. 转职后的装备兼容：最伤玩家的一环`
> 　　　审核 `audit/godot/class-awaken.md#8`

## 0. 交付物定义

⚠ **这是转职系统最高频的严重体验事故**：不崩溃、不报错，
只是玩家转完职发现**战斗力断崖式下跌**因为没有装备能穿了。

⛔ 不要"静默卸下"——玩家看到装备栏空了却不知道为什么，
会认为是 bug 或丢装备，直接转成投诉和工单。

做完这一步，应该能**当场演示**：

1. 打开转职预览 → **列出哪些装备会失效**（不是转完才发现）
2. 转职完成 → 没有一件装备"静默消失"
3. ⚠ 采用降级方案时，降级后属性**不会出现负值**
4. 采用过渡装方案时，赠品**不会绕过经济系统**（有来源记录）
5. 兼容判定只看 `equip_types`，**不依赖渲染层**

**产出物**（下游按名字对接）：

```text
_simulate() 返回的变更清单里含：
  incompatible_equip: [{instance_id, 处理: 保留/降级/替换}]
```

## 2. 工序

### Step 1　⚠ 三选一并写进文档　`[class/04#S1]`

【读】`howto/godot/class-awaken.md#3. 转职后的装备兼容：最伤玩家的一环`

【做】明确保留 / 降级 / 过渡装中的**哪一种**，写进域文档。

| 方案 | 代价 |
|---|---|
| 装备通用（不绑职业） | 职业差异感弱 |
| 转职保留（降级） | 要写降级规则 |
| 提供过渡装 | 经济系统被绕过 |

⛔ 不选就默认成了"静默卸下"——因为没写规则的代码就是什么都不做。

【产出】方案选择 + 书面记录

【判据】⚠ 新人不看代码、只看文档，**能说出是哪种方案**

【审】`audit/godot/class-awaken.md#8`

### Step 2　⛔ 兼容判定必须在试算阶段跑完　`[class/04#S2]`

【读】`howto/godot/class-awaken.md#3. 转职后的装备兼容：最伤玩家的一环`

【做】把兼容检查放进 `_simulate()`，产出失效清单。

⛔ 放到穿戴时才判，那时玩家已经转完了——
**一切都晚了**，只能事后补偿。

【产出】`_simulate()` 返回 `incompatible_equip` 清单

【判据】⚠ 不执行转职，仅调用 `_simulate()`，**就能拿到完整失效清单**

【审】`audit/godot/class-awaken.md#9`

### Step 3　⚠ 判定只看 equip_types　`[class/04#S3]`

【读】`howto/godot/class-awaken.md#3. 转职后的装备兼容：最伤玩家的一环`

【做】判定依据是 `ClassTemplate.equip_types` 与装备类型的交集。

⛔ 不要在渲染/穿戴时才判，也不要依赖 UI 的状态。
⚠ 依赖 UI 会导致"后台批量转职"（如活动统一转职）时判定被跳过。

【产出】纯数据判定函数，不引用任何节点

【判据】⚠ 在无场景的纯单元测试里**能跑通判定**

【审】`audit/godot/class-awaken.md#9`

### Step 4　⚠ 降级不能产生负属性　`[class/04#S4]`

【读】`howto/godot/class-awaken.md#3. 转职后的装备兼容：最伤玩家的一环`

【做】降级规则要**钳制下界**。

⛔ 只写"属性 ×0.5"的话，某些词条（如减益抗性）会出现负值或反效果，
表现为"穿了装备反而更弱"。

【产出】降级函数 + 下界钳制

【判据】⚠ 遍历全部装备类型，降级后**无一项属性为负**

【审】`audit/godot/class-awaken.md#8`

### Step 5　⛔ 绝不静默卸下　`[class/04#S5]`

【读】`howto/godot/class-awaken.md#3. 转职后的装备兼容：最伤玩家的一环`

【做】失效装备要么保留（降级）、要么换成过渡装，
⛔ **绝不能从背包里消失**。

⚠ 即便保留后穿不上，也要**留在背包里**并标注原因
——玩家至少能看到东西还在，知道去换装备。

【产出】失效装备的去向明确（保留 / 替换），⛔ 无删除路径

【判据】⚠ 转职前后背包物品总数**不减少**

【审】`audit/godot/class-awaken.md#8`

### Step 6　⚠ 过渡装要有来源记录　`[class/04#S6]`

【读】`howto/godot/class-awaken.md#3. 转职后的装备兼容：最伤玩家的一环`

【做】若采用过渡装，赠品必须记录来源（`source: class_change_reward`）。

⛔ 无来源记录的话，分解/交易/掉落统计会把它算成正常产出，
长期会**污染经济系统数据**（与 `economy.md` 防通胀边界相关）。

【产出】赠品带来源标记

【判据】⚠ 经济系统的产出统计里能**单独筛出**这批赠品

【审】`audit/godot/class-awaken.md#8`

## 5. 常见返工

**① 没选方案就开工。** 默认变成静默卸下。

**② 兼容判定写在穿戴时。** 转完才发现，只能事后补偿。

**③ 降级没钳下界。** 穿了装备反而更弱。

**④ 过渡装无来源。** 污染经济统计。
