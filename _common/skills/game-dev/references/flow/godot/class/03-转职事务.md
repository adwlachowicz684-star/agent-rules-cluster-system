> **前置**：`02-模板与状态实例.md` 已完成

> 　　　审核 `audit/godot/class-awaken.md#5`

## 0. 交付物定义

⚠ **这是全域唯一有外部副作用的一步**，也是唯一会**丢玩家资产**的一步。

⛔ 两个直觉顺序都会丢东西：

| 顺序 | 失败时的后果 |
|---|---|
| 先扣消耗 → 再转职 | 扣了没转成，**玩家资产凭空消失** |
| 先转职 → 再扣消耗 | 转了没扣成，**白嫖**（且难以追回） |

做完这一步，应该能**当场演示**：

1. 条件不满足 → 点不动，**且消耗未被扣**
2. 消耗不足 → 明确提示，**且职业未变**
3. ⚠ 人为让"提交"失败（如注入异常）→ **消耗被完整退回**
4. 正常路径 → 转职成功，消耗正确扣除，无重复扣除
5. 并发连点两次 → **只扣一次、只转一次**

**产出物**（下游按名字对接）：

```text
try_change_class(p, target_id) -> {ok, reason?, preview?}
  ├─ _meets_requirement()  # 纯判断，无副作用
  ├─ _simulate()           # 纯函数，返回变更清单（预览与提交共用）
  ├─ _begin_cost() / _rollback_cost() / _commit_cost()
  └─ _apply()              # 唯一写 ClassState 的地方
```

## 2. 工序

### Step 1　⛔ 顺序写死：试算 → 扣费 → 提交 → 回滚　`[class/03#S1]`

【读】`howto/godot/class-awaken.md#2. 转职是事务：三个动作的顺序不能错`

【做】四段严格顺序，**不可调换**：

```gdscript
if not _meets_requirement(p, target_id): return {"ok": false, ...}
var preview = _simulate(p, target_id)      # ① 试算：零副作用
if not _cost_affordable(p, target_id): return {"ok": false, ...}
var tx = _begin_cost(p, target_id)         # ② 扣费：唯一外部副作用
var before = p.class_state.duplicate(true)
if not _apply(p, preview):                 # ③ 提交
    _rollback_cost(tx); p.class_state = before   # ④ 回滚
    return {"ok": false, ...}
_commit_cost(tx)
return {"ok": true, "preview": preview}
```

ⓘ 试算必须**零副作用**——它还要被预览复用（见 06），
有副作用的话"打开预览界面"就会扣东西。

【产出】`try_change_class()` 骨架，四段顺序固定

【判据】⚠ 注入异常让 `\_apply` 失败，消耗**完整退回**且 `class_state` 与调用前逐字段相同

【审】`audit/godot/class-awaken.md#5` `audit/godot/class-awaken.md#6`

### Step 2　⚠ 预览与提交共用同一函数　`[class/03#S2]`

【读】`howto/godot/class-awaken.md#2. 转职是事务：三个动作的顺序不能错`

【做】`_simulate()` 是纯函数，预览和提交**都调它**，提交只多一步写回。

⛔ 预览算一遍、提交再算一遍 → 两边漂移，
表现为"预览说能穿的装备，转完穿不上"。

【产出】`_simulate()` 纯函数，无写入、无随机

【判据】⚠ 连续调用两次 `_simulate()`，**返回值完全相等**（可序列化比对）

【审】`audit/godot/class-awaken.md#7`

### Step 3　⚠ 提交失败要能整体回滚　`[class/03#S3]`

【读】`howto/godot/class-awaken.md#2. 转职是事务：三个动作的顺序不能错`

【做】`before = p.class_state.duplicate(true)` 在提交**之前**取。

⛔ 用 `duplicate()`（浅拷贝）会让子资源共享——
回滚时改的其实是同一份，等于没回滚。
ⓘ 与 `datatable.md` 的 `duplicate(true)` 注意事项同源。

【产出】回滚路径，且用深拷贝

【判据】⚠ 回滚后 `class_state` 与 `before` **逐字段相等**（不是"看起来一样"）

【审】`audit/godot/class-awaken.md#5`

### Step 4　⚠ 不可逆消耗单独标记　`[class/03#S4]`

【读】`howto/godot/class-awaken.md#6. 不可逆性与后悔机制`

【做】区分可逆消耗（货币/道具）与不可逆消耗（任务完成标记、一次性剧情）。

⛔ 不可逆消耗**不能被"退回"**。若转职失败却把任务标记重置了，
玩家会卡在"任务已完成但职业没转成"的状态，**无法重试**。

ⓘ 正确做法：不可逆消耗**放在最后提交**，且失败时不重置。

【产出】消耗类型表，标明哪些可逆

【判据】⚠ 提交失败后重试，**条件仍判定为满足**

【审】`audit/godot/class-awaken.md#6`

### Step 5　⚠ 防连点与并发　`[class/03#S5]`

【读】`howto/godot/class-awaken.md#8. 服务端权威`

【做】加请求序号或状态锁，同一次转职未完成前拒绝新请求。

⛔ 没有锁的话连点两次会**扣两次、转两次**（第二次可能转到后继职业），
表现为"点一下跳了两级，钱扣了双份"。

【产出】`_pending` 标记或序号校验

【判据】⚠ 100ms 内连发 3 次请求，**只成功 1 次、只扣 1 次**

【审】`audit/godot/class-awaken.md#20`

### Step 6　⚠ 转职后立刻让面板缓存失效　`[class/03#S6]`

【读】`howto/godot/class-awaken.md#4. 属性重算：职业成长系数变了`

【做】提交成功**立即**调用属性重算并广播变更。

⛔ 只改职业不刷缓存，UI 显示的还是旧职业面板，
玩家会以为没转成——然后**再点一次**（见 Step 5 的连点问题）。

【产出】提交成功后的缓存失效调用

【判据】⚠ 转职成功后不切场景，**面板数字当场变化**

【审】`audit/godot/class-awaken.md#11`

## 5. 常见返工

**① 先扣后转。** 网络异常时"钱没了职业没换"，是最严重的投诉来源。

**② 回滚用浅拷贝。** 子资源共享，回滚等于没回滚。

**③ 忘了刷缓存。** 玩家以为没转成 → 再点 → 连点扣两次。

**④ 预览有副作用。** 打开界面就扣东西。
