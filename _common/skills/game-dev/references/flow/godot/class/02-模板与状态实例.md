# 02 职业模板与状态实例（转职域）

> **前置**：`01-职业模型定性.md` 已完成（已定性、职业链无环）

> **对应**：做法 `howto/godot/class-awaken.md#1. 职业是模板，玩家职业状态是实例`
> 　　　审核 `audit/godot/class-awaken.md#2`

## 0. 交付物定义

⚠ 与 `economy.md` 的 `EquipmentBase / EquipmentInstance` **同构**。
⛔ 不要另发明一套——两套并存的话，做"装备与职业联动"时要写两份适配。

做完这一步，应该能**当场演示**：

1. 配表改一个职业的成长系数，**所有该职业玩家**的面板随之变化
2. 两个玩家同职业，各自的等级/经验**互不影响**
3. `ClassTemplate` 改字段后**旧存档仍能读**（存的是 ID）
4. ⚠ `history` 只增不删

**产出物**（下游按名字对接）：

```text
ClassTemplate: class_id / display_name / prev_class / next_classes
               growth(每级增量) / skill_ids / equip_types / awake_only
ClassState:    class_id / level / exp / awake_level / history[]
```

## 2. 工序

### Step 1　⚠ 模板与实例分离　`[class/02#S1]`

【读】`howto/godot/class-awaken.md#1. 职业是模板，玩家职业状态是实例`

【做】`ClassTemplate extends Resource`（配表导入，运行时只读），
`ClassState extends Resource`（进存档，可写）。

⛔ **绝不把等级/经验写进模板。** 模板是所有玩家共享的 Resource，
写进去就是一个玩家升级、全服同职业一起升级。

【产出】两个 Resource 类，职责不重叠

【判据】⚠ 两个玩家实例同职业，改其中一个的 `level`，另一个**不变**

【审】`audit/godot/class-awaken.md#2`

### Step 2　⚠ 成长系数存每级增量　`[class/02#S2]`

【读】`howto/godot/class-awaken.md#1. 职业是模板，玩家职业状态是实例`

【做】`growth` 存**每级加多少**，不存满级终值。

⛔ 存终值的话，改等级上限就要改所有职业的整张表，
而且**看不出中间等级怎么长**——调平衡时无从下手。

【产出】`growth: Dictionary`，值为每级增量

【判据】⚠ 把等级上限从 60 改成 80，配表**一行都不用改**

【审】`audit/godot/class-awaken.md#4`

### Step 3　⚠ history 只增不删　`[class/02#S3]`

【读】`howto/godot/class-awaken.md#1. 职业是模板，玩家职业状态是实例`

【做】`ClassState.history: Array[StringName]` 记录转职经过。

ⓘ 它是排查"这个玩家为什么有这个技能"的**唯一依据**。
⛔ 删了之后客服面对申诉只能靠猜。

ⓘ 只增不删还有一个好处：**撤销转职靠快照而不是反向转职**时，
`history` 不会被污染（见 06）。

【产出】`history` 字段，且没有任何删除它的代码路径

【判据】⚠ 全项目搜索对 `history` 的 `erase/remove/clear`，**结果为 0**

【审】`audit/godot/class-awaken.md#3`

### Step 4　⛔ 存 ID 不存引用　`[class/02#S4]`

【读】`howto/godot/class-awaken.md#7. 存档与迁移`

【做】`ClassState.class_id` 存 `StringName`。

⛔ 存 Resource 引用的话，改配表时旧存档会指向已删除的职业——
表现为"读档后职业变成空"，且**没有报错**。

ⓘ 与 `datatable.md` 的"外键存 ID 而非 Resource 引用"同源。

【产出】`class_id: StringName`（不是 `ClassTemplate`）

【判据】⚠ 删除配表里某个职业后读旧档，得到**明确报错**而非空对象

【审】`audit/godot/class-awaken.md#18` `audit/godot/class-awaken.md#19`

### Step 5　⚠ 面板属性走统一入口　`[class/02#S5]`

【读】`howto/godot/class-awaken.md#4. 属性重算：职业成长系数变了`

【做】属性计算**只有一个入口**，职业成长是其中一环：

```text
基础模板 → 等级缩放 → 职业成长 → 品阶 → 词条 → 强化 → 镶嵌 → 外部 buff
```

⛔ 转职时直接改 `attack` 这类最终值 → 下次重算被覆盖，
表现为"转职后攻击力变高了，打一场又变回去了"。

【产出】属性计算器单一入口，职业成长作为一环插在固定位置

【判据】⚠ 改职业后调用一次重算，结果**与直接改最终值的结果一致**

【审】`audit/godot/class-awaken.md#10` `audit/godot/class-awaken.md#11`

## 5. 常见返工

**① 把等级写进模板。** 一个玩家升级、全服同职业一起升级。

**② 存满级终值。** 改等级上限要重排整张表。

**③ 属性计算有两个入口。** 转职改一处、换装备改另一处，
两边漂移表现为"面板数字忽高忽低"。
