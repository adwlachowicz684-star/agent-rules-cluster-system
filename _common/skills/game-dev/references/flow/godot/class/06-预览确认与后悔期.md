# 06 预览、确认、后悔期（转职域）

> **前置**：`03` 事务 / `04` 装备清单 / `05` 返还数量 均已完成
> **本步交付**：玩家**在转之前就知道代价**，且转错了能回头
> **对应**：做法 `howto/godot/class-awaken.md#6. 不可逆性与后悔机制`
> 　　　审核 `audit/godot/class-awaken.md#15`

## 0. 交付物定义

⚠ **"转职不可逆"本身不是问题，"不可逆且没有确认"才是。**

⛔ 没有预览的转职，"转完发现装备全穿不上"会变成**差评和客服工单**，
而不是一个能被发现的 bug——因为它不崩溃、不报错。

做完这一步，应该能**当场演示**：

1. 点转职 → 先看到**预览**：技能变什么样、哪些装备失效、返还多少点
2. 预览 → **显式确认**，确认文案包含关键代价
3. 转错 → 后悔期内**撤销一次**，且 `history` 未被污染
4. ⚠ 撤销后**能再次转职**（不会被卡住）
5. 后悔期快照**只存最近一次**（存档不无限增长）

**产出物**（下游按名字对接）：

```text
preview = _simulate() 的返回值（04/05 提供的清单直接展示）
confirm_dialog: 含失效装备数、返还点数
undo_snapshot: ClassState + 消耗记录，只存 1 份
```

## 2. 工序

### Step 1　⚠ 预览直接展示 _simulate 的输出　`[class/06#S1]`

【读】`howto/godot/class-awaken.md#2. 转职是事务：三个动作的顺序不能错`

【做】UI 渲染 `_simulate()` 的返回，**不再自己算一遍**。

⛔ UI 自己算就是第三份逻辑（试算 / 提交 / 展示），
三份漂移时表现为"预览能穿的装备转完穿不上"。

【产出】预览界面数据源 = `_simulate()`

【判据】⚠ 预览展示的失效数 与 实际转职后的失效数**逐项相等**

【审】`audit/godot/class-awaken.md#7`

### Step 2　⛔ 确认文案必须含关键代价　`[class/06#S2]`

【读】`howto/godot/class-awaken.md#6. 不可逆性与后悔机制`

【做】二次确认的文案里写清：哪些装备失效、技能是否重置、返还多少。

⛔ 只写"确定要转职吗？"等于没确认。
⚠ 玩家点确认时**并不知道自己放弃了什么**。

【产出】确认弹窗含具体代价数字

【判据】⚠ 不打开预览、只看确认弹窗，**也能知道代价**

【审】`audit/godot/class-awaken.md#15`

### Step 3　⚠ 后悔期用快照而非反向转职　`[class/06#S3]`

【读】`howto/godot/class-awaken.md#6. 不可逆性与后悔机制`

【做】转职前保存 `ClassState` 快照，撤销时**直接恢复**。

⛔ 用"反向再转一次"实现撤销会**污染 `history`**，
而且可能**不满足原职业的前置条件**（如要求某任务已完成但标记已清）
——表现为"撤销失败，玩家被卡在新职业"。

【产出】`undo_snapshot`（深拷贝）+ 恢复路径

【判据】⚠ 撤销后 `history` 长度**比撤销前少 0**（未被追加）

【审】`audit/godot/class-awaken.md#16`

### Step 4　⚠ 快照只存最近一次　`[class/06#S4]`

【读】`howto/godot/class-awaken.md#6. 不可逆性与后悔机制`

【做】`undo_snapshot` 是**单槽**，新转职覆盖旧的。

⛔ 存多份的话存档随转职次数**线性增长**，
而老快照里的旧职业数据其实已经不可用了。

【产出】单槽快照

【判据】⚠ 连续转职 10 次后，存档大小**基本不变**

【审】`audit/godot/class-awaken.md#17`

### Step 5　⚠ 撤销后仍可再次转职　`[class/06#S5]`

【读】`howto/godot/class-awaken.md#6. 不可逆性与后悔机制`

【做】撤销恢复状态的同时，**恢复消耗的可用性判定**。

⛔ 只恢复职业不恢复消耗条件的话，玩家会卡在
"职业退回去了但再也转不了"的状态。

【产出】撤销路径同时恢复消耗相关状态

【判据】⚠ 撤销后立刻再次转职，**条件判定与首次完全相同**

【审】`audit/godot/class-awaken.md#16`

### Step 6　⚠ 预览与服务端结果不一致时以服务端为准　`[class/06#S6]`

【读】`howto/godot/class-awaken.md#8. 服务端权威`

【做】联网项目里，客户端可本地算预览，但**提交结果以服务端为准**；
不一致时提示玩家，⛔ 不静默采用客户端结果。

【产出】结果比对与提示

【判据】⚠ 人为让服务端返回不同结果，玩家**看到提示**而非静默接受

【审】`audit/godot/class-awaken.md#21`

## 5. 常见返工

**① UI 自己算预览。** 三份逻辑漂移。

**② 确认弹窗无代价信息。** 等于没确认。

**③ 用反向转职实现撤销。** 污染 history，且可能卡住。

**④ 快照多槽。** 存档随转职次数线性增长。
