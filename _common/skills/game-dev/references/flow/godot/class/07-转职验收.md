## 0. 交付物定义

⚠ **各功能点自己的验收不能替代域级验收。**
部件全合格、拼起来不能用，是跨域开发的典型失败——
转职尤其如此，它横跨 economy / build-affix / save-migration / netsync 四个域。

做完这一步，应该能**当场演示**并**签核**：

1. 01 定义的三个证明场景全部成立
2. ⚠ **失败路径实测**：扣费后提交失败，资产完整退回
3. ⚠ **资产保全实测**：全程背包物品总数不减少
4. 长时间稳定性：连续转职 / 撤销 20 次无异常
5. ⚠ **接缝复查**：与 economy / save / netsync 的六条契约全对上

### Step 2　⚠ 失败路径实测（最重要的一步）　`[class/07#S2]`

【读】`howto/godot/class-awaken.md#2. 转职是事务：三个动作的顺序不能错`

【做】注入异常让提交失败，逐项确认：
- 消耗**完整退回**
- `class_state` 与调用前**逐字段相等**
- 不可逆消耗**未被重置**（可重试）
- 背包物品总数**未减少**

⛔ 只测正常路径等于没测。⚠ 正常路径人人都会测，
而**出事的都是失败路径**——且它不崩溃、不报错，只是东西没了。

【产出】失败路径实测表（4 项）

【判据】⚠ 四项全部成立，且有日志可查

【审】`audit/godot/class-awaken.md#5` `audit/godot/class-awaken.md#6`

### Step 3　⚠ 资产保全实测　`[class/07#S3]`

【读】`howto/godot/class-awaken.md#3. 转职后的装备兼容：最伤玩家的一环`

【做】全程记录**背包物品总数**与**总点数**：

```text
转职前 → 预览 → 确认 → 提交 → 撤销 → 再转职
每个节点记录一次，总数只允许因"返还"增加，不允许减少
```

⛔ 任何一步出现减少 = 有资产静默消失。

【产出】资产流水表

【判据】⚠ 全流程物品总数与总点数**不减少**

【审】`audit/godot/class-awaken.md#8`

### Step 4　⚠ 连续操作稳定性　`[class/07#S4]`

【读】`howto/godot/class-awaken.md#7. 存档与迁移`

【做】连续"转职 → 撤销"20 次，记录存档大小与对象计数。

⛔ 只转一次看不出问题：
快照多槽、history 无限追加、对象泄漏都是**累积型**的。

【产出】20 次循环后的存档大小 / 对象计数曲线

【判据】⚠ 存档大小基本不变；对象计数**不单调增长**

【审】`audit/godot/class-awaken.md#17`
