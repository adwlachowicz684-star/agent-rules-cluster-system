> 　　　审核 `audit/godot/class-awaken.md#1`

## 0. 交付物定义

⚠ **这一步不写业务代码，但它是全域的地基。**
⛔ 跳过它直接建数据结构，做到一半会发现结构撑不住——
那时存档格式、UI、技能系统全都按错误模型写完了，改动面是**全系统级**的。

做完这一步，应该能**当场回答三句话**：

1. 是 **转职**（替换）/ **觉醒**（追加）/ **多职业**（并存）中的哪一个
2. ⛔ 明确排除的另外两个，以及**业务需求为什么不支持它们**
3. 转职后玩家还能不能变回原职业、原职业的技能还在不在

**产出物**（下游按名字对接）：

```text
ClassTemplate.class_id / prev_class / next_classes   # 模板层（配表）
ClassState.class_id / level / awake_level / history  # 实例层（存档）
```

⚠ 两套都要有。⛔ 只做一套 = 默认选了"单职业且不可回溯"。

## 2. 工序

### Step 1　⚠ 用一句判据定性　`[class/01#S1]`

【读】`howto/godot/class-awaken.md#0. 先分清三件事：转职、觉醒、多职业`

【做】回答一个问题：**转职后玩家还能不能变回原职业、原职业的技能还在不在**。
- 不能，且原职业消失 → **转职**
- 能，且是被增强 → **觉醒**
- 两套独立并存 → **多职业**

ⓘ 判据不是"游戏里叫什么名字"。⚠ 很多叫"转职"的系统实际是觉醒
（原职业保留并被增强），叫"觉醒"的也可能是转职（换了一套技能组）。

【产出】一句话定性 + 一条原始需求依据

【判据】⚠ 能指出**需求文档里哪一条**支持这个判断，⛔ 不是"我觉得"

【审】`audit/godot/class-awaken.md#1`

### Step 2　⛔ 显式排除另外两个　`[class/01#S2]`

【读】`howto/godot/class-awaken.md#0. 先分清三件事：转职、觉醒、多职业`

【做】把排除的两种**写下来，附业务需求理由**。

ⓘ 这不是走形式。⚠ 三个月后有人提"能不能加个双职业"时，这条记录
是唯一能说明"当时的结构为什么不支持"的东西。

【产出】两条"本次不做 X，因为 Y"

【判据】每条都指向**具体业务需求**，⛔ 不是"太复杂""以后再说"

【审】`audit/godot/class-awaken.md#1` `audit/godot/class-awaken.md#22`

### Step 3　⚠ 画出职业链　`[class/01#S3]`

【读】`howto/godot/class-awaken.md#0. 先分清三件事：转职、觉醒、多职业`

【做】列出全部职业、前置（`prev_class`）、后继（`next_classes`）。

⚠ **链必须无环。** ⛔ 有环的话"转一圈回来"会让 `history` 无限增长，
且等级/技能状态无法判定该用哪一份。

ⓘ 分支是允许的（战士 → 骑士 / 狂战士），但**回溯边不允许**。

【产出】职业链图（文本即可）

【判据】⚠ 从任一节点出发**不可能回到自己**；每个职业的前置至多一个

【审】`audit/godot/class-awaken.md#1`

### Step 4　确定觉醒层数与上限　`[class/01#S4]`

【读】`howto/godot/class-awaken.md#0. 先分清三件事：转职、觉醒、多职业`

【做】若定性为觉醒，定 `awake_level` 的取值与上限。

⚠ **上限必须写死在配表里**，⛔ 不能只在 UI 里不显示入口。
只关 UI 的话，服务端仍会接受超限请求——表现为"有人觉醒了 99 层"。

【产出】`awake_level` 范围（如 0–3）

【判据】⚠ 直接调服务端接口提交超限层数，被拒绝且有日志

【审】`audit/godot/class-awaken.md#22`

### Step 5　⚠ 写下验证这三者的最小场景　`[class/01#S5]`

【读】`howto/godot/class-awaken.md#0. 先分清三件事：转职、觉醒、多职业`

【做】写三个可演示的场景，分别证明"是这一个而不是另外两个"：

| 定性为 | 证明场景 |
|---|---|
| 转职 | 转完后**旧职业技能消失**，且无法变回 |
| 觉醒 | 转完后**旧职业技能仍在**且被增强 |
| 多职业 | **两套技能同时可用**，可切换 |

ⓘ 这三个场景就是 07 验收的输入。⛔ 现在不定，到 07 时只能凭感觉。

【产出】三个可演示场景（写进 00 总览第 0 节的验收标准）

【判据】⚠ 每个场景都能在 10 分钟内手工跑完

【审】`audit/godot/class-awaken.md#1`

## 5. 常见返工

**① 定性时看的是名词而不是行为。**
"觉醒"这个名字的系统实际是替换型转职 → 做到 05 才发现旧技能要保留。

**② 职业链画成了网。**
分支可以，回溯边不可以。⛔ 有环时 `history` 无限增长。

**③ 觉醒上限只在 UI 关了入口。**
服务端仍接受超限请求，表现为"有人觉醒了 99 层"。
