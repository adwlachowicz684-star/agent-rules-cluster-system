# 2D 渲染与屏幕特效（排序 / 贴图 / 视差 / 光照 / 屏幕特效 / 打击反馈）—— 域流程总览

> ⚠ **第 0 步：先定排序与贴图口径。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 俯视角遮挡关系 | 01 → 07 |
| 像素风 / 贴图发糊 | 02 → 07 |
| 视差背景 | 03 → 07 |
| 2D 光照与阴影 | 04 → 07 |
| 屏幕扭曲、溶解、描边 | 05 → 07 |
| 打击感（抖动 / 顿帧） | 06 → 07 |
| 转场 | 05 → 07 |
| 全套 2D 表现 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只要做俯视角，01 不能跳过** ——
排序错了不会报错、不会崩溃，只会"看着不对"，
而这种不对会在美术资源替换、关卡扩建之后**成片地**冒出来，那时结构已定型。

⛔ **06 不能留到最后**：打击反馈是玩家最先感知的部分，
但它依赖 `Engine.time_scale` 的全局副作用，
⛔ 后接意味着它会被塞进已经写好的战斗流程里，恢复路径极容易漏。

ⓘ 若本次只是**"换一张贴图、调个颜色"**，那是资源配置，不套本域。
ⓘ 若只是**排查 2D 掉帧**，先看 `perf` 域定位，确认是绘制/填充率问题再回本域。

ⓘ 分工：
- `howto/godot/2d-rendering.md` 讲**单个要素怎么实现**（Y-Sort、视差、光照、shader、抖动、顿帧）
- 本域讲**这些要素按什么顺序做、怎么保证换分辨率换设备后仍然对**

⛔ 若本域某步需要"某个分辨率下的具体帧耗时"这类细节，
指向 `perf` 域实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 排序与深度地基 | — | 排序父节点结构 + 原点口径 + z_index 约定 |
| 02 | 贴图与像素风一致性 | 01 | 三层过滤口径 + 重新导入 + stretch 模式 |
| 03 | 视差与背景层 | 01, 02 | 层速率表 + 滚动限制余量 + 循环尺寸 |
| 04 | 2D 光照与阴影 | 01, 02 | 光照节点组 + 法线贴图走法 + 遮挡轮廓 |
| 05 | 屏幕特效与着色器 | 01, 02 | 抓屏边界 + 效果清单 + 参数常量化 |
| 06 | 打击反馈：抖动与顿帧 | 01 | trauma 上限口径 + 顿帧恢复路径 |
| 07 | 2D 渲染验收 | 全部 | 多分辨率实测 + 敌意环境实测 |

⚠ **01 必须在美术铺开之前**：那时所有精灵已经按"看着差不多"摆完，
原点口径一改，**每一张**的 offset 都要重算。

⚠ **02 必须在批量导入之后**、但在美术验收之前：
改默认过滤不追溯已导入文件，⛔ 越晚改要重新导入的文件越多。

⚠ **03 的滚动限制要留视口余量** —— 这不是调参，是**成立条件**：
不满足时视差层直接不动，且不报错。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `shaders` 域 着色器系统 | 材质共享、`set_shader_parameter` 命名、渲染后端差异见 `shaders/04`；⛔ 本域不重复定材质口径 |
| `perf` 域 性能分析 | 填充率、绘制调用、真机帧率见 `perf` 域实测；本域只定"必须测"的动作 |
| `ui` 域 UI | UI 内部的层级与锚点走 `ui` 域，⛔ UI 与世界层的 z_index 边界由本域 01 定 |
| `camera` 域 相机 | 相机跟随与限界见 `camera` 域，⛔ 抖动写 `offset` 的职责边界由本域 06 定 |
| `combat` 域 战斗 | 打击感的参数区间见 `combat/05`，⛔ 抖动与顿帧的**实现与恢复**由本域 06 负责 |
| `level` 域 关卡 | 关卡分块与加载见 `level` 域，⛔ 分块后动态实例进排序父节点由本域 01 负责 |
| `mobile` 域 移动端 | 移动端阴影光源数量与像素比见 `mobile` 域，⛔ 本域不另定移动端口径 |
| `platform-export` 域 导出发布 | stretch 模式与窗口缩放的最终表现见 `platform-export` 域 |
| `art-assets` | ⓘ howto 层，暂无 flow 域 —— 美术资源的命名与规格见该篇 |
| `lighting` | ⓘ howto 层，暂无 flow 域 —— 3D 光照与烘焙见该篇 |
