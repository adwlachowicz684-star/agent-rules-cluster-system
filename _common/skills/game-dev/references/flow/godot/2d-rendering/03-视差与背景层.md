# 03 视差与背景层（2D 渲染域）

> **本步交付**：层速率表 + 滚动限制余量 + 循环尺寸
> **对应**：流程 `howto/godot/2d-rendering.md` · 审核 `audit/godot/2d-rendering.md`

## 0. 交付物定义

1. 每层的 `scroll_scale` 已定，⛔ 不是"看着差不多"
2. `limit_begin` / `limit_end` **已按视口尺寸留余量**（这是成立条件，不是调参）
3. 手动滚动一律走 `scroll_offset`
4. `repeat_size` 与贴图尺寸一致
5. 已在不同分辨率与 zoom 下复测

## 1. 前置检查清单

- [ ] 层速率表已写下（每层一个明确数值）
- [ ] 滚动限制的余量已按视口算过，不是照抄关卡边界
- [ ] 代码中没有直接改 `position` / `screen_offset`
- [ ] `repeat_size` 与贴图尺寸逐层核对过
- [ ] 至少两种分辨率下测过

## 2. 工序

### Step 1　层速率表先写，别靠"看着差不多"　`[2d-rendering/03#S1]`

【读】`howto/godot/2d-rendering.md#3. Parallax2D 视差背景`

【做】
给每层写下明确的 `scroll_scale`，远景小、近景大。
⛔ 不设 `scroll_scale` 就期待有景深 —— 全部是默认 `1.0`，
多层**同速**滚动，等于只有一层，表现为"加了三层视差但完全看不出来"。

ⓘ 速率要有间隔：0.1 / 0.3 / 0.6 这种三档能读出层次，
⛔ 0.5 / 0.55 / 0.6 看着是三个数，画面上分辨不出来，等于白做三层。

【产出】层速率表（层名 × scroll_scale × 视觉定位）

【判据】相邻层速率差 ≥ 0.15，且能说出每层代表多远。

【审】`audit/godot/2d-rendering.md#13`

### Step 2　滚动限制必须留视口余量 —— 这是成立条件，不是调参　`[2d-rendering/03#S2]`

【读】`howto/godot/2d-rendering.md#3. Parallax2D 视差背景`

【做】
按官方口径设 `limit_begin` / `limit_end`：
`limit_begin` 要低于 `limit_end` **减去视口尺寸**，`limit_end` 要高于 `limit_begin` **加上视口尺寸**。
⛔ 照着关卡边界原样填（如 `limit_begin=(0,0)`、`limit_end=关卡尺寸`）会**直接不满足条件**。

⛔ 这是本域最硬的一条：不满足时**视差层完全不动**，
而 `scroll_scale`、贴图、子节点、相机全部检查都是对的，
⛔ 于是排查被引向 `scroll_scale` 或相机跟随，不会想到是两个限制值本身不成立。

ⓘ 换分辨率时视口尺寸会变，余量要跟着重算 ——
表现为"开发机上对的，打包到另一种分辨率就不动了"。

【产出】limit 取值（含视口余量的计算式）

【判据】把视口尺寸写进计算式，换分辨率后仍成立。

【审】`audit/godot/2d-rendering.md#20`

### Step 3　手动滚动走 `scroll_offset`，不动 `position` / `screen_offset`　`[2d-rendering/03#S3]`

【读】`howto/godot/2d-rendering.md#3. Parallax2D 视差背景`

【做】
需要脚本驱动滚动时操作 `scroll_offset`。
⛔ 改 `position` —— `follow_viewport=true` 时会被相机逻辑覆盖，
表现为"设了没反应"或"闪一下又回去"。

⛔ 改 `screen_offset` 同样是坑：官方口径明确
*"如果 ignore_camera_scroll 为 false 或者修改了 screen_offset，那么该节点进入场景树后发生的任何位移都会被覆盖"*
—— 即**改了 `screen_offset` 会让之后的位移一并被覆盖**。
⛔ 这条极难联想到：看起来只是在设一个偏移量，实际是把整个节点推入"位移被覆盖"状态。
`scroll_offset` 是官方写明 **不会被覆盖** 的那个字段。

【产出】滚动驱动方式说明（哪个字段、为什么）

【判据】脚本滚动与相机滚动能同时生效且互不打架。

【审】`audit/godot/2d-rendering.md#21`、`audit/godot/2d-rendering.md#14`

### Step 4　`repeat_size` 与贴图尺寸逐层核对　`[2d-rendering/03#S4]`

【读】`howto/godot/2d-rendering.md#3. Parallax2D 视差背景`

【做】
让 `repeat_size` 等于该层贴图的实际尺寸（考虑缩放后的像素尺寸）。
⛔ 不一致 —— 循环处会**跳一下**，
表现为"走一段就抖一下"，⛔ 极易被当成相机抖动或帧率问题去查。

ⓘ `repeat_times` 要在 zoom 缩小时够铺满屏幕：
缩小视野后原本够用的重复次数会不够，边缘露出空白。

【产出】逐层的 repeat_size / repeat_times 核对记录

【判据】连续走两屏无跳变；最小 zoom 下无边缘空白。

【审】`audit/godot/2d-rendering.md#22`

### Step 5　在目标分辨率与 zoom 下复测，不只测开发机　`[2d-rendering/03#S5]`

【读】`howto/godot/2d-rendering.md#3. Parallax2D 视差背景`

【做】
在至少两种分辨率（含最小 zoom）下复跑一遍视差。
⛔ 只在开发机的窗口尺寸下测 —— 视差的效果**依赖视口尺寸**：
限制余量、重复次数、缩放后的覆盖面积全都与它有关。

⛔ 表现为"开发机完美、打包后有一层不动或露边"，
而打包后能改的东西很少，排查成本远高于开发期多测一遍。

【产出】分辨率 × zoom 的复测记录

【判据】最小与最大窗口下，各层均滚动且无边缘空白。

【审】`audit/godot/2d-rendering.md#38`、`audit/godot/2d-rendering.md#12`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：速率表 + 视口余量 + scroll_offset 驱动
const LAYER_SCALES := {
    "sky": 0.1,
    "mountains": 0.3,
    "trees": 0.6,
}   # ⓘ 相邻档差 ≥ 0.15，否则画面上分辨不出层次

func setup(layer: Parallax2D, key: String, viewport_size: Vector2) -> void:
    layer.scroll_scale = Vector2.ONE * LAYER_SCALES[key]
    # ⓘ limit 必须给视口留余量：否则视差层完全不动且不报错
    var margin := viewport_size * 2.0
    layer.limit_begin = -margin
    layer.limit_end = _level_size + margin

# ⓘ 手动滚动只走 scroll_offset：官方写明它不会被覆盖
func scroll_by(layer: Parallax2D, delta: Vector2) -> void:
    layer.scroll_offset += delta
```

```gdscript
# ⓘ repeat 核对：贴图尺寸 × 缩放 = 实际重复步长
func sync_repeat(layer: Parallax2D, tex: Texture2D, scale: Vector2) -> void:
    layer.repeat_size = tex.get_size() * scale
    layer.repeat_times = 4   # ⓘ 最小 zoom 下要够铺满，否则边缘露白
```

- [ ] 层速率表已写下，相邻档差可分辨
- [ ] limit 已按视口留余量，换分辨率仍成立
- [ ] 手动滚动只走 `scroll_offset`
- [ ] `repeat_size` 与贴图尺寸一致，最小 zoom 下无露白
- [ ] 至少两种分辨率复测通过

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 三层视差看不出来 | `scroll_scale` 没设 / 档差太小 | S1 |
| 视差层完全不动 | limit 未留视口余量 | S2 |
| 设了没反应 / 闪一下回去 | 改了 `position` 或 `screen_offset` | S3 |
| 走一段抖一下 | `repeat_size` 与贴图不符 | S4 |
| 打包后有一层不动 | 只测了开发机窗口 | S5 |
