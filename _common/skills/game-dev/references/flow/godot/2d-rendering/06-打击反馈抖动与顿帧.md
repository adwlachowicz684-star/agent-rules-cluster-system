# 06 打击反馈：抖动与顿帧（2D 渲染域）

> **本步交付**：trauma 上限口径 + 顿帧恢复路径
> **对应**：流程 `howto/godot/2d-rendering.md` · 审核 `audit/godot/2d-rendering.md`

## 0. 交付物定义

1. 抖动写 `offset`，跟随写 `position`
2. trauma 有上限与衰减，多处叠加不会失控
3. 顿帧时长已定，且**恢复路径无遗漏**
4. 恢复的是**进入前的值**，不是写死 1.0
5. 抖动幅度按分辨率归一
6. 与暂停、慢动作的共存关系已明确

## 1. 前置检查清单

- [ ] 抖动只写 `offset`，`position` 由相机跟随独占
- [ ] `add_trauma` 有 clamp 上限
- [ ] 顿帧的计时器第四参数 `ignore_time_scale = true`
- [ ] 恢复用的是进入前保存的 `time_scale`
- [ ] 幅度按视口尺寸（或基准分辨率）归一
- [ ] 暂停期间触发顿帧的行为已定义

## 2. 工序

### Step 1　抖动写 `offset`，跟随写 `position`　`[2d-rendering/06#S1]`

【读】`howto/godot/2d-rendering.md#6. 屏幕抖动（Trauma 模型）`

【做】
把抖动输出到相机的 `offset`，跟随逻辑独占 `position`。
⛔ 抖动写 `position` —— 相机跟随每帧都会覆写它，
⛔ 表现为"抖动完全没效果"或"抖动与跟随打架，画面一跳一跳"。

⛔ 这个 bug 的排查很绕：抖动代码明明在跑、数值也在变，
⛔ 只是被另一个系统每帧覆盖掉，而两个系统各自看都完全正确。

【产出】相机职责划分（跟随 → position，抖动 → offset，缩放 → zoom）

【判据】单独触发抖动时，跟随目标不发生位移。

【审】`audit/godot/2d-rendering.md#27`

### Step 2　trauma 要 clamp 上限，多处叠加不能失控　`[2d-rendering/06#S2]`

【读】`howto/godot/2d-rendering.md#6. 屏幕抖动（Trauma 模型）`

【做】
`add_trauma` 里 clamp 到 1.0，并设衰减速率。
⛔ 只累加不设上限 —— 连续命中、群体爆炸时 trauma 冲到远超 1，
抖动幅度跟着爆掉，表现为"屏幕糊成一片看不清"，
⛔ 而这在单发命中的测试里**一次都不会出现**。

ⓘ 衰减与平方映射是关键：直接线性衰减会在末尾"持续高频抖"，
⛔ 而平方让它在小值时快速收敛，观感上差别很大。

【品】`craft/godot/feel-params.md#5. 屏幕震动（Trauma 模型）`

【产出】trauma 上限 + 衰减速率 + 映射方式

【判据】连续触发 10 次后画面仍可辨认。

【审】`audit/godot/2d-rendering.md#26`

### Step 3　顿帧时长定了，但恢复路径才是重点　`[2d-rendering/06#S3]`

【读】`howto/godot/2d-rendering.md#7. 命中停顿（Hitstop）`

【做】
定下顿帧时长，并**先把恢复路径写出来**再写触发。
⛔ 计时器第四参数 `ignore_time_scale` 不是 true ——
`time_scale = 0` 时计时器也停了，游戏**永久卡死**。

⛔ 这是本域唯一能造成"硬死"的坑，
而它的触发条件极其普通：一次命中的顿帧。

ⓘ 另一个同源陷阱：重入。已经在顿帧中时再次触发，
若不加保护，第二次的恢复会把 `time_scale` 提前设回 1，
或者叠加出两个恢复路径互相打架。

【品】`craft/godot/feel-params.md#4. 顿帧（Hitstop / Freeze Frame）`

【产出】顿帧时长 + 恢复函数 + 重入保护

【判据】连续触发 20 次后 `time_scale` 仍为 1。

【审】`audit/godot/2d-rendering.md#17`、`audit/godot/2d-rendering.md#11`

### Step 4　恢复的是进入前的值，不是写死 1.0　`[2d-rendering/06#S4]`

【读】`howto/godot/2d-rendering.md#7. 命中停顿（Hitstop）`

【做】
进入顿帧前保存 `Engine.time_scale`，恢复时写回保存值。
⛔ 恢复写死 `1.0` —— 与慢动作（子弹时间）叠加时，
一次命中会把慢动作的 `time_scale` 直接拉回 1，
⛔ 表现为"命中之后慢动作突然结束"，而慢动作系统自己检查全对。

ⓘ 顿帧是**全局**副作用：Tween、Timer、粒子、动画全部受影响。
只想停部分东西时⛔ 不要用 `time_scale`，改用各节点的 `set_process(false)`。

【产出】time_scale 的保存/恢复封装（唯一入口）

【判据】慢动作中触发顿帧，顿帧后仍是慢动作速率。

【审】`audit/godot/2d-rendering.md#29`

### Step 5　抖动幅度按分辨率归一，别写死像素　`[2d-rendering/06#S5]`

【读】`howto/godot/2d-rendering.md#6. 屏幕抖动（Trauma 模型）`

【做】
把 `max_offset` 定义为视口尺寸的比例（或基准分辨率下的值再按比例换算）。
⛔ 写死像素 —— 在 640×360 上合适的 24 像素，
到了 1920×1080 上几乎看不出来，⛔ 表现为"高分辨率下打击感变弱了"，
而美术会以为是参数没调好。

ⓘ 这与 02 的过滤/stretch 是同一类问题：
**任何写死的像素值都会在换分辨率后失真**。

【产出】幅度换算方式（比例 / 基准分辨率 × 缩放系数）

【判据】两种分辨率下，抖动的视觉幅度观感一致。

【审】`audit/godot/2d-rendering.md#28`

### Step 6　与暂停、慢动作的共存关系要定义　`[2d-rendering/06#S6]`

【读】`howto/godot/2d-rendering.md#7. 命中停顿（Hitstop）`

【做】
明确顿帧期间玩家暂停会发生什么，并写进代码。
⛔ 不定义 —— 暂停时 `time_scale` 与 `paused` 两套机制叠加，
恢复顺序不同会得到不同结果，⛔ 表现为"暂停后恢复，游戏要么卡住要么快进"。

ⓘ 一个可行的口径：**暂停优先**，暂停时先恢复 `time_scale` 再 `paused = true`；
恢复时反向。⛔ 关键是这个顺序只有一处实现，
⛔ 分散在多处就会出现"有时候对有时候不对"。

【产出】暂停 × 顿帧的状态机（进入/退出顺序）

【判据】顿帧中暂停、再恢复，速率正常且无残留。

【审】`audit/godot/2d-rendering.md#29`、`audit/godot/2d-rendering.md#11`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：trauma 上限 + 顿帧恢复 + 幅度归一
# hitstop.gd —— Autoload
extends Node

const HITSTOP_TIME := 0.06
const MAX_TRAUMA := 1.0

var _saved_scale := 1.0
var _stopping := false

func stop(duration: float = HITSTOP_TIME) -> void:
    if _stopping:
        return                       # ⓘ 重入保护：否则两条恢复路径互相打架
    _stopping = true
    _saved_scale = Engine.time_scale # ⓘ 存进入前的值，⛔ 不写死 1.0
    Engine.time_scale = 0.0
    # ⓘ 第四参数 ignore_time_scale=true：否则 time_scale=0 时计时器也停，永久卡死
    await get_tree().create_timer(duration, true, false, true).timeout
    Engine.time_scale = _saved_scale
    _stopping = false
```

```gdscript
# ⓘ 抖动：只写 offset，幅度按视口归一
const SHAKE_RATIO := 0.04          # ⓘ 占视口高度的比例，⛔ 不是固定像素

func _apply_shake(shake: float, viewport_h: float) -> void:
    var amp := viewport_h * SHAKE_RATIO * shake
    offset.x = _noise.get_noise_1d(_t * 100.0) * amp
    offset.y = _noise.get_noise_1d(_t * 100.0 + 1000.0) * amp
```

```gdscript
# ⓘ trauma 累加必须 clamp，否则连续命中后画面糊成一片
# ⓘ MAX_TRAUMA：承接本步参考实现第一段 hitstop.gd 中的声明
func add_trauma(amount: float) -> void:
    _trauma = clampf(_trauma + amount, 0.0, MAX_TRAUMA)
```

## 4. 验收清单

- [ ] 抖动只写 `offset`，跟随不受影响
- [ ] 连续 10 次触发后画面仍可辨认
- [ ] 连续 20 次顿帧后 `time_scale` 仍为 1
- [ ] 慢动作中触发顿帧后仍是慢动作
- [ ] 两种分辨率下抖动幅度观感一致
- [ ] 顿帧中暂停再恢复无残留

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 抖动完全没效果 | 写 `position` 被跟随覆盖 | S1 |
| 连续命中后屏幕糊成一片 | trauma 无上限 | S2 |
| 一次命中后游戏永久卡死 | `ignore_time_scale` 未开 | S3 |
| 命中后慢动作突然结束 | 恢复写死 1.0 | S4 |
| 高分辨率下打击感变弱 | 幅度写死像素 | S5 |
| 暂停恢复后卡住或快进 | 未定义共存顺序 | S6 |
