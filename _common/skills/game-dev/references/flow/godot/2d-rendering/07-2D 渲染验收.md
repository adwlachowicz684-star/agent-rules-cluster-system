# 07 2D 渲染验收（2D 渲染域）

> **本步交付**：多分辨率实测通过 + 敌意环境实测通过
> **对应**：流程 `howto/godot/2d-rendering.md` · 审核 `audit/godot/2d-rendering.md`

## 0. 交付物定义

1. 已在至少两种分辨率下截图比对，⛔ 不只是"开发机上看过"
2. 视差与屏幕特效在最小 / 最大窗口下均正确
3. 排序在大量动态实例下仍正确
4. 打击反馈连打 20 次后速率与幅度正常
5. 转场前后输入可被正确接收

## 2. 工序

### Step 1　至少两种分辨率截图比对，开发机上看过不算　`[2d-rendering/07#S1]`

【读】`howto/godot/2d-rendering.md#9. 纹理过滤：像素风的三层开关`

【做】
在最小与最大窗口（至少两种分辨率）下各截一组图，逐项比对。
⛔ 只在开发机的窗口尺寸下验收 —— 过滤、stretch、视差限制、抖动幅度
**全都与视口尺寸有关**，⛔ 换一个尺寸就可能全错，而每一处单看都是对的。

⛔ 表现为"开发机完美、打包后发糊/露边/抖动变弱"，
那时能改的余地很小，排查成本远高于开发期多截一组图。

【品】`craft/godot/aesthetics.md#0. 总判据：截图测试`

【产出】两组分辨率的截图 + 逐项比对结论

【判据】两组的清晰度、边距、特效位置、抖动幅度观感一致。

【审】`audit/godot/2d-rendering.md#12`、`audit/godot/2d-rendering.md#39`

### Step 2　视差与屏幕特效在最小 / 最大窗口下复跑　`[2d-rendering/07#S2]`

【读】`howto/godot/2d-rendering.md#3. Parallax2D 视差背景`

【做】
把窗口拉到最小与最大，各跑一遍视差与屏幕特效。
⛔ 只测初始窗口 —— 视差的 `limit` 余量是按视口算的，
屏幕特效的坐标是屏幕空间的，⛔ 两者都会随窗口尺寸变化而失效。

ⓘ 特别要测"打包后的默认窗口"：
它与编辑器里的窗口尺寸常常不同，⛔ 这正是"开发机对的、打包后不对"的直接来源。

【产出】最小 / 最大 / 打包默认三种窗口的复跑记录

【判据】三种窗口下各层均滚动、无露白、特效无错位。

【审】`audit/godot/2d-rendering.md#38`、`audit/godot/2d-rendering.md#20`

### Step 3　排序压力测试：大量动态实例一起跑　`[2d-rendering/07#S3]`

【读】`howto/godot/2d-rendering.md#1. Y-Sort：俯视角 2D 的地基`

【做】
刷出几十个动态实例，与手摆物体混在一起验证遮挡关系。
⛔ 只测手摆的那几个 —— 运行时生成的实例可能没进排序父节点，
⛔ 表现为"手摆的对、刷出来的错"，而这在少量对象的测试里完全不出现。

ⓘ 同时确认互排对象的 `z_index` 仍然相同：
后期为了做"飞在空中的单位"常会顺手改 `z_index`，
⛔ 一改就整体退出互排，而且是**悄悄**退出的。

【产出】压力测试记录（实例数 × 遮挡关系 × z_index 复核）

【判据】动态与静态对象之间的遮挡关系全部正确。

【审】`audit/godot/2d-rendering.md#35`、`audit/godot/2d-rendering.md#19`

### Step 4　打击反馈连打 20 次，看速率与幅度　`[2d-rendering/07#S4]`

【读】`howto/godot/2d-rendering.md#7. 命中停顿（Hitstop）`

【做】
连续触发 20 次顿帧与抖动，确认 `time_scale` 回到 1、幅度未累积失控。
⛔ 只打一次 —— trauma 无上限、顿帧重入、恢复写死 1.0
这三个问题**全部只在连打时出现**，
⛔ 而单次测试给出的"很稳"是完全错误的信心。

ⓘ 连打之后还要专门测"慢动作中命中"和"顿帧中暂停"，
这两个组合才是恢复路径真正被考验的地方。

【产出】连打 20 次的记录（time_scale 终值 + 幅度观感 + 两个组合用例）

【判据】20 次后 `time_scale` 为 1；两个组合用例速率正常。

【审】`audit/godot/2d-rendering.md#26`、`audit/godot/2d-rendering.md#29`

### Step 5　转场前后输入都能被正确接收　`[2d-rendering/07#S5]`

【读】`howto/godot/2d-rendering.md#8. 转场`

【做】
转场开始、进行中、结束后各点一次，确认输入屏蔽是显式的、结束后立即恢复。
⛔ 只测"正常走完一次转场" —— 转场被打断（快速连点、切场景失败重试）
时输入屏蔽可能没解除，⛔ 表现为"偶发地点不了"，而复现全靠运气。

ⓘ 同时确认转场层的 `mouse_filter = Ignore`：
靠控件"顺带"挡输入，等于把输入开关藏在一个属性里，
⛔ 后面加任何全屏层都可能重犯。

【产出】转场 × 打断的输入接收记录

【判据】打断后输入屏蔽一定被解除。

【审】`audit/godot/2d-rendering.md#5`、`audit/godot/2d-rendering.md#11`

## 3. 验收清单

- [ ] 两种分辨率截图比对一致
- [ ] 最小 / 最大 / 打包默认三种窗口复跑通过
- [ ] 大量动态实例下排序正确
- [ ] 连打 20 次后速率与幅度正常
- [ ] 转场（含打断）后输入恢复

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 打包后发糊 / 露边 / 抖动变弱 | 只测开发机分辨率 | S1 |
| 开发机对的、打包后不对 | 未测打包默认窗口 | S2 |
| 手摆的对、刷出来的错 | 动态实例未进排序父节点 | S3 |
| 连打后卡住或糊成一片 | 只测单发 | S4 |
| 偶发地点不了 | 转场被打断后屏蔽未解除 | S5 |
