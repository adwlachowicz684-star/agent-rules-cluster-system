# 07 RTS 验收（RTS 域）

> **本步交付**：上千单位实测通过 + 敌意环境实测通过
> **对应**：流程 `howto/godot/genres-rts.md` · 审核 `audit/godot/genres-rts.md`

## 0. 交付物定义

1. 在**目标规模**下实测，⛔ 不是几十个单位跑一遍
2. 相机平滑与 limits 全开时框选仍精确
3. 改包伪造命令与结果被服务端拒绝
4. 强杀 / 重连后单位与命令状态可恢复
5. 单位卡住有可判定的原因，不是"无报错地停住"

## 2. 工序

### Step 1　按目标规模实测，⛔ 不是几十个单位跑一遍　`[rts/07#S1]`

【读】`howto/godot/genres-rts.md#6. 性能三档降级`

【做】
按**上线目标单位数**实测帧时间，覆盖三档切换点。
⛔ 只跑几十个单位 —— 档位阈值、避障开销、脏区提交
这三类问题**都只在规模上去之后出现**，
⛔ 而小规模下每一处单看都正常，于是"跑通了"这个结论会保持到上线。

【产出】规模 × 帧时间实测记录（含三档切换点）

【判据】目标规模下帧时间在预算内，且切换点无尖峰。

【审】`audit/godot/genres-rts.md#8`

### Step 2　相机平滑与 limits 全开时框选仍精确　`[rts/07#S2]`

【读】`howto/godot/genres-rts.md#9. 相机与屏幕坐标：官方口径`

【做】
把相机平滑、旋转平滑、边界限制**全部打开**再测框选与点选。
⛔ 只测默认相机 —— 用 `global_position` 反推屏幕中心的错法
在平滑关闭时偏移恰好为 0，
⛔ 于是这类 bug **只在开了平滑之后才暴露**，
而"相机看着没问题"会让排查被引向选框绘制。

【产出】平滑全开时的框选回归用例

【判据】平滑全开时点击单位中心仍能精确选中。

【审】`audit/godot/genres-rts.md#13`

### Step 3　改包伪造命令与结果必须被拒　`[rts/07#S3]`

【读】`howto/godot/genres-rts.md#0. 四层分离`

【做】
构造三类伪造：客户端直接提交战斗结果、伪造命令（瞬移 / 无限命令）、改资源数量，
验证服务端**全部拒绝**。
⛔ 只测正常路径 —— 这类伪造在正常流程里永远测不出来，
⛔ 而测试环境下没人会改包。

【产出】三类伪造用例 + 服务端拒绝记录

【判据】三类全部被拒，客户端回退无中间态。

【审】`audit/godot/genres-rts.md#38`

### Step 4　强杀 / 重连后状态可恢复　`[rts/07#S4]`

【读】`howto/godot/genres-rts.md#5. 单位管理：持有数组，不要每帧遍历场景树`

【做】
实测**强杀进程**与**断线重连**：单位集合、命令队列、迷雾层是否按 `unit_id` 正确重建。
⛔ 只测"点退出再进" —— 强杀走超时判定与服务端补算，
点退出走正常提交，**是两条不同的代码路径**。

⛔ 重连后按节点路径取单位会静默失效，
表现为"重连后所有命令没了"，⛔ 而界面上单位都还在。

【产出】强杀 / 重连对照记录（单位数、队列长度、迷雾状态）

【判据】重连前后单位集合与命令队列一致。

【审】`audit/godot/genres-rts.md#33`

### Step 5　单位卡住要能判定原因　`[rts/07#S5]`

【读】`howto/godot/genres-rts.md#8. 避障与寻路：三条官方约束`

【做】
针对"单位停住"建三类可判定的观测：
避障注册数是否超上限、路径点是否在物理步取、是否在信号回调里递归。
⛔ 只靠"看起来没报错" —— 无限递归与路径逻辑不更新
**都不抛异常**，只表现为再也不动，
⛔ 而日志里最后一条是正常到达路径点。

【产出】卡住诊断清单（三条观测 + 对应判据）

【判据】人为制造三种卡法，诊断清单能各自定位到原因。

【审】`audit/godot/genres-rts.md#19`

### Step 6　两态迷雾在敌我双方下不互相泄漏　`[rts/07#S6]`

【读】`howto/godot/genres-rts.md#4. 战争迷雾是独立的格子状态，不是 Light2D`

【做】
两个阵营各开一层，互相验证**看不到**对方视野；观战层不含任一方视野。
⛔ 只测单阵营 —— 共享层的泄漏在单机下永远测不出来，
表现为"对面知道你在哪"的线上投诉，
⛔ 而本地两个人开两个窗口测，往往只登录了同一阵营。

【产出】双阵营视野对照记录 + 观战层校验

【判据】任一方层不含对方视野；观战层不含任一方视野。

【审】`audit/godot/genres-rts.md#27`

## 3. 验收清单

- [ ] 目标规模下帧时间在预算内
- [ ] 平滑全开时框选精确
- [ ] 三类伪造全部被拒
- [ ] 强杀重连后状态一致
- [ ] 三种卡法都能定位
- [ ] 双阵营视野不互相泄漏

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 上线后掉帧 | 只跑过几十个单位 | S1 |
| 开平滑后框选偏 | 只测默认相机 | S2 |
| 排行榜不可能战绩 | 只测正常路径 | S3 |
| 重连后命令全没了 | 只测点退出 | S4 |
| 单位停住查不出 | 卡住无观测点 | S5 |
| 对面知道你在哪 | 只测单阵营 | S6 |
