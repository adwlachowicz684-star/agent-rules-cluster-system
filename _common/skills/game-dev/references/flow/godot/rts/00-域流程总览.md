# RTS / 即时战略 —— 域流程总览

> ⚠ **第 0 步：先定"这是不是一个命令队列系统"。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 单位选择与框选 / 编组 | 01 → 02 → 07 |
| 移动、攻击移动、 patrol | 01 → 03 → 04 → 07 |
| 战争迷雾与视野 | 01 → 05 → 07 |
| 大规模单位（> 200） | 01 → 04 → 06 → 07 |
| 联机 / 反作弊 | 01 → 06 → 07 |
| 全套（RTS 常见） | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过** ——
RTS 的架构核心是**命令模式 + 组选择 + 降频 AI**，
不是"每个单位一个 Node 自己跑逻辑"。
⛔ 先做框选再补命令层，会写成"选中即下达、选完就没了"，
于是没有队列、不能 Shift 追加、目标死了就站着，
⛔ 而演示时点一下走一下，看起来完全正常。

⛔ **03 要在 04 之前**：
命令是**数据**（`Array[Command]`），编队只是 MOVE 命令的偏移参数。
先写编队移动再补队列，等于把"移动"写死在一次调用里，
后面每加一个命令类型都要改移动代码。

⛔ **06 的降级档位要随规模同步定，不能最后统一补**：
档位决定了单位用什么节点、走不走物理、渲染走不走 `MultiMesh`，
⛔ 等上千单位卡了再改，要同时推翻单位节点、移动代码与渲染层。

ⓘ 若本次只是"加一个可建造单位、配一张造价表"，那是资源配置，不套本域。
ⓘ 若只是排查"单位挤成一团"，先看 `ai` 域确认转向与分离逻辑，再回本域 04。

ⓘ 分工：
- `howto/godot/genres-rts.md` 讲**四层各自的技术做法**（命令数据、框选换算、编队偏移、迷雾格子、单位持有、三档降级）
- 本域讲**这些层按什么顺序做、怎么保证上千单位与联机下行为仍然对**

⛔ 若本域某步需要"降级档位阈值""避障代理上限""迷雾格边长"这类细节，
指向项目实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 四层分离与命令模型 | — | 四层职责边界 + `Command` 数据结构 + 稳定 `unit_id` |
| 02 | 选择与框选 | 01 | 屏幕→世界换算 + 上限可判 + 编组与选中序 |
| 03 | 命令队列与执行 | 01 | `Array[Command]` + 有效性检查 + 队首占用语义 |
| 04 | 编队移动与避障 | 03 | 偏移按朝向旋转 + 避障按需开关 + 物理步取值 |
| 05 | 战争迷雾与视野 | 01 | 每方独立层 + `visible / explored` 两态 + 脏区批量 |
| 06 | 大规模降级与权威边界 | 01–05 | 三档降级 + 稳定 id 下发 + 服务端权威清单 |
| 07 | RTS 验收 | 全部 | 上千单位实测 + 敌意环境实测 |

⚠ **01 要在任何一个交互开工之前**：
那时改"命令是什么"只需要改一处；
⛔ 等框选、编队、迷雾各写各的，再统一就是四套语义各改一次。

⚠ **02 的换算要在做编组之前**：
换算定的是"玩家点的区域对应哪些单位"，
⛔ 先做编组再补换算，选中的集合每次都不一样。

⚠ **05 的迷雾层要在做视野 UI 之前**：
层结构决定了渲染与查询的形状，
⛔ 先画小地图再补层，小地图与逻辑两套状态会各自漂移。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是单条命令，是接缝。**

| 接缝 | 契约 |
|---|---|
| `ai` 域 AI 与行为 | 单位级决策（寻路目标、攻击目标选择）见 `ai`，⛔ 本域只定**命令怎么下发与消费** |
| `combat` 域 战斗结算 | 命中与伤害见 `combat`，⛔ 本域不另定伤害口径 |
| `netsync` 域 网络同步 | 传输与 authority 见 `netsync`；⛔ 本域只定"单位 id 必须是服务端下发的稳定 id" |
| `security` 域 安全 | 改包伪造见 `security`，⛔ 本域只定"客户端提交单位结果必须被拒" |
| `perf` 域 性能 | 剖析与预算见 `perf`，⛔ 本域只定"档位要实测" |
| `level` 域 关卡场景 | 地形与阻挡见 `level`，⛔ 本域只定"迷雾层关 `navigation_enabled`" |
| `ui` 域 界面 | 选择框与小地图的呈现见 `ui`，⛔ 本域只定选中集合的**顺序契约** |
| `2d-rendering` 域 2D 渲染 | 排序与批处理见 `2d-rendering`，⛔ 本域只定"降级档要换渲染路径" |
| `genres-tactics` | ⓘ howto 层，暂无 flow 域 —— 回合制战棋的格子与行动序见该篇 |
| `genres-roguelike` | ⓘ howto 层，暂无 flow 域 —— 与 `procgen` 域（程序化生成）相邻 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `MAX_SELECT` 最多同时选中数 | 02 | — | — | 待实测（⛔ 必须显式传给 `intersect_shape`，不能吃默认 32） |
| `FORMATION_SPACING` 编队间距 | 04 | — | — | 待实测（与单位半径、转向半径相关） |
| `AVOIDANCE_MAX_AGENTS` 同时注册避障上限 | 04 | — | — | 待实测（⛔ 官方点名大量注册有显著开销） |
| `FOG_CELL_SIZE` 迷雾格边长 | 05 | — | — | 待实测（与视野半径、地图尺寸相关） |
| `FOG_FLUSH_EVERY_N_TICKS` 脏区提交间隔 | 05 | — | — | 待实测（按逻辑帧，⛔ 不是渲染帧） |
| `TIER2_UNIT_COUNT` 二档降级阈值 | 06 | — | — | 待实测（⛔ 200/800 是品类经验值，不是本项目实测值） |
| `TIER3_UNIT_COUNT` 三档降级阈值 | 06 | — | — | 待实测（⛔ 与二档同步实测，不能只定一档） |
| `UNIT_TICK_EVERY_N` 单位降频间隔 | 06 | — | — | 待实测（与单位数与帧预算相关） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"框选漏了一半""单位卡住""某个规模段突然掉帧"，
⛔ 而这类失败在几十个单位的测试场景里几乎不出现。
