# 04 编队移动与避障（RTS 域）

> **本步交付**：偏移按朝向旋转 + 避障按需开关 + 物理步取值
> **对应**：流程 `howto/godot/genres-rts.md` · 审核 `audit/godot/genres-rts.md`

## 0. 交付物定义

1. 编队偏移按行进方向旋转，不是写死的网格
2. 避障只开在**当前需要**的单位上，有注册上限
3. 每个物理帧调一次 `get_next_path_position()`，且不在信号回调里调
4. 降级档要么走物理、要么跳过物理，⛔ 不并存
5. `target_position` 只在目标真正变化时设

## 1. 前置检查清单

- [ ] 编队偏移乘了行进方向的旋转
- [ ] `avoidance_enabled` 有按需开关逻辑与上限
- [ ] `get_next_path_position()` 只出现在物理步
- [ ] 降级档的物理 / 非物理路径互斥
- [ ] `target_position` 赋值前比较了旧值

## 2. 工序

### Step 1　编队偏移要按行进方向旋转　`[rts/04#S1]`

【读】`howto/godot/genres-rts.md#3. 编队：算偏移位，不要所有单位同目标点`

【做】
先算网格 / 菱形偏移，再按**行进方向**旋转偏移后叠加到目标点。
⛔ 偏移写死不随朝向转 —— 队形在转向时会翻转或穿插，
表现为"拐弯后队伍散了"，⛔ 而每个单位单独看都在正确走向自己的点。

ⓘ 单位间距 `FORMATION_SPACING` 要大于单位半径之和，
否则偏移位互相重叠，避障会持续介入，表现为"队形永远收不拢"。

【产出】`formation_offsets(n)` + 按方向旋转的叠加函数

【判据】连续两次转向后，队形相对行进方向的关系不变。

【审】`audit/godot/genres-rts.md#29`

### Step 2　所有单位指向同一目标点会挤成一团　`[rts/04#S2]`

【读】`howto/godot/genres-rts.md#3. 编队：算偏移位，不要所有单位同目标点`

【做】
各 agent 各自寻路到**自己的偏移位**，⛔ 不共用一条路径再靠 RVO 挤开。
RVO 能缓解但会引入抖动，表现为"大军到位后原地抖"，
⛔ 而每个单位都"到达了目标点"，检查位置是对的。

【产出】每单位独立 `target_position`（偏移位）

【判据】10 个单位到达后位置之间距离不小于间距，且无持续抖动。

【审】`audit/godot/genres-rts.md#5`

### Step 3　避障只在需要的单位上开，⛔ 不全局开　`[rts/04#S3]`

【读】`howto/godot/genres-rts.md#8. 避障与寻路：三条官方约束`

【做】
`avoidance_enabled` 默认 `false`，置 true 后代理在 `NavigationServer2D`
注册 RVO 回调，完成后用 `safe_velocity` 经 `velocity_computed` 返回。
⛔ **官方原话**：大量注册代理的避障处理**有显著性能开销**，
只应在**当前需要**的 agent 上启用。
⛔ 给上千单位全开 —— 开销出现在导航服务器上，
单位表现为"卡住不动原地挤"，
⛔ 这时看 `velocity` 与碰撞都正常，排查被引向寻路网格而不是避障开关。

【产出】避障按需开关策略 + `AVOIDANCE_MAX_AGENTS` 上限登记

【判据】上千单位时注册避障的代理数不超过上限。

【审】`audit/godot/genres-rts.md#17`

### Step 4　每物理帧取一次路径点，⛔ 不在信号回调里取　`[rts/04#S4]`

【读】`howto/godot/genres-rts.md#8. 避障与寻路：三条官方约束`

【做】
官方 Note：设了 `target_position` 之后**必须每物理帧调一次**
`get_next_path_position()` 来更新内部路径逻辑。
⛔ 更隐蔽的是递归 —— 官方写明该方法**会触发新的路径计算**，
在 `waypoint_reached` 这类信号回调里调用它**会导致无限递归**。

⛔ 而"到点后取下一个点"恰恰是 RTS 最自然的写法。
于是卡死表现为"单位走到第一个路径点后停住"，
日志里**没有报错**，只是再也不动了。

【产出】物理步取值循环（帧末才改 `target_position`）

【判据】单位能连续走过 5 个路径点不停住。

【审】`audit/godot/genres-rts.md#19`

### Step 5　降级档的物理与非物理路径互斥　`[rts/04#S5]`

【读】`howto/godot/genres-rts.md#6. 性能三档降级`

【做】
二档取路径点后**直接位置赋值、跳过物理**；
三档走逻辑网格 + 批量 `MultiMesh`。
⛔ 直接改 `position` 但仍挂 `CharacterBody2D` —— 物理与逻辑双驱动，
表现为抖动或穿墙，⛔ 而碰撞体本身配置正确。

ⓘ 另：`target_position` 只在目标真正变化时设，
⛔ 每帧刷新会**每帧触发一次重新寻路**，
表现为"单位数一多就卡"，⛔ 而每次寻路单看都是必要的。

【产出】三档移动路径实现 + `target_position` 变更比较

【判据】二档下单位不抖动；上千单位时每帧不触发重新寻路。

【审】`audit/godot/genres-rts.md#31`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：FORMATION_SPACING / AVOIDANCE_MAX_AGENTS 见 00 参数登记（待实测）
func formation_offsets(n: int, dir: Vector2) -> Array[Vector2]:
    var out: Array[Vector2] = []
    var cols := int(ceil(sqrt(float(n))))
    var rot := Transform2D(0.0, Vector2.ZERO, 1.0, Vector2.ZERO, dir.normalized())
    for i in n:
        var r := i / cols
        var c := i % cols
        out.append(rot * (Vector2(c - cols / 2.0, r) * FORMATION_SPACING))
    return out

# ⛔ 不要在 waypoint_reached 回调里调 get_next_path_position（官方：会无限递归）
func _physics_process(_d: float) -> void:
    if agent.is_navigation_finished():
        return
    _next = agent.get_next_path_position()      # ✅ 每物理帧一次
    if _target_changed():
        agent.target_position = _goal           # ✅ 只在变化时设
```
