# 02 选择与框选（RTS 域）

> **本步交付**：屏幕→世界换算 + 上限可判 + 编组与选中序
> **对应**：流程 `howto/godot/genres-rts.md` · 审核 `audit/godot/genres-rts.md`

## 0. 交付物定义

1. 屏幕点经 viewport 变换换算到世界坐标，⛔ 不用相机节点的方法
2. 框选显式传 `max_results`，且达到上限时能判断"可能还有"
3. 框选不用 `Area2D` 实体，不依赖物理帧
4. `Rect2.has_point()` 边界按官方约定处理
5. 选中集合有确定顺序，编组与命令下发顺序稳定

## 1. 前置检查清单

- [ ] 换算走 `get_viewport()` 的 `screen_transform` 与 `canvas_transform`
- [ ] `intersect_shape` 显式传 `MAX_SELECT`
- [ ] 返回数等于上限时有"可能被截断"的分支
- [ ] 框选路径里没有 `Area2D` / `PhysicsBody2D`
- [ ] 选中集合排序后再下发命令

## 2. 工序

### Step 1　屏幕→世界走 viewport，⛔ 不用相机节点的 `get_screen_transform()`　`[rts/02#S1]`

【读】`howto/godot/genres-rts.md#9. 相机与屏幕坐标：官方口径`

【做】
换算写成 `(vp.get_screen_transform() * vp.get_canvas_transform()).affine_inverse() * screen_pos`。
⛔ 用 `Camera2D` 继承来的 `get_screen_transform()` ——
它是 `CanvasItem` 的方法，含义是**节点自身变换到屏幕**，
其逆变换把屏幕点换到**节点局部空间**，不是世界空间。
相机不在世界原点时框选整体偏移，⛔ 而关掉平滑时偏移恰好为 0，
**于是只在开了平滑之后才暴露**。

ⓘ `_input()` 里的 `event.position` 是 **viewport 坐标**，不是世界坐标。

【产出】`screen_to_world()` + 相机平滑开启时的回归用例

【判据】相机平滑与 limits 全开时，点击单位中心仍能精确选中。

【审】`audit/godot/genres-rts.md#15`

### Step 2　取屏幕中心用 `get_screen_center_position()`　`[rts/02#S2]`

【读】`howto/godot/genres-rts.md#9. 相机与屏幕坐标：官方口径`

【做】
需要"当前看到的世界范围"时用 `get_screen_center_position()`，
⛔ 不用 `Camera2D.global_position`。
官方 Note 写明：`global_position` 因平滑与边界限制**不等于真实屏幕位置**。
表现为框选矩形整体偏一个平滑量，
⛔ 而相机代码一处都没错，排查被引向选框绘制。

【产出】视野范围查询接口（基于 `get_screen_center_position()`）

【判据】快速拖动相机后立刻框选，选中集合与画面一致。

【审】`audit/godot/genres-rts.md#13`

### Step 3　框选显式传 `max_results`，⛔ 不吃默认 32　`[rts/02#S3]`

【读】`howto/godot/genres-rts.md#2. 框选：世界坐标转换 + Rect2，不要用 Area2D 套`

【做】
`intersect_shape(q, MAX_SELECT)` 显式传上限。
⛔ 官方签名 `max_results: int = 32` —— 框选 200 个单位只回来 32 个，
玩家看到"选了一部分"，⛔ **没有任何报错**。
⛔ 更隐蔽的是**按返回顺序截断，不是按优先级**：
丢掉的是"引擎先碰到的之外"的，不是"最不该选的"，
表现为框选结果**随单位摆放顺序变化**。

【产出】框选查询（显式上限）+ 上限参数登记

【判据】框住 200 个单位时返回 200 个，不是 32 个。

【审】`audit/godot/genres-rts.md#12`

### Step 4　达到上限要能判断"可能还有"　`[rts/02#S4]`

【读】`howto/godot/genres-rts.md#2. 框选：世界坐标转换 + Rect2，不要用 Area2D 套`

【做】
返回数 `== MAX_SELECT` 时走"可能截断"分支：提示或改用空间哈希自算。
⛔ 静默截断 —— 玩家以为全选了，实际漏了一大半，
⛔ 而界面上选中数看着是"三千二百"，没有任何迹象表明少了。

【产出】截断检测分支 + 提示 / 降级查询路径

【判据】框住超过上限的单位时，界面明确提示或自动走自算。

【审】`audit/godot/genres-rts.md#23`

### Step 5　框选不用 `Area2D`，且结果要排序　`[rts/02#S5]`

【读】`howto/godot/genres-rts.md#2. 框选：世界坐标转换 + Rect2，不要用 Area2D 套`

【做】
用屏幕 `Rect2` + 世界坐标转换 + `Rect2.has_point()`，
⛔ 不实例化一个 `Area2D` 去套 —— 那要等物理帧才出结果（延迟一帧），
且上千单位时开销大。
另注意 `Rect2.has_point()` **约定右边缘与底边缘不算包含**，
做"框到才算选中"要手动加容差。

⛔ 选中集合**不排序直接下发** —— 下发顺序不确定会让编队位置每次操作后互换，
表现为"点了两次队形变了"，⛔ 而选中的还是那批单位。

【产出】`Rect2` 框选实现（含边界容差）+ 选中序排序规则

【判据】同一批单位连续两次框选下发后，编队位置一致。

【审】`audit/godot/genres-rts.md#24`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：MAX_SELECT 见 00 参数登记（待实测），⛔ 必须显式传
# SELECT_TOLERANCE 边界容差：Rect2.has_point 不含右/底边缘
const SELECT_TOLERANCE := 1.0
const SELECT_LAYER := 2

func screen_to_world(screen_pos: Vector2) -> Vector2:
    var vp := get_viewport()
    return (vp.get_screen_transform() * vp.get_canvas_transform()).affine_inverse() * screen_pos

func box_select(drag_start: Vector2, drag_end: Vector2) -> Array:
    var a := screen_to_world(drag_start)
    var b := screen_to_world(drag_end)
    var rect := Rect2(a, b - a).abs().grow(SELECT_TOLERANCE)
    var out := []
    for u in _units:                       # _units 见 01 S4
        if rect.has_point(u.global_position):
            out.append(u)
    out.sort_custom(func(x, y): return x.unit_id < y.unit_id)   # 稳定选中序
    return out
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 开平滑后框选偏移 | 用了相机节点的 get_screen_transform | S1 |
| 快速拖动后选不中 | 用 global_position 当屏幕中心 | S2 |
| 框选只选中一部分 | 吃了默认 max_results | S3 |
| 玩家以为全选了 | 截断无提示 | S4 |
| 两次操作队形互换 | 选中集合未排序 | S5 |
