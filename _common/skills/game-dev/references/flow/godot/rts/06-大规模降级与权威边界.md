# 06 大规模降级与权威边界（RTS 域）

> **本步交付**：三档降级 + 稳定 id 下发 + 服务端权威清单
> **对应**：流程 `howto/godot/genres-rts.md` · 审核 `audit/godot/genres-rts.md`

## 0. 交付物定义

1. 三档降级（完整物理 / 路径点跳物理 / 逻辑网格 + `MultiMesh`）按实测阈值切换
2. 阈值是**实测值**，⛔ 不是品类经验值
3. 单位 id 由服务端下发，重连后仍有效
4. 客户端提交单位结果一律被拒
5. 降频 AI 与脏区提交按逻辑 tick 走

## 1. 前置检查清单

- [ ] 三档各有明确的单位节点与渲染路径
- [ ] 档位阈值来自本项目实测
- [ ] `unit_id` 由服务端分配，客户端不自行生成
- [ ] 服务端权威清单覆盖：命令、结果、资源
- [ ] 降频间隔按逻辑 tick，不是渲染帧

## 2. 工序

### Step 1　三档降级：完整物理 / 路径点 / 逻辑网格　`[rts/06#S1]`

【读】`howto/godot/genres-rts.md#6. 性能三档降级`

【做】
一档完整 `CharacterBody2D` + `move_and_slide` + avoidance；
二档 `NavigationAgent2D` 取路径点 + 直接位置赋值（跳过物理）；
三档逻辑网格单元 + 批量 `MultiMesh` 渲染，重结算走 C# 或 GDExtension。
⛔ 1000 个 `CharacterBody2D` 各跑 `move_and_slide` + avoidance 在 GDScript 下迅速掉帧。

ⓘ 2D RTS **别指望 Jolt 加速** —— Jolt 自 4.4 实验、4.6 起是 **3D** 默认物理引擎，
**2D 默认仍是 Godot Physics**。
⛔ 以为换 Jolt 能救 2D 单位数，会白白等一个不会来的收益。

【产出】三档实现 + 切换开关（按单位数）

【判据】在目标规模下帧时间落在预算内（预算口径见 `perf` 域）。

【审】`audit/godot/genres-rts.md#8`

### Step 2　档位阈值必须实测，⛔ 不沿用品类经验值　`[rts/06#S2]`

【读】`howto/godot/genres-rts.md#6. 性能三档降级`

【做】
`TIER2_UNIT_COUNT` 等阈值由**本项目实测**得出并记录。
⛔ 沿用"200 / 800"这类数字 —— 填错**不会报错**，
只表现为某个规模段突然掉帧，⛔ 而低于阈值时一切正常，
于是"文档是对的"这个错觉会一直保持到上线。

【产出】实测记录（单位数 × 帧时间）+ 阈值登记

【判据】阈值有对应的实测数据支撑，不是引用来的数字。

【审】`audit/godot/genres-rts.md#30`

### Step 3　`unit_id` 由服务端下发　`[rts/06#S3]`

【读】`howto/godot/genres-rts.md#5. 单位管理：持有数组，不要每帧遍历场景树`

【做】
单位标识由服务端分配并下发，客户端 ⛔ 不自行生成（比如用节点路径或本地自增）。
⛔ 用节点路径做标识 —— 重连后路径失效，
表现为"重连后所有命令静默失效"，⛔ 而日志里命令仍在、单位仍在。

【产出】服务端 id 分配 + 客户端反查表（重连后重建）

【判据】重连后按 id 反查能取到同一批单位。

【审】`audit/godot/genres-rts.md#33`

### Step 4　客户端提交单位结果一律被拒　`[rts/06#S4]`

【读】`howto/godot/genres-rts.md#0. 四层分离`

【做】
权威清单覆盖三类：命令（客户端只上报意图）、结算（伤害与产出服务端算）、资源（数量服务端记）。
客户端直接提交"谁打死了谁""采了多少"一律拒绝。
⛔ 只测正常路径 —— 改包伪造**在正常流程里永远测不出来**，
它只在有人主动改包时触发，⛔ 而测试环境下没人会改包。

【产出】权威清单 + 三类伪造用例与拒绝记录

【判据】三类伪造全部被拒，客户端回退无中间态。

【审】`audit/godot/genres-rts.md#38`

### Step 5　降频与脏区按逻辑 tick 走　`[rts/06#S5]`

【读】`howto/godot/genres-rts.md#7. 视野更新做脏区批量`

【做】
单位决策降频（`UNIT_TICK_EVERY_N`）与迷雾脏区提交都挂在**逻辑 tick** 上。
⛔ 挂在渲染帧 —— 帧率一变，决策频率跟着变，
表现为"高刷屏上 AI 反应更快"，⛔ 而每台机器单看都是"正常反应"。

ⓘ 降频要**错峰**（按 `unit_id % N` 分散），
否则每 N 帧有一帧集中算完上千单位，表现为周期性卡顿。

【产出】逻辑 tick 调度器 + 错峰分配

【判据】不同帧率下 AI 决策次数相同；无周期性尖峰。

【审】`audit/godot/genres-rts.md#39`

### Step 6　单位集合的增删不碰场景树　`[rts/06#S6]`

【读】`howto/godot/genres-rts.md#5. 单位管理：持有数组，不要每帧遍历场景树`

【做】
上千单位下，启用 / 销毁只改 `Array[Unit]`，
⛔ 不做场景树查询也不逐节点 `queue_free` 后立刻重建。
⛔ 每帧查场景树 —— 开销出现在 profiling 的"脚本函数"里而不是"物理"里，
排查被引向物理设置，⛔ 而物理设置一处都没错。

【产出】批量增删接口（含复用池）

【判据】上千单位批量销毁与重建不产生帧时间尖峰。

【审】`audit/godot/genres-rts.md#28`

## 3. 参考实现

```gdscript
# ⓘ TIER2_UNIT_COUNT / TIER3_UNIT_COUNT / UNIT_TICK_EVERY_N 见 00 参数登记（待实测）
enum Tier { FULL_PHYSICS, PATH_POINTS, LOGIC_GRID }

var _tier: Tier = Tier.FULL_PHYSICS
var _tick := 0

func _on_logic_tick() -> void:
    _tick += 1
    var n := _units.size()                       # _units 见 01 S4
    _tier = Tier.LOGIC_GRID if n > TIER3_UNIT_COUNT else (
            Tier.PATH_POINTS if n > TIER2_UNIT_COUNT else Tier.FULL_PHYSICS)
    for u in _units:
        if u.unit_id % UNIT_TICK_EVERY_N != _tick % UNIT_TICK_EVERY_N:
            continue                             # 错峰降频
        u.decide(_tick)
    fog._flush()                                 # 脏区：逻辑帧末提交
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 上千单位掉帧 | 全走完整物理 | S1 |
| 某规模段突然掉帧 | 阈值未实测 | S2 |
| 重连后命令全失效 | 客户端自生 id | S3 |
| 排行榜出现不可能战绩 | 只测正常路径 | S4 |
| 高刷屏 AI 更快 | 降频挂渲染帧 | S5 |
| 脚本函数帧时间高 | 每帧查场景树 | S6 |
