# 03 命令队列与执行（RTS 域）

> **本步交付**：`Array[Command]` + 有效性检查 + 队首占用语义
> **对应**：流程 `howto/godot/genres-rts.md` · 审核 `audit/godot/genres-rts.md`

## 0. 交付物定义

1. 每个单位一个 `Array[Command]`，命令可插入 / 取消 / 替换
2. 消费循环按"无效则移除、未完成则占用队首"两条语义
3. 五种命令类型各有明确的执行完成条件
4. 命令执行在**逻辑帧**，不在渲染帧
5. 命令失效时单位回到可判定的待命态

## 1. 前置检查清单

- [ ] 队列是 `Array[Command]`，不是信号连接
- [ ] `_is_valid` 覆盖：目标已死、目标已消失、单位自身已死
- [ ] `_execute` 返回 false 时不移除队首
- [ ] 执行在逻辑帧推进，与渲染帧解耦
- [ ] HOLD 与 PATROL 有明确的完成 / 循环条件

## 2. 工序

### Step 1　队列语义：无效则移除，未完成则占用队首　`[rts/03#S1]`

【读】`howto/godot/genres-rts.md#1. 命令是数据，不是信号`

【做】
消费循环两条语义分开：
`_is_valid` 为假 → `remove_at(0)` 并 `continue`；
`_execute` 返回假 → `break`（队首继续占用）。
⛔ 把"无效"和"未完成"合并成一个分支 ——
无效命令会被反复执行到"完成"才移除，
表现为"攻击一个不存在的目标要等超时"，
⛔ 而超时值通常是调过的，看起来只是"反应慢"。

【产出】命令消费循环（两条语义分离）

【判据】下发攻击已死目标的命令后，队列在同一 tick 清空。

【审】`audit/godot/genres-rts.md#21`

### Step 2　命令要支持插入、取消、替换　`[rts/03#S2]`

【读】`howto/godot/genres-rts.md#1. 命令是数据，不是信号`

【做】
提供 `push` / `queue`（Shift 追加）/ `cancel` / `replace` 四个入口，
⛔ 不要"取消"实现成"清空再加回" ——
那会让正在执行的中间态（已移动的距离、已锁定的目标）丢失，
表现为"取消后单位回到起点重走"，⛔ 而命令列表看着完全正确。

ⓘ 替换要保留**队首正在执行**的那条，只换后续 ——
否则会出现"改了目标但当前动作被打断"的观感。

【产出】四个命令入口 + 取消时保留中间态的约定

【判据】取消队尾命令后，队首命令的执行进度不变。

【审】`audit/godot/genres-rts.md#20`

### Step 3　目标用 `unit_id` 反查，⛔ 不缓存节点　`[rts/03#S3]`

【读】`howto/godot/genres-rts.md#5. 单位管理：持有数组，不要每帧遍历场景树`

【做】
执行时按 `target_unit_id` 走反查表取当前单位，
⛔ 不在下发命令时把节点缓存进命令对象。
目标销毁后缓存变成悬挂引用，
⛔ **不报错**，表现为"攻击命令既不报错也不动"，
⛔ 而检查命令对象时它确实"有目标"。

【产出】id 反查函数 + 命令执行前的反查步骤

【判据】目标销毁后命令在下一 tick 被判无效。

【审】`audit/godot/genres-rts.md#22`

### Step 4　执行在逻辑帧推进，⛔ 不在渲染帧　`[rts/03#S4]`

【读】`howto/godot/genres-rts.md#5. 单位管理：持有数组，不要每帧遍历场景树`

【做】
命令推进挂在**固定逻辑步长**上（配合 06 的降频），
⛔ 不要在 `_process` 里直接推进 —— 渲染帧随帧率变化，
命令推进速度会跟着变，表现为"高刷屏上单位走得快"，
⛔ 而每台机器单看都是"正常速度"。

【产出】逻辑帧推进入口（`_physics_process` 或自建 tick）

【判据】30 / 60 / 144 FPS 下单位走完同一段命令用时相同。

【审】`audit/godot/genres-rts.md#36`

### Step 5　失效后要落到可判定的待命态　`[rts/03#S5]`

【读】`howto/godot/genres-rts.md#1. 命令是数据，不是信号`

【做】
队列清空后单位进入显式待命态（含当前是否可再接受命令），
⛔ 不要"队列空了就什么都不做" ——
那么"空队列"和"正在执行"在外部无法区分，
表现为"选中后点地面没反应"，⛔ 而队列长度是 0，看起来"该响应"。

ⓘ 待命态要能被 UI 查询 —— 这是"能不能下令"的唯一判据来源。

【产出】待命态定义 + UI 查询接口

【判据】队列清空后可以立刻下发新命令并生效。

【审】`audit/godot/genres-rts.md#37`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：Command 与 _units 见 01；_by_id 反查见 01 S3
var _queue: Array[Command] = []
var _idle: bool = true

func push(cmd: Command) -> void:
    if not cmd.queued:
        _queue.clear()
    _queue.append(cmd)
    _idle = false

func cancel_tail() -> void:
    if _queue.size() > 1:
        _queue.remove_at(_queue.size() - 1)   # ⛔ 保留队首执行进度

func _tick() -> void:
    while not _queue.is_empty():
        var cmd := _queue[0] as Command
        if not _is_valid(cmd):                # 无效：移除并继续
            _queue.remove_at(0)
            continue
        if not _execute(cmd):                 # 未完成：占用队首
            break
        _queue.remove_at(0)
    _idle = _queue.is_empty()
```

## 4. 验收清单

- [ ] 攻击已死目标时队列同 tick 清空
- [ ] 取消队尾后队首进度不变
- [ ] 目标销毁后命令判无效
- [ ] 不同帧率下命令用时相同
- [ ] 队列清空后可立刻受命

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 攻击空目标要等超时 | 无效与未完成合并 | S1 |
| 取消后单位回起点 | 取消实现成清空重加 | S2 |
| 攻击命令静默不动 | 命令缓存了节点 | S3 |
| 高刷屏单位走得快 | 在渲染帧推进 | S4 |
| 点了地面没反应 | 空队列无待命态 | S5 |
