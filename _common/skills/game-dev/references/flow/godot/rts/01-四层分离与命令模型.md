# 01 四层分离与命令模型（RTS 域）

> **本步交付**：四层职责边界 + `Command` 数据结构 + 稳定 `unit_id`
> **对应**：流程 `howto/godot/genres-rts.md` · 审核 `audit/godot/genres-rts.md`

## 0. 交付物定义

1. 选择层 / 命令层 / 执行层 / 感知层四层职责不互相越界
2. 命令是**数据**，不是信号、不是节点树
3. 单位标识是稳定的 `unit_id`，不是节点引用或节点路径
4. 单位集合由 `UnitManager` 持有数组，不是每帧查场景树
5. 命令支持插入、取消、替换与有效性检查

## 1. 前置检查清单

- [ ] 四层各有一个明确的入口函数，没有互相直接调私有方法
- [ ] `Command` 是 `Resource` 或纯数据结构，能存进数组
- [ ] 命令里存 `unit_id`，⛔ 没有 `Node` 字段
- [ ] 单位表是 `Array[Unit]`，没有 `get_nodes_in_group` 出现在每帧路径
- [ ] 命令类型枚举覆盖 MOVE / ATTACK_MOVE / ATTACK_TARGET / HOLD / PATROL

## 2. 工序

### Step 1　先分四层，⛔ 不要每个单位一个 Node 自己跑逻辑　`[rts/01#S1]`

【读】`howto/godot/genres-rts.md#0. 四层分离`

【做】
把系统切成**选择层**（单选 / 框选 / 编组）、**命令层**（每个单位一个 `Array[Command]`）、
**执行层**（单位消费队首命令、算编队偏移）、**感知层**（战争迷雾、视野）。
⛔ 把选择、命令、执行、感知全塞进单位自己的 `_process` ——
那么"框选了谁"这件事同时存在于 UI、单位与迷雾三处，
表现为"取消选中后单位还在走""迷雾里看不见的单位照样执行"，
⛔ 而每一处单看都自洽。

【产出】四层各自的入口函数清单（含调用方向）

【判据】取消选中并清空命令后，单位在下一逻辑帧停止。

【审】`audit/godot/genres-rts.md#20`

### Step 2　命令是数据，⛔ 不用信号串起来　`[rts/01#S2]`

【读】`howto/godot/genres-rts.md#1. 命令是数据，不是信号`

【做】
`Command` 做成 `Resource`：含 `type` 枚举、`target_pos`、`target_unit_id`、`queued` 标志。
⛔ 用信号把指令串起来 —— 信号适合"事件已经发生"，不适合"待执行的意图"；
意图要支持**插入、取消、替换**，信号做不到，
表现为"Shift 追加指令变成覆盖""取消后队列残留"，
⛔ 而信号连上了就收得到，看起来是通的。

ⓘ 顺带把 Shift 追加定成 `queued = true` 而不是"多发一次 MOVE"——
后者会让队列里出现两条语义相同但不可取消的命令。

【产出】`Command` 定义（含 `queued`）+ 类型枚举

【判据】Shift 追加后队列长度为 2，取消一条后剩 1。

【审】`audit/godot/genres-rts.md#1`

### Step 3　单位标识用稳定的 `unit_id`，⛔ 不用节点引用　`[rts/01#S3]`

【读】`howto/godot/genres-rts.md#5. 单位管理：持有数组，不要每帧遍历场景树`

【做】
每个单位有服务端下发（或生成时分配）的 `unit_id: int`；
命令里的 `target_unit_id` 存它，⛔ 不存 `Node` 引用或节点路径。
目标销毁后引用变成悬挂引用或 `null`，⛔ **不报错**，
表现为"攻击一个已死单位时既不报错也不动"，
⛔ 而检查命令对象时它确实"有目标"。

ⓘ 联机下节点路径在重连后会失效 ——
表现为"重连后所有攻击命令静默失效"，日志里命令仍在。

【产出】`unit_id` 分配与反查表 + 命令里的 id 字段

【判据】销毁目标单位后，命令在下一 tick 被判无效并移除。

【审】`audit/godot/genres-rts.md#22`

### Step 4　单位集合由 `UnitManager` 持有数组　`[rts/01#S4]`

【读】`howto/godot/genres-rts.md#5. 单位管理：持有数组，不要每帧遍历场景树`

【做】
`UnitManager` 持有 `Array[Unit]`，启用 / 销毁只改数组，⛔ 不碰场景树做查询。
⛔ 每帧 `get_nodes_in_group("units")` —— 那是全树扫描，
几十个单位时完全正常，⛔ 上千单位时开销出现在 profiling 的
"脚本函数"里而不是"物理"里，排查被引向物理设置。

【产出】`UnitManager` + 增删接口（不含场景树查询）

【判据】上千单位时每帧路径里没有 `get_nodes_in_group` 调用。

【审】`audit/godot/genres-rts.md#28`

### Step 5　命令要做有效性检查，⛔ 不是取出来就执行　`[rts/01#S5]`

【读】`howto/godot/genres-rts.md#1. 命令是数据，不是信号`

【做】
消费循环用 `while` 配合 `_is_valid(cmd)`：无效就 `remove_at(0)` 继续，
未执行完就 `break`（继续占用队首）。
⛔ 单位死亡后不清队列 —— 队首是条死命令，
单位表现为"站住不动但仍显示在编队里"，
⛔ 而队列长度不为零，看起来"还有指令"。

【产出】命令消费循环 + `_is_valid` 判定规则

【判据】目标单位死亡后，队列在下一 tick 清空并回到待命。

【审】`audit/godot/genres-rts.md#21`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：Command 是数据；unit_id 见 S3；MAX_SELECT 见 00 参数登记（待实测）
class_name Command extends Resource

enum Type { MOVE, ATTACK_MOVE, ATTACK_TARGET, HOLD, PATROL }
@export var type: Type = Type.MOVE
@export var target_pos: Vector2
@export var target_unit_id: int = -1   # ⛔ 存 id，不存 Node
@export var queued: bool = false

var _units: Array[Unit] = []           # UnitManager 持有，启停只改数组
var _by_id: Dictionary = {}            # unit_id -> Unit 反查

func _tick() -> void:
    while not _queue.is_empty():
        var cmd := _queue[0] as Command
        if not _is_valid(cmd):
            _queue.remove_at(0)
            continue
        if not _execute(cmd):
            break                      # 未完成的命令继续占用队首
        _queue.remove_at(0)
```

## 4. 验收清单

- [ ] 取消选中并清空命令后单位下一逻辑帧停止
- [ ] Shift 追加后队列长度为 2
- [ ] 目标销毁后命令被判无效并移除
- [ ] 上千单位时每帧无 `get_nodes_in_group`
- [ ] 目标死亡后队列清空回到待命

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 取消选中后单位还在走 | 四层越界，命令不在命令层 | S1 |
| Shift 追加变成覆盖 | 命令用信号 / 没带 queued | S2 |
| 重连后攻击命令全失效 | 命令存节点路径 | S3 |
| 上千单位帧时间涨在脚本上 | 每帧查场景树 | S4 |
| 单位站着不动但队列非空 | 死亡后不清队首 | S5 |
