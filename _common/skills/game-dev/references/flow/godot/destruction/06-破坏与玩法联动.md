# 06 破坏与玩法联动（destruction 域）

> **前置**：03 完成
> **本步交付**：**破坏能改变世界状态，且能存档恢复**
> **对应**：做法 `howto/godot/destruction-cloth.md#2. 碎片池化与预算`
> 　　　审核 `audit/godot/destruction-cloth.md#7`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：打碎了会掉东西。**

⛔ 常见假完成：破坏只是"把节点换成碎片"，
世界状态（哪些已碎、地形还通不通、掉落给没给）**没进任何数据**。
⚠ 于是读档后"墙碎着但能走过去"，或"重开后碎片还在原地"。

做完这一步，应该能**当场演示**：

1. ⛔ 破坏状态是**数据**，不是"场景里有没有这个节点"
2. ⚠ 结构连通判定（打断承重 → 上层塌）
3. ⚠ 掉落走**同一条掉落链**，不单独写
4. ⚠ 破坏改变可行走区域时**导航重烘**
5. ⛔ 存档存"已碎 ID 集合"，**不存碎片 transform**
6. ⚠ 风只吹软体，吹碎片要自己施力

**产出物**（下游按名字对接）：

```text
DestructionWorld: shattered_ids: Set[String], structural_graph
存档字段：shattered_ids
```

## 2. 工序

### Step 1　⛔ 破坏状态是数据，不是节点存在与否　`[destruction/06#S1]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】用 `shattered_ids: Set[String]` 记录，运行时据此决定显示完整网格还是碎片。

⛔ 靠"节点在不在"判断 →
⚠ 读档后节点是新建的，状态全丢；
⛔ 且破坏过的物件在下次进入场景时**又变回完整的**。

【产出】`DestructionWorld.shattered_ids`

【判据】⛔ 读档后已碎物件**仍是碎的**

【审】`audit/godot/destruction-cloth.md#7`

### Step 2　⚠ 结构连通要显式建模，别靠物理自己塌　`[destruction/06#S2]`

【读】`howto/godot/destruction-cloth.md#1. 预切分 vs 动态切割`

【做】用结构图记录承重关系：打断某节点 → 遍历失去支撑的上层并触发其碎裂。

⛔ 指望刚体自己堆叠坍塌 →
⚠ 堆叠稳定性差（官方：Jolt 才"better stacking stability"），
⛔ 且表现不可控——玩家打断柱子，上面可能纹丝不动，也可能整片乱飞。

【产出】`structural_graph` 与连通判定

【判据】⛔ 打断承重柱后，失去支撑的部分**确实塌**

【审】`audit/godot/destruction-cloth.md#43`

### Step 3　⚠ 掉落走同一条掉落链，不单独写一套　`[destruction/06#S3]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】破坏掉落调用既有掉落接口。

⛔ 单独写一套 → 掉落概率、保底、日志、反作弊**各走各的**，
⚠ 表现为"破坏掉的东西统计里查不到"。

【产出】掉落走统一入口

【判据】⚠ 破坏掉落与击杀掉落在同一份统计里

【审】`audit/godot/destruction-cloth.md#41`

### Step 4　⚠ 破坏改变可行走区域时，导航要重烘　`[destruction/06#S4]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】破坏打通/堵死通路后触发导航重烘。

⛔ 不重烘 → AI 撞在"已经不存在的墙"上，
⚠ 表现为"打穿了门，怪却绕远路"，⛔ 极易被当成 AI 寻路 bug 排查。

【产出】破坏 → 导航重烘的接线

【判据】⚠ 打穿墙后 AI **走新路**

【审】`audit/godot/destruction-cloth.md#42`

### Step 5　⛔ 存档存已碎 ID 集合，不存碎片 transform　`[destruction/06#S5]`

【读】`howto/godot/destruction-cloth.md#4. 碎片刚体的休眠与回收`

【做】只序列化 `shattered_ids`。

⛔ 存碎片的 transform/速度 →
⚠ 存档随破坏次数线性膨胀；
⛔ 且碎片是**瞬时表现**，读档后理应是"已经碎完、碎片已回收"的状态，
复原一堆半空中的碎片毫无意义。

【产出】存档字段 `shattered_ids`

【判据】⛔ 存档大小**不随破坏次数增长**

【审】`audit/godot/destruction-cloth.md#17`

### Step 6　⚠ 风只吹软体，要吹碎片必须自己施力　`[destruction/06#S6]`

【读】`howto/godot/destruction-cloth.md#12. 风力只作用于软体（跨域澄清）`

【做】想让碎片被风吹，自己 `apply_force`（且先唤醒）。

⛔ 以为 `Area3D` 的风能吹动碎片 →
官方在 `wind_force_magnitude` 与 `wind_source_path` 两处**各写了一遍**
*"Wind force only applies to SoftBody3D nodes"*。
⚠ 碎片若已休眠，`apply_force` **唤不醒**（见 03/S4），要先 `apply_impulse` 或置 `sleeping = false`。

【产出】碎片受风的实现（若需要）

【判据】⚠ 需要碎片被吹时，碎片**确实会动**

【审】`audit/godot/destruction-cloth.md#37`

## 5. 常见返工

**① 靠节点存在与否判断。** 读档全丢。

**② 指望物理自己塌。** 表现不可控。

**③ 掉落另写一套。** 统计查不到。

**④ 存碎片 transform。** 存档膨胀。
