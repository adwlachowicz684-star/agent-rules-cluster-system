# 01 破坏方案定型（destruction 域）

> **前置**：无（本域地基）
> **本步交付**：**预切分 / 动态切割 / 预设破坏簇 三选一，写下来**
> **对应**：做法 `howto/godot/destruction-cloth.md#0. 先认清：没有内置破坏系统`
> 　　　审核 `audit/godot/destruction-cloth.md#1`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：反正东西会碎。**

⛔ 常见假完成：直接开写 `shatter()`、先调冲量、先看碎片飞得爽不爽，
而**方案从没写下来**。
⚠ 等要做"整面墙任意位置都能打穿"时才发现预切分撑不住，
⛔ 02 烘焙的凸包、03 的切状态逻辑、04 的池子**全部推倒**。

做完这一步，应该能**当场演示**：

1. 写明了用哪种方案，以及为什么
2. ⛔ 知道 Godot **没有**内置破坏系统，不会去找不存在的节点
3. ⚠ 知道碎裂峰值发生在哪一步
4. ⚠ 物理引擎已定（Jolt / GodotPhysics）
5. ⛔ 知道本方案撑不住时的降级路径

**产出物**（下游按名字对接）：

```text
DestructionPlan: scheme ∈ {PRESPLIT, DYNAMIC_CUT, PRESET_CLUSTER}
退化路径：PRESPLIT 撑不住 → PRESET_CLUSTER + 装饰粒子
```

## 1. 前置检查清单

- [ ] ⚠ 已知没有 `DestructibleBody3D`、没有实时 Voronoi 破碎器
- [ ] 已确认破坏是否需要"任意位置都能打"
- [ ] 已定物理引擎（4.6+ 新项目默认 Jolt）
- [ ] 已确认是否需要布料/软体（决定走不走 05）

## 2. 工序

### Step 1　⛔ 先认清没有内置破坏系统，别去找不存在的节点　`[destruction/01#S1]`

【读】`howto/godot/destruction-cloth.md#0. 先认清：没有内置破坏系统`

【做】明确记录：Godot 无 `DestructibleBody3D`、无实时网格切割节点、无 Voronoi 破碎器，全部自实现。

⛔ 不知道这点 → 花时间找内置节点 / 装插件后才发现要自己拼，
⚠ 且社区插件要**校验是否针对目标版本 API 与 Jolt 重编译**。

【产出】`DestructionPlan.scheme` 的候选清单

【判据】⛔ 能说清"没有内置，本方案是自实现的哪条路径"

【审】`audit/godot/destruction-cloth.md#1`

### Step 2　⛔ 默认走预切分凸碎片，动态切割只在窄场景用　`[destruction/01#S2]`

【读】`howto/godot/destruction-cloth.md#1. 预切分 vs 动态切割`

【做】默认选预切分凸碎片：离线切好，运行时只切状态。

⛔ 默认选动态切割 → 要自己做 CSG/BSP、凸分解、拓扑缝合、法线 UV 重建，
⚠ 官方口径是**实时动态切割只有短裂纹适合运行时**。

【产出】`scheme = PRESPLIT`（默认）

【判据】⚠ 运行时不做凸分解（见 02/S1）

【审】`audit/godot/destruction-cloth.md#6`

### Step 3　⚠ 动态切割只在短裂纹 / 规则切缝下才划算　`[destruction/01#S3]`

【读】`howto/godot/destruction-cloth.md#1. 预切分 vs 动态切割`

【做】只有"短裂纹、规则切缝"这类**切分结果可预期**的需求才选动态切割。

⛔ 用它去做全网格任意破坏 → 拓扑缝合与 UV 重建复杂度爆炸，
⚠ 且切分结果不可预期会让 02 的资产预算失效。

【产出】动态切割的适用边界（写下来）

【判据】⚠ 选了动态切割时，能列出"哪些形状是允许被切的"

【审】`audit/godot/destruction-cloth.md#6`

### Step 4　⛔ 全网格任意破坏要降级，不要硬做　`[destruction/01#S4]`

【读】`howto/godot/destruction-cloth.md#1. 预切分 vs 动态切割`

【做】需求是"任意位置都能打"时，降级为预设破坏簇 + 装饰粒子。

⛔ 硬做实时全网格切割 → 主线程卡死（破坏瞬间从零算全部顶点），
⚠ 且这条坑在**只有几个物件时测不出来**，物件一多才爆。

【产出】降级路径写进 `DestructionPlan`

【判据】⚠ 存在明确的降级路径，而不是"到时候再说"

【审】`audit/godot/destruction-cloth.md#3`

### Step 5　⚠ 物理引擎先定，因为参数会随引擎变　`[destruction/01#S5]`

【读】`howto/godot/destruction-cloth.md#7. 物理引擎选择`

【做】定 `physics/3d/physics_engine`，并记下版本。

⛔ 不定 → 02 烘焙的凸包、04 的休眠阈值、05 的软体参数
在切换引擎后**全部要重调**。
⚠ 4.6+ **新项目**默认 Jolt，**旧项目不会自动切**；
⚠ 4.7 软体 `mass` 默认值与 `linear_stiffness` 算法又变了。

【产出】引擎选择 + 版本记录

【判据】⚠ 有明确记录，且升级版本时会回看这一条

【审】`audit/godot/destruction-cloth.md#14`
