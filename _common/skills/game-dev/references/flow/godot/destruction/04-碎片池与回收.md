# 04 碎片池与回收（destruction 域）

> **前置**：03 完成
> **本步交付**：**池化的碎片：有寿命回收、会 reset 插值、能防穿透**
> **对应**：做法 `howto/godot/destruction-cloth.md#4. 碎片刚体的休眠与回收`
> 　　　审核 `audit/godot/destruction-cloth.md#17`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：碎片会消失。**

⛔ 常见假完成：只做了休眠，没做回收。
⚠ 官方口径很清楚：**休眠只省 CPU，不省内存和实例数** ——
打碎 100 个物件后场景里几千个节点，即使全部休眠，遍历与内存仍在涨。

做完这一步，应该能**当场演示**：

1. ⛔ 池化有**寿命回收**（超时淡出或回池），不只是休眠
2. ⛔ 从池取出时调 `reset_physics_interpolation()`
3. ⚠ 小而快的碎片开了 `continuous_cd`
4. ⛔ 需要"不动但能挡"的碎片用的是 `StaticBody3D`
5. ⚠ 性能调优前先定位峰值（GC-06）

**产出物**（下游按名字对接）：

```text
FragmentPool: acquire() / release() / MAX_ALIVE / lifetime
回收策略：超时淡出 → 回池
```

## 2. 工序

### Step 1　⚠ 调优前先定位峰值，不要凭感觉　`[destruction/04#S1]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】用 profiler 定位：峰值在切分/凸包/刚体创建/渲染上传，还是长尾物理。

⛔ 凭感觉优化 → 官方明确峰值**不在长尾物理**，
⚠ 把力气花在"减少物理 tick"上，实际开销在刚体创建那一帧。
ⓘ 这是 GC-06 先定位再优化的典型场景。

【产出】峰值归属结论

【判据】⚠ 能说出本项目的峰值落在哪一步

【审】`audit/godot/destruction-cloth.md#40`

### Step 2　⛔ 池化必须有寿命回收，休眠不算回收　`[destruction/04#S2]`

【读】`howto/godot/destruction-cloth.md#4. 碎片刚体的休眠与回收`

【做】碎片有 `lifetime`，超时淡出或直接回池。

⛔ 只休眠不回收 → 打碎 100 个物件后场景里几千节点，
⚠ 表现为**越玩越卡**，且重启前不会恢复。

【产出】`FragmentPool.lifetime` 与回池路径

【判据】⛔ 打碎 100 个物件后活动节点数**回到基线**

【审】`audit/godot/destruction-cloth.md#17`

### Step 3　⛔ 从池取出必须 reset 物理插值　`[destruction/04#S3]`

【读】`howto/godot/destruction-cloth.md#8. 物理插值：碎片瞬移必须 reset，软体完全不受插值影响`

【做】`global_transform = t` 后紧接 `reset_physics_interpolation()`。

⛔ 少了这行 → 碎片**拖一条长影**（streaking）。
ⓘ 池化必然瞬移，这正是官方明确要求 reset 的场景，不是可选优化。
⚠ 症状只在开了物理插值时出现，关掉插值就"好了"——
于是容易被误判成"插值功能有问题"。

【产出】`_spawn()` 中的 reset 调用

【判据】⛔ 开插值状态下碎片**无拖影**

【审】`audit/godot/destruction-cloth.md#26`

### Step 4　⚠ 小而快的碎片要开 continuous_cd　`[destruction/04#S4]`

【读】`howto/godot/destruction-cloth.md#9. 小而快的碎片会穿墙：continuous_cd 与 tick 率`

【做】碎片 `continuous_cd = true`（或提高 tick 率 / 换 Jolt）。

⛔ 不开 → 小而快的碎片**穿过薄墙**。
ⓘ 数值直觉：60 Hz 下 60 m/s 每 tick 走 1 米，墙厚不足就有风险。
⚠ 别指望 `contact_monitor` 能救：它是**事后**上报，
且 `max_contacts_reported` 默认 0 → 一条都不报。

【产出】CCD 策略

【判据】⛔ 高速碎片打薄墙**不穿透**

【审】`audit/godot/destruction-cloth.md#28`

### Step 5　⛔ "不动但能挡"的碎片用 StaticBody3D，不用 freeze 的刚体　`[destruction/04#S5]`

【读】`howto/godot/destruction-cloth.md#4. 碎片刚体的休眠与回收`

【做】需要永久静止但仍要挡住玩家的碎片，改用 `StaticBody3D` / `AnimatableBody3D`。

⛔ 用 `freeze = true` 的 `RigidBody3D` →
官方原话：*"For a body that is always frozen, use StaticBody3D or
AnimatableBody3D instead."*
⚠ 表现为静止碎片仍在参与刚体求解，白花开销。

【产出】静止碎片的节点类型约定

【判据】⛔ 没有"永久 freeze"的 RigidBody 碎片

【审】`audit/godot/destruction-cloth.md#25`

## 5. 常见返工

**① 只休眠不回收。** 越玩越卡。

**② 不 reset 插值。** 碎片拖影。

**③ 不开 CCD。** 穿墙。

**④ freeze 刚体当静态。** 白花求解开销。
