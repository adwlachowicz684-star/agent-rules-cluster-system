# 02 碎片资产与凸包预烘焙（destruction 域）

> **前置**：01 完成
> **本步交付**：**离线烘焙好的凸包碎片集，带冲量权重、共享材质**
> **对应**：做法 `howto/godot/destruction-cloth.md#2. 碎片池化与预算`
> 　　　审核 `audit/godot/destruction-cloth.md#2`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：碎片能飞、形状看着对。**

⛔ 常见假完成：运行时调 `create_multiple_convex_collisions()` 现算凸包。
⚠ 只有一个物件打碎时完全看不出问题，
⛔ 而**运行时凸分解正是"碎裂峰值"的一部分** ——
同时打碎几个就卡帧。

做完这一步，应该能**当场演示**：

1. ⛔ 凸包是**离线烘焙**的，运行时不凸分解
2. ⚠ 凹网格用的是**凸代理**，不是 `Mesh` 碰撞体
3. ⚠ 能用盒子近似的碎片**没用凸包**
4. ⛔ 材质是**共享**的，没有 `Resource.duplicate()`
5. ⚠ 每个碎片带冲量权重（供 03 分配初速度）

**产出物**（下游按名字对接）：

```text
FragmentSet: fragments[i] = { transform, convex_hull, impulse_scale, mass }
材质：共享引用，非逐碎片副本
```

- [ ] 01 已定方案（决定烘焙什么）
- [ ] ⚠ 已知运行时凸分解是峰值来源之一
- [ ] 已知哪些碎片可以用基元形状近似
- [ ] 已确认材质是否需要按碎片变色（决定能否共享）

## 2. 工序

### Step 1　⛔ 凸包必须离线预烘焙，运行时不凸分解　`[destruction/02#S1]`

【读】`howto/godot/destruction-cloth.md#5. 碰撞形状选型：官方的性能排序`

【做】编辑器里选中 `MeshInstance3D` → 视口上方 Mesh 菜单 →
Create Multiple Convex Collision Siblings，存成资产。

⛔ 运行时脚本调 `create_multiple_convex_collisions()` →
⚠ 这正是碎裂峰值的一部分（切分/凸包/刚体创建/渲染上传挤在一帧），
⛔ 且只在"同时碎多个"时才暴露。

【产出】离线烘焙的凸包资产

【判据】⛔ 全局 grep 不到运行时凸分解调用

【审】`audit/godot/destruction-cloth.md#3`

### Step 2　⛔ 凹网格用凸代理，不能转单一碰撞体　`[destruction/02#S2]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】凹网格拆成多个凸代理。

⛔ 直接用 `Mesh` 碰撞体（trimesh）→
官方三条警告：**最慢**、只适配静态体（动态碎片不能用）、**空心**会被小而快的物体穿透。

【产出】每个碎片的 `ConvexPolygonShape3D`

【判据】⛔ 没有动态碎片用 `ConcavePolygonShape3D`

【审】`audit/godot/destruction-cloth.md#18`

### Step 3　⚠ 能用盒子近似就别用凸包　`[destruction/02#S3]`

【读】`howto/godot/destruction-cloth.md#5. 碰撞形状选型：官方的性能排序`

【做】碎片形状能用一个 `BoxShape3D` / `SphereShape3D` 近似的，用基元。

⛔ 一律上凸包 → 官方明确 `ConvexPolygonShape3D` **比球/盒等基元慢**，
且建议"先考虑基元形状"。
⚠ 碎片碰撞形状**不是越精确越好** —— 凸近似足够，精确更贵。

【产出】形状选型记录（哪些用基元、哪些必须凸包）

【判据】⚠ 有相当比例的碎片用基元形状

【审】`audit/godot/destruction-cloth.md#4`

### Step 4　⛔ 材质共享，切分时不要复制全部材质　`[destruction/02#S4]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】碎片共享同一份材质资源。

⛔ 每个碎片 `Resource.duplicate()` 一份材质 →
⚠ 显存与 draw call 双双上涨，
⛔ 且表现为"碎得越多越卡"，很容易被误判成物理开销。

【产出】共享材质引用

【判据】⛔ 碎片创建路径里没有 `duplicate()`

【审】`audit/godot/destruction-cloth.md#5`

### Step 5　⚠ 每个碎片带冲量权重，别全用同一个值　`[destruction/02#S5]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】在资产里为每片写 `impulse_scale`。

⛔ 所有碎片用同一个冲量 → 碎裂像"整体炸开"，
⚠ 而真实的碎裂是**离爆心近的飞得快**。
ⓘ 权重要在资产里可配，否则美术改一次形状就要程序员改一次代码（GC-03）。

【产出】`fragments[i].impulse_scale`

【判据】⚠ 爆心附近的碎片明显快于边缘碎片

【审】`audit/godot/destruction-cloth.md#4`

## 5. 常见返工

**① 运行时凸分解。** 碎裂卡帧。

**② 碎片用 trimesh。** 最慢 + 会被穿透。

**③ 材质逐片复制。** 显存涨、draw call 涨。

**④ 冲量一刀切。** 碎裂不像碎裂。
