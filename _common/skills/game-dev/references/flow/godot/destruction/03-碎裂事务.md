# 03 碎裂事务（destruction 域）

> **前置**：02 完成
> **本步交付**：**一次原子的碎裂：切状态 → 预算内生成 → 分配冲量**
> **对应**：做法 `howto/godot/destruction-cloth.md#2. 碎片池化与预算`
> 　　　审核 `audit/godot/destruction-cloth.md#7`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：打一下，碎片飞出来。**

⛔ 常见假完成：在伤害结算里直接 `queue_free()` 原物件再生成碎片。
⚠ 两个顺序坑都在这里：
**先删后生** → 中间态失败则原物件与碎片同时消失；
**先生后删** → 原物件还在，碎片从它体内冒出来。

做完这一步，应该能**当场演示**：

1. ⛔ 碎裂是**一次事务**：状态切换在前，生成在后
2. ⛔ 活动碎片总数**有上限**（预算）
3. ⚠ 冲量按 `impulse_scale` 分配，不是一刀切
4. ⛔ 一次性冲击用 `apply_impulse`，不是 `apply_force`
5. ⛔ 碎裂由**事件**驱动，伤害逻辑里不直接生成碎片

**产出物**（下游按名字对接）：

```text
shatter(center, impulse) -> void   事务入口
DestructibleState: intact / shattered
MAX_ACTIVE: int                    活动碎片预算
```

## 2. 工序

### Step 1　⛔ 碎裂是一次事务：先切状态，再生成碎片　`[destruction/03#S1]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】`shatter()` 内先置 `state = shattered`，再生成碎片实例。

⛔ 先 `queue_free()` 原物件再生成 →
中间态抛错则**原物件与碎片都没有了**，表现为"打了没反应"。
⛔ 先生成再删原物件 → 碎片从原物件体内冒出，穿模。

【产出】`shatter()` 与 `DestructibleState`

【判据】⛔ 连续快速触发两次，不会重复生成、也不会什么都不剩

【审】`audit/godot/destruction-cloth.md#7`

### Step 2　⛔ 活动碎片总数必须有上限　`[destruction/03#S2]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】`var n := mini(_fragments.size(), MAX_ACTIVE)`，超出部分不生成或用粒子降级。

⛔ 不设上限 → 同时打碎多个物件时**一帧内创建上百刚体**，
⚠ 这正是官方说的峰值来源（切分/凸包/刚体创建/渲染实例上传），
⛔ 且表现为"偶尔卡一下"，很难归因。

【产出】`MAX_ACTIVE` 与超预算降级策略

【判据】⛔ 同时打碎 10 个物件，单帧耗时不出现尖峰

【审】`audit/godot/destruction-cloth.md#7`

### Step 3　⚠ 冲量按权重分配，不是所有碎片同一个值　`[destruction/03#S3]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】`f.apply_impulse(impulse * _fragments[i].impulse_scale)`。

⛔ 一刀切 → 碎裂像"整体炸开"而非"由爆心扩散"。
ⓘ 权重来自 02/S5，本步只负责按它分配。

【产出】冲量分配逻辑

【判据】⚠ 近爆心碎片明显快于边缘碎片

【审】`audit/godot/destruction-cloth.md#4`

### Step 4　⛔ 一次性冲击用 apply_impulse，不是 apply_force　`[destruction/03#S4]`

【读】`howto/godot/destruction-cloth.md#4. 碎片刚体的休眠与回收`

【做】碎裂、爆炸这类一次性冲击一律 `apply_impulse`。

⛔ 用 `apply_force` → **唤不醒休眠的刚体**（需要超过唤醒阈值），
⚠ 症状极具迷惑性：碎片落地休眠后"爆炸把它们推开"完全没反应，
⛔ 排查方向会被引到"力太小"，而实际是**根本没唤醒**。
ⓘ 持续力（如风）才需要先 `sleeping = false` 再 `apply_force`。

【产出】冲击一律走 impulse 的约定

【判据】⛔ 对已休眠的碎片施加冲击，碎片**确实会动**

【审】`audit/godot/destruction-cloth.md#16`

### Step 5　⛔ 破坏瞬间不要从零计算全部顶点　`[destruction/03#S5]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】顶点/凸包/刚体全部来自 02 的预烘焙，运行时只切状态。

⛔ 运行时算 → **主线程卡死**。
⚠ 只在物件少的时候测不出来。

【产出】运行时零几何计算

【判据】⛔ 碎裂函数内无顶点遍历 / 无凸分解

【审】`audit/godot/destruction-cloth.md#3`

### Step 6　⛔ 碎裂必须由事件驱动，伤害里不直接生成碎片　`[destruction/03#S6]`

【读】`howto/godot/destruction-cloth.md#2. 碎片池化与预算`

【做】伤害结算只发 `damaged` 事件，可破坏物件自己订阅并调 `shatter()`。

⛔ 在伤害逻辑里直接调碎裂 →
伤害模块要知道所有可破坏类型，⚠ 违反 GC-04 事件解耦，
⛔ 且新增一种可破坏物件就要改伤害模块。

【产出】`damaged` 事件 + 订阅方

【判据】⚠ 新增一种可破坏物件，伤害模块**不用改**

【审】`audit/godot/destruction-cloth.md#7`

## 5. 常见返工

**① 先删后生。** 中间态失败两边都没了。

**② 不设预算。** 一帧几百刚体。

**③ 用 force 推开碎片。** 唤不醒，没反应。

**④ 伤害里直接碎。** 耦合，加类型要改伤害。
