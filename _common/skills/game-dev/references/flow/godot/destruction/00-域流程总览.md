# 破坏 / 布料 / 软体 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只要碎成几块、能飞 | **不要套本域** → 见下 |
| 可破坏物件（打碎花瓶/木箱） | 01 → 02 → 03 → 07 |
| 大量破坏、要控性能 | 01 → 02 → 03 → 04 → 07 |
| 旗帜/披风/软垫会飘 | 01 → 05 → 07 |
| 破坏影响玩法（开路、掉材料） | 01 → 02 → 03 → 06 → 07 |
| 角色死亡布娃娃 | 01 → 05 → 07 |
| 全套 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只会消失、不产生碎片的不要套本域。**
⚠ 那属于 `howto/godot/combat.md` 与 `vfx-feel.md` 的范围——
本域处理的是**碎片是真实物理体、要池化、要回收**的复杂度。

ⓘ 分工：
- `howto/godot/destruction-cloth.md` 讲**单个要素怎么配**（预切分/凸包/软体参数/休眠）
- 本域讲**这些要素按什么顺序做、怎么管状态**

⛔ 若本域某步需要"凸分解怎么生成"这类细节，
指向那篇，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 破坏方案定型 | — | 预切分 / 动态 / 预设簇三选一 |
| 02 | 碎片资产与凸包预烘焙 | 01 | 离线凸包 + 共享材质 + 冲量权重 |
| 03 | 碎裂事务 | 02 | 切状态 → 分配冲量 → 预算内生成 |
| 04 | 碎片池与回收 | 03 | 池化 + 休眠策略 + 寿命回收 + reset 插值 |
| 05 | 布料与软体 | 01 | SoftBody3D 配置 + 父碰撞忽略 + 风力 |
| 06 | 破坏与玩法联动 | 03 | 结构连通 + 掉落 + 存档恢复 |
| 07 | 破坏布料验收 | 全部 | 峰值/穿透/拖影/回收/读档实测 |

⚠ **01 必须在一切之前**：方案不定，02 不知道烘焙什么、03 不知道切什么状态。
⚠ **02 必须在 03 之前**：运行时才做凸分解 = 碎裂卡帧（见 01/S4）。
⚠ **03 必须在 04 之前**：没有统一的生成入口，池化无处可挂。
⚠ **03 必须在 06 之前**：玩法联动订阅的是"某个物件已碎"这个事件。

## 2. 与其他域的接缝

| 接缝 | 契约 |
|---|---|
| `combat` 域 伤害 | 伤害只是触发条件，碎裂走本域 03，不在伤害里直接生成碎片 |
| `weather` 域 风 | ⚠ 官方：风力**只作用于 SoftBody3D**，吹不动碎片（见 05/S4） |
| `camera` 域 相机 | 物理插值下相机要 `top_level`，屏震可能被插值平滑掉（见 04/S4） |
| `level` 域 关卡 | 破坏改变可行走区域，导航要重烘（见 06/S4） |
| `save` 域 存档 | 存"哪些已碎"的 ID 集合，不存碎片 transform（见 06/S5） |
| `vegetation` 域 植被 | 砍树是本域 03 的调用方，共用碎片池 |
| `performance` 域 性能 | 峰值定位走 GC-06，先测再调（见 04/S1） |

⛔ **若某条接缝对不上，要单独立一个接线功能点**。

## 3. 本域最容易做反的顺序

⛔ **先做碎裂表现（03）再做方案定型（01）。**

"打碎东西"是最直观的需求，
于是先写 `shatter()`、先调冲量、先看碎片飞得爽不爽，
⚠ 而此时**方案还没定** ——
等要做"整面墙任意位置都能打穿"时，
才发现预切分撑不住、要改动态切割，
⛔ 而 02 烘焙的凸包、03 的切状态逻辑、04 的池子**全部要推倒**。

✅ 正确顺序：先定方案（01），再烘焙资产（02），最后才做碎裂（03）。

⛔ 第二容易做反的：**先做布料（05）再做碎裂（03）。**
布料视觉反馈强，先做了会让人以为"物理这块搞定了"，
⚠ 而碎裂是**峰值型**开销、布料是**持续型**开销，
两者的预算模型完全不同（见 04/S1）。
