# 06 运行时实例与热重载（配置表域）

> **前置**：05 已能取到只读模板
> **本步交付**：运行时数据从模板**安全拷贝**而来；改表后能重载（或明确说清要重启）
> **对应**：做法 `howto/godot/datatable.md` · 审核 `audit/godot/datatable.md`

## 0. 交付物定义

⚠ **本步是全域最容易出事故的地方。**
"改一个全改"是 Godot 4 的 #1 新手 bug，而它的根因只有一句话：
**每行同一份 Resource 会被共享。**

做完这一步，应该能**当场演示**：

1. 从模板拷贝出实例，改实例的数值，**模板不变**
2. ⚠ 用 `duplicate_deep(DEEP_DUPLICATE_INTERNAL)`，不是 `duplicate(false)`
3. 每个配表类的 `_init()` 无必需参数（否则 `duplicate()` 失败）
4. ⚠ 改 CSV 后重载，**已有实例已处理**（不是"重新 load 就完事"）
5. 已实测深拷贝耗时（大表批量生成时不掉帧）

**产出物**（下游按名字对接）：

```text
SkillData.instantiate_runtime() -> SkillData   从模板造实例
Data.reload()                                   重载：重建索引 + 通知持有者
```

## 2. 工序

### Step 1　⛔ 绝不能直接用模板当实例　`[datatable/06#S1]`

【读】`howto/godot/datatable.md#2. Resource 作为配表载体` 的 ⚠

【做】⚠ **表结构里的"运行时状态"禁止写进 Resource** ——
每行同一份 Resource 会被共享，写进去就全改了。

ⓘ 判断标准：**这个字段会不会因为玩家行为而改变？**
会 → 运行时状态，必须在拷贝出来的实例上。

【产出】运行时数据一律来自拷贝，模板只被读

【判据】⚠ 造两个实例，改其中一个的冷却，**另一个不变**

【审】`audit/godot/datatable.md#3`（Resource 存运行时状态没事 → 会被共享）

### Step 2　duplicate 的精确语义　`[datatable/06#S2]`

【读】`howto/godot/datatable.md#7. duplicate 的精确语义（4.x 官方文档口径）`

【做】⚠ "深拷贝"在 Godot 里**不是**"全复制"：

| 调用 | 官方说明 |
|---|---|
| `duplicate(false)` | 浅拷贝：嵌套 Array / Dictionary / **Resource 都不复制，与原对象共享** |
| `duplicate(true)` | 递归复制嵌套数组字典；⚠ **其中的 Resource 只有 "local" 的才复制**，等价于 `DEEP_DUPLICATE_INTERNAL` |

```gdscript
template.duplicate_deep(Resource.DEEP_DUPLICATE_INTERNAL) as SkillData
```

⚠ **两个额外约束**：

1. ⛔ **自定义 Resource 若 `_init()` 有必需参数，`duplicate()` 会失败。**
2. `duplicate(true)` 时**每个资源只复制一次**：
   若 A 引用 B 两次，得到的新 A' 引用**同一个** B' 两次（⛔ 不是两个独立的 B'）。

⚠ **这才是"改一个全改"的源头**——
`duplicate()` 默认浅拷贝会共享子资源。

【产出】统一走 `duplicate_deep(DEEP_DUPLICATE_INTERNAL)`

【判据】⚠ 改实例里的**嵌套数组**，模板不受影响

【审】`audit/godot/datatable.md#4` `audit/godot/datatable.md#5`

### Step 3　DEEP_DUPLICATE_ALL 什么时候用　`[datatable/06#S3]`

【读】`howto/godot/datatable.md#7. duplicate 的精确语义（4.x 官方文档口径）`

【做】三级模式：

| 模式 | 行为 | 用在哪 |
|---|---|---|
| （不复制） | 子资源共享 | ⛔ 配表实例不要用 |
| `DEEP_DUPLICATE_INTERNAL` | 只复制无路径/场景本地的子资源 | ✅ **配表实例默认** |
| `DEEP_DUPLICATE_ALL` | 全部复制，含单独存的大资源 | ⚠ 会把纹理模型也复制一份 |

⚠ `DEEP_DUPLICATE_ALL` 会把**单独存储的大资源也复制**——
图标、网格、音频被复制一份，内存翻倍。

ⓘ 配表实例通常**希望共享图标纹理**（几十个火球共享一张图是对的），
所以 `INTERNAL` 是默认正确选择。

【产出】全项目只用 INTERNAL（除非有明确理由）

【判据】⚠ 造 100 个实例，内存增长**不含图标纹理部分**

【审】`audit/godot/datatable.md#5`

### Step 4　⛔ 热重载不是"重新 load 一次"　`[datatable/06#S4]`

【读】`howto/godot/datatable.md#9. 缓存、热重载与"重新 load 没用"`

【做】⚠ **热重载不是"重新 `load()` 一次"** ——
已有实例和运行时索引不会自动刷新。

三个相关事实：
1. `ResourceLoader.has_cached(path)` 可查缓存；
   资源一旦加载就**缓存在内存**，后续 `load()` 返回同一引用。
2. `Resource.take_over_path(path)` 可**覆盖**某路径的缓存条目
   （直接设 `resource_path` 在该路径已有缓存时会报错）。
3. 真正的热重载必须：重新生成资源 → `take_over_path` → **重建索引**
   → **通知持有旧实例的地方重建**，或重启当前关卡。

【产出】若要热重载：有明确的"重建 + 通知"路径

【判据】⚠ 改 CSV 后触发重载，**已存在的技能实例数值真的变了**

【审】`audit/godot/datatable.md#10`（改了表重新 load 就热重载了 → 已有实例不会刷新）

### Step 5　接受"改表重启"是合法选择　`[datatable/06#S5]`

【读】`howto/godot/datatable.md#9. 缓存、热重载与"重新 load 没用"`

【做】ⓘ 很多项目选"改表重启游戏"——**这是合法且常见的选择**。

⚠ 但要在文档里**明确写出来**，⛔ 不能让策划以为改了表就能立刻看到。
否则会出现"我改了啊怎么没变"的反复沟通。

✅ 折中方案：**开发期支持热重载**（方便调数值），
**发布版只支持重启**（省掉一整套通知逻辑）。

【产出】已在 00 总览里写明重载策略

【判据】⚠ 团队里每个人都知道"改表后要做什么"

【审】`audit/godot/datatable.md#10`

### Step 6　批量拷贝的耗时　`[datatable/06#S6]`

【读】`howto/godot/datatable.md#7. duplicate 的精确语义（4.x 官方文档口径）`

【做】⚠ 深拷贝不是免费的。批量生成时（开战造 50 个怪物数据）
要实测耗时。

ⓘ 若实测成为瓶颈，考虑：
- 只在**真正要改**时才拷贝（不变的直接共享模板）
- 用对象池复用实例

【产出】批量拷贝耗时已实测

【判据】⚠ 一次生成 100 个实例，**不掉帧**（或已做池化）

【审】`audit/godot/datatable.md#5`

## 3. 参考实现

```gdscript
# skill_data.gd
class_name SkillData extends Resource

@export var id: StringName
@export var base_damage: int
@export var icon: Texture2D          # ⚠ 共享是对的，别复制

# ⛔ 不要写 func _init(p_id, p_dmg) —— duplicate() 会失败

func instantiate_runtime() -> SkillData:
    # ⚠ 统一入口，避免各处写出不同的拷贝深度
    var inst := duplicate_deep(Resource.DEEP_DUPLICATE_INTERNAL) as SkillData
    return inst
```

```gdscript
# 调用方
var skill := Data.get_skill(&"skill.fireball")     # 只读模板
var runtime := skill.instantiate_runtime()          # ✅ 改这个
runtime.current_cooldown = 0.0
```

⚠ `instantiate_runtime()` 做成**统一入口**很重要——
如果每个调用方各写一行 `duplicate(...)`，
一定会有人写成 `duplicate()` 或 `duplicate(false)`，
然后花三天查"为什么改冷却会影响所有人"。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 改一个冷却全服都变 | 直接用了模板 / 浅拷贝 | S1 S2 |
| duplicate 返回 null | `_init()` 有必需参数 | S2 |
| 内存翻倍 | 用了 DEEP_DUPLICATE_ALL | S3 |
