## 2. 工序

### Step 1　⛔ 导入期校验拦不住历史存档　`[datatable/07#S1]`

【读】`howto/godot/datatable.md#11. 版本演进：删行与历史存档`

【做】⚠ **导入期校验能拦住"新增的悬空引用"，拦不住历史存档里已有的 ID。**

玩家存档里存着 `skill.fireball`（v3），而 v5 删掉了这一行——
导入期校验通过（表里没问题），**运行时读档才炸**。

【产出】已确认读档路径对"找不到 ID"有处理

【判据】⚠ 用一份**引用已删除 ID** 的存档读档，**不崩**

【审】`audit/godot/datatable.md#6`

### Step 2　三种删行策略选一个　`[datatable/07#S2]`

【读】`howto/godot/datatable.md#11. 版本演进：删行与历史存档`

【做】三选一：

| 策略 | 做法 | 代价 |
|---|---|---|
| **永不删除** | 只标记 `deprecated` | 表会膨胀，但最安全 |
| **重定向表** | 保留 `old_id -> new_id` 映射，读档时翻译 | 要维护映射 |
| **兜底替换** | 找不到就换成默认项并记录 | 玩家会感到物品变了 |

⚠ 无论选哪种，**读档时都不要崩**——
配表问题是数据问题，⛔ 不应该让玩家丢档。

ⓘ 推荐组合：**永不删除为主 + 兜底替换兜底**。
重定向表维护成本高，只在 ID 大规模改名时才值得。

【产出】删行策略已选定并写进文档

【判据】⚠ 构造"存档引用已删 ID"的场景，按策略处理且**有日志**

【审】`audit/godot/datatable.md#6`

### Step 3　产物 diff 干净　`[datatable/07#S3]`

【读】`howto/godot/datatable.md#3. 导入期校验是必做步骤`

【做】⚠ 改一个数值 → 产物 diff **只有那一行**。

⛔ 若 diff 里有 UID 变化、子资源路径变化、顺序变化，
说明导入不幂等（见 03 S6），会让代码评审失效。

【产出】改一个数值后 `git diff` 只有一处

【判据】⚠ 改一个数值，diff 行数 **< 5 行**

【审】`audit/godot/datatable.md#7`

### Step 4　全局扫一遍模板写入　`[datatable/07#S4]`

【读】`howto/godot/datatable.md#2. Resource 作为配表载体`

【做】⚠ 全项目搜索对 `Data.get_*()` 结果的赋值。

⛔ 任何一处漏网都会造成"改一个全改"，
而这种 bug 的排查成本极高（症状与原因隔了十万八千里）。

【产出】扫描结果为空，或每处都有 `instantiate_runtime()`

【判据】⚠ 搜索结果为 0（或有明确的处理）

【审】`audit/godot/datatable.md#3` `audit/godot/datatable.md#4` `audit/godot/datatable.md#5`
