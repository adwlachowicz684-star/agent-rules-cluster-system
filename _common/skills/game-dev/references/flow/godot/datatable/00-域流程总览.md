# 配置表域 — 流程总览

> **本域交付**：一套"策划改数值不用程序员重新导出"的数据管线——从 CSV 到只读模板，再到运行时实例，全程有校验。
> **对应**：做法 `howto/godot/datatable.md`
> 　　　审核 `audit/godot/datatable.md`

---

## 0. 先定做什么（⛔ 没写这三行不许开工）

⚠ 同在配置表域，"把几个技能数值搬到 CSV"和"建一套带校验的导入管线"
是**两条不同流程**——后者是前者的十倍工作量。

```text
做什么：<哪几张表、谁来编辑、要不要校验、要不要热重载>
不做什么：⛔ <至少两条>
验收标准：<可观测的>
```

示例（本次只搬技能数值）：

```text
做什么：技能数值搬到 CSV，导入生成 .tres，运行时只读
不做什么：⛔ 不做导入期校验（本次只有 20 行，人工核对）
         ⛔ 不做热重载（改表重启游戏）
验收标准：改 CSV 的数值后重启，游戏内生效；
         策划改 CSV 不需要我改代码；
         .tres 是只读模板，运行时实例改了不影响模板
```

### 然后挑功能点

| 本次要做的 | 需要的功能点 |
|---|---|
| 只是把数值搬出代码 | 01 → 02 → 05 → 07 |
| 策划要自己编辑 | 01 → 02 → 03 → 05 → 07 |
| 表会变大、会多人协作 | 01 → 02 → 03 → 04 → 05 → 07 |
| 有运行时实例（技能/物品/角色属性） | 01 → 02 → 05 → 06 → 07 |
| 要支持改表不重启 | 01–07 全做（06 的热重载部分） |

⛔ **不要全做。** 三张表的项目不需要校验管线。

## 1. 功能点拆解与依赖顺序

```text
01 边界与格式选型 ── 02 表结构与 schema ── 03 导入管线 ── 04 导入期校验 ──┐
                                                                        │
        └────────── 05 运行时加载与索引 ── 06 实例深拷贝与热重载 ────────┴── 07 版本演进与验收
```

| # | 功能点 | 前置 | 为什么这个顺序 |
|---|---|---|---|
| 01 | 配表边界与格式选型 | 无 | ⚠ 什么该配表、什么该硬编码——定错后面全是返工 |
| 02 | 表结构与 schema 定义 | 01 | 先定字段与 ID 规范，再写导入器 |
| 03 | 导入管线与常量生成 | 02 | 有 schema 才知道 CSV 列怎么映射 |
| 04 | 导入期校验 | 03 | ⚠ 校验挂在导入器里，不能独立存在 |
| 05 | 运行时加载与索引 | 02 03 | 先有产物才能加载 |
| 06 | 运行时实例与热重载 | 05 | ⚠ 实例从模板拷贝，先有模板 |
| 07 | 版本演进与验收 | 01–06 | 链路完整才谈得上演进 |

---

## 2. ⚠ 五个最容易做反的顺序

**① 先写代码后搬数据。**
用硬编码数值写完整个系统，再"抽"成配表。
⛔ 结果是配表字段照着当时的代码结构定，后面加一个字段要改两处。

**② 先做导入器后定 ID 规范。**
ID 是**跨系统的契约**（战斗、背包、存档都引用它）。
导入器写完再改 ID 规则，等于所有引用处全改。

**③ 校验做成警告。**
⚠ **校验失败应该报错并阻止导入**，不是警告——
否则坏数据进了包，问题会在运行时以**完全无关的形式**出现。

**④ 运行时直接改模板。**
⛔ 每行同一份 Resource 会被共享，写进去就全改了。
这是 Godot 4 的 #1 新手 bug，而且症状是"改一个全改"，很难定位。

**⑤ 最后才考虑删行。**
⚠ **导入期校验能拦住新增的悬空引用，拦不住历史存档里已有的 ID。**
玩家存档存着 v3 的 ID，v5 删了那一行——校验通过，读档才炸。

## 3. 每做完一个功能点必做

1. 跑一遍该步的**验收清单**，逐条打勾
2. ⛔ 有没过的，不进下一步
3. 过该步【审】列的 audit 条目
4. 过功能点末尾的「整体审核」节
5. ⚠ 实测参数已回填，⛔ 不留示例值
