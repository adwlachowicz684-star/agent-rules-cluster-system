# 03 帧数据与判定窗（战斗结算域）

> **前置**：01 已有 hitbox（默认关闭），02 已有结算入口
> **本步交付**：攻击有明确的前摇/判定帧/后摇，判定窗由**动画事件**驱动而不是计时器
> **对应**：做法 `howto/godot/combat.md` · 审核 `audit/godot/combat.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 按攻击键后**先出招再判定**（有可感知的前摇），不是按键瞬间就命中
2. 改动画时长后，判定窗**自动跟着变**，不用改代码
3. 判定结束后立刻关 hitbox，不会拖着判定进后摇
4. 连按攻击键时，输入被缓冲而不是被吞掉

**产出物**（下游按名字对接）：

```text
AttackData (Resource)   startup / active / recovery / cancel_windows
AnimationPlayer 上的 Call Method Track：begin_attack() / end_attack()
InputBuffer            全局唯一，供 06 连招取消读取
```

⚠ `AttackData` 做成 Resource 是关键——策划在 Inspector 里改前后摇，
⛔ 不用改代码。

## 2. 工序

### Step 1　定义三段帧数据　`[combat/03#S1]`

【读】`howto/godot/combat.md#3. 帧数据（动作游戏的地基）`

【做】
```
startup（前摇） → active（判定帧） → recovery（后摇）
```

| 段 | 手感意义 |
|---|---|
| startup | 太长 = 迟钝；太短 = 无预兆 |
| active | 决定"能不能打中" |
| recovery | 太长 = 惩罚重；可取消 = 连招空间 |

写成 `AttackData` Resource：`startup / active / recovery` 三个字段。

【产出】`attack_data.gd`（Resource），Inspector 里能改三段时长

【判据】把 startup 改成 0.5 秒，能明显看到"按了键要等一下才出手"

【审】`audit/godot/combat.md#11` `audit/godot/combat.md#41`（动画时长用计时器对齐 → 要用 Call Method Track）

### Step 2　用 Call Method Track 驱动判定窗　`[combat/03#S2]`

【读】`howto/godot/combat.md#3. 帧数据` 与 `#6. 技能系统` 的 ⚠ 提示

【做】在 `AnimationPlayer` 的攻击动画上：
- active 帧起点 → Call Method Track 调 `hitbox.begin_attack()`
- active 帧终点 → Call Method Track 调 `hitbox.end_attack()`

⛔ **不要用** `await get_tree().create_timer(0.3).timeout` 猜时间点。

【产出】改动画时长后判定窗自动跟随

【判据】⚠ **把动画时长拉长一倍，判定窗跟着延后一倍，且不改一行代码**

【审】`audit/godot/combat.md#11`（动画一改就错 → 用 Call Method Track）

### Step 3　判定服从固定步长　`[combat/03#S3]`

【读】`howto/godot/combat.md#3. 帧数据` 的 ⚠ 提示

【做】判定逻辑放 `_physics_process`；表现层可以插值。

⚠ 判定跟渲染帧走 → 高刷屏和低帧机器手感不一致。

【产出】判定相关逻辑全部在固定步长内

【判据】⚠ 帧率上限 30 与 240 下，同一次攻击的命中结果**完全一致**

【审】`audit/godot/combat.md#3`（帧率不同手感不同）

### Step 4　区分 BUFFER 与 INSTANT 取消窗　`[combat/03#S4]`

【读】`howto/godot/combat.md#8.6 连招与取消：窗口是区间，表是配置`

【做】取消窗口 ⛔ 不是布尔，要区分两种：

| 类型 | 含义 |
|---|---|
| **BUFFER** | 提前输入被记下，到窗口就放 |
| **INSTANT** | 恰好落在窗口内才立即取消 |

⚠ 「动画播完自动连」是**设计内容**，不是便利功能。
要显式 `CancelTable`，换武器只换数据。

【产出】`AttackData.cancel_windows` 是配置表，不是硬编码 if-else

【判据】⚠ 换一把武器（换 Resource）后连招派生不同，且**不改代码**

【审】`audit/godot/combat.md#35`（取消窗口是个布尔 → 要区分 BUFFER / INSTANT）
　　　`#36`（「动画播完自动连」→ 要显式 CancelTable）
　　　`#37`（优先级靠 if-else 书写顺序 → 要写成常量数组）

### Step 5　全局唯一的输入缓冲　`[combat/03#S5]`

【读】`howto/godot/combat.md#8.6 连招与取消`

【做】`InputBuffer` **全局唯一**，各状态读取并消费。
⛔ 每个状态各存一份 → 会出现"这个状态读了、那个状态没读"的幽灵输入。

【产出】`InputBuffer` 单例；任意状态机状态都能 `consume()` 到同一次输入

【判据】⚠ 在 startup 期间按攻击键，active 结束后**确实**接上了下一段

【审】`audit/godot/combat.md#15`（连招吃键是玩家手慢 → 缺输入缓冲）
　　　`#38`（每个状态各存一份 InputBuffer → 要全局唯一）

## 3. 参考实现

```gdscript
# attack_data.gd —— ⚠ Resource，策划可配
class_name AttackData
extends Resource

@export var anim_name: StringName = &"attack_1"
@export var startup: float = 0.08
@export var active: float = 0.06
@export var recovery: float = 0.20
@export var damage: float = 10.0
@export var cancel_windows: Array[CancelWindow] = []

# cancel_window.gd
class_name CancelWindow
extends Resource
enum Kind { BUFFER, INSTANT }     # ⚠ 两种语义不同，不能合成布尔
@export var kind: Kind = Kind.BUFFER
@export var from_phase: StringName = &"recovery"
@export var at_ratio: float = 0.5
@export var to_attack: StringName = &"attack_2"
@export var priority: int = 0     # ⚠ 优先级是数据，不是 if-else 顺序

# input_buffer.gd —— autoload，全局唯一
extends Node
var _buf: Dictionary = {}

func press(action: StringName) -> void:
    _buf[action] = Time.get_ticks_msec()

func consume(action: StringName, window_ms: int) -> bool:
    var t: int = _buf.get(action, 0)
    if t == 0: return false
    if Time.get_ticks_msec() - t > window_ms:
        return false
    _buf.erase(action)            # ⚠ 消费掉，不留幽灵输入
    return true
```

⚠ `InputBuffer` 用 `Time.get_ticks_msec()`，⛔ 不要用系统时间
（系统时间可改表，见 `howto/godot/security.md`）。
