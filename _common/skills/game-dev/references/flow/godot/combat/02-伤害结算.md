# 02 伤害结算（战斗结算域）

> **前置**：01 命中判定已产出 `AttackContext` 与 `CombatResolver.resolve_hit()` 入口
> **本步交付**：一个**顺序写死、可复现**的结算管线，输出 `HitResponse` 并发出伤害信号
> **对应**：做法 `howto/godot/combat.md` · 审核 `audit/godot/combat.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 同样的攻击、同样的状态，打出的伤害**每次都一样**（或只在设计允许的随机范围内）
2. 暴击、格挡、闪避三者的判定顺序**固定**，玩家能形成预期
3. 加一个 +50% 攻击的 buff 后，伤害按"乘区"规则变化，不是意外叠加
4. ⚠ 伤害还没接到血条上也能验证（只看 `print` 的数值）

**产出物**（下游按名字对接）：

```text
CombatResolver.resolve_hit(target, ctx) -> HitResponse
damage_applied 信号   携带 target / final_amount / response / is_crit
DamageFormula        纯函数，输入 ctx + 属性 → 输出最终数值
```

⚠ `DamageFormula` 必须是**纯函数**——同样的输入永远给同样的输出，
这样 05 打击感（需要根据暴击/格挡分支播不同反馈）和 06 对抗层才能稳定对接。

## 2. 工序

### Step 1　写死结算顺序　`[combat/02#S1]`

【读】`howto/godot/combat.md#4. 伤害公式：先定顺序，再定数值`

【做】推荐顺序，⚠ **写进代码注释，不许边写边改**：

```
1. 是否命中    （闪避判定）
2. 是否格挡    （防御框 / 朝向）
3. 是否暴击
4. 基础×加成   （乘区）
5. 减抗性      （加区/乘区）
6. 应用伤害
7. 触发后续    （反击、吸血、连击计数）
```

⚠ **先判闪避再判格挡，还是反过来，是设计决策——但必须写死。**
两边都写"随机判定"，玩家永远无法形成预期。

【产出】`resolve_hit()` 的分支顺序与上面 7 步一一对应

【判据】⚠ **对照检查**：把代码分支从上到下念一遍，与注释里的 7 步完全一致

【审】`audit/godot/combat.md#6`（暴击和格挡都随机判 → 顺序必须写死）

### Step 2　乘区与加区分开　`[combat/02#S2]`

【读】`howto/godot/combat.md#4. 伤害公式` 末尾 ⚠ 与 `#5. Buff / Debuff` 的修改器顺序

【做】属性修改器统一按：

```text
最终值 = (基础 + flat 加成) × (1 + percent 加成)
```

⚠ 全用乘区会**指数爆炸**，全用加区后期**无成长感**。
⛔ 混在一起算会出现"两个 +50% 叠成 +125%"这类意外。

【产出】`DamageFormula` 里 flat 与 percent 是两个独立列表，先加后乘

【判据】⚠ 两个 +50% 的 percent buff → 结果应是 ×2.0，**不是** ×2.25
（若得到 2.25，说明 percent 走了连乘）

【审】`audit/godot/combat.md#7`（buff 数值加起来就行 → flat 与 percent 要分顺序）

### Step 3　返回 HitResponse，不直接改状态　`[combat/02#S3]`

【读】`howto/godot/combat.md#0. 四层分离` 与 `#1. AttackContext` 的 enum

【做】`resolve_hit()` 返回 `HitResponse`（ACCEPTED / BLOCKED / DODGED /
IMMUNE / DEAD / CONSUMED），由**调用方或监听者**决定后续。

⚠ 攻防双方 ⛔ **不要互相持引用**。靠事件与 `AttackContext` 解耦，
结果用**返回码**回流——否则加一个新状态要改所有武器。

【产出】`resolve_hit()` 有返回值，且不直接 `target.hp -= x` 之外的副作用

【判据】单测：传入"必定闪避"的目标，返回 `DODGED` 且 hp 不变

【审】`audit/godot/combat.md#39`（攻防双方互相持引用 → 要靠事件与 AttackContext 解耦）

### Step 4　发出伤害信号　`[combat/02#S4]`

【读】`howto/godot/combat.md#0. 四层分离` 的事件流

【做】结算完成后 emit `damage_applied(target, final_amount, response, is_crit)`。

⚠ 扣血与表现**分离**：结算层只改数值并发信号，血条/飘字/受击动画由监听者做。

【产出】血条、飘字、受击动画都能通过**只订阅信号**实现，不需要改结算代码

【判据】⚠ 临时加一个"打印伤害"的监听者，不改 `resolve_hit` 一行代码

【审】`audit/godot/combat.md#9`（buff 自己播特效 → 状态应只管数据）

### Step 5　同输入同输出（可复现性）　`[combat/02#S5]`

【读】`howto/godot/combat.md#4. 伤害公式` 与 `#3. 帧数据` 的固定步长原则

【做】`DamageFormula` 做成纯函数；随机（暴击）用**可注入的种子**，
⛔ 不要直接散落 `randi()`。

【产出】传入相同 ctx + 相同属性对象 → 返回相同数值

【判据】⚠ 固定随机数种子后，连续跑 100 次同参数结算，结果**完全一致**

【审】`audit/godot/combat.md#6`（顺序写死才能复现）

## 3. 参考实现

```gdscript
# combat_resolver.gd —— autoload 或场景内单例
extends Node
class_name CombatResolver

signal damage_applied(target, final_amount, response, is_crit)

## ⚠ 结算顺序（写死，不许改）：
## 1 闪避 2 格挡 3 暴击 4 乘区 5 抗性 6 应用 7 后续
func resolve_hit(target: Node, ctx: AttackContext) -> AttackContext.HitResponse:
    var resp := _evaluate(target, ctx)      # 1–3：判定分支
    if resp != AttackContext.HitResponse.ACCEPTED:
        return resp                          # 闪避/格挡/免疫直接回流

    var amount := DamageFormula.compute(ctx, target.stats)   # 4–5：纯函数
    target.stats.hp -= amount                                 # 6：应用
    var is_dead := target.stats.hp <= 0.0
    damage_applied.emit(target, amount, resp, ctx.is_crit)   # 发信号
    return AttackContext.HitResponse.DEAD if is_dead else AttackContext.HitResponse.ACCEPTED

# damage_formula.gd —— ⚠ 纯函数，同输入必同输出
static func compute(ctx: AttackContext, stats) -> float:
    var flat := 0.0
    var percent := 0.0
    for m in stats.get_modifiers(ctx.damage_tag):
        if m.is_percent: percent += m.value
        else:            flat    += m.value
    var base := ctx.base_amount
    var raw := (base + flat) * (1.0 + percent)   # ⚠ 先加后乘
    if ctx.is_crit: raw *= ctx.crit_multiplier
    raw -= ctx.flat_reduction                    # 抗性（加区）
    raw *= (1.0 - ctx.percent_reduction)         # 抗性（乘区）
    return maxf(raw, 1.0)                        # ⚠ 设下限，避免 0 伤害的意外分支
```

⚠ `maxf(raw, 1.0)` 的下限是设计决策——有些游戏要允许 0 伤害（用于触发效果）。
⛔ 不要默认成 0，否则"打不死但也没反馈"是最难查的手感问题。

## 5. 常见返工

|---|---|---|
