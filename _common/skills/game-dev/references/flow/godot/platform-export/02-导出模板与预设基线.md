# 02 导出模板与预设基线（多平台导出与发布域）

> **本步交付**：模板版本锁定 + 预设名 + 资源过滤器 + 工具链版本
> **对应**：流程 `howto/godot/platform-export.md` · 审核 `audit/godot/platform-export.md`

## 0. 交付物定义

1. 导出模板版本已锁定，且与编辑器版本精确匹配
2. 预设名已定下并进版本库，⛔ 后续不再改
3. 非资源文件已在 `Resources > Filters` 显式登记
4. Android 工具链版本已按矩阵配好，Gradle 构建模板已装
5. 渲染器按平台覆盖已落进项目设置，不维护两套工程

## 1. 前置检查清单

- [ ] 模板版本与编辑器版本（含 beta/rc 状态）完全一致
- [ ] 预设名已确定，且 CI 脚本已用同一名字
- [ ] 外部 `.json` / `.txt` 已在过滤器里登记
- [ ] Android NDK 精确到 r28b，Gradle 构建模板已按项目安装
- [ ] ⚠ 渲染器按平台覆盖已生效，不是两套工程

## 2. 工序

### Step 1　导出模板版本必须与编辑器精确匹配，含 beta/rc　`[platform-export/02#S1]`

【读】`howto/godot/platform-export.md#0. 导出模板`

【做】
确认模板版本与编辑器版本完全一致，写进团队文档。
⛔ "版本差不多就行" —— 导出模板是**独立于编辑器的下载项**，
4.3.2 的编辑器配 4.3.1 的模板会失败，⛔ beta / rc 这些状态也算在版本里。

⛔ 失败形态极具误导性：报的是"各种奇怪错误"，
而不是"版本不匹配"。表现为升级编辑器后导出突然全线报错，
⛔ 排查被引向项目配置或平台工具链，不会想到是模板没跟着升。

ⓘ 升级编辑器后要**重新下载**匹配模板，这不是可选项。
ⓘ `export_presets.cfg` 建议进版本库，让全队共用同一套导出配置。

【产出】模板版本锁定记录 + 升级编辑器的配套动作

【判据】能说出当前编辑器版本与模板版本，且两者字符串一致。

【审】`audit/godot/platform-export.md#18`

### Step 2　预设名一次定下，进版本库后不再改　`[platform-export/02#S2]`

【读】`howto/godot/platform-export.md#7. 命令行导出与 CI（预设名是硬匹配）`

【做】
定下每个预设的名字，写进 CI 脚本，之后不再改。
⛔ 预设名是**硬匹配** —— `"Windows"` 配不出名为 `"Windows Desktop"` 的预设，
⛔ 且失败信息不会提示"是不是名字写错了"。
名字含空格或特殊字符时**必须加引号**。

⛔ 改名是最隐蔽的一类破坏：编辑器里点选预设仍能正常导出，
⛔ 只有 CI 会失败 —— 于是表现为"我本地能出包、CI 出不了"，
排查被引向 CI 环境而不是一次改名。

ⓘ 预设名同时是 CLI 导出的唯一标识，
所以它属于**对外契约**，不是内部命名习惯。

【产出】预设名清单（与 CI 脚本逐字一致）

【判据】CI 脚本里的预设名与 `export_presets.cfg` 里的逐字相同。

【审】`audit/godot/platform-export.md#20`

### Step 3　非资源文件要在过滤器里显式登记　`[platform-export/02#S3]`

【读】`howto/godot/platform-export.md#7. 命令行导出与 CI（预设名是硬匹配）`

【做】
把外部数据文件（`.json`、`.txt` 等）加进预设的 `Resources > Filters`。
⛔ 以为"在项目目录里就会被打进包" ——
非资源文件**不会自动包含**，必须显式加过滤规则（如 `*.json`）。

⛔ 这是最典型的"编辑器能跑、导出后不行"：
导出过程**完全无警告**，⛔ 而运行时报错是"文件不存在"或读取返回空，
排查被引向路径拼接或打包逻辑，不会想到是过滤器没配。

ⓘ 与之同源的是 `res://` 只读：导出后往 `res://` 写**静默失败**，
⛔ 所以"读不到"和"写不进"都要在这一步一并确认。

【产出】过滤器规则清单 + 导出后实际校验文件存在

【判据】解开产物（PCK / APK）能看到那些外部文件。

【审】`audit/godot/platform-export.md#21`

### Step 4　Android 工具链按版本矩阵配，Gradle 模板按项目装　`[platform-export/02#S4]`

【读】`howto/godot/platform-export.md#8. Android：Gradle 构建模板要按项目装一次`

【做】
按官方矩阵配好 JDK 17 / Build-Tools / Platform / NDK，并装 Gradle 构建模板。
⛔ **NDK 必须精确到 r28b** —— 4.7 的 Gradle 模板锁死这个版本，
换成更新的 NDK 会构建失败。这是"Gradle 构建失败"最高频的原因，
⛔ 而报错是 Gradle 的 Java 错误栈，⛔ 完全不提 NDK 版本。

⛔ 还有第二层坑：预设勾了 `Use Gradle Build` 时，
编辑器要求项目内有 `res://android/build/`，
来自 `Project > Install Android Build Template`（**每项目一次**，目录要提交）。
缺它时报"路径找不到，指向 templates 文件夹"，
⛔ 看起来像导出模板没装，于是反复重装几百 MB 的模板包 —— 而根因在项目里。

ⓘ Linux 上别用发行版仓库里的 Android SDK，普遍过时。
ⓘ AAB 输出也依赖 Gradle 模板：没装时导出下拉里只有 APK。

【产出】工具链版本矩阵记录 + `res://android/build/` 已提交

【判据】新建一个干净克隆（含 android/build 目录）能直接出包。

【审】`audit/godot/platform-export.md#5`、`audit/godot/platform-export.md#22`

### Step 5　渲染器按平台覆盖落进项目设置，不维护两套工程　`[platform-export/02#S5]`

【读】`howto/godot/platform-export.md#1. 各平台速查表`

【做】
用按平台覆盖机制（如 `rendering/renderer/rendering_method.mobile`）
让 Web 走 Compatibility、桌面走 Forward+。
⛔ 复制一份工程改成 Compatibility 专门出 Web 包 ——
两套工程的配置会**无声漂移**：资源导入设置、插件、预设各不相同，
⛔ 表现为"Web 版有个桌面版没有的 bug"，而它在两套工程里无法复现对照。

⛔ Web 只有 Compatibility 是硬限制，不是性能取舍：
Forward+ 和 Mobile 依赖 Vulkan / D3D12 / Metal，Web 上全部用不上。
⛔ 所以"Web 版降级"不是可选优化，是唯一路径。

【产出】项目设置里的按平台覆盖清单

【判据】同一份工程不改动即可导出 Web 与桌面两种产物。

【审】`audit/godot/platform-export.md#1`

## 3. 参考实现

```
# ⓘ 承接本步产出：版本与名称都是对外契约，写进文件而不是记在脑子里
# docs/release/toolchain.md

编辑器版本        4.7.2.stable
导出模板版本      4.7.2.stable      ⛔ 含状态，必须与上一行一致

预设名（CI 硬匹配，改名会静默破坏 CI）：
  "Windows Desktop"     →  build/windows/game.exe
  "Web"                 →  build/web/index.html

资源过滤器（非资源文件不会自动进包）：
  *.json, *.txt

Android 工具链（NDK 必须精确到 r28b）：
  JDK 17 / Build-Tools 35.0.1 / Platform android-35 / NDK 28.1.13356709
  res://android/build/   ← Project > Install Android Build Template，每项目一次
```
