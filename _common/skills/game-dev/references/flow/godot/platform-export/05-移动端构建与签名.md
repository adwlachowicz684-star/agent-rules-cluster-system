# 05 移动端构建与签名（多平台导出与发布域）

> **本步交付**：Android 工具链/keystore/权限 + iOS 三件套与 Xcode 工程
> **对应**：流程 `howto/godot/platform-export.md` · 审核 `audit/godot/platform-export.md`

## 0. 交付物定义

1. Android 工具链按官方矩阵配好，无"最新版"侥幸
2. Gradle 构建模板已按项目安装并入库
3. 架构与纹理压缩口径一致
4. Keystore 已加密存储 + 多人备份，密码分开保管
5. 权限按最小必要勾选，敏感权限走运行时申请
6. iOS 三件套已配齐，Xcode 工程命名与导出目录已按官方要求

## 1. 前置检查清单

- [ ] JDK 17 / Build-Tools / Platform / NDK r28b 齐备
- [ ] `res://android/build/` 已生成并入库
- [ ] 架构清单与纹理压缩设置一致
- [ ] release keystore 已备份，密码分开保管
- [ ] 权限清单与实际收集一致
- [ ] ⚠ iOS：Team ID 为 10 位代码，工程名无空格，导出目录为空

## 2. 工序

### Step 1　Android 工具链是版本矩阵，不是"装最新"　`[platform-export/05#S1]`

【读】`howto/godot/platform-export.md#环境是环环相扣的版本矩阵`

【做】
按官方矩阵逐项配好，写进团队文档。
⛔ 装最新版 —— **NDK 必须精确到 r28b**，4.7 的 Gradle 模板锁死这个版本，
换成更新的 NDK 会构建失败。这是"Gradle 构建失败"最高频的原因。

⛔ 报错形态极具误导性：是 Gradle 的 Java 错误栈，
⛔ 完全不提 NDK 版本，排查被引向 JDK 或 Gradle 配置。

ⓘ Linux 用户别用发行版仓库里的 Android SDK，普遍过时 ——
⛔ 而"SDK 太旧"的报错同样不指向 SDK 版本。

【产出】工具链版本矩阵记录（含 NDK 精确版本）

【判据】文档里的 NDK 版本号与官方矩阵逐字相同。

【审】`audit/godot/platform-export.md#5`、`audit/godot/platform-export.md#17`

### Step 2　Gradle 构建模板按项目装一次，目录要入库　`[platform-export/05#S2]`

【读】`howto/godot/platform-export.md#8. Android：Gradle 构建模板要按项目装一次`

【做】
执行 `Project > Install Android Build Template`，把 `res://android/build/` 提交进版本库。
⛔ 以为装了编辑器导出模板就够 —— 预设勾了 `Use Gradle Build` 时，
编辑器要求项目内有这个目录，**每个项目一次**。

⛔ 缺它时报"路径找不到，指向 templates 文件夹"，
⛔ 看起来像导出模板没装，于是反复重装几百 MB 的模板包 —— 而根因在项目里。
⛔ 团队里表现为"我这儿能出包、同事出不了"，排查被引向环境差异。

ⓘ AAB 输出也依赖它：没装时导出下拉里只有 APK。

【产出】`res://android/build/` 已提交

【判据】新克隆的仓库（不含本机模板）能直接出包。

【审】`audit/godot/platform-export.md#22`

### Step 3　架构与纹理压缩口径一致，别为兼容翻倍　`[platform-export/05#S3]`

【读】`howto/godot/platform-export.md#架构与纹理压缩`

【做】
确认架构清单，并让项目设置与导出预设的纹理压缩口径一致。
⛔ 把 arm64-v8a 和 armeabi-v7a 都勾上"兼容更全" ——
arm64 已覆盖 2015 年后所有主流设备，⛔ 加 v7a 的代价是**包体翻倍**。

⛔ 纹理压缩是**联动**的：项目设置的 `Import ETC2 ASTC`
与导出预设的 `For Mobile` **必须一致**，不一致会触发导出校验失败。
表现为"导出报错但看不出是哪个设置错了"。

ⓘ ETC2 是 Android 最稳妥默认（通用），ASTC 质量好但需硬件支持。
ⓘ 一张 2048² 贴图从 16MB 压到 2MB ——
⛔ 这个差距对低端机**是否崩溃**有决定性影响。

【产出】架构清单 + 纹理压缩一致口径

【判据】项目设置与导出预设的压缩选项可互相印证。

【审】`audit/godot/platform-export.md#16`、`audit/godot/platform-export.md#34`

### Step 4　Keystore 丢了包名永久报废，备份是发布门禁　`[platform-export/05#S4]`

【读】`howto/godot/platform-export.md#Keystore 一旦丢了，包名永久报废`

【做】
release keystore 加密存储 + 多人备份 + 密码分开保管。
⛔ 以为丢了能找回 —— **不能**。同名包再也无法更新，
只能换包名重新上架，⛔ **流失全部评价**。

⛔ 这条的残酷之处在于：它在**一切正常时完全不可见**，
⛔ 只在换机器、重装系统、换人接手时才爆发，
而那时已经无法补救 —— 所以备份必须在第一次出包之前就做完。

ⓘ 同时确认 `Export With Debug` 已取消（见 03/S3）：
debug 签名与已装正式版冲突，报"解析包时出现问题"，
⛔ 而这个提示完全不指向签名。

【产出】keystore 备份位置记录（多人）+ 密码分开保管说明

【判据】能说出至少两个备份位置和它们的保管人。

【审】`audit/godot/platform-export.md#7`

### Step 5　权限按最小必要勾选，敏感权限走运行时申请　`[platform-export/05#S5]`

【读】`howto/godot/platform-export.md#4. Android`

【做】
权限清单逐项对应实际收集，敏感权限用 `OS.request_permission()` 运行时申请。
⛔ 全勾省事 —— Google Play 数据安全表单按实际收集申报，
⛔ **多报会被下架**。

⛔ 表现为"审核被拒"，而拒因描述指向数据收集声明，
⛔ 排查被引向隐私政策文案，不会想到是预设里多勾了一个权限。

ⓘ 权限清单必须与合规域的数据收集清单**同源**（见 `compliance/02`），
⛔ 两处各自维护必然漂移。

【产出】权限清单（每项对应实际用途）+ 与合规清单的一致性说明

【判据】预设里每个权限都能指到实际使用的那一行代码。

【审】`audit/godot/platform-export.md#8`

### Step 6　iOS 三件套之外，Xcode 工程有三个静默坑　`[platform-export/05#S6]`

【读】`howto/godot/platform-export.md#9. iOS：Xcode 工程的三个静默坑`

【做】
配齐证书 / App ID / Provisioning Profile，并同时核对工程命名与导出目录。
⛔ 只盯三件套 —— 官方另有三条要求，⛔ **症状全是"签名失败"**，
而三件套本身可能全是对的：

1. 导出目录**必须是空文件夹**
2. Xcode 工程名⛔ **不能带空格**（会损坏 Xcode 工程文件）
3. `godot_project_to_export` ⛔ **不得**与 `exported_xcode_project_name` 同名（导致签名问题）

⛔ Team ID 填错还有一条特别的：官方记录的错误是
`JSON text did not start with array or object and option to allow fragments not set`
—— 官方明确说这是 Team ID 格式错（要 10 位 `ABCDE12XYZ`，
⛔ 不是 Xcode 在 Signing & Capabilities 里显示的"你的名字"）。
⛔ 这条报错**看起来是 JSON 解析问题**，会把排查引向完全无关的方向。

ⓘ iOS 模拟器导出目前不支持（GH-102149）；
Apple Silicon Mac 可直接运行 iOS app，不必走模拟器。

【产出】三件套配置记录 + 工程命名/导出目录检查记录

【判据】Team ID 为 10 位代码；工程名无空格；两处名字不同；导出目录为空。

【审】`audit/godot/platform-export.md#24`、`audit/godot/platform-export.md#25`、`audit/godot/platform-export.md#26`、`audit/godot/platform-export.md#23`、`audit/godot/platform-export.md#27`

## 3. 参考实现

```bash
# ⓘ 承接本步产出：工具链与签名凭据都是一次性损失巨大的东西
# S1 Android 工具链（NDK 必须精确到 r28b）
sdkmanager --sdk_root="$ANDROID_HOME" "platform-tools" "build-tools;35.0.1" \
  "platforms;android-35" "cmdline-tools;latest" \
  "cmake;3.10.2.4988404" "ndk;28.1.13356709"

# S4 release keystore（⛔ 丢了包名永久报废，必须多人备份）
keytool -v -genkey -keystore mygame.keystore -alias mygame \
        -keyalg RSA -validity 10000
```

```
# S6 iOS 导出时的四项检查（⛔ 症状全是"签名失败"）
导出目录            = 空文件夹
Xcode 工程名        = MyGame            ⛔ 不含空格
godot_project_to_export = godot_project ⛔ 不得与上一行同名
App Store Team ID   = ABCDE12XYZ        ⛔ 10 位代码，不是 Xcode 显示的姓名
```

## 4. 验收清单

- [ ] NDK 为 r28b，工具链其余项与官方矩阵一致
- [ ] `res://android/build/` 已入库，新克隆能出包
- [ ] 架构未为兼容翻倍；纹理压缩两处一致
- [ ] keystore 有 ≥2 个备份位置，密码分开保管
- [ ] 权限清单与实际收集一致，与合规清单同源

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| Gradle 构建失败（Java 错误栈） | NDK 不是 r28b / SDK 过时 | S1 |
| 我这儿能出包、同事出不了 | 构建模板没入库 | S2 |
| 导出校验失败 / 包体翻倍 | 压缩口径不一致 / 多勾架构 | S3 |
| 换机器后无法更新应用 | keystore 丢失 | S4 |
| 商店审核被拒（数据收集） | 权限多勾 | S5 |
| iOS 签名失败但三件套都对 | 空格 / 同名 / 非空目录 / Team ID 格式 | S6 |
