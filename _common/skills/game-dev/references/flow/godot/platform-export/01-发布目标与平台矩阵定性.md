# 01 发布目标与平台矩阵定性（多平台导出与发布域）

> **本步交付**：平台清单 + 各维度限制表 + 构建环境可得性
> **对应**：流程 `howto/godot/platform-export.md` · 审核 `audit/godot/platform-export.md`

## 0. 交付物定义

1. 要上的平台清单已写下，且每个平台能说出为什么在清单里
2. 渲染器、线程、存档持久性三项已按平台分级
3. 每个目标平台的构建环境可得性已确认（不是"到时候再想办法"）
4. 签名与公证需求已按平台列出
5. 架构与包体预算已定
6. ⛔ 不在清单里的平台已明确排除，不会中途插入

## 1. 前置检查清单

- [ ] 平台清单已写下，不是口头约定
- [ ] 每个平台的渲染器限制已查过（尤其 Web 只有 Compatibility）
- [ ] 存档持久性已按平台分级，Web 已标为"中低"
- [ ] iOS / macOS 的构建主机已确认可得（物理机或 CI）
- [ ] 各平台是否需要签名/公证已列出
- [ ] ⚠ 包体预算已按最受限的平台定

## 2. 工序

### Step 1　平台清单先定死，它决定渲染器选型　`[platform-export/01#S1]`

【读】`howto/godot/platform-export.md#1. 各平台速查表`

【做】
写下这次要上的平台，并从速查表推出每项的渲染器限制。
⛔ 先做完游戏再决定上哪些平台 —— 渲染器是**立项级**的不可回退选择：
Web 只有 Compatibility 一条路，而 Forward+ / Mobile 依赖 Vulkan、D3D12、Metal，
在 Web 上**全部用不上**。

⛔ 更要命的是 Compatibility 下的静默降级：`GPUParticles2D/3D` 在
Compatibility 下**粒子不出现、无报错**。
表现为"桌面端好好的、Web 端特效全没了"，
⛔ 排查必然被引向资源打包或粒子参数，不会想到是渲染后端。

ⓘ 正确做法是按平台覆盖渲染器，让 Web 走 Compatibility、桌面走 Forward+，
⛔ 而不是维护两套工程 —— 两套工程的配置漂移是长期成本。

【产出】平台清单 + 每平台的渲染器结论

【判据】指着清单里每个平台，能说出它用哪个渲染器、依据是哪一行。

【审】`audit/godot/platform-export.md#1`

### Step 2　存档路径与持久性按平台分级，Web 单列一档　`[platform-export/01#S2]`

【读】`howto/godot/platform-export.md#6. Web`

【做】
把存档持久性按平台分级，Web 单独标为"中低"。
⛔ 用"都是 `user://`"一句话带过 —— 路径一样，**可靠性完全不同**：
原生平台是真实文件系统，Web 端 `user://` 是 IndexedDB，
⛔ 禁用 Cookie、无痕模式、配额超限都可能导致拒绝写入或定期清理。

⛔ `OS.is_userfs_persistent()` 官方明示**会误报**，
所以"检测通过"不等于真的能存住 —— 它只是个提示。
表现为"检测说能存，玩家还是反馈进度没了"，
⛔ 排查会被引向存档代码，而根因在浏览器策略。

ⓘ 存档统一走 `user://`：导出后 `res://` 只读，
⛔ 往那里写**静默失败**，连报错都没有。

【产出】存档持久性分级表 + Web 端的降级提示方案

【判据】Web 端启动时有持久化检测，且未持久化时玩家看得见提示。

【审】`audit/godot/platform-export.md#30`、`audit/godot/platform-export.md#14`

### Step 3　线程能力按平台定性，Web 是条件开关　`[platform-export/01#S3]`

【读】`howto/godot/platform-export.md#三重硬限制`

【做】
写明每个平台能否用 `Thread`，Web 单独标为"条件开关"。
⛔ 把线程当成全平台通用能力 —— 只有 Web 是条件开关：
`SharedArrayBuffer` **只在跨域隔离的文档里存在**，
需要 `Cross-Origin-Opener-Policy: same-origin` +
`Cross-Origin-Embedder-Policy: require-corp` + 安全上下文，三者缺一不可。

⛔ 托管方能不能配这两个头是**平台级**差异，不是配置细节：
GitHub Pages **默认不能设自定义头**，于是多线程直接不可选。
表现为"本地多线程好好的、上传后黑屏"，
⛔ 排查必然被引向构建产物，不会想到是托管方能力。

【产出】线程能力表 + Web 端的线程结论（开 / 关）+ 托管方头能力

【判据】能说出本次 Web 托管方是否支持自定义头，以及据此定的线程结论。

【审】`audit/godot/platform-export.md#2`、`audit/godot/platform-export.md#4`

### Step 4　构建环境可得性先确认，iOS 最晚不得晚于本步　`[platform-export/01#S4]`

【读】`howto/godot/platform-export.md#5. iOS`

【做】
确认每个目标平台的构建环境是否可得，iOS 明确写下"用哪台 Mac / 哪个 CI"。
⛔ 留到发布前再想办法 —— Windows 上**无法产出可上架的 iOS 包**，
Godot 生成的是 Xcode 工程，编译、签名、归档全靠 Xcode。

⛔ 三条现实路径里没有一条是"临时搞定的"：远程 CI 要配、
借 Mac 要借、而虚拟机/黑苹果违反许可协议且稳定性无保障。
表现为"功能都做完了，iOS 版上不了"，⛔ 而工期是从零开始。

ⓘ 同时确认账号：免费 Apple 账号**不能上架**，需要付费开发者账号。

【产出】每平台的构建环境结论（主机 / CI / 不可得）+ Apple 账号状态

【判据】iOS 那一栏填的是具体机器或具体 CI 服务，不是"待定"。

【审】`audit/godot/platform-export.md#11`、`audit/godot/platform-export.md#12`

### Step 5　签名与公证需求按平台列出，macOS 是硬拦　`[platform-export/01#S5]`

【读】`howto/godot/platform-export.md#3. macOS`

【做】
列出每平台是否需要签名 / 公证，并写明不做时的后果。
⛔ 把签名当成"发布前补一下" —— macOS 上它是**硬拦**不是软提示：
没有 Developer ID 时的 `Built-in (ad-hoc only)` **不能过 Gatekeeper**。

⛔ Gatekeeper 判定链是环环相扣的：签名 → 公证签发 ticket → 联网验证 → 通过。
⛔ 任何一环断掉就弹"无法验证开发者"或"已损坏"，
而这两个提示**都不指向断的是哪一环**。

ⓘ Windows 相反：不签名只是 SmartScreen 弹"未知发布者"，
⛔ 是软拦截不是死路，个人独游完全可以接受 ——
⛔ 不要因为"要签名"这句话把两个平台当成同一件事。

【产出】签名/公证需求表 + 每平台不做时的具体后果

【判据】能说清 macOS 那一行是硬拦、Windows 那一行是软提示。

【审】`audit/godot/platform-export.md#9`、`audit/godot/platform-export.md#28`

### Step 6　架构与包体预算按最受限的平台定　`[platform-export/01#S6]`

【读】`howto/godot/platform-export.md#架构与纹理压缩`

【做】
定下架构清单与包体预算，按**最受限**的平台定，不是按平均定。
⛔ 把 arm64-v8a 和 armeabi-v7a 都勾上"兼容更全" ——
arm64-v8a 已覆盖 2015 年后所有主流设备，⛔ 加上 v7a 的代价是**包体翻倍**。

⛔ 纹理压缩是联动的：项目设置的 `Import ETC2 ASTC`
与导出预设的 `For Mobile` **必须一致**，不一致会触发导出校验失败。
表现为"导出报错但看不出是哪个设置错了"。

ⓘ 一张 2048² 贴图从 16MB 压到 ETC2 的 2MB，
⛔ 这个差距对低端机**是否崩溃**有决定性影响 ——
所以预算要按最低档设备算，不是按自己的开发机算。

【产出】架构清单 + 包体预算 + 纹理压缩口径

【判据】预算表里存在"最低档设备"这一列，且预算按它定。

【审】`audit/godot/platform-export.md#16`、`audit/godot/platform-export.md#34`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：平台能力在启动期一次性定性，玩家代码不散落判断
# autoload: platform_caps.gd
extends Node

# ⓘ 渲染器按平台覆盖（项目设置覆盖），不维护两套工程
# Web → gl_compatibility；桌面 → forward_plus
var threads_ok: bool:
    get:
        if OS.has_feature("web"):
            # ⓘ 单线程是 4.3 起的默认；多线程需 COOP+COEP+HTTPS（见 S3）
            return false
        return true

var save_reliable: bool:
    get:
        if OS.has_feature("web"):
            # ⓘ OS.is_userfs_persistent() 官方明示会误报，只当提示不当保证
            return OS.is_userfs_persistent()
        return true

func _ready() -> void:
    if not save_reliable:
        $UI/WarnPersistent.visible = true   # ⛔ 让玩家看见，不静默
```

## 4. 验收清单

- [ ] 平台清单已写下，每平台渲染器结论可追溯到速查表
- [ ] 存档持久性已分级，Web 单列且启动有降级提示
- [ ] 线程结论已定，依据能追溯到托管方是否支持自定义头
- [ ] iOS 构建环境已填具体机器或 CI，不是"待定"
- [ ] 签名需求已分级，macOS 硬拦 / Windows 软提示已区分
- [ ] 包体预算按最低档设备定，架构未为兼容而翻倍

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| Web 端特效全没了 | 渲染器后端差异，GPUParticles 静默失效 | S1 |
| 玩家反馈进度没了但检测说能存 | `is_userfs_persistent()` 误报 | S2 |
| 上传后黑屏 | 托管方不支持跨域隔离头 | S3 |
| 功能做完了 iOS 上不了 | 构建环境未提前确认 | S4 |
| 用户打不开"已损坏" | macOS 签名链断环 | S5 |
| 低端机崩溃 | 包体预算按开发机算 | S6 |
