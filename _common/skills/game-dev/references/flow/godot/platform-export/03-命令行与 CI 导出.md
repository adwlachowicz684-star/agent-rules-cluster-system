# 03 命令行与 CI 导出（多平台导出与发布域）

> **本步交付**：可复现的导出命令 + release/debug 分离
> **对应**：流程 `howto/godot/platform-export.md` · 审核 `audit/godot/platform-export.md`

## 0. 交付物定义

1. 每个平台的导出命令已写进脚本，可复现
2. 输出路径基准已确认（相对 `project.godot` 目录）
3. release 与 debug 产物已分离，debug 不会进商店
4. 编辑器升级时模板同步升级的动作已固化进 CI
5. 产物形态符合商店要求（AAB / APK 不混用）

## 1. 前置检查清单

- [ ] 导出命令在脚本里，不是手敲
- [ ] 相对路径的基准已验证过一次（不是想当然）
- [ ] release 与 debug 输出目录不同
- [ ] CI 里含模板安装/校验步骤
- [ ] ⚠ 产物形态与商店要求已核对

## 2. 工序

### Step 1　预设名在 CLI 里硬匹配，含空格要引号　`[platform-export/03#S1]`

【读】`howto/godot/platform-export.md#7. 命令行导出与 CI（预设名是硬匹配）`

【做】
在 CI 脚本里用与 `export_presets.cfg` **完全一致**的预设名。
⛔ 手敲一个"差不多"的名字 —— 预设名是硬匹配，
`"Windows"` 配不出 `"Windows Desktop"`，⛔ 且失败信息不提示是名字错了。
名字含空格或特殊字符时**必须加引号**。

⛔ 这条在 CI 上比本地更容易踩：本地是点选预设，永远不会遇到名字问题，
⛔ 于是"名字对不对"这件事在接 CI 之前**从未被验证过**。

ⓘ 必须用 editor 二进制跑导出，不能用导出模板；
无 GPU 的 CI 环境要加 `--headless`。

【产出】CI 脚本里的导出命令（预设名与配置文件逐字一致）

【判据】脚本里的预设名与 `export_presets.cfg` 逐字相同，含空格已加引号。

【审】`audit/godot/platform-export.md#20`

### Step 2　输出路径的基准是 project.godot 目录，不是当前目录　`[platform-export/03#S2]`

【读】`howto/godot/platform-export.md#7. 命令行导出与 CI（预设名是硬匹配）`

【做】
验证一次相对输出路径到底落在哪。
⛔ 官方 Warning：相对路径**相对于包含 `project.godot` 的目录**，
⛔ **不是**当前工作目录。

⛔ 表现为"命令成功、产物找不到"：
在 CI 里换个工作目录跑同一条命令，产物会落在完全不同的地方，
而退出码是 0、日志没有报错，
⛔ 排查被引向构建脚本或权限，不会想到是路径基准。

ⓘ 最省事的规避：CI 里一律用绝对路径，或在脚本开头先 `cd` 到项目根。

【产出】路径基准验证记录 + 脚本里已统一用绝对/已 cd 到根

【判据】换一个工作目录跑同一条命令，产物仍落在预期位置。

【审】`audit/godot/platform-export.md#19`

### Step 3　release 与 debug 产物分开，debug 不进商店　`[platform-export/03#S3]`

【读】`howto/godot/platform-export.md#7. 命令行导出与 CI（预设名是硬匹配）`

【做】
`--export-release` 与 `--export-debug` 输出到不同目录，且 debug 不上传。
⛔ 以为 debug 只是"多个调试符号" —— 它还会开启远程调试与调试检查，
⛔ Android 上更会打出 **debug 签名包**：与已装的正式版签名冲突，
报"解析包时出现问题"，⛔ 而这个提示完全不指向签名。

⛔ 导出预设里的 `Export With Debug` 同理：
忘了取消就打出 debug 签名包，而导出过程**完全无警告**，
表现为"测试时装得上、正式发布后用户装不上"。

ⓘ 两者的差别是"能不能上线"，不是"体积大小" ——
所以产物分离是发布门禁，不是整洁习惯。

【产出】release / debug 输出目录分离 + 预设里 debug 已取消

【判据】发布目录里不存在任何 debug 产物，且预设 `Export With Debug` 未勾选。

【审】`audit/godot/platform-export.md#29`

### Step 4　编辑器升级时模板同步升级，动作固化进 CI　`[platform-export/03#S4]`

【读】`howto/godot/platform-export.md#0. 导出模板`

【做】
把"编辑器版本 → 模板版本"的对应关系写进 CI，让不匹配直接失败。
⛔ 靠人记得升级模板 —— 模板是独立下载项，
⛔ 不匹配时报的是"各种奇怪错误"而不是"版本不匹配"。

⛔ 这条在 CI 上尤其致命：CI 机器上的编辑器可能是镜像里的旧版，
而模板是另一时刻装的，⛔ 两者的不匹配**只在出包时才暴露**，
而且表现为平台相关的杂错，排查被引向平台配置。

ⓘ 校验方式很轻：CI 启动时比对编辑器版本与已装模板版本，不等即失败。

【产出】CI 里的版本一致性校验步骤

【判据】故意把模板版本改错，CI 在建包前就失败并说明是版本问题。

【审】`audit/godot/platform-export.md#18`

### Step 5　产物形态按商店要求产出，AAB 与 APK 不混用　`[platform-export/03#S5]`

【读】`howto/godot/platform-export.md#APK vs AAB`

【做】
按发布渠道确认产物形态：Google Play 用 AAB，侧载与测试用 APK。
⛔ 打 APK 传 Google Play —— 自 2021 年 8 月起**强制新应用上传 AAB**，
APK 通道已关闭。

⛔ 反过来 `AAB` **无法直接装到手机**，测试要用 `bundletool`。
⛔ 于是"发布包不能测、测试包不能传"是个硬分工，
混用的表现是"上传被拒"或"装不上"，而两者都不说明形态错了。

ⓘ 同时复查非资源文件确实在包里（见 02/S3）：
产物形态换了以后过滤器规则不会自动跟随。

【产出】每渠道的产物形态表 + 测试用 AAB 的验证方式

【判据】能说出每个渠道要哪种包，以及测试时怎么装。

【审】`audit/godot/platform-export.md#6`、`audit/godot/platform-export.md#21`

## 3. 参考实现

```bash
#!/usr/bin/env bash
# ⓘ 承接本步产出：名称、路径、版本、形态四项都是契约
set -euo pipefail

# S2：先 cd 到项目根 —— 相对路径的基准是 project.godot 所在目录
cd "$(dirname "$0")/.."

# S4：版本一致性在建包前校验，不等到报错
EDIT_VER="$(godot --version | awk '{print $NF}')"
TPL_VER="$(cat "$HOME/.local/share/godot/export_templates/version.txt" 2>/dev/null || echo none)"
if [ "$EDIT_VER" != "$TPL_VER" ]; then
    echo "⛔ 编辑器 $EDIT_VER 与模板 $TPL_VER 不匹配" >&2
    exit 1
fi

# S1：预设名与 export_presets.cfg 逐字一致，含空格要引号
# S3：release 与 debug 输出目录分离
godot --headless --export-release "Windows Desktop" "$PWD/build/win/game.exe"
godot --headless --export-release "Web"             "$PWD/build/web/index.html"
```

- [ ] 预设名与配置文件逐字一致，含空格已加引号

- [ ] release 与 debug 输出目录分离，发布目录无 debug 产物
- [ ] CI 建包前校验模板版本，不匹配即失败

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| CI 出包失败但本地能出 | 预设名不一致 | S1 |
| 命令成功却找不到产物 | 相对路径基准搞错 | S2 |
| 用户装不上"解析包时出现问题" | debug 签名混进发布 | S3 |
| 升级编辑器后导出全线报错 | 模板未同步升级 | S4 |
| 上传被拒 / 装不上 | AAB 与 APK 混用 | S5 |
