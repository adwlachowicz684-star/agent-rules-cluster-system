# 07 发布验收（多平台导出与发布域）

> **本步交付**：干净机器实测通过 + 商店要求核对通过
> **对应**：流程 `howto/godot/platform-export.md` · 审核 `audit/godot/platform-export.md`

## 0. 交付物定义

1. 已在一台**没装过该应用**的机器上完成首次安装与启动
2. 每个目标平台的产物都实际装过、启动过，不是只构建成功
3. 商店要求逐项核对完毕（产物形态、权限、隐私描述）
4. Web 已在**真实托管环境**（非本地 http）实测
5. 旧版本存档能被新版本读出

## 2. 工序

### Step 1　在没装过该应用的机器上实测，开发机不算　`[platform-export/07#S1]`

【读】`howto/godot/platform-export.md#3. macOS`

【做】
在一台干净机器上走完"下载 → 安装 → 首次打开"。
⛔ 在开发机上双击通过就算完 —— 开发机通常已信任过证书、已装过依赖、
⛔ 而这三个条件在玩家机器上一个都不成立。

⛔ macOS 上尤其如此：Gatekeeper 判定链的任何一环断掉，
都弹"无法验证开发者"或"已损坏"，
⛔ 而这两个提示**都不指向断的是哪一环**。
表现为"我这儿好好的、用户打不开"，排查被引向文件损坏或下载问题。

ⓘ 同时复查模板版本与编辑器版本一致：
⛔ 不匹配时报"各种奇怪错误"而非"版本不匹配"，
⛔ 在干净机器上会以平台相关的杂错形态出现。

【产出】干净机器实测记录（系统版本 / 是否首次 / 结果）

【判据】记录里那台机器此前从未装过该应用。

【审】`audit/godot/platform-export.md#9`、`audit/godot/platform-export.md#18`

### Step 2　每个平台都实际装上并启动，构建成功不算　`[platform-export/07#S2]`

【读】`howto/godot/platform-export.md#9. iOS：Xcode 工程的三个静默坑`

【做】
把每个目标平台的产物实际装到设备上并启动。
⛔ CI 显示"build success"就发布 —— 构建成功只证明**编译通过**，
⛔ 证明不了能装、能启动。

⛔ iOS 上这条尤其硬：导出目录必须是**空文件夹**，
工程名不能带空格、不能与项目目录同名，
⛔ 而这三条的症状全是"签名失败"，三件套本身可能全对。
表现为"构建过了但真机装不上"，排查被引向证书。

ⓘ 同时确认发布产物不是 debug 签名（见 03/S3）：
debug 包与已装正式版冲突，报"解析包时出现问题"，
⛔ 而这个提示完全不指向签名。

【产出】每平台的装机启动记录（设备 / 系统版本 / 产物来源）

【判据】每个目标平台都有一条"装上了并跑起来了"的记录。

【审】`audit/godot/platform-export.md#29`、`audit/godot/platform-export.md#23`

### Step 3　商店要求逐项核对，产物形态与隐私描述是高频拒因　`[platform-export/07#S3]`

【读】`howto/godot/platform-export.md#隐私描述是硬要求`

【做】
按渠道清单逐项核对：产物形态、权限申报、隐私描述、隐私清单。
⛔ 打 APK 传 Google Play —— 自 2021 年 8 月起**强制新应用上传 AAB**。
⛔ 权限多勾会被下架（数据安全表单按实际收集申报）。

⛔ 隐私描述缺了会**直接崩在首次调用处，且不提示具体原因** ——
表现为"一用麦克风就闪退"，⛔ 排查被引向权限申请逻辑或 SDK，
不会想到是缺一个 Info.plist 键。

ⓘ App Store 另一常见拒因：隐私清单 `NSPrivacyAccessedAPITypes`
与实际使用的 API 不符（用了第三方 SDK 必须声明追踪用途）。

【产出】逐渠道核对清单（产物形态 / 权限 / 隐私描述 / 隐私清单）

【判据】清单每项都有"已核对"的日期与执行人，无待定项。

【审】`audit/godot/platform-export.md#6`、`audit/godot/platform-export.md#13`

### Step 4　Web 要在真实托管环境实测，本地 http 不算　`[platform-export/07#S4]`

【读】`howto/godot/platform-export.md#其他限制`

【做】
上传到真实托管环境后访问实测。
⛔ 用本地 `http://localhost` 验收 —— localhost 通常是安全上下文的例外，
⛔ 而线上缺 COOP / COEP 时 `SharedArrayBuffer` 根本不存在。

⛔ itch.io 上要专门确认勾了 "SharedArrayBuffer support"：
⛔ 忘勾＝本地正常、上传后黑屏，而根因在托管方开关不在构建产物。

⛔ iframe 场景还要单独测第三方 cookie：官方要求
iframe 内游玩**必须启用第三方 cookie**，
⛔ 否则持久化失效 —— 表现为"itch.io 上进度丢失"，
排查被引向存档代码而根因在浏览器策略。

【产出】真实托管环境的访问记录（URL / 托管方 / 是否 iframe / 存档是否持久）

【判据】记录里的 URL 是真实托管地址，不是 localhost。

【审】`audit/godot/platform-export.md#3`、`audit/godot/platform-export.md#31`

### Step 5　旧版本存档能被新版本读出，别让更新变成删档　`[platform-export/07#S5]`

【读】`howto/godot/platform-export.md#6. Web`

【做】
用旧版本产出一个存档，再用新版本读取。
⛔ 只测新装 —— "升级后存档读不出来"是发布后才出现的事故，
⛔ 而它在全新安装路径上**永远测不到**，因为压根没有旧档。

⛔ 存档必须走 `user://`：导出后 `res://` 只读，
⛔ 往那里写**静默失败**，连报错都没有 ——
表现为"设置存了但重开就没了"，排查被引向序列化代码。

ⓘ Web 上还要确认持久化检测的结果与实际一致：
`OS.is_userfs_persistent()` 官方明示**会误报**，
⛔ 所以升级后要实测读写，不能只看检测返回值。

【产出】跨版本存档读取记录（旧版本 → 新版本）

【判据】存在一个"旧版本产生、新版本读出"的存档实例。

【审】`audit/godot/platform-export.md#15`、`audit/godot/platform-export.md#30`

## 3. 验收清单

- [ ] 干净机器完成下载→安装→首次打开，无"已损坏"
- [ ] 每平台产物实际装机启动，有设备与系统版本记录
- [ ] 商店要求逐项核对，产物形态/权限/隐私描述无待定
- [ ] Web 在真实托管地址实测（非 localhost），itch.io 开关已确认
- [ ] 旧版本存档能被新版本读出

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 用户打不开"已损坏" | 只在开发机验证 | S1 |
| 构建过了但装不上 | 未实际装机；iOS 工程命名/目录问题 | S2 |
| 审核被拒 / 一用麦克风就闪退 | 产物形态或隐私描述缺失 | S3 |
| 本地正常、上传后黑屏 | 未配隔离头 / 忘勾 itch.io 开关 | S4 |
| 更新后存档没了 | 未测跨版本读取 / 写到了 res:// | S5 |
