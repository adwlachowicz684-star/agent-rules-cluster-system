## 0. 交付物定义

⚠ **接入层的典型腐化：每个系统自己判一次等级。**

⛔ 扫荡写 `if vip >= 3: +2 次`、掉落写 `if vip >= 3: +10%`、商城写 `if vip >= 5: 打折`——
三处都能通过各自的测试，⛔ 但改权益时要改三处，且**必然漏一处**。

做完这一步，应该能**当场演示**：

1. 三个系统都通过 `get_benefit()` 取值，**不判断等级**
2. ⚠ 改一条权益，**三个系统同时生效**
3. ⛔ 权益过期时三个系统**同时失效**（不是各停各的）
4. 新增第四个接入方**不用改 VIP 侧代码**
5. ⚠ 权益值有缓存时，失效路径**一处统一**

**产出物**（下游按名字对接）：

```text
get_benefit(key)            # 唯一入口
# 各系统：value = get_benefit("sweep_count")
```

## 2. 工序

### Step 1　⚠ 列出全部接入方　`[vip/06#S1]`

【读】`howto/godot/vip-subscription.md#6. ⓘ 权益表要一处定义`

【做】枚举所有读权益的系统，逐项接入。

⛔ 边做边接 → 一定会有系统**直接判等级**，
而它照样能跑，只是改权益时不会跟着变。

【产出】接入方清单

【判据】⚠ 清单覆盖所有读权益的位置

【审】`audit/godot/vip-subscription.md#15`

### Step 2　⛔ 接入方只取值不判等级　`[vip/06#S2]`

【读】`howto/godot/vip-subscription.md#6. ⓘ 权益表要一处定义`

【做】`value = get_benefit("sweep_count")`，⛔ 不写 `vip_level >= N`。

⛔ 判等级 → 每加一个等级要改所有接入方，
而漏改的**不报错**，只是那条权益没生效。

【产出】各接入方的取值调用

【判据】⚠ 全库搜索散落等级判断**结果为 0**

【审】`audit/godot/vip-subscription.md#15` `audit/godot/vip-subscription.md#16`

### Step 3　⚠ 权益过期各系统同时失效　`[vip/06#S3]`

【读】`howto/godot/vip-subscription.md#7. ⚠ 到期的三种处理，选错就是事故`

【做】到期由 `get_benefit()` 统一返回默认值，⛔ 不各系统各判一次。

⛔ 各判一次 → 有的系统失效了有的没有，
表现为"VIP 过期了但扫荡还能多两次"。

【产出】统一失效

【判据】⚠ 到期瞬间**所有接入方同时**回到默认值

【审】`audit/godot/vip-subscription.md#17`

### Step 4　⚠ 缓存失效路径一处统一　`[vip/06#S4]`

【读】`howto/godot/vip-subscription.md#9. 待核对项（运行时验证）`

【做】若缓存权益值，失效只在 `get_benefit()` 侧，⛔ 不在各接入方。

⛔ 各接入方各自缓存 → 过期后有的还在用旧值，
⚠ 且"哪个缓存先失效"是不确定的，症状随机。

【产出】统一缓存与失效

【判据】⚠ 权益变更后**所有接入方同帧**拿到新值

【审】`audit/godot/vip-subscription.md#24`

### Step 5　⚠ 新增接入方不改 VIP 侧　`[vip/06#S5]`

【读】`howto/godot/vip-subscription.md#6. ⓘ 权益表要一处定义`

【做】新接入方只需调 `get_benefit(key)`。

⛔ 需要改 VIP 侧才能接入 → 说明 key 的设计不够正交，
之后每个新系统都会成为新的腐化点。

【产出】接入方式（只加一个调用）

【判据】⚠ 新增一个接入方**不修改** VIP 侧任何文件

【审】`audit/godot/vip-subscription.md#16`

### Step 6　⚠ 权益值参与数值链路的顺序　`[vip/06#S6]`

【读】`howto/godot/vip-subscription.md#10. 相关文档`

【做】与 `economy.md` 的加成链顺序对齐。

⛔ 顺序不一致 → VIP 加成与活动加成谁先乘的结果不同，
表现为"客服算不出来玩家到底该拿多少"。

【产出】链路顺序

【判据】⚠ 叠加多种加成时结果**可复算**

【审】`audit/godot/vip-subscription.md#16`

## 5. 常见返工

**① 各系统判等级。** 改权益漏改。

**② 各系统各判过期。** 有的失效有的没有。

**③ 各系统各自缓存。** 症状随机。

**④ 加成顺序不一致。** 客服算不清。
