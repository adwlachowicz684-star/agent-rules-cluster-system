> 　　　审核 `audit/godot/vip-subscription.md#17`

## 0. 交付物定义

⚠ **到期是硬边界判定，不是定时任务。**

⛔ 三种处理里两种是事故：

| 处理 | 后果 |
|---|---|
| 到期清掉权益数据 | 玩家**永久损失**已解锁内容 |
| ⛔ 到期删除数据 | 续期后**历史等级丢失**，最严重 |
| 到期什么都不做 | 白嫖 |

做完这一步，应该能**当场演示**：

1. 到期后权益**失效**，但累积数据**仍在**
2. ⚠ 续期后历史等级**立刻恢复**
3. ⛔ 服务器重启/玩家离线期间到期，**不漏判定**
4. 到期判定与 `time-progression.md` 的周期重置同源
5. ⚠ 倒计时展示与判定**同一时刻**

**产出物**（下游按名字对接）：

```text
expire_at_unix: int        # 绝对时刻
is_active(now) -> bool     # 硬边界判定，纯函数
# ⛔ 不删除任何累积字段
```

## 2. 工序

### Step 1　⚠ 硬边界判定，不用定时任务　`[vip/04#S1]`

【读】`howto/godot/vip-subscription.md#7. ⚠ 到期的三种处理，选错就是事故`

【做】每次读取时判 `now >= expire_at`，⛔ 不依赖定时器触发。

⛔ 定时任务 → 服务器重启或玩家离线时会**漏执行**，
表现为"明明过期了还能用"，且只在特定时序下出现。

【产出】`is_active(now)` 纯函数

【判据】⚠ 把时间直接设到过期后且**不重启**，权益立刻失效

【审】`audit/godot/vip-subscription.md#19`

### Step 2　⛔ 到期只改状态，不删数据　`[vip/04#S2]`

【读】`howto/godot/vip-subscription.md#7. ⚠ 到期的三种处理，选错就是事故`

【做】到期只让权益不再生效，累积字段**一个都不删**。

⛔ 删除 → 续期后历史等级丢失，
⚠ 这是本域**最严重**的事故类型：玩家认为"我充的钱没了"。

【产出】到期处理（只改状态）

【判据】⚠ 到期后再续期，**历史等级立刻恢复**

【审】`audit/godot/vip-subscription.md#17` `audit/godot/vip-subscription.md#18`

### Step 3　⚠ 展示与判定同一时刻　`[vip/04#S3]`

【读】`howto/godot/vip-subscription.md#1. ⛔ 不能用本地系统时间算到期`

【做】倒计时用判定的同一时间戳算，⛔ 不另取一次时间。

⛔ 另取一次 → 边界上"显示还剩 1 秒但已失效"，
表现为玩家截图投诉"我明明还有时间"。

【产出】统一时间源

【判据】⚠ 倒计时归零与权益失效**同一帧**

【审】`audit/godot/vip-subscription.md#1`

### Step 4　⚠ 离线期间到期要能补判　`[vip/04#S4]`

【读】`howto/godot/vip-subscription.md#10. 相关文档`

【做】上线时按服务器时间一次判完，⛔ 不按"上次在线"倒推。

⛔ 倒推 → 离线期间的到期被跳过，
表现为"离线三天回来还能领一次"。

【产出】上线补判

【判据】⚠ 离线跨越到期点后上线，**权益已失效**

【审】`audit/godot/vip-subscription.md#19`

### Step 5　⚠ 到期与离线其他状态不冲突　`[vip/04#S5]`

【读】`howto/godot/vip-subscription.md#10. 相关文档`

【做】与 `time-progression.md` 的离线结算顺序对齐。

⛔ 顺序不一致 → "先用 VIP 加成算了离线收益，再判定到期"，
表现为"过期后仍享受了一次加成"。

【产出】结算顺序

【判据】⚠ 到期点前后的离线收益**分别按各自状态算**

【审】`audit/godot/vip-subscription.md#20`

## 5. 常见返工

**① 定时任务触发。** 漏执行，时序相关。

**② 到期删数据。** 续期后历史丢失。

**③ 展示另取时间。** 差 1 秒投诉。

**④ 离线不补判。** 多领一次。
