## 0. 交付物定义

⚠ **权益最常见的腐化方式是散落，不是写错。**

⛔ 每条权益写成 `if vip_level >= 3:` 散在十几个地方 →
改一次权益要改十几处，⛔ 且**必然漏**，
而漏掉的那处**不报错**，只是"这条权益没生效"。

做完这一步，应该能**当场演示**：

1. 改一条权益值，**只改一个地方**且立刻全生效
2. ⚠ 全库搜索 `vip_level >` 之类的判断**结果为 0**
3. 权益是**取值**而不是布尔判断
4. 新增一条权益**不用改业务代码**
5. ⛔ 权益表在配置里，不硬编码

**产出物**（下游按名字对接）：

```text
vip_benefits: Dictionary    # key -> 按等级的值
get_benefit(key) -> int/float/bool
```

## 2. 工序

### Step 1　⚠ 一张表定义全部权益　`[vip/02#S1]`

【读】`howto/godot/vip-subscription.md#6. ⓘ 权益表要一处定义`

【做】`vip_benefits` 表，key → 各等级的值。

⛔ 散落写 → 改一次改十几处，必然漏且漏了不报错。

【产出】`vip_benefits` 配置

【判据】⚠ 改一条权益**只改一处**

【审】`audit/godot/vip-subscription.md#15`

### Step 2　⛔ 用取值不用布尔判断　`[vip/02#S2]`

【读】`howto/godot/vip-subscription.md#6. ⓘ 权益表要一处定义`

【做】`get_benefit(key) -> value`，⛔ 不做 `is_vip()`。

⛔ 布尔判断 → "不同等级不同值"退化成一堆 if，
每加一个等级就要改所有 if。

【产出】`get_benefit()`

【判据】⚠ 加一个等级**不用改业务代码**

【审】`audit/godot/vip-subscription.md#16`

### Step 3　⛔ 全库禁止散落等级判断　`[vip/02#S3]`

【读】`howto/godot/vip-subscription.md#6. ⓘ 权益表要一处定义`

【做】业务只读 `get_benefit()`。

⛔ 任何地方写 `vip_level >= N` 都是新增的腐化点，
⚠ 且这类代码**能通过所有功能测试**（它只是会在改权益时漏改）。

【产出】约定（可加进代码审查）

【判据】⚠ 全库搜索散落判断**结果为 0**

【审】`audit/godot/vip-subscription.md#15`

### Step 4　⚠ 权益表进配置不硬编码　`[vip/02#S4]`

【读】`howto/godot/vip-subscription.md#9. 待核对项（运行时验证）`

【做】阈值与权益内容走配置表。

⛔ 硬编码 → 改数值要重新发版，
而运营改权益是**高频**操作。

【产出】配置项

【判据】⚠ 改配置**不用重新编译**

【审】`audit/godot/vip-subscription.md#23`

### Step 5　⚠ 缺省值要有定义　`[vip/02#S5]`

【读】`howto/godot/vip-subscription.md#6. ⓘ 权益表要一处定义`

【做】`get_benefit()` 查不到时返回**无权益**的默认值。

⛔ 返回 null 或 0 而不定义语义 →
调用方各写各的兜底，⛔ 于是"没有这条权益"在不同地方表现不同。

【产出】缺省语义

【判据】⚠ 查不存在的 key，**行为一致且不崩**

【审】`audit/godot/vip-subscription.md#16`

## 5. 常见返工

**① `is_vip()` 布尔。** 加等级就全改。

**② 散落 if。** 改权益漏改。

**③ 硬编码阈值。** 改数值要发版。

**④ 缺省未定义。** 各处兜底不一致。
