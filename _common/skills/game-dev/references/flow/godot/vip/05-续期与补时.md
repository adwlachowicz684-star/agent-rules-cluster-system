> **对应**：做法 `howto/godot/vip-subscription.md#8. ⚠ 订阅续期要处理"叠加"与"补时"`
> 　　　审核 `audit/godot/vip-subscription.md#21`

## 0. 交付物定义

⚠ **续期是本域最容易"算错方向"的一步：错的结果不是报错，是时间变少。**

⛔ 两种错法：

| 写法 | 后果 |
|---|---|
| `end = end + duration`（未到期时） | 看似叠加，但**若 end 已过期**就把过期段也算进去 |
| `end = now + duration`（未到期时） | 续费反而**缩短**了剩余时间 |

做完这一步，应该能**当场演示**：

1. 未到期续费 → 剩余时间**增加**
2. ⚠ 已过期补买 → 得到**完整**时长，不是"倒欠"
3. ⛔ 连续续费 3 次 → 到期时刻**单调**增加
4. 叠加/覆盖的产品语义已明确（二选一，不模糊）
5. ⚠ 续费与到期的判定用**同一时间基准**

**产出物**（下游按名字对接）：

```text
extend(now, duration)      # max(expire_at, now) + duration
POLICY: stack | override   # 产品语义，明确二选一
```

## 2. 工序

### Step 1　⚠ 先 max 再加，不直接加　`[vip/05#S1]`

【读】`howto/godot/vip-subscription.md#8. ⚠ 订阅续期要处理"叠加"与"补时"`

【做】`expire_at = max(expire_at, now) + duration`。

⛔ `expire_at + duration` 在已过期时会把**过期那段也算进去**，
玩家得到"倒欠"的时间，表现为"我买了月卡，显示已过期"。

【产出】`extend()`

【判据】⚠ 过期后补买 → 得到**完整**时长

【审】`audit/godot/vip-subscription.md#22`

### Step 2　⛔ 未到期续费不能缩短　`[vip/05#S2]`

【读】`howto/godot/vip-subscription.md#8. ⚠ 订阅续期要处理"叠加"与"补时"`

【做】叠加语义下必须先 `max(expire_at, now)`。

⛔ `now + duration` → 续费反而缩短，
表现为"我续费了，剩余天数反而变少了"，
⛔ 这是最容易被玩家发现并投诉的一类。

【产出】叠加实现

【判据】⚠ 未到期续费 → 剩余时间**只增不减**

【审】`audit/godot/vip-subscription.md#21`

### Step 3　⚠ 产品语义二选一，不模糊　`[vip/05#S3]`

【读】`howto/godot/vip-subscription.md#9. 待核对项（运行时验证）`

【做】明确 `stack`（叠加）或 `override`（覆盖），写进文档。

⛔ 不确定就先写 `now + duration`（那是覆盖），
而运营**预期是叠加** → 玩家损失时间。

【产出】语义声明

【判据】⚠ 文档里能指出是哪种，且有对应测试

【审】`audit/godot/vip-subscription.md#21`

### Step 4　⛔ 掉单重试不能重复加时　`[vip/05#S4]`

【读】`howto/godot/vip-subscription.md#10. 相关文档`

【做】按订单号去重，⛔ 不按"收到几次回调加几次"。

⛔ 不去重 → 玩家一次付费得到多份时长；
⚠ 这是**可以直接被利用**的漏洞（重放回调）。

【产出】订单去重

【判据】⚠ 同一订单回调两次 → **只加一次**

【审】`audit/godot/vip-subscription.md#22`

### Step 5　⚠ 续费与到期同一时间基准　`[vip/05#S5]`

【读】`howto/godot/vip-subscription.md#1. ⛔ 不能用本地系统时间算到期`

【做】`now` 取自 01 的服务器基准。

⛔ 续费用本地时间、到期用服务器时间 →
两者在边界上不一致，表现为"续费后立刻显示已过期"。

【产出】统一 `now` 来源

【判据】⚠ 改系统时间后续费，**到期时刻不变**

【审】`audit/godot/vip-subscription.md#1`

### Step 6　⚠ 连续续费单调性　`[vip/05#S6]`

【读】`howto/godot/vip-subscription.md#8. ⚠ 订阅续期要处理"叠加"与"补时"`

【做】连续续费 3 次，到期时刻单调增加。

⛔ 不单调说明某处用了 `now` 而非 `max`，
⚠ 而这个 bug **单次续费测不出来**。

【产出】单调性确认

【判据】⚠ 续 3 次 → 到期时刻**逐次增大**

【审】`audit/godot/vip-subscription.md#21`

## 5. 常见返工

**① 直接 end+duration。** 过期段被算进去。

**② now+duration。** 续费反而缩短。

**③ 回调不去重。** 可被重放利用。

**④ 单次测试。** 单调性问题测不出。
