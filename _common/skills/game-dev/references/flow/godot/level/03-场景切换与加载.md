# 03 场景切换与加载（关卡流程域）

> **前置**：01 已完成（知道关卡数据在哪、要交接什么）
> **本步交付**：关卡之间能稳定进出，⛔ 不在切换时序上踩 null
> **对应**：做法 `howto/godot/systems.md` · 审核 `audit/godot/systems.md` `openworld.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 切场景后能可靠拿到新场景（⛔ 不是 null）
2. 切换时玩家数据不丢
3. 大场景有进度条，且不卡帧
4. 重开一局后，全局状态被正确重置

**产出物**：

```text
SceneManager.goto(path, payload)     # 统一的切换入口
SceneManager.scene_ready 信号        # 切换真正完成
```

## 2. 工序

### Step 1　理解官方的切换时序：两段式　`[level/03#S1]`

【读】`howto/godot/systems.md#⚠ 官方的切换时序`

【做】记住并注释进代码：

```text
① 旧场景立即出树   → 此刻旧场景里 get_tree() 返回 null
② 帧末删除旧场景   → 然后把新场景加入树
③ 之后恢复正常
```

✅ 要访问新场景必须 `await get_tree().scene_changed`。

【产出】`SceneManager.goto()` + 注释说明时序

【判据】切换后 `current_scene` 非 null；连续切 20 次不崩

【审】`audit/godot/systems.md#8`

### Step 2　切换前的数据交接　`[level/03#S2]`

【读】`howto/godot/systems.md#切换时保留数据`

【做】数据在切之前落到 Autoload 或存档，⛔ 不指望局部变量。

⚠ `change_scene_to_file` 会**销毁当前场景的所有节点**。

【产出】交接清单（哪些字段、存在哪）

【判据】切场景后血量/背包/任务与切换前一致

【审】`audit/godot/systems.md#13`

### Step 3　⛔ 不在退出回调里做收尾　`[level/03#S3]`

【读】`howto/godot/systems.md#⚠ 官方的切换时序`

【做】检查所有 `_exit_tree()` / `tree_exiting` 回调：
只要里面调了 `get_tree()`，就搬走。

⚠ 官方明确：旧场景已移出树时 `get_tree()` 返回 **null**。
"退出前再存一次盘"这种写法会静默失败或崩。

【产出】一份"退出回调里不能做什么"的检查结果

【判据】全项目搜索 `_exit_tree` 里无 `get_tree().`

【审】`audit/godot/systems.md#9`

### Step 4　异步加载与进度条　`[level/03#S4]`

【读】`howto/godot/systems.md#异步加载：进度来自`


【做】三件套，并接返回值：

```gdscript
var err := ResourceLoader.load_threaded_request(path)
if err != OK and err != ERR_ALREADY_IN_USE:
    push_error("加载请求失败 %d" % err)
```

⛔ 不要在轮询外"顺手"调 `load_threaded_get()` ——
它未完成时会**阻塞调用线程**，异步直接退化成同步。

【产出】加载画面 + 真实进度

【判据】大场景加载时游戏不冻结；重复触发不刷错误

【审】`audit/godot/systems.md#11` `audit/godot/systems.md#12` `audit/godot/openworld.md#2`
【品】`craft/godot/cheapness.md#4. 节奏类廉价感`

### Step 5　重开一局：reload 不会重置 Autoload　`[level/03#S5]`

【读】`howto/godot/systems.md#reload_current_scene 与 Autoload 的重载边界`

【做】Autoload 只持**数据**；节点引用由场景自己注册/注销：

```gdscript
func _enter_tree() -> void: GameState.level = self
func _exit_tree() -> void:
    if GameState.level == self: GameState.level = null
```

⚠ `reload_current_scene()` **不重载 Autoload**，
`@onready` 持有的旧节点引用会全部失效。

【产出】Autoload 的显式注册/注销约定

【判据】连续重开 10 局不出现空引用

【审】`audit/godot/systems.md#10`

### Step 6　真正的开销常在 instantiate，不在加载　`[level/03#S6]`

【读】`howto/godot/openworld.md#1. Chunk 流式加载`

【做】加载完成后测一次 **instantiate 耗时**；高频进出用池化而非
`queue_free` / 重新 `instantiate`。

⚠ `instantiate()` 必须在主线程。

【产出】加载与实例化各自的耗时数据

【判据】有实测数字；超过预算已改为池化

【审】`audit/godot/openworld.md#1` `audit/godot/openworld.md#12`

## 3. 参考实现

```gdscript
func goto(path: String, payload: Dictionary = {}) -> void:
    GameState.pending = payload
    get_tree().change_scene_to_file(path)
    await get_tree().scene_changed      # ⚠ 不等这行就是 null
    scene_ready.emit(get_tree().current_scene)
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 切完拿到 null | 没等 `scene_changed` | S1 |
| 切完数据丢了 | 靠局部变量传 | S2 |
| 切场景时偶发崩溃 | 退出回调里调 `get_tree()` | S3 |
| 加载条不动/卡帧 | 轮询外调了 `load_threaded_get` | S4 |
| 重开后空引用 | Autoload 持节点引用 | S5 |
| 切场景有明显卡顿 | instantiate 才是大头 | S6 |
