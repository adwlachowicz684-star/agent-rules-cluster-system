# 01 关卡数据与场景组织（关卡流程域）

> **前置**：已定死 2D/3D、已确定关卡的大致规模（单场景 / 需流式加载）
> **本步交付**：一个 `LevelData` Resource + 一个只读它并构建自身的关卡场景
> **对应**：做法 `howto/godot/level-design.md` · 审核 `audit/godot/level-design.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 改 `LevelData` 里的数值，⛔ **不碰场景**，关卡行为就变了
2. 两个关卡实例共用同一份配置，改一处两处同时生效
3. 从调试菜单能跳到任意关卡，并且**带指定状态**进入

**产出物**（下游按名字对接）：

```text
LevelData              class_name：id / display_name / spawn_point_id /
                       goal / time_limit / enemy_budget / reward
Level.get_data() -> LevelData
LevelDebug.jump_to(id, state)   # 跳关入口
```

⚠ 产出物必须能指认到符号。⛔ "关卡数据分离好了"不算——
02（出生点）和 06（进度）要靠 `LevelData` 的字段名对接。

## 1. 前置检查清单

- [ ] 已列出本关的**全部可调数值**（敌人数量、时限、奖励、目标）
- [ ] ⛔ 已确认**没有**一个数值写在场景节点的 inspector 里
- [ ] 已确认关卡场景是**一个根 + 若干子场景**，不是一坨
- [ ] 已确认 `ProjectSettings` 里 `.tscn` 的协作方式（拆小 + 单人所有权）

## 2. 工序

### Step 1　写 LevelData：所有可调数值的唯一来源　`[level/01#S1]`

【读】`howto/godot/level-design.md#4. 关卡场景的组织方式`

【做】新建 `level_data.gd`：

```gdscript
class_name LevelData
extends Resource

@export var id: StringName = &""
@export var display_name: String = ""
@export var spawn_point_id: StringName = &"default"
@export var goal: StringName = &"reach_exit"
@export var time_limit_sec: float = 0.0      # 0 = 不限时
@export var enemy_budget: int = 0
@export var reward: Dictionary = {}
```

⚠ 判据：把场景里**任意一个**数值改掉，游戏行为必须变化。

【产出】`LevelData` 类 + 至少一份 `.tres` 实例

【判据】`grep` 场景 inspector 里没有硬编码数值；改 `.tres` 生效

【审】`audit/godot/level-design.md#15`

### Step 2　场景只读数据构建，⛔ 场景本身不含数值　`[level/01#S2]`

【读】`howto/godot/level-design.md#关卡数据（Resource）`

【做】关卡根节点持有 `@export var data: LevelData`，`_ready()` 里按它构建：

```gdscript
func _ready() -> void:
    assert(data != null, "关卡缺少 LevelData")
    _spawn_marker = _find_spawn(data.spawn_point_id)
    _spawn_enemies(data.enemy_budget)
```

⛔ 反例：场景里摆 8 个敌人，代码里再写"删掉多余的"。

【产出】一个"换 data 就换行为"的关卡场景

【判据】同一场景挂两份不同 `.tres`，行为不同且都不报错

【审】`audit/godot/level-design.md#16`

### Step 3　场景拆分与协作所有权　`[level/01#S3]`

【读】`howto/godot/level-design.md#5. ⚠ .tscn 是文本`

【做】定三条并写进项目 README：

1. 一个 `.tscn` 只由一个人编辑（所有权）
2. 大关卡拆成子场景，用实例化组合
3. ⛔ 不做 `.tscn` 的自动合并——文本可 diff ≠ 语义可合并

【产出】场景拆分方案 + 所有权表

【判据】两人同时改同一 `.tscn` 时不会静默丢内容

【审】`audit/godot/level-design.md#17` `audit/godot/level-design.md#18`

### Step 4　跳关入口：⛔ 不能只能从头玩　`[level/01#S4]`

【读】`howto/godot/level-design.md#6. 快速迭代是基础设施`

【做】调试菜单支持三种跳转：

| 跳转 | 用途 |
|---|---|
| 跳到指定关卡 | 测后面的关 |
| 带状态跳（中段、指定装备） | ⚠ 跳过前置 |
| 跳过教程 | 老玩家回归 |

⚠ "能跳过去"不等于"能测到"——跳过去时状态不对，测的是假场景。

【产出】`LevelDebug.jump_to(id, state)`

【判据】调到最后一关只花一次点击；跳转后状态与正常流程一致

【审】`audit/godot/level-design.md#19` `audit/godot/level-design.md#20`

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 改数值没反应 | 数值写在场景 inspector 里 | S1 |
| 两个关卡数值不一致 | 各自复制了一份 | S2 |
| 合场景丢内容 | 当 `.tscn` 可自动合并 | S3 |
| 测后面的关要玩 20 分钟 | 没有跳关入口 | S4 |
| 跳过去行为不对 | 跳转不带状态 | S4 |
