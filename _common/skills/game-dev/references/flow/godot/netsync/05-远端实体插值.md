# 05 远端实体插值（网络同步域）

> **前置**：03 服务端已在发权威快照
> **本步交付**：远端玩家平滑不抖，且**同一套时钟链**贯穿预测/回滚/插值
> **对应**：做法 `howto/godot/netsync-advanced.md` `multiplayer.md` · 审核 `audit/godot/netsync-advanced.md`

## 0. 交付物定义

⚠ 远端玩家的状态包**到达时间不均匀**，直接照用会抖。
做法是**延迟一小段时间再渲染**，在快照之间插值。

做完这一步，应该能**当场演示**：

1. 远端玩家移动**平滑**，不跳、不抖
2. 丢包/抖动时仍能平滑（缓冲吸收）
3. ⚠ 快照带的是**发送端时钟**，不是到达时间
4. 预测/回滚/插值**共用同一套输入序号 + tick 时钟链**
5. 已实测出本项目的缓冲时长（⛔ 不是抄经验值）

**产出物**（下游按名字对接）：

```text
_snapshots: Array       带 tick 的快照缓冲
INTERPOLATION_DELAY_MS  插值延迟
_server_now_ms()        与服务端对齐的时钟
```

## 2. 工序

### Step 1　快照必须打发送端时钟　`[netsync/05#S1]`

【读】`howto/godot/netsync-advanced.md#2. 延迟补偿（核心）` 的「2.0.1 快照必须打发送端时钟」

【做】⚠ **快照在发送端打上模拟时钟，不能让接收端用到达时间** ——
否则网络早到/晚到/乱序会**直接改变世界**。

包内携带 `tick` / `server_time` / `entity_id` / 位置 / 速度 / 状态 / 版本号。
接收时刻只用于统计 RTT/抖动。

【产出】快照字典含 `tick` 与 `server_time`

【判据】⚠ 人为让包乱序到达（延迟第二个包），世界表现**不变**

【审】`audit/godot/netsync-advanced.md`

### Step 2　固定延迟缓冲 + 插值　`[netsync/05#S2]`

【读】`howto/godot/netsync-advanced.md#2. 延迟补偿（核心）` 的「2.3 远端实体插值」

【做】
```gdscript
if _snapshots.size() < 2:
    return
var render_time := _server_now_ms() - INTERPOLATION_DELAY_MS
_interpolate_to(render_time)
```

⚠ **代价是额外的显示延迟**（典型 100ms）。
⛔ 少于 2 个快照时不插值——只有 1 个点没有"之间"可插。

【产出】远端实体按 render_time 插值

【判据】⚠ 远端玩家移动**连续**（⛔ 不是一格一格跳）

【审】`audit/godot/netsync-advanced.md`

### Step 3　⚠ 缓冲时长的权衡　`[netsync/05#S3]`

【读】`howto/godot/netsync-advanced.md#2. 延迟补偿（核心）` 的「2.0.1」末尾

【做】⚠ 缓冲越小越"实时"，越容易抖动；越大越稳，越放大控制误差。

10Hz 快照在 5% 丢包、两帧抖动下经验值约 **350ms**
（其中 300ms 用于容忍连丢两包）
—— ⚠ **这是经验值不是 Godot 默认值**。

✅ 按自己项目的 tick 率与实测丢包率调。

【产出】缓冲时长是**实测值**并已回填参数表

【判据】⚠ 在 5% 丢包下测试，**不出现**"卡顿—追帧"循环；
　　　且参数表里填的是自己测的数（⛔ 不是抄 350）

【审】`audit/godot/netsync-advanced.md`

### Step 4　三者共用同一套时钟链　`[netsync/05#S4]`

【读】`howto/godot/netsync-advanced.md#2. 延迟补偿（核心）` 的「2.3」末尾

【做】⚠ 预测/回滚/插值三者要共用**同一套输入序号 + tick 时钟链**，缺一不可。

⛔ 各用各的时间基准，会出现"远端玩家与我自己的位置关系错乱"——
明明看到的画面里我打中了，服务器判定没中。

【产出】全局只有一个 tick 时钟源

【判据】⚠ 同一时刻打印三处 tick（预测/回滚/插值），**数值一致或可换算**

【审】`audit/godot/netsync-advanced.md`

### Step 5　快照缓冲的长度上限　`[netsync/05#S5]`

【读】`howto/godot/multiplayer.md#4. 快照缓冲与插值`

【做】缓冲要有上限，过期快照（早于 render_time 的）要丢弃。

⚠ 不清理的话，长时间运行后缓冲无限增长，
且 `_snapshots[0]` 是很久以前的，插值会拉出诡异的结果。

【产出】缓冲长度恒定（不是单调增长）

【判据】⚠ 跑 10 分钟后 `_snapshots.size()` **仍在上限内**

【审】`audit/godot/multiplayer.md`

### Step 6　生成/销毁走可靠通道　`[netsync/05#S6]`

【读】`howto/godot/netsync-advanced.md#3. `@rpc` 深入` 的「各参数」

【做】实体生成/销毁/命中/死亡走 `reliable`，
⛔ 不能走 `unreliable`——丢一个"生成"包，该实体在客户端永远不存在。

⚠ 与位置同步相反：**位置可以丢，生灭不能丢**。

【产出】生成销毁事件用 reliable，位置用 unreliable_ordered

【判据】⚠ 在 10% 丢包下，所有生成的实体**都能在客户端出现**

【审】`audit/godot/multiplayer.md`

## 3. 参考实现

```gdscript
const INTERPOLATION_DELAY_MS := 100

var _snapshots: Array = []          # [{tick, pos, vel, ...}] 按 tick 升序

func _on_remote_state(state: Dictionary) -> void:
    # ⚠ 用包里的 tick 排序，不是到达顺序
    _snapshots.append(state)
    _snapshots.sort_custom(func(a, b): return a["tick"] < b["tick"])
    while _snapshots.size() > MAX_SNAPSHOTS:
        _snapshots.pop_front()

func _process_remote_rendering(_delta: float) -> void:
    if _snapshots.size() < 2:
        return
    var render_time := _server_now_ms() - INTERPOLATION_DELAY_MS
    _interpolate_to(render_time)

func _interpolate_to(t: int) -> void:
    # 找 t 两侧的两个快照
    var prev := null
    var next := null
    for i in _snapshots.size() - 1:
        if _snapshots[i]["tick"] <= t:
            prev = _snapshots[i]
            next = _snapshots[min(i + 1, _snapshots.size() - 1)]
            break
    if prev == null:
        prev = _snapshots[0]
        next = _snapshots[0]
    var span := maxi(1, next["tick"] - prev["tick"])
    var alpha := clampf(float(t - prev["tick"]) / float(span), 0.0, 1.0)
    global_position = prev["pos"].lerp(next["pos"], alpha)
```

⚠ `sort_custom` 是必要的：包会乱序到达，
⛔ 按到达顺序插值会让远端玩家来回抽搐。
