# 网络同步域 — 流程总览

> **本域交付**：一套服务器权威、本地零等待、远端不抖动、断线能接管的联网玩法。
> **对应**：做法 `howto/godot/multiplayer.md` `netsync-advanced.md`
> 　　　审核 `audit/godot/multiplayer.md` `netsync-advanced.md`

---

## 0. 先定做什么（⛔ 没写这三行不许开工）

⚠ **本域是所有域里最"本地测不出来"的一个。**
单机跑一切正常、上线才炸，是联网开发的典型失败。
所以本域的验收**必须在有延迟/丢包的环境下做**，⛔ 不能只在本机跑通就算完。

```text
做什么：<同步模型、谁是权威、目标延迟/丢包容忍度>
不做什么：⛔ <至少两条>
验收标准：<在高延迟/丢包下可观测的>
```

示例（本次做权威状态同步 + 本地预测）：

```text
做什么：服务器算权威世界，客户端预测自己的移动，远端玩家插值显示
不做什么：⛔ 不做锁步（见 01 的选型表）
         ⛔ 不做大厅/匹配（见 sharding-matchmaking）
验收标准：150ms 延迟 + 5% 丢包下本地移动无等待感；
         伪造 RPC 改血量被服务端拒绝；
         断线后 authority 能迁移且不残留孤儿实体
```

### 然后挑功能点

| 本次要做的 | 需要的功能点 |
|---|---|
| 只是"能连上、能同步位置" | 01 → 02 → 07 |
| 要服务器权威防作弊 | 01 → 02 → 03 → 07 |
| 要本地操作零等待 | 01 → 02 → 03 → 04 → 07 |
| 远端玩家要平滑不抖 | 01 → 02 → 03 → 05 → 07 |
| 要断线重连 / 载具换手 | 01 → 02 → 06 → 07 |
| 要上专用服务器 | 01 → 02 → 03 → 07（07 的 S4 必做） |

⛔ **不要全做。**

## 1. 功能点拆解与依赖顺序

```text
01 同步模型选型 ── 02 传输层与 RPC ──┬── 03 服务器权威与输入上报 ──┬── 04 预测与回滚 ──┐
                                     │                            └── 05 远端插值 ────┼── 07 验收
                                     └── 06 authority 迁移与断线 ─────────────────────┘
```

| # | 功能点 | 前置 | 为什么这个顺序 |
|---|---|---|---|
| 01 | 同步模型选型 | 无 | ⚠ 选错模型后面全部白做——锁步与状态同步是两套完全不同的东西 |
| 02 | 传输层与 RPC | 01 | 先定好通道与注解默认值，再往上堆逻辑 |
| 03 | 服务器权威与输入上报 | 02 | ⚠ 权威是所有防作弊的地基，预测与插值都建立在它之上 |
| 04 | 客户端预测与回滚 | 03 | 预测是"本地先动"，必须先有权威状态可对照 |
| 05 | 远端实体插值 | 03 | 插值用的是服务端快照，先有快照才有插值 |
| 06 | authority 迁移与断线 | 02 03 | 迁移依赖已建立的 authority 关系 |
| 07 | 上线验收 | 01–06 | ⚠ 含**必须**在劣化网络下做的实测 |

## 2. ⚠ 五个最容易做反的顺序

**① 先用 `@rpc` 默认参数写完再优化。**
⚠ **默认 `reliable` 是性能陷阱**：每帧位置同步忘了写 `unreliable_ordered`
就走可靠通道——丢包重传会让位置**越来越滞后**。
而且默认 `authority` 意味着**客户端调用会被静默忽略，不报错**。

**② 先做同步再做权威。**
先让"客户端算完广播"跑通，之后再加服务端校验，
会发现**所有计算逻辑都要搬到服务端**，等于重写。

**③ 预测不存输入历史。**
预测先做出来很爽，但服务器纠偏后**无法重放**，
只能瞬移回权威位置——手感比不做预测更差。

**④ 把命中结算/任务计数放进预测副作用。**
⚠ 回滚时会**重复触发**：音效重复、粒子重复、奖励翻倍。
⛔ 绝不能把可累加逻辑放进预测。

**⑤ 只在开发环境验收。**
⚠ 局域网延迟 <5ms、丢包 0%，所有抖动问题都被隐藏。
必须造 150ms + 5% 丢包的环境。

## 3. 每做完一个功能点必做

1. 跑一遍该步的**验收清单**，逐条打勾
2. ⛔ 有没过的，不进下一步
3. 过该步【审】列的 audit 条目
4. 过功能点末尾的「整体审核」节
5. ⚠ 实测参数已回填，⛔ 不留示例值
6. ⚠ **本域额外一条**：在劣化网络（延迟 + 丢包）下复测
