# 05 性能预算与移动兼容（着色器域）

> **本步交付**：分支 / 采样 / 精度预算 + 真机验证
> **对应**：流程 `howto/godot/shaders.md` · 审核 `audit/godot/shaders.md`

## 0. 交付物定义

1. 逐像素动态分支已换成 `mix` / `step` / `smoothstep`
2. `discard` 只用在硬孔，⛔ 不用来做移动端透明优化
3. 重复采样同一坐标已缓存结果
4. 移动端全屏 pass 的屏幕纹理读取已评估
5. 精度已按用途分级，且**在真机验证过**

## 2. 工序

### Step 1　连续变化用 mix/step，别用逐像素动态分支　`[shaders/05#S1]`

【读】`howto/godot/shaders.md#`if` 的代价`

【做】
连续变化的效果用 `mix` / `step` / `smoothstep` 表达，别写成逐像素 `if`。
⛔ 简单理解成"GPU 没有分支预测所以永远别用 if" ——
对大块区域、uniform 条件、昂贵函数，分支反而能显著减少无效计算。

⛔ 真正该换掉的是**逐像素高度不一致**的分支：GPU 可能仍保留两条路径，
代价是"两条都付"，而这在桌面 GPU 上往往看不出来。

【产出】分支分类：哪些改成 mix/step，哪些保留 if

【判据】每个保留的 if 都能说出"它的条件跨线程一致"。

【审】`audit/godot/shaders.md#14`

### Step 2　discard 不省性能　`[shaders/05#S2]`

【读】`howto/godot/shaders.md#`discard``

【做】
`discard` 只用于 alpha scissor 无法接受的硬孔。
⛔ 用 `discard` 做移动端透明优化 —— 它会阻止有效利用深度 prepass，
而且即使像素最终被丢弃，顶点阶段**仍然执行了**。
"把所有像素都 discard"不会比不渲染这个物体更便宜。

⛔ 表现为"加了 discard 反而更慢"，而直觉上它应该更快。

【产出】discard 使用点清单 + 每处的理由

【判据】每处 discard 都能说出"为什么 alpha scissor 不够用"。

【审】`audit/godot/shaders.md#13`

### Step 3　重复采样同一坐标先缓存结果　`[shaders/05#S3]`

【读】`howto/godot/shaders.md#纹理`

【做】
同一坐标的重复采样，先把结果存成局部变量再用。
⛔ 图省事多写几次 `texture()` —— 每次访问显存都可能 cache miss，
⛔ 而"多采样几次看不出差别"是错觉：差别体现在带宽与 tile 内存，
不会在桌面 GPU 的帧时间上明显显示。

ⓘ 屏幕后处理应在**降采样 RT** 上执行；
像素艺术用 nearest 关 mipmap，3D 颜色纹理用 linear mipmap。

【产出】采样点清单（坐标 → 次数 → 是否已缓存）

【判据】shader 里不存在"同一坐标采两次"的写法。

【审】`audit/godot/shaders.md#35`

### Step 4　移动端全屏 pass 读屏幕纹理要单独评估　`[shaders/05#S4]`

【读】`howto/godot/shaders.md#性能反模式（按影响排序）`

【做】
移动端全屏 pass 无限制读屏幕纹理会破坏 tile 优化，代价远高于桌面，
必须单独评估，⛔ 不按桌面表现推断。

⛔ 全分辨率多 pass 后处理 + 大半径多采样是清单里影响最大的一条，
而它在桌面 60 帧下常常"完全没问题"。

【产出】后处理清单（每个 pass：分辨率 / 采样次数 / 是否读屏幕纹理）

【判据】每个全屏 pass 都标了分辨率与采样次数，且移动端单独测过。

【审】`audit/godot/shaders.md#36`

### Step 5　精度按用途分级，且必须在真机验证　`[shaders/05#S5]`

【读】`howto/godot/shaders.md#精度限定符`

【做】
世界坐标、屏幕 UV、`TIME`、深度重建、远距离法线插值用 `highp`；
颜色权重、归一化后的局部方向、0–1 参数可用 `mediump`。

⛔ 全局调低精度求快 —— 移动端降级精度在**桌面预览完全正常**，
只在特定设备上出现远处闪烁。⛔ 不真机验证就交付，
等于把这个 bug 直接发给玩家，而它在开发机上永远复现不了。

【产出】精度分级表（变量 → 限定符 → 理由）

【判据】精度分级表已在最低目标设备上验证过，无远处闪烁。

【审】`audit/godot/shaders.md#15`

## 3. 参考实现

```gdshader
// ⓘ 承接本步产出：连续变化用 mix 不用 if；重复采样先缓存
shader_type spatial;

uniform float u_amount : hint_range(0.0, 1.0, 0.01) = 0.0;
uniform sampler2D u_tex : source_color;

varying highp vec3 v_world_pos;   // ⓘ 世界坐标必须 highp，mediump 会远处闪烁

void fragment() {
    vec4 base = texture(u_tex, UV);          // ⓘ 同一坐标不再采第二次
    vec3 tint = vec3(1.0, 0.3, 0.3);
    ALBEDO = mix(base.rgb, base.rgb * tint, u_amount);   // ⛔ 不用逐像素 if
}
```

| 症状 | 原因 | 回到 |
|---|---|---|
| 真机远处闪烁 | 世界坐标用了 mediump | S5 |
| 加了 discard 反而更慢 | 用 discard 做透明优化 | S2 |
| 移动端掉帧但桌面满帧 | 全屏 pass 破坏 tile 优化 | S4 |
| 带宽吃紧但帧时间看不出 | 重复采样没缓存 | S3 |
| 分支开销比预期大 | 逐像素动态分支 | S1 |
