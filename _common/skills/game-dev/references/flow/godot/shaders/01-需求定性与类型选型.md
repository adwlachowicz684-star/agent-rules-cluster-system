# 01 需求定性与类型选型（着色器域）

> **本步交付**：视觉目标定性 + `shader_type` 定死 + uniform 参数清单
> **对应**：流程 `howto/godot/shaders.md` · 审核 `audit/godot/shaders.md`

## 0. 交付物定义

1. 视觉目标能一句话说清，且**说得出它是不是画面的主角**
2. `shader_type` 已定死，不打算中途改
3. 2D / 3D 的坐标空间与内置变量已确认，⛔ 不互相套用
4. uniform 清单先写出来，作为接口对待
5. 精度与平台基线已定，⛔ 不以桌面预览为准

## 1. 前置检查清单

- [ ] 视觉目标能一句话说清（不是"要好看"）
- [ ] 已确认引擎自带材质 / 参数做不到这件事
- [ ] `shader_type` 已定（`canvas_item` / `spatial` / `particles` / `sky` / `fog`）
- [ ] 已确认 2D 与 3D 的内置变量不通用
- [ ] ⚠ uniform 清单已写出，且每个参数标了逐实例 / 全局
- [ ] 已确定目标渲染器与最低设备档位

## 2. 工序

### Step 1　先定性视觉目标，它是不是画面的主角　`[shaders/01#S1]`

【读】`howto/godot/shaders.md#0. 五种 shader 类型`

【做】
一句话说清这个效果要干什么，并明确**它是不是这个画面里的主角**。
⛔ 上来就写 shader —— 一半以上的"加个效果"需求，引擎自带材质参数、
`render_mode` 或贴图就能解决，写 shader 反而引入变体与预热成本。

⛔ 更要命的是全屏后处理堆叠：每个单看都对，叠上去画面没有主体，
玩家说不清该看哪里，而每个效果的作者都认为自己那个是必要的。

【品】`craft/godot/aesthetics.md#1. 视觉层次：一个画面只允许一个主角`

【产出】一句话的视觉目标 + 是否为主角的定性

【判据】截图给别人看，对方能一眼说出画面主体是什么。

【审】`audit/godot/shaders.md#38`

### Step 2　2D 与 3D 是两套内置变量，不能互抄　`[shaders/01#S2]`

【读】`howto/godot/shaders.md#2. CanvasItem（2D）`

【做】
确认用的是 2D 还是 3D，然后只用那一套的内置变量。
⛔ 把 2D 的写法套到 3D 上（或反过来）—— 2D 的 `VERTEX` 是**像素坐标**，
3D 的是模型空间坐标；`UV`、`NORMAL` 的可用性也不同。

⛔ 表现为"代码能编译、效果完全不对"，而排查会被引向算法写错，
实际只是用错了另一套坐标系。

【产出】已确认的 shader 类型与对应的内置变量清单

【判据】能说清当前 `shader_type` 下 `VERTEX` 是什么空间、单位是什么。

【审】`audit/godot/shaders.md#8`

### Step 3　3D 必须先确认坐标空间再写逻辑　`[shaders/01#S3]`

【读】`howto/godot/shaders.md#坐标空间（最容易出错的地方）`

【做】
写任何空间变换前，先写明"这个量当前在哪个空间、要转到哪个空间"。
⛔ `CAMERA_MATRIX` 当成相机变换用 —— 它是**视图到世界**，方向是反的；
⛔ 开了 `world_vertex_coords` 之后再乘一次 `MODEL` —— 双重变换。

⛔ 这两类的共同表现是"整体偏移/朝向奇怪，但大体像那么回事"，
于是会被反复微调一个根本不该调的系数，越调越乱。

【产出】变换链说明：每步的输入空间与输出空间

【判据】指着每个矩阵乘法，能说出它把什么转成了什么。

【审】`audit/godot/shaders.md#9`、`audit/godot/shaders.md#10`

### Step 4　uniform 清单先写，它是接口　`[shaders/01#S4]`

【读】`howto/godot/shaders.md#uniform 提示（hint）完整清单`

【做】
先列出所有 uniform：名字、类型、提示、默认值、逐实例还是全局。
⛔ 边写逻辑边加 uniform —— 名字随手起，后面 GDScript 侧靠字符串传参，
大小写不符**不报错也不生效**，最后变成"改了没反应"的幽灵问题。

ⓘ `source_color` 不是编辑器控件而是**颜色空间语义**：
颜色纹理缺了会发白，而法线 / 粗糙度 / 金属度 / 高度**不能加**。

【产出】uniform 清单表（名字 / 类型 / 提示 / 默认值 / 归属）

【判据】GDScript 侧每个 `set_shader_parameter()` 的名字都能在清单里逐字符对上。

【审】`audit/godot/shaders.md#4`、`audit/godot/shaders.md#5`

### Step 5　GDShader 是方言，抄来的 GLSL 多数跑不了　`[shaders/01#S5]`

【读】`howto/godot/shaders.md#1. 语言基础`

【做】
明确 GDShader 不是标准 GLSL，从网上抄的代码要逐条核对内置名与语法。
⛔ 假定"能编译就是对" —— 方言差异往往编译得过、结果不对，
比如没有隐式类型转换，`1` 与 `1.0` 不等价，浮点字面量都要写 `.0`。

⛔ 局部变量**不会默认初始化为 0**，读到的是未定义数据。
表现是"某些像素出现随机噪点"，而只在部分设备、部分帧出现。

【产出】已核对的内置名清单（只用文档里确认存在的）

【判据】shader 里没有"网上抄来但文档查不到"的标识符。

【审】`audit/godot/shaders.md#1`、`audit/godot/shaders.md#2`、`audit/godot/shaders.md#3`

## 3. 参考实现

```gdshader
// ⓘ 承接本步产出：类型定死 + uniform 清单先行 + 默认值写在提示之后
shader_type spatial;

uniform vec4 u_tint : source_color = vec4(1.0);
uniform float u_amount : hint_range(0.0, 1.0, 0.01) = 0.0;
uniform int u_mode : hint_enum("Off", "Rim", "Toon") = 0;

void fragment() {
    ALBEDO = u_tint.rgb;
}
```

## 4. 验收清单

- [ ] 视觉目标一句话说清，且能指出画面主体
- [ ] `shader_type` 已定死，无"中途再改"的打算
- [ ] 2D / 3D 内置变量未混用
- [ ] 每个矩阵乘法都写明了源空间与目标空间
- [ ] uniform 清单已落文档，名字与代码逐字符一致

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 效果大体像但整体偏移 | 坐标空间用错 / 双重变换 | S3 |
| 改参数没反应 | uniform 名大小写不符 | S4 |
| 颜色发白 | 颜色纹理缺 `source_color` | S4 |
| 部分像素随机噪点 | 局部变量未初始化 | S5 |
| 画面没有主体 | 后处理堆叠，没人定性主角 | S1 |
