# 着色器（GDShader / 材质 / 变体 / 预热）—— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 一个物体 / 一个角色加个效果 | 01 → 02 → 03 → 07 |
| 要进正式包，怕首帧卡顿 | 01 → 02 → 03 → 04 → 05 → 07 |
| 要上移动端 / 低端设备 | 01 → 02 → 03 → 04 → 05 → 07 |
| 批量换材质、3.x 迁移 | 01 → 02 → 06 → 07 |
| 全套着色器工程 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只要效果能进包，04 也不能跳过** ——
编译卡顿在正常流程下测不出来，只在玩家改分辨率、首次进新区域时出现，
⛔ 而"首帧顿一下"在产品上等于"这游戏优化差"，解释成本极高。

ⓘ 若本次只是**"改个颜色、调个参数"**，那是材质配置，不套本域。
ⓘ 若只是**排查为什么卡顿**，先看 `perf` 域，确认是着色器问题再回本域 04 / 05。

ⓘ 分工：
- `howto/godot/shaders.md` 讲**单个要素怎么实现**（语言、配方、性能工程、调试、迁移）
- 本域讲**这些要素按什么顺序做、怎么保证不串实例、怎么保证真机不劣化**

⛔ 若本域某步需要"某个 GPU 上的具体耗时"这类细节，
指向 `perf` 域实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 需求定性与类型选型 | — | 视觉目标定性 + shader_type 定死 + 参数清单 |
| 02 | 材质实例与参数契约 | 01 | 逐实例 / 全局定性 + 共享或复制 + uniform 名表 |
| 03 | 原型与最小可见闭环 | 01, 02 | 一个 uniform 一个效果，跑通且可调试 |
| 04 | 变体与编译预热 | 03 | 变体数可控 + 预热清单 + 首帧无新增卡顿 |
| 05 | 性能预算与移动兼容 | 03, 04 | 分支 / 采样 / 精度预算 + 真机验证 |
| 06 | 接入替换与迁移 | 02 | 批量替换 + 旧 API 清理 |
| 07 | 着色器验收 | 全部 | 截图测试 + 真机 + 敌意环境实测 |

⚠ **01 必须在一切之前**：`shader_type` 后改等于重写 ——
2D 与 3D 的内置变量、坐标空间、可用 `render_mode` 都不是同一套。

⚠ **02 必须在 03 之前**：先跑通效果再想"这个参数归谁"，
会发现十个敌人同时溶解，⛔ 而要改回来必须动所有调用点。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `perf` 域 性能分析 | 首帧与管线编译归属见 04；⛔ 具体耗时以实测为准，本域不给数字 |
| `mobile` | ⓘ howto 层，暂无 flow 域 —— 移动端精度与后端差异见 05 |
| `2d-rendering` | ⓘ howto 层，暂无 flow 域 —— 2D 后处理与本域 01 的类型选型相接 |
| `rendering-advanced` | ⓘ howto 层，暂无 flow 域 —— 管线预热细节见 04 |
| `destruction` 域 破坏 | 碎裂 / 溶解效果的逐实例参数走本域 02，⛔ 不各自 duplicate 一套 |
| `combat` 域 战斗结算 | 受击白闪是逐实例参数，走本域 02；⛔ 不要共享材质导致全场一起闪 |
| `weather` 域 天气昼夜 | 全局色调是**故意共享**的典型，见 02 S5 |
| `ui` 域 UI | UI 材质与 3D 材质是两套，⛔ 不共用同一份 ShaderMaterial |
