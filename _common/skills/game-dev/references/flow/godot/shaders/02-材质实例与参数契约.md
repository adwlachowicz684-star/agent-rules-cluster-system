# 02 材质实例与参数契约（着色器域）

> **本步交付**：逐实例 / 全局定性 + 共享或复制的决定 + uniform 名表
> **对应**：流程 `howto/godot/shaders.md` · 审核 `audit/godot/shaders.md`

## 0. 交付物定义

1. 每个 uniform 都标了**逐实例**还是**全局**
2. 共享材质与逐实例材质的分法已确定并落代码
3. `Local to Scene` 的适用边界已写明（⛔ 只对运行时实例生效）
4. 挂点已确认（surface override，不是 mesh 资源）
5. 全局效果**故意共享**，⛔ 不做逐个复制

## 1. 前置检查清单

- [ ] uniform 清单里每个参数都标了归属（01 产出）
- [ ] 已确认哪些节点共用同一个材质资源
- [ ] 已确认这些节点是运行时生成的还是编辑器手摆的
- [ ] ⚠ 已确认材质挂在 MeshInstance3D 的 override 上，不是 mesh 资源上
- [ ] 已确认全局效果用的是共享材质

## 2. 工序

### Step 1　材质是共享资源，改一个会改全部　`[shaders/02#S1]`

【读】`howto/godot/shaders.md#材质是共享资源，改一个会改全部`

【做】
先认清 `ShaderMaterial` 是 Resource：从文件系统拖到检查器上时，
所有引用它的节点拿到的是**同一个对象**，`set_shader_parameter()` 改的是它。

⛔ 给一个敌人设 `dissolve_amount`，十个敌人同时开始溶解 ——
这是它最常见的表现，⛔ 而代码逐行看完全正确、无任何报错。
排查方向几乎必然被引向"逻辑写错了"，而不是"材质是共享的"。

【产出】共享关系图：哪些节点共用哪个材质资源

【判据】指着任一材质，能列出所有引用它的节点。

【审】`audit/godot/shaders.md#19`

### Step 2　先定性逐实例还是全局，再决定共享还是复制　`[shaders/02#S2]`

【读】`howto/godot/shaders.md#全局效果反而要故意共享`

【做】
把 01 的 uniform 清单逐个标注归属：受击白闪、单个角色的溶解是**逐实例**；
世界色调、全局溶解是**全局**。
⛔ 先写完 shader 再想参数归谁 —— 这一步必然返工，
因为改的时候要动所有调用点，而且已经"看起来能用"了没人愿意改。

【产出】uniform 清单补上归属列

【判据】每个参数都能一句话说清"它应该只影响这一个，还是影响全部"。

【审】`audit/godot/shaders.md#26`

### Step 3　逐实例：运行时生成的用 Local to Scene，手摆的要 duplicate　`[shaders/02#S3]`

【读】`howto/godot/shaders.md#两种正确做法`

【做】
运行时 `PackedScene.instantiate()` 出来的实例，勾材质的 `Resource → Local to Scene`；
编辑器里手动摆放的实例，在 `_ready()` 里 `duplicate()` 再赋回节点。

⛔ **`Local to Scene` 只对运行时实例生效**，对编辑器手摆的**不生效**。
表现为"勾了但部分敌人仍然联动"——运行时刷的各自独立、手摆的仍共享，
⛔ 这种"部分生效"比完全不生效更难查，因为它看起来像配置生效了一半。

【产出】每个逐实例节点的材质获取代码（含 duplicate 或直接依赖 Local to Scene）

【判据】改一个实例的参数，其他实例**画面上**不变。

【审】`audit/godot/shaders.md#20`

### Step 4　材质要挂 override，不是挂在 mesh 资源上　`[shaders/02#S4]`

【读】`howto/godot/shaders.md#两种正确做法`

【做】
材质挂到 MeshInstance3D 的 **surface override / global material override**，
⛔ 不要挂到 mesh 资源本身上。挂在 mesh 上时 `Local to Scene` 同样不生效，
而且要让材质独立就得连 mesh 数据一起 duplicate —— 那是极大的浪费。

ⓘ 用了 override 之后，`get_active_material(0)` 才能拿到你要改的那个材质。

【产出】材质挂点已全部改为 override

【判据】`get_active_material(0)` 返回的材质，改参数只影响当前节点。

【审】`audit/godot/shaders.md#21`

### Step 5　全局效果故意共享，别逐个复制　`[shaders/02#S5]`

【读】`howto/godot/shaders.md#全局效果反而要故意共享`

【做】
世界色调、全局溶解这类"所有实例同步变化"的效果，**共享才是正确做法**。
⛔ 逐个 `duplicate()` —— 反而会漏掉某些实例（尤其是后加入的对象），
表现为"有的变了有的没变"，而这比全部同步变化更难发现。

【产出】全局参数清单 + 一个共享材质的引用点

【判据】改全局参数，画面上所有目标**同步**变化，无一例外。

【审】`audit/godot/shaders.md#25`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：逐实例材质要 duplicate，全局材质故意共享
extends MeshInstance3D

var _mat: ShaderMaterial

func _ready() -> void:
    # ⛔ 不复制就改 → 所有共用该材质的实例一起变
    # ⓘ Local to Scene 只对运行时 instantiate 生效，手摆的必须走这里
    _mat = get_active_material(0).duplicate() as ShaderMaterial
    set_surface_override_material(0, _mat)

func set_dissolve(amount: float) -> void:
    _mat.set_shader_parameter("dissolve_amount", amount)
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 十个敌人同时溶解 | 材质共享，没复制 | S1 |
| 部分敌人联动、部分不联动 | 手摆的实例没用 duplicate | S3 |
| 改参数只有一个节点响应 | 全局参数被复制成了多份 | S5 |
| `get_active_material(0)` 拿不到 | 材质挂在 mesh 资源上 | S4 |
| 后期才改参数归属，动一堆调用点 | 先写完 shader 再想归属 | S2 |
