# 运营服务端：A/B、配置下发、活动、补偿、兑换码（Godot 4.7.2）

"ab测试""配置下发""停服""cdk""兑换码""邀请码" 此前 **全部 0 命中**。

⚠ **Godot 引擎既不内置账号、A/B 测试、远程配置后台，也没有兑换码或补偿系统。**
这些必须由项目自建后端或第三方 LiveOps 服务实现。

## 0. ⚠ 一句话边界

**客户端只能展示和转发，不能成为事实来源。**

玩家可以改配置、改时钟、改内存、重复点击、断线重试、批量扫描兑换码。
因此**活动资格、奖励数量、剩余次数、兑换结果、分桶**都必须服务端决定。

## 1. A/B 测试与灰度：分组必须服务端算

⚠ **客户端不能自己 `randf()` 分桶** —— 每次启动/闪退重启/切场景都可能重新分组，
实验样本瞬间污染；更糟的是攻击者能选对自己最有利的一组。

服务端应用"不可猜测的玩家主键 + 实验版本盐 + 层标识"算，
返回稳定的 `experiment_id / group / assigned_at / config_version`。
**客户端只保存结果并附在埋点里，不能重建分组逻辑。**

- 灰度维度：账号 / 设备 / 地区 / 版本 / 渠道
- ⚠ **灰度要能秒级回滚**
- ⚠ **样本污染**：同一设备多账号、同一账号多设备

## 2. 配置下发不是"下载个 JSON"

除了下载，还要有：**版本、灰度规则、校验/签名、失败重试、本地默认值、可回滚生效**。

⚠ **离线玩家拉不到配置** —— 启动后才拉，拉不到时用什么？**必须内置默认值**。

## 3. ⚠ 活动时间必须服务端给

⚠ **不要用本地时间判活动**（改钟就能提前领奖）。客户端只接收
**截止时间或剩余秒数**，不自己算。

### 活动五态（"结算中"最常被漏）

`未开始 / 进行中 / 已结束 / 结算中 / 已关闭`

⚠ **"结算中"是常被漏掉的第四态** —— 活动到点了但奖励还没发完，
这时显示"已结束"会让玩家以为自己没拿到。

⚠ **停服维护**：由网关或登录服务**直接拒绝**，不是让客户端"判断维护"。

## 4. 补偿与发放：必须幂等

⚠ **补偿必须按运营流水号幂等** —— 重复发 = 刷道具。

- 自动到账：体验好，但背包满/资产不存在时会失败
- 系统邮件：允许异步与客服复核，但要处理**邮件过期、附件满、领取幂等**
- ⚠ **发奖失败要能重试与对账**

## 5. CDK / 兑换码 / 邀请码

⚠ **兑换必须服务端校验** —— 客户端校验 = 可以无限刷。
⚠ **兑换码要防猜测** —— 可猜测的码会被扫库。
⚠ **批次管理**：同批次不能重复兑换、跨批次能否叠加要明确。
⚠ **邀请码双向奖励要防小号刷**。

## 6. 埋点的运营视角

（技术实现见 `analytics.md`，本文只讲运营要求）

- ⚠ **关键事件服务端校验**（客户端报"我通关了"不可信）
- ⚠ **埋点要带分组信息** —— 没有分组就无法分析实验
- ⚠ **断网缓存 + 恢复补发**

## 7. 优先级：按爆炸半径排序

| 优先级 | 内容 |
|---|---|
| 1 | 资产与兑换安全（唯一约束、原子消耗、请求 ID、审计） |
| 2 | 时间可信（服务端时间锚、五态、结算窗口） |
| 3 | 可运营性（灰度、公告、停服、热更、秒级回滚） |
| 4 | 展示体验（离线兜底、倒计时、按钮禁用） |

⚠ **顺序反过来，项目会拥有漂亮界面和脆弱经济。**

## 8. 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Godot 有运营后台 | **没有**，要自建或接第三方 |
| 2 | 客户端能判活动资格 | 玩家改内存/改钟就绕过 |
| 3 | 客户端 random 分桶 | 每次启动都变，**样本污染** |
| 4 | 分组存本地就行 | 换设备/重装会变，要**服务端算** |
| 5 | 配置下载完就完事 | 还要**版本/灰度/校验/默认值/回滚** |
| 6 | 离线时没配置就报错 | 要**内置默认值兜底** |
| 7 | 用本地时间算倒计时 | 改钟就提前领奖 |
| 8 | 活动只有三态 | 还有**结算中** |
| 9 | 到点就显示已结束 | 奖励可能还没发完 |
| 10 | 客户端判断是否在维护 | 要**网关直接拒绝** |
| 11 | 补偿发一次就行 | 要**幂等**，否则刷道具 |
| 12 | 邮件不会有问题 | 要处理**过期/附件满/领取幂等** |
| 13 | 发奖失败就算了 | 要**重试与对账** |
| 14 | 客户端能校验兑换码 | = **无限刷** |
| 15 | 兑换码随便生成 | 可猜测会被**扫库** |
| 16 | 同批次可重复领 | 要**玩家—批次唯一约束** |
| 17 | 邀请奖励直接发 | 要防**小号刷** |
| 18 | 客户端报通关可信 | 要**服务端校验** |
| 19 | 埋点不用带分组 | 没有分组就**无法分析实验** |
| 20 | 断网埋点丢了就算 | 要**缓存+补发** |
