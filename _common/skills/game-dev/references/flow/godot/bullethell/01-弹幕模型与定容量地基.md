# 01 弹幕模型与定容量地基（弹幕域）

> **本步交付**：四层分离 + 定容量 MultiMesh + 空闲链表
> **对应**：流程 `howto/godot/genres-bullet-hell.md` · 审核 `audit/godot/genres-bullet-hell.md`

## 0. 交付物定义

1. 数据 / 世界 / 图案 / 碰撞四层已定义，且**逐层写下不应混入什么**
2. `MultiMesh` 的 `instance_count` 在加载时一次定到上限
3. `visible_instance_count` 已**显式**设为 0（⛔ 默认是 -1）
4. 空闲链表已实现，spawn / 回收只改索引，⛔ 不做数组搬移
5. 弹幕数据用扁平数组存，⛔ 不是每颗一个 Vector2 对象

## 1. 前置检查清单

- [ ] 能用一句话说清四层各自职责与禁止字段
- [ ] `instance_count` 只在初始化时写一次
- [ ] `visible_instance_count` 显式设为 0
- [ ] 空闲链表已存在，回收是 O(1)
- [ ] 弹幕位置/速度存在扁平数组里

## 2. 工序

### Step 1　弹幕不是节点：先把四层分开，并写下各层禁止项　`[bullethell/01#S1]`

【读】`howto/godot/genres-bullet-hell.md#0. 四层分离`

【做】
定义 `BulletData`（pos / vel / accel / radius / lifetime）、
`BulletWorld`（定长数组 + 活跃索引）、
`BulletPattern`（Resource + 时间轴）、
碰撞层（只查玩家判定点）四层，并**逐层写下不应混入什么**。
⛔ 每颗子弹一个 `Area2D` —— 千个 `Area2D` 就是千个每物理帧回调
加千份碰撞形状管理，是本类游戏最典型的死法。

ⓘ 四层分开的收益在打满上限时才显现：出问题时能直接问
"是数据错了、世界错了、图案错了、还是判定错了"，
⛔ 混成一层就只能全量排查。

【产出】四层数据结构定义（含各层禁止字段清单）

【判据】指着任意字段能说出它属于哪一层；⛔ 没有字段跨层重复出现。

【审】`audit/godot/genres-bullet-hell.md#1`

### Step 2　instance_count 一次定到上限，运行时只改 visible_instance_count　`[bullethell/01#S2]`

【读】`howto/godot/genres-bullet-hell.md#1. MultiMesh 定容量，运行时只改可见数`

【做】
`mm.instance_count = MAX_BULLETS` 在初始化时写一次，
运行时只改 `mm.visible_instance_count` 与每实例 transform。
⛔ 每帧 `instance_count = n` —— 官方明确该属性
*"clears and (re)sizes the buffers"*，
**完全抵消合批收益**，表现为"合批了但一点没变快"。

ⓘ `MAX_BULLETS` 在这里是**硬上限**，不是当前数量；
上限之内的"有多少颗"由 `visible_instance_count` 与活跃索引表达。

【产出】初始化一次的 MultiMesh 配置

【判据】全局只有一处写 `instance_count`；其余位置只写 `visible_instance_count`。

【审】`audit/godot/genres-bullet-hell.md#2`

### Step 3　visible_instance_count 默认是 -1，必须显式设为 0　`[bullethell/01#S3]`

【读】`howto/godot/genres-bullet-hell.md#8. ⛔ 官方口径：定容量与插值的三条硬约束`

【做】
初始化时显式 `mm.visible_instance_count = 0`。
⛔ 依赖默认值 —— 官方默认值是 `-1`，含义是**画出全部实例**，
会立刻画出 `MAX_BULLETS` 个 transform 未初始化的实例，**全部堆在原点**，
而 `instance_count`、`mesh`、纹理全都检查无误。

ⓘ 这条与 `use_colors` / `use_custom_data` 同源：
官方这几个属性都要求 **在 `instance_count` 为 0 及以下时设置**，
⛔ 先定容量再开颜色 = 逐实例颜色静默不生效。

【产出】显式的初始可见数设置

【判据】空场上线时画面上没有堆在原点的多余子弹。

【审】`audit/godot/genres-bullet-hell.md#12`

### Step 4　空闲链表做对象池，回收是改索引不是搬数组　`[bullethell/01#S4]`

【读】`howto/godot/genres-bullet-hell.md#1. MultiMesh 定容量，运行时只改可见数`

【做】
维护 `_free_list`，spawn 时 `pop_back()`、回收时 `append()`，
⛔ 不用 `Array.remove_at()` 搬移活跃表 ——
搬移会让后续索引整体错位，
表现为"偶尔少一颗 / 偶尔多一颗"，且不报错。
回收统一在**遍历之后**做，⛔ 不在遍历中改活跃表。

ⓘ 回收只是把索引还回空闲链表，**不是把数据清零**；
清零要在 spawn 时做，见 05 的插值重置。

【产出】`spawn()` / `recycle()` / `flush()` 三个函数

【判据】连续打满并回收一万次后，活跃数与空闲数之和恒等于 `MAX_BULLETS`。

【审】`audit/godot/genres-bullet-hell.md#16`

### Step 5　数据扁平化：PackedFloat32Array 交错存，不用对象数组　`[bullethell/01#S5]`

【读】`howto/godot/genres-bullet-hell.md#6. 性能三档`

【做】
位置与速度用 `PackedFloat32Array` 按 `x,y,vx,vy` 交错扁平存，
⛔ 不用 `Array[Vector2]` 或每颗一个字典 / 对象 ——
GDScript 里每帧遍历数千颗更新 `Vector2` 数组通常撑不住，
表现为"弹幕一上千就掉帧"，而逻辑本身没有任何问题。

ⓘ 扁平数组也让 06 的规模档切换更容易：
换 C# / GDExtension 时只需换更新函数，数据布局不变。

【产出】扁平数组布局定义（含各字段偏移量）

【判据】千颗弹幕单帧更新耗时可测，且与弹数近似线性。

【审】`audit/godot/genres-bullet-hell.md#11`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：定容量 + 空闲链表 + 扁平数组
# ⛔ MAX_BULLETS 由 06 规模档实测后回填，此处只示形
class_name BulletWorld extends RefCounted

var mm: MultiMesh
var _x: PackedFloat32Array      # 交错布局：见 S5
var _y: PackedFloat32Array
var _free_list: PackedInt32Array
var _active: PackedInt32Array
# ⛔ 本块只声明步进用的常量，MAX_BULLETS / LOGIC_STEP 由 00 参数表回填
const STRIDE := 4               # x, y, vx, vy

func _init(cap: int) -> void:
    mm = MultiMesh.new()
    mm.transform_format = MultiMesh.TRANSFORM_2D
    mm.mesh = _quad_mesh()
    mm.instance_count = cap         # ⛔ 只在这里写一次
    mm.visible_instance_count = 0   # ⛔ 默认 -1 会画出全部实例
    _x.resize(cap); _y.resize(cap)
    for i in cap:
        _free_list.append(i)

func spawn(px: float, py: float, vx: float, vy: float) -> void:
    if _free_list.is_empty():
        return                      # ⛔ 打满即丢弃，不扩容（见 06）
    var i := _free_list.pop_back()
    _x[i] = px; _y[i] = py
    _active.append(i)
```

ⓘ 上例只示范"定容量 + 空闲链表"，
⛔ 逐实例 transform 的写入要用 `set_instance_transform_2d()`（见 05）。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 弹幕一多就掉帧、GC 抖动 | 每颗一个 `Area2D` 节点 | S1 |
| 合批了但一点没变快 | 每帧写 `instance_count` | S2 |
| 空场也有子弹堆在原点 | `visible_instance_count` 默认 -1 | S3 |
| 偶尔少一颗 / 多一颗 | 遍历中搬移活跃索引 | S4 |
| 上千颗就掉帧 | 用对象数组而非扁平数组 | S5 |
