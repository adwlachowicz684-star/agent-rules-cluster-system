# 06 规模分档与性能预算（弹幕域）

> **本步交付**：档位选型 + 硬上限丢弃策略 + 帧预算分配
> **对应**：流程 `howto/godot/genres-bullet-hell.md` · 审核 `audit/godot/genres-bullet-hell.md`

## 0. 交付物定义

1. 规模档已选定，且选型理由写在参数表里
2. 各档的数据结构与更新方案已确定
3. `MAX_BULLETS` 是**硬上限**，溢出策略已定义
4. 弹幕的帧预算已分配，且给敌机 AI / 掉落留了余量
5. 换档只需要换更新函数，数据布局不变

## 1. 前置检查清单

- [ ] 已实测目标同屏弹幕峰值
- [ ] 档位选型与峰值匹配
- [ ] 溢出策略是丢弃 / 复用最旧，⛔ 不是扩容
- [ ] 有弹幕单独的帧预算数字
- [ ] 换档不改动图案层

## 2. 工序

### Step 1　先实测峰值再选档，⛔ 不凭感觉选方案　`[bullethell/06#S1]`

【读】`howto/godot/genres-bullet-hell.md#6. 性能三档`

【做】
先实测目标场景的**同屏弹幕峰值**，再对照三档选方案：
数百–千余颗用 **GDScript + `PackedFloat32Array`**，
千–数千颗上 **C# 值类型数组**，数千–上万颗才需要 **GDExtension**。
⛔ 凭感觉选 —— 选低了中期全体返工（GDScript 硬扛数千颗通常撑不住），
选高了早期过度设计，⛔ 而两者在开工时都"看起来合理"。

ⓘ 峰值要取**最坏场景**（Boss 全弹幕 + 分裂弹 + 道具掉落），
⛔ 取平均值的后果是"平时很流畅，一到 Boss 就卡"。

【产出】峰值实测记录与档位结论

【判据】参数表里能查到峰值数字与选档理由。

【审】`audit/godot/genres-bullet-hell.md#11`

### Step 2　数百–千余颗：GDScript + 扁平数组 + @onready 缓存　`[bullethell/06#S2]`

【读】`howto/godot/genres-bullet-hell.md#6. 性能三档`

【做】
这一档用 GDScript + `PackedFloat32Array`，节点与资源用 `@onready` 缓存。
⛔ 直接上 C# / GDExtension —— 过早的复杂度，
表现为"弹幕逻辑没人敢改"，
⛔ 而 GDScript 在这一档其实完全够。

【产出】GDScript 档的实现与性能基线

【判据】目标峰值下单帧更新耗时在预算内。

【审】`audit/godot/genres-bullet-hell.md#11`

### Step 3　千–数千颗：C# 用值类型数组，⛔ 不是每颗一个类　`[bullethell/06#S3]`

【读】`howto/godot/genres-bullet-hell.md#6. 性能三档`

【做】
C# 档要用**结构体数组 / 值类型**布局。
⛔ 每颗子弹一个类实例 —— 只是把 GC 压力从 GDScript 搬到 C#，
收益极小，表现为"换了 C# 但没快多少"。

ⓘ 换 C# 的收益来自**去掉装箱与对象头**，
⛔ 保留对象模型就只拿到了语言切换的成本。

【产出】C# 档的结构体布局

【判据】同弹数下 C# 档耗时显著低于 GDScript 档。

【审】`audit/godot/genres-bullet-hell.md#24`

### Step 4　数千–上万颗：GDExtension 要 SoA + 分块，⛔ 不是 AoS　`[bullethell/06#S4]`

【读】`howto/godot/genres-bullet-hell.md#6. 性能三档`

【做】
GDExtension 档用 **SoA（结构数组）**布局并分块处理以拿到 SIMD 收益。
⛔ 用 `Array[Vector2]` 这类 AoS —— 与 GDScript 差别不大，
表现为"写了 GDExtension 但收益配不上维护成本"。

【产出】SoA 布局与分块更新

【判据】上万颗时单帧更新仍在预算内。

【审】`audit/godot/genres-bullet-hell.md#25`

### Step 5　打满即丢弃，⛔ 运行时扩容　`[bullethell/06#S5]`

【读】`howto/godot/genres-bullet-hell.md#1. MultiMesh 定容量，运行时只改可见数`

【做】
`MAX_BULLETS` 是硬上限，打满时**丢弃新弹或复用最旧**。
⛔ 运行时扩容 —— 改 `instance_count` 会
*"clear and (re)size the buffers"*，
表现为"偶尔爆量时整局卡一下"，
⛔ 且这个卡顿只在最坏的那一瞬间出现，最难复现。

ⓘ 丢弃要有**可观察标记**（计数或日志级别），
⛔ 静默丢弃会让"弹幕变少了"变成一个无法定位的现象。

【产出】溢出策略与丢弃计数

【判据】强制打满后丢弃数可见，且帧时间不出现尖峰。

【审】`audit/godot/genres-bullet-hell.md#26`

### Step 6　弹幕要留帧预算给敌机 AI 与掉落，⛔ 不能吃满整帧　`[bullethell/06#S6]`

【读】`howto/godot/genres-bullet-hell.md#6. 性能三档`

【做】
给弹幕定单独的帧预算，剩余留给敌机 AI、掉落、UI。
⛔ 弹幕吃满整帧 —— 表现为"弹幕很流畅但敌机变傻、掉落卡住"，
⛔ 而性能剖析会显示弹幕部分"完全达标"。

ⓘ 预算要按**最坏场景**定，不是平均：
平均帧时间达标但 P99 超预算，玩家感知到的就是偶发卡顿。

【产出】帧预算分配表（弹幕 / AI / 掉落 / UI）

【判据】最坏场景下总帧时间在目标帧率内。

【审】`audit/godot/genres-bullet-hell.md#27`

## 3. 参考实现

```gdscript
# ⓘ 承接 01/02：硬上限 + 丢弃策略
# ⛔ MAX_BULLETS / BULLET_FRAME_MS 由 00 参数表回填
var _dropped := 0

func spawn(px: float, py: float, vx: float, vy: float) -> bool:
    if _free_list.is_empty():
        _dropped += 1               # ⛔ 必须可观察，不能静默丢弃
        return false                # ⛔ 不扩容：改 instance_count 会重分配 buffer
    var i := _free_list.pop_back()
    _x[i] = px; _y[i] = py
    _active.append(i)
    return true

func get_dropped() -> int:
    return _dropped
```
