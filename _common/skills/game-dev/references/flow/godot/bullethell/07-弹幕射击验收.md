# 07 弹幕射击验收（弹幕域）

> **本步交付**：帧率无关实测 + 打满上限实测 + 回放比对实测
> **对应**：流程 `howto/godot/genres-bullet-hell.md` · 审核 `audit/godot/genres-bullet-hell.md`

## 0. 交付物定义

1. **帧率无关性**已实测（锁 30 / 60 / 144 三档）
2. **打满上限**已实测（丢弃可见、无帧时间尖峰）
3. **确定性回放**已实测（同输入两遍 tick 序列一致）
4. 判定点与擦弹已实测（重叠、穿过、边界）
5. 拖影已实测（逐帧截图，新弹第一帧位置正确）

⛔ 弹幕域的 bug **在正常游玩下几乎全测不出** ——
它们只在特定帧率、打满上限、长时间回放、对象池复用时才出现。
所以本步的判据全部是"敌意条件实测"，⛔ 不是"跑一遍看效果"。

## 2. 工序

### Step 1　锁 30 / 60 / 144 FPS 三档跑同一图案，比对弹幕分布　`[bullethell/07#S1]`

【读】`howto/godot/genres-bullet-hell.md#4. 弹幕逻辑用固定步长，不是 delta`

【做】
同一图案在三档帧率下各跑一遍，比对**弹幕数量与分布**。
⛔ 只在 60 FPS 下测 —— 固定步长若没生效，
表现为"144Hz 显示器上弹幕密度不同"，
⛔ 而开发机上通常只有一种帧率，这个问题**永远发现不了**。

【判据】三档下同一 tick 的弹幕位置与数量一致。

【审】`audit/godot/genres-bullet-hell.md#7`

### Step 2　强制打满上限，验证丢弃可见且无帧时间尖峰　`[bullethell/07#S2]`

【读】`howto/godot/genres-bullet-hell.md#1. MultiMesh 定容量，运行时只改可见数`

【做】
用调试指令一次性生成远超上限的弹幕。
⛔ 只测"正常数量" —— 打满路径**几乎不执行**，
一旦执行就是成片问题（扩容重分配或索引越界）。

【判据】丢弃计数可见，帧时间无尖峰，活跃数从不越界。

【审】`audit/godot/genres-bullet-hell.md#26`

### Step 3　同一输入跑两遍，比对 tick 序列与最终分布　`[bullethell/07#S3]`

【读】`howto/godot/genres-bullet-hell.md#5. 图案是数据，不是代码`

【做】
录制输入后跑两遍，比对触发 tick 序列与最终弹幕分布。
⛔ 只比对"看起来一样" —— 浮点漂移会**缓慢累积**，
表现为"回放第 3 分钟开始不一样"，
⛔ 而前两分钟完全一致会给出"没问题"的信号。

【判据】两遍的 tick 序列与最终分布**逐位一致**。

【审】`audit/godot/genres-bullet-hell.md#17`

### Step 4　判定点与擦弹的边界实测：重叠、穿过、边界　`[bullethell/07#S4]`

【读】`howto/godot/genres-bullet-hell.md#3. 判定点与擦弹是两个半径`

【做】
构造三种边界：① 200 颗重叠在判定点；② 一颗子弹缓慢穿过擦弹圈；③ 高速子弹一帧跨过擦弹圈。
⛔ 只测"正常命中" —— 这三个边界分别对应
截断（默认 `max_results` 32）、重复记分、漏记，
⛔ 三者**都不报错**，只是数值不对。

【判据】重叠时返回全部；穿过只加一次分；高速弹的漏记率可接受或已处理。

【审】`audit/godot/genres-bullet-hell.md#4`、`audit/godot/genres-bullet-hell.md#6`

### Step 5　逐帧截图验证新弹第一帧无拖影　`[bullethell/07#S5]`

【读】`howto/godot/genres-bullet-hell.md#8. ⛔ 官方口径：定容量与插值的三条硬约束`

【做】
在弹幕密集、对象池高频复用时逐帧截图，
检查新生成的子弹**第一帧就出现在正确位置**。
⛔ 只看连续动画 —— 拖影是"从旧位置滑过来"，
肉眼在高速运动中**看不出来**，只在逐帧截图里可见。

ⓘ 复用槽位时的拖影最容易漏：
槽位上一帧在屏幕另一头，插值会跨屏滑行。

【判据】逐帧截图里不存在跨屏的拖影线段。

【审】`audit/godot/genres-bullet-hell.md#13`

### Step 6　改系统负载与切后台，验证能恢复到正常速度　`[bullethell/07#S6]`

【读】`howto/godot/genres-bullet-hell.md#9. ⛔ 固定步长累加器必须有上限`

【做】
人为制造一次长卡顿（加载、切后台、断点调试），检查恢复情况。
⛔ 只测"一直流畅" —— 累加器上限的问题**只在卡顿后出现**，
表现为"掉一次帧后再也回不到正常速度"，
⛔ 而开发时卡顿是常态，会被误当成"调试器的问题"。

【判据】长卡顿后能在 1 秒内回到正常速度，且不持续追帧。

【审】`audit/godot/genres-bullet-hell.md#14`

## 3. 验收清单

- [ ] 30 / 60 / 144 FPS 三档弹幕分布一致
- [ ] 打满上限丢弃可见、无尖峰
- [ ] 两遍回放 tick 序列逐位一致
- [ ] 重叠 / 穿过 / 高速三个边界已测
- [ ] 逐帧截图无拖影
- [ ] 长卡顿后能恢复

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 144Hz 上密度不同 | 吃了渲染 delta | 02/S1 |
| 打满时卡一下 | 运行时扩容 | 06/S5 |
| 回放几分钟后不一样 | 时间轴用秒 | 02/S5 |
| 重叠弹漏判 / 擦弹重复计分 | 默认 32 截断 / 未去重 | 03/S2、03/S4 |
| 新弹有拖影 | 插值重置漏了或顺序错 | 05/S5 |
| 卡顿后再也回不去 | 累加器无上限 | 02/S2 |
