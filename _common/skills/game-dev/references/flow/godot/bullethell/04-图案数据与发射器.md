# 04 图案数据与发射器（弹幕域）

> **本步交付**：BulletPattern Resource + tick 时间轴 + 深度上限
> **对应**：流程 `howto/godot/genres-bullet-hell.md` · 审核 `audit/godot/genres-bullet-hell.md`

## 0. 交付物定义

1. 图案是 **Resource**，⛔ 不是一串 `for` 循环
2. 时间轴以 tick 驱动发射器，发射器参数已 Resource 化
3. 图案层只产出 **spawn 请求**，⛔ 不直接碰渲染
4. 分裂弹有**深度上限**
5. 图案支持 seek 到任意 tick 预览

## 1. 前置检查清单

- [ ] `BulletPattern` 是 Resource 且可序列化
- [ ] 时间轴字段是 tick 序号
- [ ] 图案代码里没有出现 `set_instance_transform`
- [ ] 分裂弹有 `MAX_SUB_DEPTH`
- [ ] 有 seek / 预览入口

## 2. 工序

### Step 1　图案是数据，⛔ 不是一串 for 循环　`[bullethell/04#S1]`

【读】`howto/godot/genres-bullet-hell.md#5. 图案是数据，不是代码`

【做】
把图案定义成 `BulletPattern` Resource（发射器表 + 时间轴），
由 `PatternRunner` 按时间表驱动。
⛔ 写成一串 `for` 循环 —— 图案不可复用、不可调参、不可预览，
表现为"改一个角度要改代码重跑"，
⛔ 而这类代码在只有三五个图案时看起来完全够用。

ⓘ 数据化的收益在 Boss 阶段复用时才显现：
同一个环形图案换个半径就是新弹幕，
⛔ 硬编码时每加一个 Boss 都要抄一遍并发散修改。

【产出】`BulletPattern` / `EmitterSpec` / `EmitCommand` 定义

【判据】新增一个图案不需要改任何流程代码。

【审】`audit/godot/genres-bullet-hell.md#8`

### Step 2　发射器参数 Resource 化，⛔ 不写在发射函数里　`[bullethell/04#S2]`

【读】`howto/godot/genres-bullet-hell.md#5. 图案是数据，不是代码`

【做】
弹速、角度、间隔、数量全部是 `@export` 字段。
⛔ 写死在发射函数里 —— 图案无法复用也无法调参，
表现为"数值改一点就要全局搜一遍魔法数"。

ⓘ 参数化还让图案能**跨弹型复用**：
换个贴图或碰撞半径就是新的弹，逻辑不变。

【产出】发射器参数字段清单

【判据】任意弹型的外观与数值可单独改，互不影响。

【审】`audit/godot/genres-bullet-hell.md#19`

### Step 3　图案层只产出 spawn 请求，⛔ 不直接碰渲染　`[bullethell/04#S3]`

【读】`howto/godot/genres-bullet-hell.md#0. 四层分离`

【做】
`PatternRunner` 产出 `spawn(pos, vel)` 请求交给世界层执行。
⛔ 图案直接 `set_instance_transform` —— 图案与规模档耦合，
表现为"换渲染方案要改所有图案"，
⛔ 而这正是 06 要避免的返工。

ⓘ 解耦也带来一个正确性收益：
打满上限时的**丢弃策略**只在世界层一处，
⛔ 图案直接写渲染时每个图案都要自己判断一次。

【产出】`emit()` 请求接口

【判据】图案代码中不出现任何 MultiMesh / 渲染 API。

【审】`audit/godot/genres-bullet-hell.md#20`

### Step 4　分裂弹递归必须有深度上限　`[bullethell/04#S4]`

【读】`howto/godot/genres-bullet-hell.md#5. 图案是数据，不是代码`

【做】
给分裂弹设 `MAX_SUB_DEPTH`，并在运行时检查当前深度。
⛔ 无上限 —— 分裂会被指数级放大，
表现为"某个图案一开就一帧打满上限、整局卡住"，
⛔ 而日志里每一次分裂都是"正常执行"。

ⓘ 上限不是性能调参，是**正确性约束**：
子母弹的分裂次数决定弹幕总量，
⛔ 不设上限等于把总量交给指数函数。

【产出】深度字段与超限处理（不再分裂 or 丢弃）

【判据】任意图案的分裂总量有可计算的解析上界。

【审】`audit/godot/genres-bullet-hell.md#21`

### Step 5　图案要能 seek 到任意 tick 预览　`[bullethell/04#S5]`

【读】`howto/godot/genres-bullet-hell.md#5. 图案是数据，不是代码`

【做】
提供"跳到 tick N"的预览入口（编辑器工具或调试快捷键）。
⛔ 只能从头跑一遍看 —— 调第 40 秒的一个角度要等 40 秒，
表现为"弹幕调参极慢"，进而导致**图案参数长期没人敢动**。

ⓘ seek 能成立的前提是 02 的 tick 计数基准；
⛔ 时间轴若用秒，seek 会因浮点漂移而不精确。

【产出】`seek(tick)` 预览入口

【判据】能直接跳到第 3000 tick 观察该时刻的弹幕形态。

【审】`audit/godot/genres-bullet-hell.md#22`

## 3. 参考实现

```gdscript
# ⓘ 承接 02：时间轴以 tick 计数，不是秒
# ⛔ MAX_SUB_DEPTH 由 00 参数表回填
class_name BulletPattern extends Resource
@export var emitters: Array[EmitterSpec] = []
@export var timeline: Array[EmitCommand] = []   # tick / emitter_id / params

class_name PatternRunner extends RefCounted
var _pattern: BulletPattern
var _tick := 0

func step(world) -> void:            # ⛔ 只产出请求，不碰渲染
    for c in _pattern.timeline:
        if c.tick == _tick:         # ⛔ tick 序号，不是秒
            var spec := _pattern.emitters[c.emitter_id]
            for k in spec.count:
                var a := spec.base_angle + spec.step_angle * k
                world.request_spawn(c.params.pos, Vector2.RIGHT.rotated(a) * spec.speed)
    _tick += 1

func seek(t: int) -> void:
    _tick = t                        # ⓘ 预览入口
```

- [ ] 弹型数值可单独改

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 改一个角度要改代码重跑 | 图案硬编码成 for 循环 | S1 |
| 数值改一点要全局搜魔法数 | 发射器参数写死 | S2 |
| 换渲染方案要改所有图案 | 图案直接写渲染 | S3 |
| 某图案一开就一帧打满 | 分裂无深度上限 | S4 |
| 弹幕调参极慢没人敢动 | 没有 seek 预览 | S5 |
