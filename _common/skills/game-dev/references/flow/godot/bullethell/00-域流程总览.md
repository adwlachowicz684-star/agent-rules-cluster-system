# 弹幕射击（Bullet Hell / SHMUP）—— 域流程总览

> ⚠ **第 0 步：先定"弹幕规模档"，再选渲染与更新方案。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 弹幕发射与基本命中 | 01 → 02 → 03 → 07 |
| 加图案（Boss 弹幕、编队） | 01 → 02 → 04 → 07 |
| 上千颗弹幕的性能优化 | 01 → 02 → 06 → 07 |
| 画面卡顿、拖影、重绘 | 01 → 05 → 06 → 07 |
| 完整弹幕系统 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过** —— 弹幕的形态差异很大（直线弹 / 追踪弹 / 激光 / 分裂弹），
但**定容量与空闲链表**高度统一。⛔ 不先定容量，
就会写成"按需 `add_child()` 再 `queue_free()`"，
表现为"弹幕一多就掉帧、GC 抖动明显"，
而排查时每一处单看都合理。

⛔ **02 的步长要在图案之前定**：先把逻辑步长与 tick 计数定下来，
图案时间轴才有可复现的时间基准。
⛔ 反过来先写图案再改步长 = 所有图案参数要重调一遍。

⛔ **05 的插值重置不能最后补**：
对象池复用槽位时不调 `reset_instance_physics_interpolation()`，
子弹会从上一帧的位置滑过来。
⛔ 这是发版后靠补日志无法定位的问题 —— 日志里每一次 spawn 都正常。

ⓘ 若本次只是**"换一张子弹贴图、加一种弹型外观"**，那是资源配置，不套本域。
ⓘ 若只是**排查子弹不显示**，先看 `2d-rendering` 域确认是排序还是可见性问题，再回本域 01/05。

ⓘ 分工：
- `howto/godot/genres-bullet-hell.md` 讲**各层的技术做法**（MultiMesh、固定步长、判定点、图案 Resource）
- `howto/godot/2d-rendering.md` 讲 **2D 排序与 CanvasLayer 分层**
- 本域讲**这些做法按什么顺序做、怎么保证换规模换帧率后仍然对**

⛔ 若本域某步需要"同屏弹幕上限""判定点像素半径"这类细节，
指向项目实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 弹幕模型与定容量地基 | — | 四层分离 + 定容量 MultiMesh + 空闲链表 |
| 02 | 批量更新与固定步长 | 01 | 固定逻辑步长 + 有上限累加器 + tick 计数 |
| 03 | 碰撞判定点与擦弹 | 01, 02 | 单点查询 + 双半径 + 擦弹去重 |
| 04 | 图案数据与发射器 | 01, 02 | BulletPattern Resource + 时间轴 + 深度上限 |
| 05 | 渲染合批与分层重绘 | 01 | 2D transform 正确写法 + 插值重置 + CanvasLayer 分层 |
| 06 | 规模分档与性能预算 | 01, 02, 05 | 档位选型 + 硬上限丢弃策略 + 帧预算 |
| 07 | 弹幕射击验收 | 全部 | 帧率无关实测 + 打满上限实测 + 回放比对 |

⚠ **01 的定容量要在第一个弹型做出来之前**：
定容量决定整个弹幕世界的数据结构（定长数组 + 索引），
⛔ 先写完"每颗子弹一个节点"再改定容量，等于整块重写。

⚠ **02 的固定步长要在图案之前**：图案时间轴依赖 tick 计数，
⛔ 用秒会因浮点累积让回放密度不同，且这种差异**只在长时间回放时才显现**。

⚠ **06 的规模档要随弹型同步写，不能最后统一补**：
补的时候会顺手把"先用 GDScript 扛着"当成结论，
表现为"中期开始所有弹幕相关改动都在改性能"。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是单颗子弹，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `perf` 域 性能 | 帧预算与剖析方法见 `perf`，⛔ 本域只定弹幕的**硬上限与丢弃策略** |
| `2d-rendering` 域 2D 渲染 | 排序与 CanvasLayer 分层见 `2d-rendering`，⛔ 本域不另定排序口径 |
| `combat` 域 战斗 | 伤害结算与状态见 `combat`，⛔ 本域只产出"命中了哪颗" |
| `firearms` 域 枪械射击 | 玩家侧射击见 `firearms`，⛔ 本域讲敌方弹幕与批量判定 |
| `physics` 域 物理 | 物理插值与 `reset_physics_interpolation` 见 `physics`，⛔ 本域只在 spawn / 复用处引用该口径 |
| `mobile` 域 移动端 | 移动端弹幕数量与内存预算见 `mobile`，⛔ 本域不另定移动端口径 |
| `shaders` 域 着色器 | 弹幕材质与逐实例颜色见 `shaders`，⛔ 本域只定分组与 buffer 写入时机 |
| `ai` 域 敌人 AI | Boss 行为与阶段见 `ai`，⛔ 本域只定图案的触发与停止 |
| `time-progression` | ⓘ howto 层，暂无 flow 域 —— 离线与结算时序见该篇 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `MAX_BULLETS` 弹幕硬上限 | 01 | — | — | 待实测（与规模档与显存相关） |
| `LOGIC_STEP` 固定逻辑步长 | 02 | 1/60 | — | 待实测（⛔ 与 `physics_ticks_per_second` 分开登记） |
| `MAX_CATCHUP_STEPS` 追帧上限 | 02 | — | — | 待实测（⛔ 无上限会 spiral of death） |
| `HIT_RADIUS` 判定点半径 | 03 | 3.0 | — | 待实测（与判定点可视大小相关） |
| `GRAZE_RADIUS` 擦弹半径 | 03 | 24.0 | — | 待实测（与弹速相关，太快会漏记） |
| `MAX_SUB_DEPTH` 分裂弹递归深度 | 04 | — | — | 待实测（⛔ 无上限一帧打满） |
| `BULLET_FRAME_MS` 弹幕帧预算 | 06 | — | — | 待实测（要留预算给敌机 AI 与掉落） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发掉帧""偶发漏判""偶发爆量"，
⛔ 而这类偶发在测试环境几乎不出现。
