# 03 碰撞判定点与擦弹（弹幕域）

> **本步交付**：单点查询 + 双半径 + 擦弹去重
> **对应**：流程 `howto/godot/genres-bullet-hell.md` · 审核 `audit/godot/genres-bullet-hell.md`

## 0. 交付物定义

1. 命中判定是**每帧一次单点查询**，⛔ 不是每颗子弹一个 `Area2D`
2. `intersect_point` 的 `max_results` 已按上限显式设置
3. 判定点与精灵中心分离，且判定点**可见**
4. 擦弹是独立半径，且每颗只记一次
5. 参与判定的碰撞形状确认是 **solid shape**

## 1. 前置检查清单

- [ ] 每帧只有一次 `intersect_point`
- [ ] `max_results` 显式传值，不依赖默认 32
- [ ] 判定点有独立渲染
- [ ] 擦弹集合每帧重建或有去重标记
- [ ] 碰撞形状不是 Segments build mode

## 2. 工序

### Step 1　命中判定是查判定点，⛔ 不是让每颗子弹报 enter　`[bullethell/03#S1]`

【读】`howto/godot/genres-bullet-hell.md#2. 碰撞只查玩家判定点`

【做】
每帧用 `PhysicsPointQueryParameters2D` 在玩家判定点上做**一次**查询。
⛔ 用玩家 `Area2D` 检测每颗子弹进入 ——
几千次 enter / exit 信号分发加每颗一份碰撞形状是双重浪费，
表现为"弹幕一密集就掉帧"，而子弹本身绘制完全正常。

ⓘ 判定点查询还有个正确性收益：
命中与擦弹可以用**同一批数据**算，
⛔ 分成两套检测时两边会各自漂移。

【产出】每帧一次的点查询函数

【判据】弹幕数从 100 涨到 3000，命中判定耗时增长远小于弹数增长。

【审】`audit/godot/genres-bullet-hell.md#3`

### Step 2　intersect_point 的 max_results 默认 32 会截断　`[bullethell/03#S2]`

【读】`howto/godot/genres-bullet-hell.md#2. 碰撞只查玩家判定点`

【做】
显式传 `max_results`（按弹幕上限或粗筛后的候选数），
或先按距离批量粗筛再精查。
⛔ 依赖默认值 —— 密集弹幕下结果被截断，
表现为"明明被打中却没死"，而判定点与半径全都检查无误。

ⓘ 截断**不报错**、也不影响返回值的格式，
⛔ 所以排查时根本不会想到"返回少了"。

【产出】显式的 `max_results` 或粗筛函数

【判据】构造 200 颗重叠在同一判定点的弹幕，返回值包含全部 200 颗。

【审】`audit/godot/genres-bullet-hell.md#4`

### Step 3　判定点不等于精灵中心，且必须看得见　`[bullethell/03#S3]`

【读】`howto/godot/genres-bullet-hell.md#3. 判定点与擦弹是两个半径`

【做】
判定点单独定义并**单独渲染/发光提示**，常见 2–4 px。
⛔ 直接用精灵中心 —— 玩家会按视觉去躲，
表现为"看着躲开了还是被打中"，
⛔ 而这是本类游戏**最能摧毁信任**的一类 bug。

ⓘ 判定点可见不只是美术要求：
它是调试工具，能让"到底哪颗打中了"变成可观察的。

【产出】判定点坐标与独立渲染

【判据】暂停一帧，能指出画面上判定点的确切位置。

【审】`audit/godot/genres-bullet-hell.md#5`

### Step 4　擦弹是独立半径，且每颗只记一次　`[bullethell/03#S4]`

【读】`howto/godot/genres-bullet-hell.md#3. 判定点与擦弹是两个半径`

【做】
擦弹用独立半径，且**每颗子弹只记一次**（进入擦弹圈时打标记，
出圈或子弹回收时清除）。
⛔ 与命中用同一半径 —— 要么"没擦到就算擦了"，要么"擦到了但判定已死"，
表现为擦弹分数与实际玩法不符，且不报错。

ⓘ 擦弹半径要按弹速复核：速度太快时一帧跨过整个擦弹圈，
会**漏记**（见参数登记 `GRAZE_RADIUS`）。

【产出】擦弹集合与去重标记

【判据】让一颗子弹缓慢穿过擦弹圈，只加一次分。

【审】`audit/godot/genres-bullet-hell.md#6`

### Step 5　参与判定的形状必须是 solid shape　`[bullethell/03#S5]`

【读】`howto/godot/genres-bullet-hell.md#2. 碰撞只查玩家判定点`

【做】
确认弹幕碰撞形状不是 **Segments build mode** 的 `CollisionPolygon2D`、
也不是 `ConcavePolygonShape2D`。
⛔ 官方明确这两类**不是 solid shape**，
`intersect_point` 不会检测到它们 ——
表现为"子弹明明在身上却永远判定不到"，
而形状在编辑器里看得到、面积也正确。

ⓘ 这条与"用 Area2D 报 enter"是相反的两个错法：
前者查不到，后者查得到但慢；
⛔ 所以排查"判定不到"时不要只怀疑半径。

【产出】形状类型清单（含禁止项）

【判据】逐颗列出弹型的形状类型，无 Segments / Concave 项。

【审】`audit/godot/genres-bullet-hell.md#18`

## 3. 参考实现

```gdscript
# ⓘ 承接 01/02：扁平数组 + 每帧一次点查询
# ⛔ HIT_RADIUS / GRAZE_RADIUS / MAX_BULLETS 由 00 参数表回填
# ⓘ BULLET_LAYER 为项目物理层常量，在项目的层名常量文件中定义并承接于此
const BULLET_LAYER := 2
const HIT_RADIUS := 3.0
const GRAZE_RADIUS := 24.0

func _check_hit(player_p: Vector2) -> void:
    var q := PhysicsPointQueryParameters2D.new()
    q.position = player_p            # ⛔ 判定点，不是精灵中心
    q.collision_mask = BULLET_LAYER
    # ⛔ max_results 默认 32 会截断密集弹幕，必须显式给
    var hits := get_world_2d().direct_space_state.intersect_point(q, MAX_BULLETS)
    for h in hits:
        _kill_player()

func _check_graze(player_p: Vector2) -> void:
    for i in _active:
        if _grazed.has(i):
            continue                 # ⛔ 每颗只记一次
        if _dist_sq(i, player_p) < GRAZE_RADIUS * GRAZE_RADIUS:
            _grazed[i] = true
            _add_graze_score()
```

ⓘ 上例的 `MAX_BULLETS` 承接 01 参数表，
⛔ `intersect_point` 的第二个参数不能省略。

## 4. 验收清单

- [ ] 弹幕数涨十倍，判定耗时不线性暴涨
- [ ] 200 颗重叠时返回全部
- [ ] 判定点可见且位置可指认
- [ ] 一颗子弹穿过擦弹圈只加一次分
- [ ] 无 Segments / Concave 形状参与判定

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 弹幕一密集就掉帧 | 每颗一个 Area2D 信号 | S1 |
| 明明被打中却没死 | `max_results` 32 截断 | S2 |
| 看着躲开了还是被打中 | 判定点用精灵中心 | S3 |
| 擦弹分数对不上 | 与命中同一半径或未去重 | S4 |
| 子弹在身上判定不到 | 用了非 solid 形状 | S5 |
