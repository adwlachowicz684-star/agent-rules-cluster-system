# 05 渲染合批与分层重绘（弹幕域）

> **本步交付**：2D transform 正确写法 + 插值重置 + CanvasLayer 分层
> **对应**：流程 `howto/godot/genres-bullet-hell.md` · 审核 `audit/godot/genres-bullet-hell.md`

## 0. 交付物定义

1. `TRANSFORM_2D` 格式下用 `set_instance_transform_2d()`
2. `use_colors` / `use_custom_data` 在 `instance_count` 之前开启
3. 单色弹幕用纹理 + shader 参数分组，⛔ 不逐实例刷颜色
4. CanvasLayer 分层，⛔ 不所有节点每帧 `queue_redraw()`
5. spawn / 复用槽位按"三步顺序"重置插值

## 1. 前置检查清单

- [ ] 无 `set_instance_transform()` 出现在 2D 弹幕代码里
- [ ] `use_colors` 的调用位置在定容量之前
- [ ] 颜色按发射器分组而非逐实例
- [ ] 背景 / UI / 玩家 / 弹幕分层
- [ ] spawn 处有 `reset_instance_physics_interpolation()`

## 2. 工序

### Step 1　TRANSFORM_2D 格式要用 set_instance_transform_2d()　`[bullethell/05#S1]`

【读】`howto/godot/genres-bullet-hell.md#8. ⛔ 官方口径：定容量与插值的三条硬约束`

【做】
`transform_format = MultiMesh.TRANSFORM_2D` 时，
逐实例写入一律用 `set_instance_transform_2d()`。
⛔ 用 `set_instance_transform()`（3D 版）传 `Transform2D` ——
类型不匹配，表现为报错或画出的位置完全不对，
⛔ 而这行代码在只有几颗子弹的早期版本里可能"看起来能跑"。

【产出】统一的 2D transform 写入封装

【判据】全局搜索 `set_instance_transform(`，弹幕相关命中为 0。

【审】`audit/godot/genres-bullet-hell.md#23`

### Step 2　use_colors 必须在 instance_count 之前开，⛔ 之后开静默无效　`[bullethell/05#S2]`

【读】`howto/godot/genres-bullet-hell.md#8. ⛔ 官方口径：定容量与插值的三条硬约束`

【做】
`use_colors = true` / `use_custom_data = true` 要在**定容量之前**设置
（或先把 `instance_count` 临时置 0）。
⛔ 先定容量再开 —— 官方明确只能在 `instance_count` 为 0 及以下设置，
结果是逐实例颜色**静默不生效**，
表现为"设了颜色但所有子弹一个色"，且不报错。

ⓘ 这类"顺序敏感的属性"最难查：
属性面板上 `use_colors` 确实是 `true`，
⛔ 排查方向必然被引向颜色值或材质，而不是设置顺序。

【产出】初始化顺序约定（先 flag 后容量）

【判据】给两颗子弹设不同颜色，画面上确实是两种颜色。

【审】`audit/godot/genres-bullet-hell.md#12`

### Step 3　同屏单色弹幕按发射器分组，⛔ 不逐实例刷颜色　`[bullethell/05#S3]`

【读】`howto/godot/genres-bullet-hell.md#7. 渲染与重绘`

【做】
按发射器（颜色）分组，用一张纹理 + shader 参数表达颜色，
⛔ 不每帧调 `set_instance_color` ——
官方说明它仍要走 buffer，
表现为"改了颜色但帧率掉了"，合批收益被抵消。

ⓘ 需要真正逐实例差异时（比如按寿命渐变），
优先用 `custom_data` 传一个标量进 shader 算，
⛔ 而不是在 CPU 侧逐实例算好颜色再写回。

【产出】分组渲染方案（纹理 + shader 参数 / custom_data）

【判据】颜色变化不带来可测的帧时间增长。

【审】`audit/godot/genres-bullet-hell.md#9`

### Step 4　CanvasLayer 分层，⛔ 不让所有节点每帧重绘　`[bullethell/05#S4]`

【读】`howto/godot/genres-bullet-hell.md#7. 渲染与重绘`

【做】
背景、UI、玩家、弹幕分到独立 CanvasLayer，只让需要的节点重绘。
⛔ 所有节点每帧 `queue_redraw()` ——
表现为"弹幕没变但 UI 也跟着重绘，帧时间被背景吃掉"。

ⓘ 弹幕通常**不需要** `queue_redraw()`：
它的位置更新走 MultiMesh transform，不是 CanvasItem 绘制。
⛔ 把弹幕当 CanvasItem 手绘是最常见的性能分档错判。

【产出】CanvasLayer 分层表

【判据】静止场景下（弹幕不动）帧时间内无重绘开销。

【审】`audit/godot/genres-bullet-hell.md#10`

### Step 5　spawn 与复用槽位要按三步顺序重置插值　`[bullethell/05#S5]`

【读】`howto/godot/genres-bullet-hell.md#8. ⛔ 官方口径：定容量与插值的三条硬约束`

【做】
每颗子弹（含对象池复用）按官方"移动起始"三步：
① 设初始 transform → ② `reset_instance_physics_interpolation()` → ③ 立即设第一个 tick 后的 transform。
⛔ 顺序颠倒或漏掉 —— 官方原文：
*"otherwise you will see unwanted streaking"*，
表现为"子弹凭空拖一条线"。

ⓘ 对象池复用时这条**尤其致命**：
该槽位上一帧还在屏幕另一头，
插值会让它从旧位置滑到新位置，
⛔ 而弹幕的 spawn 频率极高，这个拖影会持续可见。

【产出】spawn 与复用处的重置调用

【判据】逐帧截图，新生成的子弹第一帧就出现在正确位置，无拖影。

【审】`audit/godot/genres-bullet-hell.md#13`

## 3. 参考实现

```gdscript
# ⓘ 承接 01：定容量世界；transform_format 为 TRANSFORM_2D
# ⓘ 承接 02 参数表：LOGIC_STEP 为固定逻辑步长，在本块前置声明
const LOGIC_STEP := 1.0 / 60.0

func _init_bullet_mesh(cap: int) -> void:
    mm.use_colors = false            # ⛔ 必须在 instance_count 之前设置
    mm.use_custom_data = true        # 同上；用 custom_data 传标量进 shader
    mm.instance_count = cap
    mm.visible_instance_count = 0

func _place(i: int, px: float, py: float, vx: float, vy: float) -> void:
    # ⛔ 三步顺序：设初始 → reset → 立即设第一 tick 后的位置
    mm.set_instance_transform_2d(i, Transform2D(0.0, Vector2(px, py)))
    mm.reset_instance_physics_interpolation(i)
    mm.set_instance_transform_2d(i, Transform2D(0.0, Vector2(px + vx * LOGIC_STEP, py + vy * LOGIC_STEP)))
    # ⛔ 2D 格式用 set_instance_transform_2d()，不是 set_instance_transform()
```

ⓘ `LOGIC_STEP` 承接 02 参数表；
⛔ 第二步 `reset_instance_physics_interpolation()` 不能省，
否则子弹会从槽位上一帧的位置滑过来。

## 4. 验收清单

- [ ] 弹幕代码无 `set_instance_transform()`
- [ ] 两颗子弹可显示不同颜色
- [ ] 颜色变化不带来帧时间增长
- [ ] 静止场景无重绘开销
- [ ] 新子弹第一帧位置正确、无拖影

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 子弹位置完全不对 / 报错 | 用了 3D 版 `set_instance_transform` | S1 |
| 设了颜色但所有子弹一个色 | `use_colors` 在定容量之后开 | S2 |
| 改了颜色帧率就掉 | 逐实例刷 `set_instance_color` | S3 |
| 弹幕没变但帧时间被吃掉 | 所有节点每帧重绘 | S4 |
| 子弹凭空拖一条线 | 漏掉 / 顺序错的插值重置 | S5 |
