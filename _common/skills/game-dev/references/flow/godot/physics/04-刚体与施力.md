# 04 刚体与施力（physics 域）

> **前置**：02（层与形状已定）
> **本步交付**：**impulse/force 分工明确 + 高速物体不穿透 + 睡眠正确 + 传送无拖影**
> **对应**：做法 `howto/godot/physics.md#3. RigidBody：施力`
> 　　　审核 `audit/godot/physics.md#5`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：物体被推动了就算过了。**

⛔ 常见假完成：用 `apply_impulse` 做持续推力，靠"多调几次"凑效果。
⚠ 这在 60 TPS 下能凑出可接受的手感，
⛔ 但一旦改 TPS（见 01）力就整体缩放，表现为"换个刻度手感全变"。

做完这一步，应该能**当场演示**：

1. 每处施力都能说清是 impulse（一次）还是 force（每物理帧）
2. ⛔ 没有直接写 `linear_velocity` 覆盖物理积分的地方（传送除外）
3. ⚠ 高速物体的 CCD 已开
4. ⚠ 睡眠策略已定，且被撞能唤醒
5. ⛔ **传送与池化复用处都调了 `reset_physics_interpolation()`**

**产出物**：

```text
FORCE_MODEL:  impulse=一次性冲击 / force=每物理帧持续
CCD:          <开启的高速物体清单>
SLEEP:        can_sleep=<bool> + 唤醒条件
RESET_POINTS: <所有传送/入池位置>
```

## 2. 工序

### Step 1　⚠ impulse 一次，force 每物理帧　`[physics/04#S1]`

【读】`howto/godot/physics.md#3. RigidBody：施力`

【做】为每处施力定类型：冲击用 impulse，持续用 force。

⛔ **impulse 每帧调 = 力被放大约 60 倍**（每 tick 施加一次冲量）。
⚠ 表现为"轻推一下物体飞出去"，
⛔ 而调小数值能"修好"——于是埋下随 TPS 变化的隐患。

【产出】`FORCE_MODEL`

【判据】⚠ 无"每帧调 impulse"的调用点

【审】`audit/godot/physics.md#5`

### Step 2　⛔ 不覆盖物理积分　`[physics/04#S2]`

【读】`howto/godot/physics.md#3. RigidBody：施力`

【做】排查直接写 `linear_velocity = x` 的地方，改走施力。

⛔ 直接写速度会**覆盖物理积分**——碰撞与摩擦失效。
⚠ 表现为"物体穿过其他物体"或"推不动"，
⛔ 且在简单场景下看着是"速度控制"，很自然。

ⓘ 例外：**只有传送**才直接改 `position`。

【产出】零覆盖证据

【判据】⛔ 无直接赋值 `linear_velocity` 的持续逻辑

【审】`audit/godot/physics.md#38`

### Step 3　⚠ 高速物体开 CCD　`[physics/04#S3]`

【读】`howto/godot/physics.md#7. 官方故障排查清单`

【做】为高速物体设 `continuous_cd = CCD_MODE_CAST_SHAPE`。

⛔ **穿透（tunneling）**：每 tick 移动距离大于碰撞体厚度时，
两个 tick 之间"跨过去了"，碰撞从未被检测到。
⚠ 官方给了四条解法（CCD / 加厚静态碰撞 / 按速度扩大形状 / 提高 TPS），
⛔ **不是"调小速度"**。

⚠ 表现为"子弹偶尔穿过墙"，
⛔ 偶发、与帧率相关，最难复现的一类。

【产出】`CCD` 清单

【判据】⚠ 清单内物体的 CCD 已开，且实测不穿透

【审】`audit/godot/physics.md#22`

### Step 4　⚠ 睡眠策略与唤醒　`[physics/04#S4]`

【读】`howto/godot/physics.md#3. RigidBody：施力`

【做】定 `can_sleep`，并明确被撞时的唤醒路径。

⛔ 开了睡眠却没唤醒路径 → 物体"睡死"，
表现为"撞它没反应"，⛔ 而检视器里一切正常。

ⓘ 配合 GA-06「状态机只写 enter 不写 exit」：
睡眠是状态，⛔ 只写"进入睡眠"不写"如何唤醒"是同一类缺失。

【产出】`SLEEP` 约定 + 唤醒代码

【判据】⚠ 静止物体能被撞醒，且实测有效

【审】`audit/godot/physics.md#4`

### Step 5　⛔ 传送与池化必须 reset_physics_interpolation　`[physics/04#S5]`

【读】`howto/godot/physics.md#0.4 物理插值（4.4+）`

【做】列出所有传送点（出生、重生、池化取出），逐处调 `reset_physics_interpolation()`。

⛔ **与 destruction 域的接缝最容易漏**：碎片池化必然瞬移，
而瞬移在开插值时必须 reset。
⚠ 表现为池化复用时碎片**拖着一条线飞过去**。

⛔ **关掉插值"就好了"是错误解法**——
它把问题掩盖成"插值有 bug"，而真问题是漏了 reset。

ⓘ 顺序也有讲究：设 transform → reset → （若需立即运动）再设一 tick 后的预期位置。
⛔ 顺序反了照样拖影。

【产出】`RESET_POINTS` 清单

【判据】⛔ 每个传送点都调了，且 10 TPS 下实测无拖影

【审】`audit/godot/physics.md#18`

## 5. 常见返工

**① 每帧 impulse 靠调小数值凑。** 改 TPS 就全变。

**② 直接写速度做推力。** 碰撞/摩擦失效。

**③ 高速物体不开 CCD。** 偶发穿透，与帧率相关。

**④ 睡死不唤醒。** 撞它没反应，检视器正常。

**⑤ 池化不 reset。** 拖影；关插值掩盖真问题。
