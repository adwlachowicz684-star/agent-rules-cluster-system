# 05 角色与移动平台（physics 域）

> **前置**：02（层与形状已定）
> **本步交付**：**角色站得住（斜坡不下滑）+ 站在移动平台上不抖**
> **对应**：做法 `howto/godot/physics.md#6.3 ⛔ 角色在斜坡上下滑`
> 　　　审核 `audit/godot/physics.md#29`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：角色能走能跳就算过了。**

⛔ 常见假完成：平地上跑跳正常就提交。
但本步的三条坑**全部只在斜坡/平台上暴露**：

1. ⛔ 重力无条件施加 → 站斜坡无输入缓慢下滑
2. ⛔ 移动平台用 `StaticBody` → 角色滑落或卡住
3. ⛔ `sync_to_physics` 未设 → 站在平台上抖动

做完这一步，应该能**当场演示**：

1. 角色站在斜坡上**无输入不下滑**，`is_on_floor()` 不闪烁
2. 角色站在移动平台上**随平台移动且不抖**
3. ⛔ 场景里移动平台是 `AnimatableBody`，不是 `StaticBody`
4. ⛔ 每个 `AnimatableBody` 都设了 `sync_to_physics`
5. ⚠ 平台的 Tween/动画跑在物理 tick

**产出物**：

```text
CHAR_FLOOR:   floor_max_angle / floor_snap_length / floor_stop_on_slope
PLATFORM:     AnimatableBody + sync_to_physics=true
GRAVITY_RULE: 仅在非地面时施加
```

## 1. 前置检查清单

- [ ] 02 的角色形状已选（⛔ 非圆柱）
- [ ] ⚠ 已知关卡里最陡的可行走坡度（决定 `floor_max_angle`）
- [ ] ⚠ 已知是否有移动平台、是否开插值
- [ ] 已知是否需要"可推动的箱子"（那是 RigidBody，不是平台）

## 2. 工序

### Step 1　⚠ 定地板三参数　`[physics/05#S1]`

【读】`howto/godot/physics.md#6.3 ⛔ 角色在斜坡上下滑`

【做】按关卡最陡坡度设 `floor_max_angle`、`floor_snap_length`、
`floor_stop_on_slope`。

⛔ `floor_max_angle` **小于实际坡度** → 坡被当成墙，
表现为"走到某个坡度就上不去/一直下滑"，
⚠ 而坡度稍缓的地方完全正常。

ⓘ `floor_stop_on_slope = true` 直接解决"无水平输入时下滑"。

【产出】`CHAR_FLOOR`

【判据】⚠ 最陡可行走坡度处角色能站住

【审】`audit/godot/physics.md#30`

### Step 2　⛔ 重力只在非地面施加　`[physics/05#S2]`

【读】`howto/godot/physics.md#6.3 ⛔ 角色在斜坡上下滑`

【做】在 `is_on_floor()` 为真且无输入时，把 `velocity.y` 归零、不累积重力。

⛔ **无条件施加重力**是斜坡下滑的首要成因：
`move_and_slide()` 把向下的速度转成沿坡面的位移。
⚠ 伴随现象是 `is_on_floor()` 在 true/false 间**闪烁**——
下滑短暂离地 → 重力再拉回 → 循环。

ⓘ 这个闪烁常被误判成"地面检测有问题"。

【产出】`GRAVITY_RULE` + 移动代码

【判据】⛔ 站斜坡无输入时**完全静止**，`is_on_floor()` 稳定

【审】`audit/godot/physics.md#29`

### Step 3　⛔ 移动平台用 AnimatableBody　`[physics/05#S3]`

【读】`howto/godot/physics.md#4. 移动平台`

【做】所有移动平台改用 `AnimatableBody2D/3D`。

⛔ `StaticBody` 移动是**传送**——不会把速度传给站在上面的角色，
⚠ 表现为角色滑落或被卡住。

ⓘ 但要注意：`AnimatableBody` **仍是 StaticBody 的子类**，
不会被玩家推动；"可推动的箱子"要用 `RigidBody`。

【产出】平台节点类型

【判据】⛔ 场景里移动平台无一个是 `StaticBody`

【审】`audit/godot/physics.md#31`

### Step 4　⛔ sync_to_physics 必须开　`[physics/05#S4]`

【读】`howto/godot/physics.md#4. 移动平台`

【做】每个 `AnimatableBody` 设 `sync_to_physics = true`。

⛔ 不设 → 平台移动与物理步不同步，
站在上面的角色**抖动**。
⚠ 抖动幅度与帧率相关，在高帧率下可能看不出来。

【产出】平台同步配置

【判据】⛔ 每个平台都设了，且实测站在上面不抖

【审】`audit/godot/physics.md#32`

### Step 5　⚠ 平台动画跑在物理 tick　`[physics/05#S5]`

【读】`howto/godot/physics.md#6.2 ⓘ 移动平台与角色`

【做】平台的 Tween/AnimationPlayer 设为物理 tick 处理。

⛔ 开了插值（01 S3）却让平台动画跑在 idle → 平台抖，
且站在上面的角色跟着抖。

ⓘ 这条与 01 的插值开关**强耦合**：
不开插值时不明显，开了就暴露——
⚠ 于是常被误判成"插值有问题"。

【产出】平台动画处理模式

【判据】⚠ 10 TPS 下平台与角色均无可见抖动

【审】`audit/godot/physics.md#33`

## 5. 常见返工

**① floor_max_angle 用默认。** 陡坡上不去/下滑。

**② 无条件施加重力。** 斜坡下滑 + is_on_floor 闪烁。

**③ 平台用 StaticBody。** 角色滑落。

**④ 不开 sync_to_physics。** 平台上抖动。

**⑤ 平台动画跑 idle。** 开插值后抖，误判成插值问题。
