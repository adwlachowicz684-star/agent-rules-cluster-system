## 2. 工序

### Step 1　改 scale 会连带改纹理清晰度　`[upscaling/06#S1]`

【读】`howto/godot/upscaling.md#11. ⚠ 负 mipmap LOD bias：改缩放 / 改 AA 会连带改纹理清晰度`

【做】
`scaling_3d_scale < 1.0` 时引擎自动施加**负 mipmap LOD bias**：

```
log2f(min(scaling_3d_scale, 1.0)) + custom_texture_mipmap_bias
```

为抵消抗锯齿的模糊，还会额外叠加：FXAA `-0.25`、TAA `-0.5`、两者都开 `-0.75`。
ⓘ 官方注明该偏移在分辨率缩放偏移**之前**应用，**不随缩放值变化**。

⛔ "改 scale 只影响分辨率"是错的 ——
⛔ 负 bias 会让画面在**运动时发颗粒感**，且可能降低性能（要采样更高分辨率的 mip）；
⛔ 正 bias 会让贴图变糊，手动调只建议在 `-0.5 ~ 0.0` 之间。

【产出】当前 scale 与 AA 下的 LOD bias 实算值

【判据】能算出当前 bias，并判断运动颗粒感是否由此而来。

【审】`audit/godot/upscaling.md#29`

### Step 2　降 scale 不涨帧 = 瓶颈不在分辨率　`[upscaling/06#S2]`

【读】`howto/godot/upscaling.md#12. ⚠ 缩放是逐轴的 + 降 scale 不涨帧说明瓶颈不在分辨率`

【做】
官方 Troubleshooting：降低到 0.5 而性能没明显提升 →
⛔ **瓶颈不在分辨率**，而在别处（官方点名两类：draw call 太多＝CPU 瓶颈；
开了 SDFGI / SSAO / SSR 等＝GPU 侧不被分辨率限制）。

⛔ "降 scale 一定涨帧"是错的。
⛔ 这条最实际的用途：**不要用"降 scale 没用"去继续降 scale** ——
那时应该去 `perf` 域定位，而不是把画质越调越低。

【产出】瓶颈归属判定（分辨率 / CPU / GPU 其他）

【判据】能把"降 scale 无效"正确归因到 CPU 或 GPU 其他环节。

【审】`audit/godot/upscaling.md#30`

### Step 3　缩放是逐轴的，0.1 的改动不是线性　`[upscaling/06#S3]`

【读】`howto/godot/upscaling.md#12. ⚠ 缩放是逐轴的 + 降 scale 不涨帧说明瓶颈不在分辨率`

【做】
官方原话：*"halving the resolution scale factor will reduce the number of
rendered megapixels per frame by a factor of **4, not 2**"*。

⛔ "缩放是线性的、0.1 微调可控"是错的 ——
从 1.0 降到 0.5 只渲 **1/4** 的像素；
反向也成立：想靠 scale 精细调性能时，0.1 的改动会带来远超预期的帧时间变化。

【产出】按逐轴关系设计的档位表

【判据】能说清 0.5 档位实际渲染多少像素。

【审】`audit/godot/upscaling.md#31`

### Step 4　不要用缩放替代画质降级　`[upscaling/06#S4]`

【读】`howto/godot/upscaling.md#12. ⚠ 缩放是逐轴的 + 降 scale 不涨帧说明瓶颈不在分辨率`

【做】
官方建议：**同时暴露"分辨率缩放"与"画质设置"两个选项**。

⛔ "用分辨率缩放代替画质档位"是错的 ——
缩放只能改渲染像素数，改不了 draw call、阴影、后处理这些真正的画质项，
⛔ 在低端硬件上靠降缩放救帧率，会把画面糊到不可用。

【产出】设置界面里两个选项都在

【判据】低端设备上玩家能分别调画质和分辨率。

【审】`audit/godot/upscaling.md#36`

### Step 5　2D 纹理默认不开 mipmap，所以通常不受影响　`[upscaling/06#S5]`

【读】`howto/godot/upscaling.md#11. ⚠ 负 mipmap LOD bias：改缩放 / 改 AA 会连带改纹理清晰度`

【做】
LOD bias 同时影响 2D 与 3D，ⓘ 但 **2D 纹理默认不开 mipmap**，
所以只有给 2D 纹理开了 mipmap 才会被影响
（表现为 2D 元素变**颗粒 / 噪点**）。

⛔ "2D 纹理也会被 LOD bias 影响"要分情况 ——
默认情况下不受影响，⛔ 盲目去改 2D 纹理的导入设置是错方向。

ⓘ 仅 Forward+ / Mobile 可用此属性，Compatibility **不支持**。

【产出】2D 纹理的 mipmap 状态与是否需处理

【判据】能说清本项目的 2D 纹理会不会被 LOD bias 影响。

【审】`audit/godot/upscaling.md#41`

## 3. 参考实现

```gdscript
# ⓘ 承接 Step 1：按官方公式实算，⛔ 不凭感觉调
func current_lod_bias(scale_3d: float, aa: String) -> float:
    var bias := log(min(scale_3d, 1.0)) / log(2.0)
    if aa == "fxaa": bias -= 0.25
    elif aa == "taa": bias -= 0.5
    return bias
```
