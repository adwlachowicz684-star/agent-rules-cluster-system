# 画质管线：超分、抗锯齿、后处理 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只是调一下画质参数 | 01 → 03 → 07 |
| 画面"糊"，要定位是哪个环节 | 01 → 02 → 03 → 04 → 07 |
| 要做画质档位 / 设置界面 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |
| 要上移动端 / 低端设备 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |
| 完整画质管线工程 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过**：画质最容易错序的一步就是 01 三条管线定性 ——
先把超分和抗锯齿一起调，会发现"糊"分不清是哪条管线造成的，
三条都会糊，而**后处理会掩盖上游的糊**。

ⓘ 若本次只是**排查为什么掉帧**，先看 `perf` 域定位瓶颈，
⛔ 不要在画质域里猜（降 scale 不涨帧说明瓶颈根本不在分辨率，见 06）。

ⓘ 分工：
- `howto/godot/upscaling.md` 讲**单个要素怎么实现**（五种超分、AA 方案、LOD bias、逐轴缩放）
- 本域讲**这些要素按什么顺序做、怎么保证档位可复现、怎么保证不看面板看画面**

⛔ 若本域某步需要"某个 GPU 上的具体耗时"这类细节，
指向 `perf` 域实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 三条管线定性 | — | 三条管线归属表 + 2D/3D 判定 + UI 分层方案 |
| 02 | 渲染器与平台基线 | 01 | 目标渲染器确认 + 支持矩阵 + 平台限制清单 |
| 03 | 超分选型与 scale 语义 | 01, 02 | 模式定死 + scale 取值语义 + 档位表 |
| 04 | 抗锯齿选型与组合 | 02, 03 | AA 方案 + 与超分的组合关系 + 透明锯齿解法 |
| 05 | 后处理与 HDR / Tonemap | 01, 02 | 后处理代价排序表 + tonemap 模式 |
| 06 | 纹理清晰度与性能归因 | 03, 04 | LOD bias 实算 + 瓶颈归属判定 + 双选项设置 |
| 07 | 画质验收 | 全部 | 逐项开关对比 + 逐档验证 + 截图判据 |

⚠ **02 必须在 03 之前**：先定模式再查支持矩阵，
会发现选中的模式在目标渲染器下**根本不是那个行为**
（FSR2 在 Compatibility 回退双线性、在 Mobile 下以原生分辨率作 TAA）。

⚠ **03 必须在 04 之前**：AA 与超分的组合关系由超分模式决定 ——
FSR2 会让 `Use TAA` 被忽略，⛔ 反过来先定 AA 会得到一个没生效的组合。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `perf` 域 性能分析 | 降 scale 不涨帧的归因见 06 S2；⛔ 具体耗时以实测为准，本域不给数字 |
| `shaders` 域 着色器 | 自定义后处理走 `CompositorEffect`，与 05 的代价排序相接；⛔ 内置 WorldEnvironment 优先 |
| `mobile` 域 移动端 | Mobile 渲染器下的模式降级见 02 S6；⛔ 摇杆与适配不属本域 |
| `platform-export` 域 导出 | 目标平台的驱动可用性（MetalFX 需 Metal 驱动）见 02 S5 |
| `ui` 域 UI | UI 分层渲染见 01 S5；⛔ UI 糊了不要回来调 3D 超分 |
| `2d-rendering` 域 2D 渲染 | 2D 走 stretch 管线，与 3D 的 scaling_3d 互不相干，见 01 S2 |
| `lighting` | ⓘ howto 层，暂无 flow 域 —— 光照与 tonemap / HDR 的选择相接（见 05 S2） |
| `render-pipeline` | ⓘ howto 层，暂无 flow 域 —— 渲染器架构背景见 02 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `POST_BUDGET_MS` 后处理总预算 | 05 | — | — | 待实测（⛔ 同效果在不同分辨率 / 渲染器下代价差异很大） |
| `NEAREST_STEPS` 低分辨率档位 | 03 | 1.0 / 0.5 / 0.3333 / 0.25 | — | 待实测（⛔ 只取 1 的整数除数，非整数除数会像素不均） |
| `SSAA_STEPS` 超采样档位 | 03 | 1.0 / 2.0 | — | 待实测（⛔ 只取整数倍，1.5 反而比 2.0 糊） |
| `DEFAULT_UPSCALE_ENABLED` 超分默认开关 | 01 | false | — | 待实测（ⓘ 按画风定：像素风默认关，⚠ 不是默认开启） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"画面糊了但说不清是哪条管线""花了性能却没买到清晰度"
"低端机上降缩放救不了帧率"，⛔ 而这类失败在默认档、桌面预览下几乎不出现。
