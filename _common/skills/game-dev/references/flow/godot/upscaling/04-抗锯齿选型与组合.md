## 2. 工序

### Step 1　TAA 与 FSR2 不能叠加，Use TAA 会被忽略　`[upscaling/04#S1]`

【读】`howto/godot/upscaling.md#10. ⛔ TAA 与 FSR2 不能叠加`

【做】
官方原话：*"The **Use TAA** project setting is **ignored** when FSR2 is used
as the 3D scaling method, since FSR2's temporal antialiasing takes priority."*

⛔ "TAA 与 FSR2 能叠加改善"是错的 —— 面板上两项**都开着**，
画质没有叠加改善，⛔ 而排查方向必然被引向"TAA 参数没调好"。

ⓘ 配套三条：FSR1 最好配 TAA 或 MSAA（FXAA 不提供时域信息，只会更糊）；
FSR2 不再叠 MSAA（收益很小）；TAA 静止画面也有轻微模糊、相机移动时更明显。

【产出】AA 与超分的组合关系表（谁真正生效）

【判据】能说清当前配置下真正生效的时域抗锯齿是哪一个。

【审】`audit/godot/upscaling.md#26`

### Step 2　MSAA 治不了 alpha scissor，要看 TAA / FXAA / 超采样　`[upscaling/04#S2]`

【读】`howto/godot/upscaling.md#7. 抗锯齿：先确认渲染器，再选方案`

【做】
alpha scissor 走 `discard`，⛔ **不产生 MSAA 需要的覆盖信息**。

⛔ "MSAA 能治植被闪烁"是错的 —— 无效。
ⓘ 官方：MSAA 不会抗锯齿纹理边缘，除非材质开了 alpha antialiasing；
但 **FXAA / TAA / 超采样**无论材质是否开 alpha antialiasing 都能抗这类边缘。

ⓘ 另一条路是材质上开 **alpha-to-coverage**：中等性能代价，
⛔ 但**不引入模糊**（与 FXAA 的关键差别）。

【产出】透明 / 植被边缘的 AA 方案

【判据】植被边缘闪烁时，知道该上 TAA / FSR2 还是 alpha-to-coverage。

【审】`audit/godot/upscaling.md#21`

### Step 3　别指望一种 AA 治所有锯齿　`[upscaling/04#S3]`

【读】`howto/godot/upscaling.md#2. 抗锯齿：渲染器支持矩阵完全不同`

【做】
FSR2 自带时域抗锯齿，⛔ 但"FSR2 能治所有锯齿"是错的 ——
官方明确 **镜面反射锯齿仍以 TAA 最有效**（屏幕空间粗糙度限制器效果远不如 TAA）；
透明边缘则见上一步，MSAA 无效而 FXAA / TAA / 超采样有效。

⛔ 表现是"上了一个方案，几何边缘好了但高光仍在闪"，
然后反复调一个对该类锯齿无效的方案。

【产出】各类锯齿 → 对应方案的对照表

【判据】能分清楚几何锯齿、透明锯齿、镜面反射锯齿分别靠什么。

【审】`audit/godot/upscaling.md#2`

### Step 4　SMAA 是内置的，别去找插件　`[upscaling/04#S4]`

【读】`howto/godot/upscaling.md#2. 抗锯齿：渲染器支持矩阵完全不同`

【做】
SMAA 1x 自 **4.2 起内置**于 `screen_space_aa` 枚举。

⛔ "SMAA 要装社区插件"是错的 —— 它不是社区方案，
⛔ 按"待核对 / 社区方案"处理会让人白去找第三方实现。
ⓘ 官方注明 1080p 及以下最有效；可与 TAA / FSR2 叠加
（代价更高、更糊）。

【产出】SMAA 是否进入候选及理由

【判据】在项目设置的 `screen_space_aa` 里能看到 SMAA，不需要插件。

【审】`audit/godot/upscaling.md#33`

### Step 5　透明 viewport 上开 TAA / FSR2 会变不透明　`[upscaling/04#S5]`

【读】`howto/godot/upscaling.md#⚠ 透明 viewport 上的已知问题（issue #69492）`

【做】
官方 issue #69492：在开了 per-pixel transparency 的 viewport 上
启用 **TAA 或 FSR2 会让 viewport 变不透明**（FXAA 与 MSAA 不受影响）。

⛔ "TAA 不影响透明背景"是错的 —— 表现为
"做透明背景 / 内嵌 3D 视图时，一开 TAA 背景就黑了"，
⛔ 而排查被引向 alpha 设置或合成模式。

【产出】透明 viewport 场景下的 TAA / FSR2 处置（禁用或换 FXAA / MSAA）

【判据】透明 viewport 场景下能说清为什么不用 TAA。

【审】`audit/godot/upscaling.md#35`

## 3. 参考实现

```gdscript
# ⓘ 承接 Step 1/5：FSR2 下 Use TAA 无效；透明 viewport 禁用时域方案
const USE_TAA := false                 # ⛔ FSR2 下该设置被忽略
const AA_FOR_TRANSPARENT_VIEWPORT := "fxaa"   # ⛔ TAA/FSR2 会让 viewport 变不透明
```
