# 01 三条管线定性（画质域）

> **本步交付**：三条管线归属表 + 2D/3D 判定 + UI 分层方案
> **对应**：流程 `howto/godot/upscaling.md` · 审核 `audit/godot/upscaling.md`

## 0. 交付物定义

1. 三条管线各自的作用对象与机制已写清，⛔ 不混为一谈
2. 本次遇到的"糊"已判定归属 2D 画布还是 3D 视口
3. `stretch/mode` 与 `stretch/aspect` 已显式写死，⛔ 不依赖默认值
4. 超分开关已按画风决定，⛔ 不是默认开启
5. UI 已在不受 3D 缩放影响的层，⛔ 不靠调回 scale 1.0 解决

## 1. 前置检查清单

- [ ] 能说出三条管线各自的作用对象（2D / 3D / 全局）
- [ ] 已确认本次的画质问题出在哪条管线
- [ ] ⚠ `stretch` 两个设置是显式选过的，不是"没改过"
- [ ] 已按画风决定超分开或关，并有理由
- [ ] UI 所在层与 3D 视口已分层

## 2. 工序

### Step 1　三条管线先分清，它们互不相干　`[upscaling/01#S1]`

【读】`howto/godot/upscaling.md#0. 三条独立管线，别混为一谈`

【做】
写下三条管线各自的作用对象与机制：

| 管线 | 作用对象 | 机制 |
|---|---|---|
| 窗口 / 画布拉伸 | 2D | `stretch/mode` + `stretch/aspect` |
| 3D 视口分辨率缩放 | 3D | `scaling_3d_mode` + `scaling_3d_scale` |
| 后处理 | 全局 | `WorldEnvironment` + `CompositorEffect` |

⛔ 最常见的错误是以为 `stretch/mode` 能降 3D 渲染分辨率 ——
这是**两套独立机制**，调一个完全不影响另一个。
表现为"改了半天没反应"，而排查被引向缓存或重启。

【产出】三条管线归属表（作用对象 + 机制）

【判据】指着任意一个画质选项，能说出它属于哪条管线、作用对象是 2D 还是 3D。

【审】`audit/godot/upscaling.md#1`

### Step 2　2D 糊与 3D 糊是两条管线，别互相调　`[upscaling/01#S2]`

【读】`howto/godot/upscaling.md#0. 三条独立管线，别混为一谈`

【做】
先判定当前这个"糊"出现在哪：UI 或 2D 元素糊 → 走 `stretch`；
3D 场景糊 → 才看 `scaling_3d`。

⛔ 调 3D 超分去修 UI 糊是**完全错误的方向** ——
2D 走 stretch，3D 走 scaling_3d，两条管线互不相干。
表现为"3D 调清楚了 UI 还是糊"，然后反复调一个不该动的旋钮。

【产出】本次"糊"的归属判定（2D 画布 / 3D 视口）

【判据】能说清当前这个"糊"出现在 2D 画布还是 3D 视口。

【审】`audit/godot/upscaling.md#23`

### Step 3　4.7 新建项目的 stretch 默认值变了　`[upscaling/01#S3]`

【读】`howto/godot/upscaling.md#4.7 的两个关键变化`

【做】
显式写死 `stretch/mode` 与 `stretch/aspect`，⛔ 不要依赖默认值：
4.7 起新建项目从 `disabled/keep` 改为 **`canvas_items/expand`**。

⛔ 这条最实际的后果是"升级引擎后画面比例变了"，
而排查被引向分辨率设置或适配代码 —— 没人会想到是默认值改了。

【产出】已写死的两个 stretch 设置及取值

【判据】项目设置里的值不是"没改过"，而是明确选过的。

【审】`audit/godot/upscaling.md#11`

### Step 4　先定 2D 画风：像素风通常不该开超分　`[upscaling/01#S4]`

【读】`howto/godot/upscaling.md#1. 超分：内置五种，没有 FSR3/DLSS/XeSS`

【做】
按画风决定超分开关，⛔ 不是默认开启。
2D 像素游戏开超分会让像素边缘糊掉，与美术目标冲突 ——
"超分对所有游戏都好"是错的。

⛔ 判据不是"要不要开"，而是"这个画风的目标是什么"：
像素风的目标是边缘锐利，超分正好破坏它。

【产出】画风与超分开关的对应关系及理由

【判据】能一句话说清本项目的画风要不要超分，以及为什么。

【审】`audit/godot/upscaling.md#7`

### Step 5　UI 要分层渲染，别靠把 scale 调回 1.0 解决　`[upscaling/01#S5]`

【读】`howto/godot/upscaling.md#⚠ UI 被超分糊掉的正确解法`

【做】
把 UI 放在**不受 3D 缩放影响的层**（独立 `CanvasLayer` / 独立 `Viewport`）。

⛔ 不要靠"把 scale 调回 1.0"来解决 —— 那等于放弃超分。
UI 和 3D 一起超分，UI 会被糊掉，而这是最容易被玩家一眼看出的画质问题。

【产出】UI 所在层与 3D 视口的分层关系

【判据】把 3D 的 scale 降到 0.5，UI 文字仍然清晰。

【审】`audit/godot/upscaling.md#8`

## 3. 参考实现

```gdscript
# ⓘ 承接 Step 3：stretch 显式写死，不依赖默认值
ProjectSettings.set_setting("display/window/stretch/mode", "canvas_items")
ProjectSettings.set_setting("display/window/stretch/aspect", "expand")
```

ⓘ 2D 画风为像素风时超分默认关（见 Step 4）：

```gdscript
const DEFAULT_UPSCALE_ENABLED := false   # ⓘ 像素风：默认关，见 01 S4
```

## 5. 常见返工

| 症状 | 回到 |
|---|---|
| 改了画质设置完全没反应 | S1 —— 调的不是那条管线 |
| UI 糊了去调 3D 超分 | S2 —— 两条管线互不相干 |
| 升级引擎后画面比例变了 | S3 —— stretch 默认值改了 |
| 超分开了但 2D 变糊 | S4 —— 画风与超分冲突 |
| 为了 UI 清晰把 scale 调回 1.0 | S5 —— 等于放弃超分 |
