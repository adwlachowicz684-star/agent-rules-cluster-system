# 02 渲染器与平台基线（画质域）

> **本步交付**：目标渲染器确认 + 支持矩阵 + 平台限制清单
> **对应**：流程 `howto/godot/upscaling.md` · 审核 `audit/godot/upscaling.md`

## 0. 交付物定义

1. 目标渲染器（Forward+ / Mobile / Compatibility）已定死
2. AA 方案按渲染器查过支持矩阵，⛔ 不是"选一个就行"
3. TAA 与 MSAA 在三个渲染器下的可用性已分别标出
4. 候选清单里没有 FSR3 / DLSS / XeSS
5. MetalFX 的可用性按**驱动**判定，⛔ 不是按操作系统
6. 所选超分模式在目标渲染器下的**实际行为**已确认

## 1. 前置检查清单

- [ ] 已定死要支持哪几个渲染器
- [ ] 已确认最低设备档位
- [ ] ⚠ 支持矩阵是查过的，不是按桌面预览推断的
- [ ] 候选模式清单里没有不存在的方案
- [ ] 已确认目标平台的渲染驱动

## 2. 工序

### Step 1　先确认目标渲染器，再谈任何画质选项　`[upscaling/02#S1]`

【读】`howto/godot/upscaling.md#2. 抗锯齿：渲染器支持矩阵完全不同`

【做】
先把目标渲染器（Forward+ / Mobile / Compatibility）定死，再查支持矩阵。

⛔ "AA 方案选一个就行"是错的 —— 必须先确认渲染器，
**支持矩阵完全不同**，在 Forward+ 上调好的组合换到 Compatibility 可能一项都不成立。

【产出】目标渲染器清单 + 最低设备档位

【判据】能说清本次要支持哪几个渲染器，以及最低档位跑哪个。

【审】`audit/godot/upscaling.md#22`

### Step 2　TAA 仅 Forward+，另两个渲染器不支持　`[upscaling/02#S2]`

【读】`howto/godot/upscaling.md#2. 抗锯齿：渲染器支持矩阵完全不同`

【做】
在支持矩阵上逐项标出三个渲染器的可用性。

⛔ "TAA 三个渲染器都能用"是错的 —— **仅 Forward+**，
Mobile 与 Compatibility 均不支持。
表现为"设置里勾了 TAA 但画面完全没变化"，⛔ 且不报错。

【产出】TAA 在三个渲染器下的可用性表

【判据】Compatibility 下不再期待 TAA 生效。

【审】`audit/godot/upscaling.md#5`

### Step 3　2D MSAA 与 3D MSAA 的支持矩阵完全不同　`[upscaling/02#S3]`

【读】`howto/godot/upscaling.md#2. 抗锯齿：渲染器支持矩阵完全不同`

【做】
2D MSAA 在 Forward+ 与 Mobile 可用、在 Compatibility 不可用 ——
这与 3D MSAA 的支持矩阵**完全不同**，⛔ 别按 3D 的经验推断 2D。

ⓘ 同一节里 FXAA 也有渲染器限制：⛔ **不支持 Compatibility**，
仅 Forward+ 与 Mobile 可用。

【产出】2D / 3D MSAA 与 FXAA 各自的可用性

【判据】能分别说出 2D MSAA、3D MSAA、FXAA 在 Compatibility 下能否用。

【审】`audit/godot/upscaling.md#6`、`audit/godot/upscaling.md#34`

### Step 4　没有 FSR3、没有原生 DLSS / XeSS，别按名字找　`[upscaling/02#S4]`

【读】`howto/godot/upscaling.md#1. 超分：内置五种，没有 FSR3/DLSS/XeSS`

【做】
只用内置的五种（Bilinear / FSR 1.0 / FSR 2.2 / MetalFX / Nearest）。

⛔ "有 FSR3"是错的 —— 内置只有 **FSR 2.2**，没有 FSR3、也没有帧生成。
⛔ "有 DLSS / XeSS"是错的 —— 只存在于 NVIDIA 的 RTX path-tracing fork
与少量 GDExtension 实验项目，属**实验性 fork**，不可投产。

⛔ 后果不是"用不了"，而是"按名字去找，找到一个看起来能用但不可投产的第三方实现"。

【产出】候选模式清单（不含不存在的方案）

【判据】清单里没有 FSR3 / DLSS / XeSS。

【审】`audit/godot/upscaling.md#3`、`audit/godot/upscaling.md#4`

### Step 5　MetalFX 是驱动级限制，不是操作系统限制　`[upscaling/02#S5]`

【读】`howto/godot/upscaling.md#MetalFX 的平台限制是**驱动级**的`

【做】
判定条件是"Metal rendering driver 是否在用"，⛔ 不是"是不是 Mac"。
官方原话：*"Only supported when the **Metal rendering driver** is in use,
which limits this scaling mode to macOS and iOS."*

⛔ "MetalFX 全平台"是错的 —— 仅 **Apple 平台**；
⛔ "在 Mac 上就能用"也是错的 —— 在 macOS 上用非 Metal 驱动**仍然不可用**。

【产出】MetalFX 可用性的判定条件（按驱动，不按系统）

【判据】能说清"在 Mac 上但仍不可用"是什么情况。

【审】`audit/godot/upscaling.md#15`、`audit/godot/upscaling.md#20`

### Step 6　同一个模式在不同渲染器下行为不同　`[upscaling/02#S6]`

【读】`howto/godot/upscaling.md#1. 超分：内置五种，没有 FSR3/DLSS/XeSS`

【做】
FSR 2.2 在 Compatibility 下**不支持、回退双线性下采样**；
在 Mobile 下**以原生分辨率作 TAA 使用**。

⛔ "FSR2 在各渲染器一样"是错的 —— 同一个枚举值在三个渲染器下是三种行为。
这是最容易误判的地方：面板上写着 FSR2，实际跑的可能是双线性甚至 TAA。

【产出】所选模式在目标渲染器下的实际行为

【判据】能说清所选模式在 Compatibility / Mobile 下分别变成什么。

【审】`audit/godot/upscaling.md#9`

## 3. 参考实现

```gdscript
# ⓘ 承接 Step 1/6：按渲染器分派，而不是写死一个模式
const MODE_BY_RENDERER := {
    "forward_plus":  Viewport.SCALING_3D_MODE_FSR2,
    "mobile":        Viewport.SCALING_3D_MODE_FSR2,   # ⓘ 原生分辨率作 TAA
    "gl_compatibility": Viewport.SCALING_3D_MODE_BILINEAR,  # ⛔ FSR2 回退双线性
}
```
