# 06 相机状态机与异常退出（camera 域）

> **前置**：`03-多相机管理与优先级.md` 已完成

> **对应**：做法 `howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`
> 　　　审核 `audit/godot/camera-cutscene.md#25`

## 0. 交付物定义

⚠ **本步针对"异常路径"：正常流程相机都对，异常一来就废。**

⛔ 常见假完成：只写"进入"逻辑——
⚠ 死亡/过场/菜单的相机状态机**只写 enter 不写 exit**，
⛔ 异常中断时相机**停在中间态**，玩家无法自行恢复。

做完这一步，应该能**当场演示**：

1. ⛔ 死亡相机在**复活后**正确还原（不是停在死亡视角）
2. ⚠ 菜单打开时相机**被接管或冻结**（背后不动）
3. ⛔ 强制中断（跳关/重开）后相机**回到正常**
4. ⚠ 状态机**有 exit**且从**快照**恢复（不是置 true）
5. ⛔ 屏震在异常中断时**不残留**

**产出物**（下游按名字对接）：

```text
状态机：enter / exit 成对
恢复方式：从快照恢复，⛔ 不是 can_move = true
栈重置：强制中断时清空
```

## 2. 工序

### Step 1　⛔ 状态机必须写 exit　`[camera/06#S1]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】每个接管相机的状态都有配对的退出逻辑。

⛔ 只写 enter → 异常中断时相机停在中间态，
⚠ 表现为"死亡后镜头一直俯视地面"，且**不会自行恢复**。

【产出】exit 逻辑

【判据】⚠ 每个接管状态**都有** exit

【审】`audit/godot/camera-cutscene.md#25`

### Step 2　⛔ 从快照恢复，不置 true　`[camera/06#S2]`

【读】`howto/godot/camera-cutscene.md#6. 过场三要素必须写成同一状态机`

【做】恢复时还原进入前的快照。

⛔ 硬编码"恢复成正常相机" → 嵌套时还原错，
⚠ 且会覆盖真实的上层请求，
表现为"菜单关掉后相机去了一个不该去的地方"。

【产出】快照恢复

【判据】⚠ 嵌套退出后**逐层正确**还原

【审】`audit/godot/camera-cutscene.md#9`

### Step 3　⚠ 死亡相机必须释放　`[camera/06#S3]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】死亡→复活流程里 pop 死亡相机请求。

⛔ 不释放 → 复活后仍在死亡视角，
⚠ 表现为"复活了但镜头还在地上"，玩家以为卡死。

【产出】死亡相机释放

【判据】⚠ 复活后**回到**正常视角

【审】`audit/godot/camera-cutscene.md#23`

### Step 4　⚠ 菜单要接管或冻结相机　`[camera/06#S4]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】菜单打开时相机被接管或冻结。

⛔ 不管 → 菜单背后相机继续动 → 视角穿帮，
⚠ 表现为"暂停了但画面还在转"。

【产出】菜单相机处理

【判据】⚠ 菜单打开时画面**静止或被接管**

【审】`audit/godot/camera-cutscene.md#24`

### Step 5　⛔ 强制中断能重置栈　`[camera/06#S5]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】跳关/重开/崩溃恢复时清空相机栈。

⛔ 不重置 → 残留层级让相机永久异常，
⚠ 且玩家**无法自行恢复**（只能重开游戏）。

【产出】栈重置

【判据】⚠ 强制中断后**回到**正常视角

【审】`audit/godot/camera-cutscene.md#25`

### Step 6　⛔ 屏震不残留　`[camera/06#S6]`

【读】`howto/godot/camera-cutscene.md#3. 屏震：trauma 模型`

【做】异常中断时把 trauma 归零。

⛔ 不归零 → 屏震一直持续，
⚠ 表现为"画面永远在抖"，
⛔ 常被误判为跟随算法或物理问题。

【产出】屏震归零

【判据】⚠ 中断后画面**完全静止**

【审】`audit/godot/camera-cutscene.md#4`
