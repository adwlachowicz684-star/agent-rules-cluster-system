# 03 多相机管理与优先级（camera 域）

> **对应**：做法 `howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`
> 　　　审核 `audit/godot/camera-cutscene.md#18`

## 0. 交付物定义

⚠ **本步是本域的核心：把"哪个相机有效"变成被显式管理的状态。**

⛔ 常见假完成：各处自己 `make_current()` 也能跑——
⚠ 但过场/载具/死亡/菜单都要相机时，
⛔ **交接会漏还**，表现为"某个流程结束后画面不对"，且不报错。

做完这一步，应该能**当场演示**：

1. ⚠ 优先级**显式定义**并写进文档（过场 > 死亡 > 载具 > 正常）
2. ⛔ 过场结束 → 相机**自动还回**下层（不是靠手动还原）
3. ⚠ 每个接管请求**都有配对的释放**
4. ⛔ 两个系统同时请求时，**按优先级**决定，不抢
5. ⚠ 栈**没有泄漏**（异常退出后能回到正常）

**产出物**（下游按名字对接）：

```text
CameraStack: push(requester, priority) / pop(requester)
PRIORITY: cutscene > death > vehicle > normal
# ⛔ 每次 push 必须有配对 pop
```

## 2. 工序

### Step 1　⚠ 显式定义优先级顺序　`[camera/03#S1]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】定出各系统的优先级，写进文档。

⛔ 不定义 → 同时请求时谁后调用谁生效 →
表现为"过场和载具同时激活时相机乱跳"，
⛔ 且与调用时序相关，极难复现。

【产出】`PRIORITY` 定义

【判据】⚠ 文档能指出顺序，且有测试覆盖同时请求

【审】`audit/godot/camera-cutscene.md#19`

### Step 2　⛔ 用栈管理，禁止各处直接 make_current　`[camera/03#S2]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】所有相机切换经 `CameraStack`。

⛔ 直接 `make_current()` → 绕过栈 →
上层释放后**回不到正确视角**，
表现为"过场结束停在某处"，⛔ 不报错。

【产出】`CameraStack`

【判据】⛔ 全库搜索直接 `make_current` **结果为 0**（栈外）

【审】`audit/godot/camera-cutscene.md#18`

### Step 3　⛔ push 与 pop 必须配对　`[camera/03#S3]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】每个接管请求在结束时释放。

⛔ 只有压栈没有出栈 → 栈泄漏 →
相机**永久停在高优先级层**，
⚠ 表现为"过场结束后镜头不动了"，玩家彻底卡住。

【产出】配对释放

【判据】⚠ 连续 10 次过场后栈**深度为 0**

【审】`audit/godot/camera-cutscene.md#20`

### Step 4　⚠ 出栈自动回到下层，不手动还原　`[camera/03#S4]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】pop 后由栈决定回哪个相机，调用方不指定。

⛔ 调用方手动"还原到正常相机" →
嵌套场景（过场中又开菜单）会还原错层，
⚠ 表现为"菜单关掉后回到过场相机而不是正常视角"。

【产出】自动回退

【判据】⚠ 嵌套接管后**逐层正确回退**

【审】`audit/godot/camera-cutscene.md#20`

### Step 5　⛔ 异常退出要能清空栈　`[camera/03#S5]`

【读】`howto/godot/camera-cutscene.md#9. 多相机管理：优先级与交接`

【做】异常路径（崩溃/强制结束/跳关）能重置栈。

⛔ 不处理 → 异常后栈残留 →
相机永久异常，⚠ 且玩家无法自行恢复。

【产出】栈重置

【判据】⚠ 强制中断后相机**回到正常视角**

【审】`audit/godot/camera-cutscene.md#25`

### Step 6　⚠ 屏震是叠加不是独立相机　`[camera/03#S6]`

【读】`howto/godot/camera-cutscene.md#3. 屏震：trauma 模型`

【做】屏震作用于**当前有效相机**，不占栈层级。

⛔ 屏震做成独立相机压栈 → 与过场抢优先级，
⚠ 表现为"过场时屏震导致镜头跳走"。

【产出】屏震叠加方式

【判据】⚠ 过场期间屏震**不夺走**相机

【审】`audit/godot/camera-cutscene.md#27`
【品】`craft/godot/feel-params.md#5. 屏幕震动（Trauma 模型）`

## 5. 常见返工

**① 不定义优先级。** 时序相关乱跳。

**② 裸调 make_current。** 还错视角。

**③ 只 push 不 pop。** 永久卡住。

**④ 屏震占层。** 过场被夺走相机。
