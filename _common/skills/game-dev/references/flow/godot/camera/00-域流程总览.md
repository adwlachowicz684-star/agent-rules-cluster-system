# 相机 / 镜头管理 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只要一个第三人称相机跟着角色 | **不要套本域** → 见下 |
| 要在第一/第三人称间切换 | 01 → 02 → 07 |
| 有多个相机（过场/载具/死亡）要管理 | 01 → 03 → 07 |
| 相机会被墙挡住（避让） | 01 → 04 → 07 |
| 相机要给载具/过场让位并还回来 | 01 → 03 → 05 → 07 |
| 全套 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只有一个固定视角的项目不要套本域。**
⚠ 那属于 `character/03-相机跟随.md` 与
`howto/godot/camera-cutscene.md#1. 跟随策略对比` 的范围——
本域处理的是**多视角、多相机并存**的复杂度。

ⓘ 分工：
- `howto/godot/camera-cutscene.md` 讲**单个相机怎么配**（跟随/屏震/黑边/过场）
- 本域讲**多个相机/视角怎么管**（切换/优先级/交接/避让）

⛔ 若本域某步需要"跟随算法"细节，
指向那篇，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 相机模型定性 | — | 视角清单 + 各视角的近裁剪/模型分层 |
| 02 | 视角切换事务 | 01 | 带朝向同步的切换 |
| 03 | 多相机管理与优先级 | 01 | 优先级栈 + 配对释放 |
| 04 | 相机碰撞与避让 | 01 | SpringArm 显式排除角色层 |
| 05 | 相机与载具/过场交接 | 03 | 交接契约 |
| 06 | 相机状态机与异常退出 | 03 | 退出 + 快照恢复 |
| 07 | 相机验收 | 全部 | 切换/抢用/异常退出实测 |

⚠ **01 必须在一切之前**：视角没列全，03 的优先级无从定义。
⚠ **03 必须在 05 之前**：没有栈管理，交接必然漏还。

## 2. 与其他域的接缝

| 接缝 | 契约 |
|---|---|
| `character` 域 03 相机跟随 | 跟随算法在那边，本域只管**哪个相机有效** |
| `vehicle` 域 载具 | 载具相机不直接用车身 transform，见 05 |
| `narrative` 域 过场 | 过场相机走同一优先级栈 |
| `camera-cutscene.md` 屏震 | 屏震是**叠加**在有效相机上，不是独立相机 |
| `input-remap.md` 输入 | 视角切换按键复用同一套 action |
| `ui` 域 菜单 | 菜单打开要接管或冻结相机 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**。

## 3. 本域最容易做反的顺序

⛔ **先做过场相机（05）再做优先级管理（03）。**

过场是最直观的"相机变化"需求，
于是先给过场写 `make_current()`，
⚠ 而此时没有栈 → **过场结束相机没还回来** →
玩家永久卡在过场视角，⛔ 且不报错。

✅ 正确顺序：先立优先级栈（03），再让过场走栈（05）。
