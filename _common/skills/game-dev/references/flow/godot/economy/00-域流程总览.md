# 游戏经济与长线养成 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只有一种货币、能加减 | **不要套本域** → 见下 |
| 多种货币、要查账、要上限 | 01 → 07 |
| 有掉落/抽卡，带保底 | 01 → 02 → 07 |
| 有商店、限购、日/周重置 | 01 → 03 → 07 |
| 有天赋树/洗点 | 01 → 04 → 07 |
| 有装备：强化/词条/洗练 | 01 → 05 → 06 → 07 |
| 有分解、怕通胀 | 01 → 05 → 06 → 07 |
| 全套长线 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **单一货币、单机、不做长线的项目不要套本域。**
⚠ 那属于 `howto/godot/economy.md#0. 地基：货币不能只是一个 int`
前半段的范围——本域处理的是**多货币、要查账、要存档、要防篡改**的复杂度。

ⓘ 分工：
- `howto/godot/economy.md` 讲**单个要素怎么配**（货币/掉落/商店/天赋/装备/分解）
- 本域讲**这些要素按什么顺序做、怎么保证不丢账、不被刷**

⛔ 若本域某步需要"蒙特卡洛怎么跑"这类细节，
指向那篇，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 货币与账本地基 | — | 多货币 + 单一入口 + 上限 + 事务日志 |
| 02 | 掉落与保底 | 01 | 权重池 + 保底持久化 + 服务端权威 |
| 03 | 商店、限购与周期重置 | 01 | 服务端校验 + 可区分失败 + UTC 周期 |
| 04 | 天赋树与加成叠加 | 01 | 单节点带 rank + 固定叠加顺序 |
| 05 | 装备四层、实例与数值 | 01 | 模板/实例/词条分离 + 唯一计算器 |
| 06 | 强化、洗练、品阶与分解 | 05 | 保底事务 + 冻结快照 + 防通胀 |
| 07 | 经济验收 | 全部 | 敌意环境实测 + 蒙特卡洛报告 |

⚠ **01 必须在一切之前**：货币不是单一入口，02 的扣券、03 的购买、06 的强化费用
就各有各的改法，**对不上账**。
⚠ **05 必须在 06 之前**：模板与实例没分离，06 的洗练"冻结旧快照"没有可冻结的对象。
⚠ **01 必须在 02 之前**：没有上限检查的货币在溢出后会**静默变成负数**。

## 2. 与其他域的接缝

| 接缝 | 契约 |
|---|---|
| `inventory` 域 背包 | 装备实例由本域定义，背包只管容器与容量 |
| `lifeskill` 域 生活产出 | 产出进 01 的账本，⛔ 不走独立计数 |
| `vip` 域 特权 | 加成走 04 的叠加管线，⛔ 不另开一套乘区 |
| `gem` 域 宝石强化 | 与 06 共用同一事务与审计日志 |
| `save` 域 存档 | 保底计数、限购计数必须随存档，见 02/03 |
| `netsync` 域 同步 | 掉落与购买的服务端权威，见 02/03 |
| `security` 域 防作弊 | 客户端算掉落 = 可篡改，见 02 |
| `analytics` 域 埋点 | 事务日志即埋点源，见 01 |
| `datatable` 域 配表 | 掉落表/商店表是数据，⛔ 逻辑不进表 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**。

## 3. 本域最容易做反的顺序

⛔ **先做掉落和商店的表现（02/03），再做货币地基（01）。**

抽卡动画和商店界面是最直观的"经济"需求，
于是先搭界面、先接配表，
⚠ 而此时货币还是各处直接 `gold += n` →
**加第二种货币时要改所有调用点**，
⛔ 且不报错，只在加货币种类/查账时才暴露。

⛔ 同类第二条：**先做强化（06），再补保底持久化。**
保底放在进程变量里，单机跑得好好的，
表现为**重开游戏后保底清零、玩家永远抽不到**，
而排查时会去查概率配表，不会想到持久化。

✅ 正确顺序：先立账本与单一入口（01），再让掉落/商店/强化都走它。
