## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：能随机出一个东西就行。**

⛔ 常见假完成：`randi() % items.size()` 抽一个——
⚠ 掉落确实会出，
⛔ 但**保底在内存里**，重开就没了；
且**概率配表与实现语义对不上**（互斥权重 vs 独立概率）。

做完这一步，应该能**当场演示**：

1. ⛔ 保底计数**随存档持久化**，重开继续累计
2. ⛔ 两个卡池的保底**互不干扰**
3. ⛔ 权重含负值时**不产生意外结果**
4. ⛔ 空池不返回 `-1` 索引
5. ⚠ 联机时掉落由**服务端**决定

**产出物**（下游按名字对接）：

```text
LootTable: 互斥权重池 + 独立概率入口（两种语义分开）
PityState: {pool_id, count}，随存档
LootContext: 表 + 上下文 + 历史 → 结果 + 状态变更
```

## 2. 工序

### Step 1　⛔ 保底计数必须随存档持久化，且绑定到卡池　`[economy/02#S1]`

【读】`howto/godot/economy.md#保底（pity）`

【做】`PityState { pool_id, count }` 进存档，按池分别存。

⛔ 放内存 / 每日清零 → **重开后保底清零**，
表现为"玩家永远抽不到"，而排查时会去查概率配表。
⛔ 全局共用一个计数器 → **跨池污染**，
表现为"在 A 池垫的次数让 B 池提前出货"。

【产出】`PityState`（持久化 + 按池）

【判据】⛔ 存档重开后保底计数**不变**，且两池计数**独立**

【审】`audit/godot/economy.md#4`

### Step 2　⛔ 联机时掉落必须在服务端算　`[economy/02#S2]`

【读】`howto/godot/economy.md#保底（pity）`

【做】客户端只发请求，服务端算结果并回传。

⛔ 客户端算 → **可篡改**，玩家改内存即可指定产出。
⚠ 且客户端算的结果服务端无法校验，事后**无从追责**。

【产出】权威判定（谁持有 `PityState`）

【判据】⛔ 改客户端本地数据**不改变**实际产出

【审】`audit/godot/economy.md#7`

### Step 3　⛔ 权重必须 ≥ 0，带幸运值的公式最容易算出负数　`[economy/02#S3]`

【读】`howto/godot/economy.md#保底（pity）`

【做】入池前 `weight = maxf(weight, 0.0)`，并记录被钳制的项。

⛔ 官方只明文两条：**空池返回 `-1`**、**权重 0 表示永不被选中**；
⚠ **负权重官方并未文档化**，已知会产生意外结果（GH-119948），
而官方 issue 举的场景正是 **"random loot generation with a luck stat"**。
⛔ `基础权重 × (1 + 幸运值)` 在幸运值为负时**算出负权重**，
表现为"某物品概率行为怪异"，且不报错。

【产出】权重钳制 + 钳制告警

【判据】⛔ 任一入池权重 **< 0 时报错**，不静默放过

【审】`audit/godot/economy.md#6`

### Step 4　⛔ rand_weighted 空池返回 -1，不能直接当索引用　`[economy/02#S4]`

【读】`howto/godot/economy.md#掉落表：互斥权重 ≠ 独立概率`

【做】每次调用后判 `-1`，空池走"无产出"分支。

⛔ 官方：空数组"输出错误并返回 `-1`"。
⚠ 不判直接索引 → 取到**数组最后一个元素**，
⛔ 表现为"某稀有度抽完后固定出同一件"，
而它**不崩溃、不报错**，极难归因。

【产出】`-1` 判空分支

【判据】⛔ 空池时走"无产出"，**不返回任何元素**

【审】`audit/godot/economy.md#38`

### Step 5　⛔ 互斥权重 ≠ 独立概率，两种语义必须分开建表　`[economy/02#S5]`

【读】`howto/godot/economy.md#掉落表：互斥权重 ≠ 独立概率`

【做】"掉不掉"用独立概率，"掉什么"用互斥权重池。

⛔ 把 0.5%/0.3%/0.2% **当互斥权重填** → 实际概率**小于配置**；
⛔ 把互斥权重表**当独立概率用** → 玩家**一次拿多件**。
⚠ 两者配错都不会报错，只表现为"概率和策划算的不一样"。

【产出】两类池的明确区分

【判据】⛔ 模拟 10 万次，各物品实测频率与配置**在误差内一致**

【审】`audit/godot/economy.md#31`

## 5. 常见返工

**① 保底放内存。** 重开清零，玩家永远抽不到。

**② 全局一个保底。** 跨池污染。

**③ 客户端算掉落。** 可篡改。

**④ 负权重。** 概率行为怪异。

**⑤ 权重/概率混用。** 实测与配置不符。
