# 01 货币与账本地基（economy 域）

> **前置**：无（本域地基）
> **本步交付**：**多货币、单一入口、有上限、能查账的账本**
> **对应**：做法 `howto/godot/economy.md#0. 地基：货币不能只是一个 int`
> 　　　审核 `audit/godot/economy.md#1`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：金币能加减就行。**

⛔ 常见假完成：一个 `var gold := 0`，各处 `gold += n`——
⚠ 功能全对、界面也正常，
⛔ 但加第二种货币时要改**所有调用点**，
且出问题**无从查账**（不知道这笔钱从哪来）。

做完这一步，应该能**当场演示**：

1. 加一种新货币**不用改调用点**
2. ⛔ 所有余额变动都有**一条可追溯的日志**
3. ⛔ 余额到上限后被**拒绝**而不是变成负数
4. 加成（如 +20%）算得对，且**不污染整数余额**
5. ⚠ 跨语言边界（C#）传大额货币**不溢出**

**产出物**（下游按名字对接）：

```text
Wallet: currencies (Dictionary[ID, int]), MAX_PER_CURRENCY
Ledger: 事务日志（来源 + 数量 + 时间戳 + 上下文）
CurrencyCalculator: 整数域 ↔ 浮点域的唯一转换点
```

## 2. 工序

### Step 1　⛔ 货币不能只是一个 int，要多货币 + 来源追踪　`[economy/01#S1]`

【读】`howto/godot/economy.md#0. 地基：货币不能只是一个 int`

【做】用 `Dictionary[货币ID, int]` + 每笔变动记来源。

⛔ 单 `int` + 各处 `+=` → 加货币种类时改所有调用点，
⚠ 且不知道一笔钱从哪来，出问题**无从查账**。

【产出】`Wallet.currencies` + `Ledger`

【判据】⛔ 新增一种货币**不改任何调用点**

【审】`audit/godot/economy.md#1`

### Step 2　⛔ 所有改货币必须走同一个入口　`[economy/01#S2]`

【读】`howto/godot/economy.md#0. 地基：货币不能只是一个 int`

【做】对外只暴露 `try_spend()` / `try_grant()`，内部记账。

⛔ 各处直接改字段 → **对不上账**：
表现为"玩家说钱少了，日志里没有任何支出"。

【产出】`Wallet.try_spend()` / `try_grant()`

【判据】⛔ 全局搜索不到余额字段的直接赋值

【审】`audit/godot/economy.md#2`

### Step 3　⛔ 整数域与浮点域要彻底分开　`[economy/01#S3]`

【读】`howto/godot/economy.md#0. 地基：货币不能只是一个 int`

【做】余额用 `int`，加成（乘区管线）用 `float`，
两者只在**一个明确转换点**相接。

⛔ 用 float 存余额 → 精度问题累积，
表现为"余额出现 0.0000001 的尾数"或"扣不干净"。

【产出】`CurrencyCalculator`（唯一转换点）

【判据】⛔ 余额字段类型是 `int`，且无 `float` 混入余额运算

【审】`audit/godot/economy.md#3`

### Step 4　⛔ 货币必须有上限检查，否则溢出会回绕成负数　`[economy/01#S4]`

【读】`howto/godot/economy.md#整数溢出是静默回绕，不是报错`

【做】每次 `grant()` 前先判 `current + n > MAX` → 拒绝并回原因。

⛔ 官方：`int` 超出范围 **it will wrap around**（回绕），**不报错**。
⚠ 于是"没有上限检查的货币"在溢出后**变成负数**，
表现为**玩家突然负债巨额**，而日志里是一次正常入账。

【产出】`MAX_PER_CURRENCY` + 超限拒绝路径

【判据】⛔ 发到上限后再发，余额**不变**且返回可区分的失败原因

【审】`audit/godot/economy.md#35`

### Step 5　⛔ 跨 C# 边界的货币字段必须用 long，不是 int　`[economy/01#S5]`

【读】`howto/godot/economy.md#整数溢出是静默回绕，不是报错`

【做】C# 侧货币/存档/网络字段一律 `long`。

⛔ GDScript 的 `int` 是 64 位，**C# 的 `int` 是 32 位**
（官方原话：*"GDScript's int is 64-bit while C#'s int is 32-bit"*）。
⚠ 用 C# `int` 接货币 → **21 亿就溢出**，
⛔ 而同一份数据在 GDScript 侧完全正常——
**只在跨语言处出错，最难归因**。

【产出】跨语言货币字段类型约定（`long`）

【判据】⛔ 一个超过 21 亿的数额经 C# 侧往返后**不变**

【审】`audit/godot/economy.md#36`

## 5. 常见返工

**① 单 int。** 加货币种类时全改。

**② 各处直接赋值。** 对不上账。

**③ float 存余额。** 尾数与扣不干净。

**④ 没上限。** 溢出回绕成负数。

**⑤ C# 用 int。** 21 亿溢出，只在跨语言处出错。
