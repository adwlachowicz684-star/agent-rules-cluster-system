> **前置**：01 货币与账本地基
> **本步交付**：**一个洗点不会破、叠加结果可预测的加成系统**
> **对应**：做法 `howto/godot/economy.md#3. 养成与天赋树（技能树）`
> 　　　审核 `audit/godot/economy.md#11`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：加点能加、界面能显示就行。**

⛔ 常见假完成：天赋 I/II/III 做成三个节点、洗点直接清空重分配——
⚠ 功能全对，
⛔ 但**前置关系爆炸**，且洗点要**按依赖逐级回退**，极易出错。

⛔ 更隐蔽的是叠加法：一个"攻击力 +20%"因实现方式不同给出
**完全不同的结果**，而**策划配表时默认它只有一个含义**。

做完这一步，应该能**当场演示**：

1. ⛔ "最大等级"是节点内的 `current_rank` / `max_rank`
2. ⛔ 洗点按「取消分配 → 校验 → 扣点」**同一事务**
3. ⛔ 三种叠加法**已约定**并在文档中写明
4. ⛔ 叠加顺序**固定**，重算顺序不影响结果
5. ⛔ 独立乘区**有数量上限**

**产出物**（下游按名字对接）：

```text
TalentNode: id, current_rank, max_rank, 前置
StatPipeline: 加区 → 乘区 → 独立乘区（顺序固定）
```

## 2. 工序

### Step 1　⛔ 最大等级是节点内的 rank，不是拆成多个节点　`[economy/04#S1]`

【读】`howto/godot/economy.md#崩坏点集中在三处`

【做】单节点带 `current_rank` / `max_rank`。

⛔ 拆成 I/II/III 三个节点 → **前置关系爆炸**，
且洗点要**按依赖逐级回退**，极易漏退。
⚠ 表现为"洗点后有个节点还亮着"。

【产出】`TalentNode.current_rank` / `max_rank`

【判据】⛔ 同一天赋在图中**只有一个节点**

【审】`audit/godot/economy.md#11`

### Step 2　⛔ 洗点必须三步同一事务：取消分配 → 校验 → 扣点　`[economy/04#S2]`

【读】`howto/godot/economy.md#崩坏点集中在三处`

【做】三步在一个事务内，任一步失败整体回滚。

⛔ 直接清空重分配 → 中间态崩溃会造成
**点没了但属性还在**（或反之）的撕裂状态。

【产出】洗点事务

【判据】⛔ 注入扣点失败后，已分配点数**回到原值**

【审】`audit/godot/economy.md#12`

### Step 3　⛔ 三种叠加法必须先约定，否则同一个 +20% 结果不同　`[economy/04#S3]`

【读】`howto/godot/economy.md#加成计算：数值崩坏的头号来源`

【做】每个词条标注叠加法，文档写明公式。

⛔ 基础 100、两个 +20%：
加法叠加 = **140**，乘法叠加 = **144**，独立乘区 = 按区相乘。
⚠ **三者都叫"+20%"**，策划配表时默认只有一个含义，
⛔ 表现为"面板和策划算的不一样"，且不报错。

【产出】叠加法标注（每个词条）

【判据】⛔ 任一词条在配表中**能查到**其叠加法

【审】`audit/godot/economy.md#13`

### Step 4　⛔ 叠加顺序必须固定，重算顺序不能影响结果　`[economy/04#S4]`

【读】`howto/godot/economy.md#加成计算：数值崩坏的头号来源`

【做】固定为 `加区 → 乘区 → 独立乘区`，只走一个管线。

⛔ 顺序不定 → **同样的词条组合因重算顺序不同给出不同结果**，
⚠ 表现为"脱下再穿上装备，属性变了"。

【产出】`StatPipeline`（唯一、有序）

【判据】⛔ 打乱装备/天赋的**应用顺序**，最终属性**不变**

【审】`audit/godot/economy.md#14`

### Step 5　⛔ 独立乘区必须严格限量，否则后期数值失控　`[economy/04#S5]`

【读】`howto/godot/economy.md#加成计算：数值崩坏的头号来源`

【做】给独立乘区的投放渠道与数量设上限。

⛔ 独立乘区**边际收益恒定**（永远 +20%），
加得越多膨胀越快，与加法叠加的**递减**特性相反。
⚠ 表现为"后期数值爆炸"，而每一条新投放单独看都"很合理"。

【产出】独立乘区数量上限

【判据】⛔ 满配情况下最终数值**在设计上限内**

【审】`audit/godot/economy.md#15`

## 5. 常见返工

**① 拆多节点。** 前置爆炸、洗点漏退。

**② 洗点分步。** 状态撕裂。

**③ 叠加法没约定。** 面板与策划不符。

**④ 顺序不定。** 穿戴顺序影响属性。

**⑤ 乘区不限量。** 后期数值爆炸。
