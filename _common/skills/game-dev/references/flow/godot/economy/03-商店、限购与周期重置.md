# 03 商店、限购与周期重置（economy 域）

> **前置**：01 货币与账本地基
> **本步交付**：**一个校验在服务端、失败能区分、周期可信的商店**
> **对应**：做法 `howto/godot/economy.md#2. 商店`
> 　　　审核 `audit/godot/economy.md#8`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：能买下来东西就行。**

⛔ 常见假完成：客户端判价格、扣钱、发货——
⚠ 单机跑得好好的，
⛔ 但联机时**可篡改**，且限购按本地时间重置 →
**改系统时间就能刷新限购**。

做完这一步，应该能**当场演示**：

1. ⛔ 购买校验在**服务端**
2. ⛔ 失败时**能区分**是货币不足 / 已达上限 / 已下架
3. ⛔ 日/周重置按**服务器 UTC**，改本地时间无效
4. ⛔ 玩家**跨周期不在线**后限购计数仍正确
5. ⛔ 扣费与发货**同一事务**

**产出物**（下游按名字对接）：

```text
ShopService.try_buy(): 校验 → 扣费 → 发货（同一事务）
PurchaseResult: 可区分的失败原因枚举
LimitState: {key, count, period_id}，随存档
```

## 2. 工序

### Step 1　⛔ 购买校验必须在服务端　`[economy/03#S1]`

【读】`howto/godot/economy.md#2. 商店`

【做】客户端只发请求，服务端校验价格/库存/限购。

⛔ 客户端判 → **可篡改**，
⚠ 且客户端算出的价格与服务端不一致时**无从发现**。

【产出】服务端校验入口

【判据】⛔ 改客户端价格/库存**不影响**实际校验结果

【审】`audit/godot/economy.md#8`

### Step 2　⛔ 失败原因必须能区分，不能统一报"购买失败"　`[economy/03#S2]`

【读】`howto/godot/economy.md#2. 商店`

【做】返回枚举：货币不足 / 已达上限 / 已下架 / 限购耗尽。

⛔ 统一提示 → **无从排查**：
表现为"玩家一直买不了，日志里只有一个失败"。

【产出】`PurchaseResult` 失败原因枚举

【判据】⛔ 每种失败在日志中**可区分**

【审】`audit/godot/economy.md#8`

### Step 3　⛔ 限购重置按服务器 UTC，不按本地时间　`[economy/03#S3]`

【读】`howto/godot/economy.md#2. 商店`

【做】周期标识由服务端下发，客户端只展示。

⛔ 用本地时间判"每天 5 点重置" →
**跨时区、改系统时钟、夏令时切换**都会让周期缺一天或多一天。
⚠ 表现为"有人已经刷新了，有人没有"，且**不报错**。

【产出】`period_id`（服务端下发）

【判据】⛔ 改本地时区/系统时间，**限购刷新时刻不变**

【审】`audit/godot/economy.md#9`

### Step 4　⛔ 限购计数必须容忍玩家跨周期不在线　`[economy/03#S4]`

【读】`howto/godot/economy.md#2. 商店`

【做】存 `{ key, count, period_id }`，登录时按 `period_id` 判定是否重置。

⛔ 只在"重置时刻"清计数 → **不在线的玩家计数永远不清**，
表现为"玩家一个月没上，回来发现限购还是满的"。

【产出】`LimitState`（含 `period_id`）

【判据】⛔ 跨多个周期不在线后登录，限购**按当前周期**正确重置

【审】`audit/godot/economy.md#10`

### Step 5　⛔ 扣费与发货必须同一事务　`[economy/03#S5]`

【读】`howto/godot/economy.md#2. 商店`

【做】校验 → 扣费 → 发货，任一步失败整体回滚。

⛔ 先发货后扣费 → 扣费失败即**白嫖**；
⛔ 先扣费后发货 → 发货失败即**钱没了东西没到**。
⚠ 两者在正常情况下都表现正常，**只在失败路径上暴露**。

【产出】购买事务（含回滚）

【判据】⛔ 注入发货失败后，货币余额**回到原值**

【审】`audit/godot/economy.md#39`

## 5. 常见返工

**① 客户端校验。** 可篡改。

**② 统一失败提示。** 无从排查。

**③ 本地时间重置。** 改时间即刷新。

**④ 不在线不清计数。** 回归后限购仍满。

**⑤ 分步扣费发货。** 失败路径白嫖或丢钱。
