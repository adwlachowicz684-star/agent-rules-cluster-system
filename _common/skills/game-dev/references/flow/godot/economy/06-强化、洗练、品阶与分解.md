# 06 强化、洗练、品阶与分解（economy 域）

> **前置**：05 装备四层、实例与数值
> **本步交付**：**强化有保底、洗练不丢数据、分解不通胀的养成链路**
> **对应**：做法 `howto/godot/economy.md#强化：面板成功率 ≠ 玩家总投入`
> 　　　审核 `audit/godot/economy.md#21`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：强化能加等级就行。**

⛔ 常见假完成：成功率配表 + 失败掉一级——
⚠ 表面上"只是难一点"，
⛔ 但同一案例下 12 级强化的期望次数可从 **31** 涨到 **2557**
——"失败掉一级"对普通玩家**实质上近似不可达**。

做完这一步，应该能**当场演示**：

1. ⛔ 保底计数**随存档**，且与等级/材料/余额**同事务**
2. ⛔ 保护符**替换失败后果**，不叠加概率
3. ⛔ 上线前有**蒙特卡洛**报告，看 P50/P90/P99 而非均值
4. ⛔ 递增概率叫**保底进度**，不叫"幸运值"
5. ⛔ 洗练**先冻结旧快照**，扣费后才切指针
6. ⛔ 品阶升级走**事务**，不直接改 `quality`
7. ⛔ 分解按**当前养成状态**折算，且有可分解边界

**产出物**（下游按名字对接）：

```text
EnhanceState: {level, pity_count, protection}，随存档
蒙特卡洛报告：P50/P90/P99 材料消耗 / 最大连败 / 目标覆盖率
RerollSnapshot: 旧快照（冻结）→ 扣费 → 切指针
```

## 1. 前置检查清单

- [ ] 已定失败规则（等级不变 / 回退 N 级）
- [ ] ⚠ 已用蒙特卡洛验证期望次数**可接受**
- [ ] 已定保底阈值与持久化位置
- [ ] 已定可分解边界（绑定/已装备/活动）
- [ ] ⚠ 已知"幸运值"是误导性命名

## 2. 工序

### Step 1　⛔ 保底必须持久化，且与等级/材料/余额同一事务　`[economy/06#S1]`

【读】`howto/godot/economy.md#强化：面板成功率 ≠ 玩家总投入`

【做】`EnhanceState` 随存档；等级、保底计数、材料、货币**一起提交**。

⛔ 放内存 / 每日清零 → **不是保底**，重开清零。
⛔ 先改等级后存保底 → 崩溃造成**状态撕裂**
（等级+1 但保底没更新，或反之）。

【产出】`EnhanceState`（持久化 + 同事务）

【判据】⛔ 注入中途崩溃，等级与保底**始终一致**

【审】`audit/godot/economy.md#21`

### Step 2　⛔ 保护符是替换失败后果，不是叠加概率　`[economy/06#S2]`

【读】`howto/godot/economy.md#强化：面板成功率 ≠ 玩家总投入`

【做】保护符把"掉一级"替换为"不掉"，**不改**成功率数值。

⛔ 当成概率提升 → 面板概率与实际不符，
⚠ 且玩家会以为"用了保护符更容易成功"。
⛔ 不能同时获得**不掉级**和**材料返还**——那是两个独立后果。

【产出】保护符的效果定义（替换后果）

【判据】⛔ 用保护符后面板成功率**不变**

【审】`audit/godot/economy.md#24`

### Step 3　⛔ 不能只看期望值，要蒙特卡洛看 P50/P90/P99　`[economy/06#S3]`

【读】`howto/godot/economy.md#强化：面板成功率 ≠ 玩家总投入`

【做】上线前模拟 10 万次，输出分位数与最大连败。

⛔ 只看均值 → 15% 概率下**连续 10 次失败约 19.7%**，
⚠ **玩家记住的是连败，不是期望**。
⛔ 表现为"期望没问题，但玩家大量投诉"。

【产出】蒙特卡洛报告

【判据】⛔ 报告中含 **P50/P90/P99** 与**最大连续失败**

【审】`audit/godot/economy.md#25`

### Step 4　⛔ 递增概率要叫"保底进度"，不能叫"幸运值"　`[economy/06#S4]`

【读】`howto/godot/economy.md#强化：面板成功率 ≠ 玩家总投入`

【做】命名为 `pity_progress`，UI 文案同步。

⛔ 叫"幸运值" → 玩家理解为**独立概率**，
⚠ 且递增概率与硬保底叠加后，
**就不能再宣称遵守面板概率**（宣传与实现不符）。

【产出】命名与 UI 文案

【判据】⛔ 代码中**不存在**"幸运值"命名的概率递增字段

【审】`audit/godot/economy.md#26`

### Step 5　⛔ 洗练先冻结旧快照，扣费后再切指针　`[economy/06#S5]`

【读】`howto/godot/economy.md#洗练 / 重铸：先冻结旧快照，扣费后再切指针`

【做】旧快照冻结 → 扣费 → 原子切换指针；失败回滚到旧快照。

⛔ 扣费前覆盖旧数据 → 扣费失败即**旧词条也没了**。
⛔ 允许客户端无限次"试洗后取消" →
等于**免费预览服务端随机结果**（可刷出满意结果再确认）。

【产出】`RerollSnapshot` + 一次性令牌

【判据】⛔ 注入扣费失败后，词条**回到旧值**

【审】`audit/godot/economy.md#27`

### Step 6　⛔ 品阶升级是事务，不能直接改 quality 字段　`[economy/06#S6]`

【读】`howto/godot/economy.md#品阶：约束词条数与上限，不是写死某条属性`

【做】走"冷却 + 材料 + 失败/保底"事务，槽数变少时明确删哪条。

⛔ 直接把 `quality` 改高 → **同一模板的旧实例行为不一致**，
⚠ 表现为"老装备的属性和新装备对不上"。
⛔ 新槽数少于旧槽数时必须明确删除规则
（优先删**不能锁定的低优先级**词条），否则静默丢词条。

【产出】品阶事务 + 词条删除规则

【判据】⛔ 升品后旧实例行为与新实例**一致**

【审】`audit/godot/economy.md#30`

### Step 7　⛔ 分解按当前养成状态折算，且有明确可分解边界　`[economy/06#S7]`

【读】`howto/godot/economy.md#分解：防通胀边界`

【做】返还按**当前**养成状态折算；绑定/已装备/活动物品默认不可分解。

⛔ 按模板原价返还 → 返还 ≥ 获取成本，
玩家可**刷分解套利**（这是最容易算错的通胀源）。
⛔ 分解与强化/洗练**共用同一事务与审计日志**，否则对不上账。

【产出】折算公式 + 可分解白名单

【判据】⛔ 任意养成状态下的返还**严格小于**该状态的获取成本

【审】`audit/godot/economy.md#33`

## 5. 常见返工

**① 保底放内存。** 重开清零。

**② 保护符当概率。** 面板与实现不符。

**③ 只看均值。** 玩家记住连败。

**④ 洗练先覆盖。** 扣费失败旧词条也没了。

**⑤ 分解按原价。** 刷分解套利。
