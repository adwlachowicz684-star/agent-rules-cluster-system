# 04 一口价、竞价与结算令牌（trade 域）

> **前置**：03 挂单托管与状态机
> **本步交付**：**一口价重读价格、竞价冻结资金、结算用唯一令牌**
> **对应**：做法 `howto/godot/player-trading.md#3. 一口价是同步成交，竞价是条件订单 + 延时结算`
> 　　　审核 `audit/godot/player-trading.md#12`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：点购买就扣钱发货就行。**

⛔ 常见假完成：信客户端传来的单价、把竞价当成"显示当前最高价" ——
⚠ 界面上价格、倒计时、领先者都对，
⛔ 但客户端改包就能低价扫货，且同一笔出价会被**应用两次**。

做完这一步，应该能**当场演示**：

1. ⛔ 客户端传 `price = 1` 买 1000 金的货 → **被拒绝**
2. ⛔ 竞价时领先者的资金是**冻结**状态，不是"显示一个数"
3. ⛔ 同一笔出价重发两次，**只生效一次**
4. ⛔ 截止前一毫秒出价**不产生争议**（定时器只转待结算）
5. ⚠ 排序可以异步，点击购买时服务端**重查**最新挂单

**产出物**（下游按名字对接）：

```text
place_bid(player, listing_id, amount, idem_key)
settle_token(listing_id, version)   ← 唯一结算令牌
funds.hold() / funds.release()
```

## 2. 工序

### Step 1　⛔ 一口价必须服务端重新读取价格　`[trade/04#S1]`

【读】`howto/godot/player-trading.md#3. 一口价是同步成交，竞价是条件订单 + 延时结算`

【做】服务端从**最新挂单**重读价格，⛔ 不信客户端附带的单价。

⛔ 信客户端传来的单价 → 改包即可低价扫货，
⛔ 表现为"货被 1 金买走了"，而服务端日志里是一次正常成交。

【产出】服务端重读价格的购买路径

【判据】⛔ 客户端传 `price = 1` 买 1000 金的货 → 被拒绝且可区分原因

【审】`audit/godot/player-trading.md#12`

### Step 2　⛔ 竞价的本质是冻结领先者资金，不是显示当前最高价　`[trade/04#S2]`

【读】`howto/godot/player-trading.md#3. 一口价是同步成交，竞价是条件订单 + 延时结算`

【做】把领先者的资金 `funds.hold()` 冻结到拍卖结束；先持久化新领先，再异步释放旧的。

⛔ 只显示"当前最高价"而不冻结 → 领先者可以在成交前把钱花掉，
表现为"拍卖结束却收不到钱"。
⛔ 释放旧领先资金早于持久化新领先 → 崩溃后**两个人的钱都被冻着**。

【产出】`funds.hold()` / `funds.release()` 与持久化顺序

【判据】⛔ 竞价结束后领先者资金**确实被冻结**，无法用于其他消费

【审】`audit/godot/player-trading.md#13`

### Step 3　⛔ 代拍要建模为服务端订单，不是客户端自动点价　`[trade/04#S3]`

【读】`howto/godot/player-trading.md#3. 一口价是同步成交，竞价是条件订单 + 延时结算`

【做】客户端只设**绝对上限**与可选增量策略，服务端只出价到"当前最低可领先额"。

⛔ 做成客户端自动点价 → 客户端掉线就停止、且可绕过上限，
表现为"代拍把我的钱全花光了"。
⛔ 服务端出价**绝不超过**玩家设的绝对上限。

【产出】服务端代拍订单 + 绝对上限校验

【判据】⛔ 代拍在达到绝对上限后停止，不会超一分

【审】`audit/godot/player-trading.md#14`

### Step 4　⛔ 价格显示只是缓存，成交必须实时　`[trade/04#S4]`

【读】`howto/godot/player-trading.md#3. 一口价是同步成交，竞价是条件订单 + 延时结算`

【做】排序可异步，点击购买时服务端重查最新挂单与价格；界面显示"价格待确认"。

⛔ 显示客户端缓存价就允许连点 → 价格已变仍按旧价成交，
表现为"看到的 100，扣了 150"，⛔ 且客户端没有任何异常提示。

【产出】"价格待确认"的界面状态 + 服务端重查

【判据】⛔ 服务端改价后，客户端点购买看到的是**新价**

【审】`audit/godot/player-trading.md#15`

### Step 5　⛔ 定时器只把 ACTIVE 转待结算，结算本身用唯一令牌　`[trade/04#S5]`

【读】`howto/godot/player-trading.md#3. 一口价是同步成交，竞价是条件订单 + 延时结算`

【做】定时器只做状态迁移；真正的发货、扣税、付款由**唯一结算令牌**执行。

⛔ 让定时器直接结算 → "截止前一毫秒出价"会因网络时钟差与并发产生争议，
⛔ 且定时器重入时可能**结算两次**。
⚠ 表现为"最后一秒被狙击"的工单，且无法判定谁先出价。

【产出】结算令牌的颁发 / 回收 + 幂等结算

【判据】⛔ 定时器重复触发 100 次，挂单只结算一次

【审】`audit/godot/player-trading.md#58`

## 5. 常见返工

**① 信客户端单价。** 改包低价扫货。

**② 竞价只显示不冻结。** 成交收不到钱。

**③ 客户端自动点价。** 掉线停止、可超上限。

**④ 缓存价直接成交。** 看到与扣款不一致。

**⑤ 定时器直接结算。** 最后一秒争议 + 重复结算。
