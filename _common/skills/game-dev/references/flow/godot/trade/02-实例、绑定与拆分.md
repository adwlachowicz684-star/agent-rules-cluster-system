## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：挂单里存 `template_id` + 数量就能买卖。**

⛔ 常见假完成：成交按模板重新生成一个实例 ——
⚠ 单看交易流程全对，
⛔ 但**词条快照、耐久、绑定、实例 ID 全丢了**，
表现为"买到的装备词缀变了""绑定的东西被卖掉了"。

做完这一步，应该能**当场演示**：

1. ⛔ 同一模板的两件唯一装备，成交后**各自的词条与耐久保留**
2. ⛔ 被绑定的物品在任何形态下都被**拒绝**，且拒绝原因是可区分的
3. ⛔ 堆叠拆分后**总量守恒**，且旧 `stack_id` 已退役
4. ⚠ 客户端改"可交易"字段**无效**（服务端重新求值）
5. ⛔ 网络只传 `item_instance_id` + 版本，**不传对象实例**

**产出物**（下游按名字对接）：

```text
ItemInstance { item_instance_id, template_id, affix_snapshot,
               durability, bind_state, stack_id, quantity, parent_stack_id }
trade_policy(source, bind_type, actor, receiver) → ALLOWED / DENIED / CONVERT_BIND_ON_RECEIVE / DELAYED
```

## 2. 工序

### Step 1　⛔ 流转的是实例，不是模板　`[trade/02#S1]`

【读】`howto/godot/player-trading.md#1. 流转的是实例，不是模板`

【做】成交依据是 `item_instance_id`；`template_id` 只用于展示和搜索。

⛔ 按模板成交 → 成交时重新生成实例，
**词条快照、耐久、绑定、实例 ID 全丢**，
⚠ 表现为"展示页看到的词缀和到手的不一样"，且不报错。

【产出】`ItemInstance` 字段表 + 实例 ID 服务端生成

【判据】⛔ 同一模板两件唯一装备成交后，词条与耐久各自保留

【审】`audit/godot/player-trading.md#4`

### Step 2　⛔ 绑定是迁移函数的输入，每次都要重新求值　`[trade/02#S2]`

【读】`howto/godot/player-trading.md#1. 流转的是实例，不是模板`

【做】服务端维护 `trade_policy`，为每种来源 / 绑定类型 / 角色 / 接收者组合返回
`ALLOWED` / `DENIED` / `CONVERT_BIND_ON_RECEIVE` / `DELAYED`。

⛔ 把绑定当显示标签 → 只在 UI 上灰掉按钮，
表现为"客户端改一下就能卖掉绑定装备"。
⚠ 绑定解除必须来自**服务端事件**（使用时绑定 / 赠送许可 / 官方解绑券）并生成独立流水。

【产出】`trade_policy()` + 绑定解除的服务端事件流水

【判据】⛔ 把客户端传来的"可交易"改成 true，服务端仍拒绝

【审】`audit/godot/player-trading.md#5`

### Step 3　⛔ 不能缓存客户端发来的"可交易"　`[trade/02#S3]`

【读】`howto/godot/player-trading.md#1. 流转的是实例，不是模板`

【做】任何交易前，用物品**当前状态和版本**重新求值 `trade_policy`。

⛔ 缓存客户端声明的可交易状态 → 物品在上架后被使用时绑定，
仍按"可交易"成交，⛔ 且**不报错**。
⚠ 表现为"绑定于 A、本应不可转、却被客户端改成可交易"。

【产出】每次转移前的实时求值调用点

【判据】⛔ 上架后把物品改为绑定，再成交 → 被拒绝

【审】`audit/godot/player-trading.md#6`

### Step 4　⛔ 拆分要退役旧 ID、生成新实例、写血缘、校验总量　`[trade/02#S4]`

【读】`howto/godot/player-trading.md#1. 流转的是实例，不是模板`

【做】旧堆 50 拆成 20 + 30：原 `stack_id` 退出，服务端建两个新实例，数量合计仍 50。

⛔ 沿用旧 `stack_id` → 外部缓存、挂单快照、邮件附件指向**已不存在的实例**；
⛔ 把 30 写成"原实例 + 数量"却不生成新 ID → 撤销原挂单时**错误释放同一份资产**。
⚠ 表现为"撤销一笔交易，另一笔的货也没了"。

【产出】拆分事务 + 血缘 `parent_stack_id` + 总量断言

【判据】⛔ 任意次拆分后总量不变，且旧 ID 查不到

【审】`audit/godot/player-trading.md#7`

### Step 5　⛔ 网络只传稳定 ID 与摘要，不传 Object / Callable　`[trade/02#S5]`

【读】`howto/godot/player-trading.md#10. Godot 实现：只发请求和显示服务端状态`

【做】客户端只发 `item_instance_id` + 版本；服务端按 ID 重新加载真实实例。

⛔ 传 `Resource` / `Object` / `Callable` → 官方明确**不序列化**这些类型，
表现为 RPC 静默失败或数据错乱，⛔ 且不总是报错。
⛔ 也禁止把服务端库存表直接赋给客户端场景节点。

【产出】物品的网络表示（稳定 ID + 显示摘要）

【判据】⛔ 协议里搜不到 `Object` / `Resource` / `Callable` 类型的参数

【审】`audit/godot/player-trading.md#50`

## 5. 常见返工

**① 按模板成交。** 词缀与耐久全丢。

**② 绑定只做 UI 灰化。** 客户端可绕过。

**③ 缓存可交易状态。** 上架后绑定仍成交。

**④ 拆分沿用旧 ID。** 撤销时错误释放。

**⑤ 传 Resource 当参数。** 官方不序列化，静默失败。
