# 05 定价边界、税与货币去向（trade 域）

> **前置**：03 挂单托管与状态机
> **本步交付**：**玩家定价 + 服务端软边界 + 税与货币去向明确**
> **对应**：做法 `howto/godot/player-trading.md#4. 玩家定价 + 服务端软边界（不是二选一）`
> 　　　审核 `audit/godot/player-trading.md#17`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：玩家随便填价、成交扣个百分比就行。**

⛔ 常见假完成：把税负模式做成"两边都支持"、把税当成"回收" ——
⚠ 单笔功能全对，
⛔ 但 UI 缓存、历史邮件、税率配置会**互相矛盾**，
且税进系统钱包后那笔钱再花出去**仍是货币回流**，通胀照旧。

做完这一步，应该能**当场演示**：

1. ⛔ 明显超界的挂单被**拒绝**，不是被"自动改成合理价"
2. ⛔ 成交中位数只包含**真正成交且未被撤销 / 回滚**的样本
3. ⛔ 全服税负模式**只有一种**，且配置与 UI 一致
4. ⚠ 阶梯税按本次 taxable base 算，**客户端不能选档位**
5. ⛔ 税的去向明确：销毁 或 sink，⛔ 不是进系统钱包就算回收

**产出物**（下游按名字对接）：

```text
price_policy：无边界 / 只限绝对上下界 / 限近期成交分布 / 按系统锚价浮动
tax_bracket(base)：min(price,b1)*r1 + max(0, min(price,b2)-b1)*r2 + ...
税收入：销毁（burn） 或 指定 sink，⛔ 不是系统钱包
```

## 1. 前置检查清单

- [ ] 已定每个物品的 `price_policy` 属于哪一档
- [ ] 已定税负模式（买家付 / 卖家付，⛔ 二选一）
- [ ] 已定税的去向（销毁 / sink）
- [ ] 已定阶梯税的档位与拆单频率限制
- [ ] ⚠ 已知全服最低挂单价**不是**成交价

## 2. 工序

### Step 1　⛔ 玩家定价 + 服务端软边界，不是二选一　`[trade/05#S1]`

【读】`howto/godot/player-trading.md#4. 玩家定价 + 服务端软边界（不是二选一）`

【做】玩家发现价格，服务端按 `price_policy` 拒绝明显超界的订单。

⛔ 纯玩家定价 → 起拍战、虚假压价、扫货抬价、低价陷阱；
⛔ 纯系统定价 → 稀缺性失真，商人玩法消失。
⚠ 低成交量时要回退到**合成成本 / NPC 锚价**兜底，⛔ 不要用不稳的中位数硬撑。

【产出】每物品的 `price_policy` + 兜底锚价

【判据】⛔ 挂一个超出软边界的价 → 被拒绝且返回可区分原因

【审】`audit/godot/player-trading.md#17`

### Step 2　⛔ 服务端拒绝超界价，不自动改成"合理价"　`[trade/05#S2]`

【读】`howto/godot/player-trading.md#4. 玩家定价 + 服务端软边界（不是二选一）`

【做】超界就拒绝并给出原因；⛔ 绝不静默改价。

⛔ 自动改成"合理价" → 卖家会认为系统偷改他的定价，
⚠ 表现为"我填 1000 系统给我挂 200"的投诉，⛔ 且日志里看不出改过。

【产出】拒绝路径 + 可区分失败码

【判据】⛔ 超界挂单被拒绝，价格字段**与提交值一致**（未被篡改）

【审】`audit/godot/player-trading.md#18`

### Step 3　⛔ 成交中位数要剔除未成交、撤销、关联与自买自卖　`[trade/05#S3]`

【读】`howto/godot/player-trading.md#4. 玩家定价 + 服务端软边界（不是二选一）`

【做】样本 = 有效窗口内**成功结算且未被撤销 / 回滚**的成交；排序后排除首尾风险比例。

⛔ 把全服最低挂单价当成交价 → 那可能是**诱饵、误操作或被脚本抢走的临时价**，
表现为"指导价低得离谱，真去买却没有"。
⛔ 自买自卖与循环买卖必须**单独剔除或降权**。

【产出】价格统计口径（样本定义 + 剔除规则）

【判据】⛔ 灌入 100 笔自买自卖后，指导价**不变**

【审】`audit/godot/player-trading.md#19`

### Step 4　⛔ 买家付税与卖家付税不可混用　`[trade/05#S4]`

【读】`howto/godot/player-trading.md#5. 税：既改变行为，也决定货币去哪`

【做】全服只选一种：买家付"成交价 + 税"，或卖家收"成交价 - 税"。

⛔ 混用 → UI 缓存、历史邮件、税率配置**互相矛盾**，
表现为"同一件商品两个人看到的价格不一样"，⛔ 且无法对账。

【产出】单一税负模式 + 统一的显示公式

【判据】⛔ 全局只有一处税负模式配置，两处引用同一常量

【审】`audit/godot/player-trading.md#20`

### Step 5　⛔ 阶梯税按本次 taxable base 服务端算，并限制拆单　`[trade/05#S5]`

【读】`howto/godot/player-trading.md#5. 税：既改变行为，也决定货币去哪`

【做】按本次交易的 taxable base 逐档累加，⛔ 不让客户端选档位；
同时限制**拆分交易**与短期上架频率。

⛔ 让客户端选档位 → 拆成多笔小额避税，
表现为"大额交易的税反而比小额低"。
⚠ 结算时按**当前**税率重算，⛔ 不能用下单时的旧税率（热更后会不一致）。

【产出】服务端 `tax_bracket()` + 拆单频率限制

【判据】⛔ 把一笔拆成十笔后，总税**不小于**整笔的税

【审】`audit/godot/player-trading.md#21`

### Step 6　⛔ 税要销毁或进 sink，进系统钱包不算回收　`[trade/05#S6]`

【读】`howto/godot/player-trading.md#5. 税：既改变行为，也决定货币去哪`

【做】税直接销毁，或进明确指定的 sink；公会捐赠、跨服中转、机器人代售同样计税。

⛔ 把税打进系统钱包当"回收" → 那笔钱再花出去**仍是货币回流**，
⚠ 表现为"收了很多税，通胀一点没缓解"。
⛔ 也⛔ 不能因为是系统账户就不计税。

【产出】税的销毁 / sink 路径 + 系统账户同样计税

【判据】⛔ 批量成交后，全服货币存量**下降**（不是转移到系统钱包）

【审】`audit/godot/player-trading.md#22`

## 5. 常见返工

**① 纯玩家定价。** 刷价与扫货。

**② 自动改合理价。** 玩家投诉系统偷改。

**③ 用最低挂单价当成交价。** 指导价失真。

**④ 税负模式混用。** 无法对账。

**⑤ 客户端选税档。** 拆单避税。

**⑥ 税进系统钱包。** 通胀照旧。
