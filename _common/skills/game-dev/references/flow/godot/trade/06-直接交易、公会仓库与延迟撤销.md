# 06 直接交易、公会仓库与延迟撤销（trade 域）

> **前置**：02 实例、绑定与拆分
> **本步交付**：**锁定确认 + ACL 库存 + 延迟到账 + 全有或全无撤销**
> **对应**：做法 `howto/godot/player-trading.md#6. 面对面交易用锁定确认，公会仓库是权限化库存`
> 　　　审核 `audit/godot/player-trading.md#25`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：双方点确认就交换、货款立刻到账就行。**

⛔ 常见假完成：确认后还能改 offer、货款立即到账、撤销只回滚货币 ——
⚠ 单笔流程全对，
⛔ 但**盗号者的最优路径就是：登录 → 批量挂单 → 低价扫给同伙 → 快速转服**，
而二次密码、设备提示**都只是提高门槛，不能撤销已完成盗窃**。

做完这一步，应该能**当场演示**：

1. ⛔ 任一方改 offer → 双方**回到 ACTIVE**（不是保留已确认）
2. ⛔ 高风险资产到账后**不可立即转卖**（延迟到账生效）
3. ⛔ 延迟结束进**可领取**状态，不是自动塞进背包
4. ⛔ 撤销是**全有或全无**，且同时冻结后续转移链
5. ⛔ 风控判的是**关系链**，不是单笔是否异常

**产出物**（下游按名字对接）：

```text
直交状态机：PENDING → ACTIVE → LOCKED_A / LOCKED_B → CONFIRMED → SETTLING → COMPLETED
GuildVault：个人暂存区 / 公会公共区 / 审批区（带 ACL）
延迟策略表（热更新）：普通小额直结 · 贵重品按保护等级延迟 · 异常链人工复核
```

## 1. 前置检查清单

- [ ] 已定延迟到账的分级（时长 / 额度 / 白名单）为**数据**不是常量
- [ ] 已定撤销的回滚边界（从当前持有人回滚）
- [ ] 已定公会仓库的三区与 ACL
- [ ] 已确认延迟策略**只作用于新交易**
- [ ] ⚠ 已知"撤销"与"补偿"是两条独立账

## 2. 工序

### Step 1　⛔ 直接交易用锁定确认，任一方改动就回到 ACTIVE　`[trade/06#S1]`

【读】`howto/godot/player-trading.md#6. 面对面交易用锁定确认，公会仓库是权限化库存`

【做】确认后对双方 offer 加**版本锁**；任一方改 offer → 双方回到 `ACTIVE`。

⛔ 确认后还能改 offer → "我一边加物品一边撤回，同时对方已点确认"，
⛔ 表现为一方损失全部物品。
⚠ 确认后任一方物品失效 → **整个交易取消**，⛔ **不做部分成交**。
⚠ 所有边距、赠礼、以物易物、货币与手续费**均服务端计算**。

【产出】直交状态机 + 版本锁 + 整体取消路径

【判据】⛔ A 确认后 B 改 offer，A 的确认**被清空**

【审】`audit/godot/player-trading.md#25`

### Step 2　⛔ 距离校验要服务端测距，不信客户端位置　`[trade/06#S2]`

【读】`howto/godot/player-trading.md#6. 面对面交易用锁定确认，公会仓库是权限化库存`

【做】面对面交易的合法性由服务端按双方**服务端坐标**判定。

⛔ 用客户端位置 → 改包即可远程"面对面"交易，
⛔ 表现为跨地图直交，而日志里是一次合法交易。

【产出】服务端测距 + 不信任客户端坐标

【判据】⛔ 客户端伪造坐标发起直交 → 被拒绝

【审】`audit/godot/player-trading.md#26`

### Step 3　⛔ 公会仓库是带 ACL 的库存服务，不是共享背包　`[trade/06#S3]`

【读】`howto/godot/player-trading.md#6. 面对面交易用锁定确认，公会仓库是权限化库存`

【做】区分个人暂存区 / 公会公共区 / 审批区；会长⛔ 不能从经济规则中豁免。

⛔ 做成共享背包 → 公会变成**洗号中转站**，
⚠ 表现为"被盗物资在公会仓库转一圈就干净了"。
⛔ 高风险取出、非成员转交、凌晨批量取走要**更长冷却**。

【产出】三区模型 + ACL + 取出冷却

【判据】⛔ 非成员无法直接取走公共区物品；会长操作同样进流水

【审】`audit/godot/player-trading.md#27`

### Step 4　⚠ 摊位掉线要停止新成交，托管中的物品不再可装备　`[trade/06#S4]`

【读】`howto/godot/player-trading.md#6. 面对面交易用锁定确认，公会仓库是权限化库存`

【做】玩家在线摊位掉线 → 立即停止新成交，存量商品进结算 / 回收队列。

⛔ 摊位物品仍算"背包里的可装备品" → 掉线期间被装备或销毁，
表现为"买家付款后拿不到货"，⛔ 且不报错。

【产出】掉线停售 + 回收队列

【判据】⛔ 卖家掉线后，摊位商品**不可购买**也不可装备

【审】`audit/godot/player-trading.md#29`

### Step 5　⛔ 高风险资产必须延迟到账，策略放热更新表　`[trade/06#S5]`

【读】`howto/godot/player-trading.md#7. 延迟到账与撤销：盗号止损的唯一窗口`

【做】把"交易发生"与"资产完全可用"分开；延迟策略放进**热更新策略表**。

⛔ 货款立即到账 → 盗号者批量挂单低价扫给同伙即可完成洗钱，
⛔ 而二次密码、设备提示**不能撤销已完成盗窃**。
⛔ 策略⛔ 不能写死在客户端常量，且变化**只作用于新交易**，⛔ 不追溯改旧订单。
ⓘ 时长 / 额度 / 白名单受安全设计约束，⛔ 不臆定（见 howto §11）。

【产出】延迟策略表 + 分级延迟

【判据】⛔ 改服务端策略表后，**新**订单生效、**旧**订单不变

【审】`audit/godot/player-trading.md#30`

### Step 6　⛔ 延迟结束进"可领取"，不是自动发到背包　`[trade/06#S6]`

【读】`howto/godot/player-trading.md#7. 延迟到账与撤销：盗号止损的唯一窗口`

【做】延迟到期 → 进可领取状态，玩家**主动领取**；领取时复查封禁 / 所有权 / 上限 / 撤销状态。

⛔ 自动发到背包 → 背包满、账号离线、资产上限会造成**隐形丢失**，
⛔ 表现为"钱到账了但不见了"，且日志里是一次成功发放。
⛔ 附件到期要先转**待回收任务**，再由服务端返还或销毁，⛔ 不能只删记录。

【产出】可领取状态 + 领取复查 + 到期回收任务

【判据】⛔ 背包满时领取被拒绝且资产**仍在**可领取列表

【审】`audit/godot/player-trading.md#33`

### Step 7　⛔ 撤销全有或全无，且要冻结后续转移链　`[trade/06#S7]`

【读】`howto/godot/player-trading.md#7. 延迟到账与撤销：盗号止损的唯一窗口`

【做】撤销时**同时冻结后续转移**，并从**当前持有人**回滚；⛔ 不能只看当前货币余额。

⛔ 只回滚货币 → 买家可能已把货款用于强化或转给第三人，
⛔ 只追回货币**无法恢复装备**，表现为"钱退了，装备没了"。
⛔ 补偿金走**独立系统账**，⛔ 不能伪装成正常交易收入。
⛔ 只冻结当前订单 → 下游已转走，撤销落空。

【产出】全有或全无撤销 + 后续链冻结 + 独立补偿账

【判据】⛔ 撤销一笔已转卖的资产，装备**回到原主**且补偿记独立账

【审】`audit/godot/player-trading.md#62`

### Step 8　⛔ 风控判的是关系链，不是单笔是否异常　`[trade/06#S8]`

【读】`howto/godot/player-trading.md#8. 防刷：目标是发现关系链，不是惩罚单一交易`

【做】综合判断**账号 / 设备 / 网络 / 行为 / 资金图**；绑定状态按**快照**恢复。

⛔ 只看单笔 → 小号刷金的每一笔**单看都正常**，
表现为"查不出问题但金币就是源源不断"。
⛔ 只检查 `is_bound` 布尔 → 漏掉"绑定于 A、却被客户端改成可交易"。
⛔ 绑定物品永远不能经交易变"干净"；解绑必须来自**服务端事件**。

【产出】关系链风控 + 绑定快照回滚

【判据】⛔ 一组关联账号循环交易后，被标记且从价格统计中剔除

【审】`audit/godot/player-trading.md#37`

## 5. 常见返工

**① 确认后还能改。** 一方损失全部。

**② 客户端测距。** 跨地图直交。

**③ 公会当共享背包。** 洗号中转站。

**④ 货款立即到账。** 盗号无法止损。

**⑤ 自动发背包。** 隐形丢失。

**⑥ 只回滚货币。** 装备追不回。

**⑦ 只看单笔。** 小号刷金查不出。
