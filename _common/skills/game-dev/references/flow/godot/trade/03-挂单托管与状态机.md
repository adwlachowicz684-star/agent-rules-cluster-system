> **对应**：做法 `howto/godot/player-trading.md#2. 挂单：先用托管把"可卖物品"从背包拿走`
> 　　　审核 `audit/godot/player-trading.md#8`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：挂单写进表、买家能看到就行。**

⛔ 常见假完成：上架只写一条挂单记录，物品**还在卖家背包**——
⚠ 界面、搜索、下单全对，
⛔ 但卖家可以**再装备、再销毁、再邮寄、再挂一次**（双卖），
且不报错，两个买家都拿到"成交成功"。

做完这一步，应该能**当场演示**：

1. ⛔ 上架后该物品**在背包里查不到**（已进托管）
2. ⛔ 卖家用另一个客户端试图装备它 → **被拒绝**
3. ⛔ "正在结算"与"已成交"**不会同时出现**
4. ⛔ 两个买家同时抢最后一件，**只有一个成功**，另一个退款并拿到幂等错误码
5. ⚠ 挂单到期后物品**主动返还**，不是留在托管里

**产出物**（下游按名字对接）：

```text
Listing { id, seller, instance_ref, qty, price_type, price, duration, version, status }
Escrow  { listing_id, instance_ref, qty, version }
状态机：PENDING → ACTIVE → BUYOUT_PENDING / BID_WIN_PENDING → SETTLING → COMPLETED
                        ↘ CANCELLED / EXPIRED / DISPUTED
```

## 2. 工序

### Step 1　⛔ 上架那一刻就把物品托管走，不是成交时再检查　`[trade/03#S1]`

【读】`howto/godot/player-trading.md#2. 挂单：先用托管把"可卖物品"从背包拿走`

【做】`escrow.place()` 在 `market.create_listing()` 之后**立即**执行，
并把背包侧标为"已挂单"。

⛔ 等成交时再检查"是否还在背包" → 卖家在这期间可以继续装备、销毁、邮寄、再挂，
⛔ 表现为**双卖**，两个买家都收到成交成功，**且不报错**。

【产出】`escrow.place()` + 背包侧 `mark_market_listed()`

【判据】⛔ 上架后卖家试图装备该物品 → 被拒绝

【审】`audit/godot/player-trading.md#8`

### Step 2　⛔ 客户端的预估费不是实际费　`[trade/03#S2]`

【读】`howto/godot/player-trading.md#2. 挂单：先用托管把"可卖物品"从背包拿走`

【做】客户端可显示**预估**费用，实际扣费由服务端按请求到达时的余额、折扣、费率计算。

⛔ 让客户端决定实际扣费 → 余额、VIP 折扣、费率都可能在请求途中变化，
表现为"界面显示 100，实际扣了 120"，⛔ 而服务端日志里是一次正常扣费。

【产出】服务端 `fee_calculator` + 客户端"预估"标注

【判据】⛔ 请求途中改费率，成交按**服务端**算的值扣

【审】`audit/godot/player-trading.md#9`

### Step 3　⛔ "正在结算"与"已成交"必须互斥　`[trade/03#S3]`

【读】`howto/godot/player-trading.md#2. 挂单：先用托管把"可卖物品"从背包拿走`

【做】状态机里 `SETTLING` 与 `COMPLETED` 是两个状态，迁移只能单向一次。

⛔ 允许两者并存 → 同一挂单被结算两次，
表现为"卖家收到两笔钱"或"买家扣款两次"，⛔ 而每笔单看都合法。

【产出】挂单状态机 + 唯一迁移路径

【判据】⛔ 并发 100 次结算请求，挂单只从 `SETTLING` 走到 `COMPLETED` 一次

【审】`audit/godot/player-trading.md#10`

### Step 4　⛔ 竞争中只有先拿到挂单版本的行能完成　`[trade/03#S4]`

【读】`howto/godot/player-trading.md#2. 挂单：先用托管把"可卖物品"从背包拿走`

【做】两个请求竞争最后一件时，失败方**退款并收到幂等错误码**。

⛔ 先给双方客户端返回成功、再后台"尽量结算" →
后台失败时客户端已提示成功，
⛔ 表现为"付了钱没拿到货"，而日志里两笔都是成功。

【产出】版本锁 + 幂等错误码 + 自动退款

【判据】⛔ 两个买家同时买最后一件，只有一个 `COMPLETED`，另一个已退款

【审】`audit/godot/player-trading.md#11`

### Step 5　⛔ 上架要收保证金并限同时挂单数，否则占位零成本　`[trade/03#S5]`

【读】`howto/godot/player-trading.md#2. 挂单：先用托管把"可卖物品"从背包拿走`

【做】按 `LISTING_DEPOSIT_RATE` 冻结或扣除保证金，并限制 `MAX_ACTIVE_LISTINGS`。

⛔ 不收保证金 → 恶意占位、刷屏挂单**零成本**，
表现为"真卖家的货被几千条垃圾挂单挤到第十页"，⛔ 且举报无从处理。
⚠ 撤销时按规则扣费或释放保证金，⛔ 不能无条件全退（否则保证金形同虚设）。

【产出】保证金冻结 / 释放路径 + 同时挂单数上限

【判据】⛔ 挂满上限后再上架被拒绝；恶意撤销**损失**保证金

【审】`audit/godot/player-trading.md#55`

### Step 6　⛔ 挂单到期必须主动返还托管物，不是只改状态　`[trade/03#S6]`

【读】`howto/godot/player-trading.md#2. 挂单：先用托管把"可卖物品"从背包拿走`

【做】`EXPIRED` 迁移时把 escrow 里的实例退回背包，并写审计。

⛔ 只把状态改成 `EXPIRED` 却不动 escrow → 物品**永久卡在托管里**，
表现为"我的装备不见了"，⛔ 而挂单列表里查不到它（已过期），**无从找回**。

【产出】过期返还任务 + 审计记录

【判据】⛔ 批量过期 1000 条后，托管区**清空**且每人背包数量对得上

【审】`audit/godot/player-trading.md#57`

## 5. 常见返工

**① 成交时才检查。** 双卖。

**② 客户端定实际费。** 界面与实际不一致。

**③ 两个状态并存。** 重复结算。

**④ 先返回成功再结算。** 付了钱没货。

**⑤ 不收保证金。** 占位零成本。

**⑥ 到期只改状态。** 物品永久消失。
