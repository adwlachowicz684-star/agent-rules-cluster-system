# 玩家交易 / 拍卖行 / C2C 经济流通 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只有邮件发奖励、没有玩家间转移 | **不要套本域** → 见 `ops.md` |
| 面对面直接交易（议价 / 以物易物 / 赠与） | 01 → 02 → 07 |
| 摆摊 / 玩家商店 | 01 → 02 → 03 → 07 |
| 拍卖行（挂单、一口价、竞价） | 01 → 02 → 03 → 04 → 07 |
| 玩家定价 + 防刷价 + 税 | 01 → … → 05 → 07 |
| 公会仓库 / 共享库存 | 01 → 02 → 06 → 07 |
| 怕盗号，要延迟到账与撤销 | 01 → 02 → 06 → 07 |
| 全套 C2C | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **没有玩家间资产转移的项目不要套本域。**

ⓘ 分工：
- `howto/godot/player-trading.md` 讲**单个要素怎么配**（形态 / 托管 / 竞价 / 税 / 延迟 / 风控 / 日志 / RPC）
- 本域讲**这些要素按什么顺序做、怎么保证不双卖、不被刷、可回滚**
- `economy.md` 讲资产**从哪来、被什么消耗**（产出与消耗侧），⛔ 本域不重复

⛔ 若本域某步需要"阶梯税怎么算"这类细节，指向那篇，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 形态定性与原子转移 | — | 五形态共用的 `TransferAsset` + 服务端权威 |
| 02 | 实例、绑定与拆分 | 01 | 实例流转 + 绑定策略 + 拆分退役旧 ID |
| 03 | 挂单托管与状态机 | 02 | 上架即托管 + 状态机 + 幂等竞争 |
| 04 | 一口价、竞价与结算令牌 | 03 | 重读价格 + 冻结领先资金 + 唯一结算令牌 |
| 05 | 定价边界、税与货币去向 | 03 | 软边界 + 阶梯税 + 销毁 sink |
| 06 | 直接交易、公会仓库与延迟撤销 | 02 | 锁定确认 + ACL 库存 + 延迟到账 + 全有或全无撤销 |
| 07 | 交易验收 | 全部 | 敌意环境实测 + 日志可定责 |

⚠ **01 必须在一切之前**：没有统一原子操作，摆摊 / 拍卖 / 邮件 / 公会各写一套 → **五套背包五种漏洞**。
⚠ **02 必须在 03 之前**：流转的不是实例、绑定不进迁移函数，03 的托管没有可托管的对象。
⚠ **03 必须在 04 之前**：物品没托管就做竞价，卖家能在成交前把货再卖一次（**双卖**）。

## 2. 与其他域的接缝

| 接缝 | 契约 |
|---|---|
| `economy` 域 货币与产出 | 本域只做**转移**，⛔ 不定义货币与掉落 |
| `inventory` 域 背包 | 托管 / 取出走 inventory 的锁与容量，⛔ 交易代码不直接改背包表 |
| `netsync` 域 同步 | 写操作 RPC 一律 `reliable`；权威留服务端，见 01 |
| `security` 域 反作弊 | 客户端算价 = 可篡改；风控看关系链，见 05 / 06 |
| `save` 域 存档 | 挂单、托管、延迟到账状态必须随存档，见 03 / 06 |
| `datatable` 域 配表 | 税率 / 延迟策略 / 价格边界是**数据**，⛔ 不写死常量 |
| `ops` 域 运营 | 补偿走独立系统账，⛔ 不伪装成交易收入，见 06 |
| `lifeskill` 域 生活产出 | 产出进 economy 账本，交易只搬**已存在**的实例 |
| `analytics` 域 埋点 | 交易日志即审计源，见 07 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**。

## 3. 本域最容易做反的顺序

⛔ **先做交易界面和 RPC（最直观），再做托管与状态机（03）。**

"能挂单、能买"是最直观的需求，于是先把 UI 与 RPC 打通，
⚠ 而此时物品**还在卖家背包里**，成交时才检查 →
卖家可以在成交前把这件装备**再邮寄、再装备、再挂一次**，
⛔ 表现为**双卖**，且不报错——两个买家都拿到了"成交成功"。

⛔ 同类第二条：**先做竞价显示，再补结算令牌（04）。**
把竞价理解成"显示当前最高价"，客户端点一次就加一次价，
表现为**同一笔出价被应用两次**（`reliable` 不保证幂等），
⛔ 而排查时会去查网络，不会想到缺幂等键。

✅ 正确顺序：先立原子转移与服务端权威（01），再让托管（03）和结算（04）都走它。
