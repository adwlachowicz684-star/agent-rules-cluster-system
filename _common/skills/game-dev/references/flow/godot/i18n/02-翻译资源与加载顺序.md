> 　　　审核 `audit/godot/i18n.md`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：切了语言、界面却没变。**

⛔ 官方对 `set_locale()` 的描述是**条件句**：
> *"If translations have been loaded beforehand for the new locale, they will be applied."*

⚠ 也就是说：翻译**没先加载**就切，切了也不生效，⛔ **且不报错**。
排查时会误以为是"翻译文件有问题"。

做完这一步，应该能**当场演示**：

1. ⛔ 先 `add_translation()` 再 `set_locale()`，顺序可验证
2. ⚠ CSV 第一列名为 `keys`，其余列为语言代码
3. ⛔ 运行时下载的语言包在切之前已 `add_translation()`
4. ⚠ locale 带地区（`zh_CN`）与纯语言（`zh`）的匹配已处理
5. ⚠ 已确认哪些翻译走项目设置、哪些走运行时加载

**产出物**：

```text
翻译资源清单（CSV / PO）
加载顺序约定（先 add 再 set）
locale 匹配规则
```

## 2. 工序

### Step 1　⛔ 先 add_translation 再 set_locale　`[02#S1]`

【读】`howto/godot/i18n.md#7. ⛔ 加载顺序：先 add_translation 再 set_locale`

【做】切换语言的封装里，⛔ 必须先把目标语言的 Translation 加进 TranslationServer，再调 `set_locale()`。

【产出】切换封装（内含先 add 后 set）

【判据】⛔ 切到一个**运行时才加载**的语言，界面**立刻**变

【审】`audit/godot/i18n.md#9`

### Step 2　⚠ CSV 第一列必须叫 keys　`[02#S2]`

【读】`howto/godot/i18n.md#1. 引擎侧机制`

【做】CSV 第一列表头固定 `keys`，其余列是语言代码；放进项目由引擎自动导入为 `.translation`。

【产出】CSV 模板 + 导入约定

【判据】⚠ 改 CSV 后自动重新导入，⛔ **无需手动重建**资源

【审】`audit/godot/i18n.md#16`

### Step 3　⛔ 运行时下载的语言包要先 add　`[02#S3]`

【读】`howto/godot/i18n.md#7. ⛔ 加载顺序：先 add_translation 再 set_locale`

【做】热更 / DLC 语言包下载完成后，先 `add_translation()`，再允许玩家切到该语言。

【产出】语言包加载流程（下载→add→解锁选项）

【判据】⛔ 语言包没下完时，该语言选项**不可选**或切了有明确提示

【审】`audit/godot/i18n.md#17`

### Step 4　⚠ locale 带地区与纯语言要能匹配　`[02#S4]`

【读】`howto/godot/i18n.md#1. 引擎侧机制`

【做】启动时用已加载 locales 去匹配系统 locale（`zh_CN` 可能只注册了 `zh`），匹配不上要有回落。

【产出】locale 匹配与回落规则

【判据】⚠ 系统语言是 `zh_CN` 而只注册了 `zh` 时，**仍显示中文**而非默认语言

【审】`audit/godot/i18n.md#24`

### Step 5　⚠ 项目设置注册与运行时加载的分工　`[02#S5]`

【读】`howto/godot/i18n.md#1. 引擎侧机制`

【做】随包语言在项目设置里注册（引擎初始化即加载）；增量语言运行时加载。**两路都要保证 add 在 set 之前**。

【产出】语言来源分工表

【判据】⛔ 两路都不出现"切了没变"

【审】`audit/godot/i18n.md#9`

## 5. 常见返工

**① 先 set 后 add。** 切了不生效，且不报错。

**② CSV 第一列不叫 keys。** 导入不出翻译，也无明显报错。

**③ 语言包下载完直接切。** 静默不生效。

**④ 只注册 zh 却用 zh_CN 匹配。** 启动时回落到默认语言。
