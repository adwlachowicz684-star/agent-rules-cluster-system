# 本地化（i18n） —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 单语言项目，先占好坑 | 01 → 07 |
| 要多语言切换 | 01 → 02 → 03 → 07 |
| 含中文 / 日文（无空格语言） | 01 → 02 → 03 → 04 → 07 |
| 要支持阿语 / 希语 | 01 → 02 → 03 → 05 → 07 |
| 要按语言换图片 / 音频 | 01 → 02 → 06 → 07 |
| 全套 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只在 UI 上写死一种语言、完全不出海的项目不要套本域。**

ⓘ 分工：
- `howto/godot/i18n.md` 讲**单个要素怎么做**（API / CSV / 切语言 / RTL / 字体 / 溢出）
- 本域讲**这些要素按什么顺序做、怎么管状态**

⛔ 若本域某步需要"翻译流程、术语表、文案 QA"这类细节，
指向独立 skill `localization`，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 文本 ID 规范与翻译边界 | — | key 命名规范 + 翻译 / 不翻译清单 |
| 02 | 翻译资源与加载顺序 | 01 | CSV / PO 资源 + ⛔ 先 add 再 set |
| 03 | 切语言与 UI 刷新事务 | 02 | set_locale + 刷新机制 + 存档持久化 |
| 04 | 字体与断行数据 | 01 | 字体回退链 + 导出含断行数据 |
| 05 | RTL 与结构化文本 | 03 | layout_direction + BiDi override |
| 06 | 资源本地化与长文本适配 | 02 | 资源 remap + 膨胀后不溢出 |
| 07 | 本地化验收 | 全部 | 伪本地化全套 + 导出包实测 |

⚠ **01 必须在一切之前**：key 没规范，后面每一项都要返工。
⚠ **02 必须在 03 之前**：翻译没加载时切语言**不生效**，官方是条件句。
⚠ **03 必须在 05 之前**：切都切不动，RTL 无从验证。

## 2. 与其他域的接缝

| 接缝 | 契约 |
|---|---|
| `ui` 域 UI 结构 | 面向玩家的文本一律走 `tr()`，见 01 |
| `narrative` 域 对话树 | 对话文本走 key，不硬编码 |
| `save` 域 存档 | ⛔ 存 key / ID，不存翻译结果，见 01 |
| `audio` 域 语音 | 语音按 locale 分包，见 06 |
| `datatable` 域 配置表 | 表内展示文本用 key |
| `camera` / `level` 域 | 非 UI 节点文字不自动翻译，见 05 |
| 导出（`platform-export`） | 断行数据与字体分包在导出设置里，见 04 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**。

## 3. 本域最容易做反的顺序

⛔ **先把文案硬编码进 UI，最后才想起要提取翻译。**

UI 是最直观的产出，于是先把按钮文字、提示语直接写死，
⚠ 界面确实能跑、能演示，
⛔ 但后期提取要逐个 UI 改，而**漏改的不报错**——
表现为"上线后某些按钮一直是原语言"，且没人知道漏的是哪几个。

✅ 正确顺序：先立 key 规范与翻译边界（01），
再建翻译资源并确认加载顺序（02），
再让切语言与 UI 刷新成为事务（03），
最后才处理字体 / RTL / 资源这些适配项（04–06）。
