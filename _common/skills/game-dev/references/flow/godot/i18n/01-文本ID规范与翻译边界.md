# 01 文本 ID 规范与翻译边界（i18n 域）

> **前置**：无（本域地基）
> **本步交付**：**key 命名规范 + 翻译 / 不翻译清单 + 插值规则**
> **对应**：做法 `howto/godot/i18n.md#6. 大型项目建议`
> 　　　审核 `audit/godot/i18n.md`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：界面上文字能显示就行。**

⛔ 常见假完成：按钮上直接写 `text = "开始游戏"`，
⚠ 界面确实能跑、能演示，
⛔ 但此时没有 key、没有边界，
后期要出海时得逐个 UI 改，而**漏改的不报错**——
表现为"上线后某些角落一直是原语言"。

做完这一步，应该能**当场演示**：

1. ⛔ 有书面的 key 命名规则（模块.位置.含义）
2. ⛔ 存档与网络包里存的是 key / ID，**不是翻译后的文本**
3. ⚠ 日志 / 配置值 / 内部 ID 明确列入"不翻译"清单
4. ⛔ 插值一律写成 `tr("KEY") % value`，不是 `tr("KEY" % value)`
5. ⚠ 复数走 `tr_n()`，且已确认承载格式是否支持复数

**产出物**（下游按名字对接）：

```text
key 命名规则表
翻译 / 不翻译清单
插值与复数规则
```

## 1. 前置检查清单

- [ ] 已定 key 命名规则
- [ ] 已列出"不翻译"清单（日志 / ID / 配置值）
- [ ] 已定插值格式（统一占位符写法）
- [ ] 已确认是否需要复数形式语言（决定用 CSV 还是 PO）

## 2. 工序

### Step 1　⛔ key 用模块.位置.含义，不能用英文原文　`[01#S1]`

【读】`howto/godot/i18n.md#6. 大型项目建议`

【做】以 `模块.位置.含义` 定义 key（如 `UI.MAIN.START_BTN`），全局唯一、不随文案改。

【产出】key 命名规则表

【判据】⛔ 改一次文案，代码与翻译表**都不用动 key**

【审】`audit/godot/i18n.md#7`

### Step 2　⛔ 存档存 key / ID，不存翻译结果　`[01#S2]`

【读】`howto/godot/i18n.md#6. 大型项目建议`

【做】落盘一律存稳定 ID；显示时才 `tr()`。

【产出】存档字段约定（只存 ID）

【判据】⛔ 切语言后，**旧存档**里的文本跟着变

【审】`audit/godot/i18n.md#1`

### Step 3　⛔ 日志 / 内部 ID / 配置值不翻译　`[01#S3]`

【读】`howto/godot/i18n.md#6. 大型项目建议`

【做】明确划出只翻译"给玩家看的"，其余一律不进翻译表。

【产出】翻译 / 不翻译清单

【判据】⛔ 切到任意语言，存档、配置、日志**行为完全一致**

【审】`audit/godot/i18n.md#6`

### Step 4　⛔ 插值必须写在 tr() 之后　`[01#S4]`

【读】`howto/godot/i18n.md#14. ⛔ 格式化必须在 tr() 之后`

【做】统一 `tr("KEY") % value`；⛔ 禁止 `tr("KEY" % value)`。

【产出】插值 helper（统一占位符）

【判据】⛔ 带变量的文本在**所有语言**下都能取到翻译

【审】`audit/godot/i18n.md#15`

### Step 5　⚠ 复数走 tr_n，复杂复数语言要换 PO　`[01#S5]`

【读】`howto/godot/i18n.md#1. 引擎侧机制`

【做】数量文本用 `tr_n()`；若目标语言复数规则复杂（俄语等），承载格式改用 PO。

【产出】复数处理约定 + 承载格式选择（CSV / PO）

【判据】⚠ 数量 1 与数量 2 **显示不同的形式**

【审】`audit/godot/i18n.md#16`

## 5. 常见返工

**① 用英文原文当 key。** 改文案时所有引用跟着改。

**② 存档存了翻译结果。** 切语言后旧存档不更新。

**③ 插值写在 tr() 里面。** key 被格式化，永远查不到。

**④ CSV 承载复杂复数。** 俄语等语言的复数形式全错。
