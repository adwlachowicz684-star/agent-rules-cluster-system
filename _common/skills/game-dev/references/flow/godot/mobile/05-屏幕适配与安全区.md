# 05 屏幕适配与安全区（移动端域）

> **本步交付**：安全区换算 + 方向切换 + 软键盘避让
> **对应**：流程 `howto/godot/mobile.md` · 审核 `audit/godot/mobile.md`

## 0. 交付物定义

1. 安全区一律走 `get_display_safe_area()`，⛔ 不用 `get_display_cutouts()` 拼
2. 屏幕坐标已转换到项目 Content 坐标，⛔ 不是直接当像素用
3. 安全区在 `size_changed` 时重算，⛔ 不止在 `_ready()`
4. 方向切换后基础宽高已正确，⛔ 竖屏不会沿用横屏的
5. 自定义输入框已做软键盘避让

## 1. 前置检查清单

- [ ] 安全区走 `get_display_safe_area()`
- [ ] 已做屏幕坐标到 Content 坐标的转换
- [ ] `size_changed` 已连接，且退出时断开
- [ ] 竖屏 / 横屏切换实测无变形
- [ ] ⚠ 自定义输入框弹出软键盘后不被遮挡
- [ ] 刘海机型上无控件被遮挡

## 2. 工序

### Step 1　安全区用 safe_area，不要用 cutouts 拼　`[mobile/05#S1]`

【读】`howto/godot/mobile.md#安全区（刘海屏）`

【做】
一律用 `DisplayServer.get_display_safe_area()`。
⛔ 用 `get_display_cutouts()` 自己算 —— 官方口径是它**只在 Android 和 macOS 实现**，
其它平台"即使设备确实有刘海 / 挖孔，也会返回空数组"。

⛔ 于是 iOS（恰恰是有刘海的平台）上会得到 0 边距，
表现为"iOS 上 UI 被刘海挡住、安卓上完全正常"，且不报错。
排查方向会被彻底带偏到 iOS 导出配置上去。

ⓘ `get_display_safe_area()` 在 Android / iOS / macOS 真实实现，
其它平台回退成 `screen_get_usable_rect()` —— 这个回退是安全的。

【产出】安全区取值方式（只用 safe_area）

【判据】 iOS 刘海机型上，顶部控件不被遮挡。

【审】`audit/godot/mobile.md#24`、`audit/godot/mobile.md#7`

### Step 2　屏幕坐标要转成本项目坐标再用　`[mobile/05#S2]`

【读】`howto/godot/mobile.md#安全区（刘海屏）`

【做】
用 `get_screen_transform()` 的逆变换把安全区矩形转到项目 Content 坐标。
⛔ 把屏幕坐标直接当项目坐标用 —— 官方明确返回值是
**相对物理屏幕、不是虚拟桌面**的。

⛔ 有 `canvas_items` / `viewport` 拉伸时边距全错，
表现为"安全区偏移了一点，但方向说不清"，
于是会被反复微调一个根本不该调的偏移量。

【产出】坐标转换代码，且转换在每次取值时执行

【判据】在拉伸模式切换后，边距仍然正确。

【审】`audit/godot/mobile.md#25`、`audit/godot/mobile.md#7`

### Step 3　安全区要响应尺寸变化，不能只算一次　`[mobile/05#S3]`

【读】`howto/godot/mobile.md#安全区（刘海屏）`

【做】
连接 `size_changed` 信号重算，并在 `_exit_tree()` 里断开。
⛔ 只在 `_ready()` 里算一次 —— 旋转屏幕、分屏、外接显示器之后
安全区就过期了，⛔ 表现为"转屏后 UI 被挡住"，而且一旦发生就不会自愈。

ⓘ 断开连接不能漏：场景反复加载时重复连接会导致重算被调用多次，
虽然结果一样，但会掩盖真正的重算时机问题。

【产出】重算路径（信号连接 + 断开）

【判据】旋转屏幕后，边距立刻更新且正确。

【审】`audit/godot/mobile.md#20`

### Step 4　竖屏不会自动交换宽高，要自己改　`[mobile/05#S4]`

【读】`howto/godot/mobile.md#方向与分辨率`

【做】
改 `display/window/handheld/orientation` 的同时，
把项目基础宽高（`viewport_width` / `viewport_height`）一起交换。
⛔ 只改方向设置 —— 引擎**不会自动交换**基础宽高，
⛔ 表现为"竖屏下 UI 被横向拉伸变形"。

ⓘ 拉伸模式与宽高比也要一并确认：2D 非像素风用 `canvas_items`、
像素风用 `viewport`，宽高比用 `expand` 避免裁切。

【产出】方向设置 + 对应的基础宽高

【判据】竖屏与横屏下 UI 都无变形。

【审】`audit/godot/mobile.md#21`

### Step 5　自定义输入框要做软键盘避让　`[mobile/05#S5]`

【读】`howto/godot/mobile.md#软键盘`

【做】
自定义输入框弹出软键盘后，轮询 `virtual_keyboard_get_height()` 调整布局。
⛔ 不做避让 —— 输入框被键盘盖住，玩家看不到自己输入了什么，
⛔ 而这在测试时极易被忽略，因为测试机上往往装了输入法但不弹出。

ⓘ `LineEdit` / `TextEdit` 会自动处理，只有自己做的输入框才需要管。
没有统一的"键盘高度变化"信号，所以只能轮询。

【产出】软键盘避让逻辑（轮询高度 + 调整布局）

【判据】弹出键盘后，输入框与光标都可见。

【审】`audit/godot/mobile.md#22`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：只用 safe_area + 坐标转换 + 响应尺寸变化
@onready var _ui_root: Control = $UI

func _ready() -> void:
    _apply_safe_area()
    get_viewport().size_changed.connect(_apply_safe_area)

func _exit_tree() -> void:
    if get_viewport().size_changed.is_connected(_apply_safe_area):
        get_viewport().size_changed.disconnect(_apply_safe_area)

func _apply_safe_area() -> void:
    # ⓘ 只用 safe_area：cutouts 在 iOS 返回空数组（见 S1）
    var area := DisplayServer.get_display_safe_area()
    # ⛔ 返回值是物理屏幕坐标，必须转到项目 Content 坐标（见 S2）
    var inv := get_viewport().get_screen_transform().affine_inverse()
    var p := inv * Vector2(area.position)
    var s := inv * Vector2(area.size)
    var screen_h := float(get_viewport().get_visible_rect().size.y)
    _ui_root.offset_top = p.y
    _ui_root.offset_bottom = -(screen_h - p.y - s.y)
```

## 4. 验收清单

- [ ] 安全区只走 `get_display_safe_area()`，代码里无 cutouts
- [ ] 每次取安全区都做了坐标转换
- [ ] `size_changed` 已连接且退出时断开
- [ ] 竖屏 / 横屏切换无变形
- [ ] 自定义输入框弹出键盘后可见

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| iOS 上 UI 被刘海挡住 | 用 cutouts 拼安全区 | S1 |
| 边距偏移一点、方向说不清 | 屏幕坐标未转换 | S2 |
| 转屏后 UI 被挡且不自愈 | 安全区只算一次 | S3 |
| 竖屏下 UI 横向拉伸 | 只改方向不改基础宽高 | S4 |
| 输入框被键盘盖住 | 未做软键盘避让 | S5 |
