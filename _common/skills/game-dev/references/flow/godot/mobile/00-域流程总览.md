# 移动端（触控 / 摇杆 / 适配 / 后台）—— 域流程总览

> ⚠ **第 0 步：先定输入架构。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 加个虚拟摇杆 | 01 → 04 → 07 |
| 触控点击 / 拖拽 | 01 → 02 → 07 |
| 双指缩放、滑动手势 | 01 → 02 → 03 → 07 |
| 适配刘海屏 / 横竖屏 | 01 → 05 → 07 |
| 安卓返回键、权限申请 | 01 → 06 → 07 |
| 切后台保进度 | 01 → 06 → 07 |
| 准备上架移动端 | 01 → 02 → 04 → 05 → 06 → 07 |
| 全套移动端工程 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只要上移动端，05 和 06 都不能跳过** ——
安全区与后台预算在正常流程下**完全测不出来**：
编辑器里是鼠标、是窗口、是常驻前台，⛔ 而真机上是拇指、是刘海、是随时被回收。
这三条恰好是"上线后一星评论"最集中的来源。

ⓘ 若本次只是**"加个按钮、换个图标"**，那是 UI 配置，不套本域。
ⓘ 若只是**排查移动端掉帧**，先看 `perf` 域定位，确认是输入/适配问题再回本域。

ⓘ 分工：
- `howto/godot/mobile.md` 讲**单个要素怎么实现**（事件、摇杆、适配、权限、性能）
- 本域讲**这些要素按什么顺序做、怎么保证真机上真的能玩**

⛔ 若本域某步需要"某台设备上的具体帧率/耗电"这类细节，
指向 `perf` 域实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 输入架构定性 | — | 输入形态定死 + 目标设备档位 + 桌面端如何共存 |
| 02 | 触控事件与多点触控 | 01 | 事件流分工 + 手指 index 管理 |
| 03 | 手势识别 | 01, 02 | 手势集 + 与点击/拖拽的裁决顺序 |
| 04 | 虚拟摇杆与屏幕按键 | 01, 02 | 摇杆参数 + 死区口径 + 桌面端隐藏 |
| 05 | 屏幕适配与安全区 | 01 | 安全区换算 + 方向切换 + 软键盘避让 |
| 06 | 平台能力与后台预算 | 01 | 返回键 + 权限 + 暂停恢复 |
| 07 | 移动端验收 | 全部 | 真机实测 + 敌意环境实测 |

⚠ **01 必须在一切之前**：输入架构后改等于所有输入代码重写 ——
摇杆、触控、手势、按键是四套不同的事件消费方式，⛔ 中途切换不是"改几行"。

⚠ **05 必须在 UI 铺开之前**：那时每处锚点都已按固定尺寸摆完，
安全区、方向切换、软键盘三件事会让**每一处**都要重算。

⚠ **06 不能留到最后**：暂停预算不足在 iOS 上是**被杀进程**，
⛔ 而这在测试期只在"切后台很久再回来"时才出现，上线后才是用户日常。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `shaders` 域 着色器 | 移动端精度与后端差异见 `shaders/05`；⛔ 本域不重复定渲染预算 |
| `perf` 域 性能分析 | 真机帧率、发热、内存见 `perf` 域实测；本域只定"必须测"的动作 |
| `ui` 域 UI | 安全区内的锚点布局走 `ui` 域，⛔ 安全区本身由本域 05 提供 |
| `input` | ⓘ howto 层，暂无 flow 域 —— 通用输入映射与手柄见该篇 |
| `platform-export` | ⓘ howto 层，暂无 flow 域 —— 导出预设与签名不属本域 |
| `analytics` 域 埋点 | 暂停时未上报的队列走 `analytics/03` 的持久化，⛔ 不另写一份 |
| `save` 域 存档 | 暂停时的落盘走 `save` 域的原子写，⛔ 不在通知里直接写文件 |
| `compliance` 域 合规 | 权限申请的理由文案与最小必要原则见 `compliance/02` |
