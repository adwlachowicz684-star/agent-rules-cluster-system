# 03 手势识别（移动端域）

> **本步交付**：手势集 + 与点击 / 拖拽的裁决顺序
> **对应**：流程 `howto/godot/mobile.md` · 审核 `audit/godot/mobile.md`

## 0. 交付物定义

1. 手势集已列出（缩放 / 滑动 / 长按 / 双击），每个都有明确用途
2. 手势与点击、拖拽的裁决顺序已定死，⛔ 不靠"哪个先触发"
3. 双指缩放用**相对变化**判定，不是绝对距离
4. 手势阈值按屏幕尺寸归一化
5. 手势与游戏操作的冲突已裁决（如拖动角色 vs 滑动翻页）

## 1. 前置检查清单

- [ ] 手势集已列出，每个都能说出用途
- [ ] 裁决顺序已定死，写在文档里
- [ ] 缩放置信度用相对变化，不是像素阈值
- [ ] 手势阈值已按屏幕尺寸归一化
- [ ] ⚠ 手势与游戏操作的冲突已裁决
- [ ] 长按 / 双击不与单击重复触发

## 2. 工序

### Step 1　先列手势集，别边做边加　`[mobile/03#S1]`

【读】`howto/godot/mobile.md#2. 手势识别器`

【做】
列出全部要支持的手势，并给每个写明用途与触发条件。
⛔ 边做边加手势 —— 后加的手势会和已有的争抢同一批事件，
而裁决逻辑是散在各处的，⛔ 表现为"加了双指缩放之后单击偶尔失灵"。

ⓘ 不支持的手势也要写下来（明确不做），否则后面会不断有人问"能不能加"。

【产出】手势集表（名称 / 用途 / 触发条件 / 是否支持）

【判据】指着每个手势，能说出它和别的手势在事件层面如何区分。

【审】`audit/godot/mobile.md#18`

### Step 2　裁决顺序定死，不靠触发先后　`[mobile/03#S2]`

【读】`howto/godot/mobile.md#2. 手势识别器`

【做】
明确"单击 / 长按 / 双击 / 拖拽 / 缩放"的判定顺序，写成显式的状态机或优先级。
⛔ 靠"哪个信号先到"隐式裁决 —— 事件到达顺序受帧率影响，
⛔ 表现为"低端机上单击被判成长按"，而高端机完全正常，
排查方向会被彻底带偏到机型适配上去。

ⓘ 常见顺序：按下 → 未移动且超时则长按 → 抬起且未移动则单击 →
移动超阈值则拖拽 → 第二指按下则转入缩放。

【产出】裁决顺序的状态机说明

【判据】人为放慢帧率，裁决结果不变。

【审】`audit/godot/mobile.md#18`

### Step 3　双指缩放用相对变化，不用绝对距离　`[mobile/03#S3]`

【读】`howto/godot/mobile.md#双指缩放：记录两指间距`

【做】
记录上一帧两指间距，用**比值**或**增量**驱动缩放。
⛔ 用绝对距离映射缩放级别 —— 同样的捏合动作在 5 寸屏和 12 寸屏上
得到完全不同的结果，⛔ 表现为"平板上缩放特别快"，
而排查会被引向缩放系数调错。

ⓘ 相对的另一个好处：不需要知道屏幕物理尺寸，也就绕开了
`screen_get_dpi()` 不该当 UI 缩放系数用的那个坑。

【产出】缩放驱动量：间距比值或增量（非绝对像素）

【判据】在两个尺寸差异明显的设备上，同样的捏合得到同样的缩放比例。

【审】`audit/godot/mobile.md#19`、`audit/godot/mobile.md#35`

### Step 4　手势阈值按屏幕尺寸归一化　`[mobile/03#S4]`

【读】`howto/godot/mobile.md#2. 手势识别器`

【做】
把滑动距离、长按时长之外的**距离类阈值**按屏幕短边归一化。
⛔ 用写死的像素阈值 —— 在小屏上很容易触发、大屏上很难触发，
⛔ 表现为"平板上滑动总是不生效"，且不报错。

ⓘ 时长类阈值（长按多久）不需要归一化，它与屏幕无关。

【产出】阈值表：哪些按屏幕归一化、哪些用固定值

【判据】在两个尺寸差异明显的设备上，同样的滑动动作结果一致。

【审】`audit/godot/mobile.md#19`、`audit/godot/mobile.md#42`

### Step 5　手势与游戏操作冲突要显式裁决　`[mobile/03#S5]`

【读】`howto/godot/mobile.md#2. 手势识别器`

【做】
明确同一块触摸区域上，手势和游戏操作谁优先。
⛔ 把滑动翻页和拖动角色放在同一区域却不裁决 ——
玩家想翻页时角色被拖动，想拖动时页面翻了，
⛔ 表现为"操作很黏、不跟手"，而这恰恰是玩家评论里最难描述、
也最容易被归为"优化差"的一类问题。

ⓘ 裁决通常用区域划分（摇杆区 / 手势区）或语义划分（先判是否落在可拖动对象上）。

【产出】触摸区域划分图或语义裁决规则

【判据】在重叠区域操作，结果符合预期且可预测。

【审】`audit/godot/mobile.md#18`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：相对缩放 + 阈值按屏幕短边归一化 + 显式裁决
extends Node

const LONG_PRESS_SEC := 0.5      # ⓘ 时长类，不随屏幕变化
const SWIPE_RATIO := 0.08        # ⓘ 距离类，占屏幕短边的比例
const TAP_RATIO := 0.02

var _prev_dist := 0.0
var _start_pos := Vector2.ZERO

func _screen_short_side() -> float:
    var s := DisplayServer.window_get_size()
    return minf(float(s.x), float(s.y))

func _on_two_finger(pos_a: Vector2, pos_b: Vector2) -> void:
    var dist := pos_a.distance_to(pos_b)
    if _prev_dist > 0.0:
        # ⓘ 用比值驱动，不用绝对距离（见 S3）
        var ratio := dist / _prev_dist
        _apply_zoom(ratio)
    _prev_dist = dist

func _on_release(pos: Vector2) -> void:
    var limit := _screen_short_side() * TAP_RATIO   # ⓘ 归一化阈值（见 S4）
    if pos.distance_to(_start_pos) < limit:
        _fire_tap()
    _prev_dist = 0.0
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 加了缩放后单击偶失灵 | 手势边做边加 | S1 |
| 低端机单击判成长按 | 靠事件到达顺序裁决 | S2 |
| 平板上缩放特别快 | 用绝对距离映射 | S3 |
| 平板上滑动不生效 | 阈值写死像素 | S4 |
| 操作很黏、不跟手 | 手势与操作未裁决 | S5 |
