# 04 虚拟摇杆与屏幕按键（移动端域）

> **本步交付**：摇杆参数 + 死区口径 + 桌面端隐藏
> **对应**：流程 `howto/godot/mobile.md` · 审核 `audit/godot/mobile.md`

## 0. 交付物定义

1. 4.7+ 已用内置 `VirtualJoystick`，⛔ 没自己造一套
2. `action_left/right/up/down` 已显式设置，⛔ 不依赖默认值
3. 死区口径已定，摇杆死区与 InputMap 死区不会意外叠加
4. `joystick_size` / `tip_size` 已按屏幕密度换算，不是默认像素值
5. 摇杆位于独立 `CanvasLayer`，触摸不被其它 UI 吞掉
6. 桌面端已隐藏摇杆；固定按键用 `TouchScreenButton`

## 1. 前置检查清单

- [ ] 引擎版本 ≥ 4.7 时用的是内置节点
- [ ] 四个 `action_*` 已显式指向本项目 Input Map 动作
- [ ] 死区只在一处设置，或已确认叠加后的值符合预期
- [ ] 摇杆尺寸已按屏幕密度换算
- [ ] ⚠ 摇杆在独立 `CanvasLayer`，且没有不可见控件压在上面
- [ ] 桌面端摇杆不可见

## 2. 工序

### Step 1　4.7+ 用内置节点，别自己造　`[mobile/04#S1]`

【读】`howto/godot/mobile.md#3. 虚拟摇杆`

【做】
4.7 起引擎内置 `VirtualJoystick`，直接用它。
⛔ 沿用 4.6 的自制实现 —— 三种模式（固定 / 动态 / 跟随）、死区、
拖动半径、绑定动作都是现成的，自己写要重新踩一遍这些坑。

ⓘ 例外是外观需要定制到内置节点做不到的程度，
或项目锁在 4.6 及更早 —— 那时才走自制实现。

【产出】摇杆节点（内置 / 自制）+ 版本依据

【判据】能说清用内置还是自制，且与引擎版本一致。

【审】`audit/godot/mobile.md#27`

### Step 2　四个 action 必须显式设置，默认值会触发 UI 导航　`[mobile/04#S2]`

【读】`howto/godot/mobile.md#3. 虚拟摇杆`

【做】
把 `action_left/right/up/down` 显式指向项目 Input Map 里的移动动作。
⛔ 留默认值 —— 四个属性的默认值是 `ui_left` / `ui_right` / `ui_up` / `ui_down`，
⛔ 摇杆一动就会触发 **UI 导航动作**。

表现为"推动摇杆时界面焦点乱跳、按钮被莫名选中"，
⛔ 而排查方向几乎必然被引向 UI 焦点逻辑或摇杆手感，
不会想到是四个没设置、且看起来"有值"的属性。

ⓘ 绑 action 是最省事的接法：摇杆等价于虚拟按键，移动逻辑零改动。
需要连续向量时才走 `flicked` / `released` 信号的 `input_vector` 参数
（⛔ 内置节点**没有**可轮询的输出属性）。

【产出】四个 action 已赋值，且能在 Input Map 里逐字符对上

【判据】摇杆推动时，UI 焦点不发生任何变化。

【审】`audit/godot/mobile.md#11`、`audit/godot/mobile.md#26`

### Step 3　死区会叠加，只在一处设　`[mobile/04#S3]`

【读】`howto/godot/mobile.md#3. 虚拟摇杆`

【做】
决定摇杆 `deadzone_ratio` 与 InputMap 动作死区**谁负责**，另一个留 0。
官方口径：两者都设时**摇杆死区先应用，随后再应用动作死区**。
⛔ 两边都设 —— 实际死区是两者的组合，比任何一边都大，
表现为"轻推摇杆没反应、要推很远才开始动"。

⛔ 这条特别隐蔽：摇杆面板上写着 0.2，InputMap 里写着 0.5，
两个数字**单独看都合理**，只有叠加后才是问题。

ⓘ 默认 `deadzone_ratio = 0.0` 表示摇杆不自带死区、完全交给 InputMap ——
这是最不容易出错的默认口径。

【产出】死区归属结论（摇杆 / InputMap 二选一）

【判据】轻推摇杆，角色立刻开始移动，无"死行程"。

【审】`audit/godot/mobile.md#12`

### Step 4　摇杆尺寸是像素，要按屏幕密度换算　`[mobile/04#S4]`

【读】`howto/godot/mobile.md#3. 虚拟摇杆`

【做】
按屏幕密度把 `joystick_size` / `tip_size` 换算成实际像素。
⛔ 用默认的 100.0 / 50.0 像素 —— 这两个值在平板和高 DPI 手机上
看起来**明显偏小**，拇指按不准。

ⓘ 换算依据是屏幕密度而非分辨率：同样 1080p 的 5 寸屏和 10 寸屏，
物理尺寸差一倍，摇杆的物理大小也就差一倍。

⛔ 可触摸区域必须**不小于**视觉半径 —— 看着在圈内、按下去没反应
是最容易被玩家描述为"摇杆坏了"的问题。

【产出】尺寸换算公式 + 可触摸区域 ≥ 视觉半径的验证

【判据】在最高密度和最低密度两台设备上，摇杆物理大小接近。

【审】`audit/godot/mobile.md#13`、`audit/godot/mobile.md#36`

### Step 5　摇杆放独立 CanvasLayer，别被上层控件吃掉触摸　`[mobile/04#S5]`

【读】`howto/godot/mobile.md#3. 虚拟摇杆`

【做】
摇杆挂在独立 `CanvasLayer` 下，并确认没有不可见控件压在它上面。
⛔ 和游戏 UI 混在同一层 —— 触摸会被上层不可见控件吞掉，
⛔ 表现为"摇杆有时不响应"，而这种间歇性失效最难复现。

ⓘ 反过来也要注意：摇杆自己的 `mouse_filter` 要是 `STOP`，
否则触摸穿透到游戏世界，表现为"推摇杆时还触发了点击地形"。

【产出】图层结构说明 + 摇杆 `mouse_filter` 设置

【判据】摇杆区域内按下拖动，不触发任何游戏世界点击。

【审】`audit/godot/mobile.md#14`、`audit/godot/mobile.md#4`

### Step 6　桌面端隐藏摇杆，固定按键用 TouchScreenButton　`[mobile/04#S6]`

【读】`howto/godot/mobile.md#固定按键用 TouchScreenButton`

【做】
非移动平台隐藏摇杆；离散的按键（跳跃、技能）用 `TouchScreenButton`。
⛔ 桌面端仍显示摇杆 —— 键鼠玩家看到一个用不上的控件，
且它会挡住画面，⛔ 这是"看起来没做完"的典型信号。

ⓘ 4.6 及更早没有 `VirtualJoystick`，那时 `TouchScreenButton` 只能做按键：
绑单个 action，没有方向输出、没有死区，⛔ 不能当摇杆用。

【产出】可见性策略 + 按键节点清单

【判据】桌面构建里看不到摇杆；按键只绑单个 action。

【审】`audit/godot/mobile.md#15`、`audit/godot/mobile.md#28`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：显式 action + 死区只在一处 + 尺寸按密度换算 + 桌面隐藏
@onready var joystick: VirtualJoystick = $UI/VirtualJoystick

# ⓘ 死区口径结论：全部交给 InputMap，摇杆留默认 0.0（见 S3）
const BASE_JOYSTICK_SIZE := 100.0
const BASE_TIP_SIZE := 50.0

func _ready() -> void:
    joystick.visible = OS.has_feature("mobile")
    if not joystick.visible:
        return

    # ⛔ 必须显式设：默认是 ui_left/right/up/down，会触发 UI 导航（见 S2）
    joystick.action_left = &"move_left"
    joystick.action_right = &"move_right"
    joystick.action_up = &"move_forward"
    joystick.action_down = &"move_back"

    # ⓘ 默认 100/50 是像素，按密度换算（见 S4）
    var density := DisplayServer.screen_get_dpi() / 160.0
    joystick.joystick_size = BASE_JOYSTICK_SIZE * density
    joystick.tip_size = BASE_TIP_SIZE * density
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 推摇杆时 UI 焦点乱跳 | action 用了默认 `ui_*` | S2 |
| 轻推没反应 | 摇杆与 InputMap 死区叠加 | S3 |
| 高 DPI 上摇杆太小 | 用默认像素值 | S4 |
| 摇杆有时不响应 | 被上层不可见控件吞噬 | S5 |
| 推摇杆时触发点击地形 | `mouse_filter` 不是 STOP | S5 |
| 桌面端看到摇杆 | 未隐藏 | S6 |
