# 外观与个性化（时装 / 称号 / 头像框 / 表情动作 / 染色）—— 域流程总览

> ⚠ **第 0 步：先定"谁拥有、谁说了算"。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 时装 / 换装 / 染色 | 01 → 03 → 04 → 07 |
| 称号 / 头像框 | 01 → 05 → 07 |
| 表情动作 | 01 → 05 → 06 → 07 |
| 坐骑皮肤 | 01 → 02 → 07 |
| 限时时装 / 有效期 | 01 → 02 → 06 → 07 |
| UGC 外观 | 01 → 06 → 07 |
| 全套外观系统 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过** ——
七类外观（时装 / 称号 / 头像框 / 表情 / 染色 / 坐骑皮肤 / UGC）技术形态差异很大，
但生命周期高度相似。⛔ 不先统一成"模板 / 实例 / 生效"三层，就会写出七套互斥逻辑，
表现为"这个能穿、那个莫名消失"，而排查时每一套单看都合理。

⛔ **02 不能留到最后**：槽位冲突与有效期是**状态问题**，不是表现问题。
先做表现后补状态，会在装备交易、限时时装到期、热更替换资产时**成片返工**。

ⓘ 若本次只是**"换一张贴图、加一个颜色"**，那是资源配置，不套本域。
ⓘ 若只是**排查外观加载不出来**，先看 `perf` 域定位，确认是加载/IO 问题再回本域 04。

ⓘ 分工：
- `howto/godot/character-customization.md` 讲**换装与染色的技术实现**（Blend Shape、换网格、实例材质）
- `howto/godot/cosmetic.md` 讲**资产系统层**（拥有权、优先级、有效期、授权、加载回退、同步、商业化承诺）
- 本域讲**这些要素按什么顺序做、怎么保证换资产换版本后仍然对**

⛔ 若本域某步需要"同屏人数上限""加载预算毫秒数"这类细节，
指向项目实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 外观模型与拥有权地基 | — | 三层模型 + 生效范围字段 + 服务端权威口径 |
| 02 | 槽位仲裁与有效期状态机 | 01 | 仲裁字段 + 三态过期 + 到期释放流程 |
| 03 | 换装染色与实例隔离 | 01, 02 | 三入口替换 + 实例材质口径 + 显示/属性隔离 |
| 04 | 异步加载与回退 | 01, 03 | 默认外观零依赖 + 令牌 + 占位口径 |
| 05 | 网络同步与版本校正 | 01, 02 | manifest + 增量 + 全量校正时机表 |
| 06 | 商业化承诺与 UGC 治理 | 01, 02 | 不改数值扫描 + 到期承诺 + UGC 三阶段 |
| 07 | 外观系统验收 | 全部 | 敌意环境实测 + 多端一致性实测 |

⚠ **01 必须在美术铺开之前**：那时七类资产已各按各的规范做完，
统一模型意味着七套数据各改一次。

⚠ **03 的显示/属性隔离要在战斗接入之前**：
外观挂点一旦被写成"顺便提供碰撞或移速"，
后面想拆就得同时改战斗、移动与经济三处。

⚠ **04 默认外观的"零外部依赖"是成立条件，不是优化** ——
回退路径自身依赖网络时，断网场景下**连默认外观都出不来**。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是换装，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `economy` 域 经济 | 装备四层分离（模板/实例/词条/养成）见 `economy/05`，⛔ 外观实例与装备实例**必须分离存储** |
| `monetization` 域 商业化 | 概率抽取、购买与退款见 `monetization`，⛔ 本域只定"外观不改什么"的承诺口径 |
| `security` 域 安全 | 客户端改内存伪造外观的检测见 `security`，⛔ 本域只保证"选择成功 ≠ 拥有" |
| `netsync` 域 网络同步 | 传输与 RPC 机制见 `netsync`，⛔ 本域定同步**内容**（ID/版本/摘要）与全量校正时机 |
| `compliance` 域 合规 | UGC 审核、举报留痕与下架见 `compliance/05`，⛔ 本域只定三阶段流程 |
| `inventory` 域 背包 | 外观库存的存取事务见 `inventory`，⛔ 本域不另定背包规则 |
| `shaders` 域 着色器 | 材质实例、`Local to Scene` 的部分生效边界见 `shaders/04`，⛔ 本域不重复定材质口径 |
| `mobile` 域 移动端 | 移动端同屏外观数量与内存预算见 `mobile`，⛔ 本域不另定移动端口径 |
| `character-customization` | ⓘ howto 层，暂无 flow 域 —— 捏脸/换网格/染色技术见该篇 |
| `companion` 域 伴侣物 | 坐骑移动驱动权转移与 reparent 时序见 `companion/03`，外观资产与驱动分离，⛔ 本域不定义坐骑驱动 |
| `art-assets` | ⓘ howto 层，暂无 flow 域 —— 美术资源命名与规格见该篇 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `LOAD_TIMEOUT_SECONDS` 加载超时 | 04 | 8.0 | — | 待实测（与目标机型相关） |
| `UGC_TOKEN_TTL_SECONDS` UGC 令牌有效期 | 06 | 3600 | — | 待实测（按合规要求与运营成本确认） |
| `LOAD_BUDGET_MS` 单帧加载预算 | 04 | — | — | 待实测（与平台和目标机型相关） |
| `MAX_VISIBLE_COSTUMES` 同屏外观预算 | 04 | — | — | 待实测（与同屏人数和内存相关） |
| 表情冷却 / 距离 / 场景过滤阈值 | 05 | — | — | 待实测（须有举报与服务端中断能力） |
| 全量校正周期 / 摘要频率 | 05 | — | — | 待实测（与同屏人数和带宽相关） |
| 限时时装宽限期 | 02 | — | — | 待实测（⛔ 退款口径不由外观系统决定） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发回退"或"偶发不一致"，
⛔ 而这类偶发在测试环境几乎不出现。
