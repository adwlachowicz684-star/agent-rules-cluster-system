# 03 换装染色与实例隔离（外观域）

> **本步交付**：三入口替换 + 实例材质口径 + 显示/属性隔离
> **对应**：流程 `howto/godot/cosmetic.md` · 审核 `audit/godot/cosmetic.md`

## 0. 交付物定义

1. `mesh` / `skeleton` / `skin` 三个入口已明确，换装是组合替换
2. 换网格前校验**骨骼层级与 Bone Rest**（不只是骨骼名），且失败在导入期
3. 染色建立在实例材质上，⛔ 不写共享材质与共享纹理
4. 显示链与属性链各自取数，外观挂点不提供数值
5. 外观资产目录经 CI 扫描，不含碰撞/移速/伤害/判定字段

## 1. 前置检查清单

- [ ] 三个入口都替换了，⛔ 不是只换网格
- [ ] 骨骼指纹校验在 CI/导入期，⛔ 不是运行时看着不对再查
- [ ] 染色用实例材质，共享材质未被写入
- [ ] 战斗/移动不读外观实例上的数值字段
- [ ] CI 能扫出外观目录里的数值字段

## 2. 工序

### Step 1　换装是三个入口的组合替换　`[cosmetic/03#S1]`

【读】`howto/godot/cosmetic.md#1. 换装与染色：技术实现见专门文档`

【做】
明确 `mesh` / `skeleton` / `skin` 是三个独立入口，换装要按需求组合替换。
⛔ 当成"替换一个预制体" —— 只换网格不换 skin，
表现为"模型换了但动画还是旧的姿势"，而检查时网格确实换成功了。

【产出】三类换装各自要动哪几个入口的对照表

【判据】指着一次换装，能说出它动了哪几个入口、为什么。

【审】`audit/godot/cosmetic.md#8`

### Step 2　骨骼指纹校验在导入期，⛔ 不靠运行时发现　`[cosmetic/03#S2]`

【读】`howto/godot/cosmetic.md#1. 换装与染色：技术实现见专门文档`

【做】
在 CI 或资产管线里比对骨骼名集合 / 层级 / Bone Rest，不符即失败。
⛔ 指望 `SkeletonProfile` 拦住 —— 官方口径是**它只是提示，不阻止导入**，
表现为"编辑器里没红字，运行时换上去手臂扭曲"。

ⓘ 判据必须是"导入期失败"：
导入期失败只有美术一个人受影响，运行时失败是全体玩家受影响。

【产出】骨骼指纹校验脚本 + 失败即中断的 CI 配置

【判据】故意导入一套不匹配网格，CI 失败，⛔ 不是运行时才发现。

【审】`audit/godot/cosmetic.md#9`、`audit/godot/cosmetic.md#10`

### Step 3　染色建立在实例材质上，两边都要对　`[cosmetic/03#S3]`

【读】`howto/godot/cosmetic.md#1. 换装与染色：技术实现见专门文档`

【做】
染色前先取得实例材质，且要同时确认**加载侧**没有复用缓存实例。
⛔ 只做了一半 —— 材质是实例材质，但 `ResourceLoader` 默认 `CACHE_MODE_REUSE`
让同一路径返回**同一个资源实例**，染色照样污染所有同材质对象。

⛔ 表现为"一个人染色，全场同款都变色"，
而检查材质时它确实是 `duplicate()` 出来的（**看着完全对**）。

【产出】实例材质获取入口 + 加载侧 `CACHE_MODE_IGNORE` 的取值说明

【判据】两个玩家同款时装染不同色，各自保持各自的颜色。

【审】`audit/godot/cosmetic.md#12`、`audit/godot/cosmetic.md#13`、`audit/godot/cosmetic.md#40`

### Step 4　显示链与属性链各自取数，外观不提供数值　`[cosmetic/03#S4]`

【读】`howto/godot/cosmetic.md#2. ⚠ 第一道隔离：显示用 A，属性用 B`

【做】
让渲染/动画/UI 走显示链，战斗/移动/碰撞/经济走属性链，两者不互相读取。
⛔ 外观挂点"顺便"提供碰撞或移速 ——
换一件时装等于改一次战斗数值，⛔ **功能测试完全测不出来**
（测试只验证"穿上后能跑能打"）。

ⓘ 落地判据是可自动化的：
战斗与移动代码**不得**读取外观实例上的任何数值字段，写进 CI。

【产出】两条取数链的说明 + CI 禁止规则

【判据】把外观实例整个清空，战斗与移动行为不变。

【审】`audit/godot/cosmetic.md#18`、`audit/godot/cosmetic.md#6`

### Step 5　坐骑皮肤只接触渲染层与附件层　`[cosmetic/03#S5]`

【读】`howto/godot/cosmetic.md#5. 坐骑皮肤：只改外观，⛔ 不能改碰撞与移速`

【做】
用能力模板驱动坐骑，⛔ 丢弃皮肤自带的移动/碰撞参数。
⛔ 一旦外观带来移速、碰撞、命中范围或隐藏判定优势，
就**不再是无属性付费**，商业化审批与玩家信任同时失效。

ⓘ CI 扫描项：是否存在 `collision_shape`、根运动、修改 `scale`、动画事件触发战斗结果。

【产出】能力模板 + 皮肤参数丢弃规则 + CI 扫描项

【判据】换任意坐骑皮肤，移速与碰撞完全一致。

【审】`audit/godot/cosmetic.md#17`

### Step 6　外观资产目录经 CI 扫描，不含数值字段　`[cosmetic/03#S6]`

【读】`howto/godot/cosmetic.md#5. 坐骑皮肤：只改外观，⛔ 不能改碰撞与移速`

【做】
把"外观目录不得含移动/碰撞/伤害/判定字段"做成自动检查。
⛔ 只在购买协议写"本商品不影响平衡" —— 每次热更新增资产都可能带入新字段，
⛔ 表现为"某个版本之后某件时装跑得更快"，而协议里明明写了不影响平衡。

【产出】CI 扫描脚本 + 发布门禁

【判据】故意在外观资源里加一个速度字段，CI 失败。

【审】`audit/godot/cosmetic.md#27`、`audit/godot/cosmetic.md#18`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：实例材质 + 加载侧独立实例
# ⛔ 两边都要对：材质是实例的，加载也必须是独立的
func dye(target: MeshInstance3D, color: Color) -> void:
    var mat := target.get_surface_override_material(0)
    if mat == null or mat.resource_local_to_scene == false:
        mat = mat.duplicate() as Material
        mat.resource_local_to_scene = true
        target.set_surface_override_material(0, mat)
    mat.set_shader_parameter("dye_color", color)

# ⓘ 加载侧：CACHE_MODE_IGNORE 才是真独立，默认 REUSE 会复用同一实例
var res := ResourceLoader.load(
    path, "", ResourceLoader.CACHE_MODE_IGNORE
)
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 模型换了但姿势是旧的 | 只换 mesh 未换 skin | S1 |
| 运行时手臂扭曲 | 只校验骨骼名，未校验层级/Bone Rest | S2 |
| 一个人染色全场变色 | 材质是实例但加载复用了缓存实例 | S3 |
| 换装后数值变了 | 外观挂点提供数值 | S4 |
| 某件坐骑跑得更快 | 皮肤自带移速未被丢弃 | S5 |
| 热更后某时装跑得快 | 新增资产未扫描 | S6 |
