# 04 异步加载与回退（外观域）

> **本步交付**：默认外观零依赖 + 令牌 + 一次性取走口径 + 占位口径
> **对应**：流程 `howto/godot/cosmetic.md` · 审核 `audit/godot/cosmetic.md`

## 0. 交付物定义

1. 默认外观**零外部依赖**，回退路径自身不依赖网络
2. 加载有超时、令牌与丢弃路径（⛔ 官方无 cancel API）
3. 同一路径**只取一次**并广播给所有等待者
4. 轮询只用 `load_threaded_get_status()`，⛔ 不在循环里调 `load_threaded_get()`
5. 导出设置已确认，运行时加载 PCK 内文件可用
6. 占位资源是自制低模，⛔ 不是引擎默认资源

## 1. 前置检查清单

- [ ] 默认外观不依赖任何网络资源
- [ ] 加载有超时与令牌，切换时旧结果被丢弃
- [ ] 同一 path 只 `load_threaded_get()` 一次
- [ ] 轮询用 status，不在循环里阻塞
- [ ] `convert_text_resources_to_binary` 已按运行时加载需求设置
- [ ] 资产缓存自己持有强引用

## 2. 工序

### Step 1　默认外观零外部依赖：这是成立条件，不是优化　`[cosmetic/04#S1]`

【读】`howto/godot/cosmetic.md#6. 加载：必须保留默认外观、超时、令牌、取消`

【做】
默认外观使用基础网格与内置材质，并有程序化占位兜底。
⛔ 默认外观也走远端加载 —— 回退路径自身依赖网络时，
断网场景下**连默认外观都出不来**，表现为"网络差时角色整个消失"。

⚠ **占位资源必须是自制的低模**，⛔ 不能是引擎默认资源（Godot 图标、灰色方块、"null" 文字）。
兜底路径是"资源没了"时才走的，⛔ 但它恰恰是玩家**最容易看到**的那一屏：
⛔ 只要漏了一两个占位图标，整体印象就会被拉到"半成品"——
这一项的破坏力远超它的工作量。

【品】`craft/godot/cheapness.md#3. 视觉类廉价感`

【产出】默认外观资源清单（含零依赖证明）+ 程序化占位实现

【判据】断网启动，全部角色显示默认外观，⛔ 无空洞无消失。

【审】`audit/godot/cosmetic.md#19`、`audit/godot/cosmetic.md#20`

### Step 2　同一路径只取一次，取走即移除　`[cosmetic/04#S2]`

【读】`howto/godot/cosmetic.md#6.1 ⚠ 官方线程加载的四个坑（与"多玩家等同一件时装"直接冲突）`

【做】
对同一 path 只调一次 `load_threaded_get()`，取到后自己缓存并广播给所有等待者。
⛔ 每个等待者各查各的 —— 官方语义是**取走即把任务从列表移除**，
第一个人取走后其余人查到 `THREAD_LOAD_INVALID_RESOURCE`，
表现为"第一个人穿上正常、后面的人全回退默认"。

⛔ 这条最难查：日志写的是**"资源无效"**，
排查必然被引向资源路径或导出设置，不会想到是**同一次加载被取了两次**。

【产出】单一取走点 + 广播给等待者的实现 + 自有的 asset_cache

【判据】五个玩家同时等同一件时装，五个人都穿上，无一回退默认。

【审】`audit/godot/cosmetic.md#34`

### Step 3　轮询用 status，⛔ 不在循环里调 get　`[cosmetic/04#S3]`

【读】`howto/godot/cosmetic.md#6.1 ⚠ 官方线程加载的四个坑（与"多玩家等同一件时装"直接冲突）`

【做】
在 `_process` 里逐帧轮询 `load_threaded_get_status()`。
⛔ 未完成时调 `load_threaded_get()` 会**阻塞调用线程**，
在主线程调用可能死锁，表现为"大厅偶发整体卡死"，且不报任何错误。

ⓘ `use_sub_threads = true` 更快但**会影响主线程造成卡顿** ——
同屏大量外观时，默认的单线程模式（false）反而是对的。

【产出】逐帧轮询实现（⛔ 无阻塞调用）

【判据】加载 20 件时装期间主线程无卡顿、无死锁。

【审】`audit/godot/cosmetic.md#35`、`audit/godot/cosmetic.md#39`

### Step 4　"取消"是丢弃结果，不是中止线程　`[cosmetic/04#S4]`

【读】`howto/godot/cosmetic.md#6. 加载：必须保留默认外观、超时、令牌、取消`

【做】
用请求令牌或 `slot_version` 校验，从 A 切到 B 时丢弃 A 的结果。
⛔ 去找 `cancel()` —— **ResourceLoader 没有取消 API**，
表现为"切来切去最后显示的是最先点的那件"，而等待逻辑看着完全正确。

ⓘ 超时同理：超时不是中止加载，是**不再等待结果**并回退默认。

【产出】令牌/`slot_version` 校验 + 超时回退路径

【判据】连续快速切换 5 件，最终显示的一定是最后点的那件。

【审】`audit/godot/cosmetic.md#22`、`audit/godot/cosmetic.md#36`、`audit/godot/cosmetic.md#42`

### Step 5　资产缓存自己持有强引用　`[cosmetic/04#S5]`

【读】`howto/godot/cosmetic.md#6.1 ⚠ 官方线程加载的四个坑（与"多玩家等同一件时装"直接冲突）`

【做】
自己持有已加载资源的引用，并区分"展示引用"与"缓存持有"。
⛔ 依赖引擎缓存 —— 官方语义是**弱引用**，没人持有就会被释放，
表现为"外观偶尔失效又重新加载"，且重载后是新实例，**已染色的实例参数丢失**。

ⓘ 卸载同理：不能只看离开视锥，角色可能很快重新进入。

【产出】缓存持有策略（强引用 + 引用计数 + 降级而非立即卸载）

【判据】角色反复进出视锥 20 次，染色参数不丢失。

【审】`audit/godot/cosmetic.md#37`、`audit/godot/cosmetic.md#23`

### Step 6　导出设置：确认运行时能读到 PCK 内文件　`[cosmetic/04#S6]`

【读】`howto/godot/cosmetic.md#6.2 ⛔ 导出后运行时加载：默认的二进制转换会让它整体失效`

【做】
确认 `editor/export/convert_text_resources_to_binary` 的设置与运行时加载需求一致。
⛔ 保持默认 `true` 又依赖运行时加载 —— 官方明确
`load()` 在导出项目里读不到被转换的文件，且 PCK 内部分路径会变
（`project.godot` → `project.binary`）。

⛔ 表现为"编辑器里一切正常、导出后外观全部回退默认"，
且**不报"路径不存在"** —— 因为文件确实在包里，只是读不出来。

【产出】导出配置检查项（发布前必查）

【判据】导出包运行时能加载外观资产，⛔ 不只是编辑器里能。

【审】`audit/godot/cosmetic.md#38`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：单一取走点 + 逐帧轮询 + 令牌丢弃
extends Node

const LOAD_TIMEOUT_SECONDS := 8.0      # ⓘ 待实测：与目标机型相关

var _cache := {}                       # ⓘ 强持有，⛔ 不依赖引擎弱引用缓存
var _pending := {}                     # path -> {status 轮询用}
var _slot_version := {}                # slot -> int，用于丢弃旧结果

func request(slot: StringName, path: String) -> void:
    _slot_version[slot] = _slot_version.get(slot, 0) + 1
    if _cache.has(path):
        _apply(slot, _cache[path]); return
    if _pending.has(path):
        _pending[path].waiters.append(slot); return
    ResourceLoader.load_threaded_request(path)
    _pending[path] = {"waiters": [slot], "elapsed": 0.0}

func _process(delta: float) -> void:
    for path in _pending.keys():
        var p := _pending[path]
        p.elapsed += delta
        var progress := []
        var st := ResourceLoader.load_threaded_get_status(path, progress)
        # ⛔ 只在 LOADED 时取，且只取一次（取走即移除）
        if st == ResourceLoader.THREAD_LOAD_LOADED:
            var res := ResourceLoader.load_threaded_get(path)
            _cache[path] = res
            for s in p.waiters: _apply(s, res)
            _pending.erase(path)
        elif st == ResourceLoader.THREAD_LOAD_FAILED or p.elapsed > LOAD_TIMEOUT_SECONDS:
            for s in p.waiters: apply_default(s)
            _pending.erase(path)
```
