# 02 槽位仲裁与有效期状态机（外观域）

> **本步交付**：仲裁字段 + 三态过期 + 到期释放流程
> **对应**：流程 `howto/godot/cosmetic.md` · 审核 `audit/godot/cosmetic.md`

## 0. 交付物定义

1. 槽位冲突按固定字段仲裁，⛔ 不是按点击顺序覆盖
2. 过期分 `unexpired` / `grace_period` / `expired` 三态
3. **到期先释放槽位再设为默认**，⛔ 不留空
4. 账号级与角色级外观共存时，角色 A 的选择不覆盖角色 B
5. 外观实例与装备实例分离存储

## 1. 前置检查清单

- [ ] 仲裁字段是 `(scope_rank, source_rank, obtain_time, instance_id)`
- [ ] 三态过期已实现，宽限期有明确处置
- [ ] 到期流程是"先释放再设默认"，不是留空
- [ ] 账号共享只影响授权范围，不影响角色各自选择
- [ ] 外观与装备是两套实例

## 2. 工序

### Step 1　槽位冲突按固定字段仲裁　`[cosmetic/02#S1]`

【读】`howto/godot/cosmetic.md#槽位冲突按优先级仲裁，不是按点击顺序覆盖`

【做】
把比较字段固定为 `(scope_rank, source_rank, obtain_time, instance_id)`。
⛔ 按点击顺序覆盖 —— 表现为"先穿 A 再穿 B，重登后变成 A"，
完全随机、不可复现，排查必然被引向存档。

⛔ 只比较付费与否也不行：基础外观可能来自新手任务，也可能是限时回归活动，
**价格无法稳定排序**。

【产出】仲裁比较函数 + 四个字段的取值表

【判据】任意顺序穿脱 5 件，重登后生效外观恒定。

【审】`audit/godot/cosmetic.md#3`、`audit/godot/cosmetic.md#4`

### Step 2　过期分三态，宽限期有明确处置　`[cosmetic/02#S2]`

【读】`howto/godot/cosmetic.md#过期要分三种状态`

【做】
实现 `unexpired` / `grace_period` / `expired` 三态，并为 `grace_period` 定义清楚：
显示什么提示、是否仍可穿、结束后走哪条分支。
⛔ 只做"有效 / 失效"两态 —— 宽限期内的外观会在到期瞬间**硬切**，
表现为"穿着穿着突然变光身子"，而日志里没有任何异常。

【产出】三态定义 + 宽限期的显示与可用性规则

【判据】宽限期内外观仍可用且有提示；结束后走预定义分支，无硬切。

【审】`audit/godot/cosmetic.md#28`、`audit/godot/cosmetic.md#5`

### Step 3　到期先释放槽位再设为默认，⛔ 不留空　`[cosmetic/02#S3]`

【读】`howto/godot/cosmetic.md#过期要分三种状态`

【做】
到期时服务端**先**把槽位从限时外观释放，**再**把 `ActiveAppearance` 设为默认/永久外观。
⛔ 把槽位留空 —— 表现为"到期后角色没有该部位"，
而"没有"和"默认"在渲染上是两件事，前者可能露出模型空洞。

【产出】到期处置流程（释放 → 设默认 → 广播）

【判据】到期后角色显示默认外观，⛔ 不是"少一个部件"。

【审】`audit/godot/cosmetic.md#5`

### Step 4　账号级与角色级共存：共享是授权范围，不是覆盖　`[cosmetic/02#S4]`

【读】`howto/godot/cosmetic.md#1. 换装与染色：技术实现见专门文档`

【做】
跨角色共享的时装按**角色**保存最后选择。
⛔ 账号共享只表示"这个账号下的角色都有权穿"，
不应让角色 A 的选择直接覆盖角色 B。
表现为"换个角色，另一个角色的时装也变了"，而玩家会当成 bug 反复重设。

【产出】账号级授权范围与角色级选择的存储划分

【判据】切换角色后各自显示各自的选择，互不干扰。

【审】`audit/godot/cosmetic.md#32`

### Step 5　外观实例与装备实例分离存储　`[cosmetic/02#S5]`

【读】`howto/godot/cosmetic.md#2. ⚠ 第一道隔离：显示用 A，属性用 B`

【做】
外观实例与装备实例用两套存储。
⛔ 共用一个实例 —— **最高优先级错误**：
装备交易 / 分解 / 回滚会让时装一起消失，
表现为"卖了一件装备，时装没了"，而玩家会认为时装被吞。

【产出】两套实例的存储划分 + 装备操作不影响外观的说明

【判据】交易、分解、回滚装备后，外观实例完整无变化。

【审】`audit/godot/cosmetic.md#6`、`audit/godot/cosmetic.md#18`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：仲裁 + 三态 + 先释放再设默认
enum ExpireState { UNEXPIRED, GRACE_PERIOD, EXPIRED }

static func cmp_active(a: AppearanceInstance, b: AppearanceInstance) -> bool:
    # ⛔ 固定四字段，⛔ 不是按点击顺序
    if a.scope_rank != b.scope_rank: return a.scope_rank > b.scope_rank
    if a.source_rank != b.source_rank: return a.source_rank > b.source_rank
    if a.obtain_time != b.obtain_time: return a.obtain_time > b.obtain_time
    return a.instance_id > b.instance_id

func on_expire(slot: StringName) -> void:
    release_slot(slot)                  # ⛔ 先释放
    set_active(slot, default_of(slot))  # ⛔ 再设默认，不是留空
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 重登后外观顺序随机变化 | 按点击顺序覆盖 | S1 |
| 穿着突然变光身子 | 只有两态，宽限期硬切 | S2 |
| 到期后角色少一个部件 | 槽位留空 | S3 |
| 换角色另一角色的时装也变 | 账号级覆盖角色级 | S4 |
| 卖装备后时装消失 | 外观与装备共用实例 | S5 |
