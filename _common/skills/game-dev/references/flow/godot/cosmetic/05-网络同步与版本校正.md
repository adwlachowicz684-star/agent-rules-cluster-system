# 05 网络同步与版本校正（外观域）

> **本步交付**：manifest + 增量 + 全量校正时机表 + 版本单调
> **对应**：流程 `howto/godot/cosmetic.md` · 审核 `audit/godot/cosmetic.md`

## 0. 交付物定义

1. 同步内容是 **ID / 版本 / 校验摘要**，⛔ 不是资源对象
2. 进场景发全量 manifest，变更走增量 + 版本
3. `appearance_version` 单调递增，有缺口即请求全量
4. 全量校正时机表已写下并重放校验（⛔ 不只进场景一次）
5. 表情动作有冷却/距离/场景过滤，服务端可中断
6. 服务端可发轻量摘要包

## 1. 前置检查清单

- [ ] 同步字段里没有资源对象、实例 ID、RID
- [ ] `appearance_version` 单调递增
- [ ] 全量时机覆盖：重新可见、客户端请求、定期、优先级/有效期变化、delta 缺口、查看名片
- [ ] 表情有冷却与举报，服务端能中断
- [ ] 摘要包可只对不一致槽位请求

## 2. 工序

### Step 1　只同步 ID / 版本 / 摘要，⛔ 不同步资源对象　`[cosmetic/05#S1]`

【读】`howto/godot/cosmetic.md#7. 网络：进场景全量 + 变更增量 + 周期全量校正`

【做】
把同步内容限定为小体积的 ID、版本、校验摘要，真实资产由客户端查找或异步加载。
⛔ 用 `MultiplayerSynchronizer` 同步 Resource ——
官方明确 **Object 类型属性不支持同步**，
且每端不同的实例 ID、RID 也⛔ 不能直接复制。

⛔ 表现为"外观同步时好时坏"：
体积小的对象偶尔成功，⛔ 于是看起来像网络抖动，不会想到是类型不支持。

【产出】同步字段表（⛔ 无资源对象字段）

【判据】同步包里没有任何 Resource / RID / 实例 ID 字段。

【审】`audit/godot/cosmetic.md#24`

### Step 2　进场景全量 manifest，变更走增量 + 版本　`[cosmetic/05#S2]`

【读】`howto/godot/cosmetic.md#7. 网络：进场景全量 + 变更增量 + 周期全量校正`

【做】
首次可见发全量 manifest（槽位、称号、头像框、表情 + 签名），后续变更走增量。
增量必须带版本，失败时返回当前权威状态。
⛔ 只有增量 —— **外观没有天然的周期性重写**，
一次"卸下帽子"的丢包会让该端永久不一致，且**不会自愈**。

【产出】全量 manifest 结构 + 增量结构（含版本与失败回退）

【判据】断网重连后外观与服务端一致，⛔ 不依赖"下次变更才修正"。

【审】`audit/godot/cosmetic.md#25`、`audit/godot/cosmetic.md#26`

### Step 3　`appearance_version` 单调递增，有缺口即请求全量　`[cosmetic/05#S3]`

【读】`howto/godot/cosmetic.md#7. 网络：进场景全量 + 变更增量 + 周期全量校正`

【做】
让版本号单调递增，客户端收到增量后比对：只有不存在历史缺口时才应用，否则请求全量。
⛔ 只比"新旧"不比"连续" —— 跳号的增量会被当成新版本直接应用，
表现为"少了一件时装但界面显示已装备"，而版本号确实更大。

【产出】版本校验逻辑（缺口检测 → 请求全量）

【判据】人为丢弃一个增量后，客户端检测到缺口并请求全量。

【审】`audit/godot/cosmetic.md#25`

### Step 4　全量校正时机表写下来，⛔ 不只进场景一次　`[cosmetic/05#S4]`

【读】`howto/godot/cosmetic.md#7. 网络：进场景全量 + 变更增量 + 周期全量校正`

【做】
写下全部全量时机：新端加入、对象重新可见、客户端请求、定期周期、
优先级/有效期变化、连续多个 delta 缺失、玩家打开名片查看角色。
⛔ 只在进场景发一次 —— 玩家重进视野、时装修改优先级、
限时时装到期都会造成永久不一致，而这些在单次测试中**完全不出现**。

【产出】全量时机表 + 每个时机的触发条件

【判据】逐个触发七个时机，每次客户端都与服务端一致。

【审】`audit/godot/cosmetic.md#26`

### Step 5　表情动作：冷却、距离、场景过滤，服务端可中断　`[cosmetic/05#S5]`

【读】`howto/godot/cosmetic.md#4. 表情动作：动画 + 网络同步，是骚扰与外挂高发点`

【做】
为表情加冷却、距离限制、场景过滤与举报入口，服务端可**停止广播并中断动作**。
⛔ 只在客户端做限制 —— 卡动作、循环播放刷屏是骚扰高发点，
⛔ 而客户端限制对改包无效，表现为"有人一直在你面前循环做动作"。

ⓘ 同步用**事件 + 截止时间**，让客户端按时间自然结束并支持中断，
⛔ 不是靠"播放完再发一次结束包"（丢包就永远不结束）。

【产出】表情的冷却/距离/场景规则 + 服务端中断接口 + 举报日志

【判据】服务端中断后所有端立即停止，⛔ 不等动画播完。

【审】`audit/godot/cosmetic.md#16`

### Step 6　服务端摘要包：只对不一致槽位请求　`[cosmetic/05#S6]`

【读】`howto/godot/cosmetic.md#7. 网络：进场景全量 + 变更增量 + 周期全量校正`

【做】
服务端发轻量摘要（每槽位 `instance_id + asset_version + checksum`），
只有摘要不一致时客户端才请求对应槽位。
⛔ 每次都全量 —— 大厅同屏几十人时带宽与加载同时爆掉，
而这在人少的测试服上完全测不出来。

【产出】摘要包结构 + 不一致才请求的流程

【判据】同屏 30 人时带宽与加载量在预算内（⛔ 数值待实测）。

【审】`audit/godot/cosmetic.md#25`、`audit/godot/cosmetic.md#42`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：只同步 ID/版本/摘要 + 版本缺口检测
func apply_delta(delta: Dictionary) -> void:
    var v: int = delta.get("version", 0)
    # ⛔ 有缺口即请求全量，⛔ 不是"版本号更大就直接应用"
    if v != _last_version + 1:
        request_full_manifest(); return
    _last_version = v
    apply_slot(delta.slot, delta.instance_id, delta.asset_version, delta.checksum)
```

## 4. 验收清单

- [ ] 同步包无资源对象 / RID / 实例 ID
- [ ] 断网重连后与服务端一致
- [ ] 人为丢包后检测到缺口并请求全量
- [ ] 七个全量时机逐个触发均一致
- [ ] 服务端中断表情后各端立即停止
- [ ] 同屏 30 人时带宽在预算内

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 外观同步时好时坏 | 同步了 Resource | S1 |
| 少一件但界面显示已装备 | 只比新旧不比连续 | S3 |
| 重进视野后外观错乱 | 全量只在进场景发 | S2, S4 |
| 有人循环做动作停不下来 | 只在客户端限制 | S5 |
| 大厅人多时卡爆 | 每次全量无摘要 | S6 |
