# 04 密集音效与池（音频域）

> **前置**：02 播放已通，03 音量已可配
> **本步交付**：高频音效不丢音、不爆音、不重复单调，且首播不卡顿
> **对应**：做法 `howto/godot/audio-advanced.md` `input-audio.md` · 审核 `audit/godot/audio-advanced.md`

## 0. 交付物定义

⚠ **同一个 `AudioStreamPlayer` 反复 `play()` 会打断自己**，
密集触发时听感是"卡住"。这是本功能点存在的全部理由。

做完这一步，应该能**当场演示**：

1. 连点 20 次**不丢音**（⛔ 不是只有最后一次响）
2. ⚠ 用池轮转或多声部，⛔ 不是反复 play 同一个播放器
3. 音高随机化在 **±15% 以内**（超过听得出变调）
4. ⚠ 首次播放**不卡顿**（已预注册样本）
5. 多声部满时能**察觉**（`INVALID_ID`）而不是静默丢失

**产出物**（下游按名字对接）：

```text
SfxPool（池化播放器 + 随机音高）
或 AudioStreamPolyphonic（多声部）
预注册列表（加载阶段批量 register_stream_as_sample）
```

## 2. 工序

### Step 1　⛔ 反复 play 会打断自己　`[audio/04#S1]`

【读】`howto/godot/audio-advanced.md#3. 音效池`

【做】⚠ **同一个 `AudioStreamPlayer` 反复 `play()` 会打断自己**，
密集触发时听感是"卡住"。

⛔ 症状是"连点只有最后一次响"或"声音一顿一顿"——
很多人以为是性能问题，其实是播放器被自己打断。

【产出】高频音效不再用同一个播放器反复 play

【判据】⚠ 连点 20 次，**20 次都响**

【审】`audit/godot/audio-advanced.md#4`（反复 play() 能叠加 → 会打断自己）

### Step 2　用池轮转　`[audio/04#S2]`

【读】`howto/godot/audio-advanced.md#3. 音效池`

【做】
```gdscript
func play(stream: AudioStream) -> void:
    var p := _players[_next]
    _next = (_next + 1) % _players.size()
    p.stream = stream
    p.pitch_scale = base_pitch * randf_range(
        1.0 - pitch_variance, 1.0 + pitch_variance)
    p.play()
```

⚠ 池大小要**实测**：太小会打断（回到 S1 的问题），太大会浪费。
ⓘ 经验起点 8，但密集战斗场景可能要 16–32。

⚠ 建池时就把 `bus` 设好，⛔ 不是每次 play 时设。

【产出】池大小已实测并回填

【判据】⚠ 按最快触发频率连点，**不丢音**

【审】`audit/godot/audio-advanced.md#4`

### Step 3　音高随机化幅度　`[audio/04#S3]`

【读】`howto/godot/audio-advanced.md#3. 音效池` 的 ⚠

【做】⚠ **音高随机化幅度别太大（±15% 以内）**，否则听出变调。

ⓘ 目的是"避免重复感"，不是"让每个音都不一样"。
超过 ±15% 玩家会察觉"这个音效走音了"。

【产出】`pitch_variance <= 0.15`

【判据】⚠ 连听 20 次，**不觉得走音**，但也不觉得完全一样

【审】`audit/godot/audio-advanced.md#11`（音高随机化越大越好 → 超过 ±15% 听得出变调）
【品】`craft/godot/cheapness.md#2. 反馈类廉价感`

### Step 4　⚠ 预注册样本防首播卡顿　`[audio/04#S4]`

【读】`howto/godot/audio-advanced.md#8. 预注册样本与延迟尖峰`

【做】⚠ **首次播放一个 `AudioStream` 时引擎要先注册它，这会造成 lag spike。**

`AudioServer.register_stream_as_sample(stream)` 强制预注册。

⚠ **官方明确建议**在**加载阶段**调用（让 lag spike 被遮掩），
⛔ 不要在开火前一刻注册——否则第一次开枪卡顿，之后就不卡了，**极难排查**。

```gdscript
for stream in _combat_sfx:
    if not AudioServer.is_stream_registered_as_sample(stream):
        AudioServer.register_stream_as_sample(stream)
```

【产出】密集音效在加载阶段已预注册

【判据】⚠ 第一次开枪**不卡**（与第 100 次一样）

【审】`audit/godot/audio-advanced.md#15`

### Step 5　多声部方案与 INVALID_ID　`[audio/04#S5]`

【读】`howto/godot/input-audio.md#2. 音频` 的「音效：用池，不要每次 new」

【做】⚠ **属性名是 `polyphony`，不是 `max_polyphony`** ——
`AudioStreamPolyphonic` 只有 `polyphony`（默认 **32**，范围 **1–128**）。

```gdscript
var id := playback.play_stream(stream)
if id == AudioStreamPlaybackPolyphonic.INVALID_ID:
    push_warning("声部已满，本次被丢弃")
```

⚠ **`play_stream()` 在"正在播放的流数 == `polyphony`"时返回 `INVALID_ID`（-1）**。
⛔ **不是裁掉最旧的声音，而是本次新的被丢弃**——表现为"连点时丢音"。

⚠ `get_stream_playback()` 必须在 `play()` 之后调用，否则拿到 null。

【产出】多声部方案已用对，且**判了 INVALID_ID**

【判据】⚠ 故意把 `polyphony` 设为 2 然后连点 10 次，**能看到丢弃警告**

【审】`audit/godot/audio-advanced.md#16`

### Step 6　并发上限与优先级　`[audio/04#S6]`

【读】`howto/godot/audio-advanced.md#3. 音效池`

【做】ⓘ 池和多声部都解决"能同时响"，但不解决"该不该响"。

⚠ 大场面（20 个敌人同时攻击）全部发声 = 糊成噪音 + 爆音。
✅ 要有**并发上限 + 优先级**：重要音效（玩家受击、Boss 技能）优先，
次要的（远处脚步）超限就丢弃。

ⓘ 另一个常用手段：**同类音效合并**（同一帧内 5 个相同脚步只播一次，音量略增）。

【产出】有并发上限与优先级策略

【判据】⚠ 20 个敌人同时攻击，**不糊、不爆、且关键音可辨**

【审】`audit/godot/audio-advanced.md#17`

## 3. 参考实现

```gdscript
class_name SfxPool
extends Node

@export var pool_size := 8              # ⚠ 实测调整
@export var base_pitch := 1.0
@export var pitch_variance := 0.15      # ⚠ 不超过 0.15

var _players: Array[AudioStreamPlayer] = []
var _next := 0

func _ready() -> void:
    for i in pool_size:
        var p := AudioStreamPlayer.new()
        p.bus = &"SFX"                  # ⚠ 建池时设一次
        add_child(p)
        _players.append(p)

func play(stream: AudioStream) -> void:
    var p := _players[_next]
    _next = (_next + 1) % _players.size()   # ⚠ 轮转，不是反复 play 同一个
    p.stream = stream
    p.pitch_scale = base_pitch * randf_range(
        1.0 - pitch_variance, 1.0 + pitch_variance)
    p.play()

static func preregister(streams: Array) -> void:
    # ⚠ 加载阶段调用，别在开火前一刻
    for s in streams:
        if not AudioServer.is_stream_registered_as_sample(s):
            AudioServer.register_stream_as_sample(s)
```

⚠ 池的"轮转"本质是**用空间换时间**：
牺牲 pool_size 个常驻节点，换取任意时刻都能找到"空闲"的那个。
池满了仍会打断最老的——所以 S6 的并发上限是必要的补充。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 连点只有最后一声 | 反复 play 同一播放器 | S1 |

| 音效走音 | 音高幅度 >15% | S3 |
| 第一次开火卡顿 | 没预注册 | S4 |
| `max_polyphony` 报错 | 属性名写错 | S5 |
| 大场面糊成噪音 | 无并发上限/优先级 | S6 |
