## 0. 交付物定义

⚠ **各功能点自己的验收清单不能替代本步。**

⚠ **音频验收必须戴耳机**。外放听不出声像、听不出细节丢失、
也听不出"某个音其实没响"。

做完这一步，应该能**当场演示**：

1. 全部声音分类正确、走对总线
2. ⚠ 暂停/慢动作/切场景的行为符合设计
3. 密集场景不丢音、不爆音
4. 长时间运行**节点数不增长**
5. ⚠ 导出包实测有声音（⛔ 不是只在编辑器里响）

**产出物**：
```text
耳机实测记录

```

## 2. 工序

### Step 1　总线与分类总扫　`[audio/07#S1]`

【读】`howto/godot/audio-advanced.md#0. 总线是混音链，不是分组标签`

【做】逐条确认：

| 声音类别 | 总线 | 节点类型 | 效果 | 一致? |
|---|---|---|---|---|
| BGM | Music | AudioStreamPlayer | EQ | |
| 战斗音效 | SFX | 2D/3D | 混响 | |
| UI 反馈 | UI ⚠独立 | AudioStreamPlayer | 无 | |
| 语音 | Voice | AudioStreamPlayer | 压缩 | |

⚠ 重点复查：**UI 是不是真的独立**——
静音 Master 后 UI 音仍应有声。

【产出】表格每行有结论

【判据】⚠ 静音 Master 后，**UI 音仍可单独出声**

【审】`audit/godot/audio-advanced.md#3`

### Step 2　音量曲线实测　`[audio/07#S2]`

【读】`howto/godot/audio-advanced.md#1. 音量：dB 不是线性`

【做】⚠ 用**耳朵**过一遍整条滑块曲线，不是只看代码。

| 滑块 | 期望听感 |
|---|---|
| 0% | **完全无声** |
| 25% | 明显小但不是没有 |
| 50% | ⚠ **约一半**（⛔ 不是几乎听不见） |
| 100% | 原始音量 |

⛔ 若 50% 听起来几乎没声 → 没做 `linear_to_db` 转换（回到 03 S1）。
⛔ 若 0% 反而变最大 → 用了 0 dB 当静音（回到 03 S2）。

【产出】曲线听感记录

【判据】⚠ 50% 时**约一半**；0% 时**完全无声**

【审】`audit/godot/audio-advanced.md#1` `audit/godot/audio-advanced.md#2`

### Step 3　三种状态下的行为　`[audio/07#S3]`

【读】`howto/godot/audio-advanced.md#5. 暂停时的音频`

【做】逐状态实测：

| 状态 | 期望 | 实际 |
|---|---|---|
| 暂停菜单 | UI 音响应、BGM/战斗音停 | |
| 恢复 | ⚠ 音乐**不错位**（没用 bus_mute 当暂停） | |
| 切场景 | 同一首 BGM **不重开** | |
| 慢动作 | ⚠ 音频**跟着变慢**（`playback_speed_scale`） | |
| 慢动作结束 | 音频恢复正常速度 | |

【产出】表格每行有实测结果

【判据】⚠ 恢复后音乐**不错位**；慢动作音频**同步变慢**

【审】`audit/godot/audio-advanced.md#7` `audit/godot/audio-advanced.md#8`

### Step 4　压力测试　`[audio/07#S4]`

【读】`howto/godot/audio-advanced.md#3. 音效池`

【做】三种压力：

1. **连点** —— 同一音效连点 20 次，20 次都响
2. **大场面** —— 20 个音源同时发声，不糊不爆
3. ⚠ **长时间** —— 跑 10 分钟，场景树节点数**回到基准**

⚠ 第 3 项最容易被漏：前两项都是短时间的，
只有长时间跑才能发现"节点泄漏"。

【产出】三项压力测试记录

【判据】⚠ 10 分钟后节点数**不增长**；大场面**无削波爆音**

【审】`audit/godot/audio-advanced.md#17`（P0 释放条目）

### Step 5　导出包实测　`[audio/07#S5]`

【读】`howto/godot/audio-advanced.md#10. headless 与总线 API 细节`

【做】⚠ **必须测导出包**，⛔ 不是只在编辑器里响。

⚠ 特别注意 `--headless` 会**自动把音频驱动设为 Dummy**——
官方原话：`--headless also automatically sets the audio driver to Dummy`。
ⓘ 专用服务器上音频调用不会崩，但也不会有声，
⛔ 不要依赖"服务器没报错"来判断音频链路正常。

【产出】导出包实测记录

【判据】⚠ 真机跑导出包，**各类声音都在**

【审】`audit/godot/audio-advanced.md#22`

### Step 6　接缝复查　`[audio/07#S6]`

【读】`structure.md#5. 组合模型`

【做】列出本域与其他域的接缝，逐条确认：

| 接缝 | 上游产出 | 下游期望 | 一致? |
|---|---|---|---|
| 音频 → 战斗 | 打击音效 + 顿帧 | 打击感播放层 | |
| 音频 → UI | 反馈音 | 按钮/菜单播放 | |
| 音频 → 时间缩放 | `playback_speed_scale` | timescale 域要联动 | |
| 音频 → 剧情 | 语音 | narrative 播放 | |
| 音频 → 服务器 | 无音频 | `--headless` Dummy | |

⚠ **各域合格 ≠ 拼起来能用。**
接缝对不上要单独立适配步骤，⛔ 不要在各处偷偷转格式。

【产出】接缝清单，每行标注"一致"或"已适配"

【判据】⚠ 每行都有明确结论，⛔ 没有"应该没问题"

【审】`audit/godot/audio-advanced.md#26` 全部条目
