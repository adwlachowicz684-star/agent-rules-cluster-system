# AI（敌人）域 — 流程总览

> **本域交付**：一套"看得见、追得上、打得有章法、跑得动"的敌人 AI。
> **对应**：做法 `howto/godot/ai-perception.md` `ai-behavior.md` `ai-navigation.md` `ai-tactics.md` `stealth-ai.md`
> 　　　审核 `audit/godot/` 同名文件

## 0. 先定做什么（⛔ 没写这三行不许开工）

⚠ 同在 AI 域，"一个会追人的小怪"和"一套会包抄、会抢掩体、会轮流攻击的战术小队"
是**两条不同流程**——后者是前者的十倍工作量，且**多出来的部分全是跨个体逻辑**。

```text
做什么：<几种敌人、各自行为、要不要战术协同、要不要潜行>
不做什么：⛔ <至少两条>
验收标准：<可观测的>
```

示例（本次只做基础敌人）：

```text
做什么：近战小怪，Idle/Patrol/Chase/Attack/Return，单个行动
不做什么：⛔ 不做战术协同（本次只有散兵，无小队）
         ⛔ 不做潜行（玩家无隐匿手段）
验收标准：背对时发现不了、正对时发现；绕柱子不卡住；
         10 个同屏时帧率不掉；杀掉追击中的敌人后其令牌被回收
```

### 然后挑功能点

| 本次要做的 | 需要的功能点 |
|---|---|
| 只是"会追人、会打" | 01 → 02 → 03 → 07 |
| 有多个目标要选（玩家+宠物） | 01 → 02 → 03 → 04 → 07 |
| 有小队/群怪，要协同 | 01 → 02 → 03 → 04 → 05 → 07 |
| 同屏单位多（>20） | 01 → 02 → 03 → 06 → 07（06 提前做） |
| 要潜行玩法 | ⚠ 另见 `howto/godot/stealth-ai.md`，本流程只覆盖到感知接入 |
| 调参/排查 AI 行为 | 06 必做（⛔ 没有可视化等于猜谜） |

⛔ **不要全做。** 单个小怪不需要攻击令牌和阵型。

## 1. 功能点拆解与依赖顺序

```text
01 感知接入 ── 02 决策层选型 ── 03 Idle与状态转移 ──┬── 04 目标选择与仇恨 ──┐
                                                    ├── 05 阵型掩体与协同 ───┼── 07 验收
                                                    └── 06 性能预算与调试 ───┘
```

⚠ 06 在依赖图里排在后面，但**同屏单位多或需要调参时应提前做**——
没有调试可视化，04/05 的每一个参数都是盲调。

| # | 功能点 | 前置 | 为什么这个顺序 |
|---|---|---|---|
| 01 | 感知接入 | 无 | ⚠ 决策的输入全来自感知；感知错了一切都错 |
| 02 | 决策层选型与实现 | 01 | 先知道有什么信息可依据，再决定用什么结构 |
| 03 | Idle 与状态转移 | 01 02 | ⚠ Idle 是最容易被写成空状态的一个，单独一步 |
| 04 | 目标选择与仇恨 | 01 02 03 | 有多个候选才需要选；单目标项目可跳过 |
| 05 | 阵型 / 掩体 / 协同 | 01–04 | ⚠ 全是跨个体规则，个体跑通前做了没法验 |
| 06 | 性能预算与调试可视化 | 01–05 | ⚠ 调参的前提；需要调参时应提前 |
| 07 | AI 验收 | 01–06 | 含长时间稳定性与群体行为实测 |

## 2. ⚠ 六个最容易做反的顺序

**① 先写决策再接感知。**
决策层拿到的是"感知认为的世界"。感知没接好，BT/FSM 写得再漂亮也是**正确地执行错误信息**。

**② 一上来就上行为树。**
⚠ **BT 不是 FSM 的升级版，是维护对象不同。**
一个近战小怪通常只有 Idle / Patrol / Chase / Attack / Stagger / Dead，
用 `match state` 最清楚；拆成 BT 只会得到"条件链 + 顺序节点"的扁平树。

**③ 把战术规则写进单个敌人。**
"不要一拥而上""要包抄""轮流攻击"天生是**跨个体**的。
写在个体里就只能靠个体互相猜测，最后变成一堆互相矛盾的补丁。

**④ Idle 写成空状态。**
写空之后单位看起来是死的，且从 Idle 转出时没有过渡（"突然弹起来追人"）。
⚠ 更隐蔽的是：**感知写在 Chase 分支里**，导致 Idle 时根本没在检测，
表现为"背对玩家永远发现不了"——排查时会去调视野角度，其实与角度无关。

**⑤ 目标选择取"分最高的"。**
不加迟滞会在评分边界**反复切换目标**。
⛔ 只有阈值还不够，还要加**最短保持时间**。

**⑥ 同屏一堆敌人后才想性能。**
⚠ AI 是唯一会随单位数**平方级**变贵的系统：
20 个敌人 × 每帧检测 20 个目标 = 400 次。

## 3. 每做完一个功能点必做

1. 跑一遍该步的**验收清单**，逐条打勾
2. ⛔ 有没过的，不进下一步
3. 过该步【审】列的 audit 条目
4. 过功能点末尾的「整体审核」节
5. ⚠ 实测参数已回填，⛔ 不留示例值
6. ⚠ **本域额外一条**：打开调试可视化**亲眼看过**该步的行为（⛔ 不是"代码应该对"）
