## 0. 交付物定义

⚠ **本功能点全是"跨个体"规则。**
判据：**只留一个敌人时这条规则还成立吗？**
不成立 → 属于本步。⛔ 写在个体 AI 里，就只能靠个体互相猜测，
最后变成一堆互相矛盾的补丁。

做完这一步，应该能**当场演示**：

1. 一群敌人接近时**不挤成一团**
2. ⚠ 同时攻击的**不超过设定值**
3. ⚠ 杀掉持有令牌的敌人后，其余**仍能继续攻击**
4. 两个单位**不会抢同一个掩体**
5. 单位中途死亡后，其预约的掩体**会被释放**

**产出物**（下游按名字对接）：

```text
Formation：槽位分配（固定分配，⛔ 不按距离每帧重分）
CoverRegistry：掩体点表 + 预约 + 超时释放
AttackTokenPool：max_attackers + 强制回收
```

## 2. 工序

### Step 1　⛔ 不要各自追玩家　`[ai/05#S1]`

【读】`howto/godot/ai-tactics.md#2. 阵型与编队：锚点 + 偏移`

【做】⚠ **不要给每个单位各自设"玩家位置"为目标点。**
结果是所有人挤向同一个点，然后被避障推开再挤回来——
表现为"**一群敌人在原地蠕动**"。

✅ 正确模型：**队形有一个锚点 + 每个单位一个槽位偏移**。

```gdscript
func slot_position(anchor: Vector3, facing: float, slot: int) -> Vector3:
    var local := FORMATION[slot]           # 如 (-1.5, 0, -2.0)
    return anchor + Vector3(local.x, 0, local.z).rotated(Vector3.UP, facing)
```

【产出】锚点 + 槽位模型（⛔ 不是各自追玩家）

【判据】⚠ 5 个单位接近玩家时**分散在扇形上**（⛔ 不是叠在一起）

【审】`audit/godot/ai-tactics.md#5`

### Step 2　槽位固定分配　`[ai/05#S2]`

【读】`howto/godot/ai-tactics.md#2. 阵型与编队：锚点 + 偏移`

【做】⚠ **槽位要固定分配**，⛔ 不要每帧按距离重新分配——
那会让两个单位争夺同一个槽位，**来回横跳**。

ⓘ 分配时机：加入小队时；单位死亡/离队时重排。

⚠ **槽位也要走导航。** 直接把世界坐标当目标会穿墙——
算出槽位世界坐标后仍要交给 `NavigationAgent`。

【产出】槽位固定分配 + 死亡重排 + 走导航

【判据】⚠ 小队移动 30 秒，**槽位归属不变**（⛔ 不是一直在换）

【审】`audit/godot/ai-tactics.md#6` `audit/godot/ai-tactics.md#7`

### Step 3　avoidance_priority 让路　`[ai/05#S3]`

【读】`howto/godot/ai-navigation.md#8. 官方明确列出的路径跟随坑`

【做】⚠ 官方原话：高优先级代理**不为低优先级让路**，
低优先级的要让得更多。

✅ 给队长/Boss/冲锋单位设高优先级，小兵让路——
比手写推挤逻辑简单，且是**引擎内建**的。

【产出】优先级已分配（⛔ 不是全默认 1.0）

【判据】⚠ Boss 穿过小兵时，**小兵让路**（⛔ 不是互相推）

【审】`audit/godot/ai-tactics.md#20`

### Step 4　掩体预烘焙 + 预约制　`[ai/05#S4]`

【读】`howto/godot/ai-tactics.md#3. 掩体与战术位置`

【做】⚠ **掩体点要预烘焙，不要运行时查询。**
运行时用射线找掩体 = 每个单位每帧几十条射线，且**结果不稳定**
（同一个位置两次查询可能给出不同点，单位来回跑）。

⚠ **"占用"必须是预约制**，不是"到了才算占用"。
两个单位同时选中同一个掩体 → 都跑过去 → 挤在一起。
✅ 选中即标记 `reserved_by`，离开时释放。

⚠ **还要有超时释放**，否则单位中途死亡会让掩体**永久锁定**。

【产出】掩体点表（预烘焙）+ 预约 + 超时释放

【判据】⚠ 两个单位同时需要掩体时**选了不同的点**；
　　　杀死预约者后其掩体**超时后释放**

【审】`audit/godot/ai-tactics.md#8` `audit/godot/ai-tactics.md#9`

### Step 5　⚠ 攻击令牌防"集体发呆"　`[ai/05#S5]`

【读】`howto/godot/ai-tactics.md#4. 群体协作：攻击令牌`

【做】⚠ **"同时最多 N 个敌人攻击"是战术层最基础的一条规则。**
没有它，一群敌人会同时挥刀，玩家毫无反应窗口——
这是"AI 很强但不好玩"的头号原因。

⚠ **令牌必须能被强制回收。**
单位在持有令牌时死亡/被击退/进入硬直 → 令牌泄漏 →
**所有人都不再攻击**。这是最典型的"**AI 突然集体发呆**"的原因。

✅ 三个回收时机：攻击动画结束、进入硬直/死亡、离战。
ⓘ 更稳的是**带超时的令牌**作为兜底。

【产出】令牌池 + 三条回收路径 + 超时兜底

【判据】⚠ 杀掉持有令牌的敌人后，**其余敌人立即能补上攻击位**

【审】`audit/godot/ai-tactics.md#10`

### Step 6　攻击节奏与破绽　`[ai/05#S6]`

【读】`howto/godot/ai-tactics.md#5. 攻击节奏：间隔、冷却、破绽`

【做】⚠ **攻击间隔不能是固定值。**
所有敌人同频 → 玩家找到节拍后无脑闪避。

✅ 三件套：个体冷却（随机 0.8–1.5 倍）、令牌限制、破绽窗口。

⚠ **破绽窗口要给玩家可读的信号**，⛔ 不只是数值。
否则玩家不知道"现在可以反击"，机制等于不存在。

【产出】随机冷却 + 令牌 + 可读的破绽表现

【判据】⚠ 蒙住 UI，玩家**能看出**敌人何时可反击

【审】`audit/godot/ai-tactics.md#11` `audit/godot/ai-tactics.md#12`

## 3. 参考实现

```gdscript
class_name AttackTokenPool
extends Node

@export var max_attackers := 2
@export var token_timeout := 6.0      # ⚠ 兜底，防泄漏

var _holders: Dictionary = {}         # who -> 已持有时长

func request(who: Node) -> bool:
    if who in _holders:
        return true
    if _holders.size() >= max_attackers:
        return false
    _holders[who] = 0.0
    return true

func release(who: Node) -> void:
    _holders.erase(who)

func _process(delta: float) -> void:
    for who in _holders.keys():
        _holders[who] += delta
        if _holders[who] > token_timeout:
            _holders.erase(who)        # ⚠ 超时回收，防"集体发呆"
            push_warning("攻击令牌超时回收: %s" % who.name)
```

⚠ 超时回收时**要打警告**——
正常情况不该触发；频繁触发说明某条回收路径没实现。

ⓘ 同类机制：**包围位限制**（最多几个单位占近战位，其余外围游走），
比"一拥而上"观感好得多。
