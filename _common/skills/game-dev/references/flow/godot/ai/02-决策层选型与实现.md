# 02 决策层选型与实现（AI 域）

> **前置**：01 感知已接入，能拿到带置信度的证据
> **本步交付**：一个**有理由存在**的决策结构（FSM 或 BT），不是为用而用
> **对应**：做法 `howto/godot/ai-behavior.md` · 审核 `audit/godot/ai-behavior.md`

## 0. 交付物定义

⚠ **BT 不是 FSM 的升级版，是维护对象不同。**
一个近战小怪通常只有 Idle / Patrol / Chase / Attack / Stagger / Dead，
这些状态互斥，转移由玩家距离、血量、受击触发 —— 用 `match state` 最清楚。
拆成行为树只会得到"条件链 + 顺序节点"的扁平树，**读起来比 match 更长**。

做完这一步，应该能**当场演示**：

1. 每个状态的进入/退出条件**写得出来**（⛔ 不是"差不多就切"）
2. 若用 BT：`RUNNING` 与 `FAILURE` 语义正确
3. 若用 BT：黑板里**没有引擎对象引用**
4. 高优先级反应能**打断**低优先级长任务
5. ⚠ 战术层规则**没有**混进决策层（判据见 S6）

**产出物**（下游按名字对接）：

```text
状态枚举 + 转移表，或 BehaviorTree 资源 + Blackboard
每个状态的进入/退出钩子
```

## 2. 工序

### Step 1　⛔ 别一上来就上行为树　`[ai/02#S1]`

【读】`howto/godot/ai-behavior.md#0. 先选对方案，别一上来就上行为树`

【做】⚠ **BT 开始变现的信号**只有两个：
- 一棵子树能被巡逻、Boss 阶段、炮台、NPC 任务**共同复用**
- 策划需要**反复调整优先级**而不碰代码

⛔ 三类典型过度设计：
1. 只有一个根 Selector 和线性 Sequence —— 本质是 `if/elif/else`
2. 为每个敌人复制整棵树 —— 节点数增长但没复用
3. 把寻路、动画状态机、伤害结算全塞进 Task —— 树变成大型回调壳

【产出】选型有书面理由（⛔ 不是"BT 更专业"）

【判据】⚠ 能说出"为什么不用 FSM"或"为什么不用 BT"，
　　　且理由属于上面两条之一

【审】`audit/godot/ai-behavior.md`

### Step 2　节点返回值不是两个布尔　`[ai/02#S2]`

【读】`howto/godot/ai-behavior.md#1. 节点返回值不是"成功/失败"两个布尔`

【做】
```
SUCCESS   完成
FAILURE   合法路径信息，不是错误
RUNNING   当前 tick 无法完成，父节点下次 tick 继续交给同一节点
```

⚠ **FAILURE 是正常路径**（"目标不在视野"失败，让 Selector 试下一分支）。
⚠ **忘记返回 RUNNING** → 播放动画、寻路、计时器会**每帧从头执行**。

【产出】三态都用对

【判据】⚠ 播放动画的 Task **不会被每帧重启**（动画能播完）

【审】`audit/godot/ai-behavior.md`

### Step 3　RUNNING 要有 abort 机制　`[ai/02#S3]`

【读】`howto/godot/ai-behavior.md#1. 节点返回值不是"成功/失败"两个布尔`

【做】⚠ **RUNNING 没有 abort 机制** → 低优先级长任务永远阻塞高优先级反应
（比如正在巡逻时被攻击却不能打断）。

ⓘ 这是 BT 相对朴素 `if/elif` 的核心价值之一：
**反应性**必须显式实现，⛔ 不会自动获得。

【产出】有 abort/中断规则（如"受击立即中断当前 Task"）

【判据】⚠ 巡逻中受击，**立刻切到受击反应**（⛔ 不是播完巡逻动作）

【审】`audit/godot/ai-behavior.md`

### Step 4　黑板不塞引擎对象　`[ai/02#S4]`

【读】`howto/godot/ai-behavior.md#3. 黑板（Blackboard）`

【做】⚠ 黑板**不要塞引擎对象引用**（Node / Resource），
否则存档时无法序列化，且对象释放后留**悬空引用**。
✅ **存 id / 路径，需要时再查**。

⛔ 症状：读档后 AI 全部失效（黑板里的引用指向已释放的对象）。

【产出】黑板只存可序列化数据

【判据】⚠ 存档→读档后，AI **仍能正常工作**

【审】`audit/godot/ai-behavior.md`

### Step 5　插件要锁版本　`[ai/02#S5]`

【读】`howto/godot/ai-behavior.md#4. 现成插件`

【做】⚠ **CI 中应锁定 commit 或 release 资产**，
⛔ 不要 `git pull` 主分支后上线。

⚠ **版本兼容以各仓库的兼容表为准**，本文不推断具体版本支持范围。

【产出】若用插件，依赖已锁定

【判据】⚠ 全新 clone 后能构建（⛔ 不是"我本地是好的"）

【审】`audit/godot/ai-behavior.md`

### Step 6　⛔ 战术层不许混进来　`[ai/02#S6]`

【读】`howto/godot/ai-behavior.md#6. 战术层不在这里`

【做】⚠ **判据：只留一个敌人时这条规则还成立吗？**
成立 → 决策层；不成立 → 战术层（去 04/05）。

ⓘ "看到玩家就追"是决策层；"同时最多两个敌人攻击"是战术层。

⛔ 混进来的后果：单个敌人测试一切正常，
一群敌人时出现"无法解释"的集体行为，且改不动。

【产出】决策层里无跨个体规则

【判据】⚠ 逐条列出决策规则，标注"单个也成立"，
　　　⛔ 没有"需要知道同伴状态"的规则

【审】`audit/godot/ai-behavior.md`

## 3. 参考实现

```gdscript
# 枚举 FSM：状态互斥、转移由明确条件触发
enum State { IDLE, PATROL, CHASE, ATTACK, STAGGER, DEAD }

func _change_state(to: State) -> void:
    if _state == to:
        return
    _on_exit(_state)
    _state = to
    _on_enter(to)      # ⚠ 进入/退出钩子，⛔ 不散落在各处

func _on_enter(s: State) -> void:
    match s:
        State.STAGGER:
            _abort_current_task()    # ⚠ 高优先级反应打断一切
        State.CHASE:
            _agent.set_target(_perception.last_known_pos)
```

⚠ 转移条件要**集中**，⛔ 不要在每个状态的 `_process` 里各自判断转移——
那会让"哪些转移存在"无法一眼看全。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 树读起来比 match 还长 | 用了 BT 但本质是 if/elif | S1 |
| 动画每帧从头播 | 忘了返回 RUNNING | S2 |
| 巡逻中挨打不反应 | RUNNING 无 abort | S3 |
| 读档后 AI 失效 | 黑板存了对象引用 | S4 |
| 同事 clone 后跑不起来 | 插件没锁版本 | S5 |
| 群怪出现无法解释的行为 | 战术规则混进决策层 | S6 |
