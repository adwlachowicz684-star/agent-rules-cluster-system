# 04 目标选择与仇恨（AI 域）

> **前置**：01 感知已接入，02 决策已定，03 Idle 与转移已通
> **本步交付**：多目标下**稳定**地选目标——有迟滞、有仇恨表、能平滑转移
> **对应**：做法 `howto/godot/ai-tactics.md` `ai-perception.md` · 审核 `audit/godot/ai-tactics.md`

## 0. 交付物定义

⚠ **只有一个候选目标的项目可以跳过本步。**
有多个候选（玩家 + 宠物 + 召唤物 + 其他 NPC）才需要。

⚠ **目标选择最容易犯的错不是"选错"，是"抖动"。**
玩家看到的是敌人**在两个目标之间来回横跳**——
这比选错目标更破坏体验，因为它看起来像 bug。

做完这一步，应该能**当场演示**：

1. 两个候选分数接近时，**不来回切换**（迟滞生效）
2. ⚠ 当前目标死亡后，AI **转向威胁表下一名**（⛔ 不是发呆）
3. 嘲讽/治疗通过**加威胁**起作用，⛔ 不是直接设目标
4. 嘲讽结束后按威胁表**自然回落**，⛔ 不是立刻回头
5. ⚠ 连续战斗 3 分钟，切换次数**明显少于**评分变更次数

**产出物**（下游按名字对接）：

```text
ThreatTable：{target_id -> 累计威胁, 最后攻击时间}
select_target() -> target_id    含迟滞 + 最短保持
add_threat(target_id, amount)
```

## 2. 工序

### Step 1　评分维度　`[ai/04#S1]`

【读】`howto/godot/ai-perception.md#3. 记忆：丢失目标 ≠ 丢失证据`

【做】ⓘ 评分维度：距离、可见性、威胁度、上次攻击时间。

⚠ **评分是输入，不是决定。** 评分结果要经过迟滞才成为"目标"。
⛔ 直接取 argmax 就是抖动的来源。

【产出】评分函数（纯函数，无副作用）

【判据】⚠ 固定输入下评分**可复现**（同输入同输出）

【审】`audit/godot/ai-tactics.md` 第 2 条

### Step 2　⚠ 迟滞：阈值 + 最短保持　`[ai/04#S2]`

【读】`howto/godot/ai-tactics.md#1. 目标选择：评分 + 迟滞 + 仇恨`

【做】⚠ **必须加迟滞**——否则在两个候选的评分边界**反复切换目标**。

✅ 换目标要求**新目标分数高出当前目标一个阈值**：
```gdscript
const SWITCH_MARGIN := 1.2    # 新目标要高出 20% 才换
```

⚠ **还要加最短保持时间**（如 2 秒）。
⛔ 只有阈值仍不够：激烈战斗中分数剧烈波动，
即使有 20% 阈值也可能每几百毫秒满足一次。

【产出】阈值 + 最短保持都实现

【判据】⚠ 连续战斗 3 分钟，**切换次数明显少于评分变更次数**

【审】`audit/godot/ai-tactics.md` 第 2 条

### Step 3　⚠ 仇恨表不是可选项　`[ai/04#S3]`

【读】`howto/godot/ai-tactics.md#1. 目标选择：评分 + 迟滞 + 仇恨`

【做】⚠ **仇恨（threat）要单独成表**，
⛔ 不能只靠"当前目标"这一个变量。

| 目标 | 累计威胁 | 最后攻击时间 |
|---|---|---|
| 玩家 | 120 | 0.4s |
| 宠物 | 35 | 3.1s |

ⓘ 有了仇恨表才能回答：
- 目标死亡/消失后**打谁**（取剩余最高）
- 被治疗/嘲讽时**怎么转移**（加威胁）
- 为什么不追着脆皮输出跑（威胁按**实际承受伤害**累计）

【产出】威胁表（⛔ 不是单个 `_current`）

【判据】⚠ 杀掉当前目标后，AI **转向威胁表下一名**（⛔ 不是发呆）

【审】`audit/godot/ai-tactics.md` 第 4 条

### Step 4　⚠ 转移目标 ≠ 重设目标　`[ai/04#S4]`

【读】`howto/godot/ai-tactics.md#1. 目标选择：评分 + 迟滞 + 仇恨`

【做】⚠ 嘲讽应该是"**给该目标加一大笔威胁**"，
让它自然在下一轮评分中胜出。

⛔ 直接设 `_current = taunter` 会让**嘲讽结束时 AI 立刻回头**——
正确行为是仇恨表仍在，嘲讽的那一笔应**随时间衰减**。

【产出】嘲讽走威胁表，不是直接设目标

【判据】⚠ 嘲讽结束 5 秒后，AI 按威胁表**自然回落**（⛔ 不是立刻回头）

【审】`audit/godot/ai-tactics.md` 第 3 条

### Step 5　威胁要衰减　`[ai/04#S5]`

【读】`howto/godot/ai-tactics.md#1. 目标选择：评分 + 迟滞 + 仇恨`

【做】⚠ 威胁**必须衰减**，否则：
- 打过的目标永远排第一（哪怕已跑到天涯海角）
- 治疗一次就永久拉住仇恨

ⓘ 衰减两种：**自然衰减**（按时间乘系数）与**距离衰减**（远了掉得快）。
✅ 两者都要——只有自然衰减会让"远处的旧目标"长期占据榜首。

【产出】威胁衰减规则（含自然 + 距离）

【判据】⚠ 打完就跑远的目标，**威胁在 N 秒内掉出榜首**

【审】`audit/godot/ai-tactics.md`

### Step 6　存 id 不存对象　`[ai/04#S6]`

【读】`howto/godot/ai-behavior.md#3. 黑板（Blackboard）`

【做】⚠ 威胁表存 **id**，⛔ 不存 Node 引用。
目标死亡后引用成悬空，且无法存档。

⚠ 还要**定期清理**死亡/离场目标的条目，
否则威胁表无限增长（长时间挂机的经典泄漏）。

【产出】威胁表存 id，有清理机制

【判据】⚠ 跑 10 分钟后威胁表**条目数稳定**（⛔ 不是持续增长）

【审】`audit/godot/ai-behavior.md`

## 3. 参考实现

```gdscript
class_name ThreatTable
extends RefCounted

const SWITCH_MARGIN := 1.2
const MIN_HOLD_TIME := 2.0
const DECAY_PER_SEC := 0.9        # ⚠ 自然衰减
const DISTANCE_DECAY := 0.5       # ⚠ 距离衰减

var _threat: Dictionary = {}      # id -> float
var _last_hit: Dictionary = {}    # id -> float(时间戳)
var _current: int = -1
var _hold := 0.0

func add(id: int, amount: float) -> void:
    _threat[id] = _threat.get(id, 0.0) + amount

func tick(delta: float, my_pos: Vector3, pos_of: Callable) -> void:
    _hold += delta
    for id in _threat.keys():
        _threat[id] *= pow(DECAY_PER_SEC, delta)
        var d := my_pos.distance_to(pos_of.call(id))
        if d > 30.0:
            _threat[id] *= pow(DISTANCE_DECAY, delta)   # 远了掉更快
        if _threat[id] < 0.5:
            _threat.erase(id)                            # ⚠ 清理，防无限增长
            _last_hit.erase(id)

func select(scores: Dictionary) -> int:
    var best := -1
    var best_score := -INF
    for id in scores:
        if scores[id] > best_score:
            best = id
            best_score = scores[id]
    if best == _current:
        return _current
    if _current >= 0 and not scores.has(_current):
        return best                                      # ⚠ 目标没了，立即换
    if _hold < MIN_HOLD_TIME:
        return _current                                  # ⚠ 最短保持
    if best_score > scores.get(_current, 0.0) * SWITCH_MARGIN:
        _current = best
        _hold = 0.0
    return _current
```

⚠ 注意"目标没了立即换"这一分支——
⛔ 它也走迟滞的话，AI 会在目标死后**发呆 2 秒**。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 敌人两目标间横跳 | 无迟滞 | S2 |
| 目标死了发呆 | 只有 `_current`，无威胁表 | S3 |
| 嘲讽结束立刻回头 | 直接设目标而非加威胁 | S4 |
| 打过的目标永远第一 | 威胁不衰减 | S5 |
| 长时间挂机内存涨 | 威胁表不清理 | S6 |
| 读档后仇恨丢失 | 存了对象引用 | S6 |
