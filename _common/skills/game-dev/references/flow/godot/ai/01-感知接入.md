# 01 感知接入（AI 域）

> **前置**：已确定敌人有哪些、各自要感知什么（见 `00-域流程总览.md` 第 0 节）
> **本步交付**：一个独立于决策的感知层——输出**带置信度的证据**，不是布尔
> **对应**：做法 `howto/godot/ai-perception.md` `ai-navigation.md` · 审核 `audit/godot/ai-perception.md`

## 0. 交付物定义

⚠ **感知是独立的一层，不是决策的一个分支。**
把"看得见吗"写在 Chase 分支里，Idle 时就不会检测——
表现为"背对玩家永远发现不了"，而排查时你会去调视野角度，其实与角度无关。

做完这一步，应该能**当场演示**：

1. 正对时能发现，**背对时不能**
2. 隔着墙**不能**发现（射线遮挡）
3. 目标消失后，AI 去**最后已知位置**查看（不是原地发呆）
4. ⚠ 感知**不是每帧**跑（10Hz 通常够）
5. 调试可视化能看到视锥与射线

**产出物**（下游按名字对接）：

```text
Perception.tick() -> 感知结果（含置信度 / 最后已知位置）
get_best_target() -> 目标 id（⛔ 不返回引擎对象引用）
```

## 2. 工序

### Step 1　⚠ 感知独立成层　`[ai/01#S1]`

【读】`howto/godot/ai-perception.md#0. 为什么感知要独立成层`

【做】⚠ 感知的输出**不是布尔**，要有置信度/证据强度。
⛔ `can_see_player() -> bool` 会让你无法表达"好像看到但不确定"，
也就做不了怀疑度、搜查、警戒等级。

ⓘ 感知层只回答"我知道什么"，⛔ 不回答"我该做什么"。

【产出】感知层独立于决策，输出证据而非 bool

【判据】⚠ 单独调用感知层（不跑 AI），**能拿到带强度的证据**

【审】`audit/godot/ai-perception.md#1` `audit/godot/ai-perception.md#2` `audit/godot/ai-perception.md#12` `audit/godot/ai-perception.md#6`

### Step 2　视觉：距离、角度、遮挡三条独立闸门　`[ai/01#S2]`

【读】`howto/godot/ai-perception.md#1. 视觉：距离、角度、遮挡三条独立闸门`

【做】⚠ 三条是**独立的**，都要过：
距离 → 角度（视锥内）→ **遮挡（射线）**。

⚠ **遮挡必须射线**。只判距离+角度会"隔着墙看见玩家"。

⚠ 4.x 用 `PhysicsRayQueryParameters3D`，
⛔ 不是 3.x 的 `intersect_ray(from, to, [])` 写法。

【产出】三条闸门都实现

【判据】⚠ 隔墙站定，**不被发现**；绕到正前方，**被发现**

【审】`audit/godot/ai-perception.md#3` `audit/godot/ai-perception.md#4` `audit/godot/ai-perception.md#5` `audit/godot/ai-perception.md#13`

### Step 3　听觉是事件，不是状态　`[ai/01#S3]`

【读】`howto/godot/ai-perception.md#2. 听觉：声音是有位置、有寿命的事件`

【做】⚠ 声音要建模成**有发出者、位置、响度、寿命**的事件。

⚠ **听到但没看到 → 去查看**，⛔ 不是直接进入战斗。
直接进战斗会让"扔个石头引怪"这类玩法失效。

【产出】声音事件总线 + 距离衰减 + 触发"去查看"

【判据】⚠ 在看不见处发出声响，AI **前往声源位置查看**（不是立刻锁定）

【审】`audit/godot/ai-perception.md#16` `audit/godot/ai-perception.md#17` `audit/godot/ai-perception.md#18`

### Step 4　记忆：丢失目标 ≠ 丢失证据　`[ai/01#S4]`

【读】`howto/godot/ai-perception.md#3. 记忆：丢失目标 ≠ 丢失证据`

【做】⚠ 目标消失后要保存**最后已知位置**，
并经历 **搜索 → 放弃 → 返回** 的有限状态。

⚠ **记忆不是缓存变量**，它是一个**有状态的过程**。
⛔ 只存一个 `last_seen_pos` 变量，没有搜索过程，
AI 会"跑到那个点然后站着不动"。

【产出】记忆是状态机（搜索/放弃/返回），有最后已知位置

【判据】⚠ 玩家躲进死角，AI **搜索一段时间后返回**（⛔ 不是永远站着）

【审】`audit/godot/ai-perception.md#8` `audit/godot/ai-perception.md#9`

### Step 5　检测频率不等于帧率　`[ai/01#S5]`

【读】`howto/godot/ai-perception.md#5. 性能与调试`

【做】⚠ **10Hz 通常足够**，⛔ 不要每帧对每个敌人做全量检测。

⚠ 还要做**距离剔除 / 空间哈希 / 分帧**。
ⓘ AI 是唯一会随单位数**平方级**变贵的系统。

【产出】感知按固定频率跑，有距离剔除

【判据】⚠ 20 个敌人时，AI 耗时**不随数量平方增长**

【审】`audit/godot/ai-perception.md#7` `audit/godot/ai-perception.md#14`

### Step 6　群体共享要带延迟　`[ai/01#S6]`

【读】`howto/godot/ai-perception.md#4. 群体共享`

【做】⚠ **不要让一个敌人瞬间改写所有同伙的黑板** ——
用**警戒等级**（未察觉 / 怀疑 / 警戒 / 战斗）+ **带延迟的传播**。

⛔ 瞬间传播的表现：打一个怪，全场立刻围过来——
玩家会觉得"它们作弊"。

【产出】警戒等级 + 延迟传播

【判据】⚠ 击杀远处敌人，附近的**过 1–2 秒才反应**（⛔ 不是同帧）

【审】`audit/godot/ai-perception.md#11` `audit/godot/ai-perception.md#11`

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 背对玩家永远发现不了 | 感知写在 Chase 分支，Idle 没检测 | S1 |
| 隔墙看见玩家 | 缺射线遮挡 | S2 |
| 用了 3.x 的 intersect_ray | API 版本错 | S2 |
| 听到声就锁定 | 听觉直接进战斗 | S3 |
| 跑到最后位置就站着 | 记忆是变量不是过程 | S4 |
| 同屏敌人多了就卡 | 每帧全量检测 | S5 |
| 打一个全场立刻围过来 | 感知瞬间传播 | S6 |
