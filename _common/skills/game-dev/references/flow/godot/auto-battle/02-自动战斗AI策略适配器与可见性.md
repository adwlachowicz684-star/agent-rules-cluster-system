# 02 自动战斗：AI 策略适配器与可见性（自动战斗域）

> **本步交付**：`Observation` 边界 + 决策三件套 + 运行时可配 + 托管不比手动强的验收
> **对应**：流程 `howto/godot/auto-battle.md` · 审核 `audit/godot/auto-battle.md`

## 0. 交付物定义

1. AI 只持有 `Observation`，看不到隐藏信息
2. 决策对齐固定 tick，不是每渲染帧扫描
3. 优先级 / 条件树 / CD 与资源感知三者分开
4. 决策写回"为什么选它"，且策略运行时可配
5. 验收口径是"托管不客观强于手动"

## 1. 前置检查清单

- [ ] AI 读不到 `current_hp`、完整行动计划、未发生的随机数
- [ ] 决策点与 `sim_tick` 对齐
- [ ] 条件不是一堆硬编码 `if`
- [ ] 有技能黑名单、血线、资源下限等运行时开关
- [ ] 决策原因可导出

## 2. 工序

### Step 1　AI 只见玩家可见信息，⛔ 不读隐藏状态　`[auto-battle/02#S1]`

【读】`howto/godot/auto-battle.md#2. 自动战斗`

【做】
AI 只持有 `Observation`：可见血量区间、可见目标、自己技能 CD、自己能合法知道的状态。
⛔ 让它读 `enemy.current_hp`、`enemy.intent_next_turn` 或 `combat._debug` ——
托管会**客观强于手动**，把"一键托管"变成隐性强制，
⛔ 而这在数值上完全合法，平衡表看不出任何异常。

ⓘ 判据不是"AI 够聪明"，而是**"蒙住隐藏字段后胜率不下降"** ——
如果下降了，说明它一直在用玩家得不到的信息。

【产出】`Observation` 结构定义 + 玩家可见性规则表

【判据】隐藏字段置空后，托管胜率与之前持平。

【审】`audit/godot/auto-battle.md#4`

### Step 2　决策点对齐固定 tick　`[auto-battle/02#S2]`

【读】`howto/godot/auto-battle.md#2. 自动战斗`

【做】
AI 决策在 `sim_tick` 上按固定间隔触发，⛔ 不在 `_process` 里每渲染帧扫描。
⛔ 每帧扫描 —— 高帧率机器上 AI 反应更快、低帧率机器上更慢，
表现为"同一套策略在不同机器上强度不同"，
⛔ 而两边都是"正常 AI"，排查被引向策略参数而不是调度。

【产出】决策调度接入点（`sim_tick % N == 0`）

【判据】30 / 60 / 144 FPS 下托管行为一致。

【审】`audit/godot/auto-battle.md#5`

### Step 3　优先级 / 条件树 / CD 感知三者分开　`[auto-battle/02#S3]`

【读】`howto/godot/auto-battle.md#2. 自动战斗`

【做】
三层分开：**优先级**给稳定终极排序、**条件树**表达可读战术、**CD 与资源感知**避免抖动。
⛔ 只写"大招优先级最高" —— 优先级表达不了条件，
表现为"残血放大招给小兵""没蓝还在等大招"；
⛔ 只写巨量 `if` —— 配置变更迫使改代码发版。

【产出】优先级表 + 条件树配置 + CD / 资源感知层

【判据】改一个技能配置不需要改代码。

【审】`audit/godot/auto-battle.md#6`

### Step 4　决策写回原因，且策略运行时可配　`[auto-battle/02#S4]`

【读】`howto/godot/auto-battle.md#2. 自动战斗`

【做】
决策后写回"为什么选它"，供复盘、观战标签与后续调弱使用。
同时把 `auto_enabled`、角色级策略、**技能黑名单**、血线、资源下限、目标偏好做成**运行时可配**。
⛔ 写死在代码里 —— 想调托管强度就得发版，
而真正决定"玩家还愿不愿意手动玩"的恰恰是这些开关，不是算法。

ⓘ 有效做法不是把 AI 写笨，而是把**玩家知识与执行能力分开**：
AI 可做精确计时和反应，但⛔ 不获得隐藏信息；关键决策仍由玩家承担。

【产出】决策原因字段 + 策略配置表（含黑名单与血线）

【判据】改配置即可调整托管强度，无需改代码。

【审】`audit/godot/auto-battle.md#37`

### Step 5　验收口径是"托管不客观强于手动"　`[auto-battle/02#S5]`

【读】`howto/godot/auto-battle.md#2. 自动战斗`

【做】
用同一批账号、同一套阵容跑**手动 vs 托管**对照：
托管胜率**不应显著高于**手动。
⛔ 只验"托管能打赢" —— 那恰恰是问题，
表现为"手动玩家被劝退去开托管"，而版本留存数据只显示"托管使用率上升"，看不出是被迫的。

ⓘ 红线是**隐藏信息**：只要 AI 用了玩家看不到的字段，
再怎么调参数都只是把"强多少"改小，问题本质没变。

【产出】手动 / 托管对照记录（含隐藏字段置空的对照）

【判据】托管胜率不显著高于手动；隐藏字段置空后胜率不变。

【审】`audit/godot/auto-battle.md#4`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：Observation 边界 + 决策写回原因
# AUTO_AI_DECIDE_EVERY_N_TICKS 见 00 参数登记，待实测
const AUTO_AI_DECIDE_EVERY_N_TICKS := 6

func decide(obs: Observation, tick: int) -> Intent:
    # ⛔ obs 只含玩家可见信息；读不到 enemy.current_hp
    var pick := pick_by_priority(obs)
    var why  := "priority:%s hp_band:%s cd_ready:%s" % [pick, obs.hp_band, obs.cd_ready]
    return Intent.new(tick, obs.actor_id, pick.type, obs.target_id, pick.skill_id, why)
```

## 4. 验收清单

- [ ] 隐藏字段置空后胜率不下降
- [ ] 30 / 60 / 144 FPS 托管行为一致
- [ ] 改技能配置不改代码

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 托管客观强于手动 | AI 读隐藏信息 | S1 |
| 高帧率机器上 AI 更强 | 决策按渲染帧 | S2 |
| 残血放大招给小兵 | 只有优先级没有条件树 | S3 |
| 想调强度要发版 | 策略写死 | S4 |
| 手动玩家被劝退 | 只验"能打赢" | S5 |
