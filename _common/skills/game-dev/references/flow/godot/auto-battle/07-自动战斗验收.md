# 07 自动战斗验收（自动战斗域）

> **本步交付**：跨构建黄金集通过 + 敌意环境实测通过
> **对应**：流程 `howto/godot/auto-battle.md` · 审核 `audit/godot/auto-battle.md`

## 0. 交付物定义

1. 同一输入在 Debug / Release、x86 / ARM、不同帧率下状态哈希一致
2. 改包伪造（提交结果 / 改次数 / 改倍率）被服务端拒绝
3. 改客户端系统时间不影响离线结算
4. 强杀 / 断线重连后不重复发奖
5. 回放校验和不匹配时的处置不是"判作弊"
6. 热更配置后离线回补不改写旧时间窗

## 2. 工序

### Step 1　跨构建黄金集，⛔ 不是编辑器里跑一遍　`[auto-battle/07#S1]`

【读】`howto/godot/auto-battle.md#9. 待核对项`

【做】
建**回放黄金集**：同一批输入在 Debug / Release、x86 / ARM、不同帧率、不同线程数下跑，
比对状态哈希。
⛔ 只在编辑器跑一遍 —— 浮点漂移会让校验在发布后失败，
字典顺序依赖会让本地测试通过而正式环境漂移，
⛔ 而这两类失败都只在"换构建 / 换机器"时出现，本地永远复现不了。

【产出】黄金集用例清单 + 跨构建哈希对照记录

【判据】所有构建组合下状态哈希一致。

【审】`audit/godot/auto-battle.md#39`

### Step 2　改包伪造必须被服务端拒绝　`[auto-battle/07#S2]`

【读】`howto/godot/auto-battle.md#8. 服务端权威清单`

【做】
构造三类伪造：客户端直接提交战斗结果、改扫荡次数、改 VIP / 活动倍率，
验证服务端**全部拒绝**。
⛔ 只测正常路径 —— 这类伪造**在正常流程里永远测不出来**，
它只在有人主动改包时才触发，⛔ 而测试环境下没人会改包。

【产出】三类伪造用例 + 服务端拒绝记录

【判据】三类全部被拒，且客户端回退无中间态。

【审】`audit/godot/auto-battle.md#30`

### Step 3　改客户端系统时间不影响离线结算　`[auto-battle/07#S3]`

【读】`howto/godot/auto-battle.md#4. 离线挂机`

【做】
把设备时间前后调一年、跨时区、跨夏令时，验证离线收益与正常情况**完全相同**。
⛔ 只测"离线 8 小时" —— 时钟攻击**只在有人改时间时出现**，
⛔ 而改时间的操作在日志里表现为一次完全正常的登录与结算。

【产出】时钟攻击用例（±1 年 / 跨时区 / 跨 DST）+ 对照记录

【判据】改时间后收益与未改时一致。

【审】`audit/godot/auto-battle.md#14`

### Step 4　强杀 / 断线重连后不重复发奖　`[auto-battle/07#S4]`

【读】`howto/godot/auto-battle.md#3. 扫荡`

【做】
实测**强杀进程**与**断线重连**：扫荡次数、奖励、离线锚点是否正确。
⛔ 只测"点确认后正常到账" —— 强杀走的是超时判定与服务端补算，
点确认走的是正常提交，**是两条不同的代码路径**。
⛔ 重复投递会导致"掉了两次同样的东西"，而网关只看到一次请求。

【产出】强杀 / 重连对照记录（次数、奖励、锚点）

【判据】重连前后次数与奖励一致，无重复发奖。

【审】`audit/godot/auto-battle.md#9`

### Step 5　校验和不匹配的处置不是"判作弊"　`[auto-battle/07#S5]`

【读】`howto/godot/auto-battle.md#5. 回放与观战`

【做】
回放校验和不匹配时，判定为**确定性已破坏或文件被改动**，
⛔ 不要直接判作弊。
⛔ 直接判作弊 —— 会把"跨版本播放""浮点漂移""存档损坏"全部误伤成封号，
表现为"玩家被封但说不出做了什么"，而系统里只有一条"校验失败"。

ⓘ 处置顺序：先比对版本元数据（见 05 S4），再查构建与平台，最后才考虑人为改动。

【产出】校验失败的分级处置流程

【判据】校验失败时能区分"版本不符 / 平台差异 / 文件损坏"，不直接封号。

【审】`audit/godot/auto-battle.md#24`

### Step 6　热更配置后离线回补不改写旧时间窗　`[auto-battle/07#S6]`

【读】`howto/godot/auto-battle.md#4. 离线挂机`

【做】
热更配置后，回补离线必须用**当时时间窗对应的 `config_version`**。
⛔ 用新规则统一回补 —— 玩家更新后离线收益突变，
表现为"版本更新后收益少了一半"的集体投诉，
⛔ 而每一笔结算单看都符合**当前**版本的规则，查不出错。

【产出】回补规则（按时间窗取版本）+ 热更前后收益对照

【判据】热更后回补的旧时间窗收益与热更前口径一致。

【审】`audit/godot/auto-battle.md#38`

## 3. 验收清单

- [ ] 所有构建组合下状态哈希一致
- [ ] 三类伪造全部被拒
- [ ] 改时间不影响离线收益
- [ ] 强杀重连不重复发奖
- [ ] 校验失败能分级不误封
- [ ] 热更回补不改旧窗口

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 发布后回放校验失败 | 只在编辑器跑过 | S1 |
| 排行榜出现不可能战绩 | 只测正常路径 | S2 |
| 改时间能刷收益 | 只测正常离线 | S3 |
| 掉了两次同样东西 | 只测正常到账 | S4 |
| 玩家被误封 | 校验失败即判作弊 | S5 |
| 更新后收益突变 | 回补用新规则 | S6 |
