# 06 上下车与切换事务（vehicle 域）

> **前置**：`05-载具碰撞与乘员.md` 已完成
> **本步交付**：**连按上下车 100 次不崩溃、不漂移**
> **对应**：做法 `howto/godot/vehicle.md#9. 上下车是事务：先定位，再切换`
> 　　　审核 `audit/godot/vehicle.md#19`

## 0. 交付物定义

⚠ **本步的关键不是"能上车"，是"反复切换不出事"。**

⛔ 常见假完成：上下车一次成功就过——
⚠ 但缺少冷却会让快速按键触发**状态反复翻转**，
且顺序错了会**丢失角色位置**，⛔ 表现为掉出地图。

做完这一步，应该能**当场演示**：

1. 上下车**位置正确**（在车门旁，不是车中心）
2. ⚠ 连按 100 次**不崩溃、不漂移**
3. ⛔ 切换有**冷却**，不会同帧反复触发
4. ⚠ 事务顺序：先定位角色 → 再切换控制
5. ⛔ 切换期间**输入不串台**（角色与车不同时响应）

**产出物**（下游按名字对接）：

```text
try_enter(vehicle) / try_exit()
SWITCH_COOLDOWN: float   # ⛔ 必设，防同帧翻转
# 顺序：定位角色 → 设控制者 → 切输入上下文
```

## 2. 工序

### Step 1　⛔ 禁止 reparent 角色到载具　`[vehicle/06#S1]`

【读】`howto/godot/vehicle.md#9. 上下车是事务：先定位，再切换`

【做】角色**不**作为载具子节点；上车时隐藏并跟随。

⛔ reparent → 角色的物理体仍在世界 →
与车身互挤 → 表现为"上车后车抖/人被弹飞"，
⛔ 且不报错。

【产出】角色保持独立

【判据】⛔ 场景树里角色**不是**载具子节点

【审】`audit/godot/vehicle.md#19`

### Step 2　⚠ 先定位角色，再切换控制　`[vehicle/06#S2]`

【读】`howto/godot/vehicle.md#9. 上下车是事务：先定位，再切换`

【做】先把角色放到下车点，再交还控制权。

⛔ 顺序反了（先切控制再定位）→ 定位发生在控制已交还之后 →
角色位置被移动逻辑覆盖 → 表现为"下车后人回到原点"。

【产出】事务顺序

【判据】⚠ 下车后角色**站在车门旁**

【审】`audit/godot/vehicle.md#21`

### Step 3　⛔ 必须有切换冷却　`[vehicle/06#S3]`

【读】`howto/godot/vehicle.md#9. 上下车是事务：先定位，再切换`

【做】设 `SWITCH_COOLDOWN`，冷却内忽略新请求。

⛔ 无冷却 → 连按触发同帧多次切换 →
状态翻转、位置抖动，⚠ 表现为"车里车外闪现"。

【产出】冷却机制

【判据】⚠ 连按 100 次**不漂移**

【审】`audit/godot/vehicle.md#20`

### Step 4　⛔ 切换期间输入不串台　`[vehicle/06#S4]`

【读】`howto/godot/vehicle.md#7. 待核对项（运行时验证）`

【做】切输入上下文，保证同一时刻只有一方响应。

⛔ 不切 → 角色与车同时响应 W →
表现为"上车后角色还在跑"或"车走了人也在走"，
⚠ 排查时不会想到是输入上下文。

【产出】输入上下文切换

【判据】⚠ 上车后按 W，**只有车动**

【审】`audit/godot/vehicle.md#22`

### Step 5　⚠ 载具不可用时的降级　`[vehicle/06#S5]`

【读】`howto/godot/vehicle.md#9. 上下车是事务：先定位，再切换`

【做】车毁/满员/距离不足时，上车请求被拒并给出反馈。

⛔ 静默失败 → 玩家按了没反应，
⚠ 表现为"上车键坏了"，实际是条件不满足。

【产出】拒绝反馈

【判据】⚠ 不满足条件时**有明确反馈**

【审】`audit/godot/vehicle.md#24`

### Step 6　⚠ 网络下的控制者同步（如适用）　`[vehicle/06#S6]`

【读】`howto/godot/vehicle.md#7. 待核对项（运行时验证）`

【做】明确控制者是本地判定还是服务器权威。

⛔ 不定义 → 多端抢控制权 →
表现为"两个人同时开一辆车，方向打架"。

【产出】控制者约定

【判据】⚠ 同一时刻**只有一个**控制者

【审】`audit/godot/vehicle.md#22`

**④ 输入串台。** 人和车一起动。
