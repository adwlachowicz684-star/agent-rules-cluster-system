# 载具 / 驾驶 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只是"有个能开的车" | 01 → 02 → 03 → 07 |
| 车要有手感（悬挂/防翻） | 01 → 02 → 03 → 04 → 07 |
| 能带人（多人乘员） | 01 → 02 → 05 → 07 |
| 能上下车、切车 | 01 → 02 → 05 → 06 → 07 |
| 飞行/船舶等非轮式载具 | 01 → 07（+ 见下） |
| 全套（轮式载具） | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **不要因为"开放世界都有车"就全做。**
⚠ 04（物理调参）是工作量分水岭——
悬挂/重心/防翻车要反复实车试，
⛔ 而这些在"只要能动就行"时完全不需要。

ⓘ **非轮式载具不要套本域的 02–04：**
`VehicleBody3D` 是**轮式**载具的专用节点，
⛔ 拿它做飞行器/船 = 悬挂系统对空输出，
行为不可控且白费 CPU。
飞行器/船应走 `RigidBody3D` + 自定义力，
本域只有 01/05/06/07 适用于它们。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 载具模型定性 | — | 类型判据 + 用哪个根节点 |
| 02 | 车身与车轮节点 | 01 | `VehicleBody3D` + 四个 `VehicleWheel3D` |
| 03 | 输入与驱动 | 02 | 引擎力/刹车/转向的持续属性 |
| 04 | 物理调参与稳定性 | 03 | 重心 + 悬挂四元组 + 防翻 |
| 05 | 载具碰撞与乘员 | 02 | `Area3D` 乘员检测 + 独立乘员状态 |
| 06 | 上下车与切换事务 | 05 | 定位→退出→生成/传送 事务 |
| 07 | 载具验收 | 全部 | 高速/落地/上下车压力实测 |

⚠ **01 必须在一切之前**：类型定错，后面全错，且**症状延迟暴露**。
⚠ **02 必须在 03 之前**：没有车轮节点，驱动无从施加。
⚠ **06 依赖 05**：没理清乘员状态，上下车必然乱。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `physics.md` 物理 | 地面摩擦与本域 `friction_slip` 的关系 |
| `movement-advanced.md` 移动 | 角色上下车时的移动状态机交接 |
| `input-remap.md` 输入 | 载具输入走同一套 action，不另起 InputMap |
| `netsync-advanced.md` 网络 | 载具同步的是**控制输入**还是**物理状态** |
| `camera-cutscene.md` 相机 | 载具相机不用 `SpringArm` 硬跟，见 04 |
| `save-migration.md` 存档 | 载具存的是 transform + 控制者，不存物理中间量 |
| `level-design.md` 关卡 | 载具生成点与可行驶区域 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**，
⛔ 不许在各处偷偷转格式。

⚠ **各功能点自己的验收不能替代集成验收** ——
部件全合格、拼起来不能用，是跨域开发的典型失败。

## 3. 本域最容易做反的顺序

⛔ **先做驱动（03）再做车轮（02）。**

"按 W 车往前走"是最直观的验收点，
于是先写输入 → 找不到施力对象 →
⚠ 就在 `VehicleBody3D` 上 `apply_force()` 凑。

⛔ 后果链：
手写力 → 没有悬挂 → 车贴地滑行像滑板 →
为了修它又加射线检测 → 与 `VehicleWheel3D` 自带的射线**重复** →
两套悬挂互相打架，抖动且不可调。

✅ 正确顺序：先把车轮节点与悬挂（02）钉死，再谈输入（03）。
