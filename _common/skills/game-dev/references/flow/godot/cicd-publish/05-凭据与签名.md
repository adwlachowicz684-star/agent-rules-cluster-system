# 05 凭据与签名（CI/CD 与导出发布域）

> **本步交付**：Secret 清单 + 签名三步 + 轮换口径
> **对应**：流程 `howto/godot/cicd-publish.md` · 审核 `audit/godot/cicd-publish.md`

## 0. 交付物定义

1. 仓库里**不含任何密钥、keystore、令牌**
2. 二进制凭据走 base64 后再存 Secret
3. **fork PR 不注入 Secret** 的约定已确立
4. 密码走环境变量，⛔ 不写进 `export_presets.cfg`
5. macOS 完成签名 → 公证 → **装订票证**三步
6. 凭据有轮换周期，且**过期前**能发现

## 1. 前置检查清单

- [ ] 仓库全历史里搜不到密钥文件
- [ ] keystore 以 base64 形式存 Secret
- [ ] PR 事件默认不注入 Secret
- [ ] 密码在环境变量里，不在预设文件里
- [ ] macOS 三步齐全（含 staple）
- [ ] 凭据有到期提醒

## 2. 工序

### Step 1　密钥绝不进仓库，⛔ Git 历史里删不掉　`[cicd-publish/05#S1]`

【读】`howto/godot/cicd-publish.md#凭据一律走 Secret`

【做】
签名密钥、商店令牌、密码一律不放仓库。
⛔ 放过一次 —— **从 Git 历史里删不掉**，
⛔ 只能轮换凭据，而轮换要重新签名、重新提交商店。

ⓘ 检查方式要覆盖历史，不只是当前工作树：
⛔ 只看当前分支的"文件不存在"会给出安全的假象。

【产出】凭据清单（全部在 Secret 里，无一份在仓库）

【判据】全历史搜索密钥文件名 / 特征串无命中。

【审】`audit/godot/cicd-publish.md#8`

### Step 2　二进制 keystore 不能直接存 Secret，先 base64　`[cicd-publish/05#S2]`

【读】`howto/godot/cicd-publish.md#凭据一律走 Secret`

【做】
Secret 是文本，二进制 keystore 要先 base64 编码再存，
用时在 CI 里还原。
⛔ 直接存 —— 二进制被破坏，⛔ 而报错发生在签名阶段，
表现为"签名失败"，排查被引向签名配置而非凭据损坏。

ⓘ 还原后要校验文件本身可用（不是只看文件存在）：
⛔ 一个损坏的 keystore 也是"存在"的。

【产出】base64 还原步骤 + 还原后的可用性校验

【判据】CI 用还原出的 keystore 能成功签名。

【审】`audit/godot/cicd-publish.md#7`

### Step 3　fork PR 不注入 Secret　`[cicd-publish/05#S3]`

【读】`howto/godot/cicd-publish.md#凭据一律走 Secret`

【做】
PR 事件**默认不注入 Secret**（防 fork PR 窃取）。
需要 Secret 的构建走 `push` 或手动触发。
⛔ 给 fork PR 开 Secret —— 任何人提个 PR 就能拿到凭据，
⛔ 且泄露后同样**只能轮换**。

ⓘ 这条与"想让 PR 也能出包"的诉求冲突：
⛔ 折中方案是在 PR 上只做"不需要凭据"的那部分（导入、测试、无签名导出），
⛔ 而不是放宽 Secret 注入。

【产出】工作流触发条件与 Secret 注入的对照表

【判据】PR 工作流里取不到任何 Secret 环境变量。

【审】`audit/godot/cicd-publish.md#29`

### Step 4　密码走环境变量，⛔ 不写进导出预设　`[cicd-publish/05#S4]`

【读】`howto/godot/cicd-publish.md#3.3 Android 高频坑`

【做】
Android 签名信息用环境变量覆盖（如 `GODOT_ANDROID_KEYSTORE_DEBUG_PATH`
/ `..._PASSWORD` / `..._USER`），CI 友好。
⛔ 写进 `export_presets.cfg` —— 该文件**可安全入库**，
⛔ 密码随之入库，等于 Step 1 白做。

ⓘ 这里有个容易混的点：
预设文件本身不该保密，所以"把密码填进预设"看起来很自然，
⛔ 但自然不等于安全 —— 正是因为它会入库，才不能放密码。

【产出】环境变量清单（密码类全部在其中）

【判据】预设文件里搜索不到任何密码串。

【审】`audit/godot/cicd-publish.md#30`

### Step 5　macOS 是三步：签名 → 公证 → 装订票证　`[cicd-publish/05#S5]`

【读】`howto/godot/cicd-publish.md#3.2 各平台要点`

【做】
macOS 发布要走完**签名 → 公证 → staple（装订票证）**。
⛔ 只签名不公证 —— **Gatekeeper 仍会拦截**，
表现为用户双击提示"已损坏"或"无法验证开发者"。

ⓘ 三步里最容易漏的是 staple：
⛔ 签名和公证都做了、看着完成了，
而用户首次离线打开时仍被拦截，⛔ 排查被引向"个别机器问题"。

【产出】三步脚本 + staple 的执行确认

【判据】在一台干净的 Mac 上首次打开无拦截（含离线）。

【审】`audit/godot/cicd-publish.md#9`

### Step 6　凭据要有到期提醒，⛔ 过期才发现等于丢失发布窗口　`[cicd-publish/05#S6]`

【读】`howto/godot/cicd-publish.md#发布检查清单`

【做】
记录每份凭据的到期时间，在到期**之前**提醒并留出轮换时间。
⛔ 过期才发现 —— 签名失败发生在发布当天，
⛔ 商店审核排队白排，发布窗口直接丢失。

ⓘ 轮换要提前演练一次：
⛔ 第一次轮换往往会发现"某个地方还硬编码着旧凭据"，
⛔ 而这个发现发生在发布当天代价最大。

【产出】凭据到期表 + 提前提醒 + 轮换演练记录

【判据】在凭据到期前完成过一次完整轮换。

【审】`audit/godot/cicd-publish.md#31`

## 3. 参考实现

```yaml
# ⓘ 承接本步产出：base64 还原 + 仅 push 注入
# ⛔ PR 事件默认不注入 Secret
- name: 还原 keystore
  if: github.event_name == 'push'
  env:
    KEYSTORE_B64: ${{ secrets.ANDROID_RELEASE_KEYSTORE_B64 }}
  run: |
    echo "$KEYSTORE_B64" | base64 -d > $HOME/release.keystore
```

```bash
# ⓘ 承接本步产出：macOS 三步，staple 不可漏
codesign --sign "Developer ID" --options runtime Game.app
ditto -c -k --keepParent Game.app Game.zip
xcrun notarytool submit Game.zip --wait
xcrun stapler staple Game.app      # ⛔ 漏了这步，离线首次打开仍被拦截
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 密钥进过仓库 | 只能轮换，删不掉 | S1 |
| 签名失败但配置没变 | keystore 二进制损坏 | S2 |
| 提 PR 就能拿凭据 | fork PR 注入了 Secret | S3 |
| 密码随预设入库 | 密码写进了预设文件 | S4 |
| Mac 上提示"已损坏" | 只签名未公证/未装订 | S5 |
| 发布当天签名失败 | 凭据过期 | S6 |
