# 02 CI 地基：无头运行与导入产物（CI/CD 与导出发布域）

> **本步交付**：可复现的导入步骤 + 缓存策略 + 版本锁定口径
> **对应**：流程 `howto/godot/cicd-publish.md` · 审核 `audit/godot/cicd-publish.md`

## 0. 交付物定义

1. CI 首次 clone 后**必定**执行导入步骤
2. `.import` 入库、`.godot` 不入库的约定已确立
3. CI 镜像的 Godot 版本与本地**严格一致**（含 beta/rc）
4. 导入缓存的 key 覆盖所有影响导入结果的文件
5. 无头环境**不用于验证画面**的口径已写下

## 1. 前置检查清单

- [ ] CI 第一步是 `--headless --import --quit`
- [ ] `.import` 已入库，`.godot/` 已在忽略列表
- [ ] 镜像 tag 与本地引擎版本完全一致
- [ ] 缓存 key 含 `.import` / `.tscn` / `project.godot`
- [ ] 没有把无头跑的"渲染测试"当通过

## 2. 工序

### Step 1　CI 首次 clone 必须显式导入，⛔ 不是"跑一下就有了"　`[cicd-publish/02#S1]`

【读】`howto/godot/cicd-publish.md#导入产物：CI 必须重新导入`

【做】
CI 流水线的固定第一步：
`godot --headless --import --quit`。
⛔ 忘了它是最常见的 CI 失败原因 ——
表现为"资源找不到"或"纹理全黑"，⛔ 而本地完全正常。

ⓘ 根因是 `.godot/` 整体不入库（体积大），
所以新机器 clone 后**没有导入产物**，必须现场生成。

【产出】CI 导入步骤（在所有后续步骤之前）

【判据】在一个全新 clone 的干净目录里跑流水线能通过。

【审】`audit/godot/cicd-publish.md#1`

### Step 2　`.import` 必须入库，`.godot/` 必须不入库　`[cicd-publish/02#S2]`

【读】`howto/godot/cicd-publish.md#导入产物：CI 必须重新导入`

【做】
`.import` 文件（导入参数元数据）提交进版本控制，
`.godot/` 整体忽略。
⛔ 不提交 `.import` —— 每个人的导入参数不一致，
纹理压缩与过滤方式在不同机器上产生不同结果，⛔ **而 diff 看不出来**。

ⓘ 这条的表现尤其隐蔽：它不会让构建失败，
只会让"这台机器出来的包和那台不一样"，
⛔ 排查时必然被引向"某台机器环境有问题"。

【产出】版本控制规则（`.import` 入库 / `.godot/` 忽略）

【判据】换一台机器导入，产出的 `.import` 内容与已入库的一致。

【审】`audit/godot/cicd-publish.md#2`

### Step 3　CI 镜像的 Godot 版本要与本地严格一致　`[cicd-publish/02#S3]`

【读】`howto/godot/cicd-publish.md#完整可抄的 GitHub Actions`

【做】
容器镜像 tag 锁定到**具体版本**（含 beta / rc），与本地开发版本一致。
⛔ 用浮动 tag 或不锁 —— 行为差异会让"本地能跑 CI 红"，
⛔ 或更糟的"CI 绿但产物不对"，后者没有失败信号。

ⓘ 升级引擎时这条要一起改：
⛔ 只升级本地、CI 滞后，会有一段时间内两者行为不同，
而这期间的 CI 结论都不可信。

【产出】镜像 tag 与本地版本的对照（含升级时同步改的清单）

【判据】CI 日志里的引擎版本字符串与本地 `godot --version` 完全一致。

【审】`audit/godot/cicd-publish.md#13`

### Step 4　导入缓存的 key 要覆盖所有影响导入结果的文件　`[cicd-publish/02#S4]`

【读】`howto/godot/cicd-publish.md#完整可抄的 GitHub Actions`

【做】
缓存 key 至少包含 `**/*.import`、`**/*.tscn`、`project.godot` 的哈希。
⛔ key 只写 `project.godot` —— 改了场景或导入参数**缓存不失效**，
一直用旧导入产物，⛔ 表现为"改了纹理设置但产物没变"，且不报错。

ⓘ 反向也成立：key 写得太宽会让缓存永远不命中，
表现为"每次全量导入很慢"，⛔ 那是性能问题不是正确性问题，两者别混。

【产出】缓存 key 定义 + 失效验证方式

【判据】改一个 `.tscn` 后缓存失效并重新导入。

【审】`audit/godot/cicd-publish.md#19`

### Step 5　无头环境不能验证画面，⛔ 别把"跑通"当"跑对"　`[cicd-publish/02#S5]`

【读】`howto/godot/cicd-publish.md#1. 无头运行`

【做】
写下无头环境的能力边界：能做导入、跑项目、导出、跑脚本、日志与文件 IO；
⛔ **不能做**：无窗口、无 GPU、**无法验证画面**、无音频输出。
⛔ 在无头里跑"渲染测试"并当通过 —— 画面相关断言从未真正执行，
⛔ 这是**假通过**，比不测更危险，因为它给出"测过了"的信号。

ⓘ 冒烟测试要用 `--quit-after N`：
⛔ 它是**帧数不是秒数**，写 600 表示跑 600 帧。

【产出】无头能力边界清单 + 冒烟测试的帧数口径

【判据】无"渲染断言在无头环境通过"这类结论。

【审】`audit/godot/cicd-publish.md#18`

## 3. 参考实现

```bash
# ⓘ 承接本步产出：导入 → 缓存 key → 版本锁定 → 冒烟
# 镜像 tag 锁定到具体版本，⛔ 不用 latest
# image: barichello/godot-ci:4.3

godot --headless --import --quit

# 冒烟：--quit-after 是帧数，不是秒数
godot --headless --path . --quit-after 600
```

```yaml
# ⓘ 承接本步产出：缓存 key 覆盖全部影响导入的文件
- uses: actions/cache@v4
  with:
    path: .godot
    key: godot-import-${{ hashFiles('**/*.import', '**/*.tscn', 'project.godot') }}
```

## 4. 验收清单

- [ ] 全新 clone 跑流水线能通过
- [ ] `.import` 入库、`.godot/` 忽略，换机器导入结果一致
- [ ] CI 与本地引擎版本字符串一致
- [ ] 改 `.tscn` 后缓存失效
- [ ] 无"渲染断言在无头通过"的结论

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| CI 上资源找不到 / 纹理全黑 | 忘了 `--import` | S1 |
| 不同机器出的包不一样 | `.import` 没入库 | S2 |
| 本地能跑 CI 红 | 镜像版本不一致 | S3 |
| 改了纹理设置产物没变 | 缓存 key 不全 | S4 |
| 无头里渲染测试"通过" | 无 GPU，断言从未执行 | S5 |
