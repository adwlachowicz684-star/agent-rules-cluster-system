# 07 发布与验收（CI/CD 与导出发布域）

> **本步交付**：发布门禁 + 回滚路径 + 变更日志
> **对应**：流程 `howto/godot/cicd-publish.md` · 审核 `audit/godot/cicd-publish.md`

## 0. 交付物定义

1. 包内 / CI / 商店后台三处版本号一致
2. **每个平台**的产物都被实际启动过（⛔ 不是"导出成功"）
3. release 版跑过完整流程（⛔ 不是只测 debug）
4. 变更日志已更新，能支撑版本回退定位
5. 有回滚路径，⛔ 不是"出问题就热修"

## 2. 工序

### Step 1　三处版本号复核一致　`[cicd-publish/07#S1]`

【读】`howto/godot/cicd-publish.md#版本号`

【做】
发布前复核：包内读取的版本号、CI 日志里的、商店后台填的，三者一致。
⛔ 散落三处 —— 必然不同步，⛔ **且不报错**。

ⓘ 表现为"崩溃日志报的版本对不上用户装的版本"，
⛔ 排查时会去查崩溃上报 SDK，而不会想到是版本号源头分叉。

【产出】三处版本号的对照记录

【判据】三处字符串完全相同。

【审】`audit/godot/cicd-publish.md#14`

### Step 2　每个平台的产物都实际启动过　`[cicd-publish/07#S2]`

【读】`howto/godot/cicd-publish.md#发布检查清单`

【做】
逐个平台**启动**产物并走到主场景。
⛔ 只验"导出成功" —— 那是命令层面的判断，
⛔ 与"能启动"在 Godot 里会给出相反结论（见 06）。

ⓘ 无头环境无法验证画面，所以这一步**必须有人工环节**：
⛔ 全部自动化会留下"构建绿但游戏开不了"的盲区。

【产出】各平台启动记录（含启动者与时间）

【判据】每个平台都有一次真实的启动到主场景的记录。

【审】`audit/godot/cicd-publish.md#17`

### Step 3　release 版跑一遍完整流程，⛔ 不是只测 debug　`[cicd-publish/07#S3]`

【读】`howto/godot/cicd-publish.md#2. CI 流水线`

【做】
用 release 产物跑一遍核心流程（进主场景、存档读档、联网、支付沙盒）。
⛔ 只测 debug —— release 下 `assert` 被剥离、优化行为不同，
⛔ 表现为"debug 一切正常，release 崩溃"，
⛔ 而崩溃点通常不在真正出问题的代码里。

ⓘ 尤其要测**存档读写**：
它同时踩到"release 优化"与"`res://` 只读"两条，
⛔ 是"编辑器全好、出包全丢"最集中的一处。

【产出】release 版核心流程实测记录

【判据】release 产物能存档、重开能读回。

【审】`audit/godot/cicd-publish.md#12`

### Step 4　变更日志要能支撑版本回退定位　`[cicd-publish/07#S4]`

【读】`howto/godot/cicd-publish.md#版本号`

【做】
变更日志按版本记录改了什么、涉及哪些平台。
⛔ 没有或只写"修复若干问题" ——
版本回退时**无法定位是哪个改动引入**，只能逐个二分，
⛔ 而二分每个版本都要重新出包与验证，代价随时间线性增长。

ⓘ 平台维度尤其重要：
⛔ 一个只在 Web 上出现的问题，在没有平台标注的日志里几乎定位不到。

【产出】按版本 + 按平台的变更日志

【判据】指着任一历史版本能说出它改了什么、影响哪些平台。

【审】`audit/godot/cicd-publish.md#36`

### Step 5　回滚路径要先有，⛔ 不能默认"出问题就热修"　`[cicd-publish/07#S5]`

【读】`howto/godot/cicd-publish.md#发布检查清单`

【做】
发布前就准备好回滚方式（上一版本产物可重新分发、商店支持回退）。
⛔ 没有回滚路径 —— 出问题只能热修，
⛔ **而热修本身没被验证过**（见 `hotupdate` 域），
⛔ 等于用一个未经验证的通道去修一个正在发生的事故。

ⓘ 回滚与热修的选择要在**出事前**定好：
⛔ 事故中临时决定，会倾向选热修（看起来更快），
而热修的验证成本恰恰在事故中最高。

【产出】回滚方案（含上一版本产物的存放位置与分发方式）

【判据】能在不重新构建的前提下拿到上一版本可分发产物。

【审】`audit/godot/cicd-publish.md#37`

## 3. 验收清单

- [ ] 三处版本号一致
- [ ] 每个平台产物都被实际启动过
- [ ] release 版跑过核心流程，存档可读回
- [ ] 变更日志按版本 + 平台可追溯
- [ ] 回滚路径已备好，无需临时构建

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 崩溃日志版本对不上 | 版本号分叉 | S1 |
| 构建绿但游戏开不了 | 只验导出成功 | S2 |
| debug 好、release 崩 | 只测 debug | S3 |
| 回退时逐个二分 | 变更日志不可用 | S4 |
| 事故中只能热修 | 没有回滚路径 | S5 |
