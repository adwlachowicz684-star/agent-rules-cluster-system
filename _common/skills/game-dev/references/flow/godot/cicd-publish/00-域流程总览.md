# CI/CD 与导出发布 —— 域流程总览

> ⚠ **第 0 步：先定"交付给谁、哪几个平台"。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 第一次把游戏打出包 | 01 → 02 → 03 → 06 → 07 |
| 接 CI 自动构建 | 01 → 02 → 06 → 07 |
| 加一个导出平台 | 01 → 03 → 04 → 05 → 06 → 07 |
| 签名 / 凭据接入 | 03 → 05 → 06 |
| 完整发布流水线 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过** ——
平台矩阵决定**主语言与渲染后端**（Web 不支持 C#、WebGL2 无 normal-roughness buffer），
⛔ 而这两项是立项时定、后期无法低成本更改的。
先配好各平台预设再定平台矩阵，等于**每个平台重配一遍**。

⛔ **06 的产物校验不能最后补** ——
Godot 导出失败**仍然以退出码 0 退出**（GH-83042）。
⛔ 先接 CI 再补校验，等于有一段时间 CI 长期全绿却根本没有产物，
而这段时间里所有"CI 通过"的判断都是假的。

⛔ **04 的文件包含边界要在第一个配置表进项目之前定**：
非资源文件（`.json` / `.csv` / `.txt`）**不会自动进包**，
⛔ 等本地化与配置表铺开再补过滤器，表现为"编辑器全好、出包全空"，
而报错是"文件打不开"，⛔ 排查方向必然被引向路径拼写。

ⓘ 若本次只是**"改一下版本号重新出包"**，那是发布操作，不套本域，看 07。
ⓘ 若只是**排查 CI 红**，先看是导入失败（02）还是导出失败（03 / 06）。

ⓘ 分工：
- `howto/godot/cicd-publish.md` 讲**各平台的技术做法**（无头命令、预设字段、纹理格式）
- `howto/godot/platform-export.md` 讲**导出预设本身的字段与平台配置**
- 本域讲**这些做法按什么顺序做、怎么保证"CI 绿"等于"真的有产物"**

⛔ 若本域某步需要"构建超时""缓存保留天数"这类细节，
指向项目实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 交付边界与平台矩阵 | — | 平台矩阵 + 产物清单 + 版本单一数据源 |
| 02 | CI 地基：无头运行与导入产物 | 01 | 可复现的导入步骤 + 缓存策略 + 版本锁定口径 |
| 03 | 导出预设与模板版本 | 01 | 预设入库公约 + 模板严格匹配校验 |
| 04 | 资源包含与文件边界 | 01, 03 | 非资源文件清单 + 只读路径口径 + 纹理格式校验 |
| 05 | 凭据与签名 | 03 | Secret 清单 + 签名三步 + 轮换口径 |
| 06 | 平台差异与产物校验 | 02, 03, 04 | 产物非空校验 + 各平台启动实测 |
| 07 | 发布与验收 | 全部 | 发布门禁 + 回滚路径 + 变更日志 |

⚠ **01 要在第一次配导出预设之前**：
那时矩阵还没定，预设里的语言、渲染后端、纹理格式都是待定项。

⚠ **04 要在第一张配置表进项目之前**：
表一旦铺开，补过滤器的同时还要回头确认哪些文件其实没进过包。

⚠ **05 的 Secret 清单要随平台同步加，不能发布前统一补**：
补的时候容易把凭据临时写进配置文件"先跑通一次"，而那次提交进了 Git 历史。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是单个平台，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `platform-export` 域 导出平台 | 预设字段与各平台配置见 `platform-export`，⛔ 本域只定**顺序与校验** |
| `testing` 域 测试 | 测试怎么跑见 `testing`，⛔ 本域只定"测试在流水线的哪一步、失败是否阻断" |
| `compliance` 域 合规 | Bundle ID、签名主体、隐私清单见 `compliance`，⛔ 本域不另定合规口径 |
| `mobile` 域 移动端 | 移动端适配与权限见 `mobile`，⛔ 本域只定 Android/iOS 的**产物校验** |
| `hotupdate` 域 热更新 | PCK 产物与补丁生成见 `hotupdate`，⛔ 本域只定整包产物的边界 |
| `datatable` 域 配置表 | 配置表怎么设计见 `datatable`，⛔ 本域定**它能不能进包**（04） |
| `i18n` 域 本地化 | 文本资源组织见 `i18n`，⛔ 本域定本地化文件的包含声明（04） |
| `save` 域 存档 | 存档路径见 `save`，⛔ 本域只定导出后 `res://` 只读、必须走 `user://` |
| `security` 域 安全 | 凭据泄露的检测见 `security`，⛔ 本域只定 Secret 的存放与注入方式 |
| `version-migration` | ⓘ howto 层，暂无 flow 域 —— 引擎版本升级的兼容检查见该篇 |
| `project-governance` | ⓘ howto 层，暂无 flow 域 —— 仓库与协作规范见该篇 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `IMPORT_TIMEOUT` 导入步骤超时 | 02 | — | — | 待实测（与项目资源量相关） |
| `EXPORT_TIMEOUT` 单平台导出超时 | 06 | — | — | 待实测（与资源量与是否含 C# 相关） |
| `MIN_ARTIFACT_BYTES` 产物最小体积阈值 | 06 | — | — | 待实测（⛔ 不能写 0，写 0 等于没校验） |
| `CACHE_RETENTION_DAYS` 导入缓存保留天数 | 02 | — | — | 待实测 |
| `SMOKE_FRAMES` 冒烟测试帧数（`--quit-after`） | 06 | — | — | 待实测（⛔ 是帧数不是秒数） |
| `CRED_ROTATE_DAYS` 签名凭据轮换周期 | 05 | — | — | 待实测（与商店要求相关） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发构建超时""偶发产物为空"，
⛔ 而这类偶发在测试环境几乎不出现。
