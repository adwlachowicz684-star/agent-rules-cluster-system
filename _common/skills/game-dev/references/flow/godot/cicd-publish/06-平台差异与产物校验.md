# 06 平台差异与产物校验（CI/CD 与导出发布域）

> **本步交付**：产物非空校验 + 各平台启动实测
> **对应**：流程 `howto/godot/cicd-publish.md` · 审核 `audit/godot/cicd-publish.md`

## 0. 交付物定义

1. **退出码 0 不被当作成功信号**
2. 每个产物都有"存在且非空"校验，阈值⛔ 不是 0
3. Web 产物经 HTTP 服务验证（含 COOP / COEP）
4. macOS 的 `.dmg` / `.zip` 差异已被理解，未因此改配置
5. Android / iOS 在**真机**上验证过

## 1. 前置检查清单

- [ ] 没有把"命令成功"当"产物成功"
- [ ] 产物体积校验的阈值大于 0
- [ ] Web 用 HTTP 服务打开过，不是 file://
- [ ] 没有人因为扩展名差异去改导出配置
- [ ] 移动端在真机上跑过

## 2. 工序

### Step 1　退出码 0 不等于成功，⛔ 这是本域最基础的判断　`[cicd-publish/06#S1]`

【读】`howto/godot/cicd-publish.md#3.7 预设名大小写敏感，且导出失败退出码仍是 0`

【做】
把"退出码 0"从成功信号里移除：
Godot 导出失败**仍然返回 0**（GH-83042）。
⛔ 依赖退出码 —— CI 全绿但产物不存在，
⛔ 且这段时间内所有"CI 通过"的结论都是假的。

ⓘ 正确信号是**产物本身**：
存在、非空、能启动。三者逐级加强，⛔ 不能只做第一级。

【产出】成功判据的定义（产物级，非命令级）

【判据】故意让导出失败，CI 报红而不是绿。

【审】`audit/godot/cicd-publish.md#32`

### Step 2　校验产物存在且非空，⛔ 阈值不能写 0　`[cicd-publish/06#S2]`

【读】`howto/godot/cicd-publish.md#完整可抄的 GitHub Actions`

【做】
每个产物做体积校验，阈值按平台实测设定。
⛔ 阈值写 0 或不校验 —— 0 字节产物也算通过，
⛔ 等于把 S1 修好的漏洞又开回来。

ⓘ 阈值要分平台：
⛔ 用一个统一数字会让小平台（Web）永远通过、大平台（桌面）误报，
⛔ 而误报一多，团队会把这条校验删掉。

【产出】各平台的产物体积阈值

【判据】人为产出一个 0 字节文件，CI 报红。

【审】`audit/godot/cicd-publish.md#4`

### Step 3　Web 产物必须经 HTTP 服务验证，⛔ 不能用 file://　`[cicd-publish/06#S3]`

【读】`howto/godot/cicd-publish.md#3.4 Web 的限制`

【做】
Web 产物用本地 HTTP 服务打开验证（⚠ 不能用 `file://`）。
多线程构建还需服务器发送
`Cross-Origin-Opener-Policy: same-origin` 与
`Cross-Origin-Embedder-Policy: require-corp`。
⛔ 用 `file://` —— wasm 加载失败白屏，
⛔ 而报错是**跨域**，不是路径错，排查方向被引向资源路径。

ⓘ 这条与 S1/S2 互补：
产物存在且非空，但仍可能打不开 ——
⛔ 字节数检查发现不了"能下载但跑不起来"。

【产出】Web 产物的本地 HTTP 验证步骤（含响应头）

【判据】浏览器里能真正启动到主场景。

【审】`audit/godot/cicd-publish.md#33`

### Step 4　macOS 产物在 CI 上是 .zip、本地是 .dmg，⛔ 别去改配置　`[cicd-publish/06#S4]`

【读】`howto/godot/cicd-publish.md#3.2 各平台要点`

【做】
理解并写下：在 macOS 上导出得到 `.dmg`，
在 Linux / Windows 上导出得到 `.zip`，**两者都含 `.app`**。
⛔ 因为"CI 上扩展名不一样"去改配置 —— 改出的是真问题，
⛔ 而原本的"不一致"是正常平台差异。

ⓘ 这类"看着像 bug 的正常差异"值得单独记：
⛔ 修它会引入真 bug，而不修只是看着别扭。

【产出】各平台产物形态对照（含已知的"正常差异"）

【判据】无人因扩展名差异修改导出配置。

【审】`audit/godot/cicd-publish.md#34`

### Step 5　移动端必须真机验证，⛔ 编辑器正常说明不了任何问题　`[cicd-publish/06#S5]`

【读】`howto/godot/cicd-publish.md#3.3 Android 高频坑`

【做】
Android / iOS 在真机上安装并运行：
权限、纹理格式、触控、性能全部只在真机上成立。
⛔ 只在编辑器测 —— 表现为"编辑器全好、真机全黑"或"真机网络全失败"，
⛔ 而这两类在编辑器里**永远测不出来**。

ⓘ 真机验证要覆盖**冷启动**：
⛔ 热更新与首次安装的资源路径行为不同，
⛔ 只测覆盖安装会漏掉首次安装的问题。

【产出】真机验证记录（权限、纹理、触控、冷启动）

【判据】真机冷启动后纹理正常、网络可用、触控响应正确。

【审】`audit/godot/cicd-publish.md#35`

## 3. 参考实现

```bash
# ⓘ 承接本步产出：产物级校验，⛔ 不看退出码
mkdir -p build
godot --headless --export-release "Linux/X11" build/game.x86_64

# ⛔ 阈值不能写 0；按平台实测设定
MIN_BYTES=1048576
sz=$(stat -c%s build/game.x86_64 2>/dev/null || echo 0)
if [ "$sz" -lt "$MIN_BYTES" ]; then
    echo "产物缺失或过小: $sz"
    exit 1
fi
```

```bash
# ⓘ 承接本步产出：Web 走 HTTP，不用 file://
python3 -m http.server 8000 --directory build/web
# ⛔ file:// 打开会白屏，且报的是跨域错误
```
