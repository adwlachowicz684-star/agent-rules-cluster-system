# 03 导出预设与模板版本（CI/CD 与导出发布域）

> **本步交付**：预设入库公约 + 模板严格匹配校验
> **对应**：流程 `howto/godot/cicd-publish.md` · 审核 `audit/godot/cicd-publish.md`

## 0. 交付物定义

1. 导出模板版本与编辑器**严格一致**（含 beta / rc），且有校验步骤
2. `export_presets.cfg` 已入库且**只用相对路径**
3. `export_credentials.cfg` 不入库的后果已被显式处理
4. 预设名与 CI 命令里的字符串**完全一致**，且有校验
5. `custom_template` 若使用，其路径形式已验证生效

## 1. 前置检查清单

- [ ] 有一步校验"模板版本 == 编辑器版本"
- [ ] `export_presets.cfg` 已入库，里面没有绝对路径
- [ ] 凭据文件缺失的处理方式已写下（⛔ 不是"跑不通再说"）
- [ ] CI 里的预设名与预设文件里的 `name=` 完全一致
- [ ] `custom_template` 若填了，已验证产物确实变了

## 2. 工序

### Step 1　模板版本必须严格匹配，含 beta / rc　`[cicd-publish/03#S1]`

【读】`howto/godot/cicd-publish.md#3.1 模板版本必须严格匹配`

【做】
导出模板版本 == 编辑器版本，**含 beta / rc / dev**。
在 CI 里加一步校验，而不是靠人记。
⛔ 用 stable 模板导 dev 构建 —— 失败或产出异常，
⛔ 而异常产物**能正常启动**，只是行为不对。

ⓘ 升级引擎后必须重新下载对应模板：
⛔ 只升引擎不换模板，是"升级之后 CI 全红"最常见的成因。

【产出】模板版本校验步骤（失败即阻断）

【判据】故意把模板换成别的版本，CI 在导出前就红。

【审】`audit/godot/cicd-publish.md#5`、`audit/godot/cicd-publish.md#6`

### Step 2　预设名要完全一致，⛔ 大小写出错是静默失败　`[cicd-publish/03#S2]`

【读】`howto/godot/cicd-publish.md#3.7 预设名大小写敏感，且导出失败退出码仍是 0`

【做】
CI 里的 `--export-release "Windows Desktop"` 必须与
`export_presets.cfg` 里的 `name=` **完全一致**（含空格与大小写）。
⛔ 写成 `"Windows"` —— 导出失败，**且退出码仍是 0**。

ⓘ 含空格或特殊字符必须加引号（官方要求）。
⛔ 这条与"退出码 0"叠加后最危险：
两个静默点相乘，结果是 CI 全绿、无产物、无任何线索。

【产出】预设名清单 + 与 CI 命令的对照校验

【判据】把预设名故意改一个字母，CI 报红而不是静默通过。

【审】`audit/godot/cicd-publish.md#20`

### Step 3　`export_presets.cfg` 入库，且只用相对路径　`[cicd-publish/03#S3]`

【读】`howto/godot/cicd-publish.md#凭据的真实存放处：export_credentials.cfg`

【做】
`export_presets.cfg` 提交进版本控制（官方：可安全入库，通常不含需保密的内容），
⛔ 且**只用相对路径**。
⛔ 用绝对路径 —— 团队里路径不同的人导出失败，CI 上同样失败，
⛔ 而报错指向的是路径不存在，不会提示"应该用相对路径"。

ⓘ 官方口径值得记住：真正需要保密的是 `.godot/export_credentials.cfg`，
不是预设文件本身。⛔ 把两者混为一谈会导致"不敢入库预设"，
于是每个人的预设各写一份，⛔ 行为不一致且不报错。

【产出】入库的预设文件（无绝对路径）+ 忽略规则

【判据】换一台机器、换个目录 clone，仍能导出。

【审】`audit/godot/cicd-publish.md#21`

### Step 4　凭据文件不入库，其缺失要显式处理　`[cicd-publish/03#S4]`

【读】`howto/godot/cicd-publish.md#凭据的真实存放处：export_credentials.cfg`

【做】
`.godot/export_credentials.cfg` 存密码与加密密钥，**不入库**。
因此 clone 到新机器后**部分导出选项会缺失** ——
官方给的补救是**从旧机器手动拷贝该文件**。
⛔ 不显式处理 —— 表现为"本地能导出、CI 导出行为不同"，
⛔ 而缺失是"选项不在了"，不是报错。

ⓘ 这与 05 的 Secret 注入是两件事：
Secret 解决自动化注入，这里解决"选项缺失导致的行为差异"。
⛔ 只做前者会漏掉后者。

【产出】凭据文件缺失的处理约定（拷贝方式 / CI 注入方式）

【判据】新机器上导出选项齐全，无需人工逐项补。

【审】`audit/godot/cicd-publish.md#22`

### Step 5　`custom_template` 填相对路径会静默失效　`[cicd-publish/03#S5]`

【读】`howto/godot/cicd-publish.md#3.7 预设名大小写敏感，且导出失败退出码仍是 0`

【做】
若用了 `custom_template`（自定义导出模板），
⛔ **填相对路径会静默回退到默认模板，且没有任何警告**。
⛔ 表现为"改了自定义模板但产物没变"，
而配置面板上路径确实填着，⛔ 排查方向被引向模板内容本身。

ⓘ 验证方式不是看配置，是**看产物**：
对比产物体积或内容（例如 `.wasm` 大小）是否真的不同。
⛔ 只看"导出成功"永远发现不了这条。

【产出】自定义模板的路径形式 + 产物级验证方式

【判据】换自定义模板后产物体积/内容确实变化。

【审】`audit/godot/cicd-publish.md#23`

## 3. 参考实现

```bash
# ⓘ 承接本步产出：预设名必须与 export_presets.cfg 的 name= 完全一致
# ⛔ "Windows" 在预设名为 "Windows Desktop" 时静默失败（退出码仍 0）
godot --headless --export-release "Windows Desktop" build/release/game.exe

# ⓘ 模板版本校验：失败即阻断，⛔ 不要等到导出才发现
godot --version
```

```
# ⓘ export_presets.cfg 里只用相对路径；⛔ 绝对路径会让别人导出失败
custom_template/debug=""      # ⛔ 相对路径会静默回退默认模板
```
