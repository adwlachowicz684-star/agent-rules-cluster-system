# 06 退款、风控与审计（商业化域）

> **本步交付**：不可变审计日志 + 退款回收 + 规则可热配
> **对应**：流程 `howto/godot/monetization.md` · 审核 `audit/godot/monetization.md`

## 0. 交付物定义

1. 所有发放 / 回滚 / 退款写**只追加**的审计日志
2. 退款不只是扣货币，还要**回收已发物品**
3. 风控规则可配置，改规则不需要发版

## 1. 前置检查清单

- [ ] 01 已完成（审计日志在第一步就存在）
- [ ] 已定义"可回收"与"不可回收"资产清单
- [ ] 风控阈值与规则存放位置已确定（配置而非代码）

## 2. 工序

### Step 1　审计日志只追加，不可 UPDATE　`[monetization/06#S1]`

【读】`howto/godot/monetization.md#9. 退款、风控与审计日志`

【做】
每次发放 / 回滚 / 退款追加一条记录（时间、账号、订单、动作、数量、前后值）。
⛔ 允许 UPDATE 或 DELETE —— 那就不是审计日志，
⛔ 事后无法自证"当时发了什么"，对账与定责全部失效。

【产出】只追加的审计表 + 保留策略

【判据】尝试 UPDATE 一条记录被拒绝；按账号能完整回放其资产变化。

【审】`audit/godot/monetization.md#36`

### Step 2　退款要回收已发物品，不只扣货币　`[monetization/06#S2]`

【读】`howto/godot/monetization.md#9. 退款、风控与审计日志`

【做】
退款时先枚举该订单发出的所有资产，逐项回收；已被消耗 / 转卖的按规则折算或标记。
⛔ 只把货币扣成负数 —— 已发的道具仍在玩家手里，
⛔ 表现为"退款成功但东西还在"，可被白嫖甚至转卖。

【产出】订单 → 已发资产清单 + 回收规则（含不可回收时的处理）

【判据】构造一笔已发货订单再退款，所有发出的资产都回到未发放状态。

【审】`audit/godot/monetization.md#33`

### Step 3　退款也要写审计日志　`[monetization/06#S3]`

【读】`howto/godot/monetization.md#9. 退款、风控与审计日志`

【做】
退款与发放走**同一条**审计链，只是动作类型不同。
⛔ 退款单独记一处 —— 对账时发放与退款拼不起来，
⛔ 且"退款了多少"成为一笔算不清的账。

【产出】统一的审计动作类型枚举（发放 / 回滚 / 退款 / 回收）

【判据】随机抽 10 个账号，发放总额 − 退款总额 = 当前资产，误差为 0。

【审】`audit/godot/monetization.md#34`

### Step 4　风控规则可热配，不硬编码　`[monetization/06#S4]`

【读】`howto/godot/monetization.md#9. 退款、风控与审计日志`

【做】
阈值（单笔上限、单日上限、频次数、异常地区）放配置，运行时可改。
⛔ 风控阈值写死在代码里 —— 出事时改一个数字要**发版**，
⛔ 而攻击窗口通常在小时级，等发版完损失已扩大。

【产出】风控配置表 + 运行时加载与生效路径

【判据】改一个阈值后无需发版即生效，且改动本身进审计日志。

【审】`audit/godot/monetization.md#37`

### Step 5　区分"可重试失败"的边界：退款不是撤销按钮　`[monetization/06#S5]`

【读】`howto/godot/monetization.md#2. 服务端必须校验的清单`

【做】
退款走平台侧流程，⛔ 不在游戏服务端开一个"撤销订单"的自有接口。
⛔ 自己实现退款 —— 平台账单与游戏数据会**对不上**，
⛔ 且这个接口一旦存在就是新的攻击面。

【产出】退款流程说明（平台侧发起 → 回调 → 服务端回收 → 审计）

【判据】不存在任何"仅凭游戏内请求就能把订单置为已退"的接口。

【审】`audit/godot/monetization.md#21`

### Step 6　对账：订单数与发货数必须能对齐　`[monetization/06#S6]`

【读】`howto/godot/monetization.md#9. 退款、风控与审计日志`

【做】
每日跑一次对账：平台订单数 vs 服务端发货数 vs 审计日志条数。
⛔ 只在出事后才对数 —— 那时数据已被覆盖或超出保留期，
⛔ 且"少发了"和"多发了"在玩家侧的观感完全不同，前者是投诉后者是资损。

【产出】对账任务 + 差异告警

【判据】人为制造一处差异（少发一笔），对账任务能定位到具体订单号。

【审】`audit/godot/monetization.md#34`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：审计只追加；退款由平台侧发起，服务端只回收
# ⛔ 不提供"撤销订单"的自有接口
enum AuditAction { GRANT, ROLLBACK, REFUND, RECLAIM }

func _append_audit(action: AuditAction, order_id: String, delta: int) -> void:
    # ⛔ 只追加：表上无 UPDATE / DELETE 权限
    _audit_store.insert({
        "ts": Time.get_unix_time_from_system(),
        "action": action, "order_id": order_id, "delta": delta,
    })
```

## 4. 验收清单

- [ ] 审计表无 UPDATE / DELETE 路径
- [ ] 退款能回收已发资产
- [ ] 发放与退款同链，可对账
- [ ] 风控阈值可热配且改动进审计
- [ ] 无自有"撤销订单"接口
- [ ] 对账任务能定位人为制造的差异

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 退款后东西还在 | 只扣货币不回收 | S2 |
| 出事改阈值要发版 | 阈值硬编码 | S4 |
| 对不上账 | 退款未进同一审计链 | S3 |
