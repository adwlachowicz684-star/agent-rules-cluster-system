# 01 支付通道与订单地基（商业化域）

> **本步交付**：客户端遥控器定位 + 服务端校验清单 + 幂等订单
> **对应**：流程 `howto/godot/monetization.md` · 审核 `audit/godot/monetization.md`

## 0. 交付物定义

1. 客户端只发起支付、不判定结果，所有判定在服务端
2. 服务端校验清单 7 项逐项落地，每项有**可区分的失败**
3. 订单号幂等，同一笔订单重复提交只生效一次

## 1. 前置检查清单

- [ ] 已选定支付通道（平台 IAP / 第三方 GDExtension）
- [ ] 服务端有订单表与幂等键（唯一索引）
- [ ] ⚠ Android 导出预设已启用 `INTERNET` 权限
- [ ] 已确认审计日志在第一版就要存在（不是事后补）

## 2. 工序

### Step 1　先确认 Godot 没有内置 IAP，客户端只是遥控器　`[monetization/01#S1]`

【读】`howto/godot/monetization.md#0. 第一句话：Godot 没有任何 IAP API`

【做】
在设计文档开头写明：Godot 4.x（含 4.7.2）**没有**内置跨平台 IAP / 支付 / 广告 API，
Class DB 里没有 `StoreKit`、`GooglePlayBilling`、`AdMob` 这类类，
商业化必须靠 **GDExtension 原生桥接**或第三方插件。
⛔ 在 GDScript 里找 `InAppPurchase` 节点 —— 不存在，且不会有报错提示。
⛔ 客户端收到"支付成功"回调就发货 —— 客户端只是**发起支付的遥控器**，判定权在服务端。

【产出】架构约束：客户端职责 = 发起 + 展示；服务端职责 = 校验 + 发货 + 记账

【判据】指着任意一次发货，能说出它是服务端哪段代码决定的，而不是客户端回调。

【审】`audit/godot/monetization.md#1`

### Step 2　服务端校验清单 7 项逐项落地　`[monetization/01#S2]`

【读】`howto/godot/monetization.md#2. 服务端必须校验的清单`

【做】
逐项实现：收据真实性（签名 / 证书链 / `bundle_id` / `product_id` / `transaction_id`）、
订单是否已发货（幂等防重放）、未成年限额与宵禁、
抽奖池对该地区是否开放、发货时余额是否足够、月卡到期按 **UTC** 算、
所有发放 / 回滚 / 退款写**不可变审计日志**。
⛔ 把"校验失败"统一返回同一个错误码 —— 网络失败和"已发货"混为一谈，重试就重复发货。

【产出】校验清单实现 + 每项一个**可区分**的错误码

【判据】模拟 7 项各自失败，客户端收到的错误码两两不同，且都能说出该不该重试。

【审】`audit/godot/monetization.md#2`

### Step 3　订单号与幂等键：不能拿系统时钟拼　`[monetization/01#S3]`

【读】`howto/godot/monetization.md#8. 订单号、幂等键与设备标识`

【做】
订单号由**服务端**下发或用 `Crypto.generate_random_bytes()` 生成随机分量，
幂等键在订单表上建**唯一索引**。
⛔ 用 `Time.get_unix_time_from_system()` 拼订单号 ——
官方明确该系统时钟**用户可手动设置**，且并发下会碰撞。
⛔ 只在应用层判"有没有处理过"而不建唯一索引 —— 并发下两个请求同时通过检查。

【产出】服务端下发的订单号 + 订单表唯一索引

【判据】同一幂等键并发提交 10 次，只成功 1 次，且失败 9 次返回同一个错误码。

【审】`audit/godot/monetization.md#9`

### Step 4　Android 的 `INTERNET` 权限与 `HTTPRequest` 三条官方限制　`[monetization/01#S4]`

【读】`howto/godot/monetization.md#7. 支付通道的 Godot 侧：HTTPRequest 与导出权限`

【做】
Android 导出预设勾选 `INTERNET`；每个请求用**独立** `HTTPRequest` 节点；
显式设置 `timeout`。
⛔ 忘了勾 `INTERNET` —— 官方原话：否则**任何**网络通信都会被 Android 阻断，
表现为支付请求发出去**永不回调**，且不报错。
⛔ 单个 `HTTPRequest` 同时发多个请求 —— 官方明确写着不要这么做。
⛔ 不设 `timeout` —— 官方默认值是 `0.0`，含义是**不超时**，请求可能永远挂着。

【产出】导出预设检查项 + 每请求独立节点 + 显式 `timeout`

【判据】断网 / 弱网下每个请求都有终态（成功或超时回调），没有"永远在转圈"。

【审】`audit/godot/monetization.md#16`

### Step 5　设备标识不能当安全依据　`[monetization/01#S5]`

【读】`howto/godot/monetization.md#8. 订单号、幂等键与设备标识`

【做】
`OS.get_unique_id()` 只用于**数据关联与统计**，⛔ 不用于任何安全判定，
也不用于加密持久化数据。
票据 / 签名比对用 `Crypto.constant_time_compare()`。
⛔ 拿设备 ID 当"这台设备已付过款"的凭证 ——
官方注明该串**可被外部程序伪造**，且重装系统 / 换硬件后会变。
⛔ 用 `==` 比较签名 —— 存在时序侧信道，官方为此提供了 `constant_time_compare()`。

【产出】设备 ID 用途约束（只做关联）+ 签名比对统一走 `constant_time_compare()`

【判据】代码里没有任何一处把设备 ID 用作鉴权或加解密依据。

【审】`audit/godot/monetization.md#18`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：独立 HTTPRequest + 显式 timeout + 只发起不判定
# ⛔ 官方：单个 HTTPRequest 不要并发请求；timeout 默认 0.0 = 不超时
const VERIFY_URL := "https://api.example.com/iap/verify"
const REQUEST_TIMEOUT_SEC := 15.0

func _begin_purchase(product_id: String) -> void:
    var http := HTTPRequest.new()
    http.timeout = REQUEST_TIMEOUT_SEC   # ⛔ 不设则默认 0.0，永不超时
    add_child(http)
    http.request_completed.connect(_on_verify_done.bind(http))
    var body := JSON.stringify({"product_id": product_id})
    var err := http.request(VERIFY_URL, [], HTTPClient.METHOD_POST, body)
    if err != OK:
        push_error("verify request failed to start: %d" % err)
```

## 4. 验收清单

- [ ] 客户端无任何一处自行判定"支付成功"
- [ ] 7 项校验各有可区分错误码
- [ ] 幂等键唯一索引生效，并发 10 次只成功 1 次
- [ ] Android 预设已勾 `INTERNET`
- [ ] 每个请求是独立 `HTTPRequest` 且 `timeout` 非 0
- [ ] 签名比对统一走 `constant_time_compare()`

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 支付无回调、一直转圈 | Android 未开 `INTERNET` 或 `timeout` 为 0 | S4 |
| 重试一次发两次货 | 无唯一索引，只在应用层判重 | S3 |
| 改系统时间能重复领 | 订单号用系统时钟拼 | S3 |
