# 04 广告与激励视频（商业化域）

> **本步交付**：服务端发奖励 + 回调超时与查询 + 幂等
> **对应**：流程 `howto/godot/monetization.md` · 审核 `audit/godot/monetization.md`

## 0. 交付物定义

1. 广告奖励由**服务端**发放，客户端回调只作为"触发"
2. 看完无回调时有超时与主动查询接口兜底
3. 同一回调重放只发一次奖励

## 1. 前置检查清单

- [ ] 01 已完成（服务端权威与幂等键）
- [ ] 广告 SDK 已完成 GDExtension 桥接（Godot 无内置）
- [ ] 服务端有"发放广告奖励"接口且带幂等键

## 2. 工序

### Step 1　奖励必须在服务器发，客户端回调只是触发　`[monetization/04#S1]`

【读】`howto/godot/monetization.md#5. 广告与激励视频`

【做】
看完广告 → 客户端通知服务端 → **服务端**校验并发放奖励。
⛔ 客户端收到回调直接加金币 —— 回调可被伪造 / 断网重放，
伪造成本极低，且表现为"数据很好看"，等发现时损失已发生。

【产出】服务端发放接口 + 客户端只上报"我看了"

【判据】伪造一次客户端回调，服务端**不发放**；真实看完一次，发放一次。

【审】`audit/godot/monetization.md#26`

### Step 2　看完没回调：要有超时与查询接口　`[monetization/04#S2]`

【读】`howto/godot/monetization.md#5. 广告与激励视频`

【做】
客户端看完后起一个超时计时，超时则主动向服务端**查询**该次广告的发放状态。
⛔ 看完没回调就当没看过 —— 玩家白看一次广告，
这是**投诉率最高**的一类问题，且日志里表现为"玩家没看完"。

【产出】超时阈值 + 主动查询接口 + 查询后的状态展示

【判据】模拟回调丢失，玩家在超时后仍能看到奖励到账，或明确看到"正在确认"。

【审】`audit/godot/monetization.md#27`

### Step 3　广告奖励同样要幂等　`[monetization/04#S3]`

【读】`howto/godot/monetization.md#5. 广告与激励视频`

【做】
每次广告曝光由服务端下发唯一 ID，奖励发放以该 ID 为幂等键。
⛔ 广告奖励不判重 —— 同一回调重放即重复发放，
而广告次数远高于内购，重复发放的**放大倍数更大**。

【产出】广告曝光 ID + 服务端幂等发放

【判据】同一曝光 ID 提交 10 次，只发放 1 次。

【审】`audit/godot/monetization.md#28`

### Step 4　无填充（`No Fill`）时的降级与冷却　`[monetization/04#S4]`

【读】`howto/godot/monetization.md#5. 广告与激励视频`

【做】
广告无填充时走**降级路径**（隐藏入口 / 给替代途径），并设置请求冷却。
⛔ 无填充就立刻重试、循环请求 —— 会被平台**限流**，
且表现为"广告一直加载不出来"，玩家以为是游戏坏了。
⛔ 把"看广告"做成唯一获取途径却在无填充时卡死玩法 —— 玩家被永久卡住。

【产出】降级路径 + 请求冷却 + 无填充时的 UI 表现

【判据】模拟无填充，入口按预期隐藏或降级，日志中无高频重试。

【审】`audit/godot/monetization.md#25`

### Step 5　广告频次冷却：防刷与体验的交界　`[monetization/04#S5]`

【读】`howto/godot/monetization.md#5. 广告与激励视频`

【做】
服务端对同一账号的广告奖励设**频次上限与冷却**，客户端只做展示。
⛔ 频次限制写在客户端 —— 可被绕过，且平台侧也会判异常流量。
⛔ 完全不设上限 —— 刷奖励只是一方面，⛔ 更常见的是被平台限流后**所有玩家**都看不了。

【产出】服务端频次规则（可配置）+ 客户端剩余次数展示

【判据】连点 20 次，只有前 N 次发放，且第 N+1 次有明确提示而非静默失败。

【审】`audit/godot/monetization.md#41`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：客户端只上报，服务端发放；超时主动查询
# ⛔ 奖励绝不可以在客户端本地加
const CONFIRM_TIMEOUT_SEC := 12.0

func _on_ad_finished(exposure_id: String) -> void:
    _await_confirm(exposure_id)
    await get_tree().create_timer(CONFIRM_TIMEOUT_SEC).timeout
    if not _confirmed.has(exposure_id):
        _query_reward_status(exposure_id)   # ⛔ 回调丢失的兜底
```

## 4. 验收清单

- [ ] 伪造回调不发放
- [ ] 回调丢失有超时查询兜底
- [ ] 同一曝光 ID 重放只发一次
- [ ] 无填充走降级且有冷却
- [ ] 频次上限由服务端判定

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 玩家白看广告 | 回调丢失无兜底 | S2 |
| 奖励被刷 | 回调伪造 / 不判重 | S1 / S3 |
| 广告突然全服加载失败 | 无填充循环重试被限流 | S4 |
