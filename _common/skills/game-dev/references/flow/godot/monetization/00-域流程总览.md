# 商业化与变现（内购 / 抽卡 / 广告）—— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只接一个内购、买一次金币 | 01 → 02 → 07 |
| 有抽卡 / 扭蛋 / 开箱 | 01 → 03 → 07 |
| 有激励视频广告 | 01 → 04 → 07 |
| 有商城、多档位定价 | 01 → 05 → 07 |
| 要处理退款、风控、合规审计 | 01 → 06 → 07 |
| 全套商业化 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只做广告变现、不做内购的项目，01 也不能跳过** ——
广告奖励同样要服务端发货、同样要幂等。

⚠ 若本次只是**"到账之后的状态"**（VIP 等级、月卡到期、权益发放），
那是 `vip` 域的事，⛔ 不要套本域——
本域管的是**钱怎么进来**，以及进来之后"没丢、没重、没被刷"。

ⓘ 分工：
- `howto/godot/monetization.md` 讲**单个机制怎么实现**（通道、掉单、概率、广告、定价、退款）
- 本域讲**这些机制按什么顺序做、怎么保证不丢钱、不被刷、不下架**

⛔ 若本域某步需要"各地法规的具体条款"这类细节，
指向那篇，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 支付通道与订单地基 | — | 客户端只是遥控器 + 服务端权威 + 幂等订单 |
| 02 | 掉单、补单与本地单据 | 01 | 本地单据持久化 + 重启恢复 + 可重入补单 |
| 03 | 概率抽取与合规公示 | 01 | 服务端随机 + 保底持久化 + 概率同源公示 |
| 04 | 广告与激励视频 | 01 | 服务端发奖励 + 回调超时与查询接口 |
| 05 | 定价、档位与本地化价格 | 01 | 平台档位 + 不自算汇率 + UTC 周期 |
| 06 | 退款、风控与审计 | 01 | 不可变审计日志 + 退款回收 + 限额实现 |
| 07 | 商业化验收 | 全部 | 敌意环境实测 + 合规自查 + 对账 |

⚠ **01 必须在一切之前**：没有服务端权威与幂等订单，
02 的补单会重复发货、03 的保底能被刷、04 的奖励能被伪造。
⚠ **06 依赖 01 的审计日志**：退款要知道当初发了什么，否则无法回收。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `economy` 域 货币 | 发货走 01 的账本单一入口，⛔ 不各自 `gold += n` |
| `vip` 域 订阅状态 | 本域只管**到账**，⛔ 不判断权益、等级与到期 |
| `trade` 域 交易 | 充值所得货币与交易货币**同一本账**，⛔ 不开第二套 |
| `security` 域 防作弊 | 客户端的一切申报都不可信，见 01 |
| `analytics` 域 埋点 | 审计日志即埋点源，见 06 |
| `datatable` 域 配表 | 概率表 / 档位表进配置，⛔ 逻辑不进表 |
| `save` 域 存档 | 本地单据必须持久化到进程外，见 02 |
| `i18n` 域 本地化 | 价格档位与合规文案按地区，见 05 |
| `hotupdate` 域 热更 | ⛔ 商业化逻辑不进热更包，否则可被改价 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**，
⛔ 不许在各处偷偷转格式（那些转换会散落多处，改接口时找不到）。

⚠ **各功能点自己的验收不能替代集成验收** ——
部件全合格、拼起来不能用，是跨域开发的典型失败。

## 3. 本域最容易做反的顺序

⛔ **先做商城 UI 和抽卡动画（05 / 03），再做支付地基（01）。**

"玩家能看到商品并点购买"是最直观的验收点，
于是先搭商城界面、先接配表、先在客户端算概率，
⚠ 而此时订单号还是拿系统时钟拼的、发货还是客户端直接加钱。

⛔ 后果链：
客户端算概率 → 可被改 → 为了修它加服务端校验 →
但订单号不幂等 → 重试一次发两次货 →
于是加"已发货"标记 → 标记存本地 → **清档后重发**。

⚠ 这些补丁会让 01 再也没法正确落地——
因为到处都已经有了"客户端算的支付状态"。

⛔ 同类第二条：**先做广告（04），再补服务端发货。**
广告回调的伪造成本最低，客户端发奖励等于**直接送**，
且表现为"数据很好看"，等发现时损失已发生。

✅ 正确顺序：先把服务端权威与幂等订单（01）钉死，
再谈商城（05）、抽卡（03）、广告（04）。
