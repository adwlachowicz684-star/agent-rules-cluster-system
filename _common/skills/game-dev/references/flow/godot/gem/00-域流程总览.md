# 宝石 / 符文 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只是"装备能插宝石、加了属性" | 01 → 02 → 03 → 07 |
| 有拆卸损耗 / 付费拆卸 | 01 → 02 → 03 → 04 → 07 |
| 有宝石合成升级 | 01 → 02 → 03 → 05 → 07 |
| 有套装 / 共鸣触发 | 01 → 02 → 03 → 06 → 07 |
| 全套（宝石 + 拆卸 + 合成 + 套装） | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **不要因为"别的项目都有"就全做。**
⚠ 每加一个功能点就多一条与经济系统的接缝，接缝越多越难平衡。

ⓘ 若本次只是"符文页/整套切换"（不挂在装备上），
那是**角色侧**的能力系统，⛔ 不要套本域——先看 `class-awaken.md` 与 `economy.md`。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 模型定性 | — | 宝石 / 符文 / 附魔，挂谁身上 |
| 02 | 模板与插槽 | 01 | `GemBase` / `GemInstance` / `SocketSlot` |
| 03 | 镶嵌事务 | 02 | 试算→扣费→提交→回滚 |
| 04 | 拆卸与损耗 | 03 | 明示规则 + 背包容量预检 |
| 05 | 合成与等级 | 02 | 无套利环的合成表 |
| 06 | 套装与共鸣 | 03 | 按槽位去重的判定 |
| 07 | 验收 | 全部 | 资产保全 + 接缝复查 |

⚠ **02 必须在 03 之前**：没有插槽结构，事务无处可写。
⚠ **03 必须在 04/05/06 之前**：它们都是提交阶段内部的分支。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `economy.md` 数值管线 | 镶嵌是 `…→强化→镶嵌→外部buff` 的一环，⛔ 不在管线外累加 |
| `economy.md` 装备实例 | `EquipmentInstance.sockets: Array[SocketSlot]` |
| `flow/godot/inventory/04-移动与原子性.md` 移动事务 | 共用"试算→提交"范式；拆卸前预检背包容量 |
| `class-awaken.md` 转职 | 转职后装备兼容判定要**带上镶嵌的宝石**一起算 |
| `save-migration.md` | 存 `gem_id` + 实例字段；解析失败进隔离区 |
| `netsync-advanced.md` | 客户端只发意图；合成成功率服务端裁决 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**，
⛔ 不许在各处偷偷转格式（那些转换会散落多处，改接口时找不到）。

⚠ **各功能点自己的验收不能替代集成验收** ——
部件全合格、拼起来不能用，是跨域开发的典型失败。

## 3. 本域最容易做反的顺序

⛔ **先做合成再做镶嵌事务。**

合成会大量产生"宝石从哪来、到哪去"的移动，
如果此时没有事务保护，每一次合成失败都是一个资产丢失点——
而且**不崩溃、不报错**，只是东西没了。等到做事务时，
合成的调用点已经散落多处，逐个补事务的成本远高于一开始就有。

✅ 正确顺序：先有事务（03），再让合成（05）调用它。
