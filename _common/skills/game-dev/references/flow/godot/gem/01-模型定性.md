> **前置**：已知道要做什么（见 `00-域流程总览.md` 第 0 节）

> 　　　审核 `audit/godot/gem-rune.md#18`

## 0. 交付物定义

⚠ **这一步不写业务代码，但它是全域地基。**
⛔ 跳过它直接建数据结构，做到一半会发现"换装备后符文没了"或
"宝石跟着角色走"，改动面是**全系统级**的。

做完这一步，应该能**当场回答三句话**：

1. 是 **宝石**（挂装备）/ **符文**（挂角色）/ **附魔**（覆盖式）中的哪一个
2. ⚠ **它挂在谁身上** —— 这是三者唯一可靠的区别
3. 换一件装备后，它还在不在

**产出物**（下游按名字对接）：

```text
GemBase.gem_id / tier / mods / socket_type   # 模板层（配表）
GemInstance.gem_id / instance_id / tier      # 实例层（存档）
```

⚠ 两套都要有。⛔ 只做一套 = 默认选了"宝石不可升级"。

## 2. 工序

### Step 1　⚠ 用"挂谁身上"定性　`[gem/01#S1]`

【读】`howto/godot/gem-rune.md#0. 先分清三件事`

【做】回答一个问题：**换一件装备后，它还在不在**。
- 不在，跟着装备走 → **宝石**
- 还在，属于角色能力 → **符文**
- 新的直接替换旧的，不并存 → **附魔**

ⓘ 判据不是"游戏里叫什么名字"。
⚠ 很多叫"符文"的系统实际是宝石（插在武器上），
叫"宝石"的也可能是符文（符文之语整套切换）。

【产出】一句话定性 + 一条原始需求依据

【判据】⚠ 能指出**需求文档里哪一条**支持这个判断

【审】`audit/godot/gem-rune.md#18`

### Step 2　⛔ 显式排除另外两种　`[gem/01#S2]`

【读】`howto/godot/gem-rune.md#0. 先分清三件事`

【做】把排除的两种**写下来，附业务需求理由**。

ⓘ 三个月后有人提"能不能加个符文页"时，这条记录是唯一能说明
"当时的结构为什么不支持"的东西。

【产出】两条"本次不做 X，因为 Y"

【判据】每条都指向**具体业务需求**，⛔ 不是"太复杂"

【审】`audit/godot/gem-rune.md#18`

### Step 3　⚠ 确认并存还是覆盖　`[gem/01#S3]`

【读】`howto/godot/gem-rune.md#0. 先分清三件事`

【做】确认是"多个并存"还是"新的覆盖旧的"。

ⓘ 覆盖式（附魔）**没有插槽数概念**——
如果按宝石做（建了 sockets 数组），就会得到"只能插一个但代码支持多个"的错配。

【产出】并存 / 覆盖 的明确结论

【判据】⚠ 若为覆盖式，则**不存在** `sockets` 数组；若为并存式，则**必然存在**

【审】`audit/godot/gem-rune.md#18`

### Step 4　⚠ 确认宝石能否升级　`[gem/01#S4]`

【读】`howto/godot/gem-rune.md#1. 宝石是 Resource，不是 Node`

【做】若可合成升级，则 `GemInstance` 必须自带 `tier`（与模板的 `tier` 不同）。

⛔ 只存模板 `tier` 的话，合成升过级的宝石读档后**退回原等级**——
表现为"合成了但下次上线变回去了"。

【产出】`GemInstance.tier` 字段（若可升级）

【判据】⚠ 合成 Lv2 后存档重读，**等级仍为 2**

【审】`audit/godot/gem-rune.md#22`

### Step 5　⚠ 写下验证这三者的最小场景　`[gem/01#S5]`

【读】`howto/godot/gem-rune.md#0. 先分清三件事`

【做】写三个可演示的场景，分别证明"是这一个而不是另外两个"：

| 定性为 | 证明场景 |
|---|---|
| 宝石 | 换一件装备，**原装备上的宝石不跟着走** |
| 符文 | 换一件装备，**符文仍在生效** |
| 附魔 | 再附一次，**旧的被替换**（不是并存） |

ⓘ 这三个场景是 07 验收的输入。⛔ 现在不定，到 07 只能凭感觉。

【产出】三个可演示场景（写进 00 总览第 0 节）

【判据】⚠ 每个场景都能在 10 分钟内手工跑完

【审】`audit/godot/gem-rune.md#18`

## 5. 常见返工

**① 定性时看名词不看归属。** 叫"符文"的实际插在武器上 → 换装就没了。

**② 覆盖式却建了 sockets 数组。** 代码支持多个但设计只允许一个。

**③ 宝石等级只存模板。** 合成后读档退回原等级。
