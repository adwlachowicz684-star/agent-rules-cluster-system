# 06 套装与共鸣（宝石域）

> **前置**：`03-镶嵌事务.md` 已完成
> **本步交付**：跨装备的触发判定，按**槽位去重**而非按总数
> **对应**：做法 `howto/godot/gem-rune.md#6. 套装与共鸣`
> 　　　审核 `audit/godot/gem-rune.md#11`

## 0. 交付物定义

⚠ **"全身镶满红宝石触发额外效果"这类规则，判定要看装备槽位。**

⛔ 只数"红宝石数量"的话，玩家把 6 颗红宝石**全插在一把武器上**也会触发——
而设计意图通常是"分布在多件装备上"。

做完这一步，应该能**当场演示**：

1. 6 颗红宝石全插一把武器 → **不触发**（若设计要求分布）
2. 分布在 6 件装备 → 触发
3. ⚠ 换一件装备后，套装状态**立即重算**
4. 相邻插槽共鸣用**邻接表**，不是 `index+1`
5. 触发状态与属性管线一致（不在管线外累加）

**产出物**（下游按名字对接）：

```text
GemSetRule:      require[{(equip_slot, gem_type)}] / effect
SocketAdjacency: 存在装备定义里（不是靠 index 推导）
_set_active(equip_slots) -> bool   # 纯函数
```

## 2. 工序

### Step 1　⚠ 判定按槽位去重集合　`[gem/06#S1]`

【读】`howto/godot/gem-rune.md#6. 套装与共鸣`

【做】按 `(装备槽位, 宝石类型)` 的**去重集合**算，不是按总数。

⛔ 按总数的话，6 颗全插一把武器也触发。

【产出】`_set_active()` 纯函数

【判据】⚠ 6 颗插一件不触发、分布 6 件触发

【审】`audit/godot/gem-rune.md#11`

### Step 2　⚠ 换装备后立即重算　`[gem/06#S2]`

【读】`howto/godot/gem-rune.md#7. 属性并入统一管线`

【做】装备变更（穿上/脱下/替换）都要触发套装重算。

⛔ 只在镶嵌时重算的话，换一件装备后套装状态是**旧的**——
表现为"明明够了却没触发"，且排查时不会想到去动宝石。

【产出】装备变更也触发重算

【判据】⚠ 换一件装备使条件满足，**套装当场触发**

【审】`audit/godot/gem-rune.md#19`

### Step 3　⛔ 邻接表存在装备定义里　`[gem/06#S3]`

【读】`howto/godot/gem-rune.md#6. 套装与共鸣`

【做】相邻插槽共鸣的邻接关系**存进装备定义**。

⛔ 用 `index+1` 推导的话，换一件装备后 index 指向的插槽
**形状完全不同**——共鸣会在不同装备上错乱触发。

【产出】`SocketAdjacency` 字段在装备定义中

【判据】⚠ 两件插槽数相同的装备，**邻接关系可以不同**

【审】`audit/godot/gem-rune.md#12`

### Step 4　⚠ 触发效果并入属性管线　`[gem/06#S4]`

【读】`howto/godot/gem-rune.md#7. 属性并入统一管线`

【做】套装效果是管线的一环，⛔ 不在管线外累加。

⛔ 管线外累加 → 下次重算被覆盖，
表现为"套装刚触发变强了，打一场又变回去"。

【产出】套装效果在管线内的固定位置

【判据】⚠ 卸下一件装备使套装失效后，结果与"从未触发过"**逐字段相等**

【审】`audit/godot/gem-rune.md#13`

### Step 5　⚠ 触发状态要可追溯　`[gem/06#S5]`

【读】`howto/godot/gem-rune.md#9. 服务端权威`

【做】记录哪些 `(槽位, 宝石)` 参与了触发，供排查与客服查询。

⛔ 不记录的话，玩家问"为什么没触发"时**无法回答**——
只能让他自己数，而他自己数的结果与你代码算的可能不一致。

【产出】触发来源清单

【判据】⚠ 任一时刻都能列出**参与触发的具体槽位与宝石**

【审】`audit/godot/gem-rune.md#23`

## 5. 常见返工

**① 按总数判定。** 全插一件也触发。

**② 只在镶嵌时重算。** 换装备后状态是旧的。

**③ `index+1` 推导邻接。** 换装备后错乱。

**④ 管线外累加。** 打一场又变回去。
