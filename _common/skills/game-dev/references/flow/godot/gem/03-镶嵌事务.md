> **前置**：`02-模板与插槽.md` 已完成

> 　　　审核 `audit/godot/gem-rune.md#6`

## 0. 交付物定义

⚠ **这是全域唯一有外部副作用的一步**，也是唯一会**丢玩家资产**的一步。

⛔ 两个直觉顺序都会丢东西：

| 顺序 | 失败时的后果 |
|---|---|
| 先删宝石 → 再插新的 | 中间态失败则宝石**凭空消失** |
| 先插 → 再扣费 | 镶了没扣成，**白嫖** |

做完这一步，应该能**当场演示**：

1. 插槽类型不匹配 → 点不动，**且宝石未被消耗**
2. ⚠ 人为让提交失败 → **宝石与金币完整退回**
3. 覆盖镶嵌 → 是**一次原子替换**，不是先删后插
4. 并发连点两次 → **只扣一次、只镶一次**
5. ⚠ 镶嵌后**立即**重算并广播（面板当场变化）

**产出物**（下游按名字对接）：

```text
try_socket(p, equip_inst, slot_idx, gem_inst) -> {ok, reason?, preview?}
  ├─ _validate()     # 纯判断，无副作用
  ├─ _simulate()     # 纯函数，返回变更清单（预览与提交共用）
  ├─ _begin_cost() / _rollback_cost() / _commit_cost()
  └─ _apply()        # 唯一写 sockets 的地方
```

## 2. 工序

### Step 1　⛔ 顺序写死：校验 → 试算 → 扣费 → 提交 → 回滚　`[gem/03#S1]`

【读】`howto/godot/gem-rune.md#3. 镶嵌是事务：顺序不能错`

【做】五段严格顺序，**不可调换**：

```gdscript
if not _validate(p, equip, slot_idx, gem): return {"ok": false, ...}
var preview = _simulate(equip, slot_idx, gem)   # ① 试算：零副作用
var tx = _begin_cost(p, gem)                    # ② 扣费：唯一外部副作用
var before = equip.sockets.duplicate(true)
if not _apply(equip, slot_idx, gem):            # ③ 提交
    _rollback_cost(tx); equip.sockets = before  # ④ 回滚
    return {"ok": false, ...}
_commit_cost(tx)
return {"ok": true, "preview": preview}
```

ⓘ 试算必须**零副作用**——它还要被预览复用（04/06），
有副作用的话"打开预览界面"就会扣东西。

【产出】`try_socket()` 骨架，五段顺序固定

【判据】⚠ 注入异常让 `_apply` 失败，宝石与金币**完整退回**

【审】`audit/godot/gem-rune.md#6` `audit/godot/gem-rune.md#7`

### Step 2　⛔ 覆盖镶嵌必须原子替换　`[gem/03#S2]`

【读】`howto/godot/gem-rune.md#3. 镶嵌是事务：顺序不能错`

【做】算出**新的 sockets 数组** → 校验 → 整体写回。

⛔ **绝不能"先删旧的再插新的"**——中间态失败则宝石凭空消失。

【产出】整体替换路径，⛔ 无"先删后插"的代码

【判据】⚠ 全项目搜索"移除宝石"的独立调用，**结果为 0**（只存在于整体替换内）

【审】`audit/godot/gem-rune.md#5`

### Step 3　⚠ 预览与提交共用同一函数　`[gem/03#S3]`

【读】`howto/godot/gem-rune.md#3. 镶嵌是事务：顺序不能错`

【做】`_simulate()` 是纯函数，预览和提交**都调它**。

⛔ 预览算一遍、提交再算一遍 → 两边漂移，
表现为"预览说加 10 攻，镶完只加了 8"。

【产出】`_simulate()` 纯函数

【判据】⚠ 连续调用两次，**返回值完全相等**（可序列化比对）

【审】`audit/godot/gem-rune.md#20`

### Step 4　⚠ 回滚用深拷贝　`[gem/03#S4]`

【读】`howto/godot/gem-rune.md#3. 镶嵌是事务：顺序不能错`

【做】`before = equip.sockets.duplicate(true)`，在提交**之前**取。

⛔ 用浅拷贝 `duplicate()` 会让子资源共享——回滚时改的其实是同一份，
等于没回滚。ⓘ 与 `datatable.md` 的 `duplicate(true)` 注意事项同源。

【产出】回滚路径 + 深拷贝

【判据】⚠ 回滚后 `sockets` 与 `before` **逐字段相等**

【审】`audit/godot/gem-rune.md#6`

### Step 5　⚠ 防连点与并发　`[gem/03#S5]`

【读】`howto/godot/gem-rune.md#9. 服务端权威`

【做】加请求序号或状态锁，未完成前拒绝新请求。

⛔ 没有锁的话连点两次会扣两次、镶两次——
第二次可能把刚镶的又覆盖掉，表现为"点一下没了两个宝石"。

【产出】`_pending` 标记或序号校验

【判据】⚠ 100ms 内连发 3 次，**只成功 1 次、只扣 1 次**

【审】`audit/godot/gem-rune.md#16`

### Step 6　⚠ 提交成功立即刷缓存　`[gem/03#S6]`

【读】`howto/godot/gem-rune.md#7. 属性并入统一管线`

【做】提交成功**立即**调用属性重算并广播变更。

⛔ 只改 sockets 不刷缓存，UI 显示的还是旧面板，
玩家会以为没镶上——然后**再点一次**（见 Step 5 的连点问题）。

【产出】提交成功后的缓存失效调用

【判据】⚠ 镶嵌成功后不切场景，**面板数字当场变化**

【审】`audit/godot/gem-rune.md#19`

## 5. 常见返工

**① 先删后插。** 中间态失败 → 宝石消失，且不报错。

**② 回滚用浅拷贝。** 子资源共享，回滚等于没回滚。

**③ 忘了刷缓存。** 玩家以为没镶上 → 再点 → 连点扣两次。

**④ 预览有副作用。** 打开界面就扣东西。
