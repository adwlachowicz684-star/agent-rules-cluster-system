> **前置**：`02-模板与插槽.md` 已完成（不依赖 03/04）

## 0. 交付物定义

⚠ **合成是经济系统的入口，不是 UI 动效。**
⛔ 合成比与拆卸返还比只要构成闭环，就是**无限刷**的漏洞。

做完这一步，应该能**当场演示**：

1. ⚠ 用脚本穷举合成/拆卸路径，**不存在**产出 > 投入的环
2. 合成失败时材料去向**明确**（全损/保留/返还部分）
3. ⚠ 合成后的宝石 `tier` 在**实例**上（读档不变）
4. 成功率由**服务端**裁决（客户端算 = 改内存必成）
5. 非整数比（5→1）在文案里写明了

**产出物**（下游按名字对接）：

```text
GemFusionRule: from_tier / from_count / to_tier / success_rate
               / on_fail: destroy | keep | partial
GemInstance.tier    # 合成结果落在实例上
```

## 2. 工序

### Step 1　⚠ 穷举验算无套利环　`[gem/05#S1]`

【读】`howto/godot/gem-rune.md#5. 合成：等级与数量`

【做】写脚本穷举：从 N 颗 Lv1 出发，任意组合合成与拆卸，
检查产出总"价值"是否可能超过投入。

⛔ `3 颗 Lv1 → 1 颗 Lv2` 且 `1 颗 Lv2 → 3 颗 Lv1` 无损 = 无限刷。
⚠ 只要存在**任何**与宝石等级相关的任务/成就/排行榜，这就是真实漏洞。

【产出】穷举脚本 + 通过结果

【判据】⚠ 脚本跑完，**无**产出大于投入的路径

【审】`audit/godot/gem-rune.md#9`

### Step 2　⚠ 失败时材料去向必须明确　`[gem/05#S2]`

【读】`howto/godot/gem-rune.md#5. 合成：等级与数量`

【做】`on_fail` 三选一：全损 / 保留 / 返还部分，**写进配表**。

⛔ "没说"会按全损处理，玩家认为被吞。
⚠ 这是合成投诉的第一大来源，且**无法事后追溯**。

【产出】`on_fail` 字段 + UI 文案

【判据】⚠ 合成失败后，材料数量**与文案承诺一致**

【审】`audit/godot/gem-rune.md#10`

### Step 3　⛔ 合成结果落在实例 tier　`[gem/05#S3]`

【读】`howto/godot/gem-rune.md#1. 宝石是 Resource，不是 Node`

【做】合成改的是 `GemInstance.tier`，⛔ 不改模板。

⛔ 只改模板 `tier` 的话，所有同级宝石一起升级——
表现为"我合成了一颗，全服的都升了"。

【产出】合成写 `GemInstance.tier`

【判据】⚠ 合成一颗 Lv2 后，背包里其他 Lv1 **仍是 Lv1**

【审】`audit/godot/gem-rune.md#22`

### Step 4　⛔ 成功率服务端裁决　`[gem/05#S4]`

【读】`howto/godot/gem-rune.md#9. 服务端权威`

【做】`success_rate` 只在服务端 roll，客户端只发意图。

⛔ 客户端算 = 玩家可以改内存必成。

【产出】成功率判定在服务端

【判据】⚠ 客户端改为必成，**服务端结果不变**

【审】`audit/godot/gem-rune.md#16`

### Step 5　⚠ 非整数比要写进文案　`[gem/05#S5]`

【读】`howto/godot/gem-rune.md#5. 合成：等级与数量`

【做】若 `5 颗 → 1 颗` 而拆卸返还 `3 颗`，文案必须说明。

⛔ 玩家会以"材料变少了"为由投诉，而这其实是设计——
**必须写进文案**，否则客服无法解释。

【产出】文案含具体比例

【判据】⚠ 玩家在合成界面能读到"5 颗合 1 颗"

【审】`audit/godot/gem-rune.md#9`

### Step 6　⚠ 合成也走事务　`[gem/05#S6]`

【读】`howto/godot/gem-rune.md#3. 镶嵌是事务：顺序不能错`

【做】合成复用事务骨架：消耗多颗 + 产出一颗，一次原子提交。

⛔ 逐颗消耗再产出的话，中途失败会吃掉一部分材料。
ⓘ 这是 00 总览里"先做事务再做合成"的直接收益——事务已经存在，直接用。

【产出】合成调用事务骨架

【判据】⚠ 注入异常让产出失败，**全部材料退回**

【审】`audit/godot/gem-rune.md#6`

## 5. 常见返工

**① 合成/拆卸构成闭环。** 无限刷。

**② `on_fail` 没定义。** 按全损处理，玩家认为被吞。

**③ 改模板 tier。** 全服同级宝石一起升级。

**④ 成功率客户端算。** 改内存必成。
