# 05 表现层、拖拽与手牌池（卡牌域）

> **本步交付**：`CardView` 是观察者 + 手牌走固定容量池 + 拖拽有重排预算 + 播放节奏不堆积
> **对应**：流程 `howto/godot/genres-card.md` · 审核 `audit/godot/genres-card.md`

## 0. 交付物定义

1. `CardView` 不持有任何对局状态，只观察数据并刷新
2. 手牌视图走**固定容量池**，抽牌只绑定新数据
3. 拖拽只用引擎的三个虚函数，没有自己模拟指针
4. 拖拽期的重排有明确预算，不是每帧全量
5. 表现的播放时长与结算间隔匹配，不堆积

## 1. 前置检查清单

- [ ] `CardView` 里搜不到"当前血量""是否已打出"这类字段
- [ ] 全局搜循环里的 `instantiate()` 结果为 0
- [ ] 拖拽逻辑只在 `_get_drag_data` / `_can_drop_data` / `_drop_data` 里
- [ ] 满手牌拖拽时帧率不掉
- [ ] 连续结算时特效不糊成一团

## 2. 工序

### Step 1　CardView 是观察者，不持有状态　`[card/05#S1]`

【读】``howto/godot/genres-card.md#0. 四层分离``

【做】
`CardView` 只持有"要显示哪张卡"的引用，每次数据变化后整体刷新。
⛔ 不要在视图里存"这张牌现在多少攻" —— 一旦视图有自己的一份，
逻辑改了而视图没收到通知，界面就是**错的**，
⛔ 而它不报错，只表现为"显示与实际不一致"。

ⓘ 读档时这条尤其致命：⛔ 视图持有状态意味着读档后要单独恢复视图状态，
漏一处就是"读档回来卡面显示的是上一局的值"。

【产出】`CardView`（只含引用 + `refresh()`）

【判据】删掉所有视图节点，逻辑仍可跑完一局；⛔ 视图里搜不到对局字段。

【审】``audit/godot/genres-card.md#6``

### Step 2　手牌用固定容量池，抽牌只绑数据　`[card/05#S2]`

【读】``howto/godot/genres-card.md#7. 拖拽 UI``

【做】
手牌区预建固定容量（`HAND_POOL`）的视图，抽牌时取出一个绑定新数据并播入场动画，
弃牌时解绑归还。
⛔ 不要在开局洗牌、整副重抽的循环里 `instantiate()` ——
实例化很贵，一次抽 5 张就掉一帧，
⛔ 表现为"抽牌时卡一下"，而排查往往被引向音效或动画。

ⓘ 池容量要 ≥ `HAND_CAP` 加上"正在播离场动画的 surplus"：
⛔ 恰好等于手牌上限，会在"满手牌打出一张"时取不到视图，
表现为"打出去后新抽的牌没有卡面"，而池子取不到通常返回 `null`。

【产出】手牌视图池（含取/还唯一入口）

【判据】连续抽满再打空 200 次，⛔ 从不出现空卡面；实例化次数为 0。

【审】``audit/godot/genres-card.md#9``

### Step 3　拖拽走引擎的三个虚函数　`[card/05#S3]`

【读】``howto/godot/genres-card.md#7. 拖拽 UI``

【做】
用 `_get_drag_data()` / `_can_drop_data()` / `_drop_data()` 三个虚函数实现拖拽。
⛔ 不要自己在 `_input()` 里模拟指针跟随与放置判定 ——
触摸与鼠标的多点、取消、窗口失焦都要自己处理一遍，
⛔ 表现是"移动端拖到一半松手卡住"，而桌面测试全绿。

ⓘ 放置合法性要在 `_can_drop_data` 里判，不是放下后再回滚：
⛔ 放下再回滚会出现"闪一下再弹回"，
而且回滚不完整时状态就错了 —— 且不报错。

【产出】三个虚函数实现（判定在 `_can_drop_data` 内）

【判据】拖到非法区域时，**不会出现**"先放下再弹回"。

【审】``audit/godot/genres-card.md#28``

### Step 4　拖拽期给重排定预算　`[card/05#S4]`

【读】``howto/godot/genres-card.md#7. 拖拽 UI``

【做】
拖拽期间把布局重排与重绘收敛到每帧一次，并只在必要时做。
⛔ 不要在拖拽的每一帧里改子节点数量或调 `queue_redraw()` ——
`Control` 的子节点数量与布局重算比纹理更耗，
⛔ 表现为"手牌一多，拖拽就掉帧"，
而剖析会指向"某个 `_process`"，看不出是重排。

ⓘ 手牌扇形排列这类"每帧都可能变"的布局尤其要算清：
⛔ 每帧重排整排手牌，牌越多越慢，而 5 张牌时完全看不出来。

【产出】拖拽期的重排预算（每帧上限 1 次 + 脏标记）

【判据】满手牌（10 张）拖拽时帧率与 3 张时一致。

【审】``audit/godot/genres-card.md#10``

### Step 5　表现的播放时长要短于结算间隔　`[card/05#S5]`

【读】``howto/godot/genres-card.md#3. 伤害要生成事件入栈，不要直接调用``

【品】``craft/godot/cheapness.md#4. 节奏类廉价感``

【做】
给结算结果的播放定一条硬约束：**单条反馈的时长不超过相邻两条的间隔**。
⛔ 不要给连锁里的每一步都配一个长特效 —— 100ms 的结算配 500ms 的特效，
下一次结算来时上一次还没播完，堆积起来**糊成一团**，
⛔ 而做的时候觉得很好看，是最难自己发现的一类。
ⓘ 判据是"关掉这个效果，我还能看懂发生了什么吗"：
⛔ 为了炫牺牲可读性，反馈反而变弱。
ⓘ 连锁步数多时要么压缩单条时长，要么合并同类结果 ——
⛔ 只压时长不改结构，长连锁依旧会堆积。

【产出】单条反馈时长上限 + 同类结果合并规则

【判据】连打 10 张牌时，⛔ 屏幕上的特效不叠加；关掉特效仍能看懂结果。

【审】``audit/godot/genres-card.md#29``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const HAND_POOL := 12            # ⛔ 要 ≥ HAND_CAP + 离场动画中的 surplus
const HAND_CAP := 10
const DRAG_REDRAW_BUDGET := 1    # 拖拽期每帧重排上限
const FEEDBACK_MAX_MS := 120     # 单条反馈时长上限（≤ 结算间隔）

var _pool: Array = []
var _used: Array = []
var _layout_dirty := false
var _redraw_used := 0

func acquire_view():
    if _pool.is_empty():
        push_warning("⛔ 视图池耗尽：HAND_POOL 要大于 HAND_CAP")
        return null
    var v = _pool.pop_back()
    _used.append(v)
    return v

func release_view(v) -> void:
    _used.erase(v)
    v.unbind()
    _pool.append(v)

func _process(_d: float) -> void:
    _redraw_used = 0
    if _layout_dirty and _redraw_used < DRAG_REDRAW_BUDGET:
        _relayout_hand()
        _redraw_used += 1
        _layout_dirty = false
```

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 读档后卡面显示上一局的值 | 返工 Step 1（视图持有状态） |
| 抽牌时卡一下 / 偶发空卡面 | 返工 Step 2（循环里实例化 / 池容量不足） |
| 移动端拖到一半松手卡住 | 返工 Step 3（自己模拟指针） |
| 手牌一多拖拽就掉帧 | 返工 Step 4（每帧全量重排） |
| 连锁时特效糊成一团 | 返工 Step 5（反馈时长超过间隔） |
