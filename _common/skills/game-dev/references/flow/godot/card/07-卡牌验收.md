# 07 卡牌验收（卡牌域）

> **本步交付**：同种子可复现 + 连锁不爆栈 + 实例隔离 + 读档自洽 + 满手牌不掉帧
> **对应**：流程 `howto/godot/genres-card.md` · 审核 `audit/godot/genres-card.md`

## 0. 交付物定义

1. 同种子同决策跑两遍，**逐条**结算序列一致
2. 互相触发的两张卡不卡死，且超限有诊断
3. 改一张卡的数值，牌库与弃牌堆的同名卡不变
4. 对局中途存档再读档，三态与计数仍自洽
5. 满手牌拖拽不掉帧、连续结算特效不堆积
6. 关掉全部表现后重算，结果与带表现时一致

## 2. 工序

### Step 1　同种子复现：跑两遍逐条比对　`[card/07#S1]`

【读】``howto/godot/genres-card.md#4. 洗牌必须走同一个 rng 实例``

【做】
用同一个种子 + 同一串决策跑两遍，比对**每一条结算结果**，不是只比最终血量。
⛔ 只比最终数值会漏掉"中间错一步、结果巧合相同"的情况 ——
这类错误在长对局里迟早暴露，但**永远不是在你测的那一局**。
ⓘ 比对时要把洗牌次数也纳进来：
⛔ 只比抽牌序列，多洗一次的情况会表现为"序列不同"，
于是排查被引向 rng，而真正的成因是洗牌次数没记。

【产出】两遍的逐条结算序列（应完全相同）

【判据】逐条一致；⛔ 洗牌次数与日志一致。

【审】``audit/godot/genres-card.md#3``

### Step 2　连锁压力：构造互相触发的两张卡　`[card/07#S2]`

【读】``howto/godot/genres-card.md#2. 效果结算用显式栈，不是信号``

【做】
专门做两张互相触发的卡（A 受伤时触发 B，B 结算又让 A 受伤），打出去。
⛔ 期望是"到达深度上限后停止并留下诊断"，**不是卡死、也不是静默少结算一条**。
ⓘ 这正是"响应链无限递归"的实测形态：栈没有深度保护时，
两条效果会一次次把对方推回栈里，永远清不空。
ⓘ 这条在正常游玩中几乎不会撞上 —— 没人会设计两张互相触发的卡，
⛔ 但玩家的组合会。**必须专门造出来测**。

【产出】超限时的诊断记录（栈内容 + 触发者）

【判据】不卡死；⛔ 诊断能指出是哪两张卡互相触发。

【审】``audit/godot/genres-card.md#11``

### Step 3　实例隔离：改一张，看其余变不变　`[card/07#S3]`

【读】``howto/godot/genres-card.md#8. ⛔ Resource 带缓存``

【做】
开局手牌里放两张同名卡，对其中一张施加"本回合费用 −1"，
然后检查牌库里剩下的同名卡费用。
⛔ 期望是"只有被改的那张变了"。
如果牌库里的也变了，说明用的是 `load()` 缓存里的同一个实例 ——
⛔ 此时检查 `Array[CardData]`、`Resource`、`@export` 全部正常，
因为错的不是类型，是**同一性**。
ⓘ 顺带比对效果数组里的元素 id：
⛔ 只比卡牌实例 id 会漏掉"卡复制了但效果没复制"。

【产出】改前 / 改后 的卡牌与效果实例 id 对照

【判据】牌库与弃牌堆的同名卡费用不变；⛔ 效果元素 id 也各不相同。

【审】``audit/godot/genres-card.md#13``

### Step 4　读档自洽：中途存读，三态与计数仍对　`[card/07#S4]`

【读】``howto/godot/genres-card.md#6. 存档用 Resource，不要用 JSON``

【做】
对局中途存盘再读档，逐项核对：牌库/手牌/弃牌堆的**顺序**与内容、
回合阶段、洗牌次数、种子的当前状态。
⛔ 只测"读档后能继续玩"会漏掉顺序错位，
表现为"读档后这一局和存的时候不一样"，
而存档文件里每个字段看起来都对。
ⓘ 一定要把原 `.tres` 改名后再读一次：
⛔ 不改名时，只存路径的存档仍能读到文件，"只存了路径"这个缺陷完全测不出来。

【产出】存前 / 读后 的三态与计数对照（含改名后重读）

【判据】逐项一致；⛔ 原文件改名后读档仍完整。

【审】``audit/godot/genres-card.md#7``

### Step 5　满手牌与连续结算：帧率与堆积　`[card/07#S5]`

【读】``howto/godot/genres-card.md#7. 拖拽 UI``

【做】
把手牌打到上限后反复拖拽，记录帧率；再连打 10 张牌，看屏幕上的特效。
⛔ 期望是"帧率与 3 张手牌时一致"且"特效不叠加"。
掉帧的成因是每帧全量重排，堆叠的成因是单条反馈时长超过结算间隔 ——
⛔ 两者在 3 张手牌、单次结算时**都完全正常**，
所以只能靠打到上限来测，不能在常规操作里验证。

【产出】满手牌拖拽帧率 + 连打 10 张的特效叠加情况

【判据】帧率不降；⛔ 特效不叠加；关掉特效仍能看懂发生了什么。

【审】``audit/godot/genres-card.md#29``

### Step 6　无头重算：关掉表现后结果一致　`[card/07#S6]`

【读】``howto/godot/genres-card.md#10. 流程：按什么顺序做``

【做】
用同一份日志在无头模式（不建任何视图、不播任何特效）下重算一整局，
与带表现的结果比对。
⛔ 期望是逐条一致。如果不一致，说明表现层参与了结算 ——
这正是 03/S4 "表现绑在逻辑里" 才会出现的情况，
⛔ 而带表现跑时**永远看不出来**，因为表现和逻辑同步发生。
ⓘ 这条同时是服务器校验的前置：
⛔ 服务器天然无头，本地能算、服务器算不出不同结果，联机就无从谈起。
⛔ 本质是要求特效与伤害数字**只由结算结果驱动**：
一旦它们在逻辑里被直接播放，无头模式下就没人播，
而带表现跑时两者同步发生，**永远看不出来**。

【产出】无头与带表现两份逐条结果（应相同）

【判据】逐条一致；⛔ 无头跑完整局不报错。

【审】``audit/godot/genres-card.md#12``


## 3. 验收清单

- [ ] 同种子同决策跑两遍，逐条结算序列一致
- [ ] 互相触发的卡不卡死且有诊断
- [ ] 改一张卡，牌库与弃牌堆的同名卡不变
- [ ] 对局中途读档三态与计数自洽，原文件改名后仍完整
- [ ] 满手牌拖拽不掉帧、连打 10 张特效不叠加
- [ ] 无头重算与带表现结果逐条一致

## 4. 常见返工

| 现象 | 返工到 |
|---|---|
| 回放对不上 | → `02#S2`（混用全局流）/ `06#S5`（只记种子） |
| 偶尔抽到刚弃掉的牌 | → `02#S4`（同帧回抽无口径） |
| 连锁卡死 | → `03#S3`（无深度上限） |
| "受伤时"类效果不生效 | → `03#S2`（直接调用跳过响应链） |
| 效果顺序在不同机器上不同 | → `03#S1`（用信号） |
| 改一张全变 | → `01#S3`（`load()` 缓存） |
| 卡复制了但效果跟着变 | → `01#S4`（数组内子资源没复制） |
| 读档后这局和存时不一样 | → `04#S4`（顺序未持久）/ `06#S4`（只存路径） |
| 自动保存覆盖了另一槽 | → `06#S3`（未改 resource_path） |
| 手牌一多拖拽掉帧 | → `05#S4`（每帧全量重排） |
| 连锁时特效糊成一团 | → `05#S5`（反馈时长超过间隔） |
