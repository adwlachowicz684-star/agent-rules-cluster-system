# 02 牌堆、洗牌与随机源（卡牌域）

> **本步交付**：三个牌堆各自持有 + 随机只有一个源 + 同帧回抽有明确口径
> **对应**：流程 `howto/godot/genres-card.md` · 审核 `audit/godot/genres-card.md`

## 0. 交付物定义

1. `Deck` / `Hand` / `Pile`（弃牌堆）各自持有数组，职责不混
2. 全工程只有一个 `RandomNumberGenerator` 实例参与结果
3. `Array.shuffle()` 的调用点数为 0
4. 牌库空了洗弃牌堆再抽的同帧情形有**明确的书面口径**
5. 种子与洗牌结果能一起进日志，可复现

## 1. 前置检查清单

- [ ] 全局搜 `Array.shuffle` 结果为 0
- [ ] 全局搜裸 `randi()` / `randf()` 的结果为 0（参与结果的部分）
- [ ] 洗牌与抽牌走的是同一个 `rng` 对象
- [ ] "牌库空且弃牌堆非空时抽牌"的行为有文字定义
- [ ] 同种子跑两遍，抽牌序列完全一致

## 2. 工序

### Step 1　三个牌堆各自持有，职责不混　`[card/02#S1]`

【读】``howto/godot/genres-card.md#4. 洗牌必须走同一个 rng 实例``

【做】
`Deck`（未抽）、`Hand`（手牌）、`Pile`（弃牌/消耗）各自持有自己的数组，
移动只走"从一个弹出、推入另一个"的函数。
⛔ 不要用一张总表加状态字段（`card.zone = HAND`）来省三个数组 ——
"抽一张"就变成"扫全表找第一个是 DECK 的"，顺序语义丢失，
⛔ 而"牌库顶"和"牌库里第一张符合的"是两回事，
表现为"检索类效果抽到的牌和预期不一样"，且不报错。

ⓘ 三个数组还带来一个必须现在定的口径：
⛔ **"消耗"与"弃牌"是不是同一个堆** —— 它决定洗弃牌堆时会不会把消耗掉的牌洗回来，
到 06 做存档时才发现分不开，等于重做整个牌堆结构。

【产出】三个容器（含"移动"的唯一入口函数）

【判据】任意一张卡能说清自己当前在哪个数组；⛔ 不存在"同时在两处"。

【审】``audit/godot/genres-card.md#5``

### Step 2　随机只有一个源：实例，不是全局　`[card/02#S2]`

【读】``howto/godot/genres-card.md#4. 洗牌必须走同一个 rng 实例``

【做】
建一个 `rng: RandomNumberGenerator`，对局开始用种子初始化，
洗牌、随机目标、随机弃牌全部走它。
⛔ 不要混用全局 `randf()/randi()` 与 `rng.randf()` ——
这两套是**互相独立的状态**，一部分洗牌走实例、一部分走全局流，
同种子下每次结果都不同，⛔ 而它**不报错**，只表现为"回放对不上"。

ⓘ 参与**结果**的一律用带种子的实例；纯表现（特效角度、飘字抖动）
可以用全局流 —— ⛔ 但要在代码里写清哪边是哪边，
否则后来者加了随机却不知道有这条约定。

【产出】`rng.gd` 单一持有者 + 种子初始化函数

【判据】全局搜裸 `randi()` / `randf()` 结果为 0（表现层除外且有注释）。

【审】``audit/godot/genres-card.md#4``

### Step 3　不用 Array.shuffle()：它走全局状态　`[card/02#S3]`

【读】``howto/godot/genres-card.md#4. 洗牌必须走同一个 rng 实例``

【做】
自己写 Fisher–Yates，逐位用 `rng.randi_range(0, i)` 取值。
⛔ 不要用 `Array.shuffle()` —— 它用的是**全局** RNG 状态，
无法复现、也无法做服务器校验。
表现是"本地回放看着对，服务器重算结果不一致"，
⛔ 而排查必然被引向网络或时序，不会想到是洗牌函数。

ⓘ 洗牌顺序本身也要能被记录：
⛔ 只记种子不记"洗了几次"，重放时只要多洗一次就全线错位，
而它看起来只是"抽牌顺序不同"这种无害差异。

【产出】`shuffle(arr)` 函数（走实例 rng）+ 洗牌计数

【判据】同种子跑两遍，牌库中序列逐位相同。

【审】``audit/godot/genres-card.md#3``

### Step 4　牌库空了洗弃牌堆，同帧口径先定死　`[card/02#S4]`

【读】``howto/godot/genres-card.md#5. 牌库空了重新洗弃牌堆要防同帧回抽``

【做】
先定口径再写代码：`RESHUFFLE_MODE` 二选一 ——
**skip**（本帧判定按洗前处理，本次抽牌直接返回"无牌可抽"）
或 **draw**（洗完立刻抽）。
⛔ 不要"洗完再走一遍抽牌逻辑" —— 会把刚洗进去的同一张抽出来，
表现为"偶尔抽到刚刚弃掉的那张"，而概率很低、几乎测不出来。
ⓘ 显式标记 `is_reshuffling` 是让口径可查的手段，
⛔ 光"洗完再抽"不标记，等于把口径留在运气里。

【产出】`draw()` 函数（含 `is_reshuffling` 分支）

【判据】构造"牌库 0 张、弃牌堆 1 张"的局面，⛔ 抽牌结果符合书面口径且可复现。

【审】``audit/godot/genres-card.md#5``

### Step 5　手牌顺序也是随机的一部分　`[card/02#S5]`

【读】``howto/godot/genres-card.md#4. 洗牌必须走同一个 rng 实例``

【做】
把手牌的排列顺序也纳入"由 rng 决定"的范围，或明确写死"按抽到的先后".
⛔ 不要一边洗牌库一边让 UI 自己按某种顺序摆手牌 ——
回放时牌库序列对了、手牌摆放不同，玩家看到的仍是"这局不一样"，
⛔ 而这类不一致在自动化比对里往往只比数据不比顺序，于是**测不出来**。

ⓘ `HAND_CAP` 要在这一步定下并与 05 的池容量同源：
⛔ 两处各写一个数字，改一处忘另一处，会出现"手牌满了但视图不够"。

【产出】手牌顺序口径（书面的）+ `HAND_CAP` 单一来源

【判据】回放时手牌的**排列**与原始对局逐位一致。

【审】``audit/godot/genres-card.md#17``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const HAND_CAP := 10             # 手牌上限（与 05 的池容量同源）
const RESHUFFLE_SKIP := 0
const RESHUFFLE_DRAW := 1
const RESHUFFLE_MODE := RESHUFFLE_SKIP   # 口径：洗完本帧不回抽（02 参数表登记）

var rng := RandomNumberGenerator.new()
var _deck: Array = []
var _hand: Array = []
var _pile: Array = []
var _is_reshuffling := false
var _shuffle_count := 0

func new_run(seed_str: String) -> void:
    rng.seed = hash(seed_str)
    _shuffle_count = 0

func shuffle(arr: Array) -> void:
    _shuffle_count += 1
    for i in range(arr.size() - 1, 0, -1):
        var j := rng.randi_range(0, i)
        var t = arr[i]; arr[i] = arr[j]; arr[j] = t

func draw():
    if _deck.is_empty():
        if _pile.is_empty():
            return null
        _is_reshuffling = true
        _deck = _pile.duplicate()
        _pile.clear()
        shuffle(_deck)
        if RESHUFFLE_MODE == RESHUFFLE_SKIP:
            _is_reshuffling = false
            return null          # ⛔ 本帧按洗前判定，不回抽
    _is_reshuffling = false
    if _hand.size() >= HAND_CAP:
        return null
    var c = _deck.pop_back()
    _hand.append(c)
    return c
```

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 回放对不上、服务器重算不一致 | 返工 Step 2（混用了全局流） |
| 本地对、服务器不对 | 返工 Step 3（用了 `Array.shuffle()`） |
| 偶尔抽到刚弃掉的牌 | 返工 Step 4（同帧回抽无口径） |
| 回放数据对但手牌摆放不同 | 返工 Step 5（手牌顺序没纳入） |
