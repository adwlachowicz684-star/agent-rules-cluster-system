# 04 回合、时机与目标合法性（卡牌域）

> **本步交付**：触发点被枚举覆盖 + 阶段边界显式 + 结算前校验目标仍合法
> **对应**：流程 `howto/godot/genres-card.md` · 审核 `audit/godot/genres-card.md`

## 0. 交付物定义

1. `Timing` 枚举覆盖了**全部**触发点，没有"时机不明"的效果
2. 回合被切成显式阶段，阶段边界只有一个地方推进
3. 结算每一步前校验目标仍合法，且有快照
4. "同时发生"的情形有书面顺序口径
5. 取消 / 替换 / 抵消有明确定义，不是"让效果自己判"
6. 回合起止的自动效果不漏触发

## 1. 前置检查清单

- [ ] 每个 `Effect` 的 `timing` 都有值，没有"默认就是出牌时"的隐式约定
- [ ] 全局只有一处推进回合阶段
- [ ] 结算里有"目标是否仍合法"的校验点
- [ ] 两张同时死亡的卡，死亡顺序可预期
- [ ] 关掉客户端，服务器单跑一局结果一致

## 2. 工序

### Step 1　把"什么时候触发"枚举出来，别留在注释里　`[card/04#S1]`

【读】``howto/godot/genres-card.md#1. CardData 与 Effect``

【做】
把 `Timing` 枚举补到覆盖全部触发点：出牌时、抽到时、回合开始、
回合结束、死亡时、受到伤害时、被弃掉时……
⛔ 不要留"不写 timing 就是出牌时"这种隐式默认 ——
后来者加一张新卡忘了填，效果就在**错误时机**生效，
⛔ 而它不报错，只表现为"这张牌偶尔提前/延后触发"。

ⓘ 枚举项要能被遍历检查：⛔ 只在文档里列时机，
和没有任何约束一样 —— 需要一个"未分类效果"的告警。

【产出】`Timing` 枚举（含"未指定"项用于告警）

【判据】所有效果的 `timing` 都不是"未指定"；⛔ 新增未填的效果会立即告警。

【审】``audit/godot/genres-card.md#22``

### Step 2　回合切成显式阶段，只有一处推进　`[card/04#S2]`

【读】``howto/godot/genres-card.md#0. 四层分离``

【做】
把一回合切成若干阶段（抽牌 / 出牌 / 结算 / 弃牌 / 结束），
阶段推进只在**一个函数**里发生。
⛔ 不要让各个效果自己改回合状态 ——
"回合结束"被多处推进会出现"结束效果触发两次"，
⛔ 而这正是"对手回合开始时多抽一张"这类反馈的常见成因，
查的时候每一处单独的推进都看起来合理。

ⓘ 阶段边界还要能**被外部观察**：
⛔ 只在内部变量里记阶段，回放与自动化测试无从知道"现在是哪个阶段"。

【产出】`TurnPhase` 枚举 + 唯一的 `advance_phase()`

【判据】全局搜阶段赋值，结果只有一处；⛔ 阶段变化可被外部订阅。

【审】``audit/godot/genres-card.md#23``

### Step 3　每一步结算前校验目标仍合法　`[card/04#S3]`

【读】``howto/godot/genres-card.md#3. 伤害要生成事件入栈，不要直接调用``

【做】
在效果 `resolve()` 开头校验目标：还在场吗？还在原来的牌堆吗？
⛔ 不要"入栈时就一定有效" —— 栈是后进先出的，
前面一条效果可能已经把这张牌送进弃牌堆，
⛔ 表现为"对已离场的牌结算"，数值照改、界面照更新，
只是改的是一个已经不在任何数组里的对象。

ⓘ 传**标识**而不是对象引用：
⛔ 直接把卡牌对象塞进事件，等结算到它时它自己都不知道还在不在场。

【产出】`is_target_valid(ctx, ref)` 校验点（结算循环内每步调用）

【判据】构造"效果 A 弃掉牌 X，效果 B 要给牌 X 加 buff"的场面，⛔ B 被跳过且有记录。

【审】``audit/godot/genres-card.md#24``

### Step 4　"同时发生"要有书面顺序　`[card/04#S4]`

【读】``howto/godot/genres-card.md#2. 效果结算用显式栈，不是信号``

【做】
给"同时死亡""同时触发"定一个顺序规则（如按入场序、按位置、按拥有者），
并写进代码。
⛔ 不要依赖数组的自然顺序 —— 数组顺序随洗牌、移动、读档而变，
同一局面在不同局里顺序不同，
⛔ 表现为"偶尔结果不一样"，而它**不是随机导致的**，于是排查被引向 rng。

【产出】稳定排序键（入场序号 / 位置 id）

【判据】打乱数组顺序后重放同一局面，⛔ 结算结果完全相同。

【审】``audit/godot/genres-card.md#25``

### Step 5　取消与替换的口径先定死　`[card/04#S5]`

【读】``howto/godot/genres-card.md#2. 效果结算用显式栈，不是信号``

【做】
明确"被抵消"是**不结算**、**结算为 0**、还是**替换成别的**，
并在栈里用统一的标记表达。
⛔ 不要让每个效果自己判"我是不是被取消了" ——
三种口径混用会得到"有的卡被抵消后仍触发死亡效果，有的不触发"，
⛔ 而每张卡各自的实现都是自洽的，只有对比时才看出不一致。

ⓘ 替换（"改为抽两张"）尤其要留痕：
⛔ 直接改数值不留痕，回放时无法解释为什么抽了两张。

【产出】`CancelPolicy` 三选一的统一标记 + 结算记录

【判据】同一张卡在"被抵消 / 被替换 / 正常"三种情形下，⛔ 结果都能从记录里解释。

【审】``audit/godot/genres-card.md#26``

### Step 6　回合起止的自动效果不漏触发　`[card/04#S6]`

【读】``howto/godot/genres-card.md#1. CardData 与 Effect``

【做】
在阶段切换点**统一**收集所有 `timing` 匹配的效果入栈。
⛔ 不要在每个卡牌脚本里各自 `_on_turn_start()` ——
新增一张卡就要记得接一次，漏了就是"这张牌的回合开始效果不生效"，
⛔ 而它完全不报错，只有玩到那张牌才发现。

ⓘ 收集顺序也要纳入 Step 4 的排序键：
⛔ 回合开始效果按"谁先被挂上去"触发，等于把顺序交给加载顺序。

【产出】阶段切换时的统一收集函数

【判据】新增一张带回合开始效果的卡，⛔ 不改任何已有脚本即生效。

【审】``audit/godot/genres-card.md#27``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const MAX_DEPTH := 32
const PHASE_DRAW := 0
const PHASE_PLAY := 1
const PHASE_RESOLVE := 2
const PHASE_DISCARD := 3

var _phase: int = PHASE_DRAW
var _enter_order: Dictionary = {}   # 实例 id -> 入场序号（稳定排序键）

func advance_phase() -> void:       # ⛔ 唯一推进点
    _phase = (_phase + 1) % 4
    _collect_by_timing(_phase)

func _collect_by_timing(phase: int) -> void:
    var pending: Array = []
    for c in _all_instances():
        for e in c.effects:
            if e.timing == phase and e.timing != e.Timing.UNSET:
                pending.append({"card": c, "effect": e})
    # ⛔ 稳定排序，不依赖数组自然顺序
    pending.sort_custom(func(a, b): return _enter_order[a.card] < _enter_order[b.card])
    for p in pending:
        _stack.append(p.effect)

func _is_valid(ctx, card_id: int) -> bool:
    return _deck.has_id(card_id) or _hand.has_id(card_id) or _pile.has_id(card_id)
```

## 4. 验收清单

- [ ] 没有 timing 为"未指定"的效果
- [ ] 阶段推进只有一处
- [ ] 对已离场牌的结算会被跳过且有记录
- [ ] 打乱数组顺序后重放，结果相同
- [ ] 新增带回合开始效果的卡不用改已有脚本

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 某张牌偶尔提前/延后触发 | 返工 Step 1（timing 隐式默认） |
| 回合结束效果触发两次 | 返工 Step 2（多处推进阶段） |
| 对已弃掉的牌仍结算 | 返工 Step 3（无目标合法性校验） |
| 同局面偶尔结果不同 | 返工 Step 4（依赖数组自然顺序） |
| 被抵消后行为因卡而异 | 返工 Step 5（取消口径不统一） |
| 新卡的回合开始效果不生效 | 返工 Step 6（各自连接，漏接） |
