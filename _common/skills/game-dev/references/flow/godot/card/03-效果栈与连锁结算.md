# 03 效果栈与连锁结算（卡牌域）

> **本步交付**：连锁走显式栈 + 有深度上限 + 伤害变成事件 + 表现由结果驱动
> **对应**：流程 `howto/godot/genres-card.md` · 审核 `audit/godot/genres-card.md`

## 0. 交付物定义

1. 效果结算走显式栈，全文件没有"用 `signal` 触发效果"
2. 伤害/治疗/抽牌等**会引发响应的动作**都生成事件入栈
3. 栈有深度上限，且有"本轮已响应"标记
4. 表现层只消费结算结果，逻辑内不直接播放
5. 结算结果是可序列化的（供 06 回放与存档）

## 1. 前置检查清单

- [ ] 全局搜"用 `signal` 触发效果"的位置数为 0
- [ ] `take_damage` 的直接调用点数为 0（都改成入栈）
- [ ] 栈深度上限是显式常量，不是隐式靠递归崩
- [ ] 逻辑文件里搜不到 `play(` / `queue_redraw(` 之类表现调用
- [ ] 一次结算能导出一份可比对的结果序列

## 2. 工序

### Step 1　连锁用显式栈，不是信号连接　`[card/03#S1]`

【读】``howto/godot/genres-card.md#2. 效果结算用显式栈，不是信号``

【做】
用 `Array[Effect]` 当栈，`pop_back()` 逐条结算，
新产生的效果 `append_array` 进同一栈（后进先出 = 连锁）。
⛔ 不要用 `signal` 把"受伤时"连到响应者 —— 那样无法控制结算顺序、
无法入栈、无法在中间插入响应、也无法取消。
表现是"两个效果的先后顺序在不同机器上不一样"，
⛔ 而信号连接本身工作正常，检查时每一处都对。

ⓘ 用栈还带来一个现在就要定的口径：
⛔ **同层多个响应按什么顺序入栈**（打出顺序 / 入场顺序 / 位置），
不定就会出现"同样的场面结果不同"，而它不是 bug，是顺序没定义。

【产出】`EffectStack`（含入栈顺序的书面口径）

【判据】同一初始局面跑两遍，结算序列逐条相同。

【审】``audit/godot/genres-card.md#1``

### Step 2　伤害要生成事件入栈，不要直接调用　`[card/03#S2]`

【读】``howto/godot/genres-card.md#3. 伤害要生成事件入栈，不要直接调用``

【做】
把 `target.take_damage(5)` 换成往栈里推一个 `DamageEvent`。
⛔ 不要图省事直接调用 —— 直接调用**跳过整条响应链**，
"受伤时""受到伤害前减半"这类效果一个都不会生效，
⛔ 而伤害数字照常扣、血条照常动，功能看起来完全正常。

ⓘ 判断标准不是"会不会扣血"，是"别的效果有没有机会插手"：
⛔ 只要有一张卡能在某个时机改变结果，这个动作就必须入栈。

【产出】`DamageEvent` / `HealEvent` / `DrawEvent` 等事件类型

【判据】挂一个"受伤时 +1"的效果，直接调用路径也能触发；⛔ 全局搜直接调用为 0。

【审】``audit/godot/genres-card.md#2``

### Step 3　栈要有深度上限与"本轮已响应"标记　`[card/03#S3]`

【读】``howto/godot/genres-card.md#2. 效果结算用显式栈，不是信号``

【做】
`while not _stack.is_empty() and guard < MAX_DEPTH`，
并给每个效果记"本轮已响应"标记。
⛔ 不要靠"递归到栈溢出再崩" —— 两个互相触发的效果会让游戏直接卡死，
⛔ 而且崩溃栈里全是引擎内部帧，看不出是哪两张卡互相触发。
ⓘ 上限触发时**必须留下可诊断的信息**（当前栈内容、触发者），
⛔ 只 `return` 了事会得到"效果偶尔少结算一个"这类最难查的表现。

【产出】带 guard 的结算循环 + 超限时的诊断记录

【判据】构造两张互相触发的卡，⛔ 不卡死、有诊断、其余效果继续结算。

【审】``audit/godot/genres-card.md#11``

### Step 4　表现从结算结果驱动，不在逻辑里播　`[card/03#S4]`

【读】``howto/godot/genres-card.md#3. 伤害要生成事件入栈，不要直接调用``

【做】
结算完成后产出一份 "发生了什么" 的结果列表，表现层照它播放。
⛔ 不要在 `resolve()` 里直接放特效、飘字、音效 ——
结算是**瞬间**的、可被服务器重算的，播放是**有时长**的、只在本地发生的；
绑在一起之后，一旦要做回放或加速，就得把所有表现调用再摘一遍。
ⓘ 表现为"加速模式下特效跟不上""回放时音效乱响"，
⛔ 而单独看每个调用点都合理。

【产出】`EffectResult` 列表（纯数据，无播放调用）

【判据】逻辑文件里搜不到播放类调用；⛔ 无头跑一局不报错。

【审】``audit/godot/genres-card.md#12``

### Step 5　结算结果可序列化，供回放与存档　`[card/03#S5]`

【读】``howto/godot/genres-card.md#6. 存档用 Resource，不要用 JSON``

【做】
让结果列表里的每一项都是 `Resource` 或纯值类型。
⛔ 不要在结果里塞节点引用 —— 节点在存档时根本不存在，
写入时会变成空引用或路径，读档回来是 `null`，
⛔ 而它只在你真的读档时才暴露，本地跑多少局都发现不了。
ⓘ 这一步是 06 的前置：⛔ 到做存档时才发现结果里有节点引用，
等于把整条结果链改一遍。

【产出】结果项的序列化约定（全为 Resource / 值类型）

【判据】把一局的结果列表存成 `.res` 再读回，⛔ 逐项与原始相同。

【审】``audit/godot/genres-card.md#21``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const MAX_DEPTH := 32            # 连锁深度上限
const RESOLVE_GUARD := 512       # 单回合结算步数上限

var _stack: Array = []
var _results: Array = []

func resolve_all(ctx) -> Array:
    var guard := 0
    _results.clear()
    while not _stack.is_empty() and guard < RESOLVE_GUARD:
        guard += 1
        var e = _stack.pop_back()
        if e.depth > MAX_DEPTH:
            push_warning("⛔ 连锁超限: %s" % e.script_name)
            continue                 # ⛔ 不是 return：其余效果继续
        var r = e.resolve(ctx)
        _results.append(r)           # ⛔ 表现只消费这里，不在 resolve 里播
        if r.spawned.size() > 0:
            for s in r.spawned:
                s.depth = e.depth + 1
            _stack.append_array(r.spawned)
    return _results
```

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 效果顺序在不同机器上不同 | 返工 Step 1（用了信号，或入栈顺序没定） |
| "受伤时"类效果不生效 | 返工 Step 2（直接调用了） |
| 互相触发导致卡死 | 返工 Step 3（无深度上限） |
| 加速/回放时表现错乱 | 返工 Step 4（表现绑在逻辑里） |
| 读档后结果里出现 null | 返工 Step 5（结果里塞了节点引用） |
