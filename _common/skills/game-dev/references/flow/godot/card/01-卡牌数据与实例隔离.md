# 01 卡牌数据与实例隔离（卡牌域）

> **本步交付**：`CardData` 是只读定义 + 对局内用复制出来的实例 + 改动边界只有一处
> **对应**：流程 `howto/godot/genres-card.md` · 审核 `audit/godot/genres-card.md`

## 0. 交付物定义

1. 四层职责各写一行，并写了每层**不负责什么**
2. `CardData` / `Effect` 是 `Resource`，卡牌视图是场景，二者没有混用
3. ⛔ 对局内拿到的卡是**复制出来的实例**，不是 `load()` 返回的那个
4. 运行时改数值的边界**只有一处**，能指着说出来
5. 深度复制的写法已按**引擎版本**选定（4.2–4.4 与 4.5+ 不同）

## 1. 前置检查清单

- [ ] 指着任意一处"这张牌本回合减费"的代码，能说出它在哪复制
- [ ] `load()` 与 `duplicate()` 的调用点能全部列出来
- [ ] 手牌、牌库、弃牌堆里的同名卡 `get_instance_id()` **互不相同**
- [ ] 改一张卡的费用，牌库里剩下的同名卡**没有变化**
- [ ] 深度复制的写法有书面的版本依据

## 2. 工序

### Step 1　先分四层：数据层 / 牌堆层 / 结算层 / 表现层　`[card/01#S1]`

【读】``howto/godot/genres-card.md#0. 四层分离``

【做】
把四层的职责各写一行，并写下**每层不负责什么**：
数据层只描述"这张牌是什么"，牌堆层只持有"现在在哪"，
结算层只管"按什么顺序生效"，表现层只观察、**不持有状态**。
⛔ 先写"打出火球掉 5 血"再回头分层 —— 一旦结算层里混进了 `CardView` 的引用，
后面所有"这局能不能复盘"都要靠猜，
而表现层一旦持有状态，**读档后看到的和真实牌堆必然不一致**。

ⓘ 这条定性决定后面所有步：
⛔ 卡牌的"定义"与"这一局里的这张"是两个东西，
混为一谈的表现是改一处全变，而它**不报错**。

【产出】四层职责表（含每层的不负责项）

【判据】指着任意一处数值能说出它属于"定义"还是"这一局的状态"；⛔ 定义没有被就地修改。

【审】``audit/godot/genres-card.md#6``

### Step 2　卡牌是 Resource，视图才是场景　`[card/01#S2]`

【读】``howto/godot/genres-card.md#1. CardData 与 Effect``

【做】
`CardData` 继承 `Resource`，持有 `id / cost / effects / tags`；
`Effect` 也是 `Resource`，持有 `timing`。
只有要显示的 `CardView` 是场景。
⛔ 不要让每张卡都是 `PackedScene` —— 同一张"火球"在牌库、手牌、弃牌堆
各来一份场景实例，内存与实例化时间成倍消耗，
⛔ 而它在手牌少的时候完全看不出来。

ⓘ `effects` 用 `Array[Effect]` 还是直接属性，这一步就要定：
它决定 Step 4 的复制写法能不能用内置 `duplicate()`。

【产出】`card_data.gd` + `effect.gd` 两个 Resource 脚本

【判据】一副 60 张的牌组在内存里只有 60 个 `CardData` 定义对象；⛔ 没有重复的 `Node`。

【审】``audit/godot/genres-card.md#6``

### Step 3　⛔ load() 带缓存：同名卡是同一个实例　`[card/01#S3]`

【读】``howto/godot/genres-card.md#8. ⛔ Resource 带缓存``

【做】
对局开始时把牌组里的每张卡**复制一份**进本局实例表，
之后本局只用这份副本。
⛔ 不要直接用 `load("res://cards/fireball.tres")` 的返回值当"这张牌" ——
官方口径是**加载结果会被缓存，后续同路径的 `load()` 返回同一个对象**。
牌库、手牌、弃牌堆里所有同名卡因此**是同一个实例**，
改一处全变，**且不报错**。

ⓘ 表现是"本回合费用 −1 一生效，牌库里剩下的火球全变 0 费"，
排查时 `Array[CardData]`、`Resource`、`@export` 全部检查都对 ——
⛔ 因为错的不是类型，是**同一性**。

【产出】对局开始时的实例复制函数（含一次性复制的边界说明）

【判据】手牌与牌库里的同名卡 `get_instance_id()` 不同；改一张，其余不变。

【审】``audit/godot/genres-card.md#13``

### Step 4　深度复制的写法按引擎版本选　`[card/01#S4]`

【读】``howto/godot/genres-card.md#9. ⛔ duplicate() 的深拷边界``

【做】
先确认项目的引擎版本，再定写法：
⛔ **不要默认 `duplicate(true)` 就是深拷** ——
数组与字典里的子资源在 **4.2–4.4 不会被复制**（已知问题），
而 `CardData.effects` **正是** `Array[Effect]`。
结果是"卡复制了，效果没复制"：改副本的效果参数，原卡跟着变，
⛔ 这是比完全不复制更难查的形态 —— 检查时 `duplicate()` 确实调了，返回值也确实是新对象。

ⓘ 4.5 起该行为已修正，并新增 `duplicate_deep()`；
同版本的默认 `duplicate()` 语义也变了（数组变成只引用不复制）。
⛔ 所以"抄一段 4.2 时代的写法"在 4.5 上会得到另一种错。

【产出】`clone_card()` 一个函数，内部逐项复制 `effects` 数组

【判据】副本 `effects` 里每个元素与原卡 `get_instance_id()` 都不同。

【审】``audit/godot/genres-card.md#14``

### Step 5　改动边界只有一处，定义全程只读　`[card/01#S5]`

【读】``howto/godot/genres-card.md#9. ⛔ duplicate() 的深拷边界``

【做】
把所有"改卡面数值"的入口收敛到一个函数，函数内部断言目标是**实例不是定义**
（可用 `resource_path` 是否为空来判）。
⛔ 不要在效果里直接 `card.cost -= 1` ——
一旦这张卡是定义，改动会泄漏到牌库、弃牌堆和**下一局**，
而下一局的牌组通常是从同一个定义重新复制的，于是表现为"上局的减费还在"。

ⓘ 只读约定要能被机器查：⛔ 只在注释里写"别改定义"，
和没有任何约束是一样的 —— 需要一处可断言的边界。

【产出】`mutate_card()` 单一入口（含实例断言）

【判据】全局搜对 `cost` 的写操作，结果只有这一处；⛔ 对定义对象调用会立即失败。

【审】``audit/godot/genres-card.md#20``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const MAX_DEPTH := 32            # 连锁深度上限（03 用）
const HAND_CAP := 10             # 手牌上限（02 用）

var _defs: Dictionary = {}       # id -> CardData（只读定义）
var _instances: Array = []       # 本局的实例

func begin_run(card_ids: Array[String]) -> void:
    for id in card_ids:
        _instances.append(clone_card(_defs[id]))

# ⛔ 不用 duplicate(true) 了事：数组内子资源在 4.2–4.4 不复制
func clone_card(src) -> Resource:
    var c = src.duplicate()
    c.effects = []
    for e in src.effects:
        c.effects.append(e.duplicate())
    c.resource_path = ""        # ⛔ 切断与原 .tres 的关联
    return c

# ⛔ 唯一改动入口：定义不可改
func mutate_card(c, key: StringName, value) -> void:
    assert(c.resource_path == "", "⛔ 不能改定义，只能改实例")
    c.set(key, value)
```

## 4. 验收清单

- [ ] 手牌与牌库同名卡 `get_instance_id()` 不同
- [ ] 改一张的 `cost`，牌库剩余同名卡不变
- [ ] 副本 `effects` 内元素也是新对象
- [ ] 对定义调用改动入口会立即失败，不是静默生效

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 减费一开，牌库里的同名卡也变 0 费 | 返工 Step 3（`load()` 缓存，用的是同一个实例） |
| 卡复制了但效果参数跟着原卡变 | 返工 Step 4（数组内子资源没复制） |
| 上一局的改动残留到下一局 | 返工 Step 5（改动落到了定义上） |
