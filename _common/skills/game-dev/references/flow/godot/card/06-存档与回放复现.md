# 06 存档与回放复现（卡牌域）

> **本步交付**：对局状态整体序列化 + 槽位路径显式 + 同种子同输入可复现
> **对应**：流程 `howto/godot/genres-card.md` · 审核 `audit/godot/genres-card.md`

## 0. 交付物定义

1. 对局状态是一个 `Resource`，能整体 `ResourceSaver.save()`
2. 压缩标志只用在**二进制**资源上
3. 多槽位存档的写入路径是显式的，不会写回旧槽
4. 外部子资源随存档一起落盘，不是只留路径
5. 回放 = 种子 + 输入序列，两端重算结果逐位一致

## 1. 前置检查清单

- [ ] 读档后牌堆三态与存前逐位一致
- [ ] 压缩标志没有用在 `.tres` 上
- [ ] 连存两个槽位后，第一个槽位内容没被覆盖
- [ ] 把原 `.tres` 改名，读档仍能拿到完整数据
- [ ] 同种子同输入重放两次，抽牌序列一致

## 2. 工序

### Step 1　存档用 Resource，不用 JSON　`[card/06#S1]`

【读】``howto/godot/genres-card.md#6. 存档用 Resource，不要用 JSON``

【做】
把整局状态（种子、牌堆三态、实例、回合阶段）放进一个 `Resource` 后整体保存。
⛔ 不要用 JSON —— 它无法表达 `Resource` 引用与类型信息，
`effects` 里的 `Effect` **子类**会被拍平成字典，
读回来变成基类，⛔ 表现为"读档后效果还在但行为不对"，
而字段一个都不少。

ⓘ 用 Resource 还要注意一件事：⛔ 存的是实例，别存定义 ——
把定义存进存档，等于把这一局的改动写回模板文件。

【产出】`RunState` Resource（含三态与种子）

【判据】存后改牌、再读档，⛔ 三态与存前逐位一致。

【审】``audit/godot/genres-card.md#7``

### Step 2　压缩标志只对二进制资源有效　`[card/06#S2]`

【读】``howto/godot/genres-card.md#6. 存档用 Resource，不要用 JSON``

【做】
要压缩就把存档存成 `.res`（二进制），再加 `FLAG_COMPRESS`。
⛔ 不要给 `.tres` 加压缩标志 —— 官方口径是
**该标志仅对二进制资源类型可用**，对文本格式无意义。
⛔ 表现为"加了压缩但文件一点没小"，
而代码不报错、保存返回 `OK`，于是没人会去查这个标志。

【产出】存档扩展名与标志的对应约定（书面的）

【判据】`.res` + 压缩后文件明显变小；⛔ 全局搜 `.tres` 与压缩标志同现为 0。

【审】``audit/godot/genres-card.md#8``

### Step 3　槽位路径要显式带走　`[card/06#S3]`

【读】``howto/godot/genres-card.md#6. 存档用 Resource，不要用 JSON``

【做】
保存时显式传目标路径，并显式带上"改变资源路径"的标志
（官方语义：该标志会把资源的 `resource_path` 改成新位置）。
⛔ 不要只写 `save(state, "user://slot2.res")` 就以为换槽了 ——
不带该标志，`state.resource_path` **仍是旧槽位**，
⛔ 之后任何"不带路径的自动保存"都会写回旧槽，
表现为"玩了半天发现覆盖了另一个存档"，且不报错。

ⓘ 自动保存是最容易出事的地方：
⛔ 它天然倾向于 `save(state)`（省事），而这一句写的就是 `resource_path`。

【产出】`save_to_slot(state, slot)`（显式路径 + 显式改路径标志）

【判据】连存 1、2 号槽后，⛔ 1 号槽内容与存 2 号之前一致。

【审】``audit/godot/genres-card.md#30``

### Step 4　外部子资源要一起落盘　`[card/06#S4]`

【读】``howto/godot/genres-card.md#6. 存档用 Resource，不要用 JSON``

【做】
保存时带上"打包外部资源"的标志，或确保状态里的子资源都是**内嵌**的。
⛔ 不要只存外部资源的路径 —— 那样存档文件里只有一行引用，
真正的内容还在原来的 `.tres` 里。
⛔ 一旦原文件变了（换版本、热更、改数值），读档拿到的就是**新的**数据，
表现为"读档后这局和存的时候不一样"，而存档文件本身是完好的。

ⓘ 这一步和 01 的"实例复制"是同一件事的两面：
⛔ 只复制不切断路径，保存时仍会被当成外部资源写回引用。

【产出】打包标志（或内嵌子资源约定）

【判据】把原 `.tres` 改名后读档，⛔ 仍能拿到完整数据。

【审】``audit/godot/genres-card.md#31``

### Step 5　回放 = 种子 + 输入序列　`[card/06#S5]`

【读】``howto/godot/genres-card.md#4. 洗牌必须走同一个 rng 实例``

【做】
日志里同时记：种子、洗牌次数、玩家的每一个决策。
⛔ 不要只记种子 —— 种子只决定"随机"，决定不了"玩家打了哪张牌"，
重放时会因为决策不同而走到完全不同的分支，
⛔ 表现为"回放对不上"，而排查永远被引向随机源。
ⓘ 两端都用同一份日志重算，比对的不是"血量"，是**逐条结算序列**：
⛔ 只比最终数值，中间错一步但结果巧合相同的情况会漏过去。

【产出】`ReplayLog`（种子 + 洗牌计数 + 决策序列）+ 重算比对函数

【判据】同日志重算两次，⛔ **逐条**结算序列一致（不是只比最终值）。

【审】``audit/godot/genres-card.md#32``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const SAVE_SLOTS := 3
const FLAG_NONE := 0
const FLAG_BUNDLE_RESOURCES := 2     # 打包外部资源
const FLAG_CHANGE_PATH := 4          # 改变 resource_path 到新位置
const FLAG_COMPRESS := 32            # ⛔ 仅对二进制资源有效

func save_to_slot(state: Resource, slot: int) -> int:
    var path := "user://run_%d.res" % slot       # ⛔ .res 不是 .tres
    var flags := FLAG_BUNDLE_RESOURCES | FLAG_CHANGE_PATH | FLAG_COMPRESS
    return ResourceSaver.save(state, path, flags)

func autosave(state: Resource, slot: int) -> int:
    # ⛔ 必须带路径：不带路径就写到 resource_path（可能是旧槽）
    return save_to_slot(state, slot)
```

- [ ] `.tres` 与压缩标志不同现
- [ ] 连存两个槽位，第一个未被覆盖
- [ ] 原 `.tres` 改名后读档仍完整

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 读档后效果还在但行为不对 | 返工 Step 1（JSON 拍平了子类） |
| 加了压缩文件没变小 | 返工 Step 2（用在 `.tres` 上） |
| 自动保存覆盖了另一个槽 | 返工 Step 3（没改 `resource_path`） |
| 换版本后读档内容变了 | 返工 Step 4（只存了路径） |
| 回放对不上 | 返工 Step 5（只记种子没记决策） |
