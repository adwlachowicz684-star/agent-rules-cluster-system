# 05 动画接入（角色控制域）

> **前置**：[01-移动基座](01-移动基座.md) + [02-跳跃手感](02-跳跃手感.md) **均已验收**
> **本步交付**：动作与状态严格对上，无滑步、无卡帧、无状态错乱
> **对应**：流程 `howto/godot/animation.md` `animation-skeletal.md` · 审核 `audit/godot/animation.md`

## 0. 交付物定义

能演示：

1. 站着不动 = 待机；跑 = 跑动画；跳 = 跳动画；落地 = 落地动画
2. ⚠ **不滑步**：跑动画的步频与实际移动速度匹配
3. ⚠ **转向不穿帧**：左右转身有过渡，不是瞬间镜像
4. 动画播完能正确回到待机（⛔ 不会卡在"跳跃"帧）

## 1. 前置检查清单

- [ ] ⚠ **01、02 已验收** —— 移动和跳跃的手感已定稿
- [ ] 已有美术资源（或占位动画）
- [ ] 已决定用 `AnimationPlayer` 还是 `AnimationTree`（⛔ 复杂状态机建议 AnimationTree）
- [ ] ⚠ 已确认动画**不驱动移动**，移动**驱动动画**（方向不能反）

## 2. 工序

### Step 1　⚠ 确认驱动方向　`[character/05#S1]`

【读】`howto/godot/animation.md#选型`

【做】先写死这条规则并写进注释：

```text
状态机/移动 → 决定播什么动画
⛔ 动画 → 不得反过来驱动位移（除 Root Motion 外）
```

⚠ **最常见的错误**：用动画的 Call Method Track 去改 `velocity` 或 `position`。
这会让移动逻辑分裂在两处，后面加"空中控制""击退"时无法维护。

ⓘ **例外**：Root Motion（动画自带位移）是合法且推荐的做法，但必须显式启用并配好。

【产出】代码结构上是"移动算完 → 设置动画参数"

【判据】⛔ 在动画资源里 grep 不到任何修改 `position`/`velocity` 的方法轨

【审】`audit/godot/animation.md#4`

### Step 2　建状态机（或 AnimationTree）　`[character/05#S2]`

【读】`howto/godot/animation.md#2. AnimationTree（状态机）`

【做】状态至少：`IDLE` `RUN` `JUMP` `FALL` `LAND`

```gdscript
enum State { IDLE, RUN, JUMP, FALL, LAND }
var _state := State.IDLE

func _update_state() -> void:
    # ⚠ 在 move_and_slide() 之后调用
    if not is_on_floor():
        _state = State.JUMP if velocity.y < 0.0 else State.FALL
    elif absf(velocity.x) > 1.0:
        _state = State.RUN
    else:
        _state = State.IDLE
```

【产出】状态与视觉一致

【判据】逐帧观察：起跳瞬间进 JUMP、顶点转 FALL、落地转 IDLE/RUN

【审】`audit/godot/animation.md#8`

### Step 3　⚠ 处理落地（最容易漏）　`[character/05#S3]`

【读】`howto/godot/animation.md#1. AnimationPlayer`

【做】记录上一帧是否在地面，检测"本帧刚落地"
```gdscript
var _was_on_floor := false
# …move_and_slide() 之后…
if is_on_floor() and not _was_on_floor:
    _play_land()          # 落地动画/音效/尘土
_was_on_floor = is_on_floor()
```

⚠ **漏掉落地检测**的表现：从高处落下没有任何落地反馈，或者一直播 FALL 不切回。

【产出】落地有反馈

【判据】从高处落下：**落地瞬间**播一次落地动画，⛔ 不是延迟也不是重复

【审】`audit/godot/animation.md#2`

### Step 4　配步频（不滑步）　`[character/05#S4]`

【读】`howto/godot/animation.md#1. AnimationPlayer`

【做】让跑步动画的播放速度与水平速度成比例
```gdscript
anim_player.speed_scale = absf(velocity.x) / move_speed
```
⚠ 或者直接 `clamp` 到一个合理范围，⛔ 不要让速度极慢时动画几乎停住（会显得鬼畜）

【产出】步频匹配速度

【判据】**实测**：角色加速过程中，脚部与地面**无明显相对滑动**。
⚠ 这是肉眼最容易看出来的穿帮，必须录像逐帧确认。

【审】`audit/godot/animation.md#9`

### Step 5　转向过渡　`[character/05#S5]`

【读】`howto/godot/animation.md#2. AnimationTree（状态机）`

【做】用 `AnimationTree` 的 blend 或直接 tween 缩放/旋转
⛔ **不要瞬间 `flip_h = true`** —— 会显得很生硬

【产出】平滑转向

【判据】连续快速左右转向：过渡自然，⛔ 无闪现

【审】`audit/godot/animation.md#10`
【品】`craft/godot/aesthetics.md#2. 动效：缓动曲线不是"随便选一个"`

### Step 6　确认不卡帧　`[character/05#S6]`

【读】`howto/godot/animation.md#3. Tween`

【做】检查每个非循环动画播完的回退
```gdscript
# ⚠ 用 animation_finished 信号回退，⛔ 不要用固定时长 Timer
```

【产出】无卡帧

【判据】反复跳、反复落地 20 次：⛔ **从不卡在某一帧**

【审】`audit/godot/animation.md#2`

## 3. 参考实现

```gdscript
# 接在 01/02 的 player.gd — Godot 4.x
enum State { IDLE, RUN, JUMP, FALL, LAND }
var _state := State.IDLE
var _was_on_floor := false

@onready var _anim := $AnimationPlayer

func _physics_process(delta: float) -> void:
    # …① 采样 ② 消耗缓冲 ③ 重力 ④ move_and_slide()…
    move_and_slide()
    _update_visual(delta)      # ⚠ 视觉更新必须在 move_and_slide 之后

func _update_visual(delta: float) -> void:
    var next := _state
    if not is_on_floor():
        next = State.JUMP if velocity.y < 0.0 else State.FALL
    elif absf(velocity.x) > 1.0:
        next = State.RUN
    else:
        next = State.IDLE

    if is_on_floor() and not _was_on_floor:
        _anim.play("land")     # 落地优先
        _was_on_floor = true
        return
    _was_on_floor = is_on_floor()

    if next != _state:
        _state = next
        _anim.play(["idle","run","jump","fall","land"][next])

    if _state == State.RUN:
        _anim.speed_scale = clampf(absf(velocity.x) / move_speed, 0.6, 1.6)
    else:
        _anim.speed_scale = 1.0
```

## 4. 验收清单

- [ ] ⛔ 动画资源里没有改 `position`/`velocity` 的方法轨
- [ ] 起跳→JUMP、顶点→FALL、落地→LAND/IDLE **逐帧正确**
- [ ] 落地有反馈，且**只触发一次**
- [ ] 跑步**不滑步**（录像逐帧确认）
- [ ] 转向有过渡，不闪现
- [ ] 连续跳 20 次：不卡帧
- [ ] 快速左右横跳：状态不打架（⛔ 不会同时播两个动画）
- [ ] ⚠ `speed_scale` 有 clamp（极慢速时动画不鬼畜）
- [ ] 暂停游戏：动画随之暂停（按 `process_mode`）



## 5. 常见返工

⚠ **动画反向驱动移动** —— 后期加击退、空中控制时逻辑分裂，要重构。

⚠ **没做落地检测** —— 从高处落下没有反馈，手感很"飘"，且这个缺失要到最后才被发现。

⚠ **`speed_scale` 直接等于速度比，没 clamp** —— 慢速移动时动画几乎静止，显得鬼畜。

⚠ **用 Timer 控制动画时长而不是 `animation_finished`** —— 美术改动画时长后全部错位。
✅ 用信号，让动画自己决定何时结束。

⚠ **移动没定稿就接动画** —— 动画掩盖移动问题，等你发现时参数已围绕错误动画调了一轮。
