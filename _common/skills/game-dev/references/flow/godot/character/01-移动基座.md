# 01 移动基座（角色控制域）

> **前置**：已定死 2D/3D、CharacterBody、视角类型（见 `00-域流程总览.md`）
> **本步交付**：一个能在场景里跑动、被墙挡住、站得住地面的角色（**色块即可，不做动画**）
> **对应**：流程 `howto/godot/character.md` · 审核 `audit/godot/character.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 按方向键，角色在地面跑起来
2. 松开键，角色停下（不是无限滑行）
3. 撞墙停住，不穿墙、不抖动
4. 站在斜坡/平台上不下滑、不弹跳
5. ⚠ **相机固定不动也能看清上述全部行为**

⚠ 这五条任何一条演示不出来，说明基座没做完。

## 1. 前置检查清单

- [ ] 场景里已有地面和墙的碰撞体（`StaticBody2D/3D` + `CollisionShape`）
- [ ] 已确认物理层：角色在哪个 layer、地面在哪个 layer
- [ ] 已确认 `Project Settings > Physics > Common > Physics Ticks Per Second`（默认 60）
- [ ] ⚠ 已确认角色**用 `CharacterBody`**，不是 `RigidBody`
- [ ] 已确认 2D 用 `CharacterBody2D` + `move_and_slide()`，3D 用 `CharacterBody3D`

### Step 2　接输入到速度　`[character/01#S2]`

【读】howto/godot/character.md —— 只查本步涉及的章节，⛔ 不要通读全文

【做】
```gdscript
extends CharacterBody2D

@export var move_speed := 300.0
@export var accel := 2000.0      # 待实测
@export var decel := 2500.0      # 待实测

func _physics_process(delta: float) -> void:
    var dir := Input.get_axis("move_left", "move_right")
    var target := dir * move_speed
    # ⚠ 用 move_toward 做加减速，⛔ 不要直接赋值（那样没有加速度，手感是"开关"）
    velocity.x = move_toward(velocity.x, target,
        (accel if dir != 0.0 else decel) * delta)
    move_and_slide()
```

【产出】角色能左右跑

【判据】按住方向键：角色**加速到最高速**（不是瞬间到顶）；松开：**平滑停下**

【审】audit/godot/character.md —— 本步相关的具体条目（步骤级即时检查）

## 3. 参考实现（2D 完整版）

```gdscript
# player.gd  — Godot 4.x
extends CharacterBody2D

@export var move_speed := 300.0
@export var accel := 2000.0
@export var decel := 2500.0
@export var gravity := 980.0

func _ready() -> void:
    up_direction = Vector2.UP
    floor_max_angle = deg_to_rad(46)
    floor_snap_length = 1.0

func _physics_process(delta: float) -> void:
    var dir := Input.get_axis("move_left", "move_right")
    var target_x := dir * move_speed
    velocity.x = move_toward(velocity.x, target_x,
        (accel if dir != 0.0 else decel) * delta)

    if not is_on_floor():
        velocity.y += gravity * delta

    move_and_slide()
```

⚠ **3D 差异**：用 `CharacterBody3D`、`velocity` 是 `Vector3`、
水平输入映射到 `velocity.x/z` 而非 `x`；`floor_snap_length` 同样要设（`floor_snap_length` 在 3D 也存在）。

⚠ **`_physics_process` 不是 `_process`** —— 移动必须在物理帧，⛔ 放 `_process` 会随帧率变化手感。

## 4. 验收清单

- [ ] 按住方向键：加速到最高速，⛔ 不是瞬间到顶
- [ ] 松开：平滑停下，⛔ 不是无限滑行也不是急停
- [ ] 撞墙：停住、不穿墙、不抖动
- [ ] 站地面：完全静止，无抖动无弹跳
- [ ] 下坡：贴地不飞
- [ ] 上坡：能上去（坡度 < `floor_max_angle`）
- [ ] 从平台边缘走出：正常下落
- [ ] ⚠ 改 `Physics Ticks Per Second` 从 60 到 30：手感**不应明显变化**（若变了说明用了 `_process` 或依赖帧率）

## 5. 常见返工

⚠ **用 `RigidBody` 做主控角色** —— 物理引擎接管速度，手感不可控。发现就得整个换掉。

⚠ **直接 `velocity.x = dir * speed`** —— 没有加速度，手感像开关，且后面加"冰面""减速debuff"要重写。

⚠ **`is_on_floor()` 在 `move_and_slide()` 之前读** —— 读到的是**上一帧**的结果。
必须 `move_and_slide()` **之后**再读状态。

⚠ **形状用矩形做角色** —— 台阶边缘会卡住。2D 用 `CapsuleShape2D`，3D 用 `CapsuleShape3D`。

⚠ **忘了 `floor_snap_length`** —— 下坡时会短暂离地，导致"下坡时不能跳"（因为 `is_on_floor()` 变 false）。

⚠ **做了动画才回来发现移动是错的** —— 这正是本步"只用色块"的原因。
