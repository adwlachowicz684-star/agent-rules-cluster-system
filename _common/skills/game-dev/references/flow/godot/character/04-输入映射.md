## 0. 交付物定义

能演示：

1. 改一个键位（如把跳从空格改成 J），**重启后仍生效**
2. 手柄插上就能用（⛔ 不需要改代码）
3. 键位冲突时**有提示**（不是静默覆盖）
4. 恢复默认能一键还原

## 3. 参考实现

```gdscript
# input_settings.gd — Godot 4.x
extends Node

const CONFIG_PATH := "user://input.cfg"
const DEFAULT_BINDINGS := {
    "jump": [KEY_SPACE],
    "move_left": [KEY_A, KEY_LEFT],
    "move_right": [KEY_D, KEY_RIGHT],
}

func save_custom() -> void:
    var cfg := ConfigFile.new()
    for action in DEFAULT_BINDINGS:
        var events := InputMap.action_get_events(action)
        var codes: Array[int] = []
        for e in events:
            if e is InputEventKey:
                codes.append(e.keycode)
        # ⚠ 只存与默认不同的
        if codes != DEFAULT_BINDINGS[action]:
            cfg.set_value("bindings", action, codes)
    cfg.save(CONFIG_PATH)

func load_custom() -> void:
    var cfg := ConfigFile.new()
    if cfg.load(CONFIG_PATH) != OK:
        return
    for action in cfg.get_section_keys("bindings"):
        if not InputMap.has_action(action):
            continue
        InputMap.action_erase_events(action)
        for code in cfg.get_value("bindings", action):
            var e := InputEventKey.new()
            e.keycode = code
            InputMap.action_add_event(action, e)
```

## 5. 常见返工

⚠ **代码里硬编码 `Input.is_key_pressed(KEY_SPACE)`** —— 后面要做重绑定就得全改。
这是最典型的返工，且改动面很大。

⚠ **把所有默认键位都存进配置** —— 之后你新增一个 action（比如 `dash`），
老玩家的配置文件里没有它，若你的加载逻辑是"用配置覆盖全部"，新 action 就丢了。

⚠ **恢复默认写成"清空所有绑定"** —— 结果是全部键位失效，玩家动不了。

⚠ **冲突静默覆盖** —— 玩家改了跳跃，攻击键没了，而且不知道为什么。

⚠ **手柄走另一套判断** —— 后面 UI 提示、图标切换全部要写两套。
