# 07 时间推进验收（时间推进域）

> **本步交付**：改时钟 / 杀进程 / 断网三天 / 真机挂起 实测
> **对应**：流程 `howto/godot/time-progression.md` · 审核 `audit/godot/time-progression.md`

## 0. 交付物定义

1. 验收第一项是**改系统时钟**，⛔ 不是正常登录
2. 离线期间**中途变更加成**的分段结算实测
3. **断网三天**上线的边界补算实测
4. **重置边界前后杀进程**的行为确定性实测
5. 加速扣款的**对账**实测
6. **真机**挂起 5 秒预算实测

## 2. 工序

### Step 1　验收第一项是改系统时钟，⛔ 不是正常登录　`[time-progression/07#S1]`

【读】`howto/godot/time-progression.md#1. 三种时间源，用错层级是万恶之源`

【做】
把设备系统时间**回调 2 小时**与**快进 8 小时**各测一遍。

⛔ 只做正常登录验收 ——
系统时钟的跳变只在玩家改表、NTP 校时、跨时区、夏令时出现，
⛔ 而正常登录路径**永远走不到**这些分支，
于是"上线后部分玩家收益异常"会长期无法定位。

ⓘ 判据不是"不崩溃"，是"**不产生负结算、不静默跳过**"：
⛔ 只验"没崩"会放过被 `max(0, ...)` 吞掉的那些次结算。

【判据】人为把系统时间回调 2 小时：不产生负结算、有回拨钳制的上报埋点；快进 8 小时：按封顶结算且不越过系统硬上限。

【审】`audit/godot/time-progression.md#25`

### Step 2　离线中途 VIP 到期的分段结算　`[time-progression/07#S2]`

【读】`howto/godot/time-progression.md#4. 分段：离线期间的速率不能按"回来那一刻"倒推`

【做】
构造：离线 8 小时，第 3 小时 VIP 到期、第 5 小时活动结束。

⛔ 只测"离线 8 小时收益对不对" ——
单一速率下，整体乘与分段算**结果相同**，
⛔ 这个测试**无法区分**正确实现与错误实现。

ⓘ 这是最隐蔽的一类假通过：**测试通过了，但它证明不了被测的那条性质**。

【判据】三段（VIP 前 / VIP 后活动前 / 活动后）速率各不相同且与日志一致。

【审】`audit/godot/time-progression.md#9`

### Step 3　断网三天上线的边界补算　`[time-progression/07#S3]`

【读】`howto/godot/time-progression.md#8. 周期重置：硬边界，不是定时任务`

【做】
断网三天后上线，验证三天的每日重置**各执行一次**。

⛔ 用"改存档时间戳"代替真实断网 ——
改时间戳只走了补算路径，**没有走"事件确实没送达"的路径**，
而后者才是生产环境的真实情况。

【判据】三天内每个边界的发放记录各一条，无重复无遗漏。

【审】`audit/godot/time-progression.md#19`

### Step 4　重置边界前后杀进程的行为确定性　`[time-progression/07#S4]`

【读】`howto/godot/time-progression.md#8. 周期重置：硬边界，不是定时任务`

【做】
在重置边界**前 1 秒**与**后 1 秒**分别强杀进程，验证恢复行为确定。

⛔ 只测"重置后状态对不对" ——
危险组合（重置清 0 + 剩余秒数存档）**只在边界附近被杀进程时**暴露，
⛔ 正常流程下它的表现完全正确。

【判据】两种杀进程时机下，队列状态均可由存档确定复算，不出现"不知该清还是该留"。

【审】`audit/godot/time-progression.md#20`

### Step 5　加速扣款的对账　`[time-progression/07#S5]`

【读】`howto/godot/time-progression.md#6. 生产 / 建造队列`

【做】
注入故障（扣款后服务重启 / 网络超时），验证扣款与产出**同进同退**。

⛔ 只测"加速成功" ——
分两步的缺陷**只在中间态**出现，
⛔ 而成功路径永远一次跑完，看不出问题。

ⓘ 对账判据是**总数相等**，不是"看起来没问题"：
扣款笔数 × 单价 与 产出笔数 × 单价 必须逐笔对得上。

【判据】注入故障后对账差额为 0，且无"扣了没完成""完成没扣"的记录。

【审】`audit/godot/time-progression.md#14`

### Step 6　真机测挂起 5 秒预算　`[time-progression/07#S6]`

【读】`howto/godot/time-progression.md#9. Godot 侧：挂起回调只做持久化`

【做】
iOS / Android **真机**切后台，测量 PAUSED 处理耗时。

⛔ 只在桌面测 ——
桌面没有 5 秒限制，且 `FOCUS_OUT` 与 `PAUSED` 的触发时机在桌面几乎一致，
⛔ 两个差异（超时被杀、高频重复）**在桌面上都测不出来**。

ⓘ 判据不是"不闪退"，是"**耗时本身被测出来了**"：
⛔ 没打点的耗时等于没测，下次改代码加了 I/O 也不会被发现。

【判据】真机测得 PAUSED 耗时 < 5 秒且有埋点；切后台不丢进度。

【审】`audit/godot/time-progression.md#22`

## 3. 验收清单

- [ ] 系统时间回调 2 小时不产生负结算
- [ ] 系统时间快进 8 小时按封顶结算
- [ ] 离线中途 VIP 到期时三段速率不同
- [ ] 断网三天上线补算三天边界
- [ ] 重置边界前后杀进程行为确定
- [ ] 注入故障后扣款产出对账差额为 0
- [ ] 真机 PAUSED 耗时 < 5 秒且有埋点

## 4. 常见返工

| 测试通过但性质没被验证 | 单一速率测不出分段 | 03 S1 |

| 边界附近行为不确定 | 清 0 + 剩余秒数组合 | 06 S3 |
