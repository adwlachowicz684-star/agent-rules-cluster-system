# 枪械 / 射击系统 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只要能开枪打中（单机） | 01 → 02 → 07 |
| 要有手感（后坐力 / 扩散 / 压枪） | 01 → 02 → 03 → 07 |
| 要有弹道下坠 / 穿透（狙击、远距） | 01 → 02 → 04 → 07 |
| 要有换弹 / 切枪节奏 | 01 → 05 → 07 |
| 多人对战、要延迟补偿 | 01 → 02 → 06 → 07 |
| 全套 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只做一次性开火演示、不要手感、不联机**的项目不要套本域。
⚠ 那属于 `howto/godot/firearms.md` 的基础用法范围 ——
本域处理的是**要手感一致、要能联机、要能修"打不中"这类 bug** 的复杂度。

ⓘ 分工：
- `howto/godot/firearms.md` 讲**单个机制与参数怎么定**
- `howto/godot/projectile.md` 讲**投射物本身怎么飞**
- 本域讲**这些按什么顺序做、怎么保证命中判定与手感可验收**

⛔ 若本域某步需要"AnimationTree 状态机怎么配"这类细节，指向那篇，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 射击模型与 FireContext | — | 模型定性 + 单一事实源 + 状态机 |
| 02 | 命中判定与统一命中源 | 01 | 三套坐标归一 + 射线时序 + 自命中排除 |
| 03 | 后坐力与扩散 | 01 | 三变量拆分 + 可学习模式 + 可读扩散 |
| 04 | 弹道下坠与穿透 | 02 | 固定子步 + 共用积分器 + 穿透规则表 |
| 05 | 换弹与武器切换 | 01 | 逻辑门限 + 部署门限 + 弹药模型 |
| 06 | 多人射击与延迟补偿 | 02 | 服务端判定 + rewind 窗口 + 时基统一 |
| 07 | 射击验收 | 全部 | 命中一致性 + 手感实测 + 联机实测 |

⚠ **01 必须在一切之前**：FireContext 是所有参数的唯一来源，不定它后面每一步都在各写各的。
⚠ **02 必须在 03/04 之前**：命中源不归一，后坐力与弹道都无从谈起（不知道从哪发）。
⚠ **02 必须在 06 之前**：联机判定本质是"把 02 的判定搬到服务端"。
⚠ **05 依赖 01 但不依赖 03/04**：换弹是状态机问题，与后坐力正交。

## 3. 本域最容易做反的顺序

⛔ **先把枪"打响"，再回头补 FireContext 与统一命中源。**

开火 + 射线 + 扣血是最直观的"射击"需求，于是先写 `fire()`：
从摄像机中心发一条射线，命中就扣血。
⚠ 而此时**没有统一命中源、后坐力等于镜头抖动、扩散是个隐藏随机数** →
**"贴墙探头打不到人""看到头露出来却打不中""连发越打越散、压枪没有意义"**，
⛔ 且不报错，只在联机或玩家投诉时才暴露 —— 那时武器系统已定型，改命中源等于重做。

✅ 正确顺序：先立 FireContext 与统一命中源（01/02），再叠手感（03）与联机（06）。
