## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：别人能看到我摆的家具，也能看到我加工。**

⛔ 常见假完成：同步了**物理查询结果**，且 `@rpc("any_peer")` 收到就执行。
前者在单机正常、多人下两端不一致；后者等于把经济状态的写权限交给了客户端。

做完这一步，应该能**当场演示**：

1. ⛔ 可见性与编辑权是**两个独立维度**
2. ⛔ 只同步**批准后的状态**，不同步物理查询结果
3. ⛔ `any_peer` 下已用 `get_remote_sender_id()` 校验发送者
4. ⛔ 需要 RPC 的节点两端 **NodePath 相同**（`force_readable_name`）
5. ⛔ RPC **参数由服务端校验**（官方不校验参数签名）

**产出物**（下游按名字对接）：

```text
权限矩阵（可见性 × 编辑权）
批准后状态同步通道（不同步物理结果）
RPC 校验三件套（sender_id / NodePath / 参数）
```

## 2. 工序

### Step 1　⛔ 可见性与编辑权是两个独立维度　`[06#S1]`

【读】`howto/godot/lifeskill-housing.md#6. 家园多人同步：只同步批准后的状态`

【审】`audit/godot/lifeskill-housing.md#28`

⚠ 可见性（私有 / 好友 / 公会 / 同实例 / 公开）
× 编辑权（所有者 / 共建者 / 访客 / 无）。
⛔ **访客不能触发会改变经济状态的 RPC** —— 能看见不等于能改。

### Step 2　⛔ 只同步批准后的状态，不同步物理查询结果　`[06#S2]`

【读】`howto/godot/lifeskill-housing.md#6. 家园多人同步：只同步批准后的状态`

【审】`audit/godot/lifeskill-housing.md#29`

⚠ 物理结果**不可回放**，同步它会让两端不一致。
✅ 同步"服务端批准后的放置结果"，客户端据此重建视图。

### Step 3　⛔ any_peer 必须校验发送者 ID　`[06#S3]`

【读】`howto/godot/lifeskill-housing.md#6. 家园多人同步：只同步批准后的状态`

【审】`audit/godot/lifeskill-housing.md#35`

⚠ `@rpc` 默认是 `("authority", "call_remote", "reliable", 0)`，
即只有 authority 能远程调用。
⛔ 一旦用 `any_peer` 接收玩家输入，就必须在函数内用
`multiplayer.get_remote_sender_id()` 校验"这个 peer 是不是它声称的那个人"，
否则任意客户端都能以他人身份触发加工与放置。

### Step 4　⛔ RPC 要求两端 NodePath 相同　`[06#S4]`

【读】`howto/godot/lifeskill-housing.md#6. 家园多人同步：只同步批准后的状态`

【审】`audit/godot/lifeskill-housing.md#36`

⚠ 官方口径：远程调用成功要求发送方与接收方节点有**相同的 NodePath**
（即相同的名字）；用 `add_child()` 添加需要 RPC 的节点时要
`force_readable_name = true`。

⛔ 家园家具节点若是动态生成且名字带随机后缀 → 两端 NodePath 不同 →
**RPC 静默不调用**，表现为"别人看不到我操作家具"，而不报错。

### Step 5　⛔ 官方不校验 RPC 参数，服务端必须自己校验　`[06#S5]`

【读】`howto/godot/lifeskill-housing.md#6. 家园多人同步：只同步批准后的状态`

【审】`audit/godot/lifeskill-housing.md#37`

⛔ 官方口径：RPC 的签名 checksum 只校验 `@rpc` 声明、函数名、返回类型与 NodePath，
**函数参数不做匹配检查**（`func f():` 与 `func f(a, b):` 会通过匹配）。

⚠ 于是客户端可以发任意数量 / 任意取值的参数（"做 99999 个"、
"负数量"、不存在的 `recipe_id`）。
✅ 服务端必须逐项校验：参数存在、范围合法、配方已解锁、材料足够、权限允许。

⛔ 另有一条：所有 RPC 一次性做 checksum 校验，不匹配时**报错信息可能与
当前正在开发的函数无关** —— 排查时不要只盯着最近改的那个 RPC。

## 3. 参考实现

```gdscript
const MAX_BATCH := 99          # 单次请求上限，待实测

# ⛔ any_peer 下必须校验 sender，并逐项校验参数
@rpc("any_peer", "call_remote", "reliable")
func request_craft(recipe_id: StringName, count: int) -> void:
    var sender := multiplayer.get_remote_sender_id()
    if not can_edit(sender):          # 权限维度：访客不能改经济状态
        return
    if count <= 0 or count > MAX_BATCH:
        return                        # ⛔ 参数必须校验，官方不校验
    if not is_recipe_known(sender, recipe_id):
        return
    server_craft(sender, recipe_id, count)   # 服务端结算
```

⛔ 动态生成的家具节点要 `add_child(node, true)`（`force_readable_name`），
否则两端 NodePath 不同，RPC 静默失效。
