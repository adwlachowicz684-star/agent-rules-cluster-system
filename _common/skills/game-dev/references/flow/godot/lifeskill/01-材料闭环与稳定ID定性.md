## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：先做了某个玩法（比如挖矿），
于是材料有了 ID，就以为 ID 统一这件事已经解决了。**

⛔ 常见假完成：只定义了 `item_id`，而 `recipe_id`、`node_template_id`、
`furniture_template_id`、`instance_id` 是后面各自补的 —— 补的时候
不会回头对齐，于是同一个"铁矿"在加工表里叫 `ore_iron`、在采集表里叫 `iron_vein`。

做完这一步，应该能**当场演示**：

1. 采集 → 加工 → 家园的**闭环图**已画出（不是三个独立玩法）
2. ⛔ 五类 ID 的**命名规则与归属**已一次定齐
3. ⛔ 绑定继承规则已定：成品继承**最严格**输入绑定
4. ⛔ `Array` / `Dictionary` 里的子资源**不会被 `duplicate()` 复制**已被确认
5. ⛔ `resource_local_to_scene` 不是服务端持久状态已被确认

**产出物**（下游按名字对接）：

```text

绑定继承规则（默认：任一输入绑定 → 输出绑定）
ItemStack.can_merge 规则（item_id + bound_to + flags）
```

## 2. 工序

### Step 1　⛔ 先定"一个闭环"，再动手做第一个玩法　`[01#S1]`

【读】`howto/godot/lifeskill-housing.md#0. 稳定 ID 与绑定必须随物品流动`

【审】`audit/godot/lifeskill-housing.md#1`

⚠ 采集 / 加工 / 家园是**同一个材料闭环的三个闸门**，不是三个玩法。
⛔ 分开实现 → 同一种材料在不同系统里有不同 ID、不同堆叠规则、
不同绑定状态和不同权威源。

### Step 2　⛔ 五类 ID 一次定齐，不要边做边补　`[01#S2]`

【读】`howto/godot/lifeskill-housing.md#0. 稳定 ID 与绑定必须随物品流动`

【审】`audit/godot/lifeskill-housing.md#2`

⚠ 五类：`item_id` / `recipe_id` / `node_template_id` /
`furniture_template_id` / `instance_id`。
⛔ 边做边补的后果是"同一个铁矿两个名字"，而对不齐要到联调才发现。

### Step 3　⛔ 绑定必须随物品流动，成品继承最严格绑定　`[01#S3]`

【读】`howto/godot/lifeskill-housing.md#0. 稳定 ID 与绑定必须随物品流动`

【审】`audit/godot/lifeskill-housing.md#3`

⚠ 绑定不能只作为 UI 文本 —— 否则玩家把绑定矿石交给公共加工设施，
再用另一个角色取走。
✅ 默认策略：**成品继承最严格绑定**（任一输入为绑定则输出绑定）。
⛔ `can_merge` 必须把 `bound_to` 与 `flags` 一并比较，只比 `item_id` 会串堆。

### Step 4　⛔ duplicate(true) 也不复制数组里的子资源　`[01#S4]`

【读】`howto/godot/lifeskill-housing.md#⛔ 官方例外：数组与字典里的子资源永不复制`

【审】`audit/godot/lifeskill-housing.md#32`

⛔ **官方口径**：`duplicate(true)` 是深拷贝，但
**`Array` 与 `Dictionary` 属性里的子资源永远不会被复制**
（"Subresources inside Array and Dictionary properties are never duplicated"）。

⚠ 本域的数据结构大量依赖数组：`yield_table: Array[YieldEntry]`、
`inputs: Array[Ingredient]`、`outputs: Array[OutputSlot]`。
⛔ 于是"模板 `duplicate(true)` 之后改副本的第一个产出项"会**改到模板本身**，
表现为"所有同模板的采集点产出一起变了" —— 排查时极难想到是复制语义。

✅ 数组元素必须**逐个显式复制**；内部 Resource 则只有 local 的才会被复制
（可配合 `duplicate_deep()` 与 `PROPERTY_USAGE_ALWAYS_DUPLICATE`）。

### Step 5　⛔ local_to_scene 不是服务端持久状态　`[01#S5]`

【读】`howto/godot/lifeskill-housing.md#0. 稳定 ID 与绑定必须随物品流动`

【审】`audit/godot/lifeskill-housing.md#5`

⚠ `resource_local_to_scene` 只是**场景级局部状态**，
⛔ 不能替代服务端持久状态 —— 场景重载即丢失。
实例状态必须另建对象并深拷贝。

## 3. 参考实现

```gdscript
class_name ItemStack extends Resource
@export var item_id: StringName
@export var quantity: int = 0
@export var bound_to: int = 0      # 0 = 未绑定
@export var flags: int = 0

func can_merge(other: ItemStack) -> bool:
    # ⛔ 只比 item_id 会让绑定与非绑定串堆
    return other.item_id == item_id and other.bound_to == bound_to and other.flags == flags

# ⛔ duplicate(true) 不会复制 Array 里的子资源，必须逐个复制
static func clone_table(src: Array) -> Array:
    var out: Array = []
    for e in src:
        out.append(e.duplicate(true))
    return out
```

⛔ 注意：自定义 Resource 若 `Object._init()` 定义了必填参数，
`duplicate()` 会失败 —— 模板 Resource 应避免必填构造参数。
