# 07 生活玩法验收（lifeskill 域）

> **前置**：`01`–`06` 全部完成
> **本步交付**：**权威清单核查 + 经济回测报告**
> **对应**：做法 `howto/godot/lifeskill-housing.md#9. 服务端权威清单`
> 　　　审核 `audit/godot/lifeskill-housing.md`

## 0. 交付物定义

⚠ **本域的验收有一个特殊困难：绝大多数越权与通胀问题在单人、短时、正常时钟下测不出来。**

⛔ 一个人跑十分钟全部通过，是**最危险的假通过** ——
它给出"没问题"的信号，而越权、通胀、刷新漂移分别只在
**多端、长时、改时钟**下出现。

做完这一步，应该能**当场演示**：

1. ⛔ 三项判定（采集产出 / 合成结果 / 放置合法性）**没有任何一条只跑在客户端**
2. ⛔ 经济回测：按**净产出速率**反推，纯产出无通胀
3. ⛔ 2,000 采集点 / 大量家具下用的是 `MultiMesh`
4. ⛔ 停服 / 校时后刷新**不漂移**
5. ⛔ 报告已归档（含版本、参数、回测结果）

## 2. 工序

### Step 1　⛔ 三项判定必须只跑服务端　`[07#S1]`

【读】`howto/godot/lifeskill-housing.md#9. 服务端权威清单`

【审】`audit/godot/lifeskill-housing.md#38`

⚠ 采集判定与产出、刷新与 `available_at`、材料扣减与产出、
合成失败与损耗、占格与放置、家园权限、`home.version` 递增 ——
**全部必须服务端**。客户端只做输入、预测、表现。

⛔ 只要有一项跑在客户端，玩家改内存即可自造产出，
而服务端日志看起来完全正常。
✅ 验收时逐个 RPC 检查：断网 / 改包后是否仍能生效。

### Step 2　⛔ 经济回测：从净产出速率反推，纯产出会通胀　`[07#S2]`

【读】`howto/godot/lifeskill-housing.md#7. 经济平衡：从净产出速率反推`

【审】`audit/godot/lifeskill-housing.md#30`

⚠ **纯产出会导致通货膨胀**。要从"净产出速率"反推采集速率与回收比例。
⛔ 绑定 / 非绑定材料的比例直接影响经济（非绑定可交易 → 工作室刷金）。

✅ 回测口径要含：单位时间净产出、消耗终点（家园）的吸收量、
回收比例、熟练度满级后的产出上限。

### Step 3　⛔ 成千上万个家具 / 采集点用 MultiMesh　`[07#S3]`

【读】`howto/godot/lifeskill-housing.md#8. Godot 实现：数据层 / 视图层 / 权威层分离`

【审】`audit/godot/lifeskill-housing.md#31`

⚠ 成千上万个 `MeshInstance3D` 逐个提交会很慢 —— 官方明确指出这点。
✅ 用 `MultiMesh`（一次绘制成千上万实例），
⛔ 但它**仍要求外部提供可见性 AABB**，不能省。

### Step 4　⛔ 停服与校时后刷新不漂移　`[07#S4]`

【读】`howto/godot/lifeskill-housing.md#1. 采集点 = 模板 + 世界实例，不是一个场景脚本`

【审】`audit/godot/lifeskill-housing.md#7`

⛔ 相对倒计时在停服、分区、离线结算、时钟校正时**累积漂移**。
✅ 验收方式：把系统时间前后各调一年，重启后采集点可用状态应与
"按绝对时间推算"一致。

### Step 5　⛔ 报告归档，供下次回归对比　`[07#S5]`

【读】`howto/godot/lifeskill-housing.md#10. 待核对项（运行时验证）`

【审】`audit/godot/lifeskill-housing.md#30`

⚠ 失败率、损耗率、熟练度收益曲线、回收比例**本轮给的是设计区间**，
须经济回测核实；数值窗口与通胀临界点须按真实产出 / 消耗速率回测。

⛔ 未归档的报告无法与下次对比 —— 而通胀恰恰是"这一版还行、
下一版突然崩"，没有基线就无法定位是哪次改动引入的。
