## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：家具能摆、能吸附、看着对齐了。**

⛔ 常见假完成：用 **`StaticBody` 碰撞**决定摆放是否合法。
这在单机、单一角度下"看着能用"，而它回答的根本不是同一个问题：

- 物理碰撞回答：**两个形状这一帧是否重叠**（受浮点、休眠、CCD、旋转顺序、缩放、图层、射线误差影响）
- 放置系统要回答：**这个 footprint 在领地版本下是否被允许** —— 必须**可回放、可存档、可服务端校验**

做完这一步，应该能**当场演示**：

1. ⛔ 占格是**整数表**，不是物理查询
2. ⛔ 网格用 `Vector3i`，旋转限制为 **90° 枚举**
3. ⛔ 所有端共用**同一个 `snap()`**
4. ⛔ 十步校验顺序，任何前置失败都不进物理阶段
5. ⛔ `home.version` 不匹配返回 `stale_version`
6. ⛔ 家具加成**分阶段累加并封顶**

**产出物**（下游按名字对接）：

```text
snap()（整数除法，统一向下取整）
十步校验顺序
home.version 与 stale_version 冲突返回
家具加成公式（flat / percent / post_flat + 四道上限）
```

## 2. 工序

### Step 1　⛔ 占格是整数表，不能用物理碰撞做校验　`[05#S1]`

【读】`howto/godot/lifeskill-housing.md#5. 家园是确定性占格系统，不是物理摆放`

【审】`audit/godot/lifeskill-housing.md#22`

⛔ 物理碰撞不可回放、不可存档、不可服务端校验。
✅ 放置系统要的是"这个 footprint 是否被允许"，用整数占格表回答。

### Step 2　⛔ 网格用 Vector3i，旋转限制为 90° 枚举　`[05#S2]`

【读】`howto/godot/lifeskill-housing.md#5. 家园是确定性占格系统，不是物理摆放`

【审】`audit/godot/lifeskill-housing.md#23`

⚠ 连续角度会产生"同一个摆放，浮点结果不同"，
于是服务端与客户端算出不同格子。✅ 90° 枚举 + 整数 `Vector3i`。

### Step 3　⛔ 所有端共用同一个 snap()　`[05#S3]`

【读】`howto/godot/lifeskill-housing.md#5. 家园是确定性占格系统，不是物理摆放`

【审】`audit/godot/lifeskill-housing.md#24`

⚠ 世界坐标到网格用**整数除法**并统一向下取整。
⛔ 各端自己 `snap()`（或让 Godot 物理查询分别决定）→ 同一摆放两端格子不同，
表现为"客户端看着能摆，服务端拒绝"，且**只有部分角度复现**。

### Step 4　⛔ 十步校验顺序，任何前置失败都不进物理阶段　`[05#S4]`

【读】`howto/godot/lifeskill-housing.md#5. 家园是确定性占格系统，不是物理摆放`

【审】`audit/godot/lifeskill-housing.md#25`

```
模板存在 → 有权限 → 领地版本匹配 → 旋转合法 → 网格在边界内
→ footprint 未占用 → 地面/墙面条件 → 无家具重叠
→ 不超过密度/重量/装饰上限 → 扣费成功 → place()
```

⛔ 跳过顺序先做物理检测 → 非法摆放也会"看起来摆上去了"。

### Step 5　⛔ home.version 不匹配要返回 stale_version　`[05#S5]`

【读】`howto/godot/lifeskill-housing.md#5. 家园是确定性占格系统，不是物理摆放`

【审】`audit/godot/lifeskill-housing.md#26`

⚠ 多人同时摆放会产生**覆盖与幽灵家具**。
✅ `home.version` 递增，不匹配返回 `stale_version` 冲突，客户端重新拉取。

### Step 6　⛔ 家具加成必须分阶段累加并封顶　`[05#S6]`

【读】`howto/godot/lifeskill-housing.md#家具加成必须分阶段累加并封顶`

【审】`audit/godot/lifeskill-housing.md#27`

```
flat_total   = sum(flat)
percent_total = clamp(sum(percent), floor, cap)
final        = (base + flat_total) * (1 + percent_total) + post_flat
```

⛔ 不封顶 → 玩家摆上千张同模型桌子叠加无限加工速度。
✅ 至少设 `max_furniture`、`total_bonus_cap`、`per_stat_cap`、**同类家具生效上限**。

## 3. 参考实现

```gdscript
func snap(world: Vector3, step: float) -> Vector3i:
    return Vector3i(floori(world.x/step), floori(world.y/step), floori(world.z/step))
```

```gdscript
# ⛔ 加成按三阶段累加，percent 先 clamp 再参与
func final_bonus(base: float, flats: Array, percents: Array, post: float) -> float:
    var flat_total := 0.0
    for f in flats: flat_total += f
    var p_total := 0.0
    for p in percents: p_total += p
    p_total = clampf(p_total, PERCENT_FLOOR, PERCENT_CAP)
    return (base + flat_total) * (1.0 + p_total) + post
```

⛔ `snap()` 必须是**同一个函数**被所有端调用；
复制一份到客户端代码会导致后续改动只改一处，两端逐渐分叉。

|---|---|
