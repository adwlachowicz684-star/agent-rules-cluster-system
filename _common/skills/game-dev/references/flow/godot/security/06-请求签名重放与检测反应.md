# 06 请求签名、重放与检测反应（安全域）

> **本步交付**：规范化串 + nonce + 常量时间比较 + 静默反应
> **对应**：流程 `howto/godot/security.md` · 审核 `audit/godot/security.md`

## 0. 交付物定义

1. 规范化串前后端一致
2. HMAC 密钥服务端按会话颁发
3. nonce 与时钟偏移双重校验
4. ⛔ 用常量时间比较
5. ⛔ 检测到之后不给攻击者反馈

## 1. 前置检查清单

- [ ] 已知 `hmac_digest` 只支持 SHA-1 / SHA-256
- [ ] 已知规范化串 Godot 不替你定
- [ ] nonce 去重状态在集群中共享
- [ ] ⛔ 反应策略已在 01 定完

## 2. 工序

### Step 1　规范化串要前后端共同定义，Godot 不替你定　`[security/06#S1]`

【读】`howto/godot/security.md#请求签名：防篡改与重放，不能证明诚实`

【做】
定义 `method + "\n" + path + "\n" + body_sha256 + "\n" + timestamp + "\n" + nonce + "\n" + app_version`。
body 先 SHA-256 再进规范串（避免大 body 与编码歧义）。
⛔ 各端自行拼接——换行符、字段顺序、编码任一不同就验签失败，
⛔ 而失败表现是"签名不对"，排查会被引向密钥。

【产出】规范化串定义（前后端同一份文档）

【判据】同一请求两端算出的规范串逐字节相同

【审】`audit/godot/security.md#37`


### Step 2　⛔ hmac_digest 当前只支持 SHA-1 / SHA-256　`[security/06#S2]`

【读】`howto/godot/security.md#请求签名：防篡改与重放，不能证明诚实`

【做】
官方原文：*"Currently, only HashingContext.HASH_SHA256 and HashingContext.HASH_SHA1 are supported."*
⛔ 传 SHA-512 期望更强——不会报"不支持"，
⛔ 只会得到错误结果或空值，表现为"签名总是对不上"。

【产出】算法常量固定为 HASH_SHA256

【判据】代码中不存在 HASH_SHA512 等不受支持的算法

【审】`audit/godot/security.md#38`


### Step 3　⛔ HMAC 密钥由服务端按会话颁发，不用固定字符串　`[security/06#S3]`

【读】`howto/godot/security.md#请求签名：防篡改与重放，不能证明诚实`

【做】
密钥必须是服务端按会话颁发的随机 32 字节密钥。
⛔ 客户端内置共享固定字符串——PCK 解包即可读出，
⛔ 与 `"my_secret_key_123"` 那种硬编码是同一个问题。

【产出】会话密钥颁发流程

【判据】抓包得到的密钥每次会话都不同

【审】`audit/godot/security.md#39`


### Step 4　nonce 至少 16 字节不可重复，且校验时钟偏移　`[security/06#S4]`

【读】`howto/godot/security.md#请求签名：防篡改与重放，不能证明诚实`

【做】
服务端维护 `(client_id, nonce)` 短期集合（TTL 5–10 分钟），
并要求 `|now - ts| <= 300s`。
⛔ nonce 只按时间生成 → 相邻请求碰撞；只用内存去重 → 重启后可重放；
集群无共享状态 → 多副本重复执行。

【产出】nonce 去重 + 时钟偏移校验

【判据】重放同一请求被拒；改时间戳到 1 小时前被拒

【审】`audit/godot/security.md#40`


### Step 5　⛔ 用 constant_time_compare 比 HMAC，不是 ==　`[security/06#S5]`

【读】`howto/godot/security.md#读取：先验签，再解密`

【做】
官方提供 `constant_time_compare()` 就是为了防止时序攻击。
⛔ 用 `==`——提前退出会泄露"前几个字节对了"的信息，
⛔ 而这是唯一一个"功能完全正确但仍然不安全"的错。

【产出】比较实现（走 constant_time_compare）

【判据】代码中不存在对 HMAC/mac 的 `==` 比较

【审】`audit/godot/security.md#41`


### Step 6　⛔ 检测到之后不给反馈：静默标记/回滚/上报/隔离　`[security/06#S6]`

【读】`howto/godot/security.md#5. 检测到之后怎么办`

【做】
四种可接受反应：静默标记+不进排行榜、静默回滚到合法值、异步上报服务端、进作弊者匹配池。
⛔ 崩溃或弹窗 = 暴露检查点位置。
⚠ 与 `social` 域的接缝：刷屏与多开是信号，处置在服务端（风控累积风险分），
⚠ 且**合法用户开两个窗口不该封号**。

【产出】反应实现（四种之一，无崩溃/弹窗）

【判据】触发检测后无任何可观测反应（不崩、不弹窗、不卡死）

【审】`audit/godot/security.md#42`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：算法固定 SHA-256，比较走常量时间
const ALGO := HashingContext.HASH_SHA256    # ⛔ hmac_digest 仅支持 SHA-1/SHA-256
const NONCE_BYTES := 16                     # 官方要求 ≥16 字节
const CLOCK_SKEW_SEC := 300                 # |now - ts| 容差
const REPLAY_TTL_SEC := 600                 # nonce 集合 TTL，官方建议 5–10 分钟

func _verify_mac(data: PackedByteArray, mac: PackedByteArray) -> bool:
    var mine := Crypto.new().hmac_digest(ALGO, _hmac_key, data)
    return Crypto.new().constant_time_compare(mine, mac)   # ⛔ 不是 ==
```

## 4. 验收清单

- [ ] 前后端规范串逐字节一致
- [ ] 算法为 SHA-256
- [ ] 密钥每次会话不同
- [ ] ⛔ 重放与超时戳均被拒
- [ ] ⛔ 无对 mac 的 `==` 比较
- [ ] ⛔ 检测后无崩溃/弹窗

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 签名总是对不上 | 规范串两端不一致 | S1 |
| 算法无效/结果异常 | 传了 SHA-512 | S2 |
| 解包即得密钥 | 固定字符串 | S3 |
| 请求可被重放 | nonce/偏移未校验 | S4 |
| 功能对但不安全 | 用 == 比 HMAC | S5 |
| 检测点被 NOP | 检测到就反馈 | S6 |
