# 07 安全验收（安全域）

> **本步交付**：敌意环境实测（改存档 / 改时钟 / 重放 / 改包）
> **对应**：流程 `howto/godot/security.md` · 审核 `audit/godot/security.md`

## 0. 交付物定义

安全域的 bug **在正常流程下几乎全部测不出来** ——
只在**改存档字节、改系统时间、重放请求、改包、开加速工具**时才出现。
所以本步验收的不是"功能能跑"，而是这些事发生后
**验签仍拦得住、判定仍由服务端、重放仍被拒、检测仍不给反馈**。

⛔ **全流程跑一遍全部通过，是最危险的假通过。**

## 2. 工序

### Step 1　改存档一个字节，验签必须拦下　`[security/07#S1]`

【读】`howto/godot/security.md#读取：先验签，再解密`

【做】
用十六进制编辑器翻转密文**一位**（不必知道结构），重新进游戏。
⛔ 只测"正常存档能读"——那验证的是读写管线，
⛔ 而验签路径从未被执行过。翻转一位若仍能读出，说明 HMAC 没生效或没覆盖全 payload。

【产出】翻转测试记录（多位各一次）

【判据】任一位翻转后验签失败，且不进入解密

【审】`audit/godot/security.md#43`


### Step 2　改系统时间到极端值，测每日奖励与体力　`[security/07#S2]`

【读】`howto/godot/security.md#4. 时间作弊`

【做】
把系统时间改到极端值（+10 年 / -10 年）各跑一次。
⛔ 只测正常时间——系统时钟可被玩家手动设置，
⛔ 而这个失效只在改时间后才出现，正常环境下全绿。

【产出】改时间实测记录（两个极端各一份）

【判据】改时间后可领取状态与服务端判定一致

【审】`audit/godot/security.md#44`


### Step 3　重放同一请求两次，第二次必须被拒　`[security/07#S3]`

【读】`howto/godot/security.md#请求签名：防篡改与重放，不能证明诚实`

【做】
抓包拿到一个合法请求，原样重发两次。
⛔ 只测"请求能成功"——重放窗口、nonce 集合、时钟偏移三条防线
⛔ 在正常单次请求下**一条都不会被触发**。

【产出】重放测试记录（含重启服务端后再试）

【判据】第二次被拒；服务端重启后仍被拒（nonce 不只在内存）

【审】`audit/godot/security.md#45`


### Step 4　抓包改 body，验签名必须失败　`[security/07#S4]`

【读】`howto/godot/security.md#请求签名：防篡改与重放，不能证明诚实`

【做】
中间人改一个字段（如数量、价格）后转发。
⛔ 只测"签名能通过"——改包路径从未被执行，
⛔ 而"有签名却不校验"是最常见的一类假安全。

【产出】改包测试记录（至少改 3 个不同字段）

【判据】任一项改动都导致验签失败

【审】`audit/godot/security.md#46`


### Step 5　⛔ 检测触发后不得有任何可观测反应　`[security/07#S5]`

【读】`howto/godot/security.md#5. 检测到之后怎么办`

【做】
人为触发每一种检测（改内存值、开加速、多开），
观察：不崩溃、不弹窗、不卡死、不断线。
⛔ 只测"检测能触发"——**反应才是真正决定成败的一半**，
⛔ 而可观测反应等于帮攻击者定位检查点。

【产出】检测反应记录（每种检测一份）

【判据】每种检测触发后界面与进程行为与正常时无异

【审】`audit/godot/security.md#47`


## 3. 验收清单

- [ ] ⛔ 翻转存档任一位被验签拦下
- [ ] 改系统时间（两个极端）后判定仍一致
- [ ] ⛔ 重放两次被拒，且重启服务端后仍被拒
- [ ] 改包改字段验签失败
- [ ] ⛔ 每种检测触发后无可观测反应

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 改了存档照样读 | HMAC 未覆盖全 payload | 01/S1（03/S3） |
| 改表即得收益 | 客户端计时 | 01/S2（05/S1） |
| 同一笔生效两次 | 无业务幂等键 | 01/S3（02/S3） |
| 抓包改价成功 | 签名未校验 | 01/S4（06/S1） |
| 检测点被 NOP | 有可观测反应 | 01/S5（06/S6） |
