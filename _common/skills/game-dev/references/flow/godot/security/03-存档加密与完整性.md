# 03 存档加密与完整性（安全域）

> **本步交付**：32 字节 key + 随机 IV + HMAC + 先验签后解密
> **对应**：流程 `howto/godot/security.md` · 审核 `audit/godot/security.md`

## 0. 交付物定义

1. key 正好 32 字节
2. 每次保存使用新的随机 IV，且 IV **真的传进了**加密调用
3. 加密之外另有 HMAC
4. ⛔ 先验签，后解密
5. ⛔ 先压缩后加密
6. IV 来自密码学安全随机数

## 1. 前置检查清单

- [ ] 已知 `open_encrypted` 的第四个参数 `iv` 默认为空
- [ ] 已知 key 必须 32 字节
- [ ] 已决定加密还是"只签名"
- [ ] 签名范围已包含所有影响收益的字段

## 2. 工序

### Step 1　⛔ key 必须正好 32 字节，短了不报"长度错"　`[security/03#S1]`

【读】`howto/godot/security.md#内置 API`

【做】
官方签名 `open_encrypted(path, mode_flags, key, iv = PackedByteArray())`，
官方 Note：*"The provided key must be 32 bytes long."*
⛔ 长度不对不会报"长度错"，只会拿到 `null` 或解出乱码，
⛔ 排查会被引向"密钥内容不对"，而去改一个长度没问题的密钥。

【产出】密钥派生实现（输出长度固定 32 字节）

【判据】`_key.size() == 32` 有断言，长度不符时立刻失败

【审】`audit/godot/security.md#21`


### Step 2　⛔ 不传 iv 就是空 IV：生成了不等于用上了　`[security/03#S2]`

【读】`howto/godot/security.md#内置 API`

【做】
`iv` 参数默认是空数组。相同密钥 + 相同（空）IV 时，
相同明文开头会产生**相同密文开头**，多个存档的前缀一模一样，
攻击者不用解出密钥就能推断结构。
⛔ 最隐蔽的错法：**代码里生成了随机 IV、写进了 payload、读出来也传了参，
但调用 `open_encrypted` 时漏了第四个参数** —— 表面完全规范，实际仍是空 IV。

【产出】加解密调用处显式传 iv

【判据】加密与解密两处调用都带第四个参数 iv

【审】`audit/godot/security.md#22`


### Step 3　⛔ 加密 ≠ 防篡改，必须再加 HMAC　`[security/03#S3]`

【读】`howto/godot/security.md#2. 单纯的轻量方案：只签名不加密`

【做】
CBC 可被比特翻转攻击：翻转密文某一位，解密后明文对应位也翻转，
**而且解密不会报错**。攻击者不改密钥就能改金币字段的某位。
⛔ 只加密不加 HMAC——篡改后的存档能正常读出来，
⛔ 表现为"金币莫名其妙变了"，而所有读写日志都是正常的。
ⓘ 很多游戏其实不需要加密，只需要"改了能发现"——只签名就够，还省性能。

【产出】HMAC 覆盖整个 payload（含 IV）

【判据】翻转密文任一位，验签失败且不会进入解密

【审】`audit/godot/security.md#23`


### Step 4　⛔ 顺序是先验签，再解密　`[security/03#S4]`

【读】`howto/godot/security.md#读取：先验签，再解密`

【做】
读取流程：读 magic → 读 version → 取 payload 与 mac → **先验签** → 签不对直接返回 → 再解密。
⛔ 先解密后验签——等于把攻击者构造的数据喂给解密器，
⛔ 解密器本身的边界（解压炸弹、异常结构）就成了攻击面。
⚠ 与 `save` 域的接缝：签名范围随字段增删变化，字段表改了要同步。

【产出】读取实现（验签在解密之前）

【判据】篡改后不产生任何解密调用

【审】`audit/godot/security.md#24`


### Step 5　⛔ 先压缩后加密，且不能链式调用　`[security/03#S5]`

【读】`howto/godot/security.md#内置 API`

【做】
`open_encrypted` 和 `open_compressed` **不能链式调用**：
要先 `Compression.compress()` 得到字节数组，再加密写入。
顺序必须是**先压缩后加密** —— 反过来压缩率接近零（密文不可压缩）。
⛔ 顺序反了不会报错，只表现为"存档没变小"，
⛔ 极易被当成压缩参数问题去调一个没问题的参数。

【产出】压缩+加密管线（顺序固定）

【判据】存档体积明显小于明文 JSON

【审】`audit/godot/security.md#25`


### Step 6　⛔ IV 必须用 CSPRNG，randi() 不是　`[security/03#S6]`

【读】`howto/godot/security.md#写入：[magic][version][IV][密文][HMAC]`

【做】
用 `Crypto.new().generate_random_bytes(n)` 生成 IV。
⛔ 用 `randi() % 256` 逐字节拼——`randi()` 不是密码学安全随机数，
IV 可预测等于没随机，而这就是 CBC 模式下 IV 的全部意义。
⛔ 表现是"每次 IV 都不同"（看起来随机），但可被预测，验证时根本查不出来。

【产出】`_random_bytes()` 实现（走 Crypto）

【判据】实现里不存在 `randi()` 参与密钥/IV/盐的生成

【审】`audit/godot/security.md#26`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：IV 必须真的传进 open_encrypted，且来自 CSPRNG
const KEY_BYTES := 32          # ⛔ 官方硬性：open_encrypted 的 key 必须 32 字节
const IV_SIZE := 16
const HMAC_SIZE := 32

func _random_bytes(n: int) -> PackedByteArray:
    return Crypto.new().generate_random_bytes(n)   # ⛔ 不是 randi()

func _encrypt(data: PackedByteArray, iv: PackedByteArray) -> PackedByteArray:
    var tmp := "user://.tmp_enc"
    # ⛔ 第四个参数 iv 必须传，漏传即空 IV
    var f := FileAccess.open_encrypted(tmp, FileAccess.WRITE, _key, iv)
    if f == null:
        return PackedByteArray()
    f.store_buffer(data); f.close()
    var out := FileAccess.get_file_as_bytes(tmp)
    DirAccess.remove_absolute(ProjectSettings.globalize_path(tmp))
    return out
```

## 4. 验收清单

- [ ] `_key.size() == 32`
- [ ] ⛔ 加密与解密两处都显式传了 iv
- [ ] 翻转密文任一位被验签拦下
- [ ] 验签在解密之前
- [ ] 存档体积小于明文 JSON
- [ ] ⛔ 密钥/IV 生成路径中无 `randi()`

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 存档读出乱码 | key 长度不对 | S1 |
| 多个存档前缀一模一样 | 空 IV（含"生成了没传"） | S2 |
| 金币莫名变化 | 只加密没签名 | S3 |
| 解密器被喂异常数据 | 先解密后验签 | S4 |
| 存档没变小 | 压缩加密顺序反了 | S5 |
| IV 看着随机但可预测 | 用 randi() | S6 |
