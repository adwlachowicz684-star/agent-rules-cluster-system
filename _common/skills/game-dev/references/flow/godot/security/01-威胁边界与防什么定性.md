# 01 威胁边界与防什么定性（安全域）

> **本步交付**：能防/防不住清单 + ROI 排序 + 反应策略先定
> **对应**：流程 `howto/godot/security.md` · 审核 `audit/godot/security.md`

## 0. 交付物定义

1. "能防 / 防不住"两张清单已写下，不是凭感觉
2. ROI 排序已定，预算投向已明确
3. 权威动作清单已列出（哪些必须服务端）
4. ⛔ 检测到之后的反应策略**先于**检测代码定下
5. PCK 加密的定位已认清（提高门槛，不是安全）

## 1. 前置检查清单

- [ ] 已写明"本作防什么、不防什么"
- [ ] 已知客户端密钥必然泄露
- [ ] 已列出哪些逻辑必须在服务端
- [ ] ⛔ 反应策略（静默/回滚/上报/隔离）已先定
- [ ] 未把 PCK 加密当成安全方案

## 2. 工序

### Step 1　先写"能防 / 防不住"两张清单，边界是结构性的　`[security/01#S1]`

【读】`howto/godot/security.md#0. 先说清楚边界（最重要的一节）`

【做】
把威胁写成两栏。**能防**：记事本/十六进制编辑器改存档、随手搜内存改数值、改系统时间。
**防不住**：会解包 PCK 的人、定向逆向的人、速度倍率工具（需额外检测）。
⛔ 不写这两张清单直接开工——"防作弊"会变成一个没有终点的需求，
⛔ 每个新功能都会被问"这个能防吗"，而边界本该一次性定死。

注意这是**结构性**结论，不是实现得不好：
密钥必须在客户端（否则游戏解不开自己的存档）→ 玩家拥有客户端完整访问权 → 密钥一定能被拿到。

【产出】能防/防不住两栏清单（写进设计文档）

【判据】指着任一威胁，能说出它属于哪一栏，且理由不是"应该能防"

【审】`audit/godot/security.md#11`


### Step 2　客户端密钥必然泄露：签名只提供完整性，不提供真实性　`[security/01#S2]`

【读】`howto/godot/security.md#请求签名：防篡改与重放，不能证明诚实`

【做】
把"有签名"当成"服务端可以信任数值"是本主题最大的误判。
签名层提供的是：完整性、绑定、提高批量构造的成本。
⛔ 它证明不了客户端没被篡改——密钥在客户端，攻击者能自己签。
⚠ 因此任何"客户端签了名所以数值可信"的推理，在本步就要否掉。

【产出】签名能力边界说明（写进接口文档）

【判据】接口文档里不存在"因有签名而信任客户端数值"的表述

【审】`audit/godot/security.md#12`


### Step 3　列出权威动作清单：哪些必须服务端判　`[security/01#S3]`

【读】`howto/godot/security.md#6. 联网游戏：唯一可靠的方案`

【做】
逐项列出并标注归属：**必须服务端**——排行榜提交、货币变动、胜负判定、每日奖励。
理由统一：客户端提交的是"数字"，服务端不知道它怎么来的。
⛔ 不列清单就开工——"这个要不要服务端校验"会在每个功能点被重新争论一次，
⛔ 而争论的结论通常取决于当时谁在写，最后形成一半校验一半不校验的烂摊子。

【产出】权威动作清单（含归属与理由）

【判据】清单里每项都能说出"为什么必须服务端"，且高价值动作无一遗漏

【审】`audit/godot/security.md#13`


### Step 4　⛔ 反应策略必须先于检测代码定下　`[security/01#S4]`

【读】`howto/godot/security.md#5. 检测到之后怎么办`

【做】
先定：检测到之后**不给攻击者反馈**。
可选反应：静默标记+不进排行榜、静默回滚到合法值、异步上报服务端、进作弊者匹配池。
⛔ 崩溃/弹窗警告 = 告诉修改者"你找到了关键检查点"，他会把检测函数 NOP 掉。
⚠ 这一步比检测本身更容易做错，⛔ 所以必须在写检测代码之前定完。

【产出】反应策略表（每种检测→对应反应）

【判据】不存在"检测到了就崩溃/弹窗"的反应项

【审】`audit/godot/security.md#14`


### Step 5　PCK 加密的定位是提高门槛，不是安全　`[security/01#S5]`

【读】`howto/godot/security.md#7. PCK 加密`

【做】
导出预设 → Encryption → 256-bit 密钥。**能防**：批量盗取素材、随手查看脚本内容。
**防不住**：下定决心的人——密钥在二进制里能被提取。
⚠ 官方没有"PCK 加密是安全的"这种说法。
⛔ 把 PCK 加密写进"安全方案"一栏，会让后面的威胁清单整体失真。

【产出】PCK 加密定位说明（门槛，非安全）

【判据】设计文档里 PCK 加密未出现在"防住了什么"一栏

【审】`audit/godot/security.md#15`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：边界与反应策略是常量，不是运行时决定
const DETECT_REACTION_SILENT := 0      # 静默标记
const DETECT_REACTION_ROLLBACK := 1    # 静默回滚
const DETECT_REACTION_REPORT := 2      # 异步上报

# ⛔ 崩溃与弹窗不在枚举里：任何可观测反应都在帮攻击者定位检查点
var _reaction_by_kind := {
    "gold": DETECT_REACTION_ROLLBACK,
    "speed": DETECT_REACTION_REPORT,
}
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 防作弊需求永远做不完 | 没定边界 | S1 |
| 服务端被假包刷 | 把签名当真实性 | S2 |
| 一半校验一半不校验 | 没列权威清单 | S3 |
| 检测逻辑被 NOP 掉 | 检测到就崩溃 | S4 |
| 以为加密了就安全 | PCK 定位误判 | S5 |
