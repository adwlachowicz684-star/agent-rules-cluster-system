# 05 随机性、确定性与模糊测试（测试域）

> **本步交付**：固定种子口径 + 不变量判定器 + 畸形输入存活测试
> **对应**：流程 `howto/godot/testing-advanced.md` · 审核 `audit/godot/testing-advanced.md`

## 0. 交付物定义

1. 随机相关逻辑有**不变量**测试，⛔ 不是枚举期望值
2. 判定器**不含随机**，同样输入给出同样结论
3. 每次随机测试都**记录并打印种子**，失败可复现
4. 模糊测试喂的是**变异后的合法输入**，⛔ 不只是纯随机
5. 模糊测试在**目标平台**跑过
6. 确定性测试用**固定 delta**，比对关键状态

## 1. 前置检查清单

- [ ] 至少一条属性测试（不变量）覆盖随机玩法
- [ ] 判定器里无 `randi` / 无未固定种子的 RNG
- [ ] 失败日志里有种子值，且能用该种子复现
- [ ] 模糊用例含"变异合法输入"路径
- [ ] 模糊在目标平台跑过（至少移动端或主机之一）
- [ ] 确定性用例用固定 delta，且遍历前已排序

## 2. 工序

### Step 1　属性测试断言不变量，⛔ 不枚举期望值　`[testing/05#S1]`

【读】`howto/godot/testing-advanced.md#1. 属性测试：检查不变量，不是穷举输出`

【做】
对随机逻辑断言**不变量**（总量守恒、非负、单调、上下界），
而不是"输入 A 应得 B"。
⛔ 写成一张"输入 → 期望输出"的用例表 ——
那就退化成了普通单元测试，
⛔ 覆盖不到没被枚举到的输入，
而随机玩法出问题的地方**恰恰在没枚举到的组合**。

ⓘ 判据：不变量应当是"任何输入都成立"的命题。
⛔ "抽 10 次必出 1 个稀有"不是不变量（那是期望），
"抽 10 次产出的稀有数 ≤ 10"才是。

【产出】不变量清单（每条都能对任意输入成立）

【判据】随机换种子跑 100 轮，不变量始终成立。

【审】`audit/godot/testing-advanced.md#11`

### Step 2　⛔ 判定器里不能有随机 —— 否则"不变量"每次都不同　`[testing/05#S2]`

【读】`howto/godot/testing-advanced.md#1. 属性测试：检查不变量，不是穷举输出`

【做】
判定器（检查不变量的那段代码）必须**确定性**，
用到的 RNG 要么不随机、要么种子固定。
⛔ 判定器自己也随机 —— 同一次运行里"不变量"的定义在变，
⛔ 表现为"偶发红但看不出规律"，
而排查时不会去查判定器，因为"它只是在检查结果"。

ⓘ 这是属性测试特有的陷阱：
被测代码和检查代码都是自己写的，
⛔ 两者都可能是错的，而报错只会指向被测代码。

【产出】判定器确定性约定（种子固定或不用随机）

【判据】同一输入跑两次判定器，结论完全一致。

【审】`audit/godot/testing-advanced.md#2`

### Step 3　随机测试必须记录并打印种子 —— 失败要能复现　`[testing/05#S3]`

【读】`howto/godot/testing-advanced.md#1. 属性测试：检查不变量，不是穷举输出`

【做】
每次随机测试前固定种子并**打印出来**；
失败时把种子与最小化后的输入一起落到文件。
⛔ 不记录种子 —— 失败的是第 8734 次随机，
⛔ 重跑一次就过了（种子变了），
表现为"这个测试不稳定"，
⛔ 而处置方式通常是加 retry 或直接跳过 —— 真 bug 就此消失。

ⓘ 配套的"最小化反例"（固定种子后二分缩小规模）见 `howto` 该节；
⛔ 不做最小化，反例可能有几千步，没人会去读。

【产出】种子记录格式 + 反例落库路径

【判据】用日志里的种子重跑，能复现同一个失败。

【审】`audit/godot/testing-advanced.md#1`

### Step 4　模糊测试要变异合法输入，⛔ 纯随机命中不了深层分支　`[testing/05#S4]`

【读】`howto/godot/testing-advanced.md#2. 模糊测试：目标是进程存活`

【做】
以**已知良好的存档 / 包**为基线，随机改若干字节后再喂进去。
⛔ 只喂纯随机字节 —— 绝大多数在前几个字节就被格式校验挡掉，
⛔ 表现为"跑了几万次全过、覆盖率虚高"，
而深层的解析分支**一次都没被执行到**。

ⓘ 这与 04/S5 的分工：
04 定"坏档必须返回明确错误"的契约，
本步负责**批量**验证该契约在大量畸形输入下都成立。

【产出】变异策略（改 N 个字节）+ 基线样本来源

【判据】能看到模糊用例确实走到了解析器的深层分支（可插桩计数）。

【审】`audit/godot/testing-advanced.md#3`

### Step 5　模糊的目标是进程存活，⛔ 且要在目标平台跑　`[testing/05#S5]`

【读】`howto/godot/testing-advanced.md#2. 模糊测试：目标是进程存活`

【做】
判据定为"要么成功、要么返回明确错误，绝不崩溃"，
并**在目标平台**跑一轮。
⛔ 只在桌面跑 —— 移动端 / 主机的内存对齐、字节序、文件系统行为不同，
⛔ 表现为"桌面稳如磐石，真机一喂脏数据就崩"，
而崩的是**真实玩家**。

ⓘ 模糊测试⛔ 不证明逻辑正确，只证明"喂垃圾不崩"：
两者都要有（见 05/S1 的属性测试）。

ⓘ 迭代次数要有上限（与 CI 时长预算挂钩），
⛔ 不设上限会让流水线无限延长。

【产出】存活判据 + 目标平台跑测记录 + 迭代上限

【判据】喂 1000 个变异输入，进程存活且每个都有明确结论。

【审】`audit/godot/testing-advanced.md#13`、`audit/godot/testing-advanced.md#14`

### Step 6　确定性测试用固定 delta，⛔ 且遍历前先排序　`[testing/05#S6]`

【读】`howto/godot/testing-advanced.md#5. 确定性测试：固定输入世界`

【做】
回放时每一步传入**固定 delta**（如 `1.0/60.0`），
遍历字典 / 哈希表前**先排序**。
⛔ 用真实 `delta` —— 同一次录制在不同机器上结果不同，
⛔ 表现为"回放对不上"，而排查被引向同步逻辑或网络，
⛔ 与 `netsync` 域的回滚问题极难区分。

ⓘ 浮点跨平台有微小差异（编译器优化、SIMD），
⛔ 严格比特一致很难，比**关键状态**（取整后的位置、死亡数、得分）即可。

【产出】固定 delta 约定 + 排序约定 + 关键状态比对清单

【判据】同一录制在不同机器跑两次，关键状态完全一致。

【审】`audit/godot/testing-advanced.md#9`、`audit/godot/testing-advanced.md#12`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：固定种子 + 确定性判定器 + 变异合法输入 + 固定 delta
const FUZZ_ITERATIONS := 2000      # ⛔ 与 CI 时长预算挂钩，不设上限会拖垮流水线
const MAX_LOOT := 10               # ⓘ 承接业务上限：掉落配置表里的单次最大产出数

func test_invariant_with_seeded_rng() -> void:
    var rng := RandomNumberGenerator.new()
    rng.seed = 20240928                      # ⛔ 不记录种子：失败无法复现
    print("seed=20240928")
    for i in FUZZ_ITERATIONS:
        var loot := Loot.roll(rng)
        # ⓘ 断言不变量（任何输入都成立），⛔ 不枚举期望值
        assert_true(loot.size() >= 1, "至少产出一件")
        assert_true(loot.size() <= MAX_LOOT, "不超过上限")

func fuzz_with_mutated_good_input() -> void:
    var good := FileAccess.get_file_as_bytes("res://tests/saves/good.sav")
    for i in FUZZ_ITERATIONS:
        var buf := good.duplicate()
        for k in mini(8, buf.size()):        # ⛔ 纯随机字节命中不了深层分支
            buf[rng.randi_range(0, buf.size() - 1)] = rng.randi_range(0, 255)
        var r := SaveParser.parse(buf)
        assert_false(r == null and not SaveParser.last_error_is_recoverable(),
            "畸形输入应返回可恢复错误，而不是崩溃")

func replay(inputs: Array) -> void:
    for i in inputs:
        _step(i, 1.0 / 60.0)                 # ⛔ 用真实 delta：不同机器结果不同
```

## 4. 验收清单

- [ ] 有不变量测试，且换了种子仍成立
- [ ] 判定器确定性，无随机
- [ ] 失败日志含种子，可复现
- [ ] 模糊含变异合法输入路径
- [ ] 模糊在目标平台跑过，且有迭代上限
- [ ] 确定性用固定 delta，遍历前排序

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 测试覆盖很全但随机玩法仍出 bug | 属性测试退化成用例表 | S1 |
| 偶发红且无规律 | 判定器里有随机 | S2 |
| 失败重跑就过了 | 没记录种子 | S3 |
| 跑几万次全过但仍有解析崩溃 | 只喂纯随机 | S4 |
| 桌面稳、真机崩 | 模糊只在桌面跑 | S5 |
| 回放对不上，被引向同步逻辑 | 用了真实 delta | S6 |
