# 04 存档回归与兼容性（测试域）

> **本步交付**：历史版本样本库 + 往返测试 + 迁移路径
> **对应**：流程 `howto/godot/testing.md` · 审核 `audit/godot/testing.md`

## 0. 交付物定义

1. 每个发版版本的存档样本**已入库**，且有入库时点约定
2. 样本库覆盖**所有历史格式**，⛔ 不是只留最新版
3. 往返测试（存 → 读 → 比对）已存在
4. 迁移路径本身有测试，⛔ 不只是"能读出来"
5. 坏档 / 截断档有明确错误返回，⛔ 不崩溃

## 1. 前置检查清单

- [ ] `tests/saves/v1...vN/` 各版本样本齐全
- [ ] 样本入库发生在**格式变更之前**（不是改完再补）
- [ ] 往返测试比对的是关键字段
- [ ] 每个迁移步骤都有对应用例
- [ ] 截断 / 乱码存档返回明确错误而非崩溃

## 2. 工序

### Step 1　⛔ 样本必须在格式变更之前存 —— 改完再补等于没有　`[testing/04#S1]`

【读】`howto/godot/testing.md#5. 存档回归测试（最值得做的一条）`

【做】
约定"改存档格式的第一步，是把**当前版本**的样本存进测试目录"。
⛔ 改完格式再补样本 —— 补进去的已经是新格式，
回归网从未覆盖旧格式，
⛔ 表现为"上线后老玩家存档读不了"，
而此时**没有任何样本可以复现**，
⛔ 只能靠线上日志猜，而日志里只有"读取失败"。

ⓘ 这条的破坏力在于**不可逆**：
旧格式一旦没人保存，就永远失去了验证它的能力。

【产出】样本入库时点约定（写进发版流程）

【判据】指着格式变更的那次提交，能看到它**之前**已有对应样本。

【审】`audit/godot/testing.md#6`

### Step 2　样本库要覆盖所有历史版本，⛔ 不是只留最新　`[testing/04#S2]`

【读】`howto/godot/testing.md#5. 存档回归测试（最值得做的一条）`

【做】
`tests/saves/` 下保留 v1..vN 全部版本样本。
⛔ 只留最新版本 —— 老玩家的存档恰恰是旧格式，
⛔ 表现为"每次格式升级都会丢一批老玩家数据"，
而测试一直是绿的（因为只测了新格式）。

ⓘ 与 S1 的区别：S1 是"能不能存到样本"，
本步是"存到的样本够不够覆盖真实分布"。
⛔ 只覆盖最新 = 测试在测一个真实玩家根本不存在的状态。

【产出】版本 × 样本清单

【判据】任意历史版本号都能指出对应样本文件。

【审】`audit/godot/testing.md#20`

### Step 3　往返测试比对关键字段，⛔ 不是"能反序列化就行"　`[testing/04#S3]`

【读】`howto/godot/testing.md#5. 存档回归测试（最值得做的一条）`

【做】
存 → 读 → 比对**关键字段**（货币、等级、实例 ID、版本字段）。
⛔ 只断言"读出来不为空" —— 字段错位、类型变了、ID 串了
全都不会被发现，⛔ 表现为"读档后数据看着都在，但某些东西不对了"，
而这类反馈在玩家侧最难描述，排查成本极高。

ⓘ 浮点与字典顺序跨平台不稳定，
⛔ 逐字节比会造成偶发红（见 02/S3），比关键状态即可。

【产出】关键字段清单 + 往返断言

【判据】把序列化里一处字段名改错，往返测试必须红。

【审】`audit/godot/testing.md#20`、`audit/godot/testing.md#13`

### Step 4　迁移路径本身要测，⛔ 不能只测结果能读　`[testing/04#S4]`

【读】`howto/godot/testing.md#5. 存档回归测试（最值得做的一条）`

【做】
为每个迁移步骤写用例：旧字段 → 新字段的映射、
默认值填补、废弃字段丢弃。
⛔ 只测"能读出来" —— 迁移可能把值填成默认值而不报错，
⛔ 表现为"老玩家上线后进度还在、但某项数值变了"，
而这类差异没有任何日志，只能靠玩家投诉发现。

ⓘ 与 `save` 域的分工：
迁移策略与版本号口径见 `save`，
⛔ 本域只定"迁移必须有测试、测试必须比字段值"。

【产出】迁移用例集（每个版本跃迁一条）

【判据】把某步迁移的默认值改错，对应用例必须红。

【审】`audit/godot/testing.md#6`

### Step 5　坏档要有明确错误，⛔ 不能崩溃 —— 且要有用例　`[testing/04#S5]`

【读】`howto/godot/testing.md#7. 上线前检查`

【做】
截断、乱码、半截写入的存档，解析器必须返回**明确错误**，
并写进用例。
⛔ 崩溃或静默返回空 —— 玩家侧表现为"进不去游戏"，
⛔ 而崩溃堆栈如果没有开启调用栈追踪（release 默认不开），
线上拿不到任何可用信息。

ⓘ 官方口径：回溯（backtrace）默认只在 editor / debug 构建可用，
release 需显式开启 `debug/settings/gdscript/always_track_call_stacks`。
⛔ 表现为"本地能复现、线上只有一句崩溃日志"。

ⓘ 畸形输入的**批量**存活验证见 05 模糊测试，
⛔ 本步只定"坏档必须返回明确错误"这条契约。

【产出】坏档错误码 + 三个用例（截断 / 乱码 / 空文件）

【判据】喂截断存档，返回明确错误且不崩溃。

【审】`audit/godot/testing.md#12`、`audit/godot/testing.md#16`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：全版本样本 + 关键字段比对 + 坏档明确错误
const SAVE_DIRS := ["v1", "v2", "v3"]   # ⛔ 不只留最新版本

func test_old_saves_load() -> void:
    for v in SAVE_DIRS:
        var path := "res://tests/saves/%s/save.dat" % v
        var data := SaveManager.load_from(path)
        # ⛔ 只断言非空：字段错位根本发现不了
        assert_true(data.size() > 0, "%s 应能读取" % v)
        assert_true(data.has("version"), "%s 应有版本字段" % v)
        assert_eq(data["version"], v, "%s 版本字段应原样保留" % v)
        assert_true(data.has("gold"), "%s 应有货币字段" % v)

func test_corrupted_save_returns_error() -> void:
    var truncated := FileAccess.get_file_as_bytes("res://tests/saves/v3/save.dat")
    truncated = truncated.slice(0, truncated.size() / 2)   # 截断
    var r := SaveManager.parse(truncated)
    # ⛔ 崩溃或静默返回空：玩家直接进不去游戏
    assert_ne(r, null, "截断存档应返回结果对象")
    assert_false(r.ok, "截断存档应标记为失败")
    assert_true(r.error != "", "截断存档应给出明确错误")
```

ⓘ 迁移用例按版本跃迁各写一条（v1→v2、v2→v3…），
⛔ 只测"最新版本能读"等于没测迁移。

## 4. 验收清单

- [ ] 各版本样本齐全，且入库早于格式变更
- [ ] 往返测试比关键字段
- [ ] 每个版本跃迁有迁移用例
- [ ] 截断 / 乱码 / 空文件返回明确错误
- [ ] release 构建已开启调用栈追踪（否则线上崩溃无线索）

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 上线后老档读不了，且无法复现 | 样本没在改格式前存 | S1 |
| 每次升级丢一批老玩家数据 | 样本只覆盖最新格式 | S2 |
| 读档后数据看着在但不对 | 只断言非空 | S3 |
| 老玩家某项数值悄悄变了 | 迁移只测能读 | S4 |
| 线上崩溃日志没有堆栈 | release 未开调用栈追踪 | S5 |
