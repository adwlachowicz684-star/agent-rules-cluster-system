# 02 单元与集成测试（测试域）

> **本步交付**：纯逻辑测试集 + 隔离口径 + 失败即红的链路
> **对应**：流程 `howto/godot/testing.md` · 审核 `audit/godot/testing.md`

## 0. 交付物定义

1. 纯逻辑（伤害、经济、背包、寻路）已有单元测试
2. 每个测试的临时节点 / 文件**都会释放**，⛔ 不污染后续用例
3. 集成测试覆盖"多系统协作"（存档→读档→状态一致）
4. 测试**顺序无关**：单跑过、全跑过、乱序跑都过
5. 测试代码本身也在 lint 范围内

## 1. 前置检查清单

- [ ] 纯逻辑每个都能指出对应测试
- [ ] 临时节点用 `add_child_autofree`（或等价释放），文件用完删除
- [ ] 有一条集成测试走完"存档 → 读档 → 比对状态"
- [ ] 随机打乱测试顺序跑一遍仍全过
- [ ] 测试目录不在 lint 排除列表里

## 2. 工序

### Step 1　临时节点必须自动释放 —— 测试间污染最难查　`[testing/02#S1]`

【读】`howto/godot/testing.md#2. GUT（Godot 单元测试框架）`

【做】
每个测试创建的节点用 `add_child_autofree()`（或 `queue_free()` 收尾）。
⛔ 直接 `add_child()` 不管 —— 上一个用例的节点仍挂在树上，
下一个用例的 `get_node()` / 信号连接会命中它们，
⛔ 表现为"单跑这个用例是过的，全跑就红"，
而排查时必然被引向被测试的业务代码。

ⓘ 这是**顺序依赖**类问题的第一大来源：
测试代码本身有 bug，但所有报错都指向业务代码。

【产出】隔离公约（节点 + 文件 + 全局单例的清理）

【判据】任意用例单独跑与全量跑结果一致。

【审】`audit/godot/testing.md#1`、`audit/godot/testing.md#13`

### Step 2　测试产生的文件也要清理 —— 别让用例互相读到对方产物　`[testing/02#S2]`

【读】`howto/godot/testing.md#3. 不装框架的最小方案`

【做】
写进 `user://` 的临时文件在用例结束时删除，
或统一写到带用例名的独立子目录。
⛔ 共用一个 `user://test.sav` ——
两个用例并发/先后写同一路径，后者读到前者的残留，
⛔ 表现为"存档往返偶发失败"，而重跑一次就好了，
⛔ 于是被归类为"不稳定测试"而跳过 —— 真问题就此消失。

【产出】临时文件命名与清理口径

【判据】跑完一轮后 `user://` 下无测试残留；连跑两轮结果一致。

【审】`audit/godot/testing.md#14`

### Step 3　集成测试要跨系统 —— 单系统全绿不代表组合对　`[testing/02#S3]`

【读】`howto/godot/testing.md#3. 不装框架的最小方案`

【做】
至少一条集成测试走完完整链路：
构造状态 → 存档 → 读档 → 比对关键字段。
⛔ 只测单个系统的单元 ——
`SaveManager` 单独测能存能读、`Inventory` 单独测能加能删，
但**组合起来字段对不上**（比如实例 ID 序列化后变了），
⛔ 而两边的单测都是绿的。

ⓘ 比对的是**关键状态**而不是逐字节：
浮点在不同平台有微小差异，⛔ 逐字节比会造成跨平台偶发红。

【产出】至少一条跨系统集成用例

【判据】删掉迁移/序列化里的一处字段映射，该用例必须红。

【审】`audit/godot/testing.md#13`

### Step 4　测试不能依赖本地环境 —— 时区、语言、路径大小写　`[testing/02#S4]`

【读】`howto/godot/testing.md#7. 上线前检查`

【做】
测试里固定时区与语言环境；路径引用统一大小写与分隔符。
⛔ 依赖本机环境 —— 表现为"我机器上过、CI 上红"，
⛔ 而这类问题几乎总被归因于"CI 环境有问题"，
于是有人在 CI 里加环境变量绕过，测试从此不再验证真实行为。

ⓘ 与 `i18n` 域同源：本地化相关的断言必须显式指定 locale，
⛔ 不能沿用运行环境的默认语言。

【产出】环境固定的清单（时区 / locale / 路径）

【判据】改本机 locale 与时区后测试结果不变。

【审】`audit/godot/testing.md#17`

### Step 5　测试代码也要过 lint —— 否则它先腐烂　`[testing/02#S5]`

【读】`howto/godot/testing.md#4. 静态检查进 CI`

【做】
把 `tests/` 目录**留在** lint 与格式检查范围内。
⛔ 把测试目录排除 —— 测试代码质量不受约束，
几个月后测试里满是硬编码、复制粘贴、失效断言，
⛔ 表现为"测试很全但抓不到回归"，
而没人会去查测试本身，因为"测试是在保护我们的"。

ⓘ 这是本域特有的反身性问题：
测试是质量的工具，但它自己也是代码，⛔ 不受约束的工具会先失效，
且失效时不产生任何信号。

【产出】lint 配置（测试目录在范围内）+ 已有的行内抑制说明

【判据】在测试文件里故意写一处未使用变量，lint 报出来。

【审】`audit/godot/testing.md#18`、`audit/godot/testing.md#5`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：自动释放 + 独立临时路径 + 固定 locale
extends GutTest

const TMP_DIR := "user://_tests/"

func before_each() -> void:
    DirAccess.make_dir_recursive_absolute(TMP_DIR)
    TranslationServer.set_locale("zh_CN")   # ⛔ 不沿用运行环境默认语言

func after_each() -> void:
    # ⛔ 不清理：下一个用例会读到本用例残留
    for f in DirAccess.open(TMP_DIR).get_files():
        DirAccess.remove_absolute(TMP_DIR.path_join(f))

func test_inventory_roundtrip() -> void:
    var inv := Inventory.new()
    add_child_autofree(inv)          # ⛔ 不用 add_child：会污染后续用例
    inv.add("sword", 1)
    var path := TMP_DIR.path_join("inv_test.sav")
    inv.save_to(path)
    var loaded := Inventory.new()
    add_child_autofree(loaded)
    loaded.load_from(path)
    assert_eq(loaded.count("sword"), 1, "读档后数量应一致")
    # ⓘ 比关键状态，⛔ 不逐字节比（浮点跨平台有微小差异）
```

## 4. 验收清单

- [ ] 纯逻辑有单元测试
- [ ] 节点与临时文件都会清理
- [ ] 至少一条跨系统集成用例
- [ ] 乱序跑仍全过
- [ ] 测试目录在 lint 范围内

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 单跑过、全跑红 | 节点未释放 / 共享状态 | S1 |
| 存档往返偶发失败 | 多个用例共写同一临时文件 | S2 |
| 各系统单测都绿、组合出错 | 没有集成测试 | S3 |
| 我机器上过、CI 上红 | 依赖时区 / locale / 路径 | S4 |
| 测试很全却抓不到回归 | 测试代码本身在腐烂 | S5 |
