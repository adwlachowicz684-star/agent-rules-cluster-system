# 06 视觉回归与性能基准（测试域）

> **本步交付**：基线管理 + 阈值断言 + 分位数判据
> **对应**：流程 `howto/godot/testing-advanced.md` · 审核 `audit/godot/testing-advanced.md`

## 0. 交付物定义

1. 已实测确认：**截图在本项目的 CI 环境里真的能出图**
2. 视觉基线**经人工确认是对的**，且有确认记录
3. 阈值非 0，且相机 / 种子 / 时间 / 随机状态已固定
4. 性能基准看 **p95 / p99**，且已预热
5. 基准有**阈值断言**，且在目标硬件跑过
6. 基线以**可 diff 的形式**存放

## 1. 前置检查清单

- [ ] 在 CI 环境（含 headless）下截出的图不是全黑/空白
- [ ] 每张基线都有"人工看过是对的"的记录
- [ ] 差异阈值 > 0，且渲染前固定了相机、种子、时间
- [ ] 基准输出 p50/p95/p99，且有预热帧
- [ ] 基准有阈值断言，并在目标硬件跑过一轮
- [ ] 基线文件可被文本 diff 或可视化比对

## 2. 工序

### Step 1　⛔ 先确认 CI 环境能真的出图 —— headless 下可能截到全黑　`[testing/06#S1]`

【读】`howto/godot/testing-advanced.md#3. 视觉回归：截图 diff`

【做】
在**真实的 CI 环境**里截一张图，确认它不是全黑 / 空白。
⛔ 认为 `--headless` 也能截图 ——
headless 下没有真实显示输出，
⛔ 表现为两种：截出来**全黑**被存成基线（此后一切都"通过"），
或等待渲染帧的 `await` **永远不返回**（测试挂死）。

ⓘ 第一种尤其危险：它给出的信号是"视觉回归通过"，
与 assert 在 release 下不执行（见 01/S1）是同一类失败——
**机制没跑起来，却显示通过**。

ⓘ 需要真实渲染时用 xvfb 之类提供显示环境，
并在流水线里写明这一步依赖它。

【产出】CI 环境出图结论（能出图 / 需 xvfb / 不支持）

【判据】CI 产物里能下载到一张**有内容**的截图。

【审】`audit/godot/testing-advanced.md#15`

### Step 2　⛔ 基线必须人工确认过是对的 —— 错图会永远"通过"　`[testing/06#S2]`

【读】`howto/godot/testing-advanced.md#3. 视觉回归：截图 diff`

【做】
每张基线入库前**人工看一眼**并记录。
⛔ 直接把当前输出存成基线 ——
若那一刻画面本来就是错的（材质没加载、相机位置不对），
⛔ 这张错图就成了标准答案，
此后每次改动都"通过"，直到有人偶然看到画面才发现。

ⓘ 这与 04/S1（样本要在格式变更前存）是同一类问题：
**基线的正确性决定了整个回归网的价值**，
⛔ 而基线的正确性无法由程序自己判断。

【产出】基线清单 + 每条的人工确认记录

【判据】随机挑一张基线，能查到谁在什么时候确认过。

【审】`audit/godot/testing-advanced.md#4`

### Step 3　阈值不能设 0，⛔ 且渲染前必须固定相机 / 种子 / 时间　`[testing/06#S3]`

【读】`howto/godot/testing-advanced.md#3. 视觉回归：截图 diff`

【做】
设一个非零阈值（如 2% 像素差），并在截图前固定
相机、随机种子、时间、随机状态。
⛔ 阈值设 0 —— 抗锯齿、浮点差异、GPU 驱动差异都会造成微小像素差，
⛔ 结果是永远红，
⛔ 而永远红的检查，团队的实际处置是忽略它或删掉它。

ⓘ 这也是 S2 的延伸：
固定不彻底 → diff 全是噪声 → 阈值被迫放大到失去意义。
⛔ 阈值放大到 20% 时，绝大多数视觉劣化都能通过。

【产出】固定项清单 + 阈值取值（待实测）

【判据】同一份代码连截两次，差异远低于阈值（如 < 0.5%）。

【审】`audit/godot/testing-advanced.md#5`

### Step 4　性能看分位数，⛔ 且必须预热　`[testing/06#S4]`

【读】`howto/godot/testing-advanced.md#4. 性能基准：看分位数，不看平均值`

【做】
输出 p50 / p95 / p99 / max，并跳过预热帧再开始采样。
⛔ 看平均值 —— 玩家感受到的是**最差的那些帧**，
平均值会被大量正常帧抹平，
⛔ 表现为"基准达标但玩家说卡"。

ⓘ 不预热的后果：前几十帧包含加载、着色器编译、首次分配，
⛔ 把这些算进帧时间，会让基准**永远超标**，
⛔ 于是有人把阈值放宽 —— 放宽后的阈值再也抓不到真劣化。

【产出】分位数输出 + 预热帧数（待实测）

【判据】同一份代码连跑两次，p99 差异在可接受范围内。

【审】`audit/godot/testing-advanced.md#6`、`audit/godot/testing-advanced.md#7`

### Step 5　基准必须有阈值断言，⛔ 且在目标硬件上跑　`[testing/06#S5]`

【读】`howto/godot/testing-advanced.md#4. 性能基准：看分位数，不看平均值`

【做】
把 p99 与预算（如 60fps → 16.6ms）做断言，
并在**目标硬件**（至少最低配机型）上跑一轮。
⛔ 只输出数字不断言 —— 数字摆在那里没人看，
⛔ 表现为"无声劣化"：每次改动退一点点，
半年后帧率掉了 30%，而没有任何一次 CI 报红。

ⓘ 只在开发机跑的后果：开发机 200fps，
⛔ 移动端 / 主机的实际表现完全没被覆盖，
⛔ 而"开发机达标"会被当成"性能没问题"的依据。

【产出】阈值断言 + 目标硬件跑测记录

【判据】人为加一段耗时代码，基准必须报红。

【审】`audit/godot/testing-advanced.md#8`、`audit/godot/testing-advanced.md#6`

### Step 6　基线要可 diff —— 评审看不见的基线等于没有评审　`[testing/06#S6]`

【读】`howto/godot/testing-advanced.md#6. 落地建议`

【做】
基线以**可比对**的形式保存（图片文件 + 文本形式的指标／元数据），
让评审能在 PR 里直接看到差异。
⛔ 只存二进制且无任何可读元数据 ——
评审时看不到变了什么，
⛔ 于是"更新基线"变成无审查操作，
任何人都能一键让红线变绿。

ⓘ 这也是**落地顺序**的最后一条：
视觉回归维护成本最高、噪声最多，
⛔ 建议排在纯逻辑测试、性能基准、模糊测试**之后**再上（见 `howto` §6）。

【产出】基线存放格式（图 + 可读指标）

【判据】PR 里能看到基线差异的可读说明。

【审】`audit/godot/testing-advanced.md#10`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：非零阈值 + 固定输入 + 分位数 + 阈值断言
const DIFF_THRESHOLD := 0.02     # ⛔ 设 0：抗锯齿噪声导致永远红
const WARMUP_FRAMES := 60        # ⛔ 不预热：把加载开销算进帧时间
const MEASURE_FRAMES := 600
const P99_BUDGET_MS := 16.6      # 60fps 预算，⛔ 待实测（与目标硬件相关）

func capture(path: String) -> void:
    _fix_camera_and_seed()       # ⛔ 不固定：diff 全是噪声
    await RenderingServer.frame_post_draw
    var img := get_viewport().get_texture().get_image()
    # ⛔ CI 无显示环境时可能截到全黑，且会被存成基线（见 S1）
    img.save_png(path)

func bench_report(r: Dictionary) -> void:
    print("p50=%.1fms p95=%.1fms p99=%.1fms" % [r["p50"], r["p95"], r["p99"]])
    # ⛔ 只打印不断言：无声劣化永远不会被发现
    check(r["p99"] < P99_BUDGET_MS, "p99 帧时间", "%.1f" % P99_BUDGET_MS, "%.1f" % r["p99"])
```

ⓘ `DIFF_THRESHOLD` / `WARMUP_FRAMES` / `P99_BUDGET_MS` 均标为待实测，
⛔ 不凭行业惯例填（见 00 参数登记）。

## 4. 验收清单

- [ ] CI 环境能截出有内容的图

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 视觉回归一直通过但画面是错的 | headless 截到全黑并存成基线 | S1 |
| 错图成了标准答案 | 基线未人工确认 | S2 |
| 永远红，最后被忽略或删掉 | 阈值设 0 / 固定不彻底 | S3 |
| 基准达标但玩家说卡 | 看平均值 | S4 |
| 帧率半年掉了 30%，CI 没红过 | 基准无阈值断言 | S5 |
| 一键更新基线就能变绿 | 基线不可 diff、无评审 | S6 |
