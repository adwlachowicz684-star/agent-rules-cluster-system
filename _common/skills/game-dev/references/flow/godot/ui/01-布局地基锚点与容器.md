# 01 布局地基：锚点与容器（UI 域）

> **前置**：已定死逻辑分辨率与 stretch 模式（见 `00-域流程总览.md` 第 0 节）
> **本步交付**：控件在**任意窗口比例**下都不出屏、不错位、不重叠
> **对应**：做法 `howto/godot/ui.md` · 审核 `audit/godot/ui.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 把窗口从 1280×720 拖到 2560×1440 和 800×600，**元素都不出屏**
2. 拖窗口过程中 UI **实时跟随**，不需要重启
3. ⚠ 在容器（HBox/VBox/Grid）里的子项，**靠 `size_flags` 排列而不是锚点**
4. HUD 用 `CanvasLayer`，相机移动时**不跟着跑**

**产出物**（下游按名字对接）：

```text
项目设置：stretch mode / aspect / 逻辑分辨率
每个顶层控件的 anchors preset
容器子项的 size_flags 与 custom_minimum_size
```

⚠ 锚点不是"坐标"，是**约束**：`anchor`（比例）+ `offset`（像素）+ `size`。
⛔ 用鼠标拖出来的位置写死了 offset，换分辨率必然错位。

## 1. 前置检查清单

- [ ] 已定死逻辑分辨率（如 1280×720）
- [ ] ⚠ 已确认 `stretch mode / aspect`（⛔ 4.7 新项目默认值变了）

## 2. 工序

### Step 1　定 stretch 模式（⚠ 4.7 默认值变了）　`[ui/01#S1]`

【读】`howto/godot/ui.md#6. 分辨率自适应`

【做】
```text
display/window/stretch/mode      = canvas_items
display/window/stretch/aspect    = expand
display/window/size/window_width  = 1280
display/window/size/window_height = 720
```

⚠ **4.7 起新建项目的默认值变了**：

| 设置 | 4.6 及更早 | 4.7 新项目 |
|---|---|---|
| `stretch/mode` | `disabled` | **`canvas_items`** |
| `stretch/aspect` | `keep` | **`expand`** |

已有项目不受影响，但**新建项目默认就会缩放 UI**——
照 4.6 的写法做适配会出现"为什么我的 UI 被拉伸了"。

【产出】项目设置写入，重启后生效

【判据】⚠ 拖窗口改变比例，UI **缩放但不变形、不裁切**

【审】`audit/godot/ui.md#14`（硬编码像素坐标 → 换分辨率 UI 错位）

### Step 2　用锚点预设，不用手拖坐标　`[ui/01#S2]`

【读】`howto/godot/ui.md#1. 锚点：先理解约束模型`

【做】
```gdscript
control.set_anchors_preset(Control.PRESET_CENTER)        # 居中
control.set_anchors_preset(Control.PRESET_FULL_RECT)     # 铺满父容器
control.set_anchors_preset(Control.PRESET_BOTTOM_RIGHT)  # 右下角
```

⚠ 用 `expand` 时，UI 元素**必须靠锚点定位**，⛔ 不能写死像素坐标——
否则宽屏下 HUD 会跑到屏幕外。

【产出】每个顶层控件都调用了 `set_anchors_preset`

【判据】⚠ 全项目搜索**没有** `position = Vector2(` 给 Control 赋值的写法

【审】`audit/godot/ui.md#7`（硬编码像素坐标）

### Step 3　容器子项用 size_flags，不用锚点　`[ui/01#S3]`

【读】`howto/godot/ui.md#1. 锚点：先理解约束模型` 的 ⚠ 提示

【做】⚠ **在容器（HBox/VBox/Grid）里的子项，锚点设置会被容器覆盖**。
容器内排列用 `size_flags` 和 `custom_minimum_size`，⛔ 不是锚点。

【产出】容器内子项只设 `size_flags` / `custom_minimum_size`

【判据】⚠ 故意给容器内子项设一个错的锚点，**布局不变**（证明被容器接管）

【审】`audit/godot/ui.md#15`（硬编码像素坐标）

### Step 4　HUD 用 CanvasLayer　`[ui/01#S4]`

【读】`howto/godot/ui.md#2. HUD（血条 + 分数）`

【做】
```
HUD (CanvasLayer)
└── MarginContainer          ← 用 theme_override_constants/margin 留边
    └── VBoxContainer
        ├── HealthBar (ProgressBar)
        │   └── HpText (Label)   ← anchors = FULL_RECT，覆盖在血条上
        └── ScoreLabel (Label)
```

⚠ HUD 用 **CanvasLayer**，⛔ 不要用 CanvasItem 直接挂在游戏场景里——
否则相机移动时 HUD 跟着跑。

【产出】移动相机，HUD 元素**屏幕位置不变**

【判据】⚠ 让相机跑一段路，HUD 在屏幕上**纹丝不动**

【审】`audit/godot/ui.md#3`（UI 不用 CanvasLayer → 相机移动时 HUD 跟着跑）

### Step 5　留边用 MarginContainer　`[ui/01#S5]`

【读】`howto/godot/ui.md#2. HUD（血条 + 分数）` 的场景结构

【做】边距用 `MarginContainer` 的 `theme_override_constants/margin`，
⛔ 不是给每个子项设 offset。

⚠ 直接设 offset 的话，换分辨率时"离边 20px"会变成"离边 20 逻辑像素"——
在小窗口下占比过大。

【产出】边距由 MarginContainer 统一控制

【判据】⚠ 改 MarginContainer 的 margin，所有子项**一起**移动

【审】`audit/godot/ui.md#16`（硬编码像素坐标）

## 3. 参考实现

```gdscript
# hud.gd
extends CanvasLayer

@onready var _health_bar: ProgressBar = $MarginContainer/VBox/HealthBar
@onready var _score_label: Label = $MarginContainer/VBox/ScoreLabel
@onready var _hp_text: Label = $MarginContainer/VBox/HealthBar/HpText

func _ready() -> void:
    # ⚠ 血条文字覆盖在进度条上，用 FULL_RECT 而不是算坐标
    _hp_text.set_anchors_preset(Control.PRESET_FULL_RECT)
    _hp_text.horizontal_alignment = HORIZONTAL_ALIGNMENT_CENTER
```

⚠ `ProgressBar` 自带的 `percent_visible` 建议关掉，用自己的 `Label` 更可控
（"80 / 100" 比 "80%" 信息量大，且不受进度条样式影响）。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 换分辨率 UI 错位 | 硬编码坐标 | S2 |
| 宽屏下 HUD 出屏 | 没用锚点 | S2 |
| 容器内子项锚点不生效 | 被容器覆盖（预期行为） | S3 |
| 相机一动 HUD 跟着跑 | 没用 CanvasLayer | S4 |
| 新建项目 UI 被拉伸 | 4.7 默认值变了 | S1 |
