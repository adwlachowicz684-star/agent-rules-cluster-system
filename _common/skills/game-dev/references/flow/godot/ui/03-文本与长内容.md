# 03 文本与长内容（UI 域）

> **前置**：01 布局已稳定，02 已懂"只在变化时赋值"
> **本步交付**：打字机、富文本、玩家输入文本——**不卡、不注入、不崩**
> **对应**：做法 `howto/godot/ui.md` `ui-advanced.md` · 审核 `audit/godot/ui.md` `ui-advanced.md`

## 0. 交付物定义

做完这一步，应该能**当场演示**：

1. 打字机逐字显示，可按键跳过
2. 玩家名/聊天内容含 `[` 时，排版**不被破坏**
3. 长文本（数千字）滚动**不掉帧**
4. ⚠ 打字机进行中切场景，**不报错**
5. 文本走 `tr()`，切语言后变化（⛔ 不是明文）

**产出物**（下游按名字对接）：

```text
show_dialog(speaker, content) -> void
DialogUI._type_next_char()
escape_bbcode(user_input) 调用点（所有玩家可控文本进入 RichTextLabel 前）
```

⚠ 本步有两个独立的坑：**打字机的协程生命周期**与**BBCode 注入**。
它们看起来无关，但都会让玩家看到"坏掉的界面"。

## 2. 工序

### Step 1　用 append_text，不用 text +=　`[ui/03#S1]`

【读】`howto/godot/ui.md#5. 对话框（打字机效果）`

【做】
```gdscript
_text.append_text(_full_text[_char_index])
```

⚠ 用 `RichTextLabel.append_text()` 而不是 `text +=` ——
后者**每帧重建整个文本**，长文本会明显卡。

【产出】逐字追加，不在每帧重建

【判据】⚠ 5000 字文本打字机播放，帧时间**稳定**（⛔ 不是越来越卡）

【审】`audit/godot/ui.md#6`（长文本用 text += 累加 → 每帧全量重建）

### Step 2　await 后判 is_instance_valid　`[ui/03#S2]`

【读】`howto/godot/ui.md#5. 对话框（打字机效果）` 的 ⚠ 提示

【做】
```gdscript
await get_tree().create_timer(0.03).timeout
if not is_instance_valid(self):
    return          # ⚠ 挂起期间节点可能已被 queue_free
_type_next_char()
```

⚠ `await` 之后**必须**判 `is_instance_valid(self)`——
玩家跳过对话、场景切换都会让节点在挂起期间被释放。

【产出】打字机进行中销毁节点，无报错

【判据】⚠ 打字到一半切场景，控制台**零错误**

【审】`audit/godot/ui.md#4`（await 后不判 is_instance_valid → 节点已释放访问报错）

### Step 3　玩家可控文本必须 escape_bbcode　`[ui/03#S3]`

【读】`howto/godot/ui-advanced.md#2. ⚠ BBCode 有注入风险`

【做】所有进入 `RichTextLabel` 的**玩家可控文本**（玩家名、聊天、公会长、
自定义签名、昵称）都要 `escape_bbcode()`。

⚠ 含 `[` 会**破坏排版**——玩家起名 `[b]管理员` 就能让自己的名字加粗，
起名 `[color=red]` 就能让后面所有文字变红。

【产出】所有玩家文本入口都有转义

【判据】⚠ 用玩家名 `[b]x[/b][color=red]y` 测试，
　　　显示的是**字面文本**（⛔ 不是加粗变红）

【审】`audit/godot/ui-advanced.md#4`（BBCode 直接拼用户输入 → 破坏排版）

### Step 4　跳过打字机：直接显示全部　`[ui/03#S4]`

【读】`howto/godot/ui.md#5. 对话框（打字机效果）` 的 `_unhandled_input`

【做】
```gdscript
if _typing:
    _text.text = _full_text
    _char_index = _full_text.length()
    _typing = false
else:
    visible = false
get_viewport().set_input_as_handled()   # ⚠ 别让输入穿透
```

⚠ 第一次按是"跳过动画"，第二次才是"关闭"——
⛔ 合成一次会导致玩家要点两次才能关，或一按就跳过看不到内容。

【产出】按一次显示全部，再按一次关闭

【判据】⚠ 连按两次：第一次文本全出，第二次对话关闭（⛔ 不是一次就关）

【审】`audit/godot/ui.md#19`（await 后不判有效性）

### Step 5　富文本性能：大量/频繁更新　`[ui/03#S5]`

【读】`howto/godot/ui-advanced.md#2. ⚠ BBCode 有注入风险` 末尾 ⚠

【做】⚠ 大量文本或**频繁更新**时要注意性能。
⛔ 不要每个物理帧都 `append_text` 一行日志（聊天刷屏、战斗日志）。

✅ 攒批：每 0.1 秒或每 N 行合并一次再更新。

【产出】聊天刷屏时帧率稳定

【判据】⚠ 每秒灌 100 条聊天，帧时间**不明显上升**

【审】`audit/godot/ui-advanced.md#11`（富文本随便更新 → 有性能代价）

### Step 6　文本走 key，不写明文　`[ui/03#S6]`

【读】`howto/godot/i18n.md`

【做】所有面向玩家的文本走 `tr(key)`，⛔ 不是硬编码字符串。

⚠ UI 文本是本地化里**量最大**的一类。
后期再改成 key 要遍历所有场景文件。

【产出】切语言后界面文本全变

【判据】⚠ 切到英文，界面全变英文且**没有改任何 .tscn**

【审】`audit/godot/ui.md#9`（硬编码像素坐标）

## 3. 参考实现

```gdscript
extends Control

@onready var _text: RichTextLabel = $Panel/RichTextLabel
@onready var _name_label: Label = $Panel/NameLabel

var _full_text: String = ""
var _char_index: int = 0
var _typing: bool = false

func show_dialog(speaker: String, content: String) -> void:
    _name_label.text = speaker            # ⚠ 玩家名的话要 escape_bbcode
    _full_text = content
    _text.text = ""
    _char_index = 0
    _typing = true
    visible = true
    _type_next_char()

func _type_next_char() -> void:
    if _char_index >= _full_text.length():
        _typing = false
        return
    _text.append_text(_full_text[_char_index])   # ⚠ 不是 text +=
    _char_index += 1
    await get_tree().create_timer(0.03).timeout
    if not is_instance_valid(self):              # ⚠ 必须判
        return
    _type_next_char()

func _unhandled_input(event: InputEvent) -> void:
    if not visible:
        return
    if event.is_action_pressed("ui_accept"):
        if _typing:
            _text.text = _full_text               # 跳过：全出
            _char_index = _full_text.length()
            _typing = false
        else:
            visible = false                       # 再按：关闭
        get_viewport().set_input_as_handled()
```

⚠ `get_viewport().set_input_as_handled()` 容易被漏——
不调用的话，这次按键还会被下层（角色移动、其他 UI）再处理一次。
