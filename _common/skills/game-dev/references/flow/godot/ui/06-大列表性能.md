# 06 大列表性能（UI 域）

> **前置**：01 布局已稳定，02 已懂"只在变化时赋值"
> **本步交付**：大量条目（>200）下**不卡、不爆内存**，且能测出真实阈值
> **对应**：做法 `howto/godot/ui-advanced.md` · 审核 `audit/godot/ui-advanced.md`

## 0. 交付物定义

⚠ **先说结论：Godot 至今没有内置虚拟列表，而且 `Tree` 也不虚拟化。**
这不是"调优能解决"的问题，是**必须自己写对象池**的结构性约束。

做完这一步，应该能**当场演示**：

1. 1000 条数据滚动**不掉帧**
2. 滚动过程中节点数**恒定**（不是随数据量增长）
3. 实测出本项目的**虚拟化阈值**（多少条开始卡）
4. 动态高度的列表**不抖动、不跳位**
5. ⚠ 用 `Tree` 承载大数据时，已确认内存开销可接受（或已放弃 Tree）

**产出物**（下游按名字对接）：

```text
VirtualList 控件：固定数量格子 + 复用
_item_height 或动态高度的测量函数
虚拟化阈值实测值（写进 00 总览参数表）
```

## 2. 工序

### Step 1　确认没有内置虚拟化（含 Tree）　`[ui/06#S1]`

【读】`howto/godot/ui-advanced.md#1. ⚠ 没有内置虚拟列表`

【做】⚠ **Godot 至今没有内置虚拟列表。**
`ScrollContainer + VBoxContainer` 里塞一千个控件节点**必然卡死**。

⚠ **`Tree` 也不虚拟化** —— 它所有行都会被布局与排版。
4.7 稳定版有公开复现：70k 项 8 列约 **1.21 GiB**，改文本后 2.81 GiB，
12 列 4.30 GiB，清空后回落到 118.3 MiB。

拆解：`TreeItem` 448 B + `TreeItem::Cell` 376 B，
每个 Cell 还无条件分配约 488 B 的 `TextParagraph`
和约 100 B 的 `AccessibilityElement` → 每个 8 列项约 **7.7 KiB**。

⚠ `ScrollContainer` 根据子节点的 `custom_minimum_size` 调整滚动条，
**并未声称**对不可见区域做裁剪或回收。

【产出】已决定：自己写对象池化虚拟列表（⛔ 不是"先按小数据量写"）

【判据】⚠ 用 `Tree` 灌 10000 条，观察内存增长并**记录数值**
（这个数字决定你能不能用 Tree）

【审】`audit/godot/ui-advanced.md#1` `audit/godot/ui-advanced.md#2` `audit/godot/ui-advanced.md#3`

### Step 2　固定数量格子 + 复用　`[ui/06#S2]`

【读】`howto/godot/ui.md#4. 背包 / 物品格` 的 ⚠ 提示

【做】⚠ 大量格子上限（>200）时 `queue_free` + `instantiate` 会卡。
改成**固定数量的格子 + 复用**（不改数量，只改内容）。

```gdscript
# 复用：只改内容，不改数量
func _refresh() -> void:
    for i in _pool.size():
        var data_index := _scroll_index + i
        _pool[i].visible = data_index < _data.size()
        if _pool[i].visible:
            _pool[i].setup(_data[data_index])
```

【产出】滚动时节点数恒定

【判据】⚠ 滚动 1000 条数据，`get_child_count()` **始终 == 可见格子数**

【审】`audit/godot/ui-advanced.md#1`

### Step 3　实测虚拟化阈值　`[ui/06#S3]`

【读】`howto/godot/ui.md#4. 背包 / 物品格` 与 `howto/godot/ui-advanced.md#1. ⚠ 没有内置虚拟列表`

【做】ⓘ 文档里的"200"是经验值，**不是硬阈值**。
按实测帧时间决定：

| 条目数 | 全量重建帧时间 | 复用帧时间 |
|---|---|---|
| 50 | | |
| 200 | | |
| 1000 | | |

✅ 判断标准是"滚动那一帧有没有掉帧"（< 16ms）。

【产出】阈值实测值，回填到 `00-域流程总览.md` 参数表

【判据】⚠ 表里填了**你自己测的数字**（⛔ 不是抄文档的 200）

【审】`audit/godot/ui-advanced.md#1`

### Step 4　动态高度要专门测量　`[ui/06#S4]`

【读】`howto/godot/ui-advanced.md#1. ⚠ 没有内置虚拟列表`

【做】⚠ 列表项高度**不能假设相等**——
文本换行、图标大小、多行内容都会让高度变化。
虚拟化必须知道"第 N 项在什么 y 位置"。

✅ 要么固定高度（简单、可控），要么**缓存已测量的高度**。

【产出】滚动到底部时位置**准确**（不留大片空白、不重叠）

【判据】⚠ 滚到最后一条，**刚好到底**（⛔ 不是还能滚半屏或最后几条被切）

【审】`audit/godot/ui-advanced.md#12`（列表项高度随便量 → 动态高度要专门测量）

### Step 5　重建必须 queue_free（小列表路径）　`[ui/06#S5]`

【读】`howto/godot/ui.md#4. 背包 / 物品格` 的 ⚠ 提示

【做】若数据量小走全量重建路径，⚠ **必须 `queue_free()` 旧节点**，
只 `remove_child()` 不释放 → 节点累积。

【产出】反复刷新 100 次，节点数回到初始值

【判据】⚠ 刷新 100 次后 `get_child_count()` 与第 1 次**相同**

【审】`audit/godot/ui.md`（重建列表只 remove_child 不 queue_free → 节点累积）

### Step 6　Tooltip 与拖拽的边界　`[ui/06#S6]`

【读】`howto/godot/ui-advanced.md#3. 拖拽：三回调只是契约`

【做】⚠ **Tooltip 在屏幕边缘会被裁切** —— 位置要专门处理。
⚠ **拖拽与 `ScrollContainer` 的冲突**：滚动区域里拖的行为要实测。

⚠ `set_drag_preview` 传入的节点**绝不能在场景树中，也不能自己 `free`**
—— 引擎会接管其生命周期。

【产出】边缘项的 tooltip 完整可见；滚动区域内拖拽行为已实测

【判据】⚠ 把鼠标停在**最后一个**条目上，tooltip **完整显示**（⛔ 不是被切一半）

【审】`audit/godot/ui-advanced.md#6` `audit/godot/ui-advanced.md#13` `audit/godot/ui-advanced.md#14`

## 3. 参考实现

```gdscript
# virtual_list.gd —— ⚠ 固定数量格子 + 复用
extends Control

@export var item_scene: PackedScene
@export var item_height: float = 64.0

var _data: Array = []
var _pool: Array[Control] = []
var _scroll_index: int = 0

func _ready() -> void:
    var visible_count := int(size.y / item_height) + 2   # ⚠ 多建 2 个做缓冲
    for i in visible_count:
        var item := item_scene.instantiate()
        add_child(item)
        item.position.y = i * item_height
        _pool.append(item)

func set_data(data: Array) -> void:
    _data = data
    _refresh()

func _refresh() -> void:
    for i in _pool.size():
        var di := _scroll_index + i
        var vis := di < _data.size()
        _pool[i].visible = vis
        if vis:
            _pool[i].setup(_data[di])       # ⚠ 只改内容，不改数量
```

⚠ `+ 2` 的缓冲是必要的：滚动到两个格子之间时，
上下各需要一个"半露"的格子，否则会看到空白边。
