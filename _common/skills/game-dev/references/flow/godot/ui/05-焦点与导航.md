# 05 焦点与导航（UI 域）

> **前置**：04 单菜单的焦点已可用
> **本步交付**：整个游戏的焦点链完整——**任何时刻都有焦点归属**，鼠标与手柄都能走通全流程
> **对应**：做法 `howto/godot/ui-advanced.md` `accessibility.md` · 审核 `audit/godot/ui-advanced.md`

## 0. 交付物定义

⚠ 本步与 04 的区别：04 是**单个菜单内部**，本步是**跨菜单、跨场景、跨输入设备**。

做完这一步，应该能**当场演示**：

1. 从主菜单 → 游戏 → 暂停 → 设置 → 返回 → 退出，**全程只用键盘/手柄**
2. ⚠ 任意时刻按方向键，**都有反应**（不存在"焦点丢失"的时刻）
3. 鼠标与手柄**混合使用**时状态一致（点了鼠标后手柄接着用不失效）
4. 焦点链覆盖**所有**可交互控件（⛔ 没有"只能点不能选"的按钮）
5. 手柄震动/键位提示与实际可用动作一致

**产出物**（下游按名字对接）：

```text
全局焦点归属约定：哪个容器在什么时候 grab_focus
每个可交互控件的 focus_mode 与 focus_neighbor_*
ui_accept / ui_cancel / ui_focus_next 的响应链
"最后一个可聚焦控件"清单（验收用）
```

## 2. 工序

### Step 1　列出全部可聚焦控件　`[ui/05#S1]`

【读】`howto/godot/ui-advanced.md#4. ⚠ 鼠标能点 ≠ 手柄能选`

【做】列一张表：

| 界面 | 控件 | focus_mode | 是否可聚焦 |
|---|---|---|---|
| 主菜单 | 开始/设置/退出 | FOCUS_ALL | ✅ |
| 设置 | 音量滑块 | FOCUS_ALL | ✅ |
| HUD | 血条 | FOCUS_NONE | ⛔ 装饰 |

⚠ 漏掉一个就是"只能点不能选"的按钮——手柄玩家**永远到不了**那里。

【产出】清单覆盖所有界面，无遗漏

【判据】⚠ 逐个界面用 Tab 走一遍，**每个可点的都能选到**

【审】`audit/godot/ui-advanced.md#7`（`鼠标能点就够了` → 手柄选不中）

### Step 2　不该聚焦的设 FOCUS_NONE　`[ui/05#S2]`

【读】`howto/godot/ui-advanced.md#4. ⚠ 鼠标能点 ≠ 手柄能选`

【做】装饰性控件（进度条、纯图标、分隔线）设 `focus_mode = FOCUS_NONE`。

⚠ 不设的话，Tab 会走到一个"看不出有焦点"的控件上，
玩家以为卡住了。

【产出】Tab 遍历时不会停在装饰控件上

【判据】⚠ 从第一个 Tab 到最后一个，**停的次数 == 可交互控件数**

【审】`audit/godot/ui-advanced.md#7`

### Step 3　跨场景的焦点归属　`[ui/05#S3]`

【读】`howto/godot/ui.md#3. 主菜单` 与 `flow/godot/ui/04-菜单与面板.md`

【做】约定每个场景/面板**打开时**由谁 `grab_focus()`，
以及**关闭时**焦点还给谁。写成一张表。

⚠ 跨场景最容易丢：新场景 `_ready` 里没 `grab_focus()`，
手柄玩家进入后**没有任何东西被选中**。

【产出】焦点归属表，覆盖 主菜单/游戏/暂停/设置/确认框

【判据】⚠ 每个界面打开后，**不碰鼠标直接按方向键都有反应**

【审】`audit/godot/ui-advanced.md#8`（弹窗关了焦点自动回来 → 要显式处理）

### Step 4　鼠标与手柄混合　`[ui/05#S4]`

【读】`howto/godot/ui-advanced.md#4. ⚠ 鼠标能点 ≠ 手柄能选`

【做】ⓘ 混合输入是真实场景：玩家用鼠标点了菜单，
然后拿起手柄继续。此时焦点可能停在鼠标悬停的控件上，也可能丢失。

⚠ 要在"检测到手柄输入"时**重新确立焦点**
（或至少保证焦点不为空）。

【产出】鼠标点过之后，手柄按方向键**仍能**操作

【判据】⚠ 用鼠标点一个按钮（不点击确认），再用手柄按方向键，
　　　焦点**从当前位置继续移动**（⛔ 不是无反应）

【审】`audit/godot/ui-advanced.md#7`

### Step 5　焦点链决定可玩性　`[ui/05#S5]`

【读】`howto/godot/ui-advanced.md#0. 商业项目"能用"与"好用"的分界`

【做】⚠ **无障碍是额外工作**是错的——
焦点链本身**决定可玩性**。四层分界里它是第二层：
列表性能 / **输入鲁棒性** / 焦点链完整性 / 无障碍。

ⓘ 呈现层（字幕、色盲、屏幕阅读器、高对比度）见 `accessibility.md`，
与本步的**交互层**是两件事，不要混。

【产出】完整走通：只用键盘完成一次完整游戏流程

【判据】⚠ 全程不碰鼠标完成 开始→设置→游戏→暂停→退出

【审】`audit/godot/ui-advanced.md#15`（无障碍是额外工作 → 焦点链决定可玩性）

### Step 6　4.7 的 AccessibilityServer（可选）　`[ui/05#S6]`

【读】`howto/godot/ui-advanced.md#5. 4.7 的无障碍：实质加强`

【做】**`AccessibilityServer` 从 `DisplayServer` 中独立成单例**，
新增 `accessibility_region` 属性 —— 屏幕阅读器可导航到**区域级节点**。

⚠ `accessibility_live` 类型改为 `AccessibilityServer.AccessibilityLiveMode`。

ⓘ 本步是**交互层**（焦点链），呈现层见 `howto/godot/accessibility.md`。

【产出】若需要屏幕阅读器支持：关键区域已标 `accessibility_region`

【判据】⚠ 开启系统屏幕阅读器，能读出界面区域（⛔ 不是一片静默）

【审】`audit/godot/ui-advanced.md#10`（无障碍只能靠自己 → 4.7 有 AccessibilityServer）

## 3. 参考实现

```gdscript
# ⚠ 焦点归属表（写在代码注释里，作为约定）
#   主菜单 _ready      → StartButton.grab_focus()
#   设置面板 打开      → 第一个滑块.grab_focus()
#   设置面板 关闭      → OptionsButton.grab_focus()
#   暂停菜单 打开      → ResumeButton.grab_focus()
#   确认框   打开      → ConfirmButton.grab_focus()
#   确认框   关闭      → 打开它的那个按钮.grab_focus()

func _unhandled_input(event: InputEvent) -> void:
    # ⚠ 检测手柄输入并重新确立焦点（混合输入场景）
    if event is InputEventJoypadButton or event is InputEventJoypadMotion:
        if get_viewport().gui_get_focus_owner() == null:
            _default_focus.grab_focus()
```

⚠ `gui_get_focus_owner()` 返回 `null` 就是"焦点丢失"状态——
这是本步要消灭的唯一病症。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 某个按钮手柄永远到不了 | 漏设 focus_mode | S1 |
| Tab 会停在装饰控件上 | 没设 FOCUS_NONE | S2 |
| 进新场景手柄失灵 | 新场景没 grab_focus | S3 |
| 鼠标点过后手柄失效 | 焦点丢失未恢复 | S4 |
| 关了弹窗焦点消失 | 没显式还回去 | S3 |
