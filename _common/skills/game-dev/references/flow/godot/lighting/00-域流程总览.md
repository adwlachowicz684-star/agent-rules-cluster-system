# 光照（Lighting）—— 域流程总览

> ⚠ **第 0 步：先选方案，再调参数。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 室内/静态场景烘焙 | 01 → 02 → 07 |
| 开放世界 / 程序化关卡 GI | 01 → 03 → 07 |
| 阴影有条纹、影子不连脚 | 01 → 04 → 07 |
| 体积雾、局部雾区、光柱 | 01 → 05 → 07 |
| 发光屏幕 / 灯箱 / 窗光 | 01 → 06 → 07 |
| 完整光照管线 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过** —— 三种 GI 方案的差别不在"效果好不好"，
而在**"谁付运行时成本"**，而这直接决定后面每一步能用什么。
⛔ 顺序反了会反复返工：参数调到满意才发现方案选错，
所有参数全部作废。

⛔ **02 的 bake mode 不能最后补**：
用 `visible = false` 隐藏的灯**照样参与烘焙**，
⛔ 官方明确这不会产生任何报错，
表现为"烘完多出一块不该有的光"。

⛔ **03 的 SDFGI 反馈上限要在调亮度之前定**：
Bounce Feedback 超过 0.5 可能触发无限反馈循环，
表现为"场景几秒内变得极亮"，
⛔ 而调参时前几秒看着正是"变亮了挺好"。

ⓘ 若本次只是**"换个天空盒、调下曝光"**，那是资源配置，不套本域。
ⓘ 若只是**排查物体全黑**，先看 `howto/godot/render-pipeline.md` 确认渲染器能力，再回本域 01。

ⓘ 分工：
- `howto/godot/lighting.md` 讲**各方案的技术做法**（烘焙、GI、阴影、雾、面光源）
- `howto/godot/render-pipeline.md` 讲**渲染器能力矩阵**
- 本域讲**这些做法按什么顺序做、怎么保证换平台换渲染器后仍然对**

⛔ 若本域某步需要"纹素密度""阴影 bias 数值"这类细节，
指向项目实测，⛔ 不在这里编数字。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 方案选型与预算地基 | — | 方案矩阵 + 渲染器能力核对 + 灯与阴影预算 |
| 02 | LightmapGI 烘焙与 UV2 地基 | 01 | gi_mode / UV2 / bake mode / 失败码处理 + 探针 |
| 03 | GI 方案与动态物体 | 01 | VoxelGI / SDFGI 选型 + 反馈上限 + 收敛与更新时机 |
| 04 | 阴影偏置与方向光级联 | 01 | bias 顺序 + PSSM 分段点 + 极端几何处理 |
| 05 | 体积雾与局部雾区 | 01 | 全局体积雾前提 + FogMaterial + 薄雾闪烁修法 |
| 06 | 面光源与光照预算 | 01 | AreaLight3D 预算 + 几何细分 + 衰减与纹理 |
| 07 | 光照验收 | 全部 | 换渲染器实测 + 目标平台烘焙实测 + 极端角度实测 |

⚠ **01 的渲染器核对要在摆第一盏灯之前**：
Mobile 与 Compatibility **只有 LightmapGI** 一个 GI 选项，
⛔ 摆完 VoxelGI 才发现渲染器不支持 = 整块重做。

⚠ **02 的 UV2 要在建模阶段就定**：
UV2 是导入期生成的，
⛔ 等到烘焙阶段才发现没有 UV2，要回头改所有资产的导入设置。

⚠ **04 的 bias 要逐灯记，不能最后统一调**：
"没有通用值"是官方口径，
⛔ 统一填一个值会让部分灯 acne、部分灯 peter-panning。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是单盏灯，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `render-pipeline` | ⓘ howto 层，暂无 flow 域 —— 渲染器能力矩阵见该篇，⛔ 本域只核对不另定 |
| `perf` 域 性能 | 帧预算与剖析方法见 `perf`，⛔ 本域只定光照的**灯数与阴影预算** |
| `2d-rendering` 域 2D 渲染 | 2D 光照与阴影见 `2d-rendering`，⛔ 本域只讲 3D |
| `shaders` 域 着色器 | 材质与自定义光照见 `shaders`，⛔ 本域只定灯与 GI 配置 |
| `openworld` 域 开放世界 | SDFGI 在大世界的级联与流式加载见 `openworld`，⛔ 本域只定 GI 参数口径 |
| `mobile` 域 移动端 | 移动端光照预算与回退见 `mobile`，⛔ 本域不另定移动端口径 |
| `platform-export` 域 导出 | 烘焙产物的打包见 `platform-export`，⛔ 本域只定 `.lmbake` 落盘口径 |
| `level` 域 关卡 | 场景装配与节点层级见 `level`，⛔ 本域只定 LightmapGI 的层级约束 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `MAX_LIGHTMAPGI_NODES` 同屏 GI 节点上限 | 01 | 8 | — | 待实测（⛔ 官方硬上限，超出会闪烁） |
| `MAX_SHADOW_LIGHTS` 带阴影方向光上限 | 01 | — | — | 待实测（⛔ 8 盏共享阴影图集） |
| `SDFGI_BOUNCE_FEEDBACK` 反弹反馈 | 03 | 0.0 | — | 待实测（⛔ 官方：> 0.5 可能无限反馈） |
| `SDFGI_MAX_DISTANCE` SDFGI 最大距离 | 03 | — | — | 待实测（⛔ 必须低于相机 far） |
| `SDFGI_Y_SCALE` 垂直比例 | 03 | 0.75 | — | 待实测（官方建议 0.5–0.75 减漏光） |
| `SHADOW_MAX_DISTANCE` 阴影最大距离 | 04 | — | — | 待实测（⛔ 性能与精度最大杠杆） |
| `AREA_LIGHT_RANGE` 面光源射程 | 06 | 5.0 | — | 待实测（⛔ 与 attenuation 联动，2.0 时远处不可见） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发闪烁""偶发极亮""偶发阴影缺失"，
⛔ 而这类偶发在编辑器默认视口下几乎不出现。
