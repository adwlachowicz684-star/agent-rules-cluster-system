# 01 方案选型与预算地基（光照域）

> **本步交付**：方案矩阵 + 渲染器能力核对 + 灯与阴影预算
> **对应**：流程 `howto/godot/lighting.md` · 审核 `audit/godot/lighting.md`

## 0. 交付物定义

1. 已按"谁付运行时成本"选定一种 GI 方案，并写下选它的理由
2. 已核对目标渲染器**支持**该方案（⛔ 不是"编辑器里能开"）
3. 灯数预算与带阴影灯数预算已定，并写在配置里
4. `WorldEnvironment` 已就位（⛔ 它决定烘焙有没有环境光）
5. 同屏 `LightmapGI` 节点数已有上限约束

## 1. 前置检查清单

- [ ] 能用一句话说清选定方案"谁付成本"
- [ ] 目标渲染器在能力矩阵里确实支持该方案
- [ ] 灯数 / 带阴影灯数已写成配置常量
- [ ] 场景里有 WorldEnvironment 且配了天空或环境色
- [ ] 同屏 LightmapGI 节点数不超过 8

## 2. 工序

### Step 1　先选方案，再调参数 —— 顺序不能反　`[lighting/01#S1]`

【读】`howto/godot/lighting.md#0. 方案选型（先看这个）`

【做】
按下表先定方案，并在方案表里写下**选定理由**（静态比例 / 是否动态 / 目标平台）。
⛔ 先摆灯调亮度再选方案 —— 参数调到满意才发现方案选错，
所有参数全部作废，且**没有任何一步会报错**。

| 方案 | 运行时成本 | 静态/动态 | 渲染器要求 |
|---|---|---|---|
| 实时光 | 最贵 | 全动态 | 都行 |
| LightmapGI | 几乎免费 | **完全静态** | 都行（烘焙需 RenderingDevice） |
| VoxelGI | 高 | 灯可动、动态物体能收 GI | **仅 Forward+** |
| SDFGI | 最高 | 半实时 | **仅 Forward+** |

【产出】一张写有"选定方案 + 理由"的方案表

【判据】指着方案表能说出本次场景静态比例与是否需要动态遮挡物。

【审】`audit/godot/lighting.md#43`

### Step 2　核对渲染器能力：移动端与 Compatibility 只有 LightmapGI　`[lighting/01#S2]`

【读】`howto/godot/lighting.md#0. 方案选型（先看这个）`

【做】
在能力矩阵里逐个核对目标渲染器，把结果写进方案表。
⛔ 在编辑器里"能开"不等于目标平台支持 ——
编辑器默认 Forward+，VoxelGI / SDFGI 面板都能开，
⛔ 出包到移动端才失效，表现为"手机上没有间接光"，
而开发机上**一切正常**。

【产出】逐渲染器的能力核对结论

【判据】每个目标渲染器后面都写着它支持哪几种 GI。

【审】`audit/godot/lighting.md#2`

### Step 3　定灯数预算与带阴影灯数预算　`[lighting/01#S3]`

【读】`howto/godot/lighting.md#3. 阴影`

【做】
把"总灯数"与"带阴影的灯数"分别写成常量，并在加灯时校验。
⛔ 每加一盏带阴影的方向光就稀释有效阴影分辨率 ——
8 盏**共享**阴影图集，
表现为"灯越多阴影越糊"，而每盏灯的面板设置**全部正确**。

【产出】`MAX_LIGHTS` / `MAX_SHADOW_LIGHTS` 两个常量与加灯校验

【判据】超出预算时加灯会被拒绝并给出提示。

【审】`audit/godot/lighting.md#11`

### Step 4　WorldEnvironment 必须先就位，且不能只靠编辑器预览天空　`[lighting/01#S4]`

【读】`howto/godot/lighting.md#7. ⛔ 烘焙的静默失效：三类不报错的错`

【做】
摆 `WorldEnvironment` 并配天空或环境色，再确认
`LightmapGI.environment_mode` 与实际配置一致。
⛔ 没有 WorldEnvironment 时 `ENVIRONMENT_MODE_SCENE` **等同 DISABLED**，
而**编辑器的预览天空与太阳不被计入烘焙** ——
表现为"编辑器里看着有天空、烘出来是黑的"，
⛔ 排查时"场景里明明有光"会是第一反应。

【产出】已配置天空/环境色的 WorldEnvironment

【判据】移除 WorldEnvironment 后烘出来会明显变暗（即它确实在起作用）。

【审】`audit/godot/lighting.md#24`

### Step 5　同屏 LightmapGI 节点上限：8　`[lighting/01#S5]`

【读】`howto/godot/lighting.md#7. ⛔ 烘焙的静默失效：三类不报错的错`

【做】
把"用多个 `LightmapGI` 分段烘焙"的段数约束在 8 以内，并写进场景规范。
⛔ 官方：**最多同时渲染 8 个 LightmapGI 节点**，
超出后视口内的实例会 **popping in and out（闪烁）**。
表现为"相机移动时光照闪"，
⛔ 排查被引向纹素密度或烘焙质量 —— 与节点数量无关的表象非常像。

【产出】场景规范里的一条段数上限

【判据】任意相机位置下可见的 LightmapGI 节点数 ≤ 8。

【审】`audit/godot/lighting.md#26`

## 3. 参考实现

```gdscript
# 光照预算校验 —— 加灯时调用
# ⓘ MAX_SHADOW_LIGHTS 承接 Step 3 定义；官方：8 盏共享阴影图集
const MAX_SHADOW_LIGHTS := 2
# ⓘ MAX_LIGHTMAPGI_NODES 为官方硬上限，非经验值
const MAX_LIGHTMAPGI_NODES := 8

var _shadow_lights: Array[DirectionalLight3D] = []

func register_shadow_light(l: DirectionalLight3D) -> bool:
    if _shadow_lights.size() >= MAX_SHADOW_LIGHTS:
        push_warning("带阴影的方向光已达上限 %d，新灯不加阴影" % MAX_SHADOW_LIGHTS)
        l.shadow_enabled = false      # ⛔ 不是拒绝加灯，是降级
        return false
    _shadow_lights.append(l)
    return true
```

ⓘ 上例只示范"预算约束"，⛔ 烘焙触发见 02。
