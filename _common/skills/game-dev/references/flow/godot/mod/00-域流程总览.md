# 00 域流程总览 · Mod / 创意工坊（mod 域）

## 0. 先定做什么

⚠ **本域的核心不是"能不能加载一个 PCK"，而是"在敌意环境与非常规路径下是否仍然成立"。**

Mod 系统的失败有个共同特征：**正常环境下全绿**。
只在换顺序、换机器、从搜索栏启动、缺依赖、恶意包时才暴露。

⛔ 所以本域的验收（07）专门针对**非常规路径**，而不是"能加载就算过"。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | Step | 交付物 |
|---|---|---:|---|
| 01 | 模型定性 | 5 | 四类 Mod + 官方两条路选定 |
| 02 | 包格式与加载时机 | 5 | PCK/ZIP 选型 + autoload `_init()` |
| 03 | 清单与依赖求解 | 5 | 拓扑排序 + 循环检测 |
| 04 | 冲突与优先级 | 5 | 覆盖链 + 声明来源分离 |
| 05 | 安全与沙箱 | 5 | zip-slip + 风险告知 |
| 06 | 启用禁用与存档交互 | 6 | id+版本记录 + 降级 |
| 07 | Mod 验收 | 6 | 可签核报告（非常规路径） |

## 2. 与其他域的接缝

| 域 | 接缝 |
|---|---|
| save | 存档记录 Mod id + 版本 |
| security | zip-slip 与任意代码执行风险 |
| datatable | Mod 提供的数据表覆盖 |
| level | Mod 提供的关卡/场景 |
| ui | Mod 管理界面与顺序调整 |

## 3. 本域最容易做反的顺序

⛔ **先做管理界面，再做加载时机。** 界面能列出 Mod 并"启用"，
但加载发生在 `_ready()` → **装了没变化**。而界面看起来完全正常。

⛔ **先做单 Mod，再做依赖。** 单 Mod 时目录顺序与拓扑序一致，
有依赖后才暴露，且报错指向依赖者而非真因。

⛔ **先做加载，再做安全。** zip-slip 在解压时发生，
后补防护要改所有解压调用点。
