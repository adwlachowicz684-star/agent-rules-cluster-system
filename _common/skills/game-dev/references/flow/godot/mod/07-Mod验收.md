## 0. 交付物定义

⚠ **验收不是"能加载一个 Mod"**，而是**在敌意环境与非常规路径下仍然成立**。

⛔ Mod 系统的 bug 有个共同特征：**正常环境下测不出来**。
只在改顺序、换机器、从搜索栏启动、缺依赖、恶意包时才出现。

做完这一步，应该能**当场演示**：

1. 四种启动方式（双击 / 快捷方式 / 搜索栏 / 符号链接）结果一致
2. ⛔ 已 `preload()` 的场景仍受 Mod 影响
3. ⛔ 依赖错排时报错**指向被依赖的 Mod**
4. ⛔ 循环依赖报出**环上的具体 id**
5. ⛔ 恶意包**零越界写入**
6. ⛔ 换一批同数量 Mod，存档校验**不通过**

**产出物**（下游按名字对接）：

```text
验收报告（含非常规路径实测记录）
返工项清单
```

## 2. 工序

### Step 1　⛔ 非常规启动路径　`[07#S1]`

【读】`howto/godot/modding.md#3. ⛔ 路径：CWD 不保证是可执行文件所在目录`

【做】分别从双击 exe、快捷方式、搜索栏、符号链接启动，确认 Mod 均加载成功。

【产出】四种启动方式的实测记录

【判据】⛔ 四种方式**结果一致**（相对路径会只在双击时成功）

【审】`audit/godot/modding.md#17`

### Step 2　⛔ preload 场景仍受 Mod 影响　`[07#S2]`

【读】`howto/godot/modding.md#2. ⛔ 加载时机：必须在 autoload 的 _init()`

【做】在菜单场景用 `preload()` 引用一个资源，装 Mod 覆盖它，看是否生效。

【产出】preload 覆盖生效记录

【判据】⛔ 覆盖**生效**（若写在 `_ready()` 则不生效）

【审】`audit/godot/modding.md#16`

### Step 3　⛔ 依赖错排时报错指向真因　`[07#S3]`

【读】`howto/godot/modding.md#7. 清单、依赖与加载顺序`

【做】手工把依赖者排在依赖之前，看报错是否指向缺失的依赖。

【产出】报错指向记录

【判据】⛔ 报错**指向被依赖的 Mod**，不是依赖者的代码

【审】`audit/godot/modding.md#20`

### Step 4　⛔ 循环依赖报出具体 id　`[07#S4]`

【读】`howto/godot/modding.md#7. 清单、依赖与加载顺序`

【做】构造 A→B→A，确认报出环上的 id 列表。

【产出】循环依赖提示截图/记录

【判据】⛔ 提示里**能读到** A 与 B 的 id

【审】`audit/godot/modding.md#21`

### Step 5　⛔ 恶意包不写出任何文件　`[07#S5]`

【读】`howto/godot/modding.md#6. ⚠ 安全：Mod 等于给玩家执行任意代码的能力`

【做】加载含 `../` 的包，确认被拒且目标目录外无新文件。

【产出】越界写入检查记录（目标根目录外文件数）

【判据】⛔ 目标根目录**之外零写入**

【审】`audit/godot/modding.md#5`

### Step 6　⛔ 换一批同数量 Mod，存档校验不通过　`[07#S6]`

【读】`howto/godot/modding.md#10. 与存档的交互`

【做】用 3 个 Mod 存档，换成另外 3 个，读档。

【产出】存档校验结果记录

【判据】⛔ 校验**识别出内容变化**（只记数量会误判通过）

【审】`audit/godot/modding.md#22`

## 4. 常见返工

⛔ **只测"双击 exe"**。相对路径在搜索栏 / 符号链接启动时失效，
而开发时几乎总是双击 → **开发期永远测不出来**。

⛔ **只测装一个 Mod**。依赖顺序、冲突、循环依赖都要 ≥3 个 Mod 才暴露。

**返工路由**：

| 失败项 | 回到 |
