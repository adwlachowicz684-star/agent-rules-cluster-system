## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：改了一堆东西，FPS 涨了就算优化完成。**

⛔ 常见假完成：一次改了五处，FPS 涨了 10——
但**不知道是哪一处起的作用**，下次别的场景又慢时，
无法判断该复用哪个手段。

做完这一步，应该能**当场演示**：

1. ⛔ 优化顺序按**性价比**，不是按"哪个最耗时"或"哪个最好改"
2. ⛔ 一次只改一个变量，改完立刻复测并记录
3. ⚠ 优先处理打断合批的问题，而不是先减三角形
4. ⚠ 每帧空间查询先降频，不要先换物理引擎
5. 屏幕外对象已停止处理
6. ⚠ 改动已同步更新基线（供 05 回归对比）

## 3. 参考实现

⛔ 一次一项 + 改完即测。改动清单写成：

```text

2. [待测] 空间查询降频
```

ⓘ 没有"已测"标记的项，不算完成。
