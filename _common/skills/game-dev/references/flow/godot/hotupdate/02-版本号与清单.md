# 02 版本号与清单（热更新域）

> **本步交付**：四个版本号 + 兼容矩阵 + 签名清单
> **对应**：流程 `howto/godot/hotupdate.md` · 审核 `audit/godot/hotupdate.md`

## 0. 交付物定义

1. 四个版本号各自独立、各自有递增规则
2. 最小兼容版本由服务端下发
3. 兼容判定顺序固定且写死
4. manifest 带签名与有效期

## 1. 前置检查清单

- [ ] 01 的形态分类已完成
- [ ] 已确认资源不复用语义版本号
- [ ] manifest 的签名密钥不进客户端明文

## 2. 工序

### Step 1　四个版本号各自独立　`[hotupdate/02#S1]`

【读】`howto/godot/hotupdate.md#7. 四个版本号：混用是唯一会让你半年后救不回来的错误`

【做】
客户端版本、资源版本、配置版本、最小兼容版本**各自独立存储**。
⛔ 共用一个 `GAME_VERSION` —— 半年后无法判断老客户端该不该踢下线。

【产出】四个版本号字段 + 各自的递增规则

【判据】改资源只涨资源版本，客户端版本不动；四者能独立读出。

【审】`audit/godot/hotupdate.md#11`

### Step 2　最小兼容版本由服务端下发　`[hotupdate/02#S2]`

【读】`howto/godot/hotupdate.md#7. 四个版本号：混用是唯一会让你半年后救不回来的错误`

【做】
`min_supported_client` 必须是服务端下发的字段，不能是客户端常量。
⛔ 写成客户端常量 —— 线上事故时**无法把老客户端踢下线**，只能等玩家自己更新。

【产出】服务端下发的 `min_supported_client` + 强更弹窗流程

【判据】服务端把该值改成当前版本，老客户端启动即被拦下并提示更新。

【审】`audit/godot/hotupdate.md#12`

### Step 3　兼容性矩阵判定顺序不能反　`[hotupdate/02#S3]`

【读】`howto/godot/hotupdate.md#兼容性矩阵：判定顺序不能反`

【做】
固定顺序：**先客户端 → 再配置 → 最后资源**。
⛔ 顺序反了 —— 先判资源，老客户端会拿到新资源，**缺贴图崩溃**。

【产出】兼容判定函数（顺序写死，带注释说明为什么不能改）

【判据】构造"客户端老、资源新"的组合，判定结果为拒绝而非放行。

【审】`audit/godot/hotupdate.md#13`

### Step 4　版本清单要签名并带有效期　`[hotupdate/02#S4]`

【读】`howto/godot/hotupdate.md#版本清单要签名 + 带有效期`

【做】
清单（manifest）带签名与有效期，过期即视为不可用。
⛔ 清单不签名 —— 中间人改一个版本号就能让玩家装错包。

【产出】签名 manifest 结构 + 有效期字段 + 校验入口

【判据】篡改清单任意字节 → 校验失败并拒绝安装；⛔ 旧清单重放必须因过期被拒（**先验签再哈希**，反了给攻击者哈希 oracle）。

【审】`audit/godot/hotupdate.md#42`

### Step 5　资源版本用单调整数，不用语义版本　`[hotupdate/02#S5]`

【读】`howto/godot/hotupdate.md#7. 四个版本号：混用是唯一会让你半年后救不回来的错误`

【做】
资源没有"主版本不兼容"的语义，用**单调整数 + 补丁链锚点**。
⛔ 照搬语义版本号 —— `2.0.0` 并不表示资源不兼容，判定逻辑会误判。

【产出】资源版本号（单调整数）+ 补丁链锚点（from/to）

【判据】能从任意老版本推出到达当前版本的补丁链，且不出现环路。

【审】`audit/godot/hotupdate.md#14`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：四版本号 + 判定顺序
# ⛔ 顺序不可改：客户端 → 配置 → 资源
var client_ver := 101
var min_supported := 0        # ⓘ 服务端下发，本地仅为默认值
var res_ver := 7
var cfg_ver := 3

func compatible(serv_min: int, serv_res: int) -> bool:
    if client_ver < serv_min: return false
    return true
```

## 4. 验收清单

- [ ] 四版本号能独立读出
- [ ] 服务端改 min → 老客户端被拦
- [ ] 老客户端 + 新资源 → 拒绝
- [ ] 清单被篡改 → 校验失败

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 老客户端拿到新资源崩 | 判定顺序反了 | S3 |
| 事故时踢不掉老版本 | min 写成客户端常量 | S2 |
