# 03 下载与断点续传（热更新域）

> **本步交付**：Range 续传 + 进度落盘 + 磁盘复检 + 状态机
> **对应**：流程 `howto/godot/hotupdate.md` · 审核 `audit/godot/hotupdate.md`

## 0. 交付物定义

1. 分块下载且可断点续传
2. 进度持久化，崩溃不归零
3. 4xx 立即放弃、5xx 退避重试
4. 磁盘余量 2 倍且中途复检

## 1. 前置检查清单

- [ ] 02 的版本号与清单已就绪
- [ ] 已确认不用 `HTTPRequest` 拉整包
- [ ] 有可控的弱网 / 中断测试手段

## 2. 工序

### Step 1　用 HTTP Range 断点续传，⛔ 不要整包拉　`[hotupdate/03#S1]`

【读】`howto/godot/hotupdate.md#下载：用 HTTP Range，⛔ 不要用 HTTPRequest 拉整包`

【做】
用 `HTTPClient` 发 Range 请求、分块写盘。
⛔ 用 `HTTPRequest` 拉整包 —— 整个响应体攒在内存，**几十 MB 在低端机直接 OOM**。

【产出】Range 分块下载器 + 分块写盘

【判据】下载到 70% 杀进程，重启后从 70% 继续，不从头开始。

【审】`audit/godot/hotupdate.md#21`

### Step 2　下载进度要持久化　`[hotupdate/03#S2]`

【读】`howto/godot/hotupdate.md#9. 客户端更新状态机`

【做】
每 64KB 或每秒落盘一次已下载字节数。
⛔ 进度只在内存 —— 崩溃后归零，弱网用户永远下不完。

【产出】进度持久化文件 + 恢复入口

【判据】杀进程三次，累计下载量单调递增且不重复下载。

【审】`audit/godot/hotupdate.md#22`

### Step 3　4xx 立即放弃并告警，⛔ 不要重试　`[hotupdate/03#S3]`

【读】`howto/godot/hotupdate.md#9. 客户端更新状态机`

【做】
403/404 是"不该再下载"的信号（签名 URL 过期），立即放弃并上报。
⛔ 对 4xx 继续重试 —— 客户端疯狂重试一个永远拿不到的地址。

【产出】状态码分流表（2xx 继续 / 4xx 放弃 / 5xx 退避重试）

【判据】构造 403，客户端在 1 次内放弃并产生一条告警日志。

【审】`audit/godot/hotupdate.md#23`

### Step 4　磁盘留 2 倍余量并中途复检　`[hotupdate/03#S4]`

【读】`howto/godot/hotupdate.md#磁盘空间：留 2 倍余量`

【做】
下载前检查 2 倍余量（包体 + 解压），下载中每 5% 复检一次。
⛔ 只留 1.2 倍 —— 解压到一半满盘。
⛔ 空间不足还继续写 —— 产生**不可恢复的部分文件**。

【产出】空间检查 + 每 5% 复检 + 不足时的明确提示

【判据】人为把可用空间压到 1.5 倍，下载在 5% 内停下并提示，不留残file。

【审】`audit/godot/hotupdate.md#24`

### Step 5　更新状态机与重试退避　`[hotupdate/03#S5]`

【读】`howto/godot/hotupdate.md#9. 客户端更新状态机`

【做】
状态机显式列出各态与转移条件，重试带指数退避。
⛔ 状态机画在脑子里 —— 中断恢复时不知道该回到哪一态。

【产出】更新状态机（idle/checking/downloading/verifying/installing/failed）

【判据】任意态断电重启，都能落到一个确定态且可继续。

【审】`audit/godot/hotupdate.md#22`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：分块 + 进度落盘
const CHUNK := 65536          # 64KB
const PROGRESS_EVERY := 1.0   # ⓘ 秒

func _tick(delta: float) -> void:
    _since_save += delta
    if _since_save >= PROGRESS_EVERY:
        _save_progress(_bytes_done)   # ⛔ 不落盘 = 崩溃归零
        _since_save = 0.0
```
