# 04 校验与安装切换（热更新域）

> **本步交付**：三层校验 + 三段式原子切换 + 基线策略
> **对应**：流程 `howto/godot/hotupdate.md` · 审核 `audit/godot/hotupdate.md`

## 0. 交付物定义

1. 签名 / 哈希 / 结构三层，顺序正确
2. 补丁可拼链且有层数上限
3. 三段式原子切换，中途断电无崩溃态

## 1. 前置检查清单

- [ ] 03 的下载器已能产出完整文件
- [ ] 签名密钥不在客户端明文
- [ ] 有归档基线可取

## 2. 工序

### Step 1　三层校验顺序不能反　`[hotupdate/04#S1]`

【读】`howto/godot/hotupdate.md#⚠ 签名与校验三层，顺序不能反`

【做】
固定顺序：**先验签 → 再哈希 → 最后结构校验**。
⛔ 先验哈希再验签 —— 给攻击者一个哈希 oracle。

【产出】三层校验管道（顺序写死）

【判据】用错误签名的包测试，在哈希计算之前就被拒绝。

【审】`audit/godot/hotupdate.md#19`

### Step 2　哈希之外还要结构校验　`[hotupdate/04#S2]`

【读】`howto/godot/hotupdate.md#8. 补丁生成：基线、差分、签名`

【做】
校验包内文件结构完整（清单与实际一致、必要文件都在）。
⛔ 只做哈希 —— 曾在"CDN 返回 200 但 body 是 HTML 错误页"集体中招。

【产出】结构校验步骤（清单比对 + 必要文件存在性）

【判据】把包换成 HTML 错误页，校验失败且错误信息可读。

【审】`audit/godot/hotupdate.md#20`

### Step 3　补丁元数据必须声明 from / to　`[hotupdate/04#S3]`

【读】`howto/godot/hotupdate.md#补丁元数据必须声明 from / to`

【做】
每个补丁声明适用区间，客户端据此拼链。
⛔ 不声明 —— 无法判断该补丁能不能装在当前版本上。
⚠ delta 叠加有**加载开销累积**，半年后要连解六层，需定期出合并基线。
⛔ 对 GDScript 字节码开 delta —— 每次构建都变，delta 无效只增开销。

【产出】补丁元数据（from/to/基线标记）+ 链路拼装逻辑

【判据】给定任意起点，能拼出到达当前的链，且层数不超过阈值。

【审】`audit/godot/hotupdate.md#16`

### Step 4　三段式原子切换　`[hotupdate/04#S4]`

【读】`howto/godot/hotupdate.md#安装：三段式原子切换`

【做】
staging → ready → installed，状态变更**在文件操作之后**。
⛔ 先更新状态再移动文件 —— 顺序反了会造**"启动即崩溃"死局**。

【产出】三段式安装流程 + 状态文件

【判据】在安装中途断电，重启后要么回到旧版、要么装完新版，**没有崩溃态**。

【审】`audit/godot/hotupdate.md#26`

### Step 5　Base Packs 必须从归档取回　`[hotupdate/04#S5]`

【读】`howto/godot/hotupdate.md#8. 补丁生成：基线、差分、签名`

【做】
生成 delta 的基线包从归档取，不要重新导出。
⛔ 重新导出一份 —— 字节不同，**delta 全部失效**。

【产出】基线包归档策略 + CI 取回步骤

【判据】用归档基线生成的 delta，能在老客户端上正确应用。

【审】`audit/godot/hotupdate.md#18`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：三段式
# ⛔ 先写状态再移文件 = 启动即崩溃死局
const READY_PATH := "user://patch_ready.pck"
const INSTALLED_PATH := "user://patch_installed.pck"

func install(staging_path: String) -> bool:
    _move(staging_path, READY_PATH)
    _write_state("ready")            # ⓘ 文件操作之后才改状态
    _move(READY_PATH, INSTALLED_PATH)
    _write_state("installed")
    return true
```
