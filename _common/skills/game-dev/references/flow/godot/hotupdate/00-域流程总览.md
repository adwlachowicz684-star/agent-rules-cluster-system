# 热更新、资源分包与 DLC —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只换贴图 / 配置数值 | 01 → 04 → 07 |
| 要能断点续传、弱网可恢复 | 01 → 02 → 03 → 04 → 07 |
| 要热换已加载场景 / 换血 | 01 → 04 → 05 → 07 |
| 要灰度、要能回滚 | 01 → 02 → 03 → 04 → 06 → 07 |
| 要 DLC / 资源分包 | 01 → 04 → 05 → 07 |
| 全套（含平台合规） | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **一次性发包、不打算回滚、不做灰度的小项目可以只走 01 → 04。**
⚠ 但**回滚路径永远是 release gate** —— 见 06 与 07。

ⓘ 分工：
- `howto/godot/hotupdate.md` 讲**单个机制怎么实现**（PCK 覆盖、签名、Range 下载、三段式安装、换血、DLC）
- 本域讲**这些机制按什么顺序做、怎么保证装不死、可回滚、可验收**

⛔ 若本域某步需要"delta 补丁怎么生成"这类细节，指向那篇，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 更新形态与产物边界 | — | 形态判定 + 产物清单 + 硬限制清单 |
| 02 | 版本号与清单 | 01 | 四个版本号 + 兼容矩阵 + 签名清单 |
| 03 | 下载与断点续传 | 02 | Range 续传 + 进度落盘 + 磁盘复检 |
| 04 | 校验与安装切换 | 03 | 三层校验 + 三段式原子切换 |
| 05 | 换血与生效时机 | 04 | 三档处理 + 生效时机 + `_init()` 加载 |
| 06 | 灰度、回滚与降级 | 04 | 可禁用开关 + 故障实测 + 稳定分桶 |
| 07 | 热更验收 | 全部 | 回滚实测 + 中断实测 + 平台专项 |

⚠ **01 必须在一切之前**：不先分清"资源热更 / 代码热更"，后面的产物边界与合规判定全是错的。
⚠ **02 必须在 03 之前**：版本号不定，下载下来也不知道该不该装。
⚠ **04 必须在 05 之前**：没完成原子切换就谈"换血"，会出现装了一半的旧新混合态。
⚠ **06 依赖 04 但不依赖 05**：回滚管的是"装的东西能不能撤"，与运行时换血无关。

## 2. 与其他域的接缝

| 接缝 | 契约 |
|---|---|
| `mod` 域 Mod / 创意工坊 | 同为"运行时加载外部包"，共用 `load_resource_pack` 与 `_init()` 时机 |
| `save` 域 存档 | 配置热更改语义时存档要链式单步迁移，见 06 |
| `netsync` 域 网络同步 | 清单下发与强更判定走服务端，见 02 |
| `economy` 域 经济 | 配置热更不可逆字段（已购货币）必须 `never`，见 06 |
| `perf` 域 性能 | 下载与安装不能卡主线程，见 03/04 |
| `ui` 域 UI | 更新进度条与强制更新弹窗，见 03 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**。

## 3. 本域最容易做反的顺序

⛔ **先把下载和安装做通（03/04），再回头补版本号与回滚（02/06）。**

下载进度条是最直观的"热更做完了"的信号，于是先写 `HTTPRequest` 拉包、先覆盖文件，
⚠ 而此时版本号是拍的、回滚只是"把补丁删掉" ——
**线上出事故时既不知道该踢谁下线，也没有可执行的回滚动作**，
⛔ 且不报错，只在第一次真正需要回滚时才暴露 —— 那一刻就是事故本身。

✅ 正确顺序：先立版本号与可禁用开关（02/06 的设计），再做下载与安装（03/04）。
