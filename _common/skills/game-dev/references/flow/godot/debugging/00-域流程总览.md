# 调试与故障定位（Debugging）—— 域流程总览

> ⚠ **第 0 步：先分清"这是哪一种故障"，再决定用哪条路径。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按当前故障挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 崩了但不知道崩在哪 | 01 → 02 → 03 → 07 |
| 卡死 / 无响应 / 不报错 | 01 → 04 → 07 |
| 帧率突然掉了 | 01 → 02 → 07（⛔ 定性为性能后转 `perf` 域） |
| 编辑器正常、导出版炸 | 01 → 05 → 07 |
| 空引用、信号没触发 | 01 → 06 → 07 |
| 内存一直涨 | 01 → 02 → 04 → 07 |
| 修完了不知道会不会复发 | 07 |

⛔ **01 不能跳过** —— 崩溃、卡死、掉帧、仅在导出版出现，
这四类**排查入口完全不同**：崩溃看栈、卡死看谁持有了执行权、
掉帧看帧时间分解、导出版看的是"编辑器替你做了什么"。
⛔ 不先定性就直接下断点，最常见的结果是**断点打在线程里的代码上**，
而官方明确：GDScript 调试器**不会在线程中的代码上中断** ——
表现为"断点没命中，于是以为这段代码根本没执行"，⛔ 且不报错。

⛔ **02 的观测手段要在 04 之前装好**：卡死类故障**复现场即消失**，
事后再想看日志已经没有了。⛔ 到定位时才发现日志没分级、
release 里 `assert` 被剥离，等于把整个可观测层重做一遍。

ⓘ 03 与 04 最容易互相甩锅：
断点用不上时，成因可能在"跑在线程里"也可能在"执行权根本没交回来"。
⛔ 所以 03 只管**能不能中断到**，04 只管**执行权在谁手上**，两边不许各判一次。

## 1. 功能点拆解与依赖

| # | 功能点 | 交付 | 依赖 |
|---|---|---|---|
| 01 | 故障定性与可复现 | 故障分类、最小复现、环境记录 | — |
| 02 | 日志与可观测性 | 分级日志、自定义监视器、release 可用指标 | 01 |
| 03 | 断点与远程调试 | 断点能命中、远程能连、线程限制已知 | 01 |
| 04 | 卡死与无响应定位 | 执行权归属、死循环与 await 悬挂区分 | 01 / 02 |
| 05 | 导出版专属故障 | 路径、资源转换、debug-only 指标清零 | 01 / 02 |
| 06 | 空引用与信号失效 | 显式取空、连接状态可查 | 01 / 02 |
| 07 | 调试验收与防复发 | 回归用例、判据固化、观测不残留 | 全部 |

⛔ **依赖是硬的**：05 的"导出版专属"靠的是 02 在 release 下还活着的指标，
⛔ 只装 debug 期指标，导出版就变成**零观测**，只能靠猜。

⛔ **02 依赖 01 而不是反过来**：先知道要盯哪个量，才知道该埋什么。
先埋一堆再挑，结果是"埋点本身成为性能问题"（audit #11）。

## 2. 域边界与接缝

| 邻域 | 分工 |
|---|---|
| `perf` 域 性能分析工作流 | 帧时间分解、优化顺序、预算分档见 `perf`，⛔ 本域只做**定性到"这是性能问题"为止** |
| `testing` 域 测试 | 用例组织与回归见 `testing`，⛔ 本域只产出"这个 bug 的最小复现" |
| `ops` 域 运营服务端 | 线上故障响应与灰度见 `ops`，⛔ 本域只管**本地可复现**的定位 |
| `save` 域 存档 | 存档损坏的修复见 `save`，⛔ 本域只管"怎么确认是存档坏了" |
| `netsync` 域 网络同步 | 同步不一致见 `netsync`，⛔ 本域只区分"本地就有"还是"只在联机出现" |
| `platform-export` 域 平台导出 | 导出配置见 `platform-export`，⛔ 本域只管导出**之后**才暴露的差异 |
| `diagnostics` | ⓘ howto 层，暂无 flow 域 —— 崩溃上报与符号化见该篇 |
| `verification` | ⓘ howto 层，暂无 flow 域 —— 事实核验与待核对标记见该篇 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `REPRO_MAX_STEPS` 最小复现步骤上限 | 01 | 7 | — | 待实测（⛔ 超了说明还没收敛到最小） |
| `LOG_FLUSH_INTERVAL` 日志刷盘间隔（秒） | 02 | 1.0 | — | 待实测（⛔ 崩溃时未刷的日志会骗人） |
| `MONITOR_SAMPLE_WINDOW` 监视器采样窗口（帧） | 02 | 120 | — | 待实测（⛔ 窗口过短读不到周期性抖动） |
| `HANG_WATCHDOG_SEC` 卡死看门狗阈值（秒） | 04 | 5.0 | — | 待实测（⛔ platform 相关，移动端与桌面不同） |
| `REMOTE_DEBUG_PORT` 远程调试端口 | 03 | 6007 | — | 待实测（⛔ 多实例同时开会冲突） |
| `AWAIT_TIMEOUT_SEC` 悬挂探测超时（秒） | 04 | 10.0 | — | 待实测（⛔ 不设则永久悬挂无任何提示） |
| `REGRESSION_CASE_MIN` 每 bug 最少回归用例数 | 07 | 1 | — | 待实测（⛔ 0 就等于没防复发） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发复现不了""偶发漏掉真故障"。

⛔ `LOG_FLUSH_INTERVAL` 与 audit #1 是同一件事的两面：
崩溃时刻未刷盘的日志**丢失且不留痕**，最后一行日志指向的是**别处**，
⛔ 于是排查方向被它带偏，而它看起来是"完整日志"。
