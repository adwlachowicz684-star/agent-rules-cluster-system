# 06 空引用与信号失效（调试域）

> **本步交付**：每处取节点都显式判空 + 连接状态可查 + 崩溃点即出错点
> **对应**：流程 `howto/godot/debugging.md` · 审核 `audit/godot/debugging.md`

## 0. 交付物定义

1. 所有 `get_node` / `$` 的结果都有判空或改用 `get_node_or_null`
2. 已知 `get_node` 失败**不报错**、返回 `null`
3. 信号连接状态可查（连没连上能验证）
4. 崩溃点尽量贴近真正的出错点
5. 节点生命周期与引用的关系已理清

## 1. 前置检查清单

- [ ] 全局搜 `get_node(` 与 `$` 的调用点都有判空或 `_or_null`
- [ ] 无"取了就用"的裸用法
- [ ] 信号连接能用一次验证确认连上了
- [ ] 已知 `queue_free()` 之后对象并非立刻消失
- [ ] 跨场景持有的引用已核对生命周期

## 2. 工序

### Step 1　`get_node` 失败不报错，它返回 null　`[debugging/06#S1]`

【读】``howto/godot/debugging.md#节点为 null``

【做】
每次取节点都判空，或改用 `get_node_or_null()`。
⛔ 不要以为 `get_node` 失败会报错 —— **它返回 `null`，不报错**（audit #10）。
⛔ 表现是崩溃点在**真正出错的地方之后很远**：
`null.method()` 炸的是调用处，⛔ 而成因在更早的取节点那一步，
排查时会一直在崩溃栈里找问题，而栈**完全正常**。

ⓘ 这条还有一个变体更难查：
⛔ 节点在场景树里被**移动过**（reparent），路径就失效了，
而移动是"正确的操作"，⛔ 于是得到"路径没错但取不到"，
排查被引向拼写和时序。

【产出】取节点统一入口（带判空）

【判据】全局无"取了就用"的裸调用。

【审】``audit/godot/debugging.md#10``

### Step 2　信号先确认连上了没有　`[debugging/06#S2]`

【读】``howto/godot/debugging.md#信号没触发``

【做】
信号不触发时，先查连接状态，再查发射条件。
⛔ 不要直接去查"为什么没 emit" —— 大量情况是**根本没连上**
（拼错信号名、节点还没 `add_child` 就 connect、连在了别的对象上），
⛔ 而这些**都不报错**：连一个不存在的信号名只会静默无事发生。

ⓘ 顺序很重要：
⛔ 先查连接是 O(1) 的确定性检查，
⛔ 查发射条件是**在运行时追状态**，成本高得多，
顺序反了会在一堆正常代码里白找一遍。

【产出】连接状态检查清单

【判据】任一信号都能立刻确认"连了 / 没连"。

【审】``audit/godot/debugging.md#10``

### Step 3　`queue_free()` 之后对象不是立刻消失　`[debugging/06#S3]`

【读】``howto/godot/debugging.md#节点为 null``

【做】
用 `is_instance_valid()` 判断，不要靠"刚 free 过所以应该没了"。
⛔ 不要假设 `queue_free()` 立即生效 —— 它**延迟到当前帧末**，
⛔ 表现是"这段时间内它还能被访问、还能收到信号"，
于是出现"已经删掉的对象还在响应事件"，⛔ 且不报错。

ⓘ 反过来同样成立：
⛔ 持有引用不等于对象活着 ——
`is_instance_valid()` 是对**已释放对象**的唯一可靠判断，
⛔ 而 `== null` 对已 free 的对象**不一定成立**，
于是"判空通过但一访问就炸"。

【产出】生命周期判断约定（用 `is_instance_valid`）

【判据】跨帧持有的引用在访问前都过 `is_instance_valid`。

【审】``audit/godot/debugging.md#10``

### Step 4　让崩溃点贴近出错点　`[debugging/06#S4]`

【读】``howto/godot/debugging.md#节点为 null``

【做】
取节点失败时**立刻**报出路径，不要等用到才炸。
⛔ 不要在取节点处静默返回 null、等到后面才崩 ——
⛔ 崩溃栈指向的是使用处，而成因在取节点处，
两者之间可能隔了**整个调用链**，
⛔ 而这类崩溃在复现时往往还得先走一遍长流程。

ⓘ 报错要带**完整路径与所在函数**：
⛔ 只报"节点为 null"没有路径，等于让人重新猜一遍是哪个，
⛔ 而路径是**取节点那一刻唯一已知的确定信息**，不记下来就永久丢失了。

【产出】取节点失败即报错（含路径）

【判据】人为改错一个路径，报错直接指出该路径。

【审】``audit/godot/debugging.md#1``

### Step 5　崩溃时最后一行日志不可信　`[debugging/06#S5]`

【读】``howto/godot/debugging.md#节点为 null``

【做】
崩溃场景下用即时刷新的输出，或不采信最后一行。
⛔ 不要靠 `print` 的最后一行定位崩溃点 —— **`print` 未刷新时崩溃会丢内容**（audit #1），
⛔ 最后一行日志指向的是崩溃**之前**的某处，
⛔ 而它看起来是"完整日志的结尾"，于是排查被它带到**错误的方向**。

ⓘ 这条与 Step 4 是配套的：
⛔ 即使有了即时报错，也要确认它**真的输出了** ——
⛔ 崩溃路径下"没看到报错"和"没发生"是两回事，
而人默认按后者理解。

【产出】崩溃期输出策略（即时刷新或外部日志）

【判据】人为崩溃一次，能拿到崩溃**当时**的输出。

【审】``audit/godot/debugging.md#1``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const STRICT_NODE := true      # 取不到即报错（06 参数表登记）

func node_or_null(path: NodePath) -> Node:
    var n := get_node_or_null(path)
    if n == null and STRICT_NODE:
        # ⛔ 立刻报出完整路径：晚一步报，崩溃栈就指向别处了
        push_error("节点取不到：%s（在 %s 中）" % [String(path), name])
    return n

func safe_use(target: Node) -> bool:
    # ⛔ 持有引用 ≠ 对象活着：queue_free 延迟到帧末，== null 未必成立
    return is_instance_valid(target)

func connect_checked(sig: Signal, cb: Callable) -> bool:
    if sig.is_connected(cb):
        return true                    # ⓘ 已连上不重复连（重复连会触发两次）
    var err := sig.connect(cb)
    if err != OK:
        # ⛔ 连不存在的信号名不会报错，只会静默无事发生
        push_error("信号连接失败 err=%d" % err)
        return false
    return true
```

## 4. 验收清单

- [ ] 全局无"取了就用"的裸 `get_node` / `$`
- [ ] 任一信号能立刻确认连接状态
- [ ] 跨帧持有引用访问前过 `is_instance_valid`
- [ ] 改错一个路径，报错直接指出该路径
- [ ] 人为崩溃一次能拿到当时输出

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 崩溃栈里找不到成因 | 返工 Step 1（get_node 静默返回 null） |
| 信号不触发，查了半天 emit | 返工 Step 2（其实没连上） |
| 已删对象还在响应事件 | 返工 Step 3（queue_free 延迟生效） |
| 崩溃点离出错点很远 | 返工 Step 4（取节点处未即报） |
| 按最后一行日志排查被带偏 | 返工 Step 5（崩溃时日志未刷新） |
