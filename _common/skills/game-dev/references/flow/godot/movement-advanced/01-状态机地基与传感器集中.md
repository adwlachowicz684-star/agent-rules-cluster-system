# 01 状态机地基与传感器集中（进阶移动域）

> **本步交付**：一份状态枚举与优先级表 + 一处传感器集中更新
> **对应**：流程 `howto/godot/movement-advanced.md` · 审核 `audit/godot/movement-advanced.md`

## 0. 交付物定义

1. 所有特殊移动被列成**显式状态枚举**（不是一串布尔）
2. 每个状态写明了进入 / 退出 / 优先级 / **可被谁打断**
3. 墙、地面、抓边传感器**只有一处**投射，状态转换只读结果
4. 落地状态是**每帧读取**的，不是事件通知
5. 角色节点的**缩放保持均匀**，尺寸差异改碰撞形状

## 1. 前置检查清单

- [ ] 状态枚举已列出，且不含"临时标志位"
- [ ] 每个状态的退出条件可写在一行内
- [ ] 缓冲与土狼时间的生效范围已覆盖**全部**状态
- [ ] 射线投射点已收敛到一个函数
- [ ] 角色与其父链上没有非均匀缩放

## 2. 工序

### Step 1　特殊移动不能堆 if，先立状态机　`[movement-advanced/01#S1]`

【读】``howto/godot/movement-advanced.md#0. 状态机是地基``

【做】
把二段跳、抓边、绳索、游泳、滑翔、攀爬全部列成**状态枚举**，
每个状态写明进入条件、退出条件、优先级、**可被谁打断**。
⛔ 不要每加一个特殊移动就加一个布尔 ——
"抓边时还能二段跳""水里还能蹬墙""摆荡中还能吃土狼时间"这类串味
在布尔堆里**每一条单看都对**，只有状态互斥矩阵能暴露。

ⓘ 优先级表要写在代码旁边，不要只存在于设计文档里：
⛔ 不写出来的优先级会在三个月后被"顺手加一个判断"悄悄改掉，
而状态机的正确性完全依赖它。

【产出】状态枚举 + 优先级表（可被打断关系）

【判据】任意两个状态都能回答"同时满足时谁赢"。

【审】``audit/godot/movement-advanced.md#1``

### Step 2　输入缓冲与土狼时间要覆盖所有状态　`[movement-advanced/01#S2]`

【读】``howto/godot/movement-advanced.md#0. 状态机是地基``

【做】
缓冲与土狼时间的生效范围显式写成"适用于哪些状态"的清单。
⛔ 不要只给跳跃加 ——
蹬墙跳、抓边起跳、出水起跳都是"离开某个附着面"，
⛔ 它们和跳跃共享同一个"刚离开还想按"的意图，
只给跳跃加会表现为"跳跃很跟手、蹬墙跳总是吃不到输入"，
⛔ 而手感问题天然会被归因到"参数没调好"。

【产出】缓冲 / 土狼时间的状态适用清单

【判据】新增一个状态时，这张清单会被显式改动（而不是默认不生效）。

【审】``audit/godot/movement-advanced.md#2``

### Step 3　传感器集中更新，不在状态里各投一次　`[movement-advanced/01#S3]`

【读】``howto/godot/movement-advanced.md#0. 状态机是地基``

【做】
墙传感器、地面传感器、抓边传感器**集中在同一个函数里**更新一次，
状态转换只读这些结果。
⛔ 不要每个状态自己投射 ——
同一帧内不同状态投射的射线**起点与长度往往不同**，
于是"这一帧抓到了、下一帧没抓到"，表现为边缘抖动，
⛔ 而抖动会被当成射线阈值没调好，越调越乱。

ⓘ 集中更新还顺带解决顺序问题：
⛔ 传感器必须在 `move_and_slide()` **之后**更新，
否则读到的是上一帧的碰撞结果。

【产出】一个 `update_sensors()` 函数 + 传感器结果结构

【判据】全局只有一个地方发射移动相关射线（可用 grep 验证）。

【审】``audit/godot/movement-advanced.md#15``

### Step 4　落地状态每帧读取，不用事件通知　`[movement-advanced/01#S4]`

【读】``howto/godot/movement-advanced.md#1. 二段跳与空中控制``

【做】
把"是否在地面"作为**每帧读取的状态**提供给状态机，
⛔ 不要做成"落地时发信号"的一次性事件。
官方：`is_on_floor()` 只反映**本帧**最近一次 `move_and_slide()` 的结果 ——
⛔ 在斜坡、吸附失效的瞬间、平台边缘，事件型通知会**漏发或重发**，
表现为"二段跳次数偶尔没重置""偶尔能跳三次"，
⛔ 而这正是最难复现的那一类 bug：它只在特定几何上出现。

【产出】每帧的地面状态（含法线与角度）

【判据】连续 60 帧在斜坡上走动，`is_on_floor()` 无跳变；若有跳变，先查 `floor_snap_length`。

【审】``audit/godot/movement-advanced.md#32``

### Step 5　角色缩放必须均匀，尺寸差异改碰撞形状　`[movement-advanced/01#S5]`

【读】``howto/godot/movement-advanced.md#6. ⚠ 改重力方向：一条被推翻的说法``

【做】
检查角色节点及其父链，**缩放保持均匀**（三轴相同）。
游泳时想让判定变小、滑翔时想压扁，改**碰撞形状**的尺寸，不改节点缩放。
⛔ 官方 Warning：CharacterBody3D 在**非均匀缩放**下可能不按预期工作。
⛔ 它不报错，表现为碰撞形状与视觉对不上、斜坡上莫名卡住，
⛔ 而排查会被引向碰撞层与射线，因为"缩放"看起来只是视觉参数。

【产出】缩放均匀性检查（可写成断言）

【判据】角色及其父链 `scale` 三轴相等。

【审】``audit/godot/movement-advanced.md#30``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量与枚举在此声明，承接上文即可直接用
enum MState { GROUND, AIR, LEDGE, ROPE, SWIM, GLIDE, CLIMB }

# 优先级：数值大的赢（同时满足时）
const PRIORITY := {
    MState.LEDGE: 50, MState.ROPE: 45, MState.CLIMB: 40,
    MState.SWIM: 35, MState.GLIDE: 30, MState.AIR: 20, MState.GROUND: 10,
}

# 缓冲 / 土狼时间适用状态（Step 2 的清单）
const BUFFERED_STATES := [MState.GROUND, MState.AIR, MState.LEDGE, MState.CLIMB]

var _state: MState = MState.GROUND
var _sensors := {"wall": false, "floor": false, "floor_normal": Vector3.UP, "ledge": false}

func update_sensors() -> void:
    # ⛔ 必须在 move_and_slide() 之后调用，否则读到上一帧结果
    _sensors["floor"] = is_on_floor()
    _sensors["floor_normal"] = get_floor_normal() if is_on_floor() else Vector3.UP
    _sensors["wall"] = is_on_wall()
    # ⛔ 抓边射线只在这里投射一次，状态转换不重复投
    _sensors["ledge"] = _probe_ledge()

func _probe_ledge() -> bool:
    # 见 03 功能点：双射线判定
    return false

func assert_uniform_scale(n: Node3D) -> void:
    var s := n.scale
    # ⛔ 非均匀缩放下 CharacterBody3D 可能不按预期工作
    assert(abs(s.x - s.y) < 0.001 and abs(s.y - s.z) < 0.001)
```

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 抓边时还能二段跳 / 水里还能蹬墙 | 返工 Step 1（状态互斥没立起来） |
| 跳跃跟手、蹬墙跳吃不到输入 | 返工 Step 2（缓冲只给了跳跃） |
| 边缘抖动，越调阈值越乱 | 返工 Step 3（多状态各投一次射线） |
| 二段跳次数偶尔没重置 | 返工 Step 4（用了事件型落地通知） |
| 碰撞与视觉对不上、斜坡莫名卡住 | 返工 Step 5（非均匀缩放） |
