# 05 游泳潜水与滑翔（进阶移动域）

> **本步交付**：介质切换是显式状态 + 浮力阻尼可调 + 过渡三处同切
> **对应**：流程 `howto/godot/movement-advanced.md` · 审核 `audit/godot/movement-advanced.md`

## 0. 交付物定义

1. 水体检测**并入传感器集中更新**，不在水里另投一次
2. 水下改的是**重力 + 阻尼 + 浮力**，不是只改重力
3. 出水 / 入水时**相机、音频、移动模式一起切**
4. 滑翔若动 `motion_mode`，落地判定失效的后果已评估
5. 攀爬姿态对齐**不把碰撞法线当表面法线**

## 1. 前置检查清单

- [ ] 01 的传感器结构已包含"当前介质"
- [ ] 水体是 Area 还是高度判断已选定
- [ ] 浮力与阻尼已登记进参数表
- [ ] 水下雾 / 后处理资源已就位（见 `environment-systems.md`）
- [ ] 切换是瞬切还是插值已决定

## 2. 工序

### Step 1　水体检测并入传感器，不另投一次　`[movement-advanced/05#S1]`

【读】``howto/godot/movement-advanced.md#0. 状态机是地基``

【做】
把"当前是否在水中"写进 01 那套集中传感器的结果里
（Area 进出 或 高度判断，二选一）。
⛔ 不要在水里另起一套检测 ——
两套检测的**边界不一致**，角色会在水面附近反复进出，
⛔ 表现为"在水面抖动、音效反复切换"，
⛔ 而每一套检测单独看都是对的，只有放在一起才打架。

【产出】介质字段并入传感器结果

【判据】角色静止在水面时，介质状态 60 帧内不跳变。

【审】``audit/godot/movement-advanced.md#15``

### Step 2　水下改的是重力、阻尼、浮力三件事　`[movement-advanced/05#S2]`

【读】``howto/godot/movement-advanced.md#4. 游泳与潜水``

【做】
进入水中时同时改：重力方向的分量、`WATER_DRAG` 阻尼、`BUOYANCY` 浮力。
⛔ 不要只把重力调小 ——
只改重力会得到"缓慢下沉但停不下来、也没有上浮"的手感，
⛔ 表现为"像在果冻里而不是在水里"，
⛔ 而"果冻感"是主观描述，不会有人去查是不是漏了浮力项。

【产出】水下三参数（重力 / 阻尼 / 浮力）

【判据】松开按键时角色稳定悬浮或缓慢上浮，不是持续下沉。

【审】``audit/godot/movement-advanced.md#8``

### Step 3　出水入水要相机、音频、移动模式一起切　`[movement-advanced/05#S3]`

【读】``howto/godot/movement-advanced.md#4. 游泳与潜水``

【做】
把"入水"做成一次**原子切换**：移动模式、相机（含雾与后处理）、音频总线同时改变。
⛔ 不要只切移动 ——
移动切了、相机没切，玩家看到的是"人在水下但画面是陆地"，
⛔ 表现为"能游但很出戏"，
⛔ 而这类问题不会被报成 bug，因为功能上**全都正常**。

ⓘ 音频总线那一路最容易漏：
⛔ 只改音效不切总线，水下的低通滤波不会生效，
⛔ 而"声音不对"比"画面不对"更难被指认为具体缺陷。

【产出】入水 / 出水的原子切换函数

【判据】切换发生在同一帧，不存在"已入水但相机还是陆地"的中间帧。

【审】``audit/godot/movement-advanced.md#9``

### Step 4　滑翔若切 Floating，落地判定就失效　`[movement-advanced/05#S4]`

【读】``howto/godot/movement-advanced.md#6. ⚠ 改重力方向：一条被推翻的说法``

【做】
评估滑翔是否要切 `MOTION_MODE_FLOATING`；
若切了，就要有**另一套**落地判定（射线或高度），不能再用 `is_on_floor()`。
⛔ 官方：Floating 模式下**所有碰撞都被视为墙**，
⛔ 于是 `is_on_floor()` 恒为 false，
表现为"滑翔后永远接不到落地动画、落地音效不播"，
⛔ 而碰撞本身完全正常，所以不会想到是模式导致的。

ⓘ 不切模式、只改升力阻力，是更省事的一条路：
⛔ 切模式换来的是"没有地面"这个语义，代价是整套落地逻辑要重写。

【产出】滑翔的落地判定方案（含是否切模式）

【判据】滑翔落地能触发落地动画与音效。

【审】``audit/godot/movement-advanced.md#12``

### Step 5　攀爬对齐不把碰撞法线当表面法线　`[movement-advanced/05#S5]`

【读】``howto/godot/movement-advanced.md#2. 爬墙 / 抓边（重点）``

【做】
攀爬时对齐表面，用射线命中的**表面法线**，
把 `get_floor_normal()` 当作碰撞法线并准备兜底。
⛔ 不要默认两者恒等 ——
官方 Warning：**碰撞法线并不总是与表面法线相同**。
⛔ 攀爬是最依赖法线的移动（姿态、手脚位置都由它决定），
⛔ 表现为"大部分表面贴得很好，少数表面手穿进去"，
⛔ 而少数表面通常被当成模型问题。

【产出】攀爬法线来源与兜底

【判据】在拼接网格与凹角上，手脚不穿模。

【审】``audit/godot/movement-advanced.md#23``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const WATER_DRAG := 0.85         # 水下阻尼系数（05 参数表登记）
const BUOYANCY := 4.0            # 浮力加速度（米/秒²，05 参数表登记）
const GLIDE_LIFT := 0.9          # 滑翔升力系数（05 参数表登记）
const SURFACE_HYSTERESIS := 0.15 # 水面迟滞（米，防抖动）

var _in_water := false
var _surface_y := 0.0

func update_medium(sensors: Dictionary, pos_y: float) -> void:
    # ⛔ 迟滞：进出水用不同阈值，防止水面抖动
    if _in_water:
        _in_water = pos_y < _surface_y + SURFACE_HYSTERESIS
    else:
        _in_water = pos_y < _surface_y - SURFACE_HYSTERESIS
    sensors["medium"] = "water" if _in_water else "air"

func apply_water(vel: Vector3, delta: float) -> Vector3:
    # ⛔ 三件事一起改：重力、阻尼、浮力
    vel.y += BUOYANCY * delta
    vel *= pow(1.0 - WATER_DRAG, delta * 60.0)
    return vel

func apply_glide(vel: Vector3) -> Vector3:
    # 简化升力 / 阻力模型：只压制下落速度
    if vel.y < 0.0:
        vel.y *= 1.0 - GLIDE_LIFT * 0.1
    return vel
```

## 4. 验收清单

- [ ] 静止在水面时，介质状态 60 帧内不跳变
- [ ] 松开按键能稳定悬浮或缓慢上浮
- [ ] 入水切换在同一帧完成，无中间态
- [ ] 滑翔落地能触发落地动画与音效
- [ ] 拼接网格与凹角上手脚不穿模

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 水面抖动、音效反复切换 | 返工 Step 1（两套检测边界不一致） |
| 像在果冻里而不是水里 | 返工 Step 2（只改了重力） |
| 能游但很出戏 | 返工 Step 3（相机/音频没同切） |
| 滑翔后落地动画不播 | 返工 Step 4（Floating 下无地板） |
| 少数表面手穿进去 | 返工 Step 5（碰撞法线当表面法线） |
