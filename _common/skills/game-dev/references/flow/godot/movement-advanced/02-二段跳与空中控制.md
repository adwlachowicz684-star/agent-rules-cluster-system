# 02 二段跳与空中控制（进阶移动域）

> **本步交付**：次数重置正确 + 空中加速度可调 + 可变跳高生效
> **对应**：流程 `howto/godot/movement-advanced.md` · 审核 `audit/godot/movement-advanced.md`

## 0. 交付物定义

1. 跳跃次数的重置读的是**本帧**地面状态
2. "空中"是显式状态，有进入 / 退出条件
3. 空中水平控制给的是**加速度**，不是直接赋速度
4. 可变跳高（松键短跳）只在**上升段**生效
5. 斜坡与平台边缘上次数重置不漏、不重

## 1. 前置检查清单

- [ ] 01 的状态机与传感器已就绪
- [ ] 地面状态来自每帧读取（非事件）
- [ ] 空中加速度已登记进参数表
- [ ] 松键检测的时机在上升段内
- [ ] `floor_snap_length` 非 0（否则吸附被禁用）

## 2. 工序

### Step 1　次数重置读本帧状态，不要缓存　`[movement-advanced/02#S1]`

【读】``howto/godot/movement-advanced.md#1. 二段跳与空中控制``

【做】
每次起跳前**重新读** `is_on_floor()`，落地时把次数清零。
⛔ 不要把"是否在地面"缓存成成员变量跨帧复用 ——
官方：它只反映**本帧**最近一次 `move_and_slide()` 的结果，
⛔ 缓存值在斜坡、平台边缘、吸附失效的那一帧会是**上一帧**的，
表现为"偶尔能跳三次"，⛔ 且不报错、只在特定几何上出现。

【产出】次数重置逻辑（每帧读取，不缓存）

【判据】在斜坡与移动平台上连续起跳 20 次，次数上限从未被突破。

【审】``audit/godot/movement-advanced.md#13``

### Step 2　空中是独立状态，写清进入与退出　`[movement-advanced/02#S2]`

【读】``howto/godot/movement-advanced.md#0. 状态机是地基``

【做】
把"空中"作为**状态机里的一个显式状态**，写明谁能打断它
（抓边、绳索挂载、入水、滑翔都能从空中进入）。
⛔ 不要写成 `if not is_on_floor()` 的隐式分支 ——
那样"空中"就成了**所有其他状态的兜底**，
⛔ 于是抓边失败会落回空中、绳索断线会落回空中，
表现为"状态看起来对，但动画和音效错了"，且不报错。

【产出】空中状态的进入 / 退出 / 可打断关系

【判据】故意让抓边失败，角色进入的是"空中"而不是某个残留态。

【审】``audit/godot/movement-advanced.md#1``

### Step 3　空中控制给加速度，特效读实际速度　`[movement-advanced/02#S3]`

【读】``howto/godot/movement-advanced.md#8. 斜坡与吸附：floor_* 四件套``

【做】
空中水平控制按 `AIR_ACCEL` 施加**加速度**，
并对齐特效时读 `get_real_velocity()` 而不是 `velocity`。
⛔ 不要用 `velocity` 当实际位移速度 ——
官方举例：爬坡时即使 velocity 是水平的，实际移动也是**斜向**的，
`velocity` 只是"请求速度"。
⛔ 二段跳的拖尾、音效音量若按 `velocity` 对齐，
在斜坡起跳时会与画面**明显不同步**，而数值上两者都"有值"。

【产出】空中加速度逻辑 + 特效速度读取方式

【判据】斜坡上起跳，拖尾方向与角色实际移动方向一致。

【审】``audit/godot/movement-advanced.md#24``

### Step 4　可变跳高只在上升段削减速度　`[movement-advanced/02#S4]`

【读】``howto/godot/movement-advanced.md#8. 斜坡与吸附：floor_* 四件套``

【做】
松开跳跃键时按 `JUMP_CUT_FACTOR` 削减**垂直速度**，
且只在角色**沿上方向运动**（还有上升速度）时才生效。
⛔ 不要在下降段也削 ——
官方写明：沿 `up_direction` 移动（含上升速度）时**不应用吸附**，
⛔ 上升段是唯一"确实在主动上升"的窗口，
在下降段削减会让"轻点一下"和"长按"落地时间**反过来**，
⛔ 表现为手感诡异但每次都能跑完，最难被判定为 bug。

【产出】可变跳高逻辑（含上升段判定）

【判据】轻点与长按的跳跃高度差稳定，且轻点**始终更矮**。

【审】``audit/godot/movement-advanced.md#27``

### Step 5　斜坡与平台边缘上的重置一致性　`[movement-advanced/02#S5]`

【读】``howto/godot/movement-advanced.md#8. 斜坡与吸附：floor_* 四件套``

【做】
把 `floor_snap_length` 设为**非 0** 并实测，
确认斜坡与移动平台边缘上跳跃次数重置稳定。
⛔ 不要把它设成 0 图省事 ——
官方：0 = **完全禁用吸附**，下坡时角色会一路弹跳，
`is_on_floor()` 时真时假，
⛔ 于是 Step 1 那套"每帧读取"读到的是**抖动的地面状态**，
次数重置跟着一起抖。⛔ 排查会被引向射线或碰撞形状，
因为"落地检测"看起来就是时灵时不灵。

【产出】`floor_snap_length` 实测值（登记进参数表）

【判据】下坡全速跑，`is_on_floor()` 连续为真无跳变。

【审】``audit/godot/movement-advanced.md#26``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const MAX_JUMPS := 2
const AIR_ACCEL := 18.0          # 空中水平加速度（02 参数表登记）
const JUMP_CUT_FACTOR := 0.5     # 松键短跳保留系数（02 参数表登记）
const FLOOR_SNAP_LEN := 0.1      # floor_snap_length（06 参数表登记，非 0）

var _jumps_used := 0

func _ready() -> void:
    floor_snap_length = FLOOR_SNAP_LEN
    # ⛔ 0 会完全禁用吸附，下坡 is_on_floor() 时真时假
    assert(FLOOR_SNAP_LEN > 0.0)

func try_jump(jump_speed: float) -> void:
    # ⛔ 每帧重读，不要缓存 is_on_floor()
    if is_on_floor():
        _jumps_used = 0
    if _jumps_used >= MAX_JUMPS:
        return
    velocity.y = jump_speed
    _jumps_used += 1

func cut_jump() -> void:
    # ⛔ 只在还有上升速度时削减
    if velocity.dot(up_direction) > 0.0:
        velocity.y *= JUMP_CUT_FACTOR

func air_control(dir: Vector3, delta: float) -> void:
    velocity.x = move_toward(velocity.x, dir.x * _max_speed, AIR_ACCEL * delta)
    velocity.z = move_toward(velocity.z, dir.z * _max_speed, AIR_ACCEL * delta)

var _max_speed := 6.0
```

- [ ] 抓边失败时进入空中态而非残留态
- [ ] 斜坡起跳的特效方向与实际移动方向一致
- [ ] 轻点始终比长按矮

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 偶尔能跳三次 | 返工 Step 1（缓存了地面状态） |
| 状态对但动画音效错 | 返工 Step 2（空中是隐式兜底分支） |
| 斜坡起跳拖尾方向不对 | 返工 Step 3（读了 velocity 而非实际速度） |
| 轻点反比长按跳得远 | 返工 Step 4（下降段也削了速度） |
| 下坡时次数重置忽好忽坏 | 返工 Step 5（floor_snap_length 为 0） |
