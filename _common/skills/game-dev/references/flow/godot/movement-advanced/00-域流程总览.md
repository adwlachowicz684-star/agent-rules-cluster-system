# 进阶移动（Advanced Movement）—— 域流程总览

> ⚠ **第 0 步：先分清"这是哪一种特殊移动"，再决定用哪条路径。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按当前要做的特殊移动挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 二段跳 / 空中控制手感 | 01 → 02 → 07 |
| 爬墙 / 抓边 / 攀爬 | 01 → 03 → 07 |
| 绳索 / 摆荡 | 01 → 04 → 07 |
| 游泳 / 潜水 / 滑翔（介质切换） | 01 → 05 → 07 |
| 改重力方向、传送门、球形星球 | 01 → 06 → 07 |
| 角色站在移动平台上被带走 | 01 → 06 → 07 |
| 斜坡上抖动 / 走不上去 / 下坡飞出去 | 01 → 06 → 07 |
| 只是基础平台跳跃 | ⛔ 转 `character` / `platformer-feel`，本域不覆盖 |

⛔ **01 不能跳过** —— 这些特殊移动的共同失败模式是**堆 if**：
二段跳的次数、抓边的进入、绳索的挂载、入水的切换，各自加一个布尔就"能跑"，
然后互相打架：抓边时还能二段跳、水里还能蹬墙、摆荡中还能触发土狼时间。
⛔ 状态机不先立起来，后面每加一个特殊移动就要回头改一遍前面所有的。

⛔ **06 是多条路径的公共收口**：改重力、移动平台、斜坡吸附，
三者其实都在改同一组量 —— `up_direction`、`motion_mode`、`floor_*` 系列。
⛔ 分头调会出现"改重力的人把 `floor_snap_length` 设成 0，斜坡那边就炸了"，
而两边单看都合理。

ⓘ 03 与 06 最容易互相甩锅：
"爬不上去"既可能是射线阈值（03），也可能是 `floor_max_angle`（06）。
⛔ 所以 03 只管**射线与状态**，06 只管**地面判定参数**，两边不许各判一次。

## 1. 功能点拆解与依赖

| # | 功能点 | 交付 | 依赖 |
|---|---|---|---|
| 01 | 状态机地基与传感器集中 | 状态枚举、优先级、传感器集中更新 | — |
| 02 | 二段跳与空中控制 | 次数重置、空中加速度、可变跳高 | 01 |
| 03 | 爬墙与抓边 | 双射线传感器、三阶段、蹬墙跳 | 01 |
| 04 | 绳索与摆荡 | 挂载/解挂、助力模型、绳长 | 01 |
| 05 | 游泳潜水与滑翔 | 介质检测、浮力阻尼、过渡同切 | 01 |
| 06 | 可变重力与移动平台承载 | up/相机/平面同变、AnimatableBody3D、floor_* 四件套 | 01 / 03 |
| 07 | 进阶移动验收 | 状态互斥、边界实测、参数登记 | 全部 |

⛔ **依赖是硬的**：02 的"次数重置"靠 01 的**每帧状态读取**，
⛔ 若 01 用信号/事件提供落地通知，02 在斜坡与平台边缘会漏重置
（官方：`is_on_floor()` 只反映**本帧**最近一次 `move_and_slide()`）。

⛔ **06 依赖 03 而不是反过来**：抓边自己要改一次上方向与移动模式，
⛔ 若 03 先写死 `Vector3.UP`，06 改重力时抓边会静默失效 ——
表现为"改了重力之后爬墙还能用，但抓边永远抓不到"。

## 2. 域边界与接缝

| 邻域 | 分工 |
|---|---|
| `character` 域 角色控制 | 基础平台跳跃、土狼时间、输入缓冲见 `character`，⛔ 本域只管**特殊移动状态** |
| `physics` 域 物理 | 物理刻度与移动手感参数的一致性见 `physics`，⛔ 本域不改物理刻度 |
| `vehicle` 域 载具 | 上下车时的移动状态机交接见 `vehicle`，⛔ 本域只提供"载人时角色进入 passenger 态" |
| `platformer-feel` | ⓘ howto 层，暂无 flow 域 —— 手感参数区间见该篇 |
| `environment-systems` | ⓘ howto 层，暂无 flow 域 —— 水下雾/后处理见该篇 |
| `animation-skeletal` | ⓘ howto 层，暂无 flow 域 —— 攀爬/游泳的姿态动画见该篇 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `LEDGE_TOP_OFFSET` 抓边上方射线起点相对胶囊顶的偏移（米） | 03 | 0.05 | — | 待实测（⛔ 必须按胶囊高度实测） |
| `LEDGE_REACH` 抓边射线长度（米） | 03 | 0.6 | — | 待实测（⛔ 过短抓不到、过长误触发） |
| `LEDGE_EDGE_BAND` 可接受的边缘高度带（米） | 03 | 0.25 | — | 待实测（⛔ 过宽会在墙中段误触发） |
| `WALLJUMP_UP_SPEED` 蹬墙跳垂直分量（米/秒） | 03 | 7.0 | — | 待实测（⛔ 不够就蹬不上去） |
| `AIR_ACCEL` 空中水平加速度（米/秒²） | 02 | 18.0 | — | 待实测（⛔ 不是"能不能控制"，是给多少） |
| `JUMP_CUT_FACTOR` 松键短跳的速度保留系数 | 02 | 0.5 | — | 待实测 |
| `SWING_ASSIST` 摆荡助力系数 | 04 | 1.15 | — | 待实测（⛔ 纯物理很难玩） |
| `ROPE_MAX_LEN` 绳索最大长度（米） | 04 | 12.0 | — | 待实测 |
| `WATER_DRAG` 水下阻尼系数 | 05 | 0.85 | — | 待实测 |
| `BUOYANCY` 浮力加速度（米/秒²） | 05 | 4.0 | — | 待实测 |
| `GLIDE_LIFT` 滑翔升力系数 | 05 | 0.9 | — | 待实测 |
| `FLOOR_SNAP_LEN` 斜坡吸附距离（米，对应 `floor_snap_length`） | 06 | 0.1 | — | 待实测（⛔ 官方默认 0.1，0 即禁用吸附） |
| `UP_LERP_SEC` 上方向切换插值时长（秒） | 06 | 0.25 | — | 待实测（⛔ 瞬切会让相机翻滚） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"某些角落抓不到""某些斜坡抖""站在平台上偶尔滑走"。

⛔ `FLOOR_SNAP_LEN` 与 audit #26 是同一件事的两面：
设为 0 等于**完全禁用吸附**，下坡会一路弹跳（`is_on_floor()` 时真时假），
⛔ 而排查会被引向射线或碰撞形状，因为"落地检测"看起来就是时灵时不灵。
