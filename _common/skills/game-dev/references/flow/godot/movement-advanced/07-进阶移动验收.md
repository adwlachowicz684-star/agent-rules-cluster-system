# 07 进阶移动验收（进阶移动域）

> **本步交付**：状态互斥回归 + 边界实测 + 参数登记回填 + 观测不残留
> **对应**：流程 `howto/godot/movement-advanced.md` · 审核 `audit/godot/movement-advanced.md`

## 0. 交付物定义

1. **状态互斥矩阵**成对跑过，任意两态互相打断都有确定去向
2. 抓边 / 斜坡 / 平台边缘三类**边界**实测过，不是只测中间情况
3. 斜坡的角度与 margin 参数分清了责任，陡壁仍不可走
4. 承载体三件事（类型、`sync_to_physics`、驱动方式）逐项复核
5. 平台速度的读取时机正确，且**没有重复叠加**

## 2. 工序

### Step 1　状态互斥矩阵：每对状态都试一遍互相打断　`[movement-advanced/07#S1]`

【读】``howto/godot/movement-advanced.md#0. 状态机是地基``

【做】
把状态两两组合，逐个强制触发"从 A 打断到 B"，记录去向。
⛔ 不要只测"每个状态自己能用" ——
进阶移动的全部风险都在**交界**上：
抓边时起跳、摆荡中入水、滑翔时抓边、游泳中蹬墙，
⛔ 这些组合在正常使用里出现频率低，
⛔ 于是测试跑完了"每个功能都正常"，上线后被玩家一次连招打穿。

ⓘ 矩阵要写成可复跑的用例，不是一次性手测：
⛔ 手测过一遍的意义仅限于当时那个版本，
⛔ 下一次改状态优先级时它不会提醒你重新跑。

【产出】状态互斥矩阵（含每对的期望去向）

【判据】矩阵中每一格都有期望值，且不为空。

【审】``audit/godot/movement-advanced.md#1``

### Step 2　边界实测：抓边、斜坡、平台边缘　`[movement-advanced/07#S2]`

【读】``howto/godot/movement-advanced.md#2. 爬墙 / 抓边（重点）``

【做】
对三类边界逐个实测：可抓边缘与不可抓边缘的**相邻**位置、
坡道的最陡可走点与最缓不可走点、平台的**边缘一帧**。
⛔ 不要只测"中间情况" ——
阈值类参数的失败**只发生在边界**，
⛔ 表现为"整体能用，就是偶尔不对"，
⛔ 而"偶尔"会让排查停留在复现上，永远走不到定位。

ⓘ 抓边阈值必须按胶囊高度实测：
⛔ 换了角色模型（胶囊尺寸变了）之后要**重新测**，
⛔ 沿用旧阈值会表现为"新角色抓不到边"，
⛔ 而代码一行没改，于是被当成新模型有问题。

【产出】三类边界的实测记录（含临界值）

【判据】每个边界都能指出临界值在哪两个数之间。

【审】``audit/godot/movement-advanced.md#6``

### Step 3　斜坡参数分清责任：角度还是 margin　`[movement-advanced/07#S3]`

【读】``howto/godot/movement-advanced.md#8. 斜坡与吸附：floor_* 四件套``

【做】
走不上斜坡时，先分清是 `floor_max_angle` 还是 `safe_margin` 的责任，再改对应的那个。
⛔ 不要一味调大 `floor_max_angle` ——
官方默认 **45°**（0.785398 弧度），超过即判为墙；
调大它确实能"修好"走不上斜坡，但陡壁也会被判成地板，角色开始爬墙。
⛔ 而官方还注明：GROUNDED 模式下 `safe_margin`（默认 0.001）
**只在 `floor_block_on_wall` 为 true 时**才影响移动 ——
⛔ 关掉 `floor_block_on_wall` 的人改 `safe_margin` 是**完全无感**的，
⛔ 于是得到"这个参数没用"的错误结论并放弃它。

【产出】角度 / margin 的责任判定记录

【判据】陡壁不可走，缓坡可走，且临界角与设定值一致。

【审】``audit/godot/movement-advanced.md#29``

### Step 4　承载体三件事逐项复核　`[movement-advanced/07#S4]`

【读】``howto/godot/movement-advanced.md#7. 移动平台承载：AnimatableBody3D 与三个平台参数``

【做】
对每个承载体复核三件事：类型是 **AnimatableBody3D**、
`sync_to_physics` 为 true、驱动方式**不是** `PhysicsBody3D.move_and_collide()`。
⛔ 不要只复核类型 ——
官方对 `sync_to_physics` 的 Warning 是**不要与 `move_and_collide()` 同时使用**，
⛔ 用 `move_and_collide()` 驱动的平台类型是对的、同步也是开的，
⛔ 但承载就是时灵时不灵，
⛔ 而这三件事里任何一件单独看都"配置正确"。

【产出】承载体复核表（三列：类型 / 同步 / 驱动方式）

【判据】每个承载体三列全绿，且站在上面不动时相对位置不变。

【审】``audit/godot/movement-advanced.md#17``

### Step 5　平台速度：读在 move_and_slide 之后，且不要重复加　`[movement-advanced/07#S5]`

【读】``howto/godot/movement-advanced.md#7. 移动平台承载：AnimatableBody3D 与三个平台参数``

【做】
需要平台速度做特效或判定时，在 `move_and_slide()` **之后**读
`get_platform_velocity()`，且**不要**再手动加到 velocity 上。
⛔ 双重错误会互相掩盖：
官方注明它仅在调用 `move_and_slide()` **之后**有效（读早了是旧值），
同时 `move_and_slide()` **自己已经**把平台速度计入本步运动 ——
⛔ 手动再加一次就是**双倍**，表现为"平台一启动人就飞出去"，
⛔ 而单看这一行代码，它只是"把平台速度加上去"，完全合理。

ⓘ 排查期若为了确认承载生效而手动加过一次，
⛔ 收尾时一定要删：它是以"调试需要"的名义加的，最容易被默认保留。

【产出】平台速度的读取点与用途清单

【判据】平台启动瞬间角色不飞出；读到的平台速度与平台实际速度一致。

【审】``audit/godot/movement-advanced.md#22``


## 3. 验收清单

- [ ] 状态互斥矩阵每格都有期望去向
- [ ] 三类边界都能指出临界值区间
- [ ] 陡壁不可走、缓坡可走，临界角与设定一致
- [ ] 承载体三列（类型 / 同步 / 驱动方式）全绿
- [ ] 平台启动瞬间角色不飞出，读数与平台实际速度一致


- [ ] 前 6 个功能点的参数已登记进 00 的参数表，实测值已回填
- [ ] 排查期加的调试可视化已清理或挂 `DEBUG_VISUAL` 总开关

## 4. 常见返工

| 现象 | 返工到 |
|---|---|
| 每个功能都正常，连招就穿 | 返工 Step 1（没跑互斥矩阵） |
| 整体能用就是偶尔不对 | 返工 Step 2（只测了中间情况） |
| 修好走坡后角色开始爬墙 | 返工 Step 3（一味调大 floor_max_angle） |
| 承载时灵时不灵 | 返工 Step 4（只复核了类型） |
| 平台一启动人就飞出去 | 返工 Step 5（平台速度加了两次） |
