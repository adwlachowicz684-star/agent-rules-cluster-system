# 06 可变重力与移动平台承载（进阶移动域）

> **本步交付**：改重力后地面判定仍成立 + 平台能带着人走 + 斜坡不抖
> **对应**：流程 `howto/godot/movement-advanced.md` · 审核 `audit/godot/movement-advanced.md`

## 0. 交付物定义

1. 改 `up_direction` 前，那**五个真因**被逐个排除
2. `up_direction` **不为零向量**
3. 改重力时 **up / 相机 / 移动平面一起变**
4. 移动平台是 **AnimatableBody3D**
5. `platform_wall_layers` 已按需要显式开启
6. 离开平台的速度继承行为已选定
7. 斜坡吸附与 `floor_*` 四件套已实测

- [ ] 相机与移动平面都存在"上方向"的可变入口

## 2. 工序

### Step 1　改 up_direction 前先排除那五个真因　`[movement-advanced/06#S1]`

【读】``howto/godot/movement-advanced.md#6. ⚠ 改重力方向：一条被推翻的说法``

【做】
"改了 `up_direction` 之后 `is_on_floor()` 失效"这个说法**不成立**，
先逐个排除真正的五个成因：先读后移动的顺序、夹角超过 `floor_max_angle`、
旋转角色却没同步上方向、切到了 Floating、坐标系不同步。
⛔ 不要一上来就判定"这个 API 有 bug 得绕开" ——
绕开的做法通常是自己写一套落地检测，
⛔ 于是真正的成因（多数是顺序或角度）**还在原地**，
⛔ 表现为"自己写的检测在大部分地方对、少数地方错"，比原来更难查。

【产出】五个真因的排除记录

【判据】能指出是哪一个成因，而不是"改了就不行"。

【审】``audit/godot/movement-advanced.md#10``

### Step 2　up_direction 不能设为零向量　`[movement-advanced/06#S2]`

【读】``howto/godot/movement-advanced.md#6. ⚠ 改重力方向：一条被推翻的说法``

【做】
保证 `up_direction` 始终是**单位向量**且非 `Vector3.ZERO`。
⛔ 不要为了"球形星球上方向一直变"就临时置零想跳过判定 ——
官方：`up_direction` 用于区分地板、墙、天花板，**不能设为 ZERO**。
⛔ 表现为地板与墙的判定整体失效，
⛔ 而它通常发生在**切换的那一帧**，于是被当成偶发问题。

ⓘ 切换上方向要**插值**（`UP_LERP_SEC`），不要瞬切：
⛔ 瞬切会让相机在一帧内翻滚，
⛔ 而"改完重力相机乱转"会被归因到相机代码，不会想到是上方向瞬切。

【产出】上方向的约束与插值切换

【判据】切换全程 `up_direction.length()` 恒为 1，且相机无翻滚。

【审】``audit/godot/movement-advanced.md#11``

### Step 3　改重力不是只改向量，三处要一起变　`[movement-advanced/06#S3]`

【读】``howto/godot/movement-advanced.md#6. ⚠ 改重力方向：一条被推翻的说法``

【做】
改重力时同时更新：**角色的 up**、**相机的上方向**、**移动平面**。
⛔ 不要只改 gravity 向量 ——
只改重力会让角色贴着新地面走，但输入仍按旧平面解析，
⛔ 表现为"WASD 方向与画面方向不一致"，
⛔ 而这种"操作别扭"不会被报成 bug，只会被说成"这游戏操作怪"。

ⓘ 还有一处最容易漏：
⛔ 抓边与蹬墙跳里若写死了 `Vector3.UP`，
改重力后它们会**静默失效**（表现为永远抓不到边），
⛔ 因为射线方向本身仍然正确，只是判据用了旧的常量。

【产出】上方向的三处同步点清单

【判据】改重力后，抓边、蹬墙跳、输入方向全部仍成立。

【审】``audit/godot/movement-advanced.md#14``

### Step 4　承载体必须是 AnimatableBody3D　`[movement-advanced/06#S4]`

【读】``howto/godot/movement-advanced.md#7. 移动平台承载：AnimatableBody3D 与三个平台参数``

【做】
场景里所有会动的承载体（电梯、飞船、吊车、闸门）都用 **AnimatableBody3D**。
⛔ 不要用 `StaticBody3D` ——
官方：AnimatableBody3D 被移动时会**估算线速度与角速度**
并用来影响路径上的其他物理体，StaticBody3D 不做这个估算，
⛔ 表现为"人站着不动、平台从脚下抽走"，
⛔ 而平台的移动代码、角色的站立代码**都完全正常**，两边都查不出问题。

ⓘ 用 AnimationPlayer 驱动时还要两处配合：
⛔ `sync_to_physics` 为 true（默认）才与物理帧同步，
⛔ 且官方明确**不要**与 `PhysicsBody3D.move_and_collide()` 同时使用。

【产出】承载体清单（含类型与驱动方式）

【判据】站在任意承载体上不动，角色与承载体相对位置不变。

【审】``audit/godot/movement-advanced.md#16``

### Step 5　platform_wall_layers 默认为 0　`[movement-advanced/06#S5]`

【读】``howto/godot/movement-advanced.md#7. 移动平台承载：AnimatableBody3D 与三个平台参数``

【做】
需要"贴着侧面被带走"的平台（电梯井、上升气流墙），
显式开启 `platform_wall_layers` 对应的层。
⛔ 不要以为配了 `platform_floor_layers` 就都覆盖了 ——
官方：**`platform_wall_layers` 默认 0，所有墙体一律忽略**，
而 `platform_floor_layers` 默认 4294967295（全开），
⛔ 两个默认值**恰好相反**，
⛔ 表现为"水平平台能带人、垂直平台不能"，
⛔ 而检查配置时"全是默认值、没动过"看起来最没问题。

【产出】两个平台层掩码的取值与理由

【判据】垂直承载体上的角色被稳定带走。

【审】``audit/godot/movement-advanced.md#19``

### Step 6　离开平台的速度继承要选定　`[movement-advanced/06#S6]`

【读】``howto/godot/movement-advanced.md#7. 移动平台承载：AnimatableBody3D 与三个平台参数``

【做】
显式选定 `platform_on_leave` 并写明理由。
官方三种：默认 `ADD_VELOCITY` 把平台最后速度加进 velocity；
`ADD_UPWARD_VELOCITY` **忽略向下运动** ——
官方注明它"即使平台向下移动也能保持完整跳跃高度"；
`DO_NOTHING` 什么都不做。
⛔ 不选定就用默认，
⛔ 表现为"从下行电梯上起跳，跳跃高度变矮"，
⛔ 而跳跃初速度的代码一行没改，排查不会去看继承行为。

【产出】`platform_on_leave` 取值 + 理由

【判据】从下行承载体起跳，跳跃高度与地面起跳一致。

【审】``audit/godot/movement-advanced.md#20``

### Step 7　斜坡吸附：floor_* 四件套按序实测　`[movement-advanced/06#S7]`

【读】``howto/godot/movement-advanced.md#8. 斜坡与吸附：floor_* 四件套``

【做】
按 `floor_max_angle` → `floor_snap_length` → `floor_constant_speed`
→ `safe_margin` 的顺序实测，并记录改前快照。
⛔ 不要把 `floor_constant_speed` 单独打开就当匀速 ——
官方原话：为 true 时**仍需 `floor_snap_length`** 才能在下坡上恒速贴合，
⛔ 只开前者，下坡会脱离地面再"抖"回去，
⛔ 表现为"开了匀速反而抖"，于是被当成这个开关有 bug 而关掉。

ⓘ `floor_max_angle` 官方默认 **45°**：
⛔ 一味调大它来"修好走不上斜坡"，会把陡壁也判成地板，角色开始爬墙。

【产出】四件套实测值 + 改前快照

【判据】上下坡速度稳定、无抖动，陡壁仍不可走。

【审】``audit/godot/movement-advanced.md#25``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const FLOOR_SNAP_LEN := 0.1      # floor_snap_length（06 参数表登记）
const UP_LERP_SEC := 0.25        # 上方向切换插值时长（06 参数表登记）
const CARRY_LAYER := 1 << 5      # 承载体所在层

var _target_up := Vector3.UP
var _up_lerp_t := 0.0

func set_up_direction(next: Vector3) -> void:
    # ⛔ 不能是零向量：它是区分地板/墙/天花板的依据
    assert(not next.is_zero_approx())
    _target_up = next.normalized()
    _up_lerp_t = 0.0

func tick_up_lerp(delta: float) -> void:
    if _up_lerp_t >= UP_LERP_SEC:
        return
    _up_lerp_t = minf(_up_lerp_t + delta, UP_LERP_SEC)
    up_direction = up_direction.slerp(_target_up, delta / UP_LERP_SEC).normalized()

func configure_carry() -> void:
    floor_snap_length = FLOOR_SNAP_LEN
    platform_floor_layers = CARRY_LAYER
    # ⛔ 默认 0 = 所有墙体一律忽略，垂直承载体必须显式开
    platform_wall_layers = CARRY_LAYER
    # 离开下行平台仍保持完整跳跃高度
    platform_on_leave = CharacterBody3D.PLATFORM_ON_LEAVE_ADD_UPWARD_VELOCITY
```
