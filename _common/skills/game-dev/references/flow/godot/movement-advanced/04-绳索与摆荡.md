# 04 绳索与摆荡（进阶移动域）

> **本步交付**：挂载/解挂是显式状态 + 助力模型可调 + 锚点跟随不丢人
> **对应**：流程 `howto/godot/movement-advanced.md` · 审核 `audit/godot/movement-advanced.md`

## 0. 交付物定义

1. 挂载 / 解挂是**状态机里的显式状态**，不是一段临时逻辑
2. 摆荡给了**助力**，不是纯物理
3. 特效与手感读的是**实际速度**
4. 锚点在移动物体上时，该物体是 **AnimatableBody3D**
5. 解挂时的速度继承行为已选定并写明

## 1. 前置检查清单

- [ ] 01 的状态机已包含 ROPE 态
- [ ] 挂载点可枚举（不是运行时随便找一个点）
- [ ] 助力系数已登记进参数表
- [ ] 可移动锚点的物理体类型已确认
- [ ] `platform_on_leave` 的取值已选定并写明理由

## 2. 工序

### Step 1　挂载与解挂是状态，不是临时逻辑　`[movement-advanced/04#S1]`

【读】``howto/godot/movement-advanced.md#0. 状态机是地基``

【做】
把挂载、摆荡中、解挂落成**状态机里的显式状态**，写明谁能打断。
⛔ 不要在 `_physics_process` 里用 `if rope_attached:` 就地分叉 ——
那样"摆荡中被抓边""摆荡中入水"都变成未定义行为，
⛔ 表现为"摆荡时抓了一下墙，人就卡在半空"，
⛔ 而不管是绳索逻辑还是抓边逻辑，单独看都执行完了自己的部分。

【产出】ROPE 相关状态的进入 / 退出 / 可打断关系

【判据】摆荡中触发抓边 / 入水，都有确定去向，不卡死。

【审】``audit/godot/movement-advanced.md#1``

### Step 2　摆荡要给助力，纯物理很难玩　`[movement-advanced/04#S2]`

【读】``howto/godot/movement-advanced.md#3. 绳索 / 摆荡``

【做】
在物理积分之上加一层**助力**（`SWING_ASSIST`），
在摆荡的最低点附近给沿切线方向的额外加速度。
⛔ 不要指望纯 pin joint 自己就好玩 ——
纯物理的能量守恒会让摆幅**只由入绳速度决定**，
玩家按键几乎没有即时反馈，
⛔ 表现为"操作了但感觉不到自己在操作"，
⛔ 而这种"手感不对"永远不会被判成 bug，只会被说成"这游戏不好玩"。

【产出】助力模型（含作用区间与系数）

【判据】在摆荡最低点按键，半秒内速度有明显变化。

【审】``audit/godot/movement-advanced.md#7``

### Step 3　摆荡特效与音效读实际速度　`[movement-advanced/04#S3]`

【读】``howto/godot/movement-advanced.md#8. 斜坡与吸附：floor_* 四件套``

【做】
风声、拖尾、镜头拉伸按 `get_real_velocity()` 对齐，不按 `velocity`。
⛔ 不要用 `velocity` —— 官方明确 `velocity` 是**请求速度**，
实际位移要读 `get_real_velocity()`；
⛔ 摆荡是强约束运动，请求与实际差异最大，
⛔ 表现为"速度值看起来很大但画面很慢"，而数值面板上一切正常。

【产出】特效速度来源统一为实际速度

【判据】拖尾长度与实际位移速率单调对应。

【审】``audit/godot/movement-advanced.md#24``

### Step 4　可移动锚点必须是 AnimatableBody3D　`[movement-advanced/04#S4]`

【读】``howto/godot/movement-advanced.md#7. 移动平台承载：AnimatableBody3D 与三个平台参数``

【做】
绳索锚点若挂在会动的物体上（吊车、飞船、电梯），
该物体必须是 **AnimatableBody3D**。
⛔ 不要用 `StaticBody3D` ——
官方：只有 AnimatableBody3D 被移动时会**估算线速度与角速度**
并影响路径上的其他物理体；
⛔ StaticBody3D 不做这个估算，
表现为"锚点走了、人还在原地，然后被绳子猛地拽回去"，
⛔ 而绳子长度约束本身一直是满足的，所以排查不会去看锚点的类型。

【产出】可移动锚点的物理体类型清单

【判据】锚点以任意速度移动，角色与锚点的相对距离始终满足绳长约束。

【审】``audit/godot/movement-advanced.md#16``

### Step 5　解挂后的速度继承要显式选定　`[movement-advanced/04#S5]`

【读】``howto/godot/movement-advanced.md#7. 移动平台承载：AnimatableBody3D 与三个平台参数``

【做】
从移动锚点解挂时，显式选定 `platform_on_leave` 的取值并写明理由。
官方三种：默认 `ADD_VELOCITY` 会把平台最后速度加进 velocity；
`ADD_UPWARD_VELOCITY` **忽略向下运动**，
⛔ 官方注明它是"即使平台向下移动也能保持完整跳跃高度"的那一种。
⛔ 不解挂前想清楚，表现为"从下行吊车上跳下来跳跃高度变矮"，
⛔ 而跳跃初速度的代码一行没改，所以不会去查继承行为。

【产出】`platform_on_leave` 取值 + 理由

【判据】从下行锚点起跳，跳跃高度与地面起跳一致。

【审】``audit/godot/movement-advanced.md#20``


## 3. 参考实现

```gdscript
# ⓘ 本块内自足：常量在此声明，承接上文即可直接用
const SWING_ASSIST := 1.15       # 摆荡助力系数（04 参数表登记）
const ROPE_MAX_LEN := 12.0       # 绳索最大长度（米，04 参数表登记）
const ASSIST_BAND := 0.35        # 助力作用区间：最低点附近 ±该比例的摆幅

var _anchor: Node3D = null
var _rope_len := 0.0

func attach(anchor: Node3D) -> void:
    _anchor = anchor
    _rope_len = minf(global_position.distance_to(anchor.global_position), ROPE_MAX_LEN)

func apply_swing_assist(vel: Vector3) -> Vector3:
    var to_anchor := (_anchor.global_position - global_position).normalized()
    # 最低点附近（绳子接近竖直）给沿切线的助力
    var verticality := absf(to_anchor.dot(Vector3.DOWN))
    if verticality < 1.0 - ASSIST_BAND:
        return vel
    var tangent := Vector3(vel.x, 0.0, vel.z).normalized()
    return vel + tangent * SWING_ASSIST

func detach_velocity() -> Vector3:
    # ⛔ 从移动锚点脱离时，平台速度继承由 platform_on_leave 决定
    platform_on_leave = CharacterBody3D.PLATFORM_ON_LEAVE_ADD_UPWARD_VELOCITY
    return velocity
```

## 5. 常见返工

| 现象 | 返工到 |
|---|---|
| 摆荡中抓墙后卡在半空 | 返工 Step 1（挂载是临时分叉） |
| 操作了但感觉不到在操作 | 返工 Step 2（纯物理无助力） |
| 速度值很大但画面很慢 | 返工 Step 3（读了请求速度） |
| 锚点走了人被拽回去 | 返工 Step 4（锚点是 StaticBody3D） |
| 从下行锚点跳起来变矮 | 返工 Step 5（继承行为未选定） |
