# 07 资源与网络验收（资源与网络域）

> **本步交付**：导出包实测 + 弱网实测 + 失败路径实测 + 公网实测 + 故障注入
> **对应**：流程 `howto/godot/io-network.md` · 审核 `audit/godot/io-network.md`

## 0. 交付物定义

1. 运行时加载在**导出包**里验过（⛔ 编辑器通过不算）
2. 弱网 / 断网下行为符合预期
3. 失败与重试路径**真的执行过**
4. 公网与 NAT 环境验过
5. 故障注入用例全部有预期结果

## 2. 工序

### Step 1　在导出包里验运行时加载，⛔ 编辑器通过不代表出包通过　`[io-network/07#S1]`

【读】`howto/godot/io-network.md#1. 资源加载`

【做】
**导出后**再跑一遍运行时加载：动态资源、热更包、`user://` 读写。
⛔ 只在编辑器验 —— `editor/export/convert_text_resources_to_binary`
**默认 `true`**，会让 `load()` 读不到被转换的文件。
⛔ 表现为"编辑器完美、出包后全回退默认"，且不报"路径不存在"。

ⓘ 这条与 02/S1、04/S1 是同一类：
⛔ 三者的共同点是**只在开发机上验证过**。
所以本域的验收第一条就是"换环境"。

【产出】导出包验收记录（加载 / 读写 / 下载各一项）

【判据】导出包里动态加载、`user://` 读写全部成功。

【审】`audit/godot/io-network.md#38`、`audit/godot/io-network.md#10`

### Step 2　弱网与断网要实测，不是靠想象　`[io-network/07#S2]`

【读】`howto/godot/io-network.md#6. HTTP`

【做】
用限速工具（或断网）实测：超时是否触发、进度是否卡死、UI 是否有出口。
⛔ 只测正常网络 —— `timeout` 没设、重试没做这类问题**全部测不出来**，
⛔ 表现为"上线后弱网用户成片反馈转圈"。

ⓘ 判据不是"最终能成功"，是**"失败时玩家有路可走"**：
能取消、能重试、能离线继续玩。

【产出】弱网用例（限速 / 高丢包 / 断网）+ 各场景的 UI 表现

【判据】断网后玩家能退出加载界面，而不是永久等待。

【审】`audit/godot/io-network.md#22`、`audit/godot/io-network.md#40`

### Step 3　只测成功路径等于没测：失败分支必须跑过　`[io-network/07#S3]`

【读】`howto/godot/io-network.md#3. HTTP 请求`

【做】
逐个执行失败分支：请求超时、重定向超限、响应体超限、
下载目录不存在、文件被截断。
⛔ 只测成功 —— 这些分支在开发环境**几乎不触发**，
⛔ 故障期间一触发就是成片，而没有一个人见过它们长什么样。

ⓘ 与 `ops` / `monetization` 域同源的原则：
⛔ **区间内所有失败必须走同一条路径**，
被分成两个分支的那条（超期 / 兜底）天然得不到验证。

【产出】失败分支用例表（用例 → 预期结果 → 实际结果）

【判据】每个失败分支都有一次实际执行记录。

【审】`audit/godot/io-network.md#40`、`audit/godot/io-network.md#29`

### Step 4　公网与 NAT 实测，⛔ 局域网通过不算通过　`[io-network/07#S4]`

【读】`howto/godot/io-network.md#建立连接`

【做】
在不同网络（跨运营商 / 移动网络 / 有 NAT）实测连接。
⛔ 只在局域网测 —— 端口、NAT、防火墙问题**全部漏掉**，
⛔ 表现为"内网能连、玩家连不上"，而服务端日志一切正常。

【产出】跨网络连通性记录（含失败时的错误码）

【判据】至少两种不同网络环境下能连通。

【审】`audit/godot/io-network.md#39`、`audit/godot/io-network.md#32`

### Step 5　故障注入：把每个静默失败都逼出来一次　`[io-network/07#S5]`

【读】`howto/godot/io-network.md#7. 落盘`

【做】
构造本域所有的"静默失败"：相对路径加载、header 带 Accept-Encoding、
`download_file` 目录未建、`get_var` 不可信来源、跨线程取错误码。
⛔ 逐个确认它们**会被发现** —— 这些失败的共同点是**不报错**，
⛔ 所以"没出问题"从来不是证据，只有"故意造出来能被抓到"才是。

ⓘ 这条是本域的收口：
前四个功能点每一条 ⛔ 都对应一个"不报错的错"，
⛔ 而它们全部只在特定环境才出现。

【产出】故障注入清单（注入方式 → 是否被发现 → 靠什么发现）

【判据】每一项注入都被日志或断言抓到。

【审】`audit/godot/io-network.md#19`、`audit/godot/io-network.md#20`、`audit/godot/io-network.md#23`、`audit/godot/io-network.md#28`、`audit/godot/io-network.md#38`

## 3. 验收清单

- [ ] 导出包里加载与读写成功
- [ ] 断网后玩家有退出路径
- [ ] 每个失败分支跑过一次
- [ ] 两种以上网络能连通
- [ ] 五项静默失败全部能被抓到

## 4. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 出包后动态加载失效 | 只在编辑器验过 | S1 |
| 上线后弱网成片转圈 | 没测弱网 | S2 |
| 故障期成片失败且无人见过 | 只测成功路径 | S3 |
| 内网能连玩家连不上 | 只在局域网测 | S4 |
| 静默失败一直潜伏 | 没做故障注入 | S5 |
