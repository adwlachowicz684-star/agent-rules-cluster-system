# 资源加载 / 文件读写 / HTTP / 联机基础 —— 域流程总览

> ⚠ **第 0 步：先定"哪些资源是共享的、谁能写哪个目录"。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 动态加载 / 加载界面 | 01 → 07 |
| 存档、配置、日志落盘 | 02 → 07 |
| 接后端接口（登录 / 配置 / 上报） | 03 → 07 |
| 资源包 / 大文件下载 | 04 → 07 |
| 联机：连得上、能发消息 | 05 → 07 |
| 联机：同步与生成 | 05 → 06 → 07 |
| 全套 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **01 不能跳过**（做动态加载时）——
资源缓存是**进程级共享**的，"改一个实例的材质"和"改所有实例的材质"
在代码上是同一行。⛔ 不先定共享契约，
就会写成"改一只怪，全场一起变"，而排查时每一处单看都对。

⛔ **05 不能跳过**（做联机时）——
`peer_id` 是连接序号，**不是玩家身份**。先写业务再用它当主键，
会在重连后串号到别人身上，⛔ 而本地单机测试永远正确。

⛔ **03 的 timeout 必须在接第一个接口之前设** ——
`HTTPRequest.timeout` 默认 `0.0` 的含义是**永不超时**。
等到弱网才发现"一直转圈"，那时所有调用点都写完了。

ⓘ 若本次只是"加一个图标资源、配一张表"，那是资源配置，不套本域。
ⓘ 若只是"排查某个请求没发出去"，先看 03 的 S4（`ERR_BUSY`），再回本域。

ⓘ 分工：
- `howto/godot/io-network.md` 讲**各要素的技术做法**（load/CacheMode/FileAccess/HTTP/ENet）
- `howto/godot/netsync-advanced.md` 讲**同步的进阶机制**（预测、回滚、插值）
- 本域讲**按什么顺序做、换平台换导出后还成立**

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 资源加载与缓存契约 | — | 共享清单 + 绝对路径公约 + CacheMode 选型 |
| 02 | 文件读写与落盘边界 | — | 路径边界 + 原子写 + 反序列化禁令 |
| 03 | HTTP 客户端与失败语义 | — | timeout/header/限流口径 + 三类结果判据 |
| 04 | 下载、断点与磁盘落盘 | 02 | 目录预建 + 校验 + 续传记录 |
| 05 | 联机基础：连接与权威边界 | — | 权威清单 + 稳定身份 + 错误码处理 |
| 06 | 联机基础：同步与生成 | 05 | replication 配置 + 生成契约 + 上限口径 |
| 07 | 资源与网络验收 | 全部 | 导出包实测 + 弱网/公网实测 + 故障注入 |

⚠ **01 要在第一个动态资源加载之前**：那时共享与独立的边界还没被写死，
改契约意味着每个加载点挨个回看。

⚠ **02 要在第一个存档功能之前**：路径边界错了，
表现是"编辑器里能存能读、出包后静默失败"，
⛔ 而这个阶段的现象会被归因为"打包配置问题"。

⚠ **05 要在第一个 RPC 之前**：权威边界补写时会顺手把客户端预测也划进权威，
表现为"手感变钝"，⛔ 而没人敢改回去。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是单个接口，是接缝。**

| 接缝 | 契约 |
|---|---|
| `netsync` 域 网络同步 | 预测回滚与插值见 `netsync`，⛔ 本域只到"连上、能同步"，不定义同步质量 |
| `save` 域 存档 | 存档结构与迁移见 `save`，⛔ 本域只定**写到哪、怎么写不半截** |
| `hotupdate` 域 热更新 | 包加载与 `CACHE_MODE_REPLACE` 见 `hotupdate`，⛔ 本域只定缓存契约本身 |
| `security` 域 安全 | 存档加密与请求签名见 `security`，⛔ 本域不定义加密方案 |
| `compliance` 域 合规 | 数据保留期限与同意状态见 `compliance`，⛔ 本域不定义保留多久 |
| `ops` 域 运营服务端 | 配置下发与重试口径见 `ops`，⛔ 本域只定客户端侧失败语义 |
| `platform-export` 域 导出 | 各平台导出预设见 `platform-export`，⛔ 本域只定"导出后仍成立"的判据 |
| `analytics` 域 埋点 | 上报队列与离线缓存见 `analytics`，⛔ 本域只定 HTTP 通道本身 |
| `cosmetic` 域 外观 | 外观资产的加载与取走语义见 `cosmetic`，⛔ 本域不重复展开 |

## 3. 参数登记

| 参数 | 所在功能点 | 初始值 | 实测值 | 状态 |
|---|---|---|---|---|
| `HTTP_TIMEOUT` 请求超时（秒） | 03 | — | — | 待实测（官方建议小 REST 10–30） |
| `BODY_SIZE_LIMIT` 响应体上限（字节） | 03 | — | — | 待实测（默认 -1 无限制，⛔ 不可留默认） |
| `DOWNLOAD_CHUNK` 下载分块（字节） | 04 | 65536 | — | 待实测（小文件可降到 4096） |
| `MAX_REDIRECTS` 重定向上限 | 04 | 8 | — | 待实测（官方默认 8） |
| `RETRY_MAX` 重试次数 | 03 | — | — | 待实测（⛔ 与退避策略一起定，不单独填） |
| `MAX_CONCURRENT_LOADS` 同时进行的线程加载数 | 01 | — | — | 待实测（与 CPU 核数和帧预算相关） |
| `DOWNLOAD_DIR` 下载落盘根目录 | 04 | `user://dl/` | — | 待实测（⛔ 必须预先建目录） |

⛔ 上表"待实测"项**不得凭行业惯例填** ——
填错不会报错，只会表现为"偶发转圈""偶发下载失败""偶发串号"，
⛔ 而这类偶发在开发环境几乎不出现。
