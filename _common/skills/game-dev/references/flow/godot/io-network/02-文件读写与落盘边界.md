# 02 文件读写与落盘边界（资源与网络域）

> **本步交付**：路径边界 + 判空与跨线程错误 + 原子写 + 反序列化禁令
> **对应**：流程 `howto/godot/io-network.md` · 审核 `audit/godot/io-network.md`

## 0. 交付物定义

1. 所有可写路径都在 `user://` 下，`res://` 只写只读
2. `FileAccess.open()` 的返回值**判空**，且错误读取在同线程
3. 落盘是**原子写**（临时文件 + rename）
4. 反序列化来源已分级，⛔ 不可信来源不走 `get_var()`
5. 目录预建与配额检查已就位

## 1. 前置检查清单

- [ ] 没有向 `res://` 写入的调用点
- [ ] 每个 `open()` 之后都判了 null
- [ ] 写盘走临时文件 + rename
- [ ] 反序列化的数据来源已标注可信 / 不可信
- [ ] 写目录前建了目录

## 2. 工序

### Step 1　路径边界：res:// 只读，且这是"导出后"才成立的条件　`[io-network/02#S1]`

【读】`howto/godot/io-network.md#2. 文件读写`

【做】
把所有写入路径收敛到 `user://`，`res://` 只用于读。
⛔ 写 `res://` —— 编辑器里**完全正常**，导出后才静默失败，
⛔ 表现为"开发期能存档、出包后存不上"，而排查被引向打包配置。

ⓘ 这条的难点在于**它在开发期是对的**：
PCK 未打包时 `res://` 就是磁盘目录，确实可写。
⛔ 所以"我试过能写"不构成证据。

【产出】路径边界清单（只读路径 / 可写路径 / 各自的读写权限）

【判据】在**导出包**里执行一次写-读-删，全部成功。

【审】`audit/godot/io-network.md#4`

### Step 2　open 返回 null 必须判，get_open_error 只反映当前线程　`[io-network/02#S2]`

【读】`howto/godot/io-network.md#2. 文件读写`

【做】
每次 `open()` 判 null，并**在同一个线程里**立刻取 `get_open_error()`。
官方：*"Returns the result of the last `open` call in the current thread"*。
⛔ 后台线程 open 失败、主线程再读错误码 —— 拿到的是**主线程自己**那次的结果
（很可能还是 OK），⛔ 于是错误被擦掉，日志里一切正常。

ⓘ 这与"不判 null 直接写会崩"是两类失败：
崩是**响亮**的，跨线程擦错误是**安静**的 —— 它会让失败彻底消失。

【产出】统一的文件访问封装（判空 + 同线程取错 + 日志）

【判据】故意给一个不可写路径，日志能打出真实错误码。

【审】`audit/godot/io-network.md#2`、`audit/godot/io-network.md#20`

### Step 3　原子写：不能让断电留下半截文件　`[io-network/02#S3]`

【读】`howto/godot/io-network.md#2. 文件读写`

【做】
写盘一律走"写临时文件 → 关闭 → rename 覆盖"。
⛔ 直接打开目标文件写 —— 写到一半崩了，
下次读到的就是**半截文件**，⛔ 而它格式合法到能通过大部分校验。

ⓘ 这条与存档域的"先写后换"是同一条规则（见 `save` 域）；
⛔ 本域额外要求：**临时文件与目标文件同目录**，否则跨分区 rename 会失败。

【产出】原子写函数 + 临时文件命名与清理规则

【判据】在写入中途强杀进程，下次启动读到的是上一份完整数据。

【审】`audit/godot/io-network.md#18`

### Step 4　⛔ 反序列化不可信来源等于执行别人的代码　`[io-network/02#S4]`

【读】`howto/godot/io-network.md#7. 落盘`

【做】
把反序列化来源分级：本机自己写的存档=可信，下载的、玩家上传的、
多人房间里交换的=⛔ **不可信**，一律走 JSON / 自定义格式，**不用 `get_var()`**。
官方 Warning 原话：*"Deserialized objects can contain code which gets executed...
potential security threats such as remote code execution."*
⛔ 图省事统一用 `get_var()` —— 功能完全正常、测试全绿，
⛔ 只在有人构造恶意数据时触发，而那时已经是任意代码执行。

ⓘ 这与"配置热更"最容易撞上：
配置是下载的，于是它同时是"要解析的数据"和"不可信来源"。

【产出】数据来源分级表（来源 → 允许的格式 → 禁用 API）

【判据】不可信来源的解析路径里搜不到 `get_var`。

【审】`audit/godot/io-network.md#19`

### Step 5　目录与配额：目录不会自动建，Web 有配额　`[io-network/02#S5]`

【读】`howto/godot/io-network.md#7. 落盘`

【做】
写入前用 `DirAccess.make_dir_recursive()` 建目录，并检查目标平台配额。
⛔ 假设目录已存在 —— 编辑器里目录早被手工建过，**一直正常**，
导出到干净环境后必然失败（同 S1 的开发期假象）。

ⓘ Web 平台 `user://` 落在浏览器存储里，**有配额且可能被清理**，
⛔ 所以"写成功"不等于"一直能读到"，关键数据要有云端兜底。

【产出】目录初始化流程 + 各平台配额说明 + 失败降级路径

【判据】删掉整个 `user://` 目录后启动，能自动重建并正常工作。

【审】`audit/godot/io-network.md#21`、`audit/godot/io-network.md#3`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：原子写 + 同线程判空 + 目录预建
# ⓘ 常量出处：WRITE / READ 为 FileAccess.ModeFlags 内置枚举值
const FLAG_WRITE := FileAccess.WRITE
const FLAG_READ := FileAccess.READ

static func ensure_dir(path: String) -> bool:
    if not DirAccess.dir_exists_absolute(path):
        var err := DirAccess.make_dir_recursive_absolute(path)
        if err != OK:
            push_error("建目录失败: %s (%d)" % [path, err])
            return false
    return true

static func write_atomic(path: String, text: String) -> bool:
    if not ensure_dir(path.get_base_dir()):
        return false
    var tmp := path + ".tmp"          # ⛔ 同目录，否则跨分区 rename 失败
    var f := FileAccess.open(tmp, FLAG_WRITE)
    if f == null:
        # ⛔ 必须在同一线程内立刻取，跨线程会读到别的结果
        push_error("打开失败: %d" % FileAccess.get_open_error())
        return false
    f.store_string(text)
    f.close()                          # ⛔ 不关 = 句柄泄漏
    var err := DirAccess.rename_absolute(tmp, path)
    if err != OK:
        push_error("rename 失败: %d" % err)
        return false
    return true
```

ⓘ 反序列化：本机存档可用 `get_var`，⛔ 下载 / 上传 / 房间交换的数据一律走 `JSON`。

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 开发期能存、出包存不上 | 写了 `res://` | S1 |
| 失败但日志一切正常 | 跨线程读错误码 | S2 |
| 偶发读到半截数据 | 非原子写 | S3 |
| 解析外部数据后行为异常 | `get_var` 执行了别人的代码 | S4 |
| 换机器/清空后首次启动失败 | 目录没预建 | S5 |
