# 01 资源加载与缓存契约（资源与网络域）

> **本步交付**：共享清单 + 绝对路径公约 + CacheMode 选型 + 线程加载取舍
> **对应**：流程 `howto/godot/io-network.md` · 审核 `audit/godot/io-network.md`

## 0. 交付物定义

1. 已明确哪些资源**共享**、哪些**必须独立**
2. 所有 `load()` 传的是**绝对路径**
3. CacheMode 三选一的口径已写下（不是"默认就行"）
4. `use_sub_threads` 的取舍已按场景定，⛔ 不是统一开
5. "取走即移除"与"没有取消 API"已写进加载器契约

## 1. 前置检查清单

- [ ] 能指着任意资源说出它是共享还是独立
- [ ] 没有 `load("相对路径")` 的调用点
- [ ] CacheMode 的选型理由写下来了
- [ ] 线程加载的参数不是默认照抄
- [ ] 加载器对"重复取同一个路径"有定义

## 2. 工序

### Step 1　先定共享边界：改一行代码影响几份资源　`[io-network/01#S1]`

【读】`howto/godot/io-network.md#缓存语义`

【做】
列出本次用到的资源，**逐项标注共享 / 独立**。同路径 `load()` 返回**同一个对象**，
改它等于改所有引用处。
⛔ 先写业务再补边界 —— 表现是"改一只怪的材质，全场一起变"，
而排查被引向"材质实例没做对"，⛔ 因为每个加载点单看都对。

ⓘ 这条与 3D 共享材质是同一个坑（见 `shaders` 域），
⛔ 区别在于运行时 `load()` 出来的资源**没有任何面板提示**，只能靠清单。

【产出】资源清单（每项标注共享 / 独立 + 独立化方式）

【判据】改任意一个"独立"资源，其他实例在画面上不变。

【审】`audit/godot/io-network.md#9`、`audit/godot/io-network.md#11`

### Step 2　路径必须绝对：相对路径会被偷偷加上前缀　`[io-network/01#S2]`

【读】`howto/godot/io-network.md#1. 资源加载`

【做】
所有 `load()` / `preload()` 传**绝对路径**（`res://` 或 `user://` 开头）。
官方 Note：*"Relative paths will be prefixed with `res://` before loading"*。
⛔ 传 `"user://foo.tres"` 之外的相对路径 —— 实际打到 `res://` 下，
拿到**空资源**，只打印一句"文件未找到"，⛔ 不抛异常、不中断。

ⓘ 这条与"循环 preload 会报错"是两类失败：
preload 是**响亮**的（解析期崩），相对路径是**安静**的（拿到空对象继续跑）。

【产出】路径公约（含拼接规则）+ 加载失败时的显式判空

【判据】全局搜不到以非 `res://` / `user://` 开头的加载路径。

【审】`audit/godot/io-network.md#10`

### Step 3　CacheMode 三选一是契约，不是性能调优　`[io-network/01#S3]`

【读】`howto/godot/io-network.md#CacheMode`

【做】
按用途**显式**指定 `CACHE_MODE_REUSE` / `REPLACE` / `IGNORE` 三选一：
普通资源 REUSE、热更替换 REPLACE、一次性大图 IGNORE。
⛔ 全部用默认 REUSE —— 热更时拿到**旧缓存**，
表现为"资源明明换了，游戏里还是旧的"，⛔ 而版本号、路径、文件都对。

ⓘ 反向也成立：一次性大图用 REUSE 会**常驻内存**，
表现为"内存越玩越高"，排查被引向泄漏，实际是缓存策略。

【产出】CacheMode 选型表（资源类别 → 模式 → 理由）

【判据】替换一个资源文件后，游戏里显示的是新版本。

【审】`audit/godot/io-network.md#17`

### Step 4　use_sub_threads 是取舍：加载更快 vs 画面不卡　`[io-network/01#S4]`

【读】`howto/godot/io-network.md#5. 线程加载`

【做】
按场景定 `use_sub_threads`：后台预加载取 `false`（把 CPU 留给主线程），
过场黑屏等"不需要画面流畅"的时刻才考虑 `true`。
官方原话：*"makes loading faster, but may affect the main thread
(and thus cause game slowdowns)"*。
⛔ 统一改成 `true` 追求更快 —— **加载画面自己开始卡**，
表现为"进度条走得很慢"，⛔ 排查必然被引向磁盘 IO 或资源体积。

ⓘ 这与"用了线程加载就不会卡"是相反的两句话：
线程加载解决的是**不阻塞**，不解决**不抢 CPU**。

【产出】线程加载参数表（场景 → use_sub_threads → 理由）

【判据】加载界面全程帧率平稳（⛔ 不是"加载总时长最短"）。

【审】`audit/godot/io-network.md#12`

### Step 5　取走即移除，且没有取消：加载器契约要写死　`[io-network/01#S5]`

【读】`howto/godot/io-network.md#线程加载（大资源不卡主线程）`

【做】
在加载器里明确三条：① `load_threaded_get()` **取走后任务即被移除**，
第二次取返回 INVALID；② 未完成时调用会**阻塞调用线程**；
③ ⛔ **官方没有取消 API**，"取消"只能做成"丢弃结果 + 令牌校验"。
⛔ 多人等同一份资源时各取一次 —— 第一个人正常、后面的人全失败，
日志写的是"资源无效"，⛔ 排查被引向资源路径或导出设置。

ⓘ status 要在**不同帧**查询（官方建议放 `_process`），
⛔ 用循环轮询等于把主线程占满等结果。

【产出】加载器契约文档（含一次性语义、阻塞语义、"取消"的真实实现）

【判据】两人同时请求同一资源，两人都拿到；请求中途放弃不产生副作用。

【审】`audit/godot/io-network.md#15`、`audit/godot/io-network.md#13`、`audit/godot/io-network.md#14`、`audit/godot/io-network.md#16`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：绝对路径 + 显式 CacheMode + 单线程后台加载
# ⓘ 常量出处：CACHE_REPLACE 为引擎内置枚举值
const MODE_REPLACE := ResourceLoader.CACHE_MODE_REPLACE
const MODE_IGNORE := ResourceLoader.CACHE_MODE_IGNORE

var _pending: Dictionary = {}   # path -> {"token": int}

func request(path: String, token: int, replace := false) -> void:
    # ⛔ path 必须是绝对路径：相对路径会被静默加上 res:// 前缀
    var mode := MODE_REPLACE if replace else ResourceLoader.CACHE_MODE_REUSE
    # ⛔ use_sub_threads 取 false：加载期间要让主线程继续出画面
    var err := ResourceLoader.load_threaded_request(path, "", false, mode)
    if err != OK:
        push_error("加载请求失败: %d" % err)
        return
    _pending[path] = {"token": token}

func poll(path: String) -> Resource:
    var st := ResourceLoader.load_threaded_get_status(path)
    if st != ResourceLoader.THREAD_LOAD_LOADED:
        return null                     # ⛔ 未完成就 get 会阻塞调用线程
    _pending.erase(path)
    return ResourceLoader.load_threaded_get(path)   # ⛔ 取走即移除，只能取一次
```
