# 04 下载、断点与磁盘落盘（资源与网络域）

> **本步交付**：目录预建 + 大文件落盘 + 完成校验 + 续传记录 + 取消语义
> **对应**：流程 `howto/godot/io-network.md` · 审核 `audit/godot/io-network.md`

## 0. 交付物定义

1. 下载目标的**目录预先建好**
2. 大文件走 `download_file` 直写盘，分块已设
3. 下载完成有**大小与校验和**双重校验
4. 断点续传记录了已下载字节
5. `cancel_request()` 之后状态机归位（⛔ 不是"自动回滚"）

## 1. 前置检查清单

- [ ] 下载目录在请求前已 `make_dir_recursive`
- [ ] 大文件没有走 `get_string_from_utf8()`
- [ ] 完成回调里校验了大小与校验和
- [ ] 续传的已下载字节有持久化
- [ ] 取消后 UI 与状态机一致

## 2. 工序

### Step 1　目录要先建：download_file 不会自动建目录　`[io-network/04#S1]`

【读】`howto/godot/io-network.md#7. 落盘`

【做】
请求前用 `DirAccess.make_dir_recursive()` 建好目标目录。
官方原话：*"Folders are not automatically created... it's recommended to
create the necessary folders beforehand"* → `RESULT_DOWNLOAD_FILE_CANT_OPEN = 10`。
⛔ 假设目录在 —— 编辑器里目录早就手工建过，**一直正常**，
⛔ 导出到干净环境后必然失败，而 URL、权限、磁盘空间全部检查通过。

ⓘ 这与 02/S1 是同一类"开发期假象"：
⛔ 在开发机上验证过，证明不了在用户机器上也成立。

【产出】下载目录初始化流程（含失败降级）

【判据】删掉下载目录后重新下载，成功。

【审】`audit/godot/io-network.md#28`

### Step 2　大文件直写盘，分块按大小调　`[io-network/04#S2]`

【读】`howto/godot/io-network.md#下载文件`

【做】
设 `download_file` 直写盘；`download_chunk_size` 按文件大小调
（官方：小文件可降到 4096 降低内存占用，代价是速度）。
⛔ 全读进内存 —— 大文件一次吃掉几百 MB，
⛔ 表现为"下到一半闪退"，排查被引向内存泄漏。

【产出】下载封装（大 → `download_file`；小 → 内存，分块已调）

【判据】下载 500MB 文件期间内存平稳。

【审】`audit/godot/io-network.md#7`

### Step 3　下载完成必须校验：大小 + 校验和　`[io-network/04#S3]`

【读】`howto/godot/io-network.md#下载文件`

【做】
完成回调里校验：① 实际文件大小 == 清单里的大小 ② 校验和匹配。
⛔ 只看 `RESULT_SUCCESS` —— **传输成功不等于文件完整**，
中断、代理截断、CDN 异常都会给出"成功"的半截文件。
⛔ 表现为"资源偶尔损坏"，排查被引向磁盘或解压库。

ⓘ 校验和要**由服务端下发**（见 `security` 域签名口径），
⛔ 客户端自己算自己验等于没验。

【产出】校验流程（大小 → 校验和 → 通过才改状态）

【判据】人为截断一个文件，被校验拦下而不是被当成完整资源使用。

【审】`audit/godot/io-network.md#29`

### Step 4　断点续传要记录已下载字节　`[io-network/04#S4]`

【读】`howto/godot/io-network.md#下载文件`

【做】
把已下载字节数持久化（与 `get_downloaded_bytes()` 对照），重连后从断点续。
⛔ 每次从头 —— 弱网环境下**永远下不完**，
⛔ 表现为"进度条到 90% 又回零"，玩家只会认为网络差。

ⓘ 续传的前提是**服务端支持 Range**，
⛔ 客户端单方面实现而服务端不支持，会得到 200 全量而非 206 部分内容。

【产出】续传记录结构（URL / 总大小 / 已下载 / 校验和）+ 恢复流程

【判据】下载到一半断网，恢复后从断点继续而不是从头。

【审】`audit/godot/io-network.md#30`

### Step 5　取消不是回滚：cancel_request 后状态机要归位　`[io-network/04#S5]`

【读】`howto/godot/io-network.md#取消`

【做】
`cancel_request()` 之后显式清理：删除半截临时文件、状态机回到可发起态。
⛔ 只调取消 —— 半截文件留在磁盘上，
⛔ 下次续传时把它当成"已下载部分"，得到**拼接错误的产物**，且不报错。

ⓘ 这与 01/S5 的"没有取消 API"呼应：
⛔ 取消是**客户端概念**，服务端/磁盘侧的状态要自己收尾。

【产出】取消处理函数（取消 → 清临时 → 状态归位）

【判据】取消后立刻重新下载，产物与首次下载一致。

【审】`audit/godot/io-network.md#30`、`audit/godot/io-network.md#18`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：目录预建 + 直写盘 + 校验 + 续传记录
# ⓘ 常量出处：CHUNK_BIG / CHUNK_SMALL 由参数表登记（官方默认 65536）
const CHUNK_BIG := 65536
const CHUNK_SMALL := 4096

func start(url: String, save_to: String, expect_size: int, expect_sum: String) -> void:
    # ⛔ 必须先建目录：download_file 不会自动建（RESULT_DOWNLOAD_FILE_CANT_OPEN）
    DirAccess.make_dir_recursive_absolute(save_to.get_base_dir())
    _http.download_file = save_to
    _http.download_chunk_size = CHUNK_BIG if expect_size > 1048576 else CHUNK_SMALL
    _expect_size = expect_size
    _expect_sum = expect_sum
    _http.request(url)

func _on_done(result: int, code: int, _h: PackedStringArray, _b: PackedByteArray) -> void:
    if result == HTTPRequest.RESULT_DOWNLOAD_FILE_CANT_OPEN:
        push_error("下载目录不存在或不可写")
        return
    if result != HTTPRequest.RESULT_SUCCESS:
        _cleanup_half()
        return
    # ⛔ RESULT_SUCCESS 不等于文件完整：必须校验大小与校验和
    if FileAccess.get_size(_path) != _expect_size or _sha(_path) != _expect_sum:
        _cleanup_half()
        return
    _mark_complete()
```

## 4. 验收清单

- [ ] 删目录后能重新下载成功
- [ ] 大文件下载期间内存平稳
- [ ] 截断的文件被校验拦下
- [ ] 断网恢复后从断点继续
- [ ] 取消后重下产物一致

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 导出后下载必失败，开发期正常 | 目录没预建 | S1 |
| 下到一半闪退 | 全读进内存 | S2 |
| 资源偶尔损坏 | 只看 RESULT_SUCCESS | S3 |
| 进度到 90% 又回零 | 没做续传 | S4 |
| 续传后产物错误 | 取消没清半截文件 | S5 |
