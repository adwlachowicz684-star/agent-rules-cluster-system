# 06 局部天气与区域（weather 域）

> **前置**：`04-天气状态机.md`
> **本步交付**：**区域天气可仲裁，室内/洞穴已屏蔽**
> **对应**：做法 `howto/godot/environment-systems.md#11. 局部天气与区域`
> 　　　审核 `audit/godot/environment-systems.md#24`

## 0. 交付物定义

⚠ **本步最容易"看起来做完了"：全局一份天气能切就行。**

⛔ 常见假完成：只有全局天气——
⚠ 户外没问题，
⛔ 但室内/洞穴照样下雨，表现为**屋顶漏雨**，
这是最容易被玩家截图传播的一类穿帮。

做完这一步，应该能**当场演示**：

1. ⛔ 室内/洞穴**屏蔽**天气
2. ⚠ 多区域重叠有**仲裁**（不是各写各的）
3. ⛔ 区域切换**插值**，不硬切
4. ⚠ 进出区域边界天气平滑
5. ⛔ 区域状态变化时清理残留粒子

**产出物**（下游按名字对接）：

```text
WeatherZone: priority, weather
房间内屏蔽标记（indoor）
```

## 2. 工序

### Step 1　⛔ 室内与洞穴必须屏蔽天气　`[weather/06#S1]`

【读】`howto/godot/environment-systems.md#11. 局部天气与区域`

【做】给区域打 `indoor` 标记，进室内停用雨雪。

⛔ 不屏蔽 → **屋顶漏雨**，
⚠ 玩家会当成穿模 bug 反馈，且极易截图传播。

【产出】`indoor` 标记与屏蔽逻辑

【判据】⚠ 室内**看不到**雨雪粒子

【审】`audit/godot/environment-systems.md#24`

### Step 2　⛔ 区域重叠要按优先级仲裁　`[weather/06#S2]`

【读】`howto/godot/environment-systems.md#11. 局部天气与区域`

【做】重叠时按 `priority` 取一个生效。

⛔ 各写各的 → 天气**来回抖**，
表现为"站在边界上雨雪不停闪"，且不报错。

【产出】仲裁规则

【判据】⚠ 站在重叠区天气**稳定**

【审】`audit/godot/environment-systems.md#25`

### Step 3　⛔ 区域切换要插值，不能硬切　`[weather/06#S3]`

【读】`howto/godot/environment-systems.md#3. 天气`

【做】进出区域走 04 的过渡机制。

⛔ 直接换 → 玩家走过边界时天气**硬切**，
⚠ 观感廉价，常被判为"完成度不够"。

【产出】边界过渡

【判据】⚠ 走过边界天气**平滑**变化

【审】`audit/godot/environment-systems.md#12`

### Step 4　⚠ 进出区域要清理残留粒子　`[weather/06#S4]`

【读】`howto/godot/environment-systems.md#9. 天气状态机：过渡是一次事务，不是直接插值`

【做】离开区域时确保旧天气粒子停掉。

⛔ 只改状态不清理 → 离开雨区后**雨还在下**，
与 04 的"不取消旧过渡"是同一类残留。

【产出】清理逻辑

【判据】⚠ 离开区域后旧天气粒子**已停**

【审】`audit/godot/environment-systems.md#38`

### Step 5　⚠ 区域状态变化要走同一条权威链　`[weather/06#S5]`

【读】`howto/godot/environment-systems.md#12. 多人同步：时间必须只有一个权威`

【做】联机时区域天气也由权威端决定。

⛔ 客户端本地随机区域天气 → **各人看到不同的雨**，
⚠ 且无法复现，排查时两端描述对不上。

【产出】区域天气同步

【判据】⚠ 两个客户端在同一区域看到**相同**天气

【审】`audit/godot/environment-systems.md#27`

## 5. 常见返工

**① 室内不屏蔽。** 屋顶漏雨。

**② 重叠各写各的。** 边界抖动。

**③ 硬切。** 观感廉价。

**④ 不清理。** 离开还在下。
