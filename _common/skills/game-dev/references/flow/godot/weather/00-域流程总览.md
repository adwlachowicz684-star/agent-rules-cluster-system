# 天气 / 昼夜循环 —— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只要一个会转的太阳 | **不要套本域** → 见下 |
| 昼夜会推进、能存档恢复 | 01 → 02 → 07 |
| 昼夜 + 天空/雾联动 | 01 → 02 → 03 → 07 |
| 有天气（雨/雪）且会切换 | 01 → 04 → 07 |
| 天气影响驾驶/AI/玩法 | 01 → 04 → 05 → 07 |
| 不同区域不同天气 | 01 → 04 → 06 → 07 |
| 多人联机 | 01 → 02 → 04 → 07 |
| 全套 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **固定时间、不推进的项目不要套本域。**
⚠ 那属于 `howto/godot/environment-systems.md#1. 天空：三种材质，取舍明确`
与 `lighting.md` 的范围——本域处理的是**会推进、要同步、要存档**的复杂度。

ⓘ 分工：
- `howto/godot/environment-systems.md` 讲**单个要素怎么配**（水/天空/雾/天气/湿滑）
- 本域讲**这些要素按什么顺序做、怎么管状态**

⛔ 若本域某步需要"Gerstner 波怎么算"这类细节，
指向那篇，**不在这里重复**。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 时间源与时钟推进 | — | 单调时钟 + 暂停冻结 + 存档恢复 |
| 02 | 昼夜驱动与光照联动 | 01 | 一个太阳角驱动一切 |
| 03 | 天空与雾的联动 | 02 | 天空/雾/曝光同一节拍更新 |
| 04 | 天气状态机 | 01 | 当前/目标/进度三态 + 可中断过渡 |
| 05 | 天气与玩法联动 | 04 | 湿滑驱动摩擦 + 状态进存档 |
| 06 | 局部天气与区域 | 04 | 区域仲裁 + 室内屏蔽 |
| 07 | 天气昼夜验收 | 全部 | 改时间/暂停/打断/读档/同步实测 |

⚠ **01 必须在一切之前**：时钟不成权威，02 的驱动源和 04 的过渡都无从计时。
⚠ **04 必须在 05 之前**：没有天气状态，玩法联动没有可订阅的对象。
⚠ **04 必须在 06 之前**：区域仲裁裁的是天气状态，不是直接改粒子。

## 2. 与其他域的接缝

| 接缝 | 契约 |
|---|---|
| `vip` 域 时间源 | 同受 `Time` 官方禁令约束，可复用同一套时钟工具 |
| `vehicle` 域 载具 | 湿滑改 `friction_slip`，见 05 |
| `ai` 域 感知 | 雨天视距缩短要接感知，见 05 |
| `save` 域 存档 | 存游戏内累计秒数，不存派生角度 |
| `netsync` 域 同步 | 时间单一权威，见 01/04 |
| `vegetation` 域 植被 | 风强度由天气驱动，见 05 |
| `level` 域 关卡 | 室内/洞穴要屏蔽天气，见 06 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**。

## 3. 本域最容易做反的顺序

⛔ **先做天气表现（04）再做时钟（01）。**

雨和雪是最直观的"天气"需求，
于是先撒粒子、先调材质，
⚠ 而此时时钟还是各写各的 →
**读档后天气对不上、联机各人看到的雨不一样**，
⛔ 且不报错，只在联机和读档时才暴露。

✅ 正确顺序：先立单调时钟与权威源（01），再让天气走状态机（04）。
