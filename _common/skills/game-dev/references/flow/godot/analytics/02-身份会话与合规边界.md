# 02 身份会话与合规边界（分析域）

> **本步交付**：可重置 player_id + 同意开关 + 同意前零采集
> **对应**：流程 `howto/godot/analytics.md` · 审核 `audit/godot/analytics.md`

## 0. 交付物定义

1. `player_id` 是可重置、可匿名的自建标识，⛔ 与设备硬件无关
2. 玩家同意之前，**零采集**（不只是"不上报"）
3. 玩家可关闭非必要分析，且关闭后立即生效
4. `session_id` 由会话层下发，⛔ 不用 peer ID 顶替
5. 有删除与保留期限策略

## 1. 前置检查清单

- [ ] 已确定 `player_id` 的生成与持久化位置
- [ ] ⚠ 已有同意开关，且采集入口全部经过它
- [ ] 已确认关闭分析后哪些必要项仍保留（崩溃、法律必要）
- [ ] 已确认 `session_id` 的来源

## 2. 工序

### Step 1　⛔ player_id 不能用设备 ID　`[analytics/02#S1]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
`OS.get_unique_id()` 是**设备唯一标识符**，属个人数据；
且官方注明它**可被外部程序伪造**（不得用于安全目的），
重装系统或换硬件后**还会变**。
⛔ 拿它当 `player_id` ——三重问题同时成立：合规风险、可被伪造、重装即断。
自建一个匿名随机 ID 持久化在 `user://`，并提供重置入口。

【产出】自建匿名 `player_id` + 持久化 + 重置入口

【判据】重置后是一个全新 ID，且清掉本地 ID 后能重新生成（不崩）。

【审】`audit/godot/analytics.md#3`

### Step 2　⛔ 同意前必须零采集，不是"不上报"　`[analytics/02#S2]`

【读】`howto/godot/analytics.md#1.5 ⚠ 同意前零采集（合规边界）`

【做】
在玩家同意之前，**连采集都不发生**——不是"先采集到本地、同意后再上报"。
⛔ 写成"先入队、同意后再 flush"——本地已经存了未同意期间的行为数据，
这本身就是采集，且同意开关形同虚设（队列里已有数据，flush 与否只是时机问题）。
采集入口必须**唯一**且经过同意状态判断。

【产出】唯一采集入口 + 同意状态门禁（未同意时直接 return）

【判据】未同意状态下调用 `track()`，内存中队列长度保持为 0。

【审】`audit/godot/analytics.md#16`

### Step 3　玩家能关闭非必要分析　`[analytics/02#S3]`

【读】`howto/godot/analytics.md#3. 后端方案`

【做】
设置项里提供关闭开关，关闭后非必要采集立即停止；
崩溃与法律必要项另走策略（不计入"分析"开关）。
⛔ 只有开没有关，或关了只是不显示——数据仍在采集，⛔ 属于违规。

【产出】分析开关（开 / 关）+ 关闭后立即停止采集

【判据】关闭后调用 `track()`，无任何网络请求、队列不增长。

【审】`audit/godot/analytics.md#17`

### Step 4　session_id 由会话层下发　`[analytics/02#S4]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
`session_id` 标识"这一次游玩"，由会话层在启动时生成并贯穿全程。
⛔ 用 `multiplayer.get_unique_id()` 当会话键——那是连接号，
每次重连都变，一次游玩会被切成多个"会话"，留存与时长全错。

【产出】会话启动时生成 `session_id` + 生命周期绑定到游玩过程

【判据】断线重连后 `session_id` 不变；主动重开一局才变。

【审】`audit/godot/analytics.md#18`

### Step 5　有删除与保留策略　`[analytics/02#S5]`

【读】`howto/godot/analytics.md#3. 后端方案`

【做】
明确数据保留期限与删除机制（玩家可请求删除其数据）。
⛔ 只管采不管删——保留期限由运营与法务按最小必要原则定，
⛔ 本域不许编一个天数出来（各地法规未给出游戏埋点的统一期限）。

【产出】保留期限策略（指向 `compliance` 域）+ 删除入口

【判据】能指出保留期限由谁定、删除请求走哪条路径。

【审】`audit/godot/analytics.md#35`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：可重置匿名 ID + 同意门禁
const PLAYER_ID_PATH := "user://player_id"

func track(event: String, params := {}) -> void:
    if not _consent_granted:      # ⛔ 同意前零采集，不是"先入队、同意后再 flush"
        return
    _enqueue(event, params)

func reset_player_id() -> void:   # ⛔ 必须提供重置入口，否则无法匿名
    DirAccess.remove_absolute(PLAYER_ID_PATH)
    _player_id = "anon_" + _new_id()
```

## 4. 验收清单

- [ ] `player_id` 非设备 ID，且提供重置入口
- [ ] 未同意时调用 `track()`，队列长度恒为 0
- [ ] 关闭分析后无任何网络请求、队列不增长
- [ ] `session_id` 在断线重连后不变

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 未同意也采到了数据 | 写成先入队、同意后再 flush | S2 |
| 换设备后玩家断了 | 用了设备 ID | S1 |
| 关了分析数据仍在采 | 只是不显示 | S3 |
