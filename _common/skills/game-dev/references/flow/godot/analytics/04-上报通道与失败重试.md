# 04 上报通道与失败重试（分析域）

> **本步交付**：批量 + 幂等 + 退避重试 + 超时
> **对应**：流程 `howto/godot/analytics.md` · 审核 `audit/godot/analytics.md`

## 0. 交付物定义

1. 批量上报，⛔ 不每条事件一个请求
2. `HTTPRequest.timeout` **显式设置**，⛔ 不留默认 `0.0`
3. 上报幂等：同一 `event_id` 重复到达只计一次
4. 重试有退避与上限，且失败**不丢弃**队列
5. `HTTPRequest` 进场景树，且单实例不并发

## 1. 前置检查清单

- [ ] 已确定批量条数与上报间隔
- [ ] ⚠ 已显式设置 HTTP 超时（非 0）
- [ ] 已确定服务端去重的键（`event_id`）
- [ ] 已确定重试策略（退避 + 上限）
- [ ] ⚠ 已确认 `HTTPRequest` 已 `add_child`

## 2. 工序

### Step 1　批量上报，不每条一个请求　`[analytics/04#S1]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
攒够 `BATCH_SIZE` 或到达 `FLUSH_INTERVAL_SEC` 才发一次，body 里放事件数组。
⛔ 每条事件发一个 HTTP —— 卡顿又费电，
移动端还会因频繁唤醒射频加剧耗电，表现为"玩久了手机发烫"。

【产出】批量上报函数 + 触发条件（条数 / 时间）

【判据】连打 100 次 `track()`，网络请求数远小于 100。

【审】`audit/godot/analytics.md#4`

### Step 2　⛔ `timeout` 默认 `0.0` 的含义是永不超时　`[analytics/04#S2]`

【读】`howto/godot/analytics.md#2.2 ⚠ HTTPRequest 的两条官方语义（超时与并发）`

【做】
官方文档：`timeout` 为 `0.0` 时**请求永不超时**；
对 REST 这类小请求建议设成与服务端响应匹配的秒数（常见 1.0–10.0）。
⛔ 留默认 `0.0` 且又用 `_http.get_http_client_status() != STATUS_DISCONNECTED` 做守卫——
服务端不响应时状态永远不是 `DISCONNECTED`，
于是 flush 永远直接 return，⛔ **队列无限增长、缓存文件越写越大，且不报错**。
ⓘ 这是两个"默认值"叠加出来的故障：单独看每个都合理。

【产出】显式 `timeout` + 请求挂起时的兜底（超时后按失败处理并重试）

【判据】把服务端改成永不响应，观察队列在超时后进入重试而非无限增长。

【审】`audit/godot/analytics.md#26`

### Step 3　上报必须幂等　`[analytics/04#S3]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
每条事件带 `event_id`，服务端按它去重。
⛔ 只靠客户端"收到 200 就清空队列"——
响应在回程丢失时客户端以为失败、服务端其实已入库，
重试一次就**重复计数一次**；付费类事件重复计数会直接毁掉对账。

【产出】`event_id` 唯一键 + 服务端去重

【判据】同一批事件连续上报两次，服务端总量不变。

【审】`audit/godot/analytics.md#28`

### Step 4　重试要有退避与上限，失败不丢队列　`[analytics/04#S4]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
失败时**保留队列**并落盘，按 `RETRY_BACKOFF_BASE_SEC` 指数退避，
超过 `MAX_RETRY` 才放弃。
⛔ 失败立即清空队列——弱网下数据成片丢失；
⛔ 无退避地立即重试——服务端抖动时会自行放大为雪崩。

【产出】退避重试状态机 + 最终失败的处理（丢弃计数 + 告警）

【判据】断网期间打点，恢复网络后数据补传且不重复。

【审】`audit/godot/analytics.md#29`

### Step 5　`HTTPRequest` 必须进场景树，且单实例不并发　`[analytics/04#S5]`

【读】`howto/godot/analytics.md#2.2 ⚠ HTTPRequest 的两条官方语义（超时与并发）`

【做】
`HTTPRequest.new()` 之后必须 `add_child(_http)`，否则发不出请求。
⛔ 单个 `HTTPRequest` 实例发起并发请求——后一个会取消前一个，
表现为"数据丢一半"，⛔ 且不报错。
需要并发就为每个请求建独立实例（用完 `queue_free`）。

【产出】`add_child` 后的请求实例 + 单实例串行（或每请求独立实例）

【判据】连续两次 flush 间隔小于单次往返时间，两条数据都到达。

【审】`audit/godot/analytics.md#7`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：批量 + 显式超时
const BATCH_SIZE := 20              # 待实测：按单条平均体积与弱网表现定
const FLUSH_INTERVAL_SEC := 30.0    # 待实测
const HTTP_TIMEOUT_SEC := 10.0      # ⛔ 绝不能留默认 0.0（含义是永不超时）

func _ready() -> void:
    _http = HTTPRequest.new()
    add_child(_http)                # ⚠ 不 add_child 发不出请求
    _http.timeout = HTTP_TIMEOUT_SEC
```

- [ ] 同一批重复上报两次，服务端总量不变

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 队列越攒越多发不出去 | `timeout` 留了默认 `0.0` | S2 |
| 数据丢一半 | 单实例并发，后一个取消前一个 | S5 |
| 付费后台数字翻倍 | 重试不幂等 | S3 |
