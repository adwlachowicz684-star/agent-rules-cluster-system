# 03 采集与离线缓存（分析域）

> **本步交付**：本地队列 + 持久化 + 退出保存 + 上限
> **对应**：流程 `howto/godot/analytics.md` · 审核 `audit/godot/analytics.md`

## 0. 交付物定义

1. 事件先进本地队列，⛔ 不在 `_process` 里即时发网络请求
2. 队列**持久化**，强杀进程后仍在
3. 退出路径**全部**覆盖（窗口关闭 / 安卓返回 / 自己的退出按钮）
4. 缓存有上限，且写入是原子的
5. 高频事件节流或采样

## 1. 前置检查清单

- [ ] 已确定队列持久化路径（`user://`）
- [ ] ⚠ 已确认**所有**退出路径都会触发保存
- [ ] 已确定缓存条数上限
- [ ] 已确定高频事件的采样率

## 2. 工序

### Step 1　队列必须持久化，不能只在内存　`[analytics/03#S1]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
游戏与 Web 不同：玩家会断网、切后台、**强杀进程**。
队列既要存在于内存，也要落盘；启动时先 `_load_cache()` 恢复。
⛔ 只在内存里攒队列——强杀进程时全部丢失，
且这类丢失**没有任何报错**，只表现为"数据比预期少"。

【产出】内存队列 + 落盘缓存 + 启动时恢复

【判据】攒够一批后强杀进程，重启后队列条数一致。

【审】`audit/godot/analytics.md#19`

### Step 2　⛔ `SceneTree.quit()` 不发送退出通知　`[analytics/03#S2]`

【读】`howto/godot/analytics.md#2.1 ⛔ 退出通知的三条官方语义（退出保存）`

【做】
官方明确：调用 `SceneTree.quit()` **不会**发送 `NOTIFICATION_WM_CLOSE_REQUEST`，
且"不会让自定义动作完成（如保存）"，**即使你尝试延迟那行强制退出的代码也不行**。
所以监听 `_notification` 是不够的——游戏里"退出游戏"按钮调的正是 `get_tree().quit()`，
⛔ 通知根本不来，未上报队列全部丢失且**无任何报错**。
正确做法是退出前**自己**发通知：
`get_tree().root.propagate_notification(NOTIFICATION_WM_CLOSE_REQUEST)`，
⛔ 然后**再**调 `SceneTree.quit()` —— 4.x 中该通知**不会终止程序**（与 3.x 不同），
只发通知不调 `quit()` 会导致"点了退出关不掉"。

【产出】退出按钮序列：propagate 通知 → 保存 → `SceneTree.quit()`

【判据】点游戏内"退出游戏"按钮，缓存文件里能看到未上报的队列。

【审】`audit/godot/analytics.md#22`

### Step 3　⛔ 安卓是 `NOTIFICATION_WM_GO_BACK_REQUEST`　`[analytics/03#S3]`

【读】`howto/godot/analytics.md#2.1 ⛔ 退出通知的三条官方语义（退出保存）`

【做】
官方：桌面与 Web 平台发 `NOTIFICATION_WM_CLOSE_REQUEST`；
⛔ **安卓发的是 `NOTIFICATION_WM_GO_BACK_REQUEST`**，
且 iOS **不支持**该通知（无物理返回键）。
同时默认 Godot 收到退出请求会**自行退出**，
要接管完整退出流程必须先 `get_tree().set_auto_accept_quit(false)`。
⛔ 只监听 `WM_CLOSE_REQUEST` —— 安卓上保存**一次都不触发**，
而桌面测试全是绿的，于是"安卓数据少"会被误判成网络问题。

【产出】`set_auto_accept_quit(false)` + 同时处理两个通知常量

【判据】安卓按返回键退出，缓存文件被写入。

【审】`audit/godot/analytics.md#23`

### Step 4　缓存要有上限，且写入是原子的　`[analytics/03#S4]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
设 `MAX_CACHED_EVENTS` 上限，超出丢弃最旧的（并计数上报丢弃量）。
写入用**临时文件 + 重命名**，不用直接覆盖。
⛔ 无上限——弱网时缓存文件无限增长，最终打满磁盘配额，
表现为"游戏越玩越卡"甚至存档失败（与埋点看似无关）。
⛔ 直接覆盖写——写一半崩掉会留下半截 JSON，
下次启动 `JSON.parse_string()` 返回 `null`，**整份缓存当作空**丢弃，
⛔ 且解析失败与"队列真的为空"无法区分（都不报错）。

【产出】条数上限 + 原子写（临时文件 + 重命名）+ 丢弃计数

【判据】人为把缓存写到一半中断，重启后仍能读出上一份完整缓存。

【审】`audit/godot/analytics.md#20`

### Step 5　高频事件要节流或采样　`[analytics/03#S5]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
性能采样、输入等高频事件必须采样或聚合后再入队。
⛔ 在 `_process` 里随手 `track()` —— 高频事件会拖垮帧率，
并让队列瞬间撑爆上限，把真正的业务事件挤出缓存。

【产出】采样率配置 + 高频事件聚合后再入队

【判据】开启性能采样后帧率无明显下降，且队列不因此触顶。

【审】`audit/godot/analytics.md#8`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：退出通知的三条官方语义
# ⓘ NOTIFICATION_WM_CLOSE_REQUEST / NOTIFICATION_WM_GO_BACK_REQUEST 为引擎内置常量

func _ready() -> void:
    get_tree().set_auto_accept_quit(false)   # ⛔ 不接管则 Godot 自行退出

func _notification(what: int) -> void:
    if what == NOTIFICATION_WM_CLOSE_REQUEST or what == NOTIFICATION_WM_GO_BACK_REQUEST:
        _save_cache()
        get_tree().quit()                    # ⛔ 4.x 中通知不终止程序，必须自己调

func quit_game() -> void:                    # 游戏内"退出游戏"按钮
    # ⛔ SceneTree.quit() 不发送通知，必须自己 propagate
    get_tree().root.propagate_notification(NOTIFICATION_WM_CLOSE_REQUEST)
```

## 4. 验收清单

- [ ] 强杀进程后队列可恢复
- [ ] 点"退出游戏"按钮会保存（⛔ 与强杀是两条路径）
- [ ] 安卓返回键退出会保存
- [ ] 缓存有上限，且写入是原子的（临时文件 + 重命名）

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 点退出后数据丢了 | `SceneTree.quit()` 不发通知 | S2 |
| 安卓数据比桌面少 | 只监听了 `WM_CLOSE_REQUEST` | S3 |
| 数据无故少一批 | 半截缓存被当空丢弃 | S4 |
