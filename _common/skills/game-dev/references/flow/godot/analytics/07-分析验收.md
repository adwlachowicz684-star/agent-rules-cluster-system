# 07 分析验收（分析域）

> **本步交付**：敌意环境下数据不丢、不重、可比
> **对应**：流程 `howto/godot/analytics.md` · 审核 `audit/godot/analytics.md`

## 0. 交付物定义

分析域的 bug **在正常流程下几乎全部测不出来** ——
只在**改系统时间、强杀进程、断网、缓存损坏、跨版本**时才出现。
所以本步验收的不是"能看到数据了"，而是这五件事发生后数据还对得上。

⛔ **联网跑一遍全部通过，是最危险的假通过。**

## 2. 工序

### Step 1　改系统时间后事件 ID 不碰撞、时序不倒流　`[analytics/07#S1]`

【读】`howto/godot/analytics.md#1.4 ⛔ 事件时间与 ID 不能用系统时钟`

【做】
把设备系统时间改到一年前、一年后各跑一遍完整流程，
检查事件 ID 是否碰撞、`client_ts` 是否倒流、漏斗步骤是否乱序。
⛔ 只在正常时间下测——改时间是玩家能做的事，
而由此产生的 ID 碰撞会让服务端去重**误删真实数据**，⛔ 且不报错。

【产出】改时间实测记录（两个极端各一份）

【判据】两个极端下事件 ID 无碰撞，按 `client_ts` 排序后步骤顺序与操作顺序一致。

【审】`audit/godot/analytics.md#13`

### Step 2　⛔ 强杀进程后队列不丢，含"退出游戏"按钮路径　`[analytics/07#S2]`

【读】`howto/godot/analytics.md#2.1 ⛔ 退出通知的三条官方语义（退出保存）`

【做】
两条路径**分别**测：① 直接强杀进程；② 点游戏内"退出游戏"按钮。
⛔ 只测强杀——按钮路径调的是 `SceneTree.quit()`，
官方明确它**不发送退出通知**，于是这条路径下的保存一次都不会执行，
⛔ 而"点按钮退出"恰恰是玩家最常用的退出方式。

【产出】两条退出路径的缓存文件对比

【判据】两条路径下，退出前未上报的事件都出现在缓存文件中。

【审】`audit/godot/analytics.md#22`

### Step 3　安卓按返回键退出会保存　`[analytics/07#S3]`

【读】`howto/godot/analytics.md#2.1 ⛔ 退出通知的三条官方语义（退出保存）`

【做】
在安卓真机上按返回键退出，检查缓存是否被写入。
⛔ 只在桌面测——安卓发的是 `NOTIFICATION_WM_GO_BACK_REQUEST`，
只监听 `WM_CLOSE_REQUEST` 的实现在安卓上**一次都不触发**，
⛔ 而桌面测试全绿，于是"安卓数据少"会被长期误判成网络或机型问题。

【产出】安卓返回键退出的缓存写入记录

【判据】安卓返回键退出后，缓存文件条数大于 0（打了点的前提下）。

【审】`audit/godot/analytics.md#23`

### Step 4　断网补传后不重复计数　`[analytics/07#S4]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
断网期间持续打点，恢复网络后观察补传结果，
并**故意**让响应在回程丢失（模拟客户端以为失败、服务端已入库）。
⛔ 只测"断网能补传"——重复计数发生在**响应丢失**这个更隐蔽的场景，
而它对付费类事件是致命的（后台数字凭空翻倍）。

【产出】补传记录 + 响应丢失场景下的服务端总量

【判据】响应丢失后重试一次，服务端总量不变（按 `event_id` 去重生效）。

【审】`audit/godot/analytics.md#28`

### Step 5　缓存损坏后不整份丢弃　`[analytics/07#S5]`

【读】`howto/godot/analytics.md#2. 实现：离线优先`

【做】
人为把缓存文件截断到一半，重启后检查恢复情况。
⛔ 不测这一项——真实崩溃确实会留下半截文件，
而 `JSON.parse_string()` 失败返回 `null` 与"队列为空"无法区分，
于是整份缓存被当作空静默丢弃，⛔ 表现为"数据无故少了一批"。

【产出】损坏恢复记录（保留上一份完整缓存 or 明确计数丢弃）

【判据】截断后重启，仍能读出上一份完整缓存（或明确上报了丢弃条数）。

【审】`audit/godot/analytics.md#21`

### Step 6　跨版本数据可比　`[analytics/07#S6]`

【读】`howto/godot/analytics.md#1. 事件模型：这是接口契约，不是自由文本`

【做】
用旧版本包产生一批数据，用新版本包产生一批，
核对事件名、枚举取值、`app.version` 三者是否仍可汇总。
⛔ 只测当前版本——事件名一旦变动，历史曲线断层，
⛔ 且断层在报表上表现为"数据突然变化"，极易被误读成玩家行为变了。

【产出】跨版本对比记录（事件名 / 枚举 / 版本号三项）

【判据】新旧两批数据按同一口径汇总，无因命名或枚举变动导致的口径断裂。

【审】`audit/godot/analytics.md#1`

## 3. 验收清单

- [ ] 改系统时间（一年前 / 一年后）各跑一遍，ID 无碰撞、时序不倒流
- [ ] 强杀进程与"退出游戏"按钮**两条路径**都会保存
- [ ] 安卓返回键退出会保存
- [ ] 断网补传成功，且响应丢失场景不重复计数
- [ ] 缓存半截损坏后不整份丢弃
- [ ] 跨版本（热更前后）数据仍可比
- [ ] ⛔ 关键事件（付费 / 通关）在强杀后仍到达服务端
- [ ] 未同意隐私政策时，队列长度恒为 0

## 4. 常见返工

| 现象 | 根因 | 回到 |
|---|---|---|
| "安卓数据比桌面少" | 只监听了 `WM_CLOSE_REQUEST` | 03/S3 |
| "点退出后数据丢了" | 用 `SceneTree.quit()` 退出，通知不来 | 03/S2 |
| "数据无故少一批" | 半截缓存被当空丢弃 | 03/S4 |
| "付费后台数字翻倍" | 重试不幂等 | 04/S3 |
| "队列越攒越多发不出去" | `timeout` 留了默认 `0.0` | 04/S2 |
| "改时间后漏斗乱了" | `client_ts` 用系统时钟 | 01/S4 |
