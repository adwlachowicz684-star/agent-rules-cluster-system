# 01 埋点契约与事件字典（分析域）

> **本步交付**：命名规范 + 不可变承诺 + 事件字典落文档
> **对应**：流程 `howto/godot/analytics.md` · 审核 `audit/godot/analytics.md`

## 0. 交付物定义

1. 事件名与字段构成**接口契约**，进生产后不可随意改
2. 命名采用两层结构（`object_action`），⛔ 不用三层
3. 通用载荷固定结构，且**必须带 `app.version`**
4. 事件时间与事件 ID **不依赖系统时钟**
5. 事件字典以文档形式落地，可查、可评审

## 1. 前置检查清单

- [ ] 已确定事件命名规范（两层，动词在后）
- [ ] 已确定通用载荷字段（`event_id` / `session_id` / `player_id` / `client_ts` / `app.version`）
- [ ] ⚠ 已确认事件字典有**唯一**的文档位置
- [ ] 已确认枚举值用稳定字符串，不用数字

## 2. 工序

### Step 1　事件模型是接口契约，不是自由文本　`[analytics/01#S1]`

【读】`howto/godot/analytics.md#1. 事件模型：这是接口契约，不是自由文本`

【做】
把事件名与字段当作**对外接口**对待：进生产后改名 = 历史数据不可比。
⛔ 把埋点当成"随手打日志"——上线三个月后发现 `level_start` 在两个模块里含义不同，
此时改名会让所有历史曲线断层，不改则永远分不清两个含义。

【产出】一份事件契约说明：事件名 = 契约，变更须走评审

【判据】指着任一事件名，能说出它的确切含义与唯一触发位置。

【审】`audit/godot/analytics.md#1`

### Step 2　命名用两层，不用三层　`[analytics/01#S2]`

【读】`howto/godot/analytics.md#命名规范（可直接抄）`

【做】
采用 `object_action` 两层结构（如 `level_start`、`item_purchase`）。
⛔ 用三层（`game_level_start_btn`）——会变成同义事件泛滥：
同一件事在不同模块里起了三个名字，任何汇总都要写三份分支。

【产出】命名规范表 + 已有事件名的自查清单

【判据】随机抽 10 个事件名，没有两个表达同一件事。

【审】`audit/godot/analytics.md#2`

### Step 3　通用载荷要固定，且必须带版本号　`[analytics/01#S3]`

【读】`howto/godot/analytics.md#通用载荷（固定结构）`

【做】
固定结构包含 `event_id` / `session_id` / `player_id` / `client_ts` / `app` / `params`，
其中 `app.version` 取自 `ProjectSettings.get_setting("application/config/version")`。
⛔ 不带版本号——热更前后数据混在一起，一次热更导致的指标变化会被误读成"玩家行为变了"。

【产出】通用载荷结构体 + 版本号注入点

【判据】任一条上报数据里都能读出 `app.version`，且与当前包版本一致。

【审】`audit/godot/analytics.md#37`

### Step 4　⛔ 事件时间与 ID 不能用系统时钟　`[analytics/01#S4]`

【读】`howto/godot/analytics.md#1.4 ⛔ 事件时间与 ID 不能用系统时钟`

【做】
官方口径：`Time` 的 `_from_system` 系列用的是**用户可手动设置**的时钟，
明确要求"绝不要用于精确时间计算"，应改用单调的 `get_ticks_usec/msec`。
⛔ 用 `Time.get_unix_time_from_system()` 拼事件 ID、用 `get_datetime_string_from_system()` 当 `client_ts` ——
玩家改系统时间会造成：事件 ID 碰撞（服务端去重**误判重复而丢弃真实数据**）、
时间戳倒流（漏斗步骤乱序、留存算错），且**两种都不报错**。
⚠ 注意 `get_ticks_msec()` 是引擎启动以来的毫秒数，**不是日期**——
绝对时间仍须由服务端下发后与 ticks 插值对齐。

【产出】事件 ID 生成（单调源 + 随机）+ `client_ts` 校时机制

【判据】把系统时间改到一年前与一年后各跑一次，事件 ID 无碰撞、`client_ts` 不倒流。

【审】`audit/godot/analytics.md#13`

### Step 5　事件字典必须落文档　`[analytics/01#S5]`

【读】`howto/godot/analytics.md#常用事件清单`

【做】
事件字典写在**唯一**的文档里，含事件名、含义、触发时机、字段与取值域。
⛔ 字典散落在各模块注释里——新人加埋点时看不到已有事件，必然重复造一个同义名。

【产出】事件字典文档（唯一位置）

【判据】新增埋点前，能在这个文档里查到是否已有同义事件。

【审】`audit/godot/analytics.md#34`


## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：事件 ID 用单调时钟，载荷带 app.version
var APP_VERSION := ProjectSettings.get_setting("application/config/version", "")

func _new_event_id() -> String:
    # ⛔ 不用 Time.get_unix_time_from_system()：玩家改系统时间会造成 ID 碰撞
    return str(Time.get_ticks_usec()) + "_" + str(randi())
```

## 4. 验收清单

- [ ] 事件名与含义一一对应，无同义事件
- [ ] 通用载荷含 `app.version`，且与当前包版本一致
- [ ] 事件 ID 不依赖系统时钟（改时间后无碰撞）
- [ ] 事件字典有唯一文档位置，可查可评审
