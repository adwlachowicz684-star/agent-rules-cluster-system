# Godot 4.x 本地化技术实现

**本文件只放技术实现**（怎么接、怎么切、怎么打包）。
翻译流程、文案管理、术语表、QA 流程 → 见独立 skill `localization`（当前为占位，待填充）。

## 1. 引擎侧机制

### 核心 API

```gdscript
tr("KEY")                      # 翻译当前 locale 下的文本
tr_n("item", "items", count)   # 复数形式
TranslationServer.get_locale()          # 当前语言，如 "zh_CN"
TranslationServer.set_locale("en")      # 切换并全局生效
TranslationServer.get_loaded_locales()  # 已加载的语言列表
OS.get_locale()                         # 系统语言（启动时自动应用）
OS.get_locale_language()                # 只要语言部分，如 "zh"
```

⚠ `OS.get_locale()` 返回 `"zh_CN"` 这种**带地区**的格式，
而 TranslationServer 里可能只注册了 `"zh"`。启动时需要根据 loaded locales 做匹配。

### 设置与资源

1. 项目设置 → Localization → Translations → 添加 `.translation` 资源
2. 运行时加载：`TranslationServer.add_translation(res)`

**推荐用 CSV 工作流**：

```
keys,en,zh_CN,ja
GREETING,Hello,你好,こんにちは
ITEM_COUNT,"{n} item","{n} 个物品","{n} 個"
```

把 CSV 放进项目，Godot 会自动导入为 `.translation`（每个语言一个）。
改 CSV 后自动重新导入，不用手动重建资源。

⚠ CSV 第一列必须叫 `keys`，表头其它列是**语言代码**。

⚠ 翻译里 `{n}` 之类的占位符要在 `tr()` 之后手动替换，
引擎不会自动做格式化：

```gdscript
# 简单场景
label.text = tr("GREETING")

# 带变量
label.text = tr("ITEM_COUNT").replace("{n}", str(count))

# 复数用 tr_n（会按 locale 的复数规则选）
label.text = tr_n("item", "items", count) % count
```

## 2. 切换语言

```gdscript
# settings 里
func set_language(locale: String) -> void:
    TranslationServer.set_locale(locale)
    SaveManager.current.language = locale
    SaveManager.save_game()
```

⚠ `set_locale()` 会**立刻让所有 `tr()` 结果变化**，
但**已经赋值到 Label 上的文本不会自动更新** —— 需要：

```gdscript
# 方案一：切换后重载场景
func apply_language() -> void:
    get_tree().reload_current_scene()

# 方案二：所有 UI 在 _ready 里用 tr() 赋值，靠重载刷新（推荐）
# 方案三：集中一个 refresh_texts()，切换时遍历调用
```

**推荐方案二**：每个 UI 的 `_ready` 里统一 `label.text = tr("XXX")`，
切语言后 `reload_current_scene()`。最省心，也最不容易漏。

⚠ 不要在 `_process` 里调 `tr()` —— 每帧查表。只在需要时赋值。

## 3. 布局方向（RTL）

阿拉伯语、希伯来语等从右向左语言：

```gdscript
# 项目设置 gui/theme/... 或代码
control.layout_direction = Control.LAYOUT_DIRECTION_RTL
```

| 枚举 | 含义 |
|---|---|
| `LAYOUT_DIRECTION_INHERIT` | 继承父节点（默认） |
| `LAYOUT_DIRECTION_APPLICATION_LOCALE` | 跟随当前 locale |
| `LAYOUT_DIRECTION_LTR` | 强制左到右 |
| `LAYOUT_DIRECTION_RTL` | 强制右到左 |
| `LAYOUT_DIRECTION_LOCALE` | 跟随节点自己的 locale |

⚠ 用 `LAYOUT_DIRECTION_APPLICATION_LOCALE` 时，
容器（HBox/VBox）的子项顺序会**自动镜像**，但锚点不会 ——
UI 要用容器布局，别写死锚点像素。

## 4. 字体与缺字

多语言最常见的翻车点：中文在英文设备上显示成方块（豆腐块）。

```gdscript
# 给字体设置回退链
@export var main_font: Font
@export var cjk_font: Font

func _ready() -> void:
    main_font.fallbacks = [cjk_font]
```

⚠ `Font.fallbacks` 是 `Array[Font]`，按顺序回退。
应该设到 **Theme 的默认字体**上，全局生效：

```gdscript
func _ready() -> void:
    var theme := load("res://ui/theme.tres") as Theme
    var f := theme.default_font as Font
    f.fallbacks = [load("res://fonts/NotoSansSC.ttf")]
```

⚠ 字体文件体积：完整 CJK 字体 10MB+。大型项目要考虑**按需子集化**
或分语言包（不同 locale 加载不同字体）。

## 5. 文本溢出

不同语言长度差异很大（德语通常比英语长 30%+）。

```gdscript
# Label 开启自动换行
label.autowrap_mode = TextServer.AUTOWRAP_WORD_SMART
label.custom_minimum_size = Vector2(200, 0)   # 限宽，高度自适应
```

⚠ **不要给按钮设固定宽度**。用 `custom_minimum_size` 限最小，
让容器根据内容撑开。

⚠ 长文本要预留空间，或用 `TextServer` 的省略号模式。

## 6. 大型项目建议

如果你要做的是**大型项目**，这几件事早点做，后期改成本极高：

| 事项 | 建议 |
|---|---|
| **Key 命名规范** | 用 `模块.位置.含义`，如 `UI.MAIN.START_BTN`；不要用英文原文当 key（改文案时 key 要跟着改） |
| **只在入口 tr()** | 所有文本集中在一处（如 `Strings` 常量类或 UI 的 `_ready`），不要在逻辑里散落 `tr()` |
| **变量插值统一** | 统一用 `{n}` / `{name}` 格式，写个 helper，别各处手写 replace |
| **别翻译的东西** | 日志、存档 key、配置值、内部 ID —— 只翻译给玩家看的 |
| **伪翻译测试** | 早期用伪本地化（把所有文本前后加 `[XX]`）检查有没有漏翻和溢出 |
| **字体分语言包** | 大字体按 locale 动态加载，不全塞进首包 |

⚠ **存档里的文本不要存翻译后的结果**。存 key 或 ID，
否则切语言后旧存档显示的还是旧语言。

```gdscript
# 反例：存翻译结果
save.item_name = tr("ITEM_SWORD")

# 正例：存 ID，显示时才翻译
save.item_id = "sword"
# 显示时
label.text = tr("ITEM_%s" % save.item_id.to_upper())
```
