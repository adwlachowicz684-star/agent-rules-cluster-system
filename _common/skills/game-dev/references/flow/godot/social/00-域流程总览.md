# 多人社交（大厅 / 房间 / 匹配 / 好友 / 聊天）—— 域流程总览

> ⚠ **第 0 步：先定做什么。**
> 本域有 7 个功能点，⛔ **不是全做** —— 按本次需求挑。

## 0. 先定做什么

| 本次要做的 | 走哪些功能点 |
|---|---|
| 只要能开房、能进人 | 01 → 02 → 07 |
| 要按分数 / 地区撮合玩家 | 01 → 03 → 07 |
| 要世界 / 队伍 / 私聊频道 | 01 → 04 → 07 |
| 要好友、师徒、结拜、婚姻 | 01 → 05 → 07 |
| 要阵营、势力、声望、战报 | 01 → 06 → 07 |
| 全套社交 | 01 → 02 → 03 → 04 → 05 → 06 → 07 |

⛔ **只做房间、不做聊天与好友的项目，01 也不能跳过** ——
房间的"谁能改设置、房主走了怎么办"同样建立在身份地基上。

⚠ 若本次只是**"进房间之后的实时同步"**（位置、状态、预测回滚），
那是 `netsync` 域的事，⛔ 不要套本域——
本域管的是**玩家怎么找到彼此、怎么组织、怎么说话**，即**控制面**。

ⓘ 分工：
- `howto/godot/social.md` 讲**单个机制怎么实现**（三层架构、房主、匹配、聊天、阵营声望战报）
- 本域讲**这些机制按什么顺序做、怎么保证掉线后社交状态不丢、怎么不被刷**

⛔ 若本域某步需要"各地法规的具体保存期限"这类细节，
指向那篇，**不在这里重复**（库里没有的就是没有，⛔ 不许编一个天数出来）。

## 1. 功能点拆解（按依赖，不可颠倒）

| # | 功能点 | 依赖 | 交付物 |
|---|---|---|---|
| 01 | 身份与会话地基 | — | peer ID ≠ 玩家身份 + 控制面 / 数据面分离 |
| 02 | 房间与房主迁移事务 | 01 | owner 与 host 分离 + 可迁移 + 断线交接 |
| 03 | 匹配与排队 | 01 | 独立匹配分 + 等待超时 + 进房交接 |
| 04 | 聊天频道与扇出限流 | 01 | 频道 / 成员资格 / 扇出三者分离 + 服务端过滤 |
| 05 | 关系型社交与 UGC 审核 | 01 | 绑定 + 收益 + 解除代价 + 玩家名头像过审 |
| 06 | 阵营、势力与战报 | 01 | 有向非对称关系 + PvpContext 冻结 + 隐私分档 |
| 07 | 社交验收 | 全部 | 敌意环境实测 + 跨端一致 + 取证可回溯 |

⚠ **01 必须在一切之前**：没有独立于 peer ID 的玩家身份，
02 的房主迁移会迁到"一个已经不存在的连接"、
03 的匹配分会在重连后归零、
04 的聊天记录会挂在一次性的连接号上。

⚠ **06 依赖 01 的服务端权威**：阵营关系与战报若由客户端提交，
身份套利（开战前转阵营领奖）就是**可直接刷取的漏洞**。

## 2. 与其他域的接缝

> ⚠ **组合的真正难点不是排序，是接缝。**
> 下面每条都必须能指认到具体符号或字段，⛔ 不能是"做完了"。

| 接缝 | 契约 |
|---|---|
| `netsync` 域 实时同步 | 本域只到"进房间"，⛔ 不管位置与状态同步 |
| `security/02#S1` 域 输入校验 | 客户端申报不可信；检测到后静默标记不反馈，见 `security/06#S6`，01 / 06 |
| `combat` 域 战斗结算 | 阵营友伤走 `PvpContext`，⛔ 不在战斗层写 `if faction ==` |
| `economy` 域 货币 | 聊天道具 / 关系解除代价走同一本账，⛔ 不开第二套 |
| `trade` 域 交易 | 公会仓库与邮件的物品进出走同一账本 |
| `analytics` 域 埋点 | 匹配质量与刷屏治理效果即埋点源，见 03 / 04 |
| `save` 域 存档 | 好友列表、邮件、关系状态**存服务端**，见 01 / 05 |
| `compliance` 域 合规 | 未成年人见 `compliance/03`；UGC 审核与举报留痕见 `compliance/05#S4`；⛔ 本域不自行编造条款 |
| `hotupdate` 域 热更 | 战报重放必须用**旧配置版本**，见 06 |

⛔ **若某条接缝对不上，要单独立一个接线功能点**，
⛔ 不许在各处偷偷转格式（那些转换会散落多处，改接口时找不到）。

⚠ **各功能点自己的验收不能替代集成验收** ——
部件全合格、拼起来不能用，是跨域开发的典型失败。

## 3. 本域最容易做反的顺序

⛔ **先搭房间和聊天（02 / 04），后补身份地基（01）。**

"能开房、能说话"是最直观的验收点，
于是先把 ENet 连上、把世界频道跑通，
⚠ 而此时"玩家是谁"还是拿 peer ID 顶替的。

⛔ 后果链：
peer ID 当身份 → 重连后换了 id，好友与战绩全断 →
为修补它加一层映射 → 但房主仍是创建者 → 创建者退出房间设置锁死 →
再补丁把房主可迁移 → 而聊天已上线且**内容没留存** → 举报无法取证。

⚠ 这些补丁会让 01 再也没法正确落地——
因为到处都已经有了"以 peer ID 为键"的社交状态。

✅ 正确顺序：先钉死身份与会话（01），
再谈房间（02）、匹配（03）、聊天（04）。
