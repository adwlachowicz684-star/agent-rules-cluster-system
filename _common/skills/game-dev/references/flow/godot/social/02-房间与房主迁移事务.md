# 02 房间与房主迁移事务（社交域）

> **本步交付**：owner 与 host 分离且都可迁移 + 断线交接
> **对应**：流程 `howto/godot/social.md` · 审核 `audit/godot/social.md`

## 0. 交付物定义

1. `owner_id`（能改设置的人）与 `host_endpoint`（负责战斗 RPC 的进程）是两个字段
2. 房主可按确定顺序迁移，⛔ 不是"创建者退出房间就消失"
3. 断线时按心跳超时自动交接，且新老房主之间状态连续

## 1. 前置检查清单

- [ ] 已完成 01（身份与会话地基）
- [ ] 服务端有房间状态表（成员、设置、版本）
- [ ] 已定义心跳间隔与超时阈值
- [ ] 已确认房间设置变更走服务端校验

## 2. 工序

### Step 1　owner 与 host 是两个字段，都要能更换　`[social/02#S1]`

【读】`howto/godot/social.md#2. ⚠ 房主不是"房间主人"`

【做】
把"能改设置的人"（`owner_id`）与"负责战斗 RPC 的进程"（`host_endpoint`）
拆成两个字段，各自可独立更换。
⛔ 把房主永久等同于创建者 —— 创建者退出后**房间设置永远锁死**，
表现为"没人能开始游戏"，而成员列表看着是正常的。

【产出】房间表含 `owner_id` 与 `host_endpoint` 两个可变更字段

【判据】创建者退出后，另一人仍能改设置并开局。

【审】`audit/godot/social.md#5`

### Step 2　迁移顺序要确定，不是随机挑一个　`[social/02#S2]`

【读】`howto/godot/social.md#2. ⚠ 房主不是"房间主人"`

【做】
按**创建者 → 副房主 / 队长 → 剩余最早加入者**的顺序交接。
⛔ 随机挑或按 peer ID 排序 —— 同一批人重开会得到不同房主，
表现为"设置被回滚"（新房主的本地状态覆盖了服务端状态）。

【产出】迁移顺序规则（可复现，与 peer ID 无关）

【判据】同一批成员重开 10 次，交接后的房主是同一个人。

【审】`audit/godot/social.md#6`

### Step 3　断线按心跳超时交接，用户主动退出时显式交接　`[social/02#S3]`

【读】`howto/godot/social.md#2. ⚠ 房主不是"房间主人"`

【做】
两种退出走两条路径：**用户主动退出**时显式交接（有明确的交接对象），
**断线**时按心跳超时触发交接。
⛔ 两种都走超时 —— 主动退出会有一个"房间悬空"的窗口，
期间没人能改设置，表现为"点了退出卡一下"。
⛔ 超时阈值低于网络抖动常见时长 —— NAT 抖动就误判掉线，频繁交接。

【产出】双路径交接实现 + 心跳超时阈值（登记在参数表）

【判据】拔网线后 N 秒内完成交接且只交接一次；主动退出无悬空窗口。

【审】`audit/godot/social.md#48`

### Step 4　房间设置与成员状态服务端权威　`[social/02#S4]`

【读】`howto/godot/social.md#1. 三层架构（推荐）`

【做】
房间设置变更（地图、模式、人数上限、密码）由服务端校验并落库，
成员只读副本。
⛔ 房主本地改了就广播给其他人 —— 房主改包即可伪造，
且新加入者的设置来自服务端还是房主**不一致**。

【产出】设置变更走服务端校验 + 成员端只读副本

【判据】房主改包伪造一个非法模式，服务端拒绝且其他人设置不变。

【审】`audit/godot/social.md#49`

### Step 5　交接期间的状态连续性　`[social/02#S5]`

【读】`howto/godot/social.md#2. ⚠ 房主不是"房间主人"`

【做】
交接时把**已确认的房间状态**（已准备、已选角色、已开始倒计时）
一并交给新房主，⛔ 不是让新房主重新拉一次。
⛔ 交接期间允许成员改设置 —— 新老房主的变更会互相覆盖，
表现为"我明明锁了地图，开局却是别的图"。

【产出】交接快照（含已确认状态）+ 交接期间的设置冻结

【判据】交接完成后，所有成员看到的房间设置与交接前逐字段一致。

【审】`audit/godot/social.md#50`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：owner 与 host 分离 + 确定顺序迁移
# ⛔ 房主 ≠ 创建者；两者都要能换
const HOST_HEARTBEAT_TIMEOUT_SEC := 5.0   # 待实测：须大于常见网络抖动

func pick_next_host(members: Array) -> String:
    # ✅ 确定顺序：副房主 → 最早加入者（按 joined_at，不按 peer id）
    for m in members:
        if m.is_vice_host:
            return m.player_id
    var earliest = members[0]
    for m in members:
        if m.joined_at < earliest.joined_at:
            earliest = m
    return earliest.player_id
```

## 5. 常见返工

| 症状 | 原因 | 回到 |
|---|---|---|
| 创建者走了就不能开局 | 房主等同创建者 | S1 |
| 重开后房主变了、设置回滚 | 迁移顺序不确定 | S2 |
| NAT 抖动频繁换房主 | 心跳超时小于抖动时长 | S3 |
