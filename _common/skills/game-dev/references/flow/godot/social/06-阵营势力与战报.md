# 06 阵营、势力与战报（社交域）

> **本步交付**：有向非对称阵营关系 + 房间级 PvpContext 冻结 + 战报隐私分档
> **对应**：流程 `howto/godot/social.md` · 审核 `audit/godot/social.md`

## 0. 交付物定义

1. 阵营关系是有向图，⛔ 不自动镜像，也不是角色表上的一个枚举
2. 友伤等规则由房间级 `PvpContext` 冻结，⛔ 不在战斗层写 `if faction ==`
3. 战报存能重建事实的最小事件集，且默认最小展示

## 2. 工序

### Step 1　阵营是三层字段，不是一个枚举　`[social/06#S1]`

【读】`howto/godot/social.md#6.1 阵营关系是有向图，不是角色表上的一个枚举`

【做】
分 `main_faction_id`（PvP / 占领 / 赛季积分）、
`memberships`（公会 / 国家 / 职业组织 / 剧情派系，可多个）、
`temporary_affiliations`（剧情效忠 / 租借 / 俘虏，**必须有过期时间**）。
⛔ 混成一个"阵营" —— 会出现"剧情让我叛变但 PvP 仍算原阵营"的矛盾。

【产出】三层字段 + 主阵营决定 PvP 身份的约束

【判据】剧情叛变后，PvP 身份不变而任务条件已变。

【审】`audit/godot/social.md#16`

### Step 2　关系是非对称有向图，不镜像　`[social/06#S2]`

【读】`howto/godot/social.md#6.1 阵营关系是有向图，不是角色表上的一个枚举`

【做】
存 `faction_relation(from, to, relation, valid_from, valid_to, rule_version)`，
查询时先找有向边，找不到再取阵营默认关系。
⛔ 把有向行自动镜像 —— A 对 B 友好 ≠ B 对 A 友好，
表现为"我打他他不还手，但他一打我就变成敌人"。

【产出】有向关系表 + 查询回退规则（有向边 → 阵营默认）

【判据】只设 A→B 友好时，B 打 A 不会被判为"背叛"。

【审】`audit/godot/social.md#17`

### Step 3　友伤规则由 PvpContext 冻结，不在战斗层打补丁　`[social/06#S3]`

【读】`howto/godot/social.md#6.1 阵营关系是有向图，不是角色表上的一个枚举`

【做】
用房间级 `PvpContext`，**服务端开房时冻结**阵营关系、友伤、占领规则与配置版本；
战斗中的切换请求**不能回溯修改**已冻结的上下文。
⛔ 在战斗层写 `if a.faction == b.faction: return false` ——
后续每种例外（公会战 / 演习 / 剧情背叛）都会变成战斗层的补丁。

【产出】`PvpContext` 结构 + 开房时冻结的实现

【判据】战斗中提交阵营切换，本局判定不变，下局才生效。

【审】`audit/godot/social.md#18`

### Step 4　阵营切换是不可撤销的事务，要三重代价　`[social/06#S4]`

【读】`howto/godot/social.md#6.2 阵营切换必须付出时间、关系和经济三重代价`

【做】
切换是一次**不可撤销的事务**：加锁 → 校验冷却与未决绑定 →
更新主阵营 → 清理旧阵营专属状态 → 算惩罚 → 写冷却 → 发事件。
清理时**保留**永久剧情标记与已购外观，**清除** vendor 解锁、日常占领标记、待领奖励。
⛔ 主要风险不是数值损失，是**身份套利** ——
开战前转入防守方领奖、战后转回优势方。

【产出】切换事务 + 代价三件套（冷却 / 赛季次数 / 未领奖励作废）

【判据】赛季内连续切换被次数上限拦下；切换后旧阵营待领奖励已作废。

【审】`audit/godot/social.md#64`

### Step 5　战报存能重建事实的最小事件集　`[social/06#S5]`

【读】`howto/godot/social.md#6.7 战报：保存能重建事实的最小事件集，不保存每个像素`

【做】
最稳组合 = 初始状态哈希 + 固定步长输入序列 + 确定性随机种子 + 配置版本 + 关键事件摘要。
⛔ 以为"把 `float` 换成 `double` 就确定性了" ——
IEEE 754 不保证跨编译器、平台、数学库、线程调度与物理求解器一致。
⛔ 用系统时钟、对象 ID、字典遍历做游戏逻辑。
⚠ 版本兼容要在**写入时隔离**：回放头存 `engine_build / data_version / balance_version / rule_set_id`。

【产出】回放头结构 + 冻结项清单（步长 / 随机源 / 容器与排序 / 回调顺序）

【判据】同一回放连放 20 次结果一致；跨版本回放用旧快照重放。

【审】`audit/godot/social.md#65`

### Step 6　战报默认最小展示，分五档　`[social/06#S6]`

【读】`howto/godot/social.md#6.8 战报隐私：默认最小展示`

【做】
分 `SELF / PARTY / FACTION_OFFICER / WAR_REPORT / PUBLIC_LEADERBOARD` 五档。
默认隐藏：真实姓名、精确对局时间、IP、设备、好友列表、聊天、位置、未成年人标识。
⛔ "战绩本来就是公开的"不能成为默认逻辑 ——
精确对局时间结合其他数据可形成**行踪**。
⛔ 团队规模小、无法建立删除请求与导出机制时，**不做跨服战绩榜**。

【产出】五档可见性表 + 脱敏投影

【判据】默认分享出去的战报不含任何可反查账号的字段。

【审】`audit/godot/social.md#66`

## 3. 参考实现

```gdscript
# ⓘ 承接本步产出：PvpContext 开房冻结 + 战报回放头
# ⛔ 战斗中不得回溯修改已冻结的上下文
const CONTEXT_VERSION := 1     # ⓘ 冻结配置版本，供旧战报按旧快照重放

func freeze_context(room_id: String) -> Dictionary:
    return {
        "room_id": room_id,
        "ctx_version": CONTEXT_VERSION,
        "friendly_fire": _rules.friendly_fire,
        "relations": _relations.snapshot(room_id),   # ✅ 快照，不是引用
    }
```

## 4. 验收清单

- [ ] 阵营是三层字段且主阵营决定 PvP 身份
- [ ] 关系有向且不自动镜像
- [ ] 友伤走 PvpContext，战斗层无 `if faction ==`
- [ ] 切换是不可撤销事务且有三重代价
- [ ] 战报回放头含版本与种子，连放 20 次一致
- [ ] 战报默认最小展示，分五档
