# 06 手感验收（角色控制域）

> **前置**：01–05 全部验收通过
> **本步交付**：一份可签核的验收报告 + 回填后的参数表
> **对应**：审核 `audit/godot/character.md` `platformer-feel.md` `camera-cutscene.md` `animation.md`

## 0. 交付物定义

1. **参数表**：所有手感参数有**实测值**（不是抄来的示例值）
2. **验收报告**：逐项打勾，有 failing 项就退回对应功能点
3. **试玩记录**：至少 3 名**未参与开发**的人试玩，记录反馈

⚠ **没有这份报告就进入关卡开发，等于把未验证的手感当成地基。**

## 1. 前置检查清单

- [ ] 01–05 各自验收清单全过
- [ ] 各步 audit 坑表已过
- [ ] 有可测场景（平地、斜坡、高低差、平台边缘、墙）

## 2. 工序

### Step 1　参数回填

【做】把 `00-域流程总览.md` 第 4 节的参数表逐项实测并填入

⚠ 实测方式：⛔ 不要"感觉差不多"，要**可复现**——
比如"跳跃高度"是量出来的像素/米数，不是"看着挺高"。

【产出】参数表全部有实测值

【判据】每个参数都能说出**怎么测出来的**

### Step 2　逐域过 audit 坑表

【做】打开并逐条确认：
`audit/godot/character.md` · `platformer-feel.md` · `camera-cutscene.md` ·
`animation.md` · `input-remap.md`

【产出】每个坑表确认无命中，或有记录的问题已修

【判据】⚠ 对每条坑都能说出"我们是怎么避免的"，⛔ 不能"应该没这个问题"

### Step 3　录制基准跑测

【做】录一段**标准操作**（跑 → 小跳 → 大跳 → 转向 → 落地 → 上坡 → 下坡）

⚠ 这段录像作为**回归基准**：以后改任何参数，都要重录对比，确认没有退化。

【产出】基准录像存档

【判据】录像能覆盖 01–05 全部验收点

### Step 4　外部试玩

【做】找 ≥3 名**没参与开发**的人操作，记录：

| 问题 | 记录 |
|---|---|
| 有没有"我以为按了跳但没跳"的时候？ | — |
| 有没有觉得晕？（相机） | — |
| 有没有觉得"脚在打滑"？ | — |
| 转向是否觉得别扭？ | — |
| ⚠ 有没有"不知道为什么死/失误"的时刻？ | — |

⚠ 最后一条最关键：**玩家归因不了自己的失误，就是手感问题**。

【产出】≥3 份反馈

【判据】⚠ 若出现"不知道为什么失误"，**必须**定位到具体功能点并修，⛔ 不能归因于"玩家不熟练"

### Step 5　出报告

【做】汇总参数表 + 验收清单 + 试玩反馈 + 基准录像链接

【产出】`角色控制-验收报告`（放项目文档目录，⛔ 不进本 skill）

【判据】可被第三人照着复现全部结论

## 3. 验收清单（域级总验）

- [ ] 参数表全部实测并回填
- [ ] 五个 audit 坑表逐条过完
- [ ] 基准录像已存档
- [ ] ≥3 人外部试玩，反馈已处理
- [ ] ⚠ "不知道为什么失误"类反馈 = 0
- [ ] 改物理 tick 60→30：全部验收点仍成立
- [ ] 高刷屏（120/144Hz）：无周期性抖动
- [ ] 暂停/恢复：状态不错乱
- [ ] 关卡设计师拿到参数表后，能**照着设计跳跃距离**

## 4. 常见返工

⚠ **参数没实测就往下走** —— 关卡按"感觉"设计跳距，等手感微调后全部关卡要重做。
✅ 参数稳定后再开始关卡设计。

⚠ **只让开发者自己试玩** —— 开发者知道意图，会无意识补偿手感缺陷。
⚠ 这是最典型的漏检。

⚠ **没留基准录像** —— 后面改手感时无法判断是改善还是退化，只能靠记忆。

⚠ **把玩家"归因不了失误"当成玩家问题** —— 这几乎总是设计或手感问题。

## 5. 完成

角色控制域完成。后续关卡、战斗等开发都依赖这里回填的参数表。

⚠ **参数一旦调整，必须回到 Step 3 重录基准并对比**，⛔ 不能只改不验。
