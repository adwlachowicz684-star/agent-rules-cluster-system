# 角色控制域 — 流程总览

> **本域交付**：一个能跑、能跳、相机跟得住、输入可重绑、动作对得上的可玩角色。
> **对应**：流程 `flow/godot/character.md` `platformer-feel.md` `movement-advanced.md`
> 　　　审核 `audit/godot/character.md`

## 0. 先决定三件事（决定了后面全部）

开工前必须定死，⛔ 不要边做边改：

| 决策 | 选项 | 影响 |
|---|---|---|
| **2D 还是 3D** | `CharacterBody2D` / `CharacterBody3D` | 几乎所有 API 不同 |
| **物理还是运动学** | `CharacterBody`(move_and_slide) / `RigidBody` | 角色控制**一律选 CharacterBody**，⛔ RigidBody 做主控手感不可控 |
| **视角类型** | 横版 / 俯视 / 第三人称 | 决定相机方案和移动轴 |

⚠ **这三个没定就开工，后面必然推倒重来。**

## 1. 功能点拆解与依赖顺序

```text
01 移动基座 ──┬── 02 跳跃手感 ──┐
              ├── 03 相机跟随 ──┤
              ├── 04 输入映射 ──┼── 05 动画接入 ── 06 手感验收
```

| # | 功能点 | 前置 | 为什么这个顺序 |
|---|---|---|---|
| 01 | 移动基座 | 无 | 没有能跑的角色，后面全都无法验证 |
| 02 | 跳跃手感 | 01 | 手感是"在能跑基础上调时间窗"，反了会分不清是谁的问题 |
| 03 | 相机跟随 | 01 | 相机跟随移动，不依赖跳跃 |
| 04 | 输入映射 | 01 | 输入层独立，但要在有移动时才能验证重绑定生效 |
| 05 | 动画接入 | 01 02 | ⚠ **必须等移动和跳跃定稿**——否则你分不清是移动错还是动画错 |
| 06 | 手感验收 | 01–05 | 只有全部做完才谈得上"手感" |

## 2. ⚠ 三个最容易做反的顺序

**① 先接动画再做移动。** 动画会掩盖移动问题（角色在滑步但动画在跑，你看不出来），
等发现时移动参数已经围绕错误动画调了一轮。⛔ 移动定稿前只用一个色块。

**② 先调参数再搭结构。** 结构没定时调出来的手感参数，结构一改全部作废。
✅ 结构是骨架，参数是皮肉，先骨后肉。

**③ 相机和移动同时写。** 相机抖了你分不清是相机的问题还是移动本身在抖。
✅ 先用固定相机验证移动干净，再上跟随。

## 3. 每做完一个功能点必做

1. 跑一遍该步的**验收清单**（在对应文件第 4 节），逐条打勾
2. ⛔ 有没过的，不进下一步
3. 打开 `audit/godot/character.md`（及相关域）过一遍坑表
4. ⚠ 手感/数值参数实测后**回填**到文档，⛔ 不要用"应该差不多"
