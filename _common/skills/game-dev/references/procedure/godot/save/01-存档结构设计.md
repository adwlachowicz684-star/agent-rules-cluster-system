# 01 存档结构设计（存档域）

> **前置**：已定死格式、路径、是否加密、是否上云（见 `00-域流程总览.md`）
> **本步交付**：一个带版本头、可迁移、边界清晰的数据结构
> **对应**：流程 `flow/godot/save-migration.md` · 审核 `audit/godot/save-migration.md`

## 0. 交付物定义

1. 一个 `SaveData` 定义（Resource 或字典结构），**第一版就带 `save_version`**
2. 明确的"什么进存档 / 什么不进"清单
3. 每个字段的"是否可重算"标注

⚠ 能演示：把一份存档 dump 出来，**能一眼看出它属于哪个版本、哪些是权威数据**。

## 1. 前置检查清单

- [ ] 已列出所有要持久化的系统（角色、背包、任务、设置…）
- [ ] 已确认路径用 `user://`
- [ ] ⚠ 已确认 `save_version` **从第一版就写进去**
- [ ] 已区分"配置数据"（来自配表，不该进存档）和"运行时状态"

## 2. 工序

### Step 1　定文件头（⛔ 不可省略）

【做】
```gdscript
const SAVE_VERSION := 1
const MAGIC := "MYSAVE"      # 用于快速判断"这是不是我们的存档"

var header := {
    "magic": MAGIC,
    "save_version": SAVE_VERSION,
    "app_version": "",        # 客户端版本，便于排查
    "created_at": 0,          # ⚠ 用 UTC 时间戳
    "updated_at": 0,
}
```

⚠ **没有 `save_version` 的存档是无法安全迁移的** —— 只能靠猜字段是否存在，
而"字段不存在"和"字段合法为空"无法区分。

【产出】文件头定义

【判据】dump 任意存档，第一眼能看到 `save_version`

### Step 2　划分：什么进存档

【做】逐系统判定，填表：

| 数据 | 进存档？ | 理由 |
|---|---|---|
| 角色等级/经验 | ✅ | 玩家资产 |
| 背包物品实例 | ✅ | 玩家资产 |
| 当前场景/位置 | ✅ | 体验连续性 |
| **数值表（攻击力公式参数）** | ⛔ | 来自配表，进存档会导致改表后历史存档不一致 |
| **派生值（当前血量上限）** | ⚠ 视情况 | 能重算就别存，见 Step 3 |
| 设置（音量/键位） | ✅ 但**独立文件** | ⛔ 不要与进度混在一起（换设备时设置不该被覆盖） |

⚠ **设置与进度分开存**：否则"云同步进度"会把 A 设备的键位覆盖 B 设备。

【产出】一份"进/不进"清单

【判据】清单里每一项都有理由，且**没有"反正都存吧"这种项**

### Step 3　⚠ 标出"存输入不存结果"

【做】对每个数值字段问：**它能不能由其他字段算出来？**

- 能算出来 → ⛔ **不要存**（存了就会不一致）
- 例子：血量上限 = 基础 + 装备加成 + buff。
  ✅ 存"基础等级 + 装备 id + buff 列表"，上限由公式重算
  ⛔ 存"当前上限" → 改表后旧存档的上限是错的

⚠ 这条与 `flow/godot/survival.md` 的"数值存输入不存计算结果"是同一条原则。

【产出】每个数值字段标了"权威源 / 可重算"

【判据】⚠ 不存在"改了配表后，老存档数值与新存档不一致"的字段

### Step 4　定 ID 引用方式

【做】跨引用的数据**存 ID 不存对象**
```gdscript
# ✅
{"equip": {"item_id": "sword_01", "level": 3, "roll": 0.82}}
# ⛔
{"equip": {"atk": 120, "name": "铁剑"}}     # 改表后无法重算
```

⚠ **存最终值 = 策划改表后历史数据无法重算、不可审计**（见 `flow/godot/build-affix.md`）

【产出】所有跨引用都走 ID

【判据】改一条配表数值 → 加载旧存档 → **显示的是新数值**

### Step 5　定槽位与命名

【做】
```text
user://saves/slot_0.save      进度
user://saves/slot_0.save.bak    ⚠ 备份
user://settings.cfg            设置（⛔ 独立）
```

【产出】目录约定

【判据】能列出 `user://saves/` 并一眼认出每个文件

## 3. 参考实现

```gdscript
# save_data.gd — Godot 4.x
class_name SaveData extends RefCounted

const SAVE_VERSION := 1
const MAGIC := "MYSAVE"

var save_version := SAVE_VERSION
var app_version := ""
var created_at := 0      # UTC 秒
var updated_at := 0

# ── 以下只存"输入"，不存可重算结果 ──
var player_level := 1
var player_exp := 0
var inventory: Array[Dictionary] = []   # [{item_id, count, rolled}]
var equipped: Dictionary = {}           # {slot: {item_id, level, roll, generation_version}}
var flags: Dictionary = {}              # 任务/剧情标记
var current_scene := ""

func to_dict() -> Dictionary:
    return {
        "magic": MAGIC,
        "save_version": save_version,
        "app_version": app_version,
        "created_at": created_at,
        "updated_at": updated_at,
        "player_level": player_level,
        "player_exp": player_exp,
        "inventory": inventory,
        "equipped": equipped,
        "flags": flags,
        "current_scene": current_scene,
    }

static func from_dict(d: Dictionary) -> SaveData:
    var s := SaveData.new()
    if d.get("magic", "") != MAGIC:
        return null          # ⚠ 不是我们的存档
    s.save_version = d.get("save_version", 0)
    s.app_version = d.get("app_version", "")
    s.created_at = d.get("created_at", 0)
    s.updated_at = d.get("updated_at", 0)
    s.player_level = d.get("player_level", 1)
    s.player_exp = d.get("player_exp", 0)
    s.inventory = d.get("inventory", [])
    s.equipped = d.get("equipped", {})
    s.flags = d.get("flags", {})
    s.current_scene = d.get("current_scene", "")
    return s
```

## 4. 验收清单

- [ ] ⚠ `save_version` 从第一版就有
- [ ] dump 存档能一眼看出版本
- [ ] 每个字段都标了"权威源 / 可重算"
- [ ] ⛔ 没有存"可重算的派生值"
- [ ] 跨引用全部走 ID，不存最终值
- [ ] **改一条配表数值 → 旧存档显示新数值**
- [ ] 设置与进度**分开文件**
- [ ] 路径全部 `user://`，grep 不到 `res://` 写存档
- [ ] ⚠ `magic` 字段存在（能快速识别"这不是我们的文件"）

## 5. 常见返工

⚠ **没有版本号，到要改结构时才补** —— 线上已有无版本存档，只能靠猜。
这是存档域最贵的返工。

⚠ **存了派生值** —— 改配表后老玩家数值异常，且**无法修复**（不知道该重算成什么）。

⚠ **设置和进度混在一个文件** —— 云同步后 A 设备的键位盖掉 B 设备的。

⚠ **存了配表数据** —— 存档体积膨胀，且配表更新后存档与新版本不一致。

⚠ **直接存对象引用** —— 序列化出来是巨大的嵌套，改类名就全崩。
