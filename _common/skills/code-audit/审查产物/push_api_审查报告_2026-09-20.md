## 二、本轮核心发现：`--prune` 删了活跃任务记录，还打印了一句反话

### 现象【实测：端到端调用真实函数】

```
远端分支        : ['main', 'pr/my-work']
prune 的 mine   : [] （只认 task/ 前缀）
传给清理函数的 remote_names: set()

[已清理] 1 条本地任务记录（远端已无此分支）： ['pr/my-work']
   仅清理本地记录，未改动远端。

tasks 前后对比:
  前: {"pr/my-work": {"last_push": "...", "pr": 12, "pushed": {"a.txt": "bbb..."}}}
  后: {}

★ 结论: pr/my-work 记录被删除 = True
★ task_branch 被清空 = True
```

**`pr/my-work` 好端端在远端**（`list_branches()` 返回了它），脚本却打印"远端已无此分支"。

### 机制【代码事实】

两个函数对"哪些分支算我的"用了**不同口径**：

```python
# prune() L2735 —— 只认 task/ 前缀
mine = [b for b in list_branches()
        if (b.get("name") or "").startswith(TASK_PREFIX)]   # TASK_PREFIX = "task/"
_prune_stale_tasks(state, {b.get("name") for b in mine})    # 只把 mine 传下去

# _prune_stale_tasks() L2696 —— 不在 remote_names 里 = 远端已无此分支
stale = [n for n in tasks if n not in remote_names]
for n in stale:
    tasks.pop(n, None)
save_state(state)
```

而 `--branch` 参数**允许任意分支名**（L3397 只拦了 `branch == BRANCH`），
docstring 也写着 `-b feat/login` 这类用法。于是任何非 `task/` 前缀的分支，
其 `tasks` 记录都会被"体检"命令判死。

### 更糟的一支：`mine` 为空时清空全部

```python
if not mine:
    print(f"\n没有 {TASK_PREFIX}* 分支，很干净。")
    _prune_stale_tasks(state, set())     # ← 传空集 = 所有记录都算 stale
```

注释断言"一个 `task/*` 分支都没有，恰恰说明 tasks 里的记录**全**是过期的"——
用户用非 `task/` 前缀时，这个推断**恰好相反**。

### 后果链：破坏的是另一个模块防误判的输入

被删的 `tasks[b]["pushed"]` 是 `_refresh_main_baseline` 的 `merged_pushed` 入参（L2580）：

```
prune 删掉 pushed
  → --merge 时 task.get("pushed") == None
  → _refresh_main_baseline 无法识别「主干上这个版本正是我推上去的」
  → 掉进 lagging → synced_commit = None
  → 下次推送被 P0-1 拦住，提示 --pull
  → 触发该函数注释里明确要防的误判：
      「--hold 推 v2 → 编辑成 v3 → --merge：本地 v3 ≠ 主干 v2
        按『本地落后』处理 → --pull 拿陈旧 v1 当 base
        → 把 v2→v3 自己的连续改动判成冲突」
```

**一个模块用来防误判的输入，被另一个模块的清理逻辑删掉了。**

### 与 docstring 的冲突【代码事实】

模块 docstring 第 57、65 行两处明确保证：

```
  【分支体检】只报告，不删任何东西
  python3 push_api.py --prune             # 列出所有任务分支的状态和建议
```
```
  所以 --prune 只报告，删除一律走 --delete-branch 并逐个确认。
```

**代码实际会删除本地 `tasks` 记录并 `save_state()` 落盘。** 这属于
"文档承诺与实现不符"，与 A1（docstring 宣称已实现、代码未接上）同类。

### 定级

三个反问：会报错吗（否，打印"已清理"）｜会遇到吗（`--prune` 是高频体检命令，
`--branch` 允许任意名）｜能恢复吗（`pushed` 字段**无法重建**）→ 本应 P0；
因需"非 `task/` 前缀 + `--hold` + 跑过 prune"三者同时成立，故定 **P1**。

### 修法

```python
# 方案 A（最小）：remote_names 用全部分支，不做前缀过滤
all_names = {b.get("name") for b in list_branches()}
_prune_stale_tasks(state, all_names)

# 方案 B（更稳）：按 tasks 自己的键逐个查远端（条目数通常远小于分支总数）
```

## 五、一个贯穿十轮的规律

| 轮次 | 现象 | 共同形态 |
|---|---|---|
| 第 4 轮 | autocrlf 致 sha 分叉 | 写进去的路径与算 sha 的路径不是同一条 |
| 第 5 轮 | symlink `.strip()` 致 sha 分叉 | ↑ 同一成因第二次发生 |
| 第 7 轮 | `_conflict_path` 命名碰撞 | 移出仓库外修了覆盖，却引入新的碰撞面 |
| 第 8 轮 | symlink 编码 4 处调用 3 种写法、2 处崩溃 | 正确写法连同注释就在 L926，另外 3 处没同步 |
| 第 9 轮 | `--prune` 误删活跃记录 | 前缀过滤既造成漏报（B4）又造成误删（E1） |
| 第 9 轮 | `--dry-run` 白名单漏 prune | 防漏的白名单自己漏了一项 |

**共同形态：防复发机制只覆盖了当时注意到的那条路径，没覆盖同族的其他入口。**

这个脚本的注释质量极高——几乎每个坑都记了成因与实测，说明作者踩过很多次。
它缺的不是"把坑记下来"，而是**记下来之后回头检查同族的其他位置**。

## 六、验证过没问题的部分（**不要重复改**）

本轮新打开的 9 个函数里，以下设计是对的：

1. **`_auth_config` token 白名单** `[A-Za-z0-9_.-]` —— 注释完整记录了从"可打印 ASCII"（放行 `"` `` ` `` `$()`，只是**碰巧安全**）收紧到真实字符集的过程，且用「拒绝」而非「清洗」（清洗后 token 变了必然 401，用户只会看到"认证失败"）。`/dev/shm` + 0600 + 退出即删
2. **`StateLock` 用 flock 且锁住整个 `_main()`** —— 注释说明"拆成多段短锁反而会重新引入竞态"，且先非阻塞探测、抢不到才打印等待（避免"一声不响卡住让人以为挂了"）
3. **`_pr_index` 一次拉全量 PR 建索引** —— 替代了"150 个分支 = 150 次 find_pr"的 N+1
4. **`find_pr` 开启中优先** —— 注释记录了"返回第一个会拿到早已合并的旧 PR，于是报『未合并，删除会丢改动』——方向恰好反了"
5. **`_write_local` 非执行文件显式 `chmod 0o644`** —— 注释记录了"只写内容不写权限位 = 只同步了一半状态，会与 pull 永久打架"
6. **`_write_local` 写完立即清 `_CHANGES_CACHE`** —— "靠调用点自觉传 refresh 太脆弱，这里从源头失效掉"
7. **`_write_local` 对 symlink 目标做路径穿越校验** —— 注释指出"读侧防了、写侧没防，是最容易被忽略的不对称"
8. **`gitignored_set` 双向 surrogateescape** —— 注释记录了"只修输出不修输入，崩溃只是换个地方（实测）"
9. **`_git_env_error` 区分三种 git 失败** —— 并强调"不是『没有改动』，是**读不到仓库**"
10. **`ensure_pr` 只复用 `state == "open"`** —— 注释记录了复用已合并/已关闭 PR 导致"推送成功、改动不进主干、报错误导"
11. **`_refresh_main_baseline` 把 `p not in lmap` 排除出 lagging** —— 注释记录了"原来两者都进 lagging，于是刚合并成功立刻被 P0-1 拦住"
12. **第一层校验用"交集"而非全局拦截冲突** —— 注释记录了"1 个文件冲突会挡住另外 15 个毫不相关的文件"
13. **`bypass = force`** —— 注释记录了曾写成 `force or bool(allowed)` 导致他人改动被静默回退的实测事故
14. **`--method` 解析后统一校验** —— "本地校验比把非法值发给 GitHub 再收一串 422 JSON 好排查得多"
15. **`--` 之后一律当路径** —— 避免以 `-` 开头的文件名被当成未知选项

## 八、一句话总结

> 第 10 轮最刺眼的是 **`--prune` ——一个在 docstring 里两处承诺"只报告，不删任何东西"
> 的体检命令，会静默删掉用户正在用的任务记录，还打印一句"远端已无此分支"
> （远端分明有这个分支）**。
>
> 更值得记的是它破坏了什么：被删掉的 `pushed` 字段，正是
> `_refresh_main_baseline` 用来区分"本地领先"与"本地落后"的输入——
> 而那个函数存在的**全部意义**就是防止注释里描述的那个误判。
>
> **一个模块的防误判输入，被另一个模块的清理逻辑删掉了。**
> 这类跨模块的隐式依赖断裂，比单点 bug 更难发现，也更值得在回归测试里钉住。
