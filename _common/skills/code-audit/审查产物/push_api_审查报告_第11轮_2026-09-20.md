## 二、【P1-NEW】`abandon_task` 缺主干保护，可删掉任意分支（含主干）

### 三兄弟函数的不对称【代码事实】

| 函数 | 是否有 `branch == BRANCH` 保护 | 注释 |
|---|---|---|
| `delete_branch_cmd` L2651 | ✅ 有 | "主干必须硬拦：删掉主干等于删掉整个项目" |
| `close_pr` L2621 | ✅ 有 | "**与 delete_branch_cmd 同一道闸**：本函数末尾会删分支" |
| **`abandon_task` L2594** | ❌ **无** | — |

`close_pr` 的注释明确写着这道闸是**共用的**，而同一族里的第三个成员没有接上。

### 可达路径：`--merge <任意 PR 号>` 不过滤前缀

```python
# _main L3223
if explicit and explicit[0].isdigit():
    n = int(explicit[0])            # ← 直接用，无任何过滤
```

对照同一分支下的另一条路径（无 PR 号时的候选列表）：

```python
open_prs = [p for p in open_prs
            if (p.get("head") or {}).get("ref", "").startswith(TASK_PREFIX)]   # ← 有过滤
```

**只有"列出来让人挑"这条路径过滤了前缀，`--merge <N>` 直接指定号码这条没有。**

### 后果链

```
python3 push_api.py --merge 42
  → do_merge(state, 42)
  → pr = GET /pulls/42；branch = pr.head.ref     ← 可以是 main / release / 任意分支
  → merge_pr 失败（conflict 或 need_update）
  → abandon_task(state, branch, 42)
  → delete_branch(branch)                        ← 无保护，直接 DELETE
  → 分支消失，无确认、无内容校验
```

`release` / `develop` 这类长生命周期分支尤其容易命中；
`main` 亦可（`--merge` 指定的 PR 若 head 为 main）。

### 与 B5 的关系

B5 报的是"abandon_task 无确认、无内容校验"。本条是它的**加重情节**：
不只是"删得草率"，而是**连主干都拦不住**——而两个兄弟函数都拦了。

### 定级

三个反问：会报错吗（否）｜会遇到吗（`--merge <N>` 是文档明示用法，长生命周期分支常见）｜
能恢复吗（**分支删除不可恢复**，GitHub 对 API 发起的删除往往保护不到）→ **P1**。

### 修法（1 行，与兄弟函数对齐）

```python
def abandon_task(state, branch, pr_number=None):
    if branch == BRANCH:
        raise SystemExit(f"拒绝删除主干分支 {BRANCH}。")
    ...
```

**更彻底**：抽出 `_guard_not_protected(branch)` 供三处共用，
避免下次新增删除路径又漏掉——这正是前十轮反复出现的形态。

## 三、修正：A2 的范围应是 **5 处**，不是 4 处

前几轮报的是 `L415 / L864 / L927 / L1799`。本轮逐处核查后发现**漏了一处**：

| 行号 | 命令 | 位置 | 影响 |
|---|---|---|---|
| L415 | `git merge-base --is-ancestor` | `_local_head_rewound` | 启动即调用 |
| L864 | `git rev-parse --is-inside-work-tree` | `require_git_repo` | 启动即调用 |
| L927 | `git hash-object --stdin` | `local_blob_sha` | 每文件 |
| **L1719** | **`git merge-file -p`** | **`_merge3`** | **pull 三方合并主路径** ← 本轮新增 |
| L1799 | `git cat-file blob` | `_git_blob_bytes` | 取 base |

**L1719 在 pull 的三方合并主路径上**：`_merge3` 对每个冲突文件调 `git merge-file`，
挂住即 pull 永久卡死、无任何输出，用户只能 Ctrl-C（而 Ctrl-C 后工作区可能停在
改写一半的状态）。

`git()` 的注释写的正是"没有超时会让整个推送永久卡死"——
**这个保护没接到 `_merge3` 这一处**。

> 说明：L619/664/672/675 也是无 timeout 的 `subprocess.run`，但那是 curl，
> 超时由 `--max-time` 负责，不属于本条。

## 四、【实证】B6 精确化：`mark_synced` 在三种情形下的行为

前几轮报的是"mark_synced 不查 conflicts"（【代码事实】）。
本轮做了端到端实证，**明确了它什么时候会漏**：

```
── 情形1 冲突文件在 rstate，远端已变本地未合
   ❌ 还有 1 个文件的远端改动未合并进本地，不能标记已同步：a.txt
   synced_commit 被设置 = False        ← ✓ 正确拦下

── 情形2 冲突文件不在 rstate（远端已删或纯本地新增）
   ✅ 已标记本地副本基于远端 eeeeeeee
   synced_commit 被设置 = True         ← ★ 漏
   conflicts 仍残留 = ['a.txt']

── 情形3 冲突文件在 rstate 且本地恰好等于远端
   ✅ 已标记本地副本基于远端 eeeeeeee
   synced_commit 被设置 = True         ← ★ 漏
   conflicts 仍残留 = ['a.txt']
```

**结论**：它查的是"远端 vs 本地"，**不是** `state["conflicts"]`。
情形 2、3 都会设置 `synced_commit` 而冲突列表仍有内容。

情形 3 相当可达：冲突后用户把文件手工改成与远端一致，然后跑 `--mark-synced`
（而不是 `--resolve`），此时 P0-1 闸门被解除而冲突标记仍在。

### 缓解因素（如实说明）

推送路径上另有一个"未解决冲突拦截"（L3285，按待推集合求交集），
它对仍在 pending 集合里的文件**仍然生效**。所以 B6 的实际爆炸半径有限，
维持 **P2**，不升级。

### 修法（1 行）

```python
if unmerged or state.get("conflicts"):
    # 有未解决冲突时同样不能声称「已同步」
```

## 六、本轮验证过没问题的部分（**不要重复改**）

1. **`save_state` 原子写 + 0600** —— 先 chmod 再 `os.replace`（"replace 会沿用 tmp 权限"），且 `OSError` / `TypeError` / `ValueError` 三档都给了"推送已生效、不要 `--reset-baseline`"的明确指引；注释还点出 `UnicodeEncodeError` 是 `ValueError` 子类、不是 `OSError`，会穿透成裸 traceback
2. **`_corrupt_state` 先备份再报错** —— "用户看到这条错误的下一步多半就是 `--reset-baseline`"，且只备份普通文件（FIFO 会让 `copy2` 永远阻塞，连错误都打印不出来）
3. **`resolve` 的成员资格校验** —— 注释说明"对一个从没冲突过的文件声明『已含远端最新』，等于无凭无据地解除 P0-1 闸门"（此前的 `--resolve` 后门已修）
4. **`delete_branch_cmd` / `close_pr` 的主干硬拦** —— 两处都有且注释说明了为什么放在函数内而非参数解析处（两个入口都要过闸）
5. **`_cleanup_failed_branch` 的 `elif` 而非独立 `if`** —— 注释记录了"写成独立 if 会把我们自己刚推上去的内容误判成『被他人改动』而跳过清理，孤儿分支就回来了"；且只重抛 `KeyboardInterrupt`、继续吞 `SystemExit`
6. **`git()` 不用 `strip()` 只用 `rstrip("\n")`** —— 注释记录了 `strip()` 吃掉 `" M a.txt"` 的首空格、导致路径被切成 `.txt`
7. **`safe_rel` 用 `realpath` 而非 `normpath`** —— 注释记录了 `etcdir -> /etc` 时 normpath 会放过
8. **`_rate_limit_hint` 把限流字段转成可操作提示** —— 给出具体重置时间而非"等几分钟"
9. **`_merge3` 二进制直接判冲突** —— "git merge-file 只按行处理，对二进制产出的是垃圾"；且 `finally` 里吞掉删除异常（"finally 抛出的异常会替换掉 try 中正在传播的真实异常"）
10. **`--merge` 无 PR 号时列出候选让人挑** —— 注释记录了"合并完当前那个后 pr_number 就空了，第二次 `--merge` 会直接报错"
