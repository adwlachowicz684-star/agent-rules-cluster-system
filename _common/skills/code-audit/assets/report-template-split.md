# 分文件报告模板（按代码归属拆分）

**默认用这份**，而不是 `report-template.md`。

整机审查产出**一个目录**而非一个文件：主窗口与各插件各自独立成文。
单模块 / 小工具审查才用 `report-template.md`。

---

## 为什么拆

- 单文件报告 300+ 行后没人读得下去；按归属拆开，每份 30~80 行，能直接派工
- 问题归属天然清晰：外壳的问题不用插件作者看
- 各文件可独立关闭：某插件修完就删掉那份，不用在大报告里标记
- 「已核对为误报」就近放在对应文件末尾，下轮不用跨文件找

## 目录结构

```
审查_<项目名>/
├── 00-索引.md
├── 01-主窗口-<子系统A>.md
├── 02-主窗口-<子系统B>.md
├── 0N-主窗口-构建与配置.md
├── NN-插件-<名称>.md
└── ...
```

**主窗口按子系统拆，不按文件类型拆。** 例：

| 子系统 | 典型范围 |
|---|---|
| Vanilla 外壳 | 原生 JS 宿主、SDK、桥接层 |
| React 外壳 | `src/*.tsx`、组件、hooks |
| 原生后端 | `src-tauri/`、Rust/C++/Go |
| 构建与配置 | `package.json`、入口 HTML、CI、忽略清单 |

**插件一个一份**；无问题的插件不建文件，只在索引里记「已审 · 未发现问题」。

**大于 5 个文件时打包成 zip 再交付。**

## 各分文件模板

```markdown
# <归属> · <子系统/插件名> 问题清单

> 审查日期：YYYY-MM-DD · 代码：<仓库> @ <分支>
> 范围：<具体路径列表>
> 方式：静态扫描 + 逐条人工验证。未跑 <命令>（原因），
> 依赖运行时行为的条目已标 `unverified`。

## P0

### 1. <一句话说清问题>

- **位置**：`<文件>:<行>`
- **现象**：<代码形态，可贴关键行>
- **后果**：<什么场景暴露、什么症状>
- **修法**：<具体改法>

### 2. ...

## P1

### N. ...

## P2

### N. ...

## 已核对为误报（不用改）

| 扫描命中 | 实际 |
|---|---|
| `<文件>:<行>` <规则说了什么> | <为什么不是问题> |
```

---

## 硬约束

1. **只写问题，不写过程** —— 不写「上轮核对」「工具改进」「扫描统计」，
   这些属于会话记录，不属于交付物
2. **每条问题必须有位置 + 后果** —— 缺后果的不写（三件套降级为二件套时也要有后果）
3. **误报段必写** —— 扫描命中但人工确认不是问题的，全部记下来，
   否则下轮会重复排查同一批
4. **拿不准就标 `unverified`** —— 不要为了凑数把推测写成结论
5. **同类问题合并** —— 同一成因的多处命中写一条，位置列全；
   计数 ≤2 的独立问题几乎条条是真问题，优先保留
6. **不写「建议加强注意」这类空话** —— 修法必须可操作
