# 执行清单

逐模块打勾。打印出来对着走，避免漏项。

## 第 1 步 摸清现状

```
□ 技术栈与外壳形态确认
□ 模块表建好（模块 / 路径 / 文件数 / 行数）
□ 是否有两套实现（有 → 进入差异比对）
□ 是否已有历史报告（有 → 本轮是复核，用 pre-existing 标记）
□ 规模分档确定推进策略
```

## 第 2 步 模式扫描

```
□ 六个扫描器 --self-test 均通过（scan-ts / scan-app / scan-py / scan-go / scan-java / scan-cpp）
□ 全量扫描跑完，基线存盘
□ P0 候选单独导出
□ 按模块排出可疑度顺序
```

## 第 3 步 文档一致性

```
□ doc-scan.py 跑完
□ 命令不存在项 —— 已核对
□ 引用文件不存在项 —— 已核对
□ 数量声明待核对项 —— 逐条数过
```

## 第 4 步 验证候选

```
□ 每条候选都读过上方注释（排除设计意图）
□ 每条候选都想清了后果
□ 批量族已抽样确认，按族合并报
□ 误报已剔除并记录理由
```

## 第 5 步 分模块精审

**维度一 契约与双实现**（`s-sandbox-host.md`）
```
□ 挂载图 / 通信图 / 能力图 画完
□ 契约五问逐项过
□ 双实现钩子名单比对（两列逐个 grep）
□ 扩展取不到宿主状态的三类根因已查
□ 消息通道四个必须（来源校验 / 去重 / 超时 / 精确退订）
□ 加载超时与错误边界
```

**维度二 沙箱与权限**（`s-sandbox-security.md`）
```
□ 隔离态下能力清单逐个跑一遍（找静默失效）
□ 桥接服务端五查（白名单 / 自授权 / 参数 / 返回值 / 错误）
□ CSP 与权限：每个入口都查 + 合并语义查清
□ 凭据与密钥六查
□ 外链入口分类正确
□ 静默失败清单（?. / catch{} / 降级 null）逐个问过
```

**维度三 原生后端**（`s-backend.md`）
```
□ 文件操作：读入有界 / 删除保护 / 递归识别链接 / 跨设备回退
□ 进程执行：shell 解析 / 可执行文件来源 / 参数传递 / 生命周期
□ 网络服务：请求体上限 / 超时 / 绑定地址 / 空口令 / 并发上限
□ 锁与错误处理（配合 panic=abort 单独判）
□ 命令注册完整性 / 孤儿文件 / 重复实现
```

**维度四 生命周期**（`s-build.md`）
```
□ 成对契约表逐项对照卸载钩子
□ 重挂载叠加（generation / 先清后加 / 卸载兜底）
□ 卸载后仍被使用的静默情形
```

**维度五 构建与卫生**（`s-build.md`）
```
□ 打包范围 / 硬编码清单 / 多入口覆盖
□ 忽略清单 / CI / 测试脚本可用性 / 依赖锁定
```

## 第 6 步 报告

```
□ 三件套齐全（位置 / 证据 / 后果）
□ 未实测的都标了 unverified
□ 「验证过没问题的部分」已写
□ 审查方式声明已写（含未执行的验证步骤）
□ 修复清单编号 + 批次建议
□ 发现的问题只报未改（或已获批准）
```

```
□ 产物 ≥5 个 → 打包 zip
□ 扫描基线一并交付
```
