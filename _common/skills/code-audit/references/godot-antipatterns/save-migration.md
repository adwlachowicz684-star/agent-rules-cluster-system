# save-migration — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于审核完成效果、约束边界。
> 「怎么做」看开发侧：`game-dev/references/godot/save-migration.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | 格式不会大变 | **必然要变**，问题是怎么办 |
| 2 | 版本号以后加也行 | 第一天没写就**只能猜** |
| 3 | 格式版本 = 游戏版本 | 是**三个独立**的版本 |
| 4 | 加密存档的元数据够用 | **不能替代**自己的版本字段 |
| 5 | 版本号放文件头就行 | 加密档**解密后才能读** |
| 6 | 迁移不用备份 | **不可逆**，失败即丢进度 |
| 7 | 迁移后签名还在就有效 | **必须重算**，否则是假象 |
| 8 | 降级读会报错 | **`get_value` 返回默认值**，静默错 |
| 9 | 损坏和降级一样处理 | 要**区分**，否则日志无法归因 |
| 10 | 未来版本硬塞进去 | 要**拒绝** |
| 11 | 写盘是原子的 | 写一半崩会**损坏**，要临时文件+原子替换 |
| 12 | 迁移一次到位更好 | **逐级**更好维护 |
| 13 | 枚举加项不影响 | 数字存储**可能错位** |
| 14 | 删字段就删干净 | 回滚需要**保留旧数据** |
| 15 | 迁移代码跑通就行 | 要**历史样本回归测试** |
