# replay — 反模式清单（审核用）

> 本文件**只写「不能怎么做」**，用于审核完成效果、约束边界。
> 「怎么做」看开发侧：`game-dev/references/godot/replay.md`

## 常见坑

| # | 本能以为 | 实际 |
|---|---|---|
| 1 | Godot 有内置回放系统 | **没有**，要自己组装原语 |
| 2 | 先找个保存函数 | 要先定**录什么** |
| 3 | Godot 物理是确定性的 | **官方明确不保证** |
| 4 | 单机能复现 = 跨平台一致 | 是**两个保证级别** |
| 5 | 固定步长就够了 | 还有**遍历顺序/浮点/随机/墙钟** |
| 6 | 录按键事件流 | 要录**每 tick 的动作状态** |
| 7 | 回放帧率不同没关系 | **必须同 tick 率** |
| 8 | 跑一遍一样就是确定性 | 要**两遍比对哈希** |
| 9 | MovieMaker 能实时录屏 | 是**离线逐帧渲染**，很慢 |
| 10 | 状态快照也要确定性 | **不需要**，这是它的优势 |
| 11 | 回放只用于精彩时刻 | **调试复现**价值更大 |
| 12 | 输入回放体积小所以都该用 | 涉及**刚体时会失配** |
| 13 | 用 `delta` 就行 | 要用**固定步长**，不能用墙钟 |
| 14 | 随机加种子就确定 | 还要**调用顺序**一致 |
| 15 | 幽灵车用输入录制 | 状态快照更稳（物理不确定） |
