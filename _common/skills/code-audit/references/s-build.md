# 场景：构建与交付（s-build）

**触发**：有构建配置 / 打包 / CI / 依赖声明 / 发布流程。
**风险**：打包范围过宽（源码进包）、硬编码清单导致新增成员静默缺失、
CI 缺失使测试形同虚设、占位资源未替换、依赖无法复现。

`overlaps:` **只管构建产物与流程**。
产物是否**实现了文档承诺的功能**归 `s-contracts`；
产物里的**后端二进制安全性**归 `s-backend`；
构建脚本里的**路径处理**归 `s-backend`（K 族）。

## 模式清单

### G-01 (P2) 打包范围过宽
- **判据**：`frontendDist` / `files` 指向项目根，且忽略清单未排除源码外的内容
- **确认**：测试目录、构建配置、源码是否进了安装包（体积 + 源码暴露）

### G-02 (P2) 构建脚本硬编码清单
- **判据**：构建配置里写死成员列表（如要拷贝的插件名数组）
- **确认**：新增成员是否会**静默缺失**
- **典型**：`const PLUGINS = ['home', 'settings', ...]` —— 新增插件不进包

### G-03 (P2) 无 CI / lint 未纳入流程
- **判据**：存在 `typecheck` / `test:*` / `lint` 脚本但无 CI 配置引用它们
- **确认**：这些脚本是否真的还能跑通（**过时的测试脚本本身就是缺陷**）
- **典型**：package.json 有 15 个校验脚本，README 只提到 7 个，且无 CI

### G-04 (P2) 依赖声明与锁定不一致
- **判据**：`package.json` 有依赖但 lock 文件缺失/过期；可选依赖未在文档说明
- **确认**：干净环境下能否复现安装

### G-05 (P3) 占位资源未替换
- **判据**：图标/证书/样例配置仍是脚手架默认值
- **典型**：`icons/` 下是占位图标、identifier 是 `com.example.*`

### G-06 (P2) 缓存/依赖目录未忽略
- **判据**：`.gitignore` / 打包忽略清单缺 `node_modules` / `dist` / `target` /
  `__pycache__` / `.DS_Store`
- **确认**：`git status` 里是否出现这些目录

### G-07 (P1) 多入口但安全策略只覆盖其一
（与 `s-sandbox` S-04 同源。**报一次即可**，归 `s-sandbox`。）

### G-08 (P1) 产物结构与运行时期望不一致
- **判据**：输出结构是否与运行时期望匹配
  （如期望 `dist/plugins/<id>/index.html`，实际输出 `<id>/index.html`）
- **确认**：跑一次构建，比对产物路径与代码里的加载路径

### G-09 (P2) 多份配置合并关系存疑
- **判据**：构建使用了 `--config <额外配置>`
- **确认**：**是合并（JSON Merge Patch）而非替换** —— 安全项谁覆盖谁要按合并规则推一遍
- **典型**：主配置 `csp: null`，另一份配置没写 csp → 合并后仍为 null

### G-10 (P2) sourcemap / minify 未按 profile 区分

### G-11 (P0) 依赖供应链无证据
- **判据**：四问——**有锁定文件吗**（npm / poetry / go / cargo 各自的全量锁文件）·
  **有 SBOM 吗**·**跑漏洞扫描吗**·**原生依赖是否进审计**
- **确认**：删掉 lock 文件重装，看依赖版本是否会漂移。会 → 构建不可复现，
  且无法回答「线上跑的到底是哪一版」
- **典型**：只有 `requirements.txt` 不锁版本 → 某次构建自动升到带后门的版本
- **修法**：锁全量（含间接依赖）+ CI 里跑 `npm audit` / `pip-audit` / `govulncheck`
- **定级**：**P0** —— 供应链攻击不经过代码审查，看代码看不出来
- **降级**：内部工具、无外部用户输入、无生产部署 → P2

### G-12 (P1) 构建不可复现
- **判据**：构建依赖当前时间、随机数、`latest` 标签、或未固定的基础镜像
- **确认**：同一份源码在两台机器上构建，产物是否逐字节一致。不一是 → 无法回滚定位
- **修法**：固定基础镜像 digest、`SOURCE_DATE_EPOCH`、锁全量依赖
- **判据**：debug 与 release 使用相同构建选项

## 检查方法

```
□ 忽略清单覆盖了 node_modules / dist / target / __pycache__ / .DS_Store
□ 打包清单是自动扫描还是硬编码数组
□ 每个入口（HTML / 插件 / 子包）都进了构建输入
□ 产物路径与运行期加载路径一致
□ CI 引用了全部 typecheck / test / lint 脚本
□ 这些脚本现在还能跑通
□ lock 文件完整；可选依赖在文档说明
□ 图标 / identifier / 样例配置已替换
□ 多份构建配置的合并语义已确认（尤其是安全项）
□ 交付前清理 __pycache__ / .DS_Store / 临时探针
```

## 常见误报

- **G-01 项目结构就是扁平的** —— 打包根合理 → 忽略
- **G-02 硬编码清单旁有校验**（构建时检查成员存在）→ 降级
- **G-03 项目用外部 CI**（非 GitHub Actions）→ 确认后忽略
- **G-05 内部工具无需替换图标** → P3 或忽略
