# 场景：契约与承诺（s-contracts）

**触发**：有对外 API / 接口声明 / README 承诺 / 两套实现 / 插件注册契约。
**风险**：声明了却没接线、文档与实现不一致、双实现能力分叉、死契约。

`overlaps:` **只管「声明 vs 实现」的一致性**。构建产物是否齐全归 `s-build`；
接口参数是否成对校验归 `s-atomicity`；文档里的命令能否跑通归 `s-build`（CI 部分）。

---

## 核心原则：把文档当需求文档

**整机/库审查中占比最高、用户最能感知的一类。**
下一个接手的人（包括下一个 AI）是靠 README 认识这个项目的——
文档说错了，他从第一条理解就是错的。

---

## 模式清单

### C-01 (P0) 声明的特性未接线（孤儿组件 / 死代码）
- **判据**：存在组件/模块/命令的**定义**但全仓库无**引用**；或定义了回调却没传
- **确认**：全局搜该标识符，只出现在自身定义与导出处 → 确认。
  **注意动态引用**（注册表、字符串拼接、构建配置自动扫描）
- **典型**：`PluginSettingsDrawer.tsx` 全仓库唯一命中自身 → Vite 模式「设置」按钮永不出现
- **修法**：接线，或删除并在文档里去掉该承诺
- **定级**：无降级。声明了却完全不可用 = 对外承诺完全失效

### C-02 (P1) 双实现 / 多栈能力不对等
- **判据**：README 或注释声称两套实现（原生/构建版、A 语言/B 语言、新旧并存）行为一致
- **确认**：把两套入口的功能点列成**两列逐项比对**，重点比对
  **回调 / 钩子 / props / 命令注册**四类接线
- **典型**：React 外壳比无构建外壳少 4 个回调（设置抽屉、侧边栏注入、
  快捷键转发、CSP 上报）→ 焦点进 iframe 后 ⌘B/R/, 全失效
- **降级**：差异只在不影响功能的呈现细节（文案、顺序）→ P2

### C-03 (P1) 文档默认值 / 数量 / 清单与代码不符
- **判据**：文档写「默认 X」「共 N 个」「M 套」，代码里是另一个值
- **确认**：定位代码里的常量/数组，数一遍
- **典型**：README 说 22 套主题，`PRESET_THEMES` 实际 23 条；
  README 说 4 个测试脚本，package.json 里 13 个
- **降级**：数量差 1 且不影响理解 → P2

### C-04 (P0) 文档把缺陷记为设计意图
- **判据**：文档描述某行为为「设计如此 / 已修复 / 已知限制」，实际是 bug 且未修
- **确认**：按文档描述的路径去代码里找对应实现，看它是否真的做了
- **典型**：README 声称「隔离后由插件自报基调，已修复」，实际自报字段没接上
- **定级**：P0。它会**阻止下一个人修复**

### C-05 (P0) 接口字段声明但从未被赋值/读取（死契约）
- **正确**：实现它，或连同 README/JSDoc 声明一起删
- **特征**：接口字段在模块内只出现 1 次（声明处）
- **确认**：同目录其他文件是否使用

### C-06 (P0/P2) 参数声明但函数体内从未使用
- **正确**：用起来或删除
- **特征**：类方法 / 独立函数 / 箭头方法三种形态
- **降级**：刻意保留的签名参数（接口一致性）→ P2 或忽略

### C-07 (P1) 文档未覆盖主要模块
- **判据**：仓库里有大模块（行数占比 >10%）在文档里完全没有章节
- **确认**：模块表 vs 文档目录，逐个对

### C-08 (P1) 注释与代码矛盾
- **判据**：注释说做了 X，代码没做（或做了相反的 Y）
- **确认**：**先确认自己没读错注释**——很多注释是在解释「为什么不能那样写」
- **降级**：注释描述历史行为、代码后来改过 → P2，改注释即可

### C-09 (P1) 同名常量清单重复定义且已分叉
- **判据**：同一语义的清单（变量白名单、主题变量表、命令列表）在两处各定义一份，内容不同
- **确认**：diff 两份清单，确认哪份是权威来源
- **典型**：`host.js` 的 `THEME_VARS` 与 `themes.js` 的 `THEME_VARS` 已分叉，
  导致插件拿到的主题快照缺一大半变量
- **降级**：**不同插件各自定义同名常量是常态**（取值本就不同）→ 忽略。
  只有**同一区域内**出现不同取值才算分叉

### C-10 (P2) 清单遗漏
- **判据**：CSS/代码里定义了某变量，但主题/配置清单里没列
- **后果**：该变量无法被主题覆盖 + 切主题时不会被清理（残留旧值）
- **典型**：CSS 定义了 `--r: 14px`，`THEME_VARS` 只有 `--r-md`

### C-11 (P1) 多订阅者互相顶掉
- **正确**：数组或 Set 存订阅者，`on()` 返回取消函数
- **特征**：`this._onXxx = fn` 直接赋值 → 第二个订阅者顶掉第一个

### C-12 (P1) 成对 API 校验不对称
- **正确**：抽 `private _normalize(raw)`，所有入口共用
- **特征**：`set`/`add`、`register`/`import`、`preview`/`upgrade` 一个有校验一个没有
- **注意**：需两个成员都出现才触发
- **规律**：**后加的便捷入口最容易漏校验**

### C-13 (P2) 死代码 / 重复实现（未被模块声明引用）
- **判据**：源文件存在但未被任何模块声明（`mod`）/ 构建入口引用
- **确认**：动态引用、待启用备份除外
- **定级**：**两份内容近似但已分叉的重复文件最危险**（改了不生效）→ 升 P1
- **典型**：`src/af.rs` 与 `src/fpx/af_flow.rs` 内容近似，`fpx/` 那份是死代码副本

### C-14 (P1/P0) 预览所见 ≠ 实际所执行（确认的是另一件事）
- **判据**：`--dry-run` / 预览 / 二次确认界面展示的**对比基准**，
  与真正执行时用的基准不是同一个对象
- **确认**：分别打印「预览的基准」与「执行的基准」，看是否指向同一版本/同一分支/同一快照
- **典型**：预览跑 `git diff HEAD`（本地快照），推送却以 `base_tree=远端最新` 为底 ——
  远端比本地新时，**用户确认的内容和他推上去的内容不是一回事**
- **同类形态**：预览按本地时间算、执行按服务端时间算；
  预览读缓存、执行读实时；预览单条、执行批量
- **修法**：预览必须与执行共用同一个基准对象；做不到就在预览里**显式标注基准是什么**
- **定级**：用户据此做**不可逆决定**（覆盖、删除、覆盖他人改动）→ **P0**；否则 P1
- **为什么易漏**：两边都「看起来合理」，只有把两个基准并排写出来才看得出分叉

## 文档一致性扫描

```bash
python3 scripts/doc-promise.py --src=<根>                 # 承诺 vs 实现
python3 scripts/doc-promise.py --src=<根> --commands-only # 只查命令是否存在
python3 scripts/doc-deliverable.py --src=<根> --missing-only  # 单元三件套是否齐全
```

三类候选**全部需人工核对**：

1. **命令不存在** —— README 写 `npm run xxx`，package.json 里没有 → 文档说谎
2. **引用文件不存在** —— README 目录树写了某路径，实际没有 → 断链
   （文档常只写文件名不写完整路径，扫描器会按 basename 全仓库兜底找）
3. **数量声明待核对** —— README 说「22 套」，代码里数出 23 → 口径不一致

第 3 类最容易被忽略但最伤人。

## 双实现比对（高产区，C-02 的展开）

存在两套实现时**必须做差异比对**，不能只看其中一条。比对清单：

```
□ 入口文件各自加载了什么
□ 宿主的回调/hooks 各实现了哪些（逐个列，不要凭印象）
□ 扩展的可用能力集合是否一致
□ 配置项是否一致（一套有的设置项另一套没有）
□ 快捷键/命令注册是否一致
□ 状态持久化是否共用同一份存储
□ 构建产物里是否都带上了（硬编码清单最常在这里出问题）
```

**最快的方法**：把两套的钩子实现名单列成两列，逐个 grep 确认。

## 「扩展取不到宿主状态」的三类根因

| 根因 | 判据 | 症状 |
|---|---|---|
| 宿主状态挂在**主窗口**全局对象上 | `window.__XXX__` | 沙箱里取不到 → **静默空** |
| 宿主没在桥接里暴露该能力 | 桥接方法表里没有 | 隔离态下取不到 |
| 上下文快照在挂载时拷贝，之后不更新 | `theme: readTheme()` | 状态变更后读到旧值 |

**「扩展自己另开监听器绕过」是强信号** —— 说明官方通道缺失，看到就该报。

## 常见误报

- **动态引用** —— 注册表、构建配置自动扫描会让静态分析误判为孤儿
- **不同插件各自定义同名常量** —— 见 C-09 降级条件
- **注释解释了为什么那样写** —— 先读注释
- **按栈分流的隐藏** —— 某些条目在特定模式下故意隐藏
