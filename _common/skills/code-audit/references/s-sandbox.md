# 场景：沙箱与权限（s-sandbox）

**触发**：有插件 / 扩展 / 微前端 / 隔离模式 / CSP / 凭据存储 / 外链策略。
**风险**：隔离后能力**静默失效**、被隔离方可自授权、路径黑名单可绕过、密钥离线可推导。

配套文件：`s-sandbox-host.md`（外壳-扩展契约、双实现比对）、
`s-sandbox-security.md`（CSP 合并语义、凭据、外链入口）。

`overlaps:` **只管隔离边界内外的权限与能力**。通道本身的消息格式/握手/超时归 `s-boundary`；
子进程与文件系统的**具体实现**归 `s-backend`；插件代码的数值问题归 `s-numerics`。

---

## 核心判据：隔离切断的是「通道」还是「能力」？

文档通常承诺「隔离 ≠ 断能力」。验证方法：
**在隔离/严格模式下把能力清单逐个跑一遍**，看哪些**静默**失效。

| 能力 | 直连通道 | 桥接通道 |
|---|---|---|
| 调后端命令 | 依赖全局注入 | 应由宿主代执行 |
| 持久化 | 依赖 localStorage | 应存在宿主侧 |
| 事件 | 依赖同文档 | 应由宿主总线中转 |
| UI 通知（标题/角标/提示） | 依赖 DOM | 应由宿主执行 |
| 状态查询（如是否隔离） | 依赖父窗口 | 应由宿主回答 |

**任何一项在隔离后静默失效 = P0**（承诺失效 + 静默）。

## 模式清单

### S-01 (P0) 隔离后能力静默失效
- **判据**：扩展层**绕过宿主上下文**直连底层 API（`@tauri-apps/api`、
  `window.parent`、`__TAURI_INTERNALS__`），而宿主提供的是 `ctx.invoke` / 桥接
- **确认**：开启严格沙箱/隔离 → 该能力是否**静默**失效（无报错、无提示）
- **典型**：插件直连 `@tauri-apps/api/core` 的 invoke/listen，
  开启严格沙箱后 run_node / watch / webhook / fs_op / 读图全部失效且不提示
- **定级**：P0。文档承诺「隔离切断的是直连通道，不是能力」，实际两者都被切断

### S-02 (P0) 桥接无白名单 / 被隔离方可自授权
- **判据**：`ns[method](...args)` 动态取成员后调用，无允许列表；
  或白名单里含**改写自身权限策略**的方法
- **确认**：枚举该模块全部导出，找出能改写安全策略/配置的那几个（如 `savePolicy`）
- **典型**：隔离插件可调用 `pluginConfig` 与 `external` 模块的任意导出 →
  自己把外链策略改成 allow-all、把域名标成 trusted，整个外链治理形同虚设
- **修法**：方法白名单 + `hasOwnProperty` 拦原型链
- **定级**：P0（权限链路的放行）

### S-03 (P1) 扩展读取宿主全局单例
- **判据**：插件里直接读 `window.__XXX__`（挂在**主窗口**上的运行时对象）
- **确认**：该插件是同页挂载还是 iframe 沙箱。iframe → 取不到 → **静默空**
- **典型**：概览页「插件总数 0」、移除按钮点了没反应（可选链不报错）
- **修法**：宿主在桥接里提供 `plugins.list` / `plugins.remove`，扩展优先走桥接、
  失败再降级直连：
  ```js
  if (bridge && typeof bridge.list === 'function') {
    try { return await bridge.list(); } catch {}
  }
  return window.__NEXUS__?.getPlugins?.() ?? [];
  ```
- **降级**：插件是同页挂载（非 iframe）→ 忽略

### S-04 (P0) 安全策略缺失或只覆盖部分入口
- **判据**：有多个入口（多份 HTML / 多套构建配置）但 CSP / 权限配置只写在其中一份
- **确认**：逐个入口查。**注意构建工具的配置是按 JSON Merge Patch 合并而非替换**——
  主配置里的安全项在另一套配置下依然生效，反之要看清谁覆盖谁
- **典型**：主配置 `csp: null`，只有无构建入口的 HTML 里有 CSP meta → Vite 模式裸奔

### S-05 (P1) 路径黑名单未规范化
- **判据**：危险路径用**字符串比较**（小写化 + 去尾斜杠 + `==` / `starts_with`），
  未做 `canonicalize` / 路径归一
- **确认**：构造 `/etc/..`、`C:\Windows\..`、含 `./` 的变体，看是否绕过
- **定级**：保护的是删除/写入这类不可逆操作 → **P0**
- **降级**：保护的是可逆操作 → P2

### S-06 (P0) 命令字符串拼接 / 可执行文件无白名单
- **判据**：`Command::new("cmd").args(["/c", "start", "", url])` 把外部输入喂给 shell；
  或可执行文件完整路径来自用户配置且无白名单
- **确认**：外部输入含 `&` / `|` 时是否被 shell 二次解析
- **修法**：改用官方 opener / 直接 spawn 并传参数数组；路径白名单 + 用户确认

### S-07 (P1) URL / 协议未校验
- **判据**：外部传入的 URL 直接用于导航、iframe src、插件入口
- **确认**：是否校验协议白名单（http/https/mailto）。`javascript:` / `file:` 是否可达
- **典型**：插件入口填外域地址 → 代码来自网络，且能访问宿主数据

### S-08 (P1) 凭据加密密钥可由同存储推导
- **判据**：「免口令」模式的密钥素材（设备特征、随机盐）**全部**存在同一个可被读出的存储里
- **确认**：攻击者拿到存储文件后能否离线复现密钥。能 → 加密只防「随手打开 DevTools 看一眼」
- **典型**：`deviceSalt` 也存在 localStorage → 整条链可离线复现
- **修法**：盐由原生侧生成并存在应用数据目录；或首次使用时引导选口令模式
- **降级**：文档已明确说明该模式的防护边界 → P2

### S-10 (P0) 敏感数据进日志 / 遥测
- **判据**：日志、埋点、错误上报的字段里出现凭据或 PII ——
  `password` / `token` / `secret` / `api_key` / `authorization` / `session_id` /
  `身份证` / `手机号` / `邮箱`
- **确认**：该日志是否落盘或上报到第三方。**落盘即长期泄露**，
  比内存泄露更严重——日志会被采集、备份、同步到日志平台，删除成本极高
- **典型**：`logger.info("user login", extra={"password": pw})` ——
  排障时确实方便，但整条凭据进了日志系统
- **修法**：脱敏（只留前 4 位 / 哈希）、或整个字段移出日志
- **注意**：**关键字名本身也要查**。`logger.info("login", password=pw)` 里
  敏感信息在 **arg** 上而不在 value 上，只看变量名的扫描器会漏
- **各语言形态**：Python 见 `p-python` PY-06

### S-11 (P0) 行级 / 对象级授权缺失（越权访问）
- **判据**：数据访问路径只在入口做一次身份校验，**后续每次取数不重复执行**
  tenant / owner 过滤
- **确认**：把 URL 里的资源 id 换成别人的，看能否读到。能 → 水平越权
- **典型**：`GET /api/orders/{id}` 只校验"已登录"，没校验"这个订单属于当前用户" →
  改个 id 就能看别人的订单
- **修法**：在数据访问层统一加租户/归属过滤，而不是在每个 handler 里各写一遍
- **为什么易漏**：入口鉴权确实存在，测试也通过——没人会想到换 id

### S-12 (P1) 密钥无轮换 / 撤销能力
- **判据**：密钥写死在配置或代码里，没有版本号、没有轮换入口、没有吊销机制
- **确认**：密钥泄露后，能否在不发版的情况下让它失效。不能 → 事故响应时间以"天"计
- **降级**：文档已明确说明该模式的防护边界与轮换流程 → P2

### S-09 (P1) 隔离态自报数据未被接上
- **判据**：宿主在隔离态下采样不到子文档，设计了「子方自报 X」机制，
  但宿主构造下游入参时**没有带上 X 字段**
- **确认**：从自报消息的接收处一路跟到消费处，看字段是否传到底
- **典型**：`reportedBase` 自报了，但 `adaptInput` 构造时没写进去 →
  判定基调一致 → 不反转 → 深色面板上一块刺眼的白，**且不报错**
- **定级**：P0（静默且对外承诺失效）

## 静默失败清单（整机审查最易漏）

以下写法让缺陷不报错，用户侧只表现为「点了没反应」。
**审查时把它们全列出来逐个问一句：有值时才执行，没值时会发生什么？**

- 可选链兜底：`window.__X__?.method?.()` —— 取不到就不执行
- 空 catch：`catch {}` / `catch { /* ignore */ }`
- 降级返回 null 后调用方不再检查
- 能力探测失败后不再重试（`_cached = null` 后永不重试）
- 采样失败后按「默认一致」处理

## 桥接服务端五查

桥接服务端跑在**宿主侧**，是权限的关键收口点：

1. **方法白名单** —— 动态派发必须配允许列表 + `hasOwnProperty` 拦原型链
2. **能否自授权** —— 白名单里是否含策略写入方法
3. **参数校验** —— 命名空间、方法名、参数类型
4. **返回值过滤** —— 函数/Symbol 等不可结构化克隆的字段（否则整条响应抛错）
5. **错误不泄密** —— 异常信息是否回显路径/堆栈

## 诚实边界

**JS 层做不了真正的拦截**（拦不住 `<img>` / `<video>` 发起的请求）。
看到代码声称「在 JS 层拦截外链」→ 报**虚假安全感**（P1）。
正确形态是「看得见、管得了、记得住」+ 生成建议 CSP 由用户落盘。

## 常见误报

- **注释解释了为什么不能那样写** —— 如「这里不能回发 ready，会互等死锁」
- **动态引用** —— 注册表、构建配置的自动扫描会让静态分析误判为「孤儿文件」
- **按栈分流的隐藏** —— 某些条目在特定模式下**故意**隐藏（如无构建模式隐藏 React 插件）
- **本地工具的路径穿越不做限制** —— 可免责，但需确认文档写明
