# 场景：架构可演进性（s-architecture）

**触发**：单文件过大 / 单函数过长 / 工具型脚本（有 CLI 且有持久化状态）/ 多层防护型代码。
**风险**：缺陷不是「跑错」，而是**「下一次修改必然出错」**——
防护静默失效、测试全量返工、跨实例串档、自动化无法分流。

`overlaps:` **只管「结构是否允许安全地改」**。
多步写的**运行时一致性**归 `s-atomicity`；持久化**内容**的正确性归 `s-state`；
对外**声明**与实现是否一致归 `s-contracts`；Python 语义特有的进程内竞态归 `p-python`。

---

## 核心判据：改不动就是缺陷

其余风险面都问「**运行时行为对不对**」；本场景问另一件事：

> **这段代码下一次被修改时，有没有机制阻止改错？**

判据一句话：**加一段 / 删一段 / 调换相邻两段，会有什么东西报警？**
答「只能靠读注释」→ 命中。

这类缺陷在单次走查里看不出来（当前行为完全正确），
只有在**下一次改动**时才爆发，且爆发形式是静默失效——
所以它必须在架构层被点名，而不是等它变成行为缺陷再报。

## 模式清单

### AR-01 (P1) 判定逻辑与输出 / 副作用耦合
- **判据**：承担判定职责的函数内部直接 `print()`；`SystemExit` / `sys.exit` 从**非 CLI 层**抛出；判定结果不通过返回值或结构体向外传递
- **确认**：
  ① 数**非入口模块**里的 `print(` 数量
  ② grep 非 CLI 层的 `SystemExit`，看错误是不是就地终止而非向上传递
  ③ 试着 `import` 该模块当库调用，看是否必须重定向 stdout 才能用
- **典型**：`validate_state()` / `_write_local()` 深处直接 `SystemExit(str)`；
  340 处 `print` 散布在 `pull()` / `prune()` 等 300+ 行的领域函数里
- **后果**：不可当库调用 · 无法 `--json` / `--quiet` · **测试只能抓 stdout 断言**
  → 改一句提示文案测试就红、重构动一处全局就要全量改测试。
  实测某工具 8732 行测试全部依赖 `mod.GLOBAL = ...` 打补丁 + stdout 字符串匹配
- **修法**：判定返回结构（`Verdict` / `Plan`），输出集中到 ui 层；
  错误用**带码**的异常类型，顶层统一转成退出码（见 **AR-04**）
- **与 A-23 的分界**：A-23 讲报错**措辞**（说了但没说清）；
  本条讲**位置与通道**（在哪说、以什么形式说出去）
- **定级**：P1；若导致**关键判定路径无法被测试覆盖** → **P0**

### AR-02 (P1) 多层防护的执行顺序无机制保障
- **判据**：≥3 层防护是同一函数内的**顺序代码块**，层与层的先后是语义的一部分，
  而该约束**只以注释形式存在**（源码出现「必须在 X 之前 / 之后」字样）
- **确认**：
  ① 数防护层数，与注释里「必须在…之前」的顺序约束条数
  ② **把相邻两层调换，看有没有测试变红** —— 不变红即顺序无保障
  ③ 设想新增一层：是否有任何机制阻止你放错位置
- **典型**：某推送工具 5 层防护（本地回退检测 / 副本过期 / 文件级基线 /
  ref 乐观锁 / 合并前基点校验），注释写明
  「未解决冲突拦截必须在 P0-1 之前」「回退检测必须在写 `synced_commit` 之前」，
  两者均无代码机制保障
- **后果**：新增或调换一层 → **防护静默失效**，且没有任何测试会发现。
  失效的表现正是这类防护型代码最想消灭的「静默」
- **修法**：抽 Guard 管线，顺序写成显式列表 `GUARDS = [...]`，
  每层可独立 `import`、独立单测；短路规则也写在列表逻辑里
- **与 `common-manual-review.md` 第 8 项的分界**：那条查**路径**
  （放行参数组合 / 拦截后能否走出来 / 终态对象复用）；本条查**顺序**。互补
- **定级**：P1；当失效会直接导致数据丢失 → **P0**
- **降级**：层数 ≤2 且有测试覆盖顺序 → P2

### AR-03 (P1) 跨实例 / 跨仓库状态串档
- **判据**：状态文件路径是**被操作目录之外的固定绝对路径**；
  且操作目标（owner / repo / root / branch）是**模块级常量**，
  无 CLI 参数、无环境变量可覆盖
- **确认**：
  ① 状态文件路径是否落在被操作目录之外
  ② **同一台机器对两个不同目标各跑一次**，看状态是否互相覆盖
  ③ 该常量有没有参数能改 —— 没有即换目标只能改源码
- **典型**：`STATE_PATH = "/data/workspace/.push-sync.json"`（在被操作仓库之外）
  配合 `OWNER, REPO = "...", "tauriTools"`、`ROOT = "/data/workspace/tauriTools"`；
  而该文件所在仓库叫 `push-api-tools`，常量指向的是**另一个仓库**
- **后果**：多仓库 / 多实例共用一份状态 → 交叉污染，
  且换目标只能改源码（把工具变成一次性脚本）
- **修法**：状态默认落在**目标内**（`<root>/.git/<tool>.json`）；
  目标收进 `Config` 显式传递，优先级 CLI > 环境变量 > 配置文件 > 默认值
- **与 PY-08 的分界**：PY-08 是「模块级**可变**全局被改」→ 进程内竞态，修法是**加锁**；
  本条是「状态文件**放错位置**」→ 跨实例串档，修法是**改默认路径**。
  两者可同时命中但修法完全不同，**不要合并**
- **与 C-15 的分界**：C-15 是「报错建议了不存在的操作」；
  本条是「默认路径本身就会串档」
- **定级**：P1；私有仓库 / 一台机器推多个项目 → **P0**

### AR-04 (P2) 退出码不分类（生产者侧）
- **判据**：CLI 的**所有**失败路径返回同一个退出码
  （Python 常见形态：到处 `SystemExit(str)` → 恒为 1），
  没有「被防护拦下」/「参数错误」/「外部依赖失败」的区分
- **确认**：
  ① grep 所有 `SystemExit` / `exit(` ② 统计不同退出码有几种
  ③ 在 CI 里能否仅凭退出码区分「照提示做即可」与「真出错」
- **典型**：某工具退出码恒为 1，只有 Ctrl-C 是 130
- **后果**：自动化无法分流。最危险的是把
  **「被拦下（改动未丢，照提示做即可）」当成错误**——
  重试和放弃两种反应都是错的
- **修法**：定义码表并写进 `--help`：
  `0` 成功 / `2` 被防护拦下 / `3` 冲突未解决 / `1` 错误 / `130` 中断
- **与既有「退出码」条目的分界**：`s-atomicity` / `s-backend` / `s-concurrency` 里
  的 4 处退出码讲的是**消费者侧**——「调用外部命令后要检查它的退出码」；
  本条是**生产者侧**——「你自己要分类自己的退出码」。方向相反，不重复
- **定级**：P2；若该工具被 CI 或别的脚本调用 → **P1**

### AR-05 (P1) 测试自建 harness，断言焊在实现与输出上
- **判据**：不用测试框架（无 `import pytest` / `unittest`）；
  以子进程跑脚本 + stdout 出现 `ALL PASS` 判定通过；
  用 `mod.X = ...` 打补丁替换**模块级全局**；断言靠字符串包含；
  **某个 `test_*.py` 被其他套件 import 当共享库用**
- **确认**：
  ① 有没有 import 测试框架 ② 通过判定是不是 `if "ALL PASS" in out`
  ③ **改一句提示文案看是否变红**（变红 = 断言焊在输出上）
  ④ 是否用 `mod.GLOBAL = ...` 注入（是 = 焊在实现上）
- **典型**：17 个 `test_*.py` / 8732 行 / **0 pytest**；
  `run_all.py` 靠 `"ALL PASS" in out` 判定；
  `test_pr_flow.GH` 被 14 个套件 import 当 fixture 库
- **后果**：**债务放大器** —— 它让「该做的重构」看起来永远不划算，
  于是架构债只增不减；且「全绿」可能是压根没测到
  （与 `common-maintenance.md` 的空变异同类：假信号比没信号更糟）
- **修法**：`conftest.py` 提供 `fake_remote` / `tmp_repo` fixture，
  在**边界层**（Remote / Config）注入而非 patch 模块全局；断言结构化返回值
- **与 `common-maintenance.md` 变异纪律的分界**：那条讲**变异定义怎么写**
  （`NOT_APPLIED` vs `SURVIVED` 要分开）；本条讲 **harness 形态**。互补
- **定级**：P1

## 本场景的扫描边界

AR-01 / AR-03 / AR-04 / AR-05 有文本特征，可机扫（`scan-py.py` / `scan-app.py`）；
**AR-02 机扫做不到** —— 判断「顺序是否只靠注释约束」需要读懂语义，
`rules/gaps.json` 已标记为 `manual`，不要纠结要不要给它写规则。
