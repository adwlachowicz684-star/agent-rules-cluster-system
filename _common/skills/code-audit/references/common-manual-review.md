# 人工精审 7 项清单

模式扫描器只能找出「形状已知」的缺陷。以下 7 项**必须人工读代码**。

## 1. 单元特有算法的正确性

算法语义只能靠读。按领域对照该领域的经典陷阱：

| 领域 | 检查点 |
|---|---|
| 搜索 / 图算法 | closed 集存的是节点还是布尔（存布尔会导致第二次查询永远返回空） |
| 空间索引 | 格子登记与实际位置是否同步（移动后是否漏检）；空桶是否回收 |
| 视野 / 光照 | 八分体符号是否写反（表现为圆形变菱形） |
| 量化 / 位运算 | 写入与读取的量化方式是否一致（floor 算、round 写 → 边界抛错） |
| 插值 / 缓动 | t=0 与 t=1 边界、非有限输入、dt=0 特殊处理 |
| 堆 / 优先队列 | 惰性删除时 size 与 pop 语义是否一致 |
| 对象池 | 是否校验对象归属；prewarm 是否有界 |
| 随机 / 采样 | 负数量、超数量是否按预期处理 |

**怎么查**：先列出该领域的已知陷阱，逐个问「这里有没有」。

## 2. 数值语义的方向

符号写反最难发现——不报错，只是「感觉不对」。

- **抗性 / 易伤**：正数到底是减伤还是加伤？上下限是否对称？上限必须 < 1（否则无敌）
- **难度自适应**：玩家表现好 → 难度该升还是该降？
- **评分**：跑得快是高分还是低分？`par` / `zero` 的方向
- **转化率**：数值指标算「已转化」还是「未转化」？
- **交易**：数量符号、价格符号、退款方向

**怎么查**：拿一个具体数字心算一遍，看结果是否符合直觉。

## 3. 文档与代码的三处对照

逐条比对，任何一处不符都是缺陷：

| 位置 | 查什么 |
|---|---|
| README 的 API 表 | 签名（参数个数、类型、返回值）是否与源码一致 |
| JSDoc 的代码示例 | 示例里的调用方式能否编译通过 |
| README 的「坑」表 | 描述的机制在源码里是否真的实现了 |

**三种从严情形**：

- 文档与实现不一致 → 默认 P1（「写错的文档比没文档更糟」）
- **文档把缺陷记为设计意图 → 默认 P0**（会阻止下一个人修复）
- **注释声称「只影响观感」但实际影响逻辑 → P0**
  （典型：注释说随机抖动只影响表现，实际参与了 AI 状态累积）

**怎么查**：把 README 的示例代码原样粘进探针跑一遍。

## 4. 时间单位一致性

全库 `dt` 用秒还是毫秒？混用是灾难（差 1000 倍，不报错）。

- 配置里的 `durationMs` vs 代码里的 `dt`
- 单元内部是否自相矛盾（一处用秒一处用毫秒）
- 与相邻单元口径是否一致
- 角度单位：度 vs 弧度是否混用

## 5. 形状与坐标语义

- **Y 轴方向**：屏幕坐标向下、世界坐标向上，转换在哪一层做？
- **起点在内部**：射线起点在盒内/圆内算 hit 还是 miss？
  同一入口下两种形状语义必须一致
- **角度基准**：0 度朝哪？顺时针还是逆时针？
- **矩形表示**：min/max 是数值大小还是「左下/右上」？
  （y 轴翻转时这两者是矛盾的）
- **边界包含**：相切算重叠吗？不同实现的 `<` / `<=` 是否一致？

## 6. 依赖合规

目标若是「每个单元可独立拷走」：

- 只 import 基础设施目录与同目录文件
- 标出横向依赖（模块 → 模块），它们破坏可拷贝性
- 确认基础设施不被反向依赖
- 文件名是否全局唯一（嵌套/扁平化时会不会撞车）
- 有无 index 桶文件（有则移动后可能断链）

注意：注释里的 import 示例不算依赖。

## 7. destroy 幂等与生命周期

- 有 `destroy()` 吗？销毁后状态标记了吗？
- 销毁后仍调用会怎样？（应早退或报错，而不是静默工作）
- 事件监听器 / 定时器 / 节点引用是否全部释放？
- 同类对象成对出现时，一个有 `destroy()` 另一个没有 → 是缺陷
- 长期运行的结构是否会积累空容器（空桶、已删句柄、过期指纹）

## 精审节奏

1. **先看 README** —— 它说明作者认为这个单元解决什么问题
2. **再看测试** —— 没有测试 = 所有缺陷裸奔；有测试也要看**覆盖了哪些输入**
3. **然后读源码** —— 带着「作者声称的能力是否真的实现了」这个问题
4. **最后写探针** —— 把怀疑的点跑出来，不靠推理下结论

## 关于「看测试」的经验

**先看「有没有测试」比先读代码更高效**，但判断不止于此：

- 无测试的核心单元，一次审查可发现多个缺陷，且全部无单测覆盖
- **有测试但只覆盖正常路径，同样会漏掉全部对抗性边界**。
  某库 3,451 项测试全绿，人工精审仍发现 39 个 P0

所以看测试时要问：**它测了 NaN 吗？测了原型键吗？测了负数数量吗？**
没测的，就是要重点精审的地方。
