# 严重度定级

## 三级定义

| 级别 | 定义 | 判据 |
|---|---|---|
| **P0** | 对外承诺完全失效 / 崩溃 / 泄漏 / 安全放行，且**静默**（不报错） | 必须修，阻断发布 |
| **P1** | 边界条件错误、契约不一致、能力在部分模式下失效、文档说谎 | 应该修 |
| **P2** | 一致性、可维护性、体验问题 | 可选，视返工成本 |
| **P3** | 加固/优化建议 | 有空再说 |

## 附加标记

| 标记 | 含义 | 何时用 |
|---|---|---|
| **regression** | 修复 A 时引入 B | 修复复核场景；**一律按 P0 下限处理** |
| **praise** | 实现得当、值得保留 | 写进「验证过没问题的部分」 |
| **pre-existing** | 本次未改动但已存在的老问题 | 与新增问题分开计数 |
| **unverified** | 静态分析得出，未实测 | **必须标注**，不得伪装成已验证 |

## 采纳的硬门槛（三件套缺一不可）

1. **行号** —— 精确到 `<文件>:<起止行>`
2. **证据** —— 实测输出，或可验证的推导链
3. **后果** —— 什么场景下暴露、表现为什么症状

**说不出后果的问题不成立** —— 通常意味着它不是真问题，或没想清楚。

## 8 条升级规则（满足任一即定为 P0）

1. **安全 / 权限链路的「放行」** —— 空口令放行、黑名单可绕过、桥接无白名单、
   CSP 缺失、自授权
2. **静默失效** —— 不报错、不提示，用户侧表现为「点了没反应」
3. **对外承诺完全失效** —— 文档声明的能力根本没接线（孤儿组件、缺回调）
4. **文档把缺陷记为设计意图** —— 会阻止下一个人修复
5. **不可逆的状态污染 / 数据损坏** —— 误删关键路径、存档写坏、配置被自己改写
6. **资源无上限** —— 可被外部输入触发的 OOM / 线程耗尽 / 无限递归
7. **随运行时长累积的泄漏** —— 测试期看不出，上线后崩
8. **隔离/严格模式下能力失效** —— 且文档承诺「隔离不断能力」

## 三个反问

### 1. 它会报错吗

**不报错的缺陷比报错的严重。** 抛异常至少能被发现、能捕获、有堆栈。
静默返回错误结果的问题往往在生产环境潜伏很久。

整机审查里最常见的静默源：可选链 `?.`、空 `catch {}`、降级返回 `null`、
采样失败按默认值处理。

### 2. 用户会不会遇到

- 正常路径必然遇到 → P0
- 特定配置/模式才遇到（如开启严格沙箱、切到浅色主题）→ P0（若静默）或 P1
- 只有极端边界才遇到（10GB 文件、跨设备移动）→ P1

注意「特定配置」的广度：**文档里写了开关，就一定会有人打开**。

### 3. 能恢复吗

- 重启模块能恢复 → 轻一档
- 必须清空数据 / 重装 → 重一档
- 数据已永久损坏 → P0

## 文档类问题的判据

| 情形 | 定级 | 理由 |
|---|---|---|
| 文档与实现不一致（数量、默认值、清单） | **默认 P1** | 写错的文档比没文档更糟 |
| 文档声称的能力完全没接线 | **P0** | 对外承诺完全失效 |
| **文档把缺陷记为设计意图** | **P0** | 它会阻止下一个人修复 |
| 文档未覆盖主要模块 | P2 | 接手成本高，但不阻断 |
| 注释与代码矛盾 | P1 | 会误导下一次修改 |

## 性能问题

- O(n²) 且 n 有上限（几十）→ P2
- O(n²) 且 n 可配置到 1e7 → P0（可被配置触发卡死）
- 每帧/每次调用分配数组 → P2，除非在热路径
- 固定 sleep 轮询 → P2，若串起来造成可感卡顿（>1s）→ P1

## 扫描候选的降级

模式扫描给出的是候选，确认后按实际影响定级。常见降级：

| 模式 | 降级条件 |
|---|---|
| J09 只注册不注销 | 生命周期与页面/应用等长（主窗口 keydown）→ P2 或忽略 |
| J10 无清理 | 定时器在卸载钩子里有 clear，但写法是间接引用 → 忽略 |
| J12 innerHTML 拼接 | 拼接内容全为内部常量/数字 → 忽略 |
| J07 直连底层 API | 该模块确实只在非隔离模式运行且有注释说明 → P2 |
| J08 读宿主全局 | 插件是同页挂载（非 iframe）→ 忽略 |
| R02 lock unwrap | 锁不可能被污染（单线程、无 panic 路径）→ P2 |
| R05 路径黑名单 | 保护的是可逆操作（非删除）→ P2 |
| R10 rename 无回退 | 目标路径保证同卷 → 忽略 |
| A08 孤儿文件 | 是动态引用 / 待启用备份且有注释 → 忽略 |

## 驳回清单（提高审查信噪比）

遇到以下情况不要报：

1. **证据不足** —— 只有推理没有实测。先写最小复现跑一遍
2. **这其实是设计意图** —— 大量「看起来像 bug」的写法都带长注释解释原因。
   **没读注释就报问题是最高频的误报来源**
3. **后果不成立** —— 理论上存在但触发路径不存在（内部私有方法、参数已在上游夹紧）
4. **重复劳动** —— 报了已审结的地基模块或已知全局问题
5. **超出范围** —— 本轮只审不改；「顺手重构」一律不做
6. **风格偏好** —— 命名、格式、架构口味，不构成缺陷

## 定级输出格式

```markdown
| 等级 | 数量 |
|---|---|
| P0 | 3 |
| P1 | 12 |
| P2 | 20 |
| P3 | 4 |

### P0-1 · <一句话>         [unverified 标注在正文]
### P0-2 · <一句话>  [regression]
### P2-x · 可表格化，不必逐个展开
```
