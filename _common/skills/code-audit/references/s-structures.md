# 场景：数据结构与内存（s-structures）

**触发**：TypedArray / 对象池 / 分桶 / 裸对象查表 / 惰性删除 / 路径与 key 编码。
**风险**：原型污染、空桶长期泄漏、尺寸未收口 OOM、删除索引错位、key 碰撞静默合并。

配套：`s-structures-fix.md`（修法）。

`overlaps:` **只管容器与索引本身的结构正确性**。容器里元素的生命周期归 `s-lifecycle`；
元素参与数值运算归 `s-numerics`；序列化格式的版本兼容归 `s-state`。

## 模式清单

### D-01 (P0) 外部键查表命中 `Object.prototype`
- **正确**：`new Map()` / `Object.create(null)` / `Object.hasOwn(T, k)`
- **特征**：`TABLE[k]` 或 `k in TABLE`
- **危险键**：`toString` / `constructor` / `__proto__` / `valueOf` / `hasOwnProperty`
- **确认**：key 是否可能来自外部输入（存档、网络、配置）

### D-02 (P1) 用 `{}` 字面量累加计数
- **正确**：`new Map<string, number>()`
- **特征**：`const x = {}` 后 `x[key] +=`
- **失效**：key 为 `__proto__` 时丢失

### D-03 (P1) 合并外部对象触发 `__proto__` setter
- **正确**：过滤 `__proto__` / `constructor` / `prototype` 后再合并
- **特征**：`Object.assign(` / `...spread` 涉及 JSON / import / state

### D-04 (P0) 路径写入未过滤危险段（原型污染）
- **正确**：解析后拒绝 `__proto__` / `prototype` / `constructor` 段，只在自有容器写入
- **特征**（三种写法都要覆盖）：
  ① `str.split('.')` ② 正则 `/([^.[\]]+)|\[(\d+)\]/g` ③ `parsePath` 类函数
- **为什么**：不可信存档/网络差量可**改写进程级对象行为**
- **注意**：只扫 split 会漏掉正则实现

### D-05 (P0) 批量删除未降序
- **正确**：同一父数组多个索引必须**按索引降序** splice
- **特征**：循环内 `splice` 且上下文无 `sort` / `reverse`
- **失效**：`['a','b','c']` 删 [1] 与 [2]，先删 1 后原 [2] 移到 [1]，
  结果 `['a','c']` 而非 `['a']`
- **注意**：**按路径深度排序不足以处理同层多删**

### D-06 (P0) 路径协议不可逆
- **正确**：JSON Pointer（RFC 6901）或带转义 token 数组
- **特征**：路径解析 + patch 应用同时存在
- **失效**：`{'a.b':1}` 往返一次变成 `{'a.b':1, a:{b:2}}`，
  合法 JSON 键被静默改造成另一棵树

### D-07 (P0) 复合 key 未编码
- **正确**：长度前缀编码/转义，或结构化 tuple / 嵌套 Map
- **特征**：`join('|')` 拼 key 或模板字符串 `${a},${b}`
- **失效**：`{a:'1,b=2'}` 与 `{a:'1', b:'2'}` 生成同一 key →
  两个维度写入同一项，数值静默合并

### D-08 (P0) TypedArray / 大数组尺寸未收口
- **正确**：有限正整数 + **总元素量上限**
- **特征**：`new Array(x)` / `new Float32Array(x)`，x 非字面量且附近无 clamp
- **为什么 P0**：错误不在 API 边界报出，而是传导到底层 `RangeError` 或瞬时 OOM，
  **诊断信息完全指向不了配置字段**
- **特别检查**：宽高相乘（两个都合法但乘积极大）

### D-09 (P1) 惰性删除 size 语义不一致
- **正确**：维护有效计数，`remove` 幂等
- **特征**：`LazyHeap` / tombstone + `get size` / `get isEmpty`
- **失效**：`size` 返回物理条目数但 `pop()` 返回 undefined →
  以 isEmpty 驱动的循环与 pop 不一致

### D-10 (P0) 分桶不回收空桶
- **正确**：删除元素后若 `bucket.size === 0` 同步删 Map key
- **特征**：`new Map()` 分桶字段有 `.delete(` 但全文无 `.size === 0`
- **为什么 P0**：开放世界持续移动会**长期积累空桶**，难以察觉的内存泄漏
- **注意与 D-11 是反向同类**：D-10 删元素不删空桶，D-11 删桶不清内容

### D-11 (P1) 容器摘除未清内容
- **正确**：删除 `Map<K, Set<V>>` 条目时先 `set.clear()`；
  `map.clear()` 前先遍历 clear 各内部容器
- **特征**：`_map.delete(k)` / `map.clear()` 附近无 `clear()`
- **确认**：**是否存在闭包持有容器内条目**（`on()` 返回的取消函数、
  暴露迭代器、直接返回容器）—— 无持有途径则 delete 后可 GC，是误报
- **降级**：摘除时容器已空（同行有 `.size === 0` 判断）→ 忽略

### D-12 (P0) 对象池三类缺陷
- **正确**：
  1. `put()` 拒绝非本池借出的对象（扣减 active 必须以归属为前提）
  2. `active` 不得为负
  3. `prewarm` 必须有限整数上限
- **特征**：`prewarm()` 无上界收口 / `active--` 无 `Math.max(0,...)` /
  `put()` 里 active 扣减**直接写在方法体**（花括号深度 1，不在任何 if 内）
- **确认**：实测 `get 3 个 → put 5 个外部对象 → active 被刷成 0`
- **⚠ 注意**：不能用「有没有 `has()`」判归属——重复归还拦截也用 `has()`，
  但它查的是「是否已空闲」，方向与归属相反（**实测会漏掉只有重复拦截的池**）

### D-13 (P1) spread 展开不定参数
- **正确**：循环归约
- **特征**：`Math.max(...arr)`
- **失效**：参数量大时 `RangeError`。**AST 深度限制挡不住**——深度很浅但参数很多

### D-14 (P1) 容量类字段无上限
- **正确**：`clampNum` 收口 + 超限裁剪
- **特征**：`_log` / `_history` / `_seen` / `_cache` 容器全文无 `shift` / `splice` / `clear`

### D-15 (P1) 嵌套全量扫描 O(n²)
- **正确**：预建索引
- **特征**：`filter` / `map` 回调内调用 `this.get()` / `indexOf` / `includes`

### D-16 (P1) 返回内部可变引用
- **正确**：返回副本 `[...arr]`，或文档明确标注
- **特征**：`return this._x;` 无 `.slice()`
- **降级**：文档已明确标注「返回内部引用，勿持有」→ P2

### D-17 (P0) 递归无访问集 / 深度上限
- **正确**：传访问集或深度上限
- **特征**：**普通函数自递归**与**方法自递归**两种形态都要检
- **确认**：深度是否由数据决定（子表互引用、嵌套树）→ 是则必改
- **失效**：互相引用 → 栈溢出

## 验证方法

| 模式 | 最小复现 |
|---|---|
| D-01~04 | 喂 `toString` / `__proto__` / `constructor` 作为 key 或路径段 |
| D-05 | `['a','b','c']` 删索引 [1,2]，看结果 |
| D-06 | `{'a.b':1}` 序列化往返一次，比对前后 |
| D-07 | 构造两个不同对象生成同一 key，看是否静默合并 |
| D-08 | 传 `1e9` 或宽高各 `1e5` |
| D-10 | 持续增删 1e5 次，观察 Map.size 是否单调增长 |
| D-12 | `get 3 → put 5 个外部对象 → active 应仍为 3 而非 0` |
| D-13 | 构造 1e6 长度数组传给 `Math.max(...arr)` |

## 常见误报

- **D-11 无闭包持有途径** —— delete 后可 GC，是误报
- **D-11 摘除时容器已空** —— 同行有 `.size === 0` → 忽略
- **D-16 文档已标注** —— 降级 P2
- **D-15 n 有上限（几十）** —— 降级 P2（见 `common-severity.md` 性能判据）
- **D-01 key 来自固定枚举** —— 忽略
