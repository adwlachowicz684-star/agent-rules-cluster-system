# Godot 4.x 3D 与渲染 API 审查报告

## 摘要

本报告面向 Godot 4.x 语言包/静态扫描器，选取六类高频、易误用的 3D 渲染 API 共 48 项，给出 GDScript/C# 签名、用途、误用、可正则匹配特征、运行时验证手段与置信度。核心结论是：局部与全局空间不是“同一变量两套名字”，而是父子关系下的派生关系；`global_position` 可读可写，但写入不免除父子变换重建，连续帧赋值仍可能被动画、物理或父节点覆盖。材质默认按资源共享，`material_override` 赋同一个资源会让改动跨实例传播；需要逐实例变化时必须 `duplicate()` 或使用实例参数。环境效果默认几乎全部关闭，`Environment` 没有“自动 GI”。`SubViewport` 的 `size` 在父 `SubViewportContainer.stretch=true` 时禁止手动改变；粒子 `local_coords`、固定步长与 `visibility_aabb` 则会直接导致“运行时不渲染”而非报错。[1][7][9]

## 一、Node3D 变换：空间层级而非坐标别名

Node3D 的 API 审查不能停留在“是否赋值”，而应检查赋值发生在哪个坐标系、哪个回调以及变换链是否会重算。`position` 是父空间平移；`global_position` 是全局平移，也等于 `global_transform.origin`。`transform` 与 `global_transform` 分别是父空间和全局空间的完整 Transform3D；`basis` 保存父空间旋转、缩放与剪切；`quaternion` 是父空间四元数旋转。`rotation_order` 默认 2，即 YXZ，欧拉角按本征顺序解释。[1]

### `Node3D.position`
- **签名**：`node.position = Vector3(...)` / `node.Position = new Vector3(...)`
- **用途**：在父节点坐标系内设置局部平移。
- **误用**：把目标的世界坐标直接赋给 `position`，结果随父节点旋转、缩放和位置变化；未检查父节点是否存在时，预期位移与最终世界位移不一致。
- **判据**：GDScript 正则 `\.position\s*=`；C# 正则 `\.Position\s*=|set_position\s*\(`。优先排除 `global_position` 与 `.origin`。
- **确认**：设置后打印 `global_position`，并旋转父节点观察是否按世界方向偏移。
- **置信度**：官方明确。

### `Node3D.global_position`
- **签名**：`node.global_position = Vector3(...)` / `node.GlobalPosition = new Vector3(...)`
- **用途**：按世界坐标放置节点；读取时直接获得当前世界平移。
- **误用**：在 `_physics_process` 连续覆盖世界位置，随后又被 CharacterBody3D/MoveAndSlide、动画、RemoteTransform3D 或父节点重算覆盖；节点尚未进入场景树时读取会失败并返回零向量。它不是“绕过物理的永久钉住”。
- **判据**：`\.global_position\s*=`；检查是否在 `_physics_process`、`_integrate_forces`、AnimationPlayer 回调或父变换更新之后重复赋值。
- **确认**：在该帧 `RenderingServer.frame_post_draw` 后采样世界坐标，同时打印 `get_physics_process_mode()` 与父节点列表；不同帧发生回弹即可确认覆盖链。
- **置信度**：官方明确。

### `Node3D.transform`
- **签名**：`node.transform = Transform3D(...)` / `node.Transform = new Transform3D(...)`
- **用途**：一次性设置局部平移、旋转、缩放/剪切。
- **误用**：从 `global_transform` 直接复制后赋值给 `transform`，以为结果仍在同一世界位置；只修改 `transform.origin` 而保留旧 basis，父缩放会累积到局部空间运动。
- **判据**：`\.transform\s*=|global_transform\b.*transform\b|Transform3D\s*\(`。
- **确认**：对比赋值前后 `global_transform`；断言允许误差内相等，并分别检查平移与 basis。
- **置信度**：官方明确。

### `Node3D.global_transform`
- **签名**：`node.global_transform = Transform3D(...)` / `node.GlobalTransform = new Transform33D(...)`
- **用途**：按世界空间设置完整仿射变换。
- **误用**：与 `global_position` 一样，写入只改变本次变换链计算；下一物理步、父变换改变或节点重排后可能失效。直接操作 3×4 矩阵而不正规化，还可能留下剪切和负缩放。
- **判据**：`\.global_transform\s*=`；检查是否伴随 `basis.orthonormalized()` 或正交化逻辑。
- **确认**：设置后读取 `global_transform` 与 `global_position`，下一帧再读一次；若在不动代码处仍变化，追溯父节点通知与物理覆盖。
- **置信度**：官方明确。

### `Node3D.basis`
- **签名**：`node.basis = Basis(...)` / `node.Basis = new Basis(...)`
- **用途**：设置父空间旋转、缩放和剪切；适合保持局部位置不变时改变朝向。
- **误用**：缩放或剪切矩阵接近奇异时，欧拉角往返会失真；只改 `basis` 却预期世界法线不变，父节点缩放仍会参与最终法线变换。
- **判据**：`\.basis\s*=|Basis\.FromEuler|Basis\.FromScale`。
- **确认**：打印 `basis.determinant()`，检查绝对值过小；同时查看非均匀缩放与法线渲染。
- **置信度**：官方明确。

### `Node3D.quaternion`
- **签名**：`node.quaternion = Quaternion(...)` / `node.Quaternion = new Quaternion(...)`
- **用途**：用四元数设置父空间旋转，适合球面插值。
- **误用**：使用非单位四元数导致隐含缩放或扭曲；从欧拉角构造时顺序与 `rotation_order` 不匹配，视觉结果不同。
- **判据**：`\.quaternion\s*=|new Quaternion\(|Quaternion\.FromEuler`。
- **确认**：`assert(quaternion.is_equal_approx(quaternion.normalized()))`；比较 `basis.get_rotation_quaternion()` 与期望值。
- **置信度**：官方明确。

### `Node3D.rotation_order`
- **签名**：`node.rotation_order = EULER_ORDER_YXZ` / `node.RotationOrder = EulerOrder.Yxz`
- **用途**：定义欧拉角的本征旋转轴顺序；默认值 2 为 YXZ。
- **误用**：把编辑器或数据文件里的 XYZ 角度按 ZXY 解释，造成万向锁与朝向差异；从 `rotation` 读取后另存，却未保存顺序。
- **判据**：`rotation_order|EulerOrder\.(Xyz|Yzx|Zxy)`。
- **确认**：构造三个独立绕轴旋转，分别用节点 `rotation` 和手动四元数乘积比较结果。
- **置信度**：官方明确。

### `Node3D.top_level`
- **签名**：`node.top_level = true` / `node.TopLevel = true`
- **用途**：不继承父节点变换，使局部变换等同全局变换。
- **误用**：打开后还按父空间偏移放置子节点；打开后以为父子逻辑或生命周期也断开，实际只影响变换继承。相机跟随场景移动时反馈抖动即属此类。
- **判据**：`top_level\s*=\s*true|TopLevel\s*=\s*true`。
- **确认**：比较 `transform == global_transform`，移动父节点后再次比较。
- **置信度**：官方明确。

### `Node3D.look_at()`
- **签名**：`node.look_at(target, Vector3.UP, false)` / `node.LookAt(target, Vector3.Up, false)`
- **用途**：使节点局部前轴 `-Z` 指向世界目标；在全局空间计算。
- **误用**：目标正好位于节点 `up` 轴方向时前向退化；传入局部坐标目标却未先转换；每帧调用时目标只按物理步更新，相机出现跳变。
- **判据**：`look_at\s*\(|LookAt\s*\(`；检查参数是否为世界坐标、是否存在 `to_global`。
- **确认**：`assert not (target - global_position).cross(up).is_zero_approx()`；用 `get_global_transform_interpolated()` 作平滑目标。
- **置信度**：官方明确。

### `Node3D.to_global()`
- **签名**：`node.to_global(local)` / `node.ToGlobal(local)`
- **用途**：把节点局部点转换为世界点。
- **误用**：把“相对网格的点”直接传入没有局部变换的节点；用世界点调用并再次获得错误偏移。
- **判据**：`to_global\s*\(|ToGlobal\s*\(`。
- **确认**：传入 `Vector3.ZERO` 应返回 `global_position`；传入子节点位置应等于子节点世界位置。
- **置信度**：官方明确。

### `Node3D.to_local()`
- **签名**：`node.to_local(world)` / `node.ToLocal(world)`
- **用途**：把世界点转换为节点局部空间。
- **误用**：用于相机拾取后直接驱动局部位移；父节点有缩放时距离并不等比例，不能直接与未变换方向相加。
- **判据**：`to_local\s*\(|ToLocal\s*\(`。
- **确认**：往返测试：`to_local(to_global(p)).is_equal_approx(p)`。
- **置信度**：官方明确。

## 二、MeshInstance3D 与材质：共享资源优先于实例外观

`MeshInstance3D` 的 `mesh` 决定几何；`GeometryInstance3D.material_override` 覆盖所有表面材质。`cast_shadow` 默认 1（SHADOW_CASTING_SETTING_ON）；`lod_bias` 默认 1；`transparency` 默认 0。材质本身只是资源，因此改 `albedo_color`、透明度、剔除等会作用于引用同一资源的所有实例。[2]

### `MeshInstance3D.mesh`
- **签名**：`mesh_instance.mesh = my_mesh` / `meshInstance.Mesh = myMesh`
- **用途**：为实例提供 `Mesh` 资源。
- **误用**：在多处复用同一网格却期待实例独有表面材质；把碰撞网格、骨骼网格与普通渲染网格混用。
- **判据**：`mesh_instance3d.*\.mesh\s*=|MeshInstance3D.*\.Mesh\s*=|create_trimesh_collision`。
- **确认**：检查 `mesh.surface_get_material()` 与 `get_active_material(0)` 是否返回预期资源。
- **置信度**：官方明确。

### `GeometryInstance3D.material_override`
- **签名**：`mesh.material_override = mat` / `mesh.MaterialOverride = mat`
- **用途**：用一个材质替代所有表面槽材质。
- **误用**：共享同一 `mat` 后改 `mat.albedo_color`，导致所有敌人、道具同步变色；只判断“已赋材质”而未判断资源身份。
- **判据**：`material_override\s*=|MaterialOverride\s*=`；对右值做资源路径/实例身份检查。
- **确认**：在两个实例上比较 `get_active_material(0)`，修改一个后观察另一个是否变化。
- **置信度**：官方明确。

### `GeometryInstance3D.cast_shadow`
- **签名**：`mesh.cast_shadow = GEOMETRY_INSTANCE_CAST_SHADOW_ON` / `mesh.CastShadow = GeometryInstance3D.ShadowCastingSetting.On`
- **用途**：控制是否从可见面或双面产生阴影。
- **误用**：设为 ON 却未理解它“不单独考虑剔除”；透明物体仍产生实阴影；灯光的 cull mask 会阻止受光，但未必阻止阴影。
- **判据**：`cast_shadow\s*=|CastShadow\s*=`。
- **确认**：开启/关闭后抓深度图或观察接收面，确认 Shadow Atlas 是否更新。
- **置信度**：官方明确。

### `GeometryInstance3D.lod_bias`
- **签名**：`mesh.lod_bias = 1.0` / `mesh.LodBias = 1.0`
- **用途**：调节向低细节网格切换的速度；0 强制最低 LOD，大于 1 保持更远处的细节。
- **误用**：把它当作“模型质量总开关”；全局放大后 GPU 成本上升，远处仍渲染高模。
- **判据**：`lod_bias\s*=|LodBias\s*=`。
- **确认**：显示线框/三角形统计，在不同距离测量网格实例的 LOD 索引。
- **置信度**：官方明确。

### `GeometryInstance3D.visibility_range_*`
- **签名**：`mesh.visibility_range_begin = d` / `mesh.VisibilityRangeBegin = d`
- **用途**：按到摄像机距离显示/隐藏；默认 0 表示禁用范围检查，还包含 `begin/end` 及两个 margin。
- **误用**：设 `end` 小于 `begin`、margin 过大导致闪烁；动态缩放物体仍按世界距离判断。
- **判据**：`visibility_range_(begin|end|begin_margin|end_margin)\s*=`。
- **确认**：在不同摄像机距离循环检查 `is_visible_in_tree()` 与视锥剔除结果。
- **置信度**：官方明确。

### `BaseMaterial3D.albedo_color`
- **签名**：`mat.albedo_color = Color(1, 0, 0)` / `mat.AlbedoColor = new Color(1, 0, 0)`
- **用途**：设置基础反照率；默认白色。
- **误用**：与自发光、光照混为一谈；共享材质下影响所有实例。
- **判据**：`albedo_color\s*=|AlbedoColor\s*=`。
- **确认**：在无光照场景比较像素与 `Color`；检查 `emission_enabled` 是否另设。
- **置信度**：官方明确。

### `BaseMaterial3D.transparency`
- **签名**：`mat.transparency = BaseMaterial3D.TRANSPARENCY_ALPHA` / `mat.Transparency = BaseMaterial3D.Transparency.Alpha`
- **用途**：选择透明模式；默认 0 为禁用。
- **误用**：只降低 `albedo_color.a` 仍得到不透明渲染；选 Alpha 后不做排序、深度预pass或软粒子处理，产生硬边与洞穿。
- **判据**：`transparency\s*=\s*BaseMaterial3D\.TRANSPARENCY_|transparency\s*=`。
- **确认**：抓取颜色缓冲并检查渲染顺序；Alpha Scissor/Hash 还应验证阴影是否继续生成。
- **置信度**：官方明确。

### `BaseMaterial3D.cull_mode`
- **签名**：`mat.cull_mode = BaseMaterial3D.CULL_DISABLED` / `mat.CullMode = BaseMaterial3D.CullMode.Disabled`
- **用途**：控制背面、正面或双面渲染；默认 0。
- **误用**：开双面只为“看见内部”，却增加光栅化与阴影成本；平面法线仍可能不一致，产生光照瑕疵。
- **判据**：`cull_mode\s*=|CullMode\s*=`。
- **确认**：渲染线框并分别关闭前后剔除，检查正反面是否同时可见。
- **置信度**：官方明确。

### `BaseMaterial3D.emission_enabled`
- **签名**：`mat.emission_enabled = true` / `mat.EmissionEnabled = true`
- **用途**：开启自发光项。
- **误用**：只改 `emission` 颜色而忘记启用；期待自发光默认照亮相邻物体，除非启用 GI 或屏幕空间间接光。
- **判据**：`emission_enabled\s*=`，并组合检查 `emission\s*=`。
- **确认**：关闭场景灯光后材质仍应保留自发光亮度。
- **置信度**：官方明确。

### `BaseMaterial3D.vertex_color_use_as_albedo`
- **签名**：`mat.vertex_color_use_as_albedo = true` / `mat.VertexColorUseAsAlbedo = true`
- **用途**：用网格顶点色替代/参与反照率。
- **误用**：导入时没有顶点色，或者顶点色在导入后归一化、烘焙为静态数据；每个实例想单独着色却误用共享材质。
- **判据**：`vertex_color_use_as_albedo\s*=|VertexColorUseAsAlbedo\s*=`。
- **确认**：读取 `ArrayMesh` 的 `ARRAY_COLOR` 层，确认非空且范围正确。
- **置信度**：官方明确。

### `BaseMaterial3D.uv1_scale`
- **签名**：`mat.uv1_scale = Vector3(2, 2, 1)` / `mat.Uv1Scale = new Vector3(2, 2, 1)`
- **用途**：在顶点阶段缩放 UV；默认 `(1,1,1)`。
- **误用**：只缩放 X/Y 却同时改变 triplanar 的 Z 分量；对 LightmapGI 所需 UV2 无效。
- **判据**：`uv1_scale\s*=|Uv1Scale\s*=`。
- **确认**：分别渲染 UV 调试颜色与最终纹理，检查映射密度。
- **置信度**：官方明确。

### `BaseMaterial3D.billboard_mode`
- **签名**：`mat.billboard_mode = BaseMaterial3D.BILLBOARD_ENABLED` / `mat.BillboardMode = BaseMaterial3D.BillboardMode.Enabled`
- **用途**：让表面朝向摄像机；默认 0 关闭。
- **误用**：期待它与粒子 `local_coords`、GPU 粒子 billboard 是同一状态；相机背面时可能不显示；`billboard_keep_scale` 另需设置。
- **判据**：`billboard_mode\s*=|BillboardMode\s*=`。
- **确认**：绕相机观察，检查保持比例与法线光照方向。
- **置信度**：官方明确。

### 材质共享的实例检查
- **签名**：`var m = mat.duplicate(); mesh.material_override = m` / `var m = mat.Duplicate<Material>(); mesh.MaterialOverride = m`
- **用途**：为实例创建独立材质副本。
- **误用**：修改原资源后误以为已隔离；`duplicate()` 仅复制资源，不影响仍引用原资源的其他节点。
- **判据**：`material_override\s*=\s*\w+\.duplicate\(|MaterialOverride\s*=\s*\w+\.Duplicate`。
- **确认**：比较 `Object.id` 或 `Resource.resource_path`，确认实例拥有独立副本。
- **置信度**：官方明确。

## 三、Camera3D：投影与层 mask 决定“渲染什么”

`Camera3D.projection` 有 PERSPECTIVE、ORTHOGONAL、FRUSTUM；默认透视。`fov` 默认 75°，`near` 默认 0.05、`far` 默认 4000；`cull_mask` 默认 1048575。`current` 与 `make_current()` 控制视口活动相机；`unproject_position()` 把世界点投影到屏幕，`project_position()` 在给定深度把屏幕点放回世界，`is_position_in_frustum()` 只检查视锥而不代表未被 cull mask 剔除。[3]

### `Camera3D.projection`
- **签名**：`camera.projection = Camera3D.PROJECTION_ORTHOGONAL` / `camera.Projection = Camera3D.ProjectionType.Orthogonal`
- **用途**：切换透视、正交或可调 frustum 偏移投影。
- **误用**：正交时还把 `fov` 当作视野；FRUSTUM 忘记 `frustum_offset` 或仍用 `set_perspective()`。
- **判据**：`projection\s*=\s*Camera3D\.PROJECTION_|Projection\s*=`。
- **确认**：移动远处物体观察大小是否随距离变化，并检查 `get_camera_projection()`。
- **置信度**：官方明确。

### `Camera3D.fov`
- **签名**：`camera.fov = 60.0` / `camera.Fov = 60.0`
- **用途**：设置透视投影垂直视野。
- **误用**：在正交模式下调整无预期效果；接近 180° 时出现严重畸变。
- **判据**：`camera\.fov\s*=|camera\.SetFov\(`。
- **确认**：测量屏幕边缘世界点夹角，检查景深和运动速度感。
- **置信度**：官方明确。

### `Camera3D.near`
- **签名**：`camera.near = 0.1` / `camera.Near = 0.1f`
- **用途**：设置近裁面距离。
- **误用**：过小造成 z 精度不足与远处闪烁；把负值、零或相对相机后方的平面当作有效。
- **判据**：`\.near\s*=\s*[\d.]+|SetNear\(`。
- **确认**：比较深度缓冲伪影；确保场景边界在 `near` 与 `far` 之间。
- **置信度**：官方明确。

### `Camera3D.far`
- **签名**：`camera.far = 1000.0` / `camera.Far = 1000.0f`
- **用途**：设置远裁面距离。
- **误用**：超大 `far` 与极小 `near` 共同降低深度精度；远平面过近则大场景被截断。
- **判据**：`\.far\s*=\s*[\d.]+|SetFar\(`。
- **确认**：深度可视化并检查最远可见几何体距离。
- **置信度**：官方明确。

### `Camera3D.cull_mask`
- **签名**：`camera.cull_mask = 1 | 4` / `camera.CullMask = 1 | 4`
- **用途**：按视觉层选择被相机渲染的 `VisualInstance3D`；默认 20 个可见层全开。
- **误用**：用灯光 cull mask 的语义理解相机层；运行时设置误触内部 12 个保留层；只开一层却让环境或天空不可见。
- **判据**：`cull_mask\s*=|CullMask\s*=`；优先配合 `set_cull_mask_value(layer, true)`。
- **确认**：`get_cull_mask_value()` 逐层检查，隐藏每层观察画面差异。
- **置信度**：官方明确。

### `Camera3D.current`
- **签名**：`camera.current = true` / `camera.Current = true`
- **用途**：标记视口当前活动相机。
- **误用**：两个相机同帧置 true，实际生效者受节点与视口注册顺序影响；切换相机后不更新 `Environment` 或 audio listener。
- **判据**：`\.current\s*=|Camera3D.*make_current\(`。
- **确认**：`assert(camera.is_current())` 并读取目标视口的活动相机。
- **置信度**：官方明确。

### `Camera3D.make_current()`
- **签名**：`camera.make_current()` / `camera.MakeCurrent()`
- **用途**：在当前视口激活该相机。
- **误用**：在 SubViewport 里调用，却未确认相机已属于目标视口的世界；旧相机未清理导致残留。
- **判据**：`make_current\s*\(\)|MakeCurrent\s*\(\)`。
- **确认**：切换前后读取 `get_viewport().get_camera_3d()`。
- **置信度**：官方明确。

### `Camera3D.unproject_position()`
- **签名**：`camera.unproject_position(world)` / `camera.UnprojectPosition(world)`
- **用途**：世界坐标转屏幕/视口坐标。
- **误用**：把返回像素直接用于 UI 布局，却不除以 viewport 尺寸；对相机后的点结果仍可计算。
- **判据**：`unproject_position\s*\(|UnprojectPosition\s*\(`。
- **确认**：`project_position(result, depth)` 回代，并检查 `is_position_behind()`。
- **置信度**：官方明确。

### `Camera3D.project_position()`
- **签名**：`camera.project_position(screen, depth)` / `camera.ProjectPosition(screen, depth)`
- **用途**：按平面深度把屏幕点映射为世界坐标。
- **误用**：把 `depth` 当成世界距离；鼠标坐标来自不同 viewport 时未转换。
- **判据**：`project_position\s*\(|ProjectPosition\s*\(`。
- **确认**：用两个深度值构造射线，检查 `project_ray_origin()` 与 `project_ray_normal()` 是否一致。
- **置信度**：官方明确。

### `Camera3D.is_position_in_frustum()`
- **签名**：`camera.is_position_in_frustum(p)` / `camera.IsPositionInFrustum(p)`
- **用途**：判断世界点是否在视锥六面体内。
- **误用**：当作完整可见性判断；点在内不代表未被 `cull_mask` 排除、未被遮挡或物体整个 AABB 可见。
- **判据**：`is_position_in_frustum\s*\(|IsPositionInFrustum\s*\(`。
- **确认**：结合 `get_frustum()` 平面，逐一验证 `plane.is_point_over()`。
- **置信度**：官方明确。

## 四、光照与环境：先确认渲染方法支持，再开效果

`Light3D` 提供能量、阴影、bias、distance_fade 与 `editor_only`；`DirectionalLight3D` 还控制级联阴影、最大阴影距离与天空模式，`OmniLight3D` 控制范围和衰减，`SpotLight3D` 控制角度与锥衰减。`Environment` 的 `background_mode`、`tonemap_mode`、glow/SSAO/SDFGI/fog/volumetric_fog 默认大多关闭。`ReflectionProbe`、`VoxelGI`、`LightmapGI` 各有烘焙、更新与网格 AABB 依赖。[4][5][8]

### `Light3D.light_energy`
- **签名**：`light.light_energy = 2.0` / `light.LightEnergy = 2.0f`
- **用途**：按倍数缩放灯光输出。
- **误用**：在物理单位模式下混用能量与强度概念；负能量（subtractive）与透明度排序或 GI 造成意外暗部。
- **判据**：`light_energy\s*=|LightEnergy\s*=`。
- **确认**：渲染基准球，测量亮度随能量是否近似线性。
- **置信度**：官方明确。

### `Light3D.shadow_enabled`
- **签名**：`light.shadow_enabled = true` / `light.ShadowEnabled = true`
- **用途**：启用该灯光阴影。
- **误用**：SpotLight3D 角度超过 89° 时阴影停止工作；omni/spot 在 Mobile/Compatibility 受网格可见 AABB 影响。
- **判据**：`shadow_enabled\s*=|ShadowEnabled\s*=`。
- **确认**：检查 `is_visible_in_tree()`、灯光阴影图与项目 shadow atlas 槽位。
- **置信度**：官方明确。

### `Light3D.shadow_bias`
- **签名**：`light.shadow_bias = 0.05` / `light.ShadowBias = 0.05f`
- **用途**：缓解阴影 acne；不同灯型默认值不同。
- **误用**：过大造成 Peter Panning；每对象还受 `shadow_normal_bias` 影响，只调一个不能定位问题。
- **判据**：`shadow_bias\s*=|ShadowBias\s*=`。
- **确认**：比较平行表面在掠射角处的阴影，逐档抓深度图。
- **置信度**：官方明确。

### `Light3D.distance_fade_*`
- **签名**：`light.distance_fade_enabled = true` / `light.DistanceFadeEnabled = true`
- **用途**：按相机距离淡出灯光或阴影。
- **误用**：开始距离大于阴影淡出距离，远处灯光“先无阴影”；动态大范围灯光导致视野外仍计算。
- **判据**：`distance_fade_(enabled|begin|length|shadow)\s*=`。
- **确认**：改变相机距离，采样灯光贡献与阴影图更新。
- **置信度**：官方明确。

### `Light3D.editor_only`
- **签名**：`light.editor_only = true` / `light.EditorOnly = true`
- **用途**：让灯光仅在编辑器中显示。
- **误用**：用它控制运行期调试灯，却未验证发布版与运行时场景实例是否仍创建资源。
- **判据**：`editor_only\s*=|EditorOnly\s*=`。
- **确认**：导出并脱离编辑器运行，比较灯光列表与画面亮度。
- **置信度**：官方明确。

### `DirectionalLight3D.directional_shadow_mode`
- **签名**：`light.directional_shadow_mode = DirectionalLight3D.SHADOW_PARALLEL_4_SPLITS` / `light.DirectionalShadowMode = DirectionalLight3D.ShadowMode.Parallel4Splits`
- **用途**：选择平行光阴影图与级联数量。
- **误用**：4 级最慢，却对近景细节没有收益；正交模式近端阴影较模糊，也不自动平衡距离。
- **判据**：`directional_shadow_mode\s*=|DirectionalShadowMode\s*=`。

### `OmniLight3D.omni_range`
- **签名**：`light.omni_range = 10.0` / `light.OmniRange = 10.0f`
- **用途**：设置点光最大照明半径。
- **误用**：拉大范围却提高衰减补偿，造成像素覆盖增加；节点 scale 不改变光照范围。

### `SpotLight3D.spot_angle`
- **签名**：`light.spot_angle = 30.0` / `light.SpotAngle = 30.0f`

- **误用**：角度大于 89° 时阴影失效；扩大角度会把同一张阴影图分布到更大面积，质量下降。
- **判据**：`spot_angle\s*=|SpotAngle\s*=`。

### `Environment.background_mode`
- **签名**：`env.background_mode = Environment.BG_SKY` / `env.BackgroundMode = Environment.BGMode.Sky`
- **用途**：选择清除色、自定义色、天空等背景。
- **误用**：选 `BG_SKY` 却无 Sky 资源；相机的 Environment 覆盖 WorldEnvironment，审查时需检查最终挂载点。

### `Environment.tonemapper`
- **签名**：`env.tonemap_mode = Environment.TONE_MAPPER_ACES` / `env.TonemapMode = Environment.ToneMapper.Aces`
- **用途**：将 HDR 场景值映射到显示范围。
- **误用**：线性映射时曝光不足却把问题归咎于灯光能量；不同后处理管线下的默认值可能不同。
- **判据**：`tonemap_mode\s*=|TonemapMode\s*=`。

### `Environment.glow_enabled`
- **签名**：`env.glow_enabled = true` / `env.GlowEnabled = true`
- **用途**：启用辉光/泛光。
- **误用**：阈值过高或 HDR 曝光不足，看似“没效果”；移动端对分辨率和采样模式敏感。
- **判据**：`glow_enabled\s*=|GlowEnabled\s*=`。

### `Environment.ssao_enabled`

- **用途**：开启屏幕空间环境光遮蔽。
- **误用**：把它当作接触阴影或烘焙 AO 的等价替代；结果依赖深度和屏幕可见性，屏幕外物体无法贡献。

### `Environment.sdfgi_enabled`

- **判据**：`sdfgi_enabled\s*=|SdfgiEnabled\s*=`。

### `Environment.fog_enabled`
- **签名**：`env.fog_enabled = true` / `env.FogEnabled = true`

## 五、SubViewport：离屏表面与显示容器是两件事

`SubViewport.size` 默认 512×512；`render_target_update_mode` 默认 2（可见时更新）。`SubViewport` 本身不自动显示，需要 `SubViewportContainer` 或 `ViewportTexture`。当父容器 `stretch=true` 时，视口 size 不可手动改变。[6][7]

### `SubViewport.size`
- **签名**：`sub.size = Vector2i(1024, 1024)` / `sub.Size = new Vector2I(1024, 1024)`
- **用途**：设置离屏渲染目标宽高。
- **误用**：设为 0/1、小于 2 的维度会不显示；父容器 stretch 时手动赋值被禁止。
- **判据**：`sub_viewport.*\.size\s*=|SubViewport.*\.Size\s*=`。
- **确认**：读取 `size`，检查 ViewportTexture 实际分辨率与报警日志。
- **置信度**：官方明确。

### `SubViewport.render_target_update_mode`
- **签名**：`sub.render_target_update_mode = SubViewport.UPDATE_ALWAYS` / `sub.RenderTargetUpdateMode = SubViewport.UpdateMode.Always`
- **用途**：控制何时重绘离屏目标。
- **误用**：静态画面仍用 ALWAYS；设为 ONCE 后又有运行时变化却不手动更新。
- **判据**：`render_target_update_mode\s*=|RenderTargetUpdateMode\s*=`。
- **确认**：统计 GPU frame time；动态场景验证是否需要显式 `render_target_update_mode = UPDATE_ONCE` 后再置 DISABLED。
- **置信度**：官方明确。

### `SubViewport.disable_3d`
- **签名**：`sub.disable_3d = true` / `sub.Disable3D = true`
- **用途**：关闭 3D 渲染以降低开销。
- **误用**：语言包扫描时遇到 4.0/4.1 的早期 API 名称差异；视口内仍含 3D 网格，结果却为空。
- **判据**：`disable_3d\s*=|Disable3D\s*=`；若该属性在目标小版本不存在，报告“API 版本不匹配”而非“错误”。
- **确认**：在纯净 3D 场景比较三角形提交数、内存与渲染结果。
- **置信度**：官方明确；成员在 4.x 小版本间可能存在 API 名/可用性变化。

### `SubViewport.transparent_bg`
- **签名**：`sub.transparent_bg = true` / `sub.TransparentBg = true`
- **用途**：使清屏/背景透明，便于合成到 UI 或场景。
- **误用**：背景透明但 `clear_mode=NEVER` 导致旧帧残留；目标容器材质或 UI 不预乘 alpha 时边缘变黑。
- **判据**：`transparent_bg\s*=|TransparentBg\s*=`。
- **确认**：在棋盘格背景抓图，检查四角 alpha 与颜色边缘。
- **置信度**：官方明确；小版本名称需核对。

### `SubViewport.msaa_3d`
- **签名**：`sub.msaa_3d = Viewport.MSAA_4X` / `sub.Msaa3D = Viewport.Msaa.Msaa4x`
- **用途**：为视口单独选择 3D MSAA。
- **误用**：把全屏后处理/alpha 效果的质量问题都归因到 MSAA；兼容渲染方法与部分效果组合可能不支持。
- **判据**：`msaa_3d\s*=|Msaa3D\s*=`。
- **确认**：比较边缘像素覆盖率、带宽与帧时间。
- **置信度**：官方明确；枚举名随 4.x 小版本变化。

### `SubViewport.scaling_3d_scale`
- **签名**：`sub.scaling_3d_scale = 0.5` / `sub.Scaling3DScale = 0.5f`
- **用途**：降低 3D 内部渲染分辨率并上采样。
- **误用**：与容器 `stretch` 双重缩放，出现模糊且无法解释；值过低使 MSAA/后处理质量下降。
- **判据**：`scaling_3d_scale\s*=|Scaling3DScale\s*=`。
- **确认**：检查实际内部尺寸、输出尺寸与 GPU 利用率。
- **置信度**：官方明确；小版本名称需核对。

### `SubViewport.hdr`
- **签名**：`sub.hdr = true` / `sub.Hdr = true`
- **用途**：允许视口目标使用高动态范围。
- **误用**：在 LDR 目标或 sRGB 容器中期待 HDR 泛光；bloom 阈值与颜色缓冲格式共同决定结果。
- **判据**：`sub_viewport.*\.hdr\s*=|Hdr\s*=`。
- **确认**：写入超亮颜色并读回 ViewportTexture，检查值是否被钳制。
- **置信度**：官方明确；小版本名称需核对。

### `SubViewportContainer.stretch`
- **签名**：`container.stretch = true` / `container.Stretch = true`
- **用途**：让容器自动拉伸视口以覆盖自身区域。
- **误用**：开启后还写 `SubViewport.size`，结果被容器控制；只设置拉伸而不处理宽高比，画面变形。
- **判据**：`sub_viewport_container.*\.stretch\s*=|SubViewportContainer.*\.Stretch\s*=`，并寻找同时赋值 `size` 的代码。

- **置信度**：官方明确。

## 六、着色器与 GPUParticles3D：代码与资源必须一起审查

Spatial shader 以 `shader_type spatial;` 声明；`render_mode` 控制混合、深度、剔除、着色和粒子特性。`uniform` 可带 `source_color`、`hint_range` 等提示，运行时可用 `set_shader_parameter()`。`GPUParticles3D` 的 `amount` 默认 8、`lifetime` 默认 1、`fixed_fps` 默认 30、`preprocess` 默认 0；`ParticleProcessMaterial` 控制方向、扩散、重力与发射形状。[10][11]

### `shader_type`
- **签名**：`shader_type spatial;` / 无直接 C# 成员；属于 `.gdshader` 源码
- **用途**：声明这是 3D 空间着色器。
- **误用**：使用 canvas_item 的 `TEXTURE`/`COLOR` 或粒子特有内置变量；把 spatial shader 赋给错误着色器类型。
- **判据**：`^shader_type\s+spatial\s*;`。
- **确认**：编辑器 shader 检查、编译日志、运行时 `RenderingServer` 错误。
- **置信度**：官方明确。

### `render_mode`
- **签名**：`render_mode cull_disabled, unshaded, depth_draw_always;` / 出现在 `.gdshader`
- **用途**：配置空间材质渲染开关。
- **误用**：同时需要透明与正确深度；开 `unshaded` 却继续调试灯光；粒子材质误开启轨迹模式。
- **判据**：`^render_mode\s+[a-z_, ]+\s*;`。
- **确认**：逐一切换模式并对比深度缓冲、颜色和阴影。
- **置信度**：官方明确。

### `uniform`
- **签名**：`uniform float cutoff : hint_range(0, 1) = 0.5;` / 无直接 C# 字段
- **用途**：向材质暴露可编辑/可设置参数。
- **误用**：使用未声明名称调用 `set_shader_parameter()`；类型不匹配；不同材质共享 shader 时未确认实例资源身份。
- **判据**：`^uniform\s+\w[\w<>:,\s]*\s+\w+(\s*:\s*\w+)?(\s*=\s*[^;]+)?\s*;`。
- **确认**：`material.get_shader_parameter_list()` 与 `get_shader_parameter()`。
- **置信度**：官方明确。

### `uniform hint_*`
- **签名**：`uniform vec4 tint : source_color;` / 无 C# 直接字段
- **用途**：给编辑器提供颜色、范围、法线图等语义与控件。
- **误用**：`hint_range` 仅约束编辑器输入，不保证运行时合法；颜色提示不执行 gamma 校正；默认值和 hint 顺序写错。
- **判据**：`uniform\s+\S+\s+\w+\s*:\s*(source_color|hint_range|hint_normal|hint_default_\w+)`。
- **确认**：检查 Inspector 控件和默认值位置，运行期读取实际值。
- **置信度**：官方明确。

### `set_shader_parameter()`
- **签名**：`material.set_shader_parameter("cutoff", 0.2)` / `material.SetShaderParameter("cutoff", 0.2f)`
- **用途**：运行时设置 material-local uniform。
- **误用**：拼写大小写不一致；修改共享材质影响所有实例；设置纹理/sampler 后未持有引用。
- **判据**：`set_shader_parameter\s*\(|SetShaderParameter\s*\(`。
- **确认**：先读 `get_shader_parameter()`，渲染后回读；逐实例材质时只影响目标实例。
- **置信度**：官方明确。

### `GPUParticles3D.emitting`
- **签名**：`particles.emitting = true` / `particles.Emitting = true`
- **用途**：控制发射开关。
- **误用**：设为 true 但 `amount=0` 或 `process_material=null`；切换后立即 `restart()`，语义和预热行为不直观。
- **判据**：`\.emitting\s*=|Emitting\s*=`。
- **确认**：观察粒子计数和画面；读取可见性与 viewport 关联。
- **置信度**：官方明确。

### `GPUParticles3D.amount`
- **签名**：`particles.amount = 256` / `particles.Amount = 256`
- **用途**：设置最大粒子数。
- **误用**：过大导致 GPU buffer 与填充压力；过小使连续发射在高 lifetime 下出现缺口。
- **判据**：`\.amount\s*=|Amount\s*=`。
- **确认**：粒子统计与 GPU memory/profiler；测试 one_shot 峰值。
- **置信度**：官方明确。

### `GPUParticles3D.lifetime`
- **签名**：`particles.lifetime = 2.5` / `particles.Lifetime = 2.5f`
- **用途**：单个粒子的存活时间。
- **误用**：`preprocess` 大于实际场景预热需要，启动卡顿；与 `explosiveness` 组合产生一次爆发现象却误判为持续发射。
- **判据**：`\.lifetime\s*=|Lifetime\s*=`。
- **确认**：计时首粒消失时间；使用 `capture_aabb()` 估计世界范围。
- **置信度**：官方明确。

### `GPUParticles3D.process_material`
- **签名**：`particles.process_material = ParticleProcessMaterial.new()` / `particles.ProcessMaterial = new ParticleProcessMaterial()`
- **用途**：提供粒子行为/外观材质。
- **误用**：共享同一材质导致所有发射器参数同步；赋 `ShaderMaterial` 却未实现必要粒子内建变量。
- **判据**：`process_material\s*=|ProcessMaterial\s*=`。
- **确认**：比较资源 id，检查 `get_surface_override_material()`/shader 编译状态。
- **置信度**：官方明确。

### `GPUParticles3D.visibility_aabb`
- **签名**：`particles.visibility_aabb = AABB(...)` / `particles.VisibilityAabb = new Aabb(...)`
- **用途**：定义粒子系统参与视锥/遮挡剔除的世界空间包围盒。
- **误用**：默认小 AABB 在相机移动后裁剪消失；本地粒子随发射器移动时未把最大位移计入。
- **判据**：`visibility_aabb\s*=|VisibilityAabb\s*=`。
- **确认**：包围盒可视化、随机运动测试，确认不同相机位置都不消失。
- **置信度**：官方明确。

### `GPUParticles3D.local_coords`
- **签名**：`particles.local_coords = true` / `particles.LocalCoords = true`
- **用途**：让粒子留在发射器局部空间并随其变换移动。
- **误用**：以为粒子发射后始终在全局空间；设为 false 时希望跟随移动发射器，却出现拖尾位置错误。
- **判据**：`local_coords\s*=|LocalCoords\s*=`。
- **确认**：移动旋转发射器，检查粒子是否保持相对位置/朝向。
- **置信度**：官方明确。

### `GPUParticles3D.fixed_fps`
- **签名**：`particles.fixed_fps = 60` / `particles.FixedFps = 60`
- **用途**：固定模拟步率。
- **误用**：把 fixed_fps 理解成粒子运动速度；过低并关闭插值导致跳跃，过高并无视觉收益。
- **判据**：`fixed_fps\s*=|FixedFps\s*=`。
- **确认**：比较低/高 fps 下轨迹与帧时间，检查 `interpolate`。
- **置信度**：官方明确。

### `GPUParticles3D.preprocess`
- **签名**：`particles.preprocess = 3.0` / `particles.Preprocess = 3.0f`
- **用途**：首次渲染前模拟若干秒，使稳定效果立即出现。
- **误用**：预处理时间长导致首帧卡顿；值为负或不与 lifetime/amount 协调。
- **判据**：`preprocess\s*=|Preprocess\s*=`。
- **确认**：测量首次 `get_frame()`/可见时间，检查稳态粒子密度。
- **置信度**：官方明确。

### `ParticleProcessMaterial.direction`
- **签名**：`mat.direction = Vector3(0, 1, 0)` / `mat.Direction = new Vector3(0, 1, 0)`
- **用途**：设置主发射方向；默认 X 轴。
- **误用**：与 `spread`、`gravity` 叠加后实际方向明显偏移；局部/世界方向随发射器旋转变化取决于节点空间。
- **判据**：`ParticleProcessMaterial.*\.direction\s*=|direction\s*=` 上下文限定。
- **确认**：零重力、零扩散时粒子应沿方向近似直线分布。
- **置信度**：官方明确。

### `ParticleProcessMaterial.spread`
- **签名**：`mat.spread = 45.0` / `mat.Spread = 45.0f`
- **用途**：设置锥角扩散；默认 45°。
- **误用**：接近 180° 期待均匀球面分布，实际圆锥模型并非各方向等概率；单位误用为弧度。
- **判据**：`\.spread\s*=|Spread\s*=`。
- **确认**：长时间采样落点，检查方向分布与角度边界。
- **置信度**：官方明确。

### `ParticleProcessMaterial.gravity`
- **签名**：`mat.gravity = Vector3(0, -9.8, 0)` / `mat.Gravity = new Vector3(0, -9.8, 0)`
- **用途**：每步对粒子施加重力加速度。
- **误用**：把重力当作初始速度；发射器旋转时默认局部重力方向与预期世界重力不一致。
- **判据**：`\.gravity\s*=|Gravity\s*=`。
- **确认**：关闭其他加速度，比较不同 lifetime 的位移抛物线。
- **置信度**：官方明确。

### `ParticleProcessMaterial.emission_shape`
- **签名**：`mat.emission_shape = ParticleProcessMaterial.EMISSION_SHAPE_SPHERE` / `mat.EmissionShape = ParticleProcessMaterial.EmissionShape.Sphere`
- **用途**：选择点、球体、盒体、环形、点组等发射位置形状。
- **误用**：设置 shape 而不设置对应 extents/radius/点纹理；点组数据缺失时退化为预期外位置。
- **判据**：`emission_shape\s*=|EmissionShape\s*=`。

- **置信度**：官方明确。

## 七、反直觉坑：八个“本能以为 X，但实际 Y”

1. **本能以为 `global_position` 是一等坐标，改了就永久生效；实际它只是全局变换链的计算结果，下一帧可能被物理、动画、父节点变换或插值重算覆盖。** 验证：在同一帧末尾与下一帧分别采样，并检查 `top_level`、物理模式、动画轨道与父节点变换通知。[1]

2. **本能以为 `look_at()` 接收的是节点局部目标；实际它在全局空间计算，传局部坐标会偏航。** 验证：将局部目标先用 `to_global()` 转换，比较最终 `-Z` 轴朝向。[1]

3. **本能以为 `albedo_color.a` 降低就能透明；实际 `BaseMaterial3D.transparency` 默认为禁用，必须选 Alpha/Scissor/Hash。** 验证：开启透明模式后检查颜色缓冲与阴影行为；不同透明模式对阴影的影响不同。[2]

4. **本能以为修改一个 MeshInstance3D 的材质只影响它自己；实际多个实例常共享同一材质资源，改动会跨对象传播。** 验证：比较 `Resource` 身份，修改后观察其他实例；需要独立即 `duplicate()`。[2]

5. **本能以为相机能渲染物体只取决于位置；实际还取决于 `cull_mask`、灯光 cull mask、视锥、AABB 和 SubViewport 是否显示。** 验证：分层隔离、检查 `is_position_in_frustum()`、网格可见 AABB 与灯光投影。[3]

6. **本能以为打开 `Environment` 就会自动启用 SDFGI、雾或泛光；实际这些开关默认大多关闭，且部分 GI 还需几何体和灯光的 `gi_mode` 配合。** 验证：读取各项 bool、检查当前渲染方法与资源挂载优先级。[4][8]

7. **本能以为 `SubViewport.size` 始终可写；实际当父 `SubViewportContainer.stretch=true` 时不能手动改 size。** 验证：同时搜索 `stretch=true` 与 `sub_viewport.size=`，并在纯净场景赋值观察日志。[7]

8. **本能以为粒子发射后永远留在世界；实际 `local_coords` 决定粒子是否跟随发射器移动，AABB 决定系统是否被剔除。** 验证：移动旋转发射器观察粒子轨迹，在屏幕边缘把包围盒可视化；`visibility_aabb` 不足时不报错的这一条尤其危险。[11]

## 八、审查规则与可执行验证方案

建议把“源码正则”升级为 AST/场景资源扫描：`.gd`/`.cs` 用于找调用，`.tscn`、`.material`、`.shader`、`.particleprocessmaterial` 用于找资源身份、默认值与共享关系。判据按风险分级：A 级为必定错误或高风险（共享材质写入、stretch 下改 size、spot_angle>89、near<=0）；B 级为语义风险（global 覆盖链、透明模式、GI mode、粒子 AABB）；C 级为性能建议（LOD bias、amount、MSAA、固定 fps、SubViewport update）。

验证流程应覆盖三类自动化测试。第一类是离线资源测试：解析场景后建立资源路径→节点引用图，找出同一 `Material` 被多个实例引用却无 `duplicate()` 的写入点。第二类是渲染冒烟测试：新建只含目标节点、相机与 DirectionalLight3D 的 scene，截图并读取 frame post-draw 状态；对变换 API 还要分别测试静止、父节点运动、物理步和插值。第三类是配置矩阵测试：在 Forward+、Mobile、Compatibility 三个渲染方法下运行，因为灯光最大数量、ReflectionProbe/VoxelGI 支持、阴影图与 shader 功能在不同方法上不一致。[5][8]

最终交付应保留“Godot 版本”作为关键列。4.x 主版本内仍会发生属性新增、重命名或默认值变化；例如 `Environment` 的 GI 属性、`SubViewport` 的 3D 渲染选项和若干枚举命名在 4.0–4.4 间并非处处一致。报告中的签名以官方稳定类参考与 4.4 类参考交叉核验为准；扫描器遇到目标工程指定的次版本不存在的成员时，应报“版本不兼容”，而不是简单报“未使用”。[1][4][7]
