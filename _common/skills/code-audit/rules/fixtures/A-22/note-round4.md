# A-22 补充样本（第 4 轮）：横切关注点 = URL 编码

- **TP2 必须命中**：同一横切关注点（此处是分支名编码）在多个出口实现，其中一处裸拼
- **FP2 必须不命中**：所有出口共用同一个编码函数

为什么需要第二组：A-22 原有样本是「重试策略在 raw 分支漏配」；
本组换成**编码**，且函数名用 `head_of()` 避开 `ref_sha()` 这类白名单内名字——
实测过：靠变量名白名单的规则，换成同义标识符后召回率 0/8。

实测来源：某推送工具 `_ref_path()` 的注释明确写「统一走这里，避免下次新增调用点又漏掉」，
而 `ref_sha()`（删除分支前的校验要用它）恰恰是裸拼的那个出口。
同族第 3 个实例：raw 分支不打印限流提示。
