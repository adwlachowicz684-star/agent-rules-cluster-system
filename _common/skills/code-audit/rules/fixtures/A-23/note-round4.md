# A-23 补充样本（第 4 轮）：收尾失败且连返回值都没检查

- **TP2 必须命中**：主操作成功后，收尾步骤用默认参数调用（失败静默或只警告），
  而状态已按「成功」落盘
- **FP2 必须不命中**：检查返回值，并在报错里区分「主体已生效」与「收尾未生效」

为什么需要第二组：A-23 原有 tp 讲「报错没说清已生效」；
本组更早一步——**压根不知道失败了**，于是连「没说清」都谈不上。

实测来源：某推送工具远端 PATCH 成功后本地补提交三步均未检查返回值；
pre-commit hook 失败 / 文件被 .gitignore 屏蔽 / 路径过多触发 ARG_MAX 时，
本地不落提交而 `synced_commit` 已写盘 → 下次 detect_changes 再列一遍，
第一层又判「已与远端一致」而跳过。
