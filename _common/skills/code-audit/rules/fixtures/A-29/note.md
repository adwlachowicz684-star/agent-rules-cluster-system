# A-29 判据过宽（用存在性 / 非空代替语义判定）

- **TP 必须命中**：判定「某规则是否启用」时只看键存在 / 字段非空 / 数组非空
- **FP 必须不命中**：判到取值层，且只把真正阻止本操作的规则作为拦截依据

实测来源：某推送工具 `_refuse_direct_if_protected()` 用 9 个键做 `any(k in prot)`，
含 `allow_force_pushes` / `allow_deletions` / `required_status_checks`。
只要仓库开了任何保护，条件恒为真 → 纯 CI 保护（最常见配置）的仓库里 `--direct`
被无谓拒绝，用户要么放弃，要么真去关掉保护设置。

与 K-41（异常处理过窄）是对偶面：库里已有「过窄」，本条补「过宽」。
与 A-27 的分界：A-27 是自己的返回值容量不够；本条是读外部结构时判据粒度不对。
