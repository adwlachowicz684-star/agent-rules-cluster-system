# mutations.example.json

变异定义的**示例**，来自 `push_api.py` 八轮审查里真实修过的 27 个缺陷。

## 它不是给本仓库用的

本 skill 没有 `test_*.py`，所以这份文件**不能**直接对本仓库跑。
它的用途是：

1. **格式参考** —— 照着它给被审项目写定义
2. **判据佐证** —— 每一条对应 `references/` 里的一个模式，
   `desc` 字段写明「这条变异对应哪次真实修复」

## 用法

```bash
# 给被审项目写定义后：
python3 scripts/mutate.py --src=<目标源码> --mutations=mutations.json
python3 scripts/mutate.py --src=<目标源码> --mutations=mutations.json --check
```

`--check` 只校验每条 `old` 是否还唯一命中 —— **每次改完目标代码都要跑**，
否则「KILLED」可能只是因为变异压根没生效（见脚本 docstring 第 1 点）。

## 字段

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识，与修复批次对应 |
| `desc` | 一句话说明「注入这个等于退回哪次修复前」 |
| `old` | 源码片段，**必须在当前代码里恰好匹配 1 处** |
| `new` | 替换后的片段（退回修复前的形态） |

## 写定义的三条纪律

1. **只写真实修过的缺陷** —— 凭空造的变异没有意义，测的是不存在的问题
2. **锚点要稳** —— 优先选带缩进的代码行，别选注释里的句子
   （实测：一条变异的 `old` 命中的第一次出现在**注释**里，代码行没被改到，
   于是成了空变异，被误报成「测试有盲区」）
3. **注入后要能被测到** —— 写了但没有任何测试覆盖的路径，
   会稳定产出 SURVIVED，那是真实盲区，正是要的结果
