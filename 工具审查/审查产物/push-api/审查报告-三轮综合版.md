### P0-1　三态布尔化：保守返回值被读成"本地改过"，PR 模式可静默回退主干

- **位置**：`_main()` 2496–2529 行；根因在 `_local_matches_baseline()` 951–964 行
- **判据归位**：**A-24（新增，见第八节）**｜与 A-15「放行粒度」对偶
- **证据** `【代码事实】`：

  ```python
  # 951 行：函数自己写明 False 是保守值
  """基线里没记录的返回 False（保守）：…不算「已知未改动」"""
  if not isinstance(base, dict) or not base.get("sha"):
      return False

  # 2506 行：调用方把它一律读成"本地确实改过"
  (revert if _local_matches_baseline(state, lmap, rel) else overlap).append((rel, why))
  ...
  for rel, _ in overlap:
      todo.append(rel)        # 无条件下放行
  ```

  `False` 有两种含义（① 本地确实改过 ② 无法判断），调用方只读成 ①。于是**"基线未记录 + 远端已存在"这类最该拦的文件被无条件放行**，还被标注为"不会静默覆盖"。
- **后果**：分支基点 = 最新主干，ours = 本地旧内容，theirs == base → GitHub 判定"你故意回退"并直接采纳，**合并成功、零报错**。这正是脚本最想防的那类事故。
- **附带不一致**：direct 模式对同一批文件是拦的（2483 行），PR 模式放行。
- **修法**：三分类，unrecorded 单独拦（代码见 7.1）。同一处的 2382 行 `skipped_stale` 判定有相同语义问题，一并改。
- **定级**：P0 —— 静默、不可逆、破坏他人产出。

### P0-2　新建分支后的清理盲区：4 条正常 `return` + 创建动作本身都在清理块外

- **判据归位**：**A-19 补充**（现有判据只讲"注入异常/中断"，未覆盖"正常 return"）
- **证据** `【代码事实】`：

  |---|---|---|---|
  | — | `create_branch` 自身抛错 | — | ❌ `branch_created_now` 还是 `None` |

### P0-3　`--dry-run` 挡不住会改东西的子命令，且此时不加锁

- **位置**：`main()` 2054 行 `enabled=not opts["dry"]`；`_main()` 的 dry 检查在 2602 行，远在子命令分发之后
- **判据归位**：**T-15（新增）**
- **证据** `【代码事实】`：子命令分发在 2127–2193 行，全部早于 2602 行。实测组合：

  | 命令 | 实际效果 |
  |---|---|
  | `--dry-run --delete-branch xxx` | **真的删除远端分支**（不可逆） |
  | `--dry-run --merge` | **真的合并 PR**（且无锁） |
  | `--dry-run --pull` | **真的改写本地工作区文件**（且无锁） |
  | `--dry-run --close-pr` / `--mark-synced` / `--resolve` | 同样真实生效 |

- **后果**：`--dry-run` 的语义是"不推送、不建分支"，用户心智模型却是"无害只读"。删分支不可逆。
- **修法**：子命令分发**之前**加门禁（代码见 7.3）；`StateLock` 的 `enabled` 改为"可能写就加锁"，不与 `dry` 绑定。

### P0-4　冲突辅助文件 `.remote` / `.base` 落在仓库内，会被自己推送上去

- **位置**：生成于 `pull()` 1393–1399 行；删除只在 `resolve()` 1466–1469 行；`conflicts` 落盘在 1431 行（**循环之后**）
- **判据归位**：**A-25（新增）**；A-18/A-20 是"残留数量/跨进程"，本条是"残留位置在工作目录内 → 被自身检测器拾取"
- **证据** `【实测】`：grep 全文确认 `detect_changes()`（816–838 行）**没有任何后缀过滤**，`--untracked-files=all` 会把这两个文件报成待推送的新增文件。
- **触发链**：pull 中途任意异常 → `save_state` 不执行 → `conflicts` 未记录 → 2197 行的全局拦截失效 → 下次推送把 `xxx.remote` / `xxx.base` 推上远端，preview 里显示成"新增"。
- **后果**：冲突比对的中间产物污染远端仓库；若冲突内容敏感，等于把远端版本**换一个文件名**重新提交了一遍。
- **修法**：写到仓库外（与 `STATE_PATH` 同目录），或 `detect_changes()` 里过滤这两个后缀（代码见 7.4）。

### P0-5　`pull` 的"远端无变化"分支不刷新基线 → direct 模式操作死锁

- **位置**：`pull()` 1312–1318 行
- **判据归位**：**A-16 新实例**（现有判据是"提示给的出路无效"，本条是"出路本身空转"）
- **证据** `【推演】`（状态机推演已跑通，未端到端执行）：

  ```
  基线无 p；远端 p=B；本地 p=C（我改的）；git HEAD 的 p=B
  → _base_bytes 回退到 git HEAD = B
  → base(B) == remote(B) 命中 1312 行 → "远端无变化，本地改动原样保留"
  → continue，基线仍未记 p
  → 无冲突 → synced_commit = head_sha（P0-1 放行）
  推送：base is None 且 rsha=B 非 None → blocked("基线里没有这个文件、远端却已存在")
        → direct 模式 return，建议 --pull
  --pull：走完全相同的分支 → 再推 → 再被拦 …
  ```

- **后果**：脚本给的建议就是它自己那条空转的路径，**用户按提示做永远走不通**，唯一出路是被引导去用 `--force-file`（而此处根本没有覆盖风险）。PR 模式不死锁（`overlap` 会放行），故为 direct 专属。
- **修法**：这条分支也刷新基线——`base == remote` 已证明远端内容就是 `base`，记下来是准确的（代码见 7.5）。

## 九、验证过没问题的部分

实测确认正确，后续复核可直接跳过：

1. **token 白名单用"拒绝"而非"清洗"**——清洗后 token 变了必然 401，用户只会看到"认证失败"而不知为何。
2. **`git status --porcelain` 的 `-z` + 不 `strip()`**——未暂存修改输出为 `" M a.txt"`，`strip()` 会吃掉前导空格，按 `item[3:]` 切出 `.txt`，最常见的"改完没 add"场景会静默推空。当前实现正确。
3. **`safe_rel` 返回值按 normpath、校验按 realpath**——合法内部链接不会被改写成目标路径。
4. **状态文件的三态防护**（`_check_state_path` 挡目录/FIFO/字符设备、`validate_state` 逐项校验、损坏先备份 `.corrupt`）——覆盖了"能不能打开"这种试探式判断的所有坑。
5. **`api()` 用 `-w "%{http_code}"` 显式查状态码**，raw 分支与 JSON 分支共用同一报错出口（注释里记着上上轮 P0 是两处分开写导致漂移）。
6. **`init_baseline` 拒绝为"本地 ≠ 远端"的文件建基线**——堵住了旧版"初始化给防覆盖开后门"的洞。
7. **`_base_bytes` 区分 `baseline` / `git` 两种来源**——用户 commit 后 HEAD 已含其改动，不能当共同祖先，这个判断是对的。

## 十三、架构层面的两点观察

这两条不是 bug，但决定了上面这些问题的复发率。

### 13.1　双真相源：自建基线 vs git

脚本在 git 之上维护了一套**平行的版本追踪**（`.push-sync.json` 记"远端每个文件的 mode+sha"），与 git 的索引/HEAD 并存。凡是两套真相需要调和的地方，代码里都留下了痕迹：`_base_bytes` 返回 `(data, source)` 并分 `baseline`/`git`/`None`；`baseline_changed_files` 存在的唯一理由就是 git status 看不见"已 commit 未推送"；`local_state_map` 要在 git 索引 mode 与工作区 mode 之间选一个，还得先探测 `core.fileMode`。

这些调和逻辑写得很好，但它们之所以存在，是因为**用户在这个仓库里用 git 命令是被允许却不被支持的**。文档只处理了 `git commit` 这一种（2324 行注释），而 `git checkout <old>` / `git reset --hard` / `git stash pop` 会让本地文件回到旧版本，同时 `synced_commit` 仍是 `head_sha`——P0-1 判定"本地副本是最新的"从而放行，第一层看到"远端 == 基线"也放行，**于是把回退内容推上去覆盖远端**。这在 git 语义下是"正确"的，但与脚本承诺的"防回退"相冲突。

**建议**：在文档顶部明确写出边界——本仓库由 push_api 独占管理，允许 `git add` / `git commit`，但 `git checkout` / `git reset` / `git stash` 之后必须 `--init-baseline` 重建基线。一句话消掉一整类误判。

### 13.2　拆分优先于继续加注释

单文件 2761 行、`_main()` 单函数约 1700 行、嵌套 5 层。建议按子命令拆成 `cmd_push` / `cmd_pull` / `cmd_merge` / `cmd_prune`，并把 `api()` 做成可注入假实现——否则第十五节的 15 条断言在离线环境里根本没法跑。
