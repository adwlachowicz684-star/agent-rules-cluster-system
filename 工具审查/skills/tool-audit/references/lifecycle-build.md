# 生命周期、构建与仓库卫生（第 5 步 · 维度四、五）

## 成对契约（最高优先级）

**缺一侧按 P0 处理**：随运行时长累积，测试期看不出，上线后 OOM，
定位成本远高于修复成本。

| 成对项 | 常见缺失 |
|---|---|
| `addEventListener` ↔ `removeEventListener` | 卸载时未摘 |
| 订阅 ↔ 退订 | 只按事件名匹配，摘错（B04） |
| `setInterval` / `setTimeout` ↔ clear | 重挂载时叠加（F02） |
| `createObjectURL` ↔ `revokeObjectURL` | 预览关闭时未释放（F03） |
| 子进程 start ↔ kill | 注册表无清理 |
| 快捷键 register ↔ unregister | 插件卸载时残留 |
| 侧边栏/UI 注入 add ↔ remove | 卸载时残留 |
| 监听器 start ↔ stop（watch / webhook） | 无 stop 命令 |

**检查方法**：列出模块创建的**全部外部资源**，逐个对照卸载钩子里的清理项。

## 重挂载叠加（F02）

判据：初始化流程可能被重复执行（插件重载、组件重渲染、主题切换触发重算）。

期望形态（三选一）：
- generation 令牌：每次挂载 `++gen`，异步回来时 `gen` 变了就丢弃结果
- 先清理再施加：施加滤镜/覆盖层之前先清一遍，保证幂等
- 卸载钩子兜底：即使前两者漏了，卸载时也能清干净

**「宿主引擎」类代码若三样都没有，几乎必然存在叠加缺陷。**

## 卸载后仍被使用（F07）

判据：对象销毁后外部仍持有引用并继续调用。

- 抛异常 → P2（能被发现，有堆栈）
- **静默产生错误结果 → P1**
- 销毁后无状态标记 → 加重标记（P2 加固）

## 构建与打包

| 检查项 | 判据 | 级别 |
|---|---|---|
| 打包范围 | `frontendDist` / `files` 指向项目根时，忽略清单是否排除源码外内容（G01） | P2 |
| 硬编码清单 | 构建脚本里写死成员数组 → 新增成员静默缺失（G02） | P2 |
| 多入口覆盖 | 每个插件/页面是否都进了构建输入（自动扫描 vs 手写） | P2 |
| 产物对应 | 输出结构是否与运行时期望一致（如 `dist/plugins/<id>/index.html`） | P1 |
| 占位资源 | 图标 / identifier 是否仍是脚手架默认值（G05） | P3 |
| sourcemap / minify | 是否按 debug/release 区分 | P3 |

## 仓库卫生

| 检查项 | 判据 | 级别 |
|---|---|---|
| 忽略清单 | 缺 `node_modules` / `dist` / `target` / `__pycache__` / `.DS_Store`（G06） | P2 |
| CI | 存在 lint/test 脚本但无 CI 引用（G03） | P2 |
| 测试脚本可用性 | 脚本是否还能跑通（**过时测试脚本本身就是缺陷**） | P2 |
| 依赖锁定 | lock 文件是否完整；可选依赖是否在文档说明（G04） | P2 |
| 评审产物 | 审查报告/探针是否误入主产物 | P3 |

## 交付前检查（热区 H010）

打包前清理 `__pycache__`、`.DS_Store`、临时探针与中间产物。
