# 沙箱、桥接与权限（第 5 步 · 维度二）

## 核心判据：隔离切断的是「通道」还是「能力」？

文档通常会承诺「隔离 ≠ 断能力」。验证方法：
**在隔离/严格模式下把能力清单逐个跑一遍**，看哪些**静默**失效。

| 能力 | 直连通道 | 桥接通道 |
|---|---|---|
| 调后端命令 | 依赖全局注入 | 应由宿主代执行 |
| 持久化 | 依赖 localStorage | 应存在宿主侧 |
| 事件 | 依赖同文档 | 应由宿主总线中转 |
| UI 通知（标题/角标/提示） | 依赖 DOM | 应由宿主执行 |
| 状态查询（如是否隔离） | 依赖父窗口 | 应由宿主回答 |

**任何一项在隔离后静默失效 = P0**（D01：文档承诺失效 + 静默）。

## 桥接服务端五查

桥接服务端跑在**宿主侧**，是权限的关键收口点。逐项查：

1. **方法白名单** —— `mod[method]` 这类动态派发必须配允许列表，
   并用 `hasOwnProperty` 拦原型链（B02）
2. **能否自授权** —— 白名单里是否含策略写入方法（改权限模式、标记域名为可信）（D02）
3. **参数校验** —— 命名空间、方法名、参数类型是否校验
4. **返回值过滤** —— 函数/Symbol 等不可结构化克隆的字段是否过滤（否则整条响应抛错）
5. **错误不泄密** —— 异常信息是否回显路径/堆栈

## CSP / 权限配置三查

1. **每个入口都查** —— 多份 HTML / 多套构建配置，逐个确认（D04）
2. **合并语义查清** —— 构建工具的 `--config` / 平台配置是**合并（JSON Merge Patch）
   而非替换**。主配置里的安全项是否被另一份覆盖掉，要按合并规则推一遍（P05）
3. **文档承诺 vs 实际拦截能力** —— 文档若声称「外链由 CSP 真正拦住」，
   而某个入口没有 CSP → 该承诺在该模式下完全失效

**诚实边界**：JS 层做不了真正的拦截（拦不住 `<img>` / `<video>` 发起的请求）。
看到代码声称"在 JS 层拦截外链" → 报**虚假安全感**（P1）。
正确形态是「看得见、管得了、记得住」+ 生成建议 CSP 由用户落盘。

## 凭据与密钥

| 检查项 | 判据 |
|---|---|
| 是否明文落盘 | 存储里能直接读到密钥 → P0 |
| 「免口令」模式的密钥素材 | 是否**全部**来自同一个可被读出的存储（D08） |
| 盐/主密钥的位置 | 应由原生侧生成并存在应用数据目录 |
| 口令模式 | 密钥是否落盘（应不落盘） |
| 迭代次数 | PBKDF2 ≥ 310k 可接受；每次解锁重复派生可加会话内缓存 |
| 文档是否说清防护边界 | 只防「随手打开 DevTools」，还是也防「读取存储文件」 |

**加密不是银弹**：同源脚本一样能走解密流程。文档若夸大防护范围 → A04（P0）。

## 外链 / 外部代码入口

| 场景 | 是否算外部代码入口 | 归谁管 |
|---|---|---|
| 插件入口是外域 URL | **是**（最危险） | 安装时警告 + 确认 |
| 插件内部的 `<img>` / `<video>` / `fetch` | 否 | CSP 对应指令 |
| 插件入口是本地相对路径 | 否 | — |

检查点：安装/更新时是否扫描入口、运行时是否登记被拦请求、
决策是否持久化、是否能生成可直接落盘的 CSP 片段。

**「生成建议 CSP 后让用户手动粘贴」是半成品**——既然已有完整决策数据，
应能一键写入配置或至少生成可直接复制的完整标签（P2）。

## 静默失败清单（整机审查最易漏）

以下写法让缺陷不报错，用户侧只表现为「点了没反应」：

- 可选链兜底：`window.__X__?.method?.()` —— 取不到就不执行
- 空 catch：`catch {}` / `catch { /* ignore */ }`
- 降级返回 null 后调用方不再检查
- 能力探测失败后不再重试（C07）
- 采样失败后按「默认一致」处理（B05）

**审查时把 `?.` 与 `catch {}` 全列出来逐个问一句：这里有值时才执行，没值时会发生什么？**
