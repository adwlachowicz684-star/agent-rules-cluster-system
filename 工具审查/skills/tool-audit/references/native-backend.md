# 原生后端（第 5 步 · 维度三）

以 Rust / Tauri 为主，原则同样适用于 Electron 主进程、Go/C++ 后端。

## 文件系统操作（最高频缺陷源）

| 检查项 | 判据 | 级别 |
|---|---|---|
| 读入是否有界 | 是否用 `take(cap)` 流式读取，而非 `fs::read` 后截断（E01） | P1 |
| `max_bytes == 0` 的语义 | 退化成 `usize::MAX` 还是合理默认值 | **P0** |
| 删除保护 | 黑名单是否 `canonicalize` 后比较（D05） | **P0** |
| 删除目录 | 是否要求显式 force + dry-run 预览 | P1 |
| 递归遍历 | 是否用 `symlink_metadata` 跳过链接点（E04） | P1 |
| 跨设备移动 | `rename` 是否有 copy+delete 回退（E05） | P2 |
| 路径穿越 | 是否允许（本地工具可免责，但要在文档写明） | P2 |

**典型缺陷**：
```rust
let bytes = std::fs::read(p)?;                        // 10GB 直接进内存
let text = &bytes[..bytes.len().min(cap)];            // 之后才截断 → 上限形同虚设
```

## 进程与命令执行

| 检查项 | 判据 | 级别 |
|---|---|---|
| shell 解析 | 是否存在 `cmd /c` + 外部输入（D06） | **P0** |
| 可执行文件来源 | 白名单 vs 用户配置任意路径 | **P0** |
| 参数传递 | 参数数组 vs 字符串拼接 | P1 |
| 子进程生命周期 | 是否有注册表 + kill 能力 | P1 |
| 注册表清理 | 进程结束后是否 remove（否则内存持续增长） | P2 |
| 权限声明 | capabilities 里的 spawn 白名单是否克制 | P2 |
| 探测命令 | `where` / `which` 起子进程在 debug 下会闪控制台窗口 | P3 |

## 本地网络服务

自建 HTTP / WebSocket 服务时逐项查：

| 检查项 | 判据 | 级别 |
|---|---|---|
| 请求体上限 | 是否按客户端声明的 `content-length` 直接分配（E03） | **P0** |
| 读写超时 | 是否设置 `set_read_timeout` / `set_write_timeout` | **P0** |
| 绑定地址 | `127.0.0.1` vs `0.0.0.0`（后者对局域网开放） | **P0** |
| 鉴权 | token 为空时是否直接放行（R09） | **P0** |
| 并发上限 | 每连接一线程是否有上限（E08） | P1 |
| 响应构造 | 状态码与 reason 是否匹配（401 却写 OK） | P2 |

**空口令放行是最容易被忽略的一条**：代码写成
`if expected.is_empty() { return true; }`，本意是「没配口令就不校验」，
实际效果是「本机任何进程都能触发工作流」——进而启动子进程、执行文件操作。

## 锁与错误处理

| 检查项 | 判据 | 级别 |
|---|---|---|
| `lock().unwrap()` | 是否改为 `unwrap_or_else(\|e\| e.into_inner())` | P1 |
| 配合 `panic = "abort"` | 一次锁中毒 = 应用直接崩，无降级空间 | **P0** |
| 错误向上抛 | `Result` 是否一路传到命令边界 | P2 |

## 命令注册与状态管理

| 检查项 | 判据 |
|---|---|
| 注册完整性 | 命令是否都在 `invoke_handler` 里注册（未注册 = 死代码） |
| 孤儿文件 | `.rs` 文件是否都被 `mod` 声明（未声明 = 改了不生效，A08） |
| 重复实现 | 是否存在内容近似但已分叉的两份文件（**最危险**：改了不生效） |
| 状态管理 | 注册表（进程/监听/端口）是否在对象销毁时清理 |
| 启动参数 | 是否在 Builder 之前处理自有子命令，避免与框架参数冲突 |

## 依赖与构建

- 引入的每个 crate 都要能说清为什么不能用标准库替代
- 平台特定依赖（Windows 句柄类型）要写明规避理由
- release profile（`lto` / `panic` / `strip`）与错误处理能力要匹配

## 常见误报

- **「刻意不引第三方 crate」**——注释常会解释（如「少一个依赖就少一类编译失败」）
- **「路径穿越不做限制」**——本地工具可免责，但需确认文档写明
- **「用 std::fs 而非官方 fs 插件」**——语义上更接近「执行一条命令」，
  可省去逐条声明路径权限，不是缺陷
