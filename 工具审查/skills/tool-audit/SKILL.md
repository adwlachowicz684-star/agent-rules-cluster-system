# 工具型应用整机审查

对**工具型应用**做全量审查：机器扫描缩小范围 → **验证候选** → **比对文档承诺** →
分模块精审 → 分级 → 报告 + 修复任务清单。

模式库来自对 Nexus Panel（Tauri 2 + 双栈插件面板，5.26 万行，审出 55 条缺陷）的
全量审查聚类，覆盖「外壳 / 插件引擎 / 主题系统 / 沙箱桥接 / 外链策略 / Rust 后端 / 8 个插件」。

## 何时使用

- 用户要求「审查」「审一遍」「体检」「挑毛病」「上线前检查」某个工具型应用
- 应用由**外壳 + 可扩展模块**构成（插件体系、微前端、脚本机制），需验证契约是否成立
- 存在**两套实现**（原生 + 构建版、双语言、新旧并存），需验证能力是否对等
- 已有历史审查报告，需**修复复核**（确认修了没、有无引入新问题）
- 接手陌生仓库，需要快速建立「哪里能信、哪里不能信」的地图

不适用：单文件走查、纯风格检查、PR diff 审查（那是另一套流程）。

## 核心原则

1. **先扫描再精读** —— 用扫描器把范围缩到具体文件具体行
2. **扫描器只出候选** —— 每条都要验证，它有漏报也有误报
3. **README 是契约** —— 把文档当需求文档逐条对实现。承诺失效类（A 族）在整机审查中
   占比最高，且用户最能感知：「文档说有，点下去没反应」
4. **先读注释再报问题** —— 大量「看起来像 bug」的写法带长注释解释原因，
   这是最高频的误报来源（Nexus Panel 里就有多处注释写着「这里不能回发 ready，会死锁」）
5. **静默失败最严重** —— 可选链 `?.`、空 `catch {}`、降级返回 `null` 让缺陷不报错，
   用户侧表现为「点了没反应」，比崩溃更难发现
6. **双实现必定分叉** —— 有两套外壳/两套语言实现时，**先做差异比对**再谈细节
7. **测试全绿 ≠ 可发布** —— 测试覆盖不到的边界（隔离态、跨设备、超大文件）才是重灾区
8. **发现的问题默认先报不改** —— 等用户批准后再落盘修正源码

## Input / Output

**接收**：仓库根路径（或源码根）；可选的 README/文档、已知台账、历史审查报告。

**返回**：

| 产物 | 位置 | 说明 |
|---|---|---|
| 整机审查报告 | `审查报告_<项目名>.md` | 按 `assets/report-template.md` 结构 |
| 修复任务清单 | 同报告内或独立文件 | 编号 + 级别 + 位置 + 修法 + 批次 |
| 文档一致性候选 | `文档一致性_候选.txt` | `doc-scan.py` 产出，供人工核对 |
| 扫描基线 | `扫描结果_全量.txt` / `_P0.txt` | 供后续复核比对 |

## 六步流程

| 步 | 做什么 | 命令 / 读哪个文件 |
|---|---|---|
| 1 | 摸清现状（技术栈、模块划分、是否已有历史报告） | `references/workflow.md` |
| 2 | 全库模式扫描（52 条，其中 28 条可机扫） | `scripts/tool-scan.py --src=<根>` |
| 3 | 文档一致性扫描（README 承诺 vs 实现） | `scripts/doc-scan.py --src=<根>` |
| 4 | **验证候选**（独立步骤，过滤误报） | `references/pattern-detection.md` |
| 5 | 分模块精审（契约、沙箱、后端、生命周期、构建） | `references/host-plugin.md` 等 5 份 |
| 6 | 分级 + 报告 + 修复清单 | `references/severity.md` · `references/reporting.md` |

详细展开见 `references/workflow.md`。

**第 4 步不可省略**：扫描器产出的是候选。每条候选都要对照实际行为
（读上下文、读注释、必要时写最小复现）确认是否为真问题。这一步是区分
「有用审查」与「噪音」的关键。

**第 3 步是整机审查特有的**：单库审查不会去对文档，但工具型应用的用户（包括
下一个接手的 AI）是靠 README 认识它的。文档说 4 个测试脚本、实际 13 个；
文档说默认主题 A、实际是 B —— 都是真缺陷，且只有这一步能发现。

## 命令速查

源码根 = 仓库根（会按一级子目录分模块）。扁平结构加 `--flat`。

```bash
# 模式扫描（28 条可机扫）
python3 scripts/tool-scan.py --src=<根>                    # 全量
python3 scripts/tool-scan.py --src=<根> --p0               # 只看致命级
python3 scripts/tool-scan.py --src=<根> js plugins src     # 只扫指定模块
python3 scripts/tool-scan.py --src=<根> --pattern=D01      # 只扫某条模式
python3 scripts/tool-scan.py --src=<根> --json             # 机器可读
python3 scripts/tool-scan.py --src=<根> --flat             # 扁平结构
python3 scripts/tool-scan.py --self-test                   # 模式自检（必过 28/28）

# 文档一致性
python3 scripts/doc-scan.py --src=<根>                     # 全量
python3 scripts/doc-scan.py --src=<根> --commands-only     # 只查命令是否存在
python3 scripts/doc-scan.py --src=<根> --links-only        # 只查引用的文件是否存在

# 变更溯源（改了技能就记一行，见 references/maintenance.md）
python3 scripts/note.py "<ID>" <类型> "<原因>"
python3 scripts/note.py --show

# skill 自检
python3 scripts/check-skill.py
```

## 硬约束

- **每条缺陷必须给三件套**：位置（`文件:起止行`）+ 证据（实测输出或可验证推导链）+
  后果（什么场景暴露、什么症状）。「应该」「可能」「似乎」一律不成立。
- **没有实测就标注「未实测（静态分析）」**，不得伪装成已验证。
- **文档承诺失效按 P1 起评**：文档说有而实际没有 = 用户必然踩到。
- **文档把缺陷记为设计意图 → P0**（会阻止下一个人修复）。
- **安全/权限链路的「放行」一律按 P0**（空口令放行、黑名单可绕过、桥接无白名单）。
- **先读注释再报问题**。最高频的误报来源就是没读注释。
- **隔离态要单独审一遍**：默认配置下跑通不代表隔离/严格模式下能跑通，
  很多能力在隔离后**静默失效**（绕过了宿主上下文直连底层 API）。
- **两条实现要逐项比对**，不能只看其中一条就下结论。
- **报告必须写「验证过没问题的部分」**——避免后续重复报已修问题。
- **发现的问题默认先报不改**，等用户批准后再落盘修正源码。

## Troubleshooting

| 症状 | 原因 | 处理 |
|---|---|---|
| 扫描出几百条候选，无从下手 | 计数多的模式（J09 只注册不注销、J10 无清理）本质是需要批量处理的族 | 先处理**计数少**的模式（D04 空口令放行、E01 整文件读入、R02 lock unwrap），它们几乎条条是真问题；计数多的抽样确认后按族批量修 |
| 候选看着像 bug，但代码上方有长注释 | 那大概率是设计意图 | 报之前先读注释。Nexus Panel 里「这里不能回发 ready」「这里必须主动 removeProperty」都被注释解释过 |
| 报「孤儿文件」但它是入口/被动态引用 | 静态分析看不到动态 import（字符串拼接、运行时扫描目录） | 确认是否出现在入口（index.html / vite inputs / package.json main）或构建配置的动态扫描里，是则忽略 |
| 文档扫描报「命令不存在」 | 命令在子目录的 package.json 里，或需要 npx | 先确认执行根；子项目用 `--src=<子目录>` 再跑一次 |
| 已修模块再扫，报的是残留项而非原问题 | 分类器会漂移 | 复核前先确认该模块是否修过，对照历史报告与当前代码 |
| 有一条模式在全库 0 命中 | 可能已全部修好，也可能模式本身失效 | 跑 `tool-scan.py --self-test`，要求 28/28 通过 |
| 想确认 skill 自身结构没问题 | — | `check-skill.py`：断链、孤儿文件、体积预算、frontmatter |
| 报告的行号指向错误的代码 | 注释剥离未保持行数守恒 | 先跑 `--self-test` 看 `✓ 行数守恒`；不通过则整份报告不可用 |
